## IPv6 in one paragraph

IPv6 addresses are **128 bits**, written as eight groups (hextets) of four hex digits separated by colons. There is **no broadcast**; multicast does that job. Every IPv6-enabled interface has a **link-local** address, most also have one or more **global unicast** addresses, and hosts can configure themselves from router advertisements (**SLAAC**) without any DHCP server.

## Writing addresses: the two abbreviation rules

1. **Drop leading zeros** in any hextet: `0DB8` becomes `DB8`, `0000` becomes `0`.
2. **Replace one run of consecutive all-zero hextets with `::`**, and only **once** per address (otherwise you could not tell how many zeros each `::` stands for).

| Full | Compressed |
|---|---|
| 2001:0DB8:0000:0000:0000:0000:0000:0001 | 2001:DB8::1 |
| 2001:0DB8:0000:00A0:0000:0000:0000:0010 | 2001:DB8:0:A0::10 |
| FE80:0000:0000:0000:021A:2BFF:FE3C:4D5E | FE80::21A:2BFF:FE3C:4D5E |
| 0000:0000:0000:0000:0000:0000:0000:0001 | ::1 |

The recommended canonical form (RFC 5952) adds: compress the **longest** run of zero hextets (the first one if two runs tie), do not use `::` for a single zero hextet, and use lowercase. IOS displays uppercase; both are valid input.

> **Watch out:** You may only remove **leading** zeros. `2001:DB8:A::` is not the same as `2001:DB8:A000::`. And `2001:DB8::1::5` is invalid because `::` appears twice.

## Address types

| Type | Prefix | Scope / purpose |
|---|---|---|
| Global unicast (GUA) | 2000::/3 (starts with 2 or 3) | Internet-routable, like public IPv4 |
| Unique local (ULA) | FC00::/7 (in practice FD00::/8) | Private, routable inside an organization, not on the internet; similar to RFC 1918 |
| Link-local | FE80::/10 | Only on the local link; never routed. Used for neighbor discovery and as routing next hops |
| Multicast | FF00::/8 | One-to-many; replaces broadcast |
| Anycast | Any unicast prefix | Same address on several devices; packets go to the nearest one |
| Loopback | ::1/128 | The host itself |
| Unspecified | ::/128 | "No address yet", e.g., source during DAD |

Anycast addresses are **indistinguishable** in format from unicast; you configure an address as anycast (on IOS, `ipv6 address 2001:DB8:1::100/64 anycast`).

Multicast addresses to know:

| Address | Group |
|---|---|
| FF02::1 | All nodes on the link |
| FF02::2 | All routers on the link |
| FF02::5 / FF02::6 | OSPFv3 all routers / DRs |
| FF02::1:2 | All DHCPv6 servers and relay agents |
| FF02::1:FFxx:xxxx | **Solicited-node** multicast: FF02::1:FF + last 24 bits of a unicast address |

## Prefix sizing

A GUA is commonly split as **global routing prefix** (assigned by your ISP/RIR) + **subnet ID** + **interface ID**.

| Prefix length | Typical use |
|---|---|
| /32 | Allocation from an RIR to an ISP or large organization |
| /48 | Typical allocation to a site/enterprise |
| /56 | Typical allocation to a home or small site |
| **/64** | **One LAN subnet** (required for SLAAC) |
| /127 | Point-to-point router link (RFC 6164) |
| /128 | A single address, e.g., a loopback |

Subnets available = 2^(64 - allocated prefix). A /48 gives 2^16 = **65,536** /64 subnets; a /56 gives **256**; a /60 gives 16.

To find the prefix of an address with a non-hextet-aligned length, keep the prefix bits and zero the rest. For 2001:DB8:ACAD:1234::1/56, the /56 boundary falls 8 bits into the 4th hextet: `12|34` keeps `12`, so the prefix is **2001:DB8:ACAD:1200::/56**.

## Modified EUI-64, step by step

Modified EUI-64 builds a 64-bit interface ID from a 48-bit MAC address. Example MAC **001A.2B3C.4D5E**:

1. Split the MAC in half: `001A2B` | `3C4D5E`.
2. Insert **FFFE** in the middle: `001A2B` `FFFE` `3C4D5E`.
3. **Flip the 7th bit** (the Universal/Local bit) of the first byte. `00` = 0000 0000, flip the 7th bit from the left: 0000 0**0**10 = **02**.
4. Result: **021A:2BFF:FE3C:4D5E**.

With prefix 2001:DB8:ACAD:10::/64, the address is **2001:DB8:ACAD:10:21A:2BFF:FE3C:4D5E**.

Flipping means the bit can go either way. Quick lookup for the second hex digit of the first byte: 0 to 2, 1 to 3, 4 to 6, 5 to 7, 8 to A, 9 to B, C to E, D to F, and the reverse (2 to 0, A to 8, E to C, and so on). Example: MAC **AABB.CC00.1122** has first byte AA (1010 1010); flipping gives A8, so the interface ID is **A8BB:CCFF:FE00:1122**.

> **Exam tip:** Only the second hex digit of the first byte ever changes, and it always changes by exactly 2 (add 2 if that bit was 0, subtract 2 if it was 1). If an answer changes any other digit, it is wrong.

## Configuring IPv6 on IOS

```ios
R1(config)# ipv6 unicast-routing
R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# ipv6 address 2001:DB8:ACAD:10::1/64
R1(config-if)# ipv6 address FE80::1 link-local
R1(config-if)# no shutdown
R1(config-if)# interface GigabitEthernet0/0/1
R1(config-if)# ipv6 address 2001:DB8:ACAD:20::/64 eui-64
```

* `ipv6 unicast-routing` enables IPv6 **forwarding** and makes the router send **router advertisements**. Without it, the router still has IPv6 addresses but behaves like a host: it does not route IPv6 and does not send RAs.
* `eui-64` takes the /64 prefix and appends the interface's modified EUI-64 ID.
* Configuring any IPv6 address automatically creates a link-local address (EUI-64 based on IOS unless set manually). `ipv6 enable` creates only the link-local.
* Router acting as a client: `ipv6 address autoconfig` (SLAAC, add `default` to install a default route from the RA) or `ipv6 address dhcp`.

```ios
R1# show ipv6 interface brief
GigabitEthernet0/0/0   [up/up]
    FE80::1
    2001:DB8:ACAD:10::1
GigabitEthernet0/0/1   [up/up]
    FE80::21A:2BFF:FE3C:4D5F
    2001:DB8:ACAD:20:21A:2BFF:FE3C:4D5F
```

(Here Gi0/0/1's MAC is 001A.2B3C.4D5F, so its EUI-64 ID ends in 4D5F.)

`show ipv6 interface GigabitEthernet0/0/0` lists the joined multicast groups. A router with `ipv6 unicast-routing` joins **FF02::2**; if FF02::2 is missing, routing is not enabled.

## How hosts get addresses: SLAAC and DHCPv6

Neighbor Discovery (NDP, part of ICMPv6) replaces ARP and adds router discovery:

| Message | ICMPv6 type | Purpose |
|---|---|---|
| Router Solicitation (RS) | 133 | Host asks routers (FF02::2) to send an RA now |
| Router Advertisement (RA) | 134 | Router announces prefix(es), flags, and itself as default gateway |
| Neighbor Solicitation (NS) | 135 | Address resolution (like an ARP request) and DAD |
| Neighbor Advertisement (NA) | 136 | Reply to NS (like an ARP reply) |

The RA carries flags that tell hosts how to configure themselves:

| Method | Address comes from | DNS comes from | RA flags |
|---|---|---|---|
| SLAAC only | Host builds it from RA prefix | RA RDNSS option (if supported) | A=1, M=0, O=0 |
| SLAAC + stateless DHCPv6 | Host builds it from RA prefix | DHCPv6 server | A=1, **O=1** |
| Stateful DHCPv6 | DHCPv6 server assigns it | DHCPv6 server | **M=1** |

In every case the **default gateway comes from the RA** (the router's link-local address). DHCPv6 has no default-gateway option. On IOS the flags are set per interface with `ipv6 nd other-config-flag` and `ipv6 nd managed-config-flag`.

With SLAAC the host appends a 64-bit interface ID to the advertised /64. That ID may be modified EUI-64 or randomized (Windows uses random IDs by default; most modern OSs also create temporary privacy addresses). Before using any address, the host performs **Duplicate Address Detection (DAD)**: it sends an NS for its tentative address to the solicited-node multicast group, and if anyone answers, the address is a duplicate.

## Troubleshooting IPv6 addressing

| Symptom | Likely cause |
|---|---|
| Host has only an FE80:: address | No RA received: `ipv6 unicast-routing` missing, RAs suppressed, wrong VLAN, or router interface has no IPv6 prefix |
| Host has a GUA but no default gateway | RA not received from the router (address statically set), or RA router lifetime is 0 |
| SLAAC does not form an address | Advertised prefix is not a /64 |
| IOS shows an address as `[DUP]` / `%IPV6_ND-4-DUPLICATE` log | Another device already uses the address (DAD failure) |
| Host address is in the wrong /64 | Router interface configured with the wrong prefix (typo in the subnet ID), or host in the wrong VLAN |
| Stateless DHCPv6 clients have no DNS | O flag not set or no DHCPv6 server/relay |
| Static route via link-local next hop rejected | A link-local next hop requires the exit interface too |

> **Real world:** When a host's default gateway shows as `fe80::1%12`, that is normal: IPv6 hosts use the router's link-local address as the next hop, and `%12` is the zone (interface) index.

## Key takeaways

* Compress by dropping **leading** zeros and using `::` **once** for a run of zero hextets.
* GUA 2000::/3, ULA FC00::/7 (FD00::/8 used), link-local FE80::/10, multicast FF00::/8; anycast uses normal unicast format.
* LANs use **/64**; a /48 contains 65,536 /64s and a /56 contains 256.
* Modified EUI-64: split the MAC, insert FFFE, flip the 7th bit (the second hex digit changes by 2).
* `ipv6 unicast-routing` is required for routing and for sending RAs; `ipv6 address <prefix>/64 eui-64` builds the address from the MAC.
* SLAAC uses RS/RA; M flag = stateful DHCPv6, O flag = stateless DHCPv6 for options; the default gateway always comes from the RA.
* A host with only a link-local address usually means it never received an RA.
