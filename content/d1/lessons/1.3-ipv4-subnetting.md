## The goal: speed and certainty

Subnetting is not hard; it is just arithmetic that must be done quickly and without mistakes under exam pressure. You need to go from any address and prefix to its **network address, broadcast address, usable host range, and host count** in well under a minute, and you need to build a VLSM plan from host requirements.

## Anatomy of an IPv4 address and mask

An IPv4 address is 32 bits, written as four decimal octets. The **subnet mask** (or prefix length) marks which leading bits are the **network** portion; the remaining bits are the **host** portion.

* **Network address**: host bits all 0. Identifies the subnet; not assignable to a host.
* **Broadcast address**: host bits all 1. Reaches every host on the subnet; not assignable.
* **Usable hosts**: 2^h - 2, where h is the number of host bits.

### Prefix / mask / block size table

Memorize the eight possible "interesting octet" values:

| Bits set in octet | Mask octet | Block size (256 - mask) |
|---|---|---|
| 1 | 128 | 128 |
| 2 | 192 | 64 |
| 3 | 224 | 32 |
| 4 | 240 | 16 |
| 5 | 248 | 8 |
| 6 | 252 | 4 |
| 7 | 254 | 2 |
| 8 | 255 | 1 |

|---|---|---|
| /20 | 255.255.240.0 | 4094 |

| /22 | 255.255.252.0 | 1022 |
| /23 | 255.255.254.0 | 510 |
| /24 | 255.255.255.0 | 254 |
| /25 | 255.255.255.128 | 126 |

| /27 | 255.255.255.224 | 30 |

| /29 | 255.255.255.248 | 6 |
| /30 | 255.255.255.252 | 2 |
| /31 | 255.255.255.254 | 2 (point-to-point only, RFC 3021) |
| /32 | 255.255.255.255 | 1 (host route / loopback) |

## The block-size method

1. Find the **interesting octet**: the octet where the mask is neither 255 nor 0.
2. **Block size** = 256 - mask value in that octet.
3. The subnet boundaries are multiples of the block size in that octet. The **network** is the largest multiple that is less than or equal to the address's value in that octet.
4. **Broadcast** = next network - 1 (in that octet), with all later octets = 255.
5. **Usable range** = network + 1 through broadcast - 1.

### Worked example 1: 192.168.10.77/27

* /27 = 255.255.255.**224**; interesting octet is the 4th; block = 32.
* Multiples of 32: 0, 32, 64, 96 ... 77 falls in the 64 block.
* Network **192.168.10.64**, broadcast **192.168.10.95**, hosts **.65 - .94** (30 usable).

### Worked example 2: 172.16.45.200/20

* /20 = 255.255.**240**.0; interesting octet is the 3rd; block = 16.
* Multiples of 16: 0, 16, 32, 48 ... 45 falls in the 32 block.
* Network **172.16.32.0**, broadcast **172.16.47.255**.
* Usable **172.16.32.1 - 172.16.47.254** (2^12 - 2 = 4094 hosts).

### Worked example 3: 10.200.13.5/14

* /14 = 255.**252**.0.0; interesting octet is the 2nd; block = 4.
* 200 is a multiple of 4, so network **10.200.0.0**, broadcast **10.203.255.255**.

> **Exam tip:** In a /23 or larger, an address ending in .0 or .255 can be a perfectly valid host. 172.16.33.0/20 is a usable host address because the network is 172.16.32.0 and the broadcast is 172.16.47.255.

## Counting subnets and hosts

When you subnet a larger block, **borrowed bits** = new prefix - old prefix, and subnets = 2^borrowed.

* 172.16.0.0/16 split into /22s: 6 borrowed bits = **64 subnets** of 1022 hosts each.
* 192.168.1.0/24 split into /28s: 4 borrowed bits = **16 subnets** of 14 hosts each.

To choose a prefix for a host requirement, find the smallest h where 2^h - 2 is greater than or equal to the hosts needed, then prefix = 32 - h. For 60 hosts: 2^6 - 2 = 62, so h = 6 and the prefix is /26. For 64 hosts, /26 is too small (62), so you need a /25.

> **Watch out:** Hosts needed usually includes the router's gateway interface. "50 PCs plus the gateway" is 51 addresses, still fine in a /26, but "62 PCs plus the gateway" is 63 and needs a /25.

## VLSM design

Variable Length Subnet Masking means using different prefix lengths inside one major block so each subnet is sized to its need. Always allocate **largest first** to keep every subnet on a valid boundary.

Requirement: from 192.168.50.0/24, create subnets for Sales (100 hosts), Engineering (50), Management (25), and two router-to-router links.

| Subnet | Need | Prefix | Network | Usable range | Broadcast |
|---|---|---|---|---|---|
| Sales | 100 | /25 (126) | 192.168.50.0 | .1 - .126 | .127 |
| Engineering | 50 | /26 (62) | 192.168.50.128 | .129 - .190 | .191 |
| Management | 25 | /27 (30) | 192.168.50.192 | .193 - .222 | .223 |
| Link 1 | 2 | /30 (2) | 192.168.50.224 | .225 - .226 | .227 |
| Link 2 | 2 | /30 (2) | 192.168.50.228 | .229 - .230 | .231 |

192.168.50.232 - .255 remains free for growth (for example a /29 at .232 and a /28 at .240).

> **Watch out:** A subnet must start on a multiple of its own block size. 192.168.50.96/26 is invalid because 96 is not a multiple of 64; the router will accept `ip address 192.168.50.100 255.255.255.192` but the subnet it lives in is 192.168.50.64/26, which may overlap your plan.

## Classful background

Classes no longer control routing (CIDR does), but the exam still expects you to recognize them:

| Class | First octet | Default mask | Purpose |
|---|---|---|---|
| A | 1 - 126 | /8 | Unicast |
| B | 128 - 191 | /16 | Unicast |
| C | 192 - 223 | /24 | Unicast |
| D | 224 - 239 | n/a | Multicast |
| E | 240 - 255 | n/a | Reserved/experimental |

127 is excluded from class A because 127.0.0.0/8 is reserved for loopback.

## Public, private, and special-use ranges

**RFC 1918 private ranges** are not routed on the internet; reaching the internet from them requires NAT:

| Range | Prefix | Size |
|---|---|---|
| 10.0.0.0 - 10.255.255.255 | 10.0.0.0/8 | One class A |
| 172.16.0.0 - 172.31.255.255 | 172.16.0.0/12 | 16 class Bs |
| 192.168.0.0 - 192.168.255.255 | 192.168.0.0/16 | 256 class Cs |

Other special ranges you must recognize:

| Range | Use |
|---|---|
| 127.0.0.0/8 | Loopback (127.0.0.1 is the local host itself) |
| 169.254.0.0/16 | Link-local / **APIPA**: a host assigns itself one when DHCP fails |
| 100.64.0.0/10 | Shared address space for carrier-grade NAT (RFC 6598), **not** RFC 1918 |
| 0.0.0.0/8 | "This network"; 0.0.0.0 is the source of a DHCP Discover |
| 255.255.255.255 | Limited broadcast |
| 224.0.0.0/4 | Multicast |
| 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 | Documentation (TEST-NET-1/2/3) |

> **Exam tip:** The 172 range trips people up. 172.16.x.x through 172.31.x.x is private; 172.15.x.x and 172.32.x.x are public. Likewise 192.168.x.x is private but 192.169.x.x is public.

> **Real world:** On IOS, a loopback interface is a virtual interface you create (`interface Loopback0`) and usually address with a /32. That is different from the 127.0.0.0/8 loopback range used inside a host's own TCP/IP stack.

## Speed drills to practice

* Address 10.1.1.130/26: block 64, network 10.1.1.128, broadcast 10.1.1.191.
* Address 172.20.99.7/22: block 4 in the 3rd octet, network 172.20.96.0, broadcast 172.20.99.255.
* Address 192.168.7.9/29: block 8, network 192.168.7.8, broadcast 192.168.7.15, hosts .9 - .14.
* Smallest prefix for 500 hosts: 2^9 - 2 = 510, so /23.

## Key takeaways

* Block size = 256 - mask value in the interesting octet; networks are multiples of the block size.
* Broadcast = next network - 1; usable hosts = 2^h - 2.
* Pick a prefix from the host count (including the gateway), then allocate VLSM subnets **largest first**.
* RFC 1918: 10/8, 172.16/12 (172.16-172.31), 192.168/16. 100.64/10 is CGNAT space, not RFC 1918.
* 169.254.0.0/16 (APIPA) means the host self-assigned; 127.0.0.0/8 is loopback.
* /31 is valid for point-to-point links; /32 is a single host.
