## Start with the status line

Every interface troubleshooting session starts with two words: the **interface status** (Layer 1) and the **line protocol** status (Layer 2).

```ios
R1# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet0/0/0   10.1.12.1       YES manual up                    up
GigabitEthernet0/0/1   10.1.13.1       YES manual administratively down down
GigabitEthernet0/0/2   10.1.14.1       YES manual down                  down
Serial0/1/0            10.1.15.1       YES manual up                    down
```

| Status / Protocol | Meaning | Typical causes |
|---|---|---|
| up / up | Working at L1 and L2 | (Look higher: IP, routing, ACLs) |
| administratively down / down | Someone typed `shutdown` | `no shutdown` fixes it |
| down / down | No usable physical link | Unplugged or broken cable, far end shut down, speed mismatch, wrong or mismatched optic, crossed fiber, err-disabled |
| up / down | Physical signal present, Layer 2 failing | Serial encapsulation mismatch (HDLC vs PPP), keepalive failures, missing clocking; uncommon on Ethernet |

On a Catalyst switch, `show interfaces status` gives a one-line view per port and, importantly, shows whether speed and duplex were **negotiated** (`a-full`, `a-1000`) or **hard-coded** (`full`, `100`):

```ios
SW1# show interfaces status

Port         Name               Status       Vlan       Duplex  Speed Type
Gi1/0/1      UPLINK-R1          connected    trunk        a-full a-1000 10/100/1000BaseTX
Gi1/0/2      PRINTER-2F         connected    20           a-half  a-100 10/100/1000BaseTX
Gi1/0/3                         notconnect   1              auto   auto 10/100/1000BaseTX
Gi1/0/4      SPARE              disabled     1              auto   auto 10/100/1000BaseTX
Gi1/0/5      CONF-ROOM          err-disabled 30             auto   auto 10/100/1000BaseTX
Gi1/0/6      CAMERA-LOBBY       inactive     99             auto   auto 10/100/1000BaseTX
```

| Switch status | Meaning |
|---|---|
| connected | Link up |
| notconnect | No link: cable, far end, or speed mismatch |
| disabled | Administratively shut down |
| err-disabled | Shut down by the switch because of a detected error condition |
| inactive | Access VLAN does not exist on this switch |

> **Exam tip:** `a-half` on a modern port is a red flag. Two auto-negotiating Gigabit devices end up full duplex; half duplex usually means the far end is hard-coded.

## Reading the counters

`show interfaces` is the main source of Layer 1/2 evidence:

```ios
SW1# show interfaces GigabitEthernet1/0/2
GigabitEthernet1/0/2 is up, line protocol is up (connected)
  Hardware is Gigabit Ethernet, address is 7c0e.ce1a.2b82 (bia 7c0e.ce1a.2b82)
  Description: PRINTER-2F
  MTU 1500 bytes, BW 100000 Kbit/sec, DLY 100 usec,
     reliability 251/255, txload 1/255, rxload 1/255
  Encapsulation ARPA, loopback not set
  Half-duplex, 100Mb/s, media type is 10/100/1000BaseTX
  ...
     55214 packets input, 7419310 bytes, 0 no buffer
     Received 210 broadcasts (180 multicasts)
     0 runts, 0 giants, 0 throttles
     0 input errors, 0 CRC, 0 frame, 0 overrun, 0 ignored
     ...
     61902 packets output, 9120844 bytes, 0 underruns
     0 output errors, 1842 collisions, 0 interface resets
     0 unknown protocol drops
     0 babbles, 377 late collision, 0 deferred
     0 lost carrier, 0 no carrier, 0 pause output
```

| Counter | What it means | Usual suspects |
|---|---|---|
| **input errors** | Total of runts, giants, CRC, frame, overrun, ignored, etc. | Look at which sub-counter is growing |
| **CRC** | Frame arrived but its FCS did not match | Bad or too-long cable, EMI, bad optic/connector, **duplex mismatch (full-duplex side)** |
| **runts** | Frames smaller than 64 bytes | Collision fragments from a **duplex mismatch**, faulty NIC |
| **giants** | Frames larger than the maximum (1518/1522 bytes) | MTU or jumbo-frame mismatch |
| **collisions** | Transmit attempts that collided | Normal in moderation on a half-duplex link; should be **zero** on full duplex |
| **late collision** | Collision after the first 64 bytes (512 bit times) were sent | **Duplex mismatch (half-duplex side)** or a cable far beyond spec |
| **output errors** | Frames that could not be transmitted | Often accompanies collisions |
| **interface resets** | Interface was reset (e.g., keepalive or carrier problems) | Flapping cable, failing hardware |

> **Watch out:** Counters are cumulative since the last clear or reload. Clear them (`clear counters GigabitEthernet1/0/2`), wait, and check whether they are *still increasing* before you act on them.

## Duplex mismatch

A duplex mismatch is the most tested Layer 1/2 fault because the link stays **up/up** and pings mostly work; only throughput suffers.

How it usually happens: one side is hard-coded `speed 100` / `duplex full`, the other is left on auto. The auto side cannot negotiate with a hard-coded partner, so it uses *parallel detection*: it can sense the speed from the signal, but it cannot learn the duplex, so at 10 or 100 Mbps it falls back to **half duplex**.

| Side | Behavior | Counters that rise |
|---|---|---|
| Half-duplex side | Uses CSMA/CD; sees the full-duplex peer transmitting "mid-frame" | **late collisions**, collisions |
| Full-duplex side | Transmits whenever it wants; receives frames the half-duplex side aborted | **CRC/FCS errors, runts**, input errors |

Fix: make both sides match. Best practice is **auto/auto on both ends**; if policy demands hard-coding, hard-code **both** ends identically.

```ios
SW1(config)# interface GigabitEthernet1/0/2
SW1(config-if)# speed auto
SW1(config-if)# duplex auto
```

## Speed mismatch

If both ends are hard-coded to different speeds (for example 100 vs 1000), there is no common signaling and the link is **down/down** (`notconnect` on a switch). If one side is on auto, parallel detection usually finds the right speed, so speed mismatches mainly happen when both sides are hard-coded. CDP may log `%CDP-4-DUPLEX_MISMATCH` for duplex problems, but a speed mismatch just shows a dead link.

## err-disabled ports

The switch puts a port into **err-disabled** state (effectively shut down) when a protection feature trips. Common triggers:

* Port security violation in `shutdown` mode (`psecure-violation`)
* BPDU Guard receiving a BPDU on a PortFast edge port (`bpduguard`)
* UDLD detecting a unidirectional link
* EtherChannel misconfiguration, link flapping, DHCP snooping rate limit exceeded

```ios
SW1# show interfaces status err-disabled

Port         Name               Status       Reason               Err-disabled Vlans
Gi1/0/5      CONF-ROOM          err-disabled bpduguard

SW1# show errdisable recovery
```

Recovery: **fix the cause first**, then bounce the port with `shutdown` followed by `no shutdown`. Automatic recovery can be enabled per cause, for example `errdisable recovery cause bpduguard` with `errdisable recovery interval 300`.

## Distance and cable faults

A copper run past 100 m, a damaged cable, or poor terminations show up as CRC errors, a link that renegotiates to a lower speed, or flapping (`%LINK-3-UPDOWN` messages repeating in the log). Many Catalyst switches can test copper with Time Domain Reflectometry:

```ios
SW1# test cable-diagnostics tdr interface GigabitEthernet1/0/3
SW1# show cable-diagnostics tdr interface GigabitEthernet1/0/3
```

The TDR result reports each pair as Normal, Open, Short, or Impedance Mismatch, plus an approximate distance to the fault.

## Optical signal levels

Fiber problems are judged by optical power in **dBm** (decibels relative to 1 mW). 0 dBm = 1 mW; negative values are less than 1 mW. Optics with digital optical monitoring (DOM) report their readings:

```ios
SW1# show interfaces transceiver
If device is externally calibrated, only calibrated values are printed.
++ : high alarm, +  : high warning, -  : low warning, -- : low alarm.
NA or N/A: not applicable, Tx: transmit, Rx: receive.
mA: milliamperes, dBm: decibels (milliwatts).

                                           Optical   Optical
            Temperature  Voltage  Current  Tx Power  Rx Power
Port        (Celsius)    (Volts)  (mA)     (dBm)     (dBm)
---------   -----------  -------  -------  --------  --------
Te1/1/1       33.1       3.30      36.2     -2.2      -3.1
Te1/1/2       32.7       3.29      35.9     -2.4     -19.6 --
```

Te1/1/1 is healthy: -3.1 dBm received is well within an LR optic's normal receive range. (To calculate the actual link loss, subtract this Rx reading from the *far end's* Tx reading; the Tx value on the same line is this optic's own transmit power toward the far end.) Te1/1/2 is receiving far too little light (low alarm, `--`). Use `show interfaces transceiver detail` to see the exact alarm and warning thresholds for the optic.

| Symptom | Likely causes |
|---|---|
| Rx very low or absent, link down | Dirty or damaged connector, crossed Tx/Rx strands, broken fiber, wrong fiber type (MMF patch on an SMF link), far-end optic failed or shut |
| Rx low but link up, CRC errors rising | Dirty connector, tight bend, bad splice, run longer than the optic's budget |
| Rx too high (high alarm) | Long-reach optic (for example ER) on a very short link; add an attenuator or use the correct optic |
| Tx low on local optic | Failing transceiver |

> **Real world:** Always compare readings from **both** ends. If A's Rx is low but B's Rx is fine, the problem is in the strand from B to A (or B's transmitter). Clean both ends with a proper fiber cleaner before replacing optics.

## A practical flow

1. `show interfaces status` / `show ip interface brief` - is it up/up, down/down, admin down, or err-disabled?
2. If down: check cable/optic presence, far-end state, speed settings, optic type match, light levels.
3. If up but slow or lossy: compare speed/duplex on both ends, then watch CRC, runts, and late collisions after clearing counters.
4. If err-disabled: find the reason, fix it, then bounce the port.

## Key takeaways

* **Admin down** = `shutdown`; **down/down** = Layer 1 problem; **up/down** = Layer 2 problem (mostly serial encapsulation or keepalives).
* Duplex mismatch: **late collisions on the half-duplex side**, **CRC errors and runts on the full-duplex side**, link stays up.
* Hard-coding one side and leaving the other on auto causes the auto side to fall back to **half duplex** at 10/100 Mbps.
* Speed mismatch with both ends hard-coded = **link down** (`notconnect`).
* Collisions should be zero on full-duplex links; late collisions point to duplex mismatch or excessive cable length.
* err-disabled ports need the cause fixed, then `shutdown`/`no shutdown` (or errdisable recovery).
* Optical power is read in dBm; low Rx usually means dirty connectors, bends, wrong fiber, or crossed strands. Check both ends.
