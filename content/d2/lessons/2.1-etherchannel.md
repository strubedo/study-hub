## Why EtherChannel

Two parallel links between switches normally means spanning tree blocks one of them. An **EtherChannel** (port channel) bundles 2–8 active physical links into one logical interface (`Port-channel N`). STP sees one link, so all members forward, and traffic is spread across the members per flow. If a member fails, its flows move to the remaining members without an STP reconvergence.

The logical interface can be Layer 2 (access or trunk) or Layer 3 (routed, with an IP address).

## Negotiation options

| Method | Standard | Modes | Bundles when |
|---|---|---|---|
| LACP | IEEE 802.3ad / 802.1AX | `active`, `passive` | At least one side is `active` |
| PAgP | Cisco proprietary | `desirable`, `auto` | At least one side is `desirable` |
| Static | none | `on` | Both sides are `on` |

Result matrix (the exam loves this):

| Side A | Side B | Result |
|---|---|---|
| active | active | Bundles (LACP) |
| active | passive | Bundles (LACP) |
| passive | passive | **No channel** — nobody starts the negotiation |
| desirable | desirable / auto | Bundles (PAgP) |
| auto | auto | **No channel** |
| on | on | Bundles, no protocol |
| on | active / desirable | **No channel** — the `on` side sends no LACPDUs/PAgP |
| LACP mode | PAgP mode | **No channel** — different protocols |

> **Exam tip:** "passive" and "auto" are the listeners. Two listeners never form a channel. Prefer LACP `active` on both ends: it is standards-based, works with servers and firewalls, and detects a miscabled or misconfigured member, which `on` cannot.

> **Watch out:** `on` on one side and anything else on the other is dangerous: the `on` side treats its links as one channel while the other side sees separate links. By default the EtherChannel misconfiguration guard (`spanning-tree etherchannel guard misconfig`) detects this and err-disables the `on`-side port channel to prevent a loop.

## Layer 2 LACP configuration

```ios
SW1(config)# interface range GigabitEthernet1/0/1 - 2
SW1(config-if-range)# switchport mode trunk
SW1(config-if-range)# switchport trunk allowed vlan 10,20,30
SW1(config-if-range)# channel-group 1 mode active
Creating a port-channel interface Port-channel 1
```

The `channel-group` command creates `Port-channel1` automatically and copies the members' Layer 2 settings onto it. After it exists, make Layer 2 changes on the **port-channel interface**; IOS pushes them down to the members. `channel-protocol lacp` is optional — the mode keyword already implies the protocol.

## What must match for a port to bundle

Every member must be compatible with the port channel (and the two ends must agree on the link-level settings):

- Same **speed** and **duplex**.
- Same **switchport mode** (all access or all trunk).
- Access members: same **access VLAN**. Trunk members: same **native VLAN** and same **allowed VLAN list**.
- Same interface type: all Layer 2 switchports or all Layer 3 (`no switchport`) ports.
- Same channel-group number and compatible negotiation modes.

What does **not** need to match: port descriptions, the physical port numbers (members need not be adjacent and can be on different members of a switch stack), and STP port cost/priority.

A member whose settings differ from the bundle is **suspended**, and IOS tells you why:

```ios
%EC-5-CANNOT_BUNDLE2: Gi1/0/3 is not compatible with Po1 and will be suspended (vlan mask is different)
```

"vlan mask is different" means the allowed VLAN list differs; other reasons include speed, duplex and native VLAN.

## LACP details worth knowing

- LACP supports up to **16** ports in a group: **8 active** and up to 8 **hot-standby** (flag `H`) that take over if an active member fails. Exact limits vary by platform.
- LACP system priority and port priority default to **32768**; lower values win when deciding which ports are active and which switch makes the decision.
- LACPDUs are sent every 30 seconds by default (`lacp rate normal`); `lacp rate fast` requests 1-second LACPDUs from the partner.
- `show lacp neighbor` shows the partner's system ID, port numbers and flags — useful for proving which far-end ports are in the bundle.

```ios
SW1# show etherchannel summary

        I - stand-alone s - suspended
        H - Hot-standby (LACP only)
        R - Layer3      S - Layer2
        U - in use      f - failed to allocate aggregator

        M - not in use, minimum links not met
        u - unsuitable for bundling
        w - waiting to be aggregated
        d - default port

        A - formed by Auto LAG

Number of channel-groups in use: 2
Number of aggregators:           2

Group  Port-channel  Protocol    Ports
------+-------------+-----------+-----------------------------------------------
1      Po1(SU)         LACP        Gi1/0/1(P)  Gi1/0/2(P)  Gi1/0/3(s)
10     Po10(RU)        LACP        Gi1/0/47(P) Gi1/0/48(P)
```

| Flag | Meaning | What to do |
|---|---|---|
| `SU` (on Po) | Layer 2 port channel, in use | Healthy L2 bundle |
| `RU` (on Po) | Layer 3 port channel, in use | Healthy L3 bundle |
| `SD` / `RD` | Port channel down | No member is bundled — check modes, cabling, the far end |
| `P` | Member bundled | Healthy |
| `D` | Member physically down | Cable, optic, far-end shutdown |
| `s` | Suspended | Member config doesn't match the bundle — check the log |
| `I` | Stand-alone | No LACP/PAgP partner; port is running as an individual link |
| `H` | Hot-standby | More members than the active limit; waiting as a spare |

## Layer 3 EtherChannel

For a routed port channel, the members must be routed ports **before** they join the group. If you add switchports to a channel group, IOS builds a Layer 2 `Port-channel` and an `ip address` on it is rejected (`% IP addresses may not be configured on L2 links.`).

Member-first method:

```ios
DSW1(config)# interface range GigabitEthernet1/0/47 - 48
DSW1(config-if-range)# no switchport
DSW1(config-if-range)# channel-group 10 mode active
DSW1(config-if-range)# exit
DSW1(config)# interface Port-channel10
DSW1(config-if)# ip address 10.10.10.1 255.255.255.252
```

Alternatively, create `interface Port-channel10`, issue `no switchport` and the IP address there first, then add `no switchport` members with `channel-group 10`. Either way, the IP address lives on the **port-channel interface**, never on the members, and the summary shows `Po10(RU)`.

> **Real world:** L3 port channels between distribution and core give you link redundancy with no STP involvement and one routing adjacency instead of two.

## Load balancing

EtherChannel does not split a single flow across links; a hash of addresses (and optionally L4 ports) chooses a member per flow, which preserves packet order. The hash inputs are set globally with `port-channel load-balance` (for example `src-dst-ip` or `src-dst-mac`) and verified with `show etherchannel load-balance`. The default differs by platform, so check it. If one member is saturated while others idle, a hash on too few inputs (for example source MAC when all traffic comes from one router) is the usual cause.

## Verification checklist

```ios
show etherchannel summary          ! flags per group and member
show etherchannel port-channel     ! protocol, age, members
show lacp neighbor                 ! LACP partner details
show interfaces Port-channel1      ! aggregate bandwidth, e.g. BW 2000000 Kbit/sec
show interfaces trunk              ! Po1 should be listed, not Gi1/0/1-2
show spanning-tree vlan 10         ! STP sees Po1 as a single port
```

## Key takeaways

- LACP (`active`/`passive`) is the standard; PAgP (`desirable`/`auto`) is Cisco-only; `on` uses no protocol and only works with `on`.
- passive + passive and auto + auto never form; LACP modes never pair with PAgP modes.
- Members must match speed, duplex, switchport mode, VLAN settings and L2/L3 type; a mismatched member shows `s` (suspended).
- In `show etherchannel summary`, `SU` = healthy L2 bundle, `RU` = healthy L3 bundle, `P` = bundled member, `D` = down, `I` = stand-alone, `H` = hot-standby.
- LACP: up to 8 active members, the rest hot-standby (platform-dependent).
- For L3 EtherChannel, configure `no switchport` on the members before `channel-group`, then put the IP address on the port-channel interface.
- Load balancing is per flow, not per packet.
