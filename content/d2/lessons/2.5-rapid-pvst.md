## Why spanning tree, and why Rapid PVST+

Redundant Layer 2 links create loops, and Ethernet frames have no TTL: a broadcast loops forever, MAC tables flap and the network melts in seconds. Spanning tree builds a loop-free tree by electing a root bridge and placing redundant ports in a discarding state.

**Rapid PVST+** is Cisco's implementation of **RSTP (802.1w)** run as **one instance per VLAN**. Per-VLAN instances let you make different switches root for different VLANs and load-share uplinks. RSTP converges in about a second on point-to-point links, instead of the 30–50 seconds of classic 802.1D.

```ios
SW1(config)# spanning-tree mode rapid-pvst
SW1# show spanning-tree summary
Switch is in rapid-pvst mode
Root bridge for: VLAN0010, VLAN0020
...
Configured Pathcost method used is short
```

Current Catalyst 9000 releases run Rapid PVST+ out of the box; many older Catalysts defaulted to PVST+. Confirm with `show spanning-tree summary`.

## The bridge ID

Each switch has a **bridge ID (BID)** per VLAN: a 2-byte priority field followed by the 6-byte switch MAC.

The 2-byte priority field is split into a **4-bit priority** and a **12-bit extended system ID**, which carries the VLAN number. Because only the top 4 bits are configurable, the configurable priority must be a **multiple of 4096** (0, 4096, 8192 … 61440). Default = **32768**.

| VLAN | Configured priority | Displayed bridge priority |
|---|---|---|
| 1 | 32768 (default) | 32769 |
| 10 | 32768 (default) | 32778 |
| 10 | 24576 | 24586 |
| 30 | 32768 (default) | 32798 |

```ios
SW1(config)# spanning-tree vlan 10 priority 1000
% Bridge Priority must be in increments of 4096.
% Allowed values are:
  0     4096  8192  12288 16384 20480 24576 28672
  32768 36864 40960 45056 49152 53248 57344 61440
```

> **Exam tip:** When `show spanning-tree` says `Priority 24586`, subtract the VLAN number (10) to get the configured value (24576).

## Electing the root bridge

The switch with the **lowest bridge ID** in a VLAN is root: lowest priority wins; if priorities tie, the **lowest MAC** wins. Every switch initially claims to be root; as soon as it hears a superior BPDU it stops claiming and relays the root's information. Because it's per VLAN, one switch can be root for VLAN 10 and another for VLAN 20.

### root primary / root secondary

`spanning-tree vlan 10 root primary` is a **one-time macro**, not a persistent setting. When you enter it, the switch looks at the current root's priority:

- If the current root's priority is higher than 24576, it sets its own priority to **24576**.
- If the current root's priority is lower than 24576, it sets its own priority to **4096 less** than the current root's.

`spanning-tree vlan 10 root secondary` sets the priority to **28672** — below the 32768 default so it wins if the primary fails, but above the primary.

The macro writes an ordinary `spanning-tree vlan 10 priority <value>` line to the config. If someone later adds a switch with priority 0, nothing re-adjusts automatically — that's what root guard (next lesson) is for.

## Path cost

Each port has a cost based on speed; the **root path cost** is the sum of the costs of the ports a BPDU enters on the way from the root (the root advertises 0).

| Speed | Short method (802.1D-1998) | Long method (802.1t) |
|---|---|---|
| 10 Mbps | 100 | 2,000,000 |
| 100 Mbps | 19 | 200,000 |
| 1 Gbps | 4 | 20,000 |
| 10 Gbps | 2 | 2,000 |

The short method is the classic Cisco default and what most exam questions assume. Real switches vary: Cisco's own Catalyst 9300 IOS-XE 17.x command-reference examples show the long method (Gigabit ports at cost 20000), so check the `Pathcost method used` line in `show spanning-tree summary` before doing cost math (`spanning-tree pathcost method {short | long}` sets it, and every switch in the domain should match). Port cost can be overridden per VLAN: `spanning-tree vlan 10 cost 10`.

## Port roles

Once the root is known, every port gets a role per VLAN:

| Role | Where | State | Description |
|---|---|---|---|
| **Root port** | Every non-root switch, exactly one per VLAN | Forwarding | Lowest root path cost toward the root |
| **Designated port** | One per segment | Forwarding | The port that offers the best path to root for that segment; **all ports on the root bridge are designated** |
| **Alternate port** | Non-root switches | Discarding | Receives a better BPDU from **another switch** than it would send: a ready backup path to the root |
| **Backup port** | Rare (shared media) | Discarding | Receives a better BPDU from **its own switch** (two ports on the same hub/segment): backs up a designated port |
| Disabled | — | — | Shut down or no link |

### Choosing the root port (tie-breakers in order)

1. Lowest **root path cost**.
2. Lowest **sender bridge ID** (the neighbor that sent the BPDU).
3. Lowest **sender port ID** — port priority (default 128, multiples of 16), then port number, **of the neighbor's port**.

> **Watch out:** With two parallel equal-cost links to the same upstream switch, the tie is broken by the **upstream** switch's port priority/number, not your own. If SW2 Gi1/0/23 connects to the root's Gi1/0/5 and SW2 Gi1/0/24 connects to the root's Gi1/0/4, SW2 chooses **Gi1/0/24** as root port. To influence this from the upstream side, change port priority there (`spanning-tree vlan 10 port-priority 64`).

### Designated port per segment

On each link, the switch advertising the lowest root path cost has the designated port; ties go to the lower sender bridge ID, then the lower port ID. The other end is either the root port (if that's its best path) or an alternate port.

## RSTP port states

| RSTP state | Learns MACs? | Forwards? | Old 802.1D equivalents |
|---|---|---|---|
| **Discarding** | No | No | Disabled, blocking, listening |
| **Learning** | Yes | No | Learning |
| **Forwarding** | Yes | Yes | Forwarding |

Cisco's `show spanning-tree` still prints a discarding port as `BLK`, alongside `LRN` and `FWD`.

### Why RSTP is fast

- **Alternate port → root port**: if the root port fails, the alternate becomes root port and forwards immediately — no timers.
- **Proposal/agreement handshake** on point-to-point links: a designated port proposes, the downstream switch syncs (blocks its other non-edge designated ports) and agrees, and the link forwards in well under a second instead of waiting 2 × forward delay.
- **Edge ports** (PortFast) go straight to forwarding.
- BPDUs are sent by every switch every **2 s** (hello); information is aged out after missing **3 hellos** (6 s) rather than 20 s max age.

Link type matters: full-duplex ports are `P2p` (rapid handshake allowed); half-duplex ports are `Shr` (shared) and fall back to slower behavior.

## Reading show spanning-tree

```ios
SW3# show spanning-tree vlan 10

VLAN0010
  Spanning tree enabled protocol rstp
  Root ID    Priority    24586
             Address     a0b4.3c11.0a00
             Cost        4
             Port        1 (GigabitEthernet1/0/1)
             Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec

  Bridge ID  Priority    32778  (priority 32768 sys-id-ext 10)
             Address     a0b4.3c33.0c00
             Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
             Aging Time  300 sec

Interface           Role Sts Cost      Prio.Nbr Type
------------------- ---- --- --------- -------- --------------------------------
Gi1/0/1             Root FWD 4         128.1    P2p
Gi1/0/2             Altn BLK 4         128.2    P2p
Gi1/0/10            Desg FWD 4         128.10   P2p Edge
```

How to read it:

- `protocol rstp` → Rapid PVST+ is running for this VLAN.
- **Root ID** is the root bridge (priority 24576 + VLAN 10). **Bridge ID** is this switch. Different addresses → SW3 is not root. On the root itself you'd see `This bridge is the root` and no root port.
- `Cost 4` = SW3's root path cost; `Port 1 (GigabitEthernet1/0/1)` = its root port.
- Gi1/0/2 is an **alternate** port, discarding (shown `BLK`).
- Gi1/0/10 is a designated **edge** (PortFast) port toward a host.
- `Prio.Nbr 128.1` = port priority 128, port number 1.

## Load-sharing across VLANs

```ios
DSW1(config)# spanning-tree vlan 10,30 root primary
DSW1(config)# spanning-tree vlan 20,40 root secondary
DSW2(config)# spanning-tree vlan 20,40 root primary
DSW2(config)# spanning-tree vlan 10,30 root secondary
```

Odd VLANs use one uplink, even VLANs the other; each switch backs up the other. Align the STP root with the FHRP (HSRP/VRRP) active gateway for each VLAN so traffic doesn't take an extra hop.

## Key takeaways

- Rapid PVST+ = RSTP per VLAN; enable with `spanning-tree mode rapid-pvst`.
- Displayed priority = configured priority (multiple of 4096, default 32768) + VLAN ID.
- Lowest BID wins root: lowest priority, then lowest MAC.
- `root primary` sets 24576, or 4096 below a lower existing root; `root secondary` sets 28672. Both are one-time macros.
- Root port: lowest root path cost → lowest sender BID → lowest sender port ID (the neighbor's port).
- Roles: root, designated, alternate, backup, disabled. States: discarding, learning, forwarding (discarding displays as `BLK`).
- Short-method costs: 100 Mbps 19, 1 Gbps 4, 10 Gbps 2 — verify the path cost method in use.
