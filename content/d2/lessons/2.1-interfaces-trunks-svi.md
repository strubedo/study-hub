## Layer 2 and Layer 3 physical interfaces

Every front-panel port on a Catalyst 9000 switch starts life as a **switchport** (Layer 2). A switchport belongs to one VLAN (access) or carries many VLANs (trunk), learns MAC addresses and runs spanning tree. You cannot put an IP address on it.

A **routed port** is a physical interface that behaves like a router interface: it has its own IP address, belongs to no VLAN, does not run STP, does not learn MACs into the VLAN MAC table and does not speak DTP. You create one with `no switchport`.

```ios
DSW1(config)# interface GigabitEthernet1/0/48
DSW1(config-if)# description P2P to R1 Gi0/0/1
DSW1(config-if)# no switchport
DSW1(config-if)# ip address 10.0.0.1 255.255.255.252
DSW1(config-if)# no shutdown
```

`switchport` (without `no`) turns it back into a Layer 2 port and removes the IP configuration. Typical uses for routed ports: point-to-point links between a distribution/core switch and a router or firewall, and routed access/core designs where you want no spanning tree across the link.

| Feature | Switchport (L2) | Routed port (L3) | SVI (L3, virtual) |
|---|---|---|---|
| Created with | default | `no switchport` | `interface vlan N` |
| IP address | No | Yes | Yes |
| VLAN membership | Access or trunk | None | Represents one VLAN |
| Runs STP | Yes | No | No (its VLAN does) |
| Typical use | Hosts, inter-switch trunks | P2P uplink to router/L3 switch | Default gateway for a VLAN |

> **Exam tip:** On a Catalyst switch, the fix for "I can't put an IP address on this port" is `no switchport`. On a router the interface is already Layer 3, and there is no `switchport` command at all on a normal routed interface.

## 802.1Q trunks

A trunk carries frames for multiple VLANs over one link. IEEE 802.1Q inserts a 4-byte tag after the source MAC: TPID 0x8100, then 3 bits of priority (CoS), 1 DEI bit and a **12-bit VLAN ID** (1–4094 usable). The FCS is recalculated.

Frames in the **native VLAN** are sent **untagged**, and untagged frames received on a trunk are placed in the native VLAN. The default native VLAN is 1.

```ios
SW1(config)# interface GigabitEthernet1/0/1
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk native vlan 99
SW1(config-if)# switchport trunk allowed vlan 10,20,99
```

### The encapsulation command (platform caveat)

Older Catalysts that also support Cisco's legacy ISL (for example 3560 and 3750) default to `switchport trunk encapsulation negotiate` and refuse a static trunk until you pick 802.1Q:

```ios
SW3(config-if)# switchport mode trunk
Command rejected: An interface whose trunk encapsulation is "Auto" can not be configured to "trunk" mode.
SW3(config-if)# switchport trunk encapsulation dot1q
SW3(config-if)# switchport mode trunk
```

Catalyst 9000 switches (and 2960-family) only do 802.1Q, so the encapsulation step is not needed there; depending on platform and release the command is either absent or only accepts `dot1q`.

### Native VLAN mismatch

If one end uses native VLAN 1 and the other uses 99, untagged frames sent from VLAN 1 on one switch arrive in VLAN 99 on the other. CDP (which carries the native VLAN in its advertisements) reports it:

```ios
%CDP-4-NATIVE_VLAN_MISMATCH: Native VLAN mismatch discovered on GigabitEthernet1/0/24 (1), with SW2 GigabitEthernet1/0/24 (99).
```

The first interface/VLAN pair is local, the second is the neighbor's. The trunk still comes up, but Rapid PVST+ also detects the mismatch (PVST+ BPDUs carry the sending VLAN) and blocks the port for the affected VLANs as **PVID-inconsistent**. The fix is to configure the same native VLAN on both ends.

> **Real world:** Use an unused, dedicated native VLAN (not VLAN 1) on trunks and don't put hosts in it. It limits the double-tagging VLAN-hopping trick and keeps untagged control traffic separate.

### The allowed VLAN list

By default a trunk allows VLANs 1–4094. The list is edited with keywords:

| Command | Effect |
|---|---|
| `switchport trunk allowed vlan 10,20` | **Replaces** the list with exactly 10 and 20 |
| `switchport trunk allowed vlan add 30` | Appends 30 |
| `switchport trunk allowed vlan remove 20` | Removes 20 |
| `switchport trunk allowed vlan except 99` | Everything except 99 |
| `switchport trunk allowed vlan all` / `none` | All / no VLANs |

> **Watch out:** Typing `switchport trunk allowed vlan 30` when you meant `add 30` silently removes every other VLAN from the trunk. This is one of the most common real outages caused by a one-word mistake.

## DTP (Dynamic Trunking Protocol)

DTP is Cisco-proprietary negotiation of trunking. On Catalyst 9000 the default administrative mode is **dynamic auto**.

| Local \ Remote | access | dynamic auto | dynamic desirable | trunk |
|---|---|---|---|---|
| **access** | Access | Access | Access | Mismatch |
| **dynamic auto** | Access | Access | Trunk | Trunk |
| **dynamic desirable** | Access | Trunk | Trunk | Trunk |
| **trunk** | Mismatch | Trunk | Trunk | Trunk |

Two switches with default ports (auto/auto) therefore form an **access** link in VLAN 1, not a trunk.

`switchport nonegotiate` stops the port from sending DTP frames. It is accepted only with `switchport mode access` or `switchport mode trunk` (not on a dynamic port). A `trunk` + `nonegotiate` port will only form a working trunk with a far end that is also statically trunking; an `auto` or `desirable` neighbor hears no DTP and stays an access port.

> **Exam tip:** Best practice: hard-code `switchport mode trunk` (plus `switchport nonegotiate`) on inter-switch links and `switchport mode access` on host ports, so an attacker cannot negotiate a trunk.

### Reading show interfaces trunk

```ios
SW1# show interfaces trunk

Port        Mode             Encapsulation  Status        Native vlan
Gi1/0/1     on               802.1q         trunking      99

Port        Vlans allowed on trunk
Gi1/0/1     10,20,99

Port        Vlans allowed and active in management domain
Gi1/0/1     10,20,99

Port        Vlans in spanning tree forwarding state and not pruned
Gi1/0/1     10,20
```

- **Mode** `on` = static trunk; `desirable`/`auto` = negotiated via DTP.
- **Allowed on trunk** = the configured allowed list.
- **Allowed and active** = allowed VLANs that also exist on this switch. A VLAN missing here usually was never created.
- **Forwarding and not pruned** = what actually forwards. A VLAN missing here (and present above) is STP-blocked on this port or VTP-pruned. Here VLAN 99 is blocked — a native VLAN mismatch or a normal STP alternate port are both possibilities to check with `show spanning-tree vlan 99`.

Access ports never appear in `show interfaces trunk`; trunk ports never appear in `show vlan brief`.

## SVIs and inter-VLAN routing on a Layer 3 switch

A **switch virtual interface** (`interface vlan 10`) is the switch's Layer 3 presence in a VLAN — usually the hosts' default gateway.

```ios
DSW1(config)# ip routing
DSW1(config)# vlan 10
DSW1(config-vlan)# name USERS
DSW1(config)# interface vlan 10
DSW1(config-if)# ip address 10.1.10.1 255.255.255.0
DSW1(config-if)# no shutdown
```

### When is an SVI up/up?

With the default **autostate** behavior, the SVI's line protocol is up only when **all** of these are true:

1. The VLAN exists and is active in the VLAN database (`show vlan brief`).
2. The SVI is not administratively shut down.
3. At least one Layer 2 port (access port in that VLAN, or a trunk allowing it) is **up and in the STP forwarding state for that VLAN**.

An IP address is **not** required for up/up, and `ip routing` does not affect SVI state. If the VLAN was never created, or every port in it is down or blocking, the SVI shows `up/down`. (`switchport autostate exclude` on a port, such as a monitoring port, removes it from this calculation.)

### ip routing

Without `ip routing` the switch acts as a host on each SVI: hosts can ping their own gateway SVI, but nothing is routed between VLANs. A quick tell is `show ip route`, which on a non-routing switch prints `Default gateway is ...` and an ICMP redirect cache instead of a routing table. Whether IP routing is on by default depends on the Catalyst model and software release, so always verify; on a router it is enabled by default.

## Router-on-a-stick

When the router does the inter-VLAN routing, one physical router interface connects to a switch trunk and is split into **subinterfaces**, one per VLAN:

```ios
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# no shutdown
R1(config-if)# interface GigabitEthernet0/0/1.10
R1(config-subif)# encapsulation dot1Q 10
R1(config-subif)# ip address 192.168.10.1 255.255.255.0
R1(config-subif)# interface GigabitEthernet0/0/1.20
R1(config-subif)# encapsulation dot1Q 20
R1(config-subif)# ip address 192.168.20.1 255.255.255.0
R1(config-subif)# interface GigabitEthernet0/0/1.99
R1(config-subif)# encapsulation dot1Q 99 native
R1(config-subif)# ip address 192.168.99.1 255.255.255.0
```

Key points:

- `encapsulation dot1Q <vlan>` must come **before** `ip address` on a subinterface. The subinterface number (`.10`) is just a label; the VLAN comes from the encapsulation command.
- The native VLAN is handled with `encapsulation dot1Q <vlan> native` (or an IP address on the physical interface itself).
- Subinterfaces inherit the physical interface's state: if `GigabitEthernet0/0/1` is shut down, every subinterface is down.
- The switch port facing the router must be a trunk allowing those VLANs, with a matching native VLAN. Routers do not run DTP, so use `switchport mode trunk`.

> **Watch out:** Router-on-a-stick pushes all inter-VLAN traffic up and back down one link. It is fine for a branch; a Layer 3 switch with SVIs scales far better.

## Key takeaways

- `no switchport` makes a Catalyst port a routed port; only then can it take an IP address.
- 802.1Q tags everything except the native VLAN; native VLANs must match on both ends, and CDP logs `NATIVE_VLAN_MISMATCH` when they don't.
- `switchport trunk allowed vlan X` replaces the list; use `add`/`remove` to edit it.
- Catalyst 9000 default is `dynamic auto`; auto + auto = access. Use static `trunk`/`access` plus `nonegotiate` in production.
- `switchport trunk encapsulation dot1q` is needed only on ISL-capable platforms.
- An SVI is up/up only if its VLAN exists, the SVI is not shut, and at least one port in the VLAN is up and STP-forwarding.
- `ip routing` is required for a multilayer switch to route between SVIs.
- Router-on-a-stick: `encapsulation dot1Q N` per subinterface, `native` keyword for the native VLAN, and the parent interface must be `no shutdown`.
