## Why neighbor discovery matters

Diagrams drift. Someone moves a cable during an outage, a switch gets replaced, a port is re-patched — and the drawing is never updated. **CDP** and **LLDP** let every device tell its directly connected neighbors who it is and which port it is sending from. Reading that data on each device lets you rebuild or validate the physical topology without walking to the closet.

Both are Layer 2 protocols: they need no IP configuration, they work on access, trunk and routed ports, and they only ever describe **directly connected** neighbors (one hop).

## CDP vs LLDP

| | CDP | LLDP |
|---|---|---|
| Standard | Cisco proprietary | IEEE **802.1AB** (vendor-neutral) |
| Default on Cisco IOS / IOS-XE | **Enabled** globally and on most interfaces | **Disabled** globally |
| Advertisement timer | **60 s** | **30 s** |
| Holdtime (TTL) | **180 s** | **120 s** |
| Destination MAC | 0100.0ccc.cccc | 0180.c200.000e |
| Global enable | `cdp run` | `lldp run` |
| Interface control | `cdp enable` / `no cdp enable` | `lldp transmit`, `lldp receive` (both on by default once `lldp run` is set) |
| Timers | `cdp timer`, `cdp holdtime` | `lldp timer`, `lldp holdtime`, `lldp reinit` (2 s default) |
| Phone extension | CDP carries voice VLAN for Cisco phones | **LLDP-MED** carries voice VLAN/network policy |

```ios
SW1(config)# lldp run                     ! enable LLDP globally
SW1(config)# interface GigabitEthernet1/0/1
SW1(config-if)# no lldp transmit          ! still listens, stops sending
SW1(config-if)# exit
SW1(config)# interface GigabitEthernet1/0/48
SW1(config-if)# no cdp enable             ! CDP off on this port only
SW1(config-if)# exit
SW1(config)# no cdp run                   ! CDP off on the whole device
```

LLDP's transmit and receive are independent: a port with `no lldp transmit` still learns its neighbor, but the neighbor never learns about it. That one-sided view is a classic exam scenario.

> **Exam tip:** "Neighbor sees me but I don't see the neighbor" (or the reverse) points to a one-way setting: `no lldp transmit` / `no lldp receive` on one side, or LLDP disabled globally on one device.

> **Real world:** Disable CDP/LLDP on ports facing the internet, ISPs or untrusted users (`no cdp enable`, `no lldp transmit`). The advertisements reveal hostname, software version, platform and management IP — free reconnaissance for an attacker. Keep them on inside the infrastructure and toward phones that need them.

## Reading show cdp neighbors

```ios
SW1# show cdp neighbors
Capability Codes: R - Router, T - Trans Bridge, B - Source Route Bridge
                  S - Switch, H - Host, I - IGMP, r - Repeater, P - Phone,
                  D - Remote, C - CVTA, M - Two-port Mac Relay

Device ID        Local Intrfce     Holdtme    Capability  Platform  Port ID
SW2.lab.local    Gig 1/0/1         152             R S I  C9300-48P Gig 1/0/24
R1               Gig 1/0/48        167              R B   ISR4331/K Gig 0/0/1
```

| Column | Meaning |
|---|---|
| Device ID | The neighbor's hostname (with domain name if one is configured) |
| **Local Intrfce** | **This** device's port the advertisement arrived on |
| Holdtme | Seconds left before the entry expires; resets to 180 each time an advertisement arrives |
| Capability | Neighbor's roles: `R S I` is typical of a Layer 3 switch with routing on; `R B` is a router |
| Platform | Neighbor's hardware model (often truncated) |
| **Port ID** | The **neighbor's** port that sent the advertisement |

So the first line says: **SW1 Gi1/0/1 connects to SW2 Gi1/0/24**. Not SW1 Gi1/0/24.

> **Watch out:** The number-one CDP/LLDP trap is swapping columns. "Local" is always the device you typed the command on; "Port ID" is always the far end.

### show cdp neighbors detail

The detail form (and `show cdp entry <name>`) adds the neighbor's **management/interface IP address**, full software version string, native VLAN, duplex and VTP domain:

```ios
SW1# show cdp neighbors GigabitEthernet1/0/48 detail
-------------------------
Device ID: R1
Entry address(es):
  IP address: 10.0.0.2
Platform: cisco ISR4331/K9,  Capabilities: Router Source-Route-Bridge
Interface: GigabitEthernet1/0/48,  Port ID (outgoing port): GigabitEthernet0/0/1
Holdtime : 151 sec

Version :
Cisco IOS XE Software, Version 17.09.04a
...
advertisement version: 2
Duplex: full
```

`Interface:` is local, `Port ID (outgoing port):` is the neighbor's. This is how you find the IP of an unknown neighbor to SSH to it.

## Reading show lldp neighbors

```ios
SW1# show lldp neighbors
Capability codes:
    (R) Router, (B) Bridge, (T) Telephone, (C) DOCSIS Cable Device
    (W) WLAN Access Point, (P) Repeater, (S) Station, (O) Other

Device ID           Local Intf     Hold-time  Capability      Port ID
AP-Lobby            Gi1/0/10       120        B,W,R           Gi0
SW2.lab.local       Gi1/0/1        120        B,R             Gi1/0/24
linux-host01        Gi1/0/12       120        S               a4bb.6d11.2233

Total entries displayed: 3
```

Same logic: `Local Intf` is ours, `Port ID` is theirs. The LLDP Port ID is whatever the neighbor chooses to send — an interface name, a description or a MAC address (common for Linux hosts running `lldpd`). `show lldp neighbors detail` adds the system description, management address and, for phones, LLDP-MED information.

Capabilities differ from CDP: `B` (Bridge) means switch, `W` access point, `T` telephone, `S` station (end host).

## Validating a diagram, step by step

1. **Collect** `show cdp neighbors` (and/or `show lldp neighbors`) on every infrastructure device.
2. **Write each line as a link**: *local device, Local Intrfce* ↔ *Device ID, Port ID*.
3. **Cross-check from the other end.** The neighbor's own output should show the reverse link. If SW1 says Gi1/0/1 ↔ SW2 Gi1/0/24, SW2 should list SW1 on Gi1/0/24 with Port ID Gi1/0/1.
4. **Compare** each link to the diagram: device names, both port numbers, and the platform/model.
5. **Investigate anomalies**:
   - A port the diagram says is connected, with no neighbor: link down, protocol disabled on one end, or the far end doesn't run CDP/LLDP (most hosts don't run CDP).
   - **Two or more neighbors on one local port**: an unmanaged switch or hub sits between them. Unmanaged devices flood CDP/LLDP multicasts instead of consuming them, so you see "through" them. (LLDP's standard nearest-bridge address is designed to be consumed by 802.1D bridges, but cheap unmanaged switches commonly pass it anyway.)
   - Holdtime counting toward zero and never resetting: the neighbor stopped sending (disabled, or a unidirectional link).

> **Exam tip:** v2.0 says "validate the accuracy of network documentation". Expect an exhibit with a diagram's link list plus CDP/LLDP output, and a question asking which documented link is wrong — and by how much (local side, remote side, or wrong device).

## Mixing CDP and LLDP

Run both if you have non-Cisco gear: CDP for Cisco-to-Cisco (more detail, native VLAN mismatch warnings), LLDP for everything else (third-party switches, servers, phones using LLDP-MED). They operate independently; enabling LLDP does not disable CDP.

## Key takeaways

- CDP: Cisco proprietary, on by default, 60 s timer / 180 s holdtime. LLDP: IEEE 802.1AB, off by default on Cisco (`lldp run`), 30 s / 120 s.
- Both are Layer 2, one hop only, and need no IP addressing.
- `Local Intrfce` / `Local Intf` is your port; `Port ID` is the neighbor's port — never swap them.
- `show cdp neighbors detail` gives the neighbor's IP address, software version and native VLAN.
- `no cdp enable` disables CDP on one interface; `no cdp run` disables it globally. LLDP uses `lldp transmit`/`lldp receive` per interface.
- Several neighbors on one local port means an unmanaged switch or hub in between.
- Validate a diagram by turning each neighbor line into a link and checking it from both ends.
