## What the routing table actually is

Every IOS router keeps a **Routing Information Base (RIB)**: the best route it knows for every destination prefix, whatever the source (connected interfaces, static configuration, OSPF, EIGRP, BGP and so on). CEF builds its forwarding table (FIB) from the RIB, so what you see in `show ip route` is what the router will forward with.

Topic 3.1 tests one skill above all: **look at a routing table and say where a given packet goes, and why**. Two different decisions are involved, and mixing them up is the number one exam trap:

| Decision | When it happens | What is compared |
|---|---|---|
| **Route installation** | When the RIB is built | Routes to the *exact same prefix and length* from different sources: lowest **administrative distance** wins; within one protocol, lowest **metric** wins |
| **Packet forwarding** | For every packet | All installed routes that *contain* the destination: the **longest prefix match** wins, no matter which protocol or AD |

AD and metric never compare a /16 against a /24. They only break ties between candidates for the *same* prefix. Once routes are in the table, the most specific match always wins.

## Reading a `show ip route` line

```ios
R1# show ip route
Codes: L - local, C - connected, S - static, R - RIP, M - mobile, B - BGP
       D - EIGRP, EX - EIGRP external, O - OSPF, IA - OSPF inter area
       N1 - OSPF NSSA external type 1, N2 - OSPF NSSA external type 2
       E1 - OSPF external type 1, E2 - OSPF external type 2
       i - IS-IS, * - candidate default
       (legend shortened)

Gateway of last resort is 203.0.113.1 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 203.0.113.1
      10.0.0.0/8 is variably subnetted, 7 subnets, 3 masks
C        10.0.12.0/24 is directly connected, GigabitEthernet0/0/1
L        10.0.12.1/32 is directly connected, GigabitEthernet0/0/1
C        10.0.13.0/24 is directly connected, GigabitEthernet0/0/2
L        10.0.13.1/32 is directly connected, GigabitEthernet0/0/2
O        10.20.0.0/16 [110/3] via 10.0.12.2, 00:14:05, GigabitEthernet0/0/1
O        10.20.5.0/24 [110/2] via 10.0.13.3, 00:14:05, GigabitEthernet0/0/2
O E2     10.99.0.0/16 [110/20] via 10.0.12.2, 00:14:05, GigabitEthernet0/0/1
      203.0.113.0/24 is variably subnetted, 2 subnets, 2 masks
C        203.0.113.0/30 is directly connected, GigabitEthernet0/0/0
L        203.0.113.2/32 is directly connected, GigabitEthernet0/0/0
```

Take `O 10.20.0.0/16 [110/3] via 10.0.12.2, 00:14:05, GigabitEthernet0/0/1` apart:

| Field | Meaning |
|---|---|
| `O` | Source: OSPF intra-area route |
| `10.20.0.0/16` | Destination prefix and length |
| `[110/3]` | `[administrative distance / metric]` |
| `via 10.0.12.2` | Next-hop IP address |
| `00:14:05` | Age: time since the route was learned or last changed |
| `GigabitEthernet0/0/1` | Outgoing interface |

The indented headers (`10.0.0.0/8 is variably subnetted, 7 subnets, 3 masks`) are just grouping lines under the classful network. They are not routes. "Is subnetted" means all child routes share one mask; "variably subnetted" means more than one mask is present.

### Route source codes you must know

| Code | Meaning |
|---|---|
| `C` | Connected: the subnet of an up/up interface |
| `L` | Local: the router's own interface address as a /32 (IPv4) or /128 (IPv6) |
| `S` | Static route |
| `S*` | Static route that is also the candidate default |
| `O` | OSPF intra-area (same area) |
| `O IA` | OSPF inter-area (learned from another area through an ABR) |
| `O E1` / `O E2` | OSPF external type 1 / type 2 (redistributed into OSPF) |
| `O*E2` | OSPF external default route, typically from `default-information originate` |
| `D` | EIGRP internal; `D EX` is EIGRP external |
| `R` | RIP |
| `B` | BGP |
| `*` | Candidate default route |

Connected and local routes show no `[AD/metric]` brackets. Their AD is 0.

> **Exam tip:** For an `O E2` route the metric shown is the external (seed) cost assigned at the redistribution point; the default is 20 for most sources and 1 for routes redistributed from BGP. It does **not** grow as the route crosses the OSPF domain. `O E1` metrics do add internal cost. A default from `default-information originate` appears as `O*E2 0.0.0.0/0 [110/1]`.

## Administrative distance

AD is a router-local trust ranking of route sources. Lower is more trusted.

| Route source | Default AD |
|---|---|
| Connected | 0 |
| Static | 1 |
| eBGP | 20 |
| EIGRP (internal) | 90 |
| OSPF | 110 |
| IS-IS | 115 |
| RIP | 120 |
| EIGRP (external) | 170 |
| iBGP | 200 |
| Unusable (never installed) | 255 |

A static route configured with only an exit interface still has **AD 1**, not 0, even though `show ip route` describes it as "directly connected".

> **Watch out:** If OSPF and EIGRP both offer `10.5.0.0/16`, the EIGRP route (90) goes in the table and OSPF's copy stays in the OSPF database only. If OSPF offers `10.5.1.0/24` and EIGRP offers `10.5.0.0/16`, **both** are installed (different prefixes), and a packet to 10.5.1.9 uses the OSPF /24.

## Metric and equal-cost paths

Inside one protocol, the route with the lowest metric is installed. If two paths tie, the router installs both (OSPF installs up to 4 equal-cost paths by default, tunable with `maximum-paths`). The table then shows one prefix with two next hops:

```ios
O        10.50.0.0/16 [110/3] via 10.0.12.2, 00:02:11, GigabitEthernet0/0/1
                      [110/3] via 10.0.13.3, 00:02:11, GigabitEthernet0/0/2
```

CEF load-shares across them, by default per destination flow (source/destination hash), not per packet.

## Longest prefix match, step by step

To find the next hop for a destination:

1. List every route whose prefix contains the destination (convert the deciding octet to binary if needed).
2. Pick the one with the **longest** prefix length.
3. If none match and a default route exists, use the default (`0.0.0.0/0` matches everything with length 0).
4. If nothing matches and there is no default, drop the packet and send ICMP unreachable.

Worked example with the table above:

| Destination | Matching routes | Winner | Next hop |
|---|---|---|---|
| 10.20.5.77 | /0, /16, /24 | `10.20.5.0/24` | 10.0.13.3 |
| 10.20.6.1 | /0, /16 | `10.20.0.0/16` | 10.0.12.2 |
| 10.21.0.1 | /0 only | default | 203.0.113.1 |
| 10.0.13.50 | /0, /24 connected | `10.0.13.0/24` | deliver directly on Gi0/0/2 (ARP for 10.0.13.50) |

Notice the /24 wins for 10.20.5.77 even though its metric (2) is unrelated to the /16's metric (3). Metric did not matter, prefix length did.

> **Exam tip:** Let the router do the lookup for you in a lab: `show ip route 10.20.5.77` prints the single entry it would use, including "Known via", distance, metric and next hop. On the exam, do the binary math on the octet where the prefix boundary falls; for a /20, the third octet moves in blocks of 16.

## Gateway of last resort and default routes

The line `Gateway of last resort is 203.0.113.1 to network 0.0.0.0` tells you a default route is installed and where it points. `Gateway of last resort is not set` means no default exists, so any destination without a specific match is dropped.

Default routes reach the table in several ways:

- `S* 0.0.0.0/0 [1/0]` from `ip route 0.0.0.0 0.0.0.0 <next-hop>`.
- `O*E2 0.0.0.0/0 [110/1]` from a neighbor running `default-information originate`.
- `S* 0.0.0.0/0 [254/0]` installed by DHCP when an interface uses `ip address dhcp`.

The `*` marks the route as the candidate default.

## Recursive lookups

A static or BGP route whose next hop is not on a connected subnet requires a second lookup: the router finds a route to the next-hop address, and uses that route's outgoing interface. If the next hop cannot be resolved, the route is **not installed**. Recursion is invisible in `show ip route` unless the route is missing, which is your clue.

## Reading `show ipv6 route`

IPv6 uses the same logic (AD, metric, longest match) with a different layout: each route takes two lines.

```ios
R1# show ipv6 route
IPv6 Routing Table - default - 7 entries
Codes: C - Connected, L - Local, S - Static, O - OSPF Intra, OI - OSPF Inter,
       OE1 - OSPF ext 1, OE2 - OSPF ext 2 (legend shortened)
S   ::/0 [1/0]
     via 2001:DB8:FFFF::1
C   2001:DB8:0:12::/64 [0/0]
     via GigabitEthernet0/0/1, directly connected
L   2001:DB8:0:12::1/128 [0/0]
     via GigabitEthernet0/0/1, receive
O   2001:DB8:20::/48 [110/2]
     via FE80::2, GigabitEthernet0/0/1
C   2001:DB8:FFFF::/64 [0/0]
     via GigabitEthernet0/0/0, directly connected
L   2001:DB8:FFFF::2/128 [0/0]
     via GigabitEthernet0/0/0, receive
L   FF00::/8 [0/0]
     via Null0, receive
```

Things that differ from IPv4:

- Connected and local routes do show `[0/0]`.
- Local routes are /128. `FF00::/8 via Null0, receive` is the multicast range entry that IOS always installs; it is counted in "7 entries".
- Routes learned from OSPFv3 (and most IGPs) use the neighbor's **link-local** address (`FE80::2`) as the next hop, always paired with the outgoing interface because link-local addresses are only unique per link.
- OSPF codes are written without spaces: `OI`, `OE2`.

> **Real world:** On busy routers, filter instead of scrolling: `show ip route ospf`, `show ip route static`, `show ip route | include 10.20`, or `show ip route 10.20.0.0 255.255.0.0 longer-prefixes` to see everything inside a block.

## Key takeaways

- Forwarding always uses the **longest prefix match** first. AD and metric only choose among routes to the identical prefix when the table is built.
- Know the default ADs cold: connected 0, static 1, eBGP 20, EIGRP 90, OSPF 110, IS-IS 115, RIP 120, external EIGRP 170, iBGP 200.
- `[x/y]` is `[AD/metric]`. `C` and `L` routes have AD 0; an exit-interface static route still has AD 1.
- `O E2` metrics stay at the redistribution seed value; `O*E2 0.0.0.0/0 [110/1]` is the classic OSPF-originated default.
- "Gateway of last resort is not set" plus no specific match means the packet is dropped.
- Equal-cost routes appear as one prefix with multiple `via` lines and are load-shared.
- IPv6 tables use the same rules; IGP next hops are link-local addresses plus an exit interface.
