## OSPF in one paragraph

OSPF (Open Shortest Path First) is a **link-state** interior gateway protocol. Each router describes its own links in **link-state advertisements (LSAs)**, floods them to every router in the area, and stores all of them in an identical **link-state database (LSDB)**. Each router then runs Dijkstra's **SPF algorithm** on that database to build a shortest-path tree with itself at the root, and installs the best routes with AD 110 and a metric called **cost**. OSPFv2 carries IPv4 and runs directly over IP (protocol 89); OSPFv3 carries IPv6. The CCNA covers a **single area**, normally the backbone, area 0.

## OSPF packets and addresses

| Packet type | Purpose |
|---|---|
| 1. Hello | Discover neighbors, verify parameters, elect DR/BDR, act as keepalive |
| 2. Database Description (DBD/DD) | Summary list of the LSAs a router holds |
| 3. Link-State Request (LSR) | Ask for LSAs the router is missing or has older copies of |
| 4. Link-State Update (LSU) | Carries the full LSAs |
| 5. Link-State Acknowledgment (LSAck) | Confirms receipt of LSUs |

| Address | OSPFv2 | OSPFv3 |
|---|---|---|
| All OSPF routers | 224.0.0.5 | FF02::5 |
| DR and BDR only | 224.0.0.6 | FF02::6 |

Default timers on broadcast and point-to-point networks: **hello 10 seconds, dead 40 seconds** (dead is four times hello by default). Non-broadcast (NBMA) networks default to 30/120.

## The router ID

Every OSPF router is identified by a 32-bit **router ID (RID)** written in dotted-decimal. It names the router in the LSDB and in neighbor tables, so it must be unique within the OSPF domain. IOS picks it in this order when the process starts:

1. The `router-id` command under the OSPF process.
2. Otherwise, the **highest IPv4 address on an up loopback interface**.
3. Otherwise, the **highest IPv4 address on any other up interface**.

The interface used for the RID does not need to run OSPF. Once chosen, the RID does **not** change just because a better address appears later; it changes after a reload or `clear ip ospf process` (which resets every adjacency on the router).

> **Exam tip:** A loopback address beats a physical address even if the physical address is numerically higher. `router-id` beats both. Duplicate router IDs prevent adjacencies between the two routers and cause LSDB corruption elsewhere, and IOS logs a duplicate-RID message.

OSPFv3 also uses a **32-bit dotted-decimal RID**, chosen by the same rules from IPv4 addresses. On an IPv6-only router there is no IPv4 address to borrow, so the OSPFv3 process cannot start until you configure `router-id` manually.

## Neighbor states

Two routers progress through these states to become fully adjacent:

| State | What has happened |
|---|---|
| **Down** | No Hello received from the neighbor within the dead interval (or it was just configured) |
| **Init** | A Hello was received, but it did not list *this* router's RID yet. One-way communication |
| **2-Way** | Each router sees its own RID in the other's Hello. Bidirectional communication. DR/BDR election happens here on broadcast networks |
| **ExStart** | The two routers decide master/slave for the database exchange (higher RID becomes master) and agree on the starting DBD sequence number |
| **Exchange** | DBD packets describing each LSDB are exchanged |
| **Loading** | LSRs are sent for missing LSAs; LSUs carry them back |
| **Full** | LSDBs are synchronized. The adjacency is complete |

(A state called **Attempt** exists only on NBMA networks with manually configured neighbors.)

"Neighbor" and "adjacency" are not the same thing. Routers that reach 2-Way are neighbors; only routers that reach Full are **adjacent** and exchange LSAs directly.

> **Watch out:** **Stuck in Init** usually means hellos only flow one way (an ACL, or a unicast/multicast problem). **Stuck in ExStart/Exchange** is the textbook symptom of an **IP MTU mismatch**: hellos match, but a DBD larger than the neighbor's MTU is discarded. **Never reaching 2-Way, or no neighbor at all**, points to a Hello parameter mismatch.

## What must match to become neighbors

OSPF checks fields in every Hello. If any of these disagree, the Hello is ignored and no neighbor appears:

| Must match | Notes |
|---|---|
| **Area ID** | Both interfaces must be in the same area |
| **Subnet and mask** | Both interfaces on the same subnet with the same mask on broadcast networks. (IOS skips the mask check on point-to-point network types.) |
| **Hello and dead intervals** | Exactly equal on both sides |
| **Authentication** | Type and key (authentication is excluded from the v2.0 blueprint, but it is still a match requirement) |
| **Stub area flag** | Both agree whether the area is a stub |

These must also be right for the adjacency to complete or work:

| Requirement | Symptom if wrong |
|---|---|
| **Unique router IDs** | No adjacency, duplicate-RID log messages |
| **Matching IP MTU** | Neighbor stuck in ExStart/Exchange |
| **Compatible network types** | Broadcast on one side and point-to-point on the other: hellos still match (both 10/40), and the routers can even reach Full, but the two sides describe the link differently in their LSAs, so routes through the link are missing |
| **Interface not passive** | Passive interfaces send no hellos, so no neighbor |

Things that do **not** need to match: the OSPF **process ID** (`router ospf 1` versus `router ospf 20` is fine, it is locally significant), interface cost, interface priority, and the reference bandwidth (mismatched reference bandwidth does not break adjacency, but gives inconsistent path choices).

## Network types

| Network type | Default on | DR/BDR? | Hello/Dead |
|---|---|---|---|
| **Broadcast** | Ethernet | Yes | 10/40 |
| **Point-to-point** | Serial (HDLC/PPP), GRE tunnels, or Ethernet with `ip ospf network point-to-point` | No | 10/40 |
| Non-broadcast | Frame Relay-style NBMA | Yes, neighbors configured manually | 30/120 |

On a point-to-point network there are only two routers, so electing a DR is pointless. Neighbors go straight from 2-Way to ExStart and show up as `FULL/  -` in `show ip ospf neighbor`. Configuring `ip ospf network point-to-point` on Ethernet links that connect exactly two routers is common practice: no DR election, no 40-second wait timer when the link comes up, and no type 2 LSA for the link.

## DR and BDR on broadcast networks

With *n* routers on a segment, a full mesh of adjacencies would need n(n-1)/2 of them, and every LSA change would be flooded by everyone. OSPF instead elects a **Designated Router (DR)** and a **Backup DR (BDR)**:

- Every router forms a Full adjacency with the DR and the BDR.
- Routers that are neither (**DROTHERs**) stay in **2-Way** with each other. That is normal, not a fault.
- DROTHERs send LSUs to 224.0.0.6 (DR and BDR); the DR re-floods them to 224.0.0.5 (everyone).
- The DR originates the **type 2 (network) LSA** describing the segment. Every router originates its own **type 1 (router) LSA**.

### Election rules

1. Highest **OSPF interface priority** wins (`ip ospf priority 0-255`, default **1**).
2. Tie: highest **router ID** wins.
3. Priority **0** means the router can never be DR or BDR.
4. The BDR is chosen the same way from the remaining eligible routers.

The election runs when an interface comes up, after a **wait timer** equal to the dead interval, unless DR/BDR announcements are already being heard. It is **non-preemptive**: a router with a higher priority or RID that joins later does **not** take over. It becomes a DROTHER. Only when the DR fails does the BDR become DR, and a new BDR is elected. To force a specific router to be DR you raise its priority and then reset OSPF on the current DR and BDR (or bounce the segment).

> **Exam tip:** DR/BDR roles are **per segment**, not per router. One router can be DR on Gi0/0/0, DROTHER on Gi0/0/1 and have no DR at all on a point-to-point Gi0/0/2.

> **Watch out:** If every router on a broadcast segment has priority 0, no DR is elected. All neighbors sit in 2-Way/DROTHER, nobody reaches Full, and no routes are learned across that segment.

## Cost: the OSPF metric

OSPF cost on an interface defaults to **reference bandwidth / interface bandwidth**, with a reference of **100 Mbps** and a minimum of 1 (fractions are dropped). The route metric is the sum of the outgoing interface costs along the path, including the local router's exit interface.

| Interface bandwidth | Cost (ref 100 Mbps) | Cost (ref 10,000 Mbps) |
|---|---|---|
| 10 Mbps | 10 | 1000 |
| 100 Mbps | 1 | 100 |
| 1 Gbps | 1 | 10 |
| 10 Gbps | 1 | 1 |

With the default reference, everything at 100 Mbps and above costs 1, so OSPF cannot tell FastEthernet from 10-Gigabit. The fix and its configuration are covered in the next lesson.

> **Real world:** In production, OSPF is often run with point-to-point links everywhere between routers and a raised reference bandwidth on every router. Both are configuration choices that remove the most common sources of "OSPF picked the slow path" and "the link took 40 seconds to come up" tickets.

## Key takeaways

- OSPF is link-state: identical LSDB in the area, SPF per router, AD 110, metric = cost.
- RID order: `router-id`, highest up loopback IPv4, highest up interface IPv4. OSPFv3 RID is also 32-bit and must be set by hand on IPv6-only routers.
- Neighbor states: Down, Init, 2-Way, ExStart, Exchange, Loading, Full. ExStart/Exchange stalls mean MTU mismatch.
- Hello must agree on area, subnet/mask, hello/dead timers, authentication and stub flag; RIDs must be unique; process IDs need not match.
- DR/BDR: highest priority, then highest RID; non-preemptive; priority 0 never elected; DROTHERs stay 2-Way with each other.
- Point-to-point network type has no DR/BDR and shows `FULL/  -`.
- Default cost = 100 Mbps / bandwidth, minimum 1.
