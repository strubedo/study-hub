## The lab topology used in this lesson

R1 connects to a LAN (Gi0/0/2, 10.1.10.0/24), to R2 over a point-to-point Ethernet link (Gi0/0/1, 10.0.12.0/30) and to the internet (Gi0/0/0, 203.0.113.0/30). R1 has Loopback0 1.1.1.1/32. Everything internal is area 0.

## Enabling OSPFv2: two methods

### Method 1: the `network` command

```ios
R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
R1(config-router)# network 10.1.10.0 0.0.0.255 area 0
R1(config-router)# network 1.1.1.1 0.0.0.0 area 0
```

The `network` command does **not** advertise a network directly. It is a pattern match against **interface IP addresses**: any interface whose primary IPv4 address matches the address/wildcard pair is enabled for OSPF in that area, and OSPF then advertises that interface's actual subnet with its actual mask.

Wildcard rules: a `0` bit must match, a `1` bit is "don't care". For a contiguous wildcard, the matched range is the address plus a block size of (wildcard octet + 1).

| Statement | Matches interface addresses |
|---|---|
| `network 10.1.10.1 0.0.0.0 area 0` | Exactly 10.1.10.1 |
| `network 10.1.10.0 0.0.0.255 area 0` | 10.1.10.0 to 10.1.10.255 |
| `network 10.1.20.0 0.0.0.31 area 0` | 10.1.20.0 to 10.1.20.31 |
| `network 10.0.0.0 0.255.255.255 area 0` | Anything in 10.0.0.0/8 |
| `network 0.0.0.0 255.255.255.255 area 0` | Every interface with an IPv4 address |

> **Exam tip:** The wildcard in a `network` statement does not have to equal the interface's mask. `network 10.0.0.0 0.255.255.255 area 0` happily enables a /30 interface. The question is only "does this interface's IP fall inside the range?"

### Method 2: interface configuration

```ios
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ip ospf 1 area 0
```

This enables OSPF process 1 on the interface directly, with no wildcard math. If both methods cover the same interface, the **interface command takes precedence**. `show ip ospf interface` tells you which one is in effect: `Attached via Network Statement` or `Attached via Interface Enable`.

## Passive interfaces

A LAN with only hosts on it needs its subnet advertised, but sending hellos there wastes CPU and lets anyone plug in a router and inject routes.

```ios
R1(config)# router ospf 1
R1(config-router)# passive-interface GigabitEthernet0/0/2
! or, secure by default:
R1(config-router)# passive-interface default
R1(config-router)# no passive-interface GigabitEthernet0/0/1
```

A passive interface still has its subnet advertised, but it sends no hellos and ignores received hellos, so **no neighbor can form on it**. A wrongly passive transit link is a classic "neighbor missing" exhibit, visible in `show ip protocols` under `Passive Interface(s):`.

## Point-to-point network type on Ethernet

```ios
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ip ospf network point-to-point
```

Configure it on **both** ends. Result: no DR/BDR election, `FULL/  -` in the neighbor table and `P2P` in `show ip ospf interface brief`.

## Influencing DR/BDR election

```ios
R1(config-if)# ip ospf priority 255   ! most preferred
R3(config-if)# ip ospf priority 0     ! never DR or BDR
```

Remember the election is non-preemptive: a new priority only matters at the next election.

## Cost and the reference bandwidth

Default cost = 100 Mbps / interface bandwidth. Because everything 100 Mbps and faster costs 1, raise the reference on **every** OSPF router (value in Mbps):

```ios
R1(config)# router ospf 1
R1(config-router)# auto-cost reference-bandwidth 10000
% OSPF: Reference bandwidth is changed.
        Please ensure reference bandwidth is consistent across all routers.
```

With 10,000 Mbps, a 1 Gbps link costs 10 and a 100 Mbps link costs 100. If only some routers are changed, each router computes costs with its own reference and paths become inconsistent (not broken, but unpredictable).

Other ways to change cost on one interface:

- `ip ospf cost 50` sets the cost directly and overrides the formula.
- `bandwidth 50000` (in kbps) changes the bandwidth value the formula uses. It does not change the real speed, and it also affects other protocols that read it.

## Advertising a default route

```ios
R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
R1(config)# router ospf 1
R1(config-router)# default-information originate
```

R1 now injects a default as an external LSA, which other routers see as `O*E2 0.0.0.0/0 [110/1]`. Without the `always` keyword, R1 advertises the default **only while it has a default route in its own routing table**. `default-information originate always` advertises it unconditionally (useful, but it can blackhole traffic if the ISP is down).

```ios
R1# show ip ospf neighbor

```

Columns to read: `State` (DR, BDR, DROTH, P2P, LOOP, WAIT, DOWN) and `Nbrs F/C`, which is **Full adjacencies / total neighbors**. A DROTHER on a segment with a DR, BDR and one other DROTHER shows `2/3`: full with two, 2-Way with one. Gi0/0/2 is DR with no neighbors because it is a passive host LAN. The costs of 10 reflect a reference bandwidth of 10,000 Mbps on 1 Gbps links.

## Troubleshooting checklist

| Symptom | Check |
|---|---|
| Neighbor missing entirely | Interface enabled for OSPF? Passive? Area, subnet/mask, hello/dead match? ACL blocking 224.0.0.5? |
| Stuck in INIT | One-way hellos (ACL, filtering) |
| Stuck in EXSTART/EXCHANGE | `ip mtu` mismatch (`show ip interface`); fix the MTU, or `ip ospf mtu-ignore` as a workaround |
| 2WAY/DROTHER with some neighbors | Normal between DROTHERs |
| Neighbors Full but routes missing | Network type mismatch, route filtering, or the remote interface not enabled/advertised |
| Slow path chosen | Reference bandwidth too low, inconsistent, or manual costs |
| No default route on other routers | Originator has no default route and no `always` keyword |

## OSPFv3 for IPv6

OSPFv3 uses the same states, election, timers, cost and areas. Configuration is interface-based; there is no `network` command.

```ios
R1(config)# ipv6 unicast-routing
R1(config)# ipv6 router ospf 1
R1(config-rtr)# router-id 1.1.1.1
R1(config-rtr)# exit
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ipv6 ospf 1 area 0
R1(config-if)# interface GigabitEthernet0/0/2
R1(config-if)# ipv6 ospf 1 area 0
```

Key differences from OSPFv2:

- The RID is still 32 bits. If the router has no IPv4 address, the process cannot pick one and does not start until `router-id` is configured.
- Neighbors talk using **link-local** addresses (multicast FF02::5 and FF02::6), so routes learned through OSPFv3 have `FE80::` next hops.
- Interfaces need an IPv6 link-local address (any IPv6-enabled interface has one), and `ipv6 unicast-routing` must be on.

```ios
R1# show ipv6 ospf neighbor

            OSPFv3 Router with ID (1.1.1.1) (Process ID 1)

Neighbor ID     Pri   State           Dead Time   Interface ID    Interface
2.2.2.2           1   FULL/DR         00:00:33    4               GigabitEthernet0/0/1

R1# show ipv6 route ospf
O   2001:DB8:20::/64 [110/2]
     via FE80::2, GigabitEthernet0/0/1
```

Notice `FULL/DR` on Gi0/0/1 even though OSPFv2 runs that link as point-to-point: the OSPFv3 network type is set separately (`ipv6 ospf network point-to-point`), so here it is still broadcast for OSPFv3. The OSPFv3 neighbor table shows the neighbor's **interface ID** instead of an address; `show ipv6 ospf neighbor detail` shows its link-local address. `show ipv6 ospf interface brief` and `show ipv6 protocols` mirror their IPv4 counterparts.

> **Watch out:** OSPFv2 and OSPFv3 are separate processes with separate neighbor tables. A Full OSPFv2 adjacency proves nothing about OSPFv3 on the same link, and vice versa.

## Key takeaways

- `network <addr> <wildcard> area <id>` matches interface addresses; `ip ospf <pid> area <id>` on the interface overrides it.
- `passive-interface` advertises the subnet but blocks neighbors on that interface.
- `ip ospf network point-to-point` (both ends) removes DR/BDR election on two-router Ethernet links.
- Set `auto-cost reference-bandwidth` identically on every router so faster links get lower costs.
- `default-information originate` needs a default route in the local table unless `always` is used; others see `O*E2`.
- Verify with `show ip ospf neighbor`, `show ip ospf interface [brief]`, `show ip protocols`.
- OSPFv3: `ipv6 router ospf`, `ipv6 ospf <pid> area <id>` per interface, manual RID on IPv6-only routers, link-local next hops.
