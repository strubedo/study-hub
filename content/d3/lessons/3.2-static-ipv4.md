## Why static routes still matter

Static routes are the simplest routing tool: you tell the router exactly where a prefix lives. They are everywhere in real networks: the default route toward an ISP, stub branch sites, a backup path that only activates when the dynamic protocol fails, or a host route that pins one server to a specific path. The v2.0 blueprint verb is **troubleshoot**, so expect exhibits where a static route exists but traffic still fails.

## Syntax

```ios
R1(config)# ip route <prefix> <mask> {<next-hop-ip> | <exit-interface> [<next-hop-ip>]} [<AD>] [name <text>] [permanent]
```

There are three ways to tell the router where to send traffic:

| Form | Example | How it shows in `show ip route` |
|---|---|---|
| Next hop only (recursive) | `ip route 10.2.0.0 255.255.0.0 10.0.12.2` | `S 10.2.0.0/16 [1/0] via 10.0.12.2` |
| Exit interface only | `ip route 10.2.0.0 255.255.0.0 GigabitEthernet0/0/1` | `S 10.2.0.0/16 is directly connected, GigabitEthernet0/0/1` |
| Fully specified (both) | `ip route 10.2.0.0 255.255.0.0 GigabitEthernet0/0/1 10.0.12.2` | `S 10.2.0.0/16 [1/0] via 10.0.12.2, GigabitEthernet0/0/1` |

All three have a default AD of **1**. The "directly connected" wording for the exit-interface form does not mean AD 0.

### Next hop only

The router must resolve the next hop with a second (recursive) lookup. If `10.0.12.2` is reachable through the connected route `10.0.12.0/24`, the static route is installed and packets leave Gi0/0/1. If no route covers the next hop, the static route is **not installed** at all.

### Exit interface only: fine on serial, risky on Ethernet

On a point-to-point link there is only one possible receiver, so naming the interface is enough. On Ethernet, the router has no next-hop address to ARP for, so it treats **every destination as if it were on the local segment** and sends an ARP request for each final destination IP. That only works if the upstream router answers with **proxy ARP** (enabled by default on IOS interfaces, often disabled by ISPs and security baselines). Even when it works it fills the ARP cache with one entry per destination. IOS even warns when you do this for a default route:

```ios
R1(config)# ip route 0.0.0.0 0.0.0.0 GigabitEthernet0/0/0
%Default route without gateway, if not a point-to-point interface, may impact performance
```

> **Watch out:** An exit-interface-only route on Ethernet that "worked in the lab" can break the moment the neighbor runs `no ip proxy-arp`. On multi-access links always give a next-hop IP (alone or with the interface).

### Fully specified

Naming both the interface and the next hop avoids the recursive lookup and the proxy-ARP problem, and the route is withdrawn if that interface goes down. It is the most deterministic form on Ethernet.

## The four static route types in the blueprint

| Type | Prefix | Example |
|---|---|---|
| **Default route** | `0.0.0.0/0` | `ip route 0.0.0.0 0.0.0.0 203.0.113.1` |
| **Network route** | Any subnet or summary | `ip route 172.16.32.0 255.255.240.0 10.0.12.2` |
| **Host route** | `/32` | `ip route 10.9.9.9 255.255.255.255 10.0.13.3` |
| **Floating static** | Any, with AD raised | `ip route 0.0.0.0 0.0.0.0 198.51.100.1 130` |

A **host route** is the most specific IPv4 route possible, so by longest-prefix match it beats any network or default route to the same host. That is how you steer one server's traffic down a different path.

A **floating static** route has an AD higher than the route it backs up. It stays out of the routing table while the preferred route exists and "floats" in when that route disappears.

```ios
! Primary: default learned by OSPF (O*E2, AD 110)
! Backup: static default to the second ISP, AD 130
R1(config)# ip route 0.0.0.0 0.0.0.0 198.51.100.1 130
```

| Primary route source | Floating static AD must be greater than |
|---|---|
| OSPF | 110 |
| EIGRP internal | 90 (external EIGRP routes are 170) |
| Another static route | That route's AD (usually 1) |

> **Exam tip:** A floating static with an AD **lower** than the dynamic route is not floating at all: it immediately replaces the dynamic route. A static default with AD 100 "backing up" an OSPF default (110) becomes the primary.

> **Watch out:** A floating static route only takes over when the primary route is *removed* from the table. If the primary is a static route pointing at a next hop on an Ethernet link that stays up while the ISP beyond it is dead, the primary never leaves and the backup never activates. Real designs add IP SLA tracking for that; on the exam, think "what removes the primary route?"

## Verifying

```ios
R1# show ip route static
Gateway of last resort is 203.0.113.1 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 203.0.113.1
      10.0.0.0/8 is variably subnetted, 6 subnets, 3 masks
S        10.2.0.0/16 [1/0] via 10.0.12.2
S        10.9.9.9/32 [1/0] via 10.0.13.3

R1# show running-config | include ^ip route
ip route 0.0.0.0 0.0.0.0 203.0.113.1
ip route 0.0.0.0 0.0.0.0 198.51.100.1 130
ip route 10.2.0.0 255.255.0.0 10.0.12.2
ip route 10.9.9.9 255.255.255.255 10.0.13.3
```

Comparing the two outputs is the core troubleshooting habit: the running config shows **what you asked for**, the routing table shows **what was accepted**. The floating default (AD 130) is configured but absent from the table, exactly as it should be while the AD 1 default exists. Note that `show ip route static` still prints the classful header with the totals for all of 10.0.0.0/8, including connected and local entries not shown by the filter (here the six subnets are 10.0.12.0/24, 10.0.13.0/24, their two /32 local routes, and the two static routes).

## Troubleshooting static routes

| Symptom | Likely cause | How to confirm |
|---|---|---|
| Route in config, not in table | Next hop unreachable (recursive lookup fails), exit interface down, or a better-AD route to the same prefix exists | `show ip route <next-hop>`, `show ip interface brief` |
| Route in table, traffic fails at the first hop | Wrong next hop (typo, a host instead of the router) | `show ip arp` shows `Incomplete`; `show cdp neighbors detail` |
| Traffic reaches the far side but replies never return | **Missing return route** on a downstream router | Ping from the far router back to the source; traceroute stops after the far router |
| Only some hosts in a range work | Wrong mask (`255.255.255.0` instead of `255.255.0.0`) | `show ip route <dest>` returns "Subnet not in table" for the others |
| Exit-interface route on Ethernet fails toward one provider only | Neighbor has proxy ARP disabled | `show ip arp` shows many `Incomplete` entries for remote IPs |
| Backup path never used, or used all the time | Floating static AD wrong relative to the primary | Compare ADs in `show ip route` and the config |

Routing is **per hop and per direction**. A ping needs a route from source to destination on every router in the forward path **and** a route back to the source on every router in the return path. A classic exhibit shows R1 with a perfect static route to a remote LAN, and R2 with no route back to R1's LAN.

> **Real world:** When a static route vanishes from the table after an interface flap or neighbor change, IOS removes it silently. `show ip route <prefix>` returning `% Subnet not in table` when the config clearly contains the route is your cue to check the next hop.

## Key takeaways

- Syntax: `ip route <prefix> <mask> <next-hop | exit-interface [next-hop]> [AD]`. Default AD is 1 for every form.
- On Ethernet, avoid exit-interface-only routes: they depend on the neighbor's proxy ARP and ARP for every destination.
- A recursive static route is installed only when its next hop is resolvable.
- Default = `0.0.0.0 0.0.0.0`; host route = `255.255.255.255` mask; a host route beats every less specific route.
- A floating static needs an AD **higher** than the route it backs up (more than 110 to back up OSPF).
- Troubleshoot by comparing config with the routing table, then check next-hop ARP and the return path.
