## What an ACL is

An access control list is an ordered list of **access control entries (ACEs)**. Each ACE is a `permit` or `deny` plus match conditions. IOS uses ACLs for packet filtering on interfaces, and also as a generic "matching tool" for NAT, route maps, QoS, VTY access and more. This lesson covers the rules every ACL follows and the **standard** ACL. The next lesson covers **extended** ACLs.

## The processing rules

1. **Top-down.** IOS compares the packet with each ACE in order.
2. **First match wins.** As soon as an ACE matches, its action is taken and processing stops. Later entries are never checked.
3. **Implicit deny.** Every ACL ends with an invisible `deny any` (standard) / `deny ip any any` (extended). A packet that matches nothing is dropped.

Consequences:

* An ACL with only `deny` statements blocks **everything**. You need at least one `permit`.
* Put **specific entries before general ones**. `permit 10.1.0.0 0.0.255.255` followed by `deny 10.1.5.0 0.0.0.255` never denies anything in 10.1.5.0/24.
* The implicit deny does not show in `show access-lists` and has no hit counter. Add an explicit `deny any log` at the end if you want to count or log drops.

## Wildcard masks

A wildcard mask tells IOS which bits must match. **0 = must match, 1 = ignore.** For a contiguous block, the wildcard is the subnet mask inverted: subtract each octet from 255.

| Network | Subnet mask | Wildcard |
|---------|-------------|----------|
| 10.1.1.0/24 | 255.255.255.0 | 0.0.0.255 |
| 172.16.32.0/20 | 255.255.240.0 | 0.0.15.255 |
| 192.168.1.64/26 | 255.255.255.192 | 0.0.0.63 |
| 10.0.0.0/8 | 255.0.0.0 | 0.255.255.255 |
| Single host | 255.255.255.255 | 0.0.0.0 |

Keywords:

* `host 10.1.1.10` = `10.1.1.10 0.0.0.0`
* `any` = `0.0.0.0 255.255.255.255`

> **Exam tip:** To find the range a wildcard matches, the base address plus the wildcard gives the last address. `172.16.32.0 0.0.15.255` covers 172.16.32.0 – 172.16.47.255.

> **Watch out:** If you enter `access-list 10 permit 192.168.1.77 0.0.0.63`, IOS stores `192.168.1.64 0.0.0.63` because the host bits under the wildcard are ignored. Always check what was actually stored.

## ACL number ranges

| Type | Numbered ranges | Matches on |
|------|-----------------|------------|
| Standard | 1–99, 1300–1999 | Source IPv4 address only |
| Extended | 100–199, 2000–2699 | Protocol, source, destination, ports, and more |

Named ACLs (`ip access-list standard NAME` / `ip access-list extended NAME`) can be either type; the keyword decides.

## Standard ACL configuration

### Numbered

```ios
R1(config)# access-list 10 remark Allow HR subnet only
R1(config)# access-list 10 permit 10.1.20.0 0.0.0.255
R1(config)# access-list 10 deny any
```

If you omit the wildcard in a standard ACE (`access-list 10 permit 10.1.20.5`), IOS treats it as a host entry.

### Named

```ios
R1(config)# ip access-list standard HR-ONLY
R1(config-std-nacl)# 10 permit 10.1.20.0 0.0.0.255
R1(config-std-nacl)# 20 deny any log
```

Named ACLs are self-documenting and easier to edit (sequence numbers are covered in the next lesson). On current IOS and IOS XE you can also edit numbered ACLs in the same sub-mode with `ip access-list standard 10`.

> **Watch out:** `no access-list 10 permit 10.1.20.0 0.0.0.255` in global configuration does **not** remove one line. It deletes the **entire** numbered ACL 10. Edit by sequence number instead.

## Applying an ACL to an interface

```ios
R1(config)# interface GigabitEthernet0/0/2
R1(config-if)# ip access-group HR-ONLY out
```

* **in** – packets arriving on the interface, checked before the routing decision.
* **out** – packets leaving the interface, checked after routing.
* One ACL **per interface, per direction, per protocol** (one IPv4 in, one IPv4 out, one IPv6 in, one IPv6 out).
* Outbound ACLs do **not** filter packets **generated by the router itself** (for example its own pings or routing updates).
* Applying an ACL name that does not exist yet does not drop traffic; an undefined ACL permits everything until you create it. As soon as you add the first ACE, the implicit deny applies.

## Placement guidance

Traditional Cisco guidance:

* **Standard ACLs: close to the destination.** They match only the source address. Placed near the source, they would block that source from reaching **every** destination beyond that point, not just the one you meant to protect.
* **Extended ACLs: close to the source.** They match source and destination precisely, so drop unwanted traffic early and save bandwidth.

Example: block host 10.1.10.25 from the server subnet 10.1.50.0/24 but allow it everywhere else.

```text
10.1.10.0/24 ---[Gi0/0/0 R1 Gi0/0/1]--- WAN ---[Gi0/0/1 R2 Gi0/0/0]--- 10.1.50.0/24 (servers)
                                                  \--Gi0/0/2--- 10.1.60.0/24 (printers)
```

With a standard ACL, the right place is R2 Gi0/0/0 **outbound**:

```ios
R2(config)# ip access-list standard PROTECT-SERVERS
R2(config-std-nacl)# deny host 10.1.10.25
R2(config-std-nacl)# permit any
R2(config-std-nacl)# exit
R2(config)# interface GigabitEthernet0/0/0
R2(config-if)# ip access-group PROTECT-SERVERS out
```

Applying it at R1 Gi0/0/0 inbound would also block 10.1.10.25 from the printers, the WAN and the internet.

## Restricting VTY access with a standard ACL

A very common real-world use of standard ACLs:

```ios
R1(config)# ip access-list standard MGMT
R1(config-std-nacl)# permit 10.99.0.0 0.0.0.255
R1(config-std-nacl)# exit
R1(config)# line vty 0 15
R1(config-line)# access-class MGMT in
```

`access-class` is applied to lines; `ip access-group` is applied to interfaces. Using `access-class` protects SSH to **every** IP address on the router with one command.

## Verifying

```ios
R2# show access-lists PROTECT-SERVERS
Standard IP access list PROTECT-SERVERS
    10 deny   10.1.10.25 (14 matches)
    20 permit any (2290 matches)
R2# show ip interface GigabitEthernet0/0/0 | include access list
  Outgoing Common access list is not set
  Outgoing access list is PROTECT-SERVERS
  Inbound Common access list is not set
  Inbound  access list is not set
```

Note that IOS displays a host entry in a standard ACL simply as the address (`10.1.10.25`), without the `host` keyword. `clear access-list counters` resets the match counters so you can watch a test.

## Key takeaways

* ACLs are processed top-down, first match wins, and end in an implicit deny that has no counter.
* Wildcard 0 bits must match, 1 bits are ignored; `host` = /32, `any` = everything.
* Standard ACLs (1–99, 1300–1999) match only the source address; place them near the destination.
* One ACL per interface, per direction, per protocol; outbound ACLs do not filter router-originated traffic.
* `no access-list <number> ...` deletes the whole numbered ACL.
* `access-class` on VTY lines restricts management sources; `ip access-group` filters interface traffic.
