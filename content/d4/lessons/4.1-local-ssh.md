## Why management access matters

Every router and switch has a management plane: the console, the VTY lines used for remote CLI access, and services such as HTTP/HTTPS, SNMP and NETCONF. If an attacker reaches privileged EXEC mode they own the device. The CCNA expects you to lock that plane down in two layers: **who** can log in (usernames, passwords, AAA) and **how** they connect (SSH only, from approved sources, with idle timeouts).

This lesson covers local credentials and SSH. The next lesson adds TACACS+ and RADIUS.

## Password storage types

IOS stores secrets in the configuration using a numbered *type*. You will see the type number in `show running-config`.

| Type | Algorithm | Reversible? | How you get it |
|------|-----------|-------------|----------------|
| 0 | Plain text | n/a | `enable password`, `username X password`, line `password` without encryption |
| 7 | Cisco Vigenère-style obfuscation | **Yes, trivially** | `service password-encryption` applied to type 0 strings |
| 5 | Salted MD5 | No, but fast to brute-force | `enable secret` / `username X secret` on older releases, or `algorithm-type md5` |
| 8 | PBKDF2 with SHA-256 | No | `algorithm-type sha256` |
| 9 | scrypt | No (memory-hard) | `algorithm-type scrypt`, and the default for `secret` on current IOS XE |

> **Watch out:** Type 4 was a flawed SHA-256 implementation and is deprecated. Never use it. Type 6 (reversible AES with a master key) exists for secrets the device itself must recover, such as some VPN keys; it is not used for login passwords.

`service password-encryption` only converts **plain-text** passwords (`enable password`, line `password`, `username X password`) to type 7. It never touches `secret` values, which are already hashed. Type 7 strings can be decoded by many free tools in seconds, so treat it as protection against shoulder surfing only.

> **Real world:** The default hashing for a plain `enable secret <pw>` changed over time. Older IOS and early IOS XE releases produce type 5 (MD5); current IOS XE releases produce type 9. If you need a specific algorithm regardless of release, say so explicitly with `algorithm-type`.

### Enable secret vs enable password

```ios
R1(config)# enable algorithm-type scrypt secret Str0ng!Enable
R1(config)# do show running-config | include enable
enable secret 9 $9$0Tq8wX3qkzGx3k$Jm2...
```

If both `enable password` and `enable secret` exist, **enable secret wins** (IOS also warns if you try to make the two identical). There is no reason to configure `enable password` today.

## Local usernames and privilege levels

IOS has 16 privilege levels (0–15). Level 1 is user EXEC (`>` prompt) and level 15 is privileged EXEC (`#` prompt). Assigning `privilege 15` to a local user drops them directly into privileged EXEC on login, so they never need the enable secret.

```ios
R1(config)# username netadmin privilege 15 algorithm-type scrypt secret C0mpl3x!Pass
R1(config)# username helpdesk privilege 1 algorithm-type scrypt secret Read0nly!Pass
```

Use `secret`, never `password`, for usernames. `username X password Y` stores type 0 (or type 7 if `service password-encryption` is on).

> **Exam tip:** A user configured without a `privilege` keyword gets level 1. They land at `R1>` and must still know the enable secret to reach `R1#`.

## Building SSH on IOS XE

SSH needs an RSA key pair, and the key pair's default name is built from the hostname and domain name. That is why the order of steps matters.

```ios
R1(config)# hostname R1
R1(config)# ip domain name corp.example.com
R1(config)# crypto key generate rsa modulus 2048
The name for the keys will be: R1.corp.example.com
% The key modulus size is 2048 bits
% Generating 2048 bit RSA keys, keys will be non-exportable...
[OK] (elapsed time was 1 seconds)
R1(config)# ip ssh version 2
R1(config)# username netadmin privilege 15 algorithm-type scrypt secret C0mpl3x!Pass
R1(config)# line vty 0 15
R1(config-line)# login local
R1(config-line)# transport input ssh
R1(config-line)# exec-timeout 10 0
```

Step-by-step requirements:

1. **Hostname other than the default** (`Router`/`Switch`). Key generation refuses to run with the default hostname.
2. **Domain name.** `ip domain name` is the current IOS XE form; the older hyphenated `ip domain-name` is still accepted and converted.
3. **RSA keys** of at least 768 bits for SSHv2. Use 2048 or larger in practice. Generating keys automatically enables the SSH server.
4. **`ip ssh version 2`** disables SSHv1. Without it, IOS advertises version 1.99 (both).
5. **A login method** on the VTY lines. `login local` checks the local username database.
6. **`transport input ssh`** blocks Telnet. The default differs by platform and release (older images allow Telnet), so always set it explicitly.

> **Watch out:** `login` (without `local`) checks the *line password* set with `password` under the line, not usernames. If no line password exists, the line refuses connections with "Password required, but none set". `login local` ignores line passwords completely.

### Verifying SSH

```ios
R1# show ip ssh
SSH Enabled - version 2.0
Authentication methods:publickey,keyboard-interactive,password
Authentication timeout: 120 secs; Authentication retries: 3
...
R1# show ssh
Connection Version Mode Encryption  Hmac         State          Username
0          2.0     IN   aes256-ctr  hmac-sha2-256 Session started netadmin
0          2.0     OUT  aes256-ctr  hmac-sha2-256 Session started netadmin
```

`show ip ssh` confirms the server is on and which version. `show ssh` lists active sessions. `show users` shows who is on which line.

## Hardening the VTY lines

### exec-timeout

`exec-timeout <minutes> [seconds]` disconnects an idle session. The default is 10 minutes. `exec-timeout 0 0` disables the timer, which is convenient in a lab and a bad idea in production.

### access-class

`access-class` filters **who can connect to the VTY lines**. It uses an ACL (normally standard) that matches the source address of incoming management sessions.

```ios
R1(config)# ip access-list standard MGMT-HOSTS
R1(config-std-nacl)# permit 10.99.0.0 0.0.0.255
R1(config-std-nacl)# exit
R1(config)# line vty 0 15
R1(config-line)# access-class MGMT-HOSTS in
```

Key points:

* `access-class ... in` filters sessions **to** the device. `access-class ... out` filters sessions a user starts **from** the device (for example `ssh` from the CLI to another box) and compares the destination address.
* The implicit deny applies, so only 10.99.0.0/24 can open SSH sessions in this example.
* `ip access-group` is the interface command; `access-class` is the line command. Mixing them up is a classic exam distractor.

> **Exam tip:** Apply `access-class` to **all** VTY lines. Catalyst 9000 switches have `line vty 0 4` and `line vty 5 15` as separate stanzas in the config. Securing only `0 4` leaves lines 5–15 open once the first five are busy.

### Console and banner

The console should also require a login. A typical baseline:

```ios
R1(config)# line console 0
R1(config-line)# login local
R1(config-line)# exec-timeout 5 0
R1(config-line)# exit
R1(config)# banner motd ^Authorized access only. Activity is logged.^
```

## Putting it together: a secure baseline

| Goal | Command |
|------|---------|
| Strong privileged password | `enable algorithm-type scrypt secret ...` |
| Named admin with direct level 15 | `username X privilege 15 algorithm-type scrypt secret ...` |
| Obfuscate leftover type 0 strings | `service password-encryption` |
| SSH prerequisites | `hostname`, `ip domain name`, `crypto key generate rsa modulus 2048` |
| SSHv2 only | `ip ssh version 2` |
| Use local accounts on VTY | `login local` |
| No Telnet | `transport input ssh` |
| Idle disconnect | `exec-timeout 10 0` |
| Source restriction | `access-class <acl> in` |

> **Real world:** Keep at least one local privilege 15 account even after deploying TACACS+. It is your break-glass account when the AAA servers are unreachable.

## Common troubleshooting patterns

* **"% Please define a hostname other than Router."** You tried to generate RSA keys with the default hostname.
* **"% Please define a domain-name first."** No `ip domain name` configured.
* **SSH client says "connection refused".** No RSA keys exist (SSH server is off) or `transport input` does not include SSH.
* **SSH connects then drops immediately.** `access-class` denies the source, or there are no free VTY lines.
* **Login accepted but user lands at `>`.** The user has privilege 1; either add `privilege 15` or the user must type `enable` and know the enable secret.
* **"Password required, but none set".** The line uses `login` instead of `login local` and has no line password.

## Key takeaways

* Use `secret`, never `password`; type 9 (scrypt) and type 8 (PBKDF2-SHA-256) are the strong choices, type 5 is legacy, type 7 is reversible.
* `service password-encryption` only turns type 0 strings into weak type 7; it does not affect secrets.
* SSH needs a non-default hostname, `ip domain name`, and an RSA key (2048 bits recommended); `ip ssh version 2` disables v1.
* `login local` + `transport input ssh` on every VTY line is the baseline; `login` alone uses the line password.
* `access-class` (line) restricts management sources; `ip access-group` (interface) filters transit traffic.
* `exec-timeout` is minutes then seconds; `0 0` disables it.
* Keep a local privilege 15 break-glass account.
