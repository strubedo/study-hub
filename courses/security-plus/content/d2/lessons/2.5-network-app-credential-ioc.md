## Network attacks

**Distributed denial of service (DDoS).** Many sources, usually a botnet of compromised PCs, servers and IoT devices, overwhelm a target's bandwidth, its connection state tables or its application. Three broad kinds: **volumetric** (flooding the pipe), **protocol** (exhausting state, such as SYN floods filling connection tables) and **application-layer** (expensive HTTP requests). **Reflected/amplified** DDoS spoofs the victim's IP address as the source of small requests to open services (DNS resolvers, NTP, memcached and the like) that send much larger responses to the victim. Indicators: traffic from very many sources, saturated links, exhausted session tables, a single URL hammered. Controls: upstream scrubbing or CDN, rate limiting, and not running open reflectors yourself.

**Protocol downgrade.** Forcing two parties to use an older, weaker version or cipher than both support, so the attacker can break it. TLS defends against this: RFC 8446 requires a TLS 1.3 server that negotiates an older version to put a fixed sentinel ("DOWNGRD") in the last 8 bytes of its random value so a TLS 1.3 client can detect tampering, and RFC 7507 defined the `TLS_FALLBACK_SCSV` signal and the `inappropriate_fallback` alert for clients that retry with a lower version. **SSL stripping** is a related downgrade from HTTPS to HTTP by an on-path attacker; HSTS (RFC 6797) prevents it once the browser knows the site's policy, though RFC 6797 notes that a first visit over `http` is still exposed ("bootstrap MITM"), which HSTS preload lists close. The best control is to disable old versions (TLS 1.0/1.1 are deprecated by RFC 8996) so there is nothing to downgrade to.

**Rogue.** An unauthorized device providing a network service: a **rogue access point**, an **evil twin** (an AP that copies a legitimate SSID to lure clients) or a **rogue DHCP server** that hands out the attacker's gateway or DNS server. Indicators: unknown BSSIDs on the corporate SSID, clients receiving unexpected gateway or DNS addresses. Controls: WIPS, 802.1X, DHCP snooping.

**Sniffing.** Capturing traffic: passively on a shared or wireless medium, or after redirecting it. Only cleartext is directly useful, which is why Telnet, FTP, HTTP logins and SNMPv1/v2c are dangerous. Encryption is the control.

**Spoofing.** Falsifying an identifier so traffic appears to come from someone else: IP address spoofing (used in reflection DDoS), MAC spoofing (to bypass MAC filtering), ARP spoofing, email sender spoofing, caller ID spoofing. Spoofing is usually a step in a larger attack.

**On-path (formerly man-in-the-middle).** The attacker sits between two parties, relaying and possibly reading or altering traffic. MITRE ATT&CK calls it **adversary-in-the-middle (AiTM)** and lists ARP cache poisoning, DHCP spoofing and evil twins as ways to get there; the goal is sniffing, data manipulation or replay. AiTM **phishing kits** proxy the real login page, so they capture the password, the MFA code and the resulting session cookie. Controls: encryption with certificate validation, 802.1X, dynamic ARP inspection, phishing-resistant MFA.

**DNS attacks** abuse the name system:

| Attack | What happens | Where |
|---|---|---|
| **DNS cache poisoning** | Forged answers are inserted into a resolver's cache, so every client of that resolver is sent to the attacker's address until the TTL expires | The recursive resolver |
| **Domain hijacking** | The attacker takes control of the domain registration (compromised registrar account, social engineering of the registrar, expired domain) and changes the name servers or records | The registrar / registry |
| **DNS hijacking / redirection** | The victim's DNS settings are changed (malware, compromised home router, rogue DHCP) to point at an attacker's resolver | The client or local network |
| **Typosquatting** | The attacker registers a misspelled or lookalike domain and waits for typing errors or uses it in phishing | Not an attack on DNS itself; the names are legitimately registered |
| **DNS tunneling** | Data or C2 traffic encoded in DNS queries and responses to slip through firewalls | Outbound DNS |
| **DNS amplification / floods** | Reflected DDoS using open resolvers, or floods of random subdomain queries against a zone | Resolvers and authoritative servers |

**Cache poisoning** is wider than DNS. **ARP cache poisoning** sends forged ARP replies so hosts map the gateway's IP to the attacker's MAC address, putting the attacker on-path within the LAN. **DNS cache poisoning** works because a resolver accepts a response that matches its outstanding query: RFC 5452 lists the question, the 16-bit ID, the source address and the destination address and port. Randomizing the ID and the source port makes forgery harder; **DNSSEC** lets a validating resolver reject unsigned or wrongly signed answers.

> **Exam tip:** Many users of one resolver suddenly reach a fake site while the registrar shows nothing changed: DNS cache poisoning. The domain's NS records changed at the registrar after an account takeover: domain hijacking. Gratuitous ARP replies claiming the gateway's IP: ARP cache poisoning (on-path).

## Application attacks

- **Injection:** untrusted input is interpreted as code or commands: **SQL injection** (`' OR 1=1--`), OS **command injection** (`; cat /etc/passwd`), LDAP and XML injection. OWASP's A05:2025 Injection category also includes **cross-site scripting (XSS)**, which injects script into pages other users load. Fix: parameterized queries, input validation, output encoding.
- **Buffer overflow:** NIST: more input is placed into a buffer than its allocated capacity, overwriting other memory, so attackers can crash the system or run inserted code. Indicators: crashes, long strings of repeated characters or NOP-like padding in input. Fixes: bounds checking, memory-safe languages, ASLR and DEP.
- **Replay:** NIST: the attacker replays previously captured messages to masquerade as the legitimate party. Defeated by nonces, timestamps and session-bound tokens.
- **Privilege escalation:** gaining rights beyond those granted. **Vertical** (user to administrator, often by exploiting a vulnerability, ATT&CK Exploitation for Privilege Escalation) or **horizontal** (user A reaches user B's data).
- **Forgery:** **cross-site request forgery (CSRF)** makes an authenticated user's browser send an unwanted request to a site where they are logged in (NIST: the subscriber unknowingly invokes unwanted actions). **Server-side request forgery (SSRF)** makes the server send requests on the attacker's behalf, often to internal addresses or cloud metadata services. Fixes: anti-CSRF tokens and SameSite cookies; allow lists for outbound server requests.
- **Directory traversal:** input such as `../../etc/passwd` or its encoded form `%2e%2e%2f` escapes the intended directory (CWE-22). Fixes: canonicalize paths, allow-list file names, run with least privilege.

> **Watch out:** Replay re-sends a *captured message or credential* as it was. **Session hijacking** takes over an *established session*, usually by stealing the session cookie or token, and then sends new requests. A captured authentication exchange re-sent later is replay; a stolen cookie used to browse the victim's mailbox is session hijacking.

## Credential attacks

| Attack | Pattern | Log signature |
|---|---|---|
| **Password spraying** | One or a few common passwords tried against **many accounts** (ATT&CK), staying under the lockout threshold | Many usernames, one or two failures each, from one or a few sources, often spread out in time |
| **Brute force** | Many passwords against **one account** (online), or guessing offline against stolen hashes | Many failures for the same account; account lockouts |
| **Credential stuffing** (related) | Username and password pairs from other sites' breaches tried against your service (ATT&CK) | Many accounts, each tried with a *different* specific password, many successes for reused passwords |
| **User enumeration** | Finding valid usernames from different responses to valid and invalid names (error messages, timing, password-reset pages) | Windows event 4625 sub-status `0xC0000064` (bad user name) in a series, which Microsoft calls a sign of user enumeration, versus `0xC000006A` (bad password) |
| **Replay** | Capturing a credential, hash, ticket or token and presenting it again | Valid authentication from an unexpected host with no matching interactive login |
| **MFA bypass** | Getting past MFA rather than breaking it: push fatigue (ATT&CK: flooding the user with MFA push requests until they approve), AiTM phishing that steals the session cookie, SIM swapping to receive SMS codes, social engineering the help desk to reset MFA, legacy protocols that do not enforce MFA | Many MFA prompts then one approval; sign-in without an MFA event; new MFA device registered after a help-desk call |

Controls: MFA, preferably phishing-resistant (FIDO2/passkeys) and with number matching for push (CISA guidance), lockout and smart lockout, banned-password lists, identical error messages for bad user and bad password, and monitoring.

## Indicators of compromise (IoCs)

NIST SP 800-150 defines indicators as technical artifacts or observables that suggest an attack is imminent, underway or has already happened.

| IoC | What to look for |
|---|---|
| **Hash** | A file's hash matches a known-malicious hash from threat intelligence. Exact, but changes with one byte |
| **IP address** | Connections to known C2, scanning or Tor exit addresses; easily changed by attackers |
| **Domain** | Lookups of known-bad, newly registered or random-looking (algorithmically generated) domains |
| **Malicious processes** | Unknown processes, misspelled system binaries in the wrong folder, Office spawning PowerShell, processes with encoded command lines |
| **File system artifacts** | New files in temp or startup folders, ransom notes, dropped tools, renamed extensions, new scheduled task or service files |
| **Timestamp** | Activity at times the user never works, and file times that do not fit: **timestomping** alters file times to blend in (ATT&CK), and NTFS records times in two attributes, so a mismatch is a clue |
| **Log manipulation** | Gaps in logs, cleared logs (Windows event 1102: "The audit log was cleared"), logging services stopped, edited entries |
| **Excessive resource consumption** | Unexplained CPU or GPU load (cryptomining, ATT&CK Resource Hijacking), disk filling (staging for exfiltration), bandwidth spikes |
| **Plaintext strings** | Readable strings inside a binary or memory dump (URLs, IPs, commands, ransom text) and credentials found in cleartext in scripts, logs or traffic |
| **Account lockout** | Lockouts (Windows event 4740) for one account suggest brute force; scattered lockouts across many accounts suggest spraying above the threshold |
| **Impossible travel** | Two sign-ins for the same account from places too far apart for the time between them (for example New York and Singapore 20 minutes apart) |
| **Concurrent sessions** | The same account active in several sessions at once from different devices or locations, when the user normally has one |

> **Exam tip:** Impossible travel and concurrent sessions point to a compromised account or stolen session token. Check for VPN or proxy egress first: a user whose traffic exits through a cloud proxy in another country can trigger impossible travel legitimately.

## Try it yourself

Paper or any OS. Write out what each line of evidence would look like for password spraying, brute force and credential stuffing against 100 accounts, then compare: which field (username, password, source, time) changes in each? On Windows you can open Event Viewer > Windows Logs > Security and filter on event IDs 4625 and 4740 on your own PC (you may need an administrator account; many home PCs log little by default). On macOS or Linux, read about where authentication logs live (`log show` on macOS, `journalctl` or `/var/log/auth.log` on Linux) in the built-in manual pages.

## Key takeaways

- DDoS (volumetric, protocol, application; reflected/amplified), downgrade (fixed by disabling old versions; TLS 1.3 sentinel), rogue APs and DHCP, sniffing, spoofing, on-path (AiTM).
- DNS cache poisoning (resolver), domain hijacking (registrar), DNS hijacking (client settings), typosquatting (lookalike names), tunneling. ARP cache poisoning puts an attacker on-path on the LAN.
- Application: injection (including XSS), buffer overflow, replay, privilege escalation, forgery (CSRF, SSRF), directory traversal.
- Spraying = few passwords, many accounts; brute force = many passwords, one account; stuffing = breached pairs; enumeration = different responses for valid users; MFA bypass = fatigue, AiTM, SIM swap, help desk.
- IoCs: hash, IP, domain, processes, file artifacts, timestamps, log manipulation, resource use, plaintext strings, lockouts, impossible travel, concurrent sessions.
