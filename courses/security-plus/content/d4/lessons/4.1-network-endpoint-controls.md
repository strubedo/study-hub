## Intrusion detection and prevention

An **intrusion detection system (IDS)** watches traffic or host activity and *alerts*. An **intrusion prevention system (IPS)** does the same analysis but sits **inline** in the traffic path, so it can *drop* or reset the offending traffic before it reaches the target.

| | IDS | IPS |
|---|---|---|
| Placement | Out of band: SPAN/mirror port or network TAP copy | Inline: traffic passes through it |
| Action | Alert, log (some can send TCP resets, but cannot stop the first packet) | Drop, block, reset, alert |
| Effect of a false positive | A wasted analyst investigation | Legitimate traffic is blocked |
| Effect of sensor failure | Visibility lost; traffic unaffected | Depends on failure mode (below) |
| Added latency | None | Some, because every packet is inspected |

**Failure modes.** An inline IPS needs a defined behavior when it fails or is overloaded. **Fail-open** (bypass) lets traffic flow uninspected, preserving availability at the cost of security; hardware bypass NICs and bypass switches do this. **Fail-closed** blocks traffic, preserving security at the cost of availability. An out-of-band IDS has no failure mode for traffic: if it dies, the network keeps working and you simply stop seeing alerts. Domain 3 (3.2) covers failure modes as an architecture decision.

**Where they run:**

- **NIDS/NIPS** (network-based): a sensor on a segment or at a perimeter, inspecting packets for many hosts. Cannot see inside encrypted traffic unless TLS is decrypted somewhere before it.
- **HIDS/HIPS** (host-based): an agent on one server or workstation that watches system calls, file changes, registry, logs and local traffic. Sees activity after decryption and on the host itself, but only on hosts where it is installed.
- **WIPS** (wireless intrusion prevention): sensors that monitor the RF environment for rogue access points, evil twins, deauthentication floods and unauthorized clients, and can contain them (for example by blocking the rogue AP's switch port or, where law allows, by sending deauthentication frames to clients associating with it).

**Detection methods:**

| Method | How it works | Strength | Weakness |
|---|---|---|---|
| Signature-based | Matches known patterns (byte strings, protocol fields) | Precise, few false positives for known attacks | Misses new attacks (zero-days) and modified variants |
| Anomaly/behavior-based | Learns a baseline and alerts on deviation | Can catch the unknown | More false positives; baseline must be clean |

A **false positive** is an alert on benign activity; a **false negative** is a real attack that produced no alert. False negatives are the more dangerous because nobody knows they happened. Tuning (lesson 4.4) trades between the two.

## Firewalls

| Type | Decides on | Notes |
|---|---|---|
| Packet filter (stateless ACL) | Addresses, protocol, ports per packet | Router and switch ACLs; return traffic needs its own rule |
| **Stateful firewall** | Layer 3/4 plus connection state | Tracks sessions in a state table; return traffic of an allowed session is permitted automatically |
| **Next-generation firewall (NGFW)** | Adds Layer 7: application identification, user identity, URL category, IPS, TLS inspection | Rules name applications (App-ID in PAN-OS, application control in FortiOS) instead of only ports |
| **Web application firewall (WAF)** | HTTP/HTTPS requests and responses to one web application | Blocks injection, XSS, path traversal and similar (OWASP); reverse-proxy, cloud or plug-in deployment |
| **Unified threat management (UTM)** | One appliance combining firewall, IPS, antivirus, web/content filter, VPN, sometimes DLP and anti-spam | Marketed at small and medium sites; the NGFW and UTM categories now overlap heavily |

**Layer 4 versus Layer 7.** A Layer 4 rule says "allow TCP 443 from any to 203.0.113.10". It cannot tell a browser from a tunneling tool on the same port. A Layer 7 rule says "allow application `ssl`/`web-browsing` to that server, block `bittorrent` on any port", which requires the firewall to identify the application from the traffic itself and, for encrypted traffic, often to decrypt it.

**Rule-based processing.** Firewall and ACL rules are evaluated **top-down, first match wins**, with an **implicit deny** at the end. Order matters: a broad permit above a specific deny makes the deny unreachable (a "shadowed" rule). Good rule sets put specific rules first, log denies, and remove unused rules.

**Rate limiting requests.** A firewall, WAF, load balancer or API gateway can cap requests per source per interval (for example 100 requests per minute per IP to `/login`). This blunts brute force, credential stuffing, scraping and application-layer DoS. It does not stop a large, distributed botnet on its own, because each bot stays under the per-source limit.

> **Exam tip:** SQL injection in form fields of a public web app: WAF. Only one box for a 15-person branch that must do firewall, AV, web filtering and VPN: UTM. Block an application regardless of port: Layer 7 / NGFW. Login API flooded by a few sources: rate limiting.

## Content filtering and DLP

Content filters inspect web and other traffic to block categories (gambling, malware, newly registered domains), file types or specific content.

- **Centralized proxy:** clients send web traffic through a forward proxy (on-premises or a cloud secure web gateway). Easy to manage in one place; laptops off the corporate network are covered only if their traffic is still forced to the proxy (VPN or a cloud proxy client).
- **Agent-based:** software on the endpoint applies policy wherever the device is: at home, in a hotel, on a phone hotspot. Policy follows the device.

**Data loss prevention (DLP)** finds sensitive data (card numbers, health records, documents with classification labels, source code) by pattern matching, fingerprinting or labels and stops it leaving: blocking an upload, stripping an attachment, encrypting an outbound email, preventing a copy to USB. DLP runs at three places: **network** (inline or proxy, sees data in transit), **endpoint** (agent, sees USB, print, clipboard and uploads even when encrypted traffic would hide them from the network) and **cloud/SaaS** (API connections to the storage or email service). Network DLP cannot read TLS-encrypted traffic unless it is decrypted first.

## Endpoint security: antivirus, EDR, XDR

| | Antivirus (AV) | EDR | XDR |
|---|---|---|---|
| Scope | One endpoint | Endpoints | Endpoints plus email, identity, network, cloud workloads |
| Detection | Mainly signatures and heuristics on files | Behavioral analytics on processes, memory, registry, network connections; continuous telemetry recording | Correlates telemetry from all those sources into one incident |
| Response | Quarantine or delete the file | Kill process, isolate host from the network, roll back, remote investigation | Coordinated response across layers (isolate host, disable account, purge email) |
| Typical question | "Known malware file was quarantined" | "Office spawned encoded PowerShell; isolate ws01" | "Phishing email, then endpoint execution, then risky sign-in: one correlated incident" |

Modern "next-generation antivirus" blurs the AV/EDR line, but the exam distinction holds: AV looks at files for known-bad; EDR records behavior on the endpoint and supports investigation and response; XDR extends detection and response beyond the endpoint.

## Network access control (NAC)

NAC decides whether a device may join the network and what it may reach, based on who the user is and what state the device is in.

**802.1X** is the IEEE standard for port-based access control on wired and wireless networks. Three roles (IEEE 802.1X terms, also used in RFC 3748):

- **Supplicant:** the client device's software requesting access (RFC 3748 calls it the *peer*).
- **Authenticator:** the switch or wireless access point/controller that controls the port. It relays EAP between the supplicant (EAP over LAN, EAPOL) and the server (EAP inside RADIUS), acting as a pass-through.
- **Authentication server:** usually a RADIUS server (Cisco ISE, Aruba ClearPass, FortiAuthenticator, Windows NPS) that runs the EAP method and checks credentials against a directory.

The flow: the port starts unauthorized and passes only EAPOL; the authenticator sends EAP-Request/Identity; the supplicant answers; the authenticator wraps the answer in a RADIUS **Access-Request** (UDP 1812); the server and supplicant run the EAP method (EAP-TLS with certificates, or PEAP with a password inside a TLS tunnel) through RADIUS **Access-Challenge** messages; the server sends **Access-Accept** (or Access-Reject), optionally with attributes such as `Tunnel-Type=VLAN`, `Tunnel-Medium-Type=802` and `Tunnel-Private-Group-ID=<VLAN ID>` (RFC 3580) to assign a VLAN, or a downloadable ACL; the authenticator then authorizes the port. Devices that cannot run a supplicant (printers, cameras) fall back to **MAC Authentication Bypass**, which is weak because MAC addresses are easy to spoof, so such devices belong in a restricted VLAN.

**Captive portals** intercept a new client's web traffic and redirect it to a page where the user logs in, registers or accepts an acceptable use policy before access is granted. Typical for guest Wi-Fi. A captive portal authenticates a person through a browser; it does not encrypt the wireless link.

**Endpoint posture/compliance** checks the device's health before (pre-admission) or during (post-admission) the connection: OS patch level, AV/EDR running and current, disk encryption on, firewall enabled, not jailbroken. Non-compliant devices are put in a **remediation (quarantine) VLAN** where they can reach only update servers.

- **Agent-based** posture uses a persistent agent installed on managed devices; it can check deeply and continuously.
- **Agentless** posture checks without a permanently installed agent, for example a temporary (dissolvable) agent downloaded through the portal, a network scan, or queries to the directory, MDM or EDR platform. It suits BYOD and contractor devices but sees less.

> **Real world:** In FortiNAC, Cisco ISE or ClearPass the policy result is usually a VLAN, a downloadable ACL or a security group tag, not only accept or reject. The exam keeps it simple: authenticate, assess posture, then allow, restrict or remediate.

## Try it yourself

Paper exercise. Write a five-rule firewall policy for a DMZ web server at 203.0.113.10: allow HTTPS from anywhere, allow SSH only from the admin subnet 10.10.99.0/24, allow the server to reach its database 10.10.30.20 on TCP 5432, deny and log everything else. Then put a broad "allow any to 203.0.113.10" rule at the top and work out which of your rules are now shadowed. On Windows, open Windows Defender Firewall with Advanced Security and read the inbound rules; on macOS, read System Settings > Network > Firewall; on Linux, read the `nft` or `firewalld` man pages and compare their rule ordering with first-match ACLs.

## Key takeaways

- IDS alerts out of band; IPS blocks inline. Fail-open keeps traffic flowing uninspected; fail-closed blocks it. NIDS sees the network, HIDS the host, WIPS the airspace.
- Signatures miss the new (false negatives); anomaly detection catches more but raises more false positives.
- Stateful = Layer 4 with session tracking; NGFW adds Layer 7 application and user awareness; WAF protects one web application; UTM bundles many functions in one box. Rules are first match, implicit deny.
- Content filtering via a centralized proxy or an endpoint agent (follows the device); DLP finds and stops sensitive data at network, endpoint and cloud.
- AV = files, known-bad; EDR = endpoint behavior, investigation, isolation; XDR = correlation across endpoint, email, identity, network and cloud.
- 802.1X: supplicant, authenticator, authentication server (RADIUS, EAP). Captive portals for guests; posture checks send non-compliant devices to remediation.
