## Secure communication and access

This half of objective 3.2 is about how people and systems reach resources: tunnels, remote access, administration paths, file transfer and the cloud-delivered security stack. Domain 1 covered the cryptography (IPsec ESP, TLS, SSH); here the question is architectural: which mechanism fits which requirement.

## VPNs and tunneling

A **tunnel** encapsulates one protocol inside another. It does not imply encryption.

| Protocol | Standard | What it does | Encrypts? |
|---|---|---|---|
| **IPsec** with **IKEv2** | RFC 4301 (architecture), RFC 4303 (ESP), RFC 7296 (IKEv2) | IKE (UDP 500, UDP 4500 with NAT traversal per RFC 3948) negotiates keys; ESP protects packets. **Tunnel mode** wraps the whole original IP packet (site-to-site between gateways); **transport mode** protects the payload between two hosts | Yes (ESP) |
| **TLS VPN** ("SSL VPN") | TLS 1.3 (RFC 8446, now RFC 9846) carrying a vendor protocol | Remote-access client or browser portal, usually on TCP 443, which passes most firewalls | Yes |
| **GRE** | RFC 2784 | Generic encapsulation; carries multicast and routing protocols between sites | **No**; often run inside IPsec |
| **L2TP** | RFC 2661 (v2), RFC 3931 (v3) | Layer 2 tunneling | **No**; L2TP/IPsec adds encryption |
| **SSH tunneling** | RFC 4254 (connection protocol) | Local, remote and dynamic port forwarding over an SSH session | Yes |
| **WireGuard** | No IETF RFC (published protocol specification) | Lightweight VPN with fixed modern cryptography | Yes |

**Site-to-site** VPNs join networks (two firewalls building IPsec tunnels). **Remote-access** VPNs join a user's device to a network. Two remote-access choices matter on the exam:

- **Full tunnel:** all of the client's traffic, including internet browsing, goes through the VPN, so corporate web filtering and logging apply. More bandwidth through the head end.
- **Split tunnel:** only traffic for corporate prefixes uses the VPN; the rest goes directly to the internet, unprotected by corporate controls. Better performance, less visibility.

## Remote access

Remote access covers users reaching internal resources and administrators reaching systems. Patterns, best to worst:

- **ZTNA** (per-application access through a broker; previous lesson) or a remote-access VPN with MFA and device posture checks.
- **Jump host / bastion** in a management zone: administrators connect to it (MFA, session recording) and only it can reach management interfaces.
- **Remote desktop gateways** that publish RDP over TLS with MFA, rather than exposing TCP 3389.
- **Never** expose RDP, SSH, Telnet or device management interfaces directly to the internet.

## User management and user access (least privilege)

**User management** is the account life cycle: provisioning when someone joins, changing access when they move roles, deprovisioning promptly when they leave, and periodic **access reviews** (recertification) in which managers confirm each person still needs each entitlement. **User access** should follow **least privilege**: role-based access control (RBAC) grants what a job needs, just-in-time (JIT) elevation grants admin rights for a limited time when a task requires them, and every remote path is restricted to the applications that role uses rather than whole networks.

## End-to-end encrypted messaging

In end-to-end encryption (E2EE) only the communicating endpoints hold the keys; the service provider relays ciphertext it cannot read. This differs from TLS to a messaging server, where the server decrypts each message (hop-by-hop protection). Examples include the Signal protocol and the IETF Messaging Layer Security protocol (MLS, RFC 9420) for group messaging.

Security implications: it protects content from the provider, from a compromised server and from interception; but it also means **network inspection and server-side DLP cannot see content**, so controls move to the endpoint (managed devices, mobile device management, approved apps). Metadata (who talked to whom and when) may still be visible. Organizations that must retain business communications need an approved E2EE platform that supports archiving, not consumer apps.

## Out-of-band management

**In-band** management uses the same network as production traffic. **Out-of-band (OOB)** management uses a separate path: a dedicated management network, console servers connected to device serial or console ports, separate internet circuits or cellular modems, and server baseboard controllers (iDRAC, iLO, IPMI) on an isolated management VLAN. Benefits: you can reach and fix a device when the production network is down or under attack, and management traffic never mixes with user traffic. Risks: the OOB network becomes a privileged back door, so it needs its own strong authentication, MFA, logging and strict access, and baseboard controllers must never be reachable from user networks or the internet.

## File transfer

| Method | Transport | Notes |
|---|---|---|
| **FTP** | TCP 21 (control) plus data channel | Credentials and data in cleartext; avoid |
| **FTPS** | FTP with TLS (RFC 4217); explicit mode on 21, implicit on 990 | Encrypted; multiple ports complicate firewall rules |
| **SFTP** | A subsystem of SSH, TCP 22 | Encrypted; one port. The SFTP protocol itself is defined in IETF drafts, not an RFC |
| **SCP** | Over SSH | Encrypted, simple; OpenSSH now implements `scp` over the SFTP protocol by default |
| **HTTPS** | TLS, TCP 443 | Web upload portals and APIs |
| **Managed file transfer (MFT)** | Usually SFTP/HTTPS | Adds workflow, logging, encryption at rest, integrity checks and partner management |

Choose encrypted, authenticated transfer; use keys or certificates for automated transfers; scan files that arrive from outside; and log every transfer of sensitive data.

## Security Service Edge (SSE)

Gartner introduced **Security Service Edge** as a market category in 2021: a cloud-delivered set of security services that protect users' access to the web, SaaS and private applications wherever the user is. Its core components, as vendors describe them:

- **Secure web gateway (SWG):** URL filtering, malware inspection and TLS inspection for web traffic.
- **Cloud access security broker (CASB):** visibility and control of SaaS use (shadow IT discovery, data controls, configuration checks), inline or through provider APIs.
- **Zero Trust network access (ZTNA):** per-application access to private apps instead of network-level VPN.
- Often also **firewall as a service (FWaaS)** and **data loss prevention (DLP)**.

**SASE** (secure access service edge) = SSE (security) **plus** WAN networking such as SD-WAN. In other words, SSE is the security half of SASE. Fortinet (FortiSASE) and Palo Alto Networks (Prisma Access) both sell SSE/SASE services; the exam only needs the concepts.

## Identity management

### Group Managed Service Accounts (gMSAs)

Services need identities, and classic service accounts are a weak spot: a domain user account with a password set once, never changed, often over-privileged, and known to several admins. A **gMSA** is an Active Directory account for services in which **Windows manages the password**:

- The domain controller computes the password from a key provided by the Key Distribution Service (KDS root key, created once per forest) and other attributes of the account; authorized member hosts retrieve the current and previous password from a DC.
- The password changes automatically, every **30 days** by default (set with `ManagedPasswordIntervalInDays` only when the account is created).
- Unlike a standalone MSA (sMSA), which is tied to **one** computer, a gMSA works across **multiple servers**, such as a web farm behind Network Load Balancing, where every instance must use the same principal.
- Access to the password is limited to the computers or groups named in `PrincipalsAllowedToRetrieveManagedPassword`. Nobody types or knows it.

Setup, per Microsoft Learn: create the KDS root key (once), create the account with `New-ADServiceAccount ... -PrincipalsAllowedToRetrieveManagedPassword <group>`, install and test it on each host (`Install-ADServiceAccount`, `Test-ADServiceAccount`), then configure the service to log on as the gMSA.

### Least privilege access accounts

Administrators should have **separate accounts**: a standard account for email and browsing, and a privileged account used only for administrative tasks, ideally from a dedicated admin workstation or jump host. Privileged access management (PAM) tools add checkout of credentials, JIT elevation, approval and session recording. Service accounts get only the rights the service needs: a backup service account does not need Domain Admins.

### Privilege creep

**Privilege creep** is the gradual accumulation of access beyond what a person's current role needs, typically when people change jobs and gain new rights without losing old ones, or receive "temporary" access that is never removed. It violates least privilege and multiplies the damage a compromised account can do. Controls: a mover process that removes old access when new access is granted, role-based provisioning, expiry dates on exceptions, and periodic access reviews.

## Try it yourself

On any computer: open a terminal (Command Prompt or PowerShell on Windows, Terminal on macOS and Linux) and run `ssh -V` to see whether an SSH client is installed (it ships with current Windows 10/11, macOS and most Linux distributions). Then, on paper, write the command you would use to forward local port 8443 through a bastion `jump.example.com` to an internal console at 10.0.5.10:443 (`ssh -L 8443:10.0.5.10:443 alice@jump.example.com`) and list which firewall rules that path needs. Finally, list the groups your own user account belongs to (`whoami /groups` on Windows, `id` on macOS/Linux) and mark any you no longer need: that is privilege creep.

## Key takeaways

- Tunnels encapsulate; only some encrypt. IPsec (IKEv2 + ESP), TLS VPNs, SSH and WireGuard encrypt; GRE and L2TP do not on their own.
- Full tunnel sends all traffic through corporate controls; split tunnel sends only corporate prefixes.
- Remote administration goes through a bastion or ZTNA with MFA; never expose RDP or management interfaces to the internet.
- E2EE hides content from the provider and from network inspection; controls move to the endpoint.
- Out-of-band management works when production is down, but must be locked down as a privileged network.
- Prefer SFTP, FTPS, HTTPS or MFT over FTP.
- SSE = SWG + CASB + ZTNA (often FWaaS, DLP), cloud-delivered; SASE = SSE + SD-WAN.
- gMSAs: Windows-managed, automatically rotated (30 days by default) service-account passwords usable on multiple servers. Separate admin accounts and access reviews stop privilege creep.
