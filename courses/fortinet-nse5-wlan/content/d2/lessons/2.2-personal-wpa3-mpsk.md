## The `security` setting

Every SSID has one `security` value (`config wireless-controller vap`). FortiOS 7.6.3 accepts:

| Value | Meaning |
|-------|---------|
| `open` | No encryption |
| `wep64`, `wep128` | Legacy WEP — do not use |
| `wpa-personal` / `wpa-enterprise` | WPA/WPA2 mixed |
| `wpa-only-personal` / `wpa-only-enterprise` | WPA (version 1) only |
| `wpa2-only-personal` (**default**) / `wpa2-only-enterprise` | WPA2 only |
| `wpa3-sae` | WPA3-Personal |
| `wpa3-sae-transition` | WPA3-SAE and WPA2-PSK on one SSID |
| `wpa3-only-enterprise` | WPA3-Enterprise, PMF mandatory |
| `wpa3-enterprise-transition` | WPA3-Enterprise, PMF optional |
| `wpa3-enterprise` | WPA3-Enterprise **192-bit**, PMF mandatory (CLI only; the GUI then shows it as WPA3 Enterprise 192-bit) |
| `owe` | Opportunistic Wireless Encryption |
| `osen` | OSU server-only authenticated L2 encryption (Hotspot 2.0) |

Captive portal is **not** a security value in 7.6; it is a separate `set captive-portal enable` that you combine with an open, personal or OWE-style mode (next lesson).

## WPA2-Personal

```text
config wireless-controller vap
    edit "iot-wlan"
        set ssid "IoT"
        set security wpa2-only-personal
        set passphrase "Example-Only-PSK-2"
        set schedule "always"
    next
end
```

* The passphrase must be **8 to 63 characters**.
* `encrypt` is `AES` by default; `TKIP-AES` (with `wpa-personal`) supports very old clients and should be avoided.
* One shared key for everyone: when a user leaves, change the key on every device. Anyone with the key can decrypt captured traffic of other users if they captured their handshake. MPSK and WPA3 address these problems.

## WPA3-Personal: SAE, H2E, SAE-PK and transition

```text
config wireless-controller vap
    edit "corp-wlan"
        set ssid "Corp"
        set security wpa3-sae
        set pmf enable
        set sae-password "Example-Only-SAE-1"
        set schedule "always"
    next
end
```

* **`sae-password`** holds the WPA3 secret (WPA2 modes use `passphrase`).
* **PMF**: WPA3-SAE needs `set pmf enable` (required).
* **`sae-h2e-only enable`** accepts only hash-to-element SAE — required for 6 GHz and for 6 GHz mesh backhaul. (Fortinet's mesh page says it is on by default with `wpa3-sae`, but other references show disable; set it explicitly and check with `show full-configuration`.)
* **SAE-PK** (`set sae-pk enable` + `set sae-private-key`) lets clients verify the AP with a public key bound to the password, defeating evil-twin APs that know the password. FortiOS can generate a matching key and password: `execute wireless-controller create-sae-pk <SSID> <curve>` (curves `prime256v1`, `secp384r1`, `secp521r1`).
* **SAE transition** — `wpa3-sae-transition` with `pmf optional`, **two secrets**: WPA2 clients use `passphrase`, WPA3 clients use `sae-password`.

```text
config wireless-controller vap
    edit "corp-wlan"
        set ssid "Corp"
        set security wpa3-sae-transition
        set pmf optional
        set passphrase "Example-Only-PSK-3"
        set sae-password "Example-Only-SAE-3"
    next
end
```

> **Exam tip:** Transition mode is how you migrate a mixed fleet: WPA3 clients get SAE and PMF, older WPA2 clients still connect. `pmf enable` would lock out WPA2 clients that cannot do PMF, which is why transition uses `optional`.

## OWE and OWE transition

OWE encrypts an "open" network: no password, a Diffie-Hellman exchange gives each client its own keys. It does not authenticate anyone, so pair it with a captive portal or policy controls when you need to know who is connected.

* **OWE only**: `set security owe`, `set pmf enable`. Only OWE-capable (WPA3-era) clients can join.
* **OWE transition**: two VAPs that reference each other. Legacy clients use the visible open SSID; capable clients are steered to a hidden OWE SSID.

```text
config wireless-controller vap
    edit "guest-wlan"
        set ssid "Guest"
        set security open
        set owe-transition enable
        set owe-transition-ssid "Guest-OWE"
    next
    edit "guest-owe"
        set ssid "Guest-OWE"
        set broadcast-ssid disable
        set security owe
        set pmf enable
        set owe-transition enable
        set owe-transition-ssid "Guest"
    next
end
```

## MPSK — multiple pre-shared keys

MPSK gives different users or device groups their own key on **one SSID**, optionally mapping each key group to a VLAN.

* Configured in an **MPSK profile** (`config wireless-controller mpsk-profile`; GUI *WiFi & Switch Controller > Connectivity Profiles > MPSK Profiles*, which appears after you enable **Advanced Wireless Features** in *System > Feature Visibility*).
* `mpsk-type`: `wpa2-personal` (default), `wpa3-sae` or `wpa3-sae-transition` (WPA3 types are new in 7.6.0). Key `key-type` is `wpa2-personal` or `wpa3-sae`.
* Structure: profile → **MPSK groups** (each with `vlan-type no-vlan|fixed-vlan` and `vlan-id`) → **keys** (`passphrase` or `sae-password`, optional `mac` binding, `mpsk-schedules`, concurrent-client limits).
* Apply with `set mpsk-profile` on the VAP. Only **one MPSK profile per VAP**. Enabling MPSK drops the single passphrase and **dynamic VLAN is enabled automatically**.
* Keys can come from an external server: `mpsk-external-server-auth enable` + `mpsk-external-server` (7.6.0 adds self-registration through **FortiGuest**), or RADIUS MAC authentication can return the key as a tunnel password.

```text
config wireless-controller mpsk-profile
    edit "iot-mpsk"
        config mpsk-group
            edit "cameras"
                set vlan-type fixed-vlan
                set vlan-id 300
                config mpsk-key
                    edit "cam-key-1"
                        set passphrase "Example-Only-Cam-1"
                        set mpsk-schedules "always"
                    next
                end
            next
        end
    next
end
config wireless-controller vap
    edit "iot-wlan"
        set ssid "IoT"
        set security wpa2-only-personal
        set mpsk-profile "iot-mpsk"
        set dynamic-vlan enable
    next
end
```

`diagnose wireless-controller wlac -d sta online` shows the `security=` and `mpsk=` fields for each client, and the event log entry "Wireless client authenticated" records which MPSK key a client used.

## PMF settings

```text
set pmf disable | enable | optional
```

* `disable` — default.
* `enable` — PMF **required**; clients without PMF are refused.
* `optional` — PMF used when the client supports it; others still connect.
* Required by `wpa3-sae`, `wpa3-only-enterprise`, `wpa3-enterprise` (192-bit) and `owe`; transition modes use `optional`.
* Related: `pmf-assoc-comeback-timeout`, `pmf-sa-query-retry-timeout`. Beacon protection (`beacon-protection`, default disable) is a further WPA3 feature supported only on specific FortiAP models.

## Choosing a personal mode

| Requirement | Mode |
|-------------|------|
| Modern clients, shared password | `wpa3-sae`, `pmf enable` |
| Mixed WPA2/WPA3 fleet | `wpa3-sae-transition`, `pmf optional` |
| Legacy-only devices | `wpa2-only-personal` (AES) |
| Per-device or per-group keys, key-to-VLAN | MPSK profile |
| Open guest network with encryption | `owe` or OWE transition |
| 6 GHz | `wpa3-sae` with H2E, or `owe` — always PMF |

## Lab it yourself

All of this is controller-side CLI and works on the FortiGate-VM trial: create one VAP per mode, try `set pmf ?`, generate an SAE-PK key with `execute wireless-controller create-sae-pk Corp prime256v1`, and build the MPSK profile above. Client behaviour (which devices connect) needs a FortiAP and a mix of client devices.

## Key takeaways

* Default `security` is `wpa2-only-personal`; WPA2 uses `passphrase` (8–63 characters), WPA3 uses `sae-password`.
* `wpa3-sae` needs `pmf enable`; `wpa3-sae-transition` uses both secrets with `pmf optional`.
* `sae-h2e-only` is required for 6 GHz; SAE-PK protects against evil twins.
* OWE = encryption without authentication; OWE transition pairs an open SSID with a hidden OWE SSID.
* MPSK: one profile per VAP, groups with fixed VLANs, keys with optional MAC binding and schedules; enabling it turns on dynamic VLAN.
* `pmf`: disable (default), enable (required), optional.
