## Why VLANs on wireless

One SSID per user population works until you have six populations and every extra SSID costs airtime. FortiOS lets one SSID place clients into different VLANs — statically, per user from RADIUS, per key with MPSK, per AP group, from a pool, or by NAC policy — so segmentation does not mean more SSIDs.

## Static VLAN on an SSID

`set vlanid <0-4094>` on the VAP (GUI *Optional VLAN ID*; 0 = no VLAN).

* **Local bridge SSID**: the AP tags the SSID's traffic with that VLAN on its Ethernet uplink. The switch port must trunk the VLAN, and the default gateway lives on the wired network.
* **Tunnel SSID**: create VLAN sub-interfaces on the SSID interface on the FortiGate (`set interface "corp-wlan"`, `set vlanid 100`). The `vlanid` on the VAP is then the SSID's default VLAN for clients that get no other assignment.
* The `vlanid` also acts as the **fallback** for dynamic methods: a RADIUS reply without VLAN attributes, or a VLAN pool without a valid VLAN, puts the client in the SSID's `vlanid`.

## Dynamic VLAN assignment by RADIUS

```text
config wireless-controller vap
    edit "corp-wlan"
        set ssid "Corp"
        set security wpa2-only-enterprise
        set auth radius
        set radius-server "RADIUS-NPS"
        set dynamic-vlan enable
        set vlanid 100
    next
end
```

The RADIUS server returns three IETF attributes in the Access-Accept:

| Attribute | Value |
|-----------|-------|
| 64 Tunnel-Type | 13 (VLAN) |
| 65 Tunnel-Medium-Type | 6 (IEEE-802) |
| 81 Tunnel-Private-Group-ID | The VLAN ID (1–4094) |

* No VLAN in the reply → the client lands in the SSID's default VLAN (`vlanid`).
* Each target VLAN must exist: for a **tunnel** SSID, VLAN sub-interfaces of the SSID interface, each with an IP, DHCP server and firewall policies; for a **local bridge** SSID, VLANs trunked to the AP's switch port.
* Works for local bridge and tunnel SSIDs.
* FortiOS can also map RADIUS-returned **VLAN names** (name tags) to VLAN IDs ("VLAN assignment by Name Tag").

```text
config system interface
    edit "corp-v200"
        set vdom "root"
        set ip 10.20.200.1 255.255.255.0
        set allowaccess ping
        set device-identification enable
        set role lan
        set interface "corp-wlan"
        set vlanid 200
    next
end
```

## VLAN by MPSK key

MPSK groups carry `vlan-type fixed-vlan` and `vlan-id`, so the key a device uses decides its VLAN (WPA2-Personal or WPA3-SAE). Enabling an MPSK profile automatically enables dynamic VLAN on the VAP.

## VLAN pooling

`set vlan-pooling` on the VAP, with VLAN IDs under `config vlan-pool`:

| `vlan-pooling` | Behaviour |
|----------------|-----------|
| `disable` | Default; no pool |
| `wtp-group` | **VLAN by FortiAP group**: each pool entry names a FortiAP group; clients get the VLAN of the group their AP belongs to |
| `round-robin` | Load balancing across the pool VLANs |
| `hash` | Load balancing across the pool VLANs by a hash method |

* Load-balancing pools (`round-robin`, `hash`) work **only for tunnel-mode SSIDs**.
* FortiOS automatically puts the pool's VLANs in a **zone named `<ssid-interface>.zone`**, so one set of policies can cover them. You still create each VLAN's addressing and DHCP.
* If the pool contains no valid VLAN ID, the SSID's static `vlanid` is used.

> **Watch out:** Fortinet's own pages describe round-robin two ways (the CLI section says it gives new clients the least busy VLAN; the GUI section says it gives each new device the next VLAN). Expect questions on *which* modes exist and the tunnel-mode restriction, not on the algorithm.

### VLAN by FortiAP group

```text
config wireless-controller wtp-group
    edit "floor1"
        set platform-type 231F
        config wtp-list
            edit "FP231FTF20000001"
            next
        end
    next
    edit "floor2"
        set platform-type 231F
        config wtp-list
            edit "FP231FTF20000003"
            next
        end
    next
end
config wireless-controller vap
    edit "corp-wlan"
        set vlan-pooling wtp-group
        config vlan-pool
            edit 101
                set wtp-group "floor1"
            next
            edit 102
                set wtp-group "floor2"
            next
        end
    next
end
```

Clients on floor-1 APs land in VLAN 101; floor-2 clients in VLAN 102. The same SSID covers the whole building while broadcast domains stay small, and policies can differ by location. Remember that an AP belongs to only one FortiAP group.

## Wireless NAC

FortiOS integrated wireless NAC onboards every client into an **onboarding VLAN**, identifies it, then moves matching clients into a policy VLAN.

1. **VLAN sub-interfaces** under the SSID interface (e.g. `corp-v100` onboarding, `corp-v200` for matched devices).
2. **NAC profile**: `config wireless-controller nac-profile` → `set onboarding-vlan "corp-v100"` (the VLAN *interface name*).
3. **SSID**: `set nac enable` and `set nac-profile "<profile>"` (GUI *NAC profile* on the SSID).
4. **SSID policy**: `config wireless-controller ssid-policy` → `set vlan "corp-v200"`.
5. **NAC policy**: `config user nac-policy` → `set category device | firewall-user | ems-tag`, the matching criteria (MAC, vendor, OS, user group, EMS tag…), and `set ssid-policy "<ssid policy>"`.

```text
config wireless-controller nac-profile
    edit "corp-nac"
        set onboarding-vlan "corp-v100"
    next
end
config wireless-controller vap
    edit "corp-wlan"
        set nac enable
        set nac-profile "corp-nac"
    next
end
config wireless-controller ssid-policy
    edit "printers-vlan"
        set vlan "corp-v200"
    next
end
config user nac-policy
    edit "printers"
        set category device
        set mac "02:1a:2b:3c:4d:5e"
        set ssid-policy "printers-vlan"
    next
end
```

**What the client experiences:** it connects and is placed in the onboarding VLAN. The FortiGate collects device information (Fortinet's example notes this can take up to about two minutes). If the client matches a NAC policy, the controller **disconnects it**; when it **reconnects**, it lands in the policy's VLAN. Non-matching clients stay in the onboarding VLAN.

Verify:

```text
FGT-HQ # diagnose wireless-controller wlac_hlp -c sta-nac
STA (001/001) vfid,mac: 0, 02:1a:2b:3c:4d:5e
    ip                 : 10.20.200.15
    wlan               : corp-wlan(tunnel)
    vlan-id(oper/dflt) : 200/100
    matched nac-policy : printers
```

`vlan-id(oper/dflt)` shows the operational VLAN versus the default (onboarding) VLAN. `diagnose wireless-controller wlac -d sta online` shows each client's `vlan_id=` and `ip=`.

## Choosing a method

| Need | Method |
|------|--------|
| Everyone on an SSID in one VLAN | `vlanid` |
| VLAN per user/role from the directory | RADIUS dynamic VLAN (attributes 64/65/81) |
| VLAN per device group without 802.1X | MPSK groups |
| VLAN per floor/building with one SSID | VLAN pool `wtp-group` |
| Spread a large SSID over several subnets | VLAN pool `round-robin`/`hash` (tunnel only) |
| VLAN by device type, OS, user group or EMS tag | Wireless NAC |

## Key takeaways

* `vlanid` on the VAP: bridge = AP tags on its uplink; tunnel = default VLAN, with VLAN sub-interfaces on the SSID interface; it is the fallback for dynamic methods.
* RADIUS dynamic VLAN: `dynamic-vlan enable`; attributes 64 = 13, 65 = 6, 81 = VLAN ID.
* VLAN pooling: `wtp-group`, `round-robin`, `hash`, `disable` (default); load balancing only for tunnel SSIDs; auto zone `<ssid>.zone`.
* VLAN by FortiAP group uses `vlan-pooling wtp-group` with a `wtp-group` per pool entry.
* Wireless NAC: onboarding VLAN from the NAC profile, then disconnect/reconnect into the SSID policy VLAN; check with `wlac_hlp -c sta-nac`.
