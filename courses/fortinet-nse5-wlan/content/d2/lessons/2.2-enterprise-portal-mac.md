## WPA2 and WPA3 Enterprise

Enterprise modes give every user their own credentials through 802.1X/EAP and unique session keys. A FortiGate SSID can authenticate them two ways:

| `auth` | Where users are checked | Notes |
|--------|-------------------------|-------|
| `radius` + `radius-server <name>` | An external RADIUS server (NPS, FortiAuthenticator, ISE…) | The FortiGate is the RADIUS client; the server must list the FortiGate as a client with the shared secret. Supports EAP-TLS, PEAP, EAP-TTLS — whatever the server supports |
| `usergroup` + `usergroup <group>` | A FortiGate firewall user group (local users and/or remote servers as group members) | With **local** users, Fortinet supports **PEAP only, not EAP-TLS** |

```text
config user radius
    edit "RADIUS-NPS"
        set server "10.0.1.20"
        set secret ENC xxxxxxxx
    next
end
config wireless-controller vap
    edit "corp-wlan"
        set ssid "Corp"
        set security wpa2-only-enterprise
        set auth radius
        set radius-server "RADIUS-NPS"
        set schedule "always"
    next
end
```

The local-group variant:

```text
config wireless-controller vap
    edit "corp-wlan"
        set ssid "Corp"
        set security wpa2-only-enterprise
        set auth usergroup
        set usergroup "wifi-staff"
    next
end
```

### WPA3-Enterprise variants

| `security` | PMF | Notes |
|-----------|-----|-------|
| `wpa3-only-enterprise` | `enable` (mandatory) | WPA3-Enterprise for WPA3 clients |
| `wpa3-enterprise-transition` | `optional` | WPA2- and WPA3-Enterprise clients on one SSID; a WPA3 client negotiates PMF |
| `wpa3-enterprise` | `enable` (mandatory) | **192-bit** mode; not shown in the GUI until configured from the CLI |

All three use `auth radius` or `auth usergroup` like WPA2-Enterprise. From the user's point of view WPA3-Enterprise feels identical to WPA2-Enterprise.

### Enterprise extras worth knowing

* **RADSEC** (RADIUS over TLS/TCP) for WPA2/WPA3-Enterprise SSIDs is new in FortiOS 7.6.0 — configured as a RADSEC client in the FortiOS user settings.
* `roaming-acct-interim-update enable` sends an interim accounting update with the same Acct-Session-Id when a client roams between FortiAPs (for ISE session stitching); only on Enterprise SSIDs.
* `eap-reauth` controls EAP re-authentication on Enterprise SSIDs.
* RADIUS-assigned VLANs (`dynamic-vlan enable`) are covered in the VLAN lesson.
* Captive portal is **not supported** with WPA/WPA2-Enterprise or WPA3-Enterprise modes.

> **Exam tip:** "Authentication works with PEAP but EAP-TLS clients fail, and the SSID uses `auth usergroup` with local users" — local FortiGate users do not support EAP-TLS. Point the SSID at a RADIUS server that does.

## Captive portal

A captive portal intercepts the client's first web request and shows a web page — login, disclaimer, or email collection. The SSID can be open, WPA2/WPA3-Personal or OWE underneath, but never Enterprise.

```text
config wireless-controller vap
    edit "guest-wlan"
        set ssid "Guest"
        set security open
        set captive-portal enable
        set portal-type auth
        set selected-usergroups "guest-users"
        set intra-vap-privacy enable
        set schedule "always"
    next
end
```

### Portal types and traffic modes

| `portal-type` | What the user sees | Traffic mode |
|---------------|--------------------|--------------|
| `auth` | Login page | Tunnel and bridge |
| `auth+disclaimer` | Login, then disclaimer to accept | Tunnel |
| `disclaimer` | Disclaimer only | Tunnel |
| `email-collect` | Email address request (enable *Email Collection* in Feature Visibility) | Tunnel |
| `auth-mac` | MAC-authenticated clients redirected to an external portal (e.g. ISE) | Tunnel (CLI only) |
| `external-auth` | External portal authentication | Bridge (CLI only) |
| `external-macauth` | External portal for MAC authentication | Bridge (CLI only) |
| `cmcc`, `cmcc-macauth` | Carrier-specific | Bridge (CLI only) |

Other portal settings:

* **Local or external portal**: the built-in FortiGate portal, or an external web server (`set external-web <FQDN or URL>`). An external portal posts the credentials back to the FortiGate at `https://<FortiGate IP>:1000/fgtauth` with the `magic` value; `config user setting` → `set auth-secure-http enable` keeps that exchange on HTTPS.
* `selected-usergroups` — who may log in (or use groups from the firewall policy).
* `security-exempt-list` — sources/destinations exempt from the portal (walled garden, e.g. the payment site or the external portal itself).
* `security-redirect-url` — where to send users after login (otherwise their original URL).
* `mac-auth-bypass enable` — clients whose MAC authenticates against local users or RADIUS skip the portal.

### Guest access

FortiOS **Guest Management** creates temporary accounts:

1. Create a **guest user group** (*User & Authentication > User Groups*), with account expiry and credential settings.
2. Create guest accounts in *User & Authentication > Guest Management* and print, email or SMS the credentials to the guest.
3. Configure the guest SSID with captive portal authentication and select the guest group.

Guests can log in until their account expires. Combine with `intra-vap-privacy enable`, a policy that allows only internet access, and a web filter.

## MAC filtering and MAC authentication

### Address-group MAC filter (on the FortiGate)

```text
config firewall address
    edit "printer-01"
        set type mac
        set macaddr "02:1a:2b:3c:4d:5e"
    next
end
config firewall addrgrp
    edit "iot-allowed"
        set member "printer-01"
    next
end
config wireless-controller vap
    edit "iot-wlan"
        set address-group "iot-allowed"
        set address-group-policy allow
    next
end
```

* `address-group-policy`: `disable` (default — the group is ignored), `allow` (only clients in the group may connect) or `deny` (clients in the group are blocked).
* GUI: *SSIDs > Client MAC Address Filtering*.
* MAC addresses are visible over the air and easy to spoof — Fortinet says to use MAC filters **only alongside** real security such as encryption.

### RADIUS MAC authentication

```text
config wireless-controller vap
    edit "iot-wlan"
        set radius-mac-auth enable
        set radius-mac-auth-server "RADIUS-NPS"
    next
end
```

The controller checks the client MAC against the RADIUS server independently of the SSID's other authentication (CLI only). Combined with MPSK, the RADIUS server can return each device's key.

## Protected management frames on these SSIDs

PMF (`set pmf disable|enable|optional`, default disable) is required for WPA3-only and 192-bit Enterprise and optional for the transition modes. It stops forged deauthentication attacks against your users. OKC (`set okc enable`, default enable) caches the PMK so Enterprise clients roaming between APs avoid a full EAP exchange; both are set only in the CLI.

## Lab it yourself

On the FortiGate-VM trial: create `RADIUS-NPS` (a Linux FreeRADIUS VM works as the server), an Enterprise SSID with `auth radius`, a guest SSID with `captive-portal enable` and a guest user group, and a MAC filter address group on an IoT SSID. Testing clients requires a FortiAP; you can still test the RADIUS server from the FortiGate with `diagnose test authserver radius RADIUS-NPS pap <user> <password>`.

## Key takeaways

* Enterprise: `auth radius` + `radius-server`, or `auth usergroup` + `usergroup`; local users support PEAP only.
* WPA3-Enterprise: `wpa3-only-enterprise` (PMF required), `wpa3-enterprise-transition` (PMF optional), `wpa3-enterprise` = 192-bit (PMF required).
* Captive portal: `captive-portal enable` + `portal-type`; not supported with Enterprise modes; disclaimer/email types are tunnel-only.
* Guest Management creates expiring guest accounts delivered by print, email or SMS.
* MAC filter: MAC address objects in a group + `address-group-policy allow|deny` (default disable); weak on its own.
* RADIUS MAC authentication: `radius-mac-auth enable` + `radius-mac-auth-server`.
