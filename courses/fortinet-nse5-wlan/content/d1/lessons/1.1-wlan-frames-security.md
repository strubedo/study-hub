## SSID, BSSID, ESS and VAP

* **SSID** — the network name clients see (up to 32 octets). In FortiOS it is `set ssid` under `config wireless-controller vap`; the default is `fortinet`.
* **BSS / BSSID** — one AP radio serving one SSID forms a basic service set, identified by a **BSSID** (a MAC address). A radio that broadcasts four SSIDs uses four BSSIDs, usually derived from the radio MAC.
* **ESS** — several BSSs with the same SSID and security, joined by a common distribution system, form an extended service set. Clients roam between BSSIDs inside the ESS.
* **VAP** — Fortinet's "virtual access point": the FortiOS object behind an SSID. The VAP name (up to 15 characters, because it becomes an interface name) is separate from the broadcast SSID. In this course the VAP `corp-wlan` broadcasts SSID `Corp`.

`diagnose wireless-controller wlac -c vap` on the FortiGate lists every BSSID with its SSID, VAP interface, the AP's CAPWAP address, radio ID and WLAN ID:

```text
FGT-HQ # diagnose wireless-controller wlac -c vap
bssid             ssid   intf       vfid:ip-port              rId wId
04:d5:90:3a:11:28 Corp   corp-wlan  ws (0-10.10.10.21:5246)   0   0
04:d5:90:3a:11:30 Corp   corp-wlan  ws (0-10.10.10.21:5246)   1   0
06:d5:90:3a:11:30 Guest  guest-wlan ws (0-10.10.10.21:5246)   1   1
```

One AP (10.10.10.21) has three BSSIDs: `Corp` on both radios and `Guest` on radio 1 (rId counts from 0 here).

## Management frames and how a client joins

802.11 has three frame types: **management** (beacons, probes, authentication, association, deauthentication, disassociation, action frames), **control** (RTS/CTS, ACK, block ACK) and **data**.

### Discovering networks

* **Passive scanning** — the AP sends a **beacon** about every 100 time units (~102 ms; FortiOS `beacon-interval` default 100) containing the SSID, supported rates, the RSN (security) element, channel, country and capabilities.
* **Active scanning** — the client sends a **probe request** (to a specific SSID or to the wildcard SSID) and APs answer with **probe responses**.
* A **hidden SSID** (`set broadcast-ssid disable`; default enable) leaves the name out of beacons. Clients must probe for it by name, which leaks the name anyway. Hiding an SSID is not a security control.

### Joining

| Step | Frames | Notes |
|------|--------|-------|
| 1. 802.11 authentication | Authentication request/response | Open System for WPA2 and OWE (no real authentication); **SAE commit/confirm** for WPA3-Personal |
| 2. Association | Association request/response | Client states its capabilities and chosen security (RSN element); AP returns an association ID |
| 3. 802.1X/EAP (Enterprise only) | EAPOL ↔ RADIUS | The client authenticates to a RADIUS server through the AP/controller |
| 4. 4-way handshake | EAPOL-Key 1/4 – 4/4 | Proves both sides hold the PMK, derives the PTK, delivers the GTK |
| 5. IP | DHCP Discover/Offer/Request/Ack | The client can now pass data |

A FortiGate client debug (`diagnose wireless-controller wlac sta_filter <mac> 2`) prints the same order, e.g. `<ih> IEEE 802.11 mgmt::assoc_req <==`, then `<eh> recv EAPOL-Key 2/4 Pairwise`, then `<dc> DHCP Ack`. Domain 4 reads those debugs in detail.

### The 4-way handshake

1. **Message 1** (AP → client): the AP's random **ANonce**.
2. **Message 2** (client → AP): the client's **SNonce** plus a MIC. The client has already computed the **PTK** from PMK + ANonce + SNonce + both MAC addresses.
3. **Message 3** (AP → client): the **GTK** (group key, encrypted) and a MIC; tells the client to install keys.
4. **Message 4** (client → AP): acknowledgement.

The **PMK** comes from different places: in WPA2-Personal it is derived from the passphrase and SSID; in WPA3-Personal it comes out of SAE; in Enterprise mode it comes from the EAP exchange (the RADIUS server sends keying material to the authenticator). A wrong WPA2 passphrase typically shows as message 2 arriving with a bad MIC, followed by retries and failure.

## The security timeline

| Generation | Cipher | Status |
|-----------|--------|--------|
| WEP (64/128-bit) | RC4, static keys | Broken; FortiOS still lists `wep64`/`wep128` for legacy only |
| WPA (TKIP) | RC4 with per-packet keys | Deprecated; Wi-Fi 4 and later rates require CCMP |
| WPA2 (802.11i) | **AES-CCMP** | Current baseline; Personal (PSK) or Enterprise (802.1X) |
| WPA3 | AES-CCMP or GCMP-256 | SAE replaces PSK; PMF mandatory; 192-bit Enterprise mode |

### WPA2

* **WPA2-Personal**: one pre-shared passphrase (8–63 ASCII characters or 64 hex digits) for everyone. Anyone who captures a 4-way handshake can run an **offline dictionary attack** against it.
* **WPA2-Enterprise**: each user authenticates with 802.1X/EAP; keys are unique per session.
* FortiOS default for a new SSID: `security wpa2-only-personal` with `encrypt AES`. `set encrypt TKIP-AES` exists for very old clients.

### WPA3

* **WPA3-Personal (SAE)**: Simultaneous Authentication of Equals (Dragonfly) replaces the PSK exchange. An eavesdropper cannot run an offline dictionary attack, and each session has forward secrecy.
* **H2E** (hash-to-element) is the newer way to derive the SAE password element, replacing the "hunting and pecking" loop; it is required in 6 GHz. FortiOS: `sae-h2e-only`.
* **SAE-PK** adds a public key bound to the password so clients can detect an evil twin that knows the password. FortiOS: `sae-pk` with `sae-private-key`.
* **Transition mode** lets WPA2-PSK and WPA3-SAE clients share one SSID; PMF is optional (capable) so WPA2 clients can still join.
* **WPA3-Enterprise** comes in three flavours: WPA3-Enterprise only (PMF required), WPA3-Enterprise transition (PMF optional), and **192-bit mode** (GCMP-256 and SHA-384 suites, EAP-TLS with CNSA-grade cipher suites, PMF required).
* **OWE** (Opportunistic Wireless Encryption, Wi-Fi "Enhanced Open") encrypts an open network with an unauthenticated Diffie-Hellman exchange: no password, but traffic is not readable by other users. **OWE transition** pairs an open SSID with a hidden OWE SSID for older clients.
* The Wi-Fi Alliance requires WPA3 for Wi-Fi 6 and Wi-Fi 7 certification, and allows only WPA3 or OWE in 6 GHz.

### PMF (802.11w)

Protected Management Frames sign deauthentication, disassociation and robust action frames so an attacker cannot simply forge a deauth to kick clients off. PMF is mandatory for WPA3 and for 6 GHz. FortiOS: `set pmf disable | enable | optional` (default `disable`; `enable` = required, `optional` = capable).

## 802.1X and EAP

| Role | Who in a FortiAP network |
|------|--------------------------|
| **Supplicant** | The wireless client |
| **Authenticator** | The AP/wireless controller. With a FortiGate controller, the FortiGate is the RADIUS client (NAS), so the RADIUS server must list the FortiGate as a client |
| **Authentication server** | RADIUS (e.g. Windows NPS, FortiAuthenticator) — or the FortiGate's own user database with `auth usergroup` |

EAP runs between supplicant and server; the authenticator relays it (EAPOL over the air, RADIUS on the wire).

| EAP method | Credentials | Notes |
|-----------|-------------|-------|
| **EAP-TLS** | Client and server certificates | Strongest; needs a PKI to issue client certificates |
| **PEAP (MSCHAPv2)** | Server certificate + username/password | Password exchange runs inside a TLS tunnel; very common with AD |
| **EAP-TTLS** | Server certificate + inner method (PAP, MSCHAPv2…) | Flexible inner methods |
| EAP-FAST | PAC or certificates | Cisco-originated |

Clients should validate the server certificate in PEAP/TTLS; otherwise a rogue AP with a fake RADIUS server can harvest credentials.

> **Exam tip:** When a FortiGate authenticates WPA2/WPA3-Enterprise users against **local** user groups, Fortinet supports **PEAP only, not EAP-TLS**. Use RADIUS for EAP-TLS.

## Roaming helpers (preview)

These live on the SSID in FortiOS and are covered in Domain 3:

* **802.11r** Fast BSS Transition (`fast-bss-transition`, default disable) — pre-computes keys so a roam skips the full handshake/EAP.
* **802.11k** (`80211k`, default enable) — neighbour reports so clients know which APs to scan.
* **802.11v** (`80211v`, default enable) — BSS transition management: the network can suggest a better AP.
* **OKC** (`okc`, default enable) — the cached PMK is shared across APs so an Enterprise client avoids a full EAP exchange when it roams.

## Key takeaways

* SSID = network name; BSSID = radio MAC for one SSID on one radio; VAP = FortiOS object/interface for an SSID.
* Join sequence: (probe) → 802.11 authentication → association → [802.1X/EAP] → 4-way handshake → DHCP.
* WPA2 uses AES-CCMP; WPA2-Personal is open to offline dictionary attacks; WPA3-SAE is not and adds forward secrecy.
* WPA3 and 6 GHz require PMF; FortiOS `pmf` default is disable.
* 802.1X roles: supplicant, authenticator (FortiGate as RADIUS client), authentication server.
* EAP-TLS = certificates both sides; PEAP-MSCHAPv2 = server certificate + password. FortiGate local groups support PEAP, not EAP-TLS.
