## What a FortiAP profile is

A **FortiAP profile** (`config wireless-controller wtp-profile`, GUI *WiFi & Switch Controller > FortiAP Profiles*) is the complete configuration for an AP model: platform, country, management access, data channel security, load balancing, and every radio's mode, band, channels, width, power, DARRP and SSIDs. Many APs share one profile, so you change dozens of APs with one edit.

* FortiOS ships a built-in **default profile per model** (for example `FAP231F-default`, `FAP431G-default`). An AP gets its model's default when it is authorized, unless you assign another profile.
* A profile is tied to a **platform** (`config platform` → `set type 231F`). You need **one profile per FortiAP model**; a FAP431G cannot use a 231F profile.
* Assign a profile on the AP entry: `config wireless-controller wtp` → `edit <serial>` → `set wtp-profile <name>`, or select several APs in the GUI and use *Assign Profile*.

```text
FGT-HQ # config wireless-controller wtp-profile
FGT-HQ (wtp-profile) # edit "FAP231F-office"
FGT-HQ (FAP231F-office) # config platform
FGT-HQ (platform) # set type 231F
FGT-HQ (platform) # end
FGT-HQ (FAP231F-office) # set ap-country NA
FGT-HQ (FAP231F-office) # set dtls-policy clear-text
FGT-HQ (FAP231F-office) # config radio-1
FGT-HQ (radio-1) # set band 802.11ax-2G
FGT-HQ (radio-1) # set channel "1" "6" "11"
FGT-HQ (radio-1) # set darrp enable
FGT-HQ (radio-1) # set vap-all manual
FGT-HQ (radio-1) # set vaps "corp-wlan" "guest-wlan"
FGT-HQ (radio-1) # end
FGT-HQ (FAP231F-office) # config radio-2
FGT-HQ (radio-2) # set band 802.11ax-5G
FGT-HQ (radio-2) # set channel-bonding 40MHz
FGT-HQ (radio-2) # set darrp enable
FGT-HQ (radio-2) # set vap-all tunnel
FGT-HQ (radio-2) # end
FGT-HQ (FAP231F-office) # end
```

### Profile-level settings worth knowing

| Setting | Meaning |
|---------|---------|
| `config platform` → `type`, `mode`, `ddscan` | Model; on supported tri-radio models the CLI Reference describes `mode single-5G` (default: one 5 GHz, one 2.4 GHz and one dedicated monitor/sniffer radio) and `dual-5G` (lower 5 GHz, higher 5 GHz and 2.4 GHz); `ddscan` uses one radio for dedicated full-band scanning |
| `ap-country` | Country for these APs; default `NA` = use the VDOM's country |
| `indoor-outdoor-deployment` | Changes which channels are allowed; default `platform-determined` |
| `allowaccess`, `login-passwd-change`/`login-passwd` | Management access (https, ssh, snmp) and the AP admin password |
| `dtls-policy` | CAPWAP data channel security (default `clear-text`) |
| `frequency-handoff`, `ap-handoff`, `handoff-rssi`, `handoff-sta-thresh` | Client load balancing (Domain 3) |
| `max-clients` | Client limit for the AP (default 0 = no limit) |
| `ext-info-enable` | Extended station/VAP/radio information for `diagnose wireless-controller wlac -d …` |
| `unii-4-5ghz-band` | UNII-4 channels on G-series (default disable) |
| `split-tunneling-acl…` | Remote AP split tunnelling |

## Radio settings

Each radio is configured under `config radio-1` … `config radio-4` (only as many as the model has).

| Setting | Values (default) |
|---------|------------------|
| `mode` | `ap` (default), `monitor` (dedicated rogue AP/WIDS scanner), `sniffer` (captures frames over the air), `sam` (connects to a neighbouring AP as a station to test the network), `disabled` |
| `band` | e.g. `802.11n-2G`, `802.11ac-5G`, `802.11ax-5G`, `802.11ax-6G`, `802.11be-6G` — limited by radio hardware; two radios of a dual-radio AP cannot use the same band |
| `channel` | The channel list the radio may use (DARRP chooses among them) |
| `channel-bonding` | `20MHz` (default), `40MHz`, `80MHz`, `160MHz`, `240MHz`, `320MHz` |
| `darrp` | DARRP on this radio (default **disable**) |
| `arrp-profile` | Which ARRP profile tunes DARRP for this radio |
| `power-mode` | `percentage` (default) or `dBm` — values are EIRP |
| `power-level` | 0–100 % (default 100) when `power-mode percentage` |
| `power-value` | 1–33 dBm (default 27) when `power-mode dBm` |
| `auto-power-level`, `auto-power-high`, `auto-power-low` | Automatic transmit power between low and high dBm bounds (defaults 10 and 17) to reduce co-channel interference |
| `vap-all` | `tunnel` (default), `bridge`, `manual` — how SSIDs are assigned |
| `vaps` | SSIDs (and SSID groups) when `vap-all manual` |
| `wids-profile` | WIDS profile for this radio (Domain 3) |
| `zero-wait-dfs` | Default enable |
| `bss-color`, `bss-color-mode` | 802.11ax BSS colour (0 = disabled; mode `auto` by default) |

> **Watch out:** The 7.6.3 CLI Reference is inconsistent about the default of `auto-power-level` (its text says enable, its default column says disable). Check with `get` on your own FortiGate rather than relying on a memorised default.

The GUI calls `power-mode` *Transmit power mode* (Percent, dBm or Auto) and offers **channel plans** on 2.4 GHz radios: *Three Channels* (1, 6, 11), *Four Channels* (1, 4, 8, 11) or *Custom*.

### Assigning SSIDs to radios

* `vap-all tunnel` (the default) — every **tunnel-mode** SSID is automatically broadcast on that radio, including ones you create later.
* `vap-all bridge` — every **local-bridge** SSID is automatically broadcast. (Not available on FortiWiFi local radio, which has no bridge mode.)
* `vap-all manual` — only the SSIDs and **SSID groups** listed in `vaps`.

> **Exam tip:** Because the default is `vap-all tunnel`, a new tunnel-mode SSID appears on every radio that still uses the default — often a surprise. Use `manual` when SSIDs must go only to some radios or bands (for example, a 2.4 GHz-only IoT SSID).

**SSID groups** (`config wireless-controller vap-group`, `set vaps "ssid1" "ssid2"`) bundle SSIDs so a radio can reference the group like a single SSID. Groups contain SSIDs, not other groups.

## Per-AP overrides

When one AP needs something different, override on the AP entry instead of cloning a profile. Each radio under `config wireless-controller wtp` has four overrides:

```text
FGT-HQ # config wireless-controller wtp
FGT-HQ (wtp) # edit "FP231FTF20000001"
FGT-HQ (FP231FTF20000001) # config radio-2
FGT-HQ (radio-2) # set override-channel enable
FGT-HQ (radio-2) # set channel "149"
FGT-HQ (radio-2) # set override-txpower enable
FGT-HQ (radio-2) # set power-mode dBm
FGT-HQ (radio-2) # set power-value 14
FGT-HQ (radio-2) # end
FGT-HQ (FP231FTF20000001) # end
```

* Radio overrides: `override-band` (overriding the band also means you must set the channels), `override-channel`, `override-txpower`, `override-vaps` (SSIDs).
* AP-level overrides: `override-allowaccess`, `override-login-passwd-change`, `override-led-state`, `override-wan-port-mode`, `override-ip-fragment`, `override-split-tunnel`, `override-lan`.
* An override wins over the profile for that AP only; the GUI shows the profile's value when the override is off.

## DARRP

**Distributed Automatic Radio Resource Provisioning** lets each AP choose its best channel automatically.

How it works (FortiAP 7.6 guide):

1. **Channel selection on the AP** — channels exceeding thresholds are excluded, using AP scans and spectral scans: `threshold-ap` (250 neighbouring APs), `threshold-noise-floor` (−85 dBm), `threshold-channel-load` (60 %), `threshold-spectral-rssi` (−65 dBm).
2. **Channel scoring on the controller** — only if every channel was excluded. Weights (`weight-managed-ap` 50, `weight-rogue-ap` 10, `weight-noise-floor` 40, `weight-channel-load` 20, `weight-spectral-rssi` 40, `weight-weather-channel` 0, `weight-dfs-channel` 0) score the channels; the lowest score wins, ties are random.
3. **Monitoring** — the AP watches TX retries and RX errors over `monitor-period` (300 s); exceeding `threshold-tx-retries` (300 %) or `threshold-rx-errors` (50 %) triggers a new selection.

Triggers: radio activation and the optimisation schedule. `selection-period` (3600 s) is the history window used for channel load, noise floor and spectral RSSI. `include-dfs-channel` and `include-weather-channel` (both default enable) decide whether those channels are candidates. With 40 MHz or wider bonding DARRP considers the channel width.

Timing lives under `config wireless-controller setting`:

* `darrp-optimize` — interval in seconds between runs inside the schedule (default **86400**, 0 = disable).
* `darrp-optimize-schedules` — firewall schedule(s); default `default-darrp-optimize` (01:00–01:30 daily).
* An ARRP profile can replace both with `override-darrp-optimize enable` plus its own `darrp-optimize` and `darrp-optimize-schedules`.

```text
FGT-HQ # config wireless-controller arrp-profile
FGT-HQ (arrp-profile) # edit "arrp-office"
FGT-HQ (arrp-office) # set include-dfs-channel disable
FGT-HQ (arrp-office) # set threshold-channel-load 50
FGT-HQ (arrp-office) # next
FGT-HQ (arrp-profile) # end
```

Then reference it per radio with `set arrp-profile "arrp-office"` (and `set darrp enable`). Without an explicit `arrp-profile`, a radio with DARRP enabled uses the default ARRP profile.

> **Real world:** Channel changes briefly disrupt clients. Keep the optimisation in a quiet maintenance window (the default 01:00–01:30) rather than running it often.

Check DARRP with `diagnose wireless-controller wlac -c darrp` (AP serial, radio, number of candidate channels, operating channel). FortiAIOps **AI-ARRP** builds on DARRP (`ai-darrp-support`); see Domain 3.

## FortiAP groups

A **FortiAP group** (`config wireless-controller wtp-group`, GUI *Managed FortiAPs > Create New > Managed AP Group*) collects APs, for example by floor:

```text
FGT-HQ # config wireless-controller wtp-group
FGT-HQ (wtp-group) # edit "floor2"
FGT-HQ (floor2) # set platform-type 231F
FGT-HQ (floor2) # config wtp-list
FGT-HQ (wtp-list) # edit "FP231FTF20000001"
FGT-HQ (FP231FTF20000001) # next
FGT-HQ (wtp-list) # end
FGT-HQ (floor2) # end
```

* An AP belongs to **one group only**.
* Uses: filter the Managed FortiAPs view; target `execute wireless-controller reset-wtp` or `rolling-wtp-upgrade` at a group; and assign **VLANs by FortiAP group** through VLAN pooling (`vlan-pooling wtp-group`, Domain 2).

## Lab it yourself

Everything on this page except watching radios change channel works on the FortiGate-VM trial:

1. Create `FAP231F-office` with the CLI above; use `set band ?` and `set channel ?` to see platform limits.
2. Create an ARRP profile and attach it to radio 2; `show` the profile.
3. Pre-authorize `FP231F****000001` with your profile, override radio 2's channel and power, then `show` the `wtp` entry.
4. Create a FortiAP group and an SSID group and reference the SSID group in `vaps`.

## Key takeaways

* One FortiAP profile per model; each model has a built-in `FAP<model>-default`.
* Radio `mode`: ap (default), monitor, sniffer, sam, disabled. `channel-bonding` defaults to 20MHz; power is EIRP, default 100 %.
* `vap-all tunnel` (default) auto-assigns all tunnel SSIDs; `manual` + `vaps` picks SSIDs or SSID groups.
* Per-AP overrides: band, channel, txpower and vaps per radio, plus several AP-level settings.
* DARRP is off by default per radio; it excludes channels by threshold (AP count 250, noise −85, load 60 %, spectral −65) and runs by default from 01:00–01:30 daily (`darrp-optimize` 86400).
* An AP can be in only one FortiAP group; groups drive resets, rolling upgrades and VLAN-by-group.
