## Two ways to manage a FortiAP

| | FortiGate integrated controller | FortiEdge Cloud |
|--|--|--|
| Where the controller runs | On the FortiGate/FortiWiFi | Fortinet's cloud |
| Typical use | Sites with a FortiGate; tunnel-mode SSIDs inspected by the firewall | Standalone APs (no FortiGate on site), many small sites |
| AP discovery | Static, DHCP 138, DNS, multicast, broadcast | Cloud discovery through `apctrl1.forticloud.com` |
| Licensing | Included with FortiGate | Per managed device; the SSID pages note that dynamic VLAN, blocking intra-SSID traffic and custom radio/rate settings need a FAP Advanced Management License |

The exam description names "FortiEdge Cloud management", so know its workflow. Note the product's status: the FortiEdge Cloud documentation (26.3) says it is transitioning to **FortiManagement Cloud** — from 8 September 2026 FortiEdge Cloud capabilities are part of FortiManagement Cloud, 26.3.a is the last standalone release, and the FortiEdge Cloud portal stays available until the end of 2026. The FortiAP 7.6 guide already calls the cloud discovery method "FortiManagement Cloud". The concepts below apply to both names.

## FortiEdge Cloud building blocks

* **FortiCloud account** — you sign in to FortiEdge Cloud with your FortiCloud account.
* **Inventory** — devices registered to the account (*Devices > Inventory Devices*). Registering an AP to the account does not yet configure it.
* **Network** — a logical grouping of FortiAP, FortiSwitch and FortiExtender devices that share configuration (for example, one network per office). An account can have many networks; Fortinet recommends several independent networks rather than one huge one.
* **Site** — a subset of devices inside a network (for example, one site per floor) for applying configuration to part of a network.
* **SSIDs, platform profiles, AP tags** — configured per network. An SSID can go to all APs or only APs with certain tags; platform profiles carry radio settings per model.

## Onboarding workflow

1. **Register on FortiCloud** and open FortiEdge Cloud.
2. **Add the FortiAP to the inventory**:
   * *With a key*: register the device using its FortiCloud key (printed on a sticker) or its registration code/serial number.
   * *Without a key* (older models): upgrade the AP to supported firmware, log in to the AP's own GUI (default `https://192.168.1.2`, user `admin`, empty password), set **AC Discovery Type** to **FortiAP Cloud** and enter the FortiEdge Cloud account name and password. Once the AP has internet access it appears in the inventory.
3. **Create a network** (and optionally sites).
4. **Deploy** the AP: in *Inventory Devices* select it, *Actions > Deploy*, choose **Deploy to FortiEdge Cloud** (the other choice is an external AP controller, i.e. a FortiGate) and pick the network. You can set the platform profile, AP tags, site and admin settings, and enable **Upgrade APs upon Connect** so the AP moves to a chosen firmware when it first connects.
5. **Add SSIDs** to the network (*Configuration > SSID*): choose an authentication method (WPA2-Personal, WPA2-Enterprise, WPA3-SAE/transition, WPA3-Enterprise variants, WPA3-OWE, FortiEdge Cloud captive portal or your own captive portal), security options, then availability (radios, all APs or tagged APs, schedule).

### What the AP needs through the upstream firewall

* DNS (port 53) to resolve the cloud host names.
* The **dispatcher** `apctrl1.forticloud.com` (also `apctrl1.fortinet.com`) over **HTTPS/TCP 443**, which tells the AP which regional AP portal to use.
* The regional AP portal (`<region>apportal…fortiedge.forticloud.com`): **TCP 443, 514 and 8443** and **UDP 5246 and 5247** (CAPWAP).

> **Exam tip:** A cloud-managed AP is still a CAPWAP AP. If its site firewall blocks UDP 5246/5247 outbound, it can reach the dispatcher over HTTPS but never finishes joining the cloud controller.

## Registering a FortiGate-managed AP to FortiCloud

A FortiAP that the FortiGate already manages can be registered to your FortiCloud account from the FortiGate: *Managed FortiAPs*, right-click the AP, *Registration*, *Register*, enter the FortiCloud credentials. Registration can take up to 30 minutes. This registers the asset (support contract, inventory); it does not move management to the cloud.

## FortiAP firmware management on the FortiGate

FortiAP firmware must be compatible with the FortiOS version; check the FortiAP release notes. Six methods appear in the 7.6 guide:

| Method | How |
|--------|-----|
| **Upgrade on authorization** | *WiFi Settings > FortiAP auto firmware provisioning*, or `config wireless-controller setting` → `set firmware-provision-on-authorization enable` (default disable). Each newly authorized AP gets `firmware-provision-latest once` and is upgraded one time to the latest compatible image from FortiGuard |
| **Automatic patch upgrades** | *System > Firmware & Registration*; `config system fortiguard` → `set auto-firmware-upgrade enable` with day/hour window. Upgrades FortiGate, FortiSwitch and FortiAP **patch** releases directly to the target without following an upgrade path |
| **GUI, per AP** | *Managed FortiAPs*, right-click > *Upgrade*; image from FortiGuard or an uploaded file. The AP reboots |
| **CLI, all APs at once** | Upload once, then reset the APs so they download it when they rejoin |
| **Directly on the AP** | From the AP CLI: `restore <image> <tftp-server-ip>` — no controller needed |
| **Rolling (hitless) upgrade** | Upgrades APs in batches so neighbours keep serving clients |

CLI method (the only method the guide describes for upgrading every AP at once):

```text
FGT-HQ # execute wireless-controller upload-wtp-image tftp FP231F-v7.6-build0123.out 10.0.1.50
FGT-HQ # execute wireless-controller list-wtp-image
FGT-HQ # execute wireless-controller reset-wtp all
```

`reset-wtp` takes `all`, a serial number or a FortiAP group name. The download happens at join time because `image-download` is enabled by default (globally under `config wireless-controller global` and per AP under `config wireless-controller wtp`). Per AP you can also pin a version with `set firmware-provision 7.6.<build>`. `execute wireless-controller push-wtp-image <vdom> <wtp-id> <filename>` pushes an uploaded image to one AP, and `delete-wtp-image` removes images.

### Rolling upgrade

```text
FGT-HQ # config wireless-controller global
FGT-HQ (global) # set rolling-wtp-upgrade enable
FGT-HQ (global) # end
FGT-HQ # execute wireless-controller rolling-wtp-upgrade all
```

* `rolling-wtp-upgrade` default **disable**; it can also be set per VDOM under `wireless-controller setting`.
* `rolling-wtp-upgrade-threshold` (default −80 dBm) decides which neighbouring APs count as covering each other.
* APs waiting their turn show *ISSU queued*. Monitor with `diagnose wireless-controller wlac -c ap-upd`.
* The target accepts `all`, a serial or a FortiAP group.

### FortiEdge Cloud firmware

In FortiEdge Cloud, upgrade one AP from *Actions > Upgrade Firmware* (choose build and schedule) — the AP reboots, so clients are interrupted. **Scheduled Upgrades** profiles upgrade fully deployed APs by model, site, tag, device or platform profile, once or on a recurring schedule, with an optional *Force Downgrade*. Newly deployed APs are handled by the platform profile's upgrade-on-connect setting.

## Getting into a FortiAP

* **From the FortiGate**: *Managed FortiAPs*, right-click > *Connect to CLI* opens an SSH console to the AP.
* **Management access**: the FortiAP profile's `allowaccess` (`https`, `ssh`, `snmp`) controls access to the APs; override for one AP with `set override-allowaccess enable` and `set allowaccess ssh` under `config wireless-controller wtp`.
* **AP password**: set it through the profile (`login-passwd-change yes` + `login-passwd`), or override per AP. Factory default is `admin` with an empty password.
* **Configuration mode** (FortiAP-S, FortiAP-W2 and E models): holding the reset button 5–10 seconds on a running AP makes it broadcast an open SSID `FAP-config-<serial>` at 1 dBm for one client; browse to `https://192.168.100.1`. It exits after 30 minutes or a reboot. Less than 5 seconds reboots; more than 10 seconds factory-resets.

## Lab it yourself

* FortiGate-VM trial: `execute wireless-controller list-wtp-image` (empty), then explore `config wireless-controller setting` → `set firmware-provision-on-authorization ?` and `config wireless-controller global` → `set rolling-wtp-upgrade ?`. Uploading an image needs a TFTP/FTP server and a FortiAP image from the support site.
* With a FortiAP and a FortiCloud account you can practise inventory, network, deploy and SSID creation (check Fortinet's current licensing terms first). Check the current FortiManagement Cloud menus, since the GUI is being remapped.

## Key takeaways

* FortiEdge Cloud manages standalone FortiAPs; it is being folded into FortiManagement Cloud (portal available until end of 2026).
* Cloud workflow: FortiCloud account → inventory (key or "FortiAP Cloud" discovery) → network/site → deploy → SSIDs.
* Cloud APs need DNS, HTTPS to `apctrl1.forticloud.com`, and UDP 5246/5247 to the regional portal.
* FortiGate firmware options: on authorization (`firmware-provision-on-authorization`, default disable), automatic patch upgrades, GUI per AP, CLI `upload-wtp-image` + `reset-wtp`, AP `restore`, rolling upgrade.
* Rolling upgrade is disabled by default; threshold −80 dBm; `exec wireless-controller rolling-wtp-upgrade all|SN|group`.
* `image-download` (default enable) lets APs fetch new firmware when they rejoin the controller.
