## The three monitors

FortiOS gives you three places to watch a wireless network from the FortiGate GUI. Know which question each one answers.

| Monitor | Path | Answers |
|---|---|---|
| **Managed FortiAPs** | WiFi & Switch Controller > Managed FortiAPs | Is each AP authorised and online? Which profile, firmware, channel, clients? |
| **WiFi Clients** | WiFi & Switch Controller > WiFi Clients | Who is connected, where, how well? |
| **Rogue APs** | Dashboard > WiFi > Rogue APs | What else is on the air and is it on my wire? (previous lessons) |

Above them sits the **WiFi dashboard** (Dashboard > WiFi), a customisable set of widgets:

| Widget | Shows |
|---|---|
| FortiAP Status | Online/offline and other AP states |
| Clients By FortiAP | Client count per AP |
| Historical Clients | Client count over the selected time frame |
| Channel Utilization | Per-radio channel utilisation of your FortiAPs |
| Interfering APs | FortiAPs that report interfering (neighbour) APs |
| Login Failures | WiFi authentication failures |
| Signal Strength | Client signal strength, useful for spotting clients at the edge of coverage |
| Rogue APs | The rogue list |

Use **+ Add Widget** to bring back any you removed.

## Managed FortiAPs and Diagnostics and Tools

The Managed FortiAPs list is where you authorise, deauthorise, upgrade and restart APs, and it shows each AP's state, profile, connected clients, channel and version. Right-click an AP and choose **Diagnostics and Tools** for a single-AP view:

* Top left: configuration and connection summary, with an **Actions** menu (Authorize/Deauthorize, Upgrade, Restart, LED blink) and Edit.
* Top right: an overall **health assessment**, also broken down per radio band.
* Bottom tabs: **Radios**, **Clients** and a filtered **Logs** view for that AP.
* **Show in WiFi Maps** if you placed the AP on a floor plan. From that same right-click menu, **Connect to CLI** opens the FortiAP's own shell, and some models show **Spectrum Analysis** when a radio is in Dedicated Monitor mode.

## The WiFi Clients monitor

Default columns include the SSID, the FortiAP serial number, client IP, MAC address (FortiGate only), device and user names, **channel**, **bandwidth Tx/Rx**, **association time**, **signal strength** and **signal strength/noise** (the signal-to-noise ratio in dB). Hover a column header and click the gear to add more. Double-click a client to drill into its applications, destinations, policies and logs, and from that summary you can **Quarantine** the host (block it) or **Disassociate** it (kick it off; it may reconnect).

The client summary also scores **Health** from three conditions:

| Condition | Good | Fair | Poor |
|---|---|---|---|
| Signal strength | stronger than -56 dBm | between -56 and -75 dBm | weaker than -75 dBm |
| Signal strength/noise (SNR) | above 39 dB | 20 to 39 dB | below 20 dB |
| Band | 5 GHz | 2.4 GHz | |

Overall health is **Good** only if all three are Good; if any condition is Fair or Poor, the overall result drops accordingly. (Fortinet's table writes the SNR bands in "dBm"; a ratio is in dB.)

> **Exam tip:** A client at -62 dBm with 33 dB SNR on 5 GHz is **Fair**, not Good: both its signal and its SNR fall in the Fair bands. One Fair condition is enough to lose Good.

## Other monitoring channels

* **SNMP from the FortiAP itself.** `config wireless-controller snmp` defines communities, SNMPv3 users and CPU/memory trap thresholds per VDOM, and you allow it on the APs with `append allowaccess snmp` in the FortiAP profile. Traps include `fapDevUp`, `fapDevDown`, `fapCpuOverload`, `fapMemOverload` and `fapAcConnected`. You need the FortiAP MIB and the Fortinet Core MIB. Not supported in local standalone mode.
* **Syslog from the FortiAP.** `config wireless-controller syslog-profile` (server IP or FQDN, port, log level), assigned with `set syslog-profile` in the FortiAP profile. Verify on the AP with `cw_diag -c syslog config`.
* **Temperature.** FortiAPs with a sensor report CPU junction temperature (not ambient): `cw_diag -c temperature` on the AP, or filter the controller's `diagnose wireless-controller wlac -c wtp <SN>` output for "Temp".
* **Event logs.** Wireless events go to Log & Report > System Events > **WiFi Events** (Domain 4 covers reading them). `config wireless-controller log` sets the lowest severity per category (`rogue-event-log`, `sta-event-log`, `wtp-event-log`, `wids-log`, `radio-event-log`, `clb-log`...; all default notification).

## FortiAP REST API

FortiAPs expose a small REST API over HTTPS on the AP's own address, separate from the FortiOS API on the FortiGate. Fortinet's guide documents it for FortiAP-S and FortiAP-W2 6.2.0 and later; the full schema is on the Fortinet Developer Network (account required). You log in first, then call `/api/v1/...` endpoints:

| Call | Method | Path | Purpose |
|---|---|---|---|
| logincheck | POST | `/logincheck` | Log in (with or without a password) |
| logout | POST | `/logout` | Log out |
| sys-status | GET | `/api/v1/sys-status` | System status (the equivalent of `fap-get-status`) |
| sys-perf | GET | `/api/v1/sys-perf` | CPU and memory usage |
| cfg-get | GET | `/api/v1/cfg-get` | Effective FortiAP variables; filter with `?names=WTP_NAME,ADMIN_TIMEOUT` |
| cfg-meta-get | GET | `/api/v1/cfg-meta-get` | List all variables |
| cfg-set | POST | `/api/v1/cfg-set` | Add or change variables (the API equivalent of `cfg -a`) |
| wtp-cfg | GET | `/api/v1/wtp-cfg` | AP configuration in the control plane |
| radio-cfg | GET | `/api/v1/radio-cfg?rId=1` | Radio configuration, optionally one radio |
| vap-cfg | GET | `/api/v1/vap-cfg?rId=0&wId=1` | SSIDs per radio, optionally one WLAN |
| reboot | POST | `/api/v1/reboot` | Reboot the AP |

A `GET https://10.10.10.21/api/v1/sys-perf` returns JSON such as `{"cpu_usage": 3, "memory_usage": 58}`. Note the pattern: read operations are GET, anything that changes state (log in, set variables, reboot) is POST.

The read-only endpoints mirror FortiAP CLI commands: `wtp-cfg`, `radio-cfg` and `vap-cfg` return the same control-plane data as `cw_diag -c wtp-cfg`, `radio-cfg` and `vap-cfg`. That makes the API handy for scripted health checks across many APs, especially where SSH is disabled.

Separately, the **FortiOS** REST API on the FortiGate can return location-based-services (LBS) data on associated and unassociated stations once you place the AP in a region and enable `station-locate` under `config lbs` in the FortiAP profile. This is the data source FortiPresence and similar tools build on; FortiPresence itself is outside this exam's topic list.

> **Watch out:** "FortiAP REST API" questions want the AP's own `https://<FAP-IP>/api/v1/...` paths. The FortiAIOps controller integration uses the FortiGate's REST API instead (next lessons).

## Lab it yourself

On the FortiGate-VM trial you can configure `config wireless-controller snmp`, a `syslog-profile` and `config wireless-controller log`, and explore Dashboard > WiFi if the menus are visible (check System > Feature Visibility; not verified on the trial). With a real FortiAP on your bench, enable HTTPS access on it and try `/logincheck` then `/api/v1/sys-status` with `curl -k`, comparing the JSON with `cw_diag -c wtp-cfg` over SSH.

## Key takeaways

* Managed FortiAPs = AP state and actions; WiFi Clients = per-client data; Rogue APs = the air around you; Dashboard > WiFi gathers widgets.
* Diagnostics and Tools gives a per-AP health view with Radios, Clients and Logs tabs.
* Client health: Good only if signal (> -56 dBm), SNR (> 39 dB) and band (5 GHz) are all Good.
* From a client's summary you can Quarantine or Disassociate it.
* FortiAPs also report via SNMP (traps like `fapDevDown`) and syslog profiles; `cw_diag -c temperature` reads CPU temperature.
* FortiAP REST API: POST `/logincheck`, GET `/api/v1/sys-status`, `sys-perf`, `cfg-get`, `wtp-cfg`, `radio-cfg`, `vap-cfg`; POST `cfg-set` and `reboot`.
