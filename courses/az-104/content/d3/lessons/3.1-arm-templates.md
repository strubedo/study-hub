## What an ARM template is

An **Azure Resource Manager (ARM) template** is a JSON file that declares the resources you want, not the steps to create them. You hand it to Resource Manager, which works out the order, creates or updates each resource, and records the run in the **deployment history** of the target scope. Running the same template again gives the same result, so templates are *idempotent*: resources that already match are left alone, resources whose properties differ are updated.

The exam objective is "interpret": given a template, say what it deploys, what an expression evaluates to, and what happens when it runs. That means reading the top-level sections fluently. The skeleton below shows the seven you will meet in almost every template; Learn's syntax reference also lists three optional ones you rarely need for the exam: `languageVersion` (set to `2.0` to use symbolic resource names), `apiProfile` and `definitions` (user-defined types, languageVersion 2.0 only).

## The top-level sections

```json
{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {},
  "variables": {},
  "functions": [],
  "resources": [],
  "outputs": {}
}
```

| Section | Required | What it holds |
|---|---|---|
| `$schema` | Yes | The template language version. The URL differs by scope: `deploymentTemplate.json` for resource groups, `subscriptionDeploymentTemplate.json`, `managementGroupDeploymentTemplate.json` and `tenantDeploymentTemplate.json` for the others |
| `contentVersion` | Yes | Your own version string, such as `1.0.0.0`. Resource Manager doesn't interpret it |
| `parameters` | No | Values supplied at deployment time |
| `variables` | No | Values computed once inside the template and reused |
| `functions` | No | User-defined functions (namespaced, built from template expressions) |
| `resources` | Yes | The resources to deploy (an array) |
| `outputs` | No | Values returned after deployment, visible in the deployment history |

### Parameters

Each parameter has a `type` and optional constraints:

```json
"parameters": {
  "environment": {
    "type": "string",
    "allowedValues": [ "Dev", "Prod" ],
    "defaultValue": "Dev",
    "metadata": { "description": "Deployment environment." }
  },
  "vmCount": {
    "type": "int",
    "defaultValue": 2,
    "minValue": 1,
    "maxValue": 5
  },
  "adminPassword": {
    "type": "secureString"
  }
}
```

The types are `string`, `securestring`, `int`, `bool`, `object`, `secureObject` and `array` (Learn's own examples write both `securestring` and `secureString`). Constraints: `allowedValues`, `defaultValue`, `minValue`/`maxValue` (int) and `minLength`/`maxLength` (string and array). A parameter **without** a `defaultValue` must be supplied at deployment time, or the Azure CLI and PowerShell prompt for it. A `secureString` or `secureObject` value isn't written to the deployment history or logs, which is why passwords should always use it.

### Variables

Variables simplify long expressions. They are evaluated once and referenced with `variables('name')`:

```json
"variables": {
  "storageName": "[concat('st', uniqueString(resourceGroup().id))]",
  "subnetId": "[resourceId('Microsoft.Network/virtualNetworks/subnets', 'vnet-app', 'snet-app')]"
}
```

### Resources

Every resource entry has at least `type`, `apiVersion` and `name`, plus `location` and `properties` for most types:

```json
{
  "type": "Microsoft.Storage/storageAccounts",
  "apiVersion": "2025-06-01",
  "name": "[variables('storageName')]",
  "location": "[resourceGroup().location]",
  "sku": { "name": "Standard_LRS" },
  "kind": "StorageV2",
  "properties": { "minimumTlsVersion": "TLS1_2" }
}
```

The `apiVersion` fixes which properties are valid for that type; the template reference under `/azure/templates/` lists every version per type.

### Outputs

```json
"outputs": {
  "blobEndpoint": {
    "type": "string",
    "value": "[reference(variables('storageName')).primaryEndpoints.blob]"
  }
}
```

## Template expressions and functions

Any string that starts with `[` and ends with `]` is an **expression**. Functions you will meet most:

| Function | Returns | Example |
|---|---|---|
| `parameters('x')`, `variables('x')` | The value | `[parameters('vmCount')]` |
| `resourceGroup()` | Object with `id`, `name`, `location` | `[resourceGroup().location]` |
| `subscription()` | Object with `subscriptionId`, `tenantId` | `[subscription().subscriptionId]` |
| `concat(a, b, ...)` | Joined strings (or arrays) | `[concat('vm-', parameters('environment'))]` |
| `format('{0}-{1}', a, b)` | Formatted string | `[format('{0}-{1}', 'nic', 'web')]` = `nic-web` |
| `toLower()`, `toUpper()` | Changed case | `[toLower('Contoso')]` = `contoso` |
| `uniqueString(...)` | 13-character deterministic hash | Same input, same output, so it's stable across redeployments to the same resource group |
| `resourceId(type, name1, ...)` | The full resource ID | Child types take one name per level: `resourceId('Microsoft.Network/virtualNetworks/subnets', 'vnet-app', 'snet-app')` |
| `reference(nameOrId)` | The runtime **properties** object of a deployed resource | `[reference(variables('storageName')).primaryEndpoints.blob]`; add `'Full'` as a later argument to get the whole object, then use `.properties.` |
| `copyIndex(offset)` | Current loop iteration (0-based, plus offset) | `copyIndex(1)` starts at 1 |

> **Exam tip:** `resourceId()` returns an ID string; it doesn't make one resource wait for another. `reference()` to a resource deployed in the same template, referred to **by its name** (not by resource ID), **does** create an implicit dependency. When a question shows a NIC that only uses `resourceId()` to point at a subnet, look for the missing `dependsOn`.

## Loops with copy

Put a `copy` element on a resource to deploy several instances:

```json
{
  "type": "Microsoft.Storage/storageAccounts",
  "apiVersion": "2025-06-01",
  "name": "[concat('stcontosologs', string(copyIndex(1)))]",
  "location": "[resourceGroup().location]",
  "sku": { "name": "Standard_LRS" },
  "kind": "StorageV2",
  "copy": {
    "name": "storageLoop",
    "count": "[parameters('vmCount')]",
    "mode": "Parallel"
  }
}
```

With `vmCount` = 3 this creates `stcontosologs1`, `stcontosologs2` and `stcontosologs3`. `copyIndex()` returns an integer and Learn documents `concat()` for strings or arrays, so wrap it in `string()` (or use `format('stcontosologs{0}', copyIndex(1))`, which is what Learn's current copy examples use). Without the offset, `copyIndex()` would start at 0. `mode` is `Parallel` (default) or `Serial` with a `batchSize`. A `count` of 0 deploys nothing. Copy loops also work on properties (for example, a list of data disks) and on variables and outputs.

## dependsOn and conditions

Resource Manager deploys resources in parallel unless it sees a dependency. Declare one explicitly:

```json
{
  "type": "Microsoft.Network/networkInterfaces",
  "apiVersion": "2025-01-01",
  "name": "nic-app-01",
  "location": "[resourceGroup().location]",
  "dependsOn": [
    "[resourceId('Microsoft.Network/virtualNetworks', 'vnet-app')]"
  ],
  "properties": {
    "ipConfigurations": [
      {
        "name": "ipconfig1",
        "properties": {
          "privateIPAllocationMethod": "Dynamic",
          "subnet": { "id": "[variables('subnetId')]" }
        }
      }
    ]
  }
}
```

A `condition` decides whether a resource is deployed at all:

```json
{
  "condition": "[equals(parameters('environment'), 'Prod')]",
  "type": "Microsoft.Network/publicIPAddresses",
  "apiVersion": "2025-01-01",
  "name": "pip-app-01",
  "location": "[resourceGroup().location]",
  "sku": { "name": "Standard" },
  "properties": { "publicIPAllocationMethod": "Static" }
}
```

When the condition is false the resource is skipped. In incremental mode an existing resource with that name is left alone; in complete mode (with current CLI and PowerShell) it is deleted. The deploy lesson covers that.

## Reading a template: a worked example

Deploy the copy-loop template above to `rg-web-prod` (East US) with `vmCount=2`:

| Question | Answer |
|---|---|
| How many storage accounts? | 2 |
| Their names? | `stcontosologs1`, `stcontosologs2` |
| Their region? | East US (`resourceGroup().location`) |
| What if you pass `vmCount=6`? | Validation fails: `maxValue` is 5 |
| What if you pass `environment=Test`? | Validation fails: not in `allowedValues` |
| What does `[toLower(concat('Contoso', '-', parameters('environment')))]` give with the default? | `contoso-dev` |

Work every expression from the inside out, substituting parameter values first, then defaults.

## Where to see and test templates

**Portal:** search **Deploy a custom template** > **Build your own template in editor**, paste the JSON, **Save**, fill the parameters and **Review + create**. The portal validates the template before deployment.

**Azure CLI** (validate without deploying):

```bash
az deployment group validate -g rg-web-prod --template-file storage.json --parameters vmCount=2
```

**Azure PowerShell:**

```powershell
Test-AzResourceGroupDeployment -ResourceGroupName rg-web-prod -TemplateFile ./storage.json -vmCount 2
```

PowerShell turns template parameters into dynamic cmdlet parameters, so `-vmCount 2` works as long as the name doesn't clash with a built-in cmdlet parameter.

## Try it yourself

Azure Cloud Shell (Bash) in any browser. Cost: a storage account with no data costs nearly nothing; delete it when you finish.

```bash
rg=rg-lab-d3arm
az group create -n $rg -l eastus
cat > st.json <<'EOF'
{
  "$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#",
  "contentVersion": "1.0.0.0",
  "parameters": {
    "prefix": { "type": "string", "defaultValue": "stlab", "maxLength": 11 },
    "count": { "type": "int", "defaultValue": 2, "minValue": 1, "maxValue": 3 }
  },
  "variables": {
    "suffix": "[take(uniqueString(resourceGroup().id), 6)]"
  },
  "resources": [
    {
      "type": "Microsoft.Storage/storageAccounts",
      "apiVersion": "2025-06-01",
      "name": "[concat(parameters('prefix'), variables('suffix'), string(copyIndex(1)))]",
      "location": "[resourceGroup().location]",
      "sku": { "name": "Standard_LRS" },
      "kind": "StorageV2",
      "copy": { "name": "stLoop", "count": "[parameters('count')]" }
    }
  ],
  "outputs": {
    "firstName": {
      "type": "string",
      "value": "[concat(parameters('prefix'), variables('suffix'), '1')]"
    }
  }
}
EOF
python3 -m json.tool st.json > /dev/null && echo "valid JSON"
az deployment group validate -g $rg --template-file st.json --parameters count=5   # fails: maxValue
az deployment group create -g $rg --template-file st.json --parameters count=2
az storage account list -g $rg --query "[].name" -o tsv
```

Predict the two names before you list them, then read the `firstName` output in the portal under the resource group's **Settings** > **Deployments**. Clean up: `az group delete -n $rg --yes --no-wait`.

## Key takeaways

- Required sections: `$schema`, `contentVersion`, `resources`. Optional: `parameters`, `variables`, `functions`, `outputs`.
- Parameter types include `string`, `int`, `bool`, `object`, `array`, `secureString`, `secureObject`; constrain them with `allowedValues`, `defaultValue`, min/max value and length.
- Expressions sit in `[ ]`; evaluate inside-out with parameter values substituted.
- `resourceId()` builds an ID only; `reference()` reads runtime properties and implies a dependency when it names a resource in the same template; `dependsOn` sets order explicitly.
- `copy` with `copyIndex()` (0-based, offset optional) creates multiple instances; `condition` skips a resource when false.
- `uniqueString()` is deterministic for the same inputs, so names stay stable across redeployments.
