## What you decide when you create an app

An App Service web app (`Microsoft.Web/sites`) is created **inside an existing or new App Service plan**. The choices that matter on AZ-104:

| Choice | Options | Notes |
|---|---|---|
| **Name** | Globally unique; becomes `<name>.azurewebsites.net` | Learn now also offers a **unique default hostname** option (`--domain-name-scope`), which adds a hash and region to the default host name; the exam still uses `<name>.azurewebsites.net` |
| **Publish** | **Code** or **Container** | Code runs on a built-in runtime stack; Container runs your image (Web App for Containers) |
| **Runtime stack** (code) | .NET, Java, Node.js, Python, PHP | Linux and Windows offer different stacks and versions; list them with `az webapp list-runtimes --os linux` |
| **Operating system** | Linux or Windows | Must match the plan's OS |
| **Region** and **plan** | Existing plan in the same region and OS, or create one | The plan sets the tier, which sets the features |

## Create the app

**Portal:** **Create a resource** > **Web App**. **Basics**: subscription, resource group, **Name**, **Publish** (Code or Container), **Runtime stack**, **Operating System**, **Region**, **Linux/Windows Plan** and **Pricing plan**. Further tabs: **Database** (optional), **Container** (image source, registry and identity for a container app), **Networking** (public access, VNet injection), **Monitor + secure** (Application Insights), **Deployment** (GitHub Actions, basic authentication) and **Tags**. **Review + create**.

**Azure CLI:**

```bash
az appservice plan create -g rg-web-prod -n asp-web-prod -l eastus --sku B1 --is-linux
az webapp list-runtimes --os linux -o table
az webapp create -g rg-web-prod -p asp-web-prod -n app-contoso-web --runtime "NODE:22-lts"
az webapp create -g rg-web-prod -p asp-web-prod -n app-contoso-ctr \
  --container-image-name mcr.microsoft.com/azuredocs/aci-helloworld:latest
```

Runtime strings change as versions come and go, so read them from `az webapp list-runtimes` instead of memorising them. For containers, `--container-image-name` replaces the deprecated `--deployment-container-image-name`. To pull from ACR with a managed identity, add `--assign-identity [system] --acr-use-identity --acr-identity [system]` and grant the identity **AcrPull** on the registry.

> **Watch out:** `az webapp up`, the one-command "create plan, create app and deploy from the current folder" shortcut that many tutorials and exam prep materials show, is **deprecated**. The current CLI reference says it no longer creates or deploys anything and exits with an error, and it tells you to use `az webapp create` followed by `az webapp deploy`. If you meet `az webapp up` in a question, recognise what it did; in practice use create plus deploy.

**Azure PowerShell:**

```powershell
New-AzAppServicePlan -ResourceGroupName rg-web-prod -Name asp-web-win -Location eastus -Tier Basic -WorkerSize Small
New-AzWebApp -ResourceGroupName rg-web-prod -Name app-contoso-win -Location eastus -AppServicePlan asp-web-win
```

`New-AzWebApp` with only a plan creates a Windows app with default stack settings; set the stack afterwards with `Set-AzWebApp` or in the portal. For Linux runtime selection the CLI is the practical route.

## App settings and connection strings

**App settings** are name/value pairs that App Service injects into the app as **environment variables** (and, for .NET on Windows, overrides of `appSettings` in `web.config`). **Connection strings** are a separate collection with a type (SQLAzure, SQLServer, MySql, PostgreSQL, Custom and others); they're also exposed as environment variables with a type prefix such as `SQLAZURECONNSTR_`. Both are encrypted at rest, and changing them **restarts the app**.

**Portal:** app > **Settings** > **Environment variables** > **App settings** or **Connection strings** > **Add** (with a **Deployment slot setting** checkbox, covered in the slots lesson) > **Apply**.

```bash
az webapp config appsettings set -g rg-web-prod -n app-contoso-web --settings APP_MODE=production FEATURE_X=off
az webapp config connection-string set -g rg-web-prod -n app-contoso-web \
  --connection-string-type SQLAzure --settings MainDb="Server=tcp:sql-contoso.database.windows.net;Database=appdb;User ID=appuser;Password=<password>"
az webapp config appsettings list -g rg-web-prod -n app-contoso-web -o table
```

```powershell
Set-AzWebApp -ResourceGroupName rg-web-prod -Name app-contoso-win -AppSettings @{ APP_MODE = 'production'; FEATURE_X = 'off' }
```

> **Watch out:** `Set-AzWebApp -AppSettings` replaces the **whole** app settings collection with the hashtable you pass. Read the existing settings first and merge, or you'll delete settings you didn't list. The CLI `appsettings set` adds or updates only the names you pass.

Better than storing secrets in settings: enable a **managed identity** and use **Key Vault references** (`@Microsoft.KeyVault(SecretUri=https://kv-contoso-prod.vault.azure.net/secrets/DbPassword/)`) as the setting value.

**General settings** (portal **Configuration** > **General settings**, CLI `az webapp config set`) include the stack version, **Always On** (Basic and up; keeps the app loaded), **HTTP version**, **Web sockets**, **ARR affinity**, **FTP state** (`--ftps-state AllAllowed|FtpsOnly|Disabled`), **minimum inbound TLS version** and **HTTPS Only** (covered in the certificates lesson).

## Deployment methods at a high level

| Method | How | Typical use |
|---|---|---|
| **ZIP / file deploy** | `az webapp deploy -g <rg> -n <app> --src-path app.zip --type zip`; PowerShell `Publish-AzWebApp -ArchivePath app.zip` | Scripts and pipelines pushing a package |
| **Run from package** | App setting `WEBSITE_RUN_FROM_PACKAGE`; the ZIP is mounted read-only | Atomic, faster deployments |
| **Continuous deployment** | **Deployment Center**: GitHub Actions, Azure Pipelines, Bitbucket, local Git, external Git | CI/CD from a repository |
| **Container** | Point the app at an image tag; optional continuous deployment webhook from ACR | Web App for Containers |
| **FTP/FTPS** | Publishing credentials | Legacy; Learn recommends disabling basic authentication and FTP where you can |
| **Deployment slots** | Deploy to `staging`, then swap | Zero-downtime releases (Standard and up) |

Deployment Center is at app > **Deployment** > **Deployment Center**. The current CLI reference says **basic authentication** (FTP and SCM user/password publishing) is **disabled by default for new apps** (`--basic-auth Disabled|Enabled` on `az webapp create` and `az webapp update`); deployment then uses Microsoft Entra identities, for example GitHub Actions with OpenID Connect.

## Try it yourself

Azure Cloud Shell (Bash). Cost: a B1 Linux plan for under an hour costs a few US cents. Delete the resource group at the end.

```bash
rg=rg-lab-d3app; plan=asp-lab-app; app=app-lab-$RANDOM$RANDOM
az group create -n $rg -l eastus
az appservice plan create -g $rg -n $plan --sku B1 --is-linux
az webapp create -g $rg -p $plan -n $app --container-image-name mcr.microsoft.com/azuredocs/aci-helloworld:latest
az webapp config appsettings set -g $rg -n $app --settings APP_MODE=lab FEATURE_X=on
az webapp config connection-string set -g $rg -n $app --connection-string-type Custom --settings LabDb="Server=lab;Password=<password>"
az webapp config set -g $rg -n $app --always-on true --ftps-state Disabled
az webapp show -g $rg -n $app --query "{host:defaultHostName, state:state, httpsOnly:httpsOnly}" -o table
curl -s https://$app.azurewebsites.net | head -n 5
az webapp log tail -g $rg -n $app    # Ctrl+C to stop
```

The first request can take a minute while the image is pulled. In the portal, open **Environment variables** to see both collections, and **Deployment Center** to see the container source. Clean up: `az group delete -n $rg --yes --no-wait`.

## Key takeaways

- A web app lives in a plan with the same OS and region; choose Publish = Code (runtime stack) or Container.
- `az webapp create -g -p -n --runtime` or `--container-image-name`; PowerShell `New-AzWebApp`. `az webapp up` is deprecated: use `az webapp create` plus `az webapp deploy`.
- App settings become environment variables; connection strings are a separate typed collection; changing either restarts the app.
- `Set-AzWebApp -AppSettings` replaces the whole collection; `az webapp config appsettings set` merges.
- Deployment options: ZIP deploy, run from package, Deployment Center CI/CD, containers, FTP (legacy) and slots.
