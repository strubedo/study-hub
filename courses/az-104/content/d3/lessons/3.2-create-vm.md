## The decisions you make when creating a VM

An Azure virtual machine is a compute resource (`Microsoft.Compute/virtualMachines`) plus the resources it needs to boot and talk: a **network interface** in a subnet, an **OS disk**, and optionally a **public IP address**, a **network security group** and **data disks**. The create wizard and the command-line tools mostly ask the same questions:

| Decision | Options and notes |
|---|---|
| Region and availability | Region; availability zone, availability set, scale set, or no redundancy. Fixed after creation (changing it means re-creating the VM) |
| Security type | **Trusted launch** (default), **Standard**, or **Confidential** |
| Image | Marketplace image (Ubuntu, Windows Server, RHEL, SUSE...), a custom image from Azure Compute Gallery, or a managed image. Generation 1 or 2; x64 or Arm64 |
| Size | vCPU, memory, temp disk and feature support (see the sizes lesson) |
| Authentication | Linux: **SSH public key** (recommended) or password. Windows: username and password |
| Inbound ports | None, or open SSH 22 / RDP 3389 / HTTP 80 / HTTPS 443 on a basic NIC NSG |
| Disks | OS disk type, size, delete-with-VM option, encryption options, data disks |
| Networking | VNet and subnet, public IP (Standard SKU), NIC NSG, load balancer, delete NIC and public IP with the VM |
| Management | Managed identity, auto-shutdown, backup, boot diagnostics, patch orchestration |
| Advanced | Extensions, VM applications, **custom data / cloud-init**, user data, proximity placement group |

### Security type: Trusted launch is the default

Microsoft Learn states that **Trusted launch is the default state for newly created Generation 2 VMs and scale sets**, and that the portal, Azure CLI and Azure PowerShell create Gen2 VMs with Trusted launch whether or not anything is registered on the subscription. Trusted launch adds **Secure Boot** (only signed boot loaders and kernels), a **virtual TPM** (vTPM) for keys and measurements, and boot integrity monitoring through Microsoft Defender for Cloud. Generation 1 images and some VM sizes (for example the A family and older Dv2/Dv3 series per the current support table) don't support it.

To deploy without it, set the security type to **Standard** (`--security-type Standard`, `-SecurityType Standard`). For ARM templates and Bicep, the older behavior was that omitting `securityProfile` created a Standard VM; Learn now documents two changes: a subscription feature registration, *Trusted Launch as default* (`TrustedLaunchByDefaultPreview`), that makes template deployments default to Trusted launch, and, with Microsoft.Compute API version **2025-11-01 or later**, a Trusted launch default for new Gen2 VMs and scale sets whenever the image, source disk and size support it (otherwise the deployment quietly creates a Standard VM). `securityType: 'Standard'` opts out at that API version. Write `securityProfile` explicitly in templates so the result doesn't depend on that registration.

> **Watch out:** You can't add a Generation 1 image to a Trusted launch VM. If a lab script fails with an image-generation error, choose a Gen2 image or set the security type to Standard.

### Basic public IPs are gone

Basic SKU public IP addresses were **retired on September 30, 2025** (Learn's public IP page). New VMs get a **Standard** SKU public IP, which is closed to inbound traffic unless an NSG allows it and is static. Also note: VMs in a subnet without an explicit outbound method (NAT gateway, load balancer outbound rule, public IP) relied on *default outbound access*, which Microsoft is retiring. Learn's default outbound access page: with network API versions released after March 31, 2026, subnets in **new** virtual networks are **private** by default (`defaultOutboundAccess` false; the portal already defaults to private subnets), so their VMs need an explicit outbound method to reach the internet; existing VNets keep their behaviour. A VM with its own public IP, like the lab VM below, uses that address for outbound traffic.

## Create a VM: portal, CLI, PowerShell

**Portal:** **Virtual machines** > **Create** > **Azure virtual machine**. Basics: subscription, resource group, name, region, availability options, security type, image, size, administrator account, inbound ports. Then the **Disks**, **Networking**, **Management**, **Monitoring**, **Advanced** and **Tags** tabs, then **Review + create**. For an SSH key you can generate a new pair and download the private key once.

**Azure CLI:**

```bash
az vm create \
  --resource-group rg-web-prod \
  --name vm-web-01 \
  --image Ubuntu2204 \
  --size Standard_D2s_v5 \
  --admin-username azureuser \
  --ssh-key-values ~/.ssh/id_rsa.pub \
  --vnet-name vnet-hub --subnet snet-web \
  --public-ip-sku Standard \
  --nsg-rule SSH \
  --zone 1 \
  --assign-identity '[system]' \
  --os-disk-delete-option Delete
```

Use `--generate-ssh-keys` to create a key pair in `~/.ssh` if none exists. If the VNet doesn't exist, `az vm create` creates one; it also creates a NIC, an OS disk, a Standard public IP and an NSG with an SSH (Linux) or RDP (Windows) rule unless you say otherwise: `--public-ip-address ""` for no public IP, `--nsg ""` for no NSG, `--nsg-rule NONE` for an NSG with no rule.

**Azure PowerShell** (simple parameter set):

```powershell
$cred = Get-Credential -UserName azureadmin -Message "VM admin password"
New-AzVM -ResourceGroupName rg-web-prod -Name vm-app-01 -Location eastus `
  -Image Win2022Datacenter -Size Standard_D2s_v5 -Credential $cred `
  -VirtualNetworkName vnet-hub -SubnetName snet-app `
  -PublicIpAddressName pip-app-01 -OpenPorts 3389 -Zone 1
```

`New-AzVM` without a password prompt uses the credential object; never put `<password>` literals in scripts. For Linux with SSH in PowerShell, add `-GenerateSshKey -SshKeyName key-web` or pass an existing public key file.

## Customizing the guest at first boot

| Mechanism | When it runs | What it's for |
|---|---|---|
| **Custom data** (`--custom-data cloud-init.yml`) | First boot only | cloud-init on Linux (install packages, write files, create users); on Windows, saved as a file for your own scripts |
| **User data** (`--user-data`) | Readable by the VM through the Instance Metadata Service, updatable later | Data your apps read at runtime |
| **VM extensions** | On demand, managed by the Azure VM agent | Custom Script Extension, Azure Monitor Agent, Key Vault extension, domain join, Microsoft Antimalware |
| **Run Command** | On demand, through the VM agent, no inbound ports needed | One-off scripts for troubleshooting or fixes |

A cloud-init file that installs a web server:

```yaml
#cloud-config
package_upgrade: true
packages:
  - nginx
runcmd:
  - echo "hello from $(hostname)" > /var/www/html/index.html
```

```bash
az vm create -g rg-web-prod -n vm-web-02 --image Ubuntu2204 --generate-ssh-keys --custom-data cloud-init.yml
```

Extensions and Run Command:

```bash
az vm extension set -g rg-web-prod --vm-name vm-web-01 --publisher Microsoft.Azure.Extensions \
  --name CustomScript --settings '{"commandToExecute":"apt-get -y install nginx"}'

az vm run-command invoke -g rg-web-prod -n vm-web-01 --command-id RunShellScript --scripts "systemctl status nginx"
```

```powershell
Invoke-AzVMRunCommand -ResourceGroupName rg-web-prod -VMName vm-app-01 `
  -CommandId RunPowerShellScript -ScriptString 'Get-Service W3SVC'
Set-AzVMCustomScriptExtension -ResourceGroupName rg-web-prod -VMName vm-app-01 -Location eastus `
  -Name InstallIIS -FileUri 'https://example.com/install-iis.ps1' -Run 'install-iis.ps1'
```

The command IDs are `RunShellScript` for Linux and `RunPowerShellScript` for Windows. Run Command needs the VM running with a healthy VM agent.

> **Exam tip:** "Run a script on a VM that has no public IP and no open ports, without Bastion" is Run Command (or the Custom Script Extension). Both go through the Azure fabric and the VM agent, not the network.

## Managed identity

A **system-assigned** managed identity lives and dies with the VM; a **user-assigned** identity is a separate resource you can attach to several VMs. Either lets code on the VM get Microsoft Entra tokens without stored secrets; you then grant it Azure roles (for example Storage Blob Data Reader on a storage account).

```bash
az vm identity assign -g rg-web-prod -n vm-web-01                     # system-assigned
az vm identity assign -g rg-web-prod -n vm-web-01 --identities id-web # user-assigned
```

```powershell
Update-AzVM -ResourceGroupName rg-web-prod -VM (Get-AzVM -ResourceGroupName rg-web-prod -Name vm-app-01) -IdentityType SystemAssigned
```

## What gets deleted with the VM

Deleting a VM doesn't automatically delete its OS disk, data disks, NIC or public IP unless their **delete option** says so. The portal sets "Delete with VM" for resources it creates; with the CLI use `--os-disk-delete-option Delete`, `--data-disk-delete-option Delete`, `--nic-delete-option Delete`. Orphaned disks and static public IPs keep costing money.

## Try it yourself

Azure Cloud Shell (Bash). Cost: a D2s_v5 VM costs well under a dollar for an hour, plus the disk and public IP; delete everything at the end. If the size isn't available in your region, list alternatives with `az vm list-skus -l eastus --size Standard_D2 -o table`.

```bash
rg=rg-lab-d3vm; az group create -n $rg -l eastus
cat > cloud-init.yml <<'EOF'
#cloud-config
packages:
  - nginx
EOF
az vm create -g $rg -n vm-lab-01 --image Ubuntu2204 --size Standard_D2s_v5 \
  --admin-username azureuser --generate-ssh-keys --custom-data cloud-init.yml \
  --public-ip-sku Standard --nsg-rule SSH --assign-identity '[system]'
az resource list -g $rg --query "[].{name:name,type:type}" -o table
az vm show -g $rg -n vm-lab-01 --query "securityProfile" -o json
az vm run-command invoke -g $rg -n vm-lab-01 --command-id RunShellScript --scripts "systemctl is-active nginx"
```

Identify the NIC, OS disk, public IP, NSG and VNet that `az vm create` made, confirm `securityType` is `TrustedLaunch`, and read the Run Command output. In the portal, open the VM's **Connect** blade to see the SSH command. Clean up: `az group delete -n $rg --yes --no-wait`.

## Key takeaways

- A VM brings a NIC and an OS disk; the tools can also create a VNet, a Standard public IP and an NSG unless told not to.
- Trusted launch (Secure Boot + vTPM) is the default security type for Gen2 VMs created in the portal, CLI and PowerShell; `Standard` opts out.
- Basic public IPs were retired on September 30, 2025; VMs get Standard public IPs.
- Linux: prefer SSH keys. Windows: username and password.
- Custom data / cloud-init run at first boot; extensions and Run Command (`RunShellScript`, `RunPowerShellScript`) run on demand through the VM agent.
- Managed identities give the VM an Entra identity without secrets; set delete options so disks, NICs and IPs don't outlive the VM.
