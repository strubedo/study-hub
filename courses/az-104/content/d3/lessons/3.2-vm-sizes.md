## Size families

A VM size fixes vCPUs, memory, temp storage, the maximum number of data disks, disk throughput limits, network bandwidth and the number of NICs. Microsoft groups sizes by workload type:

| Type | Families (examples) | Typical use |
|---|---|---|
| General purpose | **B** (burstable), **D** (Dsv5, Dasv5, Ddsv5...), DC (confidential) | Balanced CPU and memory: web servers, small databases, dev/test |
| Compute optimized | **F**, FX | High CPU-to-memory: batch, application servers, network appliances |
| Memory optimized | **E**, Eb, **M**, EC | Relational databases, caches, in-memory analytics, SAP HANA (M) |
| Storage optimized | **L** | High local disk throughput: NoSQL, data warehousing |
| GPU accelerated | **NC**, **ND**, **NV**, NG | Compute, AI training and inference, visualization |
| FPGA accelerated | NP | Hardware-accelerated workloads |
| High performance compute | **HB**, **HC**, HX | Tightly coupled HPC, often with InfiniBand |

The **B** series accumulates CPU credits while idle and spends them in bursts, which makes it cheap for workloads that are mostly idle; sustained load exhausts the credits and throttles the VM.

## Reading a size name

Learn's naming convention is:

**Family** + *subfamily* + **number of vCPUs** + *constrained vCPUs* + **additive features** + *accelerator type* + **version**

Additive feature letters (lower case) that matter for the exam:

| Letter | Meaning |
|---|---|
| `a` | AMD-based processor |
| `p` | ARM-based processor (Microsoft Cobalt or Ampere Altra) |
| (none) | Intel x86-64 |
| `d` | Includes a **local temporary disk** |
| `s` | Compatible with **Premium SSD** (any premium type) |
| `l` | Low memory (less memory per vCPU) |
| `m` | Memory intensive |
| `t` | Tiny memory |
| `i` | Isolated size |
| `b` | Remote storage bandwidth optimized |
| `e` | Encrypted, confidential TDX capabilities |
| `r` | RDMA (InfiniBand) secondary network |
| `n` | Network optimized |

Worked examples:

- `Standard_D4s_v5`: D family, 4 vCPUs, premium storage capable, version 5, Intel, **no** temp disk.
- `Standard_D4ads_v5`: 4 vCPUs, AMD, local temp disk, premium storage capable.
- `Standard_E16bds_v5`: E family, 16 vCPUs, remote storage bandwidth optimized, temp disk, premium storage.
- `Standard_M8-2ms_v2`: 8 vCPUs constrained to 2 active vCPUs (for per-core licensing), memory intensive, premium.

> **Exam tip:** If a VM must use Premium SSD disks, its size needs the `s`. If the workload needs a local temp disk (for tempdb or a page file, for example), it needs the `d`.

Newer series (v6 and later) often have no temp disk unless `d` is present and use the **NVMe** disk controller, which requires an OS image with NVMe drivers.

## Resizing a VM

You change the size of a VM to scale up or down. Facts from Learn's resize page:

- **Resizing a running VM restarts it**, even when no deallocation is needed. Treat it as disruptive.
- The sizes you can pick while the VM runs are those **available on the hardware cluster** currently hosting it. `az vm list-vm-resize-options` (CLI) and `Get-AzVMSize -ResourceGroupName -VMName` (PowerShell) list them.
- If the size you want isn't in that list, **deallocate** the VM first: a deallocated VM can be placed on any cluster in the region that offers the size, so the full regional list becomes available.
- Deallocation releases **dynamic** IP addresses; OS and data disks aren't affected.
- For a VM in an **availability set**, if the new size isn't available on the set's current cluster, you must deallocate **all** VMs in the set, resize, and start them.
- Windows VMs can't move between sizes with and without a local temp disk directly; Linux VMs can. SCSI-based VMs can't be resized straight to NVMe-only sizes.
- The new size must support the VM's features: premium disks (`s`), Trusted launch, encryption at host, accelerated networking, and enough data disk slots and NICs.
- Regional and per-family **vCPU quotas** apply; a resize that exceeds quota fails.

If a resize fails, the VM model may show the requested size while the VM keeps running at the old size until the resize succeeds.

**Portal:** VM > **Availability + scale** > **Size** > pick a size > **Resize**. If the size you want isn't listed while the VM runs, stop the VM to see more sizes.

**Azure CLI:**

```bash
az vm list-vm-resize-options -g rg-app-prod -n vm-app-01 --query "[].name" -o tsv
az vm resize -g rg-app-prod -n vm-app-01 --size Standard_D4s_v5          # running: restarts the VM

# size not available on the current cluster
az vm deallocate -g rg-app-prod -n vm-app-01
az vm resize -g rg-app-prod -n vm-app-01 --size Standard_E8s_v5
az vm start -g rg-app-prod -n vm-app-01

az vm list-sizes -l eastus -o table                                       # sizes in the region
az vm list-skus -l eastus --size Standard_E --all -o table                # includes restrictions per zone
```

**Azure PowerShell:**

```powershell
Get-AzVMSize -ResourceGroupName rg-app-prod -VMName vm-app-01
$vm = Get-AzVM -ResourceGroupName rg-app-prod -Name vm-app-01
$vm.HardwareProfile.VmSize = 'Standard_D4s_v5'
Update-AzVM -ResourceGroupName rg-app-prod -VM $vm
```

## Stopped versus stopped (deallocated)

| State | How you get there | Compute billed? | Notes |
|---|---|---|---|
| **Running** | Start | Yes | |
| **Stopped** (also "Stopped (Allocated)") | Shut down from inside the OS, `az vm stop`, or `Stop-AzVM -StayProvisioned` | **Yes** | Hardware stays reserved; IPs kept |
| **Stopped (deallocated)** | Portal **Stop**, `az vm deallocate`, or `Stop-AzVM` (default) | **No** | Hardware released; dynamic public and private IPs can change; temp disk contents lost |
| **Hibernated (deallocated)** | Hibernate (where enabled) | No | Memory saved to the OS disk |

In every state, **disks** and **static public IPs** are still billed. The CLI warns that `az vm stop` keeps billing and points you to `az vm deallocate`.

> **Watch out:** An admin who runs `shutdown -h now` or **Shut down** in Windows leaves the VM *Stopped*, still billed. The cost-saving action is deallocation, from Azure.

Auto-shutdown (VM > **Operations** > **Auto-shutdown**) deallocates the VM on a daily schedule and is a cheap way to protect lab budgets.

## Try it yourself

Azure Cloud Shell (Bash). Cost: under a dollar if you delete it within an hour.

```bash
rg=rg-lab-d3size; az group create -n $rg -l eastus
az vm create -g $rg -n vm-size-01 --image Ubuntu2204 --size Standard_D2s_v5 \
  --generate-ssh-keys --public-ip-address "" --nsg ""
az vm list-vm-resize-options -g $rg -n vm-size-01 --query "[].name" -o tsv | head -20
az vm resize -g $rg -n vm-size-01 --size Standard_D2as_v5   # if it isn't in the list above, pick a size that is
az vm get-instance-view -g $rg -n vm-size-01 --query "instanceView.statuses[1].displayStatus" -o tsv
az vm stop -g $rg -n vm-size-01
az vm get-instance-view -g $rg -n vm-size-01 --query "instanceView.statuses[1].displayStatus" -o tsv   # VM stopped (still billed)
az vm deallocate -g $rg -n vm-size-01
az vm get-instance-view -g $rg -n vm-size-01 --query "instanceView.statuses[1].displayStatus" -o tsv   # VM deallocated
```

Decode each size in the resize list using the letter table. In the portal, open the VM's **Size** blade while it is deallocated and compare the list with the running list. Clean up: `az group delete -n $rg --yes --no-wait`.

## Key takeaways

- Families: B burstable, D general, F compute, E/M memory, L storage, N GPU, H HPC.
- Letters: `a` AMD, `p` Arm, `d` temp disk, `s` premium storage, `m` memory intensive, `l` low memory; version suffix `_v5`.
- Resizing a running VM restarts it; if the size isn't in `list-vm-resize-options`, deallocate first; availability sets may need every VM deallocated.
- `az vm resize --size`; PowerShell sets `HardwareProfile.VmSize` and runs `Update-AzVM`.
- Stopped = still billed for compute; Stopped (deallocated) = no compute charge; disks and static IPs always billed.
- `Stop-AzVM` deallocates by default (`-StayProvisioned` keeps it allocated); `az vm stop` doesn't deallocate.
