## What "Insights" means

**Azure Monitor Insights** are curated monitoring experiences for one service or resource type. Each combines metrics, logs, health and a topology view in prebuilt **workbooks**, so you don't have to build charts yourself. Find them under **Monitor** > **Insights** (or on the resource's own menu). For AZ-104 the three that matter are virtual machines, storage accounts and networks; Container insights gets a mention.

| Insight | Needs you to enable anything? | Data source |
|---|---|---|
| **VM insights / VM monitoring** | **Yes**: Azure Monitor Agent, a data collection rule and a workspace | Guest performance data (and logs if you add them) |
| **Storage insights** | **No** | Platform metrics collected by default |
| **Network insights** | **No** | Resource Graph, Resource Health and platform metrics; links to Network Watcher |
| **Container insights** | Yes: enable monitoring on the AKS cluster | Container logs and Prometheus metrics |

## Virtual machines

Azure collects **host metrics** for every VM automatically and free of charge: CPU, disk and network throughput, availability. The VM **Overview** > **Monitoring** tab and the VM's **Metrics** page show them without setup.

**Guest** data needs Microsoft's enhanced monitoring, historically called **VM insights**. Learn's current VM monitoring pages describe enabling it from the VM's **Monitor** page (or **Monitor** > **Virtual machines**), which:

1. Installs the **Azure Monitor Agent** (Windows or Linux extension).
2. Creates or reuses a **data collection rule** and associates it with the VM.
3. Sends guest performance data to a destination you choose:
   - **OpenTelemetry metrics** to an **Azure Monitor workspace** (Learn calls this the recommended experience for new deployments), or
   - **Logs-based metrics** (the classic VM insights experience) to a **Log Analytics workspace**, where the counters land in the **InsightsMetrics** table.
4. Optionally creates a set of recommended alert rules.

You need permission to create DCRs and associate them with VMs. At scale, use **Azure Policy** (built-in initiatives deploy AMA and the DCR association to every VM in a scope), ARM or Bicep. For machines outside Azure, connect them with **Azure Arc** first.

What the views show:

- **Performance**: CPU, available memory, logical disk space and IOPS, network bytes, charted per VM or as top-N lists across many VMs (for example "top 5 VMs by logical disk used %"), with percentiles.
- **Map**: discovered processes and their inbound and outbound connections, including failed connections. Learn now states that the **Map experience and the Dependency Agent are deprecated**: new VMs can't be onboarded to Map from the portal since **September 30, 2025**, and the feature **retires on June 30, 2028**. Know what it did, but don't plan new deployments on it.

> **Exam tip:** If a question asks why the Performance tab of VM insights is empty for a VM, the usual answer is that the Azure Monitor Agent isn't installed or no data collection rule is associated with it. The legacy Log Analytics agent is retired and isn't an option.

Query the classic logs-based data directly:

```kusto
InsightsMetrics
| where Origin == "vm.azm.ms"
| where Namespace == "LogicalDisk" and Name == "FreeSpacePercentage"
| summarize MinFree = min(Val) by Computer
| sort by MinFree asc
```

## Storage accounts

**Storage insights** gives a unified view of performance, capacity and availability for storage accounts, either across a subscription (**Monitor** > **Insights** > **Storage accounts**) or for one account (**storage account** > **Monitoring** > **Insights**). It needs **no configuration**: it reads the platform metrics Azure already collects, and there's no charge to open it.

Its workbooks:

| Workbook / tab | Shows |
|---|---|
| **Overview** | Transactions, end-to-end and server latency, availability and errors per account |
| **Failures** | Errors by type (client throttling, authorization, network, server) |
| **Performance** | E2E latency vs server latency by API (a big gap points at the client or network) |
| **Availability** | Availability % per account and service (default thresholds can be edited) |
| **Capacity** | Used capacity per account and per service: blob, file, table, queue |

You can edit thresholds and save a copy as your own workbook. For per-request detail (who read which blob) you still need **resource logs** via a diagnostic setting, because metrics are aggregated.

## Networks

**Network insights** (**Monitor** > **Insights** > **Networks**) shows all deployed network resources across subscriptions with **no configuration**. Learn organises it as:

- **Topology**: an interactive map of virtual networks and connected resources across subscriptions, resource groups and regions, drawn from Azure Resource Graph (changes can take up to 30 hours to appear).
- **Network health and metrics**: tiles per resource type (application gateways, ER and VPN connections, load balancers, public IPs, firewalls) with Resource Health status and alert counts; select a tile to see metrics.
- **Connectivity**: results of **Connection Monitor** tests.
- **Traffic**: flow logs and **traffic analytics**.
- **Diagnostic toolkit**: shortcuts to the Network Watcher tools (IP flow verify, next hop, connection troubleshoot, packet capture and the rest), covered in Domain 4.

## Container insights (mention)

**Container insights** monitors AKS clusters and Azure Arc-enabled Kubernetes: node and pod performance, container logs, and Prometheus metrics in an Azure Monitor workspace with Grafana dashboards. You enable it on the cluster; it isn't automatic.

## Workbooks

Every Insight is built from **Azure workbooks**: interactive reports that mix text, parameters, KQL queries, metrics and Resource Graph queries. Open **Monitor** > **Workbooks** for the gallery, edit a template, and **Save as** your own copy in a resource group. Workbooks can be shared through Azure RBAC; the viewer still needs read access to the underlying data.

## Enable VM monitoring from the command line

The portal path is the main task: **VM** > **Monitoring** > **Insights** (or **Monitor**) > **Enable** > choose the metrics experience and workspace > **Configure**. The equivalent pieces from the CLI:

```bash
vmid=$(az vm show -g rg-web-prod -n vm-web-01 --query id -o tsv)
az vm identity assign --ids $vmid
az vm extension set --ids $vmid --name AzureMonitorLinuxAgent --publisher Microsoft.Azure.Monitor --enable-auto-upgrade true
# dcr-vminsights.json: the "logs-based" DCR from Learn's "Enable VM monitoring" page, with your workspace ID
az monitor data-collection rule create -g rg-mon-prod -n dcr-vminsights -l eastus --rule-file dcr-vminsights.json
dcrid=$(az monitor data-collection rule show -g rg-mon-prod -n dcr-vminsights --query id -o tsv)
az monitor data-collection rule association create --name vm-web-01-vmi --rule-id $dcrid --resource $vmid
```

PowerShell uses `Set-AzVMExtension -Name AzureMonitorWindowsAgent -ExtensionType AzureMonitorWindowsAgent -Publisher Microsoft.Azure.Monitor ...` for the agent and `New-AzDataCollectionRuleAssociation` (Az.Monitor) for the association.

## Try it yourself

Cloud Shell and the portal. Cost: cents for a small VM and a workspace for an hour.

```bash
rg=rg-lab-d5insights; loc=eastus
az group create -n $rg -l $loc
az monitor log-analytics workspace create -g $rg -n log-lab-insights -l $loc
az vm create -g $rg -n vm-lab-01 --image Ubuntu2204 --size Standard_B1s --admin-username azureuser --generate-ssh-keys --public-ip-address ""
az storage account create -g $rg -n stlabins$RANDOM -l $loc --sku Standard_LRS
```

1. In the portal, open **vm-lab-01** > **Monitoring** > **Insights** (or **Monitor**) and enable enhanced monitoring, choosing the logs-based experience and `log-lab-insights`. Note what it creates: the AMA extension on the VM and a DCR.
2. After 10 to 15 minutes, open the Performance view, then run the InsightsMetrics query above in the workspace.
3. Open **Monitor** > **Insights** > **Storage accounts** and find your new account; open **Capacity**. Nothing had to be enabled.
4. Open **Monitor** > **Insights** > **Networks** > **Topology** and select the lab resource group.

Clean up: `az group delete -n $rg --yes --no-wait`. If the portal created the DCR in another resource group, delete it too (**Monitor** > **Data Collection Rules**).

## Key takeaways

- VM monitoring needs the Azure Monitor Agent, a DCR and a workspace (Azure Monitor workspace for OpenTelemetry metrics, Log Analytics for the classic logs-based view and InsightsMetrics).
- The VM insights Map feature and Dependency Agent are deprecated: no new portal onboarding since September 30, 2025, retirement June 30, 2028.
- Storage insights and Network insights need no setup; they use platform metrics, Resource Health and Resource Graph.
- Storage insights: overview, failures, performance, availability, capacity; per-request detail still needs resource logs.
- Network insights: topology, health and metrics, connectivity (Connection Monitor), traffic (flow logs), diagnostic toolkit.
- Insights are workbooks; save customised copies as your own workbooks.
