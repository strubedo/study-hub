## Where backup monitoring lives now

The names have changed twice, so read questions carefully:

| Era | Name | Status on Learn today |
|---|---|---|
| Original | **Backup center** | Legacy; no longer in portal search, reachable from the Azure Business Continuity Center **Help** menu (Learn's Backup center page) |
| Next | **Azure Business Continuity Center** (ABCC) | Renamed; many Learn pages, screenshots and older videos still use this name |
| Current | **Resiliency** | The portal hub for backup and disaster recovery at scale: protected and protectable items, jobs, alerts, reports, vaults, policies, Azure Policy compliance |

To find it, type **Resiliency** in the portal search box (Learn's "What is Resiliency?" page; it says Resiliency extends what was in ABCC). If your portal or an exam item still says Business Continuity Center or Backup center, it's the same place. Whatever it's called, it gives a **datasource-centric** view across vaults, subscriptions, regions and (with Azure Lighthouse) tenants, for Azure Backup and Azure Site Recovery. Each vault also has its own **Backup items**, **Backup jobs** and **Alerts** pages.

## Backup jobs

Every configure-backup, backup, restore and delete operation is a **job** with a status (In progress, Completed, Completed with warnings, Failed, Cancelled) and details per subtask (for VM backups: **Take Snapshot** and **Transfer data to vault**).

```bash
az backup job list -g rg-bcdr-eus --vault-name rsv-contoso-eus --status Failed -o table
az backup job show -g rg-bcdr-eus --vault-name rsv-contoso-eus --name <job-id>
```

```powershell
Get-AzRecoveryServicesBackupJob -VaultId $v.ID -Status Failed -From (Get-Date).AddDays(-7).ToUniversalTime()
```

The vault's job list keeps a limited history; for long-term trends use Backup reports.

## Alerts for Azure Backup

### Built-in Azure Monitor alerts

Azure Backup now raises **built-in alerts in Azure Monitor** for critical scenarios with **no configuration**:

- **Security alerts**: deletion of backup data, disabling soft delete (where it can still be disabled), and similar destructive operations.
- **Configured (job failure) alerts**: **backup failures** and **restore failures**. Learn says these are now generated **by default** for both Recovery Services vaults and Backup vaults; you can turn them off in the vault's monitoring settings.

These alerts appear in **Resiliency** > **Alerts**, in the vault's **Alerts** page (filter **Monitor service = Azure Backup**), and in **Monitor** > **Alerts**. They use the standard severities and user responses (New, Acknowledged, Closed).

They are **not** created by an alert rule, so there's no rule to attach an action group to. To get an **email, SMS or webhook**, create:

1. An **action group** with the receivers.
2. An **alert processing rule** with rule type **Apply action group**, scoped to the subscription, resource group or vaults, optionally filtered (for example **Monitor service = Azure Backup**, severity Sev0 and Sev1).

The portal offers a guided **Create notification rule** / "configure notifications" flow that builds both for you.

### Classic backup alerts

The older vault-level "classic alerts" with their own email settings are being replaced. Learn's guidance is to **opt in to "Use only Azure Monitor alerts"** in the vault's monitoring settings (or through Resiliency for many vaults) so you don't get duplicate notifications, and to move any automation from classic alerts data to Azure Monitor alerts. In the CLI this is `az backup vault backup-properties set --classic-alerts Disable --job-failure-alerts Enable`.

### Custom alerts

| Need | Use |
|---|---|
| Alert on a condition the built-in alerts don't cover, with some delay acceptable | **Log search alert** on the vault diagnostic tables in a Log Analytics workspace |
| Alert on backup health or job success counts | **Metric alerts** on Azure Backup metrics (for example backup health events) |
| Real-time queries across vaults | Azure Resource Graph queries (Learn advises against building automations on them) |

## Backup reports

**Backup reports** are workbooks (in **Resiliency** > **Reports**, or a vault's **Backup reports**) that show trends over time: **backup instances**, **usage** (protected instances and storage per vault, policy or item), **jobs**, **policies**, **policy adherence** (did each item get its scheduled backup?) and **optimize** (inactive resources, retention you could trim). They cover Azure VMs, SQL and SAP HANA in VMs, Azure Files, the MARS agent, MABS and DPM, and more.

They need data in a **Log Analytics workspace**:

1. Create or choose a **Log Analytics workspace**. It can be in a different region and subscription from the vaults. Raise its retention if you want reports longer than 30 days.
2. On each vault: **Monitoring** > **Diagnostic settings** > **+ Add diagnostic setting** > **Send to Log Analytics workspace** > select **Resource specific** > tick the Azure Backup events (**Core Azure Backup Data**, **Addon Azure Backup Job Data**, **Addon Azure Backup Policy Data**, **Addon Azure Backup Storage Data**, **Addon Azure Backup Protected Instance Data**, **Azure Backup Operations**) > **Save**. For Site Recovery, add the ASR categories.
3. At scale, assign the built-in **Azure Policy** definition that deploys vault diagnostic settings to a workspace for every vault in a scope.
4. Wait: the first data can take up to **24 hours**, and the current partial day isn't shown.
5. Open **Backup reports**, choose the workspace(s), time range and filters.

The legacy **Azure Backup Reporting Data** event (which lands in **AzureDiagnostics**) and the old Power BI template app are on a deprecation path; use resource-specific mode. In the workspace, the data lands in tables such as **CoreAzureBackup**, **AddonAzureBackupJobs**, **AddonAzureBackupPolicy**, **AddonAzureBackupStorage** and **AddonAzureBackupProtectedInstance**.

```bash
rsvid=$(az backup vault show -g rg-bcdr-eus -n rsv-contoso-eus --query id -o tsv)
lawid=$(az monitor log-analytics workspace show -g rg-mon-prod -n log-contoso-prod --query id -o tsv)
az monitor diagnostic-settings create --name rsv-to-law --resource $rsvid --workspace $lawid --export-to-resource-specific true \
  --logs '[{"category":"CoreAzureBackup","enabled":true},{"category":"AddonAzureBackupJobs","enabled":true},{"category":"AddonAzureBackupPolicy","enabled":true},{"category":"AddonAzureBackupStorage","enabled":true},{"category":"AddonAzureBackupProtectedInstance","enabled":true}]'
```

```powershell
$cats = 'CoreAzureBackup','AddonAzureBackupJobs','AddonAzureBackupPolicy','AddonAzureBackupStorage','AddonAzureBackupProtectedInstance'
$logs = $cats | ForEach-Object { New-AzDiagnosticSettingLogSettingsObject -Enabled $true -Category $_ }
New-AzDiagnosticSetting -Name rsv-to-law -ResourceId $v.ID -WorkspaceId $law.ResourceId -Log $logs -LogAnalyticsDestinationType Dedicated
```

(`-LogAnalyticsDestinationType Dedicated` in PowerShell and `--export-to-resource-specific true` in the CLI select resource-specific tables.)

A query for failed backup jobs in the last day:

```kusto
AddonAzureBackupJobs
| where TimeGenerated > ago(1d)
| where JobOperation == "Backup" and JobStatus == "Failed"
| project TimeGenerated, VaultName, BackupItemUniqueId, JobFailureCode
| sort by TimeGenerated desc
```

## Backup Explorer

**Backup Explorer** is a built-in Azure Monitor workbook that uses **Azure Resource Graph** (no Log Analytics needed) to show the **current** state of your backup estate across tenants, subscriptions, regions and vaults: backup items, jobs, alerts, policies, and **protectable resources not yet backed up**. Use it for "what's protected right now and what isn't"; use Backup reports for history and trends.

## Try it yourself

Cloud Shell. Cost: cents (a workspace with a little data; an empty vault is free).

```bash
rg=rg-lab-d5bkmon; loc=eastus
az group create -n $rg -l $loc
az backup vault create -g $rg -n rsv-lab-mon -l $loc
az monitor log-analytics workspace create -g $rg -n log-lab-bkmon -l $loc
rsvid=$(az backup vault show -g $rg -n rsv-lab-mon --query id -o tsv)
lawid=$(az monitor log-analytics workspace show -g $rg -n log-lab-bkmon --query id -o tsv)
az monitor diagnostic-settings create --name rsv-to-law --resource $rsvid --workspace $lawid --export-to-resource-specific true \
  --logs '[{"category":"CoreAzureBackup","enabled":true},{"category":"AddonAzureBackupJobs","enabled":true}]'
az monitor action-group create -g $rg -n ag-backup --short-name backup --action email ops <your-email-address>
az backup vault backup-properties show -g $rg -n rsv-lab-mon -o jsonc
```

1. In the portal, open the vault > **Alerts** > **Manage alerts** (or **Resiliency** > **Alerts**) and find the option to create a notification rule; build an alert processing rule that applies `ag-backup` to Azure Backup alerts in the resource group.
2. Open the vault's **Diagnostic settings** and check that the categories you selected are listed with the destination table type **Resource specific**.
3. Open **Resiliency** > **Reports** (or **Backup reports**) and point it at `log-lab-bkmon`; with no protected items it will be empty, which is expected.

Clean up: nothing was protected, so `az group delete -n $rg --yes --no-wait` removes everything. Delete the alert processing rule too if you created it in another resource group.

## Key takeaways

- Backup center became Azure Business Continuity Center and is now **Resiliency**; vaults still have their own items, jobs and alerts pages.
- Built-in Azure Monitor alerts for Backup fire by default for security events and job failures; route them to email or webhooks with an **alert processing rule** plus an **action group**.
- Opt in to "Use only Azure Monitor alerts" to retire classic backup alerts.
- Backup reports need vault **diagnostic settings** to a **Log Analytics workspace** in **resource-specific** mode; allow up to 24 hours for data.
- Tables: CoreAzureBackup, AddonAzureBackupJobs, AddonAzureBackupPolicy, AddonAzureBackupStorage, AddonAzureBackupProtectedInstance.
- Backup Explorer shows the current estate from Azure Resource Graph; reports show history from Log Analytics.
