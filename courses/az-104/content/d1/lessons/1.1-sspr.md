## What SSPR does

**Self-service password reset (SSPR)** lets a user who forgot their password, or whose account is locked, prove who they are with methods they registered earlier and set a new password without calling the help desk. Users start at **https://aka.ms/sspr** or from the **Forgot my password** link on the sign-in page.

SSPR covers three related actions:

- **Change**: the user knows the current password and picks a new one. Available to every cloud user, even on Microsoft Entra ID Free.
- **Reset**: the user does not know the password and verifies with registered methods.
- **Unlock**: the account is locked out and the user unlocks it without changing the password (relevant with writeback).

## Licensing

| Scenario | Licenses that include it |
|---|---|
| Cloud-only user password **change** | All, including Microsoft Entra ID Free |
| Cloud-only user password **reset** | Microsoft 365 Business Standard or higher, Microsoft 365 Business Premium, Microsoft Entra ID P1 or P2 |
| Hybrid user change or reset **with on-premises writeback** | Microsoft Entra ID P1 or P2, or Microsoft 365 Business Premium (not Business Basic or Standard) |

Microsoft's guidance is that every user you intend to benefit from SSPR needs a license, even where unlicensed users can technically reach the feature. This table follows the dedicated **SSPR licensing** page on Microsoft Learn; the broader Microsoft Entra licensing overview lists "self-service password reset" under Free without splitting change from reset, so when the two read differently, go by the SSPR page.

> **Exam tip:** "Synchronized users must be able to reset their passwords in the cloud and sign in on-premises with the new password" needs **password writeback**, which needs **Microsoft Entra ID P1** (or P2, or Business Premium) and a sync engine.

## Configuring SSPR

You need at least the **Authentication Policy Administrator** role. Portal: **Microsoft Entra admin center > Entra ID > Password reset**. The blade has these pages:

### Properties: who is enabled

**Self service password reset enabled**: **None**, **Selected** or **All**.

- **None**: nobody (except administrators, see below) can use SSPR.
- **Selected**: members of **one** group you choose. The portal lets you pick a single group; nested group members are included. This is how you pilot SSPR.
- **All**: every user in the tenant.

> **Watch out:** "Enable SSPR for GroupA and GroupB" cannot be done by selecting two groups. Nest both in a third group and select that, or use **All**.

### Authentication methods: how users prove identity

- **Number of methods required to reset**: **1** or **2**.
- **Methods available to users**. The current Microsoft Learn list of methods SSPR can use is: Microsoft Authenticator push notifications, software OATH tokens, hardware OATH tokens (preview), SMS, voice call and email one-time passcode. Older material also lists **security questions** and separate mobile and office phone options; security questions no longer appear in the current list of SSPR methods and were never allowed for administrators.
- A user can only reset if they registered **at least as many** enabled methods as the number required. Microsoft recommends enabling more methods than the number required so users have a fallback.
- For SSPR, **Microsoft Authenticator, software OATH and hardware OATH tokens count as one method**: a user can't satisfy "2 required" with Authenticator plus an OATH token. For the same reason Authenticator can't be the only enabled method when one is required, and with two required you must enable Authenticator plus at least two other methods.
- In tenants that have migrated to the unified **Authentication methods policy** (**Entra ID > Authentication methods > Policies**), the methods available for SSPR are managed there rather than on this page.

### Registration

- **Require users to register when signing in**: **Yes** prompts SSPR-enabled users to register methods at their next interactive sign-in.
- **Number of days before users are asked to reconfirm their authentication information**: **0 to 730**. `0` means never ask.

Users register (or review) methods at **https://aka.ms/mysecurityinfo** (the **Security info** page). Since **combined registration** is rolled out to all tenants, one registration experience covers both MFA and SSPR methods; users no longer register twice. Administrators can also pre-populate a user's phone or email under the user's **Authentication methods** so they are ready without user action.

### Notifications

- **Notify users on password resets?**: emails the user after their own password is reset, so a reset they did not make is noticed.
- **Notify all admins when other admins reset their password?**: emails all Global Administrators when any administrator resets their own password.

### Customization

**Customize helpdesk link**: replace the "contact your administrator" link with your help desk's email or URL.

### On-premises integration

Shows the state of **password writeback** (configured in the sync engine, not here) and lets you allow users to **unlock accounts without resetting their password**.

## Administrators are different

Accounts holding a Microsoft Entra administrator role (Global Administrator, User Administrator, Helpdesk Administrator, Authentication Administrator and many others) are **enabled for SSPR by default** with a fixed **two-gate policy**: they must use **two** methods, **security questions are not allowed** (and office or mobile voice calls are not allowed on trial or Free tenants), and the policy ignores your **None / Selected / All** setting and your method choices. You cannot change the two-gate policy itself; the only switch is to turn SSPR off for all administrators by setting `AllowedToUseSspr` to false on the tenant authorization policy (`Update-MgPolicyAuthorizationPolicy -AllowedToUseSspr:$false`). Test your user policy with an account that has no admin role.

## Password writeback

Hybrid users (synchronized from Windows Server Active Directory) have their password mastered on-premises. Without writeback, an SSPR attempt by such a user ends with "contact your administrator". With **password writeback**:

- A reset or change in the cloud is written back to on-premises AD **synchronously**; if it breaks the on-premises password policy (length, complexity, history) the user is told immediately and nothing is changed.
- It works with password hash synchronization, pass-through authentication (Connect Sync) and federation.
- An administrator resetting a synchronized user's password in the admin center is also written back.
- The writeback service account cannot reset passwords of members of protected on-premises groups (for example Domain Admins); those must be reset on-premises.

Enabling it is a two-part job:

1. In the sync engine: in **Microsoft Entra Connect Sync** run the wizard, choose **Customize synchronization options**, and tick **Password writeback** under **Optional features**. With **Microsoft Entra Connect cloud sync**, enable writeback in the cloud sync configuration.
2. In **Entra ID > Password reset > On-premises integration**, turn on **Write back passwords to your on-premises directory** (and optionally **Allow users to unlock accounts without resetting their password**).

The on-premises AD DS connector account needs the reset password, change password and write permissions on the user objects; the Connect wizard documentation lists them exactly.

## The user's view

1. The user browses to **aka.ms/sspr** (or selects **Forgot my password**), enters their user name and a CAPTCHA.
2. Microsoft Entra ID checks that the user is enabled for SSPR, has a license, and has registered enough methods. If any check fails, they are told to contact an administrator.
3. The user completes one or two verification methods.
4. They set a new password that must meet the cloud password policy, and the on-premises policy if writeback applies.
5. If notifications are on, they receive an email confirming the reset.

## Command line

Most SSPR settings are portal settings. With Microsoft Graph PowerShell you can read and change the **Authentication methods policy** (`Get-MgPolicyAuthenticationMethodPolicy`) and register methods for a user, for example a phone number:

```powershell
Connect-MgGraph -Scopes "UserAuthenticationMethod.ReadWrite.All"
New-MgUserAuthenticationPhoneMethod -UserId 'ben@contoso.com' -PhoneType 'mobile' -PhoneNumber '+1 5550100'
Get-MgUserAuthenticationMethod -UserId 'ben@contoso.com'
```

The Azure CLI has no SSPR commands; `az rest` against the Microsoft Graph `authenticationMethodsPolicy` and `users/{id}/authentication` endpoints is the equivalent.

## Try it yourself

Cost: SSPR **reset** for cloud users needs Microsoft Entra ID P1 (or an equivalent bundle). If your tenant is Free, you can still walk through the configuration pages and test password **change**; a P1 trial lets you complete the reset test.

1. Create a group `sg-sspr-pilot` and a test user `sspruser` with no admin roles; add the user to the group.
2. **Entra ID > Password reset > Properties**: set **Selected** and choose `sg-sspr-pilot`.
3. **Authentication methods**: number required **1**; allow email one-time passcode and SMS (or whatever your policy page offers).
4. **Registration**: **Require users to register when signing in = Yes**, reconfirm after **180** days.
5. **Notifications**: both **Yes**.
6. In a private window, sign in as `sspruser`, complete registration at the prompt (or at aka.ms/mysecurityinfo).
7. In a new private window go to **aka.ms/sspr**, reset the password with the registered method, and check the notification email.
8. Clean up: set **Self service password reset enabled** back to its previous value, delete the test user and group. No Azure resources or resource group are used, so there is nothing to bill.

## Key takeaways

- SSPR scope is **None**, **Selected** (one group, nested members included) or **All**; administrators are enabled by default with a two-gate policy you cannot change (you can only switch admin SSPR off with `AllowedToUseSspr`).
- Number of methods required is **1 or 2**; users must register at least that many enabled methods.
- Registration can be forced at sign-in, with reconfirmation every 0 to 730 days; combined registration at aka.ms/mysecurityinfo covers MFA and SSPR together.
- Notifications: notify users on their own resets, notify all admins when an admin resets.
- Cloud-user reset needs Microsoft Entra ID P1 or P2 or Microsoft 365 Business Standard or higher; writeback needs P1 or P2 or Business Premium.
- Password writeback is enabled in Microsoft Entra Connect Sync (Optional features) or cloud sync, then in **Password reset > On-premises integration**; it is synchronous and enforces the on-premises password policy.
