## Two tools, one engine

**Azure Storage Explorer** is a free desktop application for **Windows, macOS and Linux** that browses and manages blobs, Data Lake directories, file shares, queues and tables. **AzCopy** is a free command-line tool (single executable, v10 is the supported version) for **Windows, Linux and macOS** that moves data in and out of Storage at high speed. Storage Explorer uses AzCopy for most of its data transfers, so performance and authorization rules are the same.

Inside the Azure portal, the **Storage browser** blade gives a lighter, browser-based view of the same data. **Azure Cloud Shell has AzCopy preinstalled**, which is what the lab below uses.

## Storage Explorer

How to connect, in Microsoft's order of preference:

1. **Sign in with an Azure account** (Microsoft Entra ID). You see every subscription and account you have rights to. Data access then comes from **Azure RBAC data roles** (Storage Blob Data Reader and so on) or from the account key if your role lets you list keys. For **file shares**, Microsoft Learn's Storage Explorer security page says you need an Azure role that grants permission to **list storage account keys**, because Storage Explorer's Azure RBAC support covers accounts, blobs, queues and tables.
2. **Shared access signature** (a SAS URL for an account, container, share, queue or table): ideal for giving one container to a partner. Prefer SAS tied to a stored access policy so you can revoke it.
3. **Account name and key** or a **connection string**: full access; avoid where possible.
4. Local emulator (Azurite) for developers.

What you can do with it, relevant to the exam:

- Create containers, set **anonymous access levels**, upload and download, **change access tier** (including rehydrate from archive), manage **snapshots** and **blob versions** (Manage History > Manage Versions, **Promote Version**), undelete soft-deleted blobs.
- Create **file shares**, upload files, create and browse **share snapshots**.
- **Generate SAS** and create **stored access policies** (Manage Access Policies) on containers, shares, queues and tables.
- Manage Data Lake ACLs.

> **Exam tip:** "Which tool lets an administrator on a Mac browse a container, change blob tiers and generate a SAS with a GUI?" Storage Explorer: it is cross-platform. AzCopy is command line only.

## AzCopy

### Authorization

AzCopy authorizes in one of two ways:

| Method | How | Notes |
|---|---|---|
| **Microsoft Entra ID** | `azcopy login` (device code sign-in), `azcopy login --tenant-id=<tenant-id>`, managed identity or service principal; or set `AZCOPY_AUTO_LOGIN_TYPE` (for example `AZCLI` to reuse an Azure CLI sign-in, `PSCRED` for PowerShell) | Your identity needs a **data role**: Storage Blob Data Reader to download, Storage Blob Data Contributor or Owner to upload. Being Owner of the account is **not** enough |
| **SAS token** | Append `?<sas-token>` to each URL | Works for Blob and Files; required for some Files operations that target only the share or account |


### Core commands

| Command | Purpose |
|---|---|
| `azcopy login` / `azcopy logout` / `azcopy login status` | Microsoft Entra sign-in |
| `azcopy make` | Create a container or share |
| `azcopy copy` (`azcopy cp`) | Copy files or blobs: upload, download, or account to account |
| `azcopy sync` | Make a destination match a source, using last-modified times (or MD5 with `--compare-hash`) |
| `azcopy list` | List blobs or files |
| `azcopy remove` | Delete blobs or files |
| `azcopy jobs list` / `azcopy jobs resume` | Every transfer is a job; resume after interruption |
| `azcopy set-properties` | Change tier, metadata or tags |
| `azcopy bench` | Measure throughput |

### `azcopy copy` flags you should know

| Flag | Effect |
|---|---|
| `--recursive` | Include subdirectories (default **false** for `copy`) |
| `--include-pattern "*.pdf;*.docx"` | Only file **names** matching the patterns (wildcards allowed, `;` separated) |
| `--exclude-pattern` | Skip matching names |
| `--include-path` / `--exclude-path` | Relative paths, no wildcards |
| `--include-after <ISO-8601>` | Only files modified after a time |
| `--overwrite` | `true` (default), `false`, `prompt`, `ifSourceNewer` |
| `--blob-type` | `BlockBlob`, `PageBlob`, `AppendBlob` or `Detect` |
| `--block-blob-tier` | Upload straight into `Hot`, `Cool`, `Cold` or `Archive` |
| `--put-md5` | Store an MD5 hash so downloads can be verified |
| `--dry-run` | List what would be copied without copying |
| `--preserve-permissions`, `--preserve-info` | Keep ACLs and SMB properties for Azure Files |

Use single quotes around URLs in Bash and PowerShell, double quotes in Windows `cmd.exe`.

```bash
# Upload a folder tree, PDFs only, straight to the cool tier
azcopy copy '/data/reports' 'https://stcontosodata01.blob.core.windows.net/reports?<sas-token>' \
  --recursive --include-pattern '*.pdf' --block-blob-tier Cool

# Download one virtual directory
azcopy copy 'https://stcontosodata01.blob.core.windows.net/reports/2026/q3?<sas-token>' '/restore' --recursive
```

### Copying between storage accounts

```bash
azcopy copy 'https://stcontososrc01.blob.core.windows.net/reports?<sas-token>' \
  'https://stcontosodst01.blob.core.windows.net/reports?<sas-token>' --recursive
```

AzCopy uses **server-to-server** APIs (such as Put Block From URL): the data flows **directly between the storage services**, not through the machine running AzCopy, so a small VM or Cloud Shell can move terabytes. If you use Microsoft Entra ID for **both** source and destination, both accounts must be in the **same tenant**; otherwise use a SAS on the source (and optionally the destination). The same mechanism copies from Amazon S3 and Google Cloud Storage into Blob Storage.

### `azcopy sync`

- Compares **last-modified times** by default (`--compare-hash MD5` to compare content hashes instead). A file is skipped when the destination copy is newer.
- **Recursive by default** (unlike `copy`).
- **One direction only**: source to destination.
- `--delete-destination true` (or `prompt`) **deletes** destination files and blobs that no longer exist at the source. Default `false`.

```bash
azcopy sync '/var/www/static' 'https://stcontosoweb01.blob.core.windows.net/$web?<sas-token>' --delete-destination true
```

Supported pairs include local ↔ Blob, local ↔ Files, Blob ↔ Blob, Files ↔ Files and Blob ↔ Files.

### PowerShell and CLI alternatives

For a handful of files, `az storage blob upload-batch` / `download-batch` or `Set-AzStorageBlobContent` and `Get-AzStorageBlobContent` are fine. For large or repeated transfers, use AzCopy.

## Choosing the tool

| Need | Tool |
|---|---|
| GUI on Windows, macOS or Linux; tiers, SAS, versions, snapshots | Storage Explorer |
| Scripted bulk transfer, scheduling, resume | AzCopy |
| Mirror a folder to a container and remove deleted files | `azcopy sync --delete-destination true` |
| Copy between accounts without using local bandwidth | `azcopy copy` (server-to-server) |
| Quick look from any browser | Portal Storage browser |
| Offline transfer of tens of terabytes | Azure Data Box (outside this objective) |

## Try it yourself

Azure Cloud Shell (Bash). AzCopy is already installed: run `azcopy --version`. Cost: cents.

```bash
rg=rg-lab-d2azcopy; src=stlabcpa$RANDOM; dst=stlabcpb$RANDOM
az group create -n $rg -l eastus
for sa in $src $dst; do az storage account create -n $sa -g $rg --sku Standard_LRS --kind StorageV2 -o none; done
k1=$(az storage account keys list -g $rg -n $src --query [0].value -o tsv)
k2=$(az storage account keys list -g $rg -n $dst --query [0].value -o tsv)
az storage container create --account-name $src --account-key $k1 -n data -o none
az storage container create --account-name $dst --account-key $k2 -n data -o none
end=$(date -u -d '+2 hours' '+%Y-%m-%dT%H:%MZ')
sas1=$(az storage container generate-sas --account-name $src --account-key $k1 -n data --permissions racwdl --expiry $end -o tsv)
sas2=$(az storage container generate-sas --account-name $dst --account-key $k2 -n data --permissions racwdl --expiry $end -o tsv)
mkdir -p lab/sub && echo a > lab/a.txt && echo b > lab/sub/b.pdf
azcopy copy 'lab' "https://$src.blob.core.windows.net/data?$sas1"                 # no --recursive: what happens?
azcopy copy 'lab' "https://$src.blob.core.windows.net/data?$sas1" --recursive
azcopy copy "https://$src.blob.core.windows.net/data?$sas1" "https://$dst.blob.core.windows.net/data?$sas2" --recursive
rm lab/a.txt
azcopy sync 'lab' "https://$src.blob.core.windows.net/data/lab?$sas1" --delete-destination true
azcopy list "https://$src.blob.core.windows.net/data?$sas1"
```

If you have a desktop, install Storage Explorer, sign in, and find the same containers; change a blob's tier from the context menu. Clean up: `az group delete -n $rg --yes --no-wait` and `rm -r lab`.

## Key takeaways

- Storage Explorer: free GUI for Windows, macOS and Linux; sign in with Entra ID, or connect with SAS, key or connection string; uses AzCopy under the hood.
- AzCopy v10 authorizes with Microsoft Entra ID (`azcopy login`, needs a data role) or a SAS appended to the URL.
- `azcopy copy` needs `--recursive` for folders; filter with `--include-pattern`, `--exclude-pattern`, `--include-after`.
- Account-to-account copies are server-to-server and don't use the client's bandwidth.
- `azcopy sync` is recursive by default, one-way, compares last-modified times, and deletes extras only with `--delete-destination true`.
- AzCopy is preinstalled in Azure Cloud Shell.
