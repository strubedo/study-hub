## A public IP is a resource, not a NIC property

In Azure Resource Manager a public IP address is its own resource (`Microsoft.Network/publicIPAddresses`) that you create and then **associate** with something: a VM NIC's IP configuration, a public load balancer frontend, a VPN or ExpressRoute gateway, a NAT gateway, an Application Gateway, Azure Firewall, a Bastion host, a Route Server or API Management. The VM's guest OS never sees the public address: inbound packets are translated to the NIC's private IP before they reach the VM (which is why NSG rules always reference the **private** IP), and outbound packets are translated on the way out.

## SKUs and the Basic retirement

Microsoft Learn's public IP overview says: **"On September 30, 2025, Basic SKU public IPs were retired."** Existing Basic IPs keep running, but Learn's upgrade guidance states that customers who keep them "accept the risks" of an unsupported service with no SLA, and directs you to upgrade to Standard. (Cloud Services Extended Support deployments are the one documented exception.) The CLI still lists `Basic` as a value, so an exam item can still mention it; the answer for new work is Standard.

| | **Standard** (v1) | **StandardV2** | Basic (retired) |
|---|---|---|---|
| Allocation | **Static** only (IPv4 and IPv6) | Static | IPv4 static or dynamic, IPv6 dynamic |
| Inbound by default | **Closed** ("secure by default"): an NSG must allow inbound traffic | Closed | Open |
| Zones | Zonal or zone-redundant | Always zone-redundant | None |
| Routing preference Internet | Supported (for specific resource types) | Not supported | No |
| Global tier (cross-region load balancer) | Supported | Not yet | No |
| Works with | All Standard resources | Only the StandardV2 NAT gateway today | Basic resources only |

Learn also says that former non-zonal Standard IPs are now zone-redundant in all regions with availability zones, that zone-redundant IPs can be created only in regions with three zones, and that **a public IP's zone setting can't be changed after creation**. Idle timeout for inbound-originated flows is adjustable from 4 to 30 minutes (default 4); outbound-originated flows are fixed at 4 minutes.

> **Exam tip:** "A VM has a Standard public IP but nobody can connect to it on RDP" almost always means **no NSG allows the traffic**. Standard public IPs and Standard load balancers are closed to inbound flows until an NSG on the NIC or subnet permits them.

### SKU matching

A Standard public load balancer needs Standard public IPs; you can't mix Basic and Standard resources, and a VM, availability set or scale set can reference only one load balancer SKU.

## Static vs dynamic

- **Static**: the address is assigned when the resource is created and kept until you delete it. You can't pick the address (except from a public IP prefix). Use it for DNS A records, firewall allow-lists, IP-bound certificates.
- **Dynamic** (Basic only): assigned when associated and released when the resource stops or is deleted.

## IPv4, IPv6 and dual stack

Create the address with `--version IPv6` (CLI) or `-IpAddressVersion IPv6` (PowerShell). A dual-stack VM needs an IPv6 address space on the VNet and subnet (IPv6 subnets are /64), an IPv6 IP configuration on the NIC, and a Standard IPv6 public IP. Not every resource supports IPv6: Learn's table shows, for example, no IPv6 public IP for Azure Firewall or Bastion.

## Public IP prefixes

A **public IP prefix** reserves a contiguous block in a region, for example /28 (16 addresses) down to /31 (2 addresses) for IPv4, /124 to /127 for IPv6. You then create static public IPs **from** the prefix, or attach the whole prefix to a NAT gateway or to a load balancer **outbound** rule (Learn: a prefix on a load balancer is used for outbound only, not inbound). The value: partners allow-list one CIDR instead of chasing individual IPs. The size can't change after creation and you can't choose which block you get.

```bash
az network public-ip prefix create -g rg-net-prod -n ippre-egress --length 28 --location eastus
az network public-ip create -g rg-net-prod -n pip-web-01 --public-ip-prefix ippre-egress --sku Standard
```

## DNS name label

Set a **DNS name label** and Azure creates `<label>.<region>.cloudapp.azure.com` pointing to the address (an A record for IPv4, AAAA for IPv6). The label must be unique in the region. For your own domain, create a CNAME to that name, or better, an **alias record** in Azure DNS that points at the public IP resource (covered in the DNS lesson). A preview **domain name label scope** option adds a hash to the FQDN to prevent dangling-DNS takeover.

## Routing preference

**Routing preference** chooses how traffic between Azure and the internet travels:

- **Microsoft network** (default, "cold potato"): traffic enters and leaves Microsoft's network at the edge POP closest to the user.
- **Internet** ("hot potato"): traffic uses transit ISP networks and enters or leaves Microsoft's network in the region hosting the service; it is a lower-cost option.

It is chosen when the public IP is created and can't be changed later. Traffic to other Azure destinations always stays on the Microsoft WAN. Standard v1 IPs only.

## Create a public IP

**Portal**: **Public IP addresses** > **+ Create**: region, name, IP version, SKU (Standard), availability zone (Zone-redundant, 1, 2, 3 or No Zone), tier (Regional or Global), routing preference, idle timeout, DNS name label.

```bash
az network public-ip create \
  --resource-group rg-web-prod --name pip-web-01 --location eastus \
  --sku Standard --allocation-method Static --version IPv4 \
  --zone 1 2 3 --dns-name contoso-web01

# Associate it with an existing NIC IP configuration
az network nic ip-config update -g rg-web-prod --nic-name nic-web-01 -n ipconfig1 \
  --public-ip-address pip-web-01
```

```powershell
$pip = New-AzPublicIpAddress -Name pip-web-01 -ResourceGroupName rg-web-prod -Location eastus `
  -Sku Standard -AllocationMethod Static -IpAddressVersion IPv4 -Zone 1,2,3 -DomainNameLabel contoso-web01
$nic = Get-AzNetworkInterface -Name nic-web-01 -ResourceGroupName rg-web-prod
$nic.IpConfigurations[0].PublicIpAddress = $pip
$nic | Set-AzNetworkInterface
```

The CLI defaults `--sku` to **Standard**. `-AllocationMethod` is mandatory in `New-AzPublicIpAddress`.

### Upgrading a Basic IP

Learn's upgrade guidance works per resource type: a **disassociated** Basic IP can be upgraded with the portal, PowerShell or CLI; for VMs you detach and upgrade (Learn provides scripts for standalone VMs and availability sets); a Basic load balancer needs a new Standard load balancer (upgrade script); VPN and ExpressRoute gateways have their own migration paths. If you need zone redundancy, Learn says create a **new** Standard IP instead. Plan for downtime.

## Try it yourself

Azure Cloud Shell (Bash), any browser. Cost: a Standard public IP is billed per hour while it exists, a few US cents for this lab. Delete it promptly.

```bash
rg=rg-lab-d4pip; az group create -n $rg -l eastus
az network public-ip create -g $rg -n pip-lab --sku Standard --zone 1 2 3 --dns-name lab$RANDOM
az network public-ip show -g $rg -n pip-lab \
  --query "{ip:ipAddress, alloc:publicIPAllocationMethod, zones:zones, fqdn:dnsSettings.fqdn}"
```

1. Note that the allocation method is Static and an address is already assigned even though nothing uses it.
2. Try `az network public-ip create -g $rg -n pip-dyn --sku Standard --allocation-method Dynamic` and read the error.
3. Create a /31 prefix and an IP from it: `az network public-ip prefix create -g $rg -n ippre-lab --length 31`, then `az network public-ip create -g $rg -n pip-from-prefix --public-ip-prefix ippre-lab`.
4. In the portal, open pip-lab and look for the zone setting: it is read-only after creation.
5. Clean up: `az group delete -n $rg --yes --no-wait`

## Key takeaways

- Basic SKU public IPs were retired on September 30, 2025 (Learn); use **Standard**, which is static only and closed to inbound until an NSG allows it.
- Standard IPs are zonal or zone-redundant; the zone choice is fixed at creation. StandardV2 is zone-redundant and currently works only with the StandardV2 NAT gateway.
- NSG rules match the **private** IP: the public address is translated before the NSG sees inbound traffic.
- Public IP prefixes give a contiguous block (/28 to /31 for IPv4) for allow-listing, NAT gateway and load balancer outbound rules.
- DNS name label = `<label>.<region>.cloudapp.azure.com`; routing preference (Microsoft network vs Internet) is set at creation only.
