## What Bastion replaces

Without Bastion, administrators reach VMs either by giving each VM a public IP and opening 3389/22 (exposed to scanning and brute force), or by running their own jump host that has to be patched and hardened. Azure Bastion is a managed PaaS jump service deployed **into your VNet**. You connect from the Azure portal in an HTML5 browser (or, on higher SKUs, from your native RDP/SSH client) over **TLS on 443**; Bastion opens RDP or SSH to the VM's **private** IP. The target VMs need **no public IP** and no agent.

## SKUs as Learn lists them today

Learn's SKU comparison shows four tiers: **Developer**, **Basic**, **Standard** and **Premium**.

| Feature | Developer | Basic | Standard | Premium |
|---|---|---|---|---|
| Needs AzureBastionSubnet / public IP | No / No | Yes / Yes | Yes / Yes | Yes / Yes, **except private-only** deployments |
| Dedicated host | No (shared) | Yes, 2 fixed instances | Yes, **host scaling 2–50** instances | Yes, 2–50 |
| Connect to VMs in the same VNet | Yes | Yes | Yes | Yes |
| Connect to VMs in **peered** VNets | No | Yes | Yes | Yes |
| Concurrent connections | One VM at a time | Yes | Yes | Yes |
| SSH to Linux, RDP to Windows | Yes | Yes | Yes | Yes |
| RDP to Linux, SSH to Windows | No | No | Yes | Yes |
| **Native client** (Azure CLI `az network bastion ssh/rdp/tunnel`) | No | No | Yes | Yes |
| File upload/download (native client) | No | No | Yes | Yes |
| **IP-Connect** (connect to a target by its private IP address) | No | No | Yes | Yes |
| Shareable link, custom inbound port, disable copy/paste | No | No | Yes | Yes |
| **Session recording** | No | No | No | Yes |
| **Private-only** deployment (no public IP) | No | No | No | Yes |
| Kerberos, Key Vault SSH keys, copy/paste | Yes | Yes | Yes | Yes |
| Cost | Free | Hourly | Hourly | Hourly |

Each Basic/Standard/Premium instance supports about 20 concurrent RDP and 40 SSH sessions per Learn's capacity table. **Upgrades** (Developer to Basic/Standard/Premium, Basic to Standard, and so on) take about 10 minutes; **downgrading isn't supported**: you delete and recreate. Bastion Developer is offered only in a list of regions (Learn's list includes, for example, East US 2, Central US and North Europe, but not every region).

> **Exam tip:** Match the requirement to the lowest SKU: "connect from the local RDP or SSH client" or "upload files" or "connect by IP address" = **Standard**. "Record sessions" or "no public IP on Bastion" = **Premium**. "VMs in a peered VNet" = **Basic** or higher (not Developer).

## Deployment requirements (Basic, Standard, Premium)

- A subnet named exactly **AzureBastionSubnet**, **/26 or larger**, in the VNet where Bastion lives. Nothing else may go in it. (Deployments before November 2, 2021 could use /27.)
- A **Standard, static** public IPv4 address (not needed for Developer or Premium private-only).
- Bastion is per VNet, not per subscription. One Bastion in a **hub** serves VMs in **peered** spokes, regional or global peering, without deploying Bastion in each spoke.

## Permissions to connect

Learn's FAQ lists the roles a user needs to connect: **Reader** on the VM, **Reader** on the NIC with the VM's private IP, **Reader** on the Bastion resource, and **Reader** on the target VM's virtual network if Bastion is in a peered VNet. Plus credentials for the guest OS itself.

## NSGs and Bastion

You can apply an NSG to AzureBastionSubnet, but if you do, Learn says you **must** include every required rule:

| Direction | Purpose | Source | Destination | Port |
|---|---|---|---|---|
| Inbound | Users' browsers / clients | **Internet** (or your public ranges) | Any | TCP 443 |
| Inbound | Control plane | **GatewayManager** | Any | TCP 443 |
| Inbound | Bastion internal communication | VirtualNetwork | VirtualNetwork | 8080, 5701 |
| Inbound | Health probes | **AzureLoadBalancer** | Any | TCP 443 |
| Outbound | Sessions to target VMs | Any | **VirtualNetwork** | 22, 3389 (or your custom ports) |
| Outbound | Diagnostics and metering | Any | **AzureCloud** | TCP 443 |
| Outbound | Bastion internal communication | VirtualNetwork | VirtualNetwork | 8080, 5701 |
| Outbound | Session and certificate validation | Any | Internet | 80 |

On the **target VMs' subnet**, allow RDP/SSH **from the AzureBastionSubnet range** (the default AllowVNetInBound already does if you haven't overridden it), and remove any inbound 3389/22 from the internet.

## Deploy Bastion

**Portal**: open the VNet > **Bastion** (or the VM > **Connect** > **Bastion**). For Developer, select **Deploy Bastion Developer**. For dedicated SKUs choose **Configure manually**: name, tier, instance count (Standard/Premium), VNet, the AzureBastionSubnet, the public IP, and on the **Advanced** tab features such as **Native client support**, **IP-based connection**, **Shareable link**, **Session recording**.

```bash
az network vnet subnet create -g rg-net-prod --vnet-name vnet-hub -n AzureBastionSubnet --address-prefixes 10.10.250.0/26
az network public-ip create -g rg-net-prod -n pip-bas-hub --sku Standard --location eastus
az network bastion create -g rg-net-prod -n bas-hub --vnet-name vnet-hub --public-ip-address pip-bas-hub \
  --sku Standard --enable-tunneling true --location eastus

# Native client from your workstation (Standard or Premium with native client support)
az network bastion ssh -g rg-net-prod -n bas-hub --target-resource-id <vm-resource-id> \
  --auth-type ssh-key --username azureuser --ssh-key ~/.ssh/id_rsa
```

`--enable-tunneling` is the CLI name for **Native client support**. The `az network bastion` commands come from the **bastion** CLI extension, which installs automatically on first use. The CLI's `--sku` default is Standard.

```powershell
$vnet = Get-AzVirtualNetwork -Name vnet-hub -ResourceGroupName rg-net-prod
$pip  = New-AzPublicIpAddress -Name pip-bas-hub -ResourceGroupName rg-net-prod -Location eastus `
  -Sku Standard -AllocationMethod Static
New-AzBastion -ResourceGroupName rg-net-prod -Name bas-hub -PublicIpAddress $pip -VirtualNetwork $vnet `
  -Sku Standard -EnableTunneling $true
```

Native client from Windows uses `az network bastion rdp`; from macOS and Linux, `az network bastion ssh` or `az network bastion tunnel` (then point any client at the local port). Run these from the Azure CLI installed on your own computer (it runs on Windows, macOS and Linux): Learn says the native client feature isn't supported in Cloud Shell.

## Try it yourself

Use the **Developer** SKU so the lab is free. Developer is offered only in the regions listed under **Regional availability** on Learn's "Choose the right Azure Bastion SKU" page (bastion-sku-comparison). **Check that list first** and set `loc` to a region on it; East US 2 was on the list when this lesson was checked, but the list changes. Cost: the Developer tier is free; the Standard_B1s VM costs a few US cents for an hour. Native client connections (`az network bastion ssh`) need Standard or higher and, per Learn, aren't supported from Cloud Shell, so this lab uses the portal.

```bash
loc=eastus2   # replace with a region from Learn's Bastion Developer region list
rg=rg-lab-d4bas; az group create -n $rg -l $loc
az vm create -g $rg -n vm-lab --image Ubuntu2204 --size Standard_B1s --public-ip-address "" \
  --admin-username azureuser --admin-password '<password>' --authentication-type password
```

1. In the portal, open vm-lab > **Connect** > **Connect via Bastion**. Choose **Deploy Bastion Developer**. Wait for it to finish, then connect with SSH and the password you set (use a strong value of your own in place of `<password>`).
2. Notice that the VM has no public IP and that you didn't create AzureBastionSubnet.
3. Open the Bastion resource > **Configuration** and look at which features are greyed out for Developer and what an upgrade to Basic would ask you for (a /26 AzureBastionSubnet and a Standard public IP). Don't upgrade: dedicated SKUs bill by the hour.
4. Clean up: `az group delete -n $rg --yes --no-wait`

## Key takeaways

- Bastion gives RDP/SSH over TLS 443 from the portal (or native clients) to VMs' private IPs; VMs need no public IP.
- Basic, Standard and Premium need **AzureBastionSubnet /26 or larger** and a **Standard static** public IP; Developer needs neither; Premium can be private-only.
- Developer: shared, free, same-VNet only, one connection at a time. Basic adds peered VNets. Standard adds native client, file transfer, IP-based connection, shareable links, host scaling. Premium adds session recording and private-only.
- Upgrades are allowed, downgrades aren't.
- If you put an NSG on AzureBastionSubnet, include all Learn's required rules (443 from Internet and GatewayManager, AzureLoadBalancer, 8080/5701 VNet, outbound 22/3389, AzureCloud 443, Internet 80).
- Users need Reader on the VM, NIC and Bastion (and the VNet when peered).
