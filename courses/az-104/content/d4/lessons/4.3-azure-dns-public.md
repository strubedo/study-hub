## Azure DNS is an authoritative host, not a registrar

Azure DNS (public zones) hosts the authoritative records for a domain you own, on Microsoft's global anycast name servers. It doesn't **register** domains (App Service Domains do that through a partner) and it isn't a recursive resolver for your clients. You create a **DNS zone** resource named after the domain, add **record sets**, then **delegate** the domain from its parent (the registrar for a second-level domain, or your parent zone for a subdomain).

Zones are global resources (there's no region) but live in a resource group. You can host the same zone name in different resource groups or subscriptions; delegation decides which copy the world sees.

## Delegation and the four name servers

When you create a zone, Azure assigns **four name servers** from a pool, one from each of four top-level domains, for example:

```text
ns1-37.azure-dns.com.
ns2-37.azure-dns.net.
ns3-37.azure-dns.org.
ns4-37.azure-dns.info.
```

The numbers vary per zone, so always read them from the zone (portal **Overview**, or `az network dns zone show --query nameServers`). Azure creates the apex **NS** record set and the **SOA** record set automatically. To make the zone live:

- **Second-level domain** (contoso.com): at the registrar, replace the domain's name servers with all four Azure names, exactly as the zone lists them. If the same zone name exists in several resource groups or subscriptions, each copy gets different name servers and only the set configured at the registrar is live.
- **Subdomain** in Azure (dev.contoso.com when contoso.com is also in Azure DNS): create the child zone `dev.contoso.com`, then in the **parent** zone create an **NS record set** named `dev` containing the child zone's four name servers. The portal's "This zone is a child of an existing zone already hosted in Azure DNS" checkbox, or `--parent-name`, does it for you.

Verify with any resolver: `nslookup -type=SOA contoso.com` should return an Azure name server as the primary.

## Record sets, not records

Azure DNS manages **record sets**: all records with the same **name** and **type** in a zone. The **TTL is set on the record set**, not per record (1 to 2,147,483,647 seconds; the CLI's `add-record` uses 3600 when it creates the set). Learn's limits: up to 20 records per record set in a public zone (400 for TXT), 10,000 record sets per zone, 250 public zones per subscription by default.

| Type | Use | Azure notes |
|---|---|---|
| **A** / **AAAA** | Name to IPv4 / IPv6 | Can be an **alias** to an Azure resource |
| **CNAME** | Name to another name | One record only; can't coexist with any other type of the same name; **not allowed at the apex** (@) |
| **MX** | Mail servers with preference | Points to a **name**, never an IP |
| **TXT** | SPF, domain verification | SPF is published as TXT |
| **SRV** | Service location: priority, weight, port, target; name like `_sip._tcp` | |
| **NS** | Delegation | Apex NS is automatic and can't be deleted; you can add servers to it. Other NS sets delegate child zones. |
| **SOA** | Zone authority | Automatic, one per zone; editable except the `host` field; serial isn't auto-incremented |
| **PTR** | Reverse lookup | Lives in reverse zones (`2.0.192.in-addr.arpa`); reverse delegation for public IPs comes from whoever owns the block |
| **CAA** | Which CAs may issue certificates | |

**Wildcards**: a record set named `*` answers for any name without a more specific match.

## Alias records and the zone apex

An **alias record set** is an A, AAAA or CNAME record set that points to an **Azure resource** instead of a literal value. Learn lists these targets:

- A/AAAA alias to a **Standard SKU public IP** resource.
- A/AAAA/CNAME alias to a **Traffic Manager** profile (Learn now suggests Traffic Manager Linked Records for new designs).
- An **Azure CDN** endpoint, an **Azure Front Door** endpoint.
- Another record set of the same type in the same zone.

Why it matters:

- **Zone apex**: you can't put a CNAME at `contoso.com`, but you can put an **A alias** at `@` that follows a Traffic Manager profile, Front Door or a public IP.
- **No dangling records**: the alias follows the resource's lifecycle. If the public IP changes, the record updates; if the resource is deleted, the record set returns an empty answer instead of pointing at an address someone else may now own.

## Manage records

**Portal**: **DNS zones** > **+ Create** (subscription, resource group, name `contoso.com`; tick the child-zone box for subdomains). In the zone: **+ Record set** (portal labels may read **Recordsets**): name, type, **Alias record set** Yes/No, TTL, values.

```bash
az network dns zone create -g rg-dns-prod -n contoso.com
az network dns zone show -g rg-dns-prod -n contoso.com --query nameServers
az network dns record-set a add-record -g rg-dns-prod -z contoso.com -n www -a 203.0.113.10
az network dns record-set a add-record -g rg-dns-prod -z contoso.com -n www -a 203.0.113.11 --ttl 300
az network dns record-set cname set-record -g rg-dns-prod -z contoso.com -n shop -c contoso-shop.azurewebsites.net
az network dns record-set mx add-record -g rg-dns-prod -z contoso.com -n "@" -e mail.contoso.com -p 10
az network dns record-set txt add-record -g rg-dns-prod -z contoso.com -n "@" -v "v=spf1 include:spf.protection.outlook.com -all"
# Alias A record at the apex pointing to a Standard public IP resource
az network dns record-set a create -g rg-dns-prod -z contoso.com -n "@" \
  --target-resource /subscriptions/<subscription-id>/resourceGroups/rg-web-prod/providers/Microsoft.Network/publicIPAddresses/pip-web-01
```

The second `add-record` adds a record to the existing `www` set (two A records, round robin) rather than creating a new set. `--ttl` on `add-record` applies only when the command creates the set.

```powershell
New-AzDnsZone -Name contoso.com -ResourceGroupName rg-dns-prod
$records = @(New-AzDnsRecordConfig -IPv4Address 203.0.113.10; New-AzDnsRecordConfig -IPv4Address 203.0.113.11)
New-AzDnsRecordSet -Name www -RecordType A -ZoneName contoso.com -ResourceGroupName rg-dns-prod -Ttl 3600 -DnsRecords $records
New-AzDnsRecordSet -Name "@" -RecordType A -ZoneName contoso.com -ResourceGroupName rg-dns-prod `
  -TargetResourceId (Get-AzPublicIpAddress -Name pip-web-01 -ResourceGroupName rg-web-prod).Id
```

> **Watch out:** `New-AzDnsRecordSet` fails if the set exists unless you add `-Overwrite`. To add one record to an existing set, get it with `Get-AzDnsRecordSet`, call `Add-AzDnsRecordConfig`, then `Set-AzDnsRecordSet`.

## Reading a zone exhibit

Exam items show a record set table and ask what resolves:

```text
Name    Type   TTL    Value
@       NS     172800 ns1-01.azure-dns.com. (+3 more)
@       SOA    3600   ns1-01.azure-dns.com. ...
@       A      3600   Alias: pip-web-01 (203.0.113.10)
www     CNAME  3600   contoso.com.
api     A      300    203.0.113.20, 203.0.113.21
mail    A      3600   203.0.113.30
@       MX     3600   10 mail.contoso.com.
```

- `www.contoso.com` > CNAME > `contoso.com` > the alias A > 203.0.113.10. If pip-web-01 gets deleted, the apex returns no address.
- `api.contoso.com` returns two A records; clients receive both.
- You can't add an A record named `www` (a CNAME already exists there) or a CNAME named `@`.

## Try it yourself

Azure Cloud Shell (Bash), any browser. Cost: a hosted DNS zone is billed monthly per zone plus per million queries; deleting it within the hour keeps the cost to a few cents at most (check the Azure DNS pricing page). You don't need to own contoso.com: you won't delegate it.

```bash
rg=rg-lab-d4dns; az group create -n $rg -l eastus
az network dns zone create -g $rg -n contoso.com
az network dns zone show -g $rg -n contoso.com --query nameServers -o tsv
az network dns record-set a add-record -g $rg -z contoso.com -n www -a 203.0.113.10
az network dns record-set a add-record -g $rg -z contoso.com -n www -a 203.0.113.11
az network dns record-set list -g $rg -z contoso.com -o table
ns=$(az network dns zone show -g $rg -n contoso.com --query "nameServers[0]" -o tsv)
nslookup www.contoso.com $ns
```

1. Query one of your assigned Azure name servers directly (the last line): you get both A records even though the domain isn't delegated to you.
2. Try `az network dns record-set cname set-record -g $rg -z contoso.com -n www -c example.com` and read why it fails.
3. Create a child zone `dev.contoso.com` with `--parent-name contoso.com` and look for the new NS record set `dev` in the parent.
4. Clean up: `az group delete -n $rg --yes --no-wait`

## Key takeaways

- Azure DNS hosts authoritative zones; delegate by setting the zone's **four** Azure name servers at the registrar or in the parent zone (NS record set for a subdomain).
- Records are managed as **record sets** (same name and type); TTL is per record set.
- CNAME: single record, no other types with the same name, never at the apex.
- **Alias** A/AAAA/CNAME record sets point at Azure resources (Standard public IP, Traffic Manager, Front Door, CDN), work at the apex and prevent dangling records.
- Apex NS and SOA are created automatically and can't be deleted.
- CLI: `az network dns zone create`, `az network dns record-set a add-record`; PowerShell: `New-AzDnsZone`, `New-AzDnsRecordSet`.
