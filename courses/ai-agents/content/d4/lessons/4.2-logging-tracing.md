## Logs you can debug from

The transcript-reading method in the previous lesson only works if the transcript exists. Domain 2's loop (lesson 2.2-robust-loop) logged one line per model call and per tool call. This lesson decides exactly what those lines must hold, shows where each vendor exposes request ids and traces today, and keeps secrets out of the logs.

## What to record for every call

| For every model call | Why |
|---|---|
| Run id and step number | Joins every line of one run; orders them |
| Timestamp and duration | Finds the slow step; feeds latency metrics |
| Model id and settings that matter (effort, thinking, `max_tokens`) | A behaviour change after an upgrade is traceable |
| **Request id** | The one value vendor support can look up |
| `stop_reason` | The first thing you read when debugging (lesson 4.2-reading-transcripts) |
| Usage: `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, `output_tokens` (and `output_tokens_details.thinking_tokens` if you use it) | Cost (lesson 4.3-token-accounting), context growth, cache health |
| On failure: HTTP status, error type, request id, retries made | Separates your bugs, rate limits and provider outages |

| For every tool call | Why |
|---|---|
| Tool name and `tool_use_id` | Links the call to its result and to the model turn |
| Arguments, **redacted** | Wrong-argument failures are invisible without them |
| Result size (characters or tokens) and `is_error` | Large results explain context growth; errors explain loops |
| Duration | Slow tools, timeouts |

Log structured lines (one JSON object per event) rather than prose, so you can filter by run id or sum tokens without regular expressions.

## Request ids in the Claude API and SDK

From the Claude API "Errors" page and the Python SDK page (checked 2026-11-23):

- Every API response includes a `request-id` header, a value such as `req_` followed by an identifier.
- Error bodies carry the same value as a top-level `request_id` field beside the `error` object (which always has `type` and `message`).
- The Python and TypeScript SDKs expose it as the `_request_id` property on top-level response objects. Despite the underscore, the SDK page says this property is public.
- To read other response headers, call a method through `.with_raw_response`.
- The Python SDK raises typed exceptions; `anthropic.APIStatusError` (for 4xx and 5xx) carries `status_code` and, in the SDK source, a `request_id` attribute read from the response header. Connection errors (`anthropic.APIConnectionError`, with `APITimeoutError` as a subclass) have no HTTP response and so no request id.
- Setting the environment variable `ANTHROPIC_LOG` to `debug` or `info` turns on the SDK's own logging through the standard `logging` module.

Here is a wrapper that logs both outcomes. It was compiled and exercised offline against a stub client while writing this course; it was not run against the API.

```python
# run_log.py: one structured log line per model call and per tool call, with redaction.
import json
import logging
import re
import time

import anthropic

log = logging.getLogger("agent.trace")

SECRET_PATTERNS = [
    # A word ending in password, secret, community, token or key (also api_key, x-api-key,
    # ANTHROPIC_API_KEY), then "=", ":" or a space (Cisco-style "secret 5 ..."), then the value.
    (re.compile(r"""(?i)\b([\w-]*(?:password|secret|community|token|key))\b(["']?\s*[:=]\s*["']?|\s+(?:\d\s+)?)[^\s"',]+"""),
     r"\1\2[REDACTED]"),
    # Authorization headers, as a header line or as a JSON key, with or without a Bearer/Basic scheme.
    (re.compile(r"""(?i)\b(authorization)\b(["']?\s*[:=]\s*["']?)(?:(?:bearer|basic)\s+)?[^\s"',]+"""),
     r"\1\2[REDACTED]"),
    (re.compile(r"\b[\w.+-]+@[\w-]+\.[\w.]+\b"), "[EMAIL]"),
]


def redact(text):
    for pattern, replacement in SECRET_PATTERNS:
        text = pattern.sub(replacement, text)
    return text


def emit(event, **fields):
    log.info(json.dumps({"event": event, **fields}, default=str))


def logged_create(client, run_id, step, **params):
    """Call messages.create and log the call whether it succeeds or fails."""
    started = time.monotonic()
    try:
        response = client.messages.create(**params)
    except anthropic.APIStatusError as exc:   # HTTP 4xx/5xx after the SDK's own retries
        emit("model_call", run_id=run_id, step=step, model=params["model"], ok=False,
             status=exc.status_code, request_id=exc.request_id,
             seconds=round(time.monotonic() - started, 3))
        raise
    except anthropic.APIConnectionError as exc:  # no HTTP response, so no request id
        emit("model_call", run_id=run_id, step=step, model=params["model"], ok=False,
             error=type(exc).__name__, seconds=round(time.monotonic() - started, 3))
        raise
    u = response.usage
    emit("model_call", run_id=run_id, step=step, model=response.model, ok=True,
         request_id=response._request_id, stop_reason=response.stop_reason,
         input_tokens=u.input_tokens, output_tokens=u.output_tokens,
         cache_creation_input_tokens=u.cache_creation_input_tokens,
         cache_read_input_tokens=u.cache_read_input_tokens,
         seconds=round(time.monotonic() - started, 3))
    return response


def log_tool_call(run_id, step, block, content, is_error, seconds):
    emit("tool_call", run_id=run_id, step=step, tool=block.name, tool_use_id=block.id,
         input=redact(json.dumps(block.input)), result_chars=len(content),
         is_error=is_error, seconds=round(seconds, 3))
```

With a stub response it produces lines like these (values invented):

```text
{"event": "model_call", "run_id": "run-7", "step": 3, "model": "claude-haiku-5-5", "ok": true, "request_id": "req_example01", "stop_reason": "end_turn", "input_tokens": 412, "output_tokens": 655, "cache_creation_input_tokens": 1830, "cache_read_input_tokens": 37600, "seconds": 2.41}
{"event": "model_call", "run_id": "run-7", "step": 4, "model": "claude-haiku-5-5", "ok": false, "status": 529, "request_id": "req_example02", "seconds": 1.07}
```

The error is logged and then re-raised: logging is not handling. Retries are covered in lesson 4.4-retries-timeouts; note that by the time `APIStatusError` reaches your code, the SDK has already retried transient errors on its own.

## Tracing with OpenTelemetry

Logs are flat; a trace is a tree. OpenTelemetry (OTel) is the vendor-neutral standard most observability platforms accept: a **trace** is one request through your system and a **span** is one step in it, such as a model call or a tool call. What each vendor offers on 2026-11-23:

**Claude API and Anthropic SDK (beta).** When your application registers an OTel tracer provider, the SDK emits a span for each request it sends (named `anthropic.messages.create`); the tool runner adds `anthropic.messages.tool_runner` and one `anthropic.custom_tool_use` span per client tool. Separately, an organization admin can add a trace destination in the Claude Console so the API itself exports server-side spans, including server tools. Spans use the OpenTelemetry GenAI semantic conventions. Each SDK client has a **content mode**: `metadata_only` (the default: identifiers, timing, status, token counts) or `content` (prompts and responses too). In Python it is set with the client option `open_telemetry={"traces": {"content_mode": "content"}}` or the environment variable `ANTHROPIC_OPEN_TELEMETRY_TRACES_CONTENT_MODE=content`. During the beta the docs say span names and options can change, so pin the SDK version.

**Claude Agent SDK.** The SDK runs the Claude Code CLI as a child process, and the CLI exports OTel data. Telemetry is off until `CLAUDE_CODE_ENABLE_TELEMETRY=1` and an exporter are set; traces (beta) also need `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1` with `OTEL_TRACES_EXPORTER`. Spans include `claude_code.interaction` (one turn), `claude_code.llm_request` and `claude_code.tool`. Content is not recorded by default; variables such as `OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_DETAILS` and `OTEL_LOG_TOOL_CONTENT` opt in. Spans carry a `session.id` attribute, so several `query()` calls against one session can be filtered into one timeline; the observability and cost-tracking pages read for this course document no per-request id for Agent SDK calls, so correlate on `session.id` and your own run id. The result message's `total_cost_usd` is documented as a client-side estimate, not billing data.

**OpenAI.** The Agents SDK traces runs by default (model calls, tool calls, handoffs, guardrails) and shows them in the Traces dashboard; `trace(...)` groups several runs, `RunConfig.trace_include_sensitive_data` controls whether inputs and outputs are captured, and `OPENAI_AGENTS_DISABLE_TRACING=1` turns tracing off. The Python SDK exposes `_request_id` from the `x-request-id` header.

**Google.** The Gemini API pages read for this course document no built-in trace export; log your own lines as above.

> **Real world:** Start with structured logs and request ids. Add OTel when you have more than one agent or service and want one timeline per user request. Either way, decide the content mode before the first production run, not after the first leak.

## Redaction: secrets and personal data

Agent logs are attractive to attackers because tool inputs and results contain exactly what an attacker wants: device configs with community strings, ticket text with names and phone numbers, tokens in headers. Domain 5 (topic 5.2) covers data handling in depth; for logging, four rules:

1. **Log metadata by default.** Names, ids, sizes, timings and token counts answer most debugging questions. Both Anthropic's SDK tracing and the Agent SDK default to metadata only; follow the same default in your own logs.
2. **Allow-list fields, do not block-list them.** Log `device` and `interface`; do not log "everything except password".
3. **Redact anything you do log.** The `redact` function above masks values after words ending in `password`, `secret`, `community`, `token` or `key` (so `api_key`, `x-api-key` and `ANTHROPIC_API_KEY` too, in `key=value`, `"key": "value"` and Cisco `secret 5 ...` forms), `Authorization` values in header or JSON form, and email addresses. Run offline, it turns `snmp-server community <community-string> RO` into `snmp-server community [REDACTED] RO` and `{"Authorization": "Bearer <token>"}` into `{"Authorization": "[REDACTED]"}`. Patterns are a backstop, not a guarantee: they over-redact some prose ("key findings: ..." loses its next word) and miss formats you did not anticipate, such as phone numbers, names or a bare secret with no label in front of it.
4. **Keep secrets out of reach in the first place.** If a tool never returns a credential, no log can leak it. Never put personal data in ids that are exported in every mode (the SDK docs warn this about `conversation_id`).

## Key takeaways

- Log one structured line per model call (run id, step, model, request id, `stop_reason`, the four usage counts, duration, errors) and per tool call (name, id, redacted arguments, result size, `is_error`, duration).
- Claude responses carry a `request-id` header; the Python and TypeScript SDKs expose it as `_request_id`, and error bodies carry `request_id`.
- Log failures with status and request id, then re-raise: the SDK has already retried transient errors.
- OpenTelemetry tracing exists for the Anthropic SDK and API (beta), the Agent SDK (traces in beta) and OpenAI's Agents SDK; content capture is opt-in.
- Log metadata by default, allow-list fields, redact what you keep, and keep secrets out of tool results altogether.
