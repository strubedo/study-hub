## What the minimal loop leaves out

Domain 1's minimal loop (lesson 1.2-stop-reasons-context) has the right skeleton: a bounded `for` loop keyed on `stop_reason`, the assistant content appended unchanged, one user message of results, and an `is_error` result for a bad call. It is a good first program and a poor production one. Run it against real tools and these gaps appear:

| Gap | What goes wrong |
|---|---|
| One hard-coded tool | Adding a second tool means editing the dispatcher |
| Sequential tool calls | Three read-only lookups take three times as long |
| Only `TypeError` is caught | A timeout or an API error in a tool crashes the whole run |
| No logging | When a run goes wrong you cannot see which tool was called with what |
| Every non-`tool_use` response is returned | A response cut off mid tool call looks like an answer to the caller |
| No distinction between endings | A refusal, a truncation and a real answer reach the user the same way |

This lesson closes each gap, using only behaviour the documentation describes: parallel calls with results in one message ("Parallel tool use"), `is_error` results ("Handle tool calls"), the retry advice for a truncated `tool_use` block and the handling of `pause_turn` and `refusal` ("Stop reasons and fallback"). The structure and the limits are this course's own.

## The robust loop

Every API name below comes from Anthropic's tool-use documentation and Python SDK as read on 2026-11-23. The code was compiled and its control flow exercised against a scripted fake client while writing this course; it was not run against the API.

```python
# noc_agent.py: a bounded, logged tool-use loop for read-only tools.
import json
import logging
from concurrent.futures import ThreadPoolExecutor

import anthropic

from netops_tools import TOOLS, TOOL_FUNCTIONS, ToolInputError

MODEL = "claude-haiku-5-5"      # model ids change: check the Claude models overview
MAX_ITERATIONS = 8              # hard cap on model calls per run
MAX_TOKENS = 2048
MAX_TOKENS_CEILING = 8192       # upper bound when retrying a truncated tool call
SYSTEM = ("You diagnose network problems for Example Corp using read-only tools. "
          "Never claim to have changed anything. Finish with the likely cause, the evidence "
          "(ticket ids, counters) and the runbook to follow.")

log = logging.getLogger("noc_agent")
client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY from the environment


class AgentStopped(Exception):
    """The run ended without a usable final answer."""


def run_tool(block):
    """Run one client tool call and return its tool_result block. Never raises."""
    func = TOOL_FUNCTIONS.get(block.name)
    if func is None:
        content, failed = f"Unknown tool '{block.name}'. Available: {', '.join(TOOL_FUNCTIONS)}.", True
    else:
        try:
            content, failed = json.dumps(func(**block.input)), False
        except ToolInputError as exc:      # message already written for the model
            content, failed = str(exc), True
        except TypeError as exc:           # missing or unexpected arguments
            content, failed = f"Bad arguments for {block.name}: {exc}. Check the input schema.", True
        except Exception:                  # unexpected: full details to the log, little to the model
            log.exception("tool %s raised", block.name)
            content, failed = f"{block.name} failed unexpectedly. Do not retry it; tell the user.", True
    log.info("tool=%s id=%s is_error=%s input=%s", block.name, block.id, failed, json.dumps(block.input))
    return {"type": "tool_result", "tool_use_id": block.id, "content": content, "is_error": failed}


def text_of(response):
    return "".join(b.text for b in response.content if b.type == "text")


def run_agent(goal):
    messages = [{"role": "user", "content": goal}]
    max_tokens = MAX_TOKENS
    for iteration in range(1, MAX_ITERATIONS + 1):
        response = client.messages.create(model=MODEL, max_tokens=max_tokens, system=SYSTEM,
                                          tools=TOOLS, messages=messages)
        stop = response.stop_reason
        log.info("iteration=%d stop_reason=%s input_tokens=%d output_tokens=%d", iteration, stop,
                 response.usage.input_tokens, response.usage.output_tokens)

        if stop == "tool_use":
            calls = [b for b in response.content if b.type == "tool_use"]
            with ThreadPoolExecutor(max_workers=4) as pool:   # safe because every tool is read-only
                results = list(pool.map(run_tool, calls))
            messages.append({"role": "assistant", "content": response.content})
            messages.append({"role": "user", "content": results})   # all results, one message
            continue
        if stop == "max_tokens" and response.content and response.content[-1].type == "tool_use":
            if max_tokens >= MAX_TOKENS_CEILING:
                raise AgentStopped("A tool call was cut off even at the token ceiling.")
            max_tokens = min(max_tokens * 2, MAX_TOKENS_CEILING)
            log.warning("tool call truncated; retrying with max_tokens=%d", max_tokens)
            continue                        # resend the same messages; never run a truncated call
        if stop == "pause_turn":            # only with server tools (topic 2.3)
            # With code execution, also pass container=response.container.id on the next request.
            messages.append({"role": "assistant", "content": response.content})
            continue
        if stop in ("end_turn", "stop_sequence"):
            return text_of(response)
        if stop == "refusal":
            raise AgentStopped(f"The model declined: {response.stop_details}")
        raise AgentStopped(f"Stopped on {stop}; output incomplete: {text_of(response)[:200]}")
    raise AgentStopped(f"No final answer after {MAX_ITERATIONS} model calls.")


if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    print(run_agent("Users on sw-access-12.example.com report slow transfers. "
                    "The uplink is GigabitEthernet1/0/48. What is wrong?"))
```

## Walking through it

**Dispatch table.** `TOOL_FUNCTIONS` maps names to functions. An unknown name (possible without strict mode, or if your `TOOLS` and functions drift apart) becomes an `is_error` result listing the real tools.

**Errors never escape `run_tool`.** Three tiers: `ToolInputError` carries a message already written for the model; `TypeError` catches wrong arguments; anything else is logged with its stack trace for you and reported to the model in one plain sentence. The documentation's advice is to send failures back with `is_error: true` so the model can retry or explain, and to limit retries; here `MAX_ITERATIONS` is that limit. Successful results carry `is_error: False`: the field is optional and the docs only ever set it to `true`, but the Python SDK types it as a plain boolean, so `false` is a valid value.

**Parallel execution, one results message.** `pool.map` runs the calls concurrently and keeps their order. That is safe only because every tool is read-only; the parallel tool use page says tools with side effects or ordering needs may be better run in sequence. Whatever the execution, all results go into one user message.

**Logging.** One line per model call (stop reason and token counts from `usage`) and one per tool call (name, id, error flag, input). That is enough to reconstruct a run; Domain 4 turns it into tracing. Before you log real inputs and outputs, decide what must be redacted (Domain 5).

## Ending the loop

A run must end in exactly one of these ways, and the caller should be able to tell which:

| Ending | How the loop sees it | What this loop does |
|---|---|---|
| Final answer | `end_turn` (or one of your `stop_sequences`) | Returns the text |
| Iteration cap | The `for` loop runs out | Raises `AgentStopped`; the caller reports or escalates |
| Truncated tool call | `max_tokens` and the last block is `tool_use` | Never runs it; retries the same request with a larger `max_tokens`, up to a ceiling, as "Stop reasons and fallback" advises |
| Truncated text | `max_tokens` with text last | Raises: a half answer is not an answer |
| Refusal | `refusal` (HTTP 200) | Raises with `stop_details`, so the caller can apply the documented handling: retry on a fallback Claude model, or for a `reasoning_extraction` refusal change the prompt. It never resends the same request to the same model |
| Server-tool pause | `pause_turn` | Appends the content unchanged as `assistant`, no new user message, continues |
| Context full | `model_context_window_exceeded` | Raises (Domain 3 covers compaction) |
| HTTP error | The SDK raises an exception | Not caught here: retries and backoff are Domain 4 |

Two choices here are judgment calls you may make differently. The "Stop reasons and fallback" and "Refusals and fallback" pages recommend retrying a refused request on a fallback Claude model (server-side with `fallbacks`, the SDK's refusal-fallback middleware, or your own retry); this loop leaves that to the caller to keep the code short, and you could build it in. A truncated text answer could be continued instead of raised. What matters is that the loop decides explicitly, and that no path returns partial output as if it were complete.

## The same idea at OpenAI and Google

The loop structure carries over: OpenAI's Responses API signals pending calls with `function_call` items and truncation with `status: "incomplete"`; Gemini's Interactions API uses `function_call` steps and a `status` field (see the vendor comparison in lesson 1.2-stop-reasons-context). The iteration cap, error tiers, parallel execution and logging are vendor-neutral.

## Key takeaways

- A robust loop adds a dispatch table, tiered error handling that never crashes the run, parallel execution for read-only tools with one results message, and logging of every model and tool call.
- Cap iterations; when the cap is reached, stop and report rather than returning whatever came last.
- `max_tokens` with an incomplete `tool_use` block: never run it; retry with a higher `max_tokens`, up to a ceiling.
- `refusal` arrives as HTTP 200; read `stop_details`. The documented handling is a retry on a fallback Claude model (for `reasoning_extraction`, change the prompt instead), rather than resending the same request to the same model.
- `pause_turn` (server tools only): append the content unchanged as `assistant` and continue without a new user message.
- Make every ending distinguishable to the caller: answer, cap, truncation, refusal, context full, HTTP error.
