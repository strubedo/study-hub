## The SDK you will use

The official Python SDK is the `mcp` package from the `modelcontextprotocol/python-sdk` repository. As of 2026-11-23 its current line is **v2** (PyPI lists 2.3.0, released 2026-10-02), and its documentation lives at `py.sdk.modelcontextprotocol.io`. Two naming facts matter if you read older tutorials:

- The high-level server class is **`MCPServer`**, imported with `from mcp.server import MCPServer`. In v1 it was `FastMCP` from `mcp.server.fastmcp`; the v2 "What's new" page lists the rename, and everything under `mcp.server.fastmcp.*` moved to `mcp.server.mcpserver.*`.
- The client is `from mcp import Client`. It speaks both protocol eras: it probes a server with `server/discover` and falls back to the legacy `initialize` handshake if the server is older.

Install it with `pip install "mcp[cli]"` (or `uv add "mcp[cli]"`). The `cli` extra adds the `mcp` command (`mcp dev`, `mcp run`, `mcp install`). The SDK's README and installation page require Python 3.11 or later (the PyPI metadata for 2.3.0 says 3.10; follow the documentation). SDK names change between major versions; check the SDK docs before copying anything here.

## The server: two read-only tools and one resource

The brief for Example Corp: a server that lets an agent look up devices and interface state from inventory, and **cannot change anything**. Here it reads a small dictionary of made-up devices so you can run it anywhere; a real version would call the inventory API with a read-only service account.

```python
"""Example Corp read-only inventory MCP server (stdio). Sample data only."""
import json
import logging
from typing import Annotated

from pydantic import Field

from mcp.server import MCPServer
from mcp.server.mcpserver.exceptions import ToolError
from mcp.types import ToolAnnotations

logger = logging.getLogger(__name__)  # logging writes to stderr, never stdout

mcp = MCPServer("example-netinv")

# Made-up devices. A real server would call the inventory API with a read-only account.
DEVICES = {
    "sw-core-01.example.com": {
        "site": "hq", "role": "core", "mgmt_ip": "10.10.0.11",
        "interfaces": {
            "TenGigabitEthernet1/1/1": {"admin": "up", "oper": "up", "speed_mbps": 10000, "crc_errors": 0},
            "TenGigabitEthernet1/1/2": {"admin": "up", "oper": "up", "speed_mbps": 10000, "crc_errors": 3},
        },
    },
    "sw-access-12.example.com": {
        "site": "hq", "role": "access", "mgmt_ip": "10.10.0.112",
        "interfaces": {
            "GigabitEthernet1/0/24": {"admin": "up", "oper": "down", "speed_mbps": 1000, "crc_errors": 0},
            "GigabitEthernet1/0/48": {"admin": "up", "oper": "up", "speed_mbps": 1000, "crc_errors": 1473},
        },
    },
    "rtr-branch-03.example.com": {
        "site": "branch-03", "role": "router", "mgmt_ip": "192.168.30.1",
        "interfaces": {
            "GigabitEthernet0/0/0": {"admin": "up", "oper": "up", "speed_mbps": 1000, "crc_errors": 0},
        },
    },
}

READ_ONLY = ToolAnnotations(read_only_hint=True, open_world_hint=False)


@mcp.tool(annotations=READ_ONLY)
def list_devices(
    site: Annotated[str | None, Field(description="Site code such as hq or branch-03. Omit to list every site.")] = None,
) -> list[dict[str, str]]:
    """Read-only. Lists Example Corp network devices with hostname, site, role and management IP.
    Use it to find the exact hostname before calling get_interface_status. Returns no interface data."""
    logger.info("list_devices site=%s", site)
    return [
        {"hostname": name, "site": d["site"], "role": d["role"], "mgmt_ip": d["mgmt_ip"]}
        for name, d in sorted(DEVICES.items())
        if site is None or d["site"] == site
    ]


@mcp.tool(annotations=READ_ONLY)
def get_interface_status(
    device_hostname: Annotated[str, Field(description="Full inventory hostname, for example sw-access-12.example.com")],
    interface_name: Annotated[str, Field(description="Full interface name, for example GigabitEthernet1/0/24. Do not abbreviate.")],
) -> dict[str, str | int]:
    """Read-only. Returns admin status, oper status, speed and CRC error count for ONE interface.
    Use it when a user reports a slow, flapping or dead port. Does not return configuration."""
    device = DEVICES.get(device_hostname)
    if device is None:
        raise ToolError(f"No device {device_hostname!r}. Call list_devices to get exact hostnames.")
    status = device["interfaces"].get(interface_name)
    if status is None:
        known = ", ".join(sorted(device["interfaces"]))
        raise ToolError(f"No interface {interface_name!r} on {device_hostname}. Known: {known}.")
    return {"device_hostname": device_hostname, "interface_name": interface_name, **status}


@mcp.resource("inventory://sites", mime_type="application/json")
def sites() -> str:
    """Site codes and the devices at each site, as JSON."""
    by_site: dict[str, list[str]] = {}
    for name, d in sorted(DEVICES.items()):
        by_site.setdefault(d["site"], []).append(name)
    return json.dumps(by_site)


if __name__ == "__main__":
    mcp.run()  # no argument: stdio transport
```

What each part does, according to the SDK documentation:

- **`@mcp.tool()`** registers a tool. The **function name** becomes the tool `name`, the **docstring** becomes the `description`, and the **type hints** become the `inputSchema`. `Annotated[..., Field(description=...)]` adds a description to each parameter, and a default value (`site = None`) makes a parameter optional. The SDK validates arguments against the schema before your function runs and sends a readable error back to the model if they do not match.
- **The return type** also produces an `outputSchema`, and the result arrives both as text in `content` (for the model) and as `structuredContent` (for the application). A `list` return is wrapped as `{"result": [...]}`.
- **`ToolError`** (from `mcp.server.mcpserver.exceptions`) is the documented way to report a failure the model should read: the result comes back with `isError` set to true and your message in `content`. Do not *return* an error string; the SDK docs point out that a returned string is a success. The messages say what to do next, as lesson 2.1-tool-results recommends.
- **`annotations=ToolAnnotations(read_only_hint=True, open_world_hint=False)`** sends `readOnlyHint` and `openWorldHint`. They help the host's UI; they do not make the tool read-only. What makes it read-only is that the code contains no write path.
- **`@mcp.resource("inventory://sites", mime_type="application/json")`** registers a resource at a fixed URI. The SDK only calls the function on `resources/read`, not when listing. Without `mime_type` it would be advertised as `text/plain`. A URI with a `{placeholder}` would make a resource template instead.
- **`mcp.run()`** with no argument serves over **stdio** and blocks. It sits under `if __name__ == "__main__":` because the SDK tools import the file.
- **Logging** uses the standard `logging` module, which writes to stderr. There is no `print()` anywhere: on stdio, stdout is the protocol (lesson 2.4-transports-auth).

The sample was compiled and its functions exercised offline against a stub of the SDK; it was **not** run against the real SDK.

## Run it and inspect it

Run it directly first: `python server.py` (Windows: `py server.py`). Nothing prints and it does not return; it is waiting for a client on stdin. Press Ctrl+C. A traceback here is a real bug to fix before involving any host.

Then open it in the **MCP Inspector**, the project's official testing tool (a Node.js application; its docs list the Node versions it needs):

```bash
uv run mcp dev server.py
```

`mcp dev` starts the Inspector (it needs `npx` on your `PATH`) and has it launch your file over stdio, exactly as a host would. In the web UI, the Tools tab shows both tools with forms built from your schemas; call `get_interface_status` with a good and a bad hostname and compare `isError`. The Resources tab lists `inventory://sites`. Expect the Protocol tab to show an `initialize` handshake: the Inspector's Protocol Era setting defaults to `legacy`, and your `MCPServer` answers that era too. Switch the server's Protocol Era to `auto` or `modern` to see the 2026-07-28 traffic (`server/discover`, `_meta` on every request).

The Inspector also has a scriptable CLI mode for CI checks. Its documentation shows `npx @modelcontextprotocol/inspector --cli node build/index.js --method tools/list` and says everything positional is the command to spawn, so for this server the command is `python server.py` (or the `uv run ...` launch command below) in place of `node build/index.js`.

For a repeatable test, the SDK's `Client` connects **in memory** when you pass it the server object; no process or port:

```python
import anyio

from mcp import Client

from server import mcp


async def main() -> None:
    async with Client(mcp, raise_exceptions=True) as client:
        listed = await client.list_tools()
        print([tool.name for tool in listed.tools])

        ok = await client.call_tool("get_interface_status", {"device_hostname": "sw-access-12.example.com", "interface_name": "GigabitEthernet1/0/48"})
        print(ok.is_error, ok.structured_content)

        bad = await client.call_tool("get_interface_status", {"device_hostname": "sw-acces-12.example.com", "interface_name": "Gi1/0/48"})
        print(bad.is_error, bad.content[0].text)

        sites = await client.read_resource("inventory://sites")
        print(sites.contents[0].text)


if __name__ == "__main__":
    anyio.run(main)
```

## Connect it to a host

A host needs **the command that starts your server**. The SDK docs recommend one launch command for every host, because `uv` builds the environment on the spot: `uv run --with "mcp[cli]" mcp run /absolute/path/to/server.py`. Use absolute paths: hosts start servers from their own working directory with a minimal environment.

**Claude Code.** Its MCP documentation registers a stdio server with `claude mcp add`; everything after `--` is the launch command, and options such as `--transport`, `--env` and `--scope` go before it:

```bash
claude mcp add --transport stdio netinv -- uv run --with "mcp[cli]" mcp run /absolute/path/to/server.py
```

With `--scope project`, Claude Code stores the entry in `.mcp.json` at the project root under `mcpServers`. A stdio entry there has `command`, `args` and optional `env`; `type` may be `"stdio"` or left out, because Claude Code reads an entry with no `type` as stdio:

```json
{
  "mcpServers": {
    "netinv": {
      "type": "stdio",
      "command": "uv",
      "args": ["run", "--with", "mcp[cli]", "mcp", "run", "/absolute/path/to/server.py"],
      "env": {}
    }
  }
}
```

Claude Code asks for approval before using project-scoped servers from `.mcp.json` in interactive sessions. Run `/mcp` in a session to see the server's status and tools.

**Claude Desktop** reads the same `mcpServers` shape (`command`, `args`, optional `env`) from `claude_desktop_config.json`. The MCP project's "Connect to local MCP servers" guide opens it with **Edit Config** in the app's developer settings and lists its location as macOS `~/Library/Application Support/Claude/`, Windows `%APPDATA%\Claude\`, Linux `~/.config/Claude/`. `uv run mcp install server.py` writes the entry for you, with absolute paths. Fully quit and reopen the app after editing.

## Claude's MCP connector for remote servers

The Messages API can also call a **remote** MCP server itself, with no MCP client in your code. The "MCP connector" page (2026-11-23) documents:

- **Beta**, enabled with the `anthropic-beta` header `mcp-client-2025-11-20`, or the newer `mcp-client-2026-09-15`, which adds tool-list pinning where the platform accepts it. The older `mcp-client-2025-04-04` version is deprecated.
- Two parts in the request: an **`mcp_servers`** array (each entry `type: "url"`, a `url` that must start with `https://`, a unique `name`, and an optional `authorization_token`) and, in `tools`, one **`mcp_toolset`** per server (`type: "mcp_toolset"`, `mcp_server_name`, optional `default_config`, `configs` and `cache_control`). Each server must be referenced by exactly one toolset.
- **Allowlisting**: set `default_config: {"enabled": false}` and enable named tools in `configs`.
- **Limits**: only **tool calls** are supported (no resources or prompts); the server must be publicly exposed over HTTP (Streamable HTTP or SSE); local stdio servers cannot be connected. You run the OAuth flow yourself and pass the access token.
- **Response blocks**: `mcp_tool_use` (with `server_name`) and `mcp_tool_result` (with `is_error`). The API runs these calls itself, like a server tool: the "Server tools" page says you never answer them with a `tool_result`. If Claude calls one of your own client tools in the same turn, the response ends with `stop_reason: "tool_use"` and an `mcp_tool_use` block that has no result yet; send only your client `tool_result` blocks, and the API runs the MCP call when you do.
- It is **not** eligible for zero data retention.

```python
import os

import anthropic

client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY from the environment

response = client.beta.messages.create(
    model="claude-haiku-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Is GigabitEthernet1/0/24 on sw-access-12.example.com up?"}],
    mcp_servers=[{
        "type": "url",
        "url": "https://mcp.example.com/mcp",
        "name": "netinv",
        "authorization_token": os.environ["NETINV_MCP_TOKEN"],
    }],
    tools=[{
        "type": "mcp_toolset",
        "mcp_server_name": "netinv",
        "default_config": {"enabled": False},
        "configs": {"list_devices": {"enabled": True}, "get_interface_status": {"enabled": True}},
    }],
    betas=["mcp-client-2025-11-20"],
)
print(response.stop_reason)
```

To use a **local** server with Claude instead, the same page documents client-side helpers in the Anthropic SDK (`async_mcp_tool` and friends in `anthropic.lib.tools.mcp`) that convert MCP tools for the tool runner.

The other vendors name the same idea differently: OpenAI's Responses API has a remote MCP tool (`type: "mcp"` with `server_label`, `server_url`, optional `allowed_tools` and `require_approval`), and the Gemini API has Remote MCP (`type: "mcp_server"` with `name`, `url`, `headers` and `allowed_tools`; Streamable HTTP servers only).

## The TypeScript SDK

The TypeScript SDK lives at `github.com/modelcontextprotocol/typescript-sdk`. Its v2 line (stable, targeting revision 2026-07-28) ships as separate packages, `@modelcontextprotocol/server` and `@modelcontextprotocol/client`, with `McpServer` and `StdioServerTransport` in its README example and any Standard Schema library (the README uses Zod v4) for schemas. The v1 package `@modelcontextprotocol/sdk` lives on the `v1.x` branch and still receives bug and security fixes.

## Try it yourself

Works on Windows, macOS and Linux; no model API calls in steps 1 to 5.

1. Create a virtual environment (`python3 -m venv .venv`, then `source .venv/bin/activate`; PowerShell: `py -m venv .venv` then `.venv\Scripts\Activate.ps1`) and install the SDK: `pip install "mcp[cli]"`. Docs: https://py.sdk.modelcontextprotocol.io/
2. Save the server as `server.py` and run `python server.py`. Confirm it waits silently, then Ctrl+C.
3. Add `print("netinv ready", flush=True)` at the top level, run it under `mcp dev` and watch the Inspector's Protocol tab and error output. (Without `flush=True` the line may sit in a buffer, which is exactly why a stray `print()` is hard to diagnose.) Remove it and replace it with `logger.info(...)`.
4. Save the test script as `check_server.py` and run it. Which call returns `is_error` true, and what does the message tell the model to do?
5. Register the server with Claude Code or Claude Desktop using an absolute path, and ask it which interface on `sw-access-12.example.com` is down.
6. Optional, small spend: if you can host the server over Streamable HTTP on a public HTTPS name (`mcp.run(transport="streamable-http")` behind your reverse proxy, with authentication), try the connector request above once with a small model; set `ANTHROPIC_API_KEY` with `export` (POSIX) or `$env:ANTHROPIC_API_KEY = "<api-key>"` (PowerShell).

## Key takeaways

- The Python SDK's v2 server class is `MCPServer` (`from mcp.server import MCPServer`); `@mcp.tool()`, `@mcp.resource(uri)` and `@mcp.prompt()` register primitives from plain functions.
- Function name, docstring and type hints become the tool's name, description and input schema; `ToolError` returns an `isError` result the model can read.
- `mcp.run()` defaults to stdio; never print to stdout, log to stderr.
- Test with `mcp dev` (the MCP Inspector) and with an in-memory `Client(mcp)`; then give a host the absolute launch command.
- Claude Code: `claude mcp add ... -- <command>` or `.mcp.json` under `mcpServers`; Claude Desktop: `claude_desktop_config.json`, same shape.
- Claude's MCP connector (beta) reaches public HTTPS servers only, supports tools only, and is configured with `mcp_servers` plus one `mcp_toolset` per server.
