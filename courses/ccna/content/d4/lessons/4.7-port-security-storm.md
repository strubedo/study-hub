## Layer 2 is the soft underbelly

Routers and firewalls rarely see attacks that stay inside one VLAN. MAC flooding, rogue DHCP servers, ARP spoofing, rogue IPv6 routers and broadcast storms all happen at the access switch. The 4.7 topics are the Catalyst features that stop them. This lesson covers **port security** and **storm control**; the next covers DHCP snooping, Dynamic ARP Inspection and RA guard.

## Port security

Port security limits **which** and **how many** source MAC addresses may send frames into an access port. It defends against MAC flooding (CAM table exhaustion) and against someone unplugging a desk phone or PC and plugging in an unauthorized device or a small switch.

### Requirements

* The port must be a **static access** port (`switchport mode access`) or a static trunk. On a port left in the default dynamic mode, the command is rejected:

```ios
SW1(config-if)# switchport port-security
Command rejected: GigabitEthernet1/0/5 is a dynamic port.
```

* Configuring parameters (maximum, violation) does nothing until you enter the bare `switchport port-security` command, which enables the feature.

### Configuration

```ios
SW1(config)# interface GigabitEthernet1/0/5
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 20
SW1(config-if)# switchport port-security
SW1(config-if)# switchport port-security maximum 2
SW1(config-if)# switchport port-security violation restrict
SW1(config-if)# switchport port-security mac-address sticky
```

Defaults when you only type `switchport port-security`:

| Setting | Default |
|---------|---------|
| Maximum secure MACs | 1 |
| Violation mode | shutdown |
| Sticky learning | off (addresses are learned dynamically and lost on reload or link down) |
| Aging | off (aging time 0) |

### How secure addresses are learned

* **Static** – `switchport port-security mac-address 0050.56a1.2b3c`. Saved in the config.
* **Dynamic** – learned from traffic; kept in the MAC table only, removed when the port goes down.
* **Sticky** – learned from traffic and **written into the running-config** as `switchport port-security mac-address sticky 3c52.8201.a4f0`. To survive a reload you must save the configuration (`copy running-config startup-config`).

> **Exam tip:** Sticky MACs appear in the running-config immediately but not in the startup-config until you save. "After a reload the switch learned a different MAC" usually means nobody saved.

### Violation modes

A violation occurs when a new MAC would exceed the maximum, or when a MAC secured on one port shows up on another secure port in the same VLAN.

| Mode | Offending traffic | Syslog / SNMP trap | Violation counter | Port state |
|------|-------------------|-------------------|-------------------|------------|
| protect | Dropped | No | Does not increment | Stays up |
| restrict | Dropped | Yes | Increments | Stays up |
| shutdown (default) | Dropped (port down) | Yes | Increments | **err-disabled** |

Traffic from already-secured MACs keeps flowing in protect and restrict modes. Shutdown takes the whole port down.

### Reading the show output

```ios
SW1# show port-security interface GigabitEthernet1/0/7
Port Security              : Enabled
Port Status                : Secure-shutdown
Violation Mode             : Shutdown
Aging Time                 : 0 mins
Aging Type                 : Absolute
SecureStatic Address Aging : Disabled
Maximum MAC Addresses      : 1
Total MAC Addresses        : 1
Configured MAC Addresses   : 0
Sticky MAC Addresses       : 1
Last Source Address:Vlan   : 0c1d.29e4.8a10:20
Security Violation Count   : 1
```

Port Status `Secure-shutdown` plus a violation count tells you the port is err-disabled. `Last Source Address` is the MAC that triggered it. Other useful commands: `show port-security` (one line per port), `show port-security address`, `show interfaces status err-disabled`.

The matching log messages:

```ios
%PM-4-ERR_DISABLE: psecure-violation error detected on Gi1/0/7, putting Gi1/0/7 in err-disable state
%PORT_SECURITY-2-PSECURE_VIOLATION: Security violation occurred, caused by MAC address 0c1d.29e4.8a10 on port GigabitEthernet1/0/7.
```

### Recovering an err-disabled port

Manual: fix the cause (remove the rogue device or clear/adjust the secure address), then bounce the port.

```ios
SW1(config)# interface GigabitEthernet1/0/7
SW1(config-if)# shutdown
SW1(config-if)# no shutdown
```

Automatic:

```ios
SW1(config)# errdisable recovery cause psecure-violation
SW1(config)# errdisable recovery interval 600
SW1# show errdisable recovery
```

The default recovery interval is 300 seconds. If the rogue device is still attached, the port goes err-disabled again on the next violation.

> **Watch out:** If the sticky MAC was learned from the wrong device, bouncing the port does not help; the old sticky address is still configured. Remove it with `no switchport port-security mac-address sticky <mac>` or `clear port-security sticky interface Gi1/0/7`.

> **Real world:** An IP phone with a PC behind it needs a maximum of at least 2 (the phone and the PC). Some designs use 3 to allow for the phone appearing on both the voice and data VLANs during boot.

## Storm control

A broadcast storm (often from a Layer 2 loop or a misbehaving NIC) can saturate every link in a VLAN and peg switch CPUs. Storm control measures incoming broadcast, multicast or unknown-unicast traffic per port over 1-second intervals and acts when it exceeds a threshold.

```ios
SW1(config)# interface GigabitEthernet1/0/10
SW1(config-if)# storm-control broadcast level 20.00 10.00
SW1(config-if)# storm-control multicast level pps 2k 1k
SW1(config-if)# storm-control action trap
```

* `level <rising> [falling]` as a percentage of the port bandwidth. When traffic rises above the rising threshold, the switch blocks that traffic class until it drops below the falling threshold. If you omit the falling value it equals the rising value.
* `level pps` or `level bps` sets absolute thresholds instead of a percentage (suffixes `k`, `m`, `g` are accepted).
* Only the **traffic type that exceeded** the threshold is blocked; other traffic keeps flowing.

### Actions

| Configuration | Result when the threshold is exceeded |
|---------------|----------------------------------------|
| No `storm-control action` (default) | Excess traffic of that type is **filtered (dropped)**; no message |
| `storm-control action trap` | Filters **and** sends an SNMP trap / syslog |
| `storm-control action shutdown` | Puts the port in **err-disabled** state (cause `storm-control`) |

```ios
SW1# show storm-control GigabitEthernet1/0/10 broadcast
Interface  Filter State   Upper        Lower        Current
---------  -------------  -----------  -----------  ----------
Gi1/0/10   Blocking         20.00%       10.00%       37.52%
```

`Blocking` means the current broadcast rate (37.52%) is above the upper threshold, so broadcasts are being dropped. `Forwarding` means normal.

> **Exam tip:** Storm control does not fix a loop; STP does. Storm control limits the damage while you find it. With `action shutdown`, recover the port exactly like any other err-disabled port, or with `errdisable recovery cause storm-control`.

## Comparing the two features

| | Port security | Storm control |
|--|---------------|---------------|
| Protects against | Unauthorized devices, MAC flooding | Broadcast/multicast/unknown-unicast floods |
| Measures | Source MAC addresses | Traffic rate per class |
| Default action | shutdown (err-disable) | filter (drop excess) |
| Key verify command | `show port-security interface` | `show storm-control` |

## Key takeaways

* Port security requires `switchport mode access` (static) and the bare `switchport port-security` command; defaults are maximum 1, violation shutdown.
* protect drops silently; restrict drops, logs and counts; shutdown err-disables the port.
* Sticky MACs go into the running-config; save to keep them across reloads.
* Recover err-disabled ports with `shutdown`/`no shutdown` or `errdisable recovery cause psecure-violation` (default interval 300 seconds).
* Storm control thresholds are a percentage, pps or bps with optional falling level; the default action filters, `trap` also alerts, `shutdown` err-disables.
* `show storm-control` shows Forwarding/Blocking and the current rate.
