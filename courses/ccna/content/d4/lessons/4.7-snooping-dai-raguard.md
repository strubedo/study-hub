## Three features, one idea

DHCP snooping, Dynamic ARP Inspection (DAI) and IPv6 RA guard all follow the same model: the switch divides ports into **trusted** (toward infrastructure: routers, DHCP servers, uplinks) and **untrusted** (toward end hosts), and it refuses to accept infrastructure-type messages from untrusted ports.

| Feature | Stops | Untrusted ports may not send |
|---------|-------|------------------------------|
| DHCP snooping | Rogue DHCP servers, DHCP starvation, spoofed releases | DHCP server messages (OFFER, ACK, NAK) |
| DAI | ARP spoofing / poisoning (man-in-the-middle) | ARP packets whose IP-to-MAC pair is not in the binding table |
| RA guard | Rogue IPv6 routers / SLAAC hijacking | ICMPv6 Router Advertisements (and redirects) |

## DHCP snooping

### What it checks on untrusted ports

* **Drops DHCP server messages** (DHCPOFFER, DHCPACK, DHCPNAK, and lease-query replies). A rogue DHCP server on an access port can no longer hand out a malicious default gateway or DNS server.
* **Verifies the source MAC** matches the client hardware address (chaddr) in the DHCP payload (`ip dhcp snooping verify mac-address`, on by default). This blocks the common starvation tool that spoofs chaddr.
* **Checks DHCPRELEASE and DHCPDECLINE** against the binding table, so a host cannot release another host's lease.
* **Optional rate limiting** (packets per second). Exceeding it err-disables the port (cause `dhcp-rate-limit`).

Trusted ports forward all DHCP messages normally.

### The binding table

As DHCP exchanges succeed on untrusted ports, the switch records **MAC, IP, lease, VLAN and interface**. This table is the foundation for DAI and IP Source Guard.

```ios
SW1# show ip dhcp snooping binding
MacAddress          IpAddress        Lease(sec)  Type           VLAN  Interface
------------------  ---------------  ----------  -------------  ----  --------------------
3C:52:82:01:A4:F0   10.10.20.57      85912       dhcp-snooping   20    GigabitEthernet1/0/5
0C:1D:29:E4:8A:10   10.10.20.61      86207       dhcp-snooping   20    GigabitEthernet1/0/7
Total number of bindings: 2
```

> **Real world:** The binding table lives in RAM. After a reload, hosts keep their leases but the switch has forgotten them, so DAI starts dropping their ARP until they renew. Store the table with `ip dhcp snooping database flash:dhcp-snooping.db` (or a remote URL).

### Configuration

```ios
SW1(config)# ip dhcp snooping
SW1(config)# ip dhcp snooping vlan 10,20
SW1(config)# no ip dhcp snooping information option
SW1(config)# interface GigabitEthernet1/0/48
SW1(config-if)# description Uplink to distribution
SW1(config-if)# ip dhcp snooping trust
SW1(config-if)# interface range GigabitEthernet1/0/1 - 46
SW1(config-if-range)# ip dhcp snooping limit rate 15
```

* Snooping must be enabled **globally and per VLAN**. Either one alone does nothing.
* Every port is **untrusted by default**. Trust the ports toward the legitimate DHCP server or relay (uplinks, and any port connecting to the server itself).

> **Watch out:** The classic outage after enabling snooping: nobody gets an address because the uplink was not trusted, so the real server's OFFERs are dropped. Trust the uplink; **never** trust access ports to "fix" it, which re-opens the rogue-server hole.

### The option 82 caveat

When snooping is enabled, Catalyst switches **insert DHCP option 82** (relay agent information: switch and port IDs) into client requests by default. The switch is not a relay, so it leaves the **giaddr** field as 0.0.0.0.

* An upstream **IOS router acting as relay or DHCP server** sees a packet with option 82 but giaddr 0.0.0.0 arriving on an untrusted interface and **drops** it by default. Clients get no address. Fix on the access switch with `no ip dhcp snooping information option` (the most common approach), or on the router with `ip dhcp relay information trusted` on the receiving interface (or `ip dhcp relay information trust-all` globally).
* An **aggregation switch** running snooping that receives option-82 packets from a downstream switch on an untrusted port also drops them unless you configure `ip dhcp snooping information option allow-untrusted`.

> **Exam tip:** If DHCP works the moment snooping is disabled, but fails with snooping on and the uplink correctly trusted, suspect option 82.

## Dynamic ARP Inspection

ARP has no authentication. An attacker can send gratuitous ARPs claiming to be the default gateway's IP with the attacker's MAC; every host updates its cache and sends its traffic through the attacker. DAI intercepts ARP requests and replies on **untrusted** ports in the configured VLANs and checks the **sender MAC/sender IP** pair against:

1. **ARP ACLs** (static entries you define), then
2. the **DHCP snooping binding table**.

No match = the ARP is dropped and logged.

```ios
SW1(config)# ip arp inspection vlan 20
SW1(config)# interface GigabitEthernet1/0/48
SW1(config-if)# ip arp inspection trust
```

* DAI **depends on DHCP snooping bindings**. Enable DHCP snooping for the same VLAN first, or every dynamic host's ARP is dropped.
* **Trust uplinks** and ports to other switches/routers. ARPs arriving there are not checked (the neighbor switch is expected to inspect its own access ports). The router's own ARP replies come in on the uplink.
* Untrusted ports are **rate-limited to 15 ARP pps by default**; exceeding it err-disables the port (cause `arp-inspection`). Adjust with `ip arp inspection limit rate <pps>`.

### Statically addressed hosts

A printer or server with a static IP never does DHCP, so it has no binding and DAI drops its ARPs. Add an ARP ACL:

```ios
SW1(config)# arp access-list STATIC-HOSTS
SW1(config-arp-nacl)# permit ip host 10.10.20.5 mac host 0011.2233.4455
SW1(config-arp-nacl)# exit
SW1(config)# ip arp inspection filter STATIC-HOSTS vlan 20
```

(An alternative is a static entry in the snooping table with `ip source binding <mac> vlan 20 <ip> interface <if>`.)

### Optional validation

`ip arp inspection validate src-mac dst-mac ip` adds checks that the Ethernet source MAC matches the ARP sender MAC, that the destination MACs match on replies, and that IP addresses are not invalid (0.0.0.0, broadcast, multicast). Enter all keywords on one line; each new `validate` command replaces the previous one.

### Reading a DAI drop

```ios
%SW_DAI-4-DHCP_SNOOPING_DENY: 1 Invalid ARPs (Req) on Gi1/0/9, vlan 20.([0011.2233.4455/10.10.20.5/0000.0000.0000/10.10.20.1/09:14:22 UTC Fri Oct 23 2026])
```

The bracket lists sender MAC / sender IP / target MAC / target IP. "DHCP_SNOOPING_DENY" tells you the pair was not found in the binding table (or an ARP ACL). `show ip arp inspection statistics vlan 20` shows forwarded and dropped counts.

## IPv6 RA guard

IPv6 hosts learn their default gateway (and, with SLAAC, their prefix) from **Router Advertisements**. Any host can send an RA. A rogue or misconfigured device (a laptop sharing its connection, for example) can become the default router for a whole VLAN. RA guard inspects ICMPv6 RAs arriving on a port and drops them when the port is not supposed to have a router behind it.

```ios
SW1(config)# ipv6 nd raguard policy HOST-PORTS
SW1(config-nd-raguard)# device-role host
SW1(config-nd-raguard)# exit
SW1(config)# ipv6 nd raguard policy ROUTER-PORT
SW1(config-nd-raguard)# device-role router
SW1(config-nd-raguard)# exit
SW1(config)# interface range GigabitEthernet1/0/1 - 46
SW1(config-if-range)# ipv6 nd raguard attach-policy HOST-PORTS
SW1(config-if-range)# interface GigabitEthernet1/0/48
SW1(config-if)# ipv6 nd raguard attach-policy ROUTER-PORT
```

* **device-role host** (the default role in a policy) – all inbound RAs (and ICMPv6 redirects) on the port are dropped.
* **device-role router** – RAs are allowed. A router policy can add checks such as `match ra prefix-list`, `managed-config-flag on` and `hop-limit` limits so even legitimate-looking RAs must carry expected values.
* RA guard filters **ingress** RAs on the port where the policy is attached.
* Verify with `show ipv6 nd raguard policy HOST-PORTS`.

> **Watch out:** RA guard can be evaded by RAs hidden behind IPv6 extension headers or fragmentation on older implementations. Newer switches drop such packets; this is why RA guard is one layer among several (DHCPv6 guard, IPv6 snooping) rather than a complete fix.

## Recommended order of deployment

1. Enable DHCP snooping on the VLANs, trust uplinks, deal with option 82, and confirm the binding table fills.
2. Add ARP ACLs for static hosts.
3. Enable DAI on the VLANs, trust uplinks, monitor `show ip arp inspection statistics`.
4. Attach RA guard host policy to access ports, router policy where the real router connects.

## Key takeaways

* Trusted = toward infrastructure, untrusted = toward hosts; all ports are untrusted by default.
* DHCP snooping needs `ip dhcp snooping` **and** `ip dhcp snooping vlan`; trust the uplink, not the access ports.
* Snooping inserts option 82 by default; with an IOS relay/server upstream, use `no ip dhcp snooping information option` (or trust option 82 on the relay).
* DAI validates sender IP/MAC against ARP ACLs and the snooping binding table; trust uplinks; ARP ACLs (`ip arp inspection filter`) cover static hosts; default limit 15 pps.
* RA guard: `ipv6 nd raguard policy` with `device-role host` (block RAs) or `router` (allow), applied with `ipv6 nd raguard attach-policy`.
* Rate-limit violations err-disable ports (`dhcp-rate-limit`, `arp-inspection`).
