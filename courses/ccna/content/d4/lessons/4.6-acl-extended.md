## Extended ACL anatomy

Extended ACLs match far more than the source. The general form:

```ios
permit|deny <protocol> <source> <src-wildcard> [operator port] <destination> <dst-wildcard> [operator port] [established] [log]
```

* **protocol** – `ip` (any IPv4), `tcp`, `udp`, `icmp`, `ospf`, `gre`, `esp`, or a protocol number (0–255).
* **source / destination** – address + wildcard, or `host x.x.x.x`, or `any`.
* **ports** – only valid with `tcp` or `udp`. The port written right after the **source** matches the **source port**; the port after the **destination** matches the **destination port**.
* **established** – TCP only; matches segments with the ACK or RST bit set (that is, not the initial SYN).

Numbered ranges: **100–199** and **2000–2699**. Named: `ip access-list extended NAME`.

## Port operators

| Operator | Meaning | Example |
|----------|---------|---------|
| `eq` | equal to | `eq 443`, `eq www` (80) |
| `neq` | not equal to | `neq 23` |
| `gt` | greater than | `gt 1023` |
| `lt` | less than | `lt 1024` |
| `range` | inclusive range | `range 20 21` |

IOS accepts names for common ports and displays them in `show` output: `www` (80), `telnet` (23), `smtp` (25), `domain` (53), `ftp` (21), `ftp-data` (20), `tacacs` (49), `bootps` (67, UDP), `bootpc` (68, UDP), `snmp` (161, UDP), `ntp` (123, UDP). Ports without a keyword (on most releases that includes 22 and 443) are shown as numbers.

> **Watch out:** The port position is the most common extended-ACL mistake. `permit tcp any eq 80 host 10.1.50.10` matches traffic whose **source** port is 80, which is the server's reply, not a client request. A client request to a web server is `permit tcp any host 10.1.50.10 eq 80`.

## Writing a policy

Requirement: hosts in 10.1.10.0/24 may reach the web server 10.1.50.10 on HTTP and HTTPS, and the DNS server 10.1.50.53 on UDP and TCP 53. Everything else from that subnet to 10.1.50.0/24 is blocked. Traffic from 10.1.10.0/24 to other destinations is allowed.

```ios
R1(config)# ip access-list extended USERS-IN
R1(config-ext-nacl)# remark Web
R1(config-ext-nacl)# 10 permit tcp 10.1.10.0 0.0.0.255 host 10.1.50.10 eq 80
R1(config-ext-nacl)# 20 permit tcp 10.1.10.0 0.0.0.255 host 10.1.50.10 eq 443
R1(config-ext-nacl)# remark DNS
R1(config-ext-nacl)# 30 permit udp 10.1.10.0 0.0.0.255 host 10.1.50.53 eq domain
R1(config-ext-nacl)# 40 permit tcp 10.1.10.0 0.0.0.255 host 10.1.50.53 eq domain
R1(config-ext-nacl)# 50 deny ip 10.1.10.0 0.0.0.255 10.1.50.0 0.0.0.255
R1(config-ext-nacl)# 60 permit ip 10.1.10.0 0.0.0.255 any
R1(config-ext-nacl)# exit
R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# ip access-group USERS-IN in
```

Gi0/0/0 is the interface facing 10.1.10.0/24, so this is **near the source**, **inbound**. Packets from any other source address arriving on that interface hit the implicit deny, which also blocks spoofed sources.

> **Exam tip:** When the question says "near the source", look for **inbound** on the interface facing the source subnet. Outbound on that same interface filters traffic going **toward** the users instead.

## Sequence numbers and editing

Named ACLs (and numbered ones edited through `ip access-list`) number each ACE, by default 10, 20, 30...

**Insert** an entry between two existing ones:

```ios
R1(config)# ip access-list extended USERS-IN
R1(config-ext-nacl)# 45 permit icmp 10.1.10.0 0.0.0.255 10.1.50.0 0.0.0.255 echo
```

**Delete** one entry:

```ios
R1(config-ext-nacl)# no 20
```

**Renumber** when you run out of gaps:

```ios
R1(config)# ip access-list resequence USERS-IN 10 10
```

Entries you add without a number go to the **end** (highest sequence + 10), which means **after** any final `deny`, where they will never match. This is a classic mistake.

## Reading `show access-lists`

```ios
R1# show access-lists USERS-IN
Extended IP access list USERS-IN
    10 permit tcp 10.1.10.0 0.0.0.255 host 10.1.50.10 eq www (1542 matches)
    20 permit tcp 10.1.10.0 0.0.0.255 host 10.1.50.10 eq 443 (8810 matches)
    30 permit udp 10.1.10.0 0.0.0.255 host 10.1.50.53 eq domain (4021 matches)
    40 permit tcp 10.1.10.0 0.0.0.255 host 10.1.50.53 eq domain
    45 permit icmp 10.1.10.0 0.0.0.255 10.1.50.0 0.0.0.255 echo (12 matches)
    50 deny ip 10.1.10.0 0.0.0.255 10.1.50.0 0.0.0.255 (97 matches)
    60 permit ip 10.1.10.0 0.0.0.255 any (66310 matches)
```

* Port 80 is displayed as `www` and 53 as `domain`, even though you typed numbers.
* An entry with no counter has not matched since the counters were last cleared.
* Counters increase on the entry that **matched first**, which helps prove which line is catching traffic.
* The implicit deny is not shown and not counted.

## The `established` keyword

`established` is a simple, stateless way to allow return TCP traffic. Example: on the internet-facing interface inbound, permit replies to sessions that inside users started, but not new inbound connections:

```ios
R1(config)# ip access-list extended FROM-INTERNET
R1(config-ext-nacl)# permit tcp any 10.1.0.0 0.0.255.255 established
R1(config-ext-nacl)# deny ip any any log
```

It matches any TCP segment with ACK or RST set, so a crafted packet with ACK set also passes. It is not stateful inspection, and it does nothing for UDP or ICMP (DNS replies, for example, would be dropped). Firewalls and reflexive/zone-based policies do this properly.

## Common protocol matches

| Goal | ACE |
|------|-----|
| SSH to a router | `permit tcp <mgmt> host <rtr> eq 22` |
| DHCP from clients (to relay/server) | `permit udp any any eq bootps` |
| OSPF | `permit ospf any any` (protocol 89) |
| Ping requests | `permit icmp <src> <dst> echo` |
| Ping replies | `permit icmp <src> <dst> echo-reply` |
| IPsec | `permit udp any any eq isakmp`, `permit udp any any eq non500-isakmp`, `permit esp any any` |

> **Watch out:** An inbound extended ACL on a router interface also filters packets addressed to the router itself (routing protocol hellos, SSH, DHCP relay). If you add an inbound ACL on a link running OSPF and forget `permit ospf`, the adjacency drops after the dead timer.

## Evaluating "which traffic is permitted" questions

1. Identify the interface and direction where the ACL is applied.
2. For the packet in question, figure out its source and destination **as seen at that interface in that direction**.
3. Walk the ACEs top-down; stop at the first match.
4. If nothing matches, it is denied.
5. Remember return traffic: an ACL on one interface does not automatically allow the replies through an ACL on another.

## Key takeaways

* Extended ACLs (100–199, 2000–2699 or named) match protocol, source, destination and ports; place them near the source.
* The port after the source is the source port; the port after the destination is the destination port.
* `eq`, `neq`, `gt`, `lt`, `range`; IOS shows well-known ports by name (`www`, `domain`).
* Named ACLs use sequence numbers: insert with a number, delete with `no <seq>`, renumber with `ip access-list resequence`.
* Unnumbered additions go to the end, after any explicit deny.
* `established` matches TCP with ACK or RST; it is stateless and does not help UDP.
* `show access-lists` counters show which line matched; the implicit deny is invisible.
