## Same idea, new address family

IPv6 static routing follows exactly the same logic as IPv4: longest prefix match for forwarding, AD 1 by default, floating routes by raising the AD, and a route is only installed when its next hop resolves. The differences are syntax, link-local addresses, and the fact that the router must be told to route IPv6 at all.

## Prerequisite: `ipv6 unicast-routing`

IOS does not forward IPv6 packets between interfaces until you enable it globally:

```ios
R1(config)# ipv6 unicast-routing
```

Without it, the router behaves like an IPv6 host: it can have addresses and will even accept `ipv6 route` commands, but it will not route transit IPv6 traffic, and it does not send Router Advertisements. It is the first thing to check when "the IPv6 routes look right but nothing passes through".

## Syntax

```ios
R1(config)# ipv6 route <prefix>/<length> {<next-hop> | <exit-interface> [<next-hop>]} [<AD>]
```

The prefix is written in slash notation; there is no mask argument. Examples on a router whose Gi0/0/0 faces R2 (global 2001:DB8:0:12::2, link-local FE80::2):

| Purpose | Command |
|---|---|
| Network route, global next hop | `ipv6 route 2001:DB8:20::/48 2001:DB8:0:12::2` |
| Network route, link-local next hop | `ipv6 route 2001:DB8:20::/48 GigabitEthernet0/0/0 FE80::2` |
| Fully specified with global next hop | `ipv6 route 2001:DB8:20::/48 GigabitEthernet0/0/0 2001:DB8:0:12::2` |
| Host route (/128) | `ipv6 route 2001:DB8:20::25/128 2001:DB8:0:12::2` |
| Default route | `ipv6 route ::/0 2001:DB8:0:12::2` |
| Floating default | `ipv6 route ::/0 2001:DB8:0:99::1 130` |

## Link-local next hops require the exit interface

Every IPv6 interface has a link-local address in `FE80::/10`, and the same link-local address can legitimately exist on several links (many engineers configure `FE80::1` on every router interface). A link-local address therefore means nothing without the interface it belongs to. IOS refuses a static route that uses a link-local next hop without naming the exit interface, and asks you to specify one.

```ios
R1(config)# ipv6 route 2001:DB8:20::/48 FE80::2
! rejected: an interface must be specified for a link-local next hop
R1(config)# ipv6 route 2001:DB8:20::/48 GigabitEthernet0/0/0 FE80::2
! accepted
```

Why use link-local next hops at all? They do not change when the global prefix is renumbered, and they are what IPv6 routing protocols use, so static and dynamic routes look alike.

> **Exam tip:** In `show ipv6 route`, a next hop that starts with `FE80::` is always paired with an interface name. If an answer option shows a link-local next hop without an interface in an `ipv6 route` command, it is wrong.

## Exit-interface-only routes

`ipv6 route 2001:DB8:20::/48 GigabitEthernet0/0/0` is accepted, but on Ethernet the router treats every destination in the prefix as on-link and runs Neighbor Discovery for the final destination address. Unless something on the segment answers for those addresses, traffic fails. As with IPv4, use exit-interface-only routes on point-to-point links (serial, tunnels) only.

## Verifying

```ios
R1# show ipv6 route static
IPv6 Routing Table - default - 9 entries
Codes: C - Connected, L - Local, S - Static (legend shortened)
S   ::/0 [1/0]
     via 2001:DB8:0:12::2
S   2001:DB8:20::/48 [1/0]
     via FE80::2, GigabitEthernet0/0/0
S   2001:DB8:30::25/128 [1/0]
     via 2001:DB8:0:13::3
```

Two-line entries: the prefix and `[AD/metric]` on the first line, the next hop (and interface when relevant) on the second. The entry count in the header covers the whole IPv6 table, including connected, local and the `FF00::/8` entry, not only the static routes printed.

Useful commands:

- `show ipv6 route` / `show ipv6 route static` / `show ipv6 route 2001:DB8:20::7` (performs the lookup)
- `show running-config | include ipv6 route`
- `show ipv6 interface brief` (addresses and up/down state; shows the link-local address of each interface)
- `show ipv6 neighbors` (the IPv6 equivalent of the ARP table)
- `ping` and `traceroute` with IPv6 destinations

## Floating IPv6 static routes

Exactly as in IPv4, a higher AD keeps the route out of the table while a better route exists:

```ios
! Primary default comes from OSPFv3 (AD 110)
R1(config)# ipv6 route ::/0 2001:DB8:0:99::1 130
```

The route appears in `show ipv6 route` only when the OSPFv3 default disappears.

## Troubleshooting IPv6 static routes

| Symptom | Likely cause |
|---|---|
| Static route configured, router does not forward transit IPv6 | `ipv6 unicast-routing` missing |
| Route command rejected | Link-local next hop entered without an exit interface |
| Route configured but not installed | Global next hop not covered by any route (recursive failure), exit interface down, or a lower-AD route to the same prefix |
| Route installed, traffic fails at first hop | Wrong next hop: wrong link-local (check `show ipv6 neighbors` / `show cdp neighbors detail`), or the link-local belongs to a different interface than the one named |
| One-way reachability | Missing return route on the far router, same as IPv4 |
| Prefix typo | IPv6 compression errors such as `2001:DB8:2::/64` versus `2001:DB8:0:2::/64` are different prefixes |

> **Watch out:** `2001:DB8:2::/64` expands to `2001:0DB8:0002:0000::/64` while `2001:DB8:0:2::/64` expands to `2001:0DB8:0000:0002::/64`. Both are valid, they are not the same network, and the mistake is easy to make in a static route.

> **Real world:** Link-local next hops survive global renumbering, but they couple the route to one physical interface. If the link moves to another port, the static route must be edited too.

## Key takeaways

- Enable `ipv6 unicast-routing` or the router will not forward IPv6 at all.
- Syntax: `ipv6 route <prefix>/<len> <next-hop | interface [next-hop]> [AD]`; default AD is 1.
- A link-local next hop must be paired with the exit interface.
- Default route is `ipv6 route ::/0 <next-hop>`; a host route uses `/128`.
- Floating IPv6 statics work the same way: AD above the primary route's AD.
- Avoid exit-interface-only routes on Ethernet; they rely on Neighbor Discovery for every destination.
