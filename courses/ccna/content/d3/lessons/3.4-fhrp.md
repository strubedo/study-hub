## The problem FHRPs solve

Hosts are configured (statically or by DHCP) with **one** default gateway address. If that router or SVI fails, every host on the subnet loses off-subnet connectivity even if a second router is sitting on the same VLAN. A **First Hop Redundancy Protocol** lets two or more routers share a **virtual IP address** and a **virtual MAC address**. Hosts use the virtual IP as their gateway; ARP for it returns the virtual MAC; whichever router is currently active answers for that MAC. When the active router fails, another takes over the same virtual IP and MAC, and the hosts never notice beyond a few lost packets.

The blueprint verb for 3.4 is **interpret**: you must read `show standby` and `show vrrp` output and say who is forwarding, who takes over, and what is misconfigured.

## HSRP (Cisco proprietary)

### Roles and election

- **Active** router: owns the virtual IP/MAC and forwards traffic sent to the gateway.
- **Standby** router: monitors the active router and takes over if it disappears.
- Any other routers in the group sit in **Listen**.
- Highest **priority** becomes active (0–255, **default 100**). Tie: highest interface **IP address** wins.
- **Preemption is disabled by default.** Without `standby <group> preempt`, a higher-priority router that comes up later (or recovers) stays standby and does **not** take back the active role.

Timers: **hello 3 seconds, hold 10 seconds**. If the standby hears no hello from the active for the hold time, it becomes active.

### Versions

| | HSRPv1 | HSRPv2 |
|---|---|---|
| Multicast destination | 224.0.0.2 (UDP 1985) | 224.0.0.102 (UDP 1985) |
| Group numbers | 0–255 | 0–4095 |
| Virtual MAC | `0000.0c07.acXX` (XX = group in hex, 2 digits) | `0000.0c9f.fXXX` (XXX = group in hex, 3 digits) |
| IPv6 support | No | Yes (IPv6 groups use `0005.73a0.0XXX` and FF02::66) |

Examples: HSRPv1 group 10 uses `0000.0c07.ac0a`; HSRPv2 group 10 uses `0000.0c9f.f00a`; HSRPv2 group 300 (0x12C) uses `0000.0c9f.f12c`.

> **Watch out:** v1 and v2 are not compatible. If one router runs `standby version 2` and the other does not, they never hear each other's hellos and both become Active.

### HSRP states

| State | Meaning |
|---|---|
| **Initial** | HSRP is starting or the interface just came up |
| **Learn** | No virtual IP configured locally and no hello from the active router heard yet |
| **Listen** | Knows the virtual IP; is neither active nor standby; listens for hellos |
| **Speak** | Sends hellos and takes part in the active/standby election |
| **Standby** | Next in line to become active |
| **Active** | Forwarding traffic for the virtual IP and MAC |

In a group with three routers, one is Active, one Standby, and the third settles in Listen.

### Configuration

```ios
DSW1(config)# interface Vlan10
DSW1(config-if)# ip address 10.10.10.2 255.255.255.0
DSW1(config-if)# standby version 2
DSW1(config-if)# standby 10 ip 10.10.10.1
DSW1(config-if)# standby 10 priority 110
DSW1(config-if)# standby 10 preempt
```

DSW2 has `ip address 10.10.10.3`, the same version, group and virtual IP, and the default priority 100.

### Reading `show standby brief`

```ios
DSW1# show standby brief
                     P indicates configured to preempt.
                     |
Interface   Grp  Pri P State   Active          Standby         Virtual IP
Vl10        10   110 P Active  local           10.10.10.3      10.10.10.1
Vl20        20   90    Standby 10.10.20.3      local           10.10.20.1
```

| Column | Meaning |
|---|---|
| `Pri` | This router's priority in the group |
| `P` | Preemption configured on **this** router |
| `State` | This router's state |
| `Active` / `Standby` | Who holds each role; `local` means this router; `unknown` means nobody (or not heard) |
| `Virtual IP` | The gateway address hosts use |

So DSW1 forwards for VLAN 10 and DSW2 (10.10.20.3) forwards for VLAN 20. Splitting the active role per VLAN like this is the usual way to use both uplinks with HSRP.

### Reading `show standby`

```ios
DSW1# show standby Vlan10
Vlan10 - Group 10 (version 2)
  State is Active
    2 state changes, last state change 00:41:07
  Virtual IP address is 10.10.10.1
  Active virtual MAC address is 0000.0c9f.f00a (MAC In Use)
    Local virtual MAC address is 0000.0c9f.f00a (v2 default)
  Hello time 3 sec, hold time 10 sec
    Next hello sent in 1.744 secs
  Preemption enabled
  Active router is local
  Standby router is 10.10.10.3, priority 100 (expires in 9.312 sec)
  Priority 110 (configured 110)
  Group name is "hsrp-Vl10-10" (default)
```

The MAC format confirms version 2 and group 10 (0x00a). `Preemption enabled` plus the higher priority means DSW1 will take the active role back after it recovers from a failure.

> **Exam tip:** "Router has the higher priority but is Standby" almost always means **preempt is missing on that router**. Raising its priority further does nothing without preempt.

> **Watch out:** **Both routers Active** with `Standby unknown` means they cannot hear each other's hellos: the VLAN is missing from the trunk between them, an ACL drops the hellos, or the versions or group numbers differ. Hosts will then see the virtual MAC moving between switches.

## VRRP (open standard)

VRRP (RFC 5798 for VRRPv3; VRRPv2 is RFC 3768) does the same job with different vocabulary:

| | HSRP | VRRP |
|---|---|---|
| Standard | Cisco proprietary | IETF open standard |
| Roles | Active / Standby | **Master / Backup** |
| Default priority | 100 | 100 |
| Preemption default | **Disabled** | **Enabled** |
| Multicast | 224.0.0.2 (v1) / 224.0.0.102 (v2) | **224.0.0.18** (IP protocol 112) |
| Virtual MAC | `0000.0c07.acXX` / `0000.0c9f.fXXX` | **`0000.5e00.01XX`** (XX = VRID in hex) |
| Virtual IP | Must be a spare address in the subnet | May be a spare address **or one of the router's real addresses** |
| Default timers | Hello 3 s, hold 10 s | Advertisement 1 s, master down ≈ 3 × advertisement + skew |

If the virtual IP equals a router's own interface address, that router is the **address owner**: its priority is automatically **255**, it is always master when up, and it always preempts.

```ios
R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# ip address 192.168.5.2 255.255.255.0
R1(config-if)# vrrp 5 ip 192.168.5.1
R1(config-if)# vrrp 5 priority 120
```

```ios
R1# show vrrp brief
Interface          Grp Pri Time  Own Pre State   Master addr     Group addr
Gi0/0/0            5   120 3531       Y  Master  192.168.5.2     192.168.5.1
```

`Pre Y` shows preemption (on by default), `Own` is blank because R1 is not the address owner, `Time` is the master-down interval in milliseconds (3 × 1000 ms + skew; the skew is smaller for higher priorities), `Master addr` is the real address of the current master and `Group addr` is the virtual IP.

> **Real world:** Newer IOS-XE releases implement VRRPv3 under `fhrp version vrrp v3`, with `vrrp 5 address-family ipv4` sub-mode syntax and a slightly different `show vrrp brief` layout. The concepts (master, backup, priority, preemption, owner) are identical. The commands shown above are the classic VRRPv2 form.

## GLBP, briefly

GLBP (Cisco proprietary) adds **load balancing** within a single group. One **Active Virtual Gateway (AVG)** answers ARP requests for the virtual IP with different virtual MACs (`0007.b400.XXYY`), each owned by an **Active Virtual Forwarder (AVF)**, so different hosts use different routers. Hellos go to 224.0.0.102 on UDP 3222. HSRP and VRRP, by contrast, have only one forwarding router per group; load sharing requires multiple groups (for example, one per VLAN).

## Key takeaways

- FHRPs give hosts one virtual gateway IP and MAC, served by whichever router is active/master.
- HSRP: default priority 100, highest priority then highest IP wins, **preempt off by default**, hello 3 s / hold 10 s.
- HSRPv1: 224.0.0.2, groups 0–255, MAC `0000.0c07.acXX`. HSRPv2: 224.0.0.102, groups 0–4095, MAC `0000.0c9f.fXXX`.
- HSRP states: Initial, Learn, Listen, Speak, Standby, Active.
- VRRP: open standard, master/backup, 224.0.0.18, MAC `0000.5e00.01XX`, **preempt on by default**, owner priority 255.
- Higher priority but still standby: missing preempt. Both active: hellos not getting through.
- GLBP load-balances inside one group using an AVG and multiple AVFs.
