## What DHCP hands out

DHCPv4 (RFC 2131) leases a host its IPv4 address and mask plus **options** such as the default gateway (option 3), DNS servers (option 6), domain name (option 15), and lease time (option 51). It runs over UDP: **servers listen on port 67, clients on port 68**.

## DORA

| Step | Message | Source to destination | Notes |
|---|---|---|---|
| 1 | **Discover** | 0.0.0.0:68 to **255.255.255.255:67** | Client has no address yet, so it broadcasts. Contains its MAC (chaddr) |
| 2 | **Offer** | Server:67 to client:68 | Proposed address and options. Sent broadcast or unicast depending on the client's **broadcast flag** |
| 3 | **Request** | 0.0.0.0:68 to **255.255.255.255:67** | Still a broadcast, so **every** server that made an offer learns which one was accepted |
| 4 | **Acknowledge** | Server:67 to client:68 | Lease confirmed; client may ARP to check the address is unused before using it |

Other messages: **DHCPNAK** (server refuses a request, for example the client moved subnets), **DHCPDECLINE** (client found the address already in use), **DHCPRELEASE** (client gives the address back, unicast), **DHCPINFORM** (client has an address and only wants options).

### Renewal timers

* **T1 = 50%** of the lease: the client **unicasts** a Request to the server that granted the lease.
* **T2 = 87.5%**: if renewal failed, the client **broadcasts** a Request to any server (rebinding).
* At expiry the client must stop using the address and start over with Discover.

> **Exam tip:** Discover and Request from a new client are broadcasts. Offer and Ack can be unicast or broadcast; renewals at T1 are unicast. Questions that say "all four DORA messages are broadcast" or "all are unicast" are wrong.

## IOS as a DHCP server

```ios
R1(config)# ip dhcp excluded-address 192.168.10.1 192.168.10.20
R1(config)# ip dhcp pool VLAN10-USERS
R1(dhcp-config)# network 192.168.10.0 255.255.255.0
R1(dhcp-config)# default-router 192.168.10.1
R1(dhcp-config)# dns-server 10.10.50.53 10.10.50.54
R1(dhcp-config)# domain-name corp.example
R1(dhcp-config)# lease 2 12
```

* `ip dhcp excluded-address low [high]` is a **global** command. Exclude the gateway, servers, printers, and any other static addresses. It is entered outside the pool.
* `network` defines which addresses the pool hands out **and** which subnet the pool serves. The server picks the pool whose network contains the address of the receiving interface (or the relay's giaddr).
* `default-router` sets option 3. Forgetting it gives clients an address but no gateway.
* `lease days [hours] [minutes]`; the default lease is **1 day**. `lease infinite` is possible but rarely wise.
* The DHCP server service is on by default; `no service dhcp` disables both the server and relay functions.

Before offering an address, the IOS server **pings** it (2 pings by default). If something answers, the address is recorded as a **conflict** and skipped.

## DHCP relay: ip helper-address

A Discover is a broadcast, and routers do not forward broadcasts. If the server is on another subnet, the router interface facing the **clients** must relay:

```ios
R1(config)# interface GigabitEthernet0/0/1.10
R1(config-subif)# encapsulation dot1Q 10
R1(config-subif)# ip address 192.168.10.1 255.255.255.0
R1(config-subif)# ip helper-address 10.10.50.10
```

What the relay does:

1. Receives the client's broadcast on the interface configured with `ip helper-address`.
2. Writes **its own interface address (192.168.10.1) into the giaddr field**.
3. **Unicasts** the message to 10.10.50.10 (UDP 67).
4. The server uses **giaddr** to choose the right pool (the one whose network contains 192.168.10.1) and replies to the relay, which forwards the reply to the client.

> **Watch out:** `ip helper-address` goes on the **client-facing** interface (the SVI or subinterface for the client VLAN), not on the interface that faces the server. Also, by default `ip helper-address` forwards several other UDP broadcasts too (TFTP 69, DNS 53, Time 37, IEN-116 name service 42, TACACS 49, NetBIOS 137/138, BOOTP/DHCP 67); `no ip forward-protocol udp <port>` turns individual ports off.

On a Layer 3 switch the same command goes on the SVI: `interface Vlan10` then `ip helper-address 10.10.50.10`.

The server must also have a **route back** to the giaddr subnet; otherwise its Offers never reach the relay.

## IOS as a DHCP client

An internet-facing router interface often gets its address from the ISP:

```ios
R1(config)# interface GigabitEthernet0/0/0
R1(config-if)# ip address dhcp
R1(config-if)# no shutdown

R1# show ip interface brief | include 0/0/0
GigabitEthernet0/0/0   203.0.113.45    YES DHCP   up                    up
```

The **Method** column shows `DHCP`. If the server supplies a default gateway, IOS installs a static default route toward it with **administrative distance 254**, so any manually configured default route (AD 1) overrides it.

## Common faults

| Symptom | Likely cause | Fix |
|---|---|---|
| Clients get 169.254.x.x | No server reachable: missing `ip helper-address`, helper on the wrong interface, wrong helper IP, ACL dropping UDP 67, wrong access VLAN, DHCP snooping dropping offers on an untrusted uplink | Correct relay placement, permit UDP 67/68, trust the uplink |
| Clients get an address but cannot leave the subnet | Missing or wrong `default-router` | Fix option 3 |
| Clients in one VLAN get addresses from another VLAN's range | Server matched the wrong pool (giaddr unexpected), or two pools/servers overlapping | Check `network` statements and giaddr |
| Some clients fail, others are fine; pool shows all addresses used | **Pool exhaustion** | Shorten lease, enlarge the subnet, or remove stale bindings |
| Address conflicts logged, users report duplicate IP | Static devices inside the pool range not excluded | Add `ip dhcp excluded-address`; clear conflicts |
| Offers seen at server but clients never receive them | Server has no route back to the giaddr subnet | Add the route |
| Pool exists but no addresses handed out on a directly connected LAN | Pool `network` does not match the interface subnet | Make the pool's network match |

## Key takeaways

* DORA: Discover and Request are broadcasts from 0.0.0.0; server port **67**, client port **68**.
* Renewal: T1 at 50% (unicast), T2 at 87.5% (broadcast).
* `ip dhcp excluded-address` is global; exclude the gateway and every static address.
* The pool's `network` must match the subnet of the receiving interface or giaddr; include `default-router` and `dns-server`.
* `ip helper-address` goes on the **client-facing** interface; the relay fills in **giaddr** and unicasts to the server.
* `ip address dhcp` makes an IOS interface a DHCP client; a learned default route has AD 254.
* Use `show ip dhcp binding`, `pool`, `conflict`, and `server statistics` to troubleshoot.
