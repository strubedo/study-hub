## The problem these features solve

Rapid PVST+ trusts every BPDU it receives. That makes it vulnerable to three things: an end-user plugging in a switch (or a loop through a cheap hub), a new switch with a low priority stealing the root role, and a link that silently stops delivering BPDUs in one direction. PortFast speeds up host ports; BPDU guard, root guard and loop guard each defend against one of those failure modes.

| Feature | Configure on | Trigger | Action | Recovery |
|---|---|---|---|---|
| **PortFast** | Host-facing ports | Link up | Skip discarding/learning, forward immediately | — |
| **BPDU guard** | PortFast/host ports | **Any** BPDU received | Port **err-disabled** | Manual (`shutdown`/`no shutdown`) or errdisable recovery |
| **Root guard** | Designated ports that must never lead to the root (e.g., distribution downlinks) | **Superior** BPDU received | Port **root-inconsistent** (discarding) for that VLAN | **Automatic** when superior BPDUs stop |
| **Loop guard** | Root and alternate ports (non-designated) on inter-switch links | BPDUs **stop arriving** | Port **loop-inconsistent** (discarding) instead of becoming designated | **Automatic** when BPDUs resume |

## PortFast (edge ports)

Without PortFast, a host port that comes up waits in discarding/learning before forwarding. With RSTP the handshake doesn't happen toward a host (hosts don't send BPDUs), so the port can take up to 2 × forward delay (30 s) — long enough to break DHCP or PXE boot. PortFast makes the port an **edge port**: it goes straight to forwarding, and link up/down events on it do not generate topology changes.

```ios
SW1(config)# interface GigabitEthernet1/0/10
SW1(config-if)# spanning-tree portfast
%Warning: portfast should only be enabled on ports connected to a single
 host. Connecting hubs, concentrators, switches, bridges, etc... to this
 interface  when portfast is enabled, can cause temporary bridging loops.
 Use with CAUTION
```

Global form, which applies to all **access** ports (not trunks):

```ios
SW1(config)# spanning-tree portfast default
```

Variants: `spanning-tree portfast trunk` for a trunk to a hypervisor or server, and `spanning-tree portfast disable` to exclude one port from the global default. (Some IOS releases use the `edge` keyword: `spanning-tree portfast edge`, `spanning-tree portfast edge default`.)

An edge port still sends BPDUs. If it **receives** one, it immediately loses its edge status and behaves like a normal spanning-tree port — that's the safety net. In `show spanning-tree` an operational edge port shows `P2p Edge` in the Type column.

> **Watch out:** PortFast never goes on links to other switches. A port that forwards immediately on a switch-to-switch link can create a temporary loop before BPDUs arrive.

## BPDU guard

BPDU guard assumes a port should never hear a BPDU. If one arrives, the port is shut down into the **err-disabled** state:

```ios
SW1(config)# interface GigabitEthernet1/0/18
SW1(config-if)# spanning-tree bpduguard enable
```

or globally for every port that is operationally PortFast:

```ios
SW1(config)# spanning-tree portfast bpduguard default
```

When it fires:

```ios
%SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port GigabitEthernet1/0/18 with BPDU Guard enabled. Disabling port.
%PM-4-ERR_DISABLE: bpduguard error detected on Gi1/0/18, putting Gi1/0/18 in err-disable state

SW1# show interfaces GigabitEthernet1/0/18
GigabitEthernet1/0/18 is down, line protocol is down (err-disabled)
```

Recovery: remove the offending device first, then `shutdown` followed by `no shutdown` on the interface. Or automate it:

```ios
SW1(config)# errdisable recovery cause bpduguard
SW1(config)# errdisable recovery interval 300      ! default is 300 seconds
```

Automatic recovery re-enables the port after the interval; if the switch is still there, the port err-disables again.

> **Exam tip:** The interface-level command (`spanning-tree bpduguard enable`) works whether or not PortFast is on. The global command (`spanning-tree portfast bpduguard default`) only covers ports that are operating as PortFast edge ports.

### BPDU filter (for contrast)

`spanning-tree bpdufilter enable` on an interface stops sending **and** ignores received BPDUs — effectively turning STP off on that port. It can cause loops and is not a substitute for BPDU guard. (The global `spanning-tree portfast bpdufilter default` behaves differently: edge ports stop sending BPDUs but revert to normal STP if one is received.)

## Root guard

Root guard protects the **placement** of the root bridge. Apply it on ports where the root should **never** appear — typically the distribution switches' downlinks to access switches:

```ios
DSW1(config)# interface range GigabitEthernet1/0/1 - 24
DSW1(config-if-range)# spanning-tree guard root
```

If a **superior BPDU** (one advertising a better root) arrives on such a port, the port is placed in the **root-inconsistent** state for that VLAN — it discards, so the rogue switch cannot become root through that path:

```ios
%SPANTREE-2-ROOTGUARD_BLOCK: Root guard blocking port GigabitEthernet1/0/24 on VLAN0010.

SW1# show spanning-tree inconsistentports

Name                 Interface                Inconsistency
-------------------- ------------------------ ------------------
VLAN0010             GigabitEthernet1/0/24    Root Inconsistent

Number of inconsistent ports (segments) in the system : 1
```

It is **not** err-disabled. As soon as the superior BPDUs stop (someone lowers the rogue switch's priority or removes it), the port recovers automatically and goes through normal role selection (`%SPANTREE-2-ROOTGUARD_UNBLOCK`).

> **Watch out:** Never put root guard on a port that legitimately leads to the root — for example an access switch's uplink (its root port). The real root's BPDUs are superior by definition, so the uplink would go root-inconsistent and isolate the access switch.

## Loop guard

Loop guard protects against **unidirectional** failures. Picture an alternate port that is discarding because it keeps receiving BPDUs from the designated port across the link. If the fiber's receive strand fails (or the neighbor's software stops sending BPDUs), the BPDUs stop; normally the port would age out the information, decide it is now designated and **start forwarding** — creating a loop.

With loop guard, a root or alternate port that stops receiving BPDUs goes **loop-inconsistent** (discarding) instead:

```ios
SW2(config)# interface GigabitEthernet1/0/2
SW2(config-if)# spanning-tree guard loop
! or globally, for all point-to-point links:
SW2(config)# spanning-tree loopguard default

%SPANTREE-2-LOOPGUARD_BLOCK: Loop guard blocking port GigabitEthernet1/0/2 on VLAN0010.
```

It recovers automatically when BPDUs are received again. Loop guard is configured on non-designated ports (root and alternate); on a designated port it has nothing to protect. Root guard and loop guard cannot both be enabled on the same port.

> **Real world:** UDLD (Unidirectional Link Detection) solves the same unidirectional-link problem at Layer 2 for fiber links; many designs run both.

## Where each feature goes

```text
            [DSW1 root primary]====[DSW2 root secondary]
              |  root guard            root guard |
              |  (downlinks)          (downlinks) |
           uplink: loop guard optional on root/alternate ports
              |                                   |
          [ASW1] ------------------------------ [ASW2]
            | PortFast + BPDU guard on every host port |
          hosts                                    hosts
```

- **Access switch host ports:** PortFast + BPDU guard.
- **Distribution downlinks to access switches:** root guard.
- **Inter-switch links where a port is root/alternate:** loop guard (often enabled globally).
- **Root bridges:** set with `root primary`/`secondary` (or explicit priorities) so the design, not MAC addresses, decides.

## Verification commands

```ios
show spanning-tree vlan 10                 ! Type column shows Edge, *ROOT_Inc, *LOOP_Inc
show spanning-tree interface Gi1/0/10 detail
show spanning-tree inconsistentports       ! root- and loop-inconsistent ports
show spanning-tree summary                 ! global PortFast, BPDU guard, loop guard defaults

show errdisable recovery                   ! which causes auto-recover, and the timer
```

## Key takeaways

- PortFast = edge port, forwards immediately; global `spanning-tree portfast default` covers access ports only. An edge port that receives a BPDU loses edge status.
- BPDU guard err-disables a port on **any** BPDU; recover with `shutdown`/`no shutdown` or `errdisable recovery cause bpduguard`.
- Root guard puts a port in **root-inconsistent** on a **superior** BPDU; it recovers automatically. Use it on distribution downlinks, never on a port toward the real root.
- Loop guard puts a root/alternate port in **loop-inconsistent** when BPDUs **stop**; it recovers automatically.
- Root guard and loop guard are mutually exclusive on a port.
- Err-disabled is a shutdown state; inconsistent states are STP blocking states.
