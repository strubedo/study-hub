## What an edge port is

An **edge port** connects an end device rather than another switch: a desktop, printer, camera, IP phone, access point, hypervisor host, server or appliance. Topic 2.2 is about choosing the right Layer 2 attributes for each kind of device: access vs trunk, which VLAN(s), PoE, and whether to bundle links.

## Desktops, printers and IoT devices

A single-VLAN device gets a static access port. A hardened template:

```ios
SW1(config)# interface GigabitEthernet1/0/5
SW1(config-if)# description PRINTER-2F-EAST
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 40
SW1(config-if)# spanning-tree portfast
SW1(config-if)# spanning-tree bpduguard enable
```

- `switchport mode access` stops DTP from ever negotiating a trunk (the Catalyst 9000 default, `dynamic auto`, would trunk with a `desirable` peer).
- `switchport access vlan 40` places the device in its VLAN. In VTP server or transparent mode, if VLAN 40 does not exist IOS creates it and prints `% Access VLAN does not exist. Creating vlan 40`.
- PortFast lets the port forward immediately at link-up, so DHCP doesn't time out while STP converges; BPDU guard shuts the port if someone plugs in a switch (see topic 2.5).

IoT devices (badge readers, sensors, cameras, building controllers) usually go in **their own VLAN** so they can be filtered separately; many are powered by PoE. Ports that should never supply power (a kiosk in a lobby, for example) can be set with `power inline never`.

## IP phones and the voice VLAN

A typical Cisco phone has a small built-in switch: the uplink goes to the access switch and a PC plugs into the phone. The switch port carries **two VLANs** while remaining an access port:

```ios
SW1(config)# interface GigabitEthernet1/0/12
SW1(config-if)# switchport mode access
SW1(config-if)# switchport access vlan 10
SW1(config-if)# switchport voice vlan 110
SW1(config-if)# spanning-tree portfast
```

How it works:

1. The switch advertises the voice VLAN to the phone — via **CDP** to Cisco phones, or via the **LLDP-MED** Network Policy TLV to phones that use LLDP (LLDP must be enabled with `lldp run`).
2. The phone sends its voice traffic **tagged** with VLAN 110 (802.1Q, typically CoS 5).
3. The PC behind the phone sends **untagged** frames, which the switch places in the **access (data) VLAN 10**.

```ios
SW1# show interfaces GigabitEthernet1/0/12 switchport
Name: Gi1/0/12
Switchport: Enabled
Administrative Mode: static access
Operational Mode: static access
...
Access Mode VLAN: 10 (USERS)
Trunking Native Mode VLAN: 1 (default)
...
Voice VLAN: 110 (VOICE)
```

The port does **not** appear in `show interfaces trunk`. In `show vlan brief` it is listed under both VLAN 10 and VLAN 110.

> **Watch out:** `Access Mode VLAN: 10 (Inactive)` means VLAN 10 is not in the VLAN database (deleted, or the switch is a VTP client that never learned it). The port is up but drops traffic for that VLAN.

> **Exam tip:** If a phone ends up with an address from the *data* subnet, the phone never learned a voice VLAN: check that `switchport voice vlan` is configured and that CDP (or LLDP-MED) is running on the port.

## Power over Ethernet

The switch is the **PSE** (power sourcing equipment); the phone, AP or camera is the **PD** (powered device). The switch detects a valid PD signature before applying power, then reads the PD's **class** to budget power.

| Standard | Common name | Type | Max power at the PSE port | Power available at the PD |
|---|---|---|---|---|
| 802.3af | PoE | Type 1 | 15.4 W | 12.95 W |
| 802.3at | PoE+ | Type 2 | 30 W | 25.5 W |
| 802.3bt | PoE++ / 4PPoE | Type 3 | 60 W | 51 W |
| 802.3bt | PoE++ / 4PPoE | Type 4 | 90 W | 71.3 W |

The PD's class tells the switch how much to reserve: class 0 (unclassified) and class 3 = 15.4 W, class 1 = 4 W, class 2 = 7 W, class 4 = 30 W, and the 802.3bt classes 5–8 = 45, 60, 75 and 90 W. Cisco UPOE (60 W) and UPOE+ (90 W) are Cisco's four-pair implementations in the same ranges.

Interface commands:

| Command | Effect |
|---|---|
| `power inline auto` | Default: detect and power PDs as the budget allows |
| `power inline auto max 15400` | Auto, but cap the port at 15.4 W (value in milliwatts) |
| `power inline static [max N]` | Pre-allocate power to the port, guaranteed even when the budget is tight |
| `power inline never` | Never supply power |

```ios
SW1# show power inline

Module   Available     Used     Remaining
          (Watts)     (Watts)    (Watts)
------   ---------   --------   ---------
1           370.0      362.1         7.9
Interface Admin  Oper       Power   Device              Class Max
                            (Watts)
--------- ------ ---------- ------- ------------------- ----- ----
Gi1/0/1   auto   on         30.0    C9130AXI-B          4     30.0
Gi1/0/2   auto   on         6.3     IP Phone 8845       2     30.0
Gi1/0/24  auto   power-deny 0.0     Ieee PD             4     30.0
```

`power-deny` means a PD was detected but the switch could not allocate its power — here only 7.9 W remain for a class 4 device. Other `Oper` values: `on` (powered), `off` (nothing detected or `never`), `faulty`, `err-disable`.

## Wireless access points

How an AP forwards client traffic decides the switch port type:

| AP mode | Client traffic path | Switch port |
|---|---|---|
| Lightweight AP, **local mode** (controller based) | Tunneled to the WLC inside CAPWAP | **Access** port in the AP management VLAN |
| Lightweight AP, **FlexConnect local switching** | Bridged onto the local switch in each SSID's VLAN | **Trunk**: native VLAN = AP management VLAN, allowed = management + client VLANs |
| **Autonomous / standalone** AP with several SSIDs mapped to VLANs | Bridged locally | **Trunk** with the SSID VLANs |

In local mode the switch never sees client VLAN tags — all client frames arrive inside the AP's CAPWAP tunnel sourced from the AP's management IP. The WLC (not the access switch) maps WLANs to VLANs.

> **Real world:** Modern Wi-Fi 6/6E/7 APs often need PoE+ or better for full functionality (all radios, USB, multigigabit). An AP on an 802.3af port may boot in a reduced-power mode — check `show power inline` and the AP's own power status.

## Virtualized hosts

A hypervisor (ESXi, Hyper-V, KVM) carries many VMs in many VLANs, so its uplinks are normally **802.1Q trunks** allowing the VM VLANs. The virtual switch tags frames per port group.

```ios
SW1(config)# interface range GigabitEthernet1/0/20 - 21
SW1(config-if-range)# switchport mode trunk
SW1(config-if-range)# switchport trunk allowed vlan 10,20,30
SW1(config-if-range)# switchport nonegotiate
SW1(config-if-range)# spanning-tree portfast trunk
```

- Hypervisors do not speak DTP: use a static trunk.
- Virtual switches don't run STP, so `spanning-tree portfast trunk` lets the trunk forward immediately (some IOS releases spell it `spanning-tree portfast edge trunk`).
- **Link bundling depends on the virtual switch.** A VMware vSphere Standard Switch with "Route based on IP hash" needs a **static** EtherChannel (`channel-group N mode on`) because it does not support LACP; a vSphere Distributed Switch or a Linux bond in 802.3ad mode can run **LACP**. Many hypervisor designs use no port channel at all and let the host load-share by virtual port.

## Network appliances

Firewalls, load balancers, storage and servers often attach with an **LACP port channel** for bandwidth and redundancy, as an access port channel or a trunk port channel depending on how many VLANs the appliance needs.

```ios
SW1(config)# interface range GigabitEthernet1/0/45 - 46
SW1(config-if-range)# switchport mode trunk
SW1(config-if-range)# switchport trunk allowed vlan 100,200
SW1(config-if-range)# channel-group 3 mode active
```

A Linux bond in `802.3ad` mode, Windows NIC teaming in LACP mode and most firewalls use LACP; pair them with `active` (or `passive`) on the switch. Never pair LACP on the host with `on` on the switch.

## Choosing the port type — summary

| Device | Port mode | VLANs | Extras |
|---|---|---|---|
| Desktop, printer | Access | One data VLAN | PortFast, BPDU guard |
| IoT/camera | Access | Dedicated IoT VLAN | PoE class/budget |
| IP phone + PC | Access + voice VLAN | Data (untagged) + voice (tagged) | PoE, CDP/LLDP-MED |
| AP, local mode | Access | AP management VLAN | PoE+ or better |
| AP, FlexConnect / autonomous | Trunk | Mgmt (native) + client VLANs | PoE |
| Hypervisor host | Trunk | VM VLANs | portfast trunk; static or LACP channel per vSwitch type |
| Firewall/server bond | Access or trunk port channel | As needed | LACP active |

## Key takeaways

- Host ports: `switchport mode access`, an access VLAN, PortFast and BPDU guard.
- Voice VLAN: phone traffic tagged in the voice VLAN, PC traffic untagged in the access VLAN; the phone learns the voice VLAN via CDP or LLDP-MED.
- PoE: 802.3af 15.4 W, 802.3at 30 W, 802.3bt Type 3 60 W, Type 4 90 W (at the PSE); `power-deny` means not enough budget.
- Local-mode lightweight APs need an access port (CAPWAP tunnels client traffic); FlexConnect local switching and autonomous APs need trunks.
- Hypervisor uplinks are trunks; a vSphere Standard Switch needs `mode on`, not LACP.
- Appliances and servers with LACP bonds pair with `channel-group N mode active`.
