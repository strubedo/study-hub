## Four ways to push configuration

| Operation | Where | What it pushes | Preview / cancel |
|---|---|---|---|
| **Install Policy Package & Device Settings** (Install Wizard) | Device Manager or Policy & Objects > Install Wizard | Copies the chosen package (and templates) into the device database, then installs the diff of everything to the FortiGate | Install Preview, Policy Package Diff, cancel any time before Install |
| **Install Device Settings (only)** (Install Wizard) | Install Wizard | The device database (device layer) only; no package copy | Install Preview, cancel |
| **Re-install Policy** | Re-install Policy from the Install Wizard dropdown (Policy & Objects) or the Install menu (Device Manager) | The package **already assigned** to the device(s), without the wizard's first page | Install Preview, Policy Package Diff, cancel |
| **Quick Install (Device DB)** | Device Manager > Install menu | The device database | **No preview, cannot be cancelled** |

Fortinet's guidance: for a device that has **no package installed yet**, use the Install Wizard with Install Policy Package & Device Settings the first time; once a package is assigned and installed, Re-install Policy is the quick path for later changes. Quick Install suits zero-touch provisioning and changes you already understand.

> **Exam tip:** Install Device Settings (only) is the FortiManager-wins fix for a **Conflict** config status on device-level settings. It does not touch the package, so it will not clear a Modified policy package status.

## The Install Wizard step by step

Device Manager > Device & Groups > **Install Wizard** (or Install > Install Wizard; the same button exists in Policy & Objects).

**Page 1: what to install.** Choose Install Policy Package & Device Settings (or Install Device Settings (only)) and set:

| Field | Purpose |
|---|---|
| Policy Package | The package to install |
| Comment | Free text, stored with the install |
| Create ADOM Revision | Save an ADOM revision (name and comments) as part of this install |
| Schedule Install | Install at a set date and time instead of now |
| Install and Unlock | Only shown in workspace mode when `workspace-unlock-after-install` is enabled; unlocks the ADOM when done |

**Page 2: devices.** Select the devices or groups to install to. The ADOM setting **Default Device Selection for Install** (Select All or Deselect All) decides whether the package's targets start ticked.

**Validation.** FortiManager validates each selected device:

* **Policy and object** validation (objects and policies are valid for the device and its ADOM version).
* **Interface** validation (every normalized interface used has a mapping for the device).
* **Installation preparation** (the copy into the device database succeeds).
* If the ADOM has **Perform Policy Check Before Every Install** enabled, a policy consistency check runs on added or modified policies, and the ADOM's **Action When Conflicts Occur** decides whether installation continues or stops.

Devices that fail validation are **skipped**; the others can still be installed. Click the link in the error message to open the progress report with the failing lines highlighted.

If the policy and object count passes a configured threshold you get a warning. The threshold warning is disabled by default; its value is a **percentage** of the object limit (1-100, default 80 in the 7.6 CLI Reference):

```text
FMG-HQ # config system admin setting
FMG-HQ (setting) # set object-threshold-limit enable
FMG-HQ (setting) # set object-threshold-limit-value 90
FMG-HQ (setting) # end
```

**Install Preview (optional).** Shows the exact CLI FortiManager will send to each device, for one or several devices at once (pick them from Assigned Devices), and lets you **Download** it as a text file. Metadata variables appear as their resolved values.

**Policy Package Diff (optional).** Compares the package with the policy currently on the device, with Details links for policies, each policy category and policy objects. The FGFM connection must be up.

**Install.** Click Install (or Schedule Install). The wizard shows per-device status, warnings and errors. **View History** and **View Log** open the install history and log.

## Reading an install preview

```text
Install Preview - FGT-Branch2 [root]

config firewall address
    edit "Store-LAN"
        set subnet 10.152.0.0 255.255.255.0
    next
end
config firewall policy
    edit 4
        set name "POS-Out"
        set srcintf "port3"
        set dstintf "wan1"
        set srcaddr "Store-LAN"
        set dstaddr "all"
        set action accept
        set schedule "always"
        set service "HTTPS"
        set nat enable
    next
end
config firewall address
    delete "Old-Printer"
end
```

What it tells you: `Store-LAN` resolved to FGT-Branch2's mapped value; the normalized interface used in the policy resolved to `port3` on this device; and an address nobody references any more is being removed. Because FortiManager sends a **diff**, the preview contains only what changes, not the whole package.

## Reading an install log

```text
Starting log (Run on device)
Start installing
FGVM02TM24000102 $ config firewall address
FGVM02TM24000102 (address) $ edit "Store-LAN"
FGVM02TM24000102 (Store-LAN) $ set subnet 10.152.0.0 255.255.255.0
FGVM02TM24000102 (Store-LAN) $ next
FGVM02TM24000102 (address) $ end
FGVM02TM24000102 $ config firewall policy
FGVM02TM24000102 (policy) $ edit 4
new entry '4' added
FGVM02TM24000102 (4) $ set name "POS-Out"
...
FGVM02TM24000102 (4) $ next
FGVM02TM24000102 (policy) $ end
---> generating verification report
<--- done generating verification report
install finished
```

The log replays the CLI sent to the FortiGate, with the device's responses. Note the prompt: Fortinet's own install log example uses the FortiGate's **serial number** (here FGT-Branch2's, FGVM02TM24000102), not its hostname. On a failed install, look for the FortiOS error under the command that caused it (for example `entry not found in datasource` followed by `value parse error before ...` and `Command fail.`), and use the device's Revision History > **View Install Log** to see logs of earlier installs. Troubleshooting failed installs in depth is Domain 5.

> **Real world:** After each policy package install the FortiGate restarts the FGFM tunnel and reconnects to FortiManager. If the reconnection fails, the FGFM recovery logic tries to get the FortiGate back to its previous configuration (Domain 5). With `rollback-allow-reboot` enabled under `config system dm` on FortiManager (disabled by default), the FortiGate is allowed to reboot to recover that previous configuration.

## Re-install Policy

Re-install Policy is for devices that **already have a package assigned**. Select the package in Policy & Objects and choose Re-install Policy from the Install Wizard dropdown, or select one or more devices in Device Manager and choose **Install > Re-install Policy**. After you confirm and FortiManager gathers data, the Re-install Policy Package window offers:

* **Install Preview** (several devices at once; Download or Download All)
* **Policy Package Diff**

Then click Next to install, and optionally view or download the installation log. The Re-install window has no first page, so there is no package choice and none of the page-1 options (Create ADOM Revision, Schedule Install); use the full wizard when you need those.

> **Watch out:** Re-install pushes FortiManager's version. If the device is **Out of Sync** because someone changed it locally and you want to keep that change, re-installing overwrites it. Import first (accepting the FortiGate value) and then install.

## Install settings in the ADOM

System Settings > ADOMs > Edit (Normal mode ADOMs):

| Setting | Effect |
|---|---|
| Default Device Selection for Install | Select All or Deselect All targets on the wizard's device page |
| Perform Policy Check Before Every Install | Automatic consistency check of added or modified policies |
| Action When Conflicts Occur During Policy Check | Continue Installation or Stop Installation |
| Auto-Push Policy Packages When Device Back Online | Installs pending package updates to offline devices when they reconnect |

## Partial installs

Normally an object change reaches devices through a package install. With partial install enabled, you can push selected objects directly with **More > Install Object(s)**:

```text
FMG-HQ # config system global
FMG-HQ (global) # set partial-install enable
FMG-HQ (global) # end
```

Install Preview works there too: if the object is not used in a policy, the device list shows **No record found**, and metadata variables display their real values. After an object is installed, the policy packages stay flagged **Modified** until their next full install. FortiManager 7.4.1 and later also support partial installs through the JSON API.

## Lab it yourself

1. Change a mapped address in `Branch-PP`, then use the Install Wizard with **Create ADOM Revision** ticked, and download the Install Preview for both branches.
2. Remove the per-device interface mapping for FGT-Branch2 from a normalized interface and run the wizard again: Branch2 fails interface validation and is skipped while Branch1 installs.
3. Restore the mapping and use **Re-install Policy**; compare the windows with the full wizard.
4. Enable Perform Policy Check Before Every Install with Stop Installation, add a shadowed policy, and watch the install stop.
5. Open the device's Revision History and read View Install Log.

## Key takeaways

* Install Policy Package & Device Settings copies the package into the device database and installs the diff; Install Device Settings (only) pushes only the device layer.
* Re-install Policy is for devices that already have a package assigned and offers Install Preview and Policy Package Diff before installing.
* Quick Install (Device DB) has no preview and cannot be cancelled.
* Validation covers policy and object, interface mapping and installation preparation; failing devices are skipped.
* Install Preview shows the exact CLI per device with resolved variables; the install log shows the CLI session and its responses.
* ADOM settings control default device selection, automatic policy check and its action, and auto-push to devices that come back online.
