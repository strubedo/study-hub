## What an ADOM revision is

An **ADOM revision** is a saved copy of an ADOM's policy-layer content at a point in time: its **policy packages, objects and VPN console (VPN Manager) settings**. It lets you roll the whole ADOM's policy configuration back after a bad change, or compare today's database with last week's.

It is not a device backup. Device settings such as interfaces, routes and system configuration live in each device's database and have their own revision history.

| | ADOM revision | Device configuration revision |
|---|---|---|
| Contents | Policy packages, ADOM objects, VPN console | One FortiGate's full configuration file |
| Where | Policy & Objects > **ADOM Revisions** | Device Manager > device > Dashboard > Configuration and Installation widget > **Revision History** |
| Created | Manually, or by ticking **Create ADOM Revision** in the Install Wizard | Automatically after installs, retrieves and auto-updates |
| Restore effect | Reverts packages, objects and VPN console in the ADOM database | **Revert** loads the revision into the device database only |
| Next step after restore | Install the affected packages | Import, then re-install the package (or install device settings) |

A third "undo" mechanism exists in workflow mode: **reverting a session** creates a new session that undoes later sessions (lesson 3.1). And each policy package keeps its own per-package revision history for View Diff. Know which tool answers which question.

Policy & Objects > ADOM Revisions shows:


The lock icon beside revision 14 means **Lock this revision from auto deletion** is set.

| Action | What it does |
|---|---|
| Create New | Name, optional description, optional **Lock this revision from auto deletion** |
| Edit | Change name, description or the lock checkbox |
| Delete | Removes a revision; a locked revision cannot be deleted |
| View Revision Diff | Compares the selected revision with the **current database**: Global Policy, Policy Package and ADOM-level object changes, with [Details], CLI Diff and CSV download |
| Restore | Reverts policy packages, objects and VPN console to the selected revision (confirmation required) |
| More > Lock / Unlock Revision | Protects or releases a revision from auto deletion |
| Settings | Auto deletion |

### Automatic deletion

Settings > **Auto delete revision**, then one of:

* **Keep last x revisions**: the oldest is deleted when a new one is created.
* **Delete revisions older than x days**.

Locked revisions are exempt. Lock your baselines (pre-upgrade, pre-freeze) so that a busy install schedule does not age them out.

### Creating revisions during installs

The Install Wizard's first page (Install Policy Package & Device Settings) has a **Create ADOM Revision** checkbox with a revision name and comments. Ticking it on every significant install gives you a restore point that lines up with each push.

> **Exam tip:** Restoring an ADOM revision changes only FortiManager's ADOM database. Nothing reaches the FortiGates until you install. After a restore, expect the targets of every package whose content changed to show **Modified**, and an install (with Install Preview) is what actually rolls the devices back.

## Restoring safely

1. Use **View Revision Diff** first to see exactly what the restore will change.
2. In workspace mode, lock the ADOM.
3. Restore the revision.
4. Run the Install Wizard to the affected devices and check Install Preview; restored objects can change many devices at once because objects are shared.

Remember that a restore also reverts objects that other packages use, and VPN console settings. If only one package was damaged, consider fixing that package (or using its per-package revision history) rather than restoring the whole ADOM.

## ADOM revisions and other backups

ADOM revisions complement, not replace, a FortiManager system backup (from the dashboard's System Information widget, or `execute backup all-settings ...` in the CLI, covered in Domain 1). A system backup contains every ADOM, the device databases and system settings. An ADOM revision covers a single ADOM's policy layer, but you can restore it without touching anything else.

ADOM revisions are also not tied to ADOM versions: before an ADOM upgrade, take a system backup (the upgrade converts the database format), and use an ADOM revision for policy-level checkpoints during normal operations.

## Lab it yourself

1. In Policy & Objects, click ADOM Revisions > Create New and make `baseline` with the lock checkbox set.
2. Change an address used by `Branch-PP` and delete a policy.
3. View Revision Diff on `baseline` and read the Policy Package and object sections and the CLI Diff.
4. Restore `baseline`, then look at Device Manager: the package targets show Modified until you install.
5. Set Auto delete revision to Keep last 2, create three more revisions, and confirm the locked baseline survives.

## Key takeaways

* ADOM revisions save policy packages, objects and VPN console settings for one ADOM; they do not include device settings.
* Create them manually or with Create ADOM Revision in the Install Wizard.
* View Revision Diff compares a revision with the current database; Restore reverts the ADOM database only.
* After a restore, install to push the rollback to devices.
* Auto deletion keeps the last x revisions or deletes those older than x days; locked revisions are exempt and cannot be deleted.
* Device revision history (Revert) works on the device database; workflow session Revert undoes later sessions; these are different tools.
