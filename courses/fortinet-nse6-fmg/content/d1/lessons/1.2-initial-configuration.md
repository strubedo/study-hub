## Factory default settings

A FortiManager straight out of the box (or after `execute reset all-settings`) looks like this:

| Item | Factory default |
|---|---|
| Management address | `port1` = **192.168.1.99/255.255.255.0** |
| GUI | `https://192.168.1.99` |
| Administrator | `admin`, **blank password**; you are forced to set a password at the first GUI or CLI login (hardware and VM) |
| ADOMs | **Disabled** (`adom-status disable`); only the root ADOM exists |
| ADOM device mode | Normal (`adom-mode normal`) |
| Workspace | **Disabled** (`workspace-mode disabled`): concurrent ADOM access is allowed |
| HA | Standalone (`config system ha` → `mode standalone`) |
| FortiAnalyzer features | Disabled (`faz-status disable`) |
| Offline mode | Disabled (`offline_mode disable`) |
| FortiGuard Service Access | Not enabled on any interface |
| Auto-update of FortiGate changes | Enabled (`config system admin setting` → `auto-update enable`) |
| Registration of new VM devices | Disabled (`config system global` → `fgfm-allow-vm disable`, since 7.6.3): new FortiGate-VMs and FortiAnalyzer-VMs are refused until you enable it |

To connect for the first time, give your laptop an address in 192.168.1.0/24, browse to `https://192.168.1.99`, log in as `admin` with no password and set the new password. A FortiManager-VM first asks you to **activate a licence** (Free Trial, Activate License with a registration code, or Upload License); the VM restarts to apply it.

## The FortiManager Setup wizard

After login, the Setup wizard walks through:

1. **Register with FortiCare** and enable FortiCare single sign-on. This step **cannot be skipped**; you must complete it before you can use the appliance or VM. In an air-gapped network you import an entitlement file instead.
2. **Hostname.**
3. **Change your password.** The default password policy wants at least 8 characters with upper case, lower case, a number and a special character.
4. **Upgrade firmware**, if FortiGuard reports a newer version (you can choose Later).
5. **Backup strategy** (optional): Automatic System Backup is enabled by default in the wizard; you choose the destination, frequency and an encryption password, and can enable ADOM revision auto-deletion (By Days default 90, By Revisions default 120).

Steps you complete get a green check mark; once all are done the wizard stops appearing. **Later** is available for some steps, not for FortiCare registration.

> **Exam tip:** "The administrator clicks Later on every step but still cannot reach Device Manager." The reason is FortiCare registration, the one mandatory step.

## Initial configuration from the CLI

The same basics can be done at the console. FortiManager CLI uses the familiar `config / edit / set / next / end` structure:

```text
FMG-HQ # config system global
FMG-HQ (global) # set hostname "FMG-HQ"
FMG-HQ (global) # set timezone 12
FMG-HQ (global) # end

FMG-HQ # config system interface
FMG-HQ (interface) # edit "port1"
FMG-HQ (port1) # set ip 10.0.1.50 255.255.255.0
FMG-HQ (port1) # set allowaccess https ssh ping
FMG-HQ (port1) # next
FMG-HQ (interface) # end

FMG-HQ # config system route
FMG-HQ (route) # edit 1
FMG-HQ (1) # set device "port1"
FMG-HQ (1) # set dst 0.0.0.0 0.0.0.0
FMG-HQ (1) # set gateway 10.0.1.1
FMG-HQ (1) # next
FMG-HQ (route) # end

FMG-HQ # config system dns
FMG-HQ (dns) # set primary 10.0.1.53
FMG-HQ (dns) # set secondary 10.0.2.53
FMG-HQ (dns) # end

FMG-HQ # config system ntp
FMG-HQ (ntp) # set status enable
FMG-HQ (ntp) # config ntpserver
FMG-HQ (ntpserver) # edit 1
FMG-HQ (1) # set server "pool.ntp.org"
FMG-HQ (1) # next
FMG-HQ (ntpserver) # end
FMG-HQ (ntp) # end
```

Checks afterwards: `get system status` (version, serial, hostname, HA mode, ADOM status, disk usage), `get system interface port1`, `execute ping <ip>`.

The admin guide's minimal setup order is: connect to the GUI, configure **RAID** if the hardware supports it, configure **network** settings, optionally configure **ADOMs**, then create **administrator accounts**. Fortinet recommends creating your own Super_User account and logging in with it rather than working as `admin`.

> **Watch out:** After you change the port1 address you lose the session. Reconnect to the new address. If the GUI does not answer, check `allowaccess` on the interface and the static route before suspecting anything else.

### Reset options

| Command | Result |
|---|---|
| `execute reset all-settings` | Factory defaults, including the IP address. |
| `execute reset all-except-ip` | Factory defaults but keeps the current IP address and route. |
| `execute reset all-shutdown` | Factory defaults, then shut down. |

## Organization requirements: decisions to make before adding devices

Initial configuration is also about *planning*. Several choices are hard to change later.

| Decision | Why it matters early |
|---|---|
| **ADOMs on or off** | Turning ADOMs off later requires moving every device back to root and deleting all other ADOMs. Turning them on logs you out of the GUI. |
| **ADOM layout** | By customer (MSSP), by region or business unit (enterprise/retail), by firmware version. Devices can belong to only one ADOM. |
| **ADOM device mode** | Normal (whole device in one ADOM) or Advanced (VDOMs of one FortiGate in different ADOMs). Advanced adds complexity and blocks some features, such as adding a FortiAnalyzer. |
| **Workspace / workflow** | Whether several admins may edit the same ADOM concurrently (default) or must lock it; whether changes need approval (workflow). |
| **Administrator model** | Local vs RADIUS/LDAP/TACACS+/SAML, admin profiles, which ADOMs and policy packages each admin can reach, trusted hosts. |
| **HA** | Plan peers, serial numbers, cluster ID and whether you want manual or VRRP failover; FortiAnalyzer features must stay off. |
| **FortiGuard** | Will FortiManager be the local FDS? Then plan the FortiCare contract, Service Access interface, firewall rules for 8890/443 and 53/8888. |
| **Backups** | Schedule `config system backup all-settings` to SCP/SFTP/FTP with an encryption password from day one. |
| **Licensing** | Device/VDOM count, ADOM count (model dependent; add-on ADOM licences on VMs). |

## Use case 1: a new FortiManager for a retail chain

A retailer has 300 stores, each with a FortiGate, plus two data centres. Initial build:

1. Wizard: register, hostname `FMG-HQ`, strong password, backup schedule to SFTP.
2. `port1` on the management VLAN, static route, DNS, NTP.
3. Enable ADOMs; create ADOM `Retail` (FortiGate type, version 7.6, Normal mode) for stores and `DataCentre` for the core.
4. Enable workspace mode so that the store team and the DC team cannot overwrite each other.
5. Create RADIUS-backed admin accounts restricted to their ADOM.
6. Enable **FortiGate Updates** and **Web Filtering** Service Access on the interface the stores reach, if FortiManager will serve FortiGuard.

## Use case 2: FortiAnalyzer integration with FortiManager

The retailer also owns a FortiAnalyzer `FAZ-HQ` and wants a single pane of glass.

1. Confirm both units run the **same version** and that FortiAnalyzer features are **disabled** on FortiManager (otherwise Add FortiAnalyzer is hidden).
2. Confirm ADOMs are **not** in Advanced device mode.
3. In ADOM `Retail`, go to **Device Manager > Add Device > Add FortiAnalyzer**. Enter the FortiAnalyzer address and credentials (legacy device login) or use the Fabric connection method.
4. The wizard checks that the same ADOM and the same logging devices exist on the FortiAnalyzer and synchronizes them if needed. If the FortiAnalyzer is receiving logs from devices that FortiManager does not manage, the wizard asks you to add those devices too.
5. Push log settings to the FortiGates with a system template (`log fortianalyzer setting` → the FortiAnalyzer IP).
6. FortiView, Log View, Incidents & Events and Reports appear in FortiManager. Data and reports live on FortiAnalyzer; log storage policy is configured on FortiAnalyzer, not FortiManager.

> **Real world:** If the FortiAnalyzer is a VM, enable management of VM devices on FortiManager first (`set fgfm-allow-vm enable` under `config system global`) or the wizard will not recognise it.

## Lab it yourself

On the FortiManager-VM trial:

1. Deploy the VM, log in at the console as `admin` (blank password) and set a password.
2. Configure `port1`, the default route and DNS from the CLI as above, then browse to the new address. Run `set fgfm-allow-vm enable` under `config system global` now, because your FortiGates are VMs too.
3. Activate the free trial with your FortiCloud account; the VM restarts.
4. Walk through the Setup wizard; try to skip the FortiCare step and note that you cannot.
5. Run `get system status` and `get system global` and match the values against the factory-default table.
6. FortiAnalyzer integration needs a licensed FortiManager and FortiAnalyzer; on the trial, read through the Add FortiAnalyzer wizard screens only.

## Key takeaways

* Factory default: `port1` 192.168.1.99/24, user `admin` with a blank password that must be changed at first login.
* ADOMs, workspace, HA, FortiAnalyzer features and offline mode are all off by default.
* The Setup wizard's **FortiCare registration** step is mandatory; hostname, password, firmware and backup steps follow.
* Minimal CLI: `config system interface`, `config system route`, `config system dns`, `config system global` (hostname, time zone).
* Decide ADOM layout, device mode, workspace mode, admin model, HA and FortiGuard role before adding devices.
* FortiAnalyzer integration needs matching versions, FortiAnalyzer features off on FortiManager and ADOMs not in Advanced mode.
