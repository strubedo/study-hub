## Web filter and email filter through FortiManager

Web filtering and anti-spam are **query** services: for each URL (or sender IP, or message hash) the FortiGate asks a FortiGuard server for a rating. With FortiManager as the local FortiGuard server, the FortiGate asks FortiManager instead of the public FDN.

Enable on FortiManager:

```text
FMG-HQ # config fmupdate service
FMG-HQ (service) # set query-webfilter enable
FMG-HQ (service) # set query-antispam enable
FMG-HQ (service) # end
```

and **Web Filtering** service access (`webfilter-antispam`) on the interface. When the web filter and email filter databases have been downloaded (or uploaded), their versions appear on FortiGuard > Settings next to the toggles.

### Ports

| Direction | Port |
|---|---|
| FortiGate → FortiManager, rating queries | UDP **53** or UDP **8888** (Fortinet's ports list groups UDP 53/8888 with TCP 80, 443 and 8888 for web filter queries and AV/IPS updates from FortiGates) |
| FortiGate → FortiManager, AV/IPS updates and licence validation | TCP **8890** (default) or TCP **443** (needs a Bind to IP Address, next lesson) |
| Downstream FortiManager → upstream FortiManager (cascade) | 8890 (FortiGate AV/IPS), 8891 (FortiClient AV/IPS), 8900 (FortiGate web/email filter), 8901 (FortiClient web/email filter) |
| FDN → FortiManager push | UDP 9443 |

### Tuning the query server

`config fmupdate fgd-setting` controls the FortiGuard query daemon:

| Attribute | Purpose | Default |
|---|---|---|
| `wf-cache` | Web filter service memory, MB (0 = no limit) | 600 |
| `wf-dn-cache-expire-time` | Domain-name cache entry lifetime, minutes | 30 |
| `wf-dn-cache-max-number` | Domain-name cache entries (0 = disable) | 10000 |
| `wf-preload` | Preload the web filter database into memory | disable |
| `wf-log` | `all`, `disable`, `nourl` | `nourl` |
| `as-cache`, `av-cache`, `fq-cache` | Memory (MB) for anti-spam, AV query and file query | 300 each |
| `as-log`, `av-log` | Anti-spam / AV query logging | `nospam`, `novirus` |

Logging of lookups is chosen in the GUI under FortiGuard Web Filter and Email Filter Settings > Log Settings: *Log URL disabled / Log non-URL events / Log all URL lookups*, and the equivalents for anti-spam and AV queries.

### Query server management

**FortiGuard > Query Services** shows what FortiManager is doing as a rating server:

* **Receive Status**: received rating databases, latest version, size, update history; export and import for air-gapped units. An export can include **delta data** (Download Delta Data), so an upstream FortiManager in cascade mode can give downstream FortiManagers delta updates instead of the full merged database.
* **Query Status**: graphs of **number of queries** over time, **Top 10 Unrated Sites**, **Top 10 Devices**.

CLI helpers: `diagnose fmupdate test fgd-url-rating ...` tests a URL rating against the local server; `diagnose fmupdate fgd-dbver` shows the local database versions; `diagnose fmupdate fgd-wfserver-stat {top10sites | top10devices} [<period>]` and `diagnose fmupdate fgd-wfdevice-stat <period> {all | <serial>}` give statistics.

> **Real world:** A FortiManager web filter database is a downloaded copy, so rating changes published by FortiGuard reach your FortiGates only after FortiManager's next database update. Expect a short delay compared with querying FortiGuard directly.

## Override servers on FortiManager itself

FortiManager normally connects to the default FDN servers. An **override server address** tells FortiManager to fetch from a different server or port instead, for example an upstream FortiManager.

GUI: FortiGuard > Settings, under *FortiGuard Antivirus and IPS Settings* or *FortiGuard Web Filter and Email Filter Settings*:

* **Use Override Server Address for FortiGate/FortiMail** (both sections)
* **Use Override Server Address for FortiClient** (both sections)
* **Use Override Server Address for FortiNDR** (AV/IPS section)

Each list holds up to ten override servers (IP and port).

### Server Override Mode: loose vs strict

What FortiManager does when the override server cannot be reached:

```text
FMG-HQ # config fmupdate server-override-status
FMG-HQ (server-override-status) # set mode strict
FMG-HQ (server-override-status) # end
```

| Mode | Behaviour |
|---|---|
| **Loose** (default): *Allow Access Other Servers* | Try the override server; if unreachable, **fall back to the default FortiGuard servers**. |
| **Strict**: *Access Override Server Only* | Use only the override server; if it is unreachable, **no update is retrieved**. You must configure override servers, otherwise the server list is empty. |

> **Exam tip:** Strict is what you want in a closed or tightly controlled network where FortiManager must never reach the Internet FDN. Loose is the resilient default.

### Cascade: a FortiManager as FDS for another FortiManager

An offline (downstream) FortiManager can use an Internet-facing (upstream) FortiManager as its FDS:

1. Upstream: enable `serviceaccess fgtupdates fclupdates webfilter-antispam` on the interface the downstream unit reaches.
2. Downstream: FortiGuard > Settings, keep Communication with FortiGuard Server on **Global Servers**, then enable the override server addresses: upstream IP with port **8890** (FortiGate/FortiMail AV/IPS), **8891** (FortiClient AV/IPS), **8900** (FortiGate/FortiMail web/email filter), **8901** (FortiClient web/email filter).

### Override FortiGuard Server (Local FortiManager): private servers

A separate section lets you list **other** FortiManagers or private FDS servers that **managed FortiGates** should use, with an option to fall back to the public FDN. CLI:

```text
FMG-HQ # config fmupdate server-access-priorities
FMG-HQ (server-access-priorities) # set access-public enable
FMG-HQ (server-access-priorities) # set av-ips enable
FMG-HQ (server-access-priorities) # set web-spam enable
FMG-HQ (server-access-priorities) # config private-server
FMG-HQ (private-server) # edit 1
FMG-HQ (1) # set ip 10.20.0.50
FMG-HQ (1) # next
FMG-HQ (private-server) # end
FMG-HQ (server-access-priorities) # end
```

| Attribute | Meaning | Default |
|---|---|---|
| `private-server` | Up to 10 private servers (IP or IPv6 and time zone) | |
| `av-ips` | Use the private servers for AV/IPS updates | disable |
| `web-spam` | Use the private servers for web filter and email filter | enable |
| `access-public` | *Allow FortiGates to Access Public FortiGuard Servers when Private Servers are Unavailable* | disable |

## FortiGate/FortiMail server override: AV and IPS

The blueprint line "FortiGate/FortiMail server override" refers to the override list FortiManager uses when it fetches AV/IPS for FortiGate and FortiMail devices (above), and, from the device side, the FortiGate's own override list pointing at FortiManager (next lesson). Keep the direction straight:

| Where configured | Points | Used for |
|---|---|---|
| FortiManager: *Use Override Server Address for FortiGate/FortiMail* | FortiManager → another server | Where FortiManager gets FortiGate/FortiMail AV/IPS packages |
| FortiGate: `config system central-management` → `config server-list` | FortiGate → FortiManager | Where the FortiGate gets updates and ratings |

## Closed networks

To run FortiManager as an FDS with no Internet:

1. FortiGuard > Settings: turn **off** *Enable Communication with FortiGuard Server* (`config fmupdate publicnetwork` → `set status disable`).
2. Enable the services you need (AV/IPS, web filter, email filter).
3. Download packages from the Fortinet Support portal, or export them from an online FortiManager (metadata packages such as *Signature Meta Data (IPS Slim)* can only come from an online FortiManager).
4. Upload them (GUI upload, or CLI for large databases: `execute fmupdate {ftp | scp | tftp} import <type> <remote_file> ...`).
5. Upload the **service licences** (account entitlement files) so FortiManager knows what each device is entitled to.

A FortiGate downloads from FortiManager only the services it has enabled.

## Proxy and anycast

* FortiManager can reach the FDN through a web proxy: `config system web-proxy` (`status` default disable; `mode tunnel` default, which uses TCP 443, or `proxy`, which uses TCP 80; proxy `port` default 1080).
* `config fmupdate fds-setting` → `set fortiguard-anycast enable` makes FortiManager use FortiGuard's anycast addresses with OCSP-stapled certificate validation; `fortiguard-anycast-source {fortinet | aws}`.

## Lab it yourself

Needs a licensed FortiManager with FortiCare Premium/Elite. On the trial you can still read the defaults:

1. `get fmupdate server-access-priorities` (expect `access-public : disable`, `av-ips : disable`, `web-spam : enable`).
2. Look at FortiGuard > Settings and find Server Override Mode and the override lists.
3. With a licensed unit and a FortiGate pointed at it: run `diagnose fmupdate fgd-wfserver-stat top10devices` after browsing from behind the FortiGate.

## Key takeaways

* Web and email filtering are **query services**; enable `query-webfilter`/`query-antispam` and Web Filtering service access.
* Rating queries arrive on UDP 53/8888; AV/IPS downloads on TCP 8890 or 443.
* Query Services shows rating databases, query counts, top unrated sites and top devices.
* **Loose** override mode (default) falls back to public FDS; **strict** never does.
* Downstream FortiManager → upstream FortiManager uses ports 8890, 8891, 8900, 8901.
* `server-access-priorities` lists private servers for managed FortiGates; `access-public` (default disable) allows public fallback.
* Closed network: disable public network, import packages, databases and licences.
