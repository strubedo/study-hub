## FortiGuard terminology

| Term | Meaning |
|---|---|
| **FortiGuard** | Fortinet's threat-intelligence services: AV and IPS signatures and engines, application control, web filtering, email (anti-spam) filtering, IoT, outbreak prevention and more. |
| **FDN** (FortiGuard Distribution Network) | The worldwide network of Fortinet servers that publishes those updates and answers rating queries. |
| **FDS** (FortiGuard Distribution Server) | One server in the FDN. FortiManager has a **built-in FDS**. |
| **Local FDS** | FortiManager acting as a FortiGuard server for devices on your network. |
| **Update service** (AV/IPS) | Packages (signatures, engines) downloaded and installed on the device. |
| **Query / rating service** | Real-time lookups (web filter category, anti-spam, file query); the device asks per URL/IP/hash. |
| **Override server** | An address a device (or a FortiManager) is told to use instead of the public FDN. |
| **Push update** | The FDN notifies FortiManager that an urgent AV/IPS update exists so it downloads at once instead of waiting for the next poll. |
| **Package management** | FortiManager's view of which AV/IPS packages it has received and which version it will hand out. |
| **Query server management** | FortiManager's view of rating queries it has answered (Query Services). |

## Why use FortiManager as a local FortiGuard server

Instead of 300 store FortiGates each downloading the same AV package over their Internet links, FortiManager downloads it **once** and redistributes it; it also answers web-filter rating queries locally. Benefits: less Internet load, faster updates, and FortiGuard for FortiGates that are not allowed Internet access at all, including fully **closed (air-gapped) networks**.

The blueprint lists two roles, *local FortiGuard server* and *local FortiGuard cache*. Fortinet's 7.6 Administration Guide does not define them as two modes (it talks about the **built-in FDS** acting as a **local FDS**), so treat them as two ways of describing what that one built-in FDS does:

* **Local FortiGuard server.** FortiManager holds FortiGuard content itself and serves it: AV/IPS packages it has downloaded from the FDN (or that you imported), and web filter and email filter databases it answers rating queries from. In a closed network this is the only option, with packages, databases and licences uploaded by hand.
* **Local FortiGuard cache.** What FortiManager has downloaded is kept and reused, so 300 FortiGates cause one download, not 300. The documented knobs are the query daemon's memory and domain-name cache (`config fmupdate fgd-setting` → `wf-cache`, `wf-dn-cache-expire-time`, `wf-dn-cache-max-number`) and the **firmware cache**: images stored on FortiManager are reused for every device of that model, and `config fmupdate fwm-setting` → `fds-failover-fmg` (default enable) uses the local image if the FortiGuard download fails (see the lesson after next).

> **Watch out:** There is no separate "cache mode" setting to look for in the 7.6 CLI reference. You enable the services you want (`config fmupdate service`), and FortiManager stores and redistributes what it downloads. If a question contrasts server and cache, the server side is about holding and answering from full content (including closed networks); the cache side is about reuse of what was already fetched.

## Prerequisites (and the licence trap)

* **FortiManager must have a valid FortiCare Elite or FortiCare Premium support contract** to act as a local FDS. Starting in 7.2.12, 7.4.9 and 7.6.5, Fortinet enforces this: FortiManager needs that contract, registered in FortiCloud, to get **object updates** from FortiGuard. The contract must be on the **FortiManager itself**; the managed FortiGates' own contracts do not satisfy it.
* **A FortiManager-VM trial licence cannot act as a local FDS** and has no FortiGuard subscriptions. Everything in this lesson needs a full licence.
* The devices must be registered with Fortinet Customer Service & Support with their FortiGuard service licences enabled; FortiManager only distributes what each device is entitled to.
* **Service Access** must be enabled on the FortiManager interface the devices use: **FortiGate Updates** (`fgtupdates`) for AV/IPS, **Web Filtering** (`webfilter-antispam`) for rating queries, `fclupdates` for FortiClient. It is not enabled on any port by default.

```text
FMG-HQ # config system interface
FMG-HQ (interface) # edit "port1"
FMG-HQ (port1) # set serviceaccess fgtupdates fclupdates webfilter-antispam
FMG-HQ (port1) # next
FMG-HQ (interface) # end
```

* FortiManager must reach the FDN (DNS, routing, firewall) or, in a closed network, have packages imported.

## Enabling the services

GUI: **FortiGuard > Settings**. CLI: `config fmupdate service`.

Example output after the web filter and email filter query services have been enabled (the defaults are in the table below):

```text
FMG-HQ # get fmupdate service
avips               : enable
query-antispam      : enable
query-antivirus     : disable
query-filequery     : disable
query-ioc           : disable
query-iot           : disable
query-outbreak-prevention: disable
query-webfilter     : enable
webfilter-https-traversal: disable
```

| Attribute | Service | Default |
|---|---|---|
| `avips` | Provide AV and IPS updates from the built-in FDS | enable |
| `query-webfilter` | Answer web filter rating queries | disable |
| `query-antispam` | Answer email filter (anti-spam) queries | disable |
| `query-antivirus`, `query-filequery`, `query-outbreak-prevention`, `query-iot` (plus `query-iot-collection`, `query-iot-vulnerability`), `query-ioc` | Other query services | disable |
| `webfilter-https-traversal` | Web filter HTTPS traversal | disable |

Other settings on the same GUI page:

| GUI setting | CLI |
|---|---|
| Enable Communication with FortiGuard Server | `config fmupdate publicnetwork` → `set status {enable | disable}` (default enable). Off = closed network, manual uploads. |
| Communication with FortiGuard Server: Global Servers / Servers Located in the US Only | `config fmupdate publicnetwork` → `set update-server-location {global | usa | eu}` (default global) |
| Enable Antivirus and IPS Service (choose platforms and versions) | Pre-downloads AV/IPS packages for FortiGate, FortiMail, FortiClient, FortiSandbox and others |
| Server Override Mode | `config fmupdate server-override-status` → `set mode {loose | strict}` (next lesson) |
| Anycast | `config fmupdate fds-setting` → `set fortiguard-anycast {enable | disable}` (default disable) |

## Antivirus and IPS: package management

**FortiGuard > Packages > Receive Status** lists every package FortiManager has received, grouped by platform: package name, product, version, service entitlement, size, **To Be Deployed Version** and Update History.

* **To Be Deployed Version** defaults to the latest. Click **Change** to pin an older version, for example to hold back a signature package that caused false positives. Exports also use this version. From 7.6.2 the selection is synchronized to HA secondaries.
* **Export / Import** let you move packages from an Internet-facing FortiManager to an air-gapped one. An export contains only the version shown in To Be Deployed Version.

**FortiGuard > Packages > Service Status** shows each managed device's state:

| Status | Meaning |
|---|---|
| **Up to Date** | The device has the latest package. |
| **Never Updated** | The device has never requested or received the package. |
| **Pending** | The device has an older version for an acceptable reason (such as its scheduled update time not having come yet). |
| **Problem** | The device missed its scheduled query or did not receive the latest package correctly. |
| **Unknown** | Status not known. |

**Push Pending** (selected devices) and **Push All Pending** send pending updates immediately. View By Device or By Package.

## Push updates

Two different "pushes" appear in FortiManager:

1. **FDN → FortiManager.** When an urgent AV/IPS update is published, the FDN sends a push notification to FortiManager, which downloads immediately. Enable it under FortiGuard Antivirus and IPS Settings > **Allow Push Update**. The notification arrives on **UDP 9443**. Behind NAT, give the NAT device's external IP/port as the push override so the FDN sends to an address it can reach, and port-forward that to FortiManager UDP 9443. A dynamic (DHCP/PPPoE) public IP can break push.
2. **FortiManager → FortiGates.** FortiManager announces new packages to managed devices, which then download from it. When the FortiGates reach FortiManager through NAT, set the address they should use to download (an optional `port` can be set per entry as well):

```text
FMG-HQ # config fmupdate fds-setting
FMG-HQ (fds-setting) # config push-override-to-client
FMG-HQ (push-override-to-client) # set status enable
FMG-HQ (push-override-to-client) # config announce-ip
FMG-HQ (announce-ip) # edit 1
FMG-HQ (1) # set ip 203.0.113.20
FMG-HQ (1) # next
FMG-HQ (announce-ip) # end
FMG-HQ (push-override-to-client) # end
FMG-HQ (fds-setting) # end
```

Without push, FortiManager polls on **Scheduled Regular Updates** (Polling Frequency; CLI `config fmupdate fds-setting` → `config update-schedule`), or when you trigger an update manually. If the network is interrupted during a large download, FortiManager downloads all the files again when the network resumes.

`config fmupdate fds-setting` → `config push-override` holds the FDN-to-FortiManager push override (`status` default disable, `ip`, `port` default 9443). By default FortiManager announces all its interfaces to devices on port 8890; `push-override-to-client` changes that.

## Unregistered devices

Devices do **not** have to be authorized in Device Manager to use the built-in FDS. A FortiGate managed locally that only wants AV/IPS from FortiManager is *unregistered* from FortiManager's point of view. How it is handled:

```text
FMG-HQ # config system admin setting
FMG-HQ (setting) # set unreg_dev_opt add_allow_service
FMG-HQ (setting) # end
```

| `unreg_dev_opt` | Behaviour |
|---|---|
| `add_allow_service` (default) | Add the device as unregistered and serve it. |
| `add_no_service` | Add the device but refuse service. |

The FDS daemon has a matching option, `config fmupdate fds-setting` → `set unreg-dev-option {add-service | ignore | svc-only}` (default `add-service`; `svc-only` serves without adding the device).

## Logging FortiGuard activity

FortiGuard Antivirus and IPS Settings > **Advanced**: *Log Update Entries from FortiGuard Distribution Server* and *Log Update Histories for Each FortiGate*. Without these you cannot see the entries in the FDS download history. Local event logging must also be enabled.

## Lab it yourself

All of this needs a licensed FortiManager with a FortiCare Premium/Elite contract; the trial cannot be a local FDS. With the trial you can still:

1. Run `get fmupdate service` and `get fmupdate publicnetwork` and identify the defaults.
2. Open **FortiGuard > Settings** and **Packages** to learn the layout.
3. Check `get system interface port1` for `serviceaccess`; note it is empty by default.

## Key takeaways

* FDN is Fortinet's network; FortiManager's built-in FDS makes it a **local FDS** that distributes AV/IPS and answers rating queries.
* Needs a FortiCare Elite/Premium contract on FortiManager itself (enforced for object updates from 7.6.5) and is unavailable on the VM trial.
* Enable **Service Access** (`fgtupdates`, `webfilter-antispam`) on the interface FortiGates use; none is enabled by default.
* `config fmupdate service`: `avips` (default enable), `query-webfilter`/`query-antispam` (default disable).
* Receive Status shows packages and the **To Be Deployed Version**; Service Status shows Up to Date, Never Updated, Pending, Problem, Unknown.
* Push from FDN uses **UDP 9443**; behind NAT configure a push override address.
* `unreg_dev_opt` decides whether unregistered devices get service.
