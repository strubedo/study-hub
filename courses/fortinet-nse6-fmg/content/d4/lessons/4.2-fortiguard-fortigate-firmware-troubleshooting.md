## Pointing FortiGates at FortiManager

### Managed FortiGate

A FortiGate managed by FortiManager uses `config system central-management` for both management and FortiGuard. The `type` and `fmg` lines are written when the device is registered; the FortiGuard part is an override **server list** that you add (on the FortiGate, or from FortiManager through the device database or a CLI template):

```text
FGT-Branch1 # show system central-management
config system central-management
    set type fortimanager
    set fmg "10.0.1.50"
    config server-list
        edit 1
            set server-type update
            set server-address 10.0.1.50
        next
        edit 2
            set server-type rating
            set server-address 10.0.1.50
        next
    end
    set include-default-servers disable
end
```

| Attribute | Meaning | Default |
|---|---|---|
| `type` | `fortimanager`, `fortiguard` (FortiGate Cloud) or none | |
| `fmg` | FortiManager IP(s)/FQDN(s) for FGFM | |
| `server-list` → `server-type` | `update` (AV/IPS and other packages), `rating` (web filter/anti-spam queries), or both | |
| `server-list` → `server-address` | The FortiManager address that provides that service | |
| `include-default-servers` | Also use the public FortiGuard servers | **enable** |
| `fmg-update-port` | `8890` or `443` for updates from FortiManager | **8890** |
| `mode` | `normal` or `backup` (matches a backup-mode ADOM) | normal |
| `allow-push-configuration`, `allow-push-firmware`, `allow-remote-firmware-upgrade` | Whether FortiManager may push config/firmware | |

Fortinet's guidance for a **managed** FortiGate is `include-default-servers disable` and `server-address` = FortiManager. If default servers stay included, the FortiGate may update straight from the public FDS; FortiManager then never sees the update and its **Service Status** for that device is wrong.

With `fmg-update-port 443`, the FortiGate connects to the override update server on TCP 443. FortiManager can provide update and rating service on 443 only through a **Bind to IP Address**: a unique address in the same subnet as the interface, configured with Service Access, and only one interface can do this. If `fmg-update-port` is left at 8890, the server address must be the FortiManager's access IP.

FortiOS 7.x enables **FortiGuard anycast** by default (`config system fortiguard` → `fortiguard-anycast enable`, which uses HTTPS on TCP 443 to Fortinet's anycast servers). Fortinet's FortiManager-as-rating-server examples disable it on the FortiGate so that rating queries go to the FortiManager override server:

```text
FGT-Branch1 # config system fortiguard
FGT-Branch1 (fortiguard) # set fortiguard-anycast disable
FGT-Branch1 (fortiguard) # end
```

In the FortiGate GUI the same is **System > FortiGuard > Override FortiGuard Servers**: Create New, address, type *AntiVirus & IPS Updates*, *Filtering*, or *Both*.

### Unmanaged FortiGate

A FortiGate **does not have to be authorized in Device Manager** to use FortiManager's built-in FDS. Configure the same override servers on the FortiGate (GUI override list or `central-management` server list) pointing at FortiManager. On FortiManager, the unregistered-device option decides whether it is served:

* `config system admin setting` → `set unreg_dev_opt add_allow_service` (serve it) or `add_no_service` (refuse).

### FortiManager and FortiGate both in HA

When FortiManager is an HA cluster and FortiGates use it for ratings, give each FortiManager a **secondary IP for the rating service** (`set rating-service-ip` on its interface), list both units' update and rating addresses in the FortiGate's server list, disable `include-default-servers` and anycast. Remember the FortiGuard databases themselves are **not** synchronized by FortiManager HA; each unit downloads its own.

## Licence status and contract verification

**FortiGuard > Device Licenses** shows every managed device's support contract and FortiGuard subscription:

| Colour | Meaning |
|---|---|
| Green | Licence OK |
| Orange | Expires within 30 days (warning) |
| Red | Expired |

Columns include Support Contract (N/A, 24/7, 8/5), FortiGuard Subscription (worst status of IPS & Application Control, Antivirus, Web Filtering, Email Filtering), **Service Status** (Update Available, Up to Date, Expired, Unknown, calculated from the FortiGate's last update request), and VDOM count. **Check License** chooses which licence types FortiManager watches for expiry; **Push Update** pushes a licence update to the device.

From the CLI:

```text
FMG-HQ # diagnose fmupdate dbcontract FGVM02TM26001001
FMG-HQ # diagnose fmupdate fds-dump subs
```

`dbcontract` dumps the subscriber contract FortiManager holds for that serial; `fds-dump subs` dumps the contract file. If a device's contracts are missing in a closed network, request and upload its **account entitlement file**.

On the FortiGate:

```text
FGT-Branch1 # diagnose test update info
FGT-Branch1 # get system fortiguard-service status
FGT-Branch1 # diagnose autoupdate versions
FGT-Branch1 # diagnose fdsm contract-controller-update
```

`diagnose test update info` shows the FortiGate's update status and contract details; `diagnose autoupdate versions` lists installed engine and signature versions; `diagnose fdsm contract-controller-update` asks the FortiGate to refresh its contract information.

## Firmware: firmware cache and upgrades from FortiManager

**FortiGuard > Firmware Images** manages the images FortiManager stores for FortiGate, FortiAnalyzer, FortiManager, FortiAP, FortiExtender, FortiSwitch and FortiProxy.

* **Models: All / Managed** filters to the models you manage. Choose a **Preferred Version** per model.
* **Download** pulls an image from FortiGuard into FortiManager's local store; **Import Images** uploads one you downloaded from the support portal (the only way in a closed network).
* Once on FortiManager, an image is reused for every device of that model: that is the **firmware cache**. `config fmupdate fwm-setting` → `fds-failover-fmg enable` (default) uses the local image if the FortiGuard download fails.

Upgrading FortiGates from FortiManager:

* Device Manager: select devices > **Firmware Upgrade**, or create **firmware templates** that assign a target version and schedule to device groups.
* FortiGates need a valid **FortiCare Firmware & General Updates (FMWR)** contract, both for FortiGuard images and uploaded ones. A newly added FortiGate has a **24-hour grace period** while its contract information synchronizes. FortiManager expects the device to be on the same FortiCloud account, or its serial to be in FortiGuard's authorization list.
* The FortiGate's `central-management` must not block it (`allow-push-firmware`, `allow-remote-firmware-upgrade`).
* 7.6.5 release notes: when FortiManager upgrades FortiGates running FortiOS 7.6.1 or 7.6.2, the FortiGate pulls the image from FortiManager acting as a **local FDS**, a workaround that matters in air-gapped or restricted networks.
* `diagnose fwmanager image-download <platform> <version>` downloads an official image from the CLI.

## FortiGuard troubleshooting

### Is FortiManager talking to FortiGuard?

* FortiGuard > Settings / the License Information widget: connection to FortiGuard, server location, AV/IPS update server.
* `diagnose fmupdate view-serverlist fds` and `diagnose fmupdate view-serverlist fgd`: the FortiGuard servers FortiManager knows for updates and for queries.
* `diagnose fmupdate update-status fds` (or `fgd`): last update results.
* `diagnose fmupdate fgd-dbver`: local web filter / anti-spam / AV query database versions.
* `diagnose fmupdate updatenow fds ...`: force an update.
* `diagnose fmupdate service-restart {fds | fgd | fmtr | fwm}`: restart the update (`fds`), query (`fgd`) or firmware-manager daemon.
* `diagnose debug application fgdsvr 255` with `diagnose debug enable`: watch incoming rating queries.
* If the status stays **Disconnected**: check DNS, routes, upstream firewall/NAT, the web proxy (`config system web-proxy`), override addresses and strict mode.

### Is the FortiGate using FortiManager?

* `diagnose debug rating` on the FortiGate: the rating servers in use and their state; FortiManager's IP should be listed.
* `diagnose debug application update -1` with `diagnose debug enable`, then `execute update-now`: watch the update attempt and which server it reaches.
* `diagnose debug application urlfilter -1`: rating query responses.
* `get system fortiguard-service status`: per-service status.
* FortiManager Service Status shows **Problem** or **Never Updated**: check FortiGate `server-list`, `include-default-servers`, `fmg-update-port`, anycast and the FortiManager interface `serviceaccess`.

### Typical faults

| Symptom | Likely cause |
|---|---|
| FortiGates time out on rating queries to FortiManager | Web Filtering service access not enabled on that interface, or `query-webfilter disable`. |
| FortiGate updates fine but FortiManager shows the device as Never Updated | `include-default-servers enable` on the FortiGate: it updated from the public FDS. |
| FortiManager stops getting FortiGuard object updates after upgrading to 7.6.5 (or 7.4.9 / 7.2.12) | FortiManager lacks its own FortiCare Elite/Premium contract registered in FortiCloud. |
| FortiManager in a closed network cannot update | Expected: strict mode or public network disabled; import packages manually. |
| Push updates never arrive behind NAT | No push override IP/port, or the NAT device does not forward UDP 9443. |

## Lab it yourself

The trial has no FortiGuard subscriptions and no FDS, and the FortiGate-VM permanent trial has no FortiGuard services. You can still:

1. On the FortiGate-VM, run `show system central-management` after FortiManager adds it, and identify `include-default-servers` and `fmg-update-port` defaults with `show full-configuration system central-management`.
2. On FortiManager, open **FortiGuard > Firmware Images** and **Device Licenses** to learn the columns.
3. Run `diagnose debug rating` on the FortiGate and read the server list.

## Key takeaways

* Managed FortiGate: `central-management` server-list with `server-type update`/`rating` → FortiManager, `include-default-servers disable`.
* `fmg-update-port` default **8890**; **443** needs a Bind to IP on FortiManager. Disable anycast when FortiManager answers ratings.
* Unmanaged FortiGates can use FortiManager as FDS; `unreg_dev_opt` controls service.
* Device Licenses: green OK, orange within 30 days, red expired; `diagnose fmupdate dbcontract <serial>`.
* Firmware images are cached on FortiManager; upgrades need the FortiGate's **FMWR** contract (24-hour grace after adding).
* Troubleshoot FortiManager with `diagnose fmupdate view-serverlist`, `update-status`, `fgd-dbver`, `fgdsvr` debug; FortiGate with `diagnose debug rating`, update debug, `diagnose test update info`.
