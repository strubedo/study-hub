## Which monitoring tool answers which question?

Azure has several tools with overlapping names. Learn the question each one answers.

| Question | Tool |
|---|---|
| How can I improve cost, security, reliability, performance, operations? | Azure Advisor |
| Is Azure itself having a problem that affects me, or is maintenance planned? | Azure Service Health |
| Is *this particular VM or database* healthy from Azure's side? | Resource Health (part of Service Health) |
| What do metrics and logs from my resources say, and who should be told? | Azure Monitor |
| How is my application behaving (requests, failures, dependencies)? | Application Insights (part of Azure Monitor) |
| I need to query and analyse log data | Log Analytics (part of Azure Monitor) |

## Azure Advisor

**Azure Advisor** is a free, personalised cloud consultant. It analyses your resource configuration and usage telemetry and gives **recommendations** with suggested actions. Recommendations fall into five categories that match the pillars of the Azure Well-Architected Framework:

1. **Reliability:** keep business-critical workloads running (for example use availability zones or backups).
2. **Security:** detect threats and vulnerabilities (many come from Microsoft Defender for Cloud).
3. **Performance:** speed up applications.
4. **Cost:** reduce spend, for example shut down or resize underused VMs, or buy reservations.
5. **Operational excellence:** process, manageability and deployment best practices (for example configure Service Health alerts).

You can filter by subscription and resource type, postpone or dismiss recommendations, and see an **Advisor score**. Advisor recommends; it does **not** change anything for you, and it does not monitor live health or fire alerts about incidents.

> **Exam tip:** "Find underused VMs I could downsize" or "get best-practice advice across cost and security" = Advisor. Advisor's categories are exactly five: reliability, security, performance, cost, operational excellence.

## Azure Service Health

**Azure Service Health** is the family of experiences that tells you about Azure's health, at three levels of detail:

| Experience | Scope | Use it to |
|---|---|---|
| **Azure status** (status page) | Global view of all services in all regions, public | See widespread outages |
| **Service Health** | Personalised to the services and regions **you** use | Get service issues, planned maintenance, health advisories, security advisories and billing updates; set alerts |
| **Resource Health** | A single resource, such as one VM | Learn whether it is Available, Unavailable, Degraded or Unknown and why (platform event or your own action) |

Service Health event types: **service issues** (problems now), **planned maintenance**, **health advisories** (such as feature deprecations), **security advisories**, and **billing updates**. You can create **Service Health alerts** (through Azure Monitor) that send email, SMS or push messages, or call webhooks and ITSM tools, so the right team hears about an incident or upcoming maintenance without watching a page.

> **Watch out:** Service Health is about the **Azure platform** (the provider side). It does not tell you that your own application has a bug or that your VM is at 95 percent CPU. That is Azure Monitor. And Resource Health is for one resource, while Service Health is for services and regions.

## Azure Monitor

**Azure Monitor** is the platform for collecting, analysing and acting on **telemetry** from Azure, on-premises and other clouds. Its pieces:

- **Metrics:** lightweight numeric time-series (CPU percentage, requests per second), collected automatically for most Azure resources, near real time, good for charts and fast alerts.
- **Logs:** richer event and diagnostic records stored in a **Log Analytics workspace** and queried with **Kusto Query Language (KQL)**. The **Activity log** records control-plane operations on your subscription (who created or deleted what).
- **Insights and visualisation:** workbooks, dashboards and curated experiences such as VM insights and Container insights.
- **Alerts** and **autoscale** to act on what is observed.

### Log Analytics

**Log Analytics** is the tool in the portal (and the workspace that backs it) for writing and running KQL queries over log data. Many sources can send logs to one workspace, so you can correlate across resources, for example "show failed sign-ins and the VMs they touched in the last hour". The workspace holds the data; the tool lets you query it.

### Azure Monitor alerts

An **alert rule** has a **scope** (what to watch), a **condition** (a metric threshold, a log query result, or an activity log event) and **actions** run through an **action group** (email, SMS, push, voice, webhook, Azure Function, Logic App, ITSM). Alerts have a severity and a state (fired, then resolved). Use alerts so people hear about problems rather than discovering them.

### Application Insights

**Application Insights** is the **application performance management (APM)** feature of Azure Monitor. It watches a live web application or service (hosted in Azure, on-premises or elsewhere) and reports request rates and response times, failure rates, exceptions, dependency calls (to databases and APIs), page views and user behaviour, **availability tests** (synthetic pings from locations around the world) and an application map. You instrument the app with an SDK or agent (OpenTelemetry-based distro), and the data is stored in a Log Analytics workspace. Use it for "why is the checkout page slow" and "alert me if the site goes down".

> **Exam tip:** Application Insights = the **application** (code-level performance, failures, user behaviour). Azure Monitor metrics = **resource-level** numbers. Log Analytics = **querying** logs. They are components of one Azure Monitor platform, not alternatives.

## Choosing correctly

| Scenario | Answer |
|---|---|
| Azure announces maintenance on your region next week; notify the on-call team | Service Health alert |
| A single VM stopped responding; was it a host failure? | Resource Health |
| Alert when VM CPU exceeds a threshold for 10 minutes | Azure Monitor metric alert |
| Find which of 50 VMs logged an error at 02:14 | Log Analytics query |
| Track failed requests and slow dependencies in a web app | Application Insights |
| Get a list of cost-saving and reliability suggestions | Advisor |
| Public page showing all Azure outages worldwide | Azure status |

## Try it in the portal

1. Open **Advisor** and look at the five categories and the score; open any recommendation to see its proposed action.
2. Open **Service Health** and read the four tabs (service issues, planned maintenance, health advisories, security advisories); then find **Resource health** on any VM's menu.
3. Open **Monitor**, view **Metrics** for a resource, and walk through creating an **alert rule** (scope, condition, action group) without saving it, or save one that emails you.
4. Open **Log Analytics workspaces**, create one in a lab resource group, and run `search *` or an `AzureActivity | take 10` query once logs flow in. Delete the workspace afterwards if you are watching cost.

## Key takeaways

- Advisor gives recommendations in five categories: reliability, security, performance, cost, operational excellence.
- Service Health covers Azure status (global), Service Health (personalised events and alerts) and Resource Health (one resource).
- Service Health is about the Azure platform; Monitor is about your own resources and workloads.
- Azure Monitor collects metrics and logs, supports alerts, autoscale and visualisation.
- Log Analytics stores logs in a workspace and queries them with KQL.
- Alert rules combine scope, condition and an action group.
- Application Insights is application performance monitoring inside Azure Monitor.
