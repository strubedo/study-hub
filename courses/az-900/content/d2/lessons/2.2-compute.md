## Compute types

Azure offers three broad compute styles, which map to how much you manage:

| Type | What it is | You manage | Example services |
|---|---|---|---|
| Virtual machines (IaaS) | Full virtual server with its own OS | OS, patches, runtime, app | Azure Virtual Machines, Virtual Machine Scale Sets |
| Containers | Lightweight packages sharing the host OS kernel; start in seconds | App and container image | Azure Container Instances, Azure Kubernetes Service (AKS), Azure Container Apps |
| Serverless functions | Event-driven code, no servers to manage, billed by execution | Only the code | Azure Functions |

- **Azure Container Instances (ACI)** runs a container without orchestration, the quickest way to run one.
- **Azure Kubernetes Service (AKS)** is a managed Kubernetes cluster for orchestrating many containers; Azure manages the control plane.
- **Azure Functions** is event-driven and scales automatically; it suits short, triggered tasks (a queue message, an HTTP call, a timer).

> **Exam tip:** Containers virtualize the operating system (many containers share one OS kernel), while VMs virtualize the hardware (each VM has its own OS). That is why containers are lighter and start faster.

## Virtual machines and their resources

A VM is IaaS: Microsoft runs the host, you run everything from the guest OS up. Creating a VM involves more than the VM itself. The pieces you need:

- **Compute**: the VM size (vCPU and memory), image and OS.
- **Storage**: at least an OS disk, usually a managed disk; optional data disks. Many sizes also have a temporary disk.
- **Networking**: a virtual network and subnet, a network interface (NIC), a private IP, optionally a public IP address and a network security group (NSG).
- **Placement**: a region, resource group, and optionally an availability zone or availability set.

Deleting a VM does not automatically delete its disks, NIC or public IP unless you chose that at creation, so orphaned resources can keep costing money.

## Availability: availability sets, zones and scale sets

| Option | What it gives you | Notes |
|---|---|---|
| Availability set | Spreads VMs across **fault domains** and **update domains** within one datacenter | Protects against hardware faults and planned maintenance; not against a datacenter outage |
| Availability zones | Spreads VMs across separate datacenters in a region | Protects against a zone or datacenter outage; not available in every region |
| Virtual Machine Scale Set | Group of load-balanced VMs that autoscale | Can spread across fault domains and zones |

- A **fault domain** is a group of hardware sharing a power source and network switch. A hardware or power failure affects one fault domain.
- An **update domain** is a group of VMs that can be restarted together during planned maintenance; only one update domain is restarted at a time. (Uniform scale sets use up to five update domains, availability sets up to 20; Flexible scale sets no longer use update domains.)
- An availability set has up to three fault domains and up to 20 update domains, set at creation and not changeable afterward. Put at least two VMs in an availability set; one VM gains nothing.
- An availability set does not protect against OS or application failures.
- **Virtual Machine Scale Sets (VMSS)** create and manage a group of identical or load-balanced VMs. The number of instances can grow and shrink automatically based on demand or a schedule (autoscale), giving high availability and scalability. Flexible orchestration scale sets can hold up to 1,000 VMs.

> **Watch out:** "Availability set" and "availability zone" are different. A set protects inside one datacenter (racks and maintenance); a zone protects across datacenters. Zones give the higher SLA when workloads are spread across them.

## Azure Virtual Desktop

**Azure Virtual Desktop (AVD)** is a desktop and app virtualization service that runs in Azure. Users connect from many device types to a Windows desktop or to individual apps. Key points:

- It supports **multi-session** Windows 10/11 (several users share one VM) as well as single-session.
- Microsoft manages the control plane (gateway, broker, web access); you manage the session host VMs, images, and user profiles.
- Typical reasons to use it: remote work, secure access to apps without data leaving Azure, bring-your-own-device, and a managed desktop for contractors.

## Application hosting options

| Option | Best for | Control vs effort |
|---|---|---|
| Virtual machines | Lift-and-shift, custom OS needs, legacy apps | Most control, most admin |
| Containers (ACI, AKS, Container Apps) | Microservices, portable packaged apps | Moderate |
| Azure App Service (web apps) | Web apps, REST APIs and mobile back ends | PaaS: Microsoft manages OS and runtime |
| Azure Functions | Event-driven snippets | Least admin, billed by execution |

**Azure App Service** is the PaaS choice for hosting web applications (.NET, Java, Node.js, Python, PHP and others). It provides built-in autoscale, deployment slots, custom domains and TLS, and you do not patch servers. If an exam scenario says "host a web app and do not manage the OS", the answer is App Service, not a VM.

## Try it in the portal

1. Create a resource group `rg-lab-compute`, then **Create > Virtual machine**. Pick a small Linux size, and in the Availability options box compare *No infrastructure redundancy required*, *Availability zone* and *Availability set*.
2. After creation, open the VM and look at the linked resource group: you should see the VM, an OS disk, a NIC, a public IP and an NSG as separate resources.
3. Search **Virtual machine scale sets** and walk through the Create wizard without deploying; note the autoscale and orchestration options.
4. Create an **App Service** (free F1 plan) and browse to its default `azurewebsites.net` URL.
5. Delete `rg-lab-compute` when done.

## Key takeaways

- VMs are IaaS, containers share the host OS and start fast, Azure Functions is event-driven serverless.
- A VM needs compute, storage (disks) and networking (VNet, NIC, optionally a public IP and NSG).
- Availability sets spread VMs over fault and update domains in one datacenter; zones spread them across datacenters.
- VM Scale Sets give autoscaling groups of load-balanced VMs.
- Azure Virtual Desktop delivers Windows desktops and apps, including multi-session Windows, from Azure.
- App Service is the PaaS choice for web apps; VMs are for lift-and-shift and full control.
- Deleting a VM may leave disks, NICs and public IPs behind.
