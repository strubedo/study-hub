## Virtual networks and subnets

An **Azure Virtual Network (VNet)** is your private, isolated network in Azure. Resources such as VMs communicate over it using private IP addresses.

- A VNet lives in one **region** and one subscription, and you give it an address space in CIDR notation (for example `10.10.0.0/16`).
- A VNet is divided into **subnets**, each with a slice of the address space (for example `10.10.1.0/24`). Subnets let you separate tiers (web, app, data) and attach different security rules.
- By default, resources in the same VNet can talk to each other, resources can reach the internet outbound, and inbound internet traffic is blocked unless you allow it.
- **Network security groups (NSGs)** filter traffic with allow/deny rules by source, destination, port and protocol; they can be associated with a subnet or a NIC.
- Azure reserves a few addresses in every subnet, so a subnet is slightly smaller than its raw address count.

## Virtual network peering

**VNet peering** connects two VNets so their resources communicate over the Microsoft backbone network using private IPs, with low latency, as if they were one network.

- **Regional peering** connects VNets in the same region; **global peering** connects VNets in different regions.
- Peering is **not transitive**: if A is peered to B and B to C, A cannot reach C unless you also peer A to C (or use a hub with routing).
- The address spaces must not overlap.

## Azure DNS

**Azure DNS** hosts your DNS zones and answers DNS queries from Microsoft's global network. You can host a public zone for an internet-facing domain such as `contoso.com`, or a **private DNS zone** for name resolution inside VNets. It does not register domain names; you buy the domain from a registrar and then host the zone in Azure DNS. You manage records with the same tools, RBAC and activity logs as other Azure resources.

## Connecting on-premises to Azure

| | VPN Gateway | ExpressRoute |
|---|---|---|
| Path | Encrypted tunnel over the **public internet** (IPsec/IKE) | **Private** dedicated connection through a connectivity provider; not over the public internet |
| Connection types | Site-to-site, point-to-site, VNet-to-VNet | Circuit through a provider or ExpressRoute Direct |
| Bandwidth and latency | Variable, depends on the internet | More predictable, higher reliability and typically lower latency |
| Encryption | Encrypted by default | Private but not encrypted by default (you can add encryption) |
| Setup | Fast, low cost | Takes longer, requires a provider |

- **Site-to-site (S2S)** VPN joins an on-premises network to a VNet through an on-premises VPN device.
- **Point-to-site (P2S)** VPN lets an individual client device connect to a VNet, useful for remote workers.
- A VPN gateway requires a dedicated **gateway subnet** in the VNet (named `GatewaySubnet`).
- Choose ExpressRoute for consistent performance, large data transfers, and when traffic must not cross the internet. Choose VPN Gateway for a quick, inexpensive or backup connection. Many organizations combine both (ExpressRoute primary, VPN failover).

> **Exam tip:** "Private connection that does not go over the public internet" means ExpressRoute. "Encrypted tunnel over the internet" means VPN Gateway.

## Public and private endpoints

Many Azure PaaS services (Storage, SQL Database, Key Vault) have a **public endpoint**, an address reachable from the internet, which you can restrict with firewall rules.

A **private endpoint** is a network interface in your subnet with a private IP address that maps to a specific instance of a service, powered by **Azure Private Link**. Traffic from your VNet (and from on-premises through VPN or ExpressRoute) reaches the service over the Microsoft backbone, never traversing the public internet. After creating a private endpoint, you typically disable public network access to the service. Name resolution to the private IP is handled with a private DNS zone.

| | Public endpoint | Private endpoint |
|---|---|---|
| Address | Public IP / public DNS name | Private IP from your subnet |
| Reachable from | Internet (unless restricted) | Your VNet and connected networks |
| Technology | Service endpoint with firewall rules | Azure Private Link |

> **Watch out:** A *service endpoint* extends your VNet identity to a service but the service still uses its public address. A *private endpoint* gives the service a private IP in your subnet. Do not confuse the two.

## Which service for which job

| Requirement | Service |
|---|---|
| Isolated private network in Azure | Virtual Network |
| Connect two VNets privately | VNet peering |
| Host DNS records | Azure DNS |
| Encrypted tunnel from office to Azure over internet | VPN Gateway (site-to-site) |
| Remote laptop to VNet | VPN Gateway (point-to-site) |
| Private dedicated line to Azure | ExpressRoute |
| Reach a PaaS service on a private IP | Private endpoint (Private Link) |
| Filter traffic by port and IP | Network security group |

## Try it in the portal

1. Create `rg-lab-net` and two VNets, `vnet-a` (`10.1.0.0/16`) and `vnet-b` (`10.2.0.0/16`), each with a subnet.
2. Open `vnet-a` > **Peerings** > **Add** and peer it to `vnet-b`; confirm the status becomes Connected on both sides.
3. Create a **DNS zone** (free to create) for a name you own, or a private DNS zone linked to `vnet-a`, and add an A record.
4. Create a storage account, open **Networking** and **Private endpoint connections**, and walk through (without finishing) adding a private endpoint into `vnet-a`.
5. Open **Virtual network gateways** > **Create** just to view the options (VPN vs ExpressRoute); don't deploy, as gateways incur hourly cost.

## Key takeaways

- A VNet is a regional private network split into subnets; NSGs filter traffic.
- VNet peering links VNets privately over the Microsoft backbone and is not transitive.
- Azure DNS hosts public and private zones; it is not a domain registrar.
- VPN Gateway is an encrypted tunnel over the internet (S2S, P2S); ExpressRoute is a private connection that avoids the public internet.
- A private endpoint puts a service on a private IP in your subnet using Private Link.
- A public endpoint is reachable over the internet, optionally limited by firewall rules.
