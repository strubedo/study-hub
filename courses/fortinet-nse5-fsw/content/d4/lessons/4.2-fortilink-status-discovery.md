## Start every FortiLink ticket with get-conn-status

`execute switch-controller get-conn-status` is the FortiLink equivalent of `show cdp neighbors` plus `show interfaces status` in one line per switch. Run it first; it tells you whether the problem is discovery, authorization, the management tunnel or configuration sync. Add a switch name to see one switch only (`execute switch-controller get-conn-status FSW-Access2`).

```text
FGT-HQ # execute switch-controller get-conn-status
Managed-devices in current vdom root:
FortiLink interface : fortilink
SWITCH-ID         VERSION           STATUS         FLAG   ADDRESS        JOIN-TIME                   SERIAL
FSW-Core1         v7.6.1 (1047)     Authorized/Up   2    10.255.1.2      Thu Oct 30 07:58:12 2026    S248EPTF18000101
FSW-Core2         v7.6.1 (1047)     Authorized/Up   2    10.255.1.3      Thu Oct 30 07:58:20 2026    S248EPTF18000102
FSW-Access1       v7.6.1 (1047)     Authorized/Up   2C   10.255.1.4      Thu Oct 30 08:03:41 2026    S124EN5918000103
FSW-Access2       v7.6.1 ()         Authorized/Down 2    0.0.0.0         N/A                         S124EN5918000105
S124EN5918000106  N/A               Discovered/Down 2                    N/A                         S124EN5918000106
Flags: C=config sync, U=upgrading, S=staged, D=delayed reboot pending, E=config sync error, 2=L2, 3=L3, V=VXLAN, T=tunnel, X=External
Managed-Switches: 5 (UP: 3 DOWN: 2 MAX: 32)
```

| Column | What to read from it |
|--------|---------------------|
| **SWITCH-ID** | The managed-switch name. Since FortiOS 7.4.0 a switch can have a user-defined name (up to 16 characters, `rename <serial> to <name>` under `config switch-controller managed-switch`); otherwise the serial number is the name |
| **VERSION** | FortiSwitchOS version and build the switch reported; the build is blank while the switch is down and the version is `N/A` if it never joined |
| **STATUS** | Authorization state / connection state |
| **FLAG** | Letters from the legend (several can appear together) |
| **ADDRESS** | The switch's FortiLink management address; `0.0.0.0` when not connected |
| **JOIN-TIME** | When the switch last joined; a recent time on one switch means it just reconnected or rebooted |
| **SERIAL** | Serial number, stored read-only since FortiOS 7.4.0 |

The last line counts the switches in this VDOM, how many are up and down, and the maximum the FortiGate model can manage.

### The status values

| STATUS | Meaning | First thing to check |
|--------|---------|----------------------|
| `Authorized/Up` | Managed and connected | Nothing; look at FLAG |
| `Authorized/Down` | Authorized earlier, but no management connection now | Is it rebooting (D flag, upgrade)? Cable, ISL path, power, firmware compatibility, event logs |
| `Discovered/Down` | The FortiGate has seen the switch but it is **not authorized** | Authorize it, or enable automatic authorization on the FortiLink interface |

### The flags

| Flag | Meaning |
|------|---------|
| `C` | Configuration sync |
| `E` | Configuration sync **error** |
| `U` | Upgrading |
| `S` | Firmware staged |
| `D` | Delayed reboot pending (for example after `execute switch-controller switch-action restart delay all`) |
| `2` / `3` | Managed over layer 2 / layer 3 |
| `V` | Managed over a VXLAN tunnel (FortiOS 7.4.0 / FortiSwitchOS 7.4.0 and later) |
| `T` | Tunnel (seen, for example, with FortiLink over HTTPS) |
| `X` | External |

> **Exam tip:** Read STATUS before FLAG. `Discovered/Down` is an authorization problem, `Authorized/Down` is a connectivity problem, and `E` on an `Authorized/Up` switch is a configuration problem.

## When a switch never appears

Work from the FortiGate outward:

1. **Switch controller and FortiLink interface.** The switch controller must be enabled (`config system global` → `set switch-controller enable`; the GUI menu is **WiFi & Switch Controller**). The FortiLink interface must contain the port the switch is cabled to. Network > Interfaces shows **Dedicated to FortiSwitch** for a FortiLink interface.
2. **Supported port and mode.** FortiLink works on all Ethernet ports except **HA** and **MGMT**, and **not at all in transparent mode**.
3. **Switch in factory defaults.** A switch that was configured before (for example in standalone mode) may not join. Run `execute factoryreset` on the switch, then reconnect. Since FortiSwitchOS 7.2.0 every port is enabled for FortiLink auto-discovery by default; older releases used a model-specific set of ports, normally the last four.
4. **Zero-touch: the switch picked another manager.** From FortiSwitchOS 7.2.0 / FortiOS 7.2.0 a new switch connects to whichever manager it finds: a FortiGate, FortiEdge Cloud (called FortiLAN Cloud in the 7.6.1 guides) or FortiSwitch Manager. Only one manager is used at a time, so a switch already claimed in the cloud won't be managed by your FortiGate. Fortinet also recommends a factory reset before moving an already-configured switch to FortiSwitchOS 7.2.0 or later; otherwise it might not come online or might report a configuration sync error.
5. **Discovery has been disabled for that serial.** `config switch-controller global` → `set disable-discovery <switch-id>` stops the FortiGate from discovering a switch. `execute switch-controller switch-action set-standalone <switch>` resets a switch and also keeps the FortiGate from discovering and authorizing it again.
6. **Platform limits and compatibility.** The model limit (for example 8 for a FortiGate 40F or FortiGate-VM01) and the FortiLink Compatibility table apply. New hardware (NPI releases) might not support FortiLink yet.

## Discovered but not authorized

If **Automatically authorize devices** (`set auto-auth-extension-device enable` on the FortiLink interface) is off, every new switch stays `Discovered/Down` until you authorize it:

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit S124EN5918000106
FGT-HQ (S124EN5918000106) # set fsw-wan1-admin enable
FGT-HQ (S124EN5918000106) # end
```

In the GUI: **WiFi & Switch Controller > Managed FortiSwitches**, select the switch and click **Authorize**. You can pre-authorize a switch before it arrives by creating it with its serial number, and FortiOS accepts wildcard serials in templates (`PREFIX****nnnnnn`).

Starting in FortiOS 7.6.1, empty FortiSwitch admin passwords are no longer allowed: when a switch with no admin password is authorized, the FortiGate generates one. Set the password you want in the switch profile (`config switch-controller switch-profile`) so you can still log in to the switch directly.

## Neighbor detection and the split interface

The FortiGate finds switches on the FortiLink interface either with the FortiLink protocol or with LLDP:

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit fortilink
FGT-HQ (fortilink) # set fortilink-neighbor-detect lldp
FGT-HQ (fortilink) # set lldp-reception enable
FGT-HQ (fortilink) # set lldp-transmission enable
FGT-HQ (fortilink) # end
```

- **LLDP is the default starting in FortiOS 7.6.1** (it was `fortilink` before). LLDP detection needs `lldp-reception` and `lldp-transmission` enabled on the FortiLink interface.
- A LAG that is a member of a FortiLink software switch requires `lldp`.
- With the **FortiLink split interface** enabled (the default; exactly two aggregate members, one to each switch), only one link is active. With `fortilink` detection the standby link shows **down**; with `lldp` detection the standby link is **up** but LACP is inactive on it. An engineer who expects the standby port to be down after upgrading to 7.6.1 should not open a ticket about it.

## Authorized but down: tunnel and reachability checks

- **Topology view.** In **WiFi & Switch Controller > Managed FortiSwitches**, Topology view, a healthy link is a solid line with green status. A dashed line with a broken-link icon means the link is down; Fortinet lists a faulty cable and **mismatched firmware** as typical causes. A cloud icon on the line means the switch is managed over layer 3.
- **Ping by serial.** `config switch-controller global` → `set sn-dns-resolution enable` (default) lets you `execute ping <serial>.fsw`, or just `execute ping <serial>` after `config system dns` → `set domain "fsw"`.
- **Connection diagnostics.** `execute switch-controller diagnose-connection <switch>` collects FortiSwitch connection diagnostics from the FortiGate, and `execute switch-controller ssh <user> <switch>` opens a session to the switch.
- **Keepalives.** FortiOS 7.4.0 added two settings under `config switch-controller system`: `caputp-echo-interval` (8–600 seconds, default 30) and `caputp-max-retransmit` (0–64, default 4). Shorter intervals and fewer retransmits detect an offline switch faster.

### FortiSwitch event logs

With `config log eventfilter` → `set switch-controller enable`, the FortiGate logs switch-controller events (`type="event" subtype="switch-controller"`). They tell the story of a join or a failure:

```text
logid="0114032601" type="event" subtype="switch-controller" level="information" logdesc="Switch-Controller discovered" sn="S124EN5918000106" name="S124EN5918000106" msg="S124EN5918000106 Discovered"
logid="0114032605" type="event" subtype="switch-controller" level="information" logdesc="Switch-Controller Tunnel Up" sn="S124EN5918000103" name="FSW-Access1" msg="CAPWAP Tunnel Up (10.255.1.4)"
logid="0114032697" type="event" subtype="switch-controller" level="warning" logdesc="FortiSwitch switch" sn="S124EN5918000105" name="FSW-Access2" msg="FortiLink: internal echo reply timed out"
```

A "Discovered" message with no "Tunnel Up" after it points to authorization. Repeated echo-reply timeouts point to the path between the FortiGate and the switch.

> **Real world:** The management tunnel between the FortiGate and a managed switch is CAPWAP-based (the logs say "CAPWAP Tunnel Up"). FortiOS 7.4.2 / FortiSwitchOS 7.4.2 added FortiLink over HTTPS as an alternative; a switch uses one or the other, never both.

## Lab it yourself

On the **FortiGate-VM** permanent trial (no switch needed):

1. `config system global` → `set switch-controller enable`, then check that **WiFi & Switch Controller** appears.
2. Look at the FortiLink interface: `show system interface fortilink` (if your VM has none, create one on a spare port with `set fortilink enable`; check that it fits the 3-interface trial cap first). Note `fortilink-neighbor-detect` and `auto-auth-extension-device`.
3. Run `execute switch-controller get-conn-status`: you get the header, an empty table and a `Managed-Switches: 0` line. Note the MAX value for your VM size.
4. Run `config log eventfilter` → `get` and confirm `switch-controller` logging is on.

Anything with a real switch (factory reset, authorization, status changes) needs a **physical FortiSwitch**.

## Key takeaways

- `get-conn-status` columns: SWITCH-ID, VERSION, STATUS, FLAG, ADDRESS, JOIN-TIME, SERIAL, plus `Managed-Switches: n (UP DOWN MAX)`.
- `Discovered/Down` = seen but not authorized; `Authorized/Down` = authorized but not connected; `Authorized/Up` = managed.
- Flags: C sync, E sync error, U upgrading, S staged, D delayed reboot, 2/3 L2/L3, V VXLAN, T tunnel, X external.
- FortiLink needs a non-HA, non-MGMT port and NAT/route mode (no transparent mode); reset a used switch with `execute factoryreset`.
- Zero-touch can hand a new switch to FortiEdge Cloud or FortiSwitch Manager instead; only one manager at a time.
- FortiOS 7.6.1 uses LLDP neighbor detection by default; with the split interface the standby link is up (LACP inactive) under LLDP.
- Use the topology view, `execute ping <serial>`, `diagnose-connection` and `subtype="switch-controller"` event logs for down switches.
