## Two places to capture

Mirroring copies traffic somewhere else. Packet capture records it where it is seen. In a FortiSwitch network there are two capture engines:

| Capture engine | Runs on | Typical use |
|----------------|---------|-------------|
| **Packet-capture profile** (`config system sniffer-profile`) | The FortiSwitch (FortiSwitchOS CLI or GUI **System > Packet Capture**) | Look at frames on one switch port or one system interface, keep a .pcap on the switch |
| **FortiOS packet capture / sniffer** | The FortiGate (**Network > Diagnostics > Packet Capture** or `diagnose sniffer packet`) | Traffic that reaches the FortiGate: FortiLink management, routed traffic on FortiLink VLAN interfaces, RSPAN copies on the rspan interface |

Keep the forwarding path in mind. Traffic between two hosts in the same VLAN on the same switch (or across ISLs) is switched by FortiSwitch hardware and never reaches the FortiGate. Traffic between VLANs, to the Internet or to the FortiGate itself goes up the FortiLink and can be sniffed on the FortiGate VLAN interface. If you need same-VLAN traffic on the FortiGate, mirror it first (RSPAN), then capture on the rspan interface.

## FortiSwitchOS packet-capture profiles

The workflow has five steps: create a profile, start it, pause or stop it, display or upload the result, delete the file.

### 1. Create the profile

```text
FSW-Lab # config system sniffer-profile
FSW-Lab (sniffer-profile) # edit dhcp-port5
FSW-Lab (dhcp-port5) # set switch-interface port5
FSW-Lab (dhcp-port5) # set filter "udp and port 67"
FSW-Lab (dhcp-port5) # set max-pkt-count 200
FSW-Lab (dhcp-port5) # set max-pkt-len 256
FSW-Lab (dhcp-port5) # end
```

| Setting | Meaning |
|---------|---------|
| `switch-interface` **or** `system-interface` | Where to capture: a switch port, or a system interface such as `mgmt` or `internal`. You **can't** set both in one profile |
| `filter` | tcpdump-style expression, or `none`. Logic such as `'udp and port 1812 and host forti1 and \( forti2 or forti3 \)'` is allowed |
| `max-pkt-count` | How many packets to keep. The upper limit depends on the RAM disk size |
| `max-pkt-len` | Bytes captured per packet, **64–1534** |

The GUI version (**System > Packet Capture > Add Packet Capture**) offers simpler filter boxes for hosts, ports, VLANs and protocol numbers, each as comma-separated lists.

### Platform limits

| Platform | Max profiles | RAM disk |
|----------|-------------|----------|
| 1xx (124F, 148E, 148F) | 8 | 20 MB |
| 2xx | 8 | 50 MB |
| 4xx | 16 | 75 MB |
| 5xx, 1xxx, 3xxx | 16 | 100 MB |

### 2–3. Start, pause, stop

```text
FSW-Lab # execute system sniffer-profile start dhcp-port5
FSW-Lab # execute system sniffer-profile pause dhcp-port5
FSW-Lab # execute system sniffer-profile start dhcp-port5
FSW-Lab # execute system sniffer-profile stop dhcp-port5
```

A capture runs until it reaches `max-pkt-count` or until you pause or stop it. There is no separate "resume" keyword: `start` on a paused profile restarts it.

### 4. Display or upload

```text
FSW-Lab # get system sniffer-profile capture dhcp-port5
FSW-Lab # execute system sniffer-profile upload tftp dhcp-port5 dhcp-port5.pcap 10.10.99.25
```

`get system sniffer-profile capture` prints parsed packet information on the CLI. `upload ftp` or `upload tftp` sends the .pcap file to a server (an optional `:port` may follow the server address). In the GUI the download goes to your browser's Downloads folder.

### 5. Delete

```text
FSW-Lab # execute system sniffer-profile delete-capture dhcp-port5
```

You can delete a capture only after it is **stopped** (not while it is running or paused). Captures live on the RAM disk, so **all .pcap files are deleted when the switch is power cycled**. Upload anything you need before a reboot.

> **Exam tip:** Remember the order: create → start → pause/stop → display/upload → delete, and that delete needs a stopped capture.

> **Watch out:** `config system sniffer-profile` is a FortiSwitchOS command. In FortiLink mode, Fortinet warns that configuration typed directly on a managed switch is unknown to the FortiGate and is lost when the switch restarts. For managed switches, prefer mirroring configured from the FortiGate; use on-switch capture profiles for standalone switches or short, deliberate troubleshooting sessions.

### The FortiSwitchOS built-in sniffer

FortiSwitchOS also has a live sniffer for its system interfaces. The FortiSwitchOS guide uses it to check that sFlow datagrams leave the switch, for example `diag sniff packet <vlan_interface> "udp port 6343"`. It prints to the console and does not create a capture profile or .pcap file.

## Sniffing on the FortiGate side

### GUI packet capture

**Network > Diagnostics > Packet Capture** lets you pick an interface (the `fortilink` interface, a FortiLink VLAN interface such as `vlan10-data`, or the `rspan` interface), add a filter, capture and download a PCAP. This is the documented way to look at RSPAN traffic.

### CLI: diagnose sniffer packet

```text
FGT-HQ # diagnose sniffer packet any 'host 10.10.10.25 and icmp' 4 10 l
interfaces=[any]
filters=[host 10.10.10.25 and icmp]
2026-10-30 09:14:02.118274 vlan10-data in 10.10.10.25 -> 10.10.20.40: icmp: echo request
2026-10-30 09:14:02.118520 vlan20-voice out 10.10.10.25 -> 10.10.20.40: icmp: echo request
```

The arguments are interface, filter, verbosity (4 adds the interface name and direction), packet count and timestamp format (`l` = local time). Naming one interface, such as `vlan10-data`, shows only that interface. Using `any` captures on every interface, which is how you prove that a packet enters on one VLAN interface and leaves on another. The output above shows inter-VLAN routing through the FortiGate working: the request arrives on `vlan10-data` and is forwarded out of `vlan20-voice`.

To see the management conversation between the FortiGate and one switch, filter on the switch's FortiLink address (the ADDRESS column of `execute switch-controller get-conn-status`) on the `fortilink` interface.

## Choosing the capture point

| Symptom | Best capture point |
|---------|-------------------|
| Host can't reach another VLAN or the Internet | FortiGate: sniff the host's VLAN interface (plus `diagnose debug flow` if packets arrive) |
| Two hosts in the same VLAN can't talk | Switch: mirror the ports (SPAN to a local analyzer, or RSPAN to the FortiGate) |
| DHCP or 802.1X frames on one access port | Switch: packet-capture profile on that port, or mirror it |
| Need security-profile visibility without inline risk | FortiOS one-arm sniffer on an RSPAN/ERSPAN copy |
| FortiLink management to one switch | FortiGate: sniff `fortilink` filtered on the switch address |

## Lab it yourself

- On the **FortiGate-VM** trial, run `diagnose sniffer packet any 'icmp' 4 10 l` while you ping between two subnets that you route through the VM, and open **Network > Diagnostics > Packet Capture** to see the GUI version. No switch is needed for this part.
- The `config system sniffer-profile` steps need a **physical FortiSwitch** in standalone mode. If you have one, capture LLDP on an uplink (`filter "ether proto 0x88cc"`), stop the capture and upload it to a TFTP server on your lab PC.

## Key takeaways

- Packet-capture profiles run on the switch: `config system sniffer-profile`, then `execute system sniffer-profile start | pause | stop | upload | delete-capture`.
- A profile captures on one switch interface **or** one system interface, never both; `max-pkt-len` is 64–1534.
- 1xx/2xx models: 8 profiles; 4xx and up: 16. RAM disk 20/50/75/100 MB by family.
- Delete only a stopped capture; every .pcap is lost on power cycle.
- `get system sniffer-profile capture <profile>` shows the parsed capture on the CLI.
- On the FortiGate use **Network > Diagnostics > Packet Capture** or `diagnose sniffer packet <interface> '<filter>' <verbosity> <count> <tsformat>`.
- Same-VLAN switched traffic never reaches the FortiGate; mirror it first.
