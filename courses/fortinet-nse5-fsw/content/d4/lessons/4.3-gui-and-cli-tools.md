## The FortiGate GUI pages

In FortiLink mode most day-to-day visibility comes from the FortiGate. The pages live under **WiFi & Switch Controller** (the menu appears once the switch controller feature is enabled).

| Page | What it gives you |
|------|-------------------|
| **Managed FortiSwitches** | Every managed switch as a faceplate, in a list or in **Topology** view. Status is green when FortiLink is up; a dashed link with a broken-link icon means down; a cloud icon means managed over layer 3. Edit a switch to see its firmware build, restart, authorize/deauthorize, upgrade or rename it |
| **FortiSwitch Ports** | One row per port: status (green up, red down), trunk membership, access mode, enabled features, native VLAN, allowed VLANs, PoE status, device information, DHCP snooping status, transceiver information. **Faceplates** shows active ports (green), PoE ports (blue rectangle), the FortiLink port (link icon) and the PoE power budget (used vs reserved) |
| **FortiSwitch Clients** (FortiOS 7.2.0+) | Devices connected to the switches in the VDOM. Open a row to see the NAC policies and dynamic port policies the device matches; from here you can create a firewall device address or IP address, or **quarantine the host** |
| **Diagnostics and Tools** (pane opened from a switch) | Health summary, port and trunk lists, logs, clients per port, LED blink, cable test, plus authorize, upgrade, restart and CLI access |

Other places: **User & Device > Device List** lists devices attached to FortiSwitch ports with IP address and switch/port; the CLI equivalent is `diagnose switch-controller mac-cache show <switch>`. **Security Fabric > Physical Topology** draws the switches in the fabric and also opens the Diagnostics and Tools pane. **Network > Interfaces** marks the FortiLink interface as **Dedicated to FortiSwitch**.

## Diagnostics and Tools: health, LED blink, cable test

- **Health.** The General pane rates general health, port health and MC-LAG health as good, fair or poor. The **Legend** button lists the thresholds.
- **LED Blink.** Start it for **5, 15, 30 or 60 minutes**, find the switch in the rack, then stop it. On 5xx models only the SFP port LEDs blink. CLI from the FortiGate: `execute switch-controller switch-action physical-ports led-flash switch-id <switch> <time>` (there are also `switch-group`, `tier1` and `tier2plus` variants). On a standalone switch: `diagnose switch physical-ports led-flash <time | disable>`.
- **Cable Test.** A time domain reflectometry (TDR) test per pair. Pair states: **Open, Short, Ok, Open_Short, Unknown, Crosstalk**. With no cable attached the state is Open and the length 0 m. Running it on a port whose link is up **interrupts traffic for several seconds**. On FS-124E, FS-148E and their PoE variants crosstalk can't be detected, results take about 5 seconds, and length and open/short results are inaccurate. CLI from the FortiGate: `execute switch-controller switch-action cable-diag <switch> <port>`; on the switch: `diagnose switch physical-ports cable-diag <port>`.

```text
FSW-Access3 # diagnose switch physical-ports cable-diag port14
port14:  cable (4 pairs, length +/- 10 meters)
pair A Ok, length 37 meters
pair B Ok, length 37 meters
pair C Ok, length 37 meters
pair D Open, length 21 meters
```

This test ran on FSW-Access3, an FS-248E-POE (serial prefix S248EP), so the lengths can be trusted; on the FS-124E/148E family Fortinet documents the lengths and open/short results as inaccurate. Pair D is open about 21 m from the switch while the other pairs reach the far end: a damaged cable or a bad termination along the run. Gigabit Ethernet over copper needs all four pairs, so a broken pair can leave the port linking at a lower speed or not at all. `diagnose switch physical-ports mdix-status <port>` shows whether the port runs MDI or MDI-X.

## Port statistics from the FortiGate

GUI: **FortiSwitch Ports**, select a port, **View Statistics**. The **Traffic** tab shows bytes and frames sent and received; the **Issues** tab shows frame errors by type. **Configure Table** can add Bytes, Errors and Packets columns to the port list.

```text
FGT-HQ # diagnose switch-controller switch-info port-stats FSW-Access3 port14
Vdom: root
FSW-Access3:
Port(port14) is Admin up, line protocol is up
Interface Type is Serial Gigabit Media Independent Interface(SGMII/SerDes)
Address is 70:4C:A5:3B:10:0E, loopback is not set
MTU 9216 bytes, Encapsulation IEEE 802.3/Ethernet-II
full-duplex, 100 Mb/s, link type is auto
input  : 18273645 bytes, 154320 packets, 1873 errors, 0 drops, 0 oversizes
         150112 unicasts, 2104 multicasts, 2104 broadcasts, 0 unknowns
output : 92837465 bytes, 201554 packets, 0 errors, 0 drops, 0 oversizes
         197930 unicasts, 1812 multicasts, 1812 broadcasts
         0 fragments, 0 undersizes, 0 collisions, 0 jabbers
```

The port is up but auto-negotiated to 100 Mb/s and is logging input errors: consistent with the bad pair above. Counter commands:

| Command | Effect |
|---------|--------|
| `diagnose switch-controller switch-info port-stats <switch> <port>` | Show counters (omit the switch to cover all ports of all managed switches) |
| `diagnose switch-controller trigger reset-hardware-counters <switch> <ports>` | Zero the counters. Meant for debugging: accuracy isn't guaranteed and it can upset SNMP and other monitoring |
| `diagnose switch-controller trigger restore-hardware-counters <switch> <ports>` | Restore the counters from the switch hardware |

Port lists accept ranges and commas, for example `1,3,port6-7,internal`. On a standalone switch the equivalents are `diagnose switch physical-ports port-stats list [<ports>]`, `set-counter-zero` and `set-counter-revert` (QoS, SNMP and GUI counters are not cleared), or **Switch > Monitor > Port Stats**.

## diagnose switch-controller switch-info: pick the keyword

All take the managed switch name (device ID) first. Since FortiOS 7.4.0 that is the user-defined name if one is set.

| Symptom | Keyword |
|---------|---------|
| What is plugged into which port? | `lldp neighbors-summary <switch>`, `lldp neighbors-detail <switch> <port>`, `lldp stats <switch> <port>` |
| Port counters, speed, duplex | `port-stats <switch> <port>`, `port-properties <switch> <port>` |
| MAC addresses learned in a VLAN | `mac-table <switch> <vlan-id>` |
| LAG/ISL/ICL state | `trunk status <switch> <trunk>`, `trunk config <switch>` |
| MCLAG | `mclag icl <switch>`, `mclag list <switch> <trunk>`, `mclag peer-consistency-check <switch> <trunk>` |
| Spanning tree | `stp <switch> <instance>`, `rpvst <switch> <port>`, `bpdu-guard-status <switch>`, `loop-guard <switch>` |
| Flapping port shut down | `flapguard status <switch>` (reset with `execute switch-controller flapguard reset <switch> <port>`) |
| SFP/transceiver | `modules summary \| status \| detail \| limits <switch> <port>` |
| PoE | `poe summary \| detail <switch> <port>` |
| Security features | `802.1X <switch> <port>`, `802.1X-dacl`, `dhcp-snooping status \| database`, `arp-inspection stats <switch>`, `ip-source-guard hardware`, `mac-limit-violations all <switch>` |
| QoS and ACLs | `qos-stats <switch> <port>`, `acl-counters <switch> <port>` |
| Mirror session | `mirror status <switch>` |
| Flow export | `flow-tracking statistics \| flows \| flows-raw <switch>` |

## FortiSwitchOS get switch / diagnose switch commands

When you are on a switch console (standalone, or read-only checks on a managed switch):

| Command | Shows |
|---------|-------|
| `get switch lldp settings` / `get switch lldp profile` | LLDP global settings (default `tx-interval 30`, `tx-hold 4`) and profiles (`default`, `default-auto-isl`, …) |
| `get switch lldp neighbor-summary` | LLDP peers per port (singular `neighbor` in the 7.6.1 guide; the FortiGate keyword is `neighbors-summary`) |
| `diag switch mac-address list` | MAC table lines such as `MAC: 08:5b:0e:f1:95:e5 VLAN: 4092 Port: internal(port-id 31)`; narrow it with `diag switch mac-address filter vlan-map …` |
| `diagnose switch trunk list` | Trunk members and state |
| `diagnose switch mclag icl` / `list` | MCLAG state |
| `diagnose switch physical-ports list <port>` | Port details, including the current FEC state |
| `get switch modules summary \| status \| detail \| limit <port>` | Transceiver data via the diagnostic monitoring interface (DMI): vendor, part number, temperature, voltage, laser bias, TX/RX power, alarm and warning flags |
| `get switch stp instance`, `diagnose stp instance list` | MSTP state |
| `diagnose switch network-monitor …` | Network monitoring (directed and survey mode, disabled by default) |

```text
FSW-Core1 # get switch modules status port50
____________________________________________________________
Port(port50)
temperature      31.250000 C
voltage          3.287400 volts
alarm_flags[0]   0x0000
warning_flags[0] 0x0000
laser_bias[0]    6.104000 mAmps
tx_power[0]      -2.412000 dBm
rx_power[0]      -24.517000 dBm
options          0x000F ( TX_DISABLE TX_FAULT RX_LOSS TX_POWER_LEVEL1 )
options_status   0x0008 ( TX_POWER_LEVEL1 )
```

Transmit power looks normal but receive power is very low: check the far-end optic, the fiber and the patch panel before blaming this switch. DMI reporting per port is controlled by `config switch physical-port` → `set dmi-status {enable | disable | global}`.

> **Exam tip:** FortiGate side = `diagnose switch-controller switch-info …` with the switch name; FortiSwitch side = `get switch …` / `diagnose switch …` on the switch itself. The FortiGate 802.1X keyword is `802.1X`, the switch one is `802-1x`.

## Lab it yourself

On the **FortiGate-VM** trial you can explore the command trees with `?`: `diagnose switch-controller switch-info ?`, `execute switch-controller switch-action ?`, and the **WiFi & Switch Controller** menus (empty without switches). Everything that returns real data (cable test, port statistics, DMI, MAC tables) needs a **physical FortiSwitch**; read the exhibits in this lesson and the questions as your "lab output".

## Key takeaways

- GUI: Managed FortiSwitches (faceplate/topology), FortiSwitch Ports (per-port VLANs, PoE, DHCP snooping, transceiver), FortiSwitch Clients (matches NAC/dynamic port policies, quarantine), Diagnostics and Tools.
- LED blink: 5/15/30/60 minutes; 5xx blinks only SFP LEDs.
- Cable test: Open, Short, Ok, Open_Short, Unknown, Crosstalk; no cable = Open, 0 m; interrupts a live link for several seconds.
- `switch-info port-stats` shows counters; `trigger reset-hardware-counters` / `restore-hardware-counters` zero and restore them (debug use only).
- Learn the `switch-info` keywords by symptom: lldp, mac-table, trunk, mclag, stp, flapguard, modules, poe, mirror, flow-tracking.
- On the switch: `diagnose switch physical-ports …`, `get switch modules status`, `diag switch mac-address list`, `diagnose switch trunk list`.
