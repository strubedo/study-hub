## Getting data out of the switches

The GUI and diagnose commands answer "what is happening now". For trending, alerting and forensics you export data: SNMP for health counters and traps, sFlow or NetFlow/IPFIX for traffic, and logs for events. In FortiLink mode all of this is configured on the FortiGate under `config switch-controller`, globally for every managed switch with a per-switch override.

A recurring catch: managed switches reach your servers **through the FortiGate**. Polling a switch, receiving its traps, or receiving its sFlow/NetFlow datagrams needs a **firewall policy** across the FortiLink interface, just like any other routed traffic.

## SNMP

The managed-switch SNMP agent is **read-only**. SNMP v1 and v2c managers can query and receive traps, and SNMPv3 users can be defined. At most **8 trap hosts** per switch.

Steps for global SNMP:

1. **Firewall policy** on the FortiGate: from the interface facing the SNMP server to the FortiLink interface for polling (service SNMP), and the reverse direction for traps.
2. **Allow SNMP on the switch** through the local-access security policy. In-band management uses `internal-allowaccess`; for FortiLink over layer 3 with out-of-band management use `mgmt-allowaccess`.
3. **System information, community, trap thresholds, users.**

```text
FGT-HQ # config switch-controller security-policy local-access
FGT-HQ (local-access) # edit "default"
FGT-HQ (default) # set internal-allowaccess https ping ssh snmp
FGT-HQ (default) # next
FGT-HQ (local-access) # end
FGT-HQ # config switch-controller snmp-sysinfo
FGT-HQ (snmp-sysinfo) # set status enable
FGT-HQ (snmp-sysinfo) # set location "HQ-IDF2"
FGT-HQ (snmp-sysinfo) # end
FGT-HQ # config switch-controller snmp-community
FGT-HQ (snmp-community) # edit 1
FGT-HQ (1) # set name "noc-ro"
FGT-HQ (1) # set events cpu-high mem-low log-full intf-ip ent-conf-change
FGT-HQ (1) # config hosts
FGT-HQ (hosts) # edit 1
FGT-HQ (1) # set ip 10.10.99.40
FGT-HQ (1) # next
FGT-HQ (hosts) # end
FGT-HQ (1) # next
FGT-HQ (snmp-community) # end
```

| Item | Default / fact |
|------|----------------|
| Query port / trap ports | 161 / 162 |
| `config switch-controller snmp-trap-threshold` | `trap-high-cpu-threshold` 80 %, `trap-low-memory-threshold` 80 %, `trap-log-full-threshold` 90 % |
| SNMPv3 | `config switch-controller snmp-user`: `security-level {auth-priv \| auth-no-priv \| no-auth-no-priv}`, SHA/MD5 auth, AES/DES privacy |
| Per-switch settings | Under the managed switch: `set override-snmp-sysinfo`, `override-snmp-community`, `override-snmp-trap-threshold`, `override-snmp-user enable`, then the matching `config snmp-…` block |
| MAC change trap (FortiOS 7.6.0+) | `set events l2mac` in the community (disabled by default). On ports with `access-mode static`, also `set log-mac-event enable` (hidden for `dynamic` and `nac` ports). Only dynamic MACs; events can be lost |
| FortiGate MIB | FortiOS has FortiSwitch OIDs for switch CPU (`fgSwCpu`), memory (`fgSwMemory`) and port status (`fgSwPortStatus`); switches refresh CPU and memory every 30 seconds |

## sFlow

sFlow (version 5) samples packets and sends **flow samples** (1 of n packets, truncated) and **counter samples** (interface counters every n seconds) to a collector. It is CPU intensive, so Fortinet advises against high sampling rates for long periods.

```text
FGT-HQ # config switch-controller sflow
FGT-HQ (sflow) # set collector-ip 10.10.99.45
FGT-HQ (sflow) # set collector-port 6343
FGT-HQ (sflow) # end
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config ports
FGT-HQ (ports) # edit port14
FGT-HQ (port14) # set sflow-sampler enabled
FGT-HQ (port14) # set sflow-sample-rate 1024
FGT-HQ (port14) # set sflow-counter-interval 60
FGT-HQ (port14) # next
FGT-HQ (ports) # end
FGT-HQ (FSW-Access1) # end
```

The collector defaults are IP `0.0.0.0` and UDP port **6343**. Per port: `sflow-sample-rate` 0–99999, `sflow-counter-interval` 1–255 seconds. On a standalone switch the commands are `config system sflow` → `config collectors` (multiple collectors since FortiSwitchOS 7.0.0) and, per interface, `packet-sampler`, `packet-sample-rate` (default 512), `sample-direction {rx | tx | both}` (default both) and `sflow-counter-interval` (default 30). The FortiSwitchOS guide's check is to ping the collector from the switch and sniff for `udp port 6343`.

## Flow tracking (NetFlow / IPFIX)

Flow tracking samples IP packets on managed switches and exports flow records.

```text
FGT-HQ # config switch-controller flow-tracking
FGT-HQ (flow-tracking) # set sample-mode perimeter
FGT-HQ (flow-tracking) # set sample-rate 512
FGT-HQ (flow-tracking) # set format ipfix
FGT-HQ (flow-tracking) # set level port
FGT-HQ (flow-tracking) # config collectors
FGT-HQ (collectors) # edit "noc-ipfix"
FGT-HQ (noc-ipfix) # set ip 10.10.99.45
FGT-HQ (noc-ipfix) # set port 4739
FGT-HQ (noc-ipfix) # set transport udp
FGT-HQ (noc-ipfix) # next
FGT-HQ (collectors) # end
FGT-HQ (flow-tracking) # end
```

| Setting | Options and defaults |
|---------|---------------------|
| `sample-mode` | `local` (one specific port), `perimeter` (all ports receiving data traffic **except ISL and ICL** ports), `device-ingress` (all ports receiving data traffic, for hop-by-hop tracking) |
| `sample-rate` | 1 of n packets for perimeter and device-ingress; default **1 of 512** |
| `format` | `netflow1`, `netflow5`, `netflow9`, `ipfix` |
| `level` | `ip` (src/dst IP), `proto` (+ protocol), `port` (+ L4 ports), `vlan` (+ ToS and VLAN) |
| `config collectors` | Several collectors since FortiOS 7.2.0 (FortiSwitchOS 7.0.0+ needed; older switches use only the first); `transport {udp \| tcp \| sctp}` |
| `template-export-period` | 1–60 minutes, default 5 |
| `max-export-pkt-size` | 512–9216 bytes, default 512 |
| Timeouts | general 3600 s, TCP 3600 s, TCP FIN 300 s, TCP RST 120 s, UDP 300 s, ICMP 300 s, max 604800 s |

The flow table size depends on the model; when it is full the **oldest flow expires and is exported**. Sampling follows topology changes automatically (new switches, trunks, ports joining an ISL or ICL).

Troubleshooting commands: `diagnose switch-controller switch-info flow-tracking statistics <switch>`, `… flows-raw <switch>`, `… flows {<count> | all} {<ip> | all} <switch> <port>`; `execute switch-controller switch-action flow-tracking {delete-flows-all | expire-flows-all} <switch>` (expired flows are exported).

### The FortiView Internal Hubs monitor

From FortiOS 7.2.4 with FortiSwitchOS 7.2.3 the FortiGate can be the flow collector itself and show traffic between RFC 1918 hosts behind the switches:

- Set the flow-tracking collector IP to the **FortiLink interface IP** and enable `set switch-controller-netflow-collect enable` on the FortiLink interface.
- The FortiGate needs a **hard disk**, with historical FortiView and disk logging enabled. FortiAnalyzer is **not** supported for this monitor.
- `diagnose switch-controller flow-collector status` shows whether the collector is enabled, its interface and how many NetFlow packets and flows it processed.

## Logs

### FortiSwitch logs to the FortiGate or syslog

```text
FGT-HQ # config switch-controller switch-log
FGT-HQ (switch-log) # set status enable
FGT-HQ (switch-log) # set severity information
FGT-HQ (switch-log) # end
```

- Exporting managed-switch logs to the FortiGate is **global and enabled by default**, with default severity **information**. The FortiGate sets the user field of these entries to **`fortiswitch-syslog`**, which makes them easy to filter.
- Per switch: `config switch-log` → `set local-override enable` under the managed switch.
- Instead, the switches can send logs straight to one or two syslog servers: `config switch-controller remote-log` → `edit {syslogd | syslogd2}` (disabled by default, port **514**, facility **local7**, optional CSV), also overridable per switch.

### Switch-controller events on the FortiGate

The FortiGate's own view of the fabric (discovery, tunnel up, link and switch problems) is in event logs with `subtype="switch-controller"`, enabled with `config log eventfilter` → `set switch-controller enable`. The previous lesson used them to troubleshoot FortiLink.

### Standalone FortiSwitchOS logging

`config log eventfilter` on the switch selects event categories (`link`, `poe`, `router`, `spanning_tree`, `switch`, `switch_controller`, `system`, `user`). `config log syslogd setting` sends logs to one syslog server (port 514; `set mode reliable` for RFC 6587 reliable syslog, default port 6514). The switch's MAC event log does not report MAC changes on ports with 802.1X enabled.

## Lab it yourself

On the **FortiGate-VM** trial (no switch needed): build the `config switch-controller snmp-community`, `sflow`, `flow-tracking` and `switch-log` objects, and write the firewall policy an SNMP server would need toward the FortiLink interface (mind the 3-policy cap). Use `diagnose switch-controller flow-collector status` to see the collector state. Real sFlow/NetFlow datagrams and traps need a **physical FortiSwitch**.

## Key takeaways

- Managed-switch SNMP is read-only, configured globally under `config switch-controller snmp-…` with per-switch `override-snmp-*`; max 8 trap hosts; needs a firewall policy and `snmp` in `internal-allowaccess`.
- Trap thresholds: CPU 80 %, memory 80 %, log full 90 %. The `l2mac` MAC-change trap (7.6.0+) is off by default.
- sFlow v5: collector port 6343, per-port sample rate and counter interval; CPU intensive.
- Flow tracking: `local`, `perimeter` (skips ISL/ICL) or `device-ingress`; default 1/512; NetFlow v1/v5/v9 or IPFIX; template every 5 minutes.
- Internal Hubs: collector = FortiLink IP, `switch-controller-netflow-collect enable`, disk + historical FortiView, no FortiAnalyzer.
- Switch logs go to the FortiGate by default (user `fortiswitch-syslog`, severity information) or to `remote-log` syslog on port 514.
