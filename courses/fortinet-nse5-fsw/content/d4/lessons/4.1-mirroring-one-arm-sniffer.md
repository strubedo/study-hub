## Why mirroring matters on a FortiSwitch

A FortiSwitch forwards frames between ports in hardware. If two hosts in VLAN 10 talk to each other on the same switch, that traffic never touches the FortiGate, so a sniffer on the FortiGate sees nothing. When you need the packets, you have three choices:

| Need | Tool | Where it is configured in FortiLink mode |
|------|------|------------------------------------------|
| Copy a port's traffic to an analyzer plugged into the same switch | Port-based mirroring (SPAN) | FortiGate: `config switch-controller managed-switch` → `config mirror` |
| Bring copied traffic to the FortiGate over layer 2 | RSPAN | FortiGate: `config switch-controller traffic-sniffer` → `set mode rspan` |
| Send copied traffic to a remote collector over IP | ERSPAN | FortiGate: `config switch-controller traffic-sniffer` → `set mode erspan-auto` |
| Inspect copied traffic with FortiGate security profiles (IDS only) | FortiOS one-arm sniffer | RSPAN/ERSPAN + `set ips-sniffer-mode enable` + `config firewall sniffer` |
| Capture packets on the switch itself and save a .pcap there | Packet-capture (sniffer) profile | FortiSwitchOS CLI or GUI on the switch (next lesson) |

Remember the FortiLink rule from the deployment domain: a managed switch is configured from the FortiGate. Mirroring is no exception.

## Port-based mirroring (SPAN) on a managed switch

Port-based mirroring copies ingress and/or egress frames from source ports to a destination port on the **same** switch. The original traffic is not changed.

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config mirror
FGT-HQ (mirror) # edit "voip-debug"
FGT-HQ (voip-debug) # set status active
FGT-HQ (voip-debug) # set dst port24
FGT-HQ (voip-debug) # set switching-packet enable
FGT-HQ (voip-debug) # set src-ingress port5 port6
FGT-HQ (voip-debug) # set src-egress port5
FGT-HQ (voip-debug) # next
FGT-HQ (mirror) # end
```

- `status` and `dst` are the two required settings. A mirror that is `inactive` does nothing.
- `src-ingress` copies frames received on the listed ports; `src-egress` copies frames the switch sends out of them.
- `switching-packet enable` lets the destination port keep switching normal traffic too. Use it when the destination is not a dedicated analyzer port, for example a laptop that runs a sniffer and also needs network access.
- A port can't be both a mirror source and a mirror destination.

> **Watch out:** The FortiLink Guide 7.6.1 says you disable port mirroring with `config switch-controller traffic-sniffer` → `set mode none`. Setting the mirror to `inactive` also stops it. Know both.

## RSPAN: mirrored traffic delivered to the FortiGate

The switch-controller traffic sniffer collects traffic that matches **targets** and carries it across the FortiLink fabric to the FortiGate. In RSPAN mode the copies travel in **VLAN 4092**. The switch picks the uplink and the destination port itself, so you never name a `dst`.

```text
FGT-HQ # config switch-controller traffic-sniffer
FGT-HQ (traffic-sniffer) # set mode rspan
FGT-HQ (traffic-sniffer) # config target-mac
FGT-HQ (target-mac) # edit 00:0c:29:aa:10:15
FGT-HQ (00:0c:29:aa:10:15) # end
FGT-HQ (traffic-sniffer) # config target-ip
FGT-HQ (target-ip) # edit 10.10.20.50
FGT-HQ (10.10.20.50) # end
FGT-HQ (traffic-sniffer) # config target-port
FGT-HQ (target-port) # edit FSW-Access2
FGT-HQ (FSW-Access2) # set in-ports port7 port8
FGT-HQ (FSW-Access2) # set out-ports port12
FGT-HQ (FSW-Access2) # end
FGT-HQ (traffic-sniffer) # end
```

How the targets match:

| Target | What is mirrored |
|--------|------------------|
| `target-mac <mac>` | Traffic sent **from** that source MAC |
| `target-ip <ip>` | Traffic sent **from** that source IP |
| `target-port` → `in-ports` | Traffic sent **to** (received on) those ports |
| `target-port` → `out-ports` | Traffic sent **from** (transmitted out of) those ports |

Traffic matching any configured target is captured. To look at it, open **Network > Diagnostics > Packet Capture** on the FortiGate, capture on the **rspan** VLAN interface and download the result as a PCAP if you want Wireshark. The rspan interface comes from the VLAN templates: its default template address is `10.255.12.1/24` in the switch-controller reserved network.

### The automatic sniffer policer

Mirrored copies could easily flood the FortiLink uplink. When RSPAN or ERSPAN is used, the switch controller creates a traffic policy named **`sniffer`** (`guaranteed-bandwidth 50000`, `cos-queue 0`) and applies it to the rspan interface with `set switch-controller-traffic-policy "sniffer"`. Whether the policer is supported depends on the switch model (feature matrix).

> **Exam tip:** If a mirror "works but drops packets" on a busy port, think about the sniffer policer and the uplink capacity before blaming the analyzer.

## ERSPAN: mirrored traffic to an IP collector

ERSPAN wraps each copy in **Ethernet + IPv4 + GRE** headers and sends it to a collector IP address, so the analyzer can sit anywhere the switch can route to.

```text
FGT-HQ # config switch-controller traffic-sniffer
FGT-HQ (traffic-sniffer) # set mode erspan-auto
FGT-HQ (traffic-sniffer) # set erspan-ip 10.10.99.30
FGT-HQ (traffic-sniffer) # config target-port
FGT-HQ (target-port) # edit FSW-Access1
FGT-HQ (FSW-Access1) # set in-ports port3
FGT-HQ (FSW-Access1) # end
FGT-HQ (traffic-sniffer) # end
```

Rules that cause most ERSPAN tickets:

- The collector must answer **IPv4 ping** from the FortiSwitch. Managed switches reach other subnets through the FortiGate, so a **firewall policy** from the FortiLink side to the collector may be needed.
- If `erspan-ip` is not set, nothing is mirrored.
- Only one ERSPAN session is possible, and ERSPAN can't run together with SPAN or RSPAN.
- In FortiLink mode the switch chooses the destination port (often the ISL toward the FortiGate). `diagnose switch-controller switch-info mirror status <switch>` shows the session and the port it picked. Avoid using ISL member ports as mirror sources: they can clash with that automatically chosen destination.

## Standalone FortiSwitchOS mirroring

On a standalone switch you configure `config switch mirror` directly. All models support SPAN; RSPAN and ERSPAN depend on the model.

| Mode | Key settings | Notes |
|------|--------------|-------|
| `SPAN` | `dst`, `src-ingress`, `src-egress`, `switching-packet` | Local copy, no encapsulation |
| `RSPAN` | `dst`, `encap-vlan-id`, `encap-vlan-tpid` (default 0x8100), `encap-vlan-priority` | Copy tagged into a VLAN; destination port can't be in a trunk |
| `ERSPAN-auto` | `erspan-collector-ip` (+ TTL, ToS, GRE protocol) | Headers built automatically; you **can't** choose a destination interface |
| `ERSPAN-manual` | `dst`, `erspan-collector-ip`, `encap-ipv4-src`, `encap-mac-src`, `encap-mac-dst` (next hop) | You build the L2/L3 headers yourself |

Other FortiSwitchOS points: only one **active egress** mirror session is allowed; RSPAN traffic crossing other switches looks like unknown unicast/multicast/broadcast and is **not exempt from storm control**; `config switch global` → `set mirror-qos <0-7>` sets the priority of mirrored packets. You can also mirror with an ACL policy, which lets you mirror per VLAN or per match condition.

## The FortiOS one-arm sniffer (IDS on switch traffic)

Starting in FortiOS 7.4.1 with FortiSwitchOS 7.4.1, the FortiGate can inspect mirrored FortiSwitch traffic with its security profiles. It is an **IDS**: matches against the profiles are logged, but the sniffer never blocks or alters the real traffic, which keeps flowing through the switch untouched.

1. Mirror the source port in RSPAN or ERSPAN mode (`config switch-controller traffic-sniffer`, `config target-port`, `set in-ports`).
2. Enable the sniffer on the mirroring VLAN interface: `set ips-sniffer-mode enable`. This turns on `switch-controller-access-vlan` and `switch-controller-rspan-mode` and sets `switch-controller-traffic-policy sniffer` by default.
3. Create a `config firewall sniffer` entry on that interface. Every profile is **disabled by default**: enable each one you want (`av-profile-status`, `webfilter-profile-status`, `application-list-status`, `ips-sensor-status`, `file-filter-profile-status`) and select the profile, for example `sniffer-profile`.
4. Generate traffic and read the logs in **Log & Report > Sniffer Traffic** or with `execute log display`.

A sniffer log is a traffic log with `subtype="sniffer"` and `policytype="sniffer"`, and the source and destination interface are both the mirroring interface (for example `srcintf="rspan"` and `dstintf="rspan"`).

> **Real world:** Scanning is done by the CPU, so a one-arm sniffer can raise CPU use and miss packets in bursts. Low CPU does not prove that nothing was lost: drops can happen in the mirror path or in the FortiGate kernel buffer.

## Lab it yourself

There is no FortiSwitch VM, so the switch side needs real hardware (**physical FortiSwitch required**). On the FortiGate-VM permanent trial you can still:

1. Enable the switch controller and open `config switch-controller traffic-sniffer`. Use `?` to list the modes and target tables.
2. Look at `config switch-controller traffic-policy` and check whether the `sniffer` policy appears on your build before any switch is authorized.
3. Open `config firewall sniffer` and list which profile switches exist (`?`).

Confirm on the trial that the switch-controller menus appear before planning further steps.

## Key takeaways

- Same-VLAN traffic between switch ports never reaches the FortiGate; mirror it on the switch.
- Port-based mirroring: `config mirror` under the managed switch; `status` and `dst` are required; `switching-packet` keeps the destination usable.
- RSPAN carries copies in VLAN 4092 to the FortiGate; capture them on the **rspan** interface. ERSPAN uses Ethernet/IPv4/GRE to a pingable collector IP.
- Targets: `target-mac`/`target-ip` match the source; `in-ports` = traffic to the port, `out-ports` = traffic from the port.
- The switch controller adds the `sniffer` policer to RSPAN/ERSPAN traffic.
- Only one ERSPAN session; ERSPAN can't run with SPAN or RSPAN.
- The one-arm sniffer is IDS-only: `ips-sniffer-mode enable` + `config firewall sniffer`; profiles start disabled; logs under Sniffer Traffic.
