## Three ways to run a FortiSwitch

A FortiSwitch always runs FortiSwitchOS, but *who owns the configuration* depends on the management mode. Get this straight first, because many exam distractors put a correct command on the wrong device.

| Mode | Who configures the switch | Typical CLI you type |
|---|---|---|
| **FortiLink (managed)** | The FortiGate switch controller. The switch is an extension of the FortiGate's ports. | FortiOS: `config switch-controller managed-switch`, `edit <serial>`, `config ports` |
| **Standalone** | The switch itself, through its own GUI or CLI. | FortiSwitchOS: `config switch interface`, `config switch vlan`, `config switch physical-port` |
| **Cloud** | FortiEdge Cloud (called FortiLAN Cloud in the 7.6.1 guides), a hosted management service. | Mostly the cloud portal |

FortiSwitch Manager is a fourth manager type you will see in the zero-touch text: an on-premises controller for large switch estates without a FortiGate doing the switching control.

In FortiLink mode the FortiGate is the source of truth. If you log in to a managed switch and change something locally, the FortiGate does not know about it, and the change can be lost the next time the switch restarts and resynchronizes. Configure managed switches from the FortiGate unless a procedure explicitly says to touch the switch (MCLAG `auto-isl-port-group` is one such exception, covered in the MCLAG lesson).

> **Real world:** Coming from Cisco, think of FortiLink mode as closer to a controller-based campus than to a stack of IOS switches. There is no "write mem on the access switch" step: you save on the FortiGate and the controller pushes the switch configuration over FortiLink.

A managed FortiSwitch accepts administrative access only on the default HTTPS port, **443**. You can still reach the switch CLI from the FortiGate GUI (Diagnostics and Tools > Connect to CLI) when you need read-only `get`/`diagnose` output.

## Zero-touch management

Starting with **FortiSwitchOS 7.2.0 with FortiOS 7.2.0**, a factory-default FortiSwitch is built to find a manager on its own. Out of the box:

- every port is enabled for FortiLink auto-discovery,
- FortiLAN Cloud (FortiEdge Cloud) access is enabled,
- FortiLink CAPWAP discovery is enabled,
- all ports and the internal interface sit in VLAN 1, and the `mgmt` and `internal` interfaces use DHCP,
- auto topology (`config switch auto-network`) is on. When the switch detects a layer-2 FortiLink network it applies MSTP instances 0 and 15 and moves the internal interface to native VLAN 4094.

The switch connects to whichever manager is available — a FortiGate, FortiEdge Cloud or FortiSwitch Manager — but **only one manager is used at a time**. FortiSwitchOS doesn't stop you from enabling several, yet a switch generally can't be authorized by more than one. The zero-touch page also says the switch does not need its configuration backed up and does not need a restart to become managed.

Two practical knobs from the same page:

```text
FSW-Access1 # config switch auto-network
FSW-Access1 (auto-network) # set status disable
FSW-Access1 (auto-network) # end
```

disables auto topology on a switch you want to keep standalone, and `set defaultgw disable` under `config system interface` on the interface you don't use for management stops two DHCP-learned default routes from fighting (FortiSwitchOS may otherwise install both as ECMP).

> **Watch out:** For a switch that was already configured, Fortinet recommends `execute factoryreset` before moving it to 7.2.0+ zero-touch management. A leftover standalone configuration is a classic reason for a switch that never comes online or shows a configuration synchronization error.

## Turning on the switch controller

On many FortiGate models the feature is already visible. If not:

- GUI: **System > Feature Visibility > Switch Controller**, then the **WiFi & Switch Controller** menu appears.
- CLI:

```text
FGT-HQ # config system global
FGT-HQ (global) # set switch-controller enable
FGT-HQ (global) # end
```

## The FortiLink interface

The FortiLink interface is the FortiGate interface that carries both management (CAPWAP) and data traffic to the switches. Facts to know cold:

- It is created automatically as an **802.3ad aggregate** named `fortilink`. On FortiGate models that don't support aggregates, it is a **hardware switch** instead. Fortinet recommends keeping the default type.
- FortiLink can be enabled on any Ethernet port except the **HA** and **MGMT** ports, and FortiLink is **not supported in transparent mode**.
- You can also enable FortiLink on a single physical port or a software switch with `set fortilink enable` (then delete the unused default interface).
- Authorization is automatic only if **Automatically authorize devices** is ticked, which is `set auto-auth-extension-device enable` (CLI default: `disable`).

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "fortilink"
FGT-HQ (fortilink) # set ip 10.255.1.1 255.255.255.0
FGT-HQ (fortilink) # set member "port9" "port10"
FGT-HQ (fortilink) # set auto-auth-extension-device enable
FGT-HQ (fortilink) # set fortilink-neighbor-detect lldp
FGT-HQ (fortilink) # set lldp-reception enable
FGT-HQ (fortilink) # set lldp-transmission enable
FGT-HQ (fortilink) # next
FGT-HQ (interface) # end
```

### FortiLink split interface

`fortilink-split-interface` is **enabled by default**. It exists for one specific case: a FortiLink aggregate with **exactly two member ports, each cabled to a different FortiSwitch**. Because two independent switches can't form one LACP bundle, the FortiGate keeps only **one link active** and the other in standby.

- It **must be enabled before** you turn the two switches into an MCLAG pair, and once the MCLAG ICL is up you **disable** it so both links are active in one LACP bundle.
- If every member of the aggregate goes to the *same* switch, disable it — there is nothing to split.
- With neighbor detection `fortilink`, the standby link is down; with `lldp`, the standby link is up but inactive in LACP.

### Neighbor detection

`set fortilink-neighbor-detect {fortilink | lldp}`. **Starting in FortiOS 7.6.1 the default is `lldp`** (earlier releases used the proprietary FortiLink method). With LLDP, `lldp-reception` and `lldp-transmission` must be enabled on the FortiLink interface. LLDP neighbor detection is also required when you put aggregates into a FortiLink-enabled software switch.

### Auto-discovery and ISLs

From FortiSwitchOS 7.2.0 every port is a FortiLink auto-discovery port by default (older releases used model-specific port ranges — `show switch interface` on the switch lists them). Once a switch is discovered, every port on it is FortiLink-capable, so a second switch plugged into it forms an **inter-switch link (ISL)** automatically and is discovered through the first switch. When you want a fixed topology — FortiLink over layer 2 or layer 3, or simply locking things down — use static ISL trunks (`set static-isl enable` under `config switch trunk` on the switch) or **Lockdown ISL** in the FortiLink Interface page.

## Settings that only work before the first switch is authorized

### Management VLAN and reserved network

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "fortilink"
FGT-HQ (fortilink) # set switch-controller-mgmt-vlan 4094
FGT-HQ (fortilink) # end
FGT-HQ # config system global
FGT-HQ (global) # set switch-controller-reserved-network 10.255.0.0 255.255.0.0
FGT-HQ (global) # end
```

The management VLAN defaults to **4094** (range 1–4094) and is set per FortiLink interface. The reserved network defaults to **10.255.0.0/16**; the switch controller carves /24s out of it for automatically addressed VLAN interfaces.

### VLAN interface templates

`config switch-controller initial-config template` defines templates (`vlanid`, `ip`, `allowaccess`, `auto-ip`, `dhcp-server`), and `config switch-controller initial-config vlans` maps them to seven roles: `default-vlan`, `quarantine`, `rspan`, `voice`, `video`, `nac` and `nac-segment`. They are applied to the VLAN interfaces the FortiGate creates when it discovers new switches, and **you can only create them before the FortiGate has authorized any switch**.

| Role | Default IP in the 7.6.1 template table |
|---|---|
| quarantine | 10.255.11.1/24 |
| rspan | 10.255.12.1/24 |
| nac-segment | 10.255.13.1/24 |
| default-vlan, voice, video, nac | no IP listed |

`auto-ip enable` lets the controller pick an unused /24 from the reserved network (you can only set `ip` when `auto-ip` is disabled). `dhcp-server enable` creates a DHCP server on the VLAN interface. In the root VDOM the interface takes the template name; in other VDOMs the name is the template name plus the SNMP index (for example `quarantine.29`).

> **Exam tip:** "Only before any FortiSwitch is authorized" applies to the VLAN interface templates. If a question says switches are already managed and asks why a new template wasn't applied, that is the reason.

## Lab it yourself

There is no FortiSwitch VM to lab against — to the owner's knowledge Fortinet offers no free FortiSwitch VM trial, and none appears in the FortiSwitch 7.6 document library — so everything switch-side here is exhibit reading. The free **FortiGate-VM permanent trial** (FortiOS 7.6.x, 1 vCPU / 2 GB, maximum 3 interfaces) can still show the controller side:

1. `config system global` → `set switch-controller enable`; check that **WiFi & Switch Controller** appears (confirm this on your trial build).
2. Enable `set fortilink enable` on a spare port (remember the 3-interface cap), set an IP from 10.255.1.0/24 and look at the defaults with `get` — `fortilink-split-interface`, `fortilink-neighbor-detect`, `switch-controller-mgmt-vlan`, `auto-auth-extension-device`.
3. Browse `config switch-controller initial-config template` and `initial-config vlans` before any switch exists.
4. Run `execute switch-controller get-conn-status`: it prints the header and an empty table.

## Key takeaways

- FortiLink mode = configure from the FortiGate; local edits on a managed switch are unknown to the FortiGate and can be lost on restart. Admin access on a managed switch is HTTPS 443 only.
- Zero-touch (FortiSwitchOS 7.2.0 + FortiOS 7.2.0): the switch finds a FortiGate, FortiEdge/FortiLAN Cloud or FortiSwitch Manager, one manager at a time.
- Enable the controller with `set switch-controller enable`; the FortiLink interface is an aggregate by default (hardware switch where aggregates aren't supported), not on HA/MGMT ports, not in transparent mode.
- Split interface: on by default, two members to two switches, one active link; required before MCLAG, disabled after the ICL forms.
- FortiOS 7.6.1 uses LLDP neighbor detection by default; enable LLDP reception and transmission on the FortiLink interface.
- Management VLAN 4094, reserved network 10.255.0.0/16; VLAN interface templates only before the first authorization.
