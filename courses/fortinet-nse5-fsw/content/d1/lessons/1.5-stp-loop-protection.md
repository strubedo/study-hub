## Spanning tree on FortiSwitch: MSTP underneath

FortiSwitch runs **MSTP** (Fortinet's FortiSwitchOS guide calls it IEEE 802.1s; the FortiLink guide calls it 802.1Q — the standard was folded in, both are fine). MSTP is built on RSTP, so convergence is rapid, and it is backward-compatible with STP and RSTP neighbours. FortiSwitch can also interoperate with Cisco-style **Rapid PVST+**.

MSTP vocabulary you need:

- **Region** — switches with the same **region name**, **revision number** and **VLAN-to-instance mapping**. A region looks like one bridge to the outside.
- **IST (instance 0)** — the internal spanning tree; all VLANs belong to it until mapped elsewhere, and it is the **only instance that sends BPDUs** (other instances ride as M-records inside them). Timers are therefore common to all instances.
- **CST/CIST** — the tree that connects regions and non-MST bridges.
- **Hop count** — inside a region BPDUs age by `max-hops`, not message age.
- FortiSwitch supports **15 MST instances** in a region. Never map one VLAN to two instances.
- Port roles: root, designated, alternate, backup — same meanings as RSTP.

## FortiLink defaults that matter

- STP is **enabled by default on the non-FortiLink ports** of managed switches.
- **STP is not supported between a FortiGate and a FortiSwitch in FortiLink mode.** In switch STP output, the FortiLink port (shown as `__FoRtI1LiNk0__`) has STP status `DISABLED`. Never build a Layer 2 loop with the FortiGate in the path.
- From the FortiOS 7.6.1 CLI Reference, managed-switch port defaults: `stp-state enabled`, `edge-port enable`, `stp-root-guard disabled`, `stp-bpdu-guard disabled` (timeout 5 min), `loop-guard disabled` (timeout 45 min), `rpvst-port disabled`.
- Changing the `auto-stp-priority` setting makes FortiLink go down temporarily (FortiLink Guide note) — plan it in a window.

## Global STP settings and per-switch override

```text
FGT-HQ # config switch-controller stp-settings
FGT-HQ (stp-settings) # set name "HQ-REGION"
FGT-HQ (stp-settings) # set revision 1
FGT-HQ (stp-settings) # set hello-time 2
FGT-HQ (stp-settings) # set forward-time 15
FGT-HQ (stp-settings) # set max-age 20
FGT-HQ (stp-settings) # set max-hops 20
FGT-HQ (stp-settings) # end
```

| Setting | Range | Default |
|---|---|---|
| `hello-time` | 1–10 s | 2 |
| `forward-time` | 4–30 s | 15 |
| `max-age` | 6–40 s | 20 |
| `max-hops` | 1–40 | 20 |
| `revision` | 0–65535 | 0 |

These apply to **all** managed switches. To give one switch its own values: `config switch-controller managed-switch` → `edit <sn>` → `config stp-settings` → `set local-override enable`, then set the values there.

## MSTP instances and priorities

```text
FGT-HQ # config switch-controller stp-instance
FGT-HQ (stp-instance) # edit "1"
FGT-HQ (1) # config vlan-range "vlan10-data" "vlan20-voice"
FGT-HQ (1) # end
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit "S524DF4K15000104"
FGT-HQ (S524DF4K15000104) # config stp-instance
FGT-HQ (stp-instance) # edit "1"
FGT-HQ (1) # set priority 4096
FGT-HQ (1) # end
FGT-HQ (S524DF4K15000104) # end
```

Instances (and their VLAN ranges, by FortiLink VLAN name) are global; **bridge priority is per switch per instance**, in steps of **4096** from 0 to 61440 (default **32768**). Lowest bridge ID wins root. Per-port cost and port priority (0–224 in steps of 32, default 128) exist on FortiSwitchOS under `config switch stp instance` → `config stp-port`.

Check from the FortiGate with `diagnose switch-controller switch-info stp <serial> <instance>`, or on the switch with `diagnose stp instance list`, `diagnose stp vlan list`, `get switch stp settings` and `get switch stp instance`.

## Edge ports, BPDU guard and root guard

| Feature | FortiLink CLI (per port) | What it does |
|---|---|---|
| Edge port | `set edge-port enable` | Port moves straight to forwarding (Cisco PortFast). Default enabled on managed-switch ports |
| BPDU guard | `set stp-bpdu-guard enabled`, `set stp-bpdu-guard-timeout <0-120>` | On an **edge port**, any received BPDU shuts the port for the timeout (default **5 min**); BPDUs are not forwarded |
| Root guard | `set stp-root-guard enabled` | **Superior BPDUs are ignored/dropped**, so the port can never become the path to root |

**BPDU guard prerequisites:** the port must be an **edge port** and **STP must be enabled** on it (on a standalone switch, STP must also be enabled globally). After a BPDU-guard shutdown, the port recovers by itself when the timeout expires (unlike Cisco's default err-disable, which waits for manual action or errdisable recovery). Reset it early with `execute switch-controller switch-action bpdu-guard reset <sn> <port>` (FortiGate) or `execute bpdu-guard reset <port>` (FortiSwitchOS). Check state with `diagnose switch-controller switch-info bpdu-guard-status <sn>`.

**Root guard rules:** enable it on ports that must never lead to the root (for example access-layer downlinks to third-party switches), **never on the root port**, and STP must be enabled.

> **Watch out:** the FortiLink Guide 7.6.1 example uses `set stp-bpdu-guard-time`, but the FortiOS 7.6.1 CLI Reference lists the managed-switch port attribute as `stp-bpdu-guard-timeout` (0–120 min, default 5), the same spelling FortiSwitchOS uses. Use `?` on your build.

## Fortinet loop guard vs STP loop protection

Two different features with confusingly similar names — and a third name collision with Cisco:

| | Fortinet **loop guard** | **STP loop protection** |
|---|---|---|
| CLI | `set loop-guard enabled`, `set loop-guard-timeout <0-120>` (FortiGate port or FortiSwitchOS interface) | `set stp-loop-protection enabled` (FortiSwitchOS interface) |
| Mechanism | Port periodically sends **loop guard data packets (LGDP)**; if the port receives its own packet back, there is a loop **downstream** | A blocking (alternate/backup) port that **stops receiving BPDUs** stays blocking instead of becoming designated |
| Action | Port taken out of service for `loop-guard-timeout` (default **45 min**; **0 = manual reset**) | Port kept in blocking state |
| Default | Disabled on all ports | Disabled on all ports |
| Cisco analogue | Loopback/keepalive-style loop detection on edge ports | **Cisco Loop Guard** |

FortiSwitchOS can also trigger loop guard on a high rate of MAC moves (`loop-guard-mac-move-threshold`, 0 = off). Reset a tripped port with `execute switch-controller switch-action loop-guard reset <sn> <port>` or, on the switch, `execute loop-guard reset <port>`; view with `diagnose switch-controller switch-info loop-guard <sn>`.

Use loop guard on edge ports facing unmanaged switches or where users might cable a loop (for example through a cheap desktop switch that eats BPDUs).

## Interoperating with Rapid PVST+

Enable `set rpvst-port enabled` on the boundary port facing the RPVST+ domain (disabled by default). The VLANs used in the RPVST+ domain must also be configured on the FortiSwitch side. Two cases:

| CIST root is in… | Boundary FortiSwitch behaviour | Rule you must follow |
|---|---|---|
| The **MSTP region** | Copies instance 0 information into **one BPDU per VLAN** toward the RPVST+ domain | In the RPVST+ domain, VLANs other than VLAN 1 must have bridge priorities **worse (numerically higher)** than the CIST root |
| The **RPVST+ domain** | Uses **only VLAN 1** BPDUs; other VLANs' BPDUs are consistency checks only | In the RPVST+ domain, the root priority of VLANs other than 1 must be **better (numerically lower)** than VLAN 1's |

Breaking either rule puts the port into **Discarding** and flags it **`IC`** (inconsistent) in `diagnose stp instance list`; an **`MV`** flag means the RPVST+ VLANs are not all within the port's VLAN range. `diagnose stp rapid-pvst-port list` gives the reason; from the FortiGate use `diagnose switch-controller switch-info rpvst <sn> <port>`.

> **Real world:** this is the same "PVST simulation" logic Cisco MST uses at a PVST+ boundary. The simplest safe design is to keep the CIST root inside the MSTP region with a clearly better priority.

## Key takeaways

- FortiSwitch runs MSTP (RSTP-based), up to 15 instances per region; region = same name, revision and VLAN mapping.
- STP is on by default on non-FortiLink ports and not supported between FortiGate and FortiSwitch.
- Global settings in `switch-controller stp-settings`; per-switch values need `local-override enable`.
- Bridge priority is per switch per instance, multiples of 4096, default 32768.
- BPDU guard needs edge port + STP; shuts the port for 5 minutes by default.
- Root guard drops superior BPDUs; never enable it on the root port.
- Fortinet loop guard detects downstream loops with LGDP (default timeout 45 min); STP loop protection keeps a BPDU-starved blocking port blocked.
- RPVST+ interop: `rpvst-port enabled`; priority rules depend on where the CIST root is; violations show `IC` and Discarding.
