## What "stack" means in FortiLink

Fortinet calls the set of FortiSwitch units behind one FortiLink interface a **stack**. It is not a Cisco StackWise-style single control plane: each switch keeps its own CPU and configuration, and the FortiGate manages each one separately. All managed switches act as one Layer 2 domain, and the active FortiLink carries both data and management traffic. Building the stack is mostly about which ports become:

| Link type | Between | Purpose |
|---|---|---|
| **FortiLink** | FortiGate ↔ first-tier switch(es) | Management and data uplink |
| **ISL** (inter-switch link) | Managed switch ↔ managed switch | Extends the stack; formed automatically |
| **ICL** (inter-chassis link) | The two switches of an MCLAG peer group | Synchronises the MCLAG peers |
| **MCLAG trunk** | Downstream device ↔ both MCLAG peers | Dual-homed LAG with all links active |

## Auto-discovery and auto-ISL

- Starting with FortiSwitchOS 7.2.0, **all ports are enabled for FortiLink auto-discovery by default** (older models/releases had a fixed set, typically the last few ports). Any port can be used for FortiLink if configured manually.
- Once a switch is discovered and in FortiLink mode, plug another FortiSwitch into **any** of its ports: the **ISL forms automatically** (a trunk built through LLDP auto-ISL negotiation), and the new switch is discovered by the FortiGate.
- Auto-ISL is controlled by the LLDP profile (`auto-isl`, `auto-isl-hello-timer` 3 s, `auto-isl-receive-timeout` 9 s, `auto-isl-port-group`). The `default-auto-isl` profile always has it enabled.

### Static ISLs and "Lockdown ISL"

You may want an ISL that never changes — for FortiLink over a point-to-point Layer 2 or Layer 3 network, or simply to lock the topology after discovery so an automatically created ISL or ICL is not accidentally deleted:

```text
FSW-Core1 # config switch trunk
FSW-Core1 (trunk) # edit "isl-to-acc1"
FSW-Core1 (isl-to-acc1) # set static-isl enable
FSW-Core1 (isl-to-acc1) # set static-isl-auto-vlan enable
FSW-Core1 (isl-to-acc1) # end
```

In the GUI: **WiFi & Switch Controller > FortiLink Interface > Lockdown ISL**. Locking down ISLs and ICLs is also one of the Security Rating recommendations.

> **Watch out:** `set auto-isl` under `config switch trunk` marks a trunk as managed by the system. Do not set it on trunks you manage yourself (for example on a standalone switch without auto-topology).

## The FortiLink split interface

The default FortiLink interface is an 802.3ad aggregate. When its members go to **two different switches** that are not (yet) an MCLAG pair, a normal LACP bundle cannot form across them. The **FortiLink split interface** solves that:

- **Enabled by default** (`set fortilink-split-interface enable` on the FortiLink interface).
- The aggregate must contain **exactly two** physical ports, one to each switch.
- **Only one link is active**; the other is standby.
- The aggregate's LACP mode must be **active** (`set lacp-mode active`).
- With `fortilink-neighbor-detect fortilink`, the standby link is **down**. With `lldp` (the FortiOS 7.6.1 default), the standby link is **up, with LACP inactive**.
- If all aggregate members go to the **same** switch, you must **disable** the split interface.

The classic use: one FortiGate (or an HA pair) dual-connected to the two core switches, with the last switch of a ring acting as standby FortiLink path.

## MCLAG peer groups and the ICL

A multichassis LAG (MCLAG) groups **two** FortiSwitch units so they appear as one switch to LAG partners. Either switch can fail without interrupting the MCLAG, and all links forward — no STP-blocked uplinks. If you know Cisco vPC, the ICL plays the role of the vPC peer-link.

### Requirements (memorise these)

- **Maximum two FortiSwitch units per MCLAG peer group.**
- Both peers should be the **same hardware model and same software version**; mismatches might work but are unsupported.
- Use **at least two links for the ICL** (redundancy).
- Connect downstream devices to **both** peers with an 802.3ad aggregate.
- The MCLAG trunk **name must be the same** on both peers; member port numbers may differ.
- `mclag-stp-aware` must be enabled globally and STP enabled on all ICL trunks — both are the default.
- `min-bundle`/`max-bundle` on an MCLAG apply only to the **local** aggregate.
- For IGMP snooping with MCLAG: `mclag-igmpsnooping-aware` enabled (default), flood settings **disabled** on ISL and FortiLink trunks but **enabled** on ICL trunks, and IGMP proxy enabled.

### From split interface to FortiLink MCLAG (tier 1)

Order matters, and the FortiLink guide states it plainly: the split interface **must be enabled before MCLAG is enabled**; once the MCLAG exists you **disable** it so **both** FortiLink links become active.

1. Make sure the split interface is enabled and both core switches are managed.
2. On both core switches, assign the LLDP profile **`default-auto-mclag-icl`** to the ports that should form the ICL (from the FortiGate: `config switch-controller managed-switch` → `edit <sn>` → `config ports` → `edit port49` → `set lldp-profile default-auto-mclag-icl`).
3. On the FortiGate: `set fortilink-split-interface disable` on the FortiLink aggregate.
4. Make sure `set lacp-mode active` on the aggregate.
5. Verify the LAG: `diagnose netlink aggregate name fortilink`; verify the ICL: `diagnose switch-controller switch-info mclag icl`.

GUI alternative (FortiOS 7.2.4+): in the **Managed FortiSwitches** topology view, hover the ISL between the pair and click **Create MC-LAG pair**; Security Rating lists which pairs can form a tier-1 MCLAG.

> **Exam tip:** if you later disable the MCLAG ICL, re-enable `fortilink-split-interface`.

After the core peer group exists, downstream access switches connected to both cores get **MCLAG trunks automatically**. For tier-2 and tier-3 MCLAGs, `auto-isl-port-group` entries are configured **directly on the upper-tier FortiSwitch units** (or pushed with a custom command) so ports to the two lower-tier peers are grouped into one MCLAG.

### On a standalone FortiSwitch

```text
FSW-Core1 # config switch trunk
FSW-Core1 (trunk) # edit "icl"
FSW-Core1 (icl) # set mode lacp-active
FSW-Core1 (icl) # set mclag-icl enable
FSW-Core1 (icl) # set members "port51" "port52"
FSW-Core1 (icl) # next
FSW-Core1 (trunk) # edit "srv1-mclag"
FSW-Core1 (srv1-mclag) # set mode lacp-active
FSW-Core1 (srv1-mclag) # set mclag enable
FSW-Core1 (srv1-mclag) # set members "port10"
FSW-Core1 (srv1-mclag) # end
```

Checks on the switch: `diagnose switch mclag icl`, `diagnose switch mclag list`, `diagnose switch mclag peer-consistency-check`.

### Split-brain detection

A split brain happens when the ICL fails while both peers keep forwarding. With detection enabled (disabled by default), one peer goes **dormant** until the ICL recovers:

| Setting (`config switch global`) | Meaning |
|---|---|
| `mclag-split-brain-detect enable` | Required on **both** peers |
| `mclag-split-brain-priority` 0–100, default 50 | **Lowest** value goes dormant; on a tie, the switch with the **lowest MAC** goes dormant |
| `mclag-split-brain-all-ports-down` | Dormant switch shuts all ports (ICL ports untouched); disabled by default |

Detection also needs `set mclag enable` on the dual-homed trunk of the downstream switch. Only one split-brain failure in a system is supported at a time.

## Disabling stacking

The FortiLink Guide defines stacking as the FortiGate using its active FortiLink interface to manage all of the subtending FortiSwitch units, and documents this command (run on the FortiGate, against the FortiLink interface) to disable it:

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "fortilink"
FGT-HQ (fortilink) # set fortilink-stacking disable
FGT-HQ (fortilink) # end
```

> **Watch out:** `fortilink-stacking` appears in the FortiLink Guide 7.6.1 but is not listed on the `config system interface` page of the FortiOS 7.6.1 CLI Reference. Confirm it with `?` on your build before relying on it.

## Lab it yourself

The FortiGate-side settings (`fortilink-split-interface`, `lacp-mode`, `fortilink-neighbor-detect`, `fortilink-stacking`) can be explored on the FortiGate-VM trial by enabling FortiLink on a port or aggregate. ISL/ICL formation, MCLAG and split-brain behaviour need at least two physical FortiSwitch units; practise those from exhibits.

## Key takeaways

- ISLs form automatically between managed switches; static ISLs (`static-isl enable`) or Lockdown ISL freeze the topology.
- FortiLink split interface: default enabled, exactly two members to two switches, one active link, LACP active.
- Enable the split interface **before** MCLAG; disable it **after** to make both FortiLink links active.
- Form the ICL by assigning `default-auto-mclag-icl` to the ICL ports on both peers.
- MCLAG: max two peers, same model/firmware recommended, at least two ICL links, same trunk name on both peers.
- Split-brain detection is off by default; lowest priority (then lowest MAC) goes dormant.
- Stacking is disabled on the FortiGate's FortiLink interface (`set fortilink-stacking disable` in the FortiLink Guide).
