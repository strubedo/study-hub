## Basic port settings from the FortiGate

Every physical port of a managed switch appears under `config switch-controller managed-switch` → `edit <serial>` → `config ports`. The basics:

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit "S248EPTF18000102"
FGT-HQ (S248EPTF18000102) # config ports
FGT-HQ (ports) # edit "port7"
FGT-HQ (port7) # set description "Printer-2F"
FGT-HQ (port7) # set speed auto
FGT-HQ (port7) # set status up
FGT-HQ (port7) # end
FGT-HQ (S248EPTF18000102) # end
```

- `speed` defaults to `auto`; the available values depend on the port hardware (for example `10half` … `1000full`, `10000full`, `25000full`, `100000full`, `auto-module`).
- `status {up | down}` is the administrative state (like Cisco `shutdown` / `no shutdown`).
- To see what a port supports, use `diagnose switch-controller switch-info port-properties [<serial>] [<port>]`. Leave out the serial to see all switches, the port to see all ports.

```text
FGT-HQ # diagnose switch-controller switch-info port-properties S248EPTF18000102 port7
Vdom: root
Switch: S248EPTF18000102
Port: port7
        PoE           : 802.3af/at,30.0W
        Connector     : RJ45
        Speed         : 10Mhalf/10Mfull/100Mhalf/100Mfull/1Gauto/auto
```

On FortiSwitchOS the equivalents are under `config switch physical-port` (`set speed`, `set status`, `set description`, `set max-frame-size`). `10000full` is the normal 10G setting; `10000cr` (copper DAC) or `10000sr` (fibre optics) are alternatives if `10000full` does not work. The **auto-module** speed reads the transceiver and sets the port to the module's maximum advertised speed (1/10G ports only).

The GUI page **WiFi & Switch Controller > FortiSwitch Ports** shows, per port: status, trunk membership, access mode, enabled features, native and allowed VLANs, PoE status, device information, DHCP snooping status and **transceiver information**. The **Faceplates** view shows active ports, PoE ports, the FortiLink port, and the PoE power budget (used vs reserved).

## Power over Ethernet

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit "S248EPTF18000102"
FGT-HQ (S248EPTF18000102) # config ports
FGT-HQ (ports) # edit "port12"
FGT-HQ (port12) # set poe-status enable
FGT-HQ (port12) # set poe-port-priority critical-priority
FGT-HQ (port12) # end
FGT-HQ (S248EPTF18000102) # end
```

| Setting | Values | Notes |
|---|---|---|
| `poe-status` | enable / disable | Enabled by default on PoE ports |
| `poe-port-priority` | critical, high, medium, low (default **low**) | When power is short, power goes to critical first, then high, medium, low. Medium is only on some models |
| `poe-port-mode` | IEEE 802.3af or 802.3at | FortiOS 7.2.4 + FortiSwitchOS 7.2.3 and later |
| `poe-port-power` | normal, perpetual, perpetual-fast | Whether PoE keeps running through switch restarts (`normal` = not provided during a restart) |
| `poe-pre-standard-detection` | enable / disable | Detects pre-802.3af devices; factory default **disabled** since FortiOS 6.4.5. **Global** (per switch) on some models (FS-548D-FPOE, FS-524D-FPOE, FS-224D-POE, FS-124E-POE/FPOE, FS-148F-POE/FPOE), **per port** on the others |

Power-cycle a powered device (reboot a hung AP or phone) with **Reset PoE** on the FortiSwitch Ports page (right-click the port) or `execute switch-controller switch-action poe reset <serial> <port>` in the FortiOS 7.6.1 CLI Reference syntax. Check PoE with `diagnose switch-controller switch-info poe summary <serial>` or `poe detail <serial> <port>`; on the switch, `get switch poe inline`.

## Flap guard

A flapping port (rapid up/down) forces STP to keep recalculating and can hide a bad cable or an intrusion attempt. Flap guard counts link changes and **shuts the port** when the rate is exceeded.

| Setting | Range | Default |
|---|---|---|
| `flapguard` | enable / disable | **disabled** |
| `flap-rate` | 1–30 changes | **5** |
| `flap-duration` | 5–300 s | **30** — window in which changes are counted |
| `flap-timeout` | 0–120 minutes | **0 = no timeout** (port stays down until reset) |

So with defaults, five state changes within 30 seconds shut the port until an administrator resets it:

```text
FGT-HQ # execute switch-controller flapguard reset S248EPTF18000102 port7
FGT-HQ # diagnose switch-controller switch-info flapguard status S248EPTF18000102
```

On FortiSwitchOS: `config switch physical-port` → `set flapguard enabled`, reset with `execute flapguard reset <port>`, view with `diagnose flapguard status`. By default a reboot clears the triggered state; `config switch global` → `set flapguard-retain-trigger enable` keeps it. Some models (FS-1xxE, FS-2xxD/E, FS-4xxD/E) do not keep time across a reboot, so a triggered port clears once the switch finishes booting. Flap guard also works on switch ports that are LAG members.

## Split ports (phy-mode)

Models with 40G/100G QSFP ports can break one port into several lower-speed ports with a breakout cable. The split is configured **on the FortiSwitch** with `config switch phy-mode`, and **the switch must restart** for the port list to change:

```text
FSW-Core1 # config switch phy-mode
FSW-Core1 (phy-mode) # set port29-phy-mode 4x10G
FSW-Core1 (phy-mode) # end
This change will cause a ports to be added and removed, this will cause loss of configuration on removed ports. The system will have to reboot to apply this change.
Do you want to continue? (y/n)y
```

| `<port>-phy-mode` | Meaning |
|---|---|
| `single-port` | Use the port at full speed, unsplit |
| `4x25G` | 100G QSFP28 only: four 25G subports |
| `4x10G` | 40G or 100G QSFP: four 10G subports |
| `4x1G` | 40G or 100G QSFP: four 1G subports |
| `2x50G` | 100G QSFP only: two 50G subports |

Some models use `set port-configuration` for whole-group modes (for example `4x100G`, `6x40G`, `4x4x25G` on the FS-1048E). Use `set port-configuration ?` to see what your model offers. Subports are named with a dot: `port29.1` … `port29.4`.

In FortiLink mode: starting with FortiOS 7.2.0 / FortiSwitchOS 7.2.0 the FortiGate **automatically updates the port list** after the split and restart, and logs the change. Before 7.2.0 you had to delete the switch from the FortiGate, rediscover and reauthorize it. The FortiLink Guide notes that split ports are not configured for pre-configured FortiSwitch units. FortiSwitchOS 7.6.0 raised the software port limit from 64 to **128 ports** (130 with `internal` and `mgmt`), allowing more split ports.

## Forward error correction (FEC)

High-speed links use FEC to correct bit errors. Per port:

| `fec-state` | Use |
|---|---|
| `detect-by-module` | **Default** on FEC-capable ports: decide from the transceiver |
| `cl74` | Clause 74 FEC for **25G** ports |
| `cl91` | Clause 91 RS-FEC for **100G** ports |
| `disabled` | No FEC |

Both ends of a link must agree. Verify on the switch with `diagnose switch physical-ports list <port>`. (The FortiSwitchOS guide prints the 25G option's name inconsistently; the keyword `cl74` and its 25G use are consistent across the guides.)

## Transceivers and DMI

The **diagnostic monitoring interface (DMI)** reads a module's identity and live optical data. Per port on FortiSwitchOS: `config switch physical-port` → `set dmi-status {enable | disable | global}`.

```text
FGT-HQ # diagnose switch-controller switch-info modules summary S524DF4K15000104 port25
FGT-HQ # diagnose switch-controller switch-info modules status S524DF4K15000104 port25
FSW-Core1 # get switch modules detail port25
FSW-Core1 # get switch modules status port25
```

`detail` shows identity (identifier SFP/SFP+, transceiver type, vendor, part and serial number, manufacturing date). `status` shows live values: **temperature, voltage, laser bias current, TX power and RX power** (per lane on multi-lane optics), plus alarm and warning flags. `limits` shows the module's alarm and warning thresholds. A link that is down with very low RX power points at the far end or the fibre, not the local optic.

Fortinet publishes a **FortiSwitch compatible transceivers** list per release; use supported optics. Some special transceivers (for example the FN-TRAN-DSL VDSL module) can even be managed from the FortiGate on supported FortiGate models.

## Restricting frame types on 802.1Q ports

By default every port accepts both tagged and untagged frames. `discard-mode` changes that:

| `set discard-mode` | Effect |
|---|---|
| `none` (default) | Accept all frames |
| `all-tagged` | Drop tagged frames; only untagged frames enter |
| `all-untagged` | Drop untagged frames; only tagged frames enter |

Set it on a managed-switch port (`config switch-controller managed-switch` → `config ports` → `edit <port>`) or on FortiSwitchOS (`config switch interface`). Typical uses: `all-tagged` on a user access port so nobody can inject tagged frames into other VLANs (a VLAN-hopping control), and `all-untagged` on an uplink where every legitimate frame is tagged.

## Lab it yourself

On the FortiGate-VM trial you can only explore syntax. Without a discovered switch the `config switch-controller managed-switch` table is normally empty; FortiOS has a pre-provisioning option for switches, which may let you reach the `config ports` attributes with `?` — verify on your trial build. Everything else (PoE, flap guard, phy-mode, DMI) needs a physical FortiSwitch; read the exhibits in the question bank instead.

## Key takeaways

- Port speed defaults to `auto`; `status up/down` is the admin state; `port-properties` shows what a port supports.
- PoE priority: critical > high > medium > low (default low); pre-standard detection is disabled by default and global on some models.
- Flap guard is off by default; defaults are 5 changes in 30 s with no timeout (manual reset).
- Split ports are set with `config switch phy-mode` on the switch and require a restart; FortiOS 7.2.0+ updates the port list automatically.
- FEC: `detect-by-module` by default; `cl74` for 25G, `cl91` for 100G.
- DMI status shows temperature, voltage, bias, TX and RX power; `modules` diagnostics exist on both FortiGate and FortiSwitch.
- `discard-mode` `none` (default), `all-tagged` or `all-untagged` restricts the frames a port accepts.
