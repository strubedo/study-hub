## Why LLDP matters so much on FortiSwitch

On a Cisco campus, LLDP is optional and CDP does the voice-VLAN work. On FortiSwitch, LLDP is load-bearing:

- **Auto-ISL** between managed switches is negotiated with LLDP (the `default-auto-isl` profile).
- **FortiLink neighbor detection** uses LLDP by default from FortiOS 7.6.1.
- **LLDP-MED** tells phones and video endpoints which VLAN, 802.1p priority and DSCP to use.
- **Device detection**: LLDP data from devices such as FortiFone feeds FortiGate device detection and dynamic port policies.

## Global LLDP timers

The same three timers exist on both sides (`config switch-controller lldp-settings` on the FortiGate, `config switch lldp settings` on FortiSwitchOS):

| Setting | Range | Default | Meaning |
|---|---|---|---|
| `tx-interval` | 5–4095 s | 30 | How often LLDPDUs are sent |
| `tx-hold` | 1–16 | 4 | Multiplier: TTL = `tx-hold` × `tx-interval` (120 s by default) |
| `fast-start-interval` | 2–5 s (0 disables) | 2 | Interval for the first four LLDPDUs after link-up |

`management-interface` selects which interface address is advertised in LLDP (and CDP) PDUs. Check on a switch with `get switch lldp settings`.

> **Watch out:** a port whose LLDP profile has auto-ISL enabled transmits at the profile's `auto-isl-hello-timer` (default **3 s**) instead of `tx-interval`, but the TTL in the PDU is still `tx-hold` × `tx-interval`. In FortiLink mode, ports get auto-ISL profiles by default, so expect 3-second LLDP on managed switches.

## Per-port LLDP: status and profile

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit "S248EPTF18000101"
FGT-HQ (S248EPTF18000101) # config ports
FGT-HQ (ports) # edit "port12"
FGT-HQ (port12) # set lldp-status tx-rx
FGT-HQ (port12) # set lldp-profile "phones"
FGT-HQ (port12) # end
FGT-HQ (S248EPTF18000101) # end
```

`lldp-status` is `tx-rx` (default), `rx-only`, `tx-only` or `disable`. In the FortiOS 7.6.1 CLI Reference the default `lldp-profile` on a managed-switch port is `default-auto-isl`.

Built-in profiles you should recognise:

| Profile | Use |
|---|---|
| `default` | Created automatically on FortiSwitchOS; cannot be deleted. Its `get switch lldp profile` output shows MED TLVs inventory-management and network-policy |
| `default-auto-isl` | Auto-ISL always enabled (rejects attempts to disable it); used for switch-to-switch discovery |
| `default-auto-mclag-icl` | Assigned to the ports that should become an MCLAG ICL (lesson 1.3) |
| `fortivoice.fortilink` | Predefined FortiOS profile for FortiFone/voice ports |

## LLDP profile contents

`config switch-controller lldp-profile` (FortiGate) or `config switch lldp profile` (FortiSwitchOS) holds:

- `med-tlvs` — which LLDP-MED TLV groups to send: `inventory-management`, `network-policy`, `power-management`, `location-identification`.
- `802.1-tlvs port-vlan-id` — send the port's native VLAN.
- `802.3-tlvs` — `max-frame-size` and the PoE power-negotiation TLV.
- `auto-isl`, `auto-isl-hello-timer` (1–30 s, default 3), `auto-isl-receive-timeout` (3–90 s, default 9), `auto-isl-port-group` (0–9).
- `config med-network-policy` — one entry per application type.
- `config med-location-service` — `address-civic`, `coordinates`, `elin-number` (E911 location).
- `config custom-tlvs` — organisation-specific TLVs (`oui`, `subtype`, `information-string`).

## LLDP-MED network policies (the "voice VLAN")

The network-policy TLV tells an endpoint which VLAN, Layer 2 priority and DSCP to use. The list of policy types is **fixed** — you cannot add or delete entries, only enable and set them:

`voice`, `voice-signaling`, `guest-voice`, `guest-voice-signaling`, `softphone-voice`, `video-conferencing`, `streaming-video`, `video-signaling`

```text
FGT-HQ # config switch-controller lldp-profile
FGT-HQ (lldp-profile) # edit "phones"
FGT-HQ (phones) # set med-tlvs inventory-management network-policy
FGT-HQ (phones) # config med-network-policy
FGT-HQ (med-network-policy) # edit "voice"
FGT-HQ (voice) # set status enable
FGT-HQ (voice) # set vlan-intf "vlan20-voice"
FGT-HQ (voice) # set priority 5
FGT-HQ (voice) # set dscp 46
FGT-HQ (voice) # end
FGT-HQ (phones) # end
```

Two conditions must hold for a policy to be advertised:

1. `med-tlvs` includes **`network-policy`**, and the policy entry has `status enable`.
2. The advertised VLAN is actually usable on the port. On FortiSwitchOS, the profile's VLAN is cross-checked against the interface: it must be the native VLAN or an allowed VLAN for the TLV to be sent, and the TLV marks it **untagged** if it is the native VLAN or in the untagged list, otherwise **tagged**.

`priority` (0–7, 7 highest) and `dscp` (0–63) are what the phone should mark — pair them with a QoS policy that trusts those values (for example `voice-qos`). The FortiOS profile also has `assign-vlan enable` on network policies, used in the predefined `fortivoice.fortilink` profile.

> **Real world:** Cisco's `switchport voice vlan 20` both allows VLAN 20 tagged and advertises it via CDP/LLDP-MED. On FortiSwitch these are separate jobs: allow `vlan20-voice` on the port **and** advertise it in the LLDP profile.

Other LLDP facts worth knowing for the exam:

- Up to **16 LLDP neighbors per physical port**.
- FortiSwitch parses **CDP** and counts CDP neighbors toward that limit. CDP transmission is per port (`cdp-status`), disabled by default, and needs LLDP enabled globally.
- With 802.1X and LLDP on the same port, changing LLDP profile requires resetting the authentication sessions.
- Asset tag: `set switch-device-tag` on the managed switch (FortiGate) or `set asset-tag` in `config system global` (FortiSwitchOS); sent in the inventory TLV.

## Voice device detection and dynamic port policies

FortiSwitchOS parses LLDP from voice devices such as **FortiFone** and passes the information to the FortiGate for device detection. A **dynamic port policy** then matches the device (by device family, MAC, and other criteria) and applies three actions to the switch port:

| Action | Typical value |
|---|---|
| LLDP profile | `fortivoice.fortilink` |
| QoS policy | `voice-qos` |
| VLAN policy | e.g. a policy with native VLAN data and allowed/untagged VLANs including voice |

```text
FGT-HQ # config switch-controller dynamic-port-policy
FGT-HQ (dynamic-port-policy) # edit "phones-dpp"
FGT-HQ (phones-dpp) # set fortilink "fortilink"
FGT-HQ (phones-dpp) # config policy
FGT-HQ (policy) # edit "fortifone"
FGT-HQ (fortifone) # set family "FortiFone"
FGT-HQ (fortifone) # set lldp-profile "fortivoice.fortilink"
FGT-HQ (fortifone) # set qos-policy "voice-qos"
FGT-HQ (fortifone) # set vlan-policy "voice-vp"
FGT-HQ (fortifone) # end
FGT-HQ (phones-dpp) # end
```

Then on the port: `set access-mode dynamic` and `set port-policy "phones-dpp"`. When the phone's LLDP arrives, check the match with `diagnose switch-controller mac-device dynamic`, which lists the MAC, last-known switch and port, and the matched dynamic port policy. GUI: **WiFi & Switch Controller > FortiSwitch Port Policies**, then **Dynamic Port Policies**.

## Key takeaways

- LLDP timers: `tx-interval` 30 s, `tx-hold` 4 (TTL 120 s), `fast-start-interval` 2 s.
- Auto-ISL profiles send LLDP every `auto-isl-hello-timer` (3 s default) but keep the normal TTL.
- LLDP-MED network-policy types are fixed; enable one and include `network-policy` in `med-tlvs`.
- The advertised VLAN must be native or allowed on the port; native/untagged VLANs are advertised as untagged.
- `default` and `default-auto-isl` profiles exist automatically; `default-auto-mclag-icl` builds MCLAG ICLs.
- Voice device detection plus a dynamic port policy applies an LLDP profile, QoS policy and VLAN policy automatically.
- Up to 16 LLDP neighbors per port; CDP is parsed and transmission is off by default.
