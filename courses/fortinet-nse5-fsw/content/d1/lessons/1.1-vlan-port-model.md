## One port model, no access/trunk modes

If you come from Cisco IOS, the first thing to unlearn is the split between `switchport mode access` and `switchport mode trunk`. A FortiSwitch port has no mode. Every port, physical or trunk (LAG), carries the same three VLAN attributes, and the combination decides whether it behaves like an access port, a trunk, or something in between:

| Attribute | FortiSwitchOS CLI (`config switch interface`) | FortiGate CLI (`config switch-controller managed-switch` → `config ports`) | What it controls |
|---|---|---|---|
| Native VLAN | `set native-vlan <id>` | `set vlan <VLAN interface name>` | VLAN given to **untagged frames arriving** on the port; frames of this VLAN **leave untagged** |
| Allowed VLAN list | `set allowed-vlans <ids>` | `set allowed-vlans <names>` or `set allowed-vlans-all enable` | Tagged VLANs the port may **receive and transmit** |
| Untagged VLAN list | `set untagged-vlans <ids>` | `set untagged-vlans <names>` | VLANs that **leave the port without a tag** (egress only). Each must also be in the allowed list |

Note the different value types: on the switch itself you type VLAN **IDs**; from the FortiGate you reference FortiLink **VLAN interface names** (`vlan10-data`, `quarantine`, …), because in FortiLink mode a VLAN *is* a FortiGate interface.

> **Exam tip:** "Native VLAN" on FortiSwitch means "the port's default VLAN for untagged ingress". It is the equivalent of the Cisco *access VLAN* on an edge port and the Cisco *native VLAN* on a trunk at the same time.

## Frame processing, step by step

The switch normalises everything on ingress so that, internally, **every frame carries a VLAN tag**. Then it decides per egress port whether to keep or strip that tag.

**Ingress**

1. Untagged frame: tagged with the port's native VLAN and accepted. The allowed list is ignored for untagged frames.
2. Tagged frame: accepted only if the tag matches the native VLAN **or** a VLAN in the allowed list; otherwise dropped. The frame keeps its tag.

**Egress** (the frame is flooded or forwarded only to ports that can carry its VLAN)

1. Tag is the port's native VLAN, or is in the untagged list: tag stripped, frame sent untagged.
2. Tag is in the allowed list (and not in the untagged list): frame sent with its tag.
3. Otherwise: dropped.

Two consequences trip people up:

- A tagged frame whose tag equals the port's native VLAN is **accepted** (the hardware accepts a tagged or untagged match to a valid VLAN). Cisco does the same on an 802.1Q trunk native VLAN, but many engineers expect a drop.
- The untagged list lets a port send **several** VLANs untagged. Cisco has no direct equivalent; it is used, for example, for the quarantine VLAN on dynamically assigned ports and for MAC-based VLANs where the end host is not VLAN-aware.

### Worked example

```text
FGT-HQ # show switch-controller managed-switch S248EPTF18000101
config switch-controller managed-switch
    edit "S248EPTF18000101"
        set name "FSW-Access1"
        config ports
            edit "port5"
                set vlan "vlan10-data"
                set allowed-vlans "vlan20-voice"
                set untagged-vlans "vlan20-voice"
            next
            edit "port49"
                set vlan "vlan99-mgmt"
                set allowed-vlans "vlan10-data" "vlan20-voice" "vlan30-guest"
            next
        end
    next
end
```

- An untagged frame arriving on port5 joins `vlan10-data`. A frame tagged with VLAN 20 is accepted (allowed list); a frame tagged 30 is dropped.
- On egress from port5, both VLAN 10 (native) and VLAN 20 (untagged list) leave untagged.
- On port49, VLAN 99 traffic leaves untagged (native) and VLANs 10, 20 and 30 leave tagged.

## Creating FortiLink VLANs and assigning ports

In FortiLink mode, a VLAN is created on the FortiGate as a VLAN interface whose parent is the FortiLink interface. The FortiGate then pushes the VLAN to every managed switch.

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "vlan10-data"
FGT-HQ (vlan10-data) # set vdom "root"
FGT-HQ (vlan10-data) # set interface "fortilink"
FGT-HQ (vlan10-data) # set vlanid 10
FGT-HQ (vlan10-data) # set ip 10.10.10.1 255.255.255.0
FGT-HQ (vlan10-data) # set allowaccess ping
FGT-HQ (vlan10-data) # set role lan
FGT-HQ (vlan10-data) # end
```

GUI equivalents: **WiFi & Switch Controller > FortiSwitch VLANs** (create), and **WiFi & Switch Controller > FortiSwitch Ports** (click the Native VLAN or Allowed VLANs cell of a port). If you use the Security Rating feature, give FortiLink VLAN interfaces a role of LAN, WAN or DMZ before referencing them in policies; otherwise the "Interface Classification" check fails.

The VLAN interface is a normal FortiGate Layer 3 interface: it can run a DHCP server, appear in firewall policies and be referenced by SD-WAN or routing. That is why inter-VLAN traffic in FortiLink mode is routed by the FortiGate (lesson 1.4).

> **Watch out:** configure managed switches from the FortiGate. Changes made directly on a managed FortiSwitch are unknown to the FortiGate and are lost when the switch restarts.

## How many VLANs does "allowed-vlans-all" mean?

`set allowed-vlans-all enable` on a managed-switch port is interpreted according to `config switch-controller global` → `set vlan-all-mode`:

| `vlan-all-mode` | Meaning |
|---|---|
| `defined` (default) | All **user-defined** FortiLink VLANs |
| `all` | All possible VLAN IDs |

## Keeping ISL trunks lean: VLAN optimization and VLAN pruning

Inter-switch links (ISLs) are formed automatically between managed switches. Without help, the switch controller would allow every VLAN on them. Two related settings live under `config switch-controller global`:

| `set vlan-optimization` | Behaviour on auto-generated trunks (ISLs) |
|---|---|
| `configured` (default) | Only VLANs **created on the FortiLink interface** are allowed. This is what older releases called `set vlan-optimization enable`; the keyword changed in FortiOS 7.6.1 |
| `prune` | **VLAN pruning** (FortiOS 7.6.1 with FortiSwitchOS 7.6.1): only VLANs actually needed on or along the path between destinations are allowed |
| `none` | No optimization |

`vlan-all-mode all` cannot be combined with `vlan-optimization configured`.

VLAN pruning is disabled by default. The switches exchange Join and Leave messages that use the GVRP message format (Fortinet notes the implementation is not fully compliant with standard GVRP). On a standalone FortiSwitch running 7.6.1, the same feature is enabled with `config switch global` → `set vlan-pruning enable` and tuned under `config switch vlan-pruning` (`join-timer` 20–1000 ms, default 500; `leave-timer` 600–3000 ms, default 1800). Check results on the switch:

```text
FSW-Access1 # diagnose switch vlan-pruning dynamic-vlan list port49
FSW-Access1 # diagnose switch vlan-pruning protocol-packet stats port49
```

> **Real world:** Cisco engineers will recognise this as VTP pruning or MVRP. Like those, it only trims flooding on inter-switch trunks; it does not change what edge ports carry.

## Multiple FortiLink VLANs in one software switch

Since FortiOS 7.2.0 / FortiSwitchOS 7.2.0 you can add several FortiLink VLANs to one FortiGate software switch (`config system switch-interface`), for example to bridge two VLANs into one broadcast domain. The member VLANs must have no IP address, and traffic between members is governed by `intra-switch-policy` (default `implicit`, which allows it).

## Lab it yourself

FortiSwitchOS needs real switch hardware: Fortinet publishes no FortiSwitch VM in the FortiSwitch 7.6 document library, so everything port-side here is read-the-exhibit material unless you own a switch. On the **FortiGate-VM permanent trial** (FortiOS 7.6.x) you can still practise the FortiGate side:

1. Enable the switch controller (**System > Feature Visibility > Switch Controller**, or `config system global` → `set switch-controller enable`). Confirm the **WiFi & Switch Controller** menu appears on your trial VM before relying on it.
2. Create a FortiLink VLAN interface on the `fortilink` interface (or on a port you set `fortilink enable` on). Check first whether VLAN interfaces count against the trial's 3-interface cap on your build.
3. Inspect `config switch-controller global` and toggle `vlan-all-mode` and `vlan-optimization` to see the options your build offers.

## Key takeaways

- Every FortiSwitch port has a native VLAN, an allowed VLAN list and an untagged VLAN list; there is no access/trunk mode.
- Untagged ingress frames get the native VLAN; tagged ingress frames must match the native VLAN or an allowed VLAN.
- On egress, native and untagged-list VLANs are sent untagged, other allowed VLANs tagged, everything else dropped.
- From the FortiGate you reference VLAN interface **names**; on FortiSwitchOS you type VLAN **IDs**.
- `allowed-vlans-all` follows `vlan-all-mode` (`defined` by default).
- `vlan-optimization configured` (default) limits ISLs to FortiLink-defined VLANs; `prune` enables dynamic VLAN pruning in FortiOS 7.6.1.
- Configure managed switches from the FortiGate; direct changes on the switch are lost at restart.
