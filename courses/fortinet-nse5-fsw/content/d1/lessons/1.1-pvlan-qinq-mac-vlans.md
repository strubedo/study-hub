## Three ways to bend the basic VLAN model

The port model from the first lesson assigns VLANs by port and tag. Three FortiSwitchOS features change that:

| Feature | Problem it solves | Where you configure it |
|---|---|---|
| Private VLAN (PVLAN) | Isolate hosts that share one subnet | `config switch vlan` + `config switch interface` (FortiSwitchOS) |
| VLAN stacking (QinQ) | Carry a customer's own VLANs inside one provider VLAN | FortiSwitchOS `config switch interface` → `config qnq`; from FortiOS 7.6.1 also via the switch controller |
| MAC/IP/protocol-based VLANs | Pick the VLAN from the frame's content, not the port | `config switch vlan` → `config member-by-*` (FortiSwitchOS) |

Model support varies; check the FortiSwitchOS feature matrix for your platform before relying on any of them.

## Private VLANs

A PVLAN splits one VLAN (the **primary VLAN**) into **secondary VLANs** while keeping a single IP subnet and gateway. The primary VLAN forwards downstream to all secondary VLANs.

| Secondary VLAN type | Hosts can reach | Count per PVLAN domain |
|---|---|---|
| **Isolated** | Only promiscuous ports — not each other, not other secondaries | **One** |
| **Community** | Each other (same community) and promiscuous ports | Many |

Port types:

- **Promiscuous port (P-port)** — connects the router, firewall or gateway; talks to everything in the primary and all secondary VLANs.
- **Isolated port (I-port)** — host port in the isolated VLAN; talks only to P-ports.
- **Community port (C-port)** — host port in a community VLAN; talks to P-ports and to ports in the same community.

```text
FSW-Access1 # config switch vlan
FSW-Access1 (vlan) # edit 1000
FSW-Access1 (1000) # set private-vlan enable
FSW-Access1 (1000) # set isolated-vlan 101
FSW-Access1 (1000) # set community-vlans 200-210
FSW-Access1 (1000) # end
FSW-Access1 # config switch interface
FSW-Access1 (interface) # edit "port48"
FSW-Access1 (port48) # set private-vlan promiscuous
FSW-Access1 (port48) # set primary-vlan 1000
FSW-Access1 (port48) # next
FSW-Access1 (interface) # edit "port3"
FSW-Access1 (port3) # set private-vlan sub-vlan
FSW-Access1 (port3) # set primary-vlan 1000
FSW-Access1 (port3) # set sub-vlan 200
FSW-Access1 (port3) # next
FSW-Access1 (interface) # edit "port7"
FSW-Access1 (port7) # set private-vlan sub-vlan
FSW-Access1 (port7) # set primary-vlan 1000
FSW-Access1 (port7) # set sub-vlan 101
FSW-Access1 (port7) # end
```

Here port3 is a community port (VLAN 200), port7 is an isolated port (VLAN 101) and port48 is the promiscuous uplink. Note there is no separate "isolated" or "community" keyword on the port: `set private-vlan sub-vlan` plus the `sub-vlan` ID decides it, because the VLAN itself was declared isolated or community.

> **Real world:** this is the same design as Cisco PVLANs (`private-vlan primary/isolated/community`, `switchport mode private-vlan host/promiscuous`). The Fortinet syntax is shorter, and the "only one isolated VLAN per primary" rule is the same.

> **Exam tip:** in FortiLink mode the native way to stop hosts in one VLAN talking to each other is **blocking intra-VLAN traffic** on the FortiGate VLAN interface (`set switch-controller-access-vlan enable`, covered in domain 3), which only permits traffic to and from the FortiGate. PVLANs are a FortiSwitchOS feature.

## VLAN stacking (QinQ)

QinQ puts a second 802.1Q header in front of the customer's tag: the outer **S-VLAN** (service provider) carries the inner **C-VLAN** (customer) unchanged. The EtherType of the outer tag comes from a **VLAN TPID profile**:

- Up to **four** TPID profiles per switch, including the default `0x8100`.
- The default profile (`0x8100`) cannot be deleted or changed. Create others with `config switch vlan-tpid` → `set ether-type 0x88a8` (for example).

The split between C-VLAN and S-VLAN settings is the key exam point:

| Setting | Applies to |
|---|---|
| Everything under `config qnq` (`status`, `add-inner`, `remove-inner`, `native-c-vlan`, `allowed-c-vlan`, `vlan-mapping-miss-drop`, `priority`, `config vlan-mapping`) | **C-VLANs** (customer, inner) |
| `set native-vlan`, `set allowed-vlans`, `set vlan-tpid` on the interface | **S-VLANs** (provider, outer) |

```text
FSW-Core1 # config switch interface
FSW-Core1 (interface) # edit "port1"
FSW-Core1 (port1) # set native-vlan 3000
FSW-Core1 (port1) # config qnq
FSW-Core1 (qnq) # set status enable
FSW-Core1 (qnq) # set native-c-vlan 1
FSW-Core1 (qnq) # set allowed-c-vlan 10,20
FSW-Core1 (qnq) # end
FSW-Core1 (port1) # end
```

Customer frames tagged 10 or 20 enter port1 and are carried in S-VLAN 3000. Untagged customer frames get inner tag 1 (`native-c-vlan`), which is removed again on egress. `config vlan-mapping` entries (`match-c-vlan` → `new-s-vlan`) let different customer VLANs land in different S-VLANs; `vlan-mapping-miss-drop` drops frames that match no mapping (only when `allowed-c-vlan` is not set). Verify with `diagnose switch qnq dtag-cfg`.

**Features that do not work with VLAN stacking:** DHCP relay, DHCP snooping, IGMP snooping, IP source guard, PVLAN and STP.

### QinQ from the FortiGate (FortiOS 7.6.1)

FortiOS 7.6.1 adds QinQ to the switch controller, aimed at MSSPs that give each customer a VDOM with its own 4K VLAN range. The S-VLAN is a VLAN interface on the FortiLink interface (it must be defined in the VDOM that owns the FortiLink interface), the C-VLANs are VLAN interfaces whose parent is that S-VLAN, and the port gets `set qnq "<S-VLAN interface>"`. Multi-tenancy is covered in domain 2; for this domain, know that the same C-VLAN/S-VLAN split applies.

## MAC/IP/protocol-based VLANs

Normally the VLAN comes from the ingress port (native VLAN) or the frame's tag. A FortiSwitch can instead assign the VLAN from:

| Method | Matches | Notes |
|---|---|---|
| MAC-based | Source MAC address | `config member-by-mac` → `set mac` |
| IP-based | Source IPv4 address or subnet (`/1`–`/32`); IPv6 prefix `/1`–`/64` where hardware allows | `config member-by-ipv4` / `member-by-ipv6`; on many 2xx and higher models, matching ARP is also put in the VLAN |
| Protocol-based | EtherType plus frame type (`ethernet2`, `802.3d`, `llc`) | `config member-by-proto` |

Prerequisites: the VLAN must exist on the switch **and** be allowed on the ingress port. By default, egress frames of the assigned VLAN are **tagged**; add the VLAN to the port's `untagged-vlans` for hosts that are not VLAN-aware.

```text
FSW-Access2 # config switch vlan
FSW-Access2 (vlan) # edit 20
FSW-Access2 (20) # config member-by-mac
FSW-Access2 (member-by-mac) # edit 1
FSW-Access2 (1) # set mac 00:21:cc:3a:10:20
FSW-Access2 (1) # set description "deskphone-114"
FSW-Access2 (1) # end
FSW-Access2 (20) # end
FSW-Access2 # config switch interface
FSW-Access2 (interface) # edit "port10"
FSW-Access2 (port10) # set allowed-vlans 20
FSW-Access2 (port10) # set untagged-vlans 20
FSW-Access2 (port10) # end
```

The phone's frames are placed in VLAN 20; the PC behind it stays in port10's native VLAN. Check with `diagnose switch vlan assignment mac list sorted-by-mac`. Hardware tables limit how many entries you can add; the CLI rejects the entry on `next`/`end` when you exceed the limit.

## Lab it yourself

All three features are FortiSwitchOS configuration and need a physical FortiSwitch (there is no FortiSwitch VM in Fortinet's 7.6 library). Without one, practise by reading exhibits: for each port in a PVLAN config, write down which other ports it can reach; for each QinQ config, label every setting as C-VLAN or S-VLAN.

## Key takeaways

- PVLAN: one isolated VLAN and any number of community VLANs per primary VLAN; promiscuous ports reach everything.
- Isolated hosts reach only promiscuous ports; community hosts reach their community and promiscuous ports.
- QinQ settings under `config qnq` are for C-VLANs; `native-vlan`, `allowed-vlans` and `vlan-tpid` are for S-VLANs.
- Up to four TPID profiles; the default `0x8100` cannot be changed or deleted.
- DHCP relay, DHCP snooping, IGMP snooping, IP source guard, PVLAN and STP are not supported with VLAN stacking.
- FortiOS 7.6.1 adds switch-controller QinQ (`set qnq` on the managed-switch port).
- MAC/IP/protocol VLANs need the VLAN allowed on the ingress port; add it to `untagged-vlans` for untagged hosts.
