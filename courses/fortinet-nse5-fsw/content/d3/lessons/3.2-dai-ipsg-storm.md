## Building on the snooping database

With DHCP snooping populating the binding table (VLAN, MAC, IP, port), two features use it to stop spoofing:

| Feature | Checks | Scope | Default |
|---|---|---|---|
| **Dynamic ARP inspection (DAI)** | ARP requests/replies on untrusted ports must match a valid IP-MAC binding | Per **VLAN**, with per-port ARP trust | Off on all VLANs |
| **IPv4 source guard** | IP traffic entering the port must come from an allowed IP (static binding or snooping entry) | Per **port** | Off |

A third, unrelated L2 protection — **storm control** — limits flooding and is covered at the end.

## Dynamic ARP inspection

DAI protects against ARP-based man-in-the-middle and IP spoofing: on **untrusted** ports, only ARP packets with a valid IP-to-MAC binding are forwarded. Requirements and defaults:

- **DHCP snooping must be enabled first** on the VLAN.
- DAI is **disabled on all VLANs by default**; enable it per VLAN.
- Ports are ARP-**untrusted** by default (`arp-inspection-trust untrusted` is the CLI default); trust ports that face routers, servers with static addresses you haven't bound, or other infrastructure.

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "vlan10-data"
FGT-HQ (vlan10-data) # set switch-controller-dhcp-snooping enable
FGT-HQ (vlan10-data) # set switch-controller-arp-inspection enable
FGT-HQ (vlan10-data) # end
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Core1
FGT-HQ (FSW-Core1) # config ports
FGT-HQ (ports) # edit port20
FGT-HQ (port20) # set arp-inspection-trust trusted
FGT-HQ (port20) # end
```

> **Watch out:** The 7.6.1 DAI page prints the VLAN keyword as `switch-controller-arp-inpsection` in one example (a typo) and shows `arp-inspection-trust` without `set`. The CLI Reference spelling is `switch-controller-arp-inspection` with `set arp-inspection-trust {untrusted | trusted}`.

Hosts with **static IP addresses** never appear in the snooping database, so DAI drops their ARP unless you either trust their port or — better — add a **DHCP-snooping static entry** (`config dhcp-snooping-static-client`, previous lesson).

### ARP monitor mode (FortiOS 7.4.4+)

Sometimes you want the switch to *learn* ARP bindings rather than enforce them — for example to record static-IP devices for RADIUS accounting. Set the VLAN to monitor mode and allow ARP monitoring on a DHCP-snooping **trusted** port:

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "vlan20-voice"
FGT-HQ (vlan20-voice) # set switch-controller-dhcp-snooping enable
FGT-HQ (vlan20-voice) # set switch-controller-arp-inspection monitor
FGT-HQ (vlan20-voice) # end
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Core1
FGT-HQ (FSW-Core1) # config ports
FGT-HQ (ports) # edit port21
FGT-HQ (port21) # set dhcp-snooping trusted
FGT-HQ (port21) # set allow-arp-monitor enable
FGT-HQ (port21) # end
```

The VLAN, MAC and IP seen in the ARP packets are saved in the DHCP-snooping database. `allow-arp-monitor` is `disable` by default.

## IPv4 source guard

IPv4 source guard (the FortiSwitch counterpart of Cisco IP Source Guard) permits traffic on a port only from specific IPv4 addresses and **discards everything else — without logging it**. Allowed sources are:

- **static entries** — IP addresses bound to MAC addresses that you configure, and
- **dynamic entries** — IP addresses learned by DHCP snooping.

Facts the exam can pick on:

- **Off by default**; enable it per port.
- Configured **from FortiOS only**, and only on managed models that support it (FortiSwitchOS feature matrix).
- If a static and a dynamic entry conflict, **the static entry wins**.
- Adding **more than 2,048** IP source guard entries from a FortiGate returns an error.
- Discarded traffic is **not logged**, so "check the traffic log" is not how you troubleshoot it.

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config ports
FGT-HQ (ports) # edit port14
FGT-HQ (port14) # set ip-source-guard enable
FGT-HQ (port14) # next
FGT-HQ (ports) # end
FGT-HQ (FSW-Access1) # config ip-source-guard
FGT-HQ (ip-source-guard) # edit port14
FGT-HQ (port14) # config binding-entry
FGT-HQ (binding-entry) # edit 1
FGT-HQ (1) # set ip 10.10.10.50
FGT-HQ (1) # set mac 00:09:0f:aa:10:50
FGT-HQ (1) # end
FGT-HQ (port14) # end
FGT-HQ (FSW-Access1) # end
```

Check entries with `diagnose switch-controller switch-info ip-source-guard hardware <serial>` on the FortiGate, or `get switch ip-source-guard-violations all` on the switch.

> **Exam tip:** Source guard and DAI are independent: a VLAN can run DAI without source guard and vice versa. Both rely on DHCP snooping for dynamic bindings, and both need static entries (source guard: `binding-entry`; DAI: DHCP-snooping static entry) for static-IP hosts.

## Storm control

Storm control measures broadcast, unknown-unicast and unknown-multicast traffic in **packets per second** and drops the excess. Defaults: threshold **500 pps**, and **all three traffic types disabled**, so nothing is dropped until you enable them.

Global (applies to all managed switch ports, FortiLink and non-FortiLink):

```text
FGT-HQ # config switch-controller storm-control
FGT-HQ (storm-control) # set rate 500
FGT-HQ (storm-control) # set broadcast enable
FGT-HQ (storm-control) # set unknown-unicast enable
FGT-HQ (storm-control) # set unknown-multicast enable
FGT-HQ (storm-control) # end
```

Per port, through a storm-control policy whose `storm-control-mode` is `override`:

```text
FGT-HQ # config switch-controller storm-control-policy
FGT-HQ (storm-control-policy) # edit "access-1000pps"
FGT-HQ (access-1000pps) # set storm-control-mode override
FGT-HQ (access-1000pps) # set rate 1000
FGT-HQ (access-1000pps) # set broadcast enable
FGT-HQ (access-1000pps) # end
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config ports
FGT-HQ (ports) # edit port5
FGT-HQ (port5) # set storm-control-policy "access-1000pps"
FGT-HQ (port5) # end
```

In a policy, `rate` is 1–10,000,000 pps, or **0 to drop all** packets of the enabled types. On the switch, `get switch storm-control` shows the result.

> **Real world:** Cisco's `storm-control broadcast level pps 500` is the closest match. The FortiLink storm-control settings only drop the excess packets — there is no equivalent of Cisco's `storm-control action shutdown` to configure.

## Lab it yourself

On the FortiGate-VM trial: on a FortiLink VLAN, enable `switch-controller-dhcp-snooping`, then try `set switch-controller-arp-inspection ?` to see `enable`, `disable` and `monitor` on your build. Configure `config switch-controller storm-control` and a `storm-control-policy`. Port trust, `ip-source-guard` binding entries and every `diagnose ... arp-inspection` or `ip-source-guard` command need a managed FortiSwitch that supports the feature.

## Key takeaways

- DAI: needs DHCP snooping, off on all VLANs by default, enabled per VLAN (`switch-controller-arp-inspection`), ports ARP-untrusted by default.
- Static-IP hosts need a DHCP-snooping static entry (or a trusted port) or DAI drops their ARP.
- ARP monitor mode (7.4.4+): `switch-controller-arp-inspection monitor` + `allow-arp-monitor enable` on a trusted port.
- IPv4 source guard: per port, off by default, static `binding-entry` + snooping entries, static beats dynamic, >2,048 entries errors, drops not logged.
- Storm control: pps, default 500, all types disabled by default; per-port policy needs `storm-control-mode override`; rate 0 drops all.
