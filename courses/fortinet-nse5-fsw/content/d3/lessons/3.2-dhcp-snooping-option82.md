## Why DHCP snooping comes first

DHCP snooping is the foundation of FortiSwitch anti-spoofing. It stops rogue DHCP servers and builds the **binding database** (VLAN, client MAC, IP, port) that dynamic ARP inspection and IPv4 source guard use later. Same idea as Cisco `ip dhcp snooping`, but in FortiLink mode it is switched on **per VLAN on the FortiGate** and trust is set **per switch port**.

## Enabling it

DHCP snooping is **disabled by default** on managed FortiSwitch VLANs. Enable it on the FortiLink VLAN interface:

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "vlan10-data"
FGT-HQ (vlan10-data) # set switch-controller-dhcp-snooping enable
FGT-HQ (vlan10-data) # end
```

Related per-VLAN options in the FortiOS 7.6 CLI Reference: `switch-controller-dhcp-snooping-verify-mac` and `switch-controller-dhcp-snooping-option82` (both `enable | disable`).

## Trusted and untrusted ports

The DHCP blocking feature watches DHCP from **untrusted** sources — typically host ports and unknown DHCP servers — and filters server messages arriving on them. **Managed switch ports are untrusted by default** (`dhcp-snooping untrusted` is the CLI default). Mark the ports that face a legitimate DHCP server or relay as trusted:

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Core1
FGT-HQ (FSW-Core1) # config ports
FGT-HQ (ports) # edit port20
FGT-HQ (port20) # set dhcp-snooping trusted
FGT-HQ (port20) # end
```

In most FortiLink designs the DHCP server *is* the FortiGate VLAN interface, so the server replies come down FortiLink and ISL trunks rather than an access port. A separate server (for example a Windows DHCP server in `vlan99-mgmt`) on a switch port needs that port trusted.

How client requests are flooded is a global choice: `config switch-controller global` → `set dhcp-snoop-client-req {drop-untrusted | forward-untrusted}`. With the default **`drop-untrusted`**, the snooping switch broadcasts client requests only out **trusted** ports in the VLAN; `forward-untrusted` broadcasts them out all ports.

> **Real world:** The Cisco equivalent is `ip dhcp snooping trust` on the uplink. The difference to remember is *where* you type it: on a FortiLink-managed switch, port trust is a per-port setting under the managed-switch entry on the FortiGate, while snooping itself is enabled on the FortiGate VLAN interface.

## The DHCP server access list

Trust tells the switch *which ports* may carry server replies; the **server access list** (FortiOS 7.0.1+) tells it *which server IPs* may answer at all. It is disabled by default (all servers allowed).

```text
FGT-HQ # config switch-controller global
FGT-HQ (global) # set dhcp-server-access-list enable
FGT-HQ (global) # end
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Core1
FGT-HQ (FSW-Core1) # set dhcp-server-access-list global
FGT-HQ (FSW-Core1) # end
FGT-HQ # config system interface
FGT-HQ (interface) # edit "vlan99-mgmt"
FGT-HQ (vlan99-mgmt) # set switch-controller-dhcp-snooping enable
FGT-HQ (vlan99-mgmt) # config dhcp-snooping-server-list
FGT-HQ (dhcp-snooping-server-list) # edit "win-dhcp"
FGT-HQ (win-dhcp) # set server-ip 10.10.99.20
FGT-HQ (win-dhcp) # end
FGT-HQ (vlan99-mgmt) # end
```

- Global switch (`config switch-controller global`, per VDOM or switch-wide) plus a per-switch value `global` (follow the global setting, the default), `enable` or `disable`.
- The server's port must still be **trusted**.
- Limits: **255 servers per table**, **2,048 servers in total** across all VLANs.

## Option 82

With FortiOS 7.4.0 and FortiSwitchOS 7.2.2 or later, the snooping switch can insert option-82 data so the DHCP server knows which switch and port a request came from (the remote-ID / circuit-ID pair that Cisco uses with `ip dhcp snooping information option`).

```text
FGT-HQ # config switch-controller global
FGT-HQ (global) # set dhcp-option82-format ascii
FGT-HQ (global) # set dhcp-option82-circuit-id ?
FGT-HQ (global) # set dhcp-option82-remote-id ?
FGT-HQ (global) # end
```

With the `ascii` format you choose which fields go into each ID with `dhcp-option82-circuit-id` and `dhcp-option82-remote-id` (use `?` to list them on your build):

| Format | Circuit ID | Remote ID |
|---|---|---|
| `ascii` (CLI default) | Selectable: interface name, VLAN, host name, mode, description | Selectable: MAC, host name, IP |
| `legacy` | Fixed: `hostname-[<vlan:16><mod:8><port:8>].32bit` | Fixed: `[mac(0..6)].48bit` |

A **per-port, per-VLAN override** (`config dhcp-snoop-option82-override` under the port) supplies plain-text circuit-ID and remote-ID strings. If no override matches the VLAN and port, the global settings apply; both IDs always come from the **same** source (both global or both override); each string — and both combined — can be at most 256 characters; overrides apply to DHCP snooping only, not DHCP relay.

Check the values a port would insert with:

```text
FGT-HQ # diagnose switch-controller switch-info option82-mapping snooping ascii S248EPTF18000101 vlan10 port5
```

(`hex` instead of `ascii` for the hexadecimal form; the port is optional.)

## Binding database knobs and static entries

| Setting (`config switch-controller global`) | Default |
|---|---|
| `dhcp-snoop-client-db-exp` (server database entry expiry) | 86,400 s (300–259,200) |
| `dhcp-snoop-db-per-port-learn-limit` (bindings per port) | 64 (range depends on model) |

For hosts with **static IPs** that DHCP snooping never sees, create **DHCP-snooping static entries** — otherwise DAI will drop their ARP:

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config dhcp-snooping-static-client
FGT-HQ (dhcp-snooping-static-client) # edit "printer-2f"
FGT-HQ (printer-2f) # set vlan "vlan10-data"
FGT-HQ (printer-2f) # set ip 10.10.10.50
FGT-HQ (printer-2f) # set mac 00:09:0f:aa:10:50
FGT-HQ (printer-2f) # set port "port14"
FGT-HQ (printer-2f) # end
```

Rules: the VLAN must have DHCP snooping enabled and be the port's native or an allowed VLAN; the port must **not be trusted** and must not be an 802.1X port; one MAC to one IPv4 address; a MAC can't appear in two static entries; **maximum 64 static entries per switch**; while an entry exists you can't remove its VLAN from the port, add that port to a trunk, or delete a trunk it references.

## Checking it on the switch

From the switch CLI (Diagnostics and Tools > Connect to CLI, or standalone): `get switch dhcp-snooping status`, `get switch dhcp-snooping database-summary` and `get switch dhcp-snooping client-db-details` show whether snooping is on and which bindings were learned.

## Lab it yourself

On the FortiGate-VM trial: create `vlan10-data` on a FortiLink interface and enable `switch-controller-dhcp-snooping`, browse `config dhcp-snooping-server-list` under it, and set the option-82 globals under `config switch-controller global` (`get` shows the defaults on your build). Port trust, static entries and the `get switch dhcp-snooping` commands need a managed FortiSwitch.

## Key takeaways

- Enable snooping per VLAN on the FortiGate (`switch-controller-dhcp-snooping enable`); off by default.
- Managed-switch ports are **untrusted** by default; trust the ports toward legitimate servers with `set dhcp-snooping trusted`.
- `dhcp-snoop-client-req drop-untrusted` (default) floods client requests only to trusted ports.
- Server access list (7.0.1+): global enable + per-switch `global|enable|disable` + per-VLAN `dhcp-snooping-server-list`; 255 per table, 2,048 total.
- Option 82 (FortiOS 7.4.0 / FortiSwitchOS 7.2.2): `ascii` (default, selectable fields) or `legacy` (fixed) format; per-port per-VLAN overrides.
- Static entries for static-IP hosts: untrusted, non-802.1X port, one MAC ↔ one IP, 64 per switch.
