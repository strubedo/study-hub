## Beyond 802.1X: deciding by what the device *is*

802.1X needs a supplicant or a RADIUS entry for every MAC. Many campus devices — printers, cameras, badge readers, IoT — have neither. FortiLink offers two device-driven mechanisms, both configured on the FortiGate:

| Mechanism | Port setting | Decision source | Result |
|---|---|---|---|
| **FortiLink NAC** | `set access-mode nac` | `config user nac-policy` (device, user, EMS tag, FortiVoice tag, vulnerability) | Matched device gets a VLAN or port settings (switch MAC policy) |
| **Dynamic port policy** | `set access-mode dynamic` + `set port-policy <name>` | `config switch-controller dynamic-port-policy` (device or interface-tag criteria) | Matched device gets LLDP profile, QoS policy, 802.1X policy and/or VLAN policy |
| Static (default) | `set access-mode static` | — | Port keeps its configured VLANs |

`access-mode` values are `static` (default), `dynamic` and `nac`.

## FortiLink NAC

### How it works

1. A device appears on a NAC port and is placed in the **onboarding VLAN**.
2. The FortiGate identifies it (device detection, user authentication, FortiClient EMS tag, FortiVoice tag or vulnerability data) and evaluates **NAC policies in list order** (reorder with `move <id> {before | after} <id>`).
3. A matching device is **authorized automatically by default** and moved to the VLAN (or port settings) the policy assigns.

NAC settings are created automatically on the `fortilink` interface when the first switch is discovered. They live under `config switch-controller fortilink-settings`:

```text
FGT-HQ # config switch-controller fortilink-settings
FGT-HQ (fortilink-settings) # edit "fortilink"
FGT-HQ (fortilink) # set inactive-timer 15
FGT-HQ (fortilink) # set link-down-flush enable
FGT-HQ (fortilink) # config nac-ports
FGT-HQ (nac-ports) # set onboarding-vlan "onboarding"
FGT-HQ (nac-ports) # set bounce-nac-port enable
FGT-HQ (nac-ports) # end
FGT-HQ (fortilink) # end
```

- `inactive-timer`: default **15 minutes** (1–1440).
- `bounce-nac-port`: bounce the port after a match so the device renews DHCP in its new VLAN.
- `config switch-controller system` → `nac-periodic-interval`: default **60 s** (5–180).
- By default **no NAC onboarding VLAN is assigned** — you choose one (the `nac` template role covers it at initial setup).

A device-category policy:

```text
FGT-HQ # config user nac-policy
FGT-HQ (nac-policy) # edit "Printers"
FGT-HQ (Printers) # set category device
FGT-HQ (Printers) # set hw-vendor "HP"
FGT-HQ (Printers) # set type "Printer"
FGT-HQ (Printers) # set switch-fortilink "fortilink"
FGT-HQ (Printers) # set switch-mac-policy "printer-vlan"
FGT-HQ (Printers) # end
```

Device fields include `mac`, `hw-vendor`, `type`, `family`, `os`, `hw-version`, `sw-version`, `host`, `user` and `src`, with `*` wildcards (FortiOS 6.4.6+). Categories are `device`, `firewall-user`, `ems-tag`, `fortivoice-tag` (FortiOS 7.4.4+) and `vulnerability` (needs an Attack Surface Security Rating licence and device detection). `set switch-group` (FortiOS 7.0.2+, replaced `switch-scope`) limits a policy to switch groups; with no group it applies to all. From FortiOS 7.4.4, `match-type {dynamic | override}` and `match-period` (0–120 days, 0 = keep) control how long a match lasts.

### NAC LAN segments

FortiOS/FortiSwitchOS 7.0.1+ can put NAC VLANs into a **LAN segment**: several layer-2 VLANs sharing one layer-3 interface (the `nac-segment` interface, template default 10.255.13.1/24), so a device keeps its IP address when NAC moves it. Only **one LAN segment per FortiGate**; RSPAN VLANs can't be members; remove layer-3 settings from the member VLANs first.

### Where NAC doesn't work

FortiSwitch NAC isn't supported with **FortiLink over a layer-3 network** — a common distractor when a branch island is managed across a routed WAN.

## Dynamic port policies

Dynamic port policies apply port *settings* rather than just a VLAN:

```text
FGT-HQ # config switch-controller dynamic-port-policy
FGT-HQ (dynamic-port-policy) # edit "access-dpp"
FGT-HQ (access-dpp) # set fortilink "fortilink"
FGT-HQ (access-dpp) # config policy
FGT-HQ (policy) # edit "phones"
FGT-HQ (phones) # set category device
FGT-HQ (phones) # set hw-vendor "Yealink"
FGT-HQ (phones) # set lldp-profile "voice-lldp"
FGT-HQ (phones) # set qos-policy "voice-qos"
FGT-HQ (phones) # set vlan-policy "voice-vlans"
FGT-HQ (phones) # next
FGT-HQ (policy) # edit "default"
FGT-HQ (default) # set category device
FGT-HQ (default) # set 802-1x "corp-dot1x"
FGT-HQ (default) # end
FGT-HQ (access-dpp) # end
```

- Match criteria: `category {device | interface-tag}`, `mac`, `hw-vendor` (FortiOS 7.0.4+), `type`, `family`, `host`.
- Actions: `lldp-profile`, `qos-policy`, `802-1x` (a security policy), `vlan-policy` and `bounce-port-link`.
- A `config switch-controller vlan-policy` holds `vlan` (native), `allowed-vlans`, `untagged-vlans`, `allowed-vlans-all` and `discard-mode {none | all-untagged | all-tagged}`.
- Rules are processed from the first to the last, so **make the last rule the default** (as `default` above). FortiOS 7.4.4 moved matching to priority-based evaluation and added `match-type` / `match-period`.
- Ports use it with `set access-mode dynamic` and `set port-policy "access-dpp"`; the engine runs every `dynamic-periodic-interval` (default 60 s).

## MAC learning limits

Like Cisco port security's maximum, a **learning limit** caps how many dynamic MACs a port or VLAN learns:

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config ports
FGT-HQ (ports) # edit port12
FGT-HQ (port12) # set learning-limit 2
FGT-HQ (port12) # end
```

- Range **1–128**; **0 = no limit** (default). Static MACs don't count toward the limit.
- Per VLAN there is a matching VLAN-level learning limit.
- Violations aren't logged by default. Enable `set log-mac-limit-violations enable` under `config switch-controller global`, then view them with `diagnose switch-controller switch-info mac-limit-violations {all | interface | vlan} <serial> ...`. Only one violation is recorded per interface or VLAN until its log is reset (`execute switch-controller mac-limit-violation reset ...`).
- Changing MAC learning settings on a port or VLAN flushes its existing dynamic entries.

> **Watch out:** Don't carry Cisco's `switchport port-security violation shutdown` model over. The FortiLink Guide describes the learning limit and an optional violation log — no err-disable action — so an exam answer that "shuts the port down" when the limit is exceeded is a distractor.

## Sticky (persistent) MAC addresses

`set sticky-mac enable` on a port keeps dynamically learned MACs across port down/up events (default: not persistent). They are still lost on **reboot** unless you save them to the configuration:

```text
FGT-HQ # execute switch-controller switch-action sticky-mac save interface S124EN5918000103 port12
FGT-HQ # execute switch-controller switch-action sticky-mac save all S124EN5918000103
FGT-HQ # execute switch-controller switch-action sticky-mac delete-unsaved all S124EN5918000103
```

Related global settings: `mac-aging-interval` (default **300 s**, 10–1000000, 0 disables aging) and `mac-event-logging` (default disable) for syslog entries when MACs are learned, aged or removed.

## Lab it yourself

On the FortiGate-VM trial: build `config user nac-policy` entries, a `vlan-policy`, a `dynamic-port-policy` with a final default rule, and inspect `config switch-controller fortilink-settings` (it appears once a FortiLink interface exists — confirm on your build). Matching real devices, sticky-MAC saves and learning-limit violations need a physical FortiSwitch and clients.

## Key takeaways

- `access-mode {static | dynamic | nac}`: static by default; `nac` uses NAC policies, `dynamic` uses a `port-policy`.
- NAC: onboarding VLAN → policy match in list order → assigned VLAN; inactive timer 15 min; not supported over layer-3 FortiLink.
- NAC LAN segments keep IPs stable across NAC VLANs; one per FortiGate.
- Dynamic port policy actions: LLDP profile, QoS policy, 802.1X policy, VLAN policy, bounce; keep a default rule last.
- Learning limit 1–128 (0 = unlimited), statics not counted, violations logged only if enabled; no port shutdown.
- Sticky MAC survives link flaps; save it (`sticky-mac save`) to survive reboots.
