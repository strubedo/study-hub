## Port security in FortiLink mode

On a Cisco switch, 802.1X lives on the interface (`authentication port-control auto`, `dot1x pae authenticator`, `mab`). In FortiLink mode the same idea is split in two:

1. A reusable **FortiSwitch security policy** on the FortiGate (`config switch-controller security-policy 802-1X`) holds the authentication behaviour.
2. Each switch port references a policy with `set port-security-policy <name>`. Different ports can use different policies.

The RADIUS server (here `10.10.99.20`) is a normal FortiGate `config user radius` object inside a user group. Because the managed switch talks RADIUS through the FortiGate, **you must create a firewall policy that allows RADIUS traffic from the FortiLink interface to the server**.

## The security policy

```text
FGT-HQ # config switch-controller security-policy 802-1X
FGT-HQ (802-1X) # edit "corp-dot1x"
FGT-HQ (corp-dot1x) # set security-mode 802.1X-mac-based
FGT-HQ (corp-dot1x) # set user-group "RADIUS-Users"
FGT-HQ (corp-dot1x) # set mac-auth-bypass enable
FGT-HQ (corp-dot1x) # set guest-vlan enable
FGT-HQ (corp-dot1x) # set guest-vlan-id "vlan30-guest"
FGT-HQ (corp-dot1x) # set guest-auth-delay 30
FGT-HQ (corp-dot1x) # set auth-fail-vlan enable
FGT-HQ (corp-dot1x) # set auth-fail-vlan-id "vlan30-guest"
FGT-HQ (corp-dot1x) # set authserver-timeout-vlan enable
FGT-HQ (corp-dot1x) # set authserver-timeout-vlanid "vlan10-data"
FGT-HQ (corp-dot1x) # next
FGT-HQ (802-1X) # end
```

| Setting | Meaning | Default |
|---|---|---|
| `security-mode {802.1X \| 802.1X-mac-based}` | **Port-based**: the first device to authenticate opens the port. **MAC-based**: each device on the port authenticates separately (use it when several devices share a port, for example a phone with a PC behind it) | — |
| `user-group` | Mandatory: a user group (normally containing RADIUS servers), `Guest-group` or `SSO_Guest_Users` | — |
| `mac-auth-bypass` | **MAB**: the device MAC is used as both RADIUS user name and password | disable |
| `eap-passthru` | EAP pass-through (the option table calls it `eap-passthrough`) | — |
| `guest-vlan`, `guest-vlan-id`, `guest-auth-delay` | VLAN for devices that don't do 802.1X; delay 1–900 s before falling back | disable |
| `auth-fail-vlan`, `auth-fail-vlan-id` | VLAN for devices that **fail** authentication | disable |
| `authserver-timeout-vlan`, `authserver-timeout-vlanid`, `authserver-timeout-period` | VLAN used when the **RADIUS server doesn't answer** within the period (3–15 s, default 3) | disable |
| `authserver-timeout-tagged {disable \| lldp-voice \| static}` | Tagged VLAN during a server timeout (for example the LLDP voice VLAN) | disable |
| `radius-timeout-overwrite` | Let the RADIUS Session-Timeout override the local reauthentication timer | disable |
| `policy-type 802.1X` | The policy type | — |

> **Exam tip:** Three fallback VLANs, three different triggers: **guest** — no 802.1X response; **auth-fail** — wrong credentials; **authserver-timeout** — RADIUS unreachable. Pick the one that matches the symptom in the stem.

### Applying the policy

```text
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config ports
FGT-HQ (ports) # edit port5
FGT-HQ (port5) # set port-security-policy "corp-dot1x"
FGT-HQ (port5) # end
```

### MAC-based mode limits

In MAC-based mode a port supports **up to 20 devices** (MAC sessions). The switch-wide total depends on the model. Fortinet recommends keeping the 802.1X session rate to about 5–10 sessions per second.

## Global and per-switch 802.1X settings

`config switch-controller 802-1X-settings` sets fabric-wide timers:

| Setting | Range / values | Default |
|---|---|---|
| `link-down-auth` | `set-unauth` (port must reauthenticate after link loss) or `no-action` | `set-unauth` |
| `reauth-period` | 1–1440 minutes (0 disables, CLI only) | 60 |
| `max-reauth-attempt` | 1–15 (0 disables) | 3 |
| `tx-period` | 4–60 seconds | 30 |
| `mab-reauth` | MAB reauthentication | disable |

A single switch can override them under its managed-switch entry with `config 802-1X-settings` → `set local-override enable` (GUI: **Override 802.1x settings** in Edit Managed FortiSwitch).

## Authentication order (FortiOS 7.6.0+)

FortiOS 7.6.0 adds `auth-priority` to choose what happens when a port supports both EAP and MAB:

| `auth-priority` | Behaviour |
|---|---|
| `legacy` | Default after upgrade: EAP first, without delay |
| `dot1x-mab` | 802.1X first, then MAB |
| `mab-dot1x` | MAB first, then 802.1X |

If every method fails and an auth-fail VLAN is configured, the port uses it. For **MAB only**, set `auth-order` to `mab` (FortiSwitchOS 7.2.3+): no EAP packets are sent at all — handy for printers and cameras that choke on EAPOL.

## Dynamic VLAN assignment

RADIUS can return a VLAN in **Tunnel-Private-Group-Id**, as either a **VLAN ID** (integer) or a **name** (string). Names are matched against the **description** of the FortiGate VLAN interfaces (FortiOS 7.4.1+ can sync up to 63 characters of the interface description). If several VLANs carry the same name, `assignment-priority` (1–255, default 128) decides — the **lowest** value wins.

Other RADIUS details that sometimes appear in exhibits:

- MAC formatting for User-Name, User-Password, Called-Station-Id and Calling-Station-Id: delimiter colon, hyphen, single-hyphen or none (default **hyphen**), lowercase by default.
- NAS-IP-Address: with `switch-controller-nas-ip-dynamic` (FortiOS 7.4.2+) the attribute follows the switch's FortiLink IPv4 address; override per switch with `radius-nas-ip-override` / `radius-nas-ip`.

## Dynamic ACLs and monitor mode

From **FortiOS 7.4.4**, RADIUS can push **dynamic ACLs (DACLs)**: enable `dacl` in the security policy, then return **Filter-Id** (needs a custom command on the switch) or **NAS-Filter-Rule** (max 80 characters, no spaces — one syntax error fails the whole DACL). DACLs work with port-based and MAC-based 802.1X, with **monitor mode** (`open-auth`, which lets traffic flow while you test even if authentication fails) and with static ACLs, IPv4 only, up to **45 ACL entries per port** (static plus dynamic). Check them with:

```text
FGT-HQ # diagnose switch-controller switch-info 802.1X-dacl S124EN5918000103 port5
```

## Standalone FortiSwitchOS equivalent

On a standalone switch the policy sits directly on the interface:

```text
FSW-Lab # config switch interface
FSW-Lab (interface) # edit port5
FSW-Lab (port5) # config port-security
FSW-Lab (port-security) # set port-security-mode 802.1X-mac-based
FSW-Lab (port-security) # end
FSW-Lab (port5) # end
```

and `diagnose switch 802-1x status [<port>]` shows session state, including dynamically assigned VLANs. Note the spelling: **`802-1x`** in the switch's diagnose command, **`802.1X-dacl`** in the FortiGate's `switch-info` keyword and **`802-1X`** in the FortiGate config tree names.

## Lab it yourself

On the FortiGate-VM trial (no switch needed): create a RADIUS server object pointing at a FreeRADIUS VM, a user group containing it, then `config switch-controller security-policy 802-1X` and step through `set ?` to see every option, including `auth-priority`, `auth-order` and `dacl` on your build. Browse `config switch-controller 802-1X-settings`. Write the firewall policy from the FortiLink interface to the RADIUS server — remember the trial's 3-policy cap. Applying the policy to a port and testing supplicants needs a physical FortiSwitch.

## Key takeaways

- Security policy on the FortiGate (`config switch-controller security-policy 802-1X`), referenced per port with `port-security-policy`.
- Port-based mode: one authentication opens the port; MAC-based: per device, up to 20 per port.
- Guest VLAN = no 802.1X, auth-fail VLAN = failed credentials, authserver-timeout VLAN = RADIUS unreachable; MAB is off by default.
- Global timers in `802-1X-settings` (reauth 60 min, 3 attempts, tx-period 30 s, `link-down-auth set-unauth`); per-switch `local-override`.
- FortiOS 7.6.0 `auth-priority` (legacy, dot1x-mab, mab-dot1x); `auth-order mab` for MAB only.
- Dynamic VLAN via Tunnel-Private-Group-Id (ID or name matching the VLAN interface description); allow RADIUS from the FortiLink interface with a firewall policy.
