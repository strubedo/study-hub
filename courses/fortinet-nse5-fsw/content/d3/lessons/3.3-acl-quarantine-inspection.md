## What "security profiles" means for this exam

Fortinet's task title is "ACLs, security profiles, and VLAN security mechanisms on FortiSwitch", but Fortinet doesn't define "security profiles" for this exam. This site reads it as two things: **FortiGate inspection of FortiSwitch VLAN traffic** (firewall policies with antivirus, IPS, web filter and other profiles on the FortiLink VLAN interfaces) and the **FortiSwitch security policies** (802.1X) covered in the port-security lesson. This lesson covers the switch-side controls — ACLs, intra-VLAN blocking, quarantines and FortiLink secure fabric — and how they push traffic through the FortiGate's inspection.

## ACLs

### In FortiLink mode (FortiOS 7.4.0 + FortiSwitchOS 7.4.0 and later)

Managed-switch ACLs are **ingress only**: they act on traffic as it arrives on a port. The workflow is policy → group → port → counters.

```text
FGT-HQ # config switch-controller acl ingress
FGT-HQ (ingress) # edit 1
FGT-HQ (1) # config action
FGT-HQ (action) # set drop enable
FGT-HQ (action) # set count enable
FGT-HQ (action) # end
FGT-HQ (1) # config classifier
FGT-HQ (classifier) # set src-mac 00:0c:29:4a:10:25
FGT-HQ (classifier) # set dst-ip-prefix 10.10.99.0 255.255.255.0
FGT-HQ (classifier) # end
FGT-HQ (1) # next
FGT-HQ (ingress) # end
FGT-HQ # config switch-controller acl group
FGT-HQ (group) # edit "block-mgmt"
FGT-HQ (block-mgmt) # set ingress 1
FGT-HQ (block-mgmt) # end
FGT-HQ # config switch-controller managed-switch
FGT-HQ (managed-switch) # edit FSW-Access1
FGT-HQ (FSW-Access1) # config ports
FGT-HQ (ports) # edit port6
FGT-HQ (port6) # set acl-group "block-mgmt"
FGT-HQ (port6) # end
```

- **Classifier** fields: `src-mac`, `dst-mac`, `src-ip-prefix`, `dst-ip-prefix`, `vlan` (1–4094). Several can match one packet.
- **Actions**: `drop` and/or `count`.
- A port can carry one or more ACL groups. User-configured ACLs go into **ACL group 3** on the switch; a model without group 3 can't use them.
- ACLs live in **TCAM**, allocated best-fit when created, so the order you add classifiers matters and allocations can fragment.
- Internal ACLs created by other switch features can conflict with or override yours; validate per model.
- Counters: `diagnose switch-controller switch-info acl-counters <serial>`. On FS-4xxE, FS-1xxE and FS-1xxF, byte counters always read 0 (packet counters work).

### On a standalone FortiSwitch

FortiSwitchOS has three ACL stages under `config switch acl`:

| Stage | Applies to |
|---|---|
| `ingress` | Incoming traffic on a port |
| `prelookup` | Traffic before the switch's forwarding lookup |
| `egress` | Outgoing traffic |

Actions there include count, drop, redirect, mirror, outer-VLAN tagging and CoS queue. Entry-level models (108/124/148 E and F series) support only the ingress stage. Counters: `get switch acl counters {all | egress | ingress | prelookup}`. The FortiSwitchOS guide notes that this switch-side ACL configuration **isn't supported in FortiLink mode** — on a managed switch you use the FortiGate's `config switch-controller acl` tree instead.

## Blocking intra-VLAN traffic

Normally two hosts in the same VLAN talk directly through the switch, and the FortiGate never sees that traffic. **Block intra-VLAN traffic** changes that: on the VLAN, only traffic to and from the FortiGate is allowed; FortiSwitch port-to-port traffic is blocked (a private-VLAN-like isolation).

```text
FGT-HQ # config system interface
FGT-HQ (interface) # edit "vlan30-guest"
FGT-HQ (vlan30-guest) # set switch-controller-access-vlan enable
FGT-HQ (vlan30-guest) # end
```

GUI: Network > Interfaces > edit the VLAN > **Block intra-VLAN traffic**.

If some host-to-host traffic must still flow, route it **through the FortiGate**: enable **proxy ARP** for the VLAN's range (`config system proxy-arp`) and add a firewall policy with the same VLAN as source and destination interface — which is exactly where you attach security profiles to inspect east-west traffic. If that traffic enters and exits the same interface, `config system global` → `set allow-traffic-redirect disable` is a prerequisite.

Restrictions: IPv6 between clients isn't supported while blocking is on, and blocking isn't supported when the FortiLink interface is a **hardware or software switch**. From FortiOS/FortiSwitchOS 7.4.1, `config switch-controller fortilink-settings` → `set access-vlan-mode {legacy | fail-open | fail-close}` decides what happens if the switch loses the FortiGate: `fail-open` allows intra-VLAN traffic, `fail-close` keeps blocking it, `legacy` (default) behaves as before.

## Quarantines

Quarantine isolates a host by **MAC address**. It is enabled by default (an upgrade keeps the old setting). Two modes under `config switch-controller global` → `set quarantine-mode`:

| Mode | Behaviour |
|---|---|
| `by-vlan` (default since FortiOS 6.4.1) | The host is moved to a separate **quarantine VLAN** on the FortiGate (VLAN 4093 in Fortinet's examples, interface `qtn.<FortiLink port>` with captive-portal security mode and its own DHCP server); the quarantine VLAN is added to the allowed and untagged VLANs of all switch ports |
| `by-redirect` | The host's traffic is redirected to a firewall address group (`QuarantinedDevices`) |

GUI: right-click a host in Security Fabric > Physical/Logical Topology or FortiView Sources and choose **Quarantine Host on FortiSwitch** (this also enables the feature). CLI:

```text
FGT-HQ # config user quarantine
FGT-HQ (quarantine) # set quarantine enable
FGT-HQ (quarantine) # config targets
FGT-HQ (targets) # edit "infected-laptop"
FGT-HQ (infected-laptop) # config macs
FGT-HQ (macs) # edit 00:0c:29:4a:10:25
FGT-HQ (00:0c:29:4a:10:25) # set drop disable
FGT-HQ (00:0c:29:4a:10:25) # end
FGT-HQ (infected-laptop) # end
FGT-HQ (quarantine) # end
```

- `drop enable` discards the host's traffic; `drop disable` sends it to the FortiGate.
- An optional `traffic-policy` (from `config switch-controller traffic-policy`) limits bandwidth, burst and CoS queue for quarantined hosts; without one you can't control their resources.
- The quarantine table holds up to **512 entries** (no limit on MACs per entry).
- A quarantined DHCP client stays unreachable until it renews; `set bounce-quarantined-link enable` (default disable) bounces the port where it was last seen to force renewal.
- Release: Monitor > Quarantine Monitor > delete the entry, `delete` the MAC or target in the CLI, or `set quarantine disable` to release all. `config user quarantine` replaced the older `config switch-controller quarantine`.

> **Watch out:** The 7.6.1 guides give two different addresses for the quarantine VLAN interface (the VLAN-template table lists 10.255.11.1/24, the Quarantines page 10.254.254.254). Learn the mechanism, not the address.

## FortiGate inspection of FortiSwitch traffic

In FortiLink mode every user VLAN is a **FortiGate VLAN interface** on the FortiLink interface (`vlan10-data`, `vlan20-voice`, `vlan30-guest`, `vlan99-mgmt`). So:

- **Inter-VLAN** traffic is routed by the FortiGate and must match a **firewall policy**; attach security profiles (antivirus, web filter, application control, IPS) and SSL inspection there exactly as on any FortiGate interface.
- **Intra-VLAN** traffic is switched locally and never inspected — unless you block intra-VLAN traffic and add a same-interface policy with proxy ARP.
- **Quarantine** and **NAC** move hosts into VLANs whose policies you control.
- Give FortiLink VLAN interfaces a role (LAN, WAN, DMZ) before using them in policies; otherwise the Security Rating's Interface Classification check fails.

## FortiLink secure fabric

FortiOS/FortiSwitchOS **7.4.1+** can authenticate and encrypt **ISLs between FortiSwitch units**. Authentication uses the switches' LLDP neighbor relationship and Fortinet factory certificates (not 802.1X); encryption uses **MACsec** (IEEE 802.1AE). It is set in an LLDP profile:

```text
FGT-HQ # config switch-controller lldp-profile
FGT-HQ (lldp-profile) # edit "secure-isl"
FGT-HQ (secure-isl) # set auto-isl-auth relax
FGT-HQ (secure-isl) # set auto-isl-auth-encrypt mixed
FGT-HQ (secure-isl) # set auto-isl-auth-macsec-profile default-macsec-auto-isl
FGT-HQ (secure-isl) # end
```

| `auto-isl-auth` | On success | On failure |
|---|---|---|
| `legacy` (default) | No authentication | — |
| `relax` | Secure ISL trunk | **Restricted** ISL trunk (no user VLANs; lets you authenticate the new switch) |
| `strict` | Secure ISL trunk | **No** trunk |

| `auto-isl-auth-encrypt` | Meaning |
|---|---|
| `none` (default) | No MACsec |
| `mixed` | MACsec on members that support it; others stay unencrypted |
| `must` | MACsec on all members; non-MACsec ports are removed from the ISL but still work as user ports |

You must choose `relax` or `strict` before `mixed` or `must`. Links between the FortiGate and FortiSwitch are **always unencrypted**. Not supported: VXLAN, static ISLs (`set static-isl` disables authentication and encryption) and Security Rating topology lockdown. Check with `execute switch-controller get-physical-conn {dot | standard} <FortiLink interface>` (which ports are authenticated, secured or restricted) and on the switch `diagnose switch fortilink-auth status <port>` / `get switch lldp auto-isl-status <port>`.

## Lab it yourself

On the FortiGate-VM trial: build `config switch-controller acl ingress` and `acl group` objects, enable `switch-controller-access-vlan` on a FortiLink VLAN with a matching same-interface firewall policy (counts toward the 3-policy cap), create a `config user quarantine` target, and look at `config switch-controller lldp-profile` → `edit default-auto-isl` → `set auto-isl-auth ?`. Applying ACLs to ports, TCAM counters and MACsec need physical FortiSwitch hardware.

## Key takeaways

- FortiLink ACLs (7.4.0+): ingress only; classifier (MAC, IP prefix, VLAN) + action (drop/count) → `acl group` → `acl-group` on the port; counters with `switch-info acl-counters`.
- Standalone FortiSwitchOS ACL stages: ingress, prelookup, egress; not used in FortiLink mode.
- `switch-controller-access-vlan enable` blocks port-to-port traffic in a VLAN; allow chosen flows with proxy ARP + a same-interface policy (where profiles inspect them); not with hardware/software-switch FortiLink.
- Quarantine: `by-vlan` (default) or `by-redirect`; `config user quarantine`; 512 entries; `drop` vs send to FortiGate.
- Inspection: FortiLink VLANs are FortiGate interfaces; inter-VLAN traffic hits firewall policies and profiles, intra-VLAN doesn't unless blocked.
- Secure fabric (7.4.1+): LLDP-profile `auto-isl-auth` legacy/relax/strict and MACsec `none`/`mixed`/`must`; FortiGate links never encrypted; no VXLAN or static ISL.
