## Why variable-length masks

With a single mask for every subnet ("fixed-length subnetting") you must size every subnet for your largest segment. Cut `192.168.50.0/24` into four /26 subnets and a 2-host router-to-router link wastes 60 of its 62 usable addresses. **Variable-length subnet masking (VLSM)** lets each subnet have the prefix length it needs, carved from the same parent block. It requires that your routers carry the mask with every route, which every modern IGP does (OSPF, EIGRP, IS-IS, RIPv2) and which is inherent to BGP. Classful protocols such as RIPv1 cannot do it.

VLSM is simply CIDR applied inside an organisation: the parent block is a prefix, and each child is a smaller prefix nested inside it. Nested prefixes are the key idea, and it is also the whole theory of overlaps (below).

## The largest-first procedure

Allocate from the largest requirement to the smallest. Largest-first keeps the arithmetic aligned, because every subnet must start at an address that is a multiple of its own size, and big blocks are the hardest to place once smaller ones have fragmented the space.

1. List each subnet and the number of hosts it needs, **including the router interface** (and any gateway/HSRP/VRRP addresses and growth).
2. Sort descending by host count.
3. For each, find the smallest prefix that fits: smallest h with 2^h - 2 >= hosts, prefix = 32 - h.
4. Starting at the beginning of the parent block, give each subnet the **next free address that is aligned to its block size**, then mark that block used.
5. Verify the plan: no two subnets overlap, everything lies inside the parent, and the remaining free space is recorded.

### Worked example 1: 192.168.50.0/24

Requirements: LAN-A 100 hosts, LAN-B 50, LAN-C 25, LAN-D 10, and two router-to-router links.

| Subnet | Need | Fit | Prefix | Network | Usable | Broadcast |
|---|---|---|---|---|---|---|
| LAN-A | 100 | 2^7 - 2 = 126 | /25 | 192.168.50.0 | .1-.126 | .127 |
| LAN-B | 50 | 2^6 - 2 = 62 | /26 | 192.168.50.128 | .129-.190 | .191 |
| LAN-C | 25 | 2^5 - 2 = 30 | /27 | 192.168.50.192 | .193-.222 | .223 |
| LAN-D | 10 | 2^4 - 2 = 14 | /28 | 192.168.50.224 | .225-.238 | .239 |
| Link 1 | 2 | 2^2 - 2 = 2 | /30 | 192.168.50.240 | .241-.242 | .243 |
| Link 2 | 2 | 2^2 - 2 = 2 | /30 | 192.168.50.244 | .245-.246 | .247 |

Each network starts exactly where the previous broadcast ended plus one: 0-127, 128-191, 192-223, 224-239, 240-243, 244-247. The unused space is `192.168.50.248/29` (addresses .248-.255). The total allocated is 128 + 64 + 32 + 16 + 4 + 4 = 248 of 256.

If the links used /31 (RFC 3021, section 2.4) they would take 2 addresses each, leaving more room; /30 remains the safest default for compatibility with older equipment and tools.

### Worked example 2: 172.16.8.0/22

The parent block spans 172.16.8.0-172.16.11.255 (1024 addresses). Requirements: Campus 500 hosts, Servers 200, Branch 60, three links.

| Subnet | Need | Prefix | Network | Range |
|---|---|---|---|---|
| Campus | 500 | /23 (510) | 172.16.8.0/23 | 172.16.8.1-172.16.9.254 |
| Servers | 200 | /24 (254) | 172.16.10.0/24 | 172.16.10.1-172.16.10.254 |
| Branch | 60 | /26 (62) | 172.16.11.0/26 | 172.16.11.1-172.16.11.62 |
| Link 1 | 2 | /30 | 172.16.11.64/30 | .65-.66 |
| Link 2 | 2 | /30 | 172.16.11.68/30 | .69-.70 |
| Link 3 | 2 | /30 | 172.16.11.72/30 | .73-.74 |

The next free address is `172.16.11.76`, and everything from there to `172.16.11.255` stays reserved for growth (the aligned free blocks are .76/30, .80/28, .96/27, .128/25). Total used: 512 + 256 + 64 + 12 = 844 of 1024.

Notice what largest-first prevented. Had you placed the three /30 links first at `172.16.8.0`, the /23 would not be able to start at `172.16.8.0` and would have to jump to `172.16.10.0`, since a /23 must begin on an even third octet. You would have scattered the free space.

> **Exam tip:** Alignment is the invariant: a /N subnet's network address must be a multiple of its block size. A /26 can only start at .0, .64, .128 or .192. `192.168.50.100/26` is not a network address, it is a host inside `192.168.50.64/26`.

## Avoiding overlaps

Two IPv4 prefixes either **nest** (one contains the other) or are **disjoint**. They can never partially overlap, because every prefix is a power-of-two-sized, aligned block. So testing for overlap reduces to a single check: does the shorter prefix's block contain the longer one's network address?

Example: `192.168.50.0/25` covers .0-.127. `192.168.50.64/26` covers .64-.127. The /26 sits inside the /25, so they overlap, and using both on different segments is a design error. Similarly, `192.168.50.128/26` (.128-.191) and `192.168.50.176/28` (.176-.191) overlap, since .176 is within .128-.191.

What an overlap does in a live network:

- Two interfaces on the **same router** cannot overlap: Cisco IOS rejects the second `ip address` with `% 192.168.50.0 overlaps with GigabitEthernet0/0`. (Some platforms also allow it only with `ip address ... secondary`, which is a deliberate design.)
- On **different routers**, overlapping prefixes are accepted. Traffic follows the most specific route (longest prefix match), so hosts in the covered /25 may be reachable while a part of the /26's real hosts is routed the wrong way. The symptom is intermittent, destination-dependent failure that is miserable to find.
- Duplicate or overlapping address plans between sites commonly appear when two companies merge or a VPN joins sites that both use `192.168.1.0/24`. The fix is renumbering or NAT.

Prevent this with a plan: keep an address table (spreadsheet, IPAM tool or source-controlled file), allocate only from it, and validate it with a script that checks for overlaps (below).

> **Real world:** Allocate from the lowest end of the parent block and leave contiguous free space at the top. A tidy plan lets you **summarize** each site into one route (next lesson), and lets you grow a subnet in place by changing the prefix length to a shorter one, as long as the neighbouring block is still free.

## Planning for growth and for point-to-point links

Pick the prefix with 30-50% headroom for user segments. Use /30 or /31 for point-to-point links and /32 for loopbacks (a router ID, a management address or a BGP update source). Each router-to-router link needs its own subnet; do not reuse a /24 for a 2-host link in a large network, since this is exactly the waste VLSM exists to prevent.

For a hub-and-spoke network with many sites, allocate each site a power-of-two block that holds all of its subnets (a /23, say), so that each site advertises one summary and you can renumber a site's internals without touching the core.

## Lab it yourself

Check a plan for overlaps and compute the leftover space with Python:

```text
$ python3 -c "
import ipaddress as i
plan = ['192.168.50.0/25','192.168.50.128/26','192.168.50.192/27',
        '192.168.50.224/28','192.168.50.240/30','192.168.50.244/30']
nets = [i.ip_network(p) for p in plan]
print('overlap:', any(a.overlaps(b) for k,a in enumerate(nets) for b in nets[k+1:]))
parent = i.ip_network('192.168.50.0/24')
free = [parent]
for n in nets:
    free = [x for f in free for x in (f.address_exclude(n) if n.subnet_of(f) else [f])]
print('free:', sorted(free))"
```

It prints `overlap: False` and `free: [IPv4Network('192.168.50.248/29')]`. Now change `192.168.50.128/26` to `192.168.50.64/26` and it prints `overlap: True`. On a router lab, give GigabitEthernet0/0 `192.168.50.1 255.255.255.128` and then try GigabitEthernet0/1 `192.168.50.65 255.255.255.192` to watch IOS refuse the overlap. Build the whole plan on a router with loopbacks, one per subnet, and run `show ip route connected` to confirm every prefix is present and distinct.

## Key takeaways

- VLSM gives each subnet the prefix it needs from one parent block; it requires routing protocols that carry the mask.
- Allocate largest-first, aligning each subnet on a multiple of its block size.
- A /N subnet's network address must be a multiple of its block size; otherwise it is a host address inside another subnet.
- Prefixes nest or are disjoint; if one block contains the other's network address they overlap, which is a design error.
- IOS rejects overlapping subnets on one router; overlaps between routers silently cause longest-match surprises.
- Count the router interface in host requirements, leave headroom and a free tail, and keep the plan in a table.
- Use /30 (or /31) for links and /32 for loopbacks.
