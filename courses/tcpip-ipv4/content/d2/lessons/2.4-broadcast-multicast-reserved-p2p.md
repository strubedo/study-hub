## 0.0.0.0: "this host" and "this network"

The IANA registry reserves `0.0.0.0/8` as "this network" (RFC 791) and the single address `0.0.0.0/32` as "this host on this network" (RFC 1122, section 3.2.1.3). The address is only valid as a **source**, used by a host that does not yet know its own address, and never as a destination you send to. You will see it in four places:

- **DHCP Discover and Request**: a client without an address sends from `0.0.0.0` (UDP port 68) to `255.255.255.255` (UDP port 67).
- **Listening sockets**: a server bound to `0.0.0.0:443` accepts connections on every local address.
- **The default route**: `0.0.0.0/0` has a prefix length of zero, so it matches every destination and, being the shortest prefix, loses to every more specific route. In `ip route` the same route shows as `default via 192.0.2.1`. In Cisco IOS it is `ip route 0.0.0.0 0.0.0.0 192.0.2.1`.
- **ACLs and policies**: `any` is `0.0.0.0 255.255.255.255` in wildcard notation.

> **Exam tip:** `0.0.0.0` (an address) and `0.0.0.0/0` (the whole IPv4 space) are different things. The first identifies "unspecified source"; the second is a prefix that matches everything.

## Limited broadcast: 255.255.255.255

`255.255.255.255` is the **limited broadcast** address (RFC 919, section 7): "all hosts on **this** network". A router **never forwards** it, because it is defined as local to the sender's link. On Ethernet it is sent to MAC `ff:ff:ff:ff:ff:ff`, so every device in the VLAN (the broadcast domain from domain 1) must process the frame. Hosts use it before they know their own subnet, which is why DHCP uses it.

Because routers don't forward it, a DHCP client and server on different subnets need a **relay agent**. On Cisco, `ip helper-address 10.0.0.5` on the client-facing interface makes the router receive the broadcast and forward it as a **unicast** to the server. (The same helper also relays several other UDP broadcast services by default, so check which ones before you rely on it.)

## Directed broadcast

A **directed broadcast** has all host bits set to 1 for a specific subnet. For `192.0.2.0/24` it is `192.0.2.255`; for `192.0.2.64/26` it is `192.0.2.127`. A router attached to that subnet converts the packet into a link-layer broadcast. The calculation is the broadcast address from the subnetting lessons.

Directed broadcasts used to be forwarded across the Internet by default. That made them a weapon: in the **smurf attack**, an attacker sent ICMP echo requests with the victim's spoofed source address to a directed broadcast, and every host on that subnet replied to the victim. RFC 2644 changed the rule: a router must have an option to disable forwarding of directed broadcasts, and that option **must default to disabled**. Cisco IOS has done this since the 12.0 era with the interface command `no ip directed-broadcast` as the default; check it with `show ip interface <int>`, which prints "Directed broadcast forwarding is disabled". Enable `ip directed-broadcast` only for a specific legacy need (and then with an ACL).

Directed broadcast and limited broadcast reach different audiences. The limited form stays on the sender's own link. The directed form can target a remote subnet, but only if routers forward it, which they don't by default.

## Multicast: 224.0.0.0/4

`224.0.0.0/4` (224.0.0.0-239.255.255.255, first four bits `1110`) is **multicast** (RFC 1112). Addresses in this range are group identifiers: they appear as destinations only. Hosts join a group using **IGMP**; IPv4 multicast maps onto Ethernet MAC addresses `01:00:5e` + the low 23 bits of the group. The registry and RFC 5771 divide the space:

| Range | Purpose |
|---|---|
| `224.0.0.0/24` | Local network control block: **not forwarded** off the link (TTL 1 in practice) |
| `224.0.1.0/24` | Internetwork control block (for example NTP `224.0.1.1`) |
| `232.0.0.0/8` | Source-specific multicast (SSM) |
| `233.0.0.0/8` | GLOP: addresses derived from an AS number |
| `239.0.0.0/8` | Administratively scoped (private to an organisation, RFC 2365) |

Memorise the local control addresses that routing protocols and first-hop redundancy protocols use:

| Address | Meaning |
|---|---|
| `224.0.0.1` | All systems on this subnet |
| `224.0.0.2` | All routers on this subnet (also HSRPv1) |
| `224.0.0.5` | OSPF all routers |
| `224.0.0.6` | OSPF designated routers |
| `224.0.0.9` | RIPv2 |
| `224.0.0.10` | EIGRP |
| `224.0.0.13` | PIM routers |
| `224.0.0.18` | VRRP |
| `224.0.0.22` | IGMPv3 |
| `224.0.0.102` | HSRPv2 |
| `224.0.0.251` | mDNS |

Because the whole `224.0.0.0/24` block is link-local scope, an OSPF Hello to `224.0.0.5` never crosses a router, no matter what the routing table says. In a capture, a destination of `224.0.0.5` tells you immediately it is OSPF; `224.0.0.251` is mDNS (Bonjour/Avahi); `239.255.255.250` is SSDP (UPnP).

A multicast address can never be a source address. If you see one as a source, the packet is spoofed or broken.

## Reserved space: 240.0.0.0/4

`240.0.0.0/4` (240.0.0.0-255.255.255.255) is **reserved** (RFC 1112, section 4; the old "Class E"). It was set aside for future use and never assigned. Hosts and routers are not expected to forward it, and it is useless on the Internet. The single exception inside it is `255.255.255.255`, the limited broadcast above. Recognise this block in a question: an address whose first octet is 240-254 is reserved, not a usable host address.

## /31 point-to-point links (RFC 3021)

An ordinary subnet wastes two addresses on a point-to-point link: a /30 has four addresses but only two usable. RFC 3021 allows a **/31** (mask `255.255.255.254`) on point-to-point links, where **both addresses are usable host addresses** and there is no network or broadcast address. There's no one else on the link to broadcast to, since a point-to-point link has only two ends. Router links across a large network save half their address space.

```text
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip address 10.0.0.0 255.255.255.254
R2(config)# interface GigabitEthernet0/1
R2(config-if)# ip address 10.0.0.1 255.255.255.254
```

`10.0.0.0` and `10.0.0.1` are both host addresses. Use it only on true point-to-point links (serial, a routed Ethernet link between two routers), and confirm both ends and your monitoring tools handle /31. When in doubt, /30 is the compatible default. Don't apply the 2^h - 2 formula to a /31: it would give 0.

## /32 host routes

A **/32** prefix identifies exactly one address. It is used in several places:

- **Loopback interfaces**: a router's `Loopback0` is conventionally a /32 (router ID, management address, BGP/iBGP source).
- **IOS local routes**: in the routing table, `L 192.168.10.65/32` is the router's own address on that interface. `C` is the connected subnet.
- **Static host routes**: `ip route 192.0.2.99 255.255.255.255 198.51.100.2` sends one destination to a particular next hop.
- **Black-hole routes**: `ip route 203.0.113.50 255.255.255.255 Null0` silently drops traffic to one address (used in remote-triggered blackholing).
- **Longest-prefix match**: a /32 is the most specific route possible, so it always wins over any shorter prefix covering the same address.

> **Watch out:** The mask `255.255.255.255` on a host interface means it considers every other address off-link and sends everything via its gateway or a route. That is intentional for loopbacks and some tunnel/VPN endpoints, and a bug on a LAN.

## Lab it yourself

Classify a handful of destinations quickly with Python, then capture the real thing:

```text
$ python3 -c "
import ipaddress as i
for a in ['224.0.0.5','239.255.255.250','240.0.0.1','255.255.255.255','0.0.0.0']:
    x = i.ip_address(a)
    print(a, 'multicast' if x.is_multicast else '', 'unspecified' if x.is_unspecified else '', 'reserved' if x.is_reserved else '')"
```

In Wireshark, filter `ip.dst == 224.0.0.0/4` on a LAN with a router, then spot OSPF Hellos (`224.0.0.5`), mDNS (`224.0.0.251`) and IGMP membership reports (the reports go to the group's own address; IGMPv3 reports go to `224.0.0.22`). Filter `bootp` to see DHCP Discover from `0.0.0.0` to `255.255.255.255`. On a Cisco router, `show ip interface GigabitEthernet0/0 | include broadcast` shows the directed-broadcast setting, `show ip igmp groups` the joined groups and `show ip ospf neighbor` the neighbours found via 224.0.0.5. Build a two-router lab with a /31 between them and check that `ping` and `show ip route connected` behave (`C 10.0.0.0/31` and `L 10.0.0.0/32` on the first router).

## Key takeaways

- `0.0.0.0` is a source-only "unspecified" address (DHCP, listening sockets); `0.0.0.0/0` is the default route that matches all destinations.
- `255.255.255.255` is the limited broadcast: local link only, never forwarded; use a relay (`ip helper-address`) for DHCP across routers.
- A directed broadcast sets all host bits to 1 for a remote subnet; modern routers do not forward it by default (RFC 2644, `no ip directed-broadcast`).
- Multicast is `224.0.0.0/4` (destination only); `224.0.0.0/24` is link-local control traffic never forwarded (OSPF 224.0.0.5/.6, EIGRP .10, VRRP .18).
- `240.0.0.0/4` is reserved (former Class E); `255.255.255.255` is the only in-use address inside it.
- A /31 (RFC 3021) gives two usable addresses on a point-to-point link; a /32 is a single host, loopback or host route.
- Neither 2^h - 2 nor "first and last address are reserved" applies to /31 and /32.
