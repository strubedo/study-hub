## An IPv4 address is a 32-bit number

An IPv4 address (RFC 791) is a single 32-bit unsigned integer. People write it as four 8-bit **octets** in decimal separated by dots, so that 11000000 10101000 00001010 01001101 becomes `192.168.10.77`. The dots are only a reading aid: the router sees one number, 3 232 238 157 in decimal or `0xC0A80A4D` in hex. Every subnetting skill in this domain is a manipulation of those 32 bits, so fluency in binary is the foundation.

There are 2^32 = 4 294 967 296 possible addresses. Each octet holds 0 to 255 because 8 bits give 2^8 = 256 values. An "octet" is the precise word (a byte is almost always eight bits today, but RFCs say octet to remove doubt).

## Binary place values

Within one octet the bit weights, from the most significant bit (left) to the least significant (right), are:

| Bit position | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|---|---|---|---|---|---|---|---|---|
| Place value | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

Memorise this row; every mask and block size derives from it. The running totals from the left are also worth memorising, because they are exactly the values a subnet mask octet can take:

| Leading 1 bits | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| Octet value | 0 | 128 | 192 | 224 | 240 | 248 | 252 | 254 | 255 |

A mask octet can only be one of these nine values, because a valid subnet mask is a run of 1s followed by a run of 0s (more on that in the masks lesson).

## Decimal to binary

Use the **subtract-the-place-value** method. Convert 77:

1. 128 does not fit in 77, so that bit is 0.
2. 64 fits: bit is 1, remainder 77 - 64 = 13.
3. 32 does not fit in 13: 0. 16 does not fit: 0.
4. 8 fits: 1, remainder 5.
5. 4 fits: 1, remainder 1.
6. 2 does not fit: 0. 1 fits: 1, remainder 0.

Reading the bits left to right: `01001101`. Check by adding the weights that are set: 64 + 8 + 4 + 1 = 77.

Do the same for 192 (128 + 64 = `11000000`), 168 (128 + 32 + 8 = `10101000`) and 10 (8 + 2 = `00001010`). Together they spell out `192.168.10.77` as `11000000.10101000.00001010.01001101`. Another useful example from the documentation block: 203 = 128 + 64 + 8 + 2 + 1 = `11001011`, and 113 = 64 + 32 + 16 + 1 = `01110001`.

Always pad to eight bits. Writing 10 as `1010` instead of `00001010` is the most common cause of misaligned subnetting on paper.

## Binary to decimal

Add the place values of every bit that is 1. `10101100` = 128 + 32 + 8 + 4 = 172. A shortcut for the common "all ones from the left" patterns is to subtract: `11111000` is 255 - 7 = 248, because the three trailing zeros make 2^3 - 1 = 7 missing.

> **Exam tip:** In a mask octet, the value equals 256 minus the **block size**. `11111000` (248) has three zero bits, so the block size is 2^3 = 8 and 256 - 8 = 248. This identity is the heart of the block-size method taught later.

## Hexadecimal

Hex is base 16 with digits 0-9 and A-F (A = 10 ... F = 15). One hex digit is exactly four bits (a **nibble**), so one octet is exactly two hex digits. That makes hex the natural way to read raw packet bytes in Wireshark or a header dump.

| Hex | Binary | Dec | Hex | Binary | Dec |
|---|---|---|---|---|---|
| 0 | 0000 | 0 | 8 | 1000 | 8 |
| 1 | 0001 | 1 | 9 | 1001 | 9 |
| 2 | 0010 | 2 | A | 1010 | 10 |
| 3 | 0011 | 3 | B | 1011 | 11 |
| 4 | 0100 | 4 | C | 1100 | 12 |
| 5 | 0101 | 5 | D | 1101 | 13 |
| 6 | 0110 | 6 | E | 1110 | 14 |
| 7 | 0111 | 7 | F | 1111 | 15 |

To convert an octet to hex, split it into two nibbles. `192` = `1100 0000` = `C0`. `168` = `1010 1000` = `A8`. `10` = `0000 1010` = `0A`. `77` = `0100 1101` = `4D`. So `192.168.10.77` is `C0 A8 0A 4D` or `0xC0A80A4D`. In the other direction, `0x7F000001` is `7F` = 127, `00` = 0, `00` = 0, `01` = 1, which is `127.0.0.1`.

For a single octet, the decimal-to-hex formula is: high digit = integer part of n / 16, low digit = n mod 16. For 203: 203 / 16 = 12 remainder 11, so `CB`. You will meet hex constantly in packet analysis: the IPv4 header's first byte is `45` (version 4, IHL 5) and an Ethernet type of `0x0800` marks IPv4.

> **Real world:** Cisco IOS, Linux and Windows show masks in dotted decimal by default (Linux `ip addr` uses prefix length), but the BSD and macOS `ifconfig` prints `netmask 0xffffff00`. Being able to read `0xffffffc0` as /26 (twenty-six 1 bits: `ff ff ff` = 24, `c0` = two more) saves time.

## Why this matters for subnetting

The mask, the address and the network address are all 32-bit values, and combining them is a **bitwise AND** (the masks lesson). The block-size method is only a decimal shortcut for what is really bit arithmetic. When a problem looks ambiguous in decimal, write the interesting octet in binary and the answer is usually obvious: the network portion is wherever the mask has 1s.

## Lab it yourself

On any Linux box (or WSL), check your conversions with the shell and Python. None of this touches the network.

```text
$ printf '%d\n' 0xC0A80A4D
3232238157
$ python3 -c "print(format(77,'08b'), format(203,'08b'), hex(203))"
01001101 11001011 0xcb
$ python3 -c "import ipaddress as i; print(int(i.ip_address('192.168.10.77')), hex(int(i.ip_address('192.168.10.77'))))"
3232238157 0xc0a80a4d
$ python3 -c "import ipaddress as i; print(i.ip_address(0xC0A80A4D))"
192.168.10.77
```

Practice drill: take your own LAN address from `ip -4 addr` (Linux) or `ipconfig` (Windows), convert all four octets to binary by hand, then to hex, and confirm with the commands above. In Wireshark, open any capture, select the IPv4 header and look at the hex pane: the source address is bytes 12-15 of the header, and you can read the octets in the hex dump directly. On a Cisco router, `show ip interface brief` lists the addresses and `show running-config interface` the masks, giving you more numbers to convert.

## Key takeaways

- An IPv4 address is one 32-bit number written as four octets; there are 2^32 = 4 294 967 296 addresses.
- Octet place values are 128, 64, 32, 16, 8, 4, 2, 1; always write all eight bits.
- A mask octet is one of 0, 128, 192, 224, 240, 248, 252, 254, 255, and equals 256 minus the block size.
- One hex digit is a nibble (4 bits); one octet is two hex digits, so `192.168.10.77` is `C0 A8 0A 4D`.
- Convert decimal to binary by subtracting place values from the left; convert back by adding the weights of the 1 bits.
- Hex is how packet dumps show addresses; being fluent saves time in Wireshark.
- The block-size method is decimal shorthand for bitwise AND on these 32 bits.
