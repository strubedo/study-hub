## What a subnet mask does

Every IPv4 interface address comes with a **subnet mask** that says which bits identify the network and which identify the host. Wherever the mask has a 1, the bit belongs to the **network (prefix) portion**; wherever it has a 0, the bit belongs to the **host portion**. Under CIDR (RFC 4632) the mask is a contiguous run of 1s followed by 0s, so it can be abbreviated as the number of 1 bits: the **prefix length**. The address `192.168.10.77` with mask `255.255.255.192` is written `192.168.10.77/26`, because 255.255.255.192 is `11111111.11111111.11111111.11000000`: twenty-six 1 bits.

A mask that is not a solid run of 1s then 0s (for example `255.255.255.250`, which is `...11111010`) is invalid for an interface. Standard hosts and routers reject it, and CIDR notation cannot express it.

### The mask table

Because a mask octet is a leading run of 1s, only nine values occur: 0, 128, 192, 224, 240, 248, 252, 254, 255. Learn the table below until it is automatic.

| Prefix | Mask | Host bits | Block size | Usable hosts |
|---|---|---|---|---|
| /24 | 255.255.255.0 | 8 | 256 | 254 |
| /25 | 255.255.255.128 | 7 | 128 | 126 |
| /26 | 255.255.255.192 | 6 | 64 | 62 |
| /27 | 255.255.255.224 | 5 | 32 | 30 |
| /28 | 255.255.255.240 | 4 | 16 | 14 |
| /29 | 255.255.255.248 | 3 | 8 | 6 |
| /30 | 255.255.255.252 | 2 | 4 | 2 |
| /31 | 255.255.255.254 | 1 | 2 | 2 (point-to-point only, RFC 3021) |
| /32 | 255.255.255.255 | 0 | 1 | 1 (a single host or route) |

Beyond /24, the pattern repeats one octet to the left: /23 is 255.255.254.0 (block size 2 in the third octet, 510 hosts), /22 is 255.255.252.0 (block 4, 1022 hosts), /21 is 255.255.248.0 (block 8, 2046), /20 is 255.255.240.0 (block 16, 4094), /16 is 255.255.0.0 (65 534). The complete /8-/32 table is in the Reference section.

To convert a prefix length to a mask, write that many 1s left to right, split into octets and convert. /20 = 8 + 8 + 4 ones = `255.255.240.0`. /27 = 24 + 3 = `255.255.255.224`. To convert a mask back, count the 1 bits: 255.255.248.0 = 8 + 8 + 5 = /21.

## Hosts per subnet and subnets per block

If a subnet has **h** host bits, it contains 2^h addresses. Two are reserved in ordinary subnets, the **network address** (host bits all 0) and the **directed broadcast address** (host bits all 1), leaving

**usable hosts = 2^h - 2**

A /26 has h = 32 - 26 = 6, so 2^6 - 2 = 62. A /29 has 3 host bits, so 8 - 2 = 6. A /18 has 14, so 16 384 - 2 = 16 382.

Subnetting borrows bits from a larger block. If you split a /24 by borrowing **b** bits, the result is

**number of subnets = 2^b**, each with prefix length 24 + b

Borrow 3 bits (a /27): 2^3 = 8 subnets of 32 addresses (30 usable). Borrow 4 (a /28): 16 subnets of 16 addresses (14 usable). More generally, the number of /N subnets inside a larger /M block is 2^(N - M). So a /20 holds 2^(26-20) = 64 subnets of size /26.

The trade-off is fixed: each extra network bit doubles the subnet count and roughly halves the hosts per subnet.

> **Exam tip:** The 2^h - 2 rule fails at the extremes. A /31 has 2 addresses and both are usable on a point-to-point link (RFC 3021), and a /32 is one address with no network or broadcast concept. Always check the prefix length is <= /30 before applying -2.

**Subnet zero and the all-ones subnet.** The original RFC 950 discouraged the first subnet (host and subnet bits both 0) and the last one. Modern practice (RFC 1812 for routers, and Cisco IOS by default) uses them freely. Given the 192.168.1.0/24 block split into /26 subnets, all four of `192.168.1.0/26`, `.64/26`, `.128/26` and `.192/26` are valid today.

## The four addresses every subnet question asks for

For a given host address and mask, find:

1. **Network address**: host bits all 0.
2. **Broadcast address**: host bits all 1.
3. **First usable**: network address + 1.
4. **Last usable**: broadcast address - 1.

Usable range = first to last. In `192.168.10.77/26`: network `192.168.10.64`, broadcast `192.168.10.127`, usable `192.168.10.65` to `192.168.10.126`, 62 hosts.

## ANDing a host address with its mask

The network address is the **bitwise AND** of the address and the mask: a result bit is 1 only where both inputs are 1. This is exactly what hosts and routers do in hardware. Octets where the mask is 255 copy the address octet unchanged; octets where the mask is 0 give 0; only the one **interesting octet** (neither 0 nor 255) needs real work.

Take `192.168.10.77` and `255.255.255.192`:

```text
Address   192.168.10.77   11000000.10101000.00001010.01001101
Mask      255.255.255.192 11111111.11111111.11111111.11000000
AND       ----------------------------------------------------
Network   192.168.10.64   11000000.10101000.00001010.01000000
```

Only the last octet changes: `01001101` AND `11000000` = `01000000` = 64. The broadcast address sets every host bit to 1, which is the network address ORed with the **inverted mask** (the wildcard): `01000000` OR `00111111` = `01111111` = 127.

A second example with the interesting octet in the third position: `172.20.99.250` with `255.255.240.0` (/20). The first two octets copy (172.20), the fourth is 0, and the third is `99` = `01100011` AND `240` = `11110000` = `01100000` = 96. Network `172.20.96.0`. The host bits cover the low 4 bits of the third octet and all of the fourth, so the broadcast is `172.20.111.255` (96 + 15 = 111).

### Why ANDing matters in practice

A host decides **local or remote** by ANDing both its own address and the destination with its mask. If the results match, the destination is on-link and the host ARPs for it directly; if not, it sends the frame to its default gateway. This explains a classic fault: a host with `172.16.130.77/25` and a gateway `172.16.130.129` has a gateway in a different subnet (`.128/25` versus `.0/25`) and cannot reach it, so nothing leaves the subnet.

Routers apply the same AND to route entries: a route `192.168.10.64/26` matches any destination whose first 26 bits equal `192.168.10.64`'s first 26 bits.

> **Watch out:** Mask mismatches between neighbours are legal to configure and produce odd one-way failures. Host A at `192.168.1.10/24` and host B at `192.168.1.200/25` disagree about whether the other is local, and traffic may work in one direction only. When one side's answer depends on its own mask, always compute both sides.

## Lab it yourself

Verify your hand calculations with Python's `ipaddress` module, which implements exactly the AND and OR above:

```text
$ python3 -c "
import ipaddress as i
n = i.ip_interface('192.168.10.77/26').network
print(n, n.netmask, n.broadcast_address, n.num_addresses - 2)
print(list(n.hosts())[0], list(n.hosts())[-1])"
192.168.10.64/26 255.255.255.192 192.168.10.127 62
192.168.10.65 192.168.10.126
```

On Linux add an address with `sudo ip addr add 192.168.10.77/26 dev eth0` (use a lab VM or a dummy interface: `sudo ip link add d0 type dummy; sudo ip link set d0 up; sudo ip addr add 192.168.10.77/26 dev d0`) and read the result with `ip -4 addr show d0` and `ip route`. You will see `inet 192.168.10.77/26 brd 192.168.10.127` and a kernel route `192.168.10.64/26 dev d0 proto kernel scope link src 192.168.10.77`: the kernel computed the network and broadcast addresses itself. On Windows, `ipconfig` shows the mask and `route print` the on-link network.

On a Cisco router:

```text
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip address 192.168.10.65 255.255.255.192
R1(config-if)# no shutdown
R1# show ip route connected
C        192.168.10.64/26 is directly connected, GigabitEthernet0/0
L        192.168.10.65/32 is directly connected, GigabitEthernet0/0
```

IOS built the connected route from the address and mask and added the host route. Try configuring a second interface with an overlapping address such as `192.168.10.100 255.255.255.0` and IOS rejects it with `% 192.168.10.0 overlaps with GigabitEthernet0/0`.

## Key takeaways

- A mask is a contiguous run of 1s then 0s; the prefix length is the count of 1s (/26 = 255.255.255.192).
- Valid mask octet values are only 0, 128, 192, 224, 240, 248, 252, 254, 255.
- Usable hosts = 2^h - 2 with h host bits; subnets from borrowed bits = 2^b; /31 and /32 are exceptions.
- Network address = address AND mask; broadcast = network OR wildcard (host bits all 1).
- First usable = network + 1; last usable = broadcast - 1.
- Hosts and routers AND the destination with the mask to decide on-link versus via-gateway.
- A gateway outside the host's own subnet is a mask/gateway design error, not a routing problem.
