## The method in one paragraph

The **block-size method** (the "magic number" method) is a decimal shortcut for ANDing. In the **interesting octet**, the one octet of the mask that is neither 255 nor 0, subnets are consecutive blocks of a fixed size, and the network address is simply the nearest block boundary at or below the host's octet. It works because the block size equals 256 minus the mask octet, and block boundaries are multiples of the block size.

### The five steps

1. **Find the interesting octet**: the first octet from the left whose mask value is not 255. (If the prefix is /8, /16, /24 or /32 there is none, and the network is simply the unchanged leading octets.)
2. **Block size** = 256 - mask value in that octet. (Equivalent: 2 raised to the number of host bits in that octet.)
3. **Network address**: in the interesting octet, take the largest multiple of the block size that is <= the host's octet. Copy the octets to its left. Set the octets to its right to 0.
4. **Broadcast address**: in the interesting octet use network octet + block size - 1. Copy octets to the left. Set octets to its right to 255.
5. **Usable range**: network address + 1 to broadcast - 1.

Prefix lengths convert to the interesting octet like this: /9-/15 use the second octet, /17-/23 the third, /25-/31 the fourth. Inside that octet the mask value is 128, 192, 224, 240, 248, 252, 254 for one to seven network bits respectively.

## Worked examples

### Example 1: 192.168.10.77/26

Mask `255.255.255.192`, interesting octet is the fourth (192). Block size 256 - 192 = 64. Multiples of 64: 0, 64, 128, 192. The largest <= 77 is 64. Network `192.168.10.64`, broadcast `192.168.10.127` (64 + 63). Usable `.65`-`.126`, 62 hosts.

### Example 2: 172.16.45.200/21

/21 = 255.255.248.0, interesting octet is the third (248). Block size 8. Multiples of 8 near 45: 40 (next is 48). Network `172.16.40.0`; broadcast third octet 40 + 7 = 47, remaining octet 255: `172.16.47.255`. Usable `172.16.40.1`-`172.16.47.254`, 2^11 - 2 = 2046 hosts. The fourth octet (200) played no part in the answer because the mask is 0 there.

### Example 3: 10.77.130.9/12

/12 = 255.240.0.0, interesting octet is the second (240). Block size 16. Multiples of 16 near 77: 64 (next is 80). Network `10.64.0.0`, broadcast `10.79.255.255`. Usable `10.64.0.1`-`10.79.255.254`, 2^20 - 2 = 1 048 574 hosts. Notice that `10.70.0.0` and `10.79.1.1` are both ordinary host addresses in this subnet.

### Example 4: 198.51.100.37/29

/29 = 255.255.255.248. Block size 8. 37 lies between 32 and 40, so network `198.51.100.32`, broadcast `198.51.100.39`, usable `.33`-`.38`, six hosts.

### Example 5: 192.168.5.200/23

/23 = 255.255.254.0, interesting octet is the third (254). Block size 2. Multiples of 2 near 5: 4. Network `192.168.4.0`, broadcast `192.168.5.255` (4 + 1 = 5, then 255). Usable `192.168.4.1`-`192.168.5.254`, 510 hosts.

> **Watch out:** In a /23 or larger subnet, addresses ending in .0 and .255 can be perfectly good host addresses. `192.168.4.255` and `192.168.5.0` are both usable in example 5. Only the true all-zeros and all-ones host patterns (`192.168.4.0` and `192.168.5.255`) are reserved. Don't discard addresses by looking at the last octet alone.

### Example 6: a mask in the third octet that is not on a boundary

`203.0.113.45/28`: /28 = 255.255.255.240, block 16, 45 is between 32 and 48, so network `203.0.113.32`, broadcast `203.0.113.47`, usable `.33`-`.46`, 14 hosts.

## Listing every subnet in a block

Splitting `192.168.1.0/24` into /27 subnets (block size 32) just counts by 32:

| # | Network | First usable | Last usable | Broadcast |
|---|---|---|---|---|
| 1 | 192.168.1.0 | .1 | .30 | .31 |
| 2 | 192.168.1.32 | .33 | .62 | .63 |
| 3 | 192.168.1.64 | .65 | .94 | .95 |
| 4 | 192.168.1.96 | .97 | .126 | .127 |
| 5 | 192.168.1.128 | .129 | .158 | .159 |
| 6 | 192.168.1.160 | .161 | .190 | .191 |
| 7 | 192.168.1.192 | .193 | .222 | .223 |
| 8 | 192.168.1.224 | .225 | .254 | .255 |

Each network address is the previous broadcast + 1. Check that they close: the last broadcast, `.255`, is the broadcast of the parent /24. If your count of subnets or the final broadcast is off, you made an arithmetic slip.

## Are two hosts on the same subnet?

Compute the network address of each with its own mask and compare. `192.168.1.100/28` falls in the block 96-111 (network `.96`, broadcast `.111`). `192.168.1.113/28` falls in 112-127. Different subnets: they need a router even though they look adjacent. The same rule applies to a host and its default gateway: the gateway must be inside the host's subnet and must be a **usable** address, not the network or broadcast address.

## Going the other way: from requirements to a mask

**For a host requirement**: pick the smallest h with 2^h - 2 >= hosts, then prefix = 32 - h. 50 hosts: h = 6 gives 62 (h = 5 gives only 30), so /26. 300 hosts: h = 9 gives 510, so /23. Plan for growth: a subnet with 60 devices today fits a /26, but only 2 spare addresses are left.

**For a subnet-count requirement**: pick the smallest b with 2^b >= subnets and borrow b bits. Eight subnets from `10.0.0.0/24` need b = 3, giving /27 subnets with 30 hosts each. Always check that the host side still satisfies the host requirement; if not, the parent block is too small.

Quick sanity table for the fourth octet:

| Hosts needed | Prefix | Block size |
|---|---|---|
| 1-2 (point-to-point) | /30 (or /31) | 4 (or 2) |
| 3-6 | /29 | 8 |
| 7-14 | /28 | 16 |
| 15-30 | /27 | 32 |
| 31-62 | /26 | 64 |
| 63-126 | /25 | 128 |
| 127-254 | /24 | 256 |

> **Exam tip:** Errors in speed-subnetting come from two places: choosing the wrong interesting octet (watch for /17-/23, where the octet is the third) and forgetting that the broadcast is network + block - 1, not network + block. Say "next block minus one" out loud.

## Lab it yourself

Do ten problems on paper, then check with a script. This one-liner prints everything a block-size answer needs:

```text
$ python3 -c "
import ipaddress as i, sys
for s in ['172.16.45.200/21','10.77.130.9/12','192.168.5.200/23','198.51.100.37/29']:
    n = i.ip_interface(s).network
    h = list(n.hosts())
    print(s, '->', n, 'bc', n.broadcast_address, 'range', h[0], h[-1], 'hosts', len(h))"
```

To see the same arithmetic on a router, configure a loopback and inspect the connected route:

```text
R1(config)# interface Loopback10
R1(config-if)# ip address 172.16.45.200 255.255.248.0
R1# show ip route 172.16.45.200
Routing entry for 172.16.40.0/21
  Known via "connected", distance 0, metric 0 (connected, via interface)
```

IOS reports the subnet it derived: `172.16.40.0/21`, exactly the block-size answer. On Linux, `ipcalc 172.16.45.200/21` (package `ipcalc` or `sipcalc`) prints the same network, broadcast and host range, and `ip route get 172.16.45.200` shows which interface and source address the kernel would use. As a drill, generate random addresses and prefixes in the 8-30 range, solve by block size, and check against `ipaddress`. Aim for under 30 seconds per problem; that is the speed you want for troubleshooting.

## Key takeaways

- Block size = 256 - mask value in the interesting octet; block boundaries are multiples of the block size.
- Network = the largest multiple of the block size <= the host octet; broadcast = network + block size - 1.
- Octets left of the interesting octet are copied; octets to the right are 0 (network) or 255 (broadcast).
- Usable range is network + 1 to broadcast - 1; a /23 or larger can contain host addresses ending in .0 or .255.
- Two hosts are on the same subnet only if their network addresses (each with its own mask) match.
- For N hosts choose the smallest h with 2^h - 2 >= N; for S subnets borrow b bits with 2^b >= S, then recheck hosts.
- Cross-check with `ipaddress`, `ipcalc` or `show ip route`; never trust one pass at 3 a.m.
