## Classful addressing: how it began

The original IPv4 specification (RFC 791, 1981) split the 32 bits into a **network part** and a **host part** using the first bits of the address to decide where the split falls. This is **classful addressing**. The network part identified an organisation; the host part identified a device in it.

| Class | Leading bits | First octet | Default boundary | Networks | Addresses per network |
|---|---|---|---|---|---|
| A | `0` | 0-127 | /8 (N.H.H.H) | 128 (0 and 127 reserved) | 16 777 216 (2^24) |
| B | `10` | 128-191 | /16 (N.N.H.H) | 16 384 | 65 536 (2^16) |
| C | `110` | 192-223 | /24 (N.N.N.H) | 2 097 152 | 256 |
| D | `1110` | 224-239 | none (multicast) | - | - |
| E | `1111` | 240-255 | none (reserved) | - | - |

Read the class from the **leading bits** of the first octet, not from memory of ranges: `150` is `10010110`, which starts `10`, so it is Class B. `192` is `11000000`, which starts `110`, so it is Class C. The ranges follow directly: with `0` as the first bit the octet is at most `01111111` = 127; with `10` it runs `10000000`-`10111111` = 128-191; with `110` it runs `11000000`-`11011111` = 192-223; with `1110` it runs 224-239.

Class D (multicast) was defined in RFC 1112 and has no network/host split. Class E was set aside as reserved for experimental use and was never opened up for ordinary assignment; it is still the block `240.0.0.0/4`.

### Why classes broke

Three sizes were too coarse. A company needing 500 hosts was too big for a Class C (254 usable hosts) and received a Class B holding 65 534 usable addresses, wasting about 99%. This drained the Class B space within a few years and left a flood of Class C networks that each needed its own routing table entry, so the global routing table grew faster than router memory.

Two fixes arrived in sequence:

1. **Subnetting** (RFC 950, 1985) let an organisation borrow bits from the host part to split its own network into smaller subnets. It was still classful on the outside: the Internet saw the whole Class B. RFC 950 also warned against the all-zeros and all-ones subnets; this was relaxed later and modern equipment uses them (Cisco IOS treats "subnet zero" as usable by default through `ip subnet-zero`).
2. **Variable-length subnet masks** (VLSM, supported by routing protocols that carry the mask, such as OSPF, EIGRP and RIPv2) allowed different subnets of one network to have different sizes. Older classful protocols, RIPv1 and IGRP, did not carry masks and could not do this.

## CIDR: classless inter-domain routing

**CIDR** (introduced in RFCs 1518 and 1519 in 1993 and now specified in **RFC 4632**) abolished the class boundaries for routing and allocation. An address block is a **prefix**: an address plus a prefix length, written `192.0.2.0/24` or `198.51.100.64/26`. The prefix length is the number of leading bits that identify the network, so any length from /0 to /32 is possible. Two consequences changed the Internet:

- **Right-sized allocation.** A site needing 500 hosts receives a /23 (510 usable) rather than a Class B.
- **Aggregation.** An ISP holding a /16 announces that one route for all its customers instead of hundreds of Class C routes. Routers pick the **longest matching prefix**, so a more specific route still wins when it exists.

After CIDR, "Class A/B/C" survives only as a way to talk about legacy default masks (`/8`, `/16`, `/24`) and in some certification exam vocabulary. Modern hosts and routers carry an explicit mask or prefix length with every address, and routing lookups ignore the class. Cisco IOS has been classless by default for years (`ip classless`).

> **Watch out:** "Classful" and "classless" also describe routing-protocol behaviour. Some legacy configurations auto-summarize routes at classful boundaries (older EIGRP and RIP defaults; check `no auto-summary` on whatever IOS you run). That can silently break discontiguous subnets even though CIDR has been universal for decades.

IANA allocated its last free IPv4 /8 blocks to the regional registries on 3 February 2011, and APNIC was the first RIR to hit its final /8 in April 2011. Every IPv4 prefix handed out since then is a recycled or transferred one, which is why NAT and carrier-grade NAT (the `100.64.0.0/10` block, covered later) are everywhere.

> **Exam tip:** If a question mentions "Class C" and then gives a /26 mask, the class tells you nothing about the mask. The mask given is the truth. Don't assume /24 just because the first octet is 192.

## Types of IPv4 destination address

Whatever the prefix length, the **destination address** in a packet falls into one of three delivery models.

| Type | Delivered to | Identification | Example |
|---|---|---|---|
| **Unicast** | One interface | Any address outside the two special groups below | `192.0.2.10` |
| **Broadcast** | All hosts on a subnet (or link) | Host bits all 1 (directed), or `255.255.255.255` (limited) | `192.0.2.255` (in 192.0.2.0/24) |
| **Multicast** | A group of interested receivers | `224.0.0.0/4` (first four bits `1110`) | `224.0.0.5`, `239.1.1.1` |

There is also **anycast**: the same unicast address advertised from several places so the network delivers to the nearest. It is a routing technique, not a separate address format. For example, DNS root servers use it.

**Unicast** is the default. A host's unicast address is the subnet's network bits plus a unique host value; the network address (host bits all 0) and the directed broadcast address (host bits all 1) are not assignable to hosts in ordinary subnets.

**Broadcast** exists in two forms. The **limited broadcast** `255.255.255.255` is never forwarded by a router and reaches only the local link. A **directed broadcast** such as `192.0.2.255` targets every host in a particular remote subnet; routers do not forward these by default today (RFC 2644). On Ethernet both map to the broadcast MAC `ff:ff:ff:ff:ff:ff`.

**Multicast** addresses are group identifiers, never the source of a packet. A host joins a group with IGMP, and the switch/router delivers copies only toward interested receivers. Section 2.4 covers the useful ranges. The IPv4 multicast MAC mapping you met in domain 1 (`01:00:5e` plus the low 23 bits) is why 32 groups share each MAC.

A quick classifier for any destination you see in a capture: look at the first octet. 224-239 is multicast, `255.255.255.255` is limited broadcast, host bits all 1 for the interface's subnet is a directed broadcast, and everything else is unicast (subject to the special-purpose blocks in lesson 2.4).

## Lab it yourself

Classify addresses with Python and see what the interpreter already knows:

```text
$ python3 -c "
import ipaddress as i
for a in ['10.0.0.1','150.1.1.1','192.0.2.1','224.0.0.5','239.1.1.1','240.0.0.1','255.255.255.255']:
    x = i.ip_address(a)
    print(a, 'multicast' if x.is_multicast else 'reserved' if x.is_reserved else 'unicast-ish')
"
```

On a Linux host, `ip -4 addr` shows `brd 192.0.2.255` on an Ethernet interface: that is the directed broadcast for the interface's subnet. Ping it with `ping -b 192.0.2.255` (you may need `sysctl net.ipv4.icmp_echo_ignore_broadcasts=0` on the targets; most modern systems ignore it by default). In Wireshark, filter `ip.dst == 255.255.255.255` while you renew a DHCP lease to see a limited broadcast, and `ip.dst == 224.0.0.0/4` on a LAN with routing protocols to see multicast control traffic. On a Cisco router, `show ip interface GigabitEthernet0/0` displays "Directed broadcast forwarding is disabled" by default.

## Key takeaways

- Classful addressing derived the network/host split from the leading bits: A `0`, B `10`, C `110`, D `1110` (multicast), E `1111` (reserved).
- Classes wasted addresses (a 500-host site took a /16) and bloated routing tables, so CIDR (RFC 4632) replaced them with variable-length prefixes.
- Subnetting (RFC 950) borrowed host bits; VLSM allowed different mask lengths in one network and needs a protocol that carries masks.
- With CIDR, the mask or prefix length given is always authoritative; the class of the first octet is irrelevant.
- IPv4 destinations are unicast, broadcast (limited or directed) or multicast; multicast is `224.0.0.0/4`.
- The 2011 exhaustion of free IANA blocks is why NAT, CGN and address transfers dominate IPv4 operations.
