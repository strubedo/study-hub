## Why NAT exists

Network Address Translation rewrites IPv4 addresses (and for PAT, port numbers) in packets as they cross a boundary. It was created to stretch the IPv4 address space: many hosts using private RFC 1918 addresses share a few public ones. RFC 2663 defines the terminology and RFC 3022 specifies **Traditional NAT**, which has two flavours.

| RFC term | What is translated | Cisco / common name |
|---|---|---|
| **Basic NAT** | IP address only; each inside host gets its own outside address from a block | Static NAT or dynamic NAT |
| **NAPT** (Network Address Port Translation) | IP address and TCP/UDP port (or ICMP query ID); many inside hosts share one outside address | PAT, "overload", masquerade |
| **Twice NAT** | Both source and destination addresses are rewritten | Used when inside and outside address spaces overlap (RFC 2663) |

NAT is **stateful**: the first packet of a flow creates a mapping in a translation table, and later packets (and the return traffic) are translated by looking it up. Mappings expire after an idle period, so a long-lived idle connection can silently lose its mapping.

## Static NAT, dynamic NAT and PAT

**Static NAT** is a permanent one-to-one mapping between an inside address and an outside address. It is bidirectional: an outside client can start a connection to the public address and reach the inside server. Use it for servers that must be reachable.

**Dynamic NAT** maps inside hosts to addresses taken from a **pool** on demand, still one-to-one while a mapping exists. When the pool is exhausted the next host's packets are dropped until a mapping times out. It is rarely chosen today because it saves few addresses.

**PAT (NAT overload)** maps many inside hosts to **one** outside address, telling the sessions apart by the translated source port. This is what a home router or a branch edge does. The capacity is bounded by available ports (roughly 64,000 per address per protocol); a busy network can exhaust ports on a single address, and the cure is a bigger pool of overload addresses.

```text
Inside 10.1.1.10:49152  -> 198.51.100.10:80      before NAT
Outside 203.0.113.2:1024 -> 198.51.100.10:80      after NAT (source rewritten)
Return  198.51.100.10:80 -> 203.0.113.2:1024      reverse translation
Inside  198.51.100.10:80 -> 10.1.1.10:49152       delivered
```

Cisco IOS configuration of each:

```text
R1(config)# interface GigabitEthernet0/0
R1(config-if)# ip nat inside
R1(config)# interface GigabitEthernet0/1
R1(config-if)# ip nat outside

! Static one-to-one
R1(config)# ip nat inside source static 10.1.1.20 203.0.113.20

! Dynamic from a pool
R1(config)# ip nat pool PUB 203.0.113.10 203.0.113.14 netmask 255.255.255.0
R1(config)# access-list 1 permit 10.1.1.0 0.0.0.255
R1(config)# ip nat inside source list 1 pool PUB

! PAT using the outside interface address
R1(config)# ip nat inside source list 1 interface GigabitEthernet0/1 overload
```

The ACL here does not filter traffic; it only **selects which inside sources are eligible** for translation. On Linux the equivalent of the last line is `sudo iptables -t nat -A POSTROUTING -s 10.1.1.0/24 -o eth1 -j MASQUERADE` (or `-j SNAT --to-source 203.0.113.2` for a fixed address, or `nft add rule ip nat postrouting oifname "eth1" masquerade`), with `net.ipv4.ip_forward=1`.

## Inside and outside, local and global

Cisco's four-term vocabulary names an address by **where the device lives** (inside or outside the translating router) and **from whose point of view** the address is seen (local = as seen on the inside network, global = as seen on the outside network).

| Term | Meaning | In a typical outbound PAT flow |
|---|---|---|
| **Inside local** | Address of an inside host as configured on the inside network | 10.1.1.10 |
| **Inside global** | The inside host as seen from the outside | 203.0.113.2 |
| **Outside local** | An outside host as seen from the inside | 198.51.100.10 |
| **Outside global** | The outside host's real address on the outside network | 198.51.100.10 |

For ordinary internet access the outside local and outside global are the same, because only the inside is translated. They differ only when the **outside** is also translated (overlapping address ranges and twice NAT). These four terms come from Cisco's NAT documentation; RFC 2663 and RFC 3022 do not define them under these names, so do not cite them as RFC terms.

```text
R1# show ip nat translations
Pro Inside global      Inside local       Outside local      Outside global
tcp 203.0.113.2:1024   10.1.1.10:49152    198.51.100.10:80   198.51.100.10:80
tcp 203.0.113.2:1025   10.1.1.11:52311    198.51.100.10:80   198.51.100.10:80
--- 203.0.113.20       10.1.1.20          ---                ---
```

Read it left to right: the first column is what the outside world sees as the source (inside global), the second is the real inside host (inside local). The `---` row is a **simple** (address-only) entry such as the static mapping; PAT entries include ports and protocol. On Linux the equivalent view is the connection-tracking table:

```text
$ sudo conntrack -L
tcp 6 119 TIME_WAIT src=10.1.1.10 dst=203.0.113.1 sport=36572 dport=80 src=203.0.113.1 dst=203.0.113.2 sport=80 dport=36572 [ASSURED]
```

The first tuple is the original direction; the second shows what the reply looks like after translation (the reply is addressed to the translated source 203.0.113.2). Note that Linux tries to **preserve** the original source port when it is free, so the port often does not change.

## What the NAT device actually changes

- On a packet leaving the inside, it replaces the source IP (and the source port for PAT, or the ICMP query identifier) with the mapping values and **recomputes the IP header checksum and the TCP/UDP checksum**, because the TCP/UDP checksum covers a pseudo-header containing the addresses (RFC 3022 describes incremental checksum adjustment).
- On the return packet it reverses the mapping, rewriting the destination.
- ICMP errors that refer to a translated flow carry a copy of the original header inside; a correct NAT must translate that embedded header too, or traceroute and PMTUD through it break.
- Cisco processes **inside-to-outside** traffic by routing first, then translating, and **outside-to-inside** traffic by translating first, then routing. Thus the router needs a route to the inside global address and to the post-translation inside local address.

Timers matter: RFC 4787 requires a UDP mapping not to expire in under 2 minutes and recommends 5 minutes or more as the default, and RFC 5382 requires an established-TCP idle timeout of at least 2 hours 4 minutes. Cisco IOS names its timers `udp-timeout`, `tcp-timeout`, `dns-timeout`, `finrst-timeout`, `syn-timeout`, `icmp-timeout` and so on (`ip nat translation <name> <seconds>`); the default values vary by release, so check the documentation for yours.

> **Exam tip:** PAT distinguishes sessions by port; Basic NAT cannot, so it needs one outside address per concurrent inside host. "Overload" in IOS means PAT.

> **Watch out:** NAT is not a firewall. A static NAT entry exposes the inside host to the whole outside. Dynamic and PAT mappings block unsolicited inbound traffic only as a side effect of having no mapping, and that side effect disappears as soon as a mapping exists or a port-forward is added. Put an explicit stateful firewall policy in front.

## Lab it yourself

1. Build a three-namespace lab on Linux (`lan` 10.1.1.10, `gw` 10.1.1.1 and 203.0.113.2, `wan` 203.0.113.1) using `ip netns add` and veth pairs, enable `net.ipv4.ip_forward`, add `iptables -t nat -A POSTROUTING -s 10.1.1.0/24 -o <wan-veth> -j MASQUERADE` inside `gw`, and ping and `curl` from `lan` to `wan`.
2. Run `sudo ip netns exec gw conntrack -L` and map `src`/`dst`/`sport` in both tuples to inside local, inside global and outside addresses. Capture on both gateway interfaces with `tcpdump -ni <if> icmp or tcp port 80` and compare the source addresses before and after NAT.
3. On a Cisco router with `ip nat inside` and `ip nat outside` set on two interfaces, configure each of the three NAT types in turn and compare `show ip nat translations` and `show ip nat statistics`. Clear the table with `clear ip nat translation *`.
4. Shrink the pool in the dynamic NAT example to one address, ping from two inside hosts, and observe the second one fail.
5. In Wireshark capture at the router's inside and outside interface and filter `ip.addr == 198.51.100.10` to see the source address change while the destination stays the same.

## Key takeaways

- RFC 3022 Traditional NAT has two flavours: Basic NAT (address only) and NAPT (address and port); RFC 2663 supplies the terminology, including Twice NAT.
- Static NAT is a permanent one-to-one, bidirectional mapping; dynamic NAT takes addresses from a pool; PAT shares one address using ports.
- Inside local is the real inside address, inside global is the same host as seen outside; outside local and outside global differ only if the outside is translated.
- NAT is stateful: mappings are created by the first packet and expire after an idle timeout (RFC 4787: UDP at least 2 minutes; RFC 5382: established TCP at least 2 h 4 min).
- The NAT device rewrites IP and TCP/UDP checksums, and must translate addresses embedded in ICMP errors.
- On IOS inside-to-outside is routed then translated; outside-to-inside is translated then routed.
- The IOS `ip nat inside source list` ACL selects translatable sources; it does not filter traffic.
- NAT is not a security boundary; use a firewall policy.
