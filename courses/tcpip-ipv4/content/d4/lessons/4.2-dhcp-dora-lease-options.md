## What DHCP does

The Dynamic Host Configuration Protocol (RFC 2131, with options defined in RFC 2132 and the IANA BOOTP/DHCP parameters registry) lets a host with no configuration obtain an IPv4 address, mask, gateway, DNS servers and more from a server. It is carried over **UDP**: servers listen on port **67** and clients use port **68** (RFC 2131 section 4.1). DHCP evolved from BOOTP and keeps its fixed-format message with a variable options area at the end.

Important fixed fields of the message:

| Field | Meaning |
|---|---|
| `op` | 1 = request (client to server), 2 = reply |
| `xid` | Transaction ID chosen by the client; ties a reply to its request |
| `ciaddr` | Client's current address (only when it already has a usable one: renewing or rebinding) |
| `yiaddr` | "Your" address: the address the server is offering or acknowledging |
| `siaddr` | Server to use in the next bootstrap step (TFTP/boot server) |
| `giaddr` | Relay agent address; zero when no relay is involved |
| `chaddr` | Client hardware (MAC) address |
| `sname`, `file` | Optional server host name and boot file name (options 66 and 67 can carry the same data) |
| options | Magic cookie 99.130.83.99, then type-length-value options, ended by option 255 |

## The DORA exchange

A client with no address walks through four messages, **D**iscover, **O**ffer, **R**equest, **A**cknowledge.

```text
1  DHCPDISCOVER   0.0.0.0:68 -> 255.255.255.255:67   Eth dst ff:ff:ff:ff:ff:ff
                  xid 0x3903f326  chaddr 00:1a:2b:3c:4d:5e  opt 53=Discover  opt 55=[1,3,6,15,51,58,59]
2  DHCPOFFER      192.0.2.1:67 -> (broadcast or unicast to the client MAC):68
                  yiaddr 192.0.2.50  opt 53=Offer  opt 54=192.0.2.1  opt 51=86400  opt 1=255.255.255.0  opt 3=192.0.2.1  opt 6=192.0.2.53
3  DHCPREQUEST    0.0.0.0:68 -> 255.255.255.255:67
                  opt 53=Request  opt 50=192.0.2.50  opt 54=192.0.2.1
4  DHCPACK        192.0.2.1:67 -> client:68
                  yiaddr 192.0.2.50  opt 53=Ack  opt 51=86400 ...
```

Why the request is **broadcast**: more than one server may have answered the discover. The broadcast request carries the **server identifier** (option 54) of the chosen server, so every other server sees it and withdraws its offer. After the ACK the client should check that nobody else uses the address, by sending an ARP probe (RFC 5227); on a conflict it sends DHCPDECLINE and starts again. RFC 2131 also recommends that the server test an address (ICMP echo) before offering it.

All eight message types are carried in option 53 (message type, RFC 2132):

| Value | Message | Purpose |
|---|---|---|
| 1 | DHCPDISCOVER | Client looks for servers |
| 2 | DHCPOFFER | Server proposes an address and options |
| 3 | DHCPREQUEST | Client accepts one offer, or renews/rebinds/verifies a lease |
| 4 | DHCPDECLINE | Client reports that the offered address is already in use |
| 5 | DHCPACK | Server confirms the lease and options |
| 6 | DHCPNAK | Server refuses (wrong subnet, expired lease), client restarts |
| 7 | DHCPRELEASE | Client gives the address back |
| 8 | DHCPINFORM | Client already has an address and only wants configuration options |

> **Exam tip:** DISCOVER and the first REQUEST are sent from source `0.0.0.0` to destination `255.255.255.255`, UDP 68 to 67, because the client has no address yet. The Ethernet destination is the broadcast MAC. A server may answer by broadcast or by unicast to the client's MAC, depending on the client's broadcast flag.

## Leases, T1 and T2

An address is **leased** for a duration given in option 51 (seconds). The client does not wait for expiry; it tries to extend using two timers (RFC 2131 section 4.4.5):

| Timer | Default | Option | Behaviour |
|---|---|---|---|
| **T1** (renewal) | 0.5 x lease | 58 | Client enters RENEWING and sends a **unicast** DHCPREQUEST to the server that gave the lease, with `ciaddr` set. |
| **T2** (rebinding) | 0.875 x lease | 59 | If renewal got no answer, the client enters REBINDING and **broadcasts** a DHCPREQUEST to any server. |
| Expiry | 1.0 x lease | 51 | The client must stop using the address and returns to INIT (full DORA). |

For a 24-hour lease (86 400 s) this gives T1 = 43 200 s (12 h) and T2 = 75 600 s (21 h). A Cisco IOS DHCP client (`show dhcp lease`) shows renewal and rebind times that follow the same defaults, 43 200 s and 75 600 s for an 86 400-second lease. The server may override both with options 58 and 59, and RFC 2131 says the times SHOULD be randomly fuzzed to avoid synchronised renewals.

A successful renewal gets a DHCPACK with a fresh lease and the client keeps its address with no interruption. A DHCPNAK forces the client to drop the address and start over.

## Options worth knowing

Options use a one-byte code, a one-byte length and the value. The client's **parameter request list** (option 55) names the ones it would like; the server replies with those it can supply.

| Code | Name | Typical content |
|---|---|---|
| 1 | Subnet Mask | 255.255.255.0 |
| 3 | Router | Default gateway address(es) |
| 6 | Domain Name Server | DNS server addresses |
| 15 | Domain Name | example.com |
| 42 | NTP Servers | Time servers |
| 43 | Vendor Specific Information | Opaque data for the vendor named in option 60 |
| 50 | Requested IP Address | Client asks for a specific address |
| 51 | IP Address Lease Time | Seconds |
| 53 | DHCP Message Type | 1 to 8 |
| 54 | Server Identifier | The server's IP address |
| 55 | Parameter Request List | List of option codes wanted |
| 58 / 59 | Renewal (T1) / Rebinding (T2) time | Seconds |
| 60 | Vendor Class Identifier | e.g. a phone or PXE client type |
| 61 | Client Identifier | Used instead of the MAC for lease lookup |
| 66 | TFTP Server Name | Boot server host name |
| 67 | Bootfile Name | File to download |
| 82 | Relay Agent Information | Added by relays and snooping switches (RFC 3046) |
| 119 | Domain Search | Search list (RFC 3397) |
| 121 | Classless Static Route | Prefix, mask and next-hop routes (RFC 3442) |
| 255 | End | Terminates the options |

Two points trip people up. First, when a server returns option 121 the client **must ignore option 3** (RFC 3442), so a classless-route server can override the default gateway. Second, options 66 and 67 are used by IP phones and PXE/ZTP boot, which download firmware or a configuration over TFTP or HTTP, so a wrong 66 or 67 is a boot problem rather than an addressing problem.

## Reservations and address conflicts

A **reservation** (static lease) makes the server always hand the same address to one client. The server identifies the client by MAC (`chaddr`) or by client identifier (option 61). Unlike a manually configured static address, the host still uses DHCP, so the gateway, DNS and other options stay centrally managed. On Cisco IOS:

```text
R1(config)# ip dhcp excluded-address 192.0.2.1 192.0.2.20
R1(config)# ip dhcp pool LAN
R1(dhcp-config)# network 192.0.2.0 255.255.255.0
R1(dhcp-config)# default-router 192.0.2.1
R1(dhcp-config)# dns-server 192.0.2.53
R1(dhcp-config)# domain-name example.com
R1(dhcp-config)# lease 1
R1(config)# ip dhcp pool PRINTER
R1(dhcp-config)# host 192.0.2.30 255.255.255.0
R1(dhcp-config)# hardware-address 001a.2b3c.4d5e
```

Static addresses should lie **outside** the dynamic range or in the excluded list; otherwise the server may lease an address already in use. A client that cannot find any server will, on Windows, fall back to an **APIPA** address in 169.254.0.0/16 (link-local, see the special-address lesson); a plain Linux `dhclient` simply keeps retrying.

## Lab it yourself

1. Capture DHCP on a Linux client: `sudo tcpdump -nn -vv -i eth0 'udp port 67 or udp port 68'` in one terminal, then `sudo dhclient -r eth0 && sudo dhclient -v eth0` in another. Identify D, O, R and A and note which are broadcast.
2. In Wireshark use the display filter `dhcp` and, to isolate a message type, `dhcp.option.dhcp == 1` (Discover) or `== 5` (ACK). Add `dhcp.option.dhcp_server_id` as a column.
3. On Windows run `ipconfig /release`, `ipconfig /renew`, then `ipconfig /all` and read `DHCP Server`, `Lease Obtained` and `Lease Expires`. Compute T1 and T2 from the lease length.
4. On a Cisco router configure the pool above, connect a client, then use `show ip dhcp binding`, `show ip dhcp pool` and `debug ip dhcp server packet`.
5. Set a very short lease (for example `lease 0 0 4` on IOS) and watch the client renew at T1 as a unicast request in the capture.

## Key takeaways

- DHCP (RFC 2131/2132) uses UDP 67 (server) and 68 (client); DISCOVER and REQUEST are broadcasts from 0.0.0.0 to 255.255.255.255.
- DORA: Discover, Offer, Request (names the chosen server in option 54), Acknowledge.
- Message type is option 53: 1 Discover, 2 Offer, 3 Request, 4 Decline, 5 Ack, 6 Nak, 7 Release, 8 Inform.
- T1 = 50% of the lease (unicast renewal), T2 = 87.5% (broadcast rebinding); 24 h lease gives 12 h and 21 h.
- Options: 1 mask, 3 router, 6 DNS, 15 domain name, 51 lease, 66/67 boot server and file, 82 relay information, 121 classless routes override 3.
- Reservations bind a MAC or client ID to a fixed address while keeping central option management.
- The client should ARP-probe the address and send DHCPDECLINE if it is in use.
- No server answer yields an APIPA 169.254.x.x address on Windows.
