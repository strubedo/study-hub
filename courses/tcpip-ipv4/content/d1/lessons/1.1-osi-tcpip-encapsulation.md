## Two models, one purpose

Networking is split into layers so that each layer solves one problem and hides its details from the layers above. Two models are in everyday use. The **OSI reference model** has seven layers and is the vocabulary engineers use when they say "layer 2 switch" or "layer 7 firewall". The **TCP/IP model** is what the protocols on the wire were actually built around. RFC 1122 (Requirements for Internet Hosts) describes it as a stack of a link layer, an internet (IP) layer, a transport layer and an application layer, which gives four layers. Some textbooks split the link layer into "physical" and "data link" to get five; that is a teaching convenience, not what the RFC says.

| OSI layer | Name | TCP/IP (RFC 1122) layer | Typical protocols and items |
|---|---|---|---|
| 7 | Application | Application | HTTP, DNS, DHCP, SSH, SMTP |
| 6 | Presentation | Application | TLS framing, character encodings, MIME |
| 5 | Session | Application | RPC sessions, TLS session resumption |
| 4 | Transport | Transport | TCP, UDP |
| 3 | Network | Internet | IPv4, ICMP, IPsec (AH/ESP) |
| 2 | Data link | Link | Ethernet, 802.11, PPP, ARP, 802.1Q |
| 1 | Physical | Link | Cabling, optics, signalling, bits |

OSI layers 5 to 7 collapse into a single TCP/IP application layer because Internet applications implement their own session and presentation logic rather than relying on a separate layer. Real protocols do not always fit neatly: ARP is usually drawn at layer 2 or "2.5" because it carries IP addresses yet is not carried inside IP; ICMP is a layer 3 protocol even though it travels inside IP packets; TLS straddles layers 5 to 7.

> **Exam tip:** When a question says "layer 3", it means OSI layer 3, the network layer, which is the TCP/IP internet layer. The numbers always refer to OSI, even when the protocol under discussion belongs to the TCP/IP model.

## Protocol data units

The chunk of data a layer handles is its **protocol data unit (PDU)**. The names are conventions, and the RFCs are looser than the textbooks:

| Layer | PDU name | Notes |
|---|---|---|
| Layer 1 | Bits (or symbols) | Encoded on the medium |
| Layer 2 | Frame | Ethernet header + payload + FCS |
| Layer 3 | Packet | An IPv4 packet is formally an "IP datagram" in RFC 791 |
| Layer 4, TCP | Segment | RFC 9293 uses "segment" for a TCP header plus its data |
| Layer 4, UDP | Datagram | RFC 768 calls it a user datagram |
| Layer 7 | Message or data | HTTP request, DNS message |

Do not memorise these as laws. "Packet" is used loosely for anything at layer 3 and above, and RFC 791 itself says datagram for IP. For exams and conversation the safe mapping is frame at layer 2, packet at layer 3, segment (TCP) or datagram (UDP) at layer 4.

## Encapsulation and decapsulation

When a host sends data, each layer wraps the PDU from the layer above with its own **header**, and sometimes a **trailer**. This is **encapsulation**. The receiver strips the wrapping in reverse order, which is **decapsulation**.

```text
Application data           : GET / HTTP/1.1 ...
TCP segment                : [TCP header 20+ B][ data ]
IPv4 packet                : [IPv4 header 20+ B][ TCP header ][ data ]
Ethernet II frame          : [Dst MAC 6][Src MAC 6][EtherType 2][ IPv4 packet ][FCS 4]
```

Only Ethernet adds a trailer here, the 4-byte frame check sequence (FCS), because it is computed over the finished frame and must come last. The IP and TCP headers carry their own checksums inside the header. The EtherType field (0x0800 for IPv4) tells the receiver which protocol to hand the payload to; the IPv4 protocol field (6 for TCP) does the same one layer up; the TCP destination port picks the application. Each layer's header contains a demultiplexing key for the layer above.

A key idea: **each layer talks logically to the same layer on the peer**, but physically only through the layers beneath it. TCP on host A and TCP on host B negotiate sequence numbers as if directly connected, yet their segments ride inside IP packets that ride inside frames.

### What changes hop by hop

When a packet crosses a router, layers 1 and 2 are rebuilt at every hop, while layer 3 and above are carried end to end (barring NAT and similar rewrites):

| Field | Changes at each router? |
|---|---|
| Source and destination MAC addresses | Yes, replaced for the next link |
| Ethernet FCS | Yes, recomputed for the new frame |
| IPv4 TTL | Yes, decremented by 1 |
| IPv4 header checksum | Yes, because TTL changed |
| IPv4 source and destination addresses | No (unless NAT) |
| TCP/UDP ports and payload | No (unless NAT/PAT) |

This is the single most useful fact for reading captures: the IP addresses tell you the endpoints, the MAC addresses tell you the current hop.

## Where devices and protocols sit

A device is described by the highest layer whose header it examines to make a forwarding decision.

| Device | Layer it operates at | What it forwards on |
|---|---|---|
| Repeater / hub | 1 | Nothing; repeats electrical signal out every other port |
| Bridge / switch | 2 | Destination MAC address and VLAN |
| Router | 3 | Destination IP address (longest prefix match) |
| Layer 3 switch | 2 and 3 | MAC within a VLAN, IP between VLANs |
| Packet filter / stateful firewall | 3 and 4 | IP addresses, protocol, ports, connection state |
| Next-generation firewall, proxy, load balancer | 4 to 7 | Application identity, URLs, TLS names |
| Host | 1 to 7 | All layers |

A hub puts every received bit on all other ports, so everything attached shares one collision domain. A switch learns MAC addresses and forwards selectively. A router connects different IP networks, terminates the layer 2 domain on each interface and decrements TTL. A firewall may be deployed as a router (routed mode) or as a transparent bridge, which is why "which layer is a firewall" has no single answer.

> **Real world:** Cisco and others sell "multilayer switches". An SVI (`interface vlan 10`) is the layer 3 interface for VLAN 10; the switch still bridges frames inside the VLAN and routes only between VLANs.

## Why the models matter for troubleshooting

Walking the stack gives a systematic method. If the link light is down, nothing above can work (layer 1). If the interface is up but ARP fails, look at layer 2 or VLANs. If ARP succeeds but ping to a remote subnet fails, look at layer 3: gateway, routing, ACLs. If ping works but a web page does not load, look at layer 4 (port blocked, TCP handshake failing) and then layer 7. Working bottom-up or top-down are both valid so long as you are consistent and test one layer at a time.

## Lab it yourself

1. On a Linux host run `sudo tcpdump -i eth0 -e -n -c 5 icmp` in one terminal and `ping -c 2 192.0.2.1` (or any reachable host) in another. The `-e` flag prints the Ethernet header. Identify the source and destination MAC, the EtherType (`ethertype IPv4 (0x0800)`), the IP addresses and the ICMP type.
2. Open the same capture in Wireshark. In the packet details pane, expand Frame, Ethernet II, Internet Protocol Version 4 and Internet Control Message Protocol. The nesting you see is encapsulation. Click each header and watch the byte pane highlight just that header.
3. Capture `curl http://example.com/` and find the frame, IP packet, TCP segment and HTTP message in one packet. Note which header contains the port numbers and which contains the MAC addresses.
4. Ping a host on a different subnet with a capture on the first hop. Confirm the destination MAC is your gateway's, while the destination IP is the remote host's.
5. On a Cisco IOS switch, `show mac address-table` shows the layer 2 view and `show ip route` on a router the layer 3 view. Compare what each device keys its decisions on.

## Key takeaways

- OSI has seven layers; the TCP/IP model of RFC 1122 has four: link, internet, transport, application.
- OSI layers 5 to 7 map to the single TCP/IP application layer.
- Layer numbers in conversation always mean OSI numbers.
- PDU names: frame (layer 2), packet (layer 3), segment (TCP) or datagram (UDP) at layer 4.
- Encapsulation adds headers going down; Ethernet alone also adds a trailer (the FCS).
- At each router the MAC addresses, FCS, TTL and IP header checksum change; IP addresses and ports normally do not.
- A device's layer is defined by the header it uses to forward: hub 1, switch 2, router 3, firewall 3 to 7.
- Each header carries a demultiplexing field (EtherType, IP protocol, port) naming the next protocol up.
