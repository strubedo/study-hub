## How a switch learns and forwards

A layer 2 switch builds a **MAC address table** (also called the CAM table or forwarding database) and uses it to send frames only where they need to go. It follows a small set of rules for every frame that arrives:

1. **Learn:** record the frame's **source** MAC address against the ingress port and VLAN, and refresh its aging timer. A source address is never a group address, so a switch never learns broadcast or multicast MACs from the source field.
2. **Look up the destination** MAC in the table for that VLAN.
3. **Known unicast:** if the destination is learned on a different port, forward out that port only. If it is learned on the ingress port itself, **filter** (drop) the frame, since the destination is on the same segment as the sender.
4. **Unknown unicast, broadcast or (without snooping) multicast:** **flood** out every other port in the VLAN.

Entries expire if unused: the default aging time on Cisco switches is **300 seconds**, and Linux bridges default to 300 seconds as well. When a host moves to a different port, the next frame it sends relocates the entry.

```text
Switch# show mac address-table dynamic vlan 10
          Mac Address Table
-------------------------------------------
Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
  10    001a.2b3c.4d5e    DYNAMIC     Gi1/0/3
  10    0050.56aa.bbcc    DYNAMIC     Gi1/0/24
Total Mac Addresses for this criterion: 2
```

Linux equivalent: `bridge fdb show br br0`. Because the table is per VLAN, the same MAC may appear in two VLANs on different ports without conflict.

> **Watch out:** A MAC flooding attack fills the table with fake source addresses until the switch has no room and floods legitimate traffic like a hub. Port security (`switchport port-security maximum`) limits learned MACs per port. Separately, a loop with no spanning tree makes broadcasts circulate forever, because Ethernet frames have no TTL.

## Collision domains and broadcast domains

- A **collision domain** is the set of interfaces whose transmissions can collide. A hub or a shared coax segment is one collision domain; every **switch port** is its own collision domain, and on full-duplex links collisions cannot occur at all.
- A **broadcast domain** is the set of devices that receive a layer 2 broadcast sent by any member. Switches do **not** break up broadcast domains within a VLAN; **routers** (and VLANs) do.

| Device | Splits collision domains? | Splits broadcast domains? |
|---|---|---|
| Hub | No | No |
| Switch (single VLAN) | Yes, per port | No |
| Switch with VLANs | Yes | Yes, one per VLAN |
| Router interface | Yes | Yes |

Counting is a classic exam exercise: a switch with 8 ports in one VLAN, all in use, has 8 collision domains and 1 broadcast domain; a router with three connected interfaces gives three broadcast domains.

## 802.1Q VLAN tagging

VLANs let one physical switch behave as several independent layer 2 networks. On a trunk link carrying more than one VLAN, frames are tagged with a 4-byte **IEEE 802.1Q** header inserted between the source MAC and the EtherType:

```text
| Dst MAC 6 | Src MAC 6 | TPID 0x8100 (2) | TCI (2) | EtherType 2 | Payload | FCS 4 |
TCI = PCP (3 bits) | DEI (1 bit) | VLAN ID (12 bits)
```

- **TPID** 0x8100 occupies the place where the EtherType normally sits, so a receiver recognises a tagged frame.
- **PCP** is the 3-bit priority code point (802.1p class of service, values 0 to 7).
- **DEI** is one drop-eligible bit.
- **VID** is 12 bits, giving 4096 values, of which 0 (priority-tagged only) and 4095 (reserved) are not usable; VLANs 1 to 4094 are. Cisco additionally treats 1002 to 1005 as legacy reserved and 1006 to 4094 as the extended range.

A tagged frame is 4 bytes bigger: the maximum frame becomes **1522 bytes** (the 64-byte minimum is unchanged, with the tag counted inside it). The payload limit is still 1500 bytes; the tag extends the frame, it does not eat into the MTU. The FCS is recomputed when a switch adds or removes a tag. Frames on an access port are untagged; the **native VLAN** on an 802.1Q trunk is the one VLAN whose frames cross the trunk untagged. A native VLAN mismatch between the two ends is a common misconfiguration and a VLAN-hopping risk.

QinQ (802.1ad) stacks a second tag with TPID 0x88A8 for service providers.

## MTU, jumbo frames and what "1500" means

The **maximum transmission unit** is the largest layer 3 packet that an interface can send without fragmenting. For standard Ethernet it is **1500 bytes**, which equals the maximum Ethernet payload. The MTU does not include the Ethernet header, FCS or an 802.1Q tag, so a 1500-byte IP packet always fits in a 1518-byte (or 1522-byte tagged) frame.

| Link | Typical MTU |
|---|---|
| Ethernet II | 1500 |
| PPPoE (8 bytes of PPPoE and PPP overhead) | 1492 |
| GRE tunnel over Ethernet (24 bytes: 20 IP + 4 GRE) | 1476 |
| Jumbo frames (not standardised by IEEE; varies by vendor) | Often 9000 (some devices allow 9216) |
| Minimum any IPv4 link must support (RFC 791) | 68 |

**Jumbo frames** carry larger payloads (commonly 9000 bytes) to reduce per-packet overhead for storage and cluster traffic. They are not part of the IEEE standard, so every device in the path, including switch ports, must be configured for the larger size or large frames are dropped. Interface commands differ:

```text
! Linux
ip link set dev eth0 mtu 9000
! Cisco IOS router or routed interface
interface GigabitEthernet0/1
 mtu 9000
! Many Catalyst switches use a global setting (applied after reload on some models)
system mtu jumbo 9000
```

Check the device documentation: some platforms count the MTU as payload only, others quote frame size.

> **Exam tip:** MTU is a layer 3 concept (the largest IP packet). The maximum Ethernet **frame** is 1518 bytes; the maximum payload is 1500. If a question says "1500-byte frame" it is probably wrong.

An IP packet larger than the MTU of the outgoing interface must be fragmented, or dropped with an ICMP error if the Don't Fragment bit is set. Lesson 1.4 introduces the header fields involved, and Domain 3 covers path MTU discovery in depth.

## Lab it yourself

1. Linux: `ip link show eth0` prints `mtu 1500`. Test the real limit with the DF bit set: `ping -M do -s 1472 192.0.2.1` succeeds on an Ethernet path (1472 data + 8 ICMP + 20 IP = 1500) and `ping -M do -s 1473 192.0.2.1` fails with "message too long". On Windows: `ping -f -l 1472 192.0.2.1`.
2. Create a VLAN subinterface: `sudo ip link add link eth0 name eth0.20 type vlan id 20`, bring it up and capture on `eth0` with `tcpdump -nn -e -i eth0 vlan`. The line shows `ethertype 802.1Q (0x8100), vlan 20`. In Wireshark use the filter `vlan.id == 20`.
3. On a Cisco switch, run `show mac address-table`, then `show mac address-table aging-time`. Ping across the switch from two hosts and watch both MACs appear. Clear them with `clear mac address-table dynamic` and repeat.
4. Build a three-host topology in a Linux bridge or a lab switch with a hub-like mirror port and observe that unknown unicast is flooded (all hosts see it) until the destination replies.
5. Count the collision and broadcast domains in your home network diagram, then check your answer against the VLANs and router interfaces.

## Key takeaways

- A switch learns source MACs per VLAN and port, forwards known unicast to one port, and floods unknown unicast and broadcasts.
- A frame whose destination is learned on the ingress port is filtered, not sent back.
- Default MAC aging is 300 seconds on Cisco switches and Linux bridges.
- Each switch port is a collision domain; each VLAN or router interface is a broadcast domain.
- The 802.1Q tag is 4 bytes (TPID 0x8100, 3-bit PCP, 1-bit DEI, 12-bit VID) and raises the maximum frame to 1522 bytes.
- Usable VLAN IDs are 1 to 4094.
- Ethernet MTU is 1500 bytes of layer 3 packet; the maximum untagged frame is 1518 bytes.
- Jumbo frames (commonly 9000) are vendor-defined and must be enabled end to end.
