## The Ethernet II frame

Almost all IPv4 traffic on a wired LAN uses the **Ethernet II** (DIX) frame format, which RFC 894 specifies for carrying IP. A frame is the layer 2 PDU: everything from the destination MAC address through the frame check sequence.

| Field | Size | Purpose |
|---|---|---|
| Destination MAC | 6 bytes | Who should accept the frame on this link |
| Source MAC | 6 bytes | The sender's interface |
| EtherType | 2 bytes | Which protocol is in the payload (0x0800 IPv4, 0x0806 ARP, 0x86DD IPv6, 0x8100 VLAN tag) |
| Payload | 46 to 1500 bytes | The layer 3 packet, padded if shorter than 46 bytes |
| FCS | 4 bytes | CRC-32 over the frame, checked by the receiver |

Totals: header 14 bytes, trailer 4 bytes, so the **minimum frame is 64 bytes** (14 + 46 + 4) and the **maximum untagged frame is 1518 bytes** (14 + 1500 + 4). Before each frame the transmitter sends a 7-byte preamble and a 1-byte start frame delimiter, and after it leaves an inter-frame gap of 12 byte-times. These are line overhead, not part of the frame, which is why a 64-byte frame occupies 84 byte-times on the wire. Capture tools usually show the frame without the FCS, because the NIC strips and verifies it, so a minimum-size frame appears as 60 bytes in Wireshark and tcpdump. Short payloads, such as a 28-byte ARP message, are padded with zeros to reach 46 bytes; the padding is not part of the ARP message and the IP total length field exists partly so IP can discard it.

The 64-byte minimum comes from half-duplex CSMA/CD: a frame must last long enough (a 512-bit slot time) for a collision at the far end of the segment to be detected while the sender is still transmitting. Modern full-duplex switched links have no collisions, but the minimum stayed.

### EtherType versus length

The 2-byte field after the source MAC has two historical meanings. IEEE 802.3 defined it as a payload **length** (so it is 1500 or less), while Ethernet II used it as a **type**. Today the rule is: a value of **0x0600 (1536) or higher is an EtherType**, a value of 1500 or lower is a length (used with an LLC/SNAP header), and 1501 to 1535 is undefined. Common types, from the IANA registry:

| EtherType | Protocol |
|---|---|
| 0x0800 | IPv4 |
| 0x0806 | ARP |
| 0x86DD | IPv6 |
| 0x8100 | 802.1Q C-VLAN tag |
| 0x88A8 | 802.1ad S-tag (QinQ) |
| 0x88CC | LLDP |
| 0x8847 | MPLS unicast |
| 0x8863 / 0x8864 | PPPoE discovery / session |

### FCS

The FCS is a 32-bit CRC computed by the sender over the destination MAC through the payload. A receiver that finds a mismatch silently drops the frame and increments a CRC error counter; Ethernet does not retransmit. Rising CRC counters on an interface usually mean a bad cable, a duplex mismatch or electrical interference. Higher layers (TCP) recover the loss.

## MAC addresses

A MAC (media access control) address is **48 bits**, written as six hexadecimal octets such as `00:1a:2b:3c:4d:5e` (Linux and Wireshark), `00-1A-2B-3C-4D-5E` (Windows) or `001a.2b3c.4d5e` (Cisco IOS). The layout:

- **First 24 bits: OUI** (organizationally unique identifier), assigned by the IEEE to a manufacturer. `00:1a:2b` identifies the vendor.
- **Last 24 bits:** assigned by that vendor to the individual interface.

Two bits in the **first octet** carry meaning. Numbering from the least significant bit of that octet:

| Bit | Name | 0 means | 1 means |
|---|---|---|---|
| Bit 0 (LSB, value 0x01) | I/G (individual/group) | Unicast | Group (multicast or broadcast) |
| Bit 1 (value 0x02) | U/L (universal/local) | Universally administered (burned-in, OUI-based) | Locally administered (set by software) |

Ethernet transmits each byte least significant bit first, so the I/G bit is the first bit on the wire, which lets a NIC decide very early whether a frame is a group frame. Examples:

| Address | First octet | Meaning |
|---|---|---|
| `00:1a:2b:3c:4d:5e` | 0x00 = 0000 0000 | Unicast, universally administered |
| `02:42:ac:11:00:02` | 0x02 = 0000 0010 | Unicast, locally administered (typical of container and virtual interfaces) |
| `01:00:5e:00:00:05` | 0x01 = 0000 0001 | Group address (IPv4 multicast) |
| `ff:ff:ff:ff:ff:ff` | 0xff | Broadcast (all bits 1, so also a group address) |

Phones and laptops that randomise their Wi-Fi MAC set the U/L bit, so a second hex digit of 2, 6, A or E in the first octet suggests a randomised address.

### Broadcast and multicast

- **Broadcast** `ff:ff:ff:ff:ff:ff` is delivered to every host in the layer 2 domain. ARP requests and DHCP discovers use it.
- **IPv4 multicast** maps to the MAC prefix `01:00:5e` followed by a 0 bit and the **low 23 bits** of the group address. So 224.0.0.5 (OSPF) becomes `01:00:5e:00:00:05`, and 224.0.0.251 becomes `01:00:5e:00:00:fb`. A group address has 28 significant bits but only 23 are copied, so 32 different groups share each MAC.
- NICs accept frames to their own MAC, broadcast and any multicast group the host joined; **promiscuous mode** accepts everything.

> **Watch out:** Do not confuse the Ethernet MAC for multicast with the IP address. The IP class D address 224.0.0.5 is never an Ethernet address; the host derives the MAC with the rule above.

## Reading the frame in a capture

```text
$ sudo tcpdump -nn -e -c 2 -i eth0 icmp
10:15:02.114 00:1a:2b:3c:4d:5e > 00:50:56:aa:bb:cc, ethertype IPv4 (0x0800), length 98:
    192.0.2.10 > 192.0.2.1: ICMP echo request, id 7, seq 1, length 64
10:15:02.115 00:50:56:aa:bb:cc > 00:1a:2b:3c:4d:5e, ethertype IPv4 (0x0800), length 98:
    192.0.2.1 > 192.0.2.10: ICMP echo reply, id 7, seq 1, length 64
```

The length 98 is 14 (Ethernet) + 20 (IPv4) + 8 (ICMP) + 56 (ping data) with no FCS. The destination MAC in the first line belongs to the next hop on this link, which for a local destination is the destination host itself.

## Lab it yourself

1. Run `ip link show eth0` (Linux) to see your interface MAC and `ip -s link show eth0` for error counters, including CRC errors. On Windows use `ipconfig /all` (Physical Address) or `getmac`.
2. Decode a MAC by hand: take your own MAC, write the first octet in binary and identify the I/G and U/L bits. Then check a Docker veth or a VM interface and observe the locally administered bit.
3. In Wireshark capture a ping, expand Ethernet II and then the Destination field. Wireshark shows `.... ..0. .... .... .... .... = LG bit: Globally unique address (factory default)` and `.... ...0 .... .... .... .... = IG bit: Individual address (unicast)`. Apply the display filter `eth.ig == 1` to see only group frames.
4. Join a multicast group (for example run `avahi-browse -a` or watch OSPF hellos on a router link) and verify the destination MAC begins `01:00:5e`.
5. On a Cisco IOS device run `show interfaces GigabitEthernet0/1 | include CRC|MTU` and note the MTU and CRC counter. Capture with and without a VLAN tag if you have a trunk to compare frame lengths.

## Key takeaways

- Ethernet II frame: dst MAC 6, src MAC 6, EtherType 2, payload 46 to 1500, FCS 4.
- Minimum frame 64 bytes, maximum untagged frame 1518 bytes (1522 with one 802.1Q tag) including the FCS.
- EtherType values of 0x0600 and above are types; 1500 or below is an 802.3 length.
- IPv4 is 0x0800, ARP 0x0806, IPv6 0x86DD, 802.1Q 0x8100, LLDP 0x88CC.
- A MAC is 48 bits: 24-bit OUI plus 24 bits assigned by the vendor.
- I/G is the least significant bit of the first octet (1 = group); U/L is the next bit (1 = locally administered).
- Broadcast is `ff:ff:ff:ff:ff:ff`; IPv4 multicast MACs are `01:00:5e` plus the low 23 bits of the group.
- A bad FCS means a silent drop at layer 2, never a retransmission by Ethernet.
