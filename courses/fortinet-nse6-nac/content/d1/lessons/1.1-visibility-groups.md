## How FortiNAC-F learns where a host is

For every endpoint FortiNAC-F needs four facts: that it connected or disconnected, its MAC address, where it is (device and port or SSID) and its IP address. The modeled infrastructure supplies them through several channels, and a well-built deployment uses more than one.

| Source | What FortiNAC-F does | What it learns |
|---|---|---|
| **L2 polling** | Reads the device's MAC address (forwarding) table | MAC, switch and port |
| **L3 polling** | Reads the ARP table of routers, L3 switches, wireless controllers and autonomous APs | IP-to-MAC mapping |
| **Link up / link down traps** | A link up trap makes FortiNAC-F read that switch's forwarding table after a delay | Something connected on that port |
| **MAC notification traps** | The trap itself carries the MAC and port | MAC and location, no table read needed |
| **RADIUS** | 802.1X or MAC authentication requests from modeled devices | MAC, user, device and port or SSID |
| **DHCP to port1** | DHCP traffic relayed from production networks to port1 (with `dhcp` allowed) | Fingerprint data for profiling |

### Polling

- **L2 polling** defaults: **60 minutes for wired** devices, **10 minutes for wireless** devices. Wireless is polled more often because polling is how FortiNAC-F notices that a wireless client has left.
- L2 polls also run on demand (**Poll Now**, or **Poll for L2 (Hosts) Info** on a device), after a link up trap, and after a MAC notification trap whose port can't be identified.
- **L3 polling** only happens for devices in the **L3 (IP-->MAC)** group, which FortiNAC-F creates but **never fills automatically**. Add every ARP source to it (Network > Inventory, select devices, right-click > **Add Devices to Groups**). Devices added this way get L3 polling **enabled at 30 minutes, priority Low**.
- **L3 Priority** (High, Medium, Low) decides which devices are polled first when hosts appear. Give busy core routers High priority.
- Manage both from **Network > L2 Polling** and **Network > L3 Polling** (select devices > **Set Polling**), or per device on the Inventory **Polling** tab.
- FortiNAC-F schedules each device individually from its Last Successful Poll time, and any contact (Poll Now or a trap-driven read) resets that time.

> **Exam tip:** "Hosts appear with MAC and port but no IP address" points at L3: the router or L3 switch is not in the L3 (IP-->MAC) group, or L3 polling is disabled on it.

### Link traps

The switch must send traps to the FortiNAC-F **port1** address, and the device must already be modeled. On a link up trap FortiNAC-F waits **Minimum Trap Period** (default 10 s) times **Max Number of Trap Periods** (default 4), so 40 s by default, then reads the forwarding table, retrying if the MAC is not there yet. These settings are in **Network > Settings > Network Device**. Traps can be lost, so keep polling configured as a safety net.

### MAC notification traps

MAC notification (MAC learned) traps embed the host MAC and the port, so FortiNAC-F doesn't have to read forwarding tables every time something connects. Fortinet recommends them on switches that support them, especially with many ports or with hosts behind IP phones and unmanaged hubs where link state never changes. Rules from the MAC notification guide:

- Enable them on **access ports** and on ports connecting **access points**. Don't enable them on uplinks to other infrastructure, aggregate ports, or ports FortiNAC-F shows as User Defined Uplink.
- **Remove link up/link down traps** on ports where MAC notification is enabled: they are redundant, add traffic and stop the MAC Learned events from being generated.
- Point the traps at FortiNAC-F's port1 address. On an L3 switch, source traps from the IP used to model the switch (`snmp-server source-interface traps …` on Cisco), or FortiNAC-F ignores them.
- For SNMPv3-managed Cisco switches, give the SNMP group access to each VLAN **context**, because FortiNAC-F reads the bridge MIB per VLAN.
- **Ignore MAC Notification Traps for IP Phones** is enabled by default (Network > Settings > Network Device) to save processing.

A Cisco access-port example, written by hand for this lesson:

```text
interface GigabitEthernet1/0/5
 switchport mode access
 switchport access vlan 10
 snmp trap mac-notification change added
 snmp trap mac-notification change removed
 no snmp trap link-status
!
mac address-table notification change
snmp-server enable traps mac-notification change move
snmp-server host 10.0.50.10 version 2c NACro mac-notification
```

### Contact status

Separately from host tracking, FortiNAC-F pings modeled devices. A device that stops answering gets a **red box** around its icon (and its container's) in the Inventory tree. A directory server talking LDAP can show red simply because it doesn't answer ping.

## Groups

Groups collect like items so you can configure or act on all of them at once. Open **System > Groups** and click **Add**:

- **Member Type**: **Administrator**, **Hosts**, **Devices**, **Ports** or **Users** (the Groups view also lists IP phone groups).
- **Owner**: *System* for groups FortiNAC-F maintains, *User* for groups you create.
- **Nesting**: a group can contain sub-groups **of the same type** (Groups tab of the Add/Modify window). Counts include sub-group members. An item that is in a sub-group can only be removed from that sub-group's membership.
- **Days Valid / Days Inactive**: host groups only; used to age hosts out of the database.
- Right-click options include **Group Member Of**, **In Use** (what references the group; system groups never show as In Use), **Manages** (administrator groups only), **Set Aging**, **Set Host Registration Limit** (user and administrator groups) and **Modify Device Properties** (device groups).

What groups are used for: user/host profiles and policies, roles, scheduled tasks (for example a Fixed Day Task that disables a port group after hours), admin scoping with **Manages**, alarm e-mail recipients, and filtering views such as L2 Polling.

### System groups worth knowing

| Group | Type | Purpose |
|---|---|---|
| **L2 Network Devices**, **L2 Wired Devices**, **L2 Wireless Devices** | Device | Filled automatically as L2-capable devices are discovered |
| **L3 (IP-->MAC)** | Device | Filled **manually** with ARP sources for L3 polling |
| **Physical Address Filtering** | Device | Switches that take part in disabling hosts. A disabled host on a switch outside this group stays connected and shows as in violation |
| **Device Interface Status** | Device | Devices whose interface status a scheduled task refreshes; filled automatically |
| **Forced Registration** | Port | Ports switched to the Registration VLAN when an unregistered host connects |
| **Authorized Access Points** | Port | Ports with hubs or APs; no Multi-Access Point Detected events and no VLAN switching for forced registration |
| **Role-Based Access** | Port | Ports that switch VLAN according to the connected device's role |
| **Registered Hosts**, **Rogue Hosts** | Host | All registered hosts; rogue hosts, with an Access property of Deny or Allow |
| **All Management** | Administrator | Admins with all management rights; starts with admin and root, new admins join automatically; default group for alarm e-mails |

System groups can't be deleted.

### Use case: discover, then group

1. Create containers `HQ-Bldg-A` and `HQ-Bldg-B`, then run Discovery per building with read/write SNMP and CLI credentials.
2. Check that access switches landed in L2 Wired Devices and the controller in L2 Wireless Devices.
3. Add the core switch `Cisco-Core1` and the wireless controller to **L3 (IP-->MAC)**; set the core to High priority.
4. Add the access switches to **Physical Address Filtering** so disabling hosts works.
5. Create user-owned groups: a Devices group `Bldg-A-Access-Switches`, a Ports group `Lobby-Ports`, and a Hosts group `Card Readers` for later policy work.
6. Nest `Lobby-Ports` into **Forced Registration** if those ports should force registration.

## Lab it yourself (optional)

In a FortiNAC-F POC or partner lab, configure one Cisco access port as above, plug in a laptop and watch the Ports tab update; then remove `no snmp trap link-status` and compare the events. Without a lab, read the Administration Guide's System groups table and decide which groups each switch in your own network would join.

## Key takeaways

- Visibility comes from L2 polling (MAC tables), L3 polling (ARP), link traps, MAC notification traps, RADIUS and DHCP fingerprinting.
- L2 polling defaults: wired 60 minutes, wireless 10 minutes.
- The L3 (IP-->MAC) group is never filled automatically; devices added to it poll every 30 minutes at Low priority.
- Traps go to port1; with MAC notification traps, remove link up/down traps on those ports and skip uplinks.
- Groups have one member type, can nest groups of the same type, and drive policies, tasks, aging and admin scoping.
- Know the key system groups: L2/L3 device groups, Physical Address Filtering, Forced Registration, Authorized Access Points, All Management.
