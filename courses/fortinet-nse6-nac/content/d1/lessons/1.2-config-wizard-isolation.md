## Isolation networks: the captive network idea

Unknown and untrusted endpoints are not dropped; they are moved to an **isolation network** where the only useful services come from FortiNAC-F's **port2**: DHCP, DNS and the captive portal. Every DNS query resolves to FortiNAC-F, so a browser lands on the right portal page (registration, remediation, authentication or a dead-end notice). Once the host is registered, scanned or authenticated, FortiNAC-F moves it to production.

You can build isolation two ways:

- **One Isolation VLAN/scope** for every restricted state. The host's state decides which page it sees. With this in place the other types are optional.
- **One VLAN/scope per state**:

| Isolation type | Hosts placed there |
|---|---|
| **Registration** | Unknown (unregistered) hosts while they register |
| **Remediation** | Hosts marked at risk after failing a compliance scan |
| **Dead End** | Disabled hosts: little or no connectivity |
| **VPN** | Unknown or untrusted hosts arriving through a FortiNAC-managed VPN |
| **Authentication** | Registered hosts until the user authenticates |
| **Isolation** | All of the above in one network |

The wizard also lists **Access Point Management** among the isolation states that can have scopes.

Design rules from the Deployment Guide:

- In Layer 3 designs, each state needs its own VLAN at every location separated by a Layer 3 device.
- **Block outbound DNS from isolation networks except to port2**, or a host with a hard-coded resolver bypasses the portal.
- Don't NAT isolation traffic before it reaches FortiNAC-F; it needs the real MAC. (A FortiGate NAT option exists, documented in the 7.6.5 Captive Portal over NAT guide.)
- port1 and port2 must not share a network.

## Opening the Config Wizard

The wizard runs automatically after the first GUI login (EULA, licence key on VMs, first admin account, installation method) and later from **System > Config Wizard**. Edits go to a temporary file, so you can leave without changing the running system; settings are written only when you **Apply** on the **Summary** view. Its navigation is a steps pane (steps can be done in any order), **Reset** (undo edits in the current view only) and **Summary**.

## Step 1: Basic Network

| Field | Notes |
|---|---|
| **Host Name** | Letters, numbers and hyphens only; upper case is converted to lower case. Reserved: `nac`, `isolation`, `registration`, `remediation`, `remotereg`, `remotescan`, `vpn`, `authentication`, `hub`, `deadend` |
| **port1 IP Address**, **Mask**, **Default Gateway** | Management addressing |
| **DNS** Primary / Secondary | Servers FortiNAC-F itself uses |
| **Domain** | For example `corp.example.com` |
| **Forwarding DNS for all "Isolation" Networks** | Upstream DNS that lets isolated hosts reach public update sites during registration and remediation: **Use Primary and Secondary DNS** or **Specify** other servers |
| **NTP Server**, **Time Zone** | Keep time right for logs, certificates and HA |

## Step 2: Select Network Type

| Type | port2 design | Infrastructure work |
|---|---|---|
| **None** | No isolation networks; **the captive portal service is disabled** | None. Use when enforcement relies on other methods, or to stage the box first |
| **Layer 3** | port2 sits on **one VLAN on an untagged switch port**; isolation subnets live elsewhere and are **routed** to it | A **DHCP relay (helper) on every isolation network**, pointing back to the port2 isolation interface; routing between isolation subnets and the port2 VLAN |
| **Layer 2** | port2 is an **802.1Q trunk** carrying the isolation VLANs; it has **an IP address in each isolation subnet** and shares their broadcast domain | Trunk the isolation VLANs to port2; no relays needed |

Layer 3 is the type most customers use, and it is **required when HA peers are in different networks** (for example a data centre and a DR site).

> **Exam tip:** "port2 has one address per isolation VLAN and a VLAN ID per interface" is Layer 2. "DHCP helpers on each isolation VLAN, port2 on a single untagged VLAN" is Layer 3.

## Steps 3–4: DHCP attributes and network-type settings

Step 3 defines DHCPv4 attributes (standard, non-standard and vendor-specific options) for the scopes. Step 4 configures the chosen type.

**Layer 3: port2.** For each scope type you enable (check box next to Isolation, Registration, Remediation, Dead End, VPN, Authentication):

- **Interface IP Address**: a **different** port2 address for each scope type, all in the port2 VLAN.
- **Mask**: shared, so changing it in one scope type changes them all.
- **Gateway**: optional; the router between the port2 VLAN and the isolation subnets.

FortiNAC-F creates routes from each isolation subnet to the isolation gateway through port2 automatically. Unchecking **Isolation Interface port 2** and rebooting disables the captive portal.

**Layer 2: port2.** Per isolation VLAN: **Interface IPv4 Address**, **Mask**, **Gateway** and **VLAN ID** (plus optional IPv6 fields; the Administration Guide marks IPv6 in the wizard as demo only).

**Scopes** (DHCP for each isolation network):

| Field | Notes |
|---|---|
| **Label** | A name like `Bldg-B-Reg`. Don't start it with a reserved prefix: `REG_`, `REM_`, `AUTH_`, `DE_`, `ISOL_`, `VPN_` (the Configure scopes page also lists `HUB_`) |
| **Gateway** | The default gateway for that client subnet (the router's SVI), **not** the port2 gateway |
| **Mask** | Mask of that client subnet |
| **Domain** | A domain for the isolation range that is **not** your production domain (otherwise production names on the allowed domains list may fail to resolve). Avoid `.local` if agents run on macOS, iOS or some Linux hosts |
| **Lease Pools** | One or more **Start**/**End** ranges |

Each state can have several scopes, and each scope several lease pools. Scopes can also be imported. **Advanced** handles PXE environments.

**Isolation IP Subnets.** By default FortiNAC-F answers DNS only from the subnets its own DHCP scopes cover. Add subnets here when isolated hosts get addresses from someone else (for example FortiGate-integrated designs or roles-only wireless) but must still use FortiNAC-F DNS.

**Additional Routes.** Static routes FortiNAC-F needs beyond the automatic ones.

**Summary > Apply > Results > Reboot.** Apply writes the files (this can take minutes); fix any errors shown at the top of Results and apply again; then **Reboot** (or **Shutdown**). On a physical appliance staged through the wizard, connect port1 to the network after the reboot.

## Deployment configurations and licences

How many appliances, and which keys, depends on the design:

| Deployment | Appliances | Keys |
|---|---|---|
| Standalone | 1 CA | 1 endpoint key |
| Standalone in HA | 2 CAs, 1 licence pool | 1 endpoint key + 1 appliance key |
| Multiple independent standalones | 1 CA per site | 1 endpoint key per CA |
| Distributed | 1 Manager + several CAs, 1 pool | Endpoint key on the Manager, appliance key per CA |
| Distributed in HA | Manager + CA pairs | Endpoint key on the Manager, appliance keys for CAs and the secondary Manager |

On the network-device side, isolation only works if each modeled switch or controller knows the isolation VLANs: create them on the device, and enter them in that device's **Model Configuration** (Registration, Quarantine, Dead End, Authentication), or use RADIUS-assigned VLANs.

## Lab it yourself (optional)

Requires a FortiNAC-F POC or partner lab. Without one, draw your own campus with a Layer 3 design: a port2 VLAN, Registration and Remediation subnets per building, `ip helper-address` on each isolation SVI pointing back to the port2 isolation interface, and an inbound ACL on each isolation SVI that permits DHCP (`bootps`) and DNS only to port2, plus whatever portal and remediation traffic you allow. Then write the wizard values you would enter, checking each label and host name against the reserved lists.

## Key takeaways

- Isolation networks get DHCP, DNS and the captive portal from port2; a single Isolation scope can cover every state.
- None disables the captive portal; Layer 3 routes isolation subnets to port2 with DHCP relays; Layer 2 trunks isolation VLANs to port2 with an IP per VLAN.
- Layer 3 is the common choice and is required for HA peers on different networks.
- Scope labels must avoid `REG_`, `REM_`, `AUTH_`, `DE_`, `ISOL_`, `VPN_` (and `HUB_`); scope gateway is the client subnet's gateway.
- Block DNS from isolation networks except to port2, and don't NAT isolation traffic.
- Host names are lower-cased and some (`nac`, `registration`, `vpn`, `hub`…) are reserved.
- Wizard changes stay in a temporary file until Apply, then Results and a reboot.
