## What FortiNAC-F is for

FortiNAC-F is Fortinet's network access control platform. It does not sit in the traffic path. It talks to the switches, wireless controllers, access points, routers and firewalls you already own, builds a database of every endpoint it sees, decides what each endpoint should get, and then tells the network devices to enforce that decision. Fortinet's own concept material groups the product into three jobs:

| Job | What it means in practice |
|---|---|
| **Visibility** | Learn who and what is connected, where (device and port or SSID), and when. Classify endpoints with many profiling methods (Fortinet quotes "up to 21 techniques"), optionally helped by the FortiGuard IoT cloud lookup. Agentless, dissolvable agent and persistent agent options exist |
| **Control** | A **policy engine** decides access from the database (user, host, device type, state). An **enforcement engine** applies it: change the VLAN on a switch port, push RADIUS attributes, apply an ACL or CLI configuration, or tag the endpoint on a firewall |
| **Automated response** | Take events from security products (FortiGate, IPS, SIEM and others), match them to rules and act: isolate the host, notify, open an alarm |

The basic decision is simple: when an endpoint connects, FortiNAC-F asks whether it is **known**. Known endpoints get the network that policy says they should get; unknown endpoints (rogues) are placed in an **isolation network** where FortiNAC-F can register, authenticate or scan them.

> **Exam tip:** FortiNAC-F is not an inline device (it is often described as out of band). A distractor that says FortiNAC-F must be cabled inline so that all user traffic passes through it is wrong. Enforcement happens on the network devices.

## FortiNAC-F versus legacy FortiNAC

The "F" product runs on **FortiNAC-OS**, a hardened Linux platform with a FortiOS-style CLI (`config`, `get`, `show`, `diagnose`, `execute` from the base context). Older FortiNAC releases (9.x and the CentOS builds) ran on CentOS and were often deployed as a **Control Server plus Application Server pair** (`FNC-C-VM` + `FNC-A-VM`). Fortinet publishes migration guides that move such a pair onto one FortiNAC-OS appliance.

FortiNAC-F appliance roles:

| Role | Product | Job |
|---|---|---|
| **CA** (Control and Application) | `FNC-CAX-VM` or a CA hardware appliance | The working NAC server: database, policy, enforcement, portal, RADIUS, isolation services |
| **Manager** | `FNC-MX-VM` (FortiNAC-F Manager, often written FortiNAC-M) | Central management of several CAs: shared licence pool, synchronised groups and policies, global views |

The Administration Guide still uses the older words "FortiNAC Server", "Control Server" and "Application Server" in places; for FortiNAC-F treat them as the CA role.

> **Watch out:** CentOS-era habits such as starting from a root shell or working under `/bsc/...` paths are not the FortiNAC-F way. Start in the FortiNAC-OS CLI; `execute enter-shell` exists for the few tasks that need a shell.

## The two interfaces

Every CA uses two networks, and the exam expects you to know which job lives on which port.

| Interface | Name in the docs | Carries |
|---|---|---|
| **port1** | FortiNAC Management Interface | Admin UI (`https://<port1>:8443/`), SNMP and CLI communication with network devices, **SNMP trap receiver**, DHCP from the production network for fingerprinting, FortiCloud (updates, licences, IoT lookups), HA and Manager communication, agent traffic from the production network |
| **port2** | FortiNAC Service Network Interface | **DHCP, DNS and captive portal** for the isolation networks |

Fortinet states that putting port1 and port2 **in the same network is not recommended or supported**. Port2 is configured by the Config Wizard (Layer 2 or Layer 3 network type, covered in topic 1.2). If you choose the network type **None**, port2 is not used for isolation and the captive portal is disabled.

Which services an interface answers is controlled by `set allowaccess` in `config system interface`. The CLI Reference lists options such as `https-adminui` (TCP 8443), `http-adminui` (TCP 8080), `ssh` (TCP 22), `snmp` (UDP 161/162), `dhcp`, `dns`, `https` (portal, TCP 443), `http`, `nac-agent` (TCP 4568), `nac-ipc` (HA and Manager traffic), `radius-auth`, `radius-acct`, `radius-radsec`, `fsso`, `netflow`, `syslog` and `ping`. A hardware appliance arrives with only **SSH** open on port1.

> **Real world:** if a switch is modeled correctly but its traps never show up, check that `snmp` is in port1's allowaccess list and that the switch sends traps to the **port1** address, not to port2.

## Licensing

FortiNAC-F appliances will not start without a valid licence key. There are two kinds of key:

- **Appliance (Base) licence key**: says what the appliance is (Manager or CA). Hardware ships with it; VMs without an endpoint key get one.
- **Endpoint licence key**: sets the licence level (**Base, Plus or Pro**) and the endpoint quantity, and is installed on the "managing" server (the standalone CA, the HA primary, or the Manager in a distributed design).

What the levels add (per the Administration Guide's Licenses page): **Plus** brings host registration, scanning and access control; **Pro** adds automated threat response on top of Plus. High availability is included with every licence. The exact feature matrix is in the FortiNAC data sheet.

Two ways to buy endpoint licences:

| Type | How entitlements reach FortiNAC-F |
|---|---|
| **Perpetual** | Installed as an endpoint licence key file (System > Settings > System Management > License Management) |
| **Subscription** | Pulled from **FortiCloud over TCP 443** at first startup, cached in the database, then polled **every 12 hours**. Poll success and failure raise events |
| Both | Perpetual (from the key) and subscription (from FortiCloud) totals are added together |

> **Watch out:** with a subscription, the entitlements are not in the key file, so License Management shows **License Name = FortiNAC Base** and **Concurrent Licenses = 0**. That is expected. Check the License Information dashboard widget instead.

**Counting.** Concurrent licences count online connections: online hosts in the Host view (including registered hosts and IP phones) and online non-infrastructure devices in Inventory such as printers and servers. Rogues and infrastructure (switches, routers, controllers, APs) are not counted. If the limit is exceeded, new registrations are blocked ("Exceeded concurrent connection license limit") and policy-based provisioning stops, but rogue, at-risk and disabled hosts are still isolated and existing registered hosts keep access.

**Manager environments.** The endpoint key goes on the Manager; the Manager shares the pool with the CAs in its Server List. If the Manager goes offline, CAs keep working with the licences already shared.

## Reading the appliance from the CLI

Two base-context `get` commands answer most "what am I looking at" questions:

```text
get system status
get hardware status
```

- `get system status` reports the FortiNAC version, serial number, licence status (valid or expired) and expiry date, host name, release type (GA or interim) and system time.
- `get hardware status` reports the model, UUID, **MAC address**, CPU and core count, RAM and disk partitions. You need that MAC (not the one on the shipping label) when you register a hardware appliance.

`get system license` prints licence details, and `get system ha status` shows high availability state (domain 2).

## Lab it yourself (optional)

There is no self-service free trial of the FortiNAC-F VM: it needs a licence bound to port1's MAC and the VM UUID, and Fortinet routes evaluations through an SE or partner. If you have a POC, partner or employer lab, run `get system status` and `get hardware status` on the CA and match each field to the list above, then open **System > Settings > System Management > License Management** and the License Information widget. Without a lab, read the License Management field list in the Administration Guide and compare it with this lesson.

## Key takeaways

- FortiNAC-F is not inline: visibility, policy decisions and automated response, with enforcement done by the network devices.
- FortiNAC-F runs FortiNAC-OS; appliances are CAs (`FNC-CAX`) or Managers (`FNC-MX`). Legacy CentOS used separate Control and Application servers.
- port1 = management, device communication, trap receiver, FortiCloud; port2 = DHCP, DNS and captive portal for isolation. Never put them in the same network.
- `set allowaccess` decides which services each port answers; hardware ships with only SSH open on port1.
- Licence levels are Base, Plus and Pro; perpetual keys are installed, subscriptions are polled from FortiCloud every 12 hours on TCP 443.
- Rogues and infrastructure devices don't consume concurrent licences.
- `get system status` and `get hardware status` give version, serial, licence, MAC and UUID.
