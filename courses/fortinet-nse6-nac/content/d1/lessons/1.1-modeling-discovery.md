## Why modeling comes first

FortiNAC-F can only see and control endpoints through the infrastructure it knows about. "Modeling" means adding each switch, router, wireless controller or AP to the FortiNAC-F database with the credentials FortiNAC-F needs to read it (and, if it will enforce, to change it). Everything in **Network > Inventory** depends on this step. The Network Device Modeling guide lays the work out in a fixed order:

1. **Create containers** (logical folders for devices).
2. **Add infrastructure devices** to Inventory, one at a time or in bulk with Discovery.
3. **Configure Layer 3 sources** (put ARP sources in the L3 group).
4. **Validate** port data: label, connection state, VLAN, connected hosts.
5. **Review uplinks** that FortiNAC-F marked as Threshold Uplinks.
6. **Modify the System Defined Uplink Count**.
7. Configure extra maintenance tasks (wireless devices only).

## Requirements before you add anything

| Requirement | Detail |
|---|---|
| FortiNAC-F side | `snmp` must be in port1's `set allowaccess` list, or modeling and Discovery fail |
| SNMP credentials | **Read/write** for devices FortiNAC-F will control. Read-only is enough just to model a device, or for an L3 device it only reads ARP from |
| CLI or REST API credentials | Read/write for devices FortiNAC-F will control (Cisco: a **level 15** local account). Read access (Cisco level 7) for L3 devices it only reads |
| Reachability | The device must answer ping from FortiNAC-F's management address (port1) |
| Naming | Use only letters, numbers and hyphens in device item names, community strings and SNMP/CLI credentials. `#` is often read as a CLI prompt; Cisco restricts `@` and `#` |

> **Exam tip:** "FortiNAC-F can see the switch but cannot change the port VLAN" usually means the device was modeled with a read-only SNMP string or a CLI account without write privilege. For SNMPv1, enter the **read/write** community when the device has several.

## Containers

Containers live in **Network > Inventory** (Containers tab, **Add**). Use them per building, floor, site or device type: for example `HQ-Bldg-A-Fl2`. Two limits matter:

- **Containers cannot be nested.**
- **Deleting a container deletes the devices in it.** Move devices out first (right-click device > **Move To Container**).

Containers organize the Inventory tree; they are not groups. Policies, scheduled tasks and admin scoping use **groups** (next lesson).

## Adding a single device

Right-click a container > **Add Device** (or **Modify** on an existing device). The dialog asks for:

- **Add To Container**, **IP address**.
- **SNMP**: SNMPv1 security string, or SNMPv3 with User Name, **Authentication Protocol** (MD5, SHA1, SHA224, SHA256, SHA384, SHA512), Authentication Password and, for AuthPriv, **Privacy Protocol** (DES, Triple DES, AES-128/192/256 and Cisco AES variants) and Privacy Password. AuthNoPriv needs only the authentication password.
- **CLI**: User Name, Password, Enable Password, **Protocol Type** (Telnet, SSH1, SSH2). For devices managed by REST API, the user name is the device serial number and the password is its REST API key.
- **Validate Credentials** tests SNMP and CLI before you save.

After saving, open **Model Configuration** to finish the device. Each device needs a unique name. A device with several interfaces that each answer SNMP is added once per interface; FortiNAC-F does not merge them.

**RADIUS-only devices (F 7.6.7 and later).** You can add a device with just an IP address and an optional RADIUS secret, no SNMP or CLI credentials. This is meant for devices that FortiNAC-F only handles through RADIUS. Discovery cannot create RADIUS-only devices; add them individually.

**Pingable devices.** Right-click a container > **Add Pingable Device** for printers, servers, IPS/IDS appliances, hubs or wireless access points that you want in Inventory and checked by ping. A MAC address is required if FortiNAC-F can't resolve the IP from ARP.

## Discovery: bulk modeling

Select a container, click **Start Discovery** and fill in the Discovery Settings window:

| Tab or option | Content |
|---|---|
| **Use CDP** | Ask each device for its CDP neighbours and keep going to the edge. With CDP on, only a **starting** IP is required. Limit depth with **Maximum Cisco Discovery Depth** in Network > Settings > Network Device |
| **IP Range** | Starting and ending IP addresses; add as many ranges as needed |
| **SNMP Credentials** | SNMPv1 strings and/or SNMPv3 credentials to try |
| **CLI Credentials** | User name, password, enable password, protocol type |

Discovery runs in the background; status shows in the Devices header, and **Cancel Discovery** stops it. Rules to remember:

- Keep the **total** addresses across all ranges **under 65,000**, or discovery may not complete.
- Discovery finds **SNMP-enabled** devices; anything that doesn't answer SNMP with one of the supplied credentials is not modeled.
- Each found device gets a database model and lands in the chosen container. L2-capable devices are dropped automatically into the **L2 Network Devices** group and its **L2 Wired Devices** or **L2 Wireless Devices** sub-group.

## Model Configuration: the VLAN values

**Model Configuration** (right-click device in Inventory) stores how FortiNAC-F logs in to the device and what each access value means on that device. Nothing typed here is pushed to the device; it tells FortiNAC-F what to use.

| Field | Used for |
|---|---|
| **Default** | Production VLAN for untagged access ports when nothing else (such as a network access policy) chooses a VLAN |
| **Registration** | Unregistered (rogue) hosts while they register |
| **Quarantine** | Hosts that failed a compliance scan (the Remediation state) |
| **Dead End** | Disabled hosts |
| **Authentication** | Registered hosts until the user authenticates |
| **Voice** | Comma-separated voice VLANs that FortiNAC-F must not use for anything else |

**VLAN Display Format** (VLAN Name, VLAN ID or Manual) and **Read VLANs** help fill these from the device. The CLI section here also has **Protocol type**, timeouts and **Enable RADIUS authentication for this device** (FortiNAC-F processes RADIUS requests from it).

> **Watch out:** the Model Configuration field is called **Quarantine**, while the Config Wizard scope and the host state are called **Remediation**. They are the same isolation purpose.

On the device **Properties > Element** tab, **VLAN Switching** must be enabled for FortiNAC-F to switch VLANs on that device (disable it if a custom CLI script does the switching).

## Validate and review uplinks

After modeling, open **Network > Inventory**, select the container, click the **Ports** tab and **Update**. Click a connected port: the adapter details should show the right host status, IP, MAC, location and access value.

FortiNAC-F gives each port a **connection state**. Any **uplink** state means FortiNAC-F will not touch the port and won't show endpoint connections on it, which is what you want for switch-to-switch links. A port becomes a **Threshold Uplink** when it shows more MAC addresses than the **System Defined Uplink Count** (Network > Settings > Network Device, default **20**). After the initial discovery Fortinet recommends raising it to **2000**, clearing the Threshold Uplink state on ports that aren't real uplinks, polling again, and setting genuine uplinks to **Always Uplink** so any new Threshold Uplink stands out.

> **Real world:** a desk with an unmanaged switch and a docking station, a VM host, or a lab bench can easily put more than 20 MACs on one access port. With the default count, that port silently becomes an uplink and FortiNAC-F stops enforcing there.

## Lab it yourself (optional)

Needs a FortiNAC-F POC, partner or employer lab. Model a Cisco or FortiSwitch access switch twice: once with a read-only community (watch VLAN changes fail) and once with read/write plus CLI credentials. Run a Discovery on a small range with CDP off and then with CDP on. Without a lab, walk the Network Device Modeling guide's seven steps and redraw your own network as containers.

## Key takeaways

- Model in order: containers, devices, L3 sources, validate, review uplinks, raise the uplink count.
- Control needs read/write SNMP and write-capable CLI credentials; modeling alone needs read.
- port1 must allow `snmp`, and the device must answer ping from FortiNAC-F.
- Containers can't be nested, and deleting one deletes its devices.
- Discovery is SNMP based, should cover fewer than 65,000 addresses, and with CDP needs only a starting IP. It can't add RADIUS-only devices (an F 7.6.7 manual-add option).
- Model Configuration maps Default, Registration, Quarantine, Dead End, Authentication and Voice VLANs per device.
- Ports over the System Defined Uplink Count (default 20) become Threshold Uplinks and are no longer enforced.
