## Staging a new hardware appliance

The Appliance Installation guide stages each hardware CA **off the production network**:

1. Cable the management PC to **port1** (not the port labelled MGMT, which is reserved and doesn't work yet). Give the PC **192.168.1.1/255.255.255.0** with gateway 192.168.1.99.
2. **SSH to 192.168.1.99** and log in to the CLI as **`admin` with no password**. Only SSH is open on port1 out of the box.
3. Run `get hardware status` and record the **MAC address** for product registration (don't use the label on the box). Run `get system status` and record the **serial number**.
4. Open the Admin UI on port1:

```text
config system interface
edit port1
set allowaccess https-adminui ssh
next
end
```

5. Browse to **`https://192.168.1.99:8443`** and log in with **`root` / `YAMS`**.
6. Get past the licence key window and the EULA (the hardware guide shows the key window first; the generic first-login page shows the EULA first). A hardware appliance already has its appliance key embedded, so leave the key unchanged and click Next. On a **VM** you import the `.lic` file here (Fortinet advises uploading the file rather than pasting the key).
7. **Create the first Admin UI user ID and password**; this account is stored in the local FortiNAC-F database.
8. Choose the installation method. **Guided Install** creates a checklist of tasks in the **Pending Tasks** dashboard widget.
9. The Config Wizard opens: fill in Basic Network, choose a network type (staging can use **None** and come back later), **Apply**, then **Reboot** and move port1 to its real network.

VMs follow the platform deployment guide instead: port1 usually gets a DHCP address first, and you browse to `https://<port1 IP>:8443/`.

## FortiNAC-OS CLI essentials

The CLI is FortiOS-like. Top-level commands are `config`, `get`, `show`, `diagnose`, `execute`, `help` and `exit`. Inside a context, `next` stages the entry, `end` saves and leaves, and `abort` (or Ctrl-C) discards unsaved changes. Tab completes commands.

**Interfaces** (`config system interface`, `edit port1` or `edit port2`):

| Command | Effect |
|---|---|
| `set ip 10.0.50.10/24` | Address and mask in CIDR form. From F 7.6.3, changing it restarts FortiNAC services briefly |
| `set mode static` / `set mode dhcp` | Static or DHCP addressing |
| `set allowaccess <list>` | **Sets the whole list** of services the interface answers |
| `append allowaccess <list>` | **Adds** services to the existing list |
| `unselect allowaccess <list>` | Removes services from the list |
| `config secondaryip` | Secondary IPv4 addresses |

> **Watch out:** `set allowaccess https-adminui` on port1 replaces the list, so SSH is no longer allowed and your next SSH login fails. Include every service you need (`https-adminui ssh snmp …`) or use `append allowaccess`.

Other base-context configuration you will meet early: `config router static` (`edit 1`, `set dst`, `set gateway`, `set device port1`) and `config system dns` (`set primary`, `set secondary`, `set domain`). Use the CLI Reference for anything else; FortiOS diagnostics such as `diagnose debug flow` do not exist here.

## Two separate account worlds

| | CLI accounts | Admin UI administrators |
|---|---|---|
| Where | FortiNAC-OS CLI (`config system admin`) | **Users & Hosts > Administrators** |
| First login | `admin` (blank on new hardware) | `root` / `YAMS`, then the user you create in setup |
| Listed in the UI? | **No** | Yes (also shown in the Users view, since administrators are users too) |

They are independent: a GUI administrator cannot SSH to the CLI with GUI credentials, and changing the CLI password doesn't touch GUI accounts. (During the first-time setup the Guided Install also sets CLI passwords; Fortinet notes that a CLI account change made there applies only after the Config Wizard reboot.) Change a CLI password like this:

```text
config system admin
edit admin
set password <new password>
end
```

CLI/SSH passwords must be at least eight characters with an upper-case letter, a lower-case letter, a number and an allowed symbol (such as `! @ _ # $ ~ ^ - * % ?`); characters such as `( ) ; : { } [ ] ' " & + < > , = . | \ /` are refused. Admin UI passwords for local accounts may use letters, numbers and most symbols, but not single or double quotes.

## Administrators

**Users & Hosts > Administrators > Add** asks for a **User ID**, then the **Add User** dialog:

- **Authentication Type**: **Local** (password in the FortiNAC-F database), **LDAP** or **RADIUS** (password field disabled; the user logs in with the directory or RADIUS password).
- **Admin Profile** (required).
- Name, e-mail (alarm and notification e-mails), mobile number and provider (SMS), **Multi-Factor Authentication** (None, SMS or Email).
- **User Never Expires** (enabled by default).

If the User ID matches an existing network user, the two become one account with admin rights. FortiNAC-F supports up to **50** simultaneous administrator logins. In a Manager environment, administrators added on the Manager must also exist on the managed servers **with the same password**.

## Administrator profiles

Profiles (**Users & Hosts > Administrators > Profiles**) are permission templates; every administrator has exactly one.

- **General tab**: Name, **Login Availability** (Always or Specify Time), **Logout After … Minutes of Inactivity**, **Lock Out After … failed attempts**, **Lock Out Duration**, **Manage Hosts And Ports** (**All** or **Restrict By Groups**), guest kiosk options.
- **Permissions tab**: per permission set, **Access**, **Add/Modify**, **Delete** and **Custom**; plus the **Landing Page**.
- Changes to a profile in use take effect **when its administrators log out and back in**.
- A profile in use can't be deleted.

Built-in profiles include **System Administrator**, **Help desk**, **Operator** and **Security analyst** (upgraded databases may also carry variants such as *Operator with messaging*). The **System Administrator** profile can't be deleted or copied, only its Inactivity Time can change, and administrators holding it **cannot be aged out**.

## Limiting an administrator to some hosts and ports

To let a team manage only its own hosts and ports:

1. Create the host and port groups (System > Groups).
2. Create a profile with the needed permissions and **Manage Hosts And Ports = Restrict By Groups**.
3. Put the administrators in an **Administrator** group and give them that profile.
4. Right-click the administrator group > **Manages**, and tick the host and port groups.
5. **Remove the administrators from the All Management group**, or they keep access to everything.

They can still see all hosts in views their profile allows (for example Locate), but can modify only the managed groups.

## Lab it yourself (optional)

Needs a FortiNAC-F POC, partner or employer appliance. Practise the allowaccess trap safely from the console: `set allowaccess https-adminui` and confirm SSH breaks, then fix it with `append allowaccess ssh`. Create a Help desk administrator, change the profile while they are logged in and watch when it applies. Without a lab, rewrite the staging steps from memory and check them against this lesson.

## Key takeaways

- Hardware staging: PC 192.168.1.1/24 on port1, SSH to 192.168.1.99 as `admin` with no password, record MAC and serial, allow `https-adminui ssh`.
- GUI: `https://<port1>:8443/`, first login `root` / `YAMS`, then create your own admin and run the Config Wizard.
- `set allowaccess` replaces the list; `append allowaccess` adds to it.
- CLI accounts (`config system admin`) and GUI administrators are separate and not shown in each other's tools.
- Administrators authenticate Local, LDAP or RADIUS and must have an administrator profile; profile changes apply at next login.
- System Administrator can't be deleted or copied and its holders never age out.
- Restrict By Groups + Manages + removal from All Management limits an admin to chosen hosts and ports.
