## The three objects

| Object | Menu (Policy & Objects) | Contains |
|---|---|---|
| **User/host profile** | User/Host Profiles | *Who/what*, *where* and *when* criteria |
| **Network access configuration** | Network Access > Configuration | The treatment: logical network, or a direct access value (VLAN, role, VPN group policy), optional CLI configuration |
| **Network access policy** | Network Access | **One** user/host profile + **one** network access configuration, ranked |

A network access policy says: *if the host and user match this profile, apply this configuration*. Policies are checked **top down from rank 1**, and the **first** policy whose profile matches is used. More than one policy can match; only the first counts.

Network access policies are used for **registered hosts only**. Rogues are handled by registration enforcement, not by these policies. A registered host that matches no policy stays on the device's **Default** VLAN (the model configuration's default is used when no other method, such as a policy, sets the VLAN).

Policy assignment is not permanent. Hosts are re-evaluated often (switch polls, agent contact, logon/logoff, IP change), and a different policy may win next time.

## User/host profiles

| Section | Options |
|---|---|
| **Where** (Location) | Groups of devices, ports or SSIDs. Any = everywhere |
| **Who/What by Group** | User or host groups with **Any**, **Any Of** (at least one), **All Of** (every one) or **None Of** (none of them) |
| **Who/What by Attribute** | Filters on host, user, adapter and RADIUS attributes (Device Type, Host OS, Role, MDM/service connector in 7.6.7, …) |
| **When** | Always, or specific days and times |

Rules inside the profile:

- Sections are combined with AND: a host must satisfy Where **and** Who/What **and** When.
- **Attribute filters**: a host must meet *all* parameters within a single filter, but only needs to match *one* filter in the list. In the GUI the **+ at the right** of a line adds an AND condition to that filter; the **+ at the bottom** adds a new filter (OR).
- An empty field counts as Any. A profile can use only location, only a group, only an attribute or only a time.
- Attributes must be known at connection time.

Two documented gotchas:

> **Watch out:** For hosts on **FortiSwitch** ports, use a **port group** in *Where*. A device group containing the FortiSwitch does **not** match.

> **Watch out:** Don't use adapter status (Adapter > Connected > Online/Offline) in profiles for network access policies. At RADIUS post-authentication time the adapter is always offline, so the profile never matches as you expect.

Also: *Who/What by RADIUS Request Attribute* works with **local RADIUS mode** (and Legacy Proxy from 7.4).

### Which identity the profile looks at

When FortiNAC-F evaluates a connection, user and host data are prioritised as:

1. **Logged-on user** and host
2. **Registered user** (owner) and host
3. **Registered host** alone

Example: the profile matches user group *Finance*. Alice logs on to `PC-17`, which is registered to her: Alice's groups are used. She logs off: still Alice's groups, as registered owner. The host is re-registered as a *device*: no logged-on user and no owner, so no user's groups count. Bob logs on: Bob's groups are used.

## Reuse

The same profile object is used by network access, endpoint compliance, authentication, Supplicant EasyConnect and portal policies, and by security rules. Editing a profile or configuration from inside a policy edits it **everywhere** it is used; **Used By** / **In Use** shows the references, and an in-use profile can't be deleted.

## The catch-all profile

A profile with Where = Any, Who/What by Group = Any, Who/What by Attribute = Any and When = Always matches every host. Every policy **below** a policy that uses it is ignored, and the GUI shows those policies **grayed out with a line through them**. Use one catch-all as the **last** policy, if at all.

### Exhibit-style example

| Rank | Policy | User/host profile | Configuration |
|---|---|---|---|
| 1 | Cameras | IP Cameras (group Any Of IP Cameras) | Cameras Config (logical network Cameras) |
| 2 | General Access | Catch All | Corp Config (logical network Corp) |
| 3 | Card Readers | Card Readers (group Any Of Card Readers) | Card Readers Config |

Rank 3 is grayed out: card readers match rank 2 first and land in Corp. Move *Card Readers* above *General Access* to fix it.

## Use case: card readers and IP cameras

IoT devices can't run an agent or log in to a portal, so they are onboarded by **device profiling** and controlled by **group membership**:

1. **Profile and register**: a device profiling rule (Users & Hosts > Device Profiling Rules) identifies the device, for example by **Vendor OUI**, or by **ONVIF** (Profile A for access control, Profile S/G/T for video). Set Registration = Automatic, Type = Camera (or the reader's type), Register as *Device in Host View*, **Add to Group** *IP Cameras* or *Card Readers*.
2. **Logical networks** `Cameras` and, if readers have their own segment, a readers network; give them access values in each switch model.
3. **User/host profiles**: Who/What by Group = Any Of *IP Cameras*. Optionally restrict Where to a port group of camera ports, or match Who/What by Attribute *Device Type = Camera* as the IoT deployment guide does.
4. **Network access configurations**: logical network `Cameras`.
5. **Network access policies** above any general or catch-all policy.
6. **Enforcement**: the ports must be in Forced Registration and Role-Based Access (or the 7.6.7 equivalents) so that an unprofiled device is isolated and a profiled one is moved.

A camera plugged into a port in a different building matches the same policy and gets that building's camera VLAN, because the logical network translates per device.

> **Real world:** Use Location or a tight Vendor OUI in the profiling rule *and* group membership in the profile. A spoofed MAC with a camera OUI still has to look like a camera to the profiling methods (and rule confirmation can disable it if it stops matching).

## Use case: contractors

Contractors are people, so the profile keys on the **user**:

| Profile setting | Example |
|---|---|
| Who/What by Group | Any Of **Contractors** (user group populated by contractor accounts or a directory group) |
| Where | Port group *Building A Ports* and SSID group *Corp SSIDs* |
| When | Monday–Friday, 07:00–19:00 |

Configuration: logical network `Contractor`, mapped on each device (VLAN 50, or a FortiGate firewall tag). Policy *Contractor Access* ranked above the employee and catch-all policies.

What happens outside the profile:

| Situation | Result |
|---|---|
| Contractor connects Saturday | The contractor profile fails on *When*; the next matching policy applies, or the Default VLAN if none matches |
| Contractor's laptop also matches an employee profile ranked higher | The employee policy wins: rank order |
| Contractor account expires | User/host aging and guest/contractor templates (Domain 4) remove access |

To keep contractors off production entirely at weekends, add a second contractor policy below the first (same group, When = Always, configuration = a restricted or dead-end-style logical network), still above any catch-all.

## Checking your work

- **Policy Details** on the host shows the matching profile, policy, configuration, access value and tags right now.
- **Edit Test** (policy simulator) answers "what if this host connected in Building B on Sunday?".
- Logs and Port Changes show the VLAN changes actually made.

## Key takeaways

- Policy = one profile + one configuration; ranked top down, first match wins; registered hosts only.
- Profile = Where AND Who/What (group: Any/Any Of/All Of/None Of; attributes: AND inside a filter, OR between filters) AND When.
- Identity priority: logged-on user → registered user → registered host.
- Catch-all (Any/Any/Any/Always) goes last; policies below it are grayed out.
- FortiSwitch locations need port groups; don't match on adapter online/offline status.
- IoT (cameras, card readers): profile → register → group → profile → logical network. Contractors: user group + When + logical network.
