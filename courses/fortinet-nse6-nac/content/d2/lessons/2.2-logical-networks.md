## The problem logical networks solve

Imagine cameras on three sites. On `FSW-Access1` the camera VLAN is 40, on `Cisco-Access1` it is 140, and behind `FGT-Branch1` there is no VLAN at all because the FortiGate controls cameras with a firewall policy. Without an abstraction you would need one network access policy per device ("cameras on FSW-Access1 → VLAN 40", "cameras on Cisco-Access1 → VLAN 140" …).

A **logical network** is a device-independent name, such as `Cameras`. Policies say *"cameras get the Cameras logical network"*. Each modeled device then says what `Cameras` means **on that device**: VLAN 40 here, VLAN 140 there, a firewall tag on the FortiGate. FortiNAC-F translates the logical value into the physical one when it enforces. The result is fewer policies and a policy set that doesn't change when you add a switch.

| Layer | Holds | Example |
|---|---|---|
| Network access policy | Profile → configuration | *IP Camera Policy*: profile *IP Cameras* → configuration *Cameras Config* |
| Network access configuration | **Logical network** (or a direct access value / CLI) | *Cameras Config* → logical network `Cameras` |
| Device model configuration | Access value per logical network | `FSW-Access1`: Cameras = 40; `Cisco-Access1`: Cameras = 140; `FGT-Branch1` VDOM: Cameras = tag `Cameras` |

## Creating logical networks

**Network > Logical Networks > Create New**: a **Name** and optional **Description**, nothing else. (In the 7.6.7 selector layout the Logical Networks page sits under Network > Configuration.) You can modify or delete them, but a logical network that is **in use** can't be deleted; **In Use** shows where it's referenced.

If you ran the guided install task **Add Predefined Network Access Policies**, sample logical networks with matching network access policies exist already. Those predefined policies are **disabled** by default.

In a FortiNAC-F Manager deployment you can create logical networks on the Manager and push them to the managed CAs, so every site uses the same names.

> **Exam tip:** Logical networks are *names only*. Nothing is enforced until a device's model configuration gives the logical network an access value **and** a network access configuration/policy assigns the logical network to hosts.

## Giving logical networks a value on each device

**Network > Inventory**, select the device, **Model Configuration** tab. Under *Access*, each logical network has a drop-down or field for its **access value** (a VLAN ID or name, a role on a wireless controller, a firewall tag on a FortiGate VDOM). Optionally set **CLI Configuration Type** to **Port Based** or **Host Based** and pick a CLI configuration per logical network.

For many devices at once: select them in the container's **Devices** tab, right-click **Set Model Configuration**, use **Add Configuration Category** to choose a logical network, set the Access Value/VLAN (and optional CLI), OK.

The built-in networks **Default, Registration, Quarantine, Dead End, Authentication and Voice** also appear as logical networks in the Model Configuration tab, but not in the Logical Networks list. In the IoT deployment guide's words, every other logical network is optional; **Registration** is the one every enforced device needs. Each newly discovered device must be given its values (or, in 7.6.7, receive them from a selector).

> **Watch out:** If a host matches a policy whose logical network has **no access value on the device it is connected to**, there is nothing to translate, so no VLAN change happens on that device. When a policy works on one switch and not another, compare the two model configurations.

### Model configuration extract

| Logical network | `FSW-Access1` access value | `Cisco-Access1` access value |
|---|---|---|
| Default | 10 | 10 |
| Registration | 100 | 100 |
| Quarantine | 110 | 110 |
| Dead End | 120 | 120 |
| Corp | 10 | 10 |
| Cameras | 40 | 140 |
| Contractor | 50 | *(blank)* |

A contractor laptop that matches the *Contractor* policy on `FSW-Access1` lands in VLAN 50. The same laptop on `Cisco-Access1` has no Contractor value to apply.

## Network access configurations and the alias option

A **network access configuration** (Policy & Objects > Network Access > Configuration) can carry:

- a **Logical Network**, the recommended way;
- or an **Access Value/VLAN** typed directly (VLAN ID, VLAN name, Aruba role, or a VPN group policy name for a VPN concentrator);
- and optionally a **CLI** configuration applied to the port.

The **Access Value is an alias** check box treats the value as a VLAN *name* that maps to different VLAN IDs on different devices. The guide limits that option to **Cisco and Brocade** devices; logical networks are the general solution.

## Network device roles (devices in Inventory)

Network access policies apply to registered **hosts**. Devices you register into **Inventory** (Device in Topology), such as printers or IP phones you poll, get access through **network device roles** instead: **Policy & Objects > Network Device Roles**.

| Column | Meaning |
|---|---|
| Rank | Evaluation order (drag rows) |
| Role | Device role to match (Any = all roles). New devices get **NAC-Default** unless you set another |
| Location | Device or port groups where the device must connect (Any = everywhere) |
| Access Value | VLAN ID/name or vendor role to apply |
| CLI | CLI configuration to apply to the port |

One role can have several mappings, for example role *Printer* → VLAN 60 in the Accounting port group and VLAN 61 in the Lobby port group. Role-Based Access enforcement must cover those ports.

## 7.6.7: Logical VLAN Mapping Configuration

With the 7.6.7 selector architecture, you don't have to type values into every device model. **Network > Configuration > Logical Networks > Logical VLAN Mapping Configuration** holds reusable objects:

- A configuration name (for example *Office*) and optional CLI configuration (Port Based or Host Based).
- **Logical Network Access Value Mappings**: pick a logical network *or an enforcement state*, a **Network Access** of **Enforce** (apply the VLAN, default), **Deny** (block, applies to RADIUS) or **Bypass** (skip VLAN assignment), and an **Access Value**: a VLAN ID (0–4094) or a vendor-specific name (with Alias for VLAN names).

A **Logical VLAN Mapping Selector** then applies the object to every device model that matches its conditions, first match by rank. One change to the object updates every device that uses it.

## Seeing who used a logical network

**Logical network host access** reports which hosts had access to each logical network over a period you choose, handy for an investigation such as *which hosts were on the Contractor network last Tuesday?*

## Key takeaways

- A logical network is a device-independent name; each device model translates it into its own VLAN, role or firewall tag.
- Policies → network access configuration (logical network) → device model configuration (access value). Missing any link means no enforcement.
- Create at Network > Logical Networks (name + description); can't delete one in use; FortiNAC-F Manager can push them.
- Built-in Default, Registration, Quarantine, Dead End, Authentication and Voice appear in Model Configuration, not in the list.
- "Access Value is an alias" works only for Cisco and Brocade.
- Devices in Inventory get access from **network device roles** (role + location → access value/CLI), not network access policies.
- 7.6.7: Logical VLAN Mapping Configurations (Enforce/Deny/Bypass) applied by selectors.
