## Why guest manager exists

Most networks carry people who are not in the directory: a sales visitor for an afternoon, a room full of training attendees, a contractor who is on site for three months. FortiNAC-F handles them with **guest manager**: temporary accounts that are role-based, time-limited and fully logged, created either by IT or by non-IT staff called **sponsors**. Guests and contractors then log in through the captive portal (or a guest SSID), FortiNAC-F checks the credentials against the guest account (or LDAP/RADIUS, see below), optionally scans the host, and moves the host to production.

Two prerequisites are easy to forget:

- **Licensing.** Guest manager is a licensed feature, and every guest host that connects consumes a concurrent licence while it is connected (released at disconnect). Events such as *Maximum Guest/Contractor Warning* and *Maximum Guest/Contractor Exceeded* warn you as you approach the limit.
- **Email/SMS.** If the server's email settings are not configured, sponsors cannot email credentials. SMS needs the relevant **Mobile Providers** enabled and the template must collect Mobile Number and Mobile Provider.

## The four visitor types

Every account is created from a **Guest/Contractor template**, and each template has a **Visitor Type**:

| Visitor type | Typical use | Notes |
|---|---|---|
| Guest | Visitor with limited or Internet-only access for a day or a few days | Can be created singly or in bulk (email = user name) |
| Contractor | Temporary worker with full or limited access for weeks or months | Same creation options as Guest |
| Conference | A group needing identical, limited access for a short event | Bulk-style accounts; authentication is **Local only** |
| Self-Registered Guest | A visitor who requests an account from their own device in the portal | Request goes to a sponsor (or is auto-created if no approval is required) |

> **Exam tip:** "Contractor" in FortiNAC-F is a visitor type on a template, not a separate licence or a separate database. Contractors and guests are both user records created from templates, and both show up in **Users & Hosts > User Accounts** as well as in the guest/contractor views.

## Templates: the policy behind every account

Templates live under **Users & Hosts > Guests & Contractors > Templates**. A sponsor can only use the templates their administrator profile allows, so the template is where you enforce what sponsors may hand out. The settings that matter most:

| Setting | What it controls |
|---|---|
| Visitor Type | Guest, Contractor, Conference or Self-Registered Guest |
| Role / *Use A Unique Role Based On This Template Name* | The role stamped on the user **and** the host. Default choices include Guest, Contractor and NAC-Default. A per-template role lets user/host profiles tell templates apart |
| Security & Access Value | Free text (for example `Contractor`) copied to each account, usable as a user/host profile filter |
| Authentication Method | **Local** (credentials in the FortiNAC-F database), **LDAP** or **RADIUS** (the email address is the login and the password is checked against the directory or RADIUS server). Conference = Local only |
| Password Length / Password Exclusions | 5 to 64 characters; generated passwords avoid look-alike characters, and you can exclude more |
| Account Duration (hours) | Caps how long the account stays in the database |
| Login Availability | **Always** or **Specify Time** (time window and days of the week) |
| Reauthentication Period / Re-registration Period | See the F 7.6.7 note below |
| Send Email / Send SMS | Whether sponsors may send credentials that way (forced on for self-registered guests) |
| Data Fields | Required / Optional / Ignored fields the guest must fill in (Email is always required) |
| Note tab | Extra text appended to printouts, emails and SMS (an SSID name, instructions) |

**How long does an account live?** Two values work together: the template's **Account Duration** and the **Account End Date** set when the account is created. FortiNAC-F uses whichever is **shorter**. The end date becomes the user's expiration date; the guest's registered host inherits the global aging setting for registered hosts. When the guest user expires, the user *and* the host are removed; if the host expires first, only the host goes.

**Login Availability** is enforced with an admin scan: outside the allowed window the guest's host is marked **At Risk** for the *Guest No Access* scan and gets moved to remediation. That only works if you have a quarantine/remediation VLAN, the quarantine option enabled, wired guest ports in the **Forced Remediation** group, and a quarantine VLAN entry in the model configuration of every switch and AP the guests use.

> **Watch out (F 7.6.7):** the template's *Reauth Period* is renamed **Re-registration Period** after F 7.6.7. When it expires (1 to 8760 hours), the registered host is **deleted and becomes a rogue again**, so the guest must go through registration again. If an authentication policy's re-authentication period has the same interval, re-registration wins; with different intervals both run independently. On earlier 7.6 builds the field is the reauthentication period. Name the build when you study this setting.

## Sponsors and administrator profiles

A sponsor is an administrator whose **administrator profile** limits them to guest work. Profiles are under **Users & Hosts > Administrators > Profiles**. There are three flavours, and they are deliberately exclusive:

| Profile | Permission set / switch | What the sponsor can do |
|---|---|---|
| Guest manager | **Guest/Contractor Accounts** permission set with **Custom** ticked, which opens the **Manage Guests** tab; the landing page defaults to Guest/Contractor Accounts | Create and manage guest, contractor and conference accounts; locate guests; view guest reports |
| Guest kiosk | **Enable Guest Kiosk**, plus a **Kiosk Template** and **Kiosk Welcome Message** | Only log in to the kiosk PC and leave the guest self-service page running. Cannot create accounts or open other views |
| Guest self registration | **Self Registration Requests** permission set; the landing page defaults to Self Registration Requests | Approve or deny self-registration requests |

The **Manage Guests** tab is where you scope a guest manager sponsor:

- **Guest Account Access**: **No** (see and send credentials for own accounts only, no modify/delete), **Own Accounts** (also modify/delete own accounts), **All Accounts** (manage every guest account).
- **Account Types**: **Individual**, **Bulk**, **Conference**.
- **Create Accounts Days in Advance (Maximum)** and **Create Accounts Active For Days (Maximum)**: limit how far ahead and how long-lived the accounts can be.
- **Can View Passwords**: enabled by default; if disabled the operator never sees generated passwords (the guest still gets them by email or SMS).
- **Allowed Templates**: **All Templates** (default) or **Specify Templates**, which picks the exact templates.

> **Exam tip:** a person who must both create accounts *and* run the lobby kiosk needs **two logins**. A kiosk-mode profile disables every other option, and a self-registration-only sponsor cannot manage guest, contractor and conference accounts.

Sponsors can be created by hand or automatically from directory groups, and self-registration sponsors need an email address in their record to receive requests. Administrators with the full profile can do everything a sponsor can.

## Portal and network pieces

Guests and contractors only reach the guest login pages if the switch ports or SSIDs they use are in a controlled group such as **Forced Registration**, so unknown hosts land in the registration isolation network. The portal content editor (**Portal > Portal Configuration**) controls what they see: **Registration > Login Menu** turns on **Guest Login** and **Self Registration Guest Login**, and **Registration > Self Registration Login** holds the self-registration settings (default sponsor email, **Require Sponsor Approval**, **Guest Request Expiration (minutes)**, notification options and the **Default Guest Template**).

For wireless guests you can also map an SSID for **Guest Management** on the controller model (Wireless Security > SSID Mappings): you pick the **Guest Template** required on that SSID, the portal, and the access and isolation user groups or VLANs.

## Lab it yourself (optional)

There is no free FortiNAC-F VM licence, so this lab needs a POC, partner or employer appliance. Reading-only path: walk the GUI paths above in the Administration Guide and sketch the objects on paper.

1. Create a role `Contractor` and a template `Contractor-90d` (Visitor Type Contractor, Local authentication, 12-character passwords, Login Availability weekdays 07:00–19:00).
2. Create a guest manager profile that allows **Individual** and **Bulk**, **Own Accounts**, and only the `Contractor-90d` template, then an administrator `sponsor1` with that profile.
3. Log in as `sponsor1`, create one contractor account and confirm in **Users & Hosts > User Accounts** that the role and Security & Access Value were applied.
4. From the CLI, list the template: `diagnose user guest-templates list name=Contractor-90d`.

## Key takeaways

- Every guest, contractor, conference or self-registered account comes from a template; the template sets role, Security & Access Value, authentication, password rules, duration and login availability.
- Account lifetime = the shorter of the template's Account Duration and the account's end date; when the guest user expires, the user and their registered host are removed.
- Login Availability works by marking the host At Risk for the Guest No Access scan, which needs a quarantine VLAN, the Forced Remediation group and model configuration entries.
- Sponsors are administrators with restricted profiles: guest manager (Manage Guests tab), kiosk (Enable Guest Kiosk) or self-registration requests. Kiosk mode excludes everything else.
- Manage Guests settings scope a sponsor: Guest Account Access (No / Own / All), Account Types, day limits, Can View Passwords, Allowed Templates.
- Guest manager needs its licence; each connected guest host uses a concurrent licence.
- F 7.6.7 renames the template's reauth period to Re-registration Period, which deletes the host back to rogue when it expires.
