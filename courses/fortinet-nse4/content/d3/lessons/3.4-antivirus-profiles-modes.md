## The job of the AV profile

An antivirus profile (`config antivirus profile`) tells FortiGate which protocols to scan, which detection techniques to use and what to do with a detection. It is attached to a firewall policy with `set av-profile`. The profile is only half the picture. The policy's **inspection mode** decides which engine scans, the **SSL/SSH inspection profile** decides whether encrypted protocols can be scanned at all, and the **protocol options profile** decides ports and size limits (next lesson).

FortiOS ships a profile called **default**. Its `feature-set` defaults to `flow`. Like web filter and DLP profiles, the feature set must match the policy's `inspection-mode`.

## Detection techniques

| Technique | What it catches | Notes |
|---|---|---|
| **Signature scanning** (AV scan) | Known malware, matched against the FortiGuard AV database | Core feature; requires the AV subscription for updates |
| **Emulator / heuristics** | Suspicious behaviour of executables in a sandboxed emulation inside the AV engine | `emulator` per protocol, enabled by default |
| **Grayware** | Adware, PUP/PUA | Forces a full scan in flow mode |
| **AI/ML detection** | New variants of EXE, PDF and Office files | `config antivirus settings` → `machine-learning-detection` |
| **Mobile malware** | Android/iOS malware | `mobile-malware-db enable` (default) |
| **FortiGuard outbreak prevention** | Hash-based detection of brand-new outbreaks before signatures exist | Licensed; per-protocol `outbreak-prevention block/monitor` |
| **0-day malware stream scanning** | Real-time malware IOCs pushed through the `fortimq` daemon | Per-protocol `malware-stream` |
| **External malware blocklist** | File hashes from your own threat feed | `external-blocklist` |
| **EMS external feed** | Malware hashes seen by FortiClient EMS | Needs the EMS Fabric connector |
| **FortiSandbox / FortiNDR** | Unknown files detonated or analysed off-box | Inline or post-transfer; FortiNDR inline is proxy-only |
| **Content disarm & reconstruction (CDR)** | Strips active content (macros, scripts, links) from Office/PDF files | **Proxy only**; HTTP, SMTP, POP3, IMAP |

## AV databases

FortiGuard publishes the AV signatures in tiers:

- **Normal.** The base set present on every FortiGate.
- **Extended.** The **default**. It covers malware currently in the wild plus recent malware that has nearly disappeared (spreading within roughly the last year).
- **Extreme.** Extended plus a large "zoo" of dormant historical malware.

The extreme database is selected with:

```text
FGT-HQ # config antivirus settings
FGT-HQ (settings) # set use-extreme-db enable
FGT-HQ (settings) # end
```

The option only exists on models that support it. Entry-level and some mid-range models do not. Per the 8.0 guide, the **FortiGate 121G** is the lowest hardware model that supports it, and all FortiGate VMs do. Using the extreme database also forces flow-mode AV into a full scan.

The **FortiSandbox database** (`set analytics-db enable` in the profile) adds signatures for malware that your FortiSandbox discovered to the scan.

> **Exam tip:** If a question asks how to detect old, rarely seen malware, the answer is the **extreme** database, provided the model supports it. Extended is the default and is enough for current threats.

## Flow-based AV

In flow mode the **IPS engine** handles AV:

- It forwards packets while it reassembles the file. With AV engine 7.0 and later, **stream-based scanning** scans HTML and JavaScript progressively from a partial buffer, and other supported files are scanned against the flow database. This is the **default scan**.
- A **full scan** is used for unsupported file types and whenever a feature needs the complete file: ML detection, the extreme database, grayware, mobile malware, external blocklists, the EMS feed, outbreak prevention, DLP and file filter. The file is cached and handed to `scanunit`.
- On a detection, the IPS engine drops the remaining data and resets the session. The user sees a broken download. The engine caches the URL, and the **replacement message appears on the next attempt**.

`diagnose test application ipsmonitor 24` shows the *FlowAV default scan* and *FlowAV legacy scan* counters, so you can see how files were handled.

### A word on history

Older FortiOS releases offered flow-mode **quick scan** (a compact signature set, very fast) and **full scan** (the whole database, with buffering). That choice no longer exists. Since AV engine 7.0, flow mode chooses between stream-based default scanning and a full scan automatically, based on file type and the features you enabled. If you meet "quick scan" in older study material, treat it as legacy.

## Proxy-based AV

In proxy mode, WAD terminates the session, and the file is either stream-scanned in-process or buffered and passed to `scanunit`:

- WAD first decides whether a simple configuration can use a quick **in-process scan**. DLP, quarantine, outbreak prevention, external blocklists, the EMS feed, CDR and AV-engine AI scanning (EXE, PDF and Office files) cannot, so those files are buffered and sent to `scanunit`, up to the oversize limit.
- `set scan-mode default` (the default) enables **stream-based scanning** for **oversized archives** (ZIP, GZIP, BZIP2, TAR, ISO 9660) over HTTP(S), FTP(S) and SCP/SFTP. They are decompressed and scanned without buffering the whole file, with no oversize limit (best effort). HTTP POST is not stream-scanned, and files that are not oversized archives are still buffered and scanned normally. Oversized non-archive files remain subject to the protocol options oversize handling.
- `set scan-mode legacy` disables stream-based scanning, mainly for troubleshooting.
- The user gets the **replacement message immediately**, because the proxy controls the HTTP response.
- **Client comforting** trickles data to the client during a long buffered scan so it does not time out.

| | Flow AV | Proxy AV |
|---|---|---|
| Engine | IPS engine (+ scanunit for full scans) | WAD + scanunit |
| Block feedback | Reset; page on second attempt | Immediate replacement message |
| CDR | No | Yes |
| Client comforting | No | Yes |
| FortiNDR inline | No | Yes |
| MAPI and SSH scanning | No | Yes |
| Sandbox, outbreak prevention, ML, external blocklist, mobile malware, archive blocking | Yes | Yes |

> **Watch out:** **MAPI** and **SSH** (SCP/SFTP) are inspected only by proxy-based AV profiles. For SSH, the SSL/SSH profile also needs SSH deep scan.

## Building a profile

```text
FGT-HQ # config antivirus profile
FGT-HQ (profile) # edit "AV-Proxy"
FGT-HQ (AV-Proxy) # set feature-set proxy
FGT-HQ (AV-Proxy) # config http
FGT-HQ (http) # set av-scan block
FGT-HQ (http) # set outbreak-prevention block
FGT-HQ (http) # set content-disarm enable
FGT-HQ (http) # end
FGT-HQ (AV-Proxy) # config smtp
FGT-HQ (smtp) # set av-scan block
FGT-HQ (smtp) # set executables virus
FGT-HQ (smtp) # end
FGT-HQ (AV-Proxy) # set av-virus-log enable
FGT-HQ (AV-Proxy) # end
```

Key points:

- Per-protocol tables: `http`, `ftp`, `imap`, `pop3`, `smtp`, `mapi`, `nntp`, `cifs`, `ssh`, and in 8.0 also `websocket`. Each protocol's `av-scan` is `disable`, `block` or `monitor`.
- `executables virus` (IMAP/POP3/SMTP/MAPI) implements **Treat Windows executables in email attachments as viruses**.
- `quarantine enable` keeps infected files. It needs a disk, or FortiAnalyzer/FortiGate Cloud.
- *Allow transmission when an error occurs* passes traffic if the scan itself fails. Disable it for a fail-closed posture.
- HTTPS, SMTPS, IMAPS, POP3S and FTPS are only scanned if the policy's SSL/SSH profile uses **deep inspection** for them.

## Lab it yourself

The trial VM has no AV subscription, so its signatures are whatever shipped with the image. The EICAR test string is included in every database, which makes it ideal:

1. Put the `default` AV profile on your outbound policy (flow mode) with deep inspection. Download EICAR over HTTPS from the client. Note the reset, then the block page on the second attempt.
2. Switch the policy to proxy mode with a proxy-feature-set AV profile and repeat. The block page appears on the first try. (Since 7.6.5, hardware FortiGates with 2 GB RAM or less lose most proxy features, but FortiGate VMs are not affected by memory size, so the 2 GB trial VM keeps proxy-based inspection. Fortinet still recommends at least 4 GB for VMs.)
3. Run `diagnose test application ipsmonitor 24` after the flow test to see the FlowAV counters.

## Key takeaways

- The AV profile chooses protocols and techniques. Inspection mode chooses the engine, the SSL profile decides whether encrypted protocols are visible, and protocol options set ports and size limits.
- Databases: normal (base), **extended (default)** and extreme (zoo, `use-extreme-db`, supported models only).
- Flow AV: IPS engine, stream-based default scan for HTML/JS, full scan via scanunit when advanced features need it. A block resets the session and the page shows on the next attempt.
- Proxy AV: WAD in-process scan for simple configurations, otherwise buffered scanning in scanunit; `scan-mode default` adds stream-based scanning of oversized archives. Immediate replacement message, client comforting.
- Proxy-only: CDR, client comforting, FortiNDR inline, MAPI and SSH scanning.
- Encrypted protocols need deep inspection to be scanned.
