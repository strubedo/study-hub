## Static URL filter in detail

The static URL filter is a **local** list (`config webfilter urlfilter`) referenced from a web filter profile (`config web` → `set urlfilter-table <id>`). It needs no FortiGuard licence, which makes it the first tool to reach for in a lab.

### Pattern types

| Type | Matching | Example |
|---|---|---|
| `simple` (default) | Exact string. By default it also matches **subdomains** of the entry | The entry `example.com` matches `example.com` and `mail.example.com`. The entry `www.example.com` does **not** match a request for plain `example.com` |
| `wildcard` | `*` and `?` glob. An entry starting with `*.` also matches the base domain | `*.example.com`, `*tracker*` |
| `regex` | Perl-compatible regular expression | `^(www\.)?example\.com$` |

`set include-subdomains disable` on a list (the URL filter table itself, added in 7.6.3) stops simple entries from matching subdomains. It applies to the simple type only.

### Actions

| Action | Effect |
|---|---|
| `block` | Deny, show the URL block page |
| `allow` | Not blocked by the URL filter. Processing **continues** with FortiGuard, content filter, AV… |
| `monitor` | Like allow, plus a log entry |
| `exempt` | Skip the remaining inspection. By default it skips everything; `set exempt` narrows it to `av`, `web-content`, `activex-java-cookie`, `dlp`, `fortiguard`, `range-block`, `pass`, `antiphish` or `all` |

Entries are evaluated **top-down, first match wins**, so put specific entries above broad wildcards.

```text
FGT-HQ # config webfilter urlfilter
FGT-HQ (urlfilter) # edit 1
FGT-HQ (1) # set name "Staff-URLs"
FGT-HQ (1) # config entries
FGT-HQ (entries) # edit 1
FGT-HQ (1) # set url "updates.example.com"
FGT-HQ (1) # set type simple
FGT-HQ (1) # set action exempt
FGT-HQ (1) # set exempt av fortiguard
FGT-HQ (1) # next
FGT-HQ (entries) # edit 2
FGT-HQ (2) # set url "*.example.com"
FGT-HQ (2) # set type wildcard
FGT-HQ (2) # set action block
FGT-HQ (2) # end
FGT-HQ (1) # end
```

> **Watch out:** With **certificate inspection**, only the hostname is visible. An entry such as `www.example.com/downloads/*` never matches HTTPS traffic until you use deep inspection. Hostname-only entries work with either profile.

### Web content filter

Banned-word lists (`config webfilter content`) score each pattern found on a returned page. Each pattern is counted once per page, whatever the number of repeats. When the sum reaches the profile's threshold (`set bword-threshold`, default 10), the page is blocked. The default pattern score is also 10, so by default a single match blocks. The content filter needs deep inspection for HTTPS.

## Web filtering issues: a troubleshooting path

### 1. Is the traffic even hitting the profile?

- Check the policy ID with `diagnose debug flow` and look at the traffic log's `policyid`.
- Make sure the profile's `feature-set` matches the policy's `inspection-mode`.
- Check that the SSL profile is right for the job: certificate inspection for domain/category, deep inspection for paths, safe search and content.
- Check whether the site uses **QUIC/HTTP/3**. In a certificate inspection profile, HTTP/3 is bypassed. Block QUIC (in the SSL profile with deep inspection, or with application control) so browsers fall back to TCP.

### 2. Can FortiGate get ratings?

Symptoms of rating trouble: everything is blocked (rating errors with *Allow websites when a rating error occurs* disabled), or everything is allowed (with it enabled).

In 8.0 the list is sorted by **RTT** (the fastest server first); the *Weight* column is no longer used for server selection. Check DNS resolution, the upstream firewall, and the FortiGuard port and protocol in `config system fortiguard` (for example, `set fortiguard-anycast`, `set protocol`, `set port`). Confirm that web filtering is not forced off (`set webfilter-force-off disable`).

### 4. Why was this URL treated this way?

- `diagnose debug application urlfilter -1`, `diagnose debug urlfilter src-addr <client-ip>` and `diagnose debug enable` show each rating decision live.
- `diagnose webfilter fortiguard cache dump` lists the local rating cache (category shown in hex: `0x34` = 52).
- `diagnose test application urlfilter 99` restarts the URL filter daemon.
- Web filter logs (Log & Report → Security Events → Web Filter) show `eventtype` (`ftgd_blk`, `ftgd_allow`, `urlfilter`…), `cat` and `catdesc`, `action` and the `profile`. A FortiGuard category block carries `msg="URL belongs to a denied category in policy"`.
- If a site is miscategorised, submit it to FortiGuard for re-rating and use a local rating override in the meantime.

## DLP blocking GenAI chatbots

FortiOS 8.0 offers three layers for controlling generative AI services, and the blueprint expects you to know where each one lives.

| Goal | Tool | Key setting |
|---|---|---|
| Block all AI sites | Web filter | FortiGuard category **100, Artificial Intelligence Technology** (group *General Interest – Business*) → block |
| Allow/monitor/block AI **applications** with AI-specific log fields | Application control | Category **GenAI** (`set category 36`), deep inspection for full visibility |
| Allow the chatbot but stop **sensitive data** being typed or uploaded into it | **DLP profile** | Keyword dictionary + rules on `http-post`, action block |

The DLP approach documented for 8.0 works like this:

1. **Dictionary** with `keyword` entries for the sensitive terms, using `set ignore-case enable`.
2. **Sensor** referencing the dictionary.
3. **DLP profile** with `set feature-set proxy` and two rules: one inspecting **files** (the default type) and one inspecting **messages** (`set type message`). Both use `set proto http-post`, `set filter-by sensor` and `set action block`. Message rules catch prompts; file rules catch uploads.
4. A **proxy-mode** firewall policy toward the chatbot FQDNs (address group) with **deep inspection**, the DLP profile, and an **application control** profile that blocks **QUIC**. Without that, the browser uses HTTP/3 and the POST never reaches the proxy.

```text
FGT-HQ # show dlp profile "genai-dlp"
config dlp profile
    edit "genai-dlp"
        set feature-set proxy
        config rule
            edit 1
                set name "genai-files"
                set severity critical
                set proto http-post
                set filter-by sensor
                set sensor "genai-terms"
                set action block
            next
            edit 2
                set name "genai-prompts"
                set type message
                set proto http-post
                set filter-by sensor
                set sensor "genai-terms"
                set action block
            next
        end
    next
end
```

A matching DLP log shows `subtype="dlp"`, the `rulename`, `action="block"`, `httpmethod="POST"` and the chatbot `hostname`. Fortinet itself notes that chatbot front ends vary and keyword DLP is not foolproof. For a hard stop, use the web filter category or the application control category. Inline CASB (proxy-only) can additionally restrict ChatGPT and Claude to **corporate tenants**.

> **Exam tip:** DLP prompt blocking needs **proxy mode + deep inspection**. A flow policy or certificate inspection cannot see the POST body.

## Lab it yourself

1. Build a URL filter with an `allow` entry for a test site and a FortiGuard category block that also covers it. Observe that *allow* does not bypass the category (on the trial you will see rating errors instead; enable `error-allow`, then disable it and compare).
2. Change the entry to `exempt` and repeat.
3. Run `diagnose debug urlfilter src-addr <client>` with `diagnose debug application urlfilter -1` while browsing, and read the decisions.
4. Build the GenAI DLP profile above against a lab web server that accepts POSTs (a simple Python HTTPS server), and post a body containing a dictionary keyword. DLP is local and needs no FortiGuard licence. The 2 GB proxy restriction applies to physical models, not to FortiGate-VMs, so the trial VM should offer the proxy-mode policy. Record what you see.

## Key takeaways

- URL filter types: simple (subdomains included by default), wildcard, regex. Actions: block, allow, monitor, exempt. First match wins.
- *Allow* continues processing; *exempt* skips it (narrow it with `set exempt`).
- Path matches, content filters and safe search need deep inspection.
- For rating problems use `diagnose debug rating`, `diagnose webfilter fortiguard statistics list` and the urlfilter debug. Growing timeouts/errors point to FortiGuard reachability.
- GenAI control: web filter category 100 (Artificial Intelligence Technology), app control category GenAI (36), and DLP keyword rules on `http-post` for prompts and files.
- DLP for GenAI requires proxy mode, deep inspection and QUIC blocked.
