## Protocol options: the profile everyone forgets

Every firewall policy with security profiles also references a **protocol options profile** (`set profile-protocol-options`, `config firewall profile-protocol-options`). The built-in one is called **default**. It does not detect anything. It tells the inspection engines **which ports carry which protocol** and **how to treat files** while they are inspected. Many AV "misses" are really protocol options decisions.

### Per-protocol settings

Each protocol has its own sub-table: `http`, `ftp`, `imap`, `pop3`, `smtp`, `nntp`, `mapi`, `dns`, `cifs` and `ssh`.

| Setting | Default (HTTP) | Meaning |
|---|---|---|
| `ports` | 80 (SMTP 25, FTP 21, POP3 110, IMAP 143, NNTP 119, DNS 53, CIFS 445, MAPI 135) | Ports treated as this protocol. **Proxy-based policies only**: flow-based inspection checks all ports regardless of this mapping |
| `inspect-all` | disable | Look for the protocol on any port (proxy mode) |
| `oversize-limit` | 10 (MB) | Largest file that will be buffered and scanned. The range depends on the model's memory |
| `uncompressed-oversize-limit` | 10 (MB) | Largest uncompressed size of an archive's contents |
| `uncompressed-nest-limit` | 12 | Deepest archive nesting level scanned |
| `options oversize` | not set | **Block** oversized files. If unset, oversized files are **passed without scanning** |
| `options clientcomfort` | not set | Client comforting (proxy mode) |
| `comfort-interval` / `comfort-amount` | 10 s / 1 byte | Every 10 seconds, release 1 byte to the client |
| `scan-bzip2` | enable | Decompress BZIP2 for scanning |
| `range-block` | disable | Block HTTP Range requests, which would let a client fetch a file in pieces |
| `switching-protocols` | bypass | What to do on HTTP 101 upgrades (WebSocket, h2c) |
| `unknown-content-encoding` | block | Unrecognised `Content-Encoding` values |
| `strip-x-forwarded-for` | disable | Remove the XFF header |

At the top level, `set oversize-log enable` (default disable) logs every file that was too large to scan. Turn it on whenever you tune the oversize limit.

```text
FGT-HQ # show firewall profile-protocol-options "PO-Staff"
config firewall profile-protocol-options
    edit "PO-Staff"
        set oversize-log enable
        config http
            set ports 80 8080
            set options clientcomfort oversize
            set oversize-limit 25
        end
        config ftp
            set ports 21
            set options oversize
        end
        ...
    next
end
```

With this profile, HTTP downloads up to 25 MB are scanned. Anything larger is **blocked** and logged. HTTP on port 8080 is treated as HTTP. Client comforting keeps slow downloads alive in proxy mode.

> **Exam tip:** Out of the box, oversized files are **allowed** (passed unscanned) because `oversize` is not in `options`. If a question shows a large infected file getting through and no AV log, check the oversize limit and the block-oversized setting before anything else.

### Client comforting

With proxy-based inspection, FortiGate holds the file until it has been scanned. On a slow download of a big file, the browser could give up. **Client comforting** sends a small amount of data (`comfort-amount`) every `comfort-interval` seconds. Know the trade-off: the bytes already sent to the client cannot be recalled if the file turns out to be infected. The last part of the file is held back, so the client never receives a complete infected file. Server comforting does the same in the other direction, for uploads.

### Ports and SSL

Protocol options ports cover the **cleartext** protocols. The ports for HTTPS, SMTPS, IMAPS, POP3S and FTPS are set in the **SSL/SSH inspection profile** (Protocol Port Mapping), and they matter for proxy-mode policies. A proxy policy carrying HTTP on 8080 needs 8080 in protocol options. HTTPS on 8443 needs 8443 in the SSL profile, or *Inspect all ports*.

## Antivirus events: logging and monitoring

AV detections are UTM logs with `subtype="virus"`. The classic EICAR detection looks like this:

```text
FGT-HQ # execute log filter category 2
FGT-HQ # execute log display
1: date=2026-10-28 time=14:07:33 eventtime=1793214453000000000 tz="-0500"
logid="0211008192" type="utm" subtype="virus" eventtype="infected"
level="warning" vd="root" policyid=10 sessionid=90214 srcip=10.0.1.25
srcport=52110 srcintf="port2" dstip=198.51.100.44 dstport=443
dstintf="port1" proto=6 service="HTTPS" direction="incoming"
action="blocked" filename="eicar.com" quarskip="Quarantine-disabled"
virus="EICAR_TEST_FILE" viruscat="Virus" dtype="av-engine"
ref="http://www.fortinet.com/ve?vn=EICAR_TEST_FILE"
url="https://www.example.com/eicar.com" profile="default"
msg="File is infected."
```

What to read:

- `eventtype="infected"` and `dtype="av-engine"`: a signature match by the AV engine.
- `action="blocked"`: the profile action was block. With `monitor`, the file is delivered and the log records that it was passed rather than blocked.
- `service="HTTPS"` with a detection proves the policy used deep inspection. Otherwise the file would have been invisible.
- `policyid` and `profile` tell you which policy and AV profile acted.

In the GUI, use Log & Report → Security Events → AntiVirus, and the threat-related FortiView views. On the CLI, `diagnose ips av stats show` displays per-protocol detected/blocked counters for **flow-based** policies (traffic handled by the IPS engine), and `diagnose ips av stats clear` resets them. Proxy-based scans do not increment these counters.

### Checking the signature package

```text
FGT-HQ # diagnose autoupdate versions | grep -A 6 "Virus Definitions"
Virus Definitions
---------
Version: 93.07126 signed
Contract Expiry Date: Sat Mar  1 2025
Last Updated using scheduled update on Fri Feb 28 23:04:11 2025
Last Update Attempt: Wed Oct 28 12:00:02 2026
Result: No Updates
```

The contract in this example expired in 2025 and the definitions are from February 2025. The FortiGate still tries to update (the last attempt is today) but gets nothing. The device still scans, but against a database that is more than 18 months old. `execute update-now` forces an update attempt, but it cannot fix an expired contract.

## Common antivirus issues

| Symptom | Likely cause | Fix |
|---|---|---|
| Infected HTTPS downloads pass, no AV log | Certificate inspection only (or exempted destination) | Deep inspection on that policy |
| Large infected files pass, no AV log | Over `oversize-limit`; oversized files pass by default | Raise the limit and/or add `options oversize`; enable `oversize-log` |
| Password-protected ZIP passes | Encrypted archives cannot be scanned | `archive-block encrypted` in the protocol table of the AV profile |
| Proxy policy misses HTTP on 8080 | Port not in protocol options | Add the port, or `inspect-all enable` |
| User sees a reset, not a block page | Flow-mode behaviour | Expected; the page shows on the next attempt. Proxy mode shows it at once |
| AV profile not selectable on the policy | `feature-set` differs from `inspection-mode` | Match them |
| New malware not detected | Expired contract or failed updates | `diagnose autoupdate versions`; fix licensing or FortiGuard reachability |
| Proxy-based traffic passes unscanned under heavy load | Conserve mode with `av-failopen pass` (the default) | Fix the memory problem. `off` and `one-shot` change the fail-open behaviour |
| MAPI or SCP traffic never scanned | Flow-mode profile | Proxy-mode policy (plus SSH deep scan for SCP/SFTP) |

`av-failopen` lives under `config system global` and governs **proxy-based** inspection while the unit is in memory conserve mode. `pass` (default) bypasses the AV proxy, so traffic goes through unscanned, together with any other profile that depends on that proxy. `off` blocks new sessions that need the AV proxy (active sessions continue). `one-shot` behaves like `pass` but keeps bypassing even after the unit leaves conserve mode, until the setting is changed or the unit restarts. **Flow-based** inspection in conserve mode follows `config ips global` → `fail-open` instead: `disable` (default) drops new sessions that need flow inspection, `enable` passes them uninspected.

## DLP blocking GenAI chatbots: the file side

Antivirus protects against what comes **in**. A GenAI chatbot problem is about what goes **out**. The DLP profile used to block sensitive prompts (previous domain lesson) also has a **file** rule (`config rule` with the default file type, `proto http-post`, `filter-by sensor`, `action block`). It inspects documents uploaded to the chatbot. Two points relate directly to antivirus:

- DLP and AV can share a policy. In flow mode, DLP forces a full scan. In proxy mode, it forces the file to `scanunit`. Both mean buffering up to the oversize limit, so an oversized upload that passes unscanned also escapes DLP.
- 8.0.1 adds **OCR-based DLP content analysis** (`config dlp settings` → `config ocr`, enabled by default, needs a DLP licence), which finds sensitive text inside images and screenshots. A user pasting a screenshot of a spreadsheet into a chatbot can therefore be caught.

The requirements are the same as for prompt blocking: proxy mode, deep inspection, QUIC blocked by application control, and a DLP profile with `feature-set proxy`.

## Lab it yourself

1. Create a protocol options profile with `oversize-limit 1` (MB) for HTTP and `oversize-log enable`, and use it with an AV profile on your outbound policy. Host a 2 MB file of random data (for example `head -c 2M /dev/urandom > big.bin`) on a Linux web server, and download it. It passes unscanned, and an oversize log appears. (Use a non-archive file: on proxy policies with `scan-mode default`, oversized archives are stream-scanned instead of skipped.)
2. Add `options oversize` and repeat. It is blocked as oversized.
3. Create a password-protected ZIP containing EICAR. Observe that it passes, then set `archive-block encrypted` and retry.
4. Run `diagnose autoupdate versions` on the trial VM and interpret the contract dates.

## Key takeaways

- Protocol options control ports, the oversize limit (default 10 MB), archive limits, client comforting and HTTP oddities.
- Oversized files are **passed unscanned by default**. Add `options oversize` to block them, and enable `oversize-log`.
- Client comforting (proxy) trickles 1 byte every 10 seconds by default to keep clients from timing out.
- AV logs: `subtype="virus"`, `eventtype="infected"`, `logid="0211008192"`. Use `execute log filter category 2`.
- Check the contract and database age with `diagnose autoupdate versions`.
- Common misses: no deep inspection, oversized files, encrypted archives, ports not mapped, flow-mode reset behaviour.
- DLP file rules complement AV for GenAI uploads. 8.0.1 adds OCR to catch text in images.
