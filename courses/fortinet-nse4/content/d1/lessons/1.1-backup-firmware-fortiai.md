## Configuration backups

A FortiGate keeps its whole configuration as one text file of CLI commands. A factory reset, a TFTP firmware load from the boot menu or a disk failure erases it, so a backup is the only way back.

### What a backup contains

The first line of every backup is a header that FortiOS checks when you restore:

```text
#config-version=FGVM64-8.00-FW-build0125-260415:opmode=0:vdom=0:user=admin
#conf_file_ver=3471258862138401
#buildno=0125
#global_vdom=1
config system global
    set hostname "FGT-HQ"
...
```

The header records the **model**, the **firmware version and build**, the operating mode, whether VDOMs are enabled and the admin who made the file. Below it is the full configuration, including passwords and keys stored in FortiOS's encrypted form.

> **Exam tip:** You can restore a configuration only onto the **same model** (the `config-version` model string must match). Restoring a file from an older firmware onto newer firmware is supported because FortiOS converts the configuration as it loads; restoring a file from *newer* firmware onto an older build is not reliable and is not supported.

### Backup options

| Option | Notes |
|---|---|
| Destination | Local PC (GUI download), USB disk (if one is inserted), or from the CLI to TFTP, FTP, SFTP or the managing FortiManager. |
| Scope | With VDOMs enabled: the whole device (**Global**) or a single VDOM. A VDOM backup can be restored only into a VDOM. |
| Encryption | Optional. When enabled you set a password; the file is encrypted and cannot be read or restored without it. Fortinet recommends encrypting backups because they contain secrets. |
| Format | FortiOS (`.conf`, the normal CLI format) or **YAML**. YAML is handy for automation and version-control diffs. The GUI backup page also offers a *password mask* option that replaces secrets in the file, useful when you share a configuration with support. |

GUI path: click the admin name at the top right, then **Configuration > Backup**. From the CLI:

```text
FGT-HQ # execute backup config tftp FGT-HQ-2026-10-29.conf 10.0.1.50
FGT-HQ # execute backup config tftp FGT-HQ-2026-10-29.conf 10.0.1.50 Str0ngP@ss
FGT-HQ # execute backup config usb FGT-HQ.conf
FGT-HQ # execute backup config management-station "before-upgrade"
```

The optional last argument on the TFTP/FTP/USB forms is the encryption password. `management-station` saves a revision to FortiManager.

### Restoring

```text
FGT-HQ # execute restore config tftp FGT-HQ-2026-10-29.conf 10.0.1.50 Str0ngP@ss
This operation will overwrite the current setting and could possibly reboot the system!
Do you want to continue? (y/n)y
```

A full configuration restore **replaces** the running configuration and **reboots** the FortiGate. Plan for an outage. Things to check first:

* Same model, compatible firmware (restore onto the same or a newer build).
* The password, if the backup was encrypted. There is no recovery without it.
* Interface names: a file from a model with `port1`–`port10` will not map onto a model with `wan1`/`internal`.

### Revisions and automatic backups

FortiOS can keep configuration **revisions** on the device (on models with disk/flash space) and can save a revision automatically when an administrator logs out (`set revision-backup-on-logout` under `config system global`) and before a firmware upgrade (`set revision-image-auto-backup`). The GUI lists them under **Configuration > Revisions**, where you can diff two revisions or roll back. Defaults for these settings vary by model and release, so check `show full-configuration system global | grep revision` on your build rather than assuming.

> **Real world:** In a managed estate FortiManager is the system of record and keeps every installed revision. Local backups still matter for the day FortiManager is unreachable.

## Firmware upgrades

### Plan the path first

FortiOS upgrades must follow a supported **upgrade path**: you cannot jump arbitrarily from an old build to 8.0. Fortinet's **Upgrade Path Tool** (on the Fortinet Document Library, and built into the GUI) takes your model, current build and target build and lists the intermediate builds you must install in order. Skipping a required step risks configuration loss, because each release converts the configuration from specific predecessor builds only.

Before an upgrade:

1. Read the **release notes** for the target build: known issues, changes in default behaviour, removed features, and the supported upgrade paths.
2. Confirm FortiCare entitlement (firmware download needs a valid contract) and check that any FortiManager/FortiAnalyzer in the Fabric runs the same or a newer version than the FortiGate.
3. **Back up the configuration** (encrypted), and note the current build.
4. Schedule a maintenance window; a standalone FortiGate reboots during the upgrade.

### Upgrade methods

| Method | How |
|---|---|
| GUI, from FortiGuard | **System > Firmware & Registration**, select the device, *Upgrade*. The GUI offers the recommended path and can follow it automatically. |
| GUI, file upload | Download the `.out` image for the exact model from the support portal and upload it. |
| CLI | `execute restore image tftp FGT_VM64-v8.0.2.F-build0201-FORTINET.out 10.0.1.50` (also `ftp`, `usb`). |
| Boot menu (console) | Interrupt boot and load the image over TFTP (usually after formatting the boot device from the same menu). The unit comes back with the **factory default configuration**, so this is a recovery method, not an upgrade method. |
| Federated upgrade | From the Security Fabric root, upgrade the FortiGate and its downstream FortiGates, FortiSwitches and FortiAPs in the right order. |
| Scheduled / automatic | Schedule an upgrade in the GUI, or enable automatic **patch** upgrades (`config system fortiguard`, `set auto-firmware-upgrade enable`). |

FortiOS images are signed; the FortiGate verifies the signature before installing. Hardware models have two firmware partitions, so the previous image remains available as a fallback (`diagnose sys flash list` shows both, and `execute set-next-reboot` chooses which to boot).

> **Watch out:** Downgrading firmware is possible but not a rollback: configuration converted forward is not converted back. To go back cleanly, install the old image and **restore the backup you took before the upgrade**.

For HA clusters see the FGCP upgrade lesson.

## FortiAI-Assist and the CLI Code Lab (new in 8.0)

FortiOS 8.0 embeds **FortiAI-Assist**, a generative-AI assistant opened from the FortiAI icon in the GUI banner. It answers configuration questions using retrieval from the FortiOS Administration Guide and CLI Reference, analyses diagnostic output you paste (for example IKE debug output or log entries), and proposes CLI.

The **CLI Code Lab** is the companion editor (GUI banner: *CLI Console > CLI Code Lab*). You describe what you want in natural language, FortiAI generates the commands, you open them in CLI Code Lab, review and edit them, and only then run them. Nothing changes until you execute it.

| Aspect | What the 8.0 docs state |
|---|---|
| Requirements | Hardware with **more than 2 GB RAM** and **FortiCare Premium**; FortiGate-VM S-series with FortiCare Premium or an Enterprise, UTP or ATP bundle. Models with 2 GB RAM or less are not supported. Internet access is required. |
| Tokens | FortiAI provider: each device gets a monthly starter allotment of 2,000,000 tokens; more can be bought and shared across a FortiCare account. Prompts, responses and thread history all consume tokens. |
| Providers | FortiAI (default; tokens billed by Fortinet) or **OpenAI** with your own API key (tokens billed by OpenAI), selected per administrator with `set gui-llm-provider openai` (plus `openai-api-key` and `openai-model`) under `config system admin`. The FortiAI provider also validates answers against the specific FortiGate model. |
| Permissions | FortiAI calls the FortiOS REST API **with the logged-in administrator's own permissions**. Access is controlled per admin profile with *Allow using AI Assistant* (`set gui-ai-assistant enable \| disable` in `config system accprofile`, default `disable`); it can be changed on `prof_admin` but not on `super_admin`. With it disabled the FortiAI icon still shows, but queries cannot be submitted. |
| Privacy | **Data masking** replaces IP addresses, MAC addresses, email addresses, phone numbers and URLs with placeholders before data is sent to the AI provider. |

```text
FGT-HQ # config system accprofile
FGT-HQ (accprofile) # edit "helpdesk_ro"
FGT-HQ (helpdesk_ro) # set gui-ai-assistant disable
FGT-HQ (helpdesk_ro) # next
FGT-HQ (accprofile) # end
```

> **Exam tip:** FortiAI does not bypass role-based access. An admin with a read-only profile who asks FortiAI to "create a policy" gets commands, but cannot commit them, because FortiAI acts through the REST API as that admin.

> **Watch out:** The free VM trial (2 GB, no FortiGuard, no FortiCare Premium) cannot use FortiAI-Assist. Learn the workflow from the docs; do not expect it in the lab.

## Use cases

* **Pre-change safety net:** take an encrypted backup to TFTP, make the change, and if it goes wrong restore (accepting the reboot) or revert the single object.
* **Hardware replacement (RMA):** restore the old unit's backup onto the replacement of the **same model**, then re-apply the license/registration for the new serial number.
* **Major upgrade 7.6 to 8.0:** run the Upgrade Path Tool, read the 8.0 release notes, back up, upgrade through each listed build, verify with `get system status`.
* **Junior admin assistance:** give the help-desk profile read-only rights and AI Assistant access so they can ask FortiAI to explain a log or a debug, without being able to apply changes.

## Lab it yourself

1. On the trial VM, run `execute backup config tftp` to a Linux TFTP server, once plain and once with a password. Open both files and compare.
2. Change the host name, then restore the plain backup and watch the reboot.
3. Back up as YAML from the GUI (try the password mask option too) and compare it to the `.conf` file.
4. Open the Upgrade Path Tool and plan a path from your current 8.0.x build to the latest 8.0 patch (you need a support contract to download images; the plan itself is free).

## Key takeaways

* The backup header records model and firmware build; restore only to the same model and the same or newer firmware.
* A full configuration restore overwrites everything and reboots the unit.
* Encrypted backups need their password to restore; there is no recovery without it.
* Follow the Upgrade Path Tool and the release notes; back up before every upgrade, and restore that backup if you need to downgrade.
* Loading firmware over TFTP from the boot menu is a recovery method: the unit returns with the factory default configuration.
* FortiAI-Assist (8.0) needs >2 GB RAM and FortiCare Premium (or a qualifying VM bundle), acts with the admin's own permissions, and supports FortiAI or OpenAI providers.
* CLI Code Lab turns natural-language prompts into CLI that you review before running; access is governed by `gui-ai-assistant` in the admin profile.
