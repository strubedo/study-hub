## Why logging is a troubleshooting tool

On a FortiGate the logs answer most "why" questions before you ever start a debug: which policy matched, whether NAT happened, which security profile blocked the traffic, who logged in and what changed. To use them you need to know what is logged, where it is stored and how to search it.

## Log types and subtypes

| Type | Subtypes (examples) | What it records |
|---|---|---|
| **Traffic** | `forward`, `local`, `multicast`, `sniffer` | Sessions through the FortiGate (forward), to or from the FortiGate itself (local), multicast and one-arm sniffer traffic. |
| **Event** | `system`, `user`, `router`, `vpn`, `ha`, `sdwan`, `wireless`, `security-rating`, ... | Things the FortiGate does: admin logins, configuration changes, HA state changes, VPN tunnel up/down, conserve mode, FortiGuard updates. |
| **Security** (UTM) | `virus`, `webfilter`, `ips`, `app-ctrl`, `dlp`, `dns`, `ssl`, `file-filter`, `anomaly`, ... | A security profile acted on traffic. |

Every log has a **log ID** that identifies the message type, a **severity level** and key=value fields. For example, forward traffic logs use `logid="0000000013"`, local traffic logs `0001000014`, a successful admin login `0100032001` and a failed admin login `0100032002`.

### Severity levels

From most to least severe: **emergency, alert, critical, error, warning, notification, information, debug**. A log destination with a threshold of `information` stores everything except `debug`. Traffic logs are logged at `notice` (notification) level.

## The log workflow

1. **Generate.** A policy with logging enabled, a security profile, or a system event creates a log message. For traffic logs the policy setting decides: `set logtraffic all` (all sessions), `utm` (only sessions where a security profile generated an event; the default), or `disable`. `set logtraffic-start enable` also logs at session start, not only at session end.
2. **Filter.** Each destination has its own filter (severity and log types), for example `config log fortianalyzer filter`.
3. **Store or send.** Locally (memory, disk) and/or remotely (FortiAnalyzer, FortiAnalyzer Cloud, FortiGate Cloud, syslog, FortiSIEM).
4. **View and analyse.** On the FortiGate (Log & Report, FortiView, dashboards), on FortiAnalyzer (Log View, FortiView, reports, event handlers), or in the SIEM.

> **Watch out:** Logging every session (`logtraffic all`) on a busy FortiGate generates a lot of data and uses CPU. Send it to FortiAnalyzer rather than to the local disk, and avoid enabling disk logging on desktop models with small flash storage.

The **implicit deny** policy does not log by default. To see denied traffic in the logs, enable logging on the implicit deny policy (GUI: right-click the implicit deny policy > *Edit*, enable *Log Violation Traffic*; CLI: `config log setting` > `set fwpolicy-implicit-log enable`).

## Log storage options

| Destination | Characteristics |
|---|---|
| **Memory** | Always available; small, shared with system memory, cleared on reboot. Good only for short-term viewing. |
| **Local disk** | Models with an internal disk or SSD. Retains logs across reboots, allows local reports and historical FortiView. Disk logging is disabled by default on some models. |
| **FortiAnalyzer** | Up to three servers (`log fortianalyzer setting`, `fortianalyzer2`, `fortianalyzer3`). Centralised storage, correlation, reports, retention policies. Uses OFTP over TCP 514. |
| **FortiAnalyzer Cloud** | Fortinet-hosted FortiAnalyzer, needs a subscription (`config log fortianalyzer-cloud setting`). |
| **FortiGate Cloud** | Cloud management and logging service; basic retention free, longer retention with a subscription (`config log fortiguard setting`). |
| **Syslog** | Up to four servers (`log syslogd setting` to `syslogd4`), UDP/TCP/TLS, formats default, CSV, CEF, RFC 5424, JSON, and in 8.0 **custom**. |

Configuring local disk logging and a severity filter:

```text
FGT-HQ # config log disk setting
FGT-HQ (setting) # set status enable
FGT-HQ (setting) # end
FGT-HQ # config log disk filter
FGT-HQ (filter) # set severity information
FGT-HQ (filter) # end
```

With VDOMs, each VDOM uses the global log settings unless you enable an override for it, in which case the VDOM can send to its own FortiAnalyzer or syslog server (the `override-setting` tables, for example `config log syslogd override-setting`).

### 8.0 logging enhancements

* **Custom syslog formats.** Build a layout with `config log custom-format`, then use `set format custom` and `set custom-log-format <name>` on the syslog server. A field exclusion list drops fields such as `date` or `eventtime` that your SIEM does not want.
* **Secure log upload.** Rolled disk logs can be uploaded on a schedule to an **SFTP** server (new `upload-destination sftp-server`; `ftp-server` remains the default), optionally in standard **LZ4** format (configured under `config log disk setting`).
* **Enhanced TACACS+ accounting**: the accounting records sent to a TACACS+ server now carry the full CLI change detail in the `reason` field, for external audit systems.

## Viewing and searching logs on the FortiGate

In the GUI, **Log & Report** has pages per type: *Forward Traffic*, *Local Traffic*, *Events* (with tabs for System, User, VPN, HA, SD-WAN, ...) and *Security Events*. Use the **log location** selector (memory, disk, FortiAnalyzer, FortiGate Cloud) to choose which store you are browsing, add filters by clicking a column header or typing `srcip==10.0.1.10`, and double-click an entry to open its details.

From the CLI (useful when the GUI is unresponsive, for example in conserve mode):

```text
FGT-HQ # execute log filter reset
FGT-HQ # execute log filter category 0
FGT-HQ # execute log filter field srcip 10.0.1.10
FGT-HQ # execute log filter field dstport 443
FGT-HQ # execute log display
2 logs found.
2 logs returned.
1: date=2026-10-29 time=09:41:07 logid="0000000013" type="traffic" subtype="forward" level="notice" vd="root" srcip=10.0.1.10 srcport=51522 srcintf="port2" dstip=198.51.100.20 dstport=443 dstintf="port1" policyid=1 action="close" proto=6 service="HTTPS" ...
```

Category numbers include `0` traffic and `1` event. `execute log filter category 1` followed by `execute log display` is the documented way to read system events from the CLI.

### Reading a traffic log

```text
date=2026-10-29 time=09:41:07 logid="0000000013" type="traffic" subtype="forward" level="notice" vd="root"
srcip=10.0.1.10 srcport=51522 srcintf="port2" srcintfrole="lan"
dstip=198.51.100.20 dstport=443 dstintf="port1" dstintfrole="wan"
sessionid=118342 proto=6 action="close" policyid=1 policytype="policy" service="HTTPS"
trandisp="snat" transip=203.0.113.10 transport=62011 duration=14 sentbyte=2210 rcvdbyte=9834
appcat="unscanned"
```

Key fields: `policyid` (which policy matched; `0` means the implicit deny), `action` (`accept`, `close`, `timeout`, `deny`, `server-rst`, `client-rst`), `trandisp` and `transip` (source NAT to 203.0.113.10), `sessionid` (correlate with `diagnose sys session list`), and byte counts.

> **Exam tip:** `action="deny"` with `policyid=0` is the implicit deny. `action="close"` with a normal policy ID means the session was allowed and finished cleanly. A session that was allowed but returned no bytes (`rcvdbyte=0`, `action="timeout"`) points to a routing, NAT or upstream problem, not a policy block.

## Session helper statistics (8.0)

**Session helpers** are the FortiGate's protocol-aware modules (ALGs) for protocols that negotiate extra connections inside the payload: FTP, TFTP, PPTP, RTSP, SIP, H.323 and others. The helper reads the control channel and opens a pinhole (an *expectation* session) for the data channel, and adjusts embedded addresses when NAT is applied. They are listed in `config system session-helper`.

FortiOS 8.0 adds statistics for the FTP, TFTP, RTSP and PPTP helpers so you can see whether the helper is doing its job:

```text
FGT-HQ # diagnose sys session help stats ftp      (counter values illustrative)
PORT Requests: 0
EPRT Requests: 0
PASV Requests: 37
PASV Replies: 37
EPSV Requests: 112
EPSV Replies: 112
RETR Requests: 140
STOR Requests: 9
```

The keyword is `help`, not `helper`. If users report that FTP logins work but directory listings or transfers hang, these counters tell you whether the helper is even seeing the PASV/EPSV/PORT negotiation. Counters that stay at zero while users are transferring files mean the helper is not processing that traffic (for example because the FTP helper entry was deleted from `config system session-helper` or the server uses a non-standard port), which explains a failing data channel. The other outputs are protocol-specific: RTSP counts streams, client ports and data sessions (created, freed and failures), PPTP counts calls established and GRE sessions created and freed, and TFTP counts client sessions created.

## Improved telemetry and visibility hooks

Beyond logs, 8.0 widens what the FortiGate can show you:

* **FortiView** dashboards for applications and **AI applications** (shadow-AI visibility), and application performance monitoring analytics.
* **FortiTelemetry** (digital experience monitoring): the FortiGate acts as a FortiTelemetry Controller for FortiTelemetry agents; each approved agent appears as a dynamic **telemetry address** object (see the public cloud lesson).
* **Session helper statistics**, as above.
* **Automation stitches** can react to log events (for example an HA failover or conserve mode) and run CLI scripts or send notifications.

## Lab it yourself

1. Enable `logtraffic all` on a policy and `fwpolicy-implicit-log enable`. Generate allowed and denied traffic from a Linux host and compare the two logs.
2. Search with `execute log filter` for your host's IP and find the `policyid`, `trandisp` and `sessionid` fields.
3. Point a syslog server (rsyslog on Linux) at the FortiGate with `config log syslogd setting`, try `set format json`, then build a custom format.
4. FTP to a server through the FortiGate and run `diagnose sys session help stats ftp` before and after a transfer.

## Key takeaways

* Log types: traffic (forward/local), event (system, user, HA, VPN, ...), security (per profile).
* Severity runs emergency > alert > critical > error > warning > notification > information > debug.
* `logtraffic utm` (default) logs only sessions with security events; `all` logs every session. The implicit deny does not log unless you enable it.
* Storage: memory, disk, up to three FortiAnalyzers, FortiAnalyzer Cloud, FortiGate Cloud, up to four syslog servers.
* `execute log filter ...` plus `execute log display` reads logs from the CLI; category 0 is traffic, 1 is event.
* 8.0 adds custom syslog formats, SFTP/LZ4 log upload, and `diagnose sys session help stats {ftp|tftp|rtsp|pptp}`.
