## Where a new FortiGate starts

Every FortiGate leaves the factory with a small, predictable configuration designed for one thing: letting an administrator reach the device and start configuring it. Knowing exactly what that configuration contains (and what it does *not* contain) is the first thing the NSE 4 exam checks, because almost every "I can't reach the GUI" problem on a new unit traces back to it.

| Item | Factory default |
|---|---|
| Administrator account | `admin` with an **empty password**. FortiOS forces you to set a new password at the first login. |
| Operating mode | NAT mode, a single `root` VDOM (multi-VDOM disabled) |
| Management IP | `192.168.1.99/24`. On mid-range and high-end models it is on the dedicated **mgmt** port; on entry-level (desktop) models it is on the LAN-side interface (named `internal`, `lan` or `port1` depending on the model). |
| DHCP server | Entry-level models typically run a DHCP server on that LAN-side interface so a laptop plugged in gets an address in 192.168.1.0/24 automatically. Larger models generally do not; set your laptop statically. |
| Firewall policies | None that allow forwarding: the only policy is the **implicit deny** at the bottom of the list. |
| Administrative access on the management interface | Management protocols such as HTTPS, SSH and PING are enabled so you can reach the GUI and CLI; other interfaces allow little or nothing. |
| Inspection mode | Flow-based in each new policy |

> **Watch out:** Defaults differ by model and by FortiOS release. The 192.168.1.99 address and the DHCP server belong to physical units. A **FortiGate-VM** has no 192.168.1.99 by default: on most hypervisor images `port1` comes up as a DHCP client, and if your hypervisor network has no DHCP server you set `port1` statically from the VM console. Always check `get system interface physical` on the console before assuming an address.

### First login checklist

1. Connect to the console (9600 8-N-1 on hardware) or to the management port at `https://192.168.1.99`.
2. Log in as `admin` with no password and set a strong new password when prompted.
3. Set the host name, time zone and NTP, and DNS servers (FortiGuard DNS is used by default).
4. Configure the WAN interface (static or DHCP/PPPoE) and a default route.
5. Register the device with FortiCare so FortiGuard entitlements download.
6. Back up this baseline configuration.

```text
FortiGate-VM64 # config system global
FortiGate-VM64 (global) # set hostname FGT-HQ
FortiGate-VM64 (global) # end
FGT-HQ # config system interface
FGT-HQ (interface) # edit port1
FGT-HQ (port1) # set mode static
FGT-HQ (port1) # set ip 203.0.113.10 255.255.255.0
FGT-HQ (port1) # set allowaccess ping
FGT-HQ (port1) # next
FGT-HQ (interface) # end
FGT-HQ # config router static
FGT-HQ (static) # edit 1
FGT-HQ (1) # set gateway 203.0.113.1
FGT-HQ (1) # set device port1
FGT-HQ (1) # next
FGT-HQ (static) # end
```

> **Real world:** The prompt changes to the new host name as soon as the `end` is accepted. On an HA cluster in 8.0 the prompt also shows the unit's role, for example `FGT-A(Primary) #`, which is a quick sanity check before you change anything.

### The seven-day setup period on newer hardware

Newer FortiGate hardware models enforce **FortiCare registration**. From the first power-on the device gives you a seven-day setup period in which you can configure it from the GUI and CLI and click *Postpone registration*. The countdown only runs while the unit is powered up. When it expires, the GUI requires you to register (or log out), and configuration changes are blocked until the device is registered; a factory reset or firmware restore resets the period. Even when enforcement applies, a limited set of configuration stays editable (interfaces, static routes, DHCP and firewall policies, plus DNS, admin and central-management settings in recent builds) so that you can get the unit onto the internet to register it. Enforcement was introduced on G-series hardware during the 7.2/7.4/7.6 trains and applies in 8.0.

> **Exam tip:** If a brand-new G-series FortiGate suddenly refuses configuration changes after a week sitting powered on in the lab, the answer is "register it with FortiCare", not "reset the admin password".

### Resetting to defaults

| Command | Result |
|---|---|
| `execute factoryreset` | Wipes the whole configuration back to factory defaults and reboots. |
| `execute factoryreset2` | Resets everything **except** VDOM, interface, system settings and static route configuration, so you keep remote management access. |
| `execute factoryreset keepvmlicense` | VM only: resets but keeps the VM license file. |

A forgotten admin password on hardware is recovered with the `maintainer` account: from the **console only**, within about 60 seconds of a hard power cycle, log in as `maintainer` with the password `bcpb` followed by the serial number in upper case. The account can be disabled with `set admin-maintainer disable` under `config system global`, in which case the only recovery is reformatting and reloading firmware.

## Administrative access

Administrative access is controlled at three layers. All three must allow the connection.

1. **Interface:** `set allowaccess` on the interface lists the management protocols the FortiGate answers on that interface (`ping`, `https`, `ssh`, `http`, `telnet`, `snmp`, `fgfm`, `radius-acct`, `probe-response`, `ftm`, `fabric`, ...). Protocols not listed are dropped.
2. **Administrator account:** each admin has a password (or remote authentication), an admin profile, optional two-factor authentication and up to ten **trusted hosts**.
3. **Global settings:** ports, timeouts, lockout and TLS versions under `config system global`.

### Trusted hosts

Trusted hosts restrict where an administrator may log in from. An admin with no trusted hosts configured can log in from any address. If you configure trusted hosts, the FortiGate refuses that admin's logins from any other source, even with the correct password.

```text
FGT-HQ # config system admin
FGT-HQ (admin) # edit "netops"
FGT-HQ (netops) # set accprofile "prof_admin"
FGT-HQ (netops) # set vdom "root"
FGT-HQ (netops) # set password ********
FGT-HQ (netops) # set trusthost1 10.0.1.0 255.255.255.0
FGT-HQ (netops) # set trusthost2 192.0.2.50 255.255.255.255
FGT-HQ (netops) # next
FGT-HQ (admin) # end
```

> **Watch out:** Trusted hosts are evaluated per administrator, and only for administrative logins. They do not stop the interface answering ping, and they do nothing for traffic passing *through* the FortiGate. To hide the management service from the internet entirely, remove `https`/`ssh` from the WAN interface's `allowaccess`, or use a local-in policy.

### Admin profiles

An **admin profile** (`config system accprofile`) sets read/write, read-only or no access for each permission group (System, Network, Firewall, Log & Report, Security Profile, VPN, User & Device, WiFi & Switch, ...). Two profiles exist by default:

| Profile | Purpose |
|---|---|
| `super_admin` | Full access to everything, including global settings and other admins. Cannot be edited or deleted. |
| `prof_admin` | Full access within the VDOMs assigned to the admin, but not global settings or other admin accounts. |

Only a `super_admin` can create other super admins. In 8.0 an admin profile also has an *Allow using AI Assistant* setting (`set gui-ai-assistant`), covered in the backup and firmware lesson.

### Changing management ports and session behaviour

```text
FGT-HQ # config system global
FGT-HQ (global) # set admin-sport 8443
FGT-HQ (global) # set admin-ssh-port 2222
FGT-HQ (global) # set admintimeout 15
FGT-HQ (global) # set admin-lockout-threshold 3
FGT-HQ (global) # set admin-lockout-duration 300
FGT-HQ (global) # end
```

| Setting | Meaning | Default |
|---|---|---|
| `admin-sport` | HTTPS GUI port | 443 |
| `admin-port` | HTTP GUI port (redirects to HTTPS while `admin-https-redirect` is enabled) | 80 |
| `admin-ssh-port` | SSH port | 22 |
| `admintimeout` | Idle timeout in minutes | 5 |
| `admin-lockout-threshold` | Failed attempts before the source IP is locked out | 3 |
| `admin-lockout-duration` | Lockout time in seconds | 60 |

> **Exam tip:** After `set admin-sport 8443`, the GUI is at `https://<ip>:8443`. If another service must use TCP 443 on the same interface (for example IPsec VPN over TCP, which defaults to port 443, or a port-forwarding VIP), it conflicts with the GUI, so moving the admin port is common practice. Remember that SSL VPN tunnel mode no longer exists in current releases; IPsec (optionally over TCP 443) replaces it.

### New in 8.0: disallowed login methods

FortiOS 8.0 adds per-administrator control over *how* an account may log in. `set disallowed-login-methods {console | gui | ssh | telnet}` under `config system admin` blocks the chosen methods for that account; selecting the GUI method blocks both HTTP and HTTPS logins for that admin, while SSH can be blocked on its own. This is useful for an automation account that should only use SSH, or a help-desk account that should only use the GUI.

```text
FGT-HQ # config system admin
FGT-HQ (admin) # edit "helpdesk"
FGT-HQ (helpdesk) # set disallowed-login-methods ssh
FGT-HQ (helpdesk) # next
FGT-HQ (admin) # end
```

### Other hardening you should recognise

* **REST API administrators** (`config system api-user`) authenticate with an API token, have their own trusted-host list, and never log in interactively.
* **Password policy** (`config system password-policy`) enforces length, complexity and expiry for admin passwords.
* **Remote admins**: an admin can authenticate against RADIUS, LDAP or TACACS+ (`set remote-auth enable`, with a wildcard admin to accept any member of a group).
* **Pre-login banner** and **post-login disclaimer** under `config system global`.

## Lab it yourself

On the free FortiGate-VM trial (3 interfaces is plenty):

1. Boot the VM, open the console and run `get system interface physical` to see whether `port1` got a DHCP address.
2. Set the admin password, then create `netops` with `prof_admin` and a trusted host for your workstation only. Try logging in from another host and confirm it fails.
3. Move the GUI to 8443 with `set admin-sport 8443` and browse to it.
4. Remove `https` from `port1`'s `allowaccess` while logged in over SSH and watch the GUI stop answering.
5. Fail three logins on purpose and confirm the lockout, then check *Log & Report > Events > System Events* for the failed-login events.

## Key takeaways

* Factory default: user `admin`, blank password (changed at first login), 192.168.1.99/24 on the mgmt or LAN-side port; entry-level models also serve DHCP there. VMs usually start with `port1` as a DHCP client instead.
* Newer hardware enforces FortiCare registration after a seven-day setup period.
* `factoryreset2` keeps interfaces, VDOMs, system settings and static routes; `factoryreset` wipes everything.
* Admin access needs the protocol in the interface `allowaccess`, a valid account, and a source inside that account's trusted hosts (if any are set).
* `super_admin` and `prof_admin` are the default profiles; `super_admin` cannot be modified.
* `admin-sport`, `admin-ssh-port`, `admintimeout` and the lockout settings live in `config system global`.
* 8.0 adds `disallowed-login-methods` per admin account.
