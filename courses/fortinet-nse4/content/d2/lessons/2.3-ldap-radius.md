## Where user identities come from

Firewall authentication proves *who* is behind a source IP, so policies can allow or deny by user or group. FortiGate can check credentials against several sources:

| Source | Configured in | Typical use |
|---|---|---|
| Local users | `config user local` | Small sites, break-glass accounts, guests |
| LDAP server | `config user ldap` | Active Directory or OpenLDAP user and group lookup |
| RADIUS server | `config user radius` | FortiAuthenticator, NPS, ISE, or MFA servers |
| TACACS+ | `config user tacacs+` | Mostly administrator authentication |
| SAML IdP | `config user saml` | SSO for VPN, ZTNA and admin login (see FortiIdentity Cloud, 2.4) |

Policies don't reference servers directly. They reference **user groups** (`config user group`), and the groups contain local users and/or remote servers.

## LDAP server configuration

GUI: **User & Authentication > LDAP Servers**.

```text
FGT-HQ # config user ldap
FGT-HQ (ldap) # edit "TRAINING-AD"
FGT-HQ (TRAINING-AD) # set server "10.0.1.5"
FGT-HQ (TRAINING-AD) # set cnid "sAMAccountName"
FGT-HQ (TRAINING-AD) # set dn "dc=training,dc=lab"
FGT-HQ (TRAINING-AD) # set type regular
FGT-HQ (TRAINING-AD) # set username "TRAINING\\svc-fgt-ldap"
FGT-HQ (TRAINING-AD) # set password <bind-password>
FGT-HQ (TRAINING-AD) # set secure ldaps
FGT-HQ (TRAINING-AD) # set port 636
FGT-HQ (TRAINING-AD) # set ca-cert "CA_Cert_1"
FGT-HQ (TRAINING-AD) # end
```

| Attribute | Default | What it does |
|---|---|---|
| `server` | – | IP or FQDN of the directory server |
| `port` | 389 | Use 636 for LDAPS |
| `cnid` | `cn` | Attribute that holds the login name. For AD use `sAMAccountName` (or `userPrincipalName` for `user@domain` logins). Case-sensitive |
| `dn` | – | Base DN where searches start, for example `dc=training,dc=lab` or a specific OU |
| `type` (bind type) | `simple` | `simple`, `anonymous` or `regular` (see below) |
| `username` / `password` | – | Bind account for `regular`. Accepts `DOMAIN\user`, `user@domain` or a full DN. In the CLI, a backslash is typed twice |
| `secure` | `disable` (CLI) | `disable`, `starttls` (port 389) or `ldaps` (port 636) |
| `ca-cert` | – | CA that must have signed the server certificate. If unset, the certificate isn't validated |
| `server-identity-check` | `enable` | Checks the server name or IP against the certificate SAN/CN |
| `group-member-check` | `user-attr` | Read groups from a user attribute (`member-attr`, default `memberOf`), or use `group-object` / `posix-group-object` |

### Bind types

| Bind type | How FortiGate finds the user | When it works |
|---|---|---|
| **Simple** | Builds the user DN directly as `cnid=<user>,<dn>` and binds with the user's password. No search | Only when every user object sits **directly** in the `dn` container. Fails for users in sub-OUs |
| **Anonymous** | Binds without credentials, searches the subtree under `dn` for `cnid=<user>`, then binds as the user | Directories that allow anonymous search (AD normally does not) |
| **Regular** | Binds with the configured service account, **searches the subtree**, then binds as the found user DN with the user's password. After the user bind succeeds, it queries the group attribute (`memberOf`) | The normal choice for Active Directory |

> **Exam tip:** "Users in OU=Sales can authenticate but users in OU=Sales,OU=Remote cannot" points to **simple** bind (no subtree search). "Authentication works for everyone but groups are never matched" usually points to the wrong `cnid`, a group DN typo in the user group, or the bind account being unable to read `memberOf`.

### FortiOS 8.0 change: secure LDAP by default in the GUI

In FortiOS 8.0 the GUI creates new LDAP servers with **secure connection enabled**, preselecting **STARTTLS**. It has no GUI option to turn security off. You can still run `set secure disable` in the CLI. Existing servers keep their old setting after an upgrade, so a server that was plaintext stays plaintext. Practical consequences:

- The directory must support STARTTLS or LDAPS, or authentication fails.
- If a private CA signed the server certificate, import that CA certificate into the FortiGate and reference it in `ca-cert`.
- Server identity checking is on by default, so `server` should match a name in the certificate. If `server` is an IP, that IP must appear in the SAN.

> **Watch out:** The **CLI** default for `secure` is still `disable`. A server created with a CLI script is plaintext unless you set `starttls` or `ldaps`. Exam items can test that the GUI and CLI defaults differ.

### Testing LDAP

The GUI has **Test Connectivity** and **Test User Credentials**. In the CLI:

```text
FGT-HQ # diagnose test authserver ldap TRAINING-AD jsmith 'S3cret!pass'
authenticate 'jsmith' against 'TRAINING-AD' succeeded!
Group membership(s) - CN=Sales,OU=Groups,DC=training,DC=lab
                      CN=Domain Users,CN=Users,DC=training,DC=lab
```

For detail, run the authentication daemon debug first:

```text
FGT-HQ # diagnose debug application fnbamd -1
FGT-HQ # diagnose debug enable
```

Typical fnbamd lines show the search filter (`search filter is: sAMAccountName=jsmith`), the search base, the bind (`Binding to 'CN=svc-fgt-ldap,...'`), the groups found (`attr='memberOf', found 2 values`), and the result (`Result for ldap svr 10.0.1.5 is SUCCESS`). LDAP result code **49** means *invalid credentials*. Active Directory adds a sub-code: `52e` wrong password, `525` user not found, `532` password expired, `533` account disabled, `775` account locked. Turn debug off afterwards with `diagnose debug disable` and `diagnose debug application fnbamd 0`.

## RADIUS server configuration

GUI: **User & Authentication > RADIUS Servers**.

```text
FGT-HQ # config user radius
FGT-HQ (radius) # edit "FAC-RADIUS"
FGT-HQ (FAC-RADIUS) # set server "10.0.1.7"
FGT-HQ (FAC-RADIUS) # set secret <shared-secret>
FGT-HQ (FAC-RADIUS) # set auth-type ms_chap_v2
FGT-HQ (FAC-RADIUS) # set nas-ip 10.0.1.254
FGT-HQ (FAC-RADIUS) # end
```

| Attribute | Default | Notes |
|---|---|---|
| `server`, `secondary-server` | – | Primary and backup RADIUS servers |
| `secret` | – | Shared secret. It must match the client entry on the server exactly |
| `auth-type` | `auto` | `auto`, `ms_chap_v2`, `ms_chap`, `chap`, `pap`. `auto` tries several methods in turn |
| `radius-port` | 0 | 0 means use the global `radius-port`, which defaults to **1812** in `config system global` |
| `nas-ip` | 0.0.0.0 | NAS-IP-Address the server sees. Must match the RADIUS client definition when the server checks it |
| `timeout` | 5 s | Per-attempt timeout |
| `all-usergroup` | `disable` | Automatically add this server to every user group |
| `require-message-authenticator` | `enable` | Rejects responses without Message-Authenticator (Blast-RADIUS hardening) |

RADIUS group mapping: RADIUS returns no LDAP-style groups. Instead the server sends the **Fortinet-Group-Name** vendor-specific attribute (VSA), and the FortiGate user group matches it with `config match` → `set group-name`. Without a match entry, any user the RADIUS server accepts belongs to the group.

```text
FGT-HQ # diagnose test authserver radius FAC-RADIUS mschap2 jsmith 'S3cret!pass'
authenticate 'jsmith' against 'mschap2' succeeded, server=primary assigned_rad_session_id=786962683 session_timeout=0 secs idle_timeout=0 secs!
Group membership(s) - VPN-users
```

The scheme argument is `pap`, `chap`, `mschap` or `mschap2`. If the test times out, check reachability, the UDP port, the shared secret, and whether the server knows the FortiGate as a client from the **source IP or NAS-IP it is actually using**.

## User groups

A **firewall** user group (the default `group-type`) ties identities to policies:

```text
FGT-HQ # config user group
FGT-HQ (group) # edit "Sales-Users"
FGT-HQ (Sales-Users) # set member "TRAINING-AD" "FAC-RADIUS" "breakglass"
FGT-HQ (Sales-Users) # config match
FGT-HQ (match) # edit 1
FGT-HQ (1) # set server-name "TRAINING-AD"
FGT-HQ (1) # set group-name "CN=Sales,OU=Groups,DC=training,DC=lab"
FGT-HQ (1) # next
FGT-HQ (match) # edit 2
FGT-HQ (2) # set server-name "FAC-RADIUS"
FGT-HQ (2) # set group-name "Sales"
FGT-HQ (2) # end
FGT-HQ (Sales-Users) # end
```

- Adding a remote server as a member **without** a match entry means *any user that server authenticates*.
- Match entries narrow that to specific LDAP group DNs or RADIUS `Fortinet-Group-Name` values.
- Local users (`breakglass`) are listed by name.
- `set authtimeout` on the group overrides the global authentication timeout. 0, the default, uses the global value.
- Other group types: `fsso-service` (FSSO groups), `rsso` (RADIUS single sign-on), `guest`, and `scim`.

Two-factor authentication can be added per local user (`set two-factor fortitoken | fortitoken-cloud | email | sms`) or provided by the RADIUS server itself (for example FortiAuthenticator with FortiToken). The CLI keyword `fortitoken-cloud` still uses the service's old name, which is now **FortiIdentity Cloud**.

## Use cases

- **AD-backed internet access by department:** an LDAP server with regular bind, one firewall group per department with `config match`, and one policy per group.
- **MFA for privileged access:** a RADIUS server pointing to FortiAuthenticator, which enforces FortiToken. The FortiGate group matches `Fortinet-Group-Name=NetAdmins`.
- **Resilience:** a RADIUS `secondary-server`, or two LDAP servers in the same user group.

## Lab it yourself

You need a Windows Server DC or a Samba AD/OpenLDAP VM on the LAN side (`port2`). No license or FortiGuard is needed.

1. Create the LDAP server in the GUI and note that STARTTLS is preselected (8.0). If your test directory has no certificate, use the CLI to set `secure disable`, for the lab only.
2. Try `type simple` with `dn` set to the domain root while your user sits in an OU. The test fails. Switch to `regular` and it succeeds.
3. Run `diagnose test authserver ldap` with a correct and then a wrong password, with `fnbamd -1` debugging on, and find error 49 / `52e`.
4. (Optional) Install FreeRADIUS on Linux, return a `Fortinet-Group-Name` attribute, and test with `diagnose test authserver radius ... pap ...`.

## Key takeaways

- Policies use **user groups**. Groups contain local users and/or remote servers, optionally filtered with `config match`.
- LDAP: `cnid` (default `cn`, AD uses `sAMAccountName`), `dn` = search base, bind types `simple` (no subtree search, default), `anonymous`, `regular` (service account plus subtree search, the usual AD choice).
- FortiOS 8.0 GUI defaults new LDAP servers to STARTTLS. The CLI default for `secure` is still `disable`, and upgrades keep existing settings.
- Test with `diagnose test authserver ldap|radius ...` and debug with `diagnose debug application fnbamd -1`. LDAP error 49 means bad credentials.
- RADIUS: shared `secret`, `auth-type auto` by default, port 1812 (global), group mapping through the **Fortinet-Group-Name** VSA.
- FortiToken Cloud is now **FortiIdentity Cloud**, but the CLI two-factor keyword is still `fortitoken-cloud`.
