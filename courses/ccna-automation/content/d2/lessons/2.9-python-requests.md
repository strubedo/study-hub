## Why `requests`

`requests` is the third-party library almost every Python network-automation script uses for REST calls; Cisco's Catalyst Center SDK (`dnacentersdk`, now also published as `catalystcentersdk`) is built on it, and the Meraki library used it up to version 3 (Meraki 4.x moved to `httpx`, a client with a very similar interface). Install it in a virtual environment with `python -m pip install requests` (on Windows `py -m pip install requests`). Everything in this lesson was checked against the requests documentation and, where it can run without a network, against requests 2.34 on Python 3.14.

Topic 2.9 asks you to *construct* a script: pick the right function and arguments from the documentation and read the response correctly. Lesson 1.2 covers what `json.loads` returns; here `response.json()` does that step for you.

## One function per method

```python
import requests

r = requests.get(url, params=..., headers=..., timeout=...)
r = requests.post(url, json=..., headers=..., timeout=...)
r = requests.put(url, json=..., headers=..., timeout=...)
r = requests.patch(url, json=..., headers=..., timeout=...)
r = requests.delete(url, headers=..., timeout=...)
r = requests.request("GET", url, ...)     # the general form behind all of them
```

## The arguments that matter

| Argument | What it does | Example |
|---|---|---|
| `params=` | Builds and **percent-encodes the query string** from a dict | `params={"limit": 50, "site": "HQ 1"}` gives `?limit=50&site=HQ+1` |
| `headers=` | Adds request headers | `headers={"X-Auth-Token": token, "Accept": "application/json"}` |
| `json=` | **Serialises** a Python object to JSON **and sets `Content-Type: application/json`** | `json={"vlanId": 30, "name": "voice"}` |
| `data=` | A **dict is form-encoded** (`Content-Type: application/x-www-form-urlencoded`); a string or bytes is sent as-is with **no** Content-Type added | `data={"user": "alice"}`, or `data=json.dumps(body)` plus your own header |
| `auth=` | Authentication; a `(user, password)` tuple means **HTTP Basic** | `auth=("alice", "example-password")` |
| `timeout=` | Seconds to wait to connect and between bytes of the response; a tuple sets them separately. **There is no default: without it a request can hang forever** | `timeout=10`, `timeout=(5, 30)` |
| `verify=` | TLS certificate checking: `True` (default), a path to a CA bundle, or `False` | `verify="/etc/ssl/lab-ca.pem"` |

What these produce, from preparing requests without sending them:

```python
>>> import requests
>>> p = requests.Request("POST", "https://api.example.com/v1/devices",
...                      json={"hostname": "sw01", "vlan": 10}).prepare()
>>> p.headers["Content-Type"], p.body
('application/json', b'{"hostname": "sw01", "vlan": 10}')
>>> p = requests.Request("POST", "https://api.example.com/v1/devices",
...                      data={"hostname": "sw01", "vlan": 10}).prepare()
>>> p.headers["Content-Type"], p.body
('application/x-www-form-urlencoded', 'hostname=sw01&vlan=10')
>>> p = requests.Request("GET", "https://api.example.com/v1/devices",
...                      params={"limit": 50, "offset": 100}, auth=("alice", "example-password")).prepare()
>>> p.url, p.headers["Authorization"]
('https://api.example.com/v1/devices?limit=50&offset=100', 'Basic YWxpY2U6ZXhhbXBsZS1wYXNzd29yZA==')
```

> **Watch out:** `data={"hostname": "sw01"}` to a JSON API is a classic mistake: the server receives `hostname=sw01` labelled as form data and answers `400` or `415`. Use `json=`. If you pass both `json=` and `data=`, the documentation says `json` is ignored.

> **Watch out:** `verify=False` makes `requests` accept **any** certificate, including expired ones and ones for the wrong host name, so anyone in the path can impersonate the server and read your token (a man-in-the-middle attack). It also prints an `InsecureRequestWarning`. It is tolerable against a throwaway lab box; the real fix is `verify="path/to/ca.pem"`.

## Reading the response

| Attribute or method | Gives you |
|---|---|
| `r.status_code` | The status code as an `int` (`201`) |
| `r.reason` | The reason phrase (`'Created'`) |
| `r.ok` | `True` if the status code is **below 400** (so a 3xx is also "ok") |
| `r.headers` | Response headers in a **case-insensitive** dict: `r.headers["content-type"]` works |
| `r.text` | The body decoded to a `str` |
| `r.content` | The body as `bytes` |
| `r.json()` | The body parsed from JSON into `dict`/`list`; raises `requests.exceptions.JSONDecodeError` if it is not JSON (for example an HTML error page or the empty body of a 204) |
| `r.raise_for_status()` | Does nothing for codes below 400; raises **`requests.exceptions.HTTPError`** for 4xx and 5xx |
| `r.links` | The parsed `Link` header: `r.links["next"]["url"]` |
| `r.url`, `r.request` | The final URL, and the prepared request that was actually sent (`r.request.headers`, `r.request.body`) |

`raise_for_status()` produces messages like this (from a constructed 404):

```text
requests.exceptions.HTTPError: 404 Client Error: Not Found for url: https://api.example.com/v1/devices/99
```

`requests` does **not** raise anything for a 4xx or 5xx by itself: `requests.get()` returns the response and leaves checking to you. Either test `r.status_code` (or `r.ok`) or call `r.raise_for_status()`.

## A complete CRUD script

```python
import os

import requests

BASE_URL = "https://api.example.com/api/v1"
API_KEY = os.environ["EXAMPLE_API_KEY"]          # never hard-code keys
HEADERS = {"Authorization": f"Bearer {API_KEY}", "Accept": "application/json"}

# Create
r = requests.post(f"{BASE_URL}/networks/N_1001/vlans", headers=HEADERS,
                  json={"vlanId": 30, "name": "voice", "subnet": "10.30.0.0/24"}, timeout=10)
if r.status_code == 201:
    print("created at", r.headers["Location"])
elif r.status_code == 409:
    print("VLAN 30 already exists")
else:
    r.raise_for_status()

# Read with query parameters
r = requests.get(f"{BASE_URL}/networks/N_1001/vlans", headers=HEADERS,
                 params={"name": "voice"}, timeout=10)
r.raise_for_status()
for vlan in r.json():
    print(vlan["vlanId"], vlan["name"])

# Modify one field
r = requests.patch(f"{BASE_URL}/networks/N_1001/vlans/30", headers=HEADERS,
                   json={"name": "voip"}, timeout=10)
r.raise_for_status()

# Delete
r = requests.delete(f"{BASE_URL}/networks/N_1001/vlans/30", headers=HEADERS, timeout=10)
if r.status_code == 204:
    print("deleted")
```

`os.environ["EXAMPLE_API_KEY"]` raises `KeyError` if the variable is not set, which is what you want: fail fast instead of calling the API without credentials. Set it with `export EXAMPLE_API_KEY=...` (Linux, macOS), `$env:EXAMPLE_API_KEY = "..."` (PowerShell) or `set EXAMPLE_API_KEY=...` (cmd).

## Sessions

A `requests.Session` keeps settings and the TCP/TLS connection between calls:

- Headers, `auth` and `verify` set on the session apply to every request made through it.
- Connections to the same host are reused (connection pooling), which is noticeably faster for many calls.
- Cookies are kept automatically, which suits cookie-based logins.
- Use it as a context manager so connections are closed.

There is no session-wide timeout setting: pass `timeout=` on each call.

## Exceptions

All exceptions that `requests` raises inherit from `requests.exceptions.RequestException`:

| Exception | Raised when |
|---|---|
| `HTTPError` | `raise_for_status()` found a 4xx or 5xx |
| `ConnectionError` | DNS failure, connection refused, network unreachable, TLS failure (`SSLError` is a subclass) |
| `Timeout` | A timeout expired; `ConnectTimeout` (safe to retry) and `ReadTimeout` are its subclasses |
| `TooManyRedirects` | The redirect limit was exceeded |
| `JSONDecodeError` | `r.json()` could not parse the body; it is also a `ValueError` |

Catch the specific ones you can handle first, then `RequestException` as a fallback.

## Example: every page, with retries on 429

This script lists every device in a network, following RFC 8288 `Link` headers (lesson 2.3) and waiting when it is rate-limited:

```python
import os
import time

import requests

BASE_URL = "https://api.example.com/api/v1"
API_KEY = os.environ.get("EXAMPLE_API_KEY", "<YOUR_API_KEY>")


def get_all(session, url, params=None, max_retries=3):
    """Follow Link rel="next" pages and return every item."""
    items = []
    while url:
        for attempt in range(max_retries + 1):
            resp = session.get(url, params=params, timeout=(5, 30))
            if resp.status_code != 429 or attempt == max_retries:
                break
            time.sleep(int(resp.headers.get("Retry-After", 1)))
        resp.raise_for_status()
        items.extend(resp.json())
        url = resp.links.get("next", {}).get("url")
        params = None   # the next URL already contains the query string
    return items


with requests.Session() as s:
    s.headers.update({"Authorization": f"Bearer {API_KEY}", "Accept": "application/json"})
    try:
        devices = get_all(s, f"{BASE_URL}/networks/N_1001/devices", params={"perPage": 2})
    except requests.exceptions.HTTPError as e:
        print("HTTP error:", e.response.status_code, e.response.text)
    except requests.exceptions.RequestException as e:
        print("Request failed:", e)
    else:
        print(f"{len(devices)} devices")
        for d in devices:
            print(f"{d['name']:<6}{d['lanIp']}")
```

Run against a simulated API (a fake transport adapter, no network) that returned two pages and one `429` with `Retry-After: 0` on the second page, it printed:

```text
3 devices
sw01  10.10.20.11
sw02  10.10.20.12
sw03  10.10.20.13
```

Points to notice: the loop ends when the response has no `next` link; `params` is dropped after the first call because the `next` URL already carries `perPage` and `startingAfter`; the 429 is retried at most `max_retries` times; and `raise_for_status()` turns any remaining error into an exception that the caller handles. The sketch assumes `Retry-After` is in seconds; it can also be an HTTP date. For offset/limit APIs, replace the `Link` logic with `offset += limit` until a page comes back shorter than `limit`; for cursor APIs, pass the returned cursor until it is empty.

> **Exam tip:** Expect a script with one blank: the function (`requests.post`), the argument (`json=`, `params=`, `headers=`, `auth=`, `timeout=`), or the attribute (`.status_code`, `.json()`, `.headers`). Read the documentation excerpt in the stem for the method and the body format, then pick the argument that produces it.

## Lab it yourself

Any computer with Python 3 and `pip install requests` (in a virtual environment: `python -m venv .venv`, or `py -m venv .venv` on Windows, then activate it with `source .venv/bin/activate` on macOS and Linux, `.venv\Scripts\Activate.ps1` in PowerShell or `.venv\Scripts\activate.bat` in `cmd.exe`):

1. Run the three `requests.Request(...).prepare()` examples above. They make no network calls, so they work offline.
2. `requests.post("https://httpbin.org/post", json={"name": "voice"}, timeout=10).json()` and look at `headers` and `json` in the echo; repeat with `data=` and look at `form`.
3. `r = requests.get("https://httpbin.org/status/404", timeout=10)`, print `r.ok`, then call `r.raise_for_status()` inside `try`/`except requests.exceptions.HTTPError`.
4. `requests.get("https://httpbin.org/delay/5", timeout=2)` and catch `requests.exceptions.Timeout`.
5. Point the CRUD script's ideas at the Meraki DevNet sandbox: with your sandbox API key in an environment variable, `GET /api/v1/organizations`, then a paginated list such as an organisation's devices with `perPage=3`, following `r.links["next"]`.

## Key takeaways

- `requests.get/post/put/patch/delete(url, ...)` return a `Response`; nothing is raised for 4xx/5xx unless you call `raise_for_status()`.
- `params=` builds the query string; `headers=` adds headers; `json=` serialises and sets `Content-Type: application/json`; `data=` form-encodes a dict.
- `auth=(user, password)` is Basic authentication; tokens and keys go in `headers=`.
- Always pass `timeout=`: requests has no default. Keep `verify=True` or point it at your CA bundle; `verify=False` is unsafe.
- Read results with `.status_code`, `.ok` (below 400), `.headers`, `.text`, `.json()` and `.links`.
- Use a `Session` for shared headers and connection reuse; catch `HTTPError`, `ConnectionError`, `Timeout` and finally `RequestException`.
- Paginate in a loop until there is no next link, cursor or short page, and back off on 429.
