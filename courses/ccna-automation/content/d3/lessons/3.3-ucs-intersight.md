## Two ways to manage Cisco servers

| | UCS Manager | Intersight |
|---|---|---|
| Where it runs | Embedded in the UCS Fabric Interconnects, on premises | Cisco cloud (SaaS); also available as an on-premises virtual appliance |
| Scope | One UCS domain: Fabric Interconnects, chassis, blades, rack servers, service profiles | Many domains and standalone servers across sites, plus HyperFlex, third-party storage and workflow orchestration |
| API | XML API: XML documents POSTed to one URL | REST API, JSON, described by an OpenAPI 3 specification |
| Authentication | `aaaLogin` returns a session cookie | API key: every request is **signed** with the key's private key |
| Python SDK | `ucsmsdk` | `intersight` |

## UCS Manager XML API

### The management information tree

UCS Manager stores all configuration and state in a hierarchical **management information tree**, and the XML API gives access to all of it. Each node is a **managed object (MO)** of a **class** (for example `computeBlade`, `orgOrg`, `lsServer` for a service profile, `fabricVlan`) and is addressed by its **distinguished name (DN)**:

```text
sys                               the system
sys/chassis-1                     chassis 1
sys/chassis-1/blade-1             blade 1 in chassis 1
org-root                          the root organisation
org-root/ls-web01                 service profile "web01"
```

The idea is the same as ACI's managed object model, so "class" and "DN" mean the same kind of thing on both platforms.

### Every call is an XML document POSTed to /nuova

The API has a single endpoint, `/nuova`, on the UCS Manager address over HTTP or HTTPS. The method is the element name in the body:

```xml
<aaaLogin inName="alice" inPassword="example-password" />
```

```xml
<aaaLogin cookie="" response="yes" outCookie="example-cookie-not-real"
          outRefreshPeriod="600" outPriv="admin,read-only" />
```

The `outCookie` value goes in the `cookie` attribute of every later request. Sessions expire after the refresh period unless renewed with `aaaRefresh`; `aaaLogout` ends them.

Query methods include:

| Method | Returns |
|---|---|
| `configResolveDn` | The object at one DN |
| `configResolveDns` | Objects at several DNs |
| `configResolveClass` | Every object of a class |
| `configResolveClasses` | Objects of several classes |
| `configResolveChildren` / `configResolveParent` | Children or parent of a DN |
| `configScope` | Class query under a DN |

Most take `inHierarchical="true"` or `"false"` to include or omit child objects. Configuration changes use `configConfMo` and `configConfMos`.

```xml
<configResolveClass cookie="example-cookie-not-real" classId="computeBlade" inHierarchical="false" />
```

The reply wraps the objects in `<outConfigs>`, each blade as an element with attributes such as `dn`, `model`, `serial`, `operState` and `totalMemory`.

### ucsmsdk

```python
import os
from ucsmsdk.ucshandle import UcsHandle

handle = UcsHandle("ucsm.example.com", "alice", os.environ["UCSM_PASSWORD"])
handle.login()
try:
    for blade in handle.query_classid("computeBlade"):
        print(blade.dn, blade.model, blade.serial, blade.oper_state)
    sp = handle.query_dn("org-root/ls-web01")
finally:
    handle.logout()
```

`query_classid` maps to `configResolveClass` and `query_dn` to `configResolveDn`; `add_mo`, `set_mo`, `remove_mo` and `commit` make changes in one transaction. The SDK exposes XML attributes as snake_case Python attributes (`operState` becomes `oper_state`).

> **Exam tip:** UCS Manager = XML API, one URL (`/nuova`), `aaaLogin` → cookie, objects addressed by class and DN in the management information tree.

## Intersight

Intersight is Cisco's cloud operations platform for compute and hybrid infrastructure: inventory and health of UCS servers in any management mode, firmware upgrades, server profiles and policies, OS installs, HyperFlex clusters, and workflow orchestration. Devices register to Intersight as **targets**.

### REST, JSON and OpenAPI

The Intersight API is REST over HTTPS at `https://intersight.com/api/v1/...`, returning JSON. Resources are named after the object model, for example:

```text
GET /api/v1/compute/PhysicalSummaries      every server, blade or rack
GET /api/v1/compute/RackUnits              rack servers
GET /api/v1/compute/Blades                 blades
GET /api/v1/asset/DeviceRegistrations      registered targets
```

Queries use OData-style parameters such as `$filter`, `$select`, `$top`, `$skip` and `$orderby`:

```text
GET /api/v1/compute/PhysicalSummaries?$filter=OperState eq 'Operable'&$select=Name,Model,Serial
```

A list response has an `ObjectType` and the objects in a `Results` array. Property names are PascalCase (`Name`, `Model`, `Serial`, `ManagementMode`, `OperState`). Cisco publishes the full OpenAPI 3 specification, and the Python SDK is generated from it.

### Authentication: signed requests with an API key

An Intersight **API key** has two parts: a **key ID** and a **private key** (a PEM file you download once). There is no login call. Instead, each request carries an HTTP **signature** computed with the private key over the request target, `Host`, `Date` and a `Digest` of the body; the server verifies it with the public half it holds. Newer keys use elliptic-curve keys and older ones RSA, which changes the signing algorithm. A leaked request cannot be replayed with a different body or date, and the private key never travels over the network.

Signing by hand is tedious, so use the SDK, which builds the signature for every call:

```python
import intersight
from intersight.api import compute_api

config = intersight.Configuration(
    host="https://intersight.com",
    signing_info=intersight.signing.HttpSigningConfiguration(
        key_id="<YOUR_API_KEY_ID>",
        private_key_path="SecretKey.txt",
        signing_scheme=intersight.signing.SCHEME_HS2019,
        signing_algorithm=intersight.signing.ALGORITHM_ECDSA_MODE_DETERMINISTIC_RFC6979,
        hash_algorithm=intersight.signing.HASH_SHA256,
        signed_headers=[
            intersight.signing.HEADER_REQUEST_TARGET,
            intersight.signing.HEADER_HOST,
            intersight.signing.HEADER_DATE,
            intersight.signing.HEADER_DIGEST,
        ],
    ),
)
client = intersight.ApiClient(config)
api = compute_api.ComputeApi(client)
result = api.get_compute_physical_summary_list(select="Name,Model,Serial")
for server in result.results:
    print(server.name, server.model, server.serial)
```

(For an older RSA key, use `ALGORITHM_RSASSA_PKCS1v15`.)

## UCS Manager or Intersight?

| Requirement | Choice |
|---|---|
| Script must run against the Fabric Interconnects of one data centre with no internet access | UCS Manager XML API |
| Report firmware of every Cisco server in 12 sites from one place | Intersight |
| An exhibit shows `<configResolveClass ... classId="computeBlade">` | UCS Manager |
| An exhibit shows `$filter=` and `Results` with PascalCase fields | Intersight |
| No login call; each request is signed with a private key | Intersight |

## Lab it yourself

1. Reserve a UCS Manager sandbox if the DevNet catalog lists one. With curl (`curl.exe` in Windows PowerShell), `POST` an `aaaLogin` document to `https://<ucsm>/nuova`, then a `configResolveClass` for `computeBlade` with the returned cookie.
2. `pip install ucsmsdk` and repeat with `UcsHandle`; print `dn` and `serial` of each blade.
3. In the Intersight documentation, open the API reference for `compute/PhysicalSummaries` and identify the `$filter` and `$select` parameters. If you have access to an Intersight account, create an API key under its settings and run the SDK example.
4. Open the Intersight OpenAPI download page and look at how many operations are defined; that is why the SDK is generated rather than hand-written.

## Key takeaways

- UCS Manager: on-premises, one domain, **XML API** to the single `/nuova` endpoint; methods are XML elements (`aaaLogin`, `configResolveDn`, `configResolveClass`, `configConfMo`).
- `aaaLogin` returns `outCookie`, sent as the `cookie` attribute on later calls; refresh with `aaaRefresh`.
- Objects live in the management information tree, addressed by class and DN (`sys/chassis-1/blade-1`); `ucsmsdk` wraps it with `UcsHandle`, `query_classid` and `query_dn`.
- Intersight: SaaS, REST + JSON, OpenAPI 3; resources like `/api/v1/compute/PhysicalSummaries`, OData `$filter`/`$select`, results in `Results`.
- Intersight API keys sign every request (key ID + private key, HTTP signature over target, host, date and digest); there is no login call.
