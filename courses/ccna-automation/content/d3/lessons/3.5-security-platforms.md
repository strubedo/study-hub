## Six security platforms, one question each

For every product in topic 3.5, know **what it protects**, **what its API lets you automate**, and **how a script authenticates**.

| Product (older name) | What it does | API highlights | Authentication |
|---|---|---|---|
| **Cisco XDR** | Cloud extended detection and response: correlates telemetry from endpoint, network, email and cloud tools into incidents | Investigate and enrich observables (IPs, hashes, domains), manage incidents and casebooks, response actions through integrated products | OAuth 2.0 client credentials: API client ID and password → access token → `Authorization: Bearer` |

## Secure Firewall Management Center REST API

The FMC REST API is the one in this list you are most likely to script by hand, and its authentication is a classic custom-token flow.

```text
1. POST https://fmc.example.com/api/fmc_platform/v1/auth/generatetoken
     Authorization: Basic <base64 of user:password>      (empty body)
2. The response body is not used; the response HEADERS carry:
     X-auth-access-token:  <access token>
     X-auth-refresh-token: <refresh token>
     DOMAIN_UUID:          a1b2c3d4-0000-4000-8000-000000000001   (made-up value)
3. GET https://fmc.example.com/api/fmc_config/v1/domain/{domainUUID}/devices/devicerecords
     X-auth-access-token: <access token>
4. Before 30 minutes pass:
   POST https://fmc.example.com/api/fmc_platform/v1/auth/refreshtoken
     X-auth-access-token: <access token>
     X-auth-refresh-token: <refresh token>
```

The quick-start guide gives the rules:

- The token request is a `POST` with Basic authentication and a blank body; the tokens come back in **response headers**, not in a JSON body.
- An access token is valid for **30 minutes** and can be **refreshed up to three times**; after that, request a new one with credentials.
- Configuration URLs are scoped to a **domain** (FMC supports multitenancy): `/api/fmc_config/v1/domain/{domainUUID}/...`. Take the UUID from the token response.
- Platform-level calls (token, server version) are under `/api/fmc_platform/v1/...`; configuration under `/api/fmc_config/v1/...`.
- The FMC has a built-in **API Explorer** for browsing and trying the endpoints.

```python
import os
import requests

FMC = "https://fmc.example.com"
resp = requests.post(f"{FMC}/api/fmc_platform/v1/auth/generatetoken",
                     auth=(os.environ["FMC_USER"], os.environ["FMC_PASSWORD"]),
                     timeout=30)
resp.raise_for_status()
headers = {"X-auth-access-token": resp.headers["X-auth-access-token"],
           "Accept": "application/json"}
domain = resp.headers["DOMAIN_UUID"]

devices = requests.get(f"{FMC}/api/fmc_config/v1/domain/{domain}/devices/devicerecords",
                       headers=headers, timeout=30).json()
for item in devices.get("items", []):
    print(item["name"], item["id"])
```

> **Exam tip:** FMC = `generatetoken` with Basic → tokens in headers → send `X-auth-access-token` → paths include `/domain/{domainUUID}/` → 30 minutes, three refreshes.

## Cisco XDR

XDR's APIs are cloud APIs reached with an **API client** you create in the XDR console (Administration → API Clients). You cannot call the APIs with the client ID and password directly; first exchange them for a token:

```bash
curl -s -u "$CLIENT_ID:$CLIENT_PASSWORD" \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -H 'Accept: application/json' \
  -d 'grant_type=client_credentials' \
  https://visibility.amp.cisco.com/iroh/oauth2/token
```

The reply is a standard OAuth 2.0 token response: `access_token`, `token_type` `bearer`, `expires_in` (600 seconds in the documented example) and `scope`. Send `Authorization: Bearer <access_token>` and request a new token when it expires. Regional clouds use regional hosts (`visibility.eu.amp.cisco.com`, `visibility.apjc.amp.cisco.com`).

## Secure Endpoint

The current Secure Endpoint API reuses that flow. You integrate Secure Endpoint with Cisco XDR or Secure Client Cloud Management, create an API client there, get an OAuth token from the `iroh/oauth2/token` endpoint above, and exchange it at `https://api.amp.cisco.com/v3/access_tokens` (or the EU or APJC equivalent) for a Secure Endpoint token. Typical automations: list computers and their health, isolate a compromised host, pull events, manage exclusions and policies. The v3 reference covers organizations, policies, computers, devices and exclusions; endpoint isolation, events and file lists are in the legacy v1 reference, which the documentation still lists separately. Responses use a `data`/`meta`/`errors` JSON envelope.

## ISE: ERS, OpenAPI and pxGrid

ISE offers two configuration API families:

- **ERS (External RESTful Services)**: REST over HTTPS on port **443 (9060 can also be used)**, under `/ers/config/<resource>`, for example `/ers/config/networkdevice`, `/ers/config/endpoint`, `/ers/config/identitygroup`. ERS must be enabled in ISE, and the user must belong to **ERS Admin** (create, read, update, delete) or **ERS Operator** (GET only). Basic authentication; `Accept` and `Content-Type` set to `application/json` (or XML).
- **OpenAPI** (ISE 3.1 and later): newer APIs under `/api/v1/...` on port 443 with a Swagger UI at `https://<ise>/api/swagger-ui/index.html`, covering things such as repositories, backup and restore, certificates, deployment and policy.

**pxGrid** (Platform Exchange Grid) is different: it is a publish/subscribe framework for **sharing context** (sessions, user identity, device profile, TrustSec tags) between ISE and other products, and for triggering actions such as Adaptive Network Control quarantines. ISE pxGrid services combine **HTTP APIs and WebSocket pub/sub**; clients are consumers or providers. There is also a **pxGrid Cloud** offering for cloud applications.

| Need | ISE interface |
|---|---|
| Add 300 switches as network access devices from a CSV | ERS `POST /ers/config/networkdevice` (or bulk) |
| A firewall should learn which user is behind an IP as soon as they authenticate | pxGrid subscription |
| Automate configuration backups | OpenAPI backup and restore |

## Secure Malware Analytics

Formerly Threat Grid, Secure Malware Analytics detonates suspicious files and URLs in an instrumented sandbox and produces a behaviour report, threat score and indicators. Its REST API (Cisco's own sample scripts use `https://panacea.threatgrid.com/api/v2/...`) lets you **submit samples** (`POST /api/v2/samples`, multipart file upload), **search** submissions and **download reports, indicators and artefacts**. Authentication is an **API key** tied to the user account. Cisco's samples put it in an `api_key` query parameter; remember from Domain 2 that keys in URLs end up in logs, so prefer a header where the API accepts one.

## Secure Connect

Cisco describes Secure Connect as a unified, turnkey SASE product that combines networking, security and visibility with client and branch connectivity: remote-access VPN and ZTNA for users, internet access policies, private-application access, and site connections from Meraki SD-WAN hubs or non-Meraki IPsec tunnels, all configured from the Meraki dashboard. For the exam, know its place (cloud-delivered SASE, Meraki-dashboard managed). Its API surface could not be documented for this course: no separate Secure Connect API reference was found on developer.cisco.com, and the Meraki Dashboard API v1 specification only treats it as a Meraki product (for example, `secureConnect` is one of the `productTypes` filter values of `GET /organizations/{organizationId}/devices`). Check developer.cisco.com and the Meraki API reference for current details before writing code against it.

## Key takeaways

- FMC: `POST /api/fmc_platform/v1/auth/generatetoken` with Basic; tokens and `DOMAIN_UUID` come back in headers; send `X-auth-access-token`; config paths `/api/fmc_config/v1/domain/{domainUUID}/...`; 30-minute tokens, three refreshes via `refreshtoken`.
- Cisco XDR: OAuth 2.0 client credentials at `https://visibility.amp.cisco.com/iroh/oauth2/token`, then `Authorization: Bearer`.
- Secure Endpoint (formerly AMP): v3 API uses the XDR/Secure Client OAuth token exchanged at `/v3/access_tokens`; isolate hosts, list computers, read events.
- ISE: ERS (`/ers/config/...`, port 443 or 9060, ERS Admin/Operator groups) and OpenAPI (`/api/v1/...`, Swagger UI); pxGrid shares context over HTTP APIs and WebSocket pub/sub.
- Secure Malware Analytics (formerly Threat Grid): submit samples, retrieve reports and indicators, API key per user.
- Secure Connect: cloud SASE managed from the Meraki dashboard.
