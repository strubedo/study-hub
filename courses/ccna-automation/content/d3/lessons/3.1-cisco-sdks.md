## Why use an SDK at all?

Domain 2 built every call by hand with `requests`: method, URL, headers, body, status check. A **software development kit (SDK)** wraps that work for one platform in a Python package. Instead of composing `GET /organizations/{organizationId}/devices` you call a method, and the library does the rest.

What a good Cisco SDK adds over raw `requests`:

| Raw `requests` | SDK |
|---|---|
| You build the base URL and every path | Methods named after the API operations, base URL built in |
| You add the auth header or log in and track the token | Reads the credential (often from an environment variable), logs in and re-logs in for you |
| You loop over `Link` headers or `offset`/`limit` yourself | Built-in pagination, often one keyword argument |
| You sleep on `429` and honour `Retry-After` | Automatic retry and back-off |
| You parse JSON into dicts and check `status_code` | Python objects or dicts, plus a library-specific exception on failure |

What it costs you:

- **A dependency to manage.** The SDK version must match the platform version you talk to, and a stale SDK may not know a new operation.
- **Abstraction.** When something fails you still have to know which HTTP call the method made; the API documentation is still the source of truth.
- **Status.** Several Cisco SDKs are *community developed* or have been replaced. Check the README and the package index before you build on one.

> **Exam tip:** Topic 3.1 says "given SDK documentation". Expect an excerpt of an SDK's docs and a script with a missing line: the constructor, the method name, the keyword argument for pagination, or the attribute to read from the result.

## Reading SDK documentation

Every SDK page answers the same five questions. Find them before writing code:

1. **Install name and import name.** They can differ (`pip install webexpythonsdk`, `from webexpythonsdk import WebexAPI`).
2. **The connection object** and its arguments: base URL, credentials, API version, TLS verification.
3. **Where credentials come from.** Most Cisco SDKs read an environment variable when you pass nothing, which keeps secrets out of the script.
4. **How methods are named and grouped**: `client.<group>.<operation>(...)`.
5. **What comes back**: a list of dicts, an object with attributes, or a wrapper with a `.response` field, and which exception a failure raises.

## The Cisco SDKs and their current status

Status below was checked on PyPI and each project's README in November 2026.

| Platform | Install | Connection object | Status |
|---|---|---|---|
| Meraki Dashboard API | `pip install meraki` | `meraki.DashboardAPI()`; key from `MERAKI_DASHBOARD_API_KEY` | Current (4.x). Generated from the Dashboard API OpenAPI spec; community supported; built on `httpx`, not `requests` |
| Catalyst Center | `pip install catalystcentersdk` | `from catalystcentersdk import api`, then `api.CatalystCenterAPI(...)` | Current, community developed; its compatibility matrix covers Catalyst Center API versions 2.3.7.6 to 3.2.3.0 |
| Catalyst Center (older name) | `pip install dnacentersdk` | `from dnacentersdk import DNACenterAPI` | Still released (2.11.x in 2026) for API versions up to 3.1.x; the name dates from DNA Center |
| Webex | `pip install webexpythonsdk` | `from webexpythonsdk import WebexAPI`; token from `WEBEX_ACCESS_TOKEN` | Current; Python 3.10+ |
| Webex (older name) | `pip install webexteamssdk` | `WebexTeamsAPI()` | Replaced: v1.7 was announced as the last release; the README points to `webexpythonsdk` |
| ACI | Cobra: the `acicobra` and `acimodel` wheels | `cobra.mit.session.LoginSession` and `cobra.mit.access.MoDirectory` | Current, officially supported by the ACI team. The wheels are downloaded from your own APIC at `https://<apic>/cobra/_downloads/`, matched to its version |
| ACI (toolkit) | `acitoolkit` | `acitoolkit.Session` | **Deprecated**, no longer maintained; its README recommends Cobra, the Ansible collection or Terraform instead |

| Intersight | `pip install intersight` | `intersight.ApiClient(configuration)` with HTTP-signature settings | Current; generated from the Intersight OpenAPI 3 spec and updated very frequently |

> **Watch out:** Older study material uses `webexteamssdk` and `dnacentersdk` with DNA Center wording. For new code use `webexpythonsdk`, and for current Catalyst Center releases `catalystcentersdk`. Both renamed packages kept the same programming style, so old examples still teach the pattern.

## Meraki: `meraki.DashboardAPI`

Methods follow the pattern `dashboard.<scope>.<operationId>`, where the scope is the first tag in the OpenAPI spec and the operation id is the one in the API reference. `getOrganizations` lives under `organizations`, `getNetworkClients` under `networks`.

```python
import meraki

# Reads MERAKI_DASHBOARD_API_KEY from the environment.
dashboard = meraki.DashboardAPI(suppress_logging=True)

orgs = dashboard.organizations.getOrganizations()
org_id = orgs[0]["id"]

# total_pages="all" makes the SDK follow every Link: rel=next page.
devices = dashboard.organizations.getOrganizationDevices(
    org_id, total_pages="all", perPage=1000
)
for dev in devices:
    print(dev["serial"], dev["model"], dev.get("name", ""))
```

Points the documentation makes that the exam likes:

- The path parameter (`organizationId`) is a positional argument; query parameters are keyword arguments with the exact API spelling (`perPage`, `productTypes`).
- Paginated methods take `total_pages` (an integer, or `-1`/`"all"`) and `direction` (`"next"` or `"prev"`).
- Results are plain Python lists and dicts parsed from the JSON.
- Failures raise `meraki.APIError`, which carries `.status`, `.reason` and `.message`.
- "Smart flow" rate limiting is on by default: the SDK paces calls to stay under the documented 10 requests per second per organisation.

```python
try:
    dashboard.networks.getNetworkClients("N_1001", timespan=3600)
except meraki.APIError as err:
    print(err.status, err.reason, err.message)
```

## Catalyst Center: `catalystcentersdk` and `dnacentersdk`

The connection object logs in with Basic authentication, stores the token and adds `X-Auth-Token` to every call. You pass the API **version** your controller runs, so the SDK picks matching method signatures.

```python
import os
from catalystcentersdk import api

catalyst = api.CatalystCenterAPI(
    base_url="https://catalyst.example.com:443",
    username=os.environ["CC_USER"],
    password=os.environ["CC_PASSWORD"],
    version="3.2.3.0",
    verify=True,
)

devices = catalyst.devices.get_device_list(family="Switches and Hubs")
for device in devices.response:
    print(f"{device.hostname:20}{device.managementIpAddress}")
```

The return value mirrors the JSON envelope (`{"response": [...], "version": "..."}`) but allows attribute access: `devices.response[0].hostname`. The `dnacentersdk` equivalent is `DNACenterAPI(...)` with the same arguments and the same `dnac.devices.get_device_list()` call. Asynchronous operations return a task id that you check with `task.get_task_by_id(task_id=...)`, the same pattern as the raw API.

## Webex: `webexpythonsdk`

```python
from webexpythonsdk import WebexAPI

api = WebexAPI()            # reads WEBEX_ACCESS_TOKEN
room = api.rooms.create("NOC change window")
api.memberships.create(room.id, personEmail="alice@example.com")
api.messages.create(room.id, markdown="**Maintenance** starts at 22:00 UTC")

for msg in api.messages.list(roomId=room.id):   # pagination handled for you
    print(msg.personEmail, msg.text)
```

The README lists what the SDK does for you: it sources the token from the environment, follows pagination transparently, waits and retries on rate limits, and returns native objects (`room.id`, `msg.text`).

## ACI Cobra, UCS Manager and Intersight at a glance

Cobra models the whole ACI Management Information Tree as Python classes:

```python
from cobra.mit.access import MoDirectory
from cobra.mit.session import LoginSession

session = LoginSession("https://apic.example.com", "alice", "example-password")
md = MoDirectory(session)
md.login()
for tenant in md.lookupByClass("fvTenant"):
    print(tenant.dn, tenant.name)
md.logout()
```

`ucsmsdk` follows the same managed-object idea for UCS Manager (`handle.query_classid("computeBlade")`, `handle.query_dn("sys/chassis-1/blade-1")`), and the Intersight SDK hides the HTTP request signing that Intersight API keys need. Lesson 3.3 shows both.

## Lab it yourself

From any computer with Python 3.11 or later (`meraki` 4.7.0 declares `requires-python >=3.11`; use a virtual environment: `python -m venv .venv`, then activate it with `source .venv/bin/activate` on macOS or Linux or `.venv\Scripts\activate` on Windows):

1. `pip install meraki webexpythonsdk catalystcentersdk`, then `pip show meraki` and compare its version with PyPI.
2. In a Python shell, `import meraki` and run `help(meraki.DashboardAPI)`, then `help(meraki.api.organizations.Organizations.getOrganizationDevices)` and find `total_pages` and `perPage`. The docstrings are the SDK documentation, and neither call touches the network.
3. Reserve the Meraki sandbox listed in the DevNet Sandbox catalog, export the key it gives you as `MERAKI_DASHBOARD_API_KEY`, and run the Meraki script above.
4. Create a free Webex developer account, copy your personal access token from developer.webex.com, export it as `WEBEX_ACCESS_TOKEN`, and run the Webex script. Delete the test space afterwards.
5. Compare: write the Meraki call again with `requests` (lesson 3.9) and list everything the SDK did that you now do by hand.

## Key takeaways

- An SDK wraps auth, base URLs, pagination, rate-limit retries and JSON parsing; the API docs remain the reference for what each method does.
- Read the SDK docs for the install and import names, the connection object, where credentials come from, method naming and return types.
- Meraki: `meraki.DashboardAPI()` reads `MERAKI_DASHBOARD_API_KEY`; methods are `dashboard.<scope>.<operationId>()`; `total_pages="all"` paginates; errors raise `meraki.APIError`.
- Catalyst Center: `catalystcentersdk` (`api.CatalystCenterAPI`) for current releases, `dnacentersdk` (`DNACenterAPI`) for older ones; pass the API version; results expose `.response`.
- Webex: `webexpythonsdk` (`WebexAPI`, token from `WEBEX_ACCESS_TOKEN`) replaced `webexteamssdk`.
- ACI: Cobra is the supported SDK and comes from your APIC; `acitoolkit` is deprecated.
- `ucsmsdk` (`UcsHandle`) and the `intersight` package cover compute.
