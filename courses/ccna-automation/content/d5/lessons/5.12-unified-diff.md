## Why network engineers read diffs

A unified diff is how every change in this domain is reviewed: a merge request shows one, `ansible-playbook --check --diff` prints one, `pyats diff` borrows its symbols, and `git diff` produces it by default. Lesson 1.8 used `git diff` as a command; this lesson reads its output line by line. Every diff below was produced by GNU diffutils 3.12 and Git 2.55 in a throwaway directory.

## The example change

A switch configuration, `sw01.cfg`, gets a camera VLAN, a port moved to it, and a different NTP server. Old file on the left, with line numbers:

```text
 1 hostname sw01
 2 !
 3 vlan 10
 4  name users
 5 vlan 20
 6  name voice
 7 !
 8 interface GigabitEthernet1/0/1
 9  description uplink to core
10  switchport mode trunk
11 !
12 interface GigabitEthernet1/0/2
13  description desk 2-14
14  switchport mode access
15  switchport access vlan 10
16  spanning-tree portfast
17 !
18 interface GigabitEthernet1/0/3
19  description printer 2-01
20  switchport mode access
21  switchport access vlan 10
22 !
23 ntp server 192.0.2.10
24 logging host 192.0.2.20
```

## diff -u

```text
$ diff -u old/sw01.cfg new/sw01.cfg
--- old/sw01.cfg	2026-11-20 09:00:00.000000000 +0000
+++ new/sw01.cfg	2026-11-21 14:30:00.000000000 +0000
@@ -4,6 +4,8 @@
  name users
 vlan 20
  name voice
+vlan 30
+ name cameras
 !
 interface GigabitEthernet1/0/1
  description uplink to core
@@ -16,9 +18,9 @@
  spanning-tree portfast
 !
 interface GigabitEthernet1/0/3
- description printer 2-01
+ description camera 2-01
  switchport mode access
- switchport access vlan 10
+ switchport access vlan 30
 !
-ntp server 192.0.2.10
+ntp server 192.0.2.11
 logging host 192.0.2.20
```

### The two-line header

- `--- old/sw01.cfg` names the **old** ("from") file and its modification time; `+++ new/sw01.cfg` names the **new** ("to") file. The `-` and `+` here set the convention for the whole diff: `-` belongs to the old file, `+` to the new.
- `diff` exits with status **1** when the files differ (0 when identical, 2 on trouble), which is how scripts test for changes.

### Hunks

Each `@@ ... @@` line starts a **hunk**, one region of change with its surrounding context:

```text
@@ -4,6 +4,8 @@
     |  |  |  +-- 8 lines of this hunk in the new file
     |  |  +----- starting at line 4 of the new file
     |  +-------- 6 lines of this hunk in the old file
     +----------- starting at line 4 of the old file
```

The format is `@@ -start,count +start,count @@`, old first, new second. The counts include **context** lines.

Then every line in the hunk begins with one character:

| First character | Meaning | Counted in |
|---|---|---|
| space | **Context**: unchanged, present in both files | old and new counts |
| `-` | **Removed**: only in the old file | old count |
| `+` | **Added**: only in the new file | new count |

Check the first hunk: 6 old lines are the 6 context lines (old lines 4 to 9); the new side has those 6 plus 2 added lines, so 8 (new lines 4 to 11). By default `diff -u` and `git diff` show **3 lines of context** before and after each change (`-U n` changes it).

The second hunk, `@@ -16,9 +18,9 @@`, starts at old line 16 but new line **18**: the two lines added in the first hunk pushed everything after them down by two. It holds 3 removals and 3 additions, so both counts are 9. A changed line always appears as a `-` line followed by a `+` line; there is no "modified" marker.

### What the change does

- Adds VLAN 30 named `cameras` (new lines 7 and 8).
- Renames the description of GigabitEthernet1/0/3 and moves it from VLAN 10 to VLAN 30.
- Replaces NTP server 192.0.2.10 with 192.0.2.11.
- Leaves everything else, including GigabitEthernet1/0/2 and the logging host, unchanged.

> **Exam tip:** To find a line's number in the **new** file, start at the `+` start of its hunk and count down through context and `+` lines only, skipping `-` lines. For the **old** file, start at the `-` start and count context and `-` lines, skipping `+` lines. `switchport access vlan 30` is new line 23: 18, 19, 20 for the three context lines, 21 for the `+ description`, 22 for `switchport mode access`, 23.

## Zero-context and single-line hunks

With `-U0` (no context) the same change becomes four hunks:

```text
$ diff -U0 old/sw01.cfg new/sw01.cfg
--- old/sw01.cfg	2026-11-20 09:00:00.000000000 +0000
+++ new/sw01.cfg	2026-11-21 14:30:00.000000000 +0000
@@ -6,0 +7,2 @@
+vlan 30
+ name cameras
@@ -19 +21 @@
- description printer 2-01
+ description camera 2-01
@@ -21 +23 @@
- switchport access vlan 10
+ switchport access vlan 30
@@ -23 +25 @@
-ntp server 192.0.2.10
+ntp server 192.0.2.11
```

- A count of **1 is omitted**: `@@ -19 +21 @@` means one line at old line 19 replaced by one line at new line 21.
- A count of **0** means that side has no lines: `-6,0` says nothing was removed, and the insertion comes **after** old line 6; `+7,2` says the two new lines are new lines 7 and 8. The mirror image, `@@ -3,2 +2,0 @@` with two `-` lines, deletes old lines 3 and 4, which would have come after new line 2.
- A whole new file shows `@@ -0,0 +1,N @@`; a deleted file `@@ -1,N +0,0 @@`.

## What git diff adds

```text
$ git diff
diff --git a/sw01.cfg b/sw01.cfg
index 210a8c6..78056c2 100644
--- a/sw01.cfg
+++ b/sw01.cfg
@@ -4,6 +4,8 @@ vlan 10
  name users
 vlan 20
  name voice
+vlan 30
+ name cameras
 !
 interface GigabitEthernet1/0/1
  description uplink to core
@@ -16,9 +18,9 @@ interface GigabitEthernet1/0/2
  spanning-tree portfast
 !
 interface GigabitEthernet1/0/3
- description printer 2-01
+ description camera 2-01
  switchport mode access
- switchport access vlan 10
+ switchport access vlan 30
 !
-ntp server 192.0.2.10
+ntp server 192.0.2.11
 logging host 192.0.2.20
```

The hunks are identical. Git adds:

| Line | Meaning |
|---|---|
| `diff --git a/sw01.cfg b/sw01.cfg` | One header per file. `a/` is the old side, `b/` the new side (for plain `git diff`, the staging area versus the working tree; for `--staged`, the last commit versus the staging area) |
| `index 210a8c6..78056c2 100644` | Abbreviated blob hashes of the old and new contents, and the file mode (`100644` regular file, `100755` executable) |
| `--- a/sw01.cfg`, `+++ b/sw01.cfg` | Paths with the `a/` and `b/` prefixes, no timestamps |
| Text after the second `@@` | The **hunk header context**: the nearest earlier line that looks like a function heading. Git's default treats a line starting with a letter, `_` or `$` as one, so for a config file it shows the enclosing block (`interface GigabitEthernet1/0/2`) |

Extended header lines appear for special cases. Adding a new file:

```text
diff --git a/ntp.yml b/ntp.yml
new file mode 100644
index 0000000..3e05712
--- /dev/null
+++ b/ntp.yml
@@ -0,0 +1,3 @@
+ntp_servers:
+  - 192.0.2.11
+  - 192.0.2.12
```

`new file mode` and `--- /dev/null` mark a creation; a deletion shows `deleted file mode` and `+++ /dev/null`; a rename shows `similarity index`, `rename from` and `rename to`; a permission change shows `old mode` and `new mode`.

Related commands: `git diff` (working tree versus the staging area), `git diff --staged` (staged versus the last commit, what the next commit will contain), `git diff main..feature` (two commits or branches), `git diff --stat` (a summary: `sw01.cfg | 8 +++++---` and `1 file changed, 5 insertions(+), 3 deletions(-)`).

> **Watch out:** In a diff of a Python or YAML file, indentation is part of the line. The first character is the marker and the indentation starts at the second, so `+    timeout=30` is an added line indented four spaces.

## Lab it yourself

1. In a new folder on any OS (Git Bash on Windows includes `diff`), save the 24-line `sw01.cfg` as `old/sw01.cfg`, copy it to `new/`, and make the three changes.
2. Run `diff -u old/sw01.cfg new/sw01.cfg`, then `diff -U0` and `diff -U1`, and check every hunk header by counting lines.
3. `git init`, commit the old file, overwrite it with the new one and run `git diff`, `git diff --stat`, then `git add` and `git diff --staged`. Add a file and run `git diff --staged` again to see `new file mode`.

## Key takeaways

- `---` is the old file, `+++` the new file; `-` lines were removed, `+` lines added, space lines are context.
- `@@ -a,b +c,d @@`: old start `a` and count `b`, new start `c` and count `d`; counts include context.
- A count of 1 is omitted; a count of 0 means no lines on that side (an insertion after old line `a`, or a deletion whose lines would follow new line `c`).
- Earlier added or removed lines shift later hunks: new start minus old start is the running offset.
- A modified line is a `-` line followed by a `+` line.
- `git diff` adds `diff --git a/ b/`, an `index` line with blob hashes and mode, `a/` and `b/` prefixes, hunk-header context, and extended headers such as `new file mode`.
