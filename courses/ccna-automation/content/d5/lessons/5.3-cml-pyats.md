## Why simulate and test

A pipeline that pushes configuration needs somewhere safe to try it and a way to prove the result is right. Topic 5.3 names the two Cisco tools for those jobs:

| Tool | Role | Answers the question |
|---|---|---|
| **Cisco Modeling Labs (CML)** | **Network simulation**: builds topologies of virtual Cisco and open-source nodes and runs them | "Where can I run this change without touching production?" |
| **pyATS** with its library **Genie** | **Test and validation**: connects to devices (real or simulated), collects state as structured data and runs test scripts | "Did the network end up in the state I intended?" |

They are complementary: CML provides the network, pyATS checks it. In a CI/CD pipeline (lesson 5.4) a job starts a CML lab, deploys the candidate configuration, runs pyATS tests, and tears the lab down.

## Cisco Modeling Labs

CML (formerly VIRL; the Python client still carries the name `virl2_client`) is a server, installed as a virtual machine or on bare metal, that runs **labs**: topologies of **nodes** connected by **links**.

- **Nodes** are virtual machines or containers built from **node definitions** and images: IOS XE (Catalyst 8000V, Catalyst 9000V), IOSv and IOSvL2, IOS XR, NX-OS, ASA and open-source hosts such as Alpine or Ubuntu, plus unmanaged switches and **external connectors** that bridge a lab to a real network.
- **Workbench**: a browser canvas where you draw the topology, start and stop nodes and open consoles.
- **Topology files**: a lab exports to YAML and imports again, so a topology can live in Git beside the configuration it tests.
- **REST API and Python client**: everything the GUI does is in the REST API under `/api/v0/`. A client authenticates with `POST /api/v0/authenticate` and sends the returned token as `Authorization: Bearer ...`; the `virl2_client` library wraps this. The `cmlutils` package adds a `cml` command-line tool (`cml up`, `cml ls`, `cml down`).
- **Editions**: Cisco's product page lists a free tier limited to five nodes with no expiry, plus Personal (20 Cisco nodes), Personal Plus (40) and Enterprise licences. The DevNet Sandbox also offers CML.

A script that builds a two-router lab and starts it:

```python
import os
from virl2_client import ClientLibrary

client = ClientLibrary("https://cml.example.com",
                       os.environ["CML_USER"], os.environ["CML_PASSWORD"],
                       ssl_verify="cml-ca.pem")

lab = client.create_lab("ci-ospf-check")
r1 = lab.create_node("r1", "iosv", 100, 100)
r2 = lab.create_node("r2", "iosv", 300, 100)
lab.connect_two_nodes(r1, r2)

lab.start()                         # waits for the nodes to converge by default
print(lab.id, lab.state())
testbed_yaml = lab.get_pyats_testbed()   # a pyATS testbed for this lab
# ... deploy and test ...
lab.stop()
lab.wipe()
lab.remove()
```

Reading it: authenticate, **create** a lab, add **nodes** from node definitions (`iosv` here; the names available depend on the images installed), **link** them, **start**, then **stop, wipe and remove** so the next pipeline run starts clean. `get_pyats_testbed()` hands the lab straight to pyATS.

> **Real world:** The client library version must match the controller: the `virl2_client` README warns that a newer client from PyPI may not work with an older CML server, and pins such as `pip install "virl2-client<2.3.0"` keep them aligned.

## pyATS and Genie

**pyATS** (Python Automated Test System) is Cisco's test framework, used internally and free on PyPI. **Genie** is its library layer, now called the pyATS Library, installed with `pip install "pyats[library]"`. The roles:

| Part | What it does |
|---|---|
| **pyATS core** | Testbed loading, device connections (through the Unicon connection library), the **AEtest** test harness, the **Easypy** runtime with logs and reports |
| **Genie parsers** | Turn `show` command output into Python dictionaries, per OS (thousands of parsers for IOS XE, NX-OS, IOS XR, ...) |
| **Genie Ops / learn** | "Learn" a whole feature (`ospf`, `bgp`, `interface`, `routing`) by running several commands and building one OS-independent structure |
| **Genie diff** | Compare two snapshots and show only what changed |
| **Genie Conf, blitz, harness** | Configure features as objects; YAML-defined tests; reusable testcases |

pyATS runs on Linux and macOS; on Windows use WSL 2. Check PyPI for the Python versions the current release supports.

### The testbed file

pyATS describes devices in a **testbed YAML** file:

```yaml
testbed:
  name: branch-lab
  credentials:
    default:
      username: "%ENV{PYATS_USERNAME}"
      password: "%ENV{PYATS_PASSWORD}"
devices:
  rtr01:                      # must match the device's hostname prompt
    os: iosxe
    type: router
    connections:
      cli:
        protocol: ssh
        ip: 192.0.2.11
```

`os` selects the Unicon plugin and the Genie parsers; `%ENV{...}` reads a value from an environment variable at load time and `%ASK{...}` prompts for it, so no password sits in the file.

### Parsing: show output becomes a dictionary

```text
rtr01#show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
GigabitEthernet1       192.0.2.11      YES manual up                    up
GigabitEthernet2       unassigned      YES unset  administratively down down
```

```python
from pyats.topology import loader

testbed = loader.load("testbed.yaml")
rtr = testbed.devices["rtr01"]
rtr.connect(log_stdout=False)
parsed = rtr.parse("show ip interface brief")
print(parsed["interface"]["GigabitEthernet2"]["status"])   # administratively down
```

`parsed` is a dictionary following the parser's schema: `{"interface": {"GigabitEthernet1": {"ip_address": "192.0.2.11", "interface_is_ok": "YES", "method": "manual", "status": "up", "protocol": "up"}, ...}}`. No regex in your code; when IOS XE changes its output, the parser is updated, not your script.

### Learn and diff: before and after a change

The most common pyATS workflow in automation is a **pre/post-change check**:

```bash
pyats learn interface ospf --testbed-file testbed.yaml --output before
# ... make the change (Ansible, Terraform, NSO, by hand) ...
pyats learn interface ospf --testbed-file testbed.yaml --output after
pyats diff before after --output diff_report
```

`pyats learn` (also available as `genie learn`) saves one snapshot per feature and device; `pyats diff` prints only the keys that changed, in a unified-diff style with `-` for the old value and `+` for the new one (lesson 5.12). An unexpected line in the diff, such as an OSPF neighbour going from `full` to missing, fails the change.

### Test scripts with AEtest

A pyATS test script is a Python file with a `CommonSetup` (connect), one or more `Testcase` classes whose `@aetest.test` methods call `self.passed()` or `self.failed()`, and a `CommonCleanup` (disconnect). `pyats run job` runs a job file and produces a results report and archive, which a CI job can publish and use as a pass/fail gate.

> **Exam tip:** CML = simulate the network (virtual nodes, topologies, an API to drive them). pyATS = test it (testbed YAML, connections, AEtest). Genie = the pyATS library that parses `show` output into dictionaries and learns and diffs features.

## Lab it yourself

1. Install the free CML tier in a VM on your computer (VMware Workstation or Fusion, or another supported hypervisor; check the CML documentation for current requirements, including Apple silicon support) or reserve a CML sandbox. Build two IOSv nodes, link them, and export the lab to YAML.
2. In a Python virtual environment on Linux, macOS or WSL 2, run `pip install "pyats[library]"`. Write a testbed for one lab or sandbox device with `%ENV{}` credentials.
3. Run `pyats parse "show ip interface brief" --testbed-file testbed.yaml` and read the JSON it prints.
4. Run `pyats learn interface` before and after shutting an interface, then `pyats diff` the two directories and find the changed `oper_status` or `enabled` key.

## Key takeaways

- CML simulates networks: labs of virtual nodes and links, a Workbench GUI, YAML topologies and a REST API (`/api/v0/`, Bearer token) driven by `virl2_client`.
- A pipeline creates a CML lab, deploys, tests, then stops, wipes and removes it.
- pyATS is the test framework: testbed YAML, Unicon connections, AEtest scripts, reports.
- Genie (the pyATS Library) parses `show` output into dictionaries and learns and diffs whole features.
- The pre/post-change pattern: `pyats learn` before, change, `pyats learn` after, `pyats diff`.
- Keep credentials out of testbeds with `%ENV{}` or `%ASK{}`.
