## What you are asked to do

Topic 5.8 shows a playbook and asks what it automates. Cisco names four workflows: **managing packages**, **managing users related to services**, **basic service configuration**, and **starting and stopping services**. All four usually appear together, because setting up a service on a Linux host means install, create its account, configure it, and run it. Lesson 5.6 introduced Ansible's architecture; this lesson is about reading.

## A method for reading a play

Read the play header first, then each task as *module + arguments + state*, then the keywords that change when and how often a task runs.

| Element | Question to ask | Example |
|---|---|---|
| `hosts` | Which inventory group or host? | `hosts: log_servers` |
| `become` | Does it escalate privileges (sudo by default, to root by default)? | `become: true` |
| `gather_facts` | Will `ansible_facts` (OS family, distribution) be available? It defaults to true | `gather_facts: false` |
| `vars` | Which values are parameters you can read off? | `syslog_port: 514` |
| `tasks` | In which order do things happen? Tasks run top to bottom, each on all hosts before the next | |
| module name | What kind of thing is managed? | `ansible.builtin.apt`, `user`, `template`, `service` |
| `state` | What end state is declared? | `present`, `latest`, `absent`, `started`, `stopped`, `restarted` |
| `loop` | How many items? The task runs once per item, as `{{ item }}` | `loop: [cups, bluetooth]` |
| `when` | Under what condition? A false condition means `skipping` | `when: ansible_facts['os_family'] == "Debian"` |
| `notify` / `handlers` | What runs **only if this task changed something**? | `notify: Restart rsyslog` |

## The four workflows, module by module

| Workflow | Modules | States and options to know |
|---|---|---|
| **Packages** | `ansible.builtin.package` (generic), `apt` (Debian/Ubuntu), `dnf` (RHEL, Fedora; `yum` on old systems) | `present` installs if missing and never upgrades; `latest` installs or upgrades to the newest available version on every run; `absent` removes. `apt` options `update_cache` and `cache_valid_time` refresh the package index first |
| **Users related to services** | `ansible.builtin.user`, `ansible.builtin.group` | `state: present`/`absent`; `system: true` creates a system account (a low UID, for daemons); `shell: /usr/sbin/nologin` stops interactive logins; `groups` plus `append: true` adds supplementary groups without removing existing ones (`append: false` replaces them; from Ansible 2.21 `append` must be set when `groups` is given); `create_home`, `home`; `password` takes a **hash**, never plain text |
| **Basic service configuration** | `template` (renders a Jinja2 file from the control node, filling in variables), `copy` (copies a file or writes `content`), `lineinfile` (ensures one line, found by `regexp`), `file` (directories, permissions) | `dest`, `owner`, `group`, `mode` (quote it: `"0644"`); `validate` checks the new file before it replaces the old one; `backup: true` keeps the previous copy |
| **Start / stop** | `ansible.builtin.service` (any init system), `ansible.builtin.systemd_service` (systemd; also called `systemd`) | `started` and `stopped` act only if needed (idempotent); `restarted` always bounces the service; `reloaded` always reloads; `enabled: true`/`false` controls start at boot, independently of `state` |

## A complete play, read line by line

```yaml
- name: Build a central syslog server
  hosts: log_servers
  become: true
  vars:
    syslog_port: 514
    log_admins: [alice, bob]

  tasks:
    - name: Install rsyslog and logrotate
      ansible.builtin.apt:
        name: [rsyslog, logrotate]
        state: present
        update_cache: true
        cache_valid_time: 3600

    - name: Remove the telnet client
      ansible.builtin.apt:
        name: telnet
        state: absent

    - name: Create the netlogs group
      ansible.builtin.group:
        name: netlogs
        state: present

    - name: Let log admins read network logs
      ansible.builtin.user:
        name: "{{ item }}"
        groups: netlogs
        append: true
      loop: "{{ log_admins }}"

    - name: Create the log-shipping service account
      ansible.builtin.user:
        name: logship
        system: true
        shell: /usr/sbin/nologin
        home: /var/lib/logship
        create_home: true
        state: present

    - name: Accept syslog from network devices
      ansible.builtin.template:
        src: templates/10-network.conf.j2
        dest: /etc/rsyslog.d/10-network.conf
        owner: root
        group: root
        mode: "0644"
        validate: rsyslogd -N1 -f %s
      notify: Restart rsyslog

    - name: Ensure rsyslog is running and starts at boot
      ansible.builtin.service:
        name: rsyslog
        state: started
        enabled: true

    - name: Collect the list of installed services
      ansible.builtin.service_facts:

    - name: Stop and disable services a log server does not need
      ansible.builtin.service:
        name: "{{ item }}"
        state: stopped
        enabled: false
      loop: [cups, bluetooth]
      when: ansible_facts.services[item + '.service'].status | default('not-found') != 'not-found'

  handlers:
    - name: Restart rsyslog
      ansible.builtin.service:
        name: rsyslog
        state: restarted
```

| Task | Workflow | What it does | Idempotent second run |
|---|---|---|---|
| Install rsyslog and logrotate | Packages | Refreshes the apt index if older than an hour, installs both if missing | `ok`: `present` does not upgrade an installed package |
| Remove the telnet client | Packages | Uninstalls `telnet` | `ok`: already absent |
| Create the netlogs group | Users | Creates the group | `ok` |
| Let log admins read network logs | Users | Runs twice (`alice`, `bob`), adding `netlogs` to each user's groups and keeping their other groups (`append: true`). If a user does not exist yet, the module creates the account | `ok` |
| Create the log-shipping service account | Users related to a service | System account `logship`, no login shell, home `/var/lib/logship` | `ok` |
| Accept syslog from network devices | Basic service configuration | Renders the template with `syslog_port`, checks it with `rsyslogd -N1` before installing it, then **notifies** the handler | `ok`, and the handler is **not** notified |
| Ensure rsyslog is running... | Start | Starts rsyslog if stopped; enables it at boot | `ok` |
| Collect the list of installed services | (supporting) | `service_facts` fills `ansible_facts.services`, keyed by unit name such as `cups.service`, each with a `status` | `ok`: it only reads |
| Stop and disable... | Stop | For each of `cups` and `bluetooth` that exists (the `when` uses the idiom from the `service_facts` documentation: a missing entry defaults to `not-found`): stop it and disable it at boot. Without the `when`, stopping a service that does not exist would fail the task | `ok`, or `skipping` for an item that is not installed |
| Handler: Restart rsyslog | Start/stop | Runs **once, after all the tasks in the play**, and only if a notifying task reported `changed` | Does not run |

The template could look like this (Jinja2 fills `{{ syslog_port }}` from `vars`):

```text
# Managed by Ansible - do not edit by hand
module(load="imudp")
input(type="imudp" port="{{ syslog_port }}")
module(load="imtcp")
input(type="imtcp" port="{{ syslog_port }}")
$template PerHost,"/var/log/network/%HOSTNAME%.log"
if $fromhost-ip startswith '10.' then ?PerHost
& stop
```

**Workflow in one sentence:** on every host in `log_servers`, as root, install rsyslog and logrotate, remove telnet, set up a `netlogs` group for the admins and a no-login service account, deploy a validated rsyslog configuration that accepts UDP and TCP 514 from network devices, keep rsyslog running and enabled, restart it only if its configuration changed, and stop and disable `cups` and `bluetooth` wherever they are installed.

## Handlers in detail

- A handler is a task under `handlers:` that runs only when **notified** by a task that reports **changed**.
- Handlers run **after all tasks in the play** (strictly, after each of `pre_tasks`, `roles`/`tasks` and `post_tasks`), in the order they are **defined** under `handlers`, not the order they were notified.
- A handler notified by several tasks still runs **once**: the service bounces once, not once per changed file.
- `meta: flush_handlers` runs pending handlers immediately; `listen` lets several handlers answer one topic name.

## What idempotent looks like in the output

Each task reports per host: `ok` (already in the desired state), `changed`, `skipping` (`when` was false), `failed` or `unreachable`. The run ends with a recap line per host, for example (`ok` counts every successful task, including the changed ones):

```text
PLAY RECAP *********************************************************************
logs01                     : ok=10   changed=6    unreachable=0    failed=0    skipped=0    rescued=0    ignored=0
```

A second run of an idempotent play shows `changed=0`. Tasks that break that rule are worth spotting in an exhibit:

- `state: latest` changes whenever a newer package appears in the repository.
- `state: restarted` as a normal task restarts the service **every** run; use a handler instead.
- `ansible.builtin.command` and `shell` always report `changed` unless you add `creates`, `removes` or `changed_when`.

## Network playbooks are read the same way

```yaml
- name: Standard NTP on branch routers
  hosts: branch_routers
  gather_facts: false
  tasks:
    - name: Configure NTP servers
      cisco.ios.ios_config:
        lines:
          - ntp server 192.0.2.10
          - ntp server 192.0.2.11
        save_when: modified
```

The module runs on the control node and reaches the router through `network_cli` (set in the inventory). `ios_config` compares the `lines` with the running configuration and sends only missing lines; `save_when: modified` copies running to startup only if running changed since the last save. Privilege on IOS uses `become: true` with `become_method: enable`, not sudo.

## Lab it yourself

1. On Linux, macOS or WSL 2, `pip install ansible-core`. Save the play above as `syslog.yml` and run `ansible-playbook -i localhost, syslog.yml --syntax-check`: it parses the playbook without touching any host.
2. Run `ansible-doc ansible.builtin.user` and find `system`, `append` and `password`; then `ansible-doc ansible.builtin.service` and read the note on `restarted`.
3. If you have a throwaway Linux VM or container, point an inventory at it, run the play twice and compare the two recaps. Run once more with `--check --diff` after editing the template.

## Key takeaways

- Read a play as: hosts, become, vars, then each task's module and `state`, then `loop`, `when` and `notify`.
- Packages: `present` (install, no upgrade), `latest` (upgrade every run), `absent` (remove); `apt`, `dnf`, generic `package`.
- Service users: `user` with `system: true` and `shell: /usr/sbin/nologin`; `groups` with `append: true` keeps existing groups; `password` takes a hash.
- Service configuration: `template` renders Jinja2 with variables, `copy`, `lineinfile`; `validate` and `notify` a handler.
- Start/stop: `started`/`stopped` are idempotent, `restarted` always bounces; `enabled` controls boot.
- Handlers run once, at the end of the play, only when a notifying task changed.
- Idempotent playbooks report `changed=0` on the second run.
