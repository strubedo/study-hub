## Parsing means "text in, Python objects out"

An API returns **text**. Before your script can loop over interfaces or compare a VLAN number, that text has to become Python objects. Going the other way (Python objects to text, for a request body or a file) is **serialising**. The three formats map onto Python differently, and that difference is what this topic tests: JSON and YAML become ordinary dicts and lists, XML becomes a tree of **Element** objects.

All output in this lesson comes from real runs (Python 3.14 for the standard library, PyYAML 6.0.3 and xmltodict 1.0.3 for the third-party libraries), using the `sw01` documents from lesson 1.1.

## JSON with the `json` module (standard library)

| Function | Input | Output |
|---|---|---|
| `json.load(f)` | An open **file** object (anything with `.read()`) | Python object |
| `json.loads(s)` | A **string** (or bytes): the `s` means string | Python object |
| `json.dump(obj, f)` | Python object and an open file | Writes text to the file, returns `None` |
| `json.dumps(obj)` | Python object | Returns a **string** |

```python
import json

with open("device.json") as f:
    device = json.load(f)

print(type(device).__name__)
for key, value in device.items():
    print(f"{key}: {type(value).__name__} = {value!r}")
print(device["interfaces"][1]["name"])
```

```text
dict
hostname: str = 'sw01'
mgmt_ip: str = '10.10.20.11'
model: str = 'C9300-48P'
managed: bool = True
uptime_days: int = 42
cpu_load: float = 7.5
location: NoneType = None
interfaces: list = [{'name': 'GigabitEthernet1/0/1', 'enabled': True, 'vlan': 10}, {'name': 'GigabitEthernet1/0/2', 'enabled': False, 'vlan': 20}]
GigabitEthernet1/0/2
```

That is the decoding table from the Python documentation:

| JSON | Python |
|---|---|
| object | `dict` |
| array | `list` |
| string | `str` |
| number (integer) | `int` |
| number (real) | `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

When encoding, Python also accepts a `tuple` (it becomes an array). Note that `mgmt_ip` is a `str`: JSON has no IP-address type. With a REST library such as `requests`, `response.json()` does the `json.loads()` step for you.

**Keys are always strings.** JSON object keys must be strings, so a Python dict with integer keys changes on a round trip:

```python
text = '{"vlans": {"10": "users", "20": "voice"}}'
data = json.loads(text)
print(data["vlans"]["10"])
try:
    print(data["vlans"][10])
except KeyError as e:
    print("KeyError:", e)
print(json.dumps({10: "users", "up": True, "desc": None}))
print(json.loads(json.dumps({10: "users"})))
```

```text
users
KeyError: 10
{"10": "users", "up": true, "desc": null}
{'10': 'users'}
```

`json.dumps()` also converts `True` to `true` and `None` to `null`. Add `indent=2` for pretty output and `sort_keys=True` for stable ordering in files you keep in Git.

> **Exam tip:** "load" works with a file, "loads" with a string. If the exhibit passes `response.text` or a triple-quoted string, the answer is `loads`; if it passes `f` from `with open(...) as f`, it is `load`.

## XML with `xml.etree.ElementTree` (standard library)

ElementTree does **not** give you a dict. It gives you an `ElementTree` (the whole document) and `Element` objects (each tag). Every Element has:

| Attribute / method | Returns |
|---|---|
| `.tag` | The element name, e.g. `'device'` (with a namespace, `'{uri}name'`) |
| `.attrib` | A `dict` of the element's attributes, values always `str` |
| `.text` | The text directly inside the element as a `str`, or `None` if there is none |
| `.get('name')` | One attribute value, or `None` if absent |
| `.find('path')` | The **first** matching child element, or `None` |
| `.findall('path')` | A list of matching elements; a bare name matches **direct children only** |
| `.iter('tag')` | Every matching element in the **whole subtree**, at any depth |
| `el[0]`, `for child in el` | Children by index or iteration |

`ET.parse(file)` reads a file and returns an `ElementTree` (call `.getroot()`); `ET.fromstring(text)` parses a string and returns the root `Element` directly.

```python
import xml.etree.ElementTree as ET

tree = ET.parse("device.xml")
root = tree.getroot()

print(root.tag, root.attrib)
print(repr(root.find("hostname").text))
print(repr(root.find("uptime_days").text))
print(repr(root.find("location").text))
print(root.find("nosuch"))
print(len(root.findall("interface")))
print(len(root.findall("interfaces/interface")))
for intf in root.iter("interface"):
    print(intf.get("name"), intf.attrib["enabled"], int(intf.find("vlan").text))
print(type(root).__name__, type(root.attrib).__name__)
print(root.get("managed") == "true", root.get("managed") is True)
```

```text
device {'managed': 'true'}
'sw01'
'42'
None
None
0
2
GigabitEthernet1/0/1 true 10
GigabitEthernet1/0/2 false 20
Element dict
True False
```

Three things to take from that output:

1. **Everything is a string.** `uptime_days` comes back as `'42'` and the `managed` attribute as `'true'`, not `True`. Convert explicitly (`int(...)`, `== "true"`).
2. `findall("interface")` on the root returns **nothing** because `<interface>` is a grandchild. Use a path (`"interfaces/interface"`), `".//interface"`, or `iter("interface")`.
3. A missing element gives `None`, so `root.find("nosuch").text` raises `AttributeError`. An empty element (`<location/>`) has `.text` of `None`.

**Namespaces** change the tag names. With a default namespace, `.tag` is `'{urn:ietf:params:xml:ns:yang:ietf-interfaces}interfaces'`, and `find("interface")` returns `None`. Pass a prefix map:

```python
ns = {"if": "urn:ietf:params:xml:ns:yang:ietf-interfaces"}
print(root.find("if:interface/if:name", ns).text)    # GigabitEthernet1
```

> **Watch out:** The "XML security" section of the Python documentation lists attacks such as "billion laughs" entity expansion that apply when parsing attacker-controlled XML; whether you are exposed depends on the Expat library version Python uses (`pyexpat.EXPAT_VERSION`). Data from your own devices is low risk; for XML from untrusted sources, read that section first (the third-party `defusedxml` package is a common extra safeguard).

### xmltodict: dict-like XML (third party)

`pip install xmltodict` gives you `xmltodict.parse()`, popular in network scripts because the result looks like parsed JSON. Attributes get an `@` prefix and mixed text lands under `#text`:

```text
>>> xmltodict.parse("<a><b x='1'>text</b></a>")
{'a': {'b': {'@x': '1', '#text': 'text'}}}
>>> xmltodict.parse("<interfaces><interface name='Gi1/0/1'><vlan>10</vlan></interface></interfaces>")
{'interfaces': {'interface': {'@name': 'Gi1/0/1', 'vlan': '10'}}}
```

The catch: one `<interface>` becomes a **dict**, two become a **list**. Code that loops over `["interface"]` must handle both (xmltodict's `force_list` option helps). Values are still strings.

## YAML with PyYAML (third party)

YAML is not in the standard library; the usual package is **PyYAML** (`pip install pyyaml`, imported as `yaml`).

| Function | Use |
|---|---|
| `yaml.safe_load(stream)` | Parse one document from a string or file into plain Python objects. **Use this.** |
| `yaml.safe_load_all(stream)` | Iterate over several `---` documents |
| `yaml.safe_dump(obj)` / `yaml.dump(obj)` | Serialise to YAML text |
| `yaml.load(stream, Loader=...)` | Full loader; in PyYAML 6 the `Loader` argument is required |

```python
import yaml

with open("device.yaml") as f:
    device = yaml.safe_load(f)

print(device["interfaces"][0])
print(type(device["mgmt_ip"]).__name__, type(device["location"]).__name__)
```

```text
{'name': 'GigabitEthernet1/0/1', 'enabled': True, 'vlan': 10}
str NoneType
```

A mapping becomes a `dict`, a sequence a `list`, and scalars `str`, `int`, `float`, `bool` or `None`. So the JSON and YAML versions of `sw01` parse to exactly the same Python object, and the XML version does not.

**Why `safe_load`?** PyYAML's documentation says `yaml.load` "is as powerful as pickle.load and so may call any Python function": a document can carry Python-specific tags such as `!!python/object/apply:os.system`. `safe_load` recognises only standard YAML tags and refuses the rest (only the exception line of each traceback is shown; PyYAML's `ConstructorError` message goes on to print the position of the offending tag):

```text
>>> yaml.safe_load("!!python/object/apply:os.system ['echo hi']")
yaml.constructor.ConstructorError: could not determine a constructor for the tag 'tag:yaml.org,2002:python/object/apply:os.system'
>>> yaml.load("a: 1")
TypeError: load() missing 1 required positional argument: 'Loader'
```

Since PyYAML 5.1 a bare `yaml.load()` warned, and since 6.0 (2021) the `Loader` argument is required; the safe choice for inventory files and API data is always `safe_load`.

**PyYAML is YAML 1.1**, so implicit typing bites:

```python
doc = """
country: NO
cdp: on
lldp: off
shutdown: no
ios_version: 17.10
vlan_id: 010
mac: 00:1a:2b:3c:4d:5e
quoted: "no"
"""
print(yaml.safe_load(doc))
```

```text
{'country': False, 'cdp': True, 'lldp': False, 'shutdown': False, 'ios_version': 17.1, 'vlan_id': 8, 'mac': '00:1a:2b:3c:4d:5e', 'quoted': 'no'}
```

`NO`, `on`, `off` and `no` became booleans, `17.10` became the float `17.1`, and `010` became `8` (a YAML 1.1 octal). Only the quoted value stayed a string. A YAML 1.2 parser would keep `NO`, `on`, `off` and `no` as strings, but you will usually be using PyYAML.

## Lab it yourself

Any computer with Python 3 (Windows, macOS or Linux):

1. Create a virtual environment and activate it: on Windows `python -m venv .venv` then `.venv\Scripts\activate` (PowerShell or Command Prompt); on macOS and Linux `python3 -m venv .venv` then `source .venv/bin/activate`. Then `pip install pyyaml xmltodict`.
2. Run the three parsing scripts above against your `device.*` files and confirm the types.
3. Change the YAML so it has `shutdown: no`, `version: 17.10` and `vlan_id: 010`; print the result; then quote the values and print again.
4. Remove one `<interface>` from `device.xml`, parse it with `xmltodict`, and watch `["interface"]` change from a list to a dict. Then try `force_list=("interface",)`.
5. Round-trip: `json.loads(json.dumps({10: "users"}))` and explain the result.

## Key takeaways

- `json.load(file)` / `json.loads(string)` parse; `json.dump(obj, file)` / `json.dumps(obj)` serialise.
- JSON object/array/string/number/true/false/null become `dict`/`list`/`str`/`int` or `float`/`True`/`False`/`None`; keys are always `str`.
- ElementTree returns `Element` objects, not dicts: `.tag`, `.attrib` (a dict of strings), `.text` (a string or `None`), `.get()`, `.find()`, `.findall()` (direct children by default), `.iter()` (any depth).
- XML values are always strings; namespaces turn tags into `{uri}name` and need a prefix map for `find`.
- xmltodict gives dict-like output with `@attr` and `#text`, but a single repeated element becomes a dict instead of a list.
- Use `yaml.safe_load`; `yaml.load` can construct arbitrary Python objects and needs an explicit `Loader` in PyYAML 6.
- PyYAML follows YAML 1.1: `yes`/`no`/`on`/`off` become booleans, `17.10` becomes `17.1`, `010` becomes `8`. Quote them.
