## Why ports matter to automation

A transport **port** identifies the application on a host: the IP address gets the packet to the machine, the TCP or UDP port gets it to the right process. Topic 6.7 asks you to **recognise** common port values, and names five: **SSH, Telnet, HTTP, HTTPS and NETCONF**. You will also meet the others below in firewall requests, `requests` URLs, device configuration and exam exhibits.

How ports are used in a connection:

- A **server** listens on a well-known or registered port (for example 443).
- A **client** connects **from** an ephemeral source port chosen by its operating system (IANA suggests 49152 to 65535; Linux uses 32768 to 60999 by default) **to** the server's port.
- A flow is identified by the 5-tuple: source IP, destination IP, protocol, source port, destination port. Firewall rules and NAT tables are written in these terms.

Port numbers below come from the IANA Service Name and Transport Protocol Port Number Registry. IANA usually registers a well-known port for both TCP and UDP even when the protocol only uses one; the "used over" column says what the protocol actually runs on.

## The five named in the exam topic

| Protocol | Port | Used over | Notes |
|---|---|---|---|
| **SSH** | **22** | TCP | Encrypted CLI and file transfer (SCP, SFTP). Netmiko, Paramiko and Ansible's `network_cli` use it |
| **Telnet** | **23** | TCP | Clear-text CLI, including passwords. Disable it on devices; use SSH |
| **HTTP** | **80** | TCP | Clear text. Redirect to HTTPS, never send credentials or tokens over it |
| **HTTPS** | **443** | TCP (HTTP/3 uses QUIC over UDP 443) | HTTP over TLS: REST APIs, RESTCONF, controller GUIs |
| **NETCONF over SSH** | **830** | TCP | RFC 6242; the IANA name is `netconf-ssh`. NETCONF runs as an SSH subsystem on this port |

## Model-driven programmability ports

| Interface | Port | Notes |
|---|---|---|
| NETCONF over SSH | TCP 830 | The default and the one Cisco IOS XE, IOS XR and NX-OS use |
| NETCONF over TLS | TCP 6513 | IANA `netconf-tls` (RFC 7589); rare on network devices |
| RESTCONF | TCP 443 | RFC 8040 runs RESTCONF over HTTPS; it has **no dedicated port**, so it uses the HTTPS port (443 unless the device's web server is configured otherwise). Base path `/restconf` |
| gNMI | TCP 9339 (IANA), but configured per device | gRPC over HTTP/2 and TLS. IANA has registered TCP 9339 as `gnmi-gnoi`, but the gNMI specification itself does not fix a port, and platform defaults and examples differ; read it from the device configuration |

> **Exam tip:** NETCONF = **830**, RESTCONF = **443**. A question that says "RESTCONF port 830" or "NETCONF port 443" is wrong on purpose.

## Other ports a developer meets

| Protocol | Port | Used over | Where you meet it |
|---|---|---|---|
| SMTP | 25 | TCP | Server-to-server mail. Mail clients submit on 587 (submission, with STARTTLS) or 465 (implicit TLS) |
| DNS | 53 | UDP and TCP | UDP for most queries; TCP for large answers and zone transfers (lesson 6.6) |
| DHCP | 67 server, 68 client | UDP | IANA names them `bootps` and `bootpc` |
| TFTP | 69 | UDP | Image and config transfer, zero-touch provisioning |
| NTP | 123 | UDP | Both source and destination are 123 between servers |
| SNMP | 161 | UDP | Manager polls the agent |
| SNMP traps and informs | 162 | UDP | Agent sends to the manager |
| LDAP / LDAPS | 389 / 636 | TCP | Directory lookups for AAA |
| Syslog | 514 | UDP | Classic syslog (RFC 5426). IANA lists TCP 514 as `shell` (rsh), although many collectors also accept syslog on TCP 514. Syslog over TLS is TCP 6514 |
| RADIUS | 1812 auth, 1813 accounting | UDP | Network access AAA |
| TACACS+ | 49 | TCP | Device administration AAA |
| HTTP alternates | 8080, 8443 | TCP | Common for development servers and appliances; not standard for any one protocol |

## TCP or UDP: why it matters

- **TCP** (SSH, Telnet, HTTP, HTTPS, NETCONF, SMTP, LDAP) sets up a connection with a three-way handshake, delivers bytes in order and retransmits loss. A blocked or closed TCP port is visible to the client as a timeout or a refusal (lesson 6.8).
- **UDP** (DHCP, NTP, SNMP, syslog, most DNS) sends independent datagrams with no handshake. A blocked UDP port usually just means **no reply**, so the client waits and times out; the application must do its own retries. Lost syslog messages and traps are not resent.

That difference shows in firewall rules too: a stateful firewall tracks UDP "connections" with a timer, so a rule for SNMP polling must allow UDP 161 to the device, and replies come back as part of that flow.

## Ports in URLs and code

A URL carries the port explicitly or implies it from the scheme: `https://sw01.example.com/restconf/data/...` means TCP 443; `http://devbox.example.com:8080/api` means TCP 8080.

```python
import requests
from ncclient import manager

r = requests.get("https://sw01.example.com/restconf/data/ietf-interfaces:interfaces",   # TCP 443
                 auth=("alice", "<YOUR_PASSWORD>"),
                 headers={"Accept": "application/yang-data+json"}, timeout=10)

with manager.connect(host="sw01.example.com", port=830,                                  # TCP 830
                     username="alice", password="<YOUR_PASSWORD>",
                     hostkey_verify=True) as m:
    print(m.server_capabilities)
```

When you ask a firewall team for access, give the full flow: source subnet, destination address, protocol and destination port, for example "10.1.10.0/24 to 10.30.0.0/24, TCP 830 and TCP 443".

## Lab it yourself

1. **Test a TCP port without opening a session.** Windows PowerShell: `Test-NetConnection sandbox.example.com -Port 830` (replace the host with the one your DevNet Sandbox reservation gives you). macOS and Linux: `nc -vz sandbox.example.com 830`. Do the same for 443 and 22.
2. **See your own listening ports.** Windows: `netstat -an | findstr LISTENING`. macOS: `netstat -an -p tcp | grep LISTEN`. Linux: `ss -tln`. Find any service on 22 or 443.
3. **See ephemeral ports in use.** While a browser is open, run `netstat -an` and look at the local port numbers of connections to remote port 443.
4. In Python, `socket.getservbyname("ssh", "tcp")` returns 22 from your operating system's services file; try `"https"`, `"domain"`, `"ntp"` and `"netconf-ssh"` (the last may not be in every OS's file).

## Key takeaways

- SSH 22, Telnet 23, HTTP 80, HTTPS 443, NETCONF over SSH 830: all TCP.
- RESTCONF has no port of its own; it runs over HTTPS, normally 443. NETCONF over TLS is 6513. gNMI's port is set per device (IANA lists 9339 as `gnmi-gnoi`).
- DNS 53 UDP and TCP; DHCP 67/68 UDP; NTP 123 UDP; SNMP 161 polling and 162 traps, UDP; syslog 514 UDP; SMTP 25 TCP.
- Clients use ephemeral source ports; servers listen on fixed ports. Firewall rules and NAT entries use the 5-tuple.
- A blocked UDP port shows as no reply; a blocked TCP port as a timeout or refusal.
