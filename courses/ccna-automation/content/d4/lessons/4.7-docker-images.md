## Images, containers, tags and registries

Four words carry this topic:

- **Image**: a read-only template made of layers plus metadata (default command, environment, user, exposed ports). Built from a Dockerfile (lesson 4.6) or pulled from a registry.
- **Container**: a running (or stopped) **instance** of an image. Docker adds a thin **writable layer** on top of the image's read-only layers; whatever the process writes goes there and **disappears when the container is removed**, unless it was written to a volume or bind mount. One image can run as many containers at once.
- **Registry**: a server that stores images, such as Docker Hub (`docker.io`, the default), GitHub Container Registry, a cloud provider's registry, or a private one like `registry.example.com`. Inside a registry, images live in **repositories**.
- **Tag**: a human-readable name for one version of an image in a repository.

The `docker image tag` reference spells out a full image reference:

```text
[HOST[:PORT]/]NAMESPACE/REPOSITORY[:TAG]

python:3.14-slim                              -> docker.io/library/python:3.14-slim
registry.example.com/netops/netinv:1.0        -> private registry, namespace netops
registry.example.com:5000/netops/netinv       -> port 5000, tag defaults to latest
```

If the host is omitted, Docker uses Docker Hub; if the namespace is omitted, it uses `library` (Docker Official Images); if the tag is omitted, it uses **`latest`**.

> **Watch out:** `latest` is only the **default tag name**. It is not "the newest version": it points to whatever image was last tagged `latest`, and many repositories do not update it at all. Tags are also **mutable**: someone can push a different image under `1.0` tomorrow. For a reproducible deployment, use a specific tag (better, one you never reuse, such as a commit id) or pin the **digest** (`python:3.14-slim@sha256:...`), which identifies the exact content and cannot change.

## The local workflow

A complete loop for the `netinv` image from lesson 4.6. The commands are exactly the ones you type; output is shown in the format the Docker CLI reference documents (ids, times and sizes will differ on your machine, and some Docker versions lay out the tables slightly differently).

**1. Pull a base image (optional: `build` pulls it if missing).**

```text
alice@devbox:~/netinv$ docker pull python:3.14-slim
```

**2. Build and tag.** `-t` (`--tag`) names the image as `name:tag`; the final `.` is the **build context**, the directory whose files `COPY` can use (filtered by `.dockerignore`). `-f` picks a Dockerfile with another name or path.

```text
alice@devbox:~/netinv$ docker build -t netinv:1.0 .
```

**3. List local images.** `docker images` is an alias of `docker image ls`.

```text
alice@devbox:~/netinv$ docker images
REPOSITORY   TAG         IMAGE ID       CREATED          SIZE
netinv       1.0         3f2a9c1d7b44   35 seconds ago   152MB
python       3.14-slim   9b1e2f4a6c3d   10 days ago      151MB
```

**4. Run a container.**

```text
alice@devbox:~/netinv$ docker run -d --name inv -p 8080:8000 -e SITE=hq1 netinv:1.0
5c1d9e0a7b3f2e4d6c8a0b1f3e5d7c9a2b4f6e8d0c1a3b5d7f9e2c4a6b8d0f1e
```

| Flag | Meaning |
|---|---|
| `-d`, `--detach` | Run in the background and print the container id |
| `--name inv` | Give the container a fixed name (otherwise Docker invents one, such as `admiring_roentgen`) |
| `-p 8080:8000` | **Publish** container port 8000 on host port 8080: `-p HOST:CONTAINER`. Without an address it listens on all host interfaces; `-p 127.0.0.1:8080:8000` limits it to the host itself |
| `-e SITE=hq1` | Set an environment variable in the container (overrides the image's `ENV SITE=lab`); `--env-file` reads several from a file |
| `--rm` | Remove the container automatically when it exits (useful for one-off commands) |
| `-it` | `-i` keeps STDIN open and `-t` allocates a terminal: for interactive shells |
| `-v` | Mount a volume or a host directory (below) |

`EXPOSE 8000` in the Dockerfile did **not** make the port reachable: `-p` does. (`-P` publishes every exposed port on random high host ports.)

**5. Check it and test it.**

```text
alice@devbox:~/netinv$ docker ps
CONTAINER ID   IMAGE        COMMAND                  CREATED          STATUS          PORTS                    NAMES
5c1d9e0a7b3f   netinv:1.0   "python app.py --por…"   12 seconds ago   Up 11 seconds   0.0.0.0:8080->8000/tcp   inv

alice@devbox:~/netinv$ curl http://localhost:8080/
{"site": "hq1", "devices": ["sw01", "rtr01"]}
```

`PORTS` reads host side first: `0.0.0.0:8080->8000/tcp` means "host port 8080 on every interface forwards to container port 8000". `docker ps` lists **running** containers only; `docker ps -a` includes stopped ones.

**6. Read the logs and look inside.**

```text
alice@devbox:~/netinv$ docker logs inv
netinv listening on port 8000, site hq1
172.17.0.1 - - [22/Nov/2026 14:05:11] "GET / HTTP/1.1" 200 -

alice@devbox:~/netinv$ docker exec -it inv sh
$ whoami
appuser
$ echo $SITE
hq1
$ exit
```

`docker logs` prints what the container's main process wrote to stdout and stderr (`-f` follows, `--tail 20` shows the last 20 lines). `docker exec` runs an **extra** command inside a **running** container; it is how you get a shell for troubleshooting. (The client address in the log is the Docker host's bridge gateway as seen from the container; it varies by platform.)

**7. Stop and clean up.**

```text
alice@devbox:~/netinv$ docker stop inv
inv
alice@devbox:~/netinv$ docker rm inv
inv
alice@devbox:~/netinv$ docker rmi netinv:1.0
```

- `docker stop` sends `SIGTERM`, waits (10 seconds by default), then `SIGKILL`. The container still exists, stopped, and `docker start inv` would restart it.
- `docker rm` deletes a stopped container and its writable layer. `docker rm -f` stops and removes a running one in one step (using `SIGKILL`).
- `docker rmi` (alias of `docker image rm`) removes an image from **this host**, not from any registry. If the image has several tags, `docker rmi` with one tag removes only that tag. Docker refuses to remove an image that a container is still using, so remove the containers first.

**8. Share it through a registry.** Give the image a name that includes the registry, log in, push.

```text
alice@devbox:~/netinv$ docker tag netinv:1.0 registry.example.com/netops/netinv:1.0
alice@devbox:~/netinv$ docker login registry.example.com
alice@devbox:~/netinv$ docker push registry.example.com/netops/netinv:1.0
```

`docker tag` does not copy anything: it adds a second name pointing at the same image id, which is why both names show the same `IMAGE ID` in `docker images`. `docker push` uploads the layers the registry does not already have; credentials come from `docker login` (use an access token, not your account password). A teammate then runs `docker pull registry.example.com/netops/netinv:1.0` and gets the identical image.

> **Exam tip:** Expect "which command" questions: build with a tag (`docker build -t name:tag .`), run detached with a published port (`docker run -d -p host:container image`), list running containers (`docker ps`), see output (`docker logs`), get a shell (`docker exec -it name sh`), and add a registry name before pushing (`docker tag` then `docker push`).

## Keeping data: volumes and bind mounts

Because the writable layer dies with the container, data that must survive goes in a mount. `-v` takes `source:target[:options]`:

```text
# Named volume: Docker creates and manages "invdata"; survives docker rm
docker run -d --name inv -v invdata:/app/data netinv:1.0

# Bind mount: a host directory appears inside the container, read-only here
docker run -d --name inv -v "$(pwd)/configs:/app/configs:ro" netinv:1.0
```

- If the source is a **name**, it is a **named volume**, stored in Docker's own area and managed with `docker volume ls`, `docker volume rm`. Docker recommends volumes for persisting data: easier to back up and migrate, and they work the same on Linux and Windows hosts.
- If the source is a **path** (absolute, or relative such as `./configs` since Docker Engine 23), it is a **bind mount** of that host directory, ideal during development: edit the files on the host and the container sees the change at once. With `-v`, a missing host path is created as a directory; the longer `--mount type=bind,...` syntax errors instead, which is one reason Docker recommends `--mount`.
- `:ro` makes the mount read-only inside the container.
- `$(pwd)` is Bash and PowerShell syntax; in Windows `cmd.exe` use `%cd%`.

## Day-to-day commands

| Task | Command |
|---|---|
| Run a throwaway shell in a new container | `docker run --rm -it python:3.14-slim bash` |
| See all containers, including stopped | `docker ps -a` |
| Follow logs | `docker logs -f inv` |
| Restart a stopped container | `docker start inv` |
| Show image layers and the commands that made them | `docker history netinv:1.0` |
| Low-level details (env, ports, mounts, command) | `docker inspect inv` |
| Remove all stopped containers | `docker container prune` |
| Remove dangling (untagged) images | `docker image prune` |

## Lab it yourself

On your own computer with **Docker Desktop** (Windows, macOS) or **Docker Engine** or **Podman** (Linux; `podman` accepts the same commands). Use the `netinv` folder from lesson 4.6.

1. `docker build -t netinv:1.0 .`, then `docker images` and note the image id.
2. `docker run -d --name inv -p 8080:8000 -e SITE=hq1 netinv:1.0`, then `docker ps`, then browse to `http://localhost:8080/` or `curl http://localhost:8080/`.
3. `docker logs inv`, then `docker exec -it inv sh` and run `whoami` and `echo $SITE`.
4. Run a second copy from the same image: `docker run -d --name inv2 -p 8081:8000 netinv:1.0`. Two containers, one image. Try to start a third on host port 8080 and read the error: the host port is already taken.
5. `docker tag netinv:1.0 netinv:latest`, then `docker images`: same id twice. `docker rmi netinv:latest` removes only that tag.
6. `docker stop inv inv2`, `docker ps`, `docker ps -a`, then `docker rm inv inv2`.
7. Optional: create a free Docker Hub account and an access token, `docker login`, tag the image as `<your-user>/netinv:1.0` and push it.

## Key takeaways

- An image is a read-only template; a container is a running instance with a writable layer that is lost on `docker rm`. Many containers can run from one image.
- Image reference: `[host[:port]/]namespace/repo[:tag]`; defaults are Docker Hub, `library` and `latest`. `latest` is just a default name, and tags are mutable; digests are not.
- Build `docker build -t name:tag .`; run `docker run -d --name n -p HOST:CONTAINER -e K=V image`; inspect with `docker ps`, `docker logs`, `docker exec -it n sh`; clean up with `docker stop`, `docker rm`, `docker rmi`.
- `EXPOSE` documents; `-p host:container` publishes.
- `docker tag` adds a name (with a registry host to push there); `docker push` and `docker pull` move images through a registry after `docker login`.
- `-v name:/path` is a named volume managed by Docker; `-v /host/path:/path` is a bind mount; add `:ro` for read-only.
