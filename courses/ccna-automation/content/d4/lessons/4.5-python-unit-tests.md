## What a unit test is

A **unit test** checks one small piece of code (a function, a method) in isolation: given these inputs, it must return this output or raise this exception. Unit tests run in milliseconds, need no network, devices or databases, and run on every commit in the CI pipeline (lesson 4.4). Lesson 1.3 showed `unittest` driving test-driven development; this lesson is about constructing the tests themselves, which is what topic 4.5 asks.

Python's standard library includes **`unittest`**, so nothing needs installing. The rules:

1. Import `unittest` and the code under test.
2. Create a class that subclasses **`unittest.TestCase`**.
3. Write methods whose names **start with `test`**. The Python docs say this naming convention is what tells the runner which methods are tests; any other method is not run as a test.
4. Inside each test, check results with the **`assert*` methods** of `TestCase`, not the bare `assert` statement, so the runner can collect and report every result.
5. Run with **`python -m unittest`**.

## The code under test

`netutil.py`, three small helpers a network engineer might write:

```python
import ipaddress
import json


def usable_hosts(cidr):
    """Return the number of usable IPv4 host addresses in a prefix."""
    net = ipaddress.ip_network(cidr)
    if net.prefixlen >= 31:          # /31 point-to-point (RFC 3021) and /32
        return net.num_addresses
    return net.num_addresses - 2     # minus network and broadcast


def parse_vlan(value):
    """Turn '20' or 20 into an int, rejecting IDs outside 1-4094."""
    vlan = int(value)
    if not 1 <= vlan <= 4094:
        raise ValueError(f"VLAN {vlan} out of range 1-4094")
    return vlan


def load_inventory(path):
    """Read a JSON list of devices and return {hostname: mgmt_ip}."""
    with open(path) as f:
        devices = json.load(f)
    return {d["hostname"]: d["mgmt_ip"] for d in devices}
```

## The test file

`test_netutil.py`, in the same folder:

```python
import json
import os
import tempfile
import unittest

from netutil import load_inventory, parse_vlan, usable_hosts


class TestUsableHosts(unittest.TestCase):
    def test_slash_24(self):
        self.assertEqual(usable_hosts("192.0.2.0/24"), 254)

    def test_point_to_point(self):
        self.assertEqual(usable_hosts("198.51.100.0/31"), 2)


class TestParseVlan(unittest.TestCase):
    def test_string_is_converted(self):
        self.assertEqual(parse_vlan("20"), 20)

    def test_out_of_range_raises(self):
        with self.assertRaises(ValueError):
            parse_vlan(4095)

    def test_not_a_number_raises(self):
        self.assertRaises(ValueError, parse_vlan, "voice")


class TestLoadInventory(unittest.TestCase):
    def setUp(self):
        # Runs before EVERY test method in this class
        self.tmp = tempfile.TemporaryDirectory()
        self.path = os.path.join(self.tmp.name, "inventory.json")
        with open(self.path, "w") as f:
            json.dump([{"hostname": "sw01", "mgmt_ip": "10.10.20.11"},
                       {"hostname": "rtr01", "mgmt_ip": "10.10.20.1"}], f)

    def tearDown(self):
        # Runs after EVERY test method, even one that failed
        self.tmp.cleanup()

    def test_maps_hostname_to_ip(self):
        inv = load_inventory(self.path)
        self.assertEqual(inv["rtr01"], "10.10.20.1")

    def test_contains_both_devices(self):
        inv = load_inventory(self.path)
        self.assertIn("sw01", inv)
        self.assertEqual(len(inv), 2)


if __name__ == "__main__":
    unittest.main()
```

Points to notice:

- **`assertRaises` two ways.** As a **context manager** (`with self.assertRaises(ValueError):`) the code inside the block must raise that exception. As a **call**, pass the callable and its arguments separately: `self.assertRaises(ValueError, parse_vlan, "voice")`. Writing `self.assertRaises(ValueError, parse_vlan("voice"))` is a classic mistake: `parse_vlan("voice")` runs (and raises) *before* `assertRaises` is even called, so the test errors instead of passing. The docs define the outcomes: the test passes if the exception is raised, is an error if another exception is raised, and fails if no exception is raised.
- **`setUp` and `tearDown` are fixtures.** `setUp()` is called immediately before **each** test method, and `tearDown()` immediately after each one, even if the test raised an exception (but only if `setUp()` succeeded). Here every inventory test gets a fresh JSON file in a fresh temporary directory, so tests cannot affect each other. For expensive set-up shared by a whole class there are the class methods `setUpClass()` and `tearDownClass()`, which run once per class.
- **`if __name__ == "__main__": unittest.main()`** lets you also run the file directly with `python test_netutil.py`.

- `python -m unittest` with no arguments is a shortcut for `python -m unittest discover`: it searches the current directory for files matching `test*.py` (the default pattern) and runs every test in them. `-v` lists each test.
- Tests run sorted by class and method name, not in the order written. Never make one test depend on another.
- You can narrow the run: `python -m unittest test_netutil`, `python -m unittest test_netutil.TestParseVlan`, `python -m unittest test_netutil.TestParseVlan.test_string_is_converted`, or by a case-sensitive substring of the full test name with `-k` (`-k Vlan` runs the three `TestParseVlan` tests; `-k vlan` runs none).

## Choosing the assert method

| Method | Passes when | Use it for |
|---|---|---|
| `assertEqual(a, b)` / `assertNotEqual` | `a == b` / `a != b` | Most checks: return values, parsed fields |
| `assertTrue(x)` / `assertFalse(x)` | `bool(x)` is True / False | Genuine booleans, such as `is_reachable()` |
| `assertIs(a, b)` / `assertIsNone(x)` | `a is b` / `x is None` | Identity, `None` results |
| `assertIn(a, b)` / `assertNotIn` | `a in b` | Membership in a list, dict keys or a string |
| `assertIsInstance(obj, cls)` | `isinstance(obj, cls)` | Type checks |
| `assertAlmostEqual(a, b)` | `round(a - b, 7) == 0`: the difference rounds to zero at 7 decimal places | Floats, such as utilisation percentages |
| `assertRaises(exc, ...)` | `exc` is raised | Error handling |
| `assertCountEqual(a, b)` | Same elements, any order | Lists whose order does not matter |

Prefer the most specific method: its failure message shows the values. These two tests check the same thing (Python 3.14 output from a file `test_demo.py`, trimmed to the key lines of each failure):

```text
FAIL: test_with_assert_equal (test_demo.TestDemo.test_with_assert_equal)
    self.assertEqual(usable_hosts("192.0.2.0/29"), 8)
AssertionError: 6 != 8

FAIL: test_with_assert_true (test_demo.TestDemo.test_with_assert_true)
    self.assertTrue(usable_hosts("192.0.2.0/29") == 8)

```

The `assertEqual` failure tells you the function returned 6; the `assertTrue` one tells you nothing. The same file had a third method, `check_slash_30`, which was never run because its name does not start with `test`: `Ran 2 tests`.

## Mocking an API call with unittest.mock

A unit test must not call a real API: the network may be down, the sandbox may be reserved, tokens expire and the call is slow. **`unittest.mock`** replaces the dependency with a **mock object** for the duration of the test. `devices.py` uses the `requests` library (lesson 2.9):

```python
import requests

BASE_URL = "https://api.example.com/api/v1"


def get_hostnames(token):
    """Return the hostnames of every device the API knows about."""
    resp = requests.get(
        f"{BASE_URL}/devices",
        headers={"Authorization": f"Bearer {token}"},
        timeout=10,
    )
    resp.raise_for_status()
    return [d["hostname"] for d in resp.json()]
```

`test_devices.py`:

```python
import unittest
from unittest.mock import patch

import requests

from devices import get_hostnames


class TestGetHostnames(unittest.TestCase):
    @patch("devices.requests.get")
    def test_returns_hostnames(self, mock_get):
        mock_get.return_value.json.return_value = [
            {"hostname": "sw01"}, {"hostname": "rtr01"},
        ]

        result = get_hostnames("example-token-not-real")

        self.assertEqual(result, ["sw01", "rtr01"])
        mock_get.assert_called_once_with(
            "https://api.example.com/api/v1/devices",
            headers={"Authorization": "Bearer example-token-not-real"},
            timeout=10,
        )

    @patch("devices.requests.get")
    def test_http_error_is_raised(self, mock_get):
        mock_get.return_value.raise_for_status.side_effect = (
            requests.HTTPError("401 Client Error: Unauthorized")
        )

        with self.assertRaises(requests.HTTPError):
            get_hostnames("example-token-not-real")


if __name__ == "__main__":
    unittest.main()
```

```text
alice@devbox:~/netlab$ python3 -m unittest -v test_devices
test_http_error_is_raised (test_devices.TestGetHostnames.test_http_error_is_raised) ... ok
test_returns_hostnames (test_devices.TestGetHostnames.test_returns_hostnames) ... ok

----------------------------------------------------------------------
Ran 2 tests in 0.001s

OK
```

How it works:

- `@patch("devices.requests.get")` swaps `requests.get` **as seen by the `devices` module** for a `MagicMock` while the test runs and passes the mock in as an extra argument (`mock_get`). The original is restored afterwards. No request leaves the machine.
- `mock_get.return_value` is what `requests.get(...)` returns (the fake response); setting `.json.return_value` decides what `resp.json()` returns. `raise_for_status()` on a mock does nothing unless you give it a `side_effect`.
- `side_effect` set to an exception makes the call raise it, which lets you test error handling without a real 401.
- `assert_called_once_with(...)` proves the code built the right URL, headers and timeout.

> **Watch out:** Patch where the name is **looked up**, not where it is defined. The docs' rule: "patch where an object is looked up, which is not necessarily the same place as where it is defined". If `devices.py` had said `from requests import get`, the module would hold its own reference called `get`, and the target would have to be `"devices.get"`; patching `"requests.get"` would leave the real function in place.

> **Exam tip:** Know the shape: a `TestCase` subclass, `test_` methods, `setUp` before each test, `self.assertEqual(actual, expected)`, `with self.assertRaises(SomeError):`, and `python -m unittest`. Expect fill-in items for a missing assert method or a missing `test` prefix.

## Lab it yourself

Any computer with Python 3.

1. Create a folder with `netutil.py` and `test_netutil.py` as above and run `python -m unittest -v` (Windows) or `python3 -m unittest -v` (macOS, Linux). You should see `Ran 7 tests` and `OK`.
2. Break `usable_hosts` by changing `>= 31` to `> 31`. Run again and read the failure: `AssertionError: 0 != 2`. Put it back.
3. Rename `test_slash_24` to `slash_24` and confirm the count drops to 6.
4. Add a `print("setUp")` to `setUp` and run `python -m unittest -v test_netutil.TestLoadInventory` to see it run once per test.
5. For the mock example, create a virtual environment (`python -m venv .venv`, then `.venv\Scripts\activate` on Windows or `source .venv/bin/activate` on macOS and Linux), run `pip install requests`, add `devices.py` and `test_devices.py`, and run them. Disconnect from the network and run again: the tests still pass, because nothing is sent.

## Key takeaways

- A test case subclasses `unittest.TestCase`; only methods whose names start with `test` are run.
- Use specific asserts (`assertEqual`, `assertIn`, `assertIsNone`, `assertRaises`) for better failure messages; `assertTrue` reports only "False is not true".
- `assertRaises` works as a context manager (`with self.assertRaises(ValueError):`) or as `assertRaises(exc, func, *args)`; never call the function yourself inside its argument list.
- `setUp()` runs before every test and `tearDown()` after every test; `setUpClass()`/`tearDownClass()` run once per class.
- `python -m unittest` discovers `test*.py` files; `-v` lists tests; `.` pass, `F` failed assertion, `E` unexpected exception.
- `unittest.mock.patch` replaces an API call with a mock; set `return_value` and `side_effect`, check calls with `assert_called_once_with`, and patch where the name is looked up.
