## Where you will use this

Every automation host, CI runner, container and network appliance with a Linux shell speaks Bash. Topic 4.11 covers three groups of commands: **file management**, **directory navigation** and **environment variables**. Domain 5 (topic 5.9) builds on this by asking you to read whole Bash scripts.

All the sessions below are real output from Bash 5.3 with GNU coreutils, run as the user `alice` on a host called `devbox` (the prompt `alice@devbox:~/netlab$` shows user, host and current directory). On Windows, use **WSL 2** or Git Bash to follow along; macOS ships Zsh as the default shell, but every command here behaves the same there, with small differences in `ls -l` output and error wording because macOS uses BSD tools.

## Directory navigation

The filesystem is one tree starting at `/`. Your **home directory** is `/home/alice` on Linux (`/Users/alice` on macOS), written `~` for short.

| Command | Meaning |
|---|---|
| `pwd` | Print the current (working) directory |
| `cd dir` | Change to `dir`, relative to where you are |
| `cd /etc` | **Absolute** path: starts with `/`, works from anywhere |
| `cd ..` | Parent directory (`.` is the current directory) |
| `cd ../..` | Up two levels |
| `cd` or `cd ~` | Home directory |
| `cd -` | Back to the previous directory (and print it) |

```text
alice@devbox:~/netlab$ cd configs
alice@devbox:~/netlab/configs$ pwd
/home/alice/netlab/configs
alice@devbox:~/netlab/configs$ cd ..
alice@devbox:~/netlab$ cd /tmp
alice@devbox:/tmp$ cd -
/home/alice/netlab
alice@devbox:~/netlab$ cd ~
alice@devbox:~$ pwd
/home/alice
alice@devbox:~$ cd netlab/configs
alice@devbox:~/netlab/configs$ cd ../..
alice@devbox:~$ pwd
/home/alice
```

A **relative** path (`configs`, `../backups`, `./run.sh`) is resolved from the current directory, so the same command means different things in different places. An **absolute** path (`/home/alice/netlab/configs`) always means the same place. Scripts should use absolute paths, or `cd` to a known directory first. `cd -` works because Bash keeps the previous directory in the `OLDPWD` variable.

## File management

```text
alice@devbox:~$ pwd
/home/alice
alice@devbox:~$ mkdir netlab/configs
mkdir: cannot create directory ‘netlab/configs’: No such file or directory
alice@devbox:~$ mkdir -p netlab/configs netlab/backups
alice@devbox:~$ cd netlab
alice@devbox:~/netlab$ ls
backups  configs
alice@devbox:~/netlab$ printf 'hostname sw01\nvlan 10\n name USERS\nvlan 20\n name VOICE\nntp server 10.10.20.5\n' > configs/sw01.cfg
alice@devbox:~/netlab$ cp configs/sw01.cfg configs/sw02.cfg
alice@devbox:~/netlab$ touch notes.txt
alice@devbox:~/netlab$ ls -l configs
total 8
-rw-rw-r-- 1 alice alice 76 Nov 22 12:56 sw01.cfg
-rw-rw-r-- 1 alice alice 76 Nov 22 12:56 sw02.cfg
alice@devbox:~/netlab$ cat configs/sw01.cfg
hostname sw01
vlan 10
 name USERS
vlan 20
 name VOICE
ntp server 10.10.20.5
alice@devbox:~/netlab$ grep -n vlan configs/sw01.cfg
2:vlan 10
4:vlan 20
alice@devbox:~/netlab$ grep -il "NTP SERVER" configs/*.cfg
configs/sw01.cfg
configs/sw02.cfg
alice@devbox:~/netlab$ mv configs/sw02.cfg backups/sw02.cfg.bak
alice@devbox:~/netlab$ find . -name "*.cfg"
./configs/sw01.cfg
alice@devbox:~/netlab$ rm configs
rm: cannot remove 'configs': Is a directory
alice@devbox:~/netlab$ rm -r backups
alice@devbox:~/netlab$ ls
configs  notes.txt
alice@devbox:~/netlab$ chmod 600 configs/sw01.cfg
alice@devbox:~/netlab$ ls -l configs/sw01.cfg
-rw------- 1 alice alice 76 Nov 22 12:56 configs/sw01.cfg
```

| Command | What it does | Options worth knowing |
|---|---|---|
| `ls` | List directory contents | `-l` long format, `-a` include hidden dot-files, `-h` human sizes, `-R` recursive |
| `mkdir` | Create directories | `-p` create parents as needed, no error if it exists |
| `touch` | Create an empty file, or update an existing file's timestamp | |
| `cp src dst` | Copy | `-r` copy a directory recursively, `-i` ask before overwriting, `-p` keep mode and times |
| `mv src dst` | Move **or rename** (same command) | `-i` ask before overwriting |
| `rm` | Delete files; there is no recycle bin | `-r` directories and their contents, `-i` ask, `-f` never ask. `rmdir` removes only empty directories |
| `cat` | Print whole files (and concatenate several) | |
| `less` | Page through a long file interactively | Space/b page down/up, `/text` search, `n` next match, `q` quit |
| `head` / `tail` | First / last lines | `-n 20`; `tail -f` follows a growing log |
| `grep pattern file` | Print lines matching a pattern | `-i` ignore case, `-n` line numbers, `-r` recurse into directories, `-l` file names only, `-v` invert, `-c` count, `-E` extended regex |
| `find path tests` | Search a directory tree by name, type, size, time | `-name "*.cfg"` (quote the pattern), `-type f` or `-type d`, `-mtime -1`, `-exec cmd {} \;` |
| `chmod` | Change permissions | Numeric `600`, `755`; symbolic `u+x`, `go-rw` |

Notes on the session:

- `mkdir netlab/configs` failed because `netlab` did not exist yet; `-p` created both levels.
- `rm configs` refused because `configs` is a directory; `rm -r` deletes a directory tree **without asking**. Double-check before running `rm -r` with a variable or a wildcard.
- `grep -il` matched `ntp server` regardless of case and printed only file names. `grep -ril "ntp server" .` would search every file under the current directory.
- `find` searches recursively from the starting directory. Quote the pattern so the shell does not expand `*.cfg` itself before `find` sees it.
- Redirection: `>` writes a command's output to a file (replacing it), `>>` appends, and `|` pipes one command's output into another (`ls -l | grep cfg`).

### Reading permissions

```text
-rw-------  1 alice alice 76 Nov 22 12:56 configs/sw01.cfg
|\_/\_/\_/
| u  g  o     u = owner (alice), g = group (alice), o = others
type: - file, d directory, l symlink
```

Each of `r` (4), `w` (2) and `x` (1) is added up per class: `rw-` = 6, `r-x` = 5, `rwx` = 7, `---` = 0. So `chmod 600` gives the owner read and write and nobody else anything (right for a file holding credentials), `chmod 644` is a normal readable file, and `chmod 755` an executable script or a directory others may enter. Symbolic forms change only what you name: `chmod u+x run.sh` adds execute for the owner, `chmod go-rw creds.env` removes read and write from group and others. A script needs `x` to run as `./run.sh`; `bash run.sh` works without it.

## Environment variables

Every process has an **environment**: a set of `NAME=value` strings it inherits from its parent. Shells also have their own **shell variables**, which are **not** passed on unless you **export** them.

```text
alice@devbox:~$ echo $HOME
/home/alice
alice@devbox:~$ echo "$USER is in $PWD"
alice is in /home/alice
alice@devbox:~$ SITE=hq1
alice@devbox:~$ echo $SITE
hq1
alice@devbox:~$ bash -c 'echo "child sees SITE=[$SITE]"'
child sees SITE=[]
alice@devbox:~$ export SITE
alice@devbox:~$ bash -c 'echo "child sees SITE=[$SITE]"'
child sees SITE=[hq1]
alice@devbox:~$ printenv SITE
hq1
alice@devbox:~$ env | grep SITE
SITE=hq1
alice@devbox:~$ export API_BASE=https://api.example.com/api/v1
alice@devbox:~$ API_TOKEN=example-token-not-real python3 -c 'import os; print(os.environ["API_TOKEN"])'
example-token-not-real
alice@devbox:~$ echo "API_TOKEN in this shell: [$API_TOKEN]"
API_TOKEN in this shell: []
```

| Syntax | Effect |
|---|---|
| `NAME=value` | Set a shell variable. **No spaces** around `=`: `NAME = value` runs a command called `NAME` |
| `export NAME` or `export NAME=value` | Mark it for export: the Bash manual says `export` marks each name "to be passed to subsequently executed commands in the environment", so child processes (scripts, Python, Ansible) see it |
| `$NAME`, `${NAME}`, `"$NAME"` | Read it. Quote it in scripts so spaces and empty values do not break commands |
| `echo $NAME` | Print one value (empty line if unset) |
| `printenv NAME` / `printenv` | Print one / all **exported** variables |
| `env` | Print the environment (and `env NAME=value cmd` runs a command with a modified environment) |
| `NAME=value command` | Set it **only for that one command**: the Bash manual says such assignments "are added to the environment of the executed command and do not affect the current shell environment" |
| `unset NAME` | Remove it |

The one-command form is handy for secrets and debug flags, as the last two commands show: Python saw `API_TOKEN`, the shell did not keep it. (It still appears in your shell history, so for real secrets prefer reading them from a file or prompting with `read -s`.)

Common variables: `HOME` (home directory), `USER`, `PWD` and `OLDPWD`, `SHELL`, `LANG`, `EDITOR`, and the most important one, `PATH`.

### PATH

`PATH` is a colon-separated list of directories the shell searches, in order, for a command you type without a slash.

```text
alice@devbox:~$ echo $PATH
/usr/local/bin:/usr/bin:/bin
alice@devbox:~$ mkdir -p ~/bin
alice@devbox:~$ printf '#!/bin/bash\necho "checking $1"\n' > ~/bin/netcheck
alice@devbox:~$ chmod +x ~/bin/netcheck
alice@devbox:~$ netcheck sw01
bash: netcheck: command not found
alice@devbox:~$ export PATH="$HOME/bin:$PATH"
alice@devbox:~$ netcheck sw01
checking sw01
alice@devbox:~$ type netcheck
netcheck is hashed (/home/alice/bin/netcheck)
```

Prepend (`$HOME/bin:$PATH`) or append (`$PATH:$HOME/bin`) your directory; never write `PATH=$HOME/bin` alone, which drops every system directory so that even `ls` stops working in that shell. To run a program in the current directory that is not on `PATH`, give its path: `./run.sh`. `type` (or `which`, or `command -v`) shows what a name resolves to.

### Making variables persistent

Variables set at the prompt vanish when the shell exits. An interactive non-login Bash reads **`~/.bashrc`** at start-up (login shells read `~/.bash_profile` or `~/.profile`, which on most Linux systems in turn source `~/.bashrc`), so put the `export` lines there and reload the file in the current shell with `source ~/.bashrc` (or `. ~/.bashrc`):

```text
alice@devbox:~$ echo 'export SITE=hq1' >> ~/.bashrc
alice@devbox:~$ tail -1 ~/.bashrc
export SITE=hq1
alice@devbox:~$ unset SITE
alice@devbox:~$ echo "SITE=[$SITE]"
SITE=[]
alice@devbox:~$ source ~/.bashrc
alice@devbox:~$ echo "SITE=[$SITE]"
SITE=[hq1]
```

Use `>>` (append), not `>`, or you replace the whole file. On macOS with Zsh the file is `~/.zshrc`. Keep secrets out of `~/.bashrc`; it is easy to copy, share or back up by accident.

> **Exam tip:** Know the difference between `VAR=value` (shell only), `export VAR=value` (shell and its children), `VAR=value cmd` (that command only) and a line in `~/.bashrc` (every new interactive shell). Also know `cd ..`, `cd ~`, `cd -`, absolute versus relative paths, and that `mv` both moves and renames.

## Lab it yourself

On Linux, macOS, or Windows with WSL 2 (or Git Bash). Work in a scratch directory so nothing important is touched: `mkdir -p ~/bashlab && cd ~/bashlab`.

1. Repeat the file-management session above line by line and compare your output.
2. From `~/bashlab/netlab/configs`, reach `~/bashlab` three ways: with `cd ../..`, with an absolute path, and with `cd ~/bashlab`. Use `cd -` to bounce back.
3. Create `creds.env`, check its mode with `ls -l`, then make it readable only by you with `chmod 600` and again with `chmod go-rw`.
4. Run the `SITE` export demonstration, then check that a new terminal window does not see `SITE` until you add it to `~/.bashrc` (`~/.zshrc` on macOS).
5. Create the `netcheck` script in `~/bin`, see "command not found", add `~/bin` to `PATH`, and run it again.
6. Clean up with `rm -r ~/bashlab ~/bin/netcheck` and remove the `export SITE` line from your start-up file with a text editor.

## Key takeaways

- Navigation: `pwd`, `cd dir`, `cd ..`, `cd ~`, `cd -`; absolute paths start with `/`, relative ones are resolved from the current directory.
- Files: `ls -l`, `mkdir -p`, `touch`, `cp -r`, `mv` (move or rename), `rm -r` (no undo), `cat`, `less`, `grep -inrl`, `find . -name "*.cfg" -type f`, `chmod 600` / `u+x`.
- Permissions read as owner/group/others with r=4, w=2, x=1.
- `VAR=value` sets a shell variable; `export` passes it to child processes; `VAR=value command` sets it for one command; `printenv` and `env` show the environment.
- `PATH` lists where commands are found; prepend with `export PATH="$HOME/bin:$PATH"`.
- Persist settings by appending `export` lines to `~/.bashrc` and reload with `source ~/.bashrc`.
