## Navigating and creating: the everyday utilities

Domain 1 covered the Filesystem Hierarchy Standard, paths and the shell. This lesson is about the utilities that act on files, how links really work, and what the entries in `/dev` are.

| Utility | What it does | Options worth knowing |
|---|---|---|
| `pwd` | Print the working directory | `-P` prints the physical path (symlinks resolved), `-L` the logical one |
| `cd` | Change directory (a shell builtin) | `cd -` returns to the previous directory, `cd` alone goes to `$HOME` |
| `ls` | List | `-l` long, `-a` hidden, `-h` human sizes, `-i` inode numbers, `-d` the directory itself, `-t` by time, `-S` by size, `-R` recursive |
| `mkdir` | Create directories | `-p` creates parents and is not an error if it exists, `-m 750` sets the mode |
| `rmdir` | Remove **empty** directories only | `-p` also removes empty parents |
| `touch` | Create an empty file, or update timestamps | `-c` do not create, `-d "2026-11-01 10:00"` or `-t` set a time, `-r ref` copy a reference file's time |
| `cp` | Copy | `-r` recursive, `-a` archive (recursive, keeps mode, ownership, timestamps and symlinks), `-p` keep mode/owner/times, `-i` ask, `-u` only newer, `-v` verbose |
| `mv` | Move or rename | `-i` ask before overwrite, `-n` never overwrite. Within one filesystem it is a rename of a directory entry (instant); across filesystems it copies then deletes |
| `rm` | Remove | `-r` recursive, `-f` force and ignore missing, `-i` ask. There is no recycle bin |

> **Watch out:** `rm` deletes directory entries; it never "shreds". Do not run `rm -rf` with an unquoted variable (`rm -rf $DIR/*` with `DIR` empty expands to `/*`). GNU `rm` refuses `rm -r /` without `--no-preserve-root`, but that does not protect `/home` or `/*`.

`cp -r src dst` behaves differently depending on whether `dst` exists: if it does, you get `dst/src`; if not, `dst` becomes a copy of `src`. `rsync` (domain 1) handles the trailing-slash question explicitly.

## Inspecting files: file, stat, diff, sdiff

`file` identifies content by its magic bytes, not by its name: `file backup-agent` reports "ELF 64-bit LSB executable, x86-64", and `file -i` (or `--mime-type`) prints the MIME type. It is the first tool to run on an unknown file or a mystery extension.

`stat` shows the inode: size, block count, type, mode in octal and symbolic form, owner, link count, inode number, and the three timestamps.

```text
srv01$ stat report.txt
  File: report.txt
  Size: 6         	Blocks: 8          IO Block: 4096   regular file
Device: 0,46	Inode: 88410       Links: 1
Access: (0664/-rw-rw-r--)  Uid: ( 1000/   alice)   Gid: ( 1000/   alice)
Access: 2026-11-22 07:56:31.192250416 -0600
Modify: 2026-11-22 07:56:31.193739128 -0600
Change: 2026-11-22 07:56:31.195250430 -0600
 Birth: 2026-11-22 07:56:31.192250416 -0600
```

**Access** (atime) is last read, **Modify** (mtime) is last content change, **Change** (ctime) is last inode change (permissions, owner, link count, content). ctime is not creation time; **Birth** is, when the filesystem records it. `stat -c '%a %U:%G %n'` prints a custom format (`%a` octal mode, `%h` link count, `%i` inode, `%F` file type).

`diff` compares files line by line. Useful forms: `diff -u old new` (unified format, what patches and `git` use), `diff -r dirA dirB` (recursive), `diff -q` (only say whether they differ). The exit status is **0** when identical, **1** when different and **2** on trouble, so `diff -q a b && echo same` works in scripts. `sdiff a b` prints the two files **side by side**: unchanged lines appear in both columns, and the marker between the columns is `<` (only in the left file), `>` (only in the right) or `|` (changed). `sdiff -o merged a b` lets you merge interactively; `diff -y` gives the same side-by-side view without the interactive merge.

## find and locate

`find path [tests] [actions]` walks the tree live, so it is always current but can be slow. Tests combine with an implicit AND.

```text
srv01$ find /var/log -type f -name '*.log' -mtime +30
srv01$ find /home -type f -size +100M -user bob
srv01$ find / -xdev -type f -perm -4000 2>/dev/null
srv01$ find /srv/app -type f -name '*.tmp' -delete
srv01$ find . -type f -name '*.conf' -exec grep -l 'ServerName' {} +
srv01$ find . -type f -print0 | xargs -0 ls -l
```

| Test | Meaning |
|---|---|
| `-name`, `-iname` | Glob on the base name (quote it so the shell does not expand it); `-iname` ignores case |
| `-type f d l b c p s` | Regular file, directory, symlink, block device, character device, pipe, socket |
| `-mtime +30` / `-mtime -1` / `-mtime 0` | Modified **more than** 30 days ago / within the last day / in the last 24 hours. Days are whole 24-hour periods, with the fraction discarded |
| `-mmin`, `-atime`, `-ctime`, `-newer ref` | Minutes; access time; change time; newer than a reference file |
| `-size +100M` | Larger than 100 MiB (`k`, `M`, `G`; sizes round up to the unit) |
| `-user`, `-group`, `-perm` | `-perm 644` exact mode, `-perm -4000` all of these bits set (setuid), `-perm /022` any of these bits |
| `-maxdepth 2` | Limit descent. Put it before other tests, or GNU find warns |
| `-xdev` | Stay on one filesystem |

Actions: `-print` (default), `-ls`, `-delete`, `-exec cmd {} \;` (run once per file) and `-exec cmd {} +` (batch many files into one command, like `xargs`). For file names with spaces use `-print0 | xargs -0`. Test with `-print` before you switch to `-delete` or `-exec rm`.

`locate` searches a prebuilt database (`plocate` or `mlocate`), so it is very fast but only as current as the last `updatedb`, which a daily timer or cron job normally runs. A file created five minutes ago will not appear until you run `sudo updatedb`; a deleted file may still be listed. `locate -i` ignores case, `locate -c` counts matches, and results are filtered to what you are allowed to see.

## lsof: who has this open?

`lsof` lists open files, which in Linux includes sockets, pipes and devices. Common uses:

```text
srv01$ sudo lsof -i :443                 # who owns or uses port 443
srv01$ sudo lsof -u bob                  # everything user bob has open
srv01$ sudo lsof -p 2183                 # open files of one PID
srv01$ sudo lsof +D /srv/data            # what is open under a directory
srv01$ sudo lsof /mnt/backup             # why will this not unmount?
srv01$ sudo lsof +L1                     # open files with link count 0 (deleted but still held)
```

The last one explains the classic "disk is full but `du` shows free space" case: a process still holds a deleted log file open, so the blocks are not released until the process closes it or restarts. `ss -tulnp` (domain 1) is the better first tool for listening sockets; `lsof -i` is useful when you also need file context.

## Links: hard and symbolic

Every file name is a directory entry pointing at an **inode**. A **hard link** is an additional name for the same inode. A **symbolic link** (symlink) is a separate small file whose content is a path.

```text
srv01$ echo hello > a.txt
srv01$ ln a.txt b.txt
srv01$ ln -s a.txt s.txt
srv01$ ls -li a.txt b.txt s.txt
93791 -rw-rw-r-- 2 alice alice  6 Nov 22 07:56 a.txt
93791 -rw-rw-r-- 2 alice alice  6 Nov 22 07:56 b.txt
93792 lrwxrwxrwx 1 alice alice  5 Nov 22 07:56 s.txt -> a.txt
```

| | Hard link | Symbolic link |
|---|---|---|
| Inode | Same inode as the original; the link count rises | Own inode; stores a path (size = length of that path) |
| Create | `ln target name` | `ln -s target name` |
| Across filesystems | **No** | Yes |
| To directories | **No** (normal users and `ln` forbid it) | Yes |
| Original deleted | Data survives until the last name is gone | The link **dangles** (broken) |
| Permissions | Shared (they are the same inode) | The link shows `lrwxrwxrwx`; the target's permissions apply |
| Identifying | Same inode number, `Links: 2` or more | `l` in the first column of `ls -l`, `->` arrow |

The order is `ln [-s] TARGET LINK_NAME`, and mixing it up is the most common mistake. A relative symlink target is resolved relative to **the directory that holds the link**, not your current directory. `readlink -f s.txt` prints the final resolved path, and `find . -xtype l` finds dangling links. `rm s.txt` removes the link, not the target.

> **Exam tip:** "Changes made through one name show up in the other, and deleting the original does not lose the data" means hard link. "Works across filesystems / links to a directory" means symbolic link.

## Device files in /dev

Device nodes are special files that name a kernel driver by **major and minor number**. `ls -l` shows the major, minor pair where a size would be, and the first character of the mode field gives the type.

```text
srv01$ ls -l /dev/nvme0n1 /dev/loop0 /dev/null /dev/zero /dev/urandom /dev/tty /dev/stdin
brw-rw---- 1 root disk 259, 0 Nov 22 07:52 /dev/nvme0n1
brw-rw---- 1 root disk   7, 0 Nov  9 10:38 /dev/loop0
crw-rw-rw- 1 root root   1, 3 Nov  9 10:38 /dev/null
crw-rw-rw- 1 root root   1, 5 Nov  9 10:38 /dev/zero
crw-rw-rw- 1 root root   1, 9 Nov  9 10:38 /dev/urandom
crw-rw-rw- 1 root tty    5, 0 Nov 22 07:27 /dev/tty
lrwxrwxrwx 1 root root     15 Nov  9 10:37 /dev/stdin -> /proc/self/fd/0
```

| Type | `ls -l` | Behaviour | Examples |
|---|---|---|---|
| **Block** | `b` | Fixed-size blocks, random access, buffered through the page cache; can hold a filesystem | `/dev/sda`, `/dev/sda1`, `/dev/nvme0n1p2`, `/dev/loop0`, `/dev/dm-0`, `/dev/mapper/vg_data-lv_app` |
| **Character** | `c` | A stream of bytes, no block addressing | `/dev/tty`, `/dev/ttyS0`, `/dev/input/*` |
| **Special character** (pseudo-devices) | `c` | Character devices with no hardware behind them, implemented in the kernel | `/dev/null` discards writes and reads EOF; `/dev/zero` reads endless zero bytes; `/dev/random` and `/dev/urandom` supply random bytes; `/dev/full` always returns "no space"; `/dev/tty` is the process's controlling terminal |

The objectives list "special character" as its own item, so treat it as these pseudo-devices. Named pipes (`p`) and sockets (`s`) also show in `ls -l` but are not device nodes. `udev` creates and removes nodes automatically as hardware appears; `mknod /dev/x c 1 3` makes one by hand (rarely needed). The practical uses are `dd if=/dev/zero of=file bs=1M count=100`, `cmd > /dev/null 2>&1`, and `head -c 16 /dev/urandom | xxd`.

## Lab it yourself

In the lab VM (or a container running inside it):

1. `mkdir -p ~/lab/{a,b}; cd ~/lab; echo one > a/f; cp -a a/f b/f; ls -l a b`.
2. `ln a/f hard; ln -s a/f soft; ls -li a/f hard soft`; then `rm a/f` and `cat hard` (works) versus `cat soft` (fails).
3. `stat hard` and note `Links:` before and after `rm a/f`.
4. `find ~/lab -type l`, `find ~/lab -type f -name 'f' -print`, `find ~/lab -xtype l` (dangling links).
5. `diff -u a/f b/f` (recreate `a/f` first), then change one copy and run `sdiff a/f b/f`.
6. `touch -d '2026-01-01' old; find . -mtime +30 -name old`.
7. `ls -l /dev/null /dev/zero /dev/loop0`, `sudo lsof -i :22`, `sudo updatedb && locate lab`.

## Key takeaways

- `cp -a` preserves everything; `mv` within a filesystem is just a rename; `rm` has no undo; `rmdir` only removes empty directories.
- `stat` shows mode, owner, links, inode and the atime, mtime and ctime timestamps; ctime is the inode change time, not creation.
- `find` tests are ANDed; `-mtime +30` means older than 30 whole days; `-exec ... {} +` batches; test with `-print` before `-delete`.
- `locate` reads a database refreshed by `updatedb`, so it misses new files; `find` is always current.
- `lsof` finds who holds a file, port or mount open, and `lsof +L1` finds deleted-but-open files that still use space.
- Hard links share an inode, cannot cross filesystems or point at directories and survive deletion of the original; symlinks store a path and dangle when the target goes.
- `ln -s TARGET LINK_NAME`; relative targets resolve from the link's directory.
- `b` is a block device, `c` a character device, and `/dev/null`, `/dev/zero` and `/dev/urandom` are the special pseudo-devices.
