## The account files

Local accounts live in three plain-text files. Programs read them through the Name Service Switch (`passwd:` and `group:` lines in `/etc/nsswitch.conf`), which is why `getent` is the right way to query them: it also shows LDAP, SSSD or systemd-homed accounts that are not in the files.

**`/etc/passwd`** (mode 644, world-readable) has seven colon-separated fields:

```text
alice:x:1001:1001:Alice Admin:/home/alice:/bin/bash
name :pw:UID :GID :GECOS      :home       :login shell
```

The `x` means the password hash is in `/etc/shadow`. The GID is the **primary group**. A shell of `/usr/sbin/nologin` (or `/sbin/nologin`, `/bin/false`) stops interactive logins.

**`/etc/shadow`** (mode 640 root:shadow on Debian/Ubuntu, mode 000 on RHEL; only root reads it) has nine fields:

```text
alice:$y$j9T$...:20779:0:90:7:14:20849:
name:hash:last change:min:max:warn:inactive:expire:reserved
```

| Field | Meaning |
|---|---|
| hash | `$y$` yescrypt (Debian 11+, Ubuntu 22.04+, Fedora, RHEL 10), `$6$` SHA-512 (RHEL 9 default). A leading `!` or `*` means no password login is possible; `!` prefixed to a hash is a **lock** |
| last change | Days since 1 January 1970. `0` forces a change at next login |
| min / max / warn | Minimum days between changes, maximum age, days of warning before expiry |
| inactive | Days after the password expires during which the user can still log in and must change it; after that the account is disabled |
| expire | The **account** expiry date, in days since the epoch. Empty means never |

**`/etc/group`** has four fields: `name:x:GID:member,member`. The member list holds **supplementary** members only; users whose primary GID matches do not appear there. Group passwords go in `/etc/gshadow`.

## UIDs, GIDs and the kinds of account

| Account kind | UID | Purpose |
|---|---|---|
| root | 0 | Superuser. Any account with UID 0 is root, whatever its name |
| System accounts | 1-999 | Created by packages for daemons (`www-data`, `apache`, `chrony`, `systemd-resolve`), usually with a nologin shell and no password |
| Regular (human) users | 1000-60000 | Interactive logins |
| nobody | 65534 | Unprivileged placeholder (`nobody` on both families; Debian's group is `nogroup`) |

The boundaries come from **`/etc/login.defs`**: `UID_MIN 1000`, `UID_MAX 60000`, `SYS_UID_MIN` and `SYS_UID_MAX` (and the same for GIDs). Debian leaves the system range commented out (`#SYS_UID_MIN 100`, `#SYS_UID_MAX 999`), so `useradd -r` falls back to its built-in 101-999, while `adduser --system` uses 100-999 from `/etc/adduser.conf` (Debian policy reserves 0-99 for statically allocated system accounts); RHEL sets `SYS_UID_MIN 201` and `SYS_UID_MAX 999`, keeping 0-200 for accounts with fixed UIDs. `login.defs` also sets the default `PASS_MAX_DAYS`, `PASS_MIN_DAYS` and `PASS_WARN_AGE` for **new** accounts, `ENCRYPT_METHOD`, `HOME_MODE`/`UMASK`, `USERGROUPS_ENAB` (create a group with the same name as the user) and, on RHEL, `CREATE_HOME yes`.

A **service account** is a system account that exists to run one service. It is created with `useradd -r` or `adduser --system`, has no valid password, and usually has a nologin shell and a home such as `/var/lib/<service>`. systemd can also create one on the fly with `DynamicUser=yes`.

### UID, GID, EUID and EGID

Every process carries a **real** UID and GID (who started it) and an **effective** UID and GID (whose permissions it uses). They are normally equal. A setuid program such as `passwd` (`-rwsr-xr-x root`) runs with EUID 0 so it can write `/etc/shadow`, while its real UID stays that of the caller. `sudo` and `su` start a new process with a different real and effective identity. `id` shows the effective identity and groups; `/proc/<PID>/status` shows all four values on its `Uid:` and `Gid:` lines (real, effective, saved, filesystem).

```text
alice@srv01:~$ id
uid=1001(alice) gid=1001(alice) groups=1001(alice),10(wheel),1005(webdev)
alice@srv01:~$ id -un; whoami; groups
alice
alice
alice wheel webdev
```

`whoami` prints the effective user name (same as `id -un`). `groups` lists group memberships; note that a group added with `usermod -aG` only appears in a session after the user logs in again (or runs `newgrp`).

## Adding accounts and groups

`useradd` is the low-level tool on every distribution. Its defaults come from `/etc/default/useradd` (`useradd -D` prints them) and `/etc/login.defs`.

```text
srv01# useradd -m -s /bin/bash -c "Bob Ops" -G wheel bob
srv01# passwd bob
srv01# useradd -r -s /usr/sbin/nologin -d /var/lib/backup -M svc_backup
srv01# groupadd -g 1500 webdev
srv01# groupadd -r appsvc
```

| Option | Meaning |
|---|---|
| `-m` / `-M` | Create / do not create the home directory (copying `/etc/skel`) |
| `-s`, `-c`, `-d` | Shell, comment (GECOS), home directory path |
| `-u`, `-g`, `-G` | UID; primary group; comma-separated supplementary groups |
| `-r` | System account: UID from the system range, no home, no aging |
| `-e YYYY-MM-DD`, `-f days` | Account expiry date; inactive days |

The families differ in ways the exam likes:

| | RHEL / Fedora | Debian / Ubuntu |
|---|---|---|
| `useradd bob` home directory | Created (`CREATE_HOME yes` in `login.defs`) | **Not** created unless you add `-m` |
| `useradd` default shell | `/bin/bash` | `/bin/sh` (from `/etc/default/useradd`) |
| `adduser` | A symlink to `useradd`; same options, no prompts | A separate Perl script, configured by `/etc/adduser.conf`: creates the home, copies `/etc/skel`, and **interactively** asks for the password and GECOS |
| `adduser bob webdev` | Not supported | Adds existing user bob to existing group webdev |
| `deluser` / `delgroup` | Not present | Debian front ends; `deluser --remove-home bob`, `deluser bob webdev` removes him from the group |
| Admin group | `wheel` | `sudo` |

## Modifying, locking and deleting

```text
srv01# usermod -aG webdev alice        # append a supplementary group
srv01# usermod -s /bin/zsh alice       # change login shell (or: chsh -s /bin/zsh alice)
srv01# usermod -l alice2 alice         # rename the login (home is not renamed)
srv01# usermod -d /srv/home/alice -m alice   # move home and its contents
srv01# groupmod -n developers webdev   # rename a group; -g changes its GID
```

> **Watch out:** `usermod -G webdev alice` without `-a` **replaces** all of alice's supplementary groups with just `webdev`. On a server, that is how people accidentally lose `wheel` or `sudo`.

`chsh -s /bin/zsh` lets a user change their own shell to one listed in `/etc/shells`; root can change anyone's.

`passwd` sets passwords and, with options, manages locking: `passwd -l bob` locks (prefixes the hash with `!` on Debian, `!!` with RHEL's `passwd`), `passwd -u bob` unlocks, `passwd -S bob` prints status (`L` or `LK` locked, `P` or `PS` usable, `NP` no password), `passwd -e bob` expires the password so it must be changed at next login. `usermod -L` and `usermod -U` lock and unlock the same way.

> **Exam tip:** A password lock does **not** stop SSH key logins, because key authentication never checks the hash. To block every login, also expire the account (`usermod -e 1` or `chage -E 0`) or set a nologin shell. `chage -E 0 bob` sets the account expiry to day 0 (1 January 1970), so the account is already expired. Linux-PAM's `pam_unix` treats 0 as expired, but `shadow(5)` warns that some tools read 0 as "never expires", so `usermod -e 1` (or `chage -E 1`) is the unambiguous form.

Deleting: `userdel bob` removes the account entries; `userdel -r bob` also removes the home directory and mail spool. Files bob owned elsewhere keep his old UID and show as a bare number; find them with `find / -xdev -nouser`. `groupdel webdev` fails if the group is still some user's **primary** group.

## Password aging and expiration with chage

`chage` edits the aging fields of `/etc/shadow` for an existing account. Defaults for new accounts come from `login.defs` (`PASS_MAX_DAYS` and friends) and `/etc/default/useradd` (`INACTIVE`, `EXPIRE`).

```text
srv01# chage -M 90 -m 1 -W 7 -I 14 -E 2027-01-31 bob
srv01# chage -l bob
Last password change                                    : Nov 22, 2026
Password expires                                        : Feb 20, 2027
Password inactive                                       : Mar 06, 2027
Account expires                                         : Jan 31, 2027
Minimum number of days between password change          : 1
Maximum number of days between password change          : 90
Number of days of warning before password expires       : 7
```

| Option | Sets |
|---|---|
| `-l` | List (users may run it on their own account) |
| `-M` / `-m` / `-W` | Maximum age / minimum age / warning days |
| `-I` | Inactive days after the password expires |
| `-E YYYY-MM-DD` | Account expiry; `-E -1` removes it |
| `-d 0` | Set last-change to 0, forcing a change at next login |

Password expiry and account expiry are different things: an expired **password** makes the user choose a new one at login (until the inactive period ends); an expired **account** refuses login entirely.

## Listing who is there and who was there

| Command | Shows |
|---|---|
| `getent passwd alice`, `getent group webdev` | Account entries from every NSS source |
| `id`, `groups`, `whoami` | Identity of the current (or named) user |
| `who` | Users logged in now, with terminal and login time (from utmp) |
| `w` | Like `who` plus idle time, load averages and each user's current command |
| `last` | Login and reboot history from `/var/log/wtmp` (`last reboot`, `last bob`) |
| `lastlog` | The most recent login of **every** account, from `/var/log/lastlog` |
| `lastb` | Failed logins from `/var/log/btmp` (root only) |

> **Real world:** Newer distributions are replacing the old fixed-size files: util-linux `lastlog2` (database in `/var/lib/lastlog/lastlog2.db`) and `wtmpdb last` are what Fedora, openSUSE and the newest Debian and Ubuntu releases ship, sometimes without the classic `lastlog`. Debian 12, Ubuntu 24.04 and RHEL 9 still have `lastlog` and `last`. The exam names the classic commands.

## Profile templates: /etc/skel and /etc/profile

When `useradd -m` or `adduser` creates a home directory it copies the contents of **`/etc/skel`** into it, so put default `.bashrc`, `.bash_profile` or `.profile` files there. Changes to `/etc/skel` affect only accounts created afterwards; existing users keep their copies.

**`/etc/profile`** is the system-wide file every login shell reads (Domain 1 covered the bash startup order). It sources the snippets in **`/etc/profile.d/*.sh`**, which is the right place to add a site-wide variable or PATH entry, because package updates can overwrite `/etc/profile` itself.

## Lab it yourself

In the lab VM, or a container running inside it (run as root):

1. `grep -E 'UID_MIN|UID_MAX|SYS_UID|CREATE_HOME|PASS_MAX' /etc/login.defs` and `useradd -D`; compare a Debian and a Rocky or Alma container.
2. `useradd -m -s /bin/bash testuser`, `passwd testuser`, then `getent passwd testuser`, `grep testuser /etc/shadow` and `ls -la /home/testuser` (compare with `/etc/skel`).
3. `groupadd labgrp; usermod -aG labgrp testuser; id testuser`. Then try `usermod -G labgrp testuser` after adding a second group and see the first disappear.
4. `passwd -l testuser; passwd -S testuser; grep testuser /etc/shadow` (note the `!`), then `passwd -u testuser`.
5. `chage -M 30 -W 5 -E 2027-06-30 testuser; chage -l testuser`.
6. `useradd -r -s /usr/sbin/nologin svc_lab; id svc_lab` and check that its UID is below 1000.
7. `userdel -r testuser`, then `find / -xdev -nouser 2>/dev/null`.

## Key takeaways

- `/etc/passwd` has seven fields and is world-readable; hashes live in root-only `/etc/shadow`; `/etc/group` lists supplementary members only.
- UID 0 is root, 1-999 system and service accounts, 1000 and up regular users; `/etc/login.defs` defines the ranges and new-account aging defaults.
- On RHEL `useradd` creates the home and `adduser` is the same program; on Debian `useradd` needs `-m` and `adduser` is a friendlier interactive script with `deluser` as its partner.
- `usermod -aG` appends; `-G` without `-a` replaces all supplementary groups.
- `passwd -l` / `usermod -L` lock the password only; `chage -E 0` or `usermod -e 1` expires the whole account.
- `chage -l` lists aging; `-M`, `-m`, `-W`, `-I`, `-E` and `-d 0` set it.
- `who` and `w` show current sessions, `last` shows history, `lastlog` shows every account's last login.
- `/etc/skel` seeds new home directories; `/etc/profile` and `/etc/profile.d/` set system-wide login environment.
