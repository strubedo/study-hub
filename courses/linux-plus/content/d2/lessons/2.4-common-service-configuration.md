## The pattern for every service

Installing a network service always follows the same loop, and the exam tests the loop as much as the individual files:

1. Install the package (the name often differs between families: `httpd` vs `apache2`, `bind` vs `bind9`).
2. Edit the configuration in `/etc`, preferably in a drop-in directory.
3. **Check the syntax** with the service's own test command before you restart.
4. `systemctl enable --now <service>` (lesson 2.5), then `systemctl reload` for later changes when the service supports it.
5. Open the port in the host firewall (`firewall-cmd --add-service=http --permanent` or `ufw allow 80/tcp`; Domain 3).
6. Test from a client and read the logs (`journalctl -u <service>`).

| Service | Port | RHEL package / unit | Debian package / unit | Syntax check |
|---|---|---|---|---|
| DNS (BIND) | 53 UDP+TCP | `bind` / `named` | `bind9` / `named` (alias `bind9`) | `named-checkconf`, `named-checkzone` |
| NTP (chrony) | 123 UDP | `chrony` / `chronyd` | `chrony` / `chrony` | `chronyd -p` (print parsed config) |
| PTP (linuxptp) | 319, 320 UDP (or raw Ethernet) | `linuxptp` / `ptp4l`, `phc2sys` | `linuxptp` | |
| DHCP (Kea) | 67 server, 68 client UDP | `kea` / `kea-dhcp4` (BaseOS on RHEL 10; EPEL on RHEL 9) | `kea-dhcp4-server` / `kea-dhcp4-server` | `kea-dhcp4 -t <file>` |
| HTTP (Apache) | 80, 443 TCP | `httpd` / `httpd` | `apache2` / `apache2` | `apachectl configtest` (`apache2ctl` on Debian) |
| HTTP (Nginx) | 80, 443 TCP | `nginx` / `nginx` | `nginx` / `nginx` | `nginx -t` |
| SMTP (Postfix) | 25; 587 submission; 465 submissions | `postfix` | `postfix` | `postfix check`, `postconf -n` |
| IMAP4 (Dovecot) | 143; 993 IMAPS | `dovecot` | `dovecot-imapd` | `doveconf -n` |

## DNS: a caching and authoritative BIND server

The client side (`/etc/resolv.conf`, `nsswitch.conf`, `dig`) was in Domain 1, and `systemd-resolved` is in lesson 2.5. On the server side, BIND's main file is `/etc/named.conf` on RHEL and `/etc/bind/named.conf` (which includes `named.conf.options` and `named.conf.local`) on Debian.

```text
options {
    listen-on port 53 { 127.0.0.1; 10.0.10.53; };
    allow-query       { localhost; 10.0.0.0/16; };
    recursion yes;                      // act as a caching resolver for allowed clients
    allow-recursion   { localhost; 10.0.0.0/16; };
    forwarders        { 198.51.100.53; };
};

zone "example.com" IN {
    type primary;                       // older configs say "type master"
    file "example.com.zone";            // relative to "directory" (/var/named on RHEL)
};
```

A zone file starts with `$TTL` and an **SOA** record, then NS, A, AAAA, MX, CNAME and TXT records. Increase the SOA **serial** every time you edit the zone, or secondaries will not transfer the change.

```text
$TTL 3600
@     IN SOA ns1.example.com. hostmaster.example.com. ( 2026112201 3600 900 1209600 300 )
      IN NS  ns1.example.com.
      IN MX  10 mail.example.com.
ns1   IN A   10.0.10.53
www   IN A   10.0.10.80
mail  IN A   10.0.10.25
```

Check with `named-checkconf` and `named-checkzone example.com /var/named/example.com.zone`, reload with `rndc reload` (or `systemctl reload named`), and test with `dig @10.0.10.53 www.example.com`. Never leave `recursion yes` open to the whole internet: an open resolver gets used for amplification attacks. Lighter alternatives are **Unbound** (caching resolver only) and **dnsmasq** (small DNS forwarder plus DHCP for labs and appliances).

## NTP with chrony, and PTP

`chronyd` is the default NTP implementation on RHEL, Fedora, Debian and Ubuntu. The file is `/etc/chrony.conf` on RHEL and `/etc/chrony/chrony.conf` on Debian/Ubuntu (which also reads `/etc/chrony/sources.d/*.sources`).

```text
pool 2.rhel.pool.ntp.org iburst        # several servers from a DNS pool; iburst = fast first sync
server ntp1.example.com iburst         # one specific server
driftfile /var/lib/chrony/drift
makestep 1.0 3                         # step the clock if off by > 1 s, but only in the first 3 updates
rtcsync                                # copy system time to the hardware clock
allow 10.0.0.0/16                      # serve time to these clients (makes chronyd a server)
```

Without an `allow` line chronyd is a client only. Verify with `chronyc sources -v` (a `*` marks the selected source, `+` other combinable ones, `?` unreachable), `chronyc tracking` (current offset and stratum) and `chronyc makestep` to step immediately. `timedatectl` (lesson 2.5) reports `System clock synchronized: yes` once chrony is locked. ntpd from the classic ntp package (`/etc/ntp.conf`, `ntpq -p`) is legacy, and `systemd-timesyncd` is a simple SNTP client used on some Debian and Ubuntu installs instead of chrony.

**PTP** (Precision Time Protocol, IEEE 1588) gives sub-microsecond accuracy on a LAN by using **hardware timestamps** in the network card, for trading, telecom and industrial systems. The Linux implementation is **linuxptp**: `ptp4l` synchronises the NIC's PTP hardware clock (`/dev/ptp0`) to a grandmaster, and `phc2sys` then disciplines the system clock from the NIC clock. Check support with `ethtool -T eth0` (look for hardware transmit and receive timestamping and a "PTP Hardware Clock" index). A minimal run is `ptp4l -i eth0 -m` (print to stdout) and `phc2sys -s eth0 -w`. chrony can also consume a PHC as a reference clock (`refclock PHC /dev/ptp0`).

## DHCP with Kea

ISC DHCP (`dhcpd`, `/etc/dhcp/dhcpd.conf`) reached end of life in 2022; its successor from the same project is **Kea**, configured in JSON (`/etc/kea/kea-dhcp4.conf`):

```text
{
  "Dhcp4": {
    "interfaces-config": { "interfaces": [ "eth1" ] },
    "lease-database": { "type": "memfile", "persist": true },
    "valid-lifetime": 3600,
    "subnet4": [ {
        "id": 1,
        "subnet": "10.0.20.0/24",
        "pools": [ { "pool": "10.0.20.100 - 10.0.20.200" } ],
        "option-data": [
          { "name": "routers", "data": "10.0.20.1" },
          { "name": "domain-name-servers", "data": "10.0.10.53" }
        ],
        "reservations": [ { "hw-address": "52:54:00:12:34:56", "ip-address": "10.0.20.10" } ]
    } ]
  }
}
```

Test with `kea-dhcp4 -t /etc/kea/kea-dhcp4.conf`. You will still meet the old `dhcpd.conf` syntax (`subnet 10.0.20.0 netmask 255.255.255.0 { range 10.0.20.100 10.0.20.200; option routers 10.0.20.1; }`) on older systems. The DHCP exchange is DISCOVER, OFFER, REQUEST, ACK; a server on another subnet needs a relay (`ip helper-address` on a Cisco router).

## HTTP: Apache httpd and Nginx

The two families lay Apache out differently:

| | RHEL (`httpd`) | Debian / Ubuntu (`apache2`) |
|---|---|---|
| Main file | `/etc/httpd/conf/httpd.conf` | `/etc/apache2/apache2.conf` |
| Extra config | `/etc/httpd/conf.d/*.conf` (all loaded) | `sites-available/` linked into `sites-enabled/` with `a2ensite` / `a2dissite`; modules with `a2enmod` / `a2dismod`; `conf-available/` with `a2enconf` |
| Modules | `/etc/httpd/conf.modules.d/` | `mods-available/` and `mods-enabled/` |
| Document root | `/var/www/html` | `/var/www/html` |
| Logs | `/var/log/httpd/` | `/var/log/apache2/` |
| Runs as | `apache` | `www-data` |

A name-based virtual host:

```text
<VirtualHost *:80>
    ServerName www.example.com
    DocumentRoot /var/www/example
    ErrorLog  /var/log/httpd/example-error.log
    <Directory /var/www/example>
        Require all granted
    </Directory>
</VirtualHost>
```

**Nginx** uses `/etc/nginx/nginx.conf` with `http { }` containing `server { }` blocks; RHEL loads `/etc/nginx/conf.d/*.conf`, and Debian adds `sites-available/` and `sites-enabled/` (symlink by hand; there is no `a2ensite`).

```text
server {
    listen 80;
    server_name www.example.com;
    root /var/www/example;
    location /api/ {
        proxy_pass http://127.0.0.1:8080;    # reverse proxy to an app server
    }
}
```

Test with `nginx -t`, then `systemctl reload nginx` (or `nginx -s reload`). On RHEL, a non-default document root or a reverse proxy to a local port also needs SELinux attention (correct file context, or `setsebool -P httpd_can_network_connect on`; Domain 3).

## SMTP with Postfix and IMAP4 with Dovecot

Postfix delivers and relays mail. Its main settings live in `/etc/postfix/main.cf` (service definitions in `master.cf`):

```text
myhostname = mail.example.com
mydomain = example.com
myorigin = $mydomain
inet_interfaces = all              # default on RHEL is loopback-only
mydestination = $myhostname, localhost.$mydomain, localhost, $mydomain
mynetworks = 127.0.0.0/8, 10.0.0.0/16     # clients allowed to relay through this server
relayhost = [smtp.example.net]:587        # send all outbound mail via a smarthost
home_mailbox = Maildir/
```

`postconf -n` prints only the settings that differ from defaults, `postconf -e 'key = value'` edits `main.cf`, `postfix check` validates, and `postqueue -p` (or `mailq`) shows the queue. A `mynetworks` that includes the whole internet makes an **open relay**. After changing `/etc/aliases`, run `newaliases`.

Dovecot serves mailboxes to clients over **IMAP4** (143, or 993 with TLS) and POP3 (110/995). Configuration is `/etc/dovecot/dovecot.conf` plus `/etc/dovecot/conf.d/`:

```text
protocols = imap
mail_location = maildir:~/Maildir          # 10-mail.conf; must match Postfix's home_mailbox
ssl = required                              # 10-ssl.conf, with ssl_cert = </etc/pki/tls/certs/mail.pem
disable_plaintext_auth = yes                # 10-auth.conf
```

`doveconf -n` prints the effective non-default configuration. Dovecot 2.4 (Debian 13) renamed several settings, for example `mail_location` became `mail_driver` plus `mail_path`, so check the version before copying examples.

> **Exam tip:** SMTP **sends** and relays (Postfix, 25/587); IMAP4 lets a client **read and keep** mail on the server (Dovecot, 143/993). If the stem says users can send but not see their mail, look at Dovecot and the mailbox format; if mail is not leaving, look at Postfix, `relayhost` and the queue.

## Lab it yourself

Use the lab VM (services need systemd; most minimal containers do not run it):

1. Install `nginx`, create `/etc/nginx/conf.d/lab.conf` with a `server` block, break a semicolon, run `nginx -t`, fix it, `systemctl reload nginx`, `curl -H 'Host: www.example.com' http://127.0.0.1/`.
2. Install `chrony`, add `allow 127.0.0.1`, restart it and run `chronyc sources -v` and `chronyc tracking`.
3. Install BIND, add the `example.com` zone above, run `named-checkconf` and `named-checkzone`, then `dig @127.0.0.1 www.example.com +short`.
4. Install Postfix ("Local only" on Debian), run `postconf -n`, send `echo test | sendmail root`, and look at `postqueue -p` and `/var/log/mail.log` or `journalctl -u postfix`.
5. Run `ethtool -T` on your NIC to see whether it supports hardware timestamping for PTP.

## Key takeaways

- Every service: install, edit config, run the syntax check, enable and start, open the firewall, test, read the journal.
- BIND: `named.conf` (RHEL) or `/etc/bind/` (Debian); bump the SOA serial; `named-checkconf`, `named-checkzone`, `rndc reload`; do not run an open resolver.
- chrony: `/etc/chrony.conf` or `/etc/chrony/chrony.conf`; `pool`/`server ... iburst`, `allow` to serve; `chronyc sources` and `tracking`. PTP is linuxptp (`ptp4l`, `phc2sys`) with hardware timestamps.
- Kea replaces ISC dhcpd; JSON config in `/etc/kea/kea-dhcp4.conf`; check with `kea-dhcp4 -t`.
- Apache is `httpd` with `conf.d/` on RHEL and `apache2` with `a2ensite`/`a2enmod` on Debian; Nginx uses `server` blocks and `nginx -t`.
- Postfix (`main.cf`, `postconf -n`, `mynetworks`, `relayhost`) sends mail; Dovecot (`protocols = imap`, `mail_location`) serves it over IMAP4 143/993.
