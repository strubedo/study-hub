## Tests: `test`, `[ ]` and `[[ ]]`

Conditionals in the shell do not evaluate booleans; they run a command and look at its **exit status** (lesson 4.2, Scripting 1): 0 is true, anything else is false. Three commands exist mainly to produce that status:

| Form | What it is |
|---|---|
| `test expr` | The classic POSIX command |
| `[ expr ]` | The same command under another name; the closing `]` is its last argument, so **spaces are required**: `[ -f "$f" ]`, never `[-f "$f"]` |
| `[[ expr ]]` | A bash **keyword** (also in zsh and ksh, not in dash or POSIX sh). Parsed by the shell itself, so variables inside are not word-split or globbed, `&&` and `||` work inside it, and it adds pattern matching and `=~` |
| `(( expr ))` | Bash arithmetic evaluation: true when the expression is non-zero. Uses C-style `<`, `<=`, `==`, `!=`, `>=`, `>` on integers |

The file and string tests named in the objectives:

| Test | True when |
|---|---|
| `-d path` | Path exists and is a directory |
| `-f path` | Path exists and is a regular file (not a directory or device) |
| `-e path` | Path exists (any type); related: `-r`, `-w`, `-x` (permissions), `-s` (size above zero), `-L` (symbolic link) |
| `-n string` | String is **non-empty** |
| `-z string` | String is **empty** (zero length) |
| `! expr` | Negates the test: `[ ! -d "$dir" ]` |

```text
alice@srv01:~$ ./tests.sh
-d: backups is a directory
-f: backups is not a regular file
!: /etc/nologin does not exist
-z: empty string
-n: non-empty string
-n with unquoted empty var is TRUE (one-argument test)
```

That last line is a classic bug. With `empty=""`, the unquoted test `[ -n $empty ]` becomes `[ -n ]`, and a one-argument test is true whenever the argument is non-empty (the argument is the string `-n`). Quote variables inside `[ ]`: `[ -n "$empty" ]` is false, as expected. `[[ -n $empty ]]` is also correct, because `[[ ]]` does not split.

## Comparisons

**Numeric** operators work in `[ ]`, `test` and `[[ ]]`, on integers only:

| Operator | Meaning |
|---|---|
| `-eq` / `-ne` | Equal / not equal |
| `-gt` / `-ge` | Greater than / greater or equal |
| `-lt` / `-le` | Less than / less or equal |

`[ 07 -eq 7 ]` is true (numeric), `[ "x" -eq 1 ]` fails with `[: x: integer expected` (status 2), and decimals such as `1.5` are rejected; use `bc` or awk for floating point. Inside `(( ))` you write the familiar symbols instead: `(( count >= 3 ))`.

**String** operators compare text:

| Operator | `[ ]` / `test` | `[[ ]]` |
|---|---|---|
| `=` | Equal (the POSIX form) | Equal; the right side is a **glob pattern** unless quoted |
| `==` | Equal in bash's `[` (not POSIX; dash rejects it) | Same as `=`: `[[ $host == web* ]]` matches `web01` |
| `!=` | Not equal | Not equal / does not match the pattern |
| `<`, `>` | Must be escaped, `\<` and `\>`, or the shell treats them as **redirections**. Compare in ASCII order | Work unescaped. Compare in the current locale's order |
| `=~` | **Not supported**: `[: =~: binary operator expected` | Extended regular expression match (below) |
| `<=`, `>=` | **Not string operators in bash**: `[: <=: binary operator expected` | **Syntax error**: `syntax error in conditional expression` |

The objectives list `<=` and `>=` among string comparisons, so be clear about what bash really does. Neither `[ ]` nor `[[ ]]` accepts them for strings (checked in bash 5.3 above). They are valid in arithmetic, `(( a <= b ))`, and as the numeric `-le` and `-ge`. To get "less than or equal" for strings, negate the opposite test: `[[ ! $a > $b ]]`.

```text
alice@srv01:~$ cat cmp.sh
#!/bin/bash
a=apple; b=banana
[[ $a < $b ]] && echo "[[ \$a < \$b ]]: true"
[ "$a" \< "$b" ] && echo "[ \"\$a\" \\< \"\$b\" ]: true"
[ "$a" < "$b" ]; echo "[ \"\$a\" < \"\$b\" ]: status $? (reads file \$b)"
[ "$a" =~ ^a ]; echo "[ =~ ]: status $?"
(( 3 <= 5 )) && echo "(( 3 <= 5 )): true"
[[ ! $a > $b ]] && echo "[[ ! \$a > \$b ]]: true (string less-or-equal)"
alice@srv01:~$ ./cmp.sh
[[ $a < $b ]]: true
[ "$a" \< "$b" ]: true
./cmp.sh: line 5: banana: No such file or directory
[ "$a" < "$b" ]: status 1 (reads file $b)
./cmp.sh: line 6: [: =~: binary operator expected
[ =~ ]: status 2
(( 3 <= 5 )): true
[[ ! $a > $b ]]: true (string less-or-equal)
```

> **Watch out:** `<` and `>` compare **strings**, even inside `[[ ]]`: `[[ 10 < 9 ]]` is **true** because the character `1` sorts before `9`. Use `-lt`/`-gt` or `(( ))` for numbers. And an unescaped `>` inside `[ ]` silently creates a file named after the right-hand operand.

## Regular expressions with `=~`

Inside `[[ ]]`, `string =~ regex` matches a POSIX **extended** regular expression (the same dialect as `grep -E`). The match may be anywhere in the string unless you anchor it with `^` and `$`. The whole match goes into `${BASH_REMATCH[0]}` and each parenthesised group into `${BASH_REMATCH[1]}`, `[2]` and so on. Status is 0 for a match, 1 for no match and 2 for an invalid regex.

**Do not quote the regex**: any quoted part is matched literally. The safe habit is to store the pattern in a variable and use it unquoted:

```text
alice@srv01:~$ cat regex.sh
#!/bin/bash
for host in web01 web12 db01 web1x; do
    if [[ $host =~ ^web([0-9]{2})$ ]]; then
        echo "$host -> web server number ${BASH_REMATCH[1]}"
    else
        echo "$host -> no match"
    fi
done
ip="192.0.2.10"
re='^([0-9]{1,3}\.){3}[0-9]{1,3}$'
[[ $ip =~ $re ]] && echo "unquoted \$re: match"
[[ $ip =~ "$re" ]] || echo "quoted \"\$re\": treated literally, no match"
alice@srv01:~$ ./regex.sh
web01 -> web server number 01
web12 -> web server number 12
db01 -> no match
web1x -> no match
unquoted $re: match
quoted "$re": treated literally, no match
```

(That IPv4 pattern checks the shape only; it accepts `999.1.1.1`.)

## Conditionals: if and case

```bash
if command_or_test; then
    ...
elif other_test; then
    ...
else
    ...
fi
```

Any command can be the condition: `if grep -q '^alice:' /etc/passwd; then`, `if ping -c1 -W1 web01 >/dev/null; then`. A complete example that uses arguments with defaults, a file test, command substitution, numeric comparisons and its own exit status:

```text
alice@srv01:~$ cat diskcheck.sh
#!/bin/bash
# diskcheck.sh: warn when a filesystem is above a threshold
threshold=${2:-80}
target=${1:-/}

if [ ! -d "$target" ]; then
    echo "error: $target is not a directory" >&2
    exit 2
fi

used=$(df --output=pcent "$target" | tail -n 1 | tr -dc '0-9')

if [ "$used" -ge 90 ]; then
    level=CRITICAL
elif [ "$used" -ge "$threshold" ]; then
    level=WARNING
else
    level=OK
fi
echo "$level: $target is ${used}% full"
[ "$level" = OK ]
alice@srv01:~$ ./diskcheck.sh /tmp 30; echo "exit $?"
WARNING: /tmp is 36% full
exit 1
alice@srv01:~$ ./diskcheck.sh /tmp; echo "exit $?"
OK: /tmp is 36% full
exit 0
alice@srv01:~$ ./diskcheck.sh /nope; echo "exit $?"
error: /nope is not a directory
exit 2
```

The last line, a bare test, becomes the script's exit status, so monitoring tools and `&&` chains can use it.

**`case`** compares one word against **glob patterns** (not regular expressions), top to bottom, and runs the first match only. `|` separates alternatives, each branch ends with `;;`, and `*)` is the conventional catch-all:

```text
alice@srv01:~$ cat case.sh
#!/bin/bash
for arg in start STOP restart reload x; do
case "$arg" in
    start|Start)  echo "$arg: starting" ;;
    [Ss][Tt][Oo][Pp]) echo "$arg: stopping" ;;
    re*)          echo "$arg: re-something" ;;
    *)            echo "$arg: usage: $0 {start|stop|restart}" ;;
esac
done
alice@srv01:~$ ./case.sh
start: starting
STOP: stopping
restart: re-something
reload: re-something
x: usage: ./case.sh {start|stop|restart}
```

## Loops: for, while and until

| Loop | Runs |
|---|---|
| `for x in list; do ...; done` | Once per word in the list (literal words, `"$@"`, a glob such as `*.log`, brace expansion `{1..5}`, or `$(command)`) |
| `for ((i=1; i<=3; i++)); do ...; done` | C-style arithmetic loop (bash) |
| `while test; do ...; done` | As long as the test succeeds (exit 0) |
| `until test; do ...; done` | As long as the test **fails**; stops when it succeeds. Natural for "retry until ready" |

`break` leaves the loop, `continue` skips to the next iteration.

```text
alice@srv01:~$ cat loops.sh
#!/bin/bash
for h in web01 web02 db01; do echo "for-list: $h"; done
for ((i=1; i<=3; i++)); do echo "c-style: $i"; done
n=3
while [ "$n" -gt 0 ]; do echo "while: $n"; n=$((n-1)); done
tries=0
until [ "$tries" -ge 3 ]; do tries=$((tries+1)); echo "until: attempt $tries"; done
for x in a b c d; do
  [ "$x" = b ] && continue
  [ "$x" = d ] && break
  echo "loop body: $x"
done
alice@srv01:~$ ./loops.sh
for-list: web01
for-list: web02
for-list: db01
c-style: 1
c-style: 2
c-style: 3
while: 3
while: 2
while: 1
until: attempt 1
until: attempt 2
until: attempt 3
loop body: a
loop body: c
```

Read a file line by line with `while IFS= read -r line; do ...; done < file`, not `for line in $(cat file)`, which splits on every space and globs. A typical retry loop: `until systemctl is-active --quiet nginx; do sleep 2; done`. Add a counter so it cannot loop forever.

## Key takeaways

- `[ ]` is the `test` command and needs spaces and quoted variables; `[[ ]]` is a bash keyword with no word splitting, glob patterns for `==`, and `=~`.
- `-d` directory, `-f` regular file, `-e` exists, `-n` non-empty, `-z` empty, `!` negates.
- Numbers: `-eq -ne -gt -ge -lt -le`, or `(( ))` with `<`, `<=`, `>=`, `>`. Strings: `=`, `==`, `!=`, `<`, `>` (escape them in `[ ]`), `=~` only in `[[ ]]`.
- `<=` and `>=` are not string operators in bash `[ ]` or `[[ ]]`; use `(( ))` for numbers or `! [[ a > b ]]` for strings.
- `=~` uses unquoted ERE; groups land in `BASH_REMATCH`; anchor with `^` and `$`.
- `if`/`elif`/`else`/`fi` tests exit status; `case` matches globs and ends branches with `;;`.
- `for` iterates lists, `while` runs while true, `until` runs until true; read files with `while IFS= read -r line`.
