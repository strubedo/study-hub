## Anatomy of a script

A shell script is a text file of commands. The first line, the **interpreter directive** or **shebang**, tells the kernel which program runs the file when you execute it directly:

```bash
#!/bin/bash
# backup-etc.sh: archive /etc to /backup
set -euo pipefail
tar -czf "/backup/etc-$(date +%F).tar.gz" /etc
```

| Shebang | Use |
|---|---|
| `#!/bin/bash` | Bash at a fixed path (present on every mainstream distribution) |
| `#!/usr/bin/env bash` | The first `bash` found in `PATH`; portable to systems where bash is elsewhere (BSDs, macOS with Homebrew) |
| `#!/bin/sh` | A POSIX shell. On Debian and Ubuntu `/bin/sh` is **dash**, not bash, so bash-only syntax (`[[ ]]`, arrays, `${var^^}`) fails there |
| `#!/usr/bin/env python3` | Same mechanism for Python (lesson 4.3) |

Run it with `chmod +x backup-etc.sh; ./backup-etc.sh` (the shebang is used) or `bash backup-etc.sh` (the shebang is ignored, bash runs it). A script runs in a **child** process, so variables and `cd` inside it do not affect your shell; to change the current shell, `source` the file (lesson 1.5).

All output below comes from real runs of bash 5.3.

## Variables and assignment

Assign with **no spaces** around `=`: `count=0`. `count = 0` runs a command called `count`. Names are case-sensitive; by convention, exported environment variables are upper case and script-local variables lower case.

| Kind | Examples |
|---|---|
| **Shell variable** | `dir=/srv/data`, visible only in this shell |
| **Environment variable** | `export APP_MODE=test`, copied to every child process. `VAR=value command` sets it for one command only |
| **Positional arguments** | `$0` script name, `$1`...`$9`, `${10}`, `$#` count, `"$@"` all arguments as separate words, `$*` all arguments joined |
| **Special** | `$?` last exit status, `$$` this shell's PID, `$!` PID of the last background job |

```text
alice@srv01:~$ cat env.sh
#!/bin/bash
APP_MODE=test
bash -c 'echo "child sees APP_MODE=[$APP_MODE]"'
export APP_MODE
bash -c 'echo "child sees APP_MODE=[$APP_MODE]"'
unset APP_MODE
echo "after unset: [${APP_MODE}]"
alice@srv01:~$ ./env.sh
child sees APP_MODE=[]
child sees APP_MODE=[test]
after unset: []
```

Always iterate arguments with **`"$@"`**, quoted. Here the second argument contains a space:

```text
alice@srv01:~$ ./args.sh web01 "two words"
script: ./args.sh  count: 2
first: web01  second: two words
  "$@" item: web01
  "$@" item: two words
  $* item: web01
  $* item: two
  $* item: words
after shift: two words  count: 1
```

`shift` drops `$1` and renumbers the rest. The objectives also list these builtins:

| Builtin | Purpose |
|---|---|
| `export` | Mark a variable for the environment of child processes (`export -p` lists them) |
| `local` | Declare a variable local to a **function**. Outside a function bash refuses: `local: can only be used in a function` (exit status 1) |
| `set` | Without arguments, list all variables and functions. `set -- a b c` replaces the positional arguments. Options: `-e` exit on error, `-u` treat unset variables as errors, `-x` trace each command, `-o pipefail` |
| `unset` | Remove a variable (`unset var`) or function (`unset -f name`) |
| `alias` / `unalias` | Define and remove command shortcuts. **Aliases are not expanded in non-interactive shells** (scripts) unless `shopt -s expand_aliases` is set, so use functions in scripts |

```text
alice@srv01:~$ cat alias.sh
#!/bin/bash
alias ll='ls -l'
ll passwd.sample
alice@srv01:~$ ./alias.sh
./alias.sh: line 3: ll: command not found
```

## Expansion

Before running a command line, bash **expands** it: parameters, command substitutions, arithmetic, then word splitting and globbing on the unquoted results.

| Form | Meaning |
|---|---|
| `$var`, `${var}` | Value of `var`. Braces mark where the name ends: `"${host}_backup.tar"` gives `web01_backup.tar`, but `"$host_backup.tar"` looks up a variable called `host_backup` and gives `.tar` |
| `${var:-default}` | `default` if `var` is unset or empty (`var` unchanged); `${var:=default}` also assigns it |
| `${var:?message}` | Abort with `message` if unset or empty: a guard before `rm -rf "${dir:?}"/*` |
| `${#var}` | Length |
| `${var%pattern}`, `${var%%pattern}` | Remove the shortest / longest match from the end |
| `${var#pattern}`, `${var##pattern}` | Remove the shortest / longest match from the start |
| `$(command)` | **Command substitution**: replaced by the command's output, trailing newlines removed |
| `` `command` `` | The legacy form of command substitution. Same result, but it nests badly and treats backslashes oddly; prefer `$(...)` |
| `$(( expression ))` | Integer arithmetic: `$(( n * 3 + 1 ))` |
| `(commands)` | Run commands in a **subshell**: a child copy of the shell. Variable changes and `cd` inside it are lost when it ends |
| `{ commands; }` | Group commands in the **current** shell (spaces and the final `;` are required) |

```text
alice@srv01:~$ cat exp.sh
#!/bin/bash
file="report 2026.tar.gz"
echo "${file}"
echo "${file%%.*}"
echo "${file%.gz}"
echo "${file#*.}"
echo "${#file}"
echo "${missing:-none}"
echo "today is $(date -d 2026-11-22 +%A)"
echo "kernel `uname -s`"
count=0
(count=5; echo "inside subshell: $count")
echo "after subshell: $count"
{ count=7; }
echo "after group: $count"
alice@srv01:~$ ./exp.sh
report 2026.tar.gz
report 2026
report 2026.tar
tar.gz
18
none
today is Sunday
kernel Linux
inside subshell: 5
after subshell: 0
after group: 7
```

> **Watch out:** Each part of a **pipeline** also runs in a subshell. `cat file | while read -r line; do n=$((n+1)); done` leaves `n` unchanged afterwards (it printed `n=0` for a three-line file); `while read -r line; do ...; done < file` keeps the loop in the current shell and printed `n=3`.

## Quoting and word splitting

| Quote | Effect |
|---|---|
| `"double"` | Expansions (`$var`, `$(cmd)`, `$((...))`) happen; the result stays **one word**, no globbing |
| `'single'` | Everything literal: `'$name'` prints `$name` |
| `\` | Escapes the next character: `"\$HOME"` prints `$HOME` |

The result of an **unquoted** expansion is split into words on the characters in **`IFS`** and then glob-expanded:

```text
alice@srv01:~$ name="my file.txt"; touch "$name"
alice@srv01:~$ ls -1 $name
ls: cannot access 'my': No such file or directory
ls: cannot access 'file.txt': No such file or directory
alice@srv01:~$ ls -1 "$name"
my file.txt
```

Quote every expansion unless you deliberately want splitting.

## IFS and OFS

**`IFS`** (Internal Field Separator) is the list of characters bash uses to split unquoted expansions and the input of `read`. Its default is space, tab and newline. Setting it just for one `read` is the standard way to parse delimited text:

```text
alice@srv01:~$ cat ifs.sh
#!/bin/bash
while IFS=: read -r user _ uid _ _ home shell; do
    echo "$user uid=$uid home=$home"
done < passwd.sample
list="web01,web02,db01"
IFS=, read -r -a hosts <<< "$list"
echo "hosts: ${#hosts[@]}  second: ${hosts[1]}"
alice@srv01:~$ ./ifs.sh
root uid=0 home=/root
alice uid=1001 home=/home/alice
svc_backup uid=995 home=/var/lib/backup
hosts: 3  second: web02
```

`IFS=: read` changes IFS only for that command, `-r` stops backslashes being treated as escapes, and `_` is a throwaway variable for unwanted fields.

**OFS** (Output Field Separator) is not a shell variable at all: it belongs to **awk** (lesson 1.5). `-F` (or `FS`) sets how awk splits input; `OFS` sets what it puts between fields joined by a comma in `print` (default one space):

```text
alice@srv01:~$ awk -F: 'BEGIN { OFS="," } { print $1, $3, $7 }' passwd.sample
root,0,/bin/bash
alice,1001,/bin/bash
svc_backup,995,/usr/sbin/nologin
alice@srv01:~$ awk -F: '{ print $1, $3 }' OFS=' | ' passwd.sample
root | 0
alice | 1001
svc_backup | 995
```

## Return codes

Every command returns an **exit status** from 0 to 255: **0 means success**, anything else failure. `$?` holds the status of the **most recent** command, so read it immediately or save it (`rc=$?`); even `echo` resets it.

```text
alice@srv01:~$ cat rc.sh
#!/bin/bash
grep -q '^bob:' passwd.sample
echo "grep for bob: $?"
grep -q '^alice:' passwd.sample
echo "grep for alice: $?"
ls /nonexistent 2>/dev/null
echo "first: $?"
echo "second: $?"
false | true
echo "pipeline: $?  PIPESTATUS: ${PIPESTATUS[*]}"
alice@srv01:~$ ./rc.sh
grep for bob: 1
grep for alice: 0
first: 2
second: 0
pipeline: 0  PIPESTATUS: 1 0
```

`grep` returns 1 for "no match" and 2 for errors; a pipeline returns the status of its **last** command unless `set -o pipefail` is on. End a script with `exit N` to report its own status.

`set -e` (exit when a command fails) helps, but has well-known traps:

- It does not trigger for commands tested by `if`, `while`, `until`, `&&` or `||`, which is how you handle expected failures: `grep -q x f || echo "not found"`.
- `((i++))` returns status 1 when the old value of `i` is 0, so with `set -e` the script silently exits on the first increment. Use `i=$((i+1))`.
- `local out=$(cmd)` reports the status of `local` (0), hiding a failing `cmd`. Declare first, then assign: `local out; out=$(cmd)`.
- A failing command whose status is ignored on purpose (`grep -c` that finds nothing returns 1) ends the script.

## Functions

```bash
name() {
    commands
}
```

(`function name { ... }` is the bash-only alternative.) A function is called like a command, receives its own `$1`, `$2`, `$#` and `"$@"`, and must be defined before it is called. **`return N`** sets its exit status (0-255) and leaves the function; **`exit`** would end the whole script. To hand back data, print it and capture it with `$(...)`.

```text
alice@srv01:~$ cat func.sh
#!/bin/bash
greeting="global"

say_hello() {
    local greeting="hello, $1"
    echo "$greeting"
    return 3
}

say_hello alice
echo "status: $?  greeting is still: $greeting"
local x=1
echo "local outside a function: status $?"
alice@srv01:~$ ./func.sh
hello, alice
status: 3  greeting is still: global
./func.sh: line 12: local: can only be used in a function
local outside a function: status 1
```

Without `local`, a variable assigned in a function is global and overwrites the caller's.

2. Create `passwd.sample` with three `/etc/passwd`-style lines and parse it with the `IFS=: read` loop; then print user and shell with awk and `OFS=' -> '`.

4. Save `#!/bin/sh` followed by `[[ 1 -eq 1 ]] && echo ok` and run it on Debian or Ubuntu (dash reports `[[: not found`), then change the shebang to `#!/bin/bash`.

## Key takeaways

- The shebang picks the interpreter; `/bin/sh` is dash on Debian/Ubuntu, so bash features need `#!/bin/bash` or `#!/usr/bin/env bash`.
- `var=value` with no spaces; `export` for child processes; `local` only inside functions; `unset` removes; aliases do not work in scripts by default.
- Use `${var}` to delimit names, `${var:-default}` and `${var:?msg}` for safety, and `$(cmd)` instead of backticks.
- `( )` runs a subshell whose changes are lost; pipelines also run in subshells; `{ ...; }` stays in the current shell.
- Quote expansions; unquoted ones are split on `IFS` and globbed. `IFS=: read -r` parses fields; `OFS` is awk's output separator.
- Exit status 0 is success; `$?` is overwritten by every command; `set -e` has traps (`((i++))`, `local x=$(...)`).
