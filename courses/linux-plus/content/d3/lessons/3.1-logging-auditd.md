## Two logging systems side by side

Accounting is the "what happened" part of AAA. Current distributions run two loggers at once:

- **systemd-journald** captures everything: kernel messages, early-boot output, each service's stdout and stderr, and syslog calls. It stores structured, indexed binary journals and is read with `journalctl`.
- **rsyslog** receives messages (from journald, or from the network) and writes the classic plain-text files under `/var/log`, or forwards them to a central server. RHEL and Ubuntu install it by default; Debian 12 and later no longer do (the journal is the only log), so check whether `rsyslog` is installed before you go looking for `/var/log/syslog`.

The Linux audit system (**auditd**) is a third, separate trail: kernel-generated records of security-relevant events that ordinary logging cannot see.

## journalctl

Domain 2 used `journalctl -u <unit>` for service troubleshooting. The filters combine, so learn them as building blocks:

| Option | Meaning |
|---|---|
| `-u nginx` | One unit (repeat `-u` for several) |
| `-b`, `-b -1`, `--list-boots` | This boot, the previous boot, list recorded boots |
| `-p err` (or `-p 3`) | Priority `err` and more severe (`emerg`, `alert`, `crit`); `-p warning..err` is a range |
| `--since "2026-11-22 08:00" --until "1 hour ago"` | Time window (`-S`, `-U`) |
| `-f`, `-n 50`, `-r`, `-e` | Follow, last 50 lines, newest first, jump to end |
| `-k` | Kernel messages for this boot (like `dmesg`) |
| `-g 'Failed password'` | Grep the message field |
| `_UID=1001`, `_COMM=sshd`, `_PID=812` | Match journal fields |
| `-o json-pretty`, `-o verbose`, `-x` | Show all fields; add catalog explanations |
| `--disk-usage`, `--vacuum-size=500M`, `--vacuum-time=4weeks` | Check and trim journal size |

```text
srv01# journalctl -u sshd --since today -g 'invalid user' -o short-iso
2026-11-22T07:41:12+00:00 srv01 sshd[2231]: Failed password for invalid user admin from 203.0.113.50 port 51822 ssh2
2026-11-22T07:41:15+00:00 srv01 sshd[2231]: Connection closed by invalid user admin 203.0.113.50 port 51822 [preauth]
```

Where the journal is stored is set by `Storage=` in `/etc/systemd/journald.conf` (or a drop-in in `journald.conf.d/`): `volatile` keeps it in `/run/log/journal` and loses it at reboot, `persistent` writes `/var/log/journal`, `auto` is persistent only if `/var/log/journal` exists. Older systemd releases default to `auto` and recent ones to `persistent`, so if `journalctl -b -1` says there is no previous boot, check that setting and directory. `SystemMaxUse=` caps the disk space. Members of the `systemd-journal`, `adm` and `wheel` groups can read the system journal without sudo.

## rsyslog and /var/log

`/etc/rsyslog.conf` and `/etc/rsyslog.d/*.conf` contain rules of the form **selector action**. A selector is `facility.priority`; the priority means "this level and more severe", `.=` means exactly that level, `none` excludes a facility.

```text
# /etc/rsyslog.d/50-local.conf
authpriv.*                          /var/log/secure
mail.*                              -/var/log/maillog
*.info;mail.none;authpriv.none      /var/log/messages
local3.*                            /var/log/app.log
*.*                                 @@logs.example.com:514
```

Facilities include `kern`, `user`, `mail`, `daemon`, `auth`, `authpriv`, `cron` and `local0`-`local7`; priorities from most to least severe are `emerg`, `alert`, `crit`, `err`, `warning`, `notice`, `info`, `debug`. For forwarding, a single `@` is UDP and `@@` is TCP (both default to port 514). TCP plus TLS (or RELP) is the choice when log loss matters; audit evidence that travels in clear UDP is neither reliable nor confidential. Test with `logger -p local3.warning "test message"` and check the syntax with `rsyslogd -N1`.

The files you read most often differ by family:

| Content | RHEL / Fedora | Debian / Ubuntu |
|---|---|---|
| General system log | `/var/log/messages` | `/var/log/syslog` |
| Authentication, sudo, sshd | `/var/log/secure` | `/var/log/auth.log` |
| Kernel | journal (`journalctl -k`) | `/var/log/kern.log` |
| Package manager | `/var/log/dnf.log` | `/var/log/apt/history.log`, `/var/log/dpkg.log` |
| Login records (binary) | `/var/log/wtmp`, `/var/log/btmp`, `/var/log/lastlog` | same |
| Audit trail | `/var/log/audit/audit.log` | same, when `auditd` is installed |

## logrotate

Text logs grow forever unless something rotates them. **logrotate** runs daily (a systemd timer, `logrotate.timer`, or cron) and reads `/etc/logrotate.conf`, which includes `/etc/logrotate.d/*` where packages drop their own stanzas.

```text
/var/log/app/*.log {
    weekly
    rotate 8
    compress
    delaycompress
    missingok
    notifempty
    create 0640 svc_app adm
    postrotate
        systemctl kill -s HUP app.service >/dev/null 2>&1 || true
    endscript
}
```

| Directive | Effect |
|---|---|
| `daily` / `weekly` / `monthly`, `size 100M`, `maxsize` | When to rotate (`size` replaces the time interval; `maxsize` rotates early within it) |
| `rotate 8` | Keep 8 old files, delete older ones |
| `compress`, `delaycompress` | gzip old logs; leave the most recent rotated file uncompressed for one cycle |
| `missingok`, `notifempty` | No error if the log is missing; skip empty logs |
| `create mode owner group` | Create the new empty log with these permissions |
| `copytruncate` | Copy then truncate in place, for programs that cannot reopen their log (a few lines can be lost) |
| `postrotate ... endscript` | Command to make the daemon reopen its log file |

`logrotate -d /etc/logrotate.d/app` is a dry run that changes nothing; `logrotate -f` forces a rotation now. The state file (`/var/lib/logrotate/status` on Debian, `/var/lib/logrotate/logrotate.status` on RHEL) records when each log last rotated.

> **Watch out:** If a daemon keeps writing to the renamed file after rotation (the new log stays empty while `app.log.1` grows), the `postrotate` step is missing or the program ignores HUP. Fix the reopen signal, or use `copytruncate`.

## The audit system: auditd and audit.rules

The kernel audit subsystem records events from inside the kernel: system calls, file access matching a watch, logins, SELinux denials (AVC records), changes to the audit configuration itself. Records carry the **auid** (audit, or login, UID), which stays set to the user who originally logged in even after `sudo` or `su`, so you can always trace an action back to a person.

`auditd` writes the records to **`/var/log/audit/audit.log`**; its daemon settings (log size, what to do when the disk fills) are in `/etc/audit/auditd.conf`. The rules come from **`/etc/audit/rules.d/*.rules`**, which **`augenrules`** concatenates into `/etc/audit/audit.rules` and loads at boot (`augenrules --load` applies them now). `auditctl` changes the running kernel rules directly; those changes are lost at reboot, exactly like firewalld runtime rules.

```text
# /etc/audit/rules.d/50-local.rules
-w /etc/sudoers -p wa -k priv_esc
-w /etc/sudoers.d/ -p wa -k priv_esc
-w /etc/ssh/sshd_config -p wa -k sshd_cfg
-a always,exit -F arch=b64 -S execve -F euid=0 -F auid>=1000 -F auid!=unset -k root_cmds
-e 2
```

| Rule element | Meaning |
|---|---|
| `-w path` | Watch a file or directory |
| `-p rwxa` | Trigger on read, write, execute or attribute change |
| `-k key` | Tag the records so you can search for them |
| `-a always,exit -S syscall -F field=value` | Syscall rule: log on exit from the named syscall when the fields match |
| `-e 2` | Lock the configuration until reboot (put it last) |

Querying:

```text
srv01# auditctl -l                       # rules loaded in the kernel
srv01# auditctl -s                       # status: enabled, failure mode, backlog
srv01# ausearch -k priv_esc -i           # records with that key, fields interpreted
srv01# ausearch -m USER_LOGIN -ts today --success no
srv01# aureport --auth --summary         # authentication report
srv01# aureport -x --summary             # executables
```

> **Real world:** On RHEL the `auditd` unit refuses `systemctl stop` and `systemctl restart` (`RefuseManualStop=yes`), so that the audit trail always records who stopped it. Use `service auditd restart`, or `augenrules --load` to reload just the rules.

## Lab it yourself

In a throwaway VM (auditd does not work in most containers):

1. `journalctl --list-boots`, `journalctl -b -p err`, `journalctl -u ssh -n 20` (Debian unit `ssh`, RHEL `sshd`), `journalctl --disk-usage`.
2. `logger -p local3.warning "lab test"`, then `journalctl -t "$USER" -n 1` (`logger` tags messages with your user name) and, if rsyslog is installed, `grep "lab test" /var/log/syslog` or `/var/log/messages`.
3. Write the logrotate stanza above for `/var/log/app/*.log`, create a log file, run `logrotate -d /etc/logrotate.d/app`, then `logrotate -f` and list the directory.
4. Install `audit` (RHEL) or `auditd` (Debian), add the `-w /etc/ssh/sshd_config -p wa -k sshd_cfg` rule in `/etc/audit/rules.d/`, run `augenrules --load` and `auditctl -l`, touch the file with `sudo touch`, and find the event with `ausearch -k sshd_cfg -i`. Note the `auid` field.

## Key takeaways

- journald captures everything into a binary journal (`journalctl -u`, `-b`, `-p`, `--since`, `-f`, `-k`); persistence is `Storage=` in `journald.conf` and `/var/log/journal`.
- rsyslog rules are `facility.priority action`; `@` forwards over UDP, `@@` over TCP; test with `logger`.
- RHEL: `/var/log/messages` and `/var/log/secure`. Debian/Ubuntu: `/var/log/syslog` and `/var/log/auth.log`.
- logrotate: `/etc/logrotate.conf` + `/etc/logrotate.d/`; `rotate`, `compress`, `delaycompress`, `create`, `postrotate`, `copytruncate`; `-d` dry run, `-f` force.
- auditd logs to `/var/log/audit/audit.log`; persistent rules in `/etc/audit/rules.d/*.rules` loaded by `augenrules`; `auditctl` changes are runtime only.
- `-w path -p wa -k key` watches files; `ausearch -k key -i` and `aureport` read the trail; `auid` identifies the original login user.
