## Mandatory access control

Ordinary permissions are **discretionary**: the owner of a file decides who may read it, and anything running as root bypasses them. **SELinux** adds **mandatory** access control: a kernel policy, written by the distribution, says which *process types* may do what to which *object types*, and neither owners nor root can override it at will. If an attacker takes over the web server, the process is still confined to what the policy allows the web server to do.

The kernel checks normal permissions first; SELinux is consulted only if they allow the access, and a denial by either one blocks it. SELinux denials are logged as **AVC** (access vector cache) records in `/var/log/audit/audit.log`.

SELinux is enabled and enforcing by default on RHEL, Fedora, CentOS Stream, Rocky and Alma, with the **targeted** policy (network-facing daemons are confined; ordinary users run `unconfined_t`). Ubuntu and Debian ship **AppArmor** instead, a path-based MAC system with profiles in `/etc/apparmor.d/` (`aa-status`); the objectives name only SELinux.

## Modes

| Mode | Policy loaded | Denies | Logs denials |
|---|---|---|---|
| **enforcing** | Yes | Yes | Yes |
| **permissive** | Yes | No | Yes (first occurrence of each) |
| **disabled** | No | No | No; new files get no labels |

```text
srv01$ getenforce
Enforcing
srv01# setenforce 0          # permissive until reboot (setenforce Permissive also works)
srv01# setenforce 1          # back to enforcing
srv01$ sestatus
SELinux status:                 enabled
SELinuxfs mount:                /sys/fs/selinux
SELinux root directory:         /etc/selinux
Loaded policy name:             targeted
Current mode:                   enforcing
Mode from config file:          enforcing
Policy MLS status:              enabled
Policy deny_unknown status:     allowed
Memory protection checking:     actual (secure)
Max kernel policy version:      33
```

`setenforce` switches only between enforcing and permissive, only until the next boot. The boot-time mode is `SELINUX=enforcing|permissive|disabled` in **`/etc/selinux/config`** (with `SELINUXTYPE=targeted`). Kernel arguments override it: `enforcing=0` boots permissive and `selinux=0` disables SELinux; on RHEL 9 and later Red Hat documents `grubby --update-kernel ALL --args selinux=0` as the way to disable it.

Going from disabled back to enabled is not instant: files created while SELinux was off have no labels, so the whole filesystem must be **relabelled** at the next boot (`touch /.autorelabel` or `fixfiles -F onboot`, then reboot, ideally in permissive mode first). That relabel is why "disable SELinux to fix it" is the wrong habit: use permissive mode for troubleshooting, and even then you can make only one domain permissive with `semanage permissive -a httpd_t`.

## Contexts

Every process and every file carries a **context**, `user:role:type:level`. For the targeted policy you work almost entirely with the **type** (the `_t` field).

```text
srv01$ ls -Z /var/www/html/index.html
system_u:object_r:httpd_sys_content_t:s0 /var/www/html/index.html
srv01$ ps -eZ | grep httpd
system_u:system_r:httpd_t:s0       1422 ?        00:00:00 httpd
srv01$ id -Z
unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
```

The policy says that `httpd_t` may read `httpd_sys_content_t`; it says nothing that lets `httpd_t` read `user_home_t`, so it can't. `ls -Z`, `ps -Z`, `id -Z` and `stat` show labels; `-Z` also works with `cp`, `mkdir` and `ss -Z` on SELinux systems.

### Where labels come from

The policy contains **file-context rules**: regular expressions mapping paths to types (`/var/www(/.*)?` gets `httpd_sys_content_t`, `/home/[^/]+(/.*)?` gets `user_home_t`). A newly created file normally inherits the type of its parent directory. Two operations behave differently:

- `cp` creates a **new** file, which gets the label of the destination directory.
- `mv` keeps the file's **existing** label. A page written in `~alice` and moved into `/var/www/html` stays `user_home_t`, and Apache returns 403 Forbidden although the permissions are fine.

### Fixing labels: restorecon, semanage fcontext, chcon

| Tool | What it does | Survives a relabel? |
|---|---|---|
| `restorecon -Rv /var/www/html` | Resets files to what the file-context rules say | Yes (it *is* the rules) |
| `semanage fcontext -a -t TYPE "REGEX"` | Adds a rule for a non-default path; then run `restorecon` | Yes |
| `chcon -t TYPE file` | Changes the label on disk directly | **No**: the next `restorecon` or full relabel puts the rule's label back |

```text
srv01# semanage fcontext -a -t httpd_sys_content_t "/srv/web(/.*)?"
srv01# restorecon -Rv /srv/web
Relabeled /srv/web from unconfined_u:object_r:var_t:s0 to unconfined_u:object_r:httpd_sys_content_t:s0
Relabeled /srv/web/index.html from unconfined_u:object_r:var_t:s0 to unconfined_u:object_r:httpd_sys_content_t:s0
srv01# semanage fcontext -l | grep '/srv/web'
/srv/web(/.*)?                                     all files          system_u:object_r:httpd_sys_content_t:s0
```

`semanage fcontext -a -e /var/www /srv/web` ("equivalence") is another way: label `/srv/web` exactly like `/var/www`. Use `chcon` only for a quick test (`chcon -t httpd_sys_content_t index.html`, or `chcon --reference=/var/www/html /srv/web`), then make it permanent with `semanage fcontext`.

## Ports and booleans

Ports are labelled too. Apache may bind only ports of type `http_port_t` (80, 443, 8008, 8009, 8443 and a few more), so running it on 8090 fails until you add the port. If a port already has another type (8080 and 8081, for example, already belong to other types), RHEL 9's `semanage port -a` refuses with `ValueError: Port tcp/8080 already defined` and you use `-m` to modify it; policycoreutils 3.7 and later (RHEL 10, current Fedora) print "already defined, modifying instead" and modify it for you. `-m` works on both:

```text
srv01# semanage port -l | grep '^http_port_t.*tcp'
http_port_t                    tcp      80, 81, 443, 488, 8008, 8009, 8443, 9000
srv01# semanage port -a -t http_port_t -p tcp 8090
```

**Booleans** are switches the policy author built in for common variations, so you do not have to write policy:

```text
srv01$ getsebool httpd_can_network_connect
httpd_can_network_connect --> off
srv01$ getsebool -a | grep ^httpd_can
srv01# setsebool -P httpd_can_network_connect on      # -P makes it persistent
srv01# semanage boolean -l | grep httpd_can_network_connect
httpd_can_network_connect      (on   ,   on)  Allow httpd to can network connect
```

Without `-P`, `setsebool` changes only the running value and the boolean reverts at boot. In `semanage boolean -l`, the pair is (current, persistent). Common booleans: `httpd_can_network_connect` (reverse proxy to a backend port), `httpd_can_network_connect_db`, `httpd_enable_homedirs`, `samba_enable_home_dirs`, `use_nfs_home_dirs`.

## Troubleshooting denials: ausearch, sealert, audit2allow

A denial in the audit log looks like this:

```text
srv01# ausearch -m AVC -ts recent
----
time->Sun Nov 22 10:02:11 2026
type=AVC msg=audit(1795341731.412:418): avc:  denied  { read } for  pid=1422 comm="httpd" name="index.html" dev="dm-0" ino=1311744 scontext=system_u:system_r:httpd_t:s0 tcontext=unconfined_u:object_r:user_home_t:s0 tclass=file permissive=0
```

Read it as: the process `httpd` running as **scontext** type `httpd_t` was denied `read` on a **file** whose **tcontext** type is `user_home_t`. `permissive=0` means it was actually blocked. The fix here is a label (`restorecon`), not new policy.

The tools, in the order to reach for them:

1. **`sealert`** (package `setroubleshoot-server`) explains a denial in English and suggests the specific fix (a `restorecon`, a boolean, a port label): `sealert -a /var/log/audit/audit.log`, or `sealert -l <id>` using the id in the journal line "SELinux is preventing ... For complete SELinux messages run: sealert -l ...".
2. **`audit2allow -w -a`** explains *why* each denial happened (missing boolean, missing allow rule).
3. **`audit2allow -a -M mylocal`** writes a local policy module (`mylocal.te` and `mylocal.pp`) allowing what was denied; load it with `semodule -i mylocal.pp`. Use this only for genuine policy gaps, after ruling out labels, ports and booleans, and read the `.te` file first: blindly allowing everything that was denied can grant an attacker what you were trying to block.

> **Exam tip:** Labels wrong after a `mv`: `restorecon`. New path: `semanage fcontext -a` then `restorecon`. Service on a new port: `semanage port -a`. Feature switched off: `setsebool -P`. Real policy gap: `audit2allow -M` then `semodule -i`. `chcon` is temporary; `setenforce 0` is for diagnosis only.

## Lab it yourself

On a throwaway Rocky, Alma or Fedora VM (SELinux enforcing):

1. `getenforce; sestatus; id -Z; ps -eZ | head`.
2. `dnf install httpd setroubleshoot-server`, `systemctl enable --now httpd`, open port 80. As root, `echo hi > /root/index.html; mv /root/index.html /var/www/html/`, then `curl localhost/index.html` (403). Check `ls -Z`, `ausearch -m AVC -ts recent`, `sealert -a /var/log/audit/audit.log`, fix with `restorecon -v`.
3. `chcon -t user_home_t /var/www/html/index.html`, confirm the 403 returns, then `restorecon -v` and see it reverted.
4. `mkdir /srv/web`, serve it with a `DocumentRoot` change, fix it with `semanage fcontext` + `restorecon`.
5. Change `Listen 80` to `Listen 8090`, watch `systemctl restart httpd` fail, read the AVC, add `semanage port -a -t http_port_t -p tcp 8090`.
6. `getsebool httpd_can_network_connect`; `setsebool` it without and then with `-P`, and compare `semanage boolean -l` output.

## Key takeaways

- SELinux is MAC on top of DAC; default enforcing with the targeted policy on the RHEL family (Ubuntu and Debian use AppArmor).
- Modes: enforcing, permissive (log only), disabled. `getenforce`, `setenforce 0|1` (runtime only), `/etc/selinux/config` for boot; re-enabling needs a relabel.
- Contexts are `user:role:type:level`; see them with `ls -Z`, `ps -eZ`, `id -Z`. `mv` keeps a label, `cp` takes the destination's.
- `restorecon` applies the rules; `semanage fcontext -a` + `restorecon` makes a permanent new rule; `chcon` is lost on relabel.
- `semanage port -a -t http_port_t -p tcp 8090` for new ports; `setsebool -P` for persistent booleans.
- Diagnose with `ausearch -m AVC`, `sealert -a`, `audit2allow -w`; `audit2allow -M` + `semodule -i` only for real policy gaps.
