## AAA on a Linux host

Security on a Linux server is easier to reason about if you split it the way network engineers already do:

| Piece | Question it answers | Linux mechanisms |
|---|---|---|
| **Authentication** | Who are you? | PAM modules (`pam_unix`, `pam_sss`), Kerberos tickets, SSH keys |
| **Authorization** | What may you do? | File permissions, sudo, **Polkit**, SELinux, `AllowGroups` in sshd |
| **Accounting** | What did you do? | journald, rsyslog, `/var/log`, **auditd** (next lesson) |

Identities themselves live either in the local files covered in Domain 2 (`/etc/passwd`, `/etc/shadow`) or in a directory (LDAP, Active Directory, FreeIPA) that the host reaches through SSSD or Winbind. The Name Service Switch (`/etc/nsswitch.conf`) decides which sources answer "who is UID 1001?"; PAM decides how a login is checked.

## PAM: Pluggable Authentication Modules

Every program that logs people in (`login`, `sshd`, `sudo`, `su`, `gdm`, `cron`) asks the PAM library to do the work, using a stack in **`/etc/pam.d/<service>`**. Each line is `type control module [arguments]`.

| Type | Runs when |
|---|---|
| `auth` | Proving identity: password, OTP, smart card; can also set credentials |
| `account` | Is this account allowed now? Expired, locked, wrong time of day, not in an allowed group |
| `password` | Changing the authentication token: quality checks, history, hashing |
| `session` | Setup and teardown: limits, home creation, logging, `systemd --user` |

| Control | Meaning |
|---|---|
| `required` | Must succeed; on failure the rest of the stack still runs (so the caller cannot tell which module failed), then the result is failure |
| `requisite` | Must succeed; on failure return immediately |
| `sufficient` | If it succeeds and no earlier `required` failed, stop and return success; a failure is ignored |
| `optional` | Result matters only if it is the only module of that type |
| `include` / `substack` | Pull in another file's lines of the same type (`substack` limits the effect of `done`/`die` to the included stack) |

Bracketed controls such as `[success=1 default=ignore]` are the long form: Debian's `common-auth` uses them to skip the next line on success.

```text
srv01$ grep -v '^#' /etc/pam.d/system-auth      # RHEL 9: authselect select minimal with-faillock
auth        required                                     pam_env.so
auth        required                                     pam_faildelay.so delay=2000000
auth        required                                     pam_faillock.so preauth silent
auth        sufficient                                   pam_unix.so nullok
auth        required                                     pam_faillock.so authfail
auth        required                                     pam_deny.so

account     required                                     pam_faillock.so
account     required                                     pam_unix.so

password    requisite                                    pam_pwquality.so
password    sufficient                                   pam_unix.so sha512 shadow nullok use_authtok
password    required                                     pam_deny.so

session     optional                                     pam_keyinit.so revoke
session     required                                     pam_limits.so
-session    optional                                     pam_systemd.so
session     [success=1 default=ignore]                   pam_succeed_if.so service in crond quiet use_uid
session     required                                     pam_unix.so
```

(The default `sssd` profile adds `pam_sss` lines; a leading `-` on a type means "do not log an error if the module file is missing", for optional modules that are not always installed.)

The service files include shared stacks: on RHEL `system-auth` and `password-auth` (generated by **`authselect`**: `authselect current`, `authselect select sssd with-faillock`, `authselect enable-feature with-mkhomedir`); on Debian and Ubuntu `common-auth`, `common-account`, `common-password` and `common-session` (generated by **`pam-auth-update`**). Hand edits to those generated files are overwritten, so use the tool.

Modules you will meet in this domain: `pam_unix` (local passwords), `pam_sss` (SSSD), `pam_faillock` (lockout after failures), `pam_pwquality` (complexity), `pam_pwhistory` (reuse), `pam_wheel` (restrict `su`), `pam_limits` (`/etc/security/limits.conf`), `pam_mkhomedir` (create a home at first login) and `pam_nologin` (refuse non-root logins while `/etc/nologin` exists).

> **Watch out:** A typo in a PAM stack can lock everyone out, root included. Keep a root shell open in a second session while you test a change, and test with a fresh login.

## Polkit

sudo authorizes whole commands. **Polkit** (formerly PolicyKit) authorizes individual *actions* that an unprivileged process asks a privileged system service to perform over D-Bus: `systemctl restart nginx` run as a normal user, NetworkManager changes, `reboot` through logind, mounting a USB disk through udisks. The service asks `polkitd` "may this subject do this action?", and polkitd answers yes, no, or "authenticate first".

- **Actions** are declared by the service in XML under `/usr/share/polkit-1/actions/*.policy`, with default answers for any session, inactive sessions and active local sessions.
- **Rules** are JavaScript files in `/etc/polkit-1/rules.d/` (admin changes) and `/usr/share/polkit-1/rules.d/` (packages), read in lexical order of file name. Any rule that returns a result ends the search.

```text
srv01$ pkaction --action-id org.freedesktop.systemd1.manage-units --verbose
org.freedesktop.systemd1.manage-units:
  description:       Manage system services or other units
  message:           Authentication is required to manage system services or other units.
  vendor:            The systemd Project
  vendor_url:        https://systemd.io
  icon:              
  implicit any:      auth_admin
  implicit inactive: auth_admin
  implicit active:   auth_admin_keep
```

`auth_admin` means "an administrator must authenticate"; `auth_admin_keep` remembers that for a few minutes. Who counts as an administrator comes from `addAdminRule()` in the default rules: `unix-group:wheel` on RHEL and Fedora, `unix-group:sudo` on Ubuntu and Debian. A rule that lets the `webops` group manage units without a password:

```text
srv01# cat /etc/polkit-1/rules.d/50-webops.rules
polkit.addRule(function(action, subject) {
    if (action.id == "org.freedesktop.systemd1.manage-units" &&
        subject.isInGroup("webops")) {
        return polkit.Result.YES;
    }
});
```

`pkexec <command>` runs a program as another user (root by default) after a Polkit check, much like sudo. It is setuid root, which is why the 2022 "PwnKit" bug (CVE-2021-4034) was a local root exploit on almost every distribution; if nothing needs it, removing the setuid bit or the package is a common hardening step. `pkcheck` tests an authorization from scripts and `pkttyagent` supplies a text-mode authentication agent.

## Directory services

### LDAP

LDAP is the protocol for reading and writing a hierarchical directory: entries named by a **distinguished name** such as `uid=alice,ou=People,dc=example,dc=com`, each with attributes (`uid`, `uidNumber`, `memberOf`, `mail`). Port **389** carries plain LDAP or LDAP upgraded with **StartTLS**; **636** is LDAPS (TLS from the first byte). Servers include OpenLDAP, 389 Directory Server (inside Red Hat IdM/FreeIPA) and Active Directory.

```text
srv01$ ldapsearch -x -H ldap://ldap.example.com -ZZ -b "dc=example,dc=com" "(uid=alice)" cn uidNumber
```

`-x` is a simple bind (anonymous here; add `-D <bind DN> -W` to log in), `-ZZ` insists on StartTLS, `-b` is the search base, and the filter in parentheses selects entries. Never let LDAP simple binds cross the network in clear text: the password is sent as is.

### Kerberos

Kerberos proves identity with **tickets** instead of sending passwords to every service. The **KDC** (key distribution centre, TCP and UDP **88**) authenticates the user once and issues a **ticket-granting ticket** (TGT); the client then asks the KDC for service tickets (for `host/srv01.example.com`, `HTTP/web01.example.com`, `cifs/...`) and presents those to the services. Realms are written in upper case (`EXAMPLE.COM`). The client configuration is **`/etc/krb5.conf`**; a host's own keys live in the **keytab** `/etc/krb5.keytab` (list with `klist -k`).

```text
alice@srv01:~$ kinit alice@EXAMPLE.COM
Password for alice@EXAMPLE.COM:
alice@srv01:~$ klist
Ticket cache: KCM:1001
Default principal: alice@EXAMPLE.COM

Valid starting       Expires              Service principal
11/22/2026 09:00:01  11/22/2026 19:00:01  krbtgt/EXAMPLE.COM@EXAMPLE.COM
	renew until 11/29/2026 09:00:01
alice@srv01:~$ kdestroy
```

> **Exam tip:** Kerberos rejects requests when client and KDC clocks differ by more than the allowed skew, 5 minutes by default. "Kerberos login fails, the password is right" usually means time sync (chrony) or DNS is broken.

### SSSD, realm and Winbind

**SSSD** (System Security Services Daemon) is the standard client on RHEL and Ubuntu for remote identities. One daemon serves both NSS (user and group lookups, through `sss` in `/etc/nsswitch.conf`) and PAM (through `pam_sss`), talking to LDAP, Kerberos, Active Directory or FreeIPA. It caches identities and credentials, so users can still log in to a laptop that is off the network. The config is **`/etc/sssd/sssd.conf`** plus `/etc/sssd/conf.d/*.conf`, which must be owned by root with mode **0600** or SSSD refuses to start.

```text
[sssd]
domains = example.com
services = nss, pam

[domain/example.com]
id_provider = ad
access_provider = ad
default_shell = /bin/bash
fallback_homedir = /home/%u@%d
```

You rarely write that by hand. **`realm`** (realmd) discovers a domain from DNS, joins it (creating the computer account and keytab), and writes `sssd.conf`, `krb5.conf` and the PAM/NSS settings:

```text
srv01# realm discover example.com
srv01# realm join -U Administrator example.com
srv01# realm permit -g linux-admins@example.com
srv01# realm list
srv01# id alice@example.com
```

`realm permit` and `realm deny` control which domain users may log in; `realm leave` removes the host from the domain. After changing directory data, `sss_cache -E` clears SSSD's cache.

**Winbind** (`winbindd`, part of Samba) is the other way to join Active Directory. It is the right choice when the host is also a Samba file server in the domain, because smbd and winbindd share the ID mapping. You join with `net ads join -U Administrator` (or `realm join --client-software=winbind`), add `winbind` to the `passwd:` and `group:` lines of nsswitch.conf, and check with `wbinfo -u` (domain users), `wbinfo -g` (groups) and `wbinfo -t` (trust secret).

## Samba

Samba implements SMB file and print sharing (and can even be an AD domain controller). Its daemons are **`smbd`** (file and print service, TCP **445**, plus 139 for the legacy NetBIOS session service), **`nmbd`** (NetBIOS name service, UDP 137 and 138) and `winbindd`. Configuration is **`/etc/samba/smb.conf`**:

```text
[global]
   workgroup = EXAMPLE
   security = user
   server min protocol = SMB2_02

[projects]
   path = /srv/projects
   valid users = @webdev
   read only = no
```

Check the file with **`testparm`**, give a local user a Samba password with `smbpasswd -a alice` (Samba keeps its own password database, listed by `pdbedit -L`), and test with `smbclient -L //srv01 -U alice`. On RHEL also open the `samba` firewalld service and label the share `samba_share_t` (SELinux lesson). Keep SMB1 disabled: current Samba already defaults to SMB2 as the minimum, and SMB1 is what WannaCry-style worms exploited.

## Lab it yourself

In a throwaway Debian or Ubuntu VM or container:

1. Read `/etc/pam.d/sshd` and `/etc/pam.d/common-auth`; follow each `@include`. On a Rocky or Alma VM, run `authselect current` and read `/etc/pam.d/system-auth`.
2. `pkaction | wc -l`, then `pkaction --action-id org.freedesktop.login1.reboot --verbose`.
3. `apt install samba smbclient`, add the `[projects]` share above (path `/srv/projects`, `valid users = alice`), run `testparm`, `smbpasswd -a alice`, `systemctl restart smbd`, then `smbclient //localhost/projects -U alice -c ls`.
4. `apt install krb5-user`, read `/etc/krb5.conf` and run `klist` (no ticket yet). If you have a FreeIPA or Samba AD lab, `realm discover` it and `kinit` against it.
5. `grep -E '^(passwd|group|shadow)' /etc/nsswitch.conf` and `getent passwd root`.

## Key takeaways

- PAM stacks in `/etc/pam.d/` have four types (auth, account, password, session) and controls `required`, `requisite`, `sufficient`, `optional`, `include`.
- Manage shared stacks with `authselect` (RHEL) or `pam-auth-update` (Debian/Ubuntu), not by hand.
- Polkit authorizes D-Bus actions for unprivileged users: actions in `/usr/share/polkit-1/actions`, JavaScript rules in `/etc/polkit-1/rules.d`; admins are `wheel` (RHEL) or `sudo` (Ubuntu).
- LDAP: 389 (StartTLS) and 636 (LDAPS). Kerberos: KDC on 88, TGT then service tickets, `kinit`/`klist`/`kdestroy`, keytab `/etc/krb5.keytab`, 5-minute clock skew.
- SSSD serves NSS and PAM for LDAP/AD/IdM with offline caching; `sssd.conf` must be root-owned 0600.
- `realm discover/join/permit/list/leave` joins AD or IdM; Winbind is the Samba-side alternative (`wbinfo`).
- Samba: `smbd` on TCP 445, `smb.conf`, `testparm`, `smbpasswd -a`, `smbclient`; keep SMB1 off.
