## Environment variables

Every process has an **environment**: name=value strings inherited from its parent. A plain shell variable (`x=5`) is visible only inside the current shell; **`export x`** (or `export x=5`) puts it in the environment so child processes inherit it. List the environment with `env` or `printenv`; list everything the shell knows (variables, functions) with `set`. Read a value with `$NAME` or `${NAME}`.

| Variable | Meaning |
|---|---|
| `HOME` | The user's home directory; what `~` and a bare `cd` use |
| `PATH` | Colon-separated directories searched **left to right** for commands typed without a slash |
| `PS1` | The primary prompt string, for example `\u@\h:\w\$ ` (user, host, working directory, `$` or `#`) |
| `SHELL` | The user's **login** shell, from the last field of `/etc/passwd`. It does not change when you start another shell inside the current one |
| `USER` | The login name (`whoami` and `id -un` report the *effective* user, which can differ, for example after `su` without `-` to root, which keeps `USER` unchanged; `sudo` normally resets `USER` to the target user) |
| `DISPLAY` | Which X server X11 applications draw on, such as `:0` locally or `localhost:10.0` over `ssh -X`. Wayland sessions use `WAYLAND_DISPLAY` |

```text
alice@srv01:~$ echo $HOME $USER $SHELL
/home/alice alice /bin/bash
alice@srv01:~$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
alice@srv01:~$ export PATH="$PATH:$HOME/bin"        # append a directory for this shell
alice@srv01:~$ type -a ls                           # which ls would run?
ls is /usr/bin/ls
ls is /bin/ls
```

If a command exists but "command not found" appears, the directory is not in `PATH`. Run it by path (`/opt/tool/bin/tool` or `./tool`), or fix `PATH`. Putting `.` (the current directory) in `PATH` is unsafe, because a malicious file named `ls` in the directory you are in would run instead of the real one. `which` and `type` show what will be run; `hash -r` clears bash's cache of found command locations.

## Paths

An **absolute path** starts at `/` and means the same thing from anywhere (`/etc/hosts`). A **relative path** is resolved from the current working directory (`pwd`): `conf/app.cfg`, `./run.sh`, `../logs`.

| Symbol | Meaning |
|---|---|
| `/` | Root directory (and the path separator) |
| `~` | The current user's home; `~bob` is bob's home |
| `.` | The current directory (`./script.sh` runs a script in it) |
| `..` | The parent directory |
| `-` | With `cd`, the **previous** directory (`$OLDPWD`): `cd -` jumps back and prints it |

## Shell startup files

Which file bash reads depends on how the shell was started.

| Shell type | Reads | Typical examples |
|---|---|---|
| **Login** shell | `/etc/profile`, then the first one found of `~/.bash_profile`, `~/.bash_login`, `~/.profile` | Console login, `ssh` login, `su - alice`, `bash -l` |
| **Interactive non-login** shell | `~/.bashrc` (Debian also reads `/etc/bash.bashrc`; on RHEL `~/.bashrc` itself pulls in `/etc/bashrc`) | Opening a terminal window in a desktop, typing `bash` inside a shell |
| Logout | `~/.bash_logout` | |

Because a login shell does not read `~/.bashrc` by itself, the default `~/.bash_profile` (RHEL) and `~/.profile` (Debian/Ubuntu) contain a few lines that source `~/.bashrc`. **`~/.profile`** is also what other POSIX login shells read, and bash reads it only if neither `~/.bash_profile` nor `~/.bash_login` exists. Put exported variables and PATH changes in the login file, and aliases and prompt settings in `~/.bashrc`. Changes do not affect the running shell until you read the file again with **`source ~/.bashrc`** (or `. ~/.bashrc`): `source` runs the file in the *current* shell, whereas running it as a script would change only a child process.

## Standard streams and redirection

Every process starts with three **file descriptors**: **stdin** (0), **stdout** (1) and **stderr** (2).

| Syntax | Effect |
|---|---|
| `cmd < file` | Read stdin from `file` |
| `cmd > file` | Write stdout to `file`, **truncating** it |
| `cmd >> file` | **Append** stdout to `file` |
| `cmd 2> file` | Send stderr to `file` |
| `cmd > out 2>&1` | Send stderr to wherever stdout currently points (the file) |
| `cmd &> file` | bash shorthand: stdout and stderr to the file |
| `cmd > /dev/null 2>&1` | Discard both |
| `a \| b` | Pipe: a's stdout becomes b's stdin |
| `cmd <<EOF ... EOF` | **Here document**: the lines up to `EOF` become stdin |
| `cmd <<< "text"` | **Here string**: the string (plus newline) becomes stdin |

```text
alice@srv01:~$ ls /nonexistent /etc/hostname > out.txt 2> err.txt
alice@srv01:~$ cat out.txt
/etc/hostname
alice@srv01:~$ cat err.txt
ls: cannot access '/nonexistent': No such file or directory

alice@srv01:~$ cat <<EOF > motd.txt
Welcome to $(hostname)
EOF
alice@srv01:~$ tr 'a-z' 'A-Z' <<< "web01"
WEB01
```

Two traps. **Order matters**: `cmd > file 2>&1` sends both streams to the file, but `cmd 2>&1 > file` points stderr at the terminal (where stdout *was*) and only then moves stdout to the file. And **quoting the delimiter** (`<<'EOF'`) stops variable and command expansion inside the here document, while `<<-EOF` strips leading tabs. Finally, redirection is done by *your* shell before `sudo` starts, so `sudo echo x > /etc/file` fails with "Permission denied"; use `echo x | sudo tee /etc/file` (add `-a` to append).

`tee` copies stdin to stdout **and** to a file, so you can watch output and keep a log: `make 2>&1 | tee build.log`.

## History, aliases and small utilities

- **`history`** lists previous commands (kept in memory, written to `~/.bash_history` when the shell exits; sizes come from `HISTSIZE` and `HISTFILESIZE`). `history -c` clears the session list; `history -d 42` deletes one entry.
- **`!!`** repeats the last command, and `sudo !!` reruns it with privileges. `!42` runs history entry 42, `!ssh` the last command starting with `ssh`, `!$` the last argument of the previous command. **Ctrl+r** searches history interactively. History expansion works only in interactive shells.
- **`alias ll='ls -alF'`** defines a shortcut for the session; put it in `~/.bashrc` to keep it. `alias` alone lists them and `unalias ll` removes one. `\ll` or `command ll` bypasses the alias.
- **`echo`** prints its arguments (`-n` omits the newline, `-e` interprets escapes in bash). **`printf`** is more predictable, using a format string and no automatic newline: `printf '%-10s %5.1f\n' web01 3.14159` prints `web01        3.1`.
- **`bc`** is an arbitrary-precision calculator reading expressions from stdin: `echo "scale=2; 10/3" | bc` prints `3.33`. Without `scale`, division truncates to an integer; `bc -l` loads the math library with `scale=20`.
- **`uname`** reports system information: `-s` kernel name, `-r` kernel release, `-m` machine hardware (`x86_64`), `-n` hostname, `-a` everything.

> **Exam tip:** `>` overwrites and `>>` appends. `2>&1` must come *after* the `> file`. `<<` needs a delimiter word; `<<<` takes a single string. And remember `SHELL` is the login shell, not necessarily the one you are in.

> **Watch out:** `> important.conf` on an existing file empties it immediately, before the command even runs. Many "my config is empty" incidents come from `sort file > file`, which truncates the file before `sort` reads it.

## Lab it yourself

In a terminal on the lab VM:

1. `echo $PATH | tr ':' '\n'`; create `~/bin/hello` containing `#!/bin/bash` and `echo hi`, `chmod +x ~/bin/hello`, run `hello` (fails), `export PATH="$PATH:$HOME/bin"`, run it again.
2. `cd /etc; cd /var/log; cd -; pwd`.
3. Add `alias ll='ls -alF'` to `~/.bashrc`, open a new terminal, and confirm; then `source ~/.bashrc` in an old one.
4. `ls /etc /nonexistent > a.txt 2> b.txt; cat a.txt b.txt`, then compare `ls /nonexistent > c.txt 2>&1` with `ls /nonexistent 2>&1 > d.txt` and see where the error message goes.
5. `sudo echo test > /root/x` (fails), then `echo test | sudo tee /root/x`.
6. `history | tail -5`, `!!`, `echo one two three; echo !$`.

## Key takeaways

- `export` makes a variable visible to child processes; `PATH` is searched left to right; `SHELL` is the login shell.
- Absolute paths start with `/`; `~` is home, `.` current, `..` parent, `cd -` previous directory.
- Login shells read `/etc/profile` and the first of `~/.bash_profile`, `~/.bash_login`, `~/.profile`; non-login interactive shells read `~/.bashrc`; `source` applies changes to the current shell.
- `>` truncates, `>>` appends, `2>` redirects stderr, `2>&1` merges it into stdout (order matters), `<<` is a here document, `<<<` a here string.
- `sudo cmd > file` fails because your shell does the redirect; use `| sudo tee file`.
- `!!`, `!$`, Ctrl+r, `alias`, `printf`, `bc` and `uname` are small tools the exam expects you to recognise by sight.
