## Backup principles first

A backup is only real if you have **restored** from it. Know three ideas before the tools:

- **Full, incremental, differential.** A full backup copies everything. An incremental copies what changed since the *last backup of any kind* (smallest, slowest to restore: full plus every increment). A differential copies what changed since the last *full* (restore is full plus the latest differential).
- **3-2-1 rule.** Three copies, on two kinds of media, one off-site. RAID and snapshots are not backups.
- **Consistency.** Files that are being written (databases, VMs) need a quiesced or snapshot copy: an LVM snapshot, a database dump, or stopping the service.

## Archiving with tar

`tar` bundles many files into one archive. Combine an *operation* with options:

| Option | Meaning |
|---|---|
| `-c` / `-x` / `-t` | Create / extract / list (table of contents) |
| `-f archive` | The archive file (`-f -` means stdin/stdout) |
| `-v` | Verbose |
| `-z` / `-j` / `-J` | Filter through gzip / bzip2 / xz |
| `-a` | Choose compression from the archive suffix (`.tar.xz`, `.tgz`, ...) |
| `-C dir` | Change to `dir` first (where to extract) |
| `-p` | Preserve permissions (default when running as root) |
| `--exclude=PATTERN` | Skip matching files |
| `--xattrs --acls --selinux` | Keep extended attributes, ACLs and SELinux labels (needed for faithful system backups) |
| `-g file` / `--listed-incremental=file` | GNU incremental backups tracked in a snapshot file |
| `--strip-components=N` | Drop N leading path elements while extracting |

```text
srv01# tar -czvf /backup/etc-2026-11-22.tar.gz /etc
srv01# tar -tzvf /backup/etc-2026-11-22.tar.gz | head -3
srv01# tar -xzvf /backup/etc-2026-11-22.tar.gz -C /restore etc/ssh/sshd_config
srv01# tar -caf /backup/home.tar.xz --exclude='*/.cache' /home
```

GNU tar strips the leading `/` from member names ("Removing leading `/' from member names") so extraction does not overwrite absolute paths by accident; name the file you want without the slash, as in `etc/ssh/sshd_config`. Keep the order straight: `-f` takes the **next** word, so `tar -cfz x.tgz` makes an archive called `z`.

## cpio

`cpio` reads a **list of file names on stdin** and writes an archive to stdout. It is the format inside initramfs images (`newc`) and RPM payloads, so it still matters.

```text
srv01# cd / && find etc -depth | cpio -ov > /backup/etc.cpio   # copy-out (create) with relative names
srv01# cpio -it < /backup/etc.cpio | head                      # list
srv01# cd /restore && cpio -idv < /backup/etc.cpio             # copy-in (extract) under /restore; -d creates directories
srv01# find . | cpio -pdm /mnt/newdisk                     # pass-through: copy a tree
srv01# find /etc | cpio -o -H newc | gzip > etc.cpio.gz    # newc format, as used by initramfs
```

The three modes are `-o` (copy-out), `-i` (copy-in) and `-p` (pass-through). Unlike `tar`, `cpio` does not walk directories itself: you feed it `find` output. It also does **not** strip a leading `/`: an archive built from `find /etc` extracts back over the real `/etc` unless you add `--no-absolute-filenames`, which is why the example feeds it relative names.

## Compression tools

| Tool | Suffix | Speed | Ratio | Notes |
|---|---|---|---|---|
| `gzip` / `gunzip` | `.gz` | Fast | Good | Universal. `-k` keep original, `-d` decompress, `-1`..`-9` level (default 6), `-l` list |
| `bzip2` / `bunzip2` | `.bz2` | Slower | Better | `-k`, `-d` |
| `xz` / `unxz` | `.xz` | Slowest | Best | `-T0` uses all cores; high memory use. `-k`, `-d`, `-9e` |
| 7-Zip (`7z`, `7za` or `7zz`) | `.7z` | Slow | Very good | `7z a archive.7z dir`, `7z x archive.7z`, `7z l archive.7z`. Does not reliably store Unix owners and permissions, so do not use it for system backups |
| `zip` / `unzip` | `.zip` | Fast | Fair | Cross-platform, handles several files in one archive. `unzip -l a.zip` lists, `unzip a.zip -d dir` extracts |

`gzip`, `bzip2` and `xz` compress a **single stream** and by default replace the original file; combine them with `tar` for directories. The 7-Zip command name depends on the package: `p7zip` and the current Debian 13 / Ubuntu `7zip` package provide `7z`/`7za`/`7zr`, while Debian 12's `7zip` package and the upstream binary use `7zz`.

To read compressed files without extracting them, use the `z` family:

| Command | Does |
|---|---|
| `zcat file.gz` | Print a gzip file's decompressed content (`gzip -dc`) |
| `zgrep pattern file.gz` | `grep` inside a gzip file |
| `zless file.gz` | Page through a gzip file |

`bzcat`/`bzgrep`/`bzless` and `xzcat`/`xzgrep`/`xzless` do the same for `.bz2` and `.xz`. The classic use is searching rotated logs: `zgrep 'Failed password' /var/log/auth.log*.gz` (RPM-family logs are `/var/log/secure*`).

## dd and ddrescue

`dd` copies raw bytes between files and devices. It has no `-` options; arguments are `key=value`:

| Argument | Meaning |
|---|---|
| `if=` / `of=` | Input / output file or device |
| `bs=4M` | Block size (bigger is faster for disks) |
| `count=` / `skip=` / `seek=` | Blocks to copy / skip in the input / skip in the output |
| `status=progress` | Show progress |
| `conv=fsync` | Flush data to disk before finishing (`conv=noerror,sync` keeps going past read errors) |

```text
srv01# dd if=/dev/vdb of=/backup/vdb.img bs=4M status=progress conv=fsync   # image a disk
srv01# dd if=/dev/vda of=/backup/mbr.bak bs=512 count=1                     # save the MBR + partition table
srv01# dd if=/dev/vda bs=4M | gzip > /backup/vda.img.gz                     # compressed image
srv01# gunzip -c /backup/vda.img.gz | dd of=/dev/vda bs=4M status=progress  # restore
```

`dd` does exactly what you type: swapping `if` and `of` overwrites the source with the empty target. Image **unmounted** (or snapshot) filesystems, because copying a live one yields an inconsistent image.

**`ddrescue`** (GNU ddrescue; package `gddrescue` on Debian/Ubuntu, `ddrescue` on RPM systems) is for **failing disks**. `dd` stops or pads on read errors; `ddrescue` first copies the easy areas, records the bad ones in a **mapfile**, then retries, and it can be stopped and resumed.

```text
srv01# ddrescue -f -n /dev/sdb /dev/sdc rescue.map          # pass 1: skip scraping, grab good areas
srv01# ddrescue -f -d -r3 /dev/sdb /dev/sdc rescue.map      # pass 2: direct access, retry bad sectors 3 times
```

Write to a **separate** target and never mount or `fsck` the failing source before copying. Then repair the copy.

## rsync

`rsync` copies only the differences, locally or over SSH, and is the standard tool for file-level backup and sync.

```text
srv01# rsync -avh --delete /srv/data/ backup01:/backups/data/
srv01# rsync -avhn --delete /srv/data/ /mnt/usb/data/        # -n = dry run: show what would happen
srv01# rsync -aAXH --exclude={'/dev/*','/proc/*','/sys/*','/run/*','/tmp/*','/mnt/*','/media/*'} / /mnt/newroot/
```

`-a` is `-rlptgoD`: recursive, symlinks, permissions, times, group, owner, devices. It does **not** include ACLs (`-A`), extended attributes (`-X`, which carry SELinux labels) or hard links (`-H`), so add those for system copies. The system copy excludes the virtual filesystems and `/mnt` itself; without `/mnt/*` rsync would copy the target into itself. `-z` compresses in transit, `-e ssh` picks the transport, `--delete` removes files from the destination that no longer exist in the source (dangerous with the wrong paths; dry-run first), and `--link-dest=` makes space-efficient incremental snapshots with hard links.

The **trailing slash** on the source matters: `rsync -a /srv/data /backup/` creates `/backup/data/`, while `rsync -a /srv/data/ /backup/` copies the *contents* of `data` straight into `/backup/`.

> **Exam tip:** `tar -czf` = gzip, `-cjf` = bzip2, `-cJf` = xz. Compression ratio: xz > bzip2 > gzip; speed is the reverse. For a mirror of a directory that only transfers changes: rsync. For a bit-for-bit disk image: dd. For a dying disk: ddrescue.

> **Watch out:** `rsync --delete` with a missing trailing slash, or `dd of=/dev/sda`, can erase the wrong data in seconds. Check source and target, and use `rsync -n` first.

## Lab it yourself

In a terminal on the lab VM:

1. `mkdir -p ~/lab/src/sub && cd ~/lab && echo a > src/a.txt && echo b > src/sub/b.txt`.
2. `tar -czvf src.tgz src`, `tar -tzvf src.tgz`, `mkdir out && tar -xzvf src.tgz -C out`, then `diff -r src out/src`.
3. `find src | cpio -ov > src.cpio` then `cpio -it < src.cpio`.
4. Compress copies with `gzip -k`, `bzip2 -k` and `xz -k` and compare `ls -l` sizes; read with `zcat`.
5. `rsync -avn src/ dest/`, then without `-n`; run again and note that nothing transfers; then run `rsync -avn src dest/` and see the extra `src/` level.
6. `dd if=/dev/zero of=img.raw bs=1M count=16 status=progress`, then `sha256sum img.raw`.

## Key takeaways

- `tar -c/-x/-t` with `-f`; `-z` gzip, `-j` bzip2, `-J` xz; add `--xattrs --acls --selinux` for faithful system backups.
- `cpio` needs a file list on stdin: `-o` create, `-i` extract, `-p` pass-through; initramfs images are `newc` cpio archives.
- Compression: gzip fastest, xz smallest, bzip2 between; 7-Zip and zip do not preserve Unix ownership reliably.
- `zcat`, `zgrep`, `zless` read gzip files without extracting.
- `dd` uses `if=`/`of=`/`bs=`; one wrong argument destroys data. `ddrescue` with a mapfile is for failing disks.
- `rsync -a` is `-rlptgoD`; add `-A -X -H` for ACLs, xattrs and hard links; source trailing slash means "contents of".
- Test restores, and use snapshots for consistency; RAID is not a backup.
