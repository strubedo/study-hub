## The Filesystem Hierarchy Standard

Linux has one directory tree rooted at `/`. The **Filesystem Hierarchy Standard (FHS)** says what belongs where, so that scripts and administrators on different distributions find things in the same places.

| Directory | Purpose | Notes |
|---|---|---|
| `/` | Root of the tree | Not the same as `/root`, the home of the root user |
| `/bin` | Essential user commands (`ls`, `cp`, `bash`) | On modern distributions a symlink to `/usr/bin` ("merged /usr") |
| `/sbin` | Essential system administration commands (`fdisk`, `ip`, `reboot`) | Symlink to `/usr/sbin` on merged-/usr systems |
| `/boot` | Kernel, initramfs, GRUB files | Often its own small partition; `/boot/efi` is the ESP on UEFI |
| `/dev` | Device files (`/dev/sda`, `/dev/null`, `/dev/tty`) | Populated dynamically by the kernel and udev (`devtmpfs`) |
| `/etc` | Host-specific configuration, text files | Back this up |
| `/home` | User home directories | Often its own filesystem |
| `/lib`, `/lib64` | Shared libraries and kernel modules (`/lib/modules/<ver>/`) | Symlink to `/usr/lib` on merged-/usr systems |
| `/proc` | Virtual filesystem exposing processes and kernel state (`/proc/cpuinfo`, `/proc/<PID>/`) | Not on disk |
| `/sys` | Virtual filesystem exposing devices and drivers (sysfs) | Not on disk |
| `/run` | Runtime data since boot (PID files, sockets) | A tmpfs, emptied at every boot |
| `/tmp` | Temporary files, world-writable with the sticky bit (mode 1777) | Cleaned at boot or by age; a tmpfs on many distributions |
| `/usr` | Shareable, mostly read-only programs, libraries and docs | `/usr/local` is for locally installed software |
| `/var` | Variable data: logs (`/var/log`), spool, caches, databases, `/var/tmp` | Grows over time; its own filesystem on servers |
| `/opt` | Self-contained add-on software packages | Vendor software lives here |
| `/srv` | Data served by this host (web, FTP) | |
| `/mnt`, `/media` | Manual and automatic (removable media) mount points | |

> **Exam tip:** `/proc`, `/sys` and `/run` use no disk space. `/tmp` is cleared at reboot (or aged out), while `/var/tmp` is meant to **survive** reboots. A "disk full" problem is almost always `/var` (logs) or `/tmp`, not `/proc`.

## Server architectures

The CPU architecture decides which binaries and packages you can run.

| Architecture | `uname -m` | Debian/Ubuntu name | RPM name | Typical use |
|---|---|---|---|---|
| x86 (32-bit, IA-32) | `i686` | `i386` | `i686` | Legacy; most distributions have dropped it |
| x86_64 / AMD64 | `x86_64` | `amd64` | `x86_64` | Almost all servers and desktops |
| AArch64 (ARM 64-bit, ARMv8+) | `aarch64` | `arm64` | `aarch64` | Cloud instances (AWS Graviton and similar), SBCs, Apple-silicon VMs |
| RISC-V (64-bit) | `riscv64` | `riscv64` | `riscv64` | Emerging; open instruction set, appears in boards and some servers |

x86_64 and AMD64 are the same architecture: AMD designed the 64-bit extension and Intel adopted it; the name differs only by vendor convention (Debian and Ubuntu say `amd64`, RPM says `x86_64`). An architecture mismatch is a classic failure: an `exec format error` means you are running a binary built for another CPU. Check with `uname -m`, `lscpu` (the *Architecture* line), `dpkg --print-architecture` (Debian family) or `rpm --eval '%{_arch}'` (RPM family). Newer enterprise releases also set a microarchitecture baseline: RHEL 10 requires x86-64-v3 CPUs.

## Distributions: RPM-based and dpkg-based

A distribution is a kernel plus a package system, defaults and a release policy. The two families the exam cares about differ mainly in packaging:

| | RPM-based | dpkg-based |
|---|---|---|
| Examples | RHEL, Rocky Linux, AlmaLinux, CentOS Stream, Fedora, SUSE/openSUSE | Debian, Ubuntu, Linux Mint |
| Package file | `.rpm` | `.deb` |
| Low-level tool | `rpm` | `dpkg` |
| High-level tool | `dnf` (older: `yum`); SUSE uses `zypper` | `apt` (older: `apt-get`) |
| Release file | `/etc/redhat-release` (and `/etc/os-release` everywhere) | `/etc/debian_version` (and `/etc/os-release`) |
| Admin group | `wheel` | `sudo` |
| Default firewall front end | `firewalld` | `ufw` (Ubuntu) |
| Mandatory access control | SELinux | AppArmor (Ubuntu, Debian) |
| Network config | NetworkManager (`nmcli`) | Netplan on Ubuntu; ifupdown or NetworkManager on Debian |
| Default filesystem | xfs (RHEL), btrfs (Fedora Workstation, openSUSE) | ext4 |

`/etc/os-release` is the portable way to identify a system; scripts read `ID=` and `ID_LIKE=` from it (`ID_LIKE="rhel fedora"` or `ID_LIKE=debian`).

## The GUI stack

A Linux graphical session is built from separate parts, and the exam likes the distinctions.

- **Display server**: the process that owns the screen and input devices. **X Server** (X11, usually X.Org) is the traditional one: a network-transparent client/server protocol where applications are *X clients*. **Wayland** is the modern replacement: a protocol in which a **compositor** (such as Mutter in GNOME or KWin in KDE) is the display server, and applications render themselves and hand buffers to it. Wayland removes much of X's legacy design and isolates applications from each other's input. **Xwayland** runs unmodified X11 applications inside a Wayland session.
- **Window manager (WM)**: draws window frames and handles moving, resizing and stacking. Under X it is a separate program (i3, Openbox, Xfwm). Under Wayland the compositor *is* the window manager.
- **Display manager (DM)**: the graphical login screen: it authenticates the user and starts the session. Examples: GDM (GNOME), SDDM (KDE), LightDM. It is started by systemd (`display-manager.service`) when the default target is `graphical.target`.
- **Desktop environment**: a WM or compositor plus panel, settings and apps (GNOME, KDE Plasma, Xfce).

The `DISPLAY` variable (for example `:0`, or `localhost:10.0` over `ssh -X`) tells an X client which X server to draw on. Check the session type with `echo $XDG_SESSION_TYPE` (prints `x11` or `wayland`). A server normally boots to `multi-user.target` (text); `systemctl set-default graphical.target` changes that.

## Software licensing

| Term | Meaning |
|---|---|
| **Open source** | Source code is available and the licence allows use, modification and redistribution (the Open Source Definition). Focus: development model and access to source |
| **Free software** | The FSF's term: users have four freedoms (run, study and change, redistribute, distribute modified copies). "Free as in freedom", not price |
| **Proprietary** | The vendor keeps the source and restricts copying, modification and redistribution (Microsoft Windows, many drivers and firmware blobs) |
| **Copyleft** | A licence that requires derivative works, when distributed, to carry the same licence. GPL is the main example; the Linux kernel is GPL-2.0 |
| **Permissive** | Allows reuse, including in proprietary products, with few conditions (MIT, BSD, Apache 2.0) |

Two details are tested often. First, copyleft obligations are triggered by **distribution** of a modified work, not by private use. Second, the licences differ in strength: **GPL** is strong copyleft, **LGPL** allows linking from non-copyleft programs, and **AGPL** extends the source-offer duty to users who interact with the software over a network. "Freeware" (no cost, closed source) is not free software.

## Lab it yourself

In the lab VM. `uname -m` prints `x86_64` on an Intel or AMD VM and `aarch64` on an ARM64 VM (for example on an Apple silicon Mac); either is a correct result.

1. Run `cat /etc/os-release`, then `uname -m` and `lscpu | head -5`.
2. Run `ls -ld /bin /sbin /lib` and note whether they are symlinks into `/usr`.
3. Run `df -h /proc /sys /run /tmp` and see which use no real disk.
4. Run `echo $XDG_SESSION_TYPE $DISPLAY $WAYLAND_DISPLAY` in a desktop terminal, and `systemctl get-default`.
5. Run `dpkg -S /bin/ls` (Debian 12, Ubuntu 24.04; on Debian 13 and newer Ubuntu releases packages ship the file as `/usr/bin/ls`, so query that path) or `rpm -qf /bin/ls` (RPM family) to see which package owns a file.

## Key takeaways

- `/etc` is configuration, `/var` is changing data (logs), `/usr` is programs, `/boot` is kernel files, `/dev` devices, `/proc` and `/sys` are virtual, `/run` is runtime state, `/tmp` is temporary.
- x86_64 and AMD64 are the same CPU architecture; AArch64 is `arm64` in Debian naming; RISC-V is `riscv64`. `uname -m` reports it.
- RPM family: rpm, dnf, firewalld, SELinux, `wheel`. dpkg family: dpkg, apt, ufw, AppArmor, `sudo` group.
- X Server and Wayland are display servers; a window manager manages windows; a display manager is the graphical login. In Wayland the compositor is both display server and window manager.
- Open source stresses access to source, free software stresses user freedoms, and copyleft forces derivatives to keep the licence when distributed.
