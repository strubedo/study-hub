## The pipeline mindset

Linux administration leans on small tools that each do one thing with **text streams**, chained by pipes. The examples below use this sample file, `access.log`, with the fields *client method path status*:

```text
192.0.2.10 GET /index.html 200
198.51.100.7 GET /login 401
192.0.2.10 GET /about 200
203.0.113.5 POST /login 401
192.0.2.10 GET /index.html 304
198.51.100.7 GET /login 401
```

## Viewing and slicing

| Tool | Use |
|---|---|
| `cat file` | Print a file (`-n` number lines, `-A` show tabs and line ends). Also joins files: `cat a b > c` |
| `less file` | Pager for large files. `/text` search forward, `n`/`N` next/previous match, `g`/`G` top/bottom, `F` follow like `tail -f`, `q` quit. `-S` stops line wrapping |
| `more file` | The older, simpler pager (space for next page, `q` quits); `less` can scroll backwards, `more` mostly cannot |
| `head -n 5 file` | First five lines (default 10); `head -c 100` first 100 bytes |
| `tail -n 5 file` | Last five lines; `tail -n +2 file` starts **from** line 2; `tail -f file` follows growth; `tail -F` follows across log rotation |
| `wc -l file` | Count lines (`-w` words, `-c` bytes, `-m` characters) |
| `cut -d' ' -f1,3 file` | Select **fields** split by a single-character delimiter (`-d`), or characters with `-c` |
| `sort` | Sort lines. `-n` numeric, `-r` reverse, `-k3` by field 3, `-t:` field separator, `-u` unique, `-h` human sizes (`10K`, `2G`) |
| `uniq` | Collapse **adjacent** duplicate lines, so `sort` first. `-c` count, `-d` only duplicates, `-u` only singletons |
| `tr` | Translate or delete characters from **stdin only**: `tr 'a-z' 'A-Z'`, `tr -d '\r'`, `tr -s ' '` squeeze repeats |
| `tee` | Copy stdin to stdout and to files (`-a` append) |

The classic frequency count is `sort | uniq -c | sort -rn`:

```text
srv01$ awk '{print $1}' access.log | sort | uniq -c | sort -rn
      3 192.0.2.10
      2 198.51.100.7
      1 203.0.113.5
```

Here `awk` prints the first field, `sort` groups equal lines together so `uniq -c` can count them, and the final `sort -rn` orders by count, largest first. Skipping the first `sort` gives wrong counts, because `uniq` only sees adjacent duplicates.

## grep

`grep PATTERN file` prints matching lines. Its exit status is 0 if something matched, 1 if nothing did and 2 on error, which makes it useful in scripts (`if grep -q root /etc/passwd; then`).

| Option | Meaning |
|---|---|
| `-i` | Ignore case |
| `-v` | Invert: lines that do **not** match |
| `-n` | Show line numbers |
| `-c` | Count matching lines |
| `-r` | Recurse through directories |
| `-l` | List only file names that match |
| `-w` | Match whole words |
| `-o` | Print only the matching part |
| `-E` | Extended regular expressions (`\|` alternation, `+`, `?`, `()` without backslashes) |
| `-F` | Fixed strings: no regex interpretation |
| `-A 2` / `-B 2` / `-C 2` | Lines of context after / before / around |

```text
srv01$ grep -c ' 401$' access.log
3
srv01$ grep -v 200 access.log | wc -l
4
srv01$ grep -E '^(192|203)\.' access.log | wc -l
4
```

Without `-E`, plain `grep` uses *basic* regular expressions, where `+`, `?`, `|` and parentheses need a backslash.

## sed

`sed` is a **stream editor**: it reads lines, applies commands, and prints the result. Without `-i` it never changes the input file.

```text
srv01$ sed -n '/login/p' access.log | cut -d' ' -f1,3 | sort -u
198.51.100.7 /login
203.0.113.5 /login
srv01$ sed 's/^[0-9.]* //' access.log | head -2
GET /index.html 200
GET /login 401
srv01$ sed -n '2,3p' access.log          # print only lines 2 and 3
srv01$ sed '/POST/d' access.log          # delete matching lines
srv01$ sed -i.bak 's/401/403/' access.log   # edit in place, keep access.log.bak
```

`s/old/new/` replaces the **first** match per line; add `g` for every match (`s/old/new/g`). `-n` turns off automatic printing so that `p` prints only the selected lines. `-E` enables extended regexes. Any character can be the delimiter, which avoids escaping slashes: `sed 's|/var/www|/srv/www|' file`.

## awk

`awk` processes each line as fields (`$1`, `$2`, ..., `$NF` the last, `$0` the whole line; `NF` the number of fields, `NR` the line number). The structure is `pattern { action }`, with optional `BEGIN` and `END` blocks. The default field separator is whitespace; `-F:` sets another.

```text
srv01$ awk '$4 == 401 {n++} END {print n " failures"}' access.log
3 failures
srv01$ awk 'NR==2 {print $NF, NF}' access.log
401 4
srv01$ awk -F: '$3 >= 1000 {print $1, $NF}' /etc/passwd
alice /bin/bash
bob /bin/zsh
```

The last command lists regular accounts: field 3 of `/etc/passwd` is the UID and the last field is the shell (output shown for a file containing alice and bob).

## xargs

`xargs` turns lines on stdin into **arguments** for a command. Commands such as `rm` and `ls` do not read file names from stdin, so `xargs` bridges the gap.

```text
srv01$ printf 'one\ntwo\n' | xargs -I{} echo file-{}.txt
file-one.txt
file-two.txt
srv01$ find /var/tmp -name '*.tmp' -print0 | xargs -0 -r rm -v
```

`-I{}` substitutes each input item into the command, `-n 1` passes one argument per invocation, `-P 4` runs four in parallel, `-r` (GNU) skips the command when the input is empty, and the pair `-print0` / `-0` uses NUL separators so file names containing spaces or newlines are safe.

## Text editors: vi/vim and nano

`vi` (almost always `vim` or `vim-tiny` today) is on every server, so you must be able to use it. It is **modal**:

| Mode | How to enter | Purpose |
|---|---|---|
| Normal | `Esc` | Navigation and editing commands (the mode you start in) |
| Insert | `i` (before cursor), `a` (after), `o` (new line below), `O` (above), `A` (end of line) | Typing text |
| Command-line | `:` | Save, quit, search/replace |
| Visual | `v` (characters), `V` (lines) | Select text |

| Keys (Normal mode) | Action |
|---|---|
| `h j k l` or arrows | Move |
| `gg` / `G` / `0` / `$` | First line / last line / line start / line end |
| `x`, `dd`, `yy`, `p`, `P` | Delete character, delete (cut) line, yank (copy) line, paste after/before |
| `u`, `Ctrl+r` | Undo, redo |
| `/word` then `n` / `N` | Search forward, next, previous |
| `:w` | Write (save) |
| `:q` | Quit (refuses if there are unsaved changes) |
| `:wq` or `ZZ` | Save and quit |
| `:q!` | Quit and **discard** changes |
| `:%s/old/new/g` | Replace across the whole file |
| `:set number` | Show line numbers |

**nano** is modeless: the shortcuts are shown at the bottom, where `^` means Ctrl. `Ctrl+O` writes the file out, `Ctrl+X` exits, `Ctrl+W` searches, `Ctrl+K` cuts a line, `Ctrl+U` pastes it, and `Ctrl+G` shows help. The `EDITOR` and `VISUAL` variables choose the editor used by `visudo`, `crontab -e` and `git commit`; on Debian-family systems `select-editor` sets your per-user choice and `update-alternatives --config editor` sets the system default.

> **Exam tip:** In vi, "I typed text and nothing happens" means you are not in insert mode; "I can't quit" means press `Esc` first, then `:q!`. `uniq` needs sorted input. `sed` and `awk` print to stdout and do not modify the file unless you use `sed -i`.

> **Watch out:** `sed -i` rewrites the file in place with no undo. Use `-i.bak` to keep a copy while you are learning, and test the expression without `-i` first.

## Lab it yourself

In a terminal on the lab VM:

1. Create the sample `access.log` with a here document (`cat > access.log <<'EOF'`).
2. Reproduce the three outputs above: the frequency count, `grep -c`, and the `awk` failure count.
3. List the three most common sources of authentication failures with `grep ' 401$' access.log | cut -d' ' -f1 | sort | uniq -c | sort -rn | head -3`.
4. Run `sed 's/401/403/' access.log | tail -3`, then confirm `access.log` is unchanged. Repeat with `-i.bak`.
5. `printf 'a b\nc d\n' | xargs -n1 echo` and compare with `xargs` (without `-n1`).
6. Run `vimtutor` for ten minutes, and edit a file with `nano` using only the keyboard shortcuts.

## Key takeaways

- `sort | uniq -c | sort -rn` counts occurrences; `uniq` only removes **adjacent** duplicates.
- `cut` takes a single-character delimiter; `awk` handles multiple spaces and conditions; `tr` works on characters and reads only stdin.
- `grep -E` for extended regex, `-v` to invert, `-c` to count, `-r` to recurse; exit status 0/1/2 drives scripts.
- `sed 's/old/new/g'` substitutes, `-n ... p` selects lines, `-i` edits in place (`-i.bak` keeps a backup).
- `xargs` converts stdin lines to arguments; pair `find -print0` with `xargs -0` for safe file names.
- vi has Normal, Insert, Command-line and Visual modes: `i` to type, `Esc` to stop, `:wq` to save and quit, `:q!` to abandon. nano: `Ctrl+O` write out, `Ctrl+X` exit.
