## Kernel modules

The Linux kernel is modular: drivers and filesystems can be compiled into the kernel image (**built-in**) or built as **loadable modules**, files ending in `.ko` (often compressed as `.ko.xz` or `.ko.zst`) under `/lib/modules/$(uname -r)/`. Modules are loaded on demand when udev detects hardware, or manually by an administrator.

| Command | What it does |
|---|---|
| `lsmod` | Lists loaded modules, their size and "Used by" count. It is a formatted view of `/proc/modules` |
| `modinfo <module>` | Shows a module's file, description, licence, dependencies (`depends:`) and parameters (`parm:`) without loading it |
| `modprobe <module>` | Loads a module **and its dependencies**, using the database built by `depmod` |
| `modprobe -r <module>` | Unloads a module (and unused dependencies) |
| `modprobe -n -v <module>` | Dry run, verbose: show what would be loaded |
| `modprobe --show-depends <module>` | Print the dependency chain (`insmod` lines) |
| `insmod <path>.ko` | Loads **one module file by path**, with **no** dependency resolution |
| `rmmod <module>` | Unloads one module by name; fails if it is in use ("Used by" is not 0) |
| `depmod -a` | Rebuilds `modules.dep` and related map files in `/lib/modules/<version>/` |

`insmod` and `rmmod` are the low-level primitives. `modprobe` is what you should use: it reads `modules.dep` (produced by `depmod`), loads dependencies first, applies options from `/etc/modprobe.d/`, and honours blacklists. Run `depmod -a` after installing a third-party `.ko` file by hand so that `modprobe` can find it.

```text
$ lsmod | head -4
Module                  Size  Used by
nf_tables             360448  0
ext4                 1048576  1
vfat                   24576  1

$ modinfo e1000e | grep -E '^(filename|description|license|depends)'
filename:       /lib/modules/6.8.0-45-generic/kernel/drivers/net/ethernet/intel/e1000e/e1000e.ko.zst
license:        GPL v2
description:    Intel(R) PRO/1000 Network Driver
depends:
```

A module that is built into the kernel shows `filename: (builtin)` in `modinfo` and never appears in `lsmod`. A module listed with `Used by` greater than zero cannot be unloaded until its users (other modules or open devices) are gone.

### Persisting module settings

- `/etc/modprobe.d/*.conf`: per-module settings. `options e1000e InterruptThrottleRate=3000` sets a parameter; `blacklist nouveau` stops the module being loaded automatically **by alias** (udev), but it can still be loaded by name or as a dependency; `install nouveau /bin/false` makes every `modprobe nouveau` (by name, alias or dependency) run `/bin/false` instead, so modprobe can never load it (a manual `insmod` of the file still bypasses this).
- `/etc/modules-load.d/*.conf` (and `/etc/modules` on older Debian): modules to load at every boot, one name per line.
- The kernel command line: `modprobe.blacklist=nouveau`, or `module.param=value`.
- After changing blacklists that matter in early boot, rebuild the initramfs (below), because the initramfs carries its own copy of the module configuration.

> **Exam tip:** `lsmod` = list, `modinfo` = describe, `modprobe` = load/unload with dependencies, `insmod`/`rmmod` = no dependency handling, `depmod` = build the dependency database.

## Device management tools

| Tool | Reports | Notes |
|---|---|---|
| `dmesg` | Kernel ring buffer: boot messages, driver and hardware events | `-T` human-readable time (can drift after suspend), `-H` human format, `-l err,warn` filter by level, `-w` follow. Needs root when `kernel.dmesg_restrict=1` (the Ubuntu default) |
| `dmidecode` | SMBIOS/DMI tables: system model, serial number, BIOS version, memory slots | Root. `dmidecode -t memory`, `dmidecode -s system-serial-number` |
| `ipmitool` | Talks to the **BMC** (iLO, iDRAC, IPMI): sensors, power, event log | `ipmitool sdr` / `sensor`, `chassis power status`, `sel list`, `lan print`. Remotely: `ipmitool -I lanplus -H bmc01.example.com -U admin -P ... chassis power status` |
| `lm_sensors` | Temperatures, fan speeds and voltages read from on-board chips | Package name; the command is `sensors`. Run `sensors-detect` once (as root) to find chips |
| `lscpu` | CPU model, architecture, cores, threads, caches, virtualization flags | From `/proc/cpuinfo` and sysfs |
| `lsmem` | Memory ranges and blocks, online/offline state | Useful with memory hot-plug |
| `lshw` | Full hardware tree | `lshw -short`, `lshw -class network`; root for complete detail |
| `lspci` | PCI devices (NICs, storage controllers, GPUs) | `-k` shows the kernel driver in use and candidate modules; `-nn` adds numeric IDs |
| `lsusb` | USB devices | `-t` tree view, `-v` verbose |

```text
$ lspci -k | grep -A3 Ethernet
02:00.0 Ethernet controller: Intel Corporation 82574L Gigabit Network Connection
	Subsystem: Intel Corporation Gigabit CT Desktop Adapter
	Kernel driver in use: e1000e
	Kernel modules: e1000e
```

`Kernel driver in use:` is the first thing to check when a device does not work: if the line is missing, no driver is bound. Use `modinfo` to find the module, `modprobe` to load it, and `dmesg` to read the driver's errors. `lspci -nn` gives the `vendor:device` ID (such as `8086:10d3`), which you can search in `modinfo` alias lines.

```text
$ sudo ipmitool chassis power status
Chassis Power is on
$ sensors
coretemp-isa-0000
Adapter: ISA adapter
Package id 0:  +41.0°C  (high = +80.0°C, crit = +100.0°C)
```

## initrd management: dracut and mkinitrd

When you add a storage driver, change the root filesystem to LVM, RAID or LUKS, or move a VM from an emulated to a VirtIO disk, the initramfs must be rebuilt so it contains the right modules and configuration.

| | RPM family (RHEL, Fedora, SUSE) | dpkg family (Debian, Ubuntu) |
|---|---|---|
| Tool | **`dracut`** | **`update-initramfs`** (initramfs-tools) |
| Rebuild the default image | `dracut --force` (or `-f`): the **running** kernel | `update-initramfs -u`: the **newest installed** kernel, not necessarily the running one |
| Rebuild for a specific kernel | `dracut -f /boot/initramfs-6.12.0-55.el10.x86_64.img 6.12.0-55.el10.x86_64` | `update-initramfs -u -k 6.8.0-45-generic` |
| Rebuild for all kernels | `dracut --regenerate-all --force` | `update-initramfs -u -k all` |
| Add a driver | `dracut -f --add-drivers "virtio_blk virtio_scsi"` | add the name to `/etc/initramfs-tools/modules`, then `update-initramfs -u` |
| List contents | `lsinitrd` | `lsinitramfs /boot/initrd.img-<ver>` |
| Configuration | `/etc/dracut.conf`, `/etc/dracut.conf.d/*.conf` | `/etc/initramfs-tools/initramfs.conf` |

**`mkinitrd` is the legacy tool.** It built the older initrd images on early RHEL and on SUSE; dracut replaced it, and on a current distribution it is either absent or a thin compatibility wrapper. The objectives still name it, so recognise it as "the deprecated predecessor of dracut", but use `dracut` in practice. Note that dracut does not overwrite an existing image unless you pass `--force`.

> **Watch out:** After a kernel update, the package scripts rebuild the initramfs for you. You rebuild by hand only after *you* change something the early boot needs: drivers, `/etc/crypttab`, `/etc/mdadm.conf`, LVM layout or kernel module options.

## Custom hardware: embedded and GPU

**Embedded systems** (routers, kiosks, industrial controllers, single-board computers) run Linux on constrained hardware, usually AArch64, ARM or RISC-V. They often boot from flash storage with a **device tree** describing the hardware (because there is no PCI/ACPI enumeration), use compact userlands such as **BusyBox**, and are built with tools like Yocto or Buildroot rather than installed from a generic ISO. Expect limited RAM, read-only root filesystems and no `lspci`-style discovery.

**GPU use cases** on servers are compute rather than display: machine-learning training and inference, video transcoding, scientific computing and rendering, using NVIDIA (CUDA) or AMD (ROCm) stacks. The GPU needs a kernel driver and a userspace library; NVIDIA offers a proprietary driver and an open kernel module, and with Secure Boot enabled the kernel modules must be signed. Check the card with `lspci | grep -Ei 'vga|3d'` and `lspci -k`. Monitor load with the vendor tool (`nvidia-smi`) or **`nvtop`**, a `top`-like, interactive viewer that shows GPU utilisation, memory use and per-process GPU consumption for NVIDIA, AMD and Intel GPUs.

## Lab it yourself

In the lab VM (a full VM, not WSL 2, whose kernel is supplied by Windows). On an ARM64 VM, `dmidecode` shows data only if the firmware provides SMBIOS tables (UEFI VMs normally do); if it finds none, skip that command.

1. `lsmod | head`, then `modinfo loop` (or `modinfo dummy` on a system with it as a module). Note `filename`, `depends` and `parm`.
2. `sudo modprobe dummy` (or `sudo modprobe -n -v dummy` for a dry run), then `lsmod | grep dummy`, `ip link show dummy0` and `sudo modprobe -r dummy`.
3. `lspci -k | head -20` and find the driver bound to your NIC; `lscpu | grep -E 'Architecture|Virtualization'`.
4. `sudo dmidecode -t system | head` and `lsmem`.
5. Create `/etc/modprobe.d/lab.conf` containing `blacklist dummy`, read `man modprobe.d`, then delete the file.
6. `sudo dracut --force` (RPM family) or `sudo update-initramfs -u` (Debian family) and compare the image timestamp in `/boot`.

## Key takeaways

- `modprobe` resolves dependencies (via `depmod`'s database); `insmod` and `rmmod` do not.
- `lsmod` lists, `modinfo` describes; built-in drivers show `(builtin)` and never appear in `lsmod`.
- Persist with `/etc/modprobe.d/*.conf` (options, `blacklist`, `install`) and `/etc/modules-load.d/*.conf` (load at boot).
- `dmesg` for kernel messages, `dmidecode` for SMBIOS, `ipmitool` for the BMC, `sensors` (lm_sensors) for temperatures and fans, `lspci -k` for the bound driver.
- Rebuild the initramfs with `dracut -f` (RPM family) or `update-initramfs -u` (dpkg family); `mkinitrd` is deprecated.
- Embedded boards use device trees and compact userlands; GPU servers need the right driver, and `nvtop` shows GPU load.
