## Name resolution files

Three files decide how a Linux host turns a name into an address.

**`/etc/hosts`** is the static table. Each line is an address, the canonical name, then aliases:

```text
127.0.0.1       localhost
192.168.10.20   srv01.example.com   srv01
192.168.10.30   web01.example.com   web01
```

**`/etc/nsswitch.conf`** is the Name Service Switch: it sets the *order of sources* per database. The line that matters for hostnames:

```text
hosts:   files dns
```

`files` means `/etc/hosts` and `dns` means the resolvers in `/etc/resolv.conf`. Distributions add modules: Ubuntu typically has `files mdns4_minimal [NOTFOUND=return] dns`, and RHEL-family systems with systemd-resolved or `myhostname` add those. `[NOTFOUND=return]` means "if this source answers authoritatively that the name does not exist, stop".

**`/etc/resolv.conf`** tells the DNS client library which servers to ask:

```text
search example.com
nameserver 192.168.10.2
nameserver 192.168.10.3
options timeout:2 attempts:2
```

`nameserver` lines are tried in order (the glibc resolver uses at most three); `search` appends domains to short names; `options` tunes `timeout`, `attempts`, `ndots` and `rotate`. On most modern systems this file is **generated**: NetworkManager writes it, or it is a symlink to systemd-resolved's stub (`nameserver 127.0.0.53`, see `resolvectl status`). Edits to a generated file are lost, so change the connection's DNS settings instead.

> **Exam tip:** `ping`, `ssh`, `curl` and `getent hosts` go through the resolver library and **respect `nsswitch.conf`**, so they see `/etc/hosts` entries. `dig` and `nslookup` talk **directly to DNS** and ignore `/etc/hosts`. If `ping web01` works but `dig web01` returns nothing, the name is only in `/etc/hosts`.

## NetworkManager: nmcli

On RHEL-family systems (and Ubuntu Desktop) NetworkManager owns the network. **Devices** are the interfaces; **connections** are saved profiles that can be applied to devices. `nmcli` is the command-line client; `nmtui` is the text menu; `nm-connection-editor` is the GUI.

```text
srv01$ nmcli device status
DEVICE  TYPE      STATE      CONNECTION
ens192  ethernet  connected  lan0

srv01# nmcli connection add type ethernet ifname ens192 con-name lan0 \
         ipv4.method manual ipv4.addresses 192.168.10.20/24 \
         ipv4.gateway 192.168.10.1 ipv4.dns "192.168.10.2 192.168.10.3" \
         ipv4.dns-search example.com
srv01# nmcli connection modify lan0 +ipv4.dns 192.0.2.53     # add one DNS server
srv01# nmcli connection up lan0                              # apply
srv01# nmcli connection show lan0 | grep ipv4
srv01# nmcli device show ens192
```

Key points: `modify` edits the saved profile but does **not** change the running interface until you `nmcli connection up <name>` (or `nmcli device reapply <dev>`). `+ipv4.dns` appends to a list and `-ipv4.dns` removes from it, while plain `ipv4.dns` replaces it. `ipv4.method` is `auto` (DHCP), `manual` (static) or `disabled`. `nmcli general hostname web01` reads/sets the hostname through NetworkManager. Profiles are stored as keyfiles in `/etc/NetworkManager/system-connections/*.nmconnection` (RHEL 9 and later; RHEL 8 still defaulted to `ifcfg` files in `/etc/sysconfig/network-scripts/`).

> **Real world:** The objectives list a tool called "nmconnect". No NetworkManager package ships a command with that name (Debian's package-contents search for trixie finds none). The closest real commands are `nmtui-connect` (the same as `nmtui connect`, the text menu's "Activate a connection" screen, shipped alongside `nmtui-edit` and `nmtui-hostname`) and `nmcli connection up/down`; `nm-connection-editor` is the GUI. Treat "nmconnect" as meaning these.

## Netplan

**Netplan** is Ubuntu's YAML front end: you write declarative files and it generates configuration for a **renderer**, either `systemd-networkd` (server default) or NetworkManager (desktop default). Files live in `/etc/netplan/*.yaml` (also `/lib/netplan` and `/run/netplan`) and are merged in lexical filename order, so a later file overrides an earlier one. Indentation is spaces only, and files should be mode 600 (newer Netplan warns about looser permissions).

```yaml
# /etc/netplan/01-lan.yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens192:
      dhcp4: false
      addresses:
        - 192.168.10.20/24
      routes:
        - to: default
          via: 192.168.10.1
      nameservers:
        search: [example.com]
        addresses: [192.168.10.2, 192.168.10.3]
```

| Command | Effect |
|---|---|
| `netplan generate` | Validate and write backend configuration, without applying it |
| `netplan apply` | Generate and apply to the running system immediately |
| `netplan try` | Apply, then **roll back automatically** after a timeout (default **120 seconds**, `--timeout N`) unless you press Enter to accept |
| `netplan status` | Show interface state, addresses, routes and DNS as the backend sees them |
| `netplan get` / `set` | Read or change a key without editing the file by hand |

> **Watch out:** On a remote session use `netplan try`, not `netplan apply`. A wrong gateway applied with `apply` kills your SSH session and leaves the box unreachable; with `try`, the old configuration returns on its own. The old key `gateway4:` is deprecated in favour of a `routes:` entry with `to: default`.

Debian itself defaults to `ifupdown` (`/etc/network/interfaces`) or NetworkManager rather than Netplan.

## The diagnostic toolbox

Match the tool to the layer:

| Tool | Typical use |
|---|---|
| `ip address`, `ip link`, `ip route` | Show and (non-persistently) change addresses, link state and routes: `ip -br a`, `ip link set ens192 up`, `ip route add 198.51.100.0/24 via 192.168.10.1`, `ip route get 203.0.113.9` |
| `ss` | Sockets. `ss -tulnp` = TCP+UDP, listening, numeric, with process. Replaces `netstat` |
| `ping`, `ping6` | ICMP echo. `ping -c 4 host`; `ping -6 host` (same as `ping6`); path-MTU test: `ping -M do -s 1472 host` (1472 + 28 header bytes = 1500) |
| `traceroute`, `tracepath` | Hop-by-hop path. `traceroute` sends UDP by default (`-I` ICMP, `-T` TCP, `-n` no DNS); `tracepath` needs no root and reports **PMTU** |
| `mtr` | Continuous traceroute + ping. `mtr -rwn -c 10 host` prints a report |
| `dig`, `nslookup` | DNS queries. `dig +short web01.example.com`, `dig @192.168.10.2 example.com MX`, `dig -x 192.0.2.10`, `dig +trace`. `nslookup` is the older, interactive tool |
| `curl` | HTTP(S) and more. `curl -I url` headers only, `-v` verbose, `-o file`, `-L` follow redirects, `-k` skip cert check, `--resolve name:443:192.0.2.10` fake DNS |
| `nc` (netcat) | Raw TCP/UDP: port test `nc -zv host 443`, listen `nc -l 9000`. RHEL ships `ncat`; Debian ships the OpenBSD variant; basic flags match |
| `nmap` | Port and host scanner: `nmap -sn 192.168.10.0/24`, `nmap -p 22,80 -sV host`. Scan only what you are authorised to scan |
| `tcpdump` | Packet capture: `tcpdump -nn -i ens192 'tcp port 443 and host 192.0.2.10'`, `-w file.pcap`, `-r file.pcap`, `-c 20`, `-e` link-layer headers |
| `ethtool` | NIC detail: `ethtool ens192` (speed, duplex, auto-negotiation, **Link detected**), `-i` driver, `-S` counters |
| `iperf3` | Throughput test: `iperf3 -s` on one host, `iperf3 -c srv01 -t 10 -P 4` on the other (TCP 5201); `-u` for UDP, `-R` reverse direction |
| `hostname` | `hostname -f` FQDN, `hostname -I` all addresses; make a change persistent with `hostnamectl set-hostname` |
| `arp` | Legacy (net-tools) ARP table viewer. Modern: `ip neigh` |

```text
srv01# ss -tulnp
Netid State  Recv-Q Send-Q Local Address:Port Peer Address:Port Process
udp   UNCONN 0      0      127.0.0.53%lo:53        0.0.0.0:*    users:(("systemd-resolve",pid=612,fd=13))
tcp   LISTEN 0      128          0.0.0.0:22        0.0.0.0:*    users:(("sshd",pid=801,fd=3))
tcp   LISTEN 0      511          0.0.0.0:80        0.0.0.0:*    users:(("nginx",pid=1210,fd=6))
tcp   LISTEN 0      128             [::]:22           [::]:*    users:(("sshd",pid=801,fd=4))

srv01$ mtr -rwn -c 5 198.51.100.7
Start: 2026-11-22T10:00:00+0000
HOST: srv01                    Loss%   Snt   Last   Avg  Best  Wrst StDev
  1.|-- 192.168.10.1             0.0%     5    0.4   0.5   0.4   0.6   0.1
  2.|-- 203.0.113.1              0.0%     5    3.1   3.3   3.0   3.9   0.3
  3.|-- 198.51.100.7             0.0%     5    8.2   8.4   8.1   9.0   0.3

srv01$ ethtool ens192 | grep -E 'Speed|Duplex|Auto-neg|Link detected'
	Speed: 1000Mb/s
	Duplex: Full
	Auto-negotiation: on
	Link detected: yes
```

A listening socket on `0.0.0.0:80` accepts connections on every IPv4 address; `127.0.0.1:80` accepts only local ones; `[::]:22` is the IPv6 wildcard. A systematic order for "cannot reach a service": link (`ip link`, `ethtool`), address and route (`ip a`, `ip route get`), reachability (`ping`), name (`getent hosts`, `dig`), service listening (`ss -tulnp` on the server), then the path (`nc -zv`, `curl -v`, `tcpdump`).

> **Exam tip:** DNS-only tools (`dig`, `nslookup`, `host`) ignore `/etc/hosts`. Tools that go through `nsswitch.conf` (`ping`, `curl`, `getent`) honour it. `ip` changes are lost at reboot; use nmcli or Netplan to persist.

## Lab it yourself

In the lab VM. Steps 3 and 5 need a second virtual NIC or a second VM: add the NIC in the VM's settings in your hypervisor (Hyper-V, VirtualBox, UTM or virt-manager) while the VM is shut down.

1. Compare `getent hosts localhost` and `dig +short localhost`. Add `192.0.2.77 labhost` to `/etc/hosts` and compare `getent hosts labhost` with `dig +short labhost`.
2. `cat /etc/nsswitch.conf | grep ^hosts` and `ls -l /etc/resolv.conf`.
3. RPM family: `nmcli device status`, then add a second profile with a static address on a spare VM NIC, `nmcli connection up` it, check `ip -br a`. Debian/Ubuntu: write a Netplan file for a spare NIC and run `sudo netplan try`; let it expire once without pressing Enter.
4. Start `nc -l 9000` in one terminal and `echo hello | nc 127.0.0.1 9000` in another; capture it with `sudo tcpdump -nn -i lo port 9000`.
5. Between two VMs run `iperf3 -s` and `iperf3 -c <ip>`; run `ping -M do -s 1472 <ip>` then `-s 1473`.

## Key takeaways

- Lookup order comes from `nsswitch.conf` (`files dns`); `/etc/hosts` is the static source; `/etc/resolv.conf` lists DNS servers and is usually generated.
- `dig` and `nslookup` skip `/etc/hosts`; `ping`, `curl` and `getent hosts` do not.
- nmcli: `connection add/modify/up`, `device status`; `modify` does not apply until `up`. Profiles live in `/etc/NetworkManager/system-connections/`.
- Netplan: YAML in `/etc/netplan/`; `generate`, `apply`, `status`, and `try` (120 s auto-rollback) for remote changes.
- `ss -tulnp` lists listeners, `ip route get` shows the route a packet would take, `tracepath` needs no root, `mtr` combines ping and traceroute, `iperf3` measures throughput.
- `ip` changes are runtime-only; persist through NetworkManager, Netplan or ifupdown.
