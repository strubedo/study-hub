## Mounting filesystems

A filesystem is only usable once it is **mounted** at a directory (the mount point). `mount <device> <dir>` attaches it and `umount <dir>` detaches it (the command is `umount`, with no "n"). `umount` fails with "target is busy" while a process has a file open or its working directory there; `lsof +f -- /mnt/x` or `fuser -vm /mnt/x` finds the culprit.

```text
srv01# mount /dev/vg_data/lv_web /var/www
srv01# mount -o remount,ro /var/www        # change options on a mounted filesystem
srv01# umount /var/www
srv01$ findmnt /var/www
TARGET   SOURCE                       FSTYPE OPTIONS
/var/www /dev/mapper/vg_data-lv_web   xfs    rw,nosuid,nodev,noatime,attr2,inode64,logbufs=8,logbsize=32k,noquota
```

### Where mount information lives

| Path | Meaning |
|---|---|
| `/etc/fstab` | **Static** configuration: what to mount at boot, edited by the administrator |
| `/proc/mounts` | **Live** kernel view of what is mounted right now (the authoritative one) |
| `/etc/mtab` | Historical copy of the mount list; on modern systems a symlink to `/proc/self/mounts` |

`mount` with no arguments, `findmnt` and `/proc/mounts` all show the live state. Editing `/etc/fstab` does not mount anything by itself; `mount -a` mounts everything in it that is not yet mounted (a good test for typos *before* a reboot), and `findmnt --verify` checks the syntax. On systemd systems also run `systemctl daemon-reload` after editing, because systemd generates mount units from `fstab`.

### /etc/fstab fields

```text
# device                                    mountpoint  type  options                 dump pass
UUID=5b0a1c2e-7d4f-4a6b-9e10-2f3a4b5c6d7e   /var/www    xfs   defaults,noatime,nodev  0    0
/dev/mapper/vg_data-lv_db                   /var/lib/db ext4  defaults,nosuid,nofail  0    2
tmpfs                                       /tmp        tmpfs defaults,noexec,nosuid,size=2g 0 0
nfs01.example.com:/export/data              /mnt/data   nfs   defaults,_netdev,nofail 0    0
```

The six fields are: device (path, `UUID=`, `LABEL=`, or `host:/export`), mount point, filesystem type, options, **dump** (backup flag, almost always 0), and **fsck pass** (1 for the root filesystem, 2 for others checked after it, 0 for never). If the device of an entry is missing or fails to mount at boot, systemd drops the system to emergency mode; `nofail` marks the entry as optional so the boot continues.

### Mount options

| Option | Effect |
|---|---|
| `defaults` | Shorthand for `rw,suid,dev,exec,auto,nouser,async` |
| `rw` / `ro` | Read-write / read-only |
| `noatime` | Do not update access times on reads; reduces writes. It **implies** `nodiratime` |
| `nodiratime` | Do not update access times on directories only |
| `nodev` | Ignore device files on this filesystem |
| `noexec` | Forbid executing binaries from it (a hardening option; scripts can still be run via the interpreter) |
| `nosuid` | Ignore setuid/setgid bits |
| `nofail` | Do not report an error or stop the boot if the device is missing |
| `remount` | Change options of an already-mounted filesystem, e.g. `mount -o remount,rw /` |
| `_netdev` | Marks a network filesystem so it is mounted after the network is up |

The default access-time behaviour is `relatime` (update atime only if it is older than mtime/ctime, or more than a day old). Typical hardening puts `nodev,nosuid,noexec` on `/tmp`, `/var/tmp` and `/dev/shm`.

> **Exam tip:** `remount` is how you flip a live filesystem between `ro` and `rw` without unmounting it. A filesystem that suddenly turns read-only usually remounted itself `ro` after an I/O error (check `dmesg`).

## autofs

`autofs` mounts a share on first access and unmounts it after an idle period, which avoids boot-time failures when a server is down. Install the `autofs` package and enable the service (`systemctl enable --now autofs`).

```text
# /etc/auto.master   (or a file in /etc/auto.master.d/*.autofs)
/mnt/nfs   /etc/auto.nfs   --timeout=60

# /etc/auto.nfs      key   options              location
share                -rw,soft              nfs01.example.com:/export/share
```

Now `ls /mnt/nfs/share` triggers the mount. The master map lists the parent directory and the map file; each line in the map file gives the key (subdirectory), options and source.

## Network mounts: NFS and SMB

**NFS** (Network File System) is the Unix standard. Client packages are `nfs-utils` (RPM) or `nfs-common` (Debian). NFSv4 needs only TCP 2049.

```text
srv01# showmount -e nfs01.example.com
Export list for nfs01.example.com:
/export/data 192.0.2.0/24
srv01# mount -t nfs -o vers=4.2 nfs01.example.com:/export/data /mnt/data
```

On the server, `/etc/exports` lists the exports and `exportfs -ra` re-reads it. **SMB/CIFS** is the Windows protocol, served on Linux by **Samba**; the client uses `cifs-utils`:

```text
srv01# mount -t cifs //files01.example.com/share /mnt/share -o credentials=/root/.smbcred,vers=3.0
# /root/.smbcred, mode 600:
username=alice
password=...
domain=EXAMPLE
```

Never put a password in `/etc/fstab` itself, which is world-readable; use a `credentials=` file readable only by root. `smbclient -L //files01.example.com` lists shares.

## Software RAID with mdadm

Linux software RAID is the `md` driver, managed by **`mdadm`** (the package is usually installed on demand). Common levels:

| Level | Disks (min) | Capacity | Tolerates |
|---|---|---|---|
| RAID 0 (stripe) | 2 | All | No failures (faster, no redundancy) |
| RAID 1 (mirror) | 2 | One disk | Failure of all but one disk |
| RAID 5 (striping + parity) | 3 | N − 1 disks | One disk |
| RAID 6 (double parity) | 4 | N − 2 disks | Two disks |
| RAID 10 (striped mirrors) | 4 (classic layout) | Half | One disk per mirror pair |

**RAID is availability, not backup:** it will faithfully mirror a deleted file.

```text
srv01# mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/vdb1 /dev/vdc1
srv01# mkfs.xfs /dev/md0
srv01# mdadm --detail --scan >> /etc/mdadm.conf        # Debian: /etc/mdadm/mdadm.conf
srv01# mdadm --manage /dev/md0 --fail /dev/vdb1 --remove /dev/vdb1
srv01# mdadm --manage /dev/md0 --add /dev/vdd1
srv01# mdadm --detail /dev/md0
```

`/proc/mdstat` is the quick health check. In `[2/2] [UU]` the first number is the members the array wants and the second is how many are working; `U` is up and `_` is a missing member.

```text
srv01$ cat /proc/mdstat
Personalities : [raid1]
md0 : active raid1 vdc1[1] vdb1[0](F)
      10476544 blocks super 1.2 [2/1] [_U]

unused devices: <none>
```

Here `vdb1` is marked `(F)` failed and the array is **degraded**. After you add a replacement, the same file shows a `recovery = ...%` progress line. Save the array in `mdadm.conf` and rebuild the initramfs so it assembles at boot.

## Utilities for space, speed and repair

| Utility | Use |
|---|---|
| `df -h` | Free space per **mounted filesystem**. `-T` adds type, `-i` shows inodes |
| `du -sh <dir>` | Space used **by a directory tree**. `du -h --max-depth=1 /var`, `-x` stays on one filesystem |
| `fsck` | Front end to `fsck.ext4`/`e2fsck` etc.; run on an **unmounted** (or read-only) filesystem. `-n` check only, `-y` auto-yes, `-f` force. To force a check of the root filesystem at boot on systemd systems use the kernel parameter `fsck.mode=force` |
| `xfs_repair <device>` | xfs repair; **unmounted only**; `-n` dry run. (`fsck.xfs` does nothing, because xfs replays its journal at mount time) |
| `resize2fs <device> [size]` | Grow or shrink ext2/3/4 (shrink offline, after `e2fsck -f`) |
| `xfs_growfs <mountpoint>` | Grow a **mounted** xfs filesystem to fill its device |
| `mkfs.<type>` | Create a filesystem |
| `fio` | Storage benchmark: `fio --name=rr --rw=randread --bs=4k --size=1G --iodepth=32 --ioengine=libaio --direct=1 --runtime=30 --time_based` |

`df` and `du` can disagree. A deleted file that a process still holds open consumes space `du` cannot see; `lsof +L1` finds it, and restarting the process frees it. **fio write tests aimed at a raw device destroy its data**: test against a file on a mounted filesystem.

## Inodes

Every file and directory is described by an **inode**, a record holding the owner, mode, timestamps, size and block pointers (not the file name; names live in directory entries, which is why hard links can share an inode). A filesystem has a **fixed or dynamic number of inodes**. On ext4 the count is set at `mkfs` time (`mkfs.ext4 -N` or `-i bytes-per-inode`); xfs allocates inodes dynamically, so it rarely runs out.

When a filesystem has blocks free but "No space left on device" appears on file creation, suspect **inode exhaustion**, typically millions of tiny files (session files, mail queues, cache):

```text
srv01$ df -h /var
Filesystem                  Size  Used Avail Use% Mounted on
/dev/mapper/vg_data-lv_var  9.8G  1.2G  8.1G  13% /var
srv01$ df -i /var
Filesystem                  Inodes  IUsed IFree IUse% Mounted on
/dev/mapper/vg_data-lv_var  655360 655360     0  100% /var
```

`ls -i` shows a file's inode number and `stat <file>` shows its inode details. To find the guilty directory: `for d in /var/*; do echo "$(find "$d" -xdev | wc -l) $d"; done | sort -n | tail`. The fix is to delete the files. Growing an ext4 filesystem adds inodes only in proportion to the new space (each new block group brings its own inode table); to get a much higher inode count you must recreate the filesystem with a lower bytes-per-inode ratio.

## Lab it yourself

In the lab VM (a full VM, not WSL 2), as root:

1. Create a 1 GiB loop-backed file system: `truncate -s 1G /root/t.img; mkfs.ext4 -F -N 2000 /root/t.img; mkdir /mnt/t; mount -o loop /root/t.img /mnt/t`.
2. `df -i /mnt/t`, then `cd /mnt/t; for i in $(seq 1 2500); do touch f$i; done` and watch it fail with "No space left on device" while `df -h` shows free space.
3. `mount -o remount,ro /mnt/t`, try `touch x`, then `remount,rw`.
4. `findmnt /mnt/t`, `grep /mnt/t /proc/mounts`; `umount /mnt/t`.
5. Add `/root/t.img /mnt/t ext4 loop,nofail 0 0` to `/etc/fstab`, run `mount -a` and `findmnt --verify`, then remove the line.
6. With two more loop files, build `mdadm --create /dev/md0 --level=1 ...`, fail and re-add a member while watching `cat /proc/mdstat`.

## Key takeaways

- `/etc/fstab` is configuration; `/proc/mounts` (and `/etc/mtab`, a symlink to it) is live state. Test with `mount -a`.
- Use UUIDs in fstab; the six fields end with dump (0) and fsck pass (1 root, 2 others).
- `noatime` implies `nodiratime`; `nofail` keeps boot going; `remount` changes live options; `nodev,nosuid,noexec` harden data filesystems.
- autofs mounts on demand using `/etc/auto.master` and map files; NFS uses `nfs-utils`/`nfs-common`, SMB uses `cifs-utils` with a root-only credentials file.
- `/proc/mdstat` `[UU]` is healthy and `[_U]` is degraded; `mdadm --manage --fail/--remove/--add` replaces a disk. RAID is not backup.
- `df` is per filesystem, `du` per directory; `df -i` shows inodes; "no space" with free blocks means inode exhaustion.
- `xfs_growfs` takes a mount point, `resize2fs` a device, `xfs_repair` and `fsck` need the filesystem unmounted.
