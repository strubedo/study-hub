## Components

* **GlobalProtect portal**: the management point and first contact. Authenticates the user (or device), delivers the **agent configuration** (which gateways, connect method, app settings) and the root CA certificates the agent should trust. Network > GlobalProtect > Portals.
* **GlobalProtect gateway**: terminates the VPN tunnel (or acts as an internal gateway for User-ID and HIP only). Network > GlobalProtect > Gateways.
* **GlobalProtect app**: runs on the endpoint; connects to the portal over HTTPS (TCP 443), then to a gateway.
* Optional **Mobile Security Manager**, **clientless VPN**, and **satellite** (large-site firewall acting as GP client).

Portal and gateway can be the same firewall (a common small deployment) or separate. They need a **Layer 3 interface** (or loopback), a **server certificate** in an **SSL/TLS service profile**, and a **security policy** from the VPN zone to the internal zones.

## Tunnel transport

The agent prefers an **IPSec** (ESP, with UDP 4501 encapsulation) tunnel and falls back to an **SSL/TLS** tunnel over TCP 443 if UDP is blocked. IPSec needs less overhead. Disabling IPSec on the gateway forces SSL. A gateway uses a **tunnel interface** (`tunnel.N`, in the `vpn` zone with User-ID enabled), and clients receive addresses from the gateway's **client IP pool**.

## Gateway configuration

| Tab | Purpose |
|-----|---------|
| General | Interface, IP, SSL/TLS service profile |
| Authentication | SSL/TLS profile, client authentication entries (OS, authentication profile, certificate profile) |
| Agent > Tunnel Settings | Enable tunnel mode, tunnel interface, IPSec enabled, max users |
| Agent > Timeout Settings | Login lifetime (a single gateway login session), inactivity logout (default 180 minutes = 3 hours; a user is logged out if no traffic crosses the tunnel and no HIP check arrives in that time) |
| Agent > Client Settings | Config selection criteria (users/groups/OS), **IP pools**, **split tunnel** (next lesson) |
| Agent > Client Settings > Network Services | DNS, WINS, DNS suffix, inherit from an interface (DHCP) |
| Agent > HIP Notification | Messages shown on HIP match |
| Satellite | Large-site connections |

Internal gateways: **no tunnel** is needed; the agent connects to provide User-ID (IP-to-user) and HIP. Leave tunnel mode off, and use **Internal host detection** on the portal to decide the agent is on the corporate LAN.

## Portal agent configuration

Under the portal: **Agent** tab with one or more *agent configs*, evaluated **top-down, first match wins** by user/group and OS (and, optionally, by device checks/serial). Each config defines:

* **External gateways**: FQDN or IP and a **priority** (Highest, High, Medium, Low, Lowest, or Manual-only). The agent connects to the highest priority gateway(s); between equal priorities it picks the fastest response. *Manual* lets users pick it.
* **Internal gateways** and **internal host detection** (an internal host name that resolves to an internal IP only on the corporate network).
* **Connect method**:
  * **User-logon (Always On)**: connects automatically after user login.
  * **Pre-logon (Always On)**: connects before user login using a machine certificate; user identity is "pre-logon" until the user signs in. With pre-logon then on-demand, users start the connection manually after login.
  * **On-demand**: user starts the connection manually.
* **App settings**: allow user to disconnect (with passcode), uninstall protection, welcome page, certificate store usage, client certificates (SCEP-delivered).
* **Trusted root CA** and **Install in local root certificate store** so the agent trusts the gateway cert.

> **Exam tip:** A user in two groups matches the first config in the list. Order configs from most specific to least specific.

## Policy and zones

Create a `vpn` zone with the tunnel interface, enable **User-ID** on it, and write rules from `vpn` to `trust`, `dmz`, and optionally `untrust` (NAT the pool to the Internet if full-tunnel). Use the **GlobalProtect App** application and `ssl`/`web-browsing` for the portal's external access.

## Verification

```text
PA-HQ> show global-protect-gateway current-user
PA-HQ> show global-protect-gateway gateway
PA-HQ> show global-protect-portal statistics
PA-HQ> show user ip-user-mapping all
PA-HQ> show global-protect-gateway flow
```

On the endpoint, the app's **Troubleshooting** tab and `PanGPS.log` (Windows) show connect errors. Typical failures: certificate name mismatch, wrong client authentication entry, no matching agent config (empty gateway list), no route/NAT for the pool.

## Key takeaways

* Portal authenticates and distributes config; gateway terminates the tunnel; the app talks to the portal first.
* IPSec is preferred; SSL over TCP 443 is the fallback.
* Agent configs are evaluated top-down by user, group and OS, first match wins.
* Gateway priority and response time determine external gateway choice; Manual-only requires a user selection.
* Connect methods: user-logon, pre-logon, on-demand.
* Internal gateways provide User-ID/HIP without a tunnel; internal host detection decides internal vs external.
* The tunnel interface needs a zone with User-ID enabled.
