## Virtual routers and route selection

On the **legacy routing engine**, routing lives in a **virtual router** (Network > Virtual Routers). Each L3, loopback, VLAN and tunnel interface is assigned to exactly one. Static routes, RIP, OSPF, OSPFv3, BGP and multicast run per virtual router. Traffic between virtual routers requires static routes or a route leak.

Route selection: longest prefix match first, then **lowest administrative distance**, then lowest metric.

| Source | Default administrative distance |
|--------|---------------------------------|
| Static (and static IPv6) | 10 |
| OSPF internal | 30 |
| OSPF external | 110 |
| RIP | 120 |
| EBGP | 20 |
| IBGP | 200 |

Check with `show routing route`, `show routing fib`, `show routing summary`, and `test routing fib-lookup virtual-router default ip 10.2.0.5`.

> **Watch out:** A static route (distance 10) beats an OSPF or RIP route for the same prefix. Raise the static route's administrative distance to make it a floating backup for the dynamic route.

## OSPF

* Configured under the virtual router (Network > Virtual Routers > OSPF): router ID, **areas** (normal, stub, NSSA), interfaces with type (broadcast, p2p, p2mp), hello 10 s and dead 40 s defaults, authentication (password or MD5), graceful restart, and export rules.
* Mark interfaces **passive** to advertise a subnet without forming adjacencies.
* Adjacencies form on the L3 interface; the interface must be in the router and the protocol enabled on it. Neighbor traffic to the firewall's own interface IP is not a transit flow.
* Verify: `show routing protocol ospf neighbor`, `show routing protocol ospf lsdb`, `show routing protocol ospf interface`.

## BGP

* Set the **router ID**, local **AS**, and enable BGP. Create **peer groups** (type EBGP or IBGP) and **peers** (local interface, peer address and AS).
* Timers default to keepalive 30 s and hold 90 s. EBGP peers that are not directly connected need **multihop**.
* **Import and Export rules** (BGP > Policy) match prefixes, AS paths, communities or next hop and set actions: allow/deny, local preference, MED, weight, AS prepend.
* **Redistribution Rules** (BGP > Redist Rules) inject prefixes from a redistribution profile. **Conditional advertisement** advertises a prefix only when another prefix is present (or absent) in the table. **Route aggregation** can summarize.
* After changing policy, refresh the peer (soft reset) rather than clearing the session.
* Verify: `show routing protocol bgp summary`, `show routing protocol bgp peer`, `show routing protocol bgp loc-rib`, `show routing protocol bgp rib-out`.

```text
PA-HQ> show routing protocol bgp summary
virtual router: default
  router id: 10.255.0.1   local AS: 65001
  peer: ISP1   remote AS: 64500   status: Established   uptime: 0d 2h 14m
```

## RIP

RIPv2 is available but rare: interval timers, authentication, and export rules. Distance 120 means any OSPF internal route beats it.

## Redistribution and policies

Legacy engine: build a **Redistribution Profile** (Network > Virtual Routers > Redistribution Profiles) selecting source type (static, connected, RIP, OSPF, BGP), prefix filters, and priority (lowest number evaluated first). Then reference the profile in the destination protocol:

* **OSPF Export Rules**: import external routes into OSPF as type 1 or type 2 externals; set tag and metric.
* **BGP Redistribution Rules**: send routes into BGP from static/connected/OSPF.
* **RIP Export Rules**.
* **Allow Redistribute Default Route** lets `0.0.0.0/0` be redistributed (disabled by default in BGP).
* Without a redistribution profile referenced by the target protocol, nothing is redistributed. **Connected networks are not advertised automatically**; either enable the interface in the protocol or redistribute connected.

Legacy BGP **Import/Export** rules are where routing *policy* happens. Protocol-agnostic *RIB* filtering is available on the Advanced Routing Engine (route maps, prefix lists, access lists; next lesson).

## ECMP

Enable per virtual router (Network > Virtual Routers > Router Settings > ECMP): maximum **4** equal-cost paths (the Max Path setting takes 2, 3 or 4; default 2), with algorithm **IP Modulo**, **IP Hash**, **Weighted Round Robin** or **Balanced Round Robin**. Changing ECMP on a live virtual router restarts it, which can reset sessions on its routes, so schedule a window. ECMP session symmetry: enable "Symmetric Return" to reply on the ingress interface.

## BFD

Network > Network Profiles > **BFD**. Defaults: mode active, desired min Tx 1000 ms, required min Rx 1000 ms, detection time multiplier 3, hold time 0. Attach a BFD profile to static routes, OSPF, BGP and RIP peers to detect failures in milliseconds instead of waiting for hold timers. `show routing bfd summary` and `show routing bfd details` verify sessions.

## Key takeaways

* Route selection: longest prefix, administrative distance, metric.
* Default distances: static 10, EBGP 20, OSPF int 30, OSPF ext 110, RIP 120, IBGP 200.
* Redistribution needs a redistribution profile referenced by the target protocol.
* BGP policy is Import/Export rules; conditional advertisement and aggregation are separate features.
* ECMP supports up to 4 paths; changing it restarts the virtual router.
* BFD gives subsecond failure detection when attached to peers or static routes.
