## Interface types at a glance

Every data-plane port is configured under **Network > Interfaces** and must be assigned a type before it can be put in a zone.

| Type | IP / MAC behaviour | Typical use |
|------|--------------------|-------------|
| **Layer 3** | Routed; IPv4/IPv6 address (static, DHCP client, PPPoE); belongs to a virtual/logical router | Default for gateways, edge, VPN endpoints |
| **Layer 2** | Switched within a **VLAN object**; no IP on the port itself | Firewall as a transparent bridge |
| **Virtual wire (vwire)** | Two ports bound together; no MAC or IP; no routing or switching | Drop-in inspection with no addressing change |
| **Tap** | Passive copy from a SPAN port; traffic is not blocked | Visibility only |
| **Tunnel** | Logical interface (`tunnel.N`) bound to an IPSec tunnel or GlobalProtect gateway | Route-based VPN |
| **Aggregate Ethernet (AE)** | `ae1`..; bundles physical ports, optionally with LACP | Bandwidth and link redundancy |
| **Loopback / VLAN** | Logical L3 interfaces | Management services, router ID, SVI-like routing for a VLAN |
| **HA** | Dedicated HA1/HA2/HA3 ports | High availability |
| **Management (MGT)** | Out-of-band, separate from the data plane | Admin access, updates, logging, User-ID agents |

## Layer 3 interfaces

```text
PA-HQ# configure
PA-HQ# set network interface ethernet ethernet1/1 layer3 ip 203.0.113.2/24
PA-HQ# set network interface ethernet ethernet1/2 layer3 ip 10.0.1.1/24
PA-HQ# set network interface ethernet ethernet1/2 layer3 interface-management-profile allow-ping
PA-HQ# set zone untrust network layer3 ethernet1/1
PA-HQ# set zone trust network layer3 ethernet1/2
PA-HQ# set network virtual-router default interface [ ethernet1/1 ethernet1/2 ]
PA-HQ# commit
```

Three objects must line up for traffic to flow: the **interface** (with an address), a **zone** that contains it, and a **virtual router** (legacy engine) or **logical router** (Advanced Routing Engine) that owns it. An interface not in a zone passes no traffic.

* **Subinterfaces** (`ethernet1/2.100`) carry an 802.1Q tag. The tag is locally significant; the zone is set per subinterface.
* **Interface Management Profile** (Network > Network Profiles > Interface Mgmt) decides which services *answer on this interface's IP*: ping, SSH, HTTPS, SNMP, response pages, User-ID, and so on. It also supports **Permitted IP Addresses**. Dataplane traffic *through* the firewall is never affected by it; it only governs traffic *to* the interface. Attaching an HTTPS/SSH profile to an untrust interface exposes the admin plane to the internet.
* The default MTU is 1500. A **DHCP client** interface can install a default route if configured to.

> **Exam tip:** "Management profile" on a data-plane interface and the dedicated MGT port are different mechanisms. A ping to an L3 interface IP fails until a profile allowing ping is attached, even if a security rule allows it.

## Virtual wire

A virtual wire joins exactly two interfaces. The firewall is invisible to neighbours: no address, no TTL decrement, no ARP learning of its own.

* Supports App-ID, Content-ID, User-ID, **NAT**, and QoS. No routing, no DHCP server or relay on the wire.
* Its zone type must be **Virtual Wire**; the zones on both ends are separate zones, so inter-zone rules apply.
* **Virtual wire subinterfaces** classify by VLAN tag (and optionally IP classifier), allowing different zones for different VLANs crossing the wire. Tag `0` means untagged. The wire's *Allowed Tags* range controls which tagged traffic passes the parent.
* **Link State Pass Through** shuts the peer port when one side drops, so the neighbours see the failure.

## Layer 2

Layer 2 ports are placed in a **VLAN** object (Network > VLANs). The firewall learns MACs per VLAN, floods unknown unicast within the VLAN, and applies policy between *zones*. A VLAN does not itself route: to route off a VLAN create a **VLAN interface** (L3, with an IP) and attach it to the VLAN object and a router. PAN-OS does not run spanning tree; in L2 designs ensure the topology is loop-free, and note that L2 deployments are limited to active/passive HA.

## Tunnel interfaces

`tunnel.N` is created under Network > Interfaces > Tunnel and must be assigned to a **virtual router and a zone** like any L3 interface. An IP address is optional for static-routed VPNs but needed (or unnumbered, via a loopback) for dynamic routing across the tunnel. The tunnel interface is then selected in the IPSec tunnel (lesson 1.6) or the GlobalProtect gateway (lesson 1.5). A GlobalProtect gateway's tunnel interface should be in its own zone (for example `vpn`) with User-ID enabled.

## Aggregate Ethernet

```text
PA-HQ# set network interface aggregate-ethernet ae1 layer3 ip 10.0.2.1/24
PA-HQ# set network interface aggregate-ethernet ae1 layer3 lacp enable yes mode active transmission-rate fast
PA-HQ# set network interface ethernet ethernet1/3 aggregate-group ae1
PA-HQ# set network interface ethernet ethernet1/4 aggregate-group ae1
```

* Members are assigned *from the member port* (Aggregate Group on the Ethernet interface). The AE can be L2, L3 or vwire; HA3 can also use an AE.
* Members must match in speed, duplex and media type.
* **LACP** modes: `active` initiates, `passive` only responds; the transmission rate is fast (1 s) or slow (30 s). Both sides passive never form a bundle. In active/passive HA, LACP pre-negotiation (supported on some platforms) lets the passive firewall bring LACP up in advance for faster failover.
* Without LACP, the AE is a static bundle; mismatched settings against the switch lead to one-way traffic.
* Verify with `show lacp aggregate-ethernet all` and `show interface ae1`.

## Management interface

The **MGT** port is out of band: separate routing table, default address 192.168.1.1/24 on hardware, configured in **Device > Setup > Interfaces**. Management-plane services (software and content updates, DNS, NTP, syslog, LDAP, Panorama, WildFire) use MGT by default. To send any of them out a data-plane interface instead, use **Device > Setup > Services > Service Route Configuration** (customize per service, or "use management interface" per service).

```text
PA-HQ> show interface management
PA-HQ> show interface all
PA-HQ> show interface ethernet1/1
PA-HQ> show routing interface
```

> **Watch out:** Management traffic uses the MGT default gateway, not the virtual router. If updates fail while data-plane routing is fine, check the MGT gateway or the service route.

## Lab it yourself

On a VM-Series trial or PA-VM: create an L3 pair, attach a ping-only management profile, and verify that disabling the profile blocks pings to the interface but not through-traffic. Then convert the pair to a virtual wire and confirm the firewall no longer answers ARP.

## Key takeaways

* An interface must have a type, a zone, and (for L3) a router to pass traffic.
* Vwire has no IP or routing but does support NAT and full inspection; subinterfaces classify by VLAN tag.
* L2 uses VLAN objects; routing out of a VLAN needs a VLAN interface.
* Tunnel interfaces must be in a zone and router; the zone is where policy for VPN traffic is applied.
* AE members are assigned from the member port; LACP active/passive and speeds must match.
* The interface management profile controls services answered on an interface, not transit traffic.
* MGT is out of band; service routes move individual services to data-plane interfaces.
