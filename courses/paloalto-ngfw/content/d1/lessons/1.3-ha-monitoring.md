## Why monitoring matters

HA1 heartbeats prove the *other firewall is alive*. They say nothing about whether its **upstream links or next hops work**. Link and path monitoring detect those faults and trigger failover.

## Link monitoring

Device > High Availability > **Link and Path Monitoring**. Build a **Link Group** containing physical interfaces to watch.

* **Failure condition** per group: `any` (one interface down fails the group) or `all`.
* The overall **link monitoring** has its own enable switch and its failure condition across groups (`Any`/`All`).
* When the condition is met, the firewall moves toward **non-functional / passive** and its peer takes over.
* Link monitoring only sees physical link state; a dead next hop with the link still up is not detected.

## Path monitoring

A **Path Group** pings destination IPs and fails when the destinations are unreachable.

| Setting | Detail |
|---------|--------|
| Path type | Virtual Wire, VLAN, or Virtual Router (where the pings are sourced) |
| Destination IPs | Reachable addresses (gateways or remote hosts) |
| Failure condition (group) | `any` or `all` of the destinations |
| Ping interval | Default 200 ms |
| Ping count | Default 10 consecutive failed pings = path down |
| Global path-group condition | `any` or `all` path groups |

With a 200 ms interval and a count of 10, detection takes roughly 2 seconds. Pings are sourced from the interface IPs (in a virtual router group) and respect routing. Verify with `show high-availability path-monitoring`.

> **Exam tip:** Path monitoring in HA is different from static route path monitoring (lesson 1.4). HA path monitoring triggers HA failover; static route path monitoring withdraws a route.

## Failover triggers summary

1. Link monitoring group failure.
2. Path monitoring group failure.
3. Loss of heartbeats and hellos on HA1 (plus backup) within the timer.
4. Dataplane or critical process failure on the active unit.
5. Manual: `request high-availability state suspend`.
6. Preemption by a recovered higher-priority peer.
7. HA2 keep-alive failure when action is set (log only or split datapath).

## Timers

HA timers are chosen as profiles: **Recommended**, **Aggressive** or **Advanced** (custom). Settings include promotion hold time, hello interval, heartbeat interval, maximum number of flaps, preemption hold time, monitor fail hold up time and additional master hold up time. The exact Recommended/Aggressive values differ by platform and release, so check Device > High Availability for your model. Aggressive fails over faster at the cost of more false positives.

* **Monitor fail hold up time**: how long to wait after a monitor failure before failing over; protects against a momentary flap.
* **Maximum flaps**: after N preemptive failovers the firewall stops preempting and goes to suspended/non-functional to avoid a flap storm.
* **Preemption hold time**: after the preferred unit returns, wait this many minutes before preempting.

## Split-brain and sync troubleshooting

* **Split-brain**: both units active because HA1 is down but both data paths work. Prevent with HA1 backup and heartbeat backup on a different path.
* **Config out of sync**: check `show high-availability all` for the config state, version and content mismatches; force a sync from the correct unit.
* **Session sync not working**: HA2 down, HA2 transport mismatch, or MTU issues on an IP/UDP transport path. HA2 over Ethernet requires Layer 2 adjacency.
* Peer shows `non-functional`: look at the suspend reason in `show high-availability state`.
* Version mismatches block the full HA state until fixed.

## Design tips

* Monitor the **upstream next hop** with path monitoring; use link monitoring for physical ports. Using both is common.
* Do not set aggressive timers on virtual or shared-hypervisor deployments.
* After changing HA settings test failover under load; check `show session info` on the new active unit.

## Key takeaways

* HA1 heartbeat cannot see upstream failures; link and path monitoring cover that gap.
* Link group conditions are any/all; path groups ping destinations (default 200 ms interval, 10 failed pings).
* Hold times, flap limits and preemption hold time stop failover loops.
* Failover triggers include link/path failure, heartbeat loss, process failure and manual suspend.
* Use backup HA1 and heartbeat backup to avoid split-brain.
