## Static route path monitoring

A static route stays in the RIB while its next hop interface is up, even if the next hop or the ISP beyond it is dead. **Path monitoring** removes the route when monitored destinations stop answering ICMP, so that a higher-metric (floating) route to the same prefix takes over.

Legacy engine: Network > Virtual Routers > Static Routes > select the route > enable **Path Monitoring**.

| Setting | Meaning / default |
|---------|-------------------|
| Destination IP | Address(es) to ping, usually beyond the next hop (not the next hop only) |
| Source IP | Interface address the ping uses (default is the egress interface) |
| Ping interval | 3 seconds |
| Ping count | 5 missed pings marks it down (about 15 s with defaults) |
| Failure condition | `Any` (default) or `All` of the monitored destinations |
| Preemptive hold time | 2 minutes: how long the path must stay up before the route returns; 0 reinstalls immediately |

```text
PA-HQ# set network virtual-router default routing-table ip static-route ISP1 destination 0.0.0.0/0 nexthop ip-address 203.0.113.1 interface ethernet1/1 metric 10
PA-HQ# set network virtual-router default routing-table ip static-route ISP2 destination 0.0.0.0/0 nexthop ip-address 198.51.100.1 interface ethernet1/3 metric 20
```

With path monitoring on ISP1's route (destination 192.0.2.53, for instance), failure removes ISP1 from the RIB and FIB and ISP2 (metric 20) is installed. New sessions follow the new route. Policy-Based Forwarding rules have their own separate monitor option. On the Advanced Routing Engine, check status with `show advanced-routing static-route-path-monitor`; on the legacy engine confirm the effect in `show routing route`.

> **Exam tip:** Choose a destination beyond the next hop to detect upstream failure, and make sure ICMP to it is permitted by the path (including any security policy the firewall-sourced ping needs).

**BFD for static routes** is another way: attach a BFD profile when the next hop also supports BFD. It is faster, but needs a BFD-capable peer.

## Legacy engine vs Advanced Routing Engine (ARE)

| | Legacy engine | Advanced Routing Engine |
|-|---------------|-------------------------|
| Object | Virtual router | **Logical router** (Network > Routing > Logical Routers) |
| Configuration | Network > Virtual Routers | Network > Routing (logical routers and **Routing Profiles**) |
| Protocols | Static, RIP, OSPF, OSPFv3, BGP, multicast | Static, BGP/MP-BGP, OSPFv2, OSPFv3, RIPv2, IPv4 multicast, BFD |
| Redistribution/policy | Redistribution profiles; BGP import/export | Redistribution profiles, route maps, prefix lists, access lists, RIB filtering |
| CLI | `show routing ...` | `show advanced-routing ...` |
| BGP | Peer groups | Peer groups and **inherited** configuration via profiles |

Enabling ARE: Device > Setup > Management > General Settings > **Advanced Routing**, then **commit and reboot** (also required to switch back). The two engines have separate configurations; Palo Alto provides an *Advanced Routing Engine Migration Reference* to plan moves. Plan a change window. The 11.1 documentation lists PA-400, PA-1400, PA-3200, PA-3400, PA-5200, PA-5400 and PA-7000 Series, VM-Series, CN-Series and the M-series Panorama appliances as supporting it; check the docs for newer platforms.

```text
PA-HQ> show advanced-routing route
PA-HQ> show advanced-routing bgp summary
PA-HQ> show advanced-routing ospf neighbor
PA-HQ> show advanced-routing fib
```

> **Watch out:** After enabling ARE, `show routing route` shows nothing useful. Look at the `show advanced-routing` family.

## Dynamic routing in HA and VSYS

In an A/P pair, adjacencies are only up on the active unit; use graceful restart and BFD carefully because BFD timers shorter than the HA failover time will drop neighbors. With VSYS each vsys has its own virtual or logical router, or interfaces from a shared one.

## Key takeaways

* Path monitoring makes a static route conditional on ICMP reachability; defaults are 3 s interval, 5 count, any, 2 minute preemptive hold.
* Floating static routes need a higher metric (or distance) on the backup.
* ARE is enabled in Device > Setup > Management, needs commit and reboot, and uses logical routers and routing profiles.
* ARE supports BGP/MP-BGP, OSPFv2/v3, RIPv2, IPv4 multicast, static, BFD.
* Use the `show advanced-routing` commands on ARE firewalls and `show routing` on legacy engine.
