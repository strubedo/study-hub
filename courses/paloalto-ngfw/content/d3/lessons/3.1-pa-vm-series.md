## The deployment map

Palo Alto Networks ships the same PAN-OS next-generation firewall in several form factors. The exam asks you to pick the right one and install it, so learn what each is and who operates it.

| Option | Form factor | Who runs PAN-OS | Managed by |
|--------|-------------|-----------------|-----------|
| **PA-Series** | Hardware appliance (PA-400, PA-1400, PA-3400, PA-5400, PA-7500 families and earlier models) | You | Local web UI/CLI, Panorama, or Strata Cloud Manager |
| **VM-Series** | Virtual machine on a hypervisor or public cloud | You | Same as above |
| **CN-Series** | Containers on Kubernetes | You (Panorama required) | Panorama |
| **Cloud NGFW** | Cloud-native managed service on AWS or Azure | Palo Alto Networks | Cloud console, rulestacks, optionally Panorama or Strata Cloud Manager |
| **AI Runtime Security** | AI traffic inspection, part of Prisma AIRS | Firewall-based or API-based | Strata Cloud Manager or Panorama |

This lesson covers PA-Series and VM-Series install and licensing. Bootstrapping, CN-Series, Cloud NGFW and AI Runtime Security have their own lessons.

## PA-Series first boot

A new hardware firewall comes up with a default management address and credentials.

| Setting | Factory default |
|---------|-----------------|
| Management IP | `192.168.1.1/24` on the dedicated MGMT port |
| Login | `admin` / `admin` (you must change the password at first login) |
| Console | 9600 baud, 8N1 |

Typical first steps:

1. Cable your laptop to MGMT (or use the console) and set a static address in `192.168.1.0/24`.
2. Log in at `https://192.168.1.1` and change the password.
3. Set the management address under **Device > Setup > Management > Management Interface Settings**: IP, netmask, gateway, permitted services (HTTPS, SSH, ping) and, strongly recommended, **Permitted IP Addresses**.
4. Set DNS and NTP under **Device > Setup > Services**.
5. Register the serial number with the support portal, then retrieve licences under **Device > Licenses** (*Retrieve license keys from license server*) or activate with an auth code.
6. Install the required PAN-OS version and content (see Domain 2).

The same management settings from the CLI:

```text
admin@PA-HQ> configure
admin@PA-HQ# set deviceconfig system ip-address 10.0.0.5 netmask 255.255.255.0 default-gateway 10.0.0.1 dns-primary 198.51.100.53
admin@PA-HQ# commit
admin@PA-HQ# exit
admin@PA-HQ> request license fetch auth-code ABCD1234
admin@PA-HQ> show system info
```

> **Watch out:** The management plane is separate from the data plane. The MGMT port has no zone and no security policy; reaching a service route or inspecting traffic uses dataplane interfaces. Management-plane traffic (licences, updates, DNS) leaves via MGMT unless you configure **service routes**.

Hardware models differ in dataplane throughput, ports and form factor. The exam does not test model numbers; know that PA-Series are the on-premises hardware option, and that they can be managed by Panorama.

## VM-Series platforms

VM-Series is the same PAN-OS as a software image. Supported targets include:

| Category | Targets |
|----------|---------|
| Hypervisors (private cloud) | VMware ESXi, KVM, Microsoft Hyper-V, Nutanix AHV |
| Public clouds | AWS, Microsoft Azure, Google Cloud, Oracle Cloud Infrastructure (and others per the compatibility matrix) |

Image formats follow the platform: OVA for ESXi, qcow2 for KVM, VHD for Hyper-V, and marketplace images (AMI, Azure image, GCP image) in the public clouds.

### NIC to interface mapping

The first virtual NIC is the **management** interface. The second NIC becomes **ethernet1/1**, the third **ethernet1/2**, and so on. A wrong NIC order is the most common cause of "the firewall comes up but nothing passes". In clouds the same rule applies to the order interfaces are attached.

```text
PA-HQ> show interface all
total configured hardware interfaces: 3

name                    id    speed/duplex/state              mac address
--------------------------------------------------------------------------------
ethernet1/1             16    10000/full/up                   00:0c:29:aa:10:01
ethernet1/2             17    10000/full/up                   00:0c:29:aa:10:02
```

The VM-Series needs resources sized to its licensed capacity (vCPUs and memory). Hypervisor tuning such as SR-IOV or DPDK improves throughput but is a performance topic, not an installation requirement.

> **Real world:** In clouds, the default login is set by the image (an SSH key pair or a username you set at launch) rather than `admin`/`admin`. Always check the platform guide for the first-login method.

## VM-Series licensing

The VM-Series licence is bound to the VM's UUID and CPU ID. Cloning a licensed VM does not create a second licence; it breaks activation.

| Model | How you pay | Typical use |
|-------|-------------|-------------|
| **BYOL** (bring your own licence) | You buy a capacity licence (VM-50 to VM-700 style sizes) and subscriptions, activated with an **auth code** | Static private-cloud installs |
| **Flex (software NGFW) credits** | You buy credits and create a **deployment profile** in the customer support portal; the profile gives an auth code that licenses VM-Series, CN-Series, virtual Panorama and security services as you size them | Elastic, mixed or multi-cloud estates |
| **PAYG / marketplace** | Hourly or annual billing through the cloud marketplace; subscriptions come in bundles (e.g. with threat prevention or the full set) | Fast cloud trials and bursty workloads |

Activate with an auth code:

```text
admin@PA-HQ> request license fetch auth-code F1EX-CRED-EXAMPLE
admin@PA-HQ> request license info
```

Or in the web UI: **Device > Licenses > Activate feature using authorization code**. The firewall contacts the licensing service over the management interface, so DNS and an outbound path must work. If the management network has no internet access, use the offline activation method or a licence-aware Panorama workflow documented for your release.

When you retire a VM, **deactivate** the licence (Device > Licenses, or through the Panorama licence workflow) so the capacity returns to your pool.

> **Exam tip:** PAYG images need no auth code for the base licence because the cloud provider bills for it. BYOL and Flex need an auth code (or a bootstrap authcodes file). Flex credits are consumed per deployment profile, so deleting a VM without deactivating it keeps the credits tied up.

### Plugins

The **VM-Series plugin** ships with PAN-OS and exposes cloud integration (metadata, tagging, bootstrap, HA in public clouds). Panorama also has plugins (AWS, Azure, GCP, Kubernetes, VM-Series) for monitoring cloud inventories and creating dynamic tags. Keep plugin versions compatible with the PAN-OS release.

### Managing the new VM

A newly deployed VM-Series has no configuration. You have three paths:

1. Configure locally (small labs).
2. Register to **Panorama** with the Panorama IP and a **VM auth key**, then receive its template stack and device group.
3. **Bootstrap** it at first boot so the firewall configures, licences and registers itself without a login (next lesson).

## Lab it yourself

You do not need a licence to practise the install flow.

1. Import the VM-Series image into KVM, ESXi or a nested hypervisor and attach three NICs (mgmt, `ethernet1/1`, `ethernet1/2`).
2. Boot, log in as `admin` and set the management IP using the CLI shown above.
3. Run `show interface all` and confirm the NIC order maps to `ethernet1/1` and `ethernet1/2`.
4. Run `show system info` and record the model, `family`, UUID and `vm-license` field. Without a licence it is unlicensed.
5. Try `request license info` and read the error when no auth code has been applied.

## Key takeaways

* PA-Series is hardware, VM-Series is software, CN-Series is containers, Cloud NGFW is a managed cloud service, and AI Runtime Security protects AI traffic.
* A new PA-Series boots at `192.168.1.1/24` with `admin`/`admin`; set a management IP, DNS and NTP, then licences and content.
* The VM-Series management interface is the first NIC; the second NIC is `ethernet1/1`.
* VM-Series licences bind to UUID and CPU ID; deactivate a VM before retiring it.
* BYOL and Flex credits use auth codes; PAYG is billed by the cloud marketplace.
* Flex credits are organised in deployment profiles that give you an auth code.
* `request license fetch auth-code <code>` activates from the CLI; the management port needs internet access.
* Register the VM to Panorama or bootstrap it to avoid hand configuration.
