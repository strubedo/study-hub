## Where reporting lives

PAN-OS gives you three views of what the firewall saw:

| Tool | Menu | Best for |
|------|------|----------|
| **ACC** | ACC | Interactive, near-real-time view of traffic, threats and users; pivot and filter |
| **Logs** | Monitor > Logs | Individual sessions and events |
| **Reports** | Monitor > Reports (and PDF Reports) | Scheduled or on-demand summaries, emailed or exported |

Panorama has the same tools, aggregating data from its managed firewalls.

## ACC

The **Application Command Center** summarizes log data in widgets. It is built from the firewall's aggregated statistics rather than raw logs. Tabs include:

| Tab | Shows |
|-----|-------|
| **Network Activity** | Application usage, user activity, source and destination activity, zones, regions, rule usage |
| **Threat Activity** | Threats, compromised hosts, hosts visiting malicious URLs, vulnerabilities |
| **Blocked Activity** | The same views for traffic that was denied or blocked |
| **Tunnel Activity** | Tunnel inspection data (tunnel ID, tunnel user, protocol) |
| **GlobalProtect Activity** | GlobalProtect connection and user information |
| **SSL Activity** | Decrypted and non-decrypted TLS sessions, TLS versions and ciphers, decryption errors |

(The GlobalProtect and SSL tabs appear in newer releases; the exact set depends on your version.)

You can add **custom tabs** with your own set of widgets, and each tab and widget can be exported to PDF.

### Time range and data source

* The **Time** drop-down chooses the range (for example last hour, last 6 hours, last 24 hours, last 7 or 30 days) or a custom range.
* On Panorama, the **Data Source** selector chooses data held on **Panorama** or data pulled from a **remote device** (the firewall itself). Panorama needs the firewalls to forward logs for its own data to be complete.
* The **Global filters** panel at the left shows active filters.

### Widgets

Each widget is a chart or table for one attribute, such as application usage, user activity, source IP, destination IP, threats or rules. You can:

* **Sort and group**: switch the widget's primary attribute and its detail (a chart per application, table per user).
* **Drill in**: click a value to filter or open logs. The jump to logs carries the filter over to **Monitor > Logs**.
* **Export** a widget as PDF or CSV.

### Filters

| Filter | Scope | Behaviour |
|--------|-------|-----------|
| **Local (widget) filter** | One widget | Narrows only that widget; to keep it across reboots use **Set Local Filter** |
| **Global filter** | Every widget on every ACC tab | Set from a table value, elevate a widget filter, or define it in the Global Filters pane; global filters are **not persistent** |

A global filter such as `user = alice` followed by `application = ssl` shows only that traffic across all tabs. **Application, user, source IP, zone and rule** are typical attributes.

> **Exam tip:** The ACC is a pivot tool, not a log search. To see the individual sessions behind a bar, apply a filter and use the link to **Monitor > Logs**. For per-session fields (ports, bytes per session), use a detailed-log database, not ACC.

### What affects ACC data

* A rule that does not log produces no log, and ACC (which is built from log and statistic data) will not show it as expected. Traffic hits that are never logged are invisible.
* **Log at Session End** is the usual setting that yields complete bytes and packet counts.
* Time zone and system time determine the buckets; check NTP.

## Custom reports

Under **Monitor > Manage Custom Reports** you can build a report from a **database**.

| Database type | Examples | Trade-off |
|---------------|----------|-----------|
| **Summary** databases | Application Statistics, Traffic Summary, Threat Summary, URL Summary, Tunnel Summary | Aggregated and fast for long periods; no per-session detail |
| **Detailed log** databases | Traffic, Threat, URL, Data, WildFire, HIP Match, Authentication, Decryption, User-ID, Tunnel Inspection, Unified | Per-session fields and full queries; slower for long periods |

Report settings:

1. **Database**: pick the source.
2. **Scheduled**: tick to run daily and generate the report in advance; leave unticked for on-demand reports only.
3. **Time Frame**: last 24 hours, last 7 days and so on, or a custom range.
4. **Selected Columns** and **Sort By / Group By**: for example group by application and sort by bytes, limited to the top N.
5. **Query Builder**: filter with attributes, operators (and, or) and values, such as `( addr.src in 10.0.1.0/24 ) and ( app eq ssl )`.

After saving you can **Run Now**; results export as CSV, PDF or XML.

### Report groups and email

* **Report groups** (Monitor > PDF Reports > Report Groups) bundle predefined, custom and SaaS reports into one PDF, with an optional title page.
* **Email Scheduler** (Monitor > PDF Reports > Email Scheduler) sends a report group on a schedule to configured addresses, using an email server profile.
* Predefined reports include application, threat, URL and traffic reports; **PDF Summary Report** collects the top results; **User Activity Report** reports on one user or group.

> **Exam tip:** A request for "the top applications per user last week, emailed every Monday" is a custom report on the **Application Statistics** or **Traffic Summary** database, grouped by user, added to a report group, with an email scheduler. A request for "every session from host X that triggered a particular threat" is a detailed-log query, not a summary report.

### Panorama specifics

Panorama can build the same reports. Choose the data source (Panorama or remote device). Reports and the ACC on Panorama use the logs Panorama has received: if firewalls forward logs to a collector group or Strata Logging Service, those logs are the source. Check the log forwarding profile when a report is empty.

## Dashboards

The **Dashboard** is a collection of small widgets (system resources, logged-in admins, top applications, high-risk applications, threat logs, config logs). It is separate from the ACC; widgets are added or removed per administrator.

## Lab it yourself

1. Generate traffic from a Linux host through the firewall to several sites.
2. Open **ACC > Network Activity**, set the range to last hour, click an application in the Application Usage widget to create a global filter, then check that it now narrows the other tabs too.
3. Switch to Threat Activity and observe the filter stays applied.
4. Build a custom tab with three widgets you chose.
5. Create a custom report on **Traffic Summary** grouped by application, run it now, and export CSV.
6. Create a second report on the **Traffic** detailed log with a query for one source IP; note the extra columns available.

## Key takeaways

* ACC pivots aggregated log data across tabs: Network, Threat, Blocked and Tunnel Activity, plus GlobalProtect and SSL tabs in newer releases.
* Local filters affect one widget; global filters affect every tab and are not persistent.
* ACC and reports depend on logging: traffic that is not logged cannot be reported.
* Summary databases are fast and aggregated; detailed log databases give per-session fields.
* Custom reports have a database, columns, group/sort, a time frame, an optional query and an optional schedule.
* Report groups combine reports into a PDF; the email scheduler sends them.
* On Panorama, the data source is Panorama's collected logs or the firewall itself.
