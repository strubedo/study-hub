## What Panorama manages

Panorama is the centralized management platform for PAN-OS firewalls (and Log Collectors, WildFire appliances and some cloud services). It splits configuration into two halves:

| Half | Container | Holds |
|------|-----------|-------|
| **Network and Device settings** | **Templates** and **template stacks** | Interfaces, zones, virtual/logical routers, IKE/IPSec, GlobalProtect, server profiles, authentication profiles, certificates, log settings, HA |
| **Policy and objects** | **Device groups** (and the Shared location) | Security, NAT, decryption, QoS, PBF rules; addresses, services, tags, security profiles, external dynamic lists |

> **Exam tip:** "Where do I configure a zone or an interface?" is a template. "Where do I configure a security rule or address object?" is a device group. The two are pushed separately.

Panorama has several system modes, set with `request system system-mode`:

| Mode | Behaviour |
|------|-----------|
| **Panorama** | Manages firewalls and collects logs; the default for an M-Series or virtual appliance in normal use |
| **Management Only** | Manages configuration; does not collect logs |
| **Log Collector** | Dedicated log collection only; no configuration management |
| **Legacy** (virtual appliance only) | Stores logs locally and manages firewalls |

Firewalls connect **to** Panorama (TCP 3978). Add the firewall serial number under **Panorama > Managed Devices > Summary**, and enter the Panorama IP under **Device > Setup > Management > Panorama Settings** on the firewall.

## Templates

A **template** is a reusable set of Network and Device tab configuration. Create one under **Panorama > Templates**. You can assign firewalls to a template directly, but the better pattern is a **template stack**.

### Template stacks

A **template stack** is an ordered list of templates plus its own settings. Firewalls are assigned to the stack, and the stack's resulting configuration is what they receive.

```text
Template stack: Branch-Stack            (firewalls: PA-Branch1, PA-Branch2)
   1. Branch-Interfaces                  (top, highest priority)
   2. Branch-Routing
   3. Global-Device-Settings
   (stack-level settings)
```

Rules for the merge:

* Templates in the stack are evaluated **top to bottom, and settings in a higher template override the same setting in a lower one**. Put the most specific template first and the broadest last.
* Configuration made directly in the stack (not in a member template) overrides the member templates.
* A firewall's own **local** configuration can override a pushed value only if you explicitly choose to override it on the device. **Force Template Values** at push time discards local overrides.
* One firewall belongs to one stack. A stack can contain several templates; a template can appear in several stacks.

A common structure: `Global-Device-Settings` (NTP, DNS, SNMP, admin authentication), a regional template (syslog and routing defaults), and a per-site-type template (interfaces, zones). Per-firewall specifics go into variables.

> **Exam tip:** If two templates in a stack define the same setting, the one **higher in the stack** wins. A setting made in the stack itself beats both.

### Template variables

Variables remove the need for one template per site. A variable's name starts with `$` and has a **type** and a **default value**; you override the value per firewall.

| Type examples | Used for |
|---------------|----------|
| IP Netmask | Interface IPs, address objects |
| IP Range, FQDN | Ranges, hostnames |
| Interface | Which physical port plays a role |
| AS Number | BGP AS |
| Group ID | HA group |
| Device Priority | HA device priority |

Workflow:

1. In the template, define `$mgmt-gw` or `$wan-ip` with **Manage** in the **Variables** column of **Panorama > Templates** (for the template or the stack).
2. Use the variable wherever a value is accepted, e.g. an interface IP field set to `$wan-ip`.
3. For each firewall in the stack, set the value from **Manage** in the **Variables** column for the stack in **Panorama > Templates** (per-device values can also be imported from CSV).
4. Push the stack.

A variable set at a stack level can hold the default for all firewalls in it; a per-device value overrides it.

```text
Panorama > Templates > Variables column > Manage (stack Branch-Stack)
Variable    Type          PA-Branch1          PA-Branch2
$wan-ip     IP Netmask    203.0.113.10/29     203.0.113.18/29
$lan-ip     IP Netmask    10.10.1.1/24        10.10.2.1/24
$ha-prio    Device Priority  90               110
```

> **Watch out:** An unresolved variable blocks the commit. If a firewall has no value for a variable that has no default, the push fails validation.

### Template modes and feature scope

When you create a template you pick its **mode** (the template can carry multi-vsys capability, operational mode such as FIPS, and VPN mode). Settings that exist only in a given mode appear only if the template enables it. Multi-vsys templates are covered in the VSYS lesson.

### Local overrides

When the firewall's web UI shows a setting pushed from a template, an indicator marks it and you can click **Override**. The override persists locally until you **Revert**. Panorama's **Force Template Values** replaces it at the next push.

## Bringing a firewall under management

1. Panorama: add the serial number to **Managed Devices**, assign it to a device group and template stack.
2. Firewall: set the Panorama address, commit.
3. Panorama: **Commit to Panorama**, then **Push to Devices** with the device group and template stack.
4. Check status on Panorama (**Managed Devices > Summary**: connected, Shared Policy, Template columns in sync) and on the firewall:

```text
admin@PA-Branch1> show panorama-status
Panorama Server 1 : 203.0.113.50
    Connected     : yes
    HA state      : disconnected
admin@PA-Branch1> show config pushed-template
```

## Lab it yourself

A single virtual Panorama and one VM-Series firewall are enough.

1. Create templates `Base` (NTP, DNS) and `Site` (an interface using `$lan-ip`) and a stack `Lab-Stack` listing `Site` first.
2. Define `$lan-ip` with a default and a per-device value for your firewall.
3. Set the same NTP server in `Site` and `Base` with different addresses and predict which wins; push and verify with `show config pushed-template` or in the UI.
4. Override a pushed setting locally, push again with and without **Force Template Values** and watch what happens.

## Key takeaways

* Templates and stacks hold Network and Device settings; device groups hold policy and objects.
* A template stack is an ordered list of templates; higher templates override lower ones, and stack-level settings beat member templates.
* Variables (named `$...`, typed) give per-firewall values without per-site templates.
* Force Template Values overrides local firewall changes; local override is otherwise possible.
* Panorama modes: Panorama, Management Only, Log Collector, Legacy.
* Firewalls connect to Panorama over TCP 3978.
* Use `show panorama-status` and `show config pushed-template` on the firewall to confirm what arrived.
