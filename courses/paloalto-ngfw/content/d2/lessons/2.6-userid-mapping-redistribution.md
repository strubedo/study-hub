## IP-to-user mapping sources

Every mapping is `IP address -> user`, stored with a timeout. The firewall learns it from one or more **sources**. Choose according to how users log in.

| Source | How it learns | Best for |
|--------|---------------|----------|
| **Server monitoring** (PAN-OS integrated agent or Windows User-ID agent) | Reads Windows security event logs on domain controllers/Exchange servers (logon and Kerberos ticket events) via WMI or WinRM, or listens for them | Domain-joined Windows users |
| **Syslog listener** | Parses syslog from authentication systems (NAC, wireless controllers, proxies, VPN) with **syslog parse profiles / filters** | Non-Windows or network-device logins |
| **Authentication Portal** | Challenges unknown users in the browser (Kerberos SSO, NTLM, web form, SAML, certificate) | Unknown users, guests, non-domain devices |
| **GlobalProtect** | Gateway reports the user and the VPN client IP as soon as they connect | Remote users |
| **XML / REST API** | An external system posts `user-id` updates | Custom sources, NAC, SOAR |
| **Terminal Services (TS) agent** | Allocates a port range per user on a multi-user server so one IP can carry many users | Citrix/RDS hosts |
| **Cloud Identity Engine** | CIE supplies mappings it collected from Cloud Identity Agents or Prisma Access/GlobalProtect | Hybrid and cloud |
| **Redistribution** | Another firewall, Panorama or agent sends its table | Multi-site designs (below) |
| **Port mapping** and **XFF headers** | Map ports or X-Forwarded-For addresses to users | Proxy and terminal-server specifics |

### Server monitoring requirements

* A **service account** with rights to read the domain controllers' event logs (a member of Event Log Readers and, for the session monitoring option, appropriate DCOM/WMI rights) in the group mapping's domain.
* **Server Monitor** entries (Device > User Identification > User Mapping > Server Monitoring) for each DC, with transport WMI, or WinRM-HTTP/HTTPS.
* **Include/Exclude Networks** (to limit which subnets are mapped) and an **Ignore User List** (service accounts, `SYSTEM`).
* **Enable User-ID on the source zone** (Network > Zones) so traffic from that zone is looked up. Without it, mappings exist but are not used for traffic entering that zone.
* DC events used include Kerberos ticket and logon events. Ensure the DCs audit those events.

### Timeouts

* **User Identification Timeout** on the integrated agent: mappings from server monitoring expire after the configured period (the documented default is **45 minutes**). Keep it in step with the DHCP lease or Kerberos ticket lifetime. Setting it too short loses users between events; too long keeps stale mappings after IPs change.
* **Authentication Portal** has its own timer (default 60 minutes) and an idle timer.
* **GlobalProtect** mappings end on disconnect.

> **Watch out:** Stale mappings cause *wrong user* attributions in DHCP-heavy networks. Use a short timeout or a source that reports logoffs (GlobalProtect, Syslog with logoff events).

### Client probing

WMI or NetBIOS **client probing** actively asks the client who is logged in. It is a legacy approach: it is noisy, requires firewall rules and permissions, and Palo Alto recommends against it in favour of the other sources.

### Verification commands

```text
PA-HQ> show user ip-user-mapping all
PA-HQ> show user ip-user-mapping ip 10.0.1.25
PA-HQ> show user user-id-agent state all
PA-HQ> show user server-monitor state all
PA-HQ> show user ts-agent state all
```

`show user server-monitor state all` lists each monitored DC and whether it is **Connected**; a state such as `Access denied` or a connection failure points at credentials, WMI/WinRM or firewall access.

The documented check is that each server shows **Connected** (also in Device > User Identification > User Mapping). The sample below is abbreviated and the column layout varies by release.

```text
PA-HQ> show user server-monitor state all
Directory Servers:
Name           TYPE   Host        Vsys   Status
-----------------------------------------------------------------------------
DC1            AD     dc1.example.com  vsys1  Access denied
```

## The Windows User-ID agent and PAN-OS integrated agent

* **PAN-OS integrated agent**: runs on the firewall itself. Simple and no extra server, but it uses dataplane/management resources and each firewall does its own collection.
* **Windows-based User-ID agent**: a service on a Windows server that collects mappings and sends them to firewalls (default connection **TCP 5007**). Better for scale or when a central collector sits close to the DCs.

Whichever you use, the firewall must be told: **Device > User Identification > User Mapping** (integrated agent settings) or **Device > Data Redistribution > Agents** / **User-ID Agents** (a remote source).

## Redistribution and segments

In multi-site networks only a few devices need to read the DCs. Everyone else gets the mappings **redistributed**.

* A firewall (or Panorama) can be a **redistribution point**: it collects mappings, groups' IP tags and user tags, HIP data and similar, and shares them with downstream firewalls that connect to it as a **Data Redistribution agent**.
* The downstream firewall is the client and chooses what to receive: set up under **Device > Data Redistribution > Agents** with the sender's IP/hostname, port, and a connection secret, and choose the data types (IP-user mappings, IP tags, user tags, HIP).
* The sending firewall enables the **Collector Settings** (**Device > Data Redistribution > Collector Settings**): a **collector name** and **pre-shared key** that the receiver must match.
* **Include/Exclude Networks** on the sender and the receiver limit which subnets' mappings cross the link. This is how **segments** are kept apart: each regional hub only forwards the subnets of its own segment, and the receivers only accept mappings in their segment.
* Data Redistribution chains: branch firewall to regional hub to central collector, to avoid every branch querying every DC.
* Panorama can act as a redistribution point too, so a central management server can feed every managed firewall.

> **Exam tip:** In a segmented design (users in a network behind one firewall, resources behind another), the segment containing resources needs the mappings of the user segment. Redistribute them from the firewall or agent that sees the logins, filtered with **Include/Exclude Networks**, rather than running another DC read.

### Hops and caveats

* The receiver initiates the connection to the sender (like a firewall connecting to a User-ID agent); check firewall rules permit the receiver to reach the sender on the agent port (5007 by default).
* Multiple hops are supported; documented limits apply, so keep the topology shallow.
* The receiving firewall must also have **User-ID enabled on the relevant zones** to use the mappings.
* Mappings are subject to the sender's timeouts: a mapping redistributed is removed downstream when the sender removes it.

## Cloud Identity Engine as a mapping source

Beyond groups, CIE can feed **IP-user mappings**: **Configure the Cloud Identity Engine as a Mapping Source** on the firewall. This lets cloud-collected information (for example from Prisma Access and GlobalProtect logins, or from the Cloud Identity Agent reading on-prem AD events) reach firewalls without each one reading DCs. It needs the CIE tenant, the device certificate, and the mapping option in the CIE profile.

## Putting it together

For a typical AD environment:

1. LDAP (or CIE) **group mapping**.
2. **Server monitoring** on two DCs (or the Windows agent).
3. **User-ID enabled** on the internal zones and **Include/Exclude** networks defined.
4. **Authentication Portal** for what server monitoring cannot see.
5. **GlobalProtect** for remote users.
6. **Redistribution** to branch firewalls.

## Lab it yourself

1. Add a Windows eval domain controller and enable user mapping server monitoring with a read-only service account. Log in a Windows client and watch `show user ip-user-mapping all`.
2. Remove the service account's event-log permission and read the `show user server-monitor state all` error.
3. Post a mapping through the API: `curl -k "https://<fw>/api/?type=user-id&key=<key>&cmd=<uid-message>..."` using a `uid-message` that logs `jsmith` in at `10.0.1.99`, then check the table.
4. With two firewalls, make the first a redistribution collector and the second an agent; compare the tables.

## Key takeaways

* Mapping sources: server monitoring, syslog, Authentication Portal, GlobalProtect, API, TS agent, CIE, redistribution.
* User-ID must be enabled on the zone for mappings to be used for traffic entering it.
* Group mapping gives membership; mapping sources give IP-to-user; both are needed.
* A User-ID Windows agent listens on TCP 5007 by default.
* Redistribution lets central devices share mappings; Include/Exclude Networks keep segments separate.
* `show user ip-user-mapping all`, `show user server-monitor state all` and `show user user-id-agent state all` verify the pipeline.
* CIE can serve as a mapping source as well as a group source.
