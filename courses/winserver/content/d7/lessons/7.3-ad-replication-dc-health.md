## The tools you'll use every time

| Tool | Use |
|------|-----|
| `repadmin /replsummary` | One-screen summary: largest delta and failures per source and destination DC |
| `repadmin /showrepl DC2` | Inbound partners of DC2 per naming context, last attempt, last success, error code |
| `repadmin /showrepl * /csv > repl.csv` | The same for every DC, for a spreadsheet |
| `repadmin /syncall DC2 /AdeP` | Force DC2 to sync all partitions from all partners (`A` all NCs, `d` DN output, `e` enterprise/cross-site, `P` push) |
| `repadmin /queue`, `repadmin /showbackup` | Pending inbound replication; last backup time per partition |
| `dcdiag /v`, `dcdiag /test:replications`, `dcdiag /test:dns /e` | DC health tests |
| `Get-ADReplicationFailure -Target DC2`, `Get-ADReplicationPartnerMetadata -Target DC2` | PowerShell equivalents |
| `nltest /dsgetdc:contoso.com`, `nltest /dclist:contoso.com` | DC locator results and DC list |
| `netdom query fsmo`, `Get-ADDomain`/`Get-ADForest` | FSMO role holders |

## Reading replication errors

`repadmin` prints each failure with a decimal and hex code. These are the ones to know:

| Error | Text | Usual cause | First step |
|-------|------|-------------|-----------|
| **1722** (0x6ba) | The RPC server is unavailable | Destination can't connect to the source: source down, DNS points at a wrong IP, firewall blocking TCP 135 or the RPC dynamic range (49152–65535) | `Test-NetConnection source -Port 135`, check the source's A record and CNAME, `portqry` |
| **1256** (0x4e8) | The remote system is not available | Network-level failure reaching the partner | Same connectivity checks as 1722 |
| **8524** (0x214c) | The DSA operation is unable to proceed because of a DNS lookup failure | Destination can't resolve the source DC's GUID CNAME in `_msdcs.<forest root>` (or stale metadata of a removed DC) | `nslookup <DSA GUID>._msdcs.contoso.com`, check DC DNS client settings, clean up metadata |
| **8453** (0x2105) | Replication access was denied | Permissions on the naming context, or the DC computer account's `userAccountControl` missing `SERVER_TRUST_ACCOUNT`/`TRUSTED_FOR_DELEGATION` | `dcdiag /test:CheckSecurityError`, `dcdiag /test:MachineAccount` |
| **5** | Access is denied | Often time skew beyond Kerberos tolerance, broken secure channel of the DC, or SMB signing mismatch | `w32tm /monitor`, `dcdiag /test:CheckSecurityError` |
| **-2146893022** (0x80090322) | The target principal name is incorrect | Kerberos SPN mismatch: the DC's name resolves to a different machine, or a DC's machine password is out of sync | Check DNS records for the source; reset the DC's machine account password |
| **8614** (0x21a6) | The directory service cannot replicate with this server because the time since the last replication with this server has exceeded the tombstone lifetime | The DC hasn't replicated for longer than TSL (or the clock jumped); the partner is quarantined; Directory Service event **2042** | Check for lingering objects, fix replication, or demote/rebuild the stale DC |
| **8606** (0x219e) | Insufficient attributes were given to create an object | A **lingering object** on the source is blocked by a **strict replication consistency** destination; Directory Service event **1988** names the object | Remove lingering objects from the source |
| **8456 / 8457** | The source / destination server is currently rejecting replication requests | Replication was disabled manually (`repadmin /options`) or automatically: USN rollback (`Dsa Not Writable` = 4) or no free disk space for the database (`Dsa Not Writable` = 2) | `repadmin /options DC2`, read `Dsa Not Writable`, check free space on the NTDS volume |

> **Exam tip:** 1722 and 8524 are "fix the network or DNS" errors. 8453 and 5 are "fix permissions, time or the account" errors. 8606 and 8614 are "lingering object / tombstone lifetime" errors. Categorizing the code is usually enough to choose the answer.

### Lingering objects and strict replication consistency

A **lingering object** exists on one DC after it was deleted everywhere else and the tombstone has been garbage-collected. It happens when a DC is offline (or failing to replicate) for longer than the tombstone lifetime, or when a stale backup is restored.

- With **strict replication consistency** (the default in forests created on Windows Server 2003 or later), a destination DC refuses to recreate an object it no longer knows about, logs **event 1988**, and stops replicating that partition from that source (**error 8606**). That's the safe behaviour.
- With **loose** consistency, the destination would recreate (reanimate) the object, spreading it.

Enable strict mode on all DCs (registry value `Strict Replication Consistency` = 1 under `HKLM\SYSTEM\CurrentControlSet\Services\NTDS\Parameters`):

```text
C:\> repadmin /regkey * +strict
```

Remove lingering objects by comparing against a DC you trust. Run it in advisory mode first:

```text
C:\> repadmin /removelingeringobjects DC3.contoso.com 7a2b9c41-1d6e-4f0b-8b3a-5c2e9d7f0a16 DC=contoso,DC=com /advisory_mode
C:\> repadmin /removelingeringobjects DC3.contoso.com 7a2b9c41-1d6e-4f0b-8b3a-5c2e9d7f0a16 DC=contoso,DC=com
```

The first argument is the DC **holding** the lingering objects; the GUID is the **DSA object GUID** of the clean reference DC (from `repadmin /showrepl`); the third is the partition. Microsoft's **Lingering Object Liquidator** (LoL) automates the same comparison across the forest.

### USN rollback

A **USN rollback** happens when a DC's database is rolled back by an unsupported method, for example reverting a VM snapshot on a hypervisor that doesn't support VM-GenerationID, or restoring a disk image. Partners think they already have the DC's changes, so they silently ignore new ones. Windows Server detects it and:

- logs Directory Service event **2095**;
- pauses the **Netlogon** service;
- sets the registry value **Dsa Not Writable** (value 4) under `HKLM\SYSTEM\CurrentControlSet\Services\NTDS\Parameters`, which blocks replication in and out.

The supported fix is to **force-demote the DC** (or remove it and clean up its metadata), then promote it again, or restore it from a valid system state backup. Deleting `Dsa Not Writable` is unsupported.

> **Real world:** Hyper-V and Azure support **VM-GenerationID**, so reverting a checkpoint of a Windows Server 2012-or-later DC triggers safe virtualization (a new invocation ID and a non-authoritative resync) instead of a USN rollback. Restoring a raw VHD copy on a host without GenID support still causes rollback.

## Other on-premises AD DS problems

### dcdiag in practice

```text
C:\> dcdiag /s:DC2 /v /f:C:\Temp\dcdiag-DC2.txt
C:\> dcdiag /test:advertising /test:netlogons /test:services
C:\> dcdiag /test:dns /dnsbasic /e
```

| Failed test | Points to |
|-------------|-----------|
| Connectivity | DNS registration of the DC or blocked LDAP/RPC |
| Advertising | The DC isn't advertising as a DC (Netlogon stopped, SYSVOL not shared, time service not advertising) |
| NetLogons / SysVolCheck | SYSVOL or NETLOGON share missing, often because DFSR SYSVOL never initialized |
| Replications | Inbound replication errors (see the table above) |
| KnowsOfRoleHolders / FsmoCheck | A FSMO role holder is unreachable or was removed |
| DNS | Missing records, broken forwarders or delegation, dynamic update problems |

### FSMO role problems

If a role holder fails permanently, **seize** the role on a surviving DC; if it's only being retired, **transfer** it. Never bring a DC whose role was seized back online without rebuilding it.

```powershell
PS C:\> Move-ADDirectoryServerOperationMasterRole -Identity DC2 -OperationMasterRole PDCEmulator, RIDMaster
PS C:\> Move-ADDirectoryServerOperationMasterRole -Identity DC2 -OperationMasterRole SchemaMaster -Force
```

Without `-Force` the cmdlet transfers; with `-Force` it seizes if the current holder is unreachable. Symptoms by role: no new objects can be created when RID pool is exhausted and the **RID master** is down; password changes are slow to reach users and account lockouts behave oddly when the **PDC emulator** is down; time skew across the forest when the forest root PDC emulator has bad time.

### Removing a dead DC

When a DC is gone for good, delete its computer object in ADUC or its server object in AD Sites and Services (Windows Server 2008 and later clean up the metadata automatically), or run `ntdsutil` **metadata cleanup**. Then remove leftover DNS records (A, CNAME in `_msdcs`, SRV, NS) so clients and partners stop trying it.

### Database health

`ntds.dit` and its logs live in `C:\Windows\NTDS` by default. With AD DS stopped (or in DSRM):

```text
C:\> ntdsutil "activate instance ntds" "files" "integrity" quit quit
C:\> ntdsutil "activate instance ntds" "semantic database analysis" "go" quit quit
```

Low free disk on the NTDS volume causes the DC to stop writing (Directory Service events warning about disk space), so monitor that volume.

## Lab it yourself

1. Build two lab DCs (DC1, DC2). Run `repadmin /replsummary` and `repadmin /showrepl DC2`.
2. Block TCP 135 inbound on DC1 with `New-NetFirewallRule -DisplayName "Block RPC" -Direction Inbound -Protocol TCP -LocalPort 135 -Action Block`, run `repadmin /syncall DC2 /AdeP`, and read the 1722 error. Remove the rule.
3. Point DC2's DNS client at a server that can't resolve `_msdcs.contoso.com`, flush the cache, force replication and look for 8524.
4. Run `repadmin /regkey * +strict` and `dcdiag /v` and read every test result.

## Key takeaways

- Start with `repadmin /replsummary`, then `repadmin /showrepl <DC>` and `dcdiag /test:replications` on the failing destination.
- 1722/1256/8524 are network and DNS problems; 8453/5 are permissions, time or account problems.
- 8606 with event 1988 means a lingering object on the source blocked by strict replication consistency; remove it with `repadmin /removelingeringobjects` (advisory mode first) or Lingering Object Liquidator.
- 8614 with event 2042 means the partners haven't replicated within the tombstone lifetime.
- USN rollback logs event 2095, pauses Netlogon and sets Dsa Not Writable; the fix is demote and re-promote, not a registry edit.
- Transfer FSMO roles with `Move-ADDirectoryServerOperationMasterRole`; add `-Force` to seize from a dead holder.
- After removing a dead DC, clean up metadata and its DNS records.
