## What Azure Arc-enabled servers gives you

Azure Arc projects a physical server or VM that runs **outside Azure** (on-premises, at the edge, in AWS or GCP) into Azure Resource Manager as a resource of type `Microsoft.HybridCompute/machines`. Once a server is a resource you can put it in a resource group, tag it, scope Azure RBAC and Azure Policy to it, and use Azure management services on it: Update Manager, Azure Monitor Agent, Defender for Servers, Machine Configuration, Automation Hybrid Runbook Workers, Windows Admin Center and SSH from the portal.

The **control plane** features (inventory, tags, RBAC, Resource Graph, templates and extensions) are free. The services you turn on are billed according to their own pricing, and some are free for servers covered by **Windows Server Management enabled by Azure Arc** (Software Assurance or Windows Server subscription licences after attestation, or Windows Server pay-as-you-go).

> **Watch out:** Arc is for **non-Azure** machines. An Azure VM already has a native Azure resource; installing the Connected Machine agent on one is unsupported (lab guides that do it must first block the Azure instance metadata endpoint).

## The Azure Connected Machine agent

Onboarding installs the **Azure Connected Machine agent**. On Windows it adds three services:

| Service | Display name | Job |
|---|---|---|
| `himds` | Azure Hybrid Instance Metadata Service | Connection to Azure, heartbeat, the machine's **system-assigned managed identity** |
| `GCArcService` | Guest Configuration Arc Service | Evaluates and applies **Machine Configuration** (guest policy) |
| `ExtensionService` | Guest Configuration Extension Service | Installs, updates and removes **VM extensions** |

The command-line tool is `azcmagent` (in `%ProgramFiles%\AzureConnectedMachineAgent`). Logs are in `%ProgramData%\AzureConnectedMachineAgent\Log` (`himds.log`, `azcmagent.log`); extension logs are under `%ProgramData%\GuestConfig\extension_logs`.

| Command | Use |
|---|---|
| `azcmagent connect` | Register the machine with Azure |
| `azcmagent disconnect` | Remove the registration (and the Azure resource, if it can reach Azure) |
| `azcmagent show` | Status, resource ID, last heartbeat, dependent service status (no admin rights needed) |
| `azcmagent check` | Test connectivity to the required endpoints for a region |
| `azcmagent config list` / `set` | Proxy, extension allow/block lists, monitor mode, incoming ports |
| `azcmagent logs` | Zip all logs for support |

### Connection status

* **Connected** - heartbeats arriving (one every 5 minutes).
* **Disconnected** - heartbeats have stopped; the portal flips the status within **15 to 30 minutes**. Existing extensions keep running, but extension operations queue (for up to 6 hours) and Machine Configuration assignments are kept locally for only 14 days. The resource stays.
* **Expired** - after about **45 days** offline the status can change to Expired: the managed identity credential (valid up to 90 days, renewed every 45) has lapsed, and the machine must be disconnected and reconnected (onboarded again).

## Network requirements

All agent traffic is **outbound TCP 443** (HTTPS) - no inbound ports. Allow either the URLs or the service tags.

| Endpoint | Why |
|---|---|
| `download.microsoft.com` | Agent package (install and upgrade) |
| `login.microsoftonline.com`, `*.login.microsoft.com`, `pas.windows.net` | Microsoft Entra ID tokens |
| `management.azure.com` | ARM - only while connecting or disconnecting |
| `*.his.arc.azure.com` | Hybrid identity and metadata |
| `*.guestconfiguration.azure.com` | Extension management and Machine Configuration |
| `guestnotificationservice.azure.com`, `*.guestnotificationservice.azure.com`, `*.servicebus.windows.net` | Notifications (extensions, WAC, SSH) |
| `*.blob.core.windows.net` | Extension package downloads from Microsoft-managed storage (unless you use private endpoints; covered by the **Storage** tag) |
| `*.waconazure.com` | Only for Windows Admin Center in Azure |

Service tags: **AzureActiveDirectory, AzureTrafficManager, AzureResourceManager, AzureArcInfrastructure, Storage**, plus **AzureFrontDoor.Frontend** (required from April 2026) and **WindowsAdminCenter** if you use WAC.

Other options:

* **Proxy**: `azcmagent config set proxy.url "http://proxy.contoso.com:8080"`. Authenticated proxies aren't supported for the agent, and a Log Analytics gateway can't act as the agent's proxy.
* **Azure Arc gateway**: reduces the number of endpoints to allow to a handful.
* **Private Link scope**: routes the private-link-capable endpoints (`*.his.arc.azure.com`, `*.guestconfiguration.azure.com`) over ExpressRoute or VPN. Entra ID and ARM endpoints remain public.
* TLS 1.2 or 1.3 must be enabled with the cipher suites the agent requires (Windows Server 2012 R2 and later support this by default).

## Onboarding methods

| Method | Best for | Identity used |
|---|---|---|
| **Azure Arc Setup** wizard (built into Windows Server 2022 and 2025, tray icon) | A single server, GUI | Interactive Entra sign-in |
| Portal **Add a server** script | One to a few servers | Interactive browser or device code |
| **Service principal** script | Dozens to thousands | Service principal with the **Azure Connected Machine Onboarding** role |
| **Group Policy** (`DeployGPO.ps1` from the ArcEnabledServersGroupPolicy project) | Domain-joined fleets | Service principal, agent on a share |
| Configuration Manager task sequence / script | ConfigMgr shops | Service principal |
| Windows Admin Center (Azure hybrid services) | Servers already managed in WAC | Interactive |

Interactive browser sign-in is the default on Desktop Experience; **device code** (`--use-device-code`) is the default on Server Core. At scale, use a dedicated service principal that has only the **Azure Connected Machine Onboarding** role on the target resource group. That role can only read and create Arc server resources - it can't delete machines that are already registered or manage their extensions - so a leaked secret has limited blast radius. **Azure Connected Machine Resource Administrator** is the role that can read, modify, re-onboard and delete machines and manage extensions after onboarding.

```powershell
PS C:\> & "$env:ProgramFiles\AzureConnectedMachineAgent\azcmagent.exe" connect `
          --service-principal-id $appId --service-principal-secret $secret `
          --tenant-id $tenantId --subscription-id $subId `
          --resource-group RG-Arc --location eastus --tags "Datacenter=DAL1,Env=Prod"
```

Microsoft recommends passing the secret in a config file (`--config`) or using a certificate (`--service-principal-cert`) rather than on the command line, where it can land in logs. `--resource-name` overrides the default resource name (the hostname); it can't be changed later without disconnecting.

Before onboarding, the subscription needs the resource providers **Microsoft.HybridCompute**, **Microsoft.GuestConfiguration** and **Microsoft.HybridConnectivity** registered (and Microsoft.AzureArcData if SQL Server will be auto-connected).

> **Exam tip:** If a machine with SQL Server is onboarded, the SQL Server extension is deployed automatically. To opt out, tag the server `ArcSQLServerExtensionDeployment = Disabled` at connection time.

## Managing Arc servers after onboarding

* **Managed identity** - every Arc server gets a system-assigned identity. Local scripts can request tokens from the agent's local endpoint, which only local Administrators and members of the **Hybrid Agent Extension Applications** group can call. Give the identity Azure roles (for example, *Key Vault Secrets User*) instead of storing secrets on disk.
* **Agent upgrades** - via Microsoft Update/WSUS, Azure Update Manager, or reinstalling the MSI. `azcmagent upgrade` is available for supported versions.
* **Resource governance** - the extension manager and Machine Configuration agent are capped at 5% CPU by default (`extensions.agent.cpulimit`, `guestconfiguration.agent.cpulimit`).
* **Extended Security Updates** - Windows Server 2012/2012 R2 ESUs delivered through Arc end with the October 13, 2026 update; Windows Server 2016 ESUs through Arc can be configured from August 2026, billed from January 2027.
* **Hotpatch** for Windows Server 2025 Standard and Datacenter is delivered through Arc and Update Manager, so most monthly security updates install without a reboot (reboots only for quarterly baselines).

## Lab it yourself

1. In a free Azure subscription create `RG-Arc`. In the portal open **Azure Arc > Machines > Add/Create > Add a machine > Single server**, pick Windows and download the script.
2. Run the script on a Hyper-V lab VM running Windows Server 2025 (not an Azure VM). Sign in when prompted.
3. Run `azcmagent show` and confirm **Agent Status : Connected**. Then `azcmagent check --location eastus`.
4. Stop `himds` for about 30 minutes (`Stop-Service himds`) and watch the portal flip the machine to **Disconnected**; start it again.

## Key takeaways

* Arc projects non-Azure machines into ARM as `Microsoft.HybridCompute/machines`; control-plane features are free, services are billed per their pricing.
* The agent runs `himds`, `GCArcService` and `ExtensionService`; manage it with `azcmagent` (`show`, `check`, `config`, `connect`, `disconnect`).
* Only outbound TCP 443 is needed; proxy, Arc gateway and Private Link scope reduce exposure, but Entra ID and ARM stay public.
* Onboard at scale with a service principal that has only the **Azure Connected Machine Onboarding** role.
* Disconnected = no heartbeat (status changes within 15-30 minutes); Expired = credential lapsed after about 45 days offline, which requires re-onboarding.
* Every Arc server gets a system-assigned managed identity - use it instead of stored credentials.
