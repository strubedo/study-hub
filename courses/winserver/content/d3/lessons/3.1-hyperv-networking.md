## The Hyper-V Virtual Switch

The Hyper-V Virtual Switch is a software, layer 2 Ethernet switch in the host's parent partition. Every VM network adapter plugs into a port on one switch.

| Switch type | Connects VMs to | Host connectivity | Use |
|---|---|---|---|
| **External** | A physical NIC (or a SET team) and therefore the physical network | Optional host vNIC (`-AllowManagementOS`) | Production |
| **Internal** | Each other and the host | Yes, through a host vNIC | Host-only labs; base for **NAT** |
| **Private** | Each other only | No | Isolated test networks |

```powershell
PS C:\> New-VMSwitch -Name External -NetAdapterName 'Ethernet 2' -AllowManagementOS $true
PS C:\> New-VMSwitch -Name LabInternal -SwitchType Internal
PS C:\> New-VMSwitch -Name Isolated -SwitchType Private
```

When you create an External switch with `-AllowManagementOS $true`, the host's IP configuration moves from the physical NIC to a new **vEthernet** adapter - expect a brief connectivity drop, and don't do it remotely over the only NIC without a plan.

### NAT for lab networks

```powershell
PS C:\> New-VMSwitch -Name NATSwitch -SwitchType Internal
PS C:\> New-NetIPAddress -IPAddress 192.168.50.1 -PrefixLength 24 -InterfaceAlias 'vEthernet (NATSwitch)'
PS C:\> New-NetNat -Name LabNAT -InternalIPInterfaceAddressPrefix 192.168.50.0/24
```

VMs on NATSwitch use 192.168.50.1 as their gateway (there is no DHCP; assign addresses statically or run DHCP in a VM). Only one NAT network per host is supported.

### Switch settings to know

* **Bandwidth mode** is chosen at creation: `New-VMSwitch ... -MinimumBandwidthMode Weight` (or `Absolute`). You can't change it later.
* **SR-IOV** is also a creation-time choice: `-EnableIov $true`. A switch created without it must be deleted and recreated.
* **Extensions**: the Microsoft Windows Filtering Platform and NDIS Capture extensions ship in the box (`Get-VMSwitchExtension`, `Enable-VMSwitchExtension`); third parties add filtering/forwarding extensions.
* The **Default Switch** (NAT with DHCP) exists only on Windows client Hyper-V, not Windows Server.

## Virtual network adapters

| Adapter | Available on | Notes |
|---|---|---|
| **Network Adapter** (synthetic) | Gen 1 and Gen 2 | VMBus, fast; Gen 2 can PXE boot from it |
| **Legacy Network Adapter** (emulated Intel 21140) | **Gen 1 only** | Needed only for PXE boot on Gen 1 or OSes without integration components |

**Generation 2** VMs support **hot add and remove** of network adapters while running (Windows Server 2016 and later hosts); on Gen 1 VMs the VM must be off.

```powershell
PS C:\> Add-VMNetworkAdapter -VMName VM1 -SwitchName External -Name 'Backup'
PS C:\> Connect-VMNetworkAdapter -VMName VM1 -Name 'Backup' -SwitchName Isolated
```

### Adapter features

| Feature | Cmdlet / parameter | What it does |
|---|---|---|
| **VLAN (access)** | `Set-VMNetworkAdapterVlan -VMName VM1 -Access -VlanId 20` | Tags the VM's traffic on VLAN 20; the physical switch port must be a trunk carrying 20 |
| **VLAN (trunk)** | `Set-VMNetworkAdapterVlan -VMName FW1 -Trunk -AllowedVlanIdList 10-20 -NativeVlanId 1` | Guest receives tagged frames (virtual routers/firewalls) |
| **MAC address spoofing** | `Set-VMNetworkAdapter -VMName VM1 -MacAddressSpoofing On` | Lets the VM send frames with other MACs - nested virtualization, NLB in unicast mode, some appliances |
| **Static MAC** | `-StaticMacAddress 00155D010A20` | Needed for licensing or NLB; default is dynamic from the host's pool |
| **DHCP guard** | `-DhcpGuard On` | Drops DHCP server offers from the VM (rogue DHCP) |
| **Router guard** | `-RouterGuard On` | Drops router advertisements and redirects from the VM |
| **Port mirroring** | `-PortMirroring Source` / `Destination` | Copies traffic to a monitoring VM on the same switch |
| **Bandwidth** | `-MaximumBandwidth 1GB` (bits/s) / `-MinimumBandwidthWeight 20` | Caps or reserves bandwidth (weight requires a Weight-mode switch) |
| **Device naming** | `-DeviceNaming On` | Exposes the Hyper-V adapter name inside the guest (`Get-NetAdapterAdvancedProperty`) |
| **Protected network** | Hyper-V Manager advanced feature | In a cluster, moves the VM if its network disconnects |
| **NIC teaming in the guest** | `-AllowTeaming On` | Required before the guest can team its virtual adapters |
| **SR-IOV** | `-IovWeight 100` | Bypasses the virtual switch with a virtual function on an SR-IOV NIC; needs an IOV-enabled switch |
| **VMQ / vRSS** | `Set-VMNetworkAdapter -VmmqEnabled`, `Enable-NetAdapterVmq` on host | Spreads receive processing across CPUs |

Reading VLAN configuration:

```text
PS C:\> Get-VMNetworkAdapterVlan -VMName VM1

VMName VMNetworkAdapterName Mode     VlanList
------ -------------------- ----     --------
VM1    Network Adapter      Access   20
```

> **Watch out:** A VM tagged with VLAN 20 that can't reach anything usually means the **physical switch port** connected to the host isn't a trunk allowing VLAN 20 (or the host's NIC teaming/SET configuration strips tags). The Hyper-V side only adds the tag.

## NIC teaming on the host

### Switch Embedded Teaming (SET)

**SET** builds teaming into the Hyper-V Virtual Switch. It is the **only supported way to team NICs for a Hyper-V virtual switch** on Windows Server 2022 and 2025. The old LBFO team (`New-NetLbfoTeam`) still exists for non-Hyper-V uses, but **you can't bind a Hyper-V switch to an LBFO team** - the attempt fails with an error telling you to use `New-VMSwitch` to create a SET team. (Windows Server 2022 had an unsupported `New-VMSwitch -AllowNetLbfoTeams $true` override; on Windows Server 2025 that parameter is obsolete and ignored.)

```powershell
PS C:\> New-VMSwitch -Name SETswitch -NetAdapterName 'NIC1','NIC2' -EnableEmbeddedTeaming $true -AllowManagementOS $false
PS C:\> Add-VMNetworkAdapter -ManagementOS -Name 'Management' -SwitchName SETswitch
PS C:\> Add-VMNetworkAdapter -ManagementOS -Name 'SMB1' -SwitchName SETswitch
PS C:\> Set-VMSwitchTeam -Name SETswitch -LoadBalancingAlgorithm HyperVPort
PS C:\> Get-VMSwitchTeam -Name SETswitch | Format-List Name, NetAdapterInterfaceDescription, TeamingMode, LoadBalancingAlgorithm
PS C:\> Add-VMSwitchTeamMember -VMSwitchName SETswitch -NetAdapterName 'NIC3'
```

SET rules:

| Property | SET |
|---|---|
| Members | 1 to **8** physical NICs, ideally identical make, model, firmware and speed |
| Teaming mode | **Switch Independent only** - no LACP or static port channels on the physical switch |
| Load balancing | **Hyper-V Port** or **Dynamic** |
| RDMA | Supported - host vNICs can run SMB Direct (RoCE/iWARP) over the team |
| Where | Only as part of a Hyper-V virtual switch |

> **Exam tip:** If the physical switch ports are configured as an LACP port channel, SET members flap or drop traffic - configure the switch ports as independent trunk ports. "Converge management, live migration and SMB Direct storage traffic onto two 25 GbE RDMA NICs" = SET switch plus host vNICs.

### LBFO (NetLbfo) teaming

LBFO supports switch-independent, static and LACP modes with address hash, Hyper-V port and dynamic load balancing, but it **disables RDMA** on its members and can't host a Hyper-V switch on current Windows Server. Use it only for non-virtualised servers that need NIC teaming.

## NIC teaming inside a VM

You may need redundancy for a VM when it is connected to **two different external switches** (for example, two SR-IOV NICs that bypass the switch's own teaming). Steps:

1. On the host: allow teaming on each of the VM's adapters - `Set-VMNetworkAdapter -VMName VM1 -AllowTeaming On`.
2. Connect the two VM adapters to **separate external virtual switches**.
3. In the guest, create an LBFO team in **Switch Independent** mode: `New-NetLbfoTeam -Name GuestTeam -TeamMembers 'Ethernet','Ethernet 2' -TeamingMode SwitchIndependent`.

Without `AllowTeaming`, the host drops traffic from MAC addresses the team presents, and the guest team fails over badly.

## Lab it yourself

1. Create Internal, Private and NAT switches with the commands above and attach a VM to each in turn; test ping between VMs and the host.
2. On a host with two NICs, create a SET switch, add two host vNICs, then unplug one cable and watch `Get-VMSwitchTeam` and continuous ping.
3. Try `New-NetLbfoTeam` and then `New-VMSwitch -NetAdapterName <team>` to see the LBFO error.
4. Tag a VM with VLAN 20 using `Set-VMNetworkAdapterVlan` and confirm with `Get-VMNetworkAdapterVlan`.

## Key takeaways

* External, Internal and Private switches; Internal + `New-NetNat` gives a NAT lab network (one NAT per host).
* Bandwidth mode and SR-IOV are fixed when the switch is created.
* Legacy network adapters exist only on Gen 1; synthetic adapters support PXE on Gen 2 and hot add/remove.
* Know the adapter features: VLAN access/trunk, MAC spoofing, DHCP guard, router guard, port mirroring, bandwidth, device naming, AllowTeaming.
* SET is the only supported teaming for a Hyper-V switch on 2022/2025: 1-8 NICs, Switch Independent only, Hyper-V Port or Dynamic, RDMA-capable. LBFO teams can't host a vSwitch.
* Guest teaming needs `-AllowTeaming On`, adapters on separate external switches, and a Switch Independent team in the guest.
