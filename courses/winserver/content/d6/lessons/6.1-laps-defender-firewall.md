## Windows LAPS

Windows Local Administrator Password Solution (Windows LAPS) is **built into Windows**: Windows Server 2019 and 2022 received it in the April 2023 cumulative updates, and Windows Server 2025 includes it. It replaces legacy Microsoft LAPS (the separate MSI with the `AdmPwd` CSE). Each managed device generates a random password for one local account, backs it up to a directory and rotates it on schedule.

### Choosing where passwords go

| Capability | Back up to AD DS | Back up to Microsoft Entra ID |
|---|---|---|
| Device join type | AD-joined (or hybrid) | Entra joined or Entra hybrid joined |
| Schema extension needed | Yes, `Update-LapsADSchema` once per forest | No |
| Password encryption | Yes, requires **domain functional level 2016** | Always encrypted by the service |
| Password history | Yes (requires encryption) | Yes |
| **DSRM** account on DCs | **Yes (AD only, requires encryption)** | Not supported |
| Who can read | Users/groups you grant, plus the authorized decryptor (default Domain Admins) | Global Administrator, Cloud Device Administrator, Intune Administrator by default, or custom roles |
| Retrieve with | `Get-LapsADPassword`, ADUC LAPS tab | `Get-LapsAADPassword`, Entra/Intune portals |

A device backs up to **one** directory at a time (the **BackupDirectory** setting: Disabled, Entra ID or AD).

### Prepare AD DS

```powershell
PS C:\> Update-LapsADSchema -Verbose
PS C:\> Set-LapsADComputerSelfPermission -Identity "OU=Servers,DC=contoso,DC=com"
PS C:\> Set-LapsADReadPasswordPermission -Identity "OU=Servers,DC=contoso,DC=com" -AllowedPrincipals "CONTOSO\Server Ops"
PS C:\> Set-LapsADResetPasswordPermission -Identity "OU=Servers,DC=contoso,DC=com" -AllowedPrincipals "CONTOSO\Server Ops"
PS C:\> Find-LapsADExtendedRights -Identity "OU=Servers,DC=contoso,DC=com"
```

`Set-LapsADComputerSelfPermission` lets computers in the OU write their own password attributes. Without it, the device logs an error and cannot back up its password.

### Configure policy

Group Policy path: **Computer Configuration > Administrative Templates > System > LAPS**.

| Setting | Default and notes |
|---|---|
| Configure password backup directory | Disabled until you choose AD or Entra ID |
| Password Settings | Complexity 4 (all character classes), length 14, age 30 days. Windows Server 2025 adds complexity **5** (readable characters) and **6-8** (passphrases) |
| Name of administrator account to manage | Blank = built-in Administrator (by well-known RID) |
| Enable password encryption | Enabled by default for AD backup; needs DFL 2016 or later (see the warning below) |
| Configure authorized password decryptors | Default Domain Admins |
| Configure size of encrypted password history | 0 by default; up to 12 |
| Enable password backup for DSRM accounts | Off by default; DCs only; requires encryption |
| Post-authentication actions | Grace period 24 hours; action "reset the password and log off the managed account" |
| Configure automatic account management | Off by default. Windows Server 2025: LAPS creates and manages a custom account (default name `WLapsAdmin`, optionally with a random suffix) or the built-in Administrator |

> **Watch out:** If the domain is below DFL 2016 and the policy requires encryption, the device logs event **10006** and does not update the password. Raise the DFL or disable encryption (clear-text storage, protected only by ACLs, is not recommended).

> **Exam tip:** "Back up the DSRM password of each domain controller" = Windows LAPS with **AD** backup, **encryption enabled** and **Enable password backup for DSRM accounts**, on Windows Server 2019 or later DCs. Entra ID backup is never the answer for DSRM.

### Retrieve and rotate

```powershell
PS C:\> Get-LapsADPassword -Identity SRV01 -AsPlainText
PS C:\> Get-LapsADPassword -Identity DC1.contoso.com -AsPlainText
PS C:\> Get-LapsADPassword -Identity SRV01 -AsPlainText -IncludeHistory
PS C:\> Set-LapsADPasswordExpirationTime -Identity SRV01
PS C:\> Reset-LapsPassword
PS C:\> Invoke-LapsPolicyProcessing
```

- Without `-AsPlainText` the password comes back as a SecureString.
- The `Source` field tells you what you got: `CleartextPassword`, `EncryptedPassword`, `EncryptedPasswordHistory` or `EncryptedDSRMPassword`. `DecryptionStatus : Unauthorized` means you can read the attribute but are not an authorized decryptor.
- `Set-LapsADPasswordExpirationTime` (run by an admin) marks the password expired so the device rotates it at its next policy cycle (hourly). `Reset-LapsPassword` (run **on** the device) rotates immediately.
- `-Port` lets `Get-LapsADPassword` query an AD backup mounted with `dsamain`; newer builds add `-RecoveryMode` so the query works without contacting any DC.

Events are in **Applications and Services Logs > Microsoft > Windows > LAPS > Operational**.

> **Real world:** Legacy LAPS and Windows LAPS can run side by side only if they manage **different** accounts. Plan a cutover per OU and use legacy emulation mode only as a stepping stone.

## Microsoft Defender for Servers

Defender for Servers is a paid plan of **Microsoft Defender for Cloud**. It protects Azure VMs, Azure Arc-enabled servers (on-premises or other clouds) and AWS/GCP machines.

| Feature | Plan 1 | Plan 2 |
|---|---|---|
| Microsoft Defender for Endpoint integration (EDR, automatic onboarding) | Yes | Yes |
| Core vulnerability assessment (Defender Vulnerability Management) | Yes | Yes |
| Premium Defender Vulnerability Management (security baselines assessment, block vulnerable apps, and more) | No | Yes |
| Agentless scanning (vulnerabilities, malware, secrets) | No | Yes |
| **File integrity monitoring** | No | Yes |
| **Just-in-time VM access** | No | Yes (Azure and AWS VMs) |
| Regulatory compliance assessment | Yes | Yes |
| OS baseline misconfiguration assessment against the Microsoft cloud security benchmark (needs the Azure Machine Configuration extension) | No | Yes |
| 500 MB per day free Log Analytics data ingestion per server | No | Yes |
| Can be enabled per resource | Yes | No (subscription level; can be disabled per resource) |

### Onboarding on-premises servers

1. Onboard the server to **Azure Arc** (Connected Machine agent).
2. Enable Defender for Servers on the subscription that holds the Arc resources.
3. Defender for Cloud deploys the Defender for Endpoint extension (MDE.Windows) automatically.

Servers onboarded directly to Defender for Endpoint **without** Azure Arc get only Plan 1 functionality (plus premium Defender Vulnerability Management when Plan 2 is enabled). Features such as FIM and the MCSB OS baseline assessment need the server to be an Azure Arc resource.

```powershell
PS C:\> Set-AzSecurityPricing -Name "VirtualMachines" -PricingTier "Standard" -SubPlan "P2"
PS C:\> Get-AzSecurityPricing -Name "VirtualMachines" | Select-Object Name, PricingTier, SubPlan
```

> **Exam tip:** Requirements that mention **file integrity monitoring**, **just-in-time VM access**, **agentless scanning** or the **500 MB ingestion benefit** need **Plan 2**. Regulatory compliance assessment is available with either plan. "EDR only, lowest cost, enable on selected servers" points to **Plan 1**.

## Windows Firewall

### Profiles and defaults

| Profile | Applies when |
|---|---|
| Domain | The adapter can authenticate to a DC of the computer's domain |
| Private | The user or admin marked the network as private |
| Public | Everything else (the most restrictive default) |

Default behaviour on all profiles: **block inbound** that no rule allows, **allow outbound**. Rules are evaluated so that **block rules beat allow rules**, except an **Allow the connection if it is secure** rule with **Override block rules** selected, which wins for authenticated IPsec traffic.

```powershell
PS C:\> Get-NetFirewallProfile | Format-Table Name, Enabled, DefaultInboundAction, DefaultOutboundAction, LogBlocked
PS C:\> New-NetFirewallRule -DisplayName "SQL from App subnet" -Direction Inbound -Protocol TCP -LocalPort 1433 -RemoteAddress 10.10.20.0/24 -Profile Domain -Action Allow
PS C:\> Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
PS C:\> Set-NetFirewallProfile -Profile Domain,Private,Public -LogBlocked True -LogFileName "%systemroot%\system32\LogFiles\Firewall\pfirewall.log"
```

In a GPO (**Computer Configuration > Policies > Windows Settings > Security Settings > Windows Defender Firewall with Advanced Security**), the profile **Customize > Rule merging > Apply local firewall rules: No** makes the server ignore rules that local administrators create, so only GPO rules apply.

### Connection security rules (IPsec)

Firewall rules decide **whether** traffic is allowed; **connection security rules** decide **how** traffic must be authenticated (and optionally encrypted) using IPsec.

| Rule type | Use |
|---|---|
| Isolation | Domain or server isolation: require authentication based on domain membership or health |
| Authentication exemption | Hosts that must be reachable without IPsec (DCs, DHCP, DNS, gateways) |
| Server-to-server | Protect traffic between two sets of endpoints |
| Tunnel | Gateway-to-gateway tunnel mode |
| Custom | Anything else |

Authentication requirement options: **Request inbound and outbound** (try IPsec, fall back to clear text), **Require inbound and request outbound** (typical isolation setting), **Require inbound and outbound**. First authentication defaults to **computer Kerberos v5**; you can add computer certificates (for non-domain devices) and second authentication with user Kerberos. Pre-shared keys are supported but weak.

```powershell
PS C:\> New-NetIPsecRule -DisplayName "Domain isolation" -InboundSecurity Require -OutboundSecurity Request -PolicyStore "contoso.com\Domain Isolation"
PS C:\> New-NetFirewallRule -DisplayName "SQL only from authenticated app servers" -Direction Inbound -Protocol TCP -LocalPort 1433 -Authentication Required -Encryption Required -RemoteMachine "D:(A;;CC;;;S-1-5-21-1004336348-1177238915-682003330-2104)" -Action Allow
PS C:\> Get-NetIPsecMainModeSA
PS C:\> Get-NetIPsecQuickModeSA
```

The second command is the PowerShell form of **Allow the connection if it is secure** restricted to authorized computers (the SDDL names the AppServers group by SID). It only works if a connection security rule makes the traffic use IPsec.

IPsec needs **UDP 500** (IKE/AuthIP), **UDP 4500** (NAT traversal) and IP protocol **50** (ESP) between endpoints.

> **Watch out:** Exempt infrastructure servers (DCs, DNS, DHCP) from isolation rules that require inbound authentication, otherwise clients cannot obtain the Kerberos ticket they need to authenticate in the first place.

## Lab it yourself

In a two-VM lab (DC1 and SRV01, Windows Server 2025 evaluation):

```powershell
PS C:\> Update-LapsADSchema
PS C:\> Set-LapsADComputerSelfPermission -Identity "OU=Servers,DC=contoso,DC=com"
```

Create a GPO linked to the Servers OU: Configure password backup directory = Active Directory, Enable password encryption = Enabled. On SRV01 run `Invoke-LapsPolicyProcessing`, then on DC1 run `Get-LapsADPassword SRV01 -AsPlainText`. For the firewall, create the SQL-style rule above with a different port and test from each VM with `Test-NetConnection SRV01 -Port 1433`.

## Key takeaways

- Windows LAPS is in-box; AD backup needs `Update-LapsADSchema` and `Set-LapsADComputerSelfPermission`.
- Encryption needs DFL 2016; history and DSRM backup need encryption; DSRM backup is AD-only.
- `Get-LapsADPassword -AsPlainText` reads; `Set-LapsADPasswordExpirationTime` schedules rotation; `Reset-LapsPassword` rotates now on the device.
- Defender for Servers Plan 2 adds FIM, JIT, agentless scanning, the MCSB OS baseline assessment and the 500 MB ingestion benefit; Plan 1 is MDE-focused and can be enabled per resource.
- Onboard on-premises servers through Azure Arc for full Defender for Servers functionality.
- Firewall: block beats allow unless an authenticated rule overrides block rules; "Apply local firewall rules: No" ignores local rules.
- Connection security rules (IPsec) authenticate traffic; pair them with "allow if secure" firewall rules to restrict by computer or user.
