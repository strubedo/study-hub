## The DHCP conversation in one paragraph

A client with no address broadcasts **DHCPDISCOVER** from UDP 68 to UDP 67. Servers that have a matching scope reply with **DHCPOFFER**, the client broadcasts **DHCPREQUEST** naming the offer it accepts, and the chosen server confirms with **DHCPACK** (or refuses with DHCPNAK). The client renews directly with its server at **T1 (50 percent of the lease)** and, if that fails, broadcasts to any server at **T2 (87.5 percent)**. Routers do not forward broadcasts, so remote subnets need a **DHCP relay agent** (`ip helper-address` on a router, or the Routing role on Windows) that unicasts the request to the server and fills in the **giaddr** field. The server uses giaddr to pick the scope.

## Install, authorize and secure the role

```powershell
PS C:\> Install-WindowsFeature DHCP -IncludeManagementTools
PS C:\> Add-DhcpServerSecurityGroup
PS C:\> Restart-Service DHCPServer
PS C:\> Add-DhcpServerInDC -DnsName "dhcp1.contoso.com" -IPAddress 10.1.0.5
PS C:\> Get-DhcpServerInDC
PS C:\> Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\ServerManager\Roles\12" -Name ConfigurationState -Value 2
```

- `Add-DhcpServerSecurityGroup` creates the local **DHCP Administrators** and **DHCP Users** groups so you can delegate management without granting local Administrator.
- **Authorization** is an AD DS check that stops rogue servers. The list of authorized servers is stored in the forest **configuration partition**, so authorizing needs **Enterprise Admins** rights (or delegated rights on that container). A domain-member DHCP server that is not authorized will not lease addresses.
- The last command only clears the Server Manager "post-deployment configuration" warning after you authorize from PowerShell.

> **Watch out:** A standalone (workgroup) DHCP server cannot be authorized. It leases addresses until it detects an authorized Windows DHCP server on the same subnet, then stops. That is why rogue detection is most effective in AD environments.

## Scopes and exclusions

A **scope** is the pool for one subnet: a start and end range, a mask, a lease duration and options.

```powershell
PS C:\> Add-DhcpServerv4Scope -Name "Floor1" -StartRange 10.1.10.1 -EndRange 10.1.10.254 -SubnetMask 255.255.255.0 -LeaseDuration 8.00:00:00 -State Active
PS C:\> Add-DhcpServerv4ExclusionRange -ScopeId 10.1.10.0 -StartRange 10.1.10.1 -EndRange 10.1.10.19
PS C:\> Set-DhcpServerv4OptionValue -ScopeId 10.1.10.0 -Router 10.1.10.1
PS C:\> Set-DhcpServerv4OptionValue -DnsServer 10.1.0.10, 10.1.0.11 -DnsDomain "contoso.com"
PS C:\> Get-DhcpServerv4ScopeStatistics -ScopeId 10.1.10.0
```

The default lease duration for a new scope is **8 days**. Short leases (hours) suit guest Wi-Fi with high churn; long leases suit stable wired networks. The scope ID is the network address, derived from the start range and mask.

### Option levels and precedence

Options can be set at several levels. The most specific one wins:

| Level (lowest to highest precedence) | Example |
|---|---|
| Server options | DNS servers (006) and domain name (015) used everywhere |
| Server-level policy options | Different DNS for a vendor class across all scopes |
| Scope options | Router (003) for that subnet |
| Scope-level policy options | Different gateway for VoIP phones in that scope |
| Reservation options | A unique option for one printer |

Common options: **003** Router, **006** DNS Servers, **015** DNS Domain Name, **044/046** WINS, **066/067** boot server and file name for PXE, **119** domain search list.

> **Exam tip:** "Configure the DNS servers for every scope with the least effort" means **server options**. "Only for one subnet" means scope options. "Only for one device" means reservation options.

## Reservations

A reservation guarantees that a specific client always gets the same address, while still receiving options from DHCP. Clients are identified by MAC address for DHCPv4 (or client ID; DUID plus IAID for DHCPv6).

```powershell
PS C:\> Add-DhcpServerv4Reservation -ScopeId 10.1.10.0 -IPAddress 10.1.10.50 -ClientId "00-15-5D-0A-14-32" -Name "PRN-Floor1" -Description "Floor 1 printer"
PS C:\> Get-DhcpServerv4Lease -ScopeId 10.1.10.0 -IPAddress 10.1.10.77 | Add-DhcpServerv4Reservation
PS C:\> Set-DhcpServerv4OptionValue -ReservedIP 10.1.10.50 -OptionId 66 -Value "10.1.0.40"
PS C:\> Get-DhcpServerv4Reservation -ScopeId 10.1.10.0
```

Piping an existing lease into `Add-DhcpServerv4Reservation` converts the lease to a reservation with the same IP and MAC, which is the least-effort way to "freeze" a device's current address.

> **Watch out:** In a failover relationship, reservations are part of the scope configuration. After adding them on one partner, replicate the scope (`Invoke-DhcpServerv4FailoverReplication`) or the partner will not know about them.

> **Real world:** If a device is configured with a static IP inside the scope range instead of a reservation, the server may lease that address to someone else. Enable **conflict detection** (`Set-DhcpServerSetting -ConflictDetectionAttempts 1`) so the server pings before offering, and prefer reservations or exclusions for fixed devices.

## Superscopes, multicast scopes and DHCPv6

A **superscope** groups several scopes that serve the **same physical network segment**, for example when you add a second subnet (multinet) to a VLAN that ran out of addresses. The server can then answer clients on that segment from any member scope.

```powershell
PS C:\> Add-DhcpServerv4Superscope -SuperscopeName "Building2" -ScopeId 10.2.10.0, 10.2.11.0
PS C:\> Get-DhcpServerv4Superscope
```

| Feature | Use |
|---|---|
| Superscope | Multiple logical subnets on one physical segment (multinet) |
| Multicast scope | MADCAP allocation from 224.0.0.0/4 to multicast applications (`Add-DhcpServerv4MulticastScope`) |
| DHCPv6 stateful scope | Leases IPv6 addresses (`Add-DhcpServerv6Scope -Prefix 2001:db8:10:: -Name V6Floor1`) when the router sets the M flag |
| DHCPv6 stateless | Options only (DNS servers, domain) when the router sets the O flag and clients use SLAAC |

## DHCP policies

Policies assign different ranges or options to groups of clients in the same scope, based on conditions such as **vendor class**, **user class**, **MAC address** (wildcards allowed), **client ID**, **FQDN** or **relay agent information**.

```powershell
PS C:\> Add-DhcpServerv4Policy -Name "HyperVVMs" -ScopeId 10.1.10.0 -Condition OR -MacAddress EQ,00155D*
PS C:\> Add-DhcpServerv4PolicyIPRange -Name "HyperVVMs" -ScopeId 10.1.10.0 -StartRange 10.1.10.200 -EndRange 10.1.10.239
PS C:\> Set-DhcpServerv4OptionValue -ScopeId 10.1.10.0 -PolicyName "HyperVVMs" -DnsServer 10.1.0.12
```

Policies are processed by processing order; the first matching policy applies its range, and its options override scope options.

## Filters

MAC **allow** and **deny** filters (`Add-DhcpServerv4Filter -List Deny -MacAddress 00-11-22-33-44-55`) are server-wide. Enabling the allow list (`Set-DhcpServerv4FilterList -Allow $true`) means only listed MACs get addresses. Filters are a convenience, not a security boundary; MACs are easy to spoof.

## DNS integration

| Setting | Effect |
|---|---|
| Dynamically update only if requested by clients (default) | Windows clients register their A record; the server registers the PTR |
| Always dynamically update | The server registers both A and PTR and owns them |
| Update for clients that do not request updates | Needed for non-Windows devices that never register themselves |
| Discard records when lease is deleted | Removes A/PTR when the lease expires or is deleted |
| Name Protection | Uses DHCID records so a non-Windows device cannot overwrite a Windows computer's name |

```powershell
PS C:\> Set-DhcpServerv4DnsSetting -DynamicUpdates Always -DeleteDnsRROnLeaseExpiry $true -UpdateDnsRRForOlderClients $true
PS C:\> Set-DhcpServerDnsCredential -Credential (Get-Credential CONTOSO\svc-dhcpdns)
PS C:\> Set-DhcpServerv4DnsSetting -ScopeId 10.1.10.0 -NameProtection $true
```

Use a dedicated low-privilege account for DNS registration on **all** DHCP servers (especially failover partners) so either server can update records the other created.

## Backup and migration

The database lives in `%SystemRoot%\System32\dhcp`. The service makes an automatic backup every 60 minutes to the `backup` subfolder. For moves or rebuilds:

```powershell
PS C:\> Export-DhcpServer -ComputerName OLDDHCP -File C:\Temp\dhcp.xml -Leases
PS C:\> Import-DhcpServer -ComputerName DHCP1 -File C:\Temp\dhcp.xml -BackupPath C:\Temp\DhcpBackup -Leases
PS C:\> Backup-DhcpServer -Path C:\DhcpBackup
```

## Lab it yourself

On a Hyper-V host, create an internal switch, a Windows Server 2025 VM (DHCP1) joined to your lab domain and a client VM on the same switch:

```powershell
PS C:\> Install-WindowsFeature DHCP -IncludeManagementTools
PS C:\> Add-DhcpServerInDC
PS C:\> Add-DhcpServerv4Scope -Name Lab -StartRange 192.168.100.50 -EndRange 192.168.100.150 -SubnetMask 255.255.255.0
PS C:\> Set-DhcpServerv4OptionValue -ScopeId 192.168.100.0 -Router 192.168.100.1 -DnsServer 192.168.100.10
```

On the client run `ipconfig /release` and `ipconfig /renew`, then convert its lease to a reservation with the pipeline shown above.

## Key takeaways

- DORA uses UDP 67/68; remote subnets need a relay agent, and the server picks the scope from giaddr.
- Authorize domain DHCP servers in AD DS; authorization needs Enterprise Admins rights.
- Option precedence: server, server policy, scope, scope policy, reservation (most specific wins).
- Default lease is 8 days; clients renew at 50 and 87.5 percent.
- Convert a lease to a reservation by piping `Get-DhcpServerv4Lease` into `Add-DhcpServerv4Reservation`.
- Superscopes serve multiple subnets on one physical segment.
- Use a shared DNS-update credential and Name Protection for clean DNS records.
