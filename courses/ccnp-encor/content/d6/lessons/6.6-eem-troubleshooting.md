## Why EEM is a troubleshooting tool

Intermittent faults are the hardest to fix because the evidence is gone by the time someone logs in: the interface has come back, the neighbour has re-formed, the CPU is quiet again. An EEM applet sits on the device and captures the state **at the moment** the problem happens, or takes a first corrective step immediately. This lesson builds troubleshooting applets on the building blocks from the previous lesson (one event, actions in label order, `enable` first).

## Pattern 1: capture state when a log message appears

An OSPF neighbour drops every few days. Capture what the router saw at that instant:

```text
event manager applet OSPF-DOWN-CAPTURE
 event syslog pattern "%OSPF-5-ADJCHG.*from FULL to DOWN"
 action 1.0 cli command "enable"
 action 1.1 cli command "show clock | append flash:ospf-down.txt"
 action 1.2 cli command "show ip ospf neighbor | append flash:ospf-down.txt"
 action 1.3 cli command "show interfaces GigabitEthernet0/0/1 | append flash:ospf-down.txt"
 action 1.4 cli command "show ip ospf interface brief | append flash:ospf-down.txt"
 action 1.5 syslog msg "OSPF adjacency lost; state saved to flash:ospf-down.txt"
```

- **`event syslog pattern`** takes a regular expression matched against the whole message. `.*` matches anything, so this catches the adjacency change for any neighbour and reason. Make patterns specific enough not to match unrelated messages, and remember that the applet's own `syslog` action produces a message too: a pattern that matches it causes a loop.
- **`| append flash:FILE`** adds the output to a file on flash (`| redirect` overwrites instead). Each run appends a new block, so the file grows: watch flash space and clean it up.
- `$_syslog_msg` holds the triggering message, so `action 1.6 syslog msg "Captured after: $_syslog_msg"` records exactly which neighbour went down.

`occurs` and `period` turn a single event into a rate: `event syslog pattern "%LINK-3-UPDOWN.*GigabitEthernet0/0/1.*down" occurs 3 period 60` fires only on the third down within 60 seconds, which is how you catch a flapping link without reacting to a single planned shutdown.

## Pattern 2: react to a tracked object

```text
track 20 ip sla 20 reachability
!
event manager applet SLA20-LOSS
 event track 20 state down
 action 1.0 cli command "enable"
 action 2.0 cli command "show ip sla statistics 20 | append flash:sla20.txt"
 action 3.0 cli command "traceroute 198.51.100.10 numeric timeout 1 probe 1 | append flash:sla20.txt"
 action 4.0 syslog priority errors msg "IP SLA 20 lost reachability; traceroute saved"
```

Tracking (topic 4.4) turns a probe result into an up or down state; EEM turns the state change into evidence. A traceroute taken at the moment of failure often shows exactly which hop stopped answering.

## Pattern 3: decide inside the applet

Use `if` to act only when a condition holds. The applet below runs when Gi0/0/1 goes down, checks whether the backup route is in the table, and logs the result.

```text
event manager applet CHECK-BACKUP
 event syslog pattern "%LINEPROTO-5-UPDOWN.*GigabitEthernet0/0/1.*down"
 action 1.0 cli command "enable"
 action 2.0 cli command "show ip route 0.0.0.0"
 action 3.0 regexp "203\.0\.113\.5" "$_cli_result"
 action 4.0 if $_regexp_result eq "1"
 action 5.0  syslog msg "Primary down; backup default via 203.0.113.5 in use"
 action 6.0 else
 action 7.0  syslog priority critical msg "Primary down and NO backup default route"
 action 8.0 end
```

`regexp` sets `$_regexp_result` to 1 on a match and 0 otherwise. Action 2.0 deliberately has no `| include via` filter: for a static route the next hop appears on a line of its own (`* 203.0.113.5`), and only the `Known via "static"` line contains the word `via`, so the filter would hide the address the regexp looks for. The spaces before `syslog` in 5.0 and 7.0 are only for readability. `if` compares strings or numbers with `eq`, `ne`, `gt`, `ge`, `lt`, `le`.

## Pattern 4: watch a counter

```text
event manager applet INPUT-ERRORS
 event interface name GigabitEthernet0/0/1 parameter input_errors entry-op ge entry-val 100 entry-type increment poll-interval 60
 action 1.0 cli command "enable"
 action 2.0 cli command "show interfaces GigabitEthernet0/0/1 | append flash:gi001-errors.txt"
 action 3.0 cli command "show controllers GigabitEthernet0/0/1 | append flash:gi001-errors.txt"
 action 4.0 syslog msg "Gi0/0/1: 100+ new input errors in 60 s"
```

`entry-type increment` compares the **increase** since the last poll with the value, so this fires on 100 new errors in a poll interval, not on an old total.

## Pattern 5: stop a dangerous command

```text
event manager applet BLOCK-WRITE-ERASE
 event cli pattern "write erase|erase (startup|nvram)" sync no skip yes
 action 1.0 syslog priority alerts msg "write erase / erase startup attempted and blocked by EEM"
```

With `sync no skip yes`, a matching command is **not executed** and the applet logs the attempt. Test the pattern with the abbreviations people actually type. This is a guard rail, not security: anyone with privilege 15 can remove the applet. Real control belongs in AAA command authorization (topic 5.1).

## Troubleshooting the applet itself

When an applet does not do what you expect, work through these in order:

| Symptom | Check | Likely cause |
|---|---|---|
| Never runs | `show event manager policy registered` | The applet is not registered (no `event` line, or a syntax error in it) |
| Never runs, but registered | `show event manager history events`, and the exact log text | The syslog pattern does not match the real message (case, spacing, interface name format) |
| Runs, commands fail | `debug event manager action cli` | No `enable` action, or a command typed wrong; the debug shows the device's `% Invalid input` reply |
| Runs, commands fail only with TACACS+ | Debug shows authorization failures | AAA command authorization: add `event manager session cli username` or `authorization bypass` |
| Runs in the wrong order | `show running-config \| section event manager` | Labels sorted as strings (`10.0` before `2.0`) |
| Stops part-way | Long commands or waits | The applet exceeded its maximum run time; raise it with `maxrun` on the event line |
| Runs over and over | Log | The applet's own syslog message matches its pattern |

```text
R1# debug event manager action cli
Debug EEM action cli debugging is on
R1# event manager run TEST-SHOW
%HA_EM-6-LOG: TEST-SHOW : DEBUG(cli_lib) : : CTL : cli_open called.
%HA_EM-6-LOG: TEST-SHOW : DEBUG(cli_lib) : : OUT : R1>
%HA_EM-6-LOG: TEST-SHOW : DEBUG(cli_lib) : : IN  : R1>show running-config | include hostname
%HA_EM-6-LOG: TEST-SHOW : DEBUG(cli_lib) : : OUT :                                 ^
%HA_EM-6-LOG: TEST-SHOW : DEBUG(cli_lib) : : OUT : % Invalid input detected at '^' marker.
```

The `R1>` prompt is the clue: the session is still in user EXEC because the applet has no `enable` action, so `show running-config` is rejected.

## Lab it yourself

Use two Catalyst 8000V routers running OSPF in Cisco Modeling Labs, GNS3 or EVE-NG on Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a Cisco DevNet IOS XE sandbox.

1. Build `OSPF-DOWN-CAPTURE`, shut the neighbour's interface, then `more flash:ospf-down.txt`.
2. Change the pattern to something that cannot match (a typo in `ADJCHG`) and confirm with `show event manager history events` that nothing ran.
3. Build `CHECK-BACKUP` with and without a floating static default route and read which message it logs.
4. Build a `TEST-SHOW` applet with `event none sync yes` and no `enable`, run it with `debug event manager action cli` on, then add `enable` and compare.
5. Build `BLOCK-WRITE-ERASE`, type `write erase` and confirm it did not run (`dir nvram:` still shows `startup-config`).

## Key takeaways

- Troubleshooting applets capture evidence at the moment of failure: trigger on `syslog pattern`, `track`, or an `interface` counter, run `show` commands, write to flash with `| append flash:FILE`.
- `occurs N period S` fires on repeated messages; `entry-type increment` watches the change in a counter.
- `regexp` sets `$_regexp_result`; `if` / `else` / `end` branch on it or on `$_cli_result`.
- `event cli pattern ... sync no skip yes` blocks a command and logs the attempt; it is not a substitute for AAA.
- Debug applets with `show event manager policy registered`, `show event manager history events` and `debug event manager action cli`; a `>` prompt in the debug means the `enable` action is missing.
- Do not let an applet's own syslog message match its own pattern.
