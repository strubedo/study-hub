## Collecting data on a schedule or a threshold

The third job in topic 6.6 is **data collection**: gather command output regularly, or when a value crosses a threshold, and keep it on the device or send it somewhere. The building blocks are the timer and SNMP detectors, `cli command` actions with output redirection, `mail`, and `event none` for collection on demand.

## Timers

| Timer | Example | Runs |
|---|---|---|
| `watchdog` | `event timer watchdog time 900` | Every 900 seconds, starting 900 seconds after registration, repeating |
| `cron` | `event timer cron cron-entry "30 1 * * *"` | At 01:30 every day |
| `countdown` | `event timer countdown time 300` | Once, 300 seconds after registration (re-registers only if the applet is re-entered) |
| `absolute` | `event timer absolute time ...` | Once at a set time |

A cron entry has five fields: **minute, hour, day of month, month, day of week** (0 is Sunday). `"0 8 * * 1-5"` is 08:00 Monday to Friday; `"0,15,30,45 * * * *"` is every quarter-hour. Cron timers use the device clock, so the clock (and NTP, topic 3.3) must be right, and a time zone set with `clock timezone` changes when the job runs.

> **Exam tip:** **Watchdog** repeats on an interval, **countdown** fires once after a delay, **cron** follows a calendar. If the requirement says "every night at 02:00", the answer is cron, not a watchdog of 86,400 seconds (which drifts with every reload).

## A nightly collection to flash

```text
event manager applet NIGHTLY-SNAPSHOT
 event timer cron cron-entry "0 2 * * *"
 action 1.0 cli command "enable"
 action 1.1 cli command "show clock | append flash:nightly.txt"
 action 1.2 cli command "show ip interface brief | append flash:nightly.txt"
 action 1.3 cli command "show ip route summary | append flash:nightly.txt"
 action 1.4 cli command "show processes cpu sorted 5min | append flash:nightly.txt"
 action 1.5 syslog msg "Nightly snapshot appended to flash:nightly.txt"
```

- `show clock` first stamps each block with the time, because `| append` writes only the command output.
- **`| append flash:FILE`** adds to the end of the file; **`| redirect flash:FILE`** replaces it. Use `redirect` for "latest copy only", `append` for history, and plan to delete or archive the file (`delete /force flash:nightly.txt` in another applet, or copy it off with `copy flash:nightly.txt scp:` from a management station).
- On a Catalyst 9000 switch the file system is `flash:`; on routers it may be `bootflash:` (where `flash:` is usually an alias). Check with `dir`.

Reading it back: `more flash:nightly.txt`.

## Collection on demand

`event none` makes an applet a saved macro: it runs only when someone types `event manager run NAME`. With `sync yes`, the CLI waits until the applet finishes, and `puts` prints to that user's terminal.

```text
event manager applet HEALTH
 event none sync yes
 action 1.0 cli command "enable"
 action 2.0 cli command "show version | include uptime|Software,"
 action 3.0 puts "$_cli_result"
 action 4.0 cli command "show ip ospf neighbor"
 action 5.0 puts "$_cli_result"
```

```text
R1# event manager run HEALTH
```

The output of each `show` command appears in the terminal, one after the other. The same applet with a `mail` action instead of `puts` becomes a "send me the health report" button.

## Collecting when a threshold is crossed

**SNMP detector.** EEM can poll the device's own MIB objects. The 1-minute CPU utilisation is `cpmCPUTotal1minRev` in CISCO-PROCESS-MIB, OID `1.3.6.1.4.1.9.9.109.1.1.1.1.7`, followed by the instance index of the CPU entry (often `.1`; confirm it on your platform with an SNMP walk):

```text
event manager applet HIGH-CPU
 event snmp oid 1.3.6.1.4.1.9.9.109.1.1.1.1.7.1 get-type exact entry-op ge entry-val 80 poll-interval 30
 action 1.0 cli command "enable"
 action 2.0 cli command "show clock | append flash:high-cpu.txt"
 action 3.0 cli command "show processes cpu sorted | append flash:high-cpu.txt"
 action 4.0 cli command "show processes cpu history | append flash:high-cpu.txt"
 action 5.0 syslog priority warnings msg "CPU >= 80% (1 min); process list saved to flash:high-cpu.txt"
```

`entry-op ge entry-val 80` means "fire when the value is 80 or more"; `poll-interval 30` reads the OID every 30 seconds. SNMP must be enabled on the device for the detector to read it.

**Interface detector** (`event interface ... parameter ... entry-op ... entry-val ...`) does the same for interface counters such as `input_errors`, `output_drops` or `txload`; see the troubleshooting lesson.

## Sending data off the box

**Email:**

```text
event manager environment _email_server 192.0.2.25
event manager environment _email_to noc@example.com
event manager environment _email_from r1@example.com
!
event manager applet MAIL-INVENTORY
 event timer cron cron-entry "0 7 * * 1"
 action 1.0 cli command "enable"
 action 2.0 cli command "show inventory"
 action 3.0 mail server "$_email_server" to "$_email_to" from "$_email_from" subject "Weekly inventory: R1" body "$_cli_result"
```

`event manager environment NAME VALUE` defines global variables that every applet can use, so the mail server is set in one place. The router must reach the SMTP server (port 25, no authentication in the basic action), so this suits an internal relay.

**Other ways out:** a `syslog` action with the key line (collected by your syslog server, topic 4.1); `cli command "copy flash:nightly.txt tftp://192.0.2.50/r1-nightly.txt"` with a `pattern` to answer the prompts; or simply leave the files on flash and collect them with your automation tools.

## Keeping collection safe

| Risk | Mitigation |
|---|---|
| Flash fills up | `redirect` instead of `append`, or a weekly applet that deletes the file; check `dir` free space |
| Applet killed before it finishes | Long `show` commands can exceed the default maximum run time; add `maxrun` (seconds) on the event line |
| CPU load from frequent polling | Poll every 30 to 60 seconds, not every second; collect only what you need |
| Applet runs as a user that AAA rejects | `event manager session cli username` or `authorization bypass` |
| Many copies running at once | A watchdog shorter than the applet's run time stacks runs: make the interval longer than the work |

## Verifying

```text
R1# show event manager policy registered
No.  Class     Type    Event Type          Trap  Time Registered           Name
1    applet    user    timer cron          Off   Mon Nov 23 09:12:40 2026  NIGHTLY-SNAPSHOT
 cron entry {0 2 * * *}
 maxrun 20.000
 action 1.0 cli command "enable"
 ...
```

`show event manager history events` lists each run with its time and event type; `more flash:FILE` shows what was collected.

## Lab it yourself

Use a Catalyst 8000V (or a Catalyst 9000v switch) in Cisco Modeling Labs, GNS3 or EVE-NG on Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a Cisco DevNet IOS XE sandbox. Set the clock or NTP first.

1. Build `NIGHTLY-SNAPSHOT` with a cron entry two minutes ahead of the current time; after it runs, `more flash:nightly.txt`. Change `append` to `redirect` for one command and compare after two runs.
2. Build `HEALTH` and run it with `event manager run HEALTH`.
3. Enable SNMP, find the CPU instance with an SNMP walk of `1.3.6.1.4.1.9.9.109.1.1.1.1.7`, build `HIGH-CPU` with `entry-val 1` so it fires, and read `flash:high-cpu.txt`.
4. If you have a lab SMTP relay (any small mail server on a Linux VM), build `MAIL-INVENTORY` with a cron entry a few minutes ahead and check the mailbox.
5. Compare `show event manager history events` before and after each test.

## Key takeaways

- Timers: `watchdog` repeats every N seconds, `countdown` fires once after N seconds, `cron` follows a five-field calendar (minute hour day month weekday), `absolute` fires once at a set time.
- Collect with `cli command "show ... | append flash:FILE"` (history) or `| redirect flash:FILE` (latest only); stamp each block with `show clock`.
- `event none sync yes` plus `event manager run NAME` and `puts` makes an on-demand report.
- `event snmp oid ... entry-op ge entry-val N poll-interval S` collects when a MIB value crosses a threshold (1-minute CPU is `cpmCPUTotal1minRev`, 1.3.6.1.4.1.9.9.109.1.1.1.1.7 plus the index).
- Send data out with `mail` (using `event manager environment` variables), `syslog`, or `copy` to a server.
- Watch flash space, run time (`maxrun`) and polling load.
