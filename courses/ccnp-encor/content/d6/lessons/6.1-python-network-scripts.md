## Reading a script the exam way

Network automation scripts follow the same shape: **import** a library, define the **target and credentials**, **connect or send a request**, check the **result**, and **parse** the reply into Python objects to loop over. When you meet one in a question, read it in that order and answer three things: which protocol and port it uses, what it sends, and what it prints for the data given. The three libraries the exam expects you to recognise are `requests` (HTTP REST APIs, such as Catalyst Center and RESTCONF), `ncclient` (NETCONF) and Netmiko (SSH to the CLI).

| Library | Talks to | Transport | You send | You get back |
|---|---|---|---|---|
| `requests` | REST APIs: Catalyst Center, SD-WAN Manager, RESTCONF | HTTPS, TCP 443 by default | HTTP method, URL, headers, JSON body | A response object: `.status_code`, `.headers`, `.text`, `.json()` |
| `ncclient` | NETCONF servers (IOS XE `netconf-yang`) | SSH, TCP 830 | RPCs: `get`, `get_config`, `edit_config`, `lock`, `commit` | XML `rpc-reply` |
| Netmiko | Device CLI | SSH, TCP 22 | CLI commands as text | The CLI output as one string |

None of the scripts below can run without a device or controller, so each was only compiled with Python 3; the data-handling part of the first one was run against a sample body to confirm its output.

## A requests script against Catalyst Center

```python
import requests
from requests.auth import HTTPBasicAuth

CC = "https://cc.example.com"
USER = "apiuser"
PASSWORD = "ExamplePass123"          # example only: never hard-code real credentials


def get_token():
    url = f"{CC}/dna/system/api/v1/auth/token"
    resp = requests.post(url, auth=HTTPBasicAuth(USER, PASSWORD), verify=False, timeout=15)
    resp.raise_for_status()
    return resp.json()["Token"]


def get_devices(token, family=None):
    headers = {"X-Auth-Token": token, "Accept": "application/json"}
    params = {"family": family} if family else {}
    url = f"{CC}/dna/intent/api/v1/network-device"
    resp = requests.get(url, headers=headers, params=params, verify=False, timeout=15)
    if resp.status_code != 200:
        print("Request failed:", resp.status_code, resp.text)
        return []
    return resp.json()["response"]


def main():
    token = get_token()
    for dev in get_devices(token, family="Switches and Hubs"):
        if dev["reachabilityStatus"] != "Reachable":
            print(f"{dev['hostname']:<10} {dev['managementIpAddress']:<12} {dev['reachabilityStatus']}")


if __name__ == "__main__":
    main()
```

Line by line:

- `requests.post(url, auth=HTTPBasicAuth(...))` sends `POST /dna/system/api/v1/auth/token` with an HTTP Basic `Authorization` header. Catalyst Center answers with a JSON body `{"Token": "<TOKEN>"}`; `resp.json()["Token"]` extracts the string.
- `raise_for_status()` raises `requests.HTTPError` if the status code is 4xx or 5xx, so a wrong password stops the script there instead of failing later with a confusing `KeyError`.
- The token goes in the **`X-Auth-Token`** header of every later request (not `Authorization: Bearer`).
- `params={"family": "Switches and Hubs"}` becomes the query string `?family=Switches+and+Hubs`.
- `resp.json()["response"]` is a **list** of dictionaries, one per device, because the Catalyst Center Intent API wraps results in a top-level `response` key (topic 6.5 reads such bodies in detail).
- `if __name__ == "__main__":` runs `main()` only when the file is executed directly, not when it is imported.
- `verify=False` turns off certificate checking; it is acceptable in a lab only.

Given a response whose `response` list holds SW1 (Reachable), SW2 (10.10.20.12, Unreachable) and DSW1 (Reachable), the script prints one line, padded by the `:<10` and `:<12` formats:

```text
SW2        10.10.20.12  Unreachable
```

> **Exam tip:** When a question shows a script and a JSON body, find the line that drills into the body (`["response"]`, `[0]`, `["hostname"]`) and walk the same path through the JSON with your finger. A missing level (`resp.json()["hostname"]` on a body whose devices are inside `response`) raises `KeyError`; indexing a dict with a number, or a list with a string, raises `KeyError` or `TypeError`.

## An ncclient script (NETCONF)

```python
from ncclient import manager

FILTER = """
<interfaces xmlns="urn:ietf:params:xml:ns:yang:ietf-interfaces">
  <interface>
    <name>GigabitEthernet1</name>
  </interface>
</interfaces>
"""

with manager.connect(host="192.0.2.10", port=830, username="netops",
                     password="ExamplePass123",       # example only
                     hostkey_verify=False) as m:
    reply = m.get_config(source="running", filter=("subtree", FILTER))
    print(reply.xml)
```

What it does: opens SSH to **TCP 830** and the NETCONF subsystem, exchanges `<hello>` capabilities, and sends `<get-config>` on the **running** datastore with a **subtree filter** that selects only GigabitEthernet1 from the **`ietf-interfaces`** YANG model (the namespace in `xmlns` tells you which model). `reply.xml` is the `<rpc-reply>` with a `<data>` element holding just that interface's configuration. Because it is `get-config`, no operational counters are returned; `m.get()` would include state. The `with` block closes the session when it ends. Lesson 4.6 covers NETCONF itself.

What changes would change the operation:

| You see | It means |
|---|---|
| `m.get(filter=...)` | Configuration **and** state |
| `m.edit_config(target="running", config=...)` | A change, merged by default |
| `target="candidate"` then `m.commit()` | Candidate datastore transaction (needs `netconf-yang feature candidate-datastore`) |
| `xmlns="http://cisco.com/ns/yang/Cisco-IOS-XE-native"` | The IOS XE native model rather than an IETF model |

## A Netmiko script (SSH to the CLI)

```python
from netmiko import ConnectHandler

r1 = {
    "device_type": "cisco_xe",
    "host": "192.0.2.10",
    "username": "netops",
    "password": "ExamplePass123",   # example only
}

config = [
    "interface Loopback100",
    "description Managed by Netmiko",
    "ip address 10.100.100.1 255.255.255.255",
]

with ConnectHandler(**r1) as conn:
    output = conn.send_config_set(config)
    print(output)
    brief = conn.send_command("show ip interface brief | include Loopback100")
    print(brief)
    conn.save_config()
```

- `ConnectHandler(**r1)` unpacks the dictionary into keyword arguments and opens an SSH session on TCP 22. `device_type` picks the driver (`cisco_ios` and `cisco_xe` use the same IOS driver).
- `send_config_set(list)` enters configuration mode for you (`configure terminal`), sends each line, leaves configuration mode, and returns the echoed session text. You do not put `configure terminal` or `end` in the list.
- `send_command("show ...")` returns the command output as **one string**; to work with it you split lines or parse it (Netmiko can hand it to TextFSM with `use_textfsm=True` when templates are installed).
- `save_config()` runs `write mem` with the IOS driver.

Netmiko is **screen scraping**: it sends what you would type and returns what the device prints. That is why it works on any device with a CLI, and also why its output is unstructured text, unlike the YANG-modelled data from NETCONF or RESTCONF.

## Comparing the three in a question

| Clue in the script | Library | Protocol |
|---|---|---|
| `requests.get/post/put/patch/delete`, URLs, `headers=`, `.status_code`, `.json()` | requests | REST over HTTPS |
| `/restconf/data/...` and `application/yang-data+json` | requests | RESTCONF |
| `/dna/intent/api/v1/...`, `X-Auth-Token` | requests | Catalyst Center Intent API |
| `manager.connect(... port=830 ...)`, XML filters, `get_config`, `edit_config` | ncclient | NETCONF over SSH |
| `ConnectHandler`, `device_type`, `send_command`, `send_config_set` | Netmiko | SSH CLI |

> **Watch out:** A script failing at `from netmiko import ConnectHandler` with `ModuleNotFoundError` is a missing library on the workstation (`pip install netmiko`), not a device problem. A failure at `ConnectHandler(...)` is a reachability, SSH or credential problem.

## Lab it yourself

You need Python 3 on any computer (Windows: `py`; macOS: `python3` in Terminal; Linux: `python3`), the libraries (`py -m pip install requests ncclient netmiko` on Windows, `python3 -m pip install ...` elsewhere, ideally inside a virtual environment), and a target:

- **Catalyst Center:** a Cisco DevNet Catalyst Center sandbox, reached from your browser and scripts on any host OS.
- **IOS XE for NETCONF and Netmiko:** a Catalyst 8000V in Cisco Modeling Labs, GNS3 or EVE-NG on Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a DevNet IOS XE sandbox. Configure SSH and `netconf-yang` as in lesson 4.6.

1. Run the Catalyst Center script against the sandbox. Print `len(get_devices(token))`, then remove the `family` filter and compare.
2. Change the header name to `Authorization` and note the status code you get back.
3. Run the ncclient script, then change `get_config` to `get` and compare the size of the reply.
4. Run the Netmiko script and check `show running-config interface Loopback100` on the router. Print `type(brief)` to confirm it is a `str`.

## Key takeaways

- Read a script in order: imports, target and credentials, connect or request, check the result, parse, loop, print.
- `requests`: `requests.get/post(url, headers=..., auth=..., json=..., params=...)`; check `.status_code`; `.json()` parses the body; `raise_for_status()` raises on 4xx and 5xx.
- Catalyst Center: `POST /dna/system/api/v1/auth/token` with Basic authentication returns `{"Token": "<TOKEN>"}`; send it as `X-Auth-Token`; results sit in the `response` list.
- `ncclient`: `manager.connect(host, port=830, ...)`, `get_config(source="running", filter=("subtree", ...))`, `edit_config(target=...)`; XML in and out; the namespace shows the YANG model.
- Netmiko: `ConnectHandler(device_type=...)`, `send_command` returns text, `send_config_set` enters and leaves configuration mode itself, `save_config` saves.
- NETCONF and RESTCONF return structured, model-based data; Netmiko returns CLI text you must parse.
