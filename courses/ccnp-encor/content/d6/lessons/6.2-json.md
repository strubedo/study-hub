## Why JSON matters to a network engineer

**JSON** (JavaScript Object Notation, RFC 8259) is the body format of almost every API you will touch: the Catalyst Center Intent API, SD-WAN Manager, RESTCONF (`application/yang-data+json`), Meraki and most ticketing systems. Topic 6.2 says **construct**: you must be able to write a JSON document that a parser accepts and spot exactly why one is rejected. JSON is strict. A single trailing comma or a capital `T` in `True` makes the whole document invalid, and the API returns 400 Bad Request.

Every sample in this lesson was checked with `python3 -m json.tool`; every broken sample was confirmed to fail for the reason given.

## The six value types

| JSON type | Example | Rules |
|---|---|---|
| Object | `{"hostname": "R1", "mtu": 1500}` | Curly braces; members are `"name": value` pairs separated by commas; names are **strings in double quotes** |
| Array | `[10, 20, 30]` | Square brackets; values separated by commas; values can be of mixed types |
| String | `"GigabitEthernet1/0/1"` | **Double quotes only**; special characters escaped with a backslash |
| Number | `1500`, `-3`, `7.5`, `1e3` | Decimal only: no leading zeros (`010`), no hex, no `NaN` or `Infinity`, no quotes |
| Boolean | `true`, `false` | Lowercase, no quotes |
| Null | `null` | Lowercase, no quotes |

There is **no** comment syntax, no single-quoted string, no trailing comma and no date type (dates are strings). Whitespace between tokens (spaces, tabs, newlines) is ignored, so indentation is only for people. A JSON text can be any value, but APIs almost always expect an object at the top.

## A valid document, built up

```text
{
  "hostname": "SW1",
  "managed": true,
  "uptime_days": 41,
  "cpu_5min": 7.5,
  "location": null,
  "vlans": [10, 20, 99],
  "interfaces": [
    {
      "name": "GigabitEthernet1/0/1",
      "description": "Uplink to DSW1",
      "mode": "trunk",
      "allowed_vlans": [10, 20, 99]
    },
    {
      "name": "GigabitEthernet1/0/2",
      "description": "Printer \"Floor 2\"",
      "mode": "access",
      "access_vlan": 20
    }
  ],
  "backup_path": "C:\\backups\\sw1.cfg"
}
```

Read it as a tree: the top-level object has seven members; `interfaces` is an array of two objects, and each object can have different members. Brackets and braces must close in the reverse order they opened (`[` ... `{` ... `}` ... `]`). The last member of each object and the last value of each array have **no comma** after them.

### Escaping inside strings

| Write | To get |
|---|---|
| `\"` | a double quote inside the string |
| `\\` | one backslash |
| `\n`, `\t`, `\r` | newline, tab, carriage return |
| `\/` | a forward slash (optional; `/` is legal as is) |
| `\u00e9` | any Unicode character by code point |

Interface names such as `GigabitEthernet1/0/1` need no escaping. Windows paths do: every backslash must be doubled.

> **Watch out:** `"C:\backups\r1.cfg"` is **valid** JSON, and that is the trap. `\b` (backspace) and `\r` (carriage return) are legal escapes, so a parser accepts the line and silently stores a string containing control characters. `"flash:\logs\eem.txt"` is rejected (`Invalid \escape`), because `\l` is not a JSON escape. Always write `\\`.

## JSON versus Python literals

Python dictionaries look like JSON, which is exactly why people write invalid JSON by hand.

| Python | JSON |
|---|---|
| `True`, `False` | `true`, `false` |
| `None` | `null` |
| `'single'` or `"double"` quotes | `"double"` quotes only |
| `(10, 20)` tuple | `[10, 20]` array |
| Trailing comma allowed: `[10, 20,]` | Not allowed |
| `# comments` | No comments at all |
| Keys of many types (`{1: "a"}`) | Keys are always strings (`{"1": "a"}`) |

Let `json.dumps()` produce JSON from Python data rather than typing it: `json.dumps({"enabled": True, "vlan": None})` gives `{"enabled": true, "vlan": null}`. Going the other way, `json.loads()` turns `true` into `True` and `null` into `None`.

## Common errors and how a parser reports them

These are the messages Python 3's `json` module gives (the wording varies between versions and between tools, but the line and column point at or just after the fault):

| Broken JSON | Problem | Python reports |
|---|---|---|
| `{"vlans": [10, 20,]}` | Trailing comma in an array | `Illegal trailing comma before end of array` (Python 3.12 and earlier: `Expecting value`) |
| `{"mtu": 1500,}` | Trailing comma in an object | `Illegal trailing comma before end of object` (Python 3.12 and earlier: `Expecting property name enclosed in double quotes`) |
| `{'hostname': 'R1'}` | Single quotes | `Expecting property name enclosed in double quotes` |
| `{hostname: "R1"}` | Unquoted name | `Expecting property name enclosed in double quotes` |
| `{"managed": True}` | Python literal | `Expecting value` |
| `{"hostname": "R1" "managed": true}` | Missing comma between members | `Expecting ',' delimiter` |
| `{"vlan": 010}` | Leading zero | `Expecting ',' delimiter` |
| `{"descr": "Link to "R2""}` | Unescaped inner quote | `Expecting ',' delimiter` |
| `{"path": "flash:\logs"}` | Invalid escape | `Invalid \escape` |
| `{"vlans": [10, 20}` | Mismatched bracket | `Expecting ',' delimiter` |
| `{"hostname": "R1", // core` | Comment | `Expecting property name enclosed in double quotes` |

A **missing comma** is reported on the line **after** the fault, because the parser only notices when the next member starts:

```text
 9    {
10      "name": "GigabitEthernet0/0/1",
11      "enabled": false
12      "ipv4": null
13    }
```

`python3 -m json.tool` reports `Expecting ',' delimiter: line 12 column 7`, but the fix is a comma at the end of line 11.

> **Exam tip:** Scan a JSON exhibit in this order: every string and name in double quotes; `true` / `false` / `null` lowercase and unquoted; a comma between every pair of members and values but never before `}` or `]`; brackets balanced and correctly nested; backslashes doubled; numbers plain.

### Things that are legal but surprising

- **Duplicate names** (`{"vlan": 10, "vlan": 20}`) are not a syntax error. RFC 8259 says names SHOULD be unique; most parsers, Python's included, keep the last one, so you silently get 20.
- **Order** of members in an object carries no meaning; order of values in an array does.
- **Python accepts `NaN` and `Infinity`** when loading, but they are not JSON and other parsers reject them.
- Numbers and strings are different: `"vlan": "10"` is a string, so a strict API expecting an integer rejects it with 400.

## JSON in an API body

A RESTCONF body follows the same rules, plus YANG's JSON conventions (RFC 7951): the top-level member, and any member that comes from a different YANG module, is **qualified with the module name**.

```text
{
  "ietf-interfaces:interface": [
    {
      "name": "GigabitEthernet2",
      "description": "Link to R2",
      "type": "iana-if-type:ethernetCsmacd",
      "enabled": true,
      "ietf-ip:ipv4": {
        "address": [
          {
            "ip": "10.1.12.1",
            "netmask": "255.255.255.0"
          }
        ]
      }
    }
  ]
}
```

`ietf-ip:ipv4` carries a prefix because the `ipv4` container is added to the interface by a different module (`ietf-ip` augments `ietf-interfaces`; see topic 6.3). `interface` and `address` are YANG lists, so RFC 7951 encodes each as a JSON array even when it holds one entry (many Cisco examples write a single entry as an object instead; both are valid JSON, but the array is the RFC 7951 form).

## Lab it yourself

Any computer with Python 3 will do (Windows: `py`; macOS: `python3` in Terminal; Linux: `python3`), including Apple silicon Macs.

1. Save the SW1 document as `sw1.json` and run `py -m json.tool sw1.json` (Windows) or `python3 -m json.tool sw1.json`. A valid file is printed back re-indented.
2. Break it one way at a time using the error table: add a trailing comma, change `true` to `True`, change one pair of double quotes to single, delete a comma, add `// comment`. Run the tool after each change and note the line and column it reports.
3. Change `C:\\backups\\sw1.cfg` to `C:\backups\sw1.cfg`: the tool rejects it with `Invalid \escape`, because `\s` is not a JSON escape. Now change it to `C:\backups\new.cfg`: the file validates, because `\b` and `\n` are legal escapes. Load it with `python3 -c "import json; print(repr(json.load(open('sw1.json'))['backup_path']))"` and see the control characters.
4. In the Python prompt, build the same data as a dictionary and print `json.dumps(data, indent=2)`; compare it with your hand-written file.

## Key takeaways

- JSON has six value types: object `{}`, array `[]`, string, number, `true` / `false`, `null`.
- Names and strings use **double quotes only**; `true`, `false` and `null` are lowercase and unquoted.
- No trailing commas, no comments, no leading zeros, no `NaN`; brackets must balance and nest correctly.
- Escape `"` as `\"` and `\` as `\\`; an unescaped backslash may be rejected (`\l`) or silently change the data (`\b`, `\r`).
- Python `True` / `False` / `None` / single quotes / tuples are not JSON; use `json.dumps()` to produce JSON from Python.
- A missing comma is reported on the following line. RESTCONF JSON qualifies top-level and augmented members with the module name.
