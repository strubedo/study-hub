## What a hypervisor does

A **hypervisor** (also called a virtual machine monitor) is the software layer that lets one physical computer run several isolated operating systems at once. It carves the physical CPU cores, memory, storage and network adapters into virtual pieces, hands each **virtual machine (VM)** its own share, and stops one VM from touching another's memory or devices. The physical machine is the **host**; each VM's operating system is a **guest**.

Modern x86 and ARM CPUs help with hardware extensions (Intel VT-x, AMD-V, ARM virtualization extensions) so the guest runs most instructions directly on the CPU and the hypervisor only steps in for privileged operations. That is why a virtual router today runs at close to bare-metal speed.

The exam topic asks you to tell the two hypervisor types apart. The difference is **what the hypervisor runs on**.

## Type 1: bare-metal

A **type 1** hypervisor runs directly on the server hardware. There is no general-purpose operating system underneath it; the hypervisor *is* the host's operating system, kept small so that it has a small attack surface and little overhead.

| Product | Notes |
|---|---|
| VMware ESXi | Installed on the server itself; managed by vCenter |
| Microsoft Hyper-V | Once the role is enabled, the hypervisor loads first and Windows itself becomes a privileged "parent partition" on top of it, so it is type 1 |
| KVM (Kernel-based Virtual Machine) | A Linux kernel module that turns the Linux kernel into the hypervisor; usually classed as type 1 because the kernel itself runs the VMs |
| Xen, Nutanix AHV, Proxmox VE | AHV and Proxmox are built on KVM |
| Cisco NFVIS | Cisco's Linux/KVM-based hosting layer on ENCS, Catalyst 8200 uCPE and similar platforms, used to run virtual routers and firewalls at a branch |

Type 1 is what you find in data centres and in any production network functions virtualization (NFV) platform: it gives the best performance and isolation, supports clustering, high availability and live migration, and is managed remotely.

## Type 2: hosted

A **type 2** hypervisor is an application that runs on top of a normal desktop operating system (Windows, macOS or Linux). Every request a VM makes passes through the hypervisor *and* the host OS, so there is more overhead, and if the host OS crashes or reboots for updates, every VM goes with it.

| Product | Host OS |
|---|---|
| Oracle VirtualBox | Windows, Linux, macOS |
| VMware Workstation / Workstation Pro | Windows, Linux |
| VMware Fusion | macOS |
| Parallels Desktop, UTM | macOS (UTM uses QEMU and Apple's Hypervisor framework) |

Type 2 is for desktops and labs: running a Linux VM on your laptop, or running a lab platform such as Cisco Modeling Labs (CML), GNS3 VM or EVE-NG inside VMware Workstation or Fusion. Those platforms run Cisco's x86 images, so they need Windows, Linux or an Intel Mac; on an Apple silicon Mac, run them on a remote x86 server or use a Cisco DevNet sandbox. They then run *nested* virtualization: the virtual routers are VMs inside a VM.

## Comparison

| | Type 1 (bare-metal) | Type 2 (hosted) |
|---|---|---|
| Runs on | The hardware directly | A host operating system |
| Overhead | Low | Higher (extra OS layer) |
| Isolation and security | Strong; small codebase | Depends on the host OS too |
| Failure domain | Hypervisor only | Host OS crash or reboot stops all VMs |
| Management | Remote, centralised (vCenter, Hyper-V Manager, virt-manager, NFVIS portal) | Local application window |
| Typical use | Data centre, private cloud, NFV, branch uCPE | Desktop testing, labs, training |
| Examples | ESXi, Hyper-V, KVM, Xen, NFVIS | VirtualBox, Workstation, Fusion, Parallels |

> **Exam tip:** "Runs directly on the hardware" or "bare metal" means type 1. "Installed as an application on Windows or macOS" means type 2. Do not be thrown by Hyper-V being enabled from inside Windows: the hypervisor sits beneath Windows once enabled, so it is type 1.

> **Watch out:** KVM is the classic "it depends" case. Because it is part of a full Linux kernel that can also run ordinary programs, some authors call it a hybrid. Cisco material and most references group it with type 1, so answer type 1 unless the question says otherwise.

## Where Cisco network devices fit

- **Catalyst 8000V** (successor to the CSR 1000v), **ASAv**, **FTDv** and the virtual SD-WAN controllers are VMs. They run on a type 1 hypervisor in production (ESXi, KVM, NFVIS) or in a public cloud, and on type 2 only in a lab.
- **NFVIS** is the hypervisor layer for Cisco branch NFV: it runs on the appliance's hardware and hosts virtual network functions.
- **Application hosting on Catalyst 9000** (IOx) runs **containers**, not full VMs, alongside IOS XE. Containers are covered in the next lesson.

> **Real world:** Cloud providers (AWS, Azure, Google Cloud) run their own type 1 hypervisors; when you launch a Catalyst 8000V in a VPC you are a tenant on someone else's bare-metal hypervisor.

## Lab it yourself

You need nothing but your own computer.

1. Install a type 2 hypervisor: VirtualBox or VMware Workstation on Windows and Linux; VMware Fusion, Parallels or UTM on a Mac. On Apple silicon, use ARM guest images (for example Ubuntu Server for ARM).
2. Create a small Linux VM (1 vCPU, 2 GB RAM, 20 GB disk) and install it.
3. Inside the guest, run `lscpu` and `free -h`: the guest sees only the vCPUs and memory you assigned. On the host, open Task Manager, Activity Monitor or `top` to see the hypervisor process consuming real resources.
4. Optional (x86 hosts): enable nested virtualization in the VM settings, then run `grep -cE 'vmx|svm' /proc/cpuinfo` in the guest. A non-zero count means the CPU extensions are passed through and the guest could itself run KVM, which is exactly what the CML, GNS3 VM and EVE-NG appliances need when you run them on a laptop.

## Key takeaways

- A hypervisor shares one host's CPU, memory, storage and NICs among isolated VMs.
- Type 1 (bare-metal) runs on the hardware: ESXi, Hyper-V, KVM, Xen, Cisco NFVIS. Lower overhead, stronger isolation, used in production.
- Type 2 (hosted) runs as an application on a desktop OS: VirtualBox, Workstation, Fusion, Parallels. Used for labs and desktops.
- A type 2 hypervisor's VMs fail with the host OS; a type 1 hypervisor removes that layer.
- Virtual Cisco devices (Catalyst 8000V, ASAv, FTDv) are VMs that run on a type 1 hypervisor in production.
- Catalyst 9000 application hosting uses containers, not VMs.
