## Why AAA

Local usernames do not scale past a handful of devices: every password change touches every box, and nothing records which commands people ran. **AAA** moves those decisions to a central server:

- **Authentication**: who are you? (username and password, token, certificate)
- **Authorization**: what may you do? (which privilege level, which commands, which VLAN or ACL for a network user)
- **Accounting**: what did you do? (session start and stop, every command entered)

The servers speak **TACACS+** or **RADIUS**. In a Cisco network both usually live on **Cisco ISE**: TACACS+ for administrators logging in to devices ("device administration"), RADIUS for users and endpoints joining the network (802.1X, MAB, VPN).

## RADIUS versus TACACS+

| | RADIUS | TACACS+ |
|---|---|---|
| Standard | RFC 2865 (authentication and authorization), RFC 2866 (accounting) | RFC 8907 (2020), documenting the Cisco protocol |
| Transport | UDP 1812 authentication, 1813 accounting (old ports 1645 / 1646 still seen) | TCP 49 |
| What is protected | Only the User-Password attribute is hidden; the rest of the packet is clear text | The whole packet body is obfuscated with the shared key |
| AAA functions | Authentication and authorization combined in one Access-Accept | Authentication, authorization and accounting are separate exchanges |
| Per-command authorization | No | Yes: the device asks the server about each command |
| Typical use | Network access: 802.1X, MAB, VPN, wireless | Device administration: CLI logins and command control |

RFC 8907 calls the TACACS+ body protection **obfuscation**: it is an MD5-based pad XORed with the body, not modern encryption, and the RFC tells operators to protect the traffic in other ways (a management network, or TLS where supported). It is still better than RADIUS, where the username and every authorization attribute travel in the clear.

> **Exam tip:** "Separates authentication and authorization", "TCP 49", "encrypts the entire body" and "command authorization" all point to TACACS+. "UDP 1812/1813", "combined authentication and authorization", "only the password is hidden" and "802.1X" point to RADIUS.

## `aaa new-model` and what it changes immediately

AAA is off until you enter `aaa new-model`. The moment you do:

- The old line-level rules stop applying: `login`, `login local` and line `password` commands are ignored, and every line uses an AAA **method list** instead (the line shows `login authentication NAME`, or uses the list named `default`).
- If **no default login list** exists yet, IOS falls back to the **local** user database for vty and other lines, while the console is not challenged at all. So a vty with only a line password and no local users becomes inaccessible.
- `aaa new-model` cannot be undone casually: `no aaa new-model` is accepted, but plan the change rather than flip it back and forth on a production box.

So create a local fallback user **before** entering `aaa new-model`.

## Defining the servers (current syntax)

IOS XE uses named server definitions. The old `tacacs-server host` and `radius-server host` forms still exist on many releases but are deprecated.

```text
R1(config)# tacacs server ISE-TAC-1
R1(config-server-tacacs)# address ipv4 10.10.50.11
R1(config-server-tacacs)# key <TACACS-KEY>
R1(config-server-tacacs)# timeout 5
R1(config-server-tacacs)# exit
R1(config)# tacacs server ISE-TAC-2
R1(config-server-tacacs)# address ipv4 10.10.50.12
R1(config-server-tacacs)# key <TACACS-KEY>
R1(config-server-tacacs)# exit
R1(config)# aaa group server tacacs+ TAC-SERVERS
R1(config-sg-tacacs+)# server name ISE-TAC-1
R1(config-sg-tacacs+)# server name ISE-TAC-2
R1(config-sg-tacacs+)# exit
R1(config)# ip tacacs source-interface Loopback0
```

```text
R1(config)# radius server ISE-RAD-1
R1(config-radius-server)# address ipv4 10.10.50.11 auth-port 1812 acct-port 1813
R1(config-radius-server)# key <RADIUS-KEY>
R1(config-radius-server)# exit
R1(config)# aaa group server radius RAD-SERVERS
R1(config-sg-radius)# server name ISE-RAD-1
R1(config-sg-radius)# exit
R1(config)# ip radius source-interface Loopback0
```

- The TACACS+ port defaults to 49 and the RADIUS ports to 1812 and 1813; `auth-port` and `acct-port` are shown for clarity.
- The **key** must match the shared secret configured for this device on the server. A key mismatch shows up on the server as a bad authenticator or a decryption failure, and on the device as failed logins.
- **`ip tacacs source-interface`** and **`ip radius source-interface`** fix the source address of AAA packets. ISE identifies a network device (NAD) by the source IP of the request, so if the router sources requests from whichever interface faces the server, the requests come from an address ISE does not know and are dropped. A loopback is the usual choice. The same command can also be set per server group (`ip radius source-interface` or `ip tacacs source-interface` inside `aaa group server`), together with `ip vrf forwarding Mgmt-vrf` when the servers are reached through a management VRF.
- The built-in groups **`group tacacs+`** and **`group radius`** mean "all configured servers of that protocol"; a named group such as `TAC-SERVERS` gives you control over which servers and in which order.

## Method lists

A method list is an ordered list of ways to authenticate (or authorize, or account):

```text
R1(config)# aaa authentication login default group TAC-SERVERS local
R1(config)# aaa authentication login CONSOLE local
R1(config)# line con 0
R1(config-line)# login authentication CONSOLE
```

- **`default`** applies to every line that has no `login authentication` command.
- A **named list** (here `CONSOLE`) does nothing until a line references it with `login authentication NAME`.
- The methods are tried **left to right**.

### The fallback rule

This is the most tested AAA fact. IOS moves to the next method **only when the current method returns an ERROR**: no server answered, every server timed out, or the server group is unreachable. If a server answers with a **FAIL** (the user is rejected: wrong password, unknown user, account disabled), authentication **stops** and the user is denied. The local database is never consulted after a reject.

| Server result | Next method tried? |
|---|---|
| ACCEPT | No: the user is in |
| REJECT / FAIL | No: the user is denied |
| ERROR (timeout, no route, connection refused) | Yes |

That is what makes `local` a safe fallback: it only ever applies when the servers are unreachable, so a local account cannot be used to bypass a lockout that ISE has imposed.

### The method keywords

| Method | Meaning |
|---|---|
| `group NAME`, `group tacacs+`, `group radius` | Ask the servers in that group, in order. A timeout from one server moves to the next server in the same group before the group returns ERROR |
| `local` | The local `username` database; the username is not case-sensitive (the password always is) |
| `local-case` | The local database with a case-sensitive username |
| `enable` | The enable secret as the password |
| `line` | The line password |
| `none` | Succeed without any check. Never put it in a login list on a production device |

> **Watch out (the lockout trap):** `aaa authentication login default group TAC-SERVERS` with **no** fallback method applies to the console too. If the servers become unreachable (a routing change, an ISE outage, a changed key) nobody can log in anywhere, and the only way back is password recovery. Always end the default list with `local`, and give the console its own list that starts with `local` or ends with it.

## Authorization

Authentication only proves identity; by default an AAA-authenticated user lands at **privilege level 1**. Authorization tells the device what the user may do.

```text
R1(config)# aaa authorization exec default group TAC-SERVERS local if-authenticated
R1(config)# aaa authorization commands 15 default group TAC-SERVERS local if-authenticated
R1(config)# aaa authorization config-commands
R1(config)# aaa authorization console
```

- **`aaa authorization exec`** asks the server whether the user may start an EXEC shell and with what attributes, most importantly the privilege level (`priv-lvl=15` in a TACACS+ shell profile). Without it, the server's privilege level is never requested and users arrive at level 1.
- **`aaa authorization commands N`** sends each command at level N to the server before running it (TACACS+ only). Configure it for level 15, and for any custom level in use.
- **`aaa authorization config-commands`** extends command authorization to configuration-mode commands; without it, commands inside `configure terminal` are not checked.
- **`if-authenticated`** permits the request if the user is authenticated, useful as the last fallback so that local logins during an outage still work.
- Authorization is **not applied on the console** unless `aaa authorization console` is configured. That default is deliberate: the console stays usable if the authorization server is gone.

## Accounting

```text
R1(config)# aaa accounting exec default start-stop group TAC-SERVERS
R1(config)# aaa accounting commands 15 default start-stop group TAC-SERVERS
```

`start-stop` sends a record when a session begins and when it ends; `stop-only` sends only the end record. Command accounting records every level-15 command with the username, the device and the time: the audit trail that local authentication cannot give you.

## Verifying and troubleshooting

```text
R1# test aaa group TAC-SERVERS netadmin ExamplePass123 new-code
User successfully authenticated
```

`test aaa group` sends a real authentication request without logging in, so you can prove the server, key and source address work **before** you change the login lists. (The password here is a placeholder.)

```text
R1# show aaa servers
RADIUS: id 1, priority 1, host 10.10.50.11, auth-port 1812, acct-port 1813, hostname ISE-RAD-1
     State: current UP, duration 86240s, previous duration 0s
     Dead: total time 0s, count 0
     ...
     Authen: request 42, timeouts 0, failover 0, retransmission 0
             Response: accept 40, reject 2, challenge 0
```

`show aaa servers` gives per-server state (UP or DEAD), requests, timeouts and accept / reject counts. Rising **timeouts** point to reachability, source address or key problems; **rejects** mean the server is answering and refusing the user. Other useful commands:

- `show tacacs`: per-server socket opens, errors and `Server Status`.
- `show aaa method-lists all` (or `authentication`): the configured lists.
- `show aaa sessions` and `show users`: who is logged in through AAA.
- `debug aaa authentication`, `debug tacacs`, `debug radius`: the method list picked, the server asked and the result (PASS, FAIL or ERROR).

## Lab it yourself

Build an IOS XE router (Catalyst 8000V) and a TACACS+ and RADIUS server in Cisco Modeling Labs, GNS3 or EVE-NG; these run Cisco's x86 images on Windows, Linux or an Intel Mac, and on an Apple silicon Mac you can use a remote x86 server or a Cisco DevNet sandbox. ISE evaluation needs a large VM; a small Linux VM with an open-source TACACS+ daemon and FreeRADIUS is enough for this lab.

1. Create `username netadmin privilege 15 algorithm-type scrypt secret ExamplePass123` (lab-only) and test it on the console.
2. Enter `aaa new-model` and observe that the vty now asks for a username even though no list exists.
3. Define `tacacs server` and `aaa group server tacacs+ TAC-SERVERS`, set `ip tacacs source-interface Loopback0`, and prove it with `test aaa group TAC-SERVERS ...`.
4. Configure `aaa authentication login default group TAC-SERVERS local` and a `CONSOLE` list with `local`, applied with `login authentication CONSOLE`.
5. Add `aaa authorization exec` and see users land at the privilege level the server sends; remove it and see them land at level 1.
6. Log in with a wrong password (rejected, no local fallback), then stop the server and log in with the local account (ERROR, fallback works). Compare `show aaa servers` and `debug aaa authentication` for both.
7. Add command authorization and accounting for level 15 and read the server's logs.

## Key takeaways

- `aaa new-model` switches every line to method lists at once; create a local user first.
- Modern servers: `tacacs server NAME` / `radius server NAME` with `address ipv4` and `key`, grouped with `aaa group server`; set `ip tacacs` / `ip radius source-interface`.
- Method lists are tried left to right; the next method is used only on ERROR (no response), never on a reject.
- `local` (case-insensitive username), `local-case`, `enable`, `line`, `none`; end the default list with `local` to avoid the lockout trap.
- `aaa authorization exec` sets the privilege level, `commands N` and `config-commands` give per-command control (TACACS+), `console` extends it to the console.
- RADIUS: UDP 1812/1813, password-only hiding, combined authentication and authorization, RFC 2865. TACACS+: TCP 49, whole body obfuscated, separate A, A and A, per-command authorization, RFC 8907.
- Verify with `test aaa group`, `show aaa servers`, `show tacacs` and `debug aaa authentication`.
