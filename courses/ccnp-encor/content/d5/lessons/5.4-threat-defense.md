## Defence in depth

No single product stops every attack. A **layered** (defence-in-depth) design puts independent controls at each point an attack must pass, so that one failure does not mean a breach:

| Layer | Controls | Covered in |
|---|---|---|
| Identity and access | AAA, 802.1X, MAB, ISE, multi-factor authentication | 5.1, 5.4.b |
| Network edge and segments | Next-generation firewalls, IPS, ACLs, TrustSec segmentation | 5.2, 5.4.c, 5.4.d |
| DNS and web | DNS-layer security, secure web gateways | This lesson |
| Email | Secure email gateway | This lesson |
| Endpoints | Endpoint protection and response, posture | 5.4.b |
| Visibility and analytics | Flow telemetry, behavioural analytics, logs in a SIEM | This lesson |
| Devices themselves | Hardened management, CoPP, encrypted links (MACsec) | 5.1, 5.2, 5.4.d |

Two design ideas tie the layers together and appear in Cisco's architecture material:

- **Visibility**: you cannot protect what you cannot see. Every layer should report what it sees (flows, DNS queries, file verdicts, logins) to a place where it can be correlated.
- **Segmentation**: limit what a compromised host can reach, so an attack that gets in cannot move laterally. VLANs and VRFs, firewalls between zones, and policy-based segmentation such as TrustSec and SD-Access are the tools.

## Before, during and after

Cisco describes threat defence as covering the whole **attack continuum**:

| Phase | Goal | Example capabilities |
|---|---|---|
| **Before** an attack | Discover assets, enforce policy, harden, reduce the attack surface | Inventory and profiling, access control, segmentation, firewall policy, patching |
| **During** an attack | Detect and block it as it happens | IPS, malware inspection, DNS and URL blocking, email filtering |
| **After** an attack | Scope the damage, contain it and remediate | Retrospective detection, file and device trajectory, flow forensics, quarantine through ISE |

The "after" phase matters because some threats are only recognised as malicious later, when new intelligence arrives. A design that only blocks at the moment of entry has no answer for them.

## Cisco Talos

**Cisco Talos** is Cisco's threat intelligence and research organisation. It analyses malware, vulnerabilities, spam and attacker infrastructure and turns what it finds into intelligence that Cisco's security products consume automatically: IP, domain and URL reputation, malware file verdicts, IPS (Snort) rules and email filters. When an exam answer asks what keeps Cisco security products' signatures and reputation data current, the answer is Talos.

## Secure Network Analytics

**Cisco Secure Network Analytics (formerly Stealthwatch)** gives network-wide visibility and behavioural threat detection from telemetry the network already produces:

- **NetFlow and IPFIX** from routers, switches and firewalls (on Catalyst 9000 and IOS XE routers, Flexible NetFlow; see Domain 4) are sent to **Flow Collectors**, which store and analyse them; a **Manager** (formerly the Stealthwatch Management Console) provides the interface and reporting. **Flow Sensors** create flow records with application detail where the network devices cannot.
- It builds a **baseline** of normal behaviour for each host and group, then raises alarms on anomalies: a workstation scanning the network, a server sending unusual volumes to the internet (data exfiltration), command-and-control beaconing, or traffic between groups that should never talk.
- It can integrate with ISE to see **who** owns an IP address and to **quarantine** a host.
- **Encrypted Traffic Analytics (ETA)** detects malware inside encrypted sessions **without decrypting them**. Supported Catalyst switches and IOS XE routers export extra data about each flow (the initial data packet, including TLS handshake details, and the sequence of packet lengths and times). Analysed with Talos intelligence and machine learning, this lets the system tell malicious TLS sessions from benign ones and check which TLS versions and cipher suites are in use, which is useful for crypto compliance.

> **Exam tip:** "Detect threats in encrypted traffic without decryption" is Encrypted Traffic Analytics. "Find anomalous behaviour inside the network using NetFlow" is Secure Network Analytics.

## Cisco Umbrella: DNS-layer security

Almost every connection begins with a DNS lookup. **Cisco Umbrella** uses that: clients (or the network's DNS servers, routers or the roaming module of Secure Client) send DNS queries to Umbrella's recursive resolvers (the familiar 208.67.222.222 and 208.67.220.220 for IPv4), which answer normally for safe domains and return a **block page address** for domains known to host malware, phishing or command-and-control, or in categories policy forbids.

- It blocks **before a connection is made**, for any port or protocol, on and off the corporate network.
- Risky domains can be sent to an intelligent **proxy** for URL-level inspection instead of being blocked outright.
- Logs of DNS queries show which hosts tried to reach malicious domains: a cheap indicator of compromise.
- Umbrella is also the DNS and secure web gateway part of Cisco's cloud security service edge offering; the exam focuses on DNS-layer protection.

## Secure Email and Secure Web Appliance

| Product (old name) | Protects | Main capabilities |
|---|---|---|
| **Cisco Secure Email** gateway (formerly Email Security Appliance, ESA) | Inbound and outbound email | Reputation filtering of senders using Talos data, anti-spam, anti-virus, malware and attachment analysis, URL rewriting and inspection, data loss prevention and encryption for outbound mail |
| **Cisco Secure Web Appliance** (formerly Web Security Appliance, WSA) | Users' web traffic through an on-premises proxy | URL filtering by category and reputation, application visibility and control, malware scanning of downloads, HTTPS inspection, acceptable-use policy |

Email remains the most common way attacks begin (phishing, malicious attachments and links), which is why a dedicated gateway sits in front of the mail servers. The web proxy enforces the same organisation-wide web policy for every user on the network.

## How the pieces fit

Consider a phishing campaign. The **Secure Email** gateway blocks most messages; one slips through with a link. When the user clicks, **Umbrella** refuses to resolve the newly flagged domain. Another user on an unmanaged network downloads the payload; **Secure Endpoint** (next lesson) blocks it, or quarantines it later when its verdict changes. **Secure Network Analytics** sees an unusual flow from a third host to an external address and raises an alarm, and **ISE** quarantines that host. Every product drew on **Talos** intelligence. That is defence in depth: each layer catches some of what the others missed.

## Lab it yourself

Most of these products are licensed services, so this lab is mostly exploration and configuration of the network side, on any host OS.

1. Point a lab PC's DNS at 208.67.222.222 and look up a test domain from Umbrella's documentation, such as the phishing test domain it publishes; compare the answer with another resolver.
2. Configure Flexible NetFlow on a Catalyst 8000V in Cisco Modeling Labs, GNS3 or EVE-NG (Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a Cisco DevNet sandbox) and export it to a free collector; this is the telemetry Secure Network Analytics consumes.
3. Read a recent Talos blog post and note which Snort rule or reputation update it produced.
4. Check the Cisco DevNet sandboxes for security product APIs (Secure Endpoint, Umbrella) and list what each API exposes.

## Key takeaways

- Defence in depth layers identity, segmentation, DNS and web, email, endpoint and analytics controls so one failure is not a breach.
- Visibility and segmentation are the two design principles; "before, during, after" describes coverage of the attack continuum.
- Cisco Talos supplies threat intelligence (reputation, verdicts, Snort rules) to Cisco security products.
- Secure Network Analytics (formerly Stealthwatch): NetFlow-based behavioural analytics; ETA finds malware in encrypted traffic without decrypting it.
- Umbrella: DNS-layer security that blocks malicious domains before a connection is made, on or off network.
- Secure Email (formerly ESA) filters email threats; Secure Web Appliance (formerly WSA) is the on-premises web proxy.
