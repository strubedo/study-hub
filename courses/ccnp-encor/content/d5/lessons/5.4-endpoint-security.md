## The endpoint problem

Laptops, phones, printers, cameras and IoT devices are where most attacks land: a user opens an attachment, a laptop joins from a hotel network, an unpatched camera runs default credentials. Endpoint security answers three questions:

1. **Is this endpoint allowed on the network, and with what access?** (network access control: ISE, 802.1X, MAB, WebAuth)
2. **Is it healthy?** (posture: patches, anti-malware, disk encryption)
3. **Is it running something malicious, and what did that malware do?** (endpoint protection and response: Secure Endpoint)

## Cisco Secure Endpoint

**Cisco Secure Endpoint (formerly AMP for Endpoints)** is Cisco's endpoint protection and response product. A lightweight connector on Windows, macOS, Linux and mobile devices reports to a cloud console.

- **Prevention**: file reputation lookups against Cisco's cloud (fed by Talos), anti-malware engines, exploit and script protection, and blocking of connections to known-bad IP addresses.
- **Continuous monitoring and retrospective detection**: the connector records file, process and network activity. If a file was judged clean when it arrived but its **disposition later changes to malicious** because of new intelligence, Secure Endpoint raises a **retrospective detection** and can quarantine the file wherever it is, after the fact.
- **File trajectory** shows the life of a file across the environment: where it was first seen, every device that has it, and how it got there. **Device trajectory** shows the sequence of events on one endpoint (which process created which file, which made which connection), which is how you find patient zero and the scope of an outbreak.
- **Sandboxing** of unknown files through Cisco Secure Malware Analytics (formerly Threat Grid).

Retrospection is the "after" phase of the attack continuum in action: protection continues after the moment of entry.

## Cisco Secure Client

**Cisco Secure Client (formerly AnyConnect Secure Mobility Client)** is a single client with modules for different jobs:

| Module | Job |
|---|---|
| VPN | Remote-access SSL/TLS and IPsec IKEv2 VPN to a Secure Firewall or router headend |
| Network Access Manager | An 802.1X supplicant for wired and wireless (Windows) |
| ISE Posture | Checks compliance for ISE (see below) |
| Umbrella roaming security | Sends DNS to Umbrella when off network |
| Network Visibility Module | Exports flow data with user and process context |

The point for the exam: one client delivers VPN, 802.1X supplicant, posture assessment and DNS protection.

## Cisco ISE and network access control

**Cisco Identity Services Engine (ISE)** is the policy server behind wired, wireless and VPN access. It is a RADIUS server (and TACACS+ for device administration) with a policy engine that decides **who and what** gets on the network and **with which access**.

### 802.1X roles

| Role | Who | Speaks |
|---|---|---|
| **Supplicant** | The endpoint's 802.1X client (built into Windows, macOS, Linux; or Secure Client NAM) | EAP over LAN (EAPOL, EtherType 0x888E) to the switch |
| **Authenticator** | The switch port or wireless controller | EAPOL toward the supplicant; RADIUS toward the server, relaying EAP inside RADIUS |
| **Authentication server** | ISE | RADIUS; runs the EAP method with the supplicant and returns the result and authorization |

Until authentication succeeds, the switch port allows only EAPOL (plus anything an explicit pre-authentication policy permits). The flow: the supplicant starts with EAPOL-Start or the switch sends an EAP Request/Identity; the identity is forwarded to ISE in a RADIUS Access-Request; ISE and the supplicant run the EAP method through the switch; ISE sends Access-Accept with authorization attributes (a VLAN, a downloadable ACL, an SGT) or Access-Reject; the switch sends EAP-Success and opens the port.

### EAP methods

EAP (RFC 3748) is a framework; the **method** decides how the endpoint proves itself:

| Method | Credentials | Notes |
|---|---|---|
| EAP-TLS | Client and server certificates | Strongest and most common for managed devices; needs a PKI |
| PEAP (with EAP-MSCHAPv2 inside) | Server certificate; username and password inside the tunnel | Common for user passwords from Active Directory |
| EAP-FAST | A protected access credential (PAC) or certificates | Cisco-developed tunnelled method |
| EAP-TTLS | Server certificate; inner password methods | Common on non-Windows clients |
| TEAP | Tunnel that can carry machine **and** user authentication (EAP chaining) | Standardised successor to EAP-FAST chaining |

### MAB and WebAuth

Not every device has a supplicant. **MAC Authentication Bypass (MAB)**: when a port sees no EAPOL response (after the 802.1X timeout, or immediately if configured to try MAB first), the switch sends the device's MAC address to ISE as the username in a RADIUS request. ISE checks it against an endpoint list or profiling result. MAB suits printers, phones and cameras, but a MAC address is easy to spoof, so it should come with profiling and restrictive authorization.

**Web authentication (WebAuth)**: the user is redirected to a web portal to log in or accept terms. In **central WebAuth** (CWA) the switch applies a redirect ACL and URL from ISE and ISE hosts the portal; it is typical for guest access. **Local WebAuth** runs the portal on the switch or controller.

Typical order on a wired port: 802.1X first, then MAB as the fallback; guests caught by MAB get a CWA redirect. Classic IOS XE interface commands such as `authentication port-control auto`, `dot1x pae authenticator` and `mab` (or the newer `access-session` and policy-map forms) are configuration detail beyond this "describe" topic.

### Profiling, posture and Change of Authorization

- **Profiling**: ISE classifies endpoints from what it can observe (RADIUS attributes, DHCP options, CDP and LLDP, HTTP user agent, NetFlow, Nmap scans) as "Cisco IP phone", "HP printer" or "Windows workstation", and policy can use the profile.
- **Posture**: the Secure Client ISE Posture module checks the endpoint against requirements (OS patches, anti-malware running and current, disk encryption) and reports **compliant**, **non-compliant** or **unknown**. A non-compliant endpoint gets a remediation network until it is fixed.
- **Change of Authorization (CoA)**, RFC 5176: RADIUS normally works only in one direction, switch asks and server answers. CoA lets ISE **push** a change to the switch for an existing session (re-authenticate, apply a new VLAN or ACL, bounce or shut the port) when something changes: posture becomes compliant, profiling identifies the device, or an administrator or a product such as Secure Network Analytics asks to quarantine the host. The RFC port for CoA is UDP 3799; Cisco ISE and IOS XE (`aaa server radius dynamic-author`) use UDP 1700 by default, so the two ends must agree.

> **Exam tip:** Posture changes after the endpoint is already connected, so ISE needs CoA to change its access without waiting for the next authentication. "Supplicant, authenticator, authentication server" are the 802.1X roles; the switch is always the authenticator.

## Lab it yourself

ISE needs a large VM, so the practical route is the ISE DevNet sandbox or a reservable lab (any host OS). With local resources only:

1. In Cisco Modeling Labs, GNS3 or EVE-NG (Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a DevNet sandbox), build a Catalyst 9000v and a Linux host with `wpa_supplicant`, and a FreeRADIUS server VM, to see 802.1X with EAP between three real roles.
2. Capture on the host link and identify EAPOL frames (EtherType 0x888E); capture on the server link and identify RADIUS Access-Request and Access-Accept carrying EAP.
3. Turn off the supplicant and watch the switch fall back to MAB.
4. Read the Secure Endpoint user guide sections on retrospective detection and file trajectory, and sketch how they would show an outbreak.

## Key takeaways

- Secure Endpoint (formerly AMP for Endpoints): file reputation and blocking, plus continuous monitoring, retrospective detection when a verdict changes, file trajectory and device trajectory.
- Secure Client (formerly AnyConnect): one client with VPN, 802.1X supplicant (NAM), ISE posture, Umbrella roaming and visibility modules.
- 802.1X roles: supplicant (endpoint), authenticator (switch, WLC), authentication server (ISE over RADIUS); EAPOL on the access link, EAP inside RADIUS upstream.
- EAP-TLS uses certificates on both sides; PEAP and EAP-TTLS tunnel a password; EAP-FAST and TEAP are tunnelled methods.
- MAB uses the MAC address for devices without a supplicant; WebAuth redirects to a portal (CWA hosted by ISE).
- Profiling identifies device types; posture checks compliance; CoA (RFC 5176: UDP 3799; Cisco default UDP 1700) lets ISE change a live session's access.
