## The ways into a device

Every interactive session on an IOS XE device arrives on a **line**:

| Line | Command | What it is |
|---|---|---|
| Console | `line con 0` | The physical console port (RJ-45 or USB). Always present; the access of last resort |
| Auxiliary | `line aux 0` | A second serial port for an out-of-band modem, found on ISR routers. Catalyst 9000 switches and the Catalyst 8000V have none |
| Virtual terminal | `line vty 0 4`, and usually further ranges such as `line vty 5 15` | Telnet and SSH sessions. Each session uses one free vty line |

How many vty lines exist depends on the platform and release, so check `show running-config | section line vty` and secure **every** range it shows. A hardened `line vty 0 4` with an untouched `line vty 5 15` is a classic audit finding: the sixth concurrent session lands on a line with different rules.

## How a line authenticates (without AAA)

Until `aaa new-model` is entered (next lesson), each line decides how to authenticate with the `login` command:

| Line configuration | Result |
|---|---|
| `no login` | No authentication at all. Typical of the console on a factory-default device |
| `password <SECRET>` and `login` | One shared line password, no username. Weak and unaccountable |
| `login` with no `password` on a vty | Connections are refused: "Password required, but none set" |
| `login local` | Username and password checked against the local database (`username` commands) |

`login local` is the minimum for a production device without AAA: each administrator has a username, so logs and `show users` say who did what.

```text
R1(config)# username netadmin privilege 15 algorithm-type scrypt secret ExamplePass123
R1(config)# line con 0
R1(config-line)# login local
R1(config-line)# exec-timeout 10 0
R1(config-line)# exit
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh
R1(config-line)# exec-timeout 10 0
```

`ExamplePass123` here and throughout this course is a placeholder: use a real, long passphrase on your devices.

> **Watch out:** `login local` with no `username` defined locks everyone out of that line. On the console that means password recovery. Create the user first, test it from a second session, then change the line.

## Password and secret types

IOS stores every password with a **type number** in the configuration, and the type tells you how much protection it has.

| Type | How it is stored | Reversible? | Created by |
|---|---|---|---|
| 0 | Plaintext | Already plain | `password X`, `enable password X` without `service password-encryption` |
| 7 | Cisco's proprietary obfuscation (a Vigenère-style XOR with a fixed, publicly known key) | Yes, instantly, with freely available tools | `service password-encryption` applied to type 0 passwords |
| 5 | Salted MD5 hash | No, but weak against modern cracking | `secret X` on older releases |
| 4 | A flawed SHA-256 implementation | No, but easily cracked | Withdrawn; never use |
| 6 | AES encryption with a device master key | Yes, by the device that holds the key | `key config-key password-encrypt` plus `password encryption aes` |
| 8 | PBKDF2 with SHA-256 | No | `algorithm-type sha256 secret X` |
| 9 | scrypt | No | `algorithm-type scrypt secret X` |

What you see in the running configuration is the type and the stored value, never the password you typed:

```text
username netadmin privilege 15 secret 9 <HASH>
enable secret 9 <HASH>
line vty 0 4
 password 7 <ENCODED>
```

Rules worth memorising:

- **`secret` always hashes; `password` stores plaintext** (type 0) unless `service password-encryption` turns it into type 7.
- **Type 7 is obfuscation, not security.** It only stops someone reading a password over your shoulder. Anyone with the configuration file can reverse it.
- **Type 8 and type 9 are the ones to use** for local accounts and the enable secret. Use `algorithm-type scrypt` (type 9) or `algorithm-type sha256` (type 8) explicitly, because the type an unqualified `secret` produces depends on the release.
- **Type 6** is for values the device itself must recover in plaintext, such as RADIUS and TACACS+ keys or IKE pre-shared keys. It protects them in the configuration file, but they are reversible on the device.

### `enable secret` versus `enable password`

`enable password` is the legacy, reversible form; `enable secret` is hashed. If both are configured, **`enable secret` wins** and the `enable password` is ignored. Current releases warn if you set them to the same value. Configure only `enable secret`, for example `enable algorithm-type scrypt secret ExamplePass123`.

### `service password-encryption`

This global command converts every type 0 **password** in the configuration (line passwords, `enable password`, `username ... password`, some keys) to type 7. It does nothing to `secret` values, which are already hashed. Removing it with `no service password-encryption` does **not** turn existing type 7 strings back into plaintext; it only stops new passwords being encoded. Enable it anyway, because it keeps passwords out of casual view, but never treat type 7 as protection.

## Privilege levels

IOS has 16 privilege levels:

| Level | Meaning |
|---|---|
| 0 | Only `disable`, `enable`, `exit`, `help` and `logout` |
| 1 | User EXEC: the `>` prompt; basic `show`, `ping`, `traceroute` |
| 2 to 14 | Unused by default; you move commands into them |
| 15 | Privileged EXEC: the `#` prompt; everything |

A user arrives at the level in their `username ... privilege N` entry (with `login local`), or at level 1 and then types `enable` (level 15) or `enable N` with a matching `enable secret level N`. `show privilege` prints `Current privilege level is 15`.

Custom levels give a help-desk role a few extra commands without full access:

```text
R1(config)# privilege exec level 5 clear counters
R1(config)# privilege exec level 5 configure terminal
R1(config)# privilege configure level 5 interface
R1(config)# privilege interface level 5 shutdown
R1(config)# privilege interface level 5 no shutdown
R1(config)# username helpdesk privilege 5 algorithm-type scrypt secret ExamplePass123
```

A level-5 user also inherits every level 0 to 4 command. Moving a command to a level **lowers or raises who can run it for everyone**, so moving a command up from level 1 removes it from ordinary users.

> **Exam tip:** Moving `show running-config` to a lower level is a known trap: the user can run it, but it displays only the configuration commands that user is allowed to enter, so the output is nearly empty. Use `show running-config` at level 15, or AAA command authorization, instead.

Local privilege levels are hard to manage on hundreds of devices. In production, per-command authorization comes from TACACS+ (next lesson); local levels remain the fallback.

## SSH instead of Telnet

Telnet sends usernames, passwords and the session in clear text. SSH version 2 encrypts the session. The IOS XE setup:

```text
R1(config)# hostname R1
R1(config)# ip domain name example.com
R1(config)# crypto key generate rsa modulus 2048
The name for the keys will be: R1.example.com
% The key modulus size is 2048 bits
% Generating 2048 bit RSA keys, keys will be non-exportable...
[OK]
R1(config)# ip ssh version 2
R1(config)# line vty 0 4
R1(config-line)# transport input ssh
R1(config-line)# login local
```

- **Hostname and domain name come first**: the default key pair is named `hostname.domain`. Without a domain name, `crypto key generate rsa` refuses with a message asking you to define one.
- **Modulus 2048** is the practical minimum today. SSH version 2 needs an RSA key of at least 768 bits, so smaller keys cannot serve SSHv2 at all; anything under 2048 is weak, and larger keys (3072, 4096) take longer to generate.
- Generating the key is what enables the SSH server. Removing the key (`crypto key zeroize rsa`) disables it.
- **`ip ssh version 2`** disables SSHv1. Older releases otherwise run in a compatibility mode shown as version 1.99. On current IOS XE releases SSH is version 2 only and the command is the default, but configure it anyway: the exam expects it.
- **`transport input ssh`** refuses Telnet on those lines. `transport input none` refuses everything (handy on lines you want closed), and `transport input telnet ssh` allows both. The default differs between releases, so set it explicitly.

```text
R1# show ip ssh
SSH Enabled - version 2.0
Authentication methods:publickey,keyboard-interactive,password
<algorithm lines omitted>
Authentication timeout: 120 secs; Authentication retries: 3
Minimum expected Diffie Hellman key size : 2048 bits
```

`show ssh` lists the active SSH sessions with their encryption and username.

## Limiting who and how long

**`exec-timeout minutes [seconds]`** logs out an idle session. The default is 10 minutes (`exec-timeout 10 0`). `exec-timeout 0 0` never times out: convenient in a lab, a finding in an audit, because an unattended console stays logged in at level 15.

**`access-class ACL in`** on the vty lines filters by **source address** which hosts may open a session to the device. It works on every interface address at once, so it is simpler than an interface ACL for this job.

```text
R1(config)# ip access-list standard MGMT-HOSTS
R1(config-std-nacl)# permit 10.99.0.0 0.0.0.255
R1(config-std-nacl)# exit
R1(config)# line vty 0 15
R1(config-line)# access-class MGMT-HOSTS in vrf-also
```

The **`vrf-also`** keyword matters on any device managed through a VRF, including the `Mgmt-vrf` port of a Catalyst 9000 or `Mgmt-intf` on a router: without it, the access class applies to connections from the global table only and sessions arriving through a VRF interface are refused. `access-class ACL out` is different: it limits where a user may connect **to** from that line (for example with `ssh` from the device).

**`login block-for`** slows password guessing:

```text
R1(config)# login block-for 120 attempts 3 within 60
R1(config)# login quiet-mode access-class MGMT-HOSTS
R1(config)# login on-failure log
```

Three failed logins within 60 seconds put the device into **quiet mode** for 120 seconds, during which it refuses all Telnet, SSH and HTTP logins, except from hosts permitted by the `quiet-mode access-class`. That exception keeps your own management station working while an attacker is locked out. `show login` shows the settings and whether quiet mode is active.

> **Real world:** Quiet mode blocks everyone not in the exception ACL, including your colleagues. Always pair `login block-for` with `login quiet-mode access-class`.

## Verifying

| Command | What it shows |
|---|---|
| `show users` | Who is logged in, on which line (`con 0`, `vty 0`), idle time and source address; `*` marks your own session |
| `show line` | Every line with its type, use count and status; `show line vty 0` gives one line's details, including timeouts and allowed transports |
| `show ip ssh` | SSH enabled or not, version, timeout and retries |
| `show ssh` | Active SSH connections |
| `show privilege` | Your current privilege level |
| `show login` | `login block-for` settings and quiet-mode state |
| `show running-config \| section line` | The line configuration as entered |

To clear a stuck session: find its line in `show users` and use `clear line vty N`.

## Lab it yourself

Use one IOS XE router (Catalyst 8000V or IOL-XE) and one Linux or IOSv host in Cisco Modeling Labs, GNS3 or EVE-NG. These run Cisco's x86 images on Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a Cisco DevNet sandbox.

1. Connect the host to R1 Gi2 in 10.99.0.0/24. Note that the console needs no login.
2. Create `username netadmin privilege 15 algorithm-type scrypt secret ExamplePass123` and `username helpdesk privilege 5 algorithm-type scrypt secret ExamplePass123` (lab-only values). Look at the running configuration: both show `secret 9`.
3. Configure `line vty 0 4` with `password Lab-Only-Pass` (a lab-only placeholder), `login`, and `transport input telnet`. Telnet in, then turn on `service password-encryption` and see the line password become type 7.
4. Set up SSH: hostname, `ip domain name example.com`, `crypto key generate rsa modulus 2048`, `ip ssh version 2`, then `login local` and `transport input ssh` on every vty range. Confirm Telnet is refused and `ssh -l netadmin 10.99.0.1` works. Check `show ip ssh`, `show users`, `show ssh`.
5. Add the level-5 commands from this lesson and log in as `helpdesk`: run `show privilege`, `clear counters`, and try `reload` (rejected).
6. Apply `access-class MGMT-HOSTS in vrf-also`, then change the ACL to exclude your host and watch the connection being refused.
7. Configure `login block-for 60 attempts 3 within 30`, fail three logins and check `show login`.

## Key takeaways

- Lines: `con 0`, `aux 0` (ISR only), and every vty range; secure all vty ranges the device has.
- `login` uses the line password, `login local` the username database, `no login` nothing; with no password a vty refuses connections.
- Types: 0 plaintext, 7 reversible obfuscation, 5 MD5, 6 reversible AES, 8 PBKDF2-SHA-256, 9 scrypt. Use `algorithm-type scrypt` or `sha256` for secrets.
- `enable secret` overrides `enable password`; `service password-encryption` only produces type 7 and is not undone by removing it.
- Privilege levels 0, 1 and 15 exist by default; `privilege exec level N command` builds custom levels; `show privilege` verifies.
- SSH: hostname, `ip domain name`, `crypto key generate rsa modulus 2048`, `ip ssh version 2`, `transport input ssh`, `login local`.
- `exec-timeout` (default 10 minutes), `access-class ... in vrf-also`, and `login block-for` with a quiet-mode exception harden the lines; verify with `show users`, `show line`, `show ip ssh`, `show login`.
