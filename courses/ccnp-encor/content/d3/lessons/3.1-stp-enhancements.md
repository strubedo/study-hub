## What the enhancements protect against

Spanning tree trusts every BPDU it receives and assumes that a link that carries no BPDUs has no switch on it. The enhancements add rules at the edges of that trust:

| Problem | Feature | Where to apply it |
|---|---|---|
| Host ports wait 30 s and cause topology changes | **PortFast** | Ports to end hosts, servers, hypervisors |
| Someone plugs a switch into a user port | **BPDU guard** | PortFast ports |
| A port must not send or process BPDUs at all | **BPDU filter** | Rarely: provider handoffs, isolated segments |
| A downstream switch tries to become root | **Root guard** | Distribution ports facing access switches |
| A blocked port stops receiving BPDUs and starts forwarding | **Loop guard** | Root and alternate ports on uplinks |
| One direction of a fibre link fails, link stays up | **UDLD** | Fibre (and copper) inter-switch links |

## PortFast

```text
ASW1(config)# interface GigabitEthernet1/0/15
ASW1(config-if)# switchport mode access
ASW1(config-if)# spanning-tree portfast
%Warning: portfast should only be enabled on ports connected to a single
 host. Connecting hubs, concentrators, switches, bridges, etc... to this
 interface  when portfast is enabled, can cause temporary bridging loops.
 Use with CAUTION
```

A PortFast port is an **edge port**: it goes straight to forwarding at link-up and never generates topology changes. It still **sends** BPDUs, and if it **receives** one it loses its operational PortFast status and runs normal spanning tree.

- `spanning-tree portfast` applies to access ports only. On a trunk to a server or hypervisor that carries several VLANs, use `spanning-tree portfast trunk` (shown as "portfast edge trunk" mode on newer releases).
- `spanning-tree portfast default` (global) enables PortFast on **every access port**; trunks are not affected. Disable it on one port with `spanning-tree portfast disable`.
- Some IOS XE releases display and accept the explicit `edge` keyword (`spanning-tree portfast edge`, `spanning-tree portfast edge default`); the meaning is the same. The `network` port type belongs to Bridge Assurance and is not a PortFast variant.

Verify: `Edge` in the Type column of `show spanning-tree`, "The port is in the portfast mode" in `show spanning-tree interface Gi1/0/15 detail`, and `show spanning-tree interface Gi1/0/15 portfast`.

## BPDU guard

BPDU guard **err-disables** a port the moment it receives any BPDU.

```text
ASW1(config-if)# spanning-tree bpduguard enable
! or globally, for every port that is operationally PortFast:
ASW1(config)# spanning-tree portfast bpduguard default
```

The two forms differ: the interface command works on any port, PortFast or not; the global command applies only to ports that are currently in PortFast (edge) mode. When it triggers:

```text
%SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port GigabitEthernet1/0/15 with BPDU Guard enabled. Disabling port.
%PM-4-ERR_DISABLE: bpduguard error detected on Gi1/0/15, putting Gi1/0/15 in err-disable state

ASW1# show interfaces status err-disabled

Port         Name               Status       Reason               Err-disabled Vlans
Gi1/0/15                        err-disabled bpduguard
```

The port stays down until someone recovers it (below). Remove the switch first, or it will err-disable again.

## BPDU filter

BPDU filter suppresses BPDUs, and its two forms behave very differently:

| | Interface: `spanning-tree bpdufilter enable` | Global: `spanning-tree portfast bpdufilter default` |
|---|---|---|
| Applies to | That port, PortFast or not | Ports operating as PortFast |
| Sends BPDUs | Never | A few at link-up, then stops |
| Received BPDUs | **Ignored**: spanning tree is effectively disabled on the port | The port loses PortFast and BPDU filtering and runs normal STP |
| Risk | A loop through this port is never detected | Low: a switch that appears is noticed |

> **Watch out:** The interface form switches spanning tree off for that port. If two such ports are cabled together, directly or through another switch, the loop is never blocked. Use the interface form only where BPDUs must not cross a boundary by design, and prefer BPDU guard on user ports. When BPDU filter and BPDU guard are both on a port, filtering wins and guard never sees a BPDU.

`show spanning-tree summary` shows the global defaults ("Portfast Edge BPDU Guard Default" and "Portfast Edge BPDU Filter Default" on current releases, without "Edge" on older ones); `show spanning-tree interface Gi1/0/15 detail` shows "Bpdu filter is enabled" or "Bpdu guard is enabled" per port.

## Root guard

Root guard enforces where the root may be. On a port with `spanning-tree guard root`, a **superior BPDU** (one that would make the port a root port) puts the port into the **root-inconsistent** state for that VLAN: it blocks, like a listening port, instead of accepting the new root.

```text
DSW1(config)# interface GigabitEthernet1/0/24
DSW1(config-if)# spanning-tree guard root
```

```text
%SPANTREE-2-ROOTGUARD_BLOCK: Root guard blocking port GigabitEthernet1/0/24 on VLAN0010.

DSW1# show spanning-tree inconsistentports

Name                 Interface                      Inconsistency
-------------------- ------------------------------ ------------------
VLAN0010             GigabitEthernet1/0/24          Root Inconsistent

Number of inconsistent ports (segments) in the system : 1
```

In `show spanning-tree vlan 10` the port appears as `Desg BKN*` with `*ROOT_Inc`. Recovery is **automatic**: when the superior BPDUs stop (someone removes the low priority on the access switch), the port leaves the inconsistent state and transitions back to forwarding through the normal spanning-tree process. Apply root guard on the distribution ports facing access switches, never on a port that should lead to the root.

## Loop guard

Loop guard protects against the other failure: a non-designated port (root or alternate) that **stops receiving BPDUs** while the link stays up, because of a unidirectional link or a software fault upstream. Normal STP would age out the information and make the port designated forwarding, closing a loop. With loop guard the port moves to **loop-inconsistent** (blocking) instead.

```text
ASW1(config)# spanning-tree loopguard default
! or per port:
ASW1(config-if)# spanning-tree guard loop
```

```text
%SPANTREE-2-LOOPGUARD_BLOCK: Loop guard blocking port GigabitEthernet1/0/2 on VLAN0020.
```

It shows as `*LOOP_Inc` and "Loop Inconsistent" in `show spanning-tree inconsistentports`, and it recovers automatically when BPDUs arrive again. Loop guard and root guard are mutually exclusive on a port (`spanning-tree guard` takes one value), and loop guard is pointless on edge ports. Apply it on point-to-point inter-switch links, typically globally.

## UDLD

**UniDirectional Link Detection** is a Cisco Layer 2 protocol that detects links where traffic flows in only one direction: one fibre of a pair broken or miscabled, or a faulty transceiver, while the link itself stays up. Each side sends UDLD messages (every **15 seconds** by default) that echo the neighbour's device and port IDs. If a switch's messages do not come back in the neighbour's echoes, or come back from the wrong port, the link is unidirectional or miswired.

| Mode | Command | Action |
|---|---|---|
| **Normal** | `udld enable` (global, fibre ports) or `udld port` (interface) | Err-disables the port when the echoes **positively show** a unidirectional or miswired link (for example crossed fibre strands); if messages simply stop, marks the port undetermined and takes no action |
| **Aggressive** | `udld aggressive` (global, fibre ports) or `udld port aggressive` (interface) | Also err-disables when messages stop on a link that is still up, after trying to re-establish contact |

The global commands apply only to **fibre** ports; enable copper ports per interface. Both ends must run UDLD. UDLD complements loop guard: UDLD acts on the link, loop guard on the spanning-tree state, and running both is common.

```text
%UDLD-4-UDLD_PORT_DISABLED: UDLD disabled interface Te1/1/1, aggressive mode failure detected
%PM-4-ERR_DISABLE: udld error detected on Te1/1/1, putting Te1/1/1 in err-disable state
```

`show udld Te1/1/1` shows the operational state ("Bidirectional", "Unidirectional", "Undetermined") and the neighbour; `show udld neighbors` lists all neighbours; `udld reset` re-enables every port that UDLD shut down.

> **Watch out:** IOS XE 17.15 and later mark the interface `udld port` syntax as deprecated in the YANG models and introduce a new form. Check the command reference for your release before scripting UDLD changes.

## Err-disable recovery

BPDU guard, UDLD, EtherChannel misconfig guard and several security features place a port in the **err-disabled** state. Recover manually with `shutdown` then `no shutdown` on the interface after fixing the cause, or let the switch retry:

```text
ASW1(config)# errdisable recovery cause bpduguard
ASW1(config)# errdisable recovery cause udld
ASW1(config)# errdisable recovery interval 300
```

Automatic recovery is **off** for every cause by default. The interval (30–86400 seconds, default 300) applies to all causes. `show errdisable recovery` lists each cause with "Enabled" or "Disabled" and the ports waiting with their time left; `show interfaces status err-disabled` lists err-disabled ports and their reason.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (they run Cisco's x86 images; on an Apple silicon Mac use a remote x86 server or a CML instance in a DevNet Sandbox), with DSW1, ASW1 and a spare switch SW9 (IOSvL2 or Catalyst 9000v), plus a host. UDLD needs real optics to show a genuine one-way failure; in a virtual lab you can only configure and verify it.

1. On ASW1 Gi1/0/15 enable `spanning-tree portfast` and connect the host; confirm `Edge`. Then add `spanning-tree bpduguard enable` and connect SW9 instead: read the log and `show interfaces status err-disabled`.
2. Configure `errdisable recovery cause bpduguard` with `errdisable recovery interval 30`, watch `show errdisable recovery` count down, then reconnect the host.
3. On DSW1's port toward ASW1 configure `spanning-tree guard root`. Give ASW1 `spanning-tree vlan 10 priority 0` and read `show spanning-tree inconsistentports` on DSW1; remove the priority and watch automatic recovery.
4. Enable `spanning-tree loopguard default` on ASW1 and check "Loop guard is enabled by default on the port" in `show spanning-tree interface Gi1/0/2 detail`.
5. Replace BPDU guard on the host port with `spanning-tree bpdufilter enable`, connect SW9 with a second cable to DSW1, and observe that the loop is no longer blocked; remove it.

## Key takeaways

- PortFast: edge port, immediate forwarding, no topology changes; `spanning-tree portfast` (access), `portfast trunk`, global `spanning-tree portfast default` (access ports only). A received BPDU removes edge status.
- BPDU guard err-disables on any BPDU: interface `spanning-tree bpduguard enable` on any port, global `spanning-tree portfast bpduguard default` only on PortFast ports.
- BPDU filter: the interface form disables STP on the port (dangerous); the global form only affects PortFast ports and reverts them to normal STP when a BPDU arrives.
- Root guard: superior BPDU puts the port root-inconsistent (`*ROOT_Inc`); recovers automatically. Use on ports facing access switches.
- Loop guard: missing BPDUs on root or alternate ports put them loop-inconsistent (`*LOOP_Inc`); recovers automatically. Not combinable with root guard.
- UDLD detects one-way links; normal acts only on positive detection, aggressive also when messages stop; global commands cover fibre only; 15 s messages.
- Err-disable: recover with `shutdown`/`no shutdown` or `errdisable recovery cause ...` (off by default, interval 300 s).
