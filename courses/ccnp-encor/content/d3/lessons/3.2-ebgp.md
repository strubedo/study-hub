## BGP in one page

BGP-4 (RFC 4271) is the path vector protocol between autonomous systems (ASes). ENCOR expects you to configure **eBGP between directly connected neighbors** and read the results.

| Property | Value |
|---|---|
| Transport | **TCP port 179**; peers are configured manually, never discovered |
| Session types | **eBGP** between different ASes; **iBGP** inside one AS |
| Administrative distance | eBGP **20**, iBGP **200**, locally generated (aggregates) **200** |
| Timers (IOS default) | Keepalive **60 s**, hold **180 s**; the lower hold time offered in the two OPEN messages is used |
| Loop prevention (eBGP) | A router rejects any route whose AS_PATH contains its own AS number |
| Metric | Path attributes, compared by the best-path algorithm (next lesson) |
| ASN | 2-byte 1–65535 or 4-byte; private 64512–65534 and 4200000000–4294967294 |

RFC 4271 suggests a 90-second hold time; Cisco IOS defaults to 180 seconds with 60-second keepalives (one third of the hold time). `timers bgp KEEPALIVE HOLD` changes it for all neighbors, `neighbor ... timers` for one.

## Message types

| Message | Purpose |
|---|---|
| **OPEN** | First message after TCP connects: BGP version (4), the sender's AS, hold time, BGP identifier (router ID) and optional capabilities (4-byte ASN, address families, route refresh) |
| **KEEPALIVE** | Confirms the OPEN and then keeps the session alive; sent every keepalive interval |
| **UPDATE** | Advertises new paths (NLRI plus path attributes) and withdraws unreachable prefixes |
| **NOTIFICATION** | Reports an error and **closes the session** (for example "bad peer AS", "hold timer expired") |
| ROUTE-REFRESH (RFC 2918) | Asks a peer to resend its updates; used by `clear ip bgp ... soft in` |

## The neighbor state machine

| State | Meaning |
|---|---|
| **Idle** | Not trying yet: the starting state, after an error, or when the neighbor is shut down (`Idle (Admin)`) or has no route to the peer |
| **Connect** | Waiting for the TCP connection to complete |
| **Active** | The TCP attempt failed or timed out; retrying and listening for the peer to connect. A neighbor that **stays in Active** cannot complete TCP |
| **OpenSent** | TCP is up and an OPEN was sent; waiting for the peer's OPEN |
| **OpenConfirm** | A valid OPEN was received and a KEEPALIVE sent; waiting for the peer's KEEPALIVE |
| **Established** | Peers exchange UPDATE messages |

Despite its name, Active is a bad sign: TCP is not getting through (causes are in the fault table below). An AS number mismatch gets further: TCP connects, the OPEN carries the wrong AS, the router sends a NOTIFICATION and the session drops back to Idle and Active in a cycle.

## Basic eBGP configuration

```text
R1(config)# router bgp 65001
R1(config-router)# bgp router-id 10.255.0.1
R1(config-router)# bgp log-neighbor-changes
R1(config-router)# neighbor 10.0.12.2 remote-as 65002
R1(config-router)# neighbor 10.0.12.2 description ISP-A
R1(config-router)# address-family ipv4 unicast
R1(config-router-af)# network 10.10.0.0 mask 255.255.0.0
R1(config-router-af)# neighbor 10.0.12.2 activate
R1(config-router-af)# exit-address-family
```

- `router bgp 65001` declares the local AS (one BGP process per router).
- `neighbor IP remote-as ASN`: a different ASN makes it eBGP, the same ASN iBGP. The address must be the address the peer's packets come from.
- The BGP router ID is chosen like OSPF's (configured, else highest up loopback, else highest up interface). Set it.
- IPv4 unicast neighbors are activated in the IPv4 address family by default on IOS XE unless `no bgp default ipv4-unicast` is configured; with that command, or for IPv6, `neighbor ... activate` under the address family is required. IPv6 neighbors are configured the same way with IPv6 addresses and `address-family ipv6 unicast`, where `network 2001:DB8:10::/48` uses prefix-length notation.

**The `network` command does not enable BGP on interfaces.** It says "advertise this prefix if an **exact match** (same prefix and mask) is in the routing table". `network 10.10.0.0 mask 255.255.0.0` advertises nothing if the RIB has only 10.10.1.0/24 and 10.10.2.0/24. Fixes: advertise the /24s that exist, add a static route `ip route 10.10.0.0 255.255.0.0 Null0` so the /16 exists (the standard way to originate an aggregate), or use `aggregate-address` once a component is in BGP. Without `mask`, the classful mask is assumed. Routes can also enter BGP with `redistribute` (origin incomplete `?`).

## eBGP TTL, update-source and multihop

By default IOS sends eBGP packets with **IP TTL 1** and expects an eBGP neighbor to be on a directly connected subnet. Peering on physical interface addresses therefore just works. When you peer between **loopbacks** (for example, to survive the loss of one of two parallel links), three things are needed on both routers:

```text
R1(config)# ip route 10.255.0.2 255.255.255.255 10.0.12.2
R1(config)# router bgp 65001
R1(config-router)# neighbor 10.255.0.2 remote-as 65002
R1(config-router)# neighbor 10.255.0.2 update-source Loopback0
R1(config-router)# neighbor 10.255.0.2 ebgp-multihop 2
```

- A **route** to the peer's loopback (static or IGP), or the session stays Idle or Active.
- `update-source Loopback0`, so packets come **from** the address the peer has configured as its neighbor. Without it, R1 sources the session from its outgoing interface and R2 rejects the connection as coming from an unknown neighbor.
- `ebgp-multihop 2` raises the TTL (without a number it is 255) and lifts the directly connected check. For directly connected routers peering on loopbacks, `neighbor ... disable-connected-check` is an alternative that keeps TTL 1.

`neighbor ... ttl-security hops N` is a different feature: it sends TTL 255 and accepts only packets whose TTL shows they came from at most N hops away, which protects the session from remote spoofing. It cannot be combined with `ebgp-multihop`.

## Reading `show ip bgp summary`

```text
R1# show ip bgp summary
BGP router identifier 10.255.0.1, local AS number 65001
BGP table version is 23, main routing table version 23
4 network entries using 1024 bytes of memory
4 path entries using 480 bytes of memory
<output omitted>

Neighbor        V           AS MsgRcvd MsgSent   TblVer  InQ OutQ Up/Down  State/PfxRcd
10.0.12.2       4        65002    1452    1447       23    0    0 21:47:12        3
10.0.13.3       4        65003       0       0        1    0    0 00:02:10 Active
10.0.14.4       4        65004       0       0        1    0    0 00:12:30 Idle (Admin)
```

- The last column is the key: a **number** means Established, and the number is prefixes received from that neighbor. Anything else (`Idle`, `Active`, `Idle (Admin)`, `Idle (PfxCt)` after a maximum-prefix shutdown) is the current state of a session that is **not** up.
- Up/Down is how long the session has been up or down (`never` if it never came up).

`show ip bgp neighbors 10.0.12.2` gives everything else: "BGP state = Established, up for 21:47:12", the hold time and keepalive in use ("hold time is 180, keepalive interval is 60 seconds"), capabilities, message counters, the last reset reason and the TCP connection details.

```text
              t secondary path, L long-lived-stale,
Origin codes: i - IGP, e - EGP, ? - incomplete
RPKI validation codes: V valid, I invalid, N Not found

     Network          Next Hop            Metric LocPrf Weight Path
 r>  10.0.12.0/30     10.0.12.2                0             0 65002 ?
 *>  10.10.0.0/16     0.0.0.0                  0         32768 i
 *>  10.20.0.0/16     10.0.12.2                0             0 65002 i
 *>  10.30.0.0/16     10.0.12.2                              0 65002 64512 i
```

Prefixes are listed in address order, so the /30 comes first.

| Field | Meaning |
|---|---|
| `*` | Valid: the next hop is reachable |
| `>` | Best path for this prefix, the one offered to the routing table |
| `i` (status) | Learned from an iBGP peer |
| `r` | RIB failure: the best path was not installed because a route with a better AD exists (here the connected /30) |
| Next Hop `0.0.0.0` | Originated by this router (`network` or `redistribute`) |
| Metric | MED (multi-exit discriminator) received, if any |
| LocPrf | Local preference; shown for iBGP-learned and locally set paths, blank for plain eBGP-learned paths (100 applies) |
| Weight | Cisco-only, local to this router: **32768** for locally originated paths, **0** for learned paths by default |
| Path | AS_PATH, nearest AS first, origin AS last |
| Origin code | `i` IGP (`network` command), `e` EGP (historic), `?` incomplete (redistributed) |

Several lines for one prefix are alternative paths; only one carries `>`. `show ip bgp 10.30.0.0/16` shows each path's attributes, and `show ip route bgp` shows what was installed (`B` routes, `[20/0]` for eBGP).

## AS-path loop prevention

When R1 sends a route to an eBGP peer, it prepends its own AS to the AS_PATH. A router that receives an update containing its own AS drops it. That is BGP's loop prevention, and it explains a classic design problem: two sites of one company that both use AS 65001 over a provider's network never see each other's routes, because each sees 65001 in the path. Solutions are `neighbor ... allowas-in` on the customer routers or `neighbor ... as-override` on the provider side.

## Common adjacency faults

| Symptom | Likely cause |
|---|---|
| Stays `Active` | No route to the peer, wrong neighbor address, TCP 179 blocked, peer has no `neighbor` statement for this router |
| `Idle` with loopback peering | Missing `ebgp-multihop` (or `disable-connected-check`) for an eBGP loopback peer, or no route to the loopback |
| Cycles Idle and Active, NOTIFICATION "bad peer AS" in the log | `remote-as` does not match the peer's `router bgp` ASN |
| Connection refused by the peer, session never leaves Active | Peer expects a different source address: missing `update-source` |
| `Idle (Admin)` | `neighbor ... shutdown` |
| Established but `PfxRcd 0` | Peer advertises nothing (its `network` has no exact RIB match, or an outbound filter), or an inbound filter here drops everything |
| Drops every 3 minutes, "hold time expired" | Keepalives lost: MTU problems with large updates, CPU, or an unstable path to a multihop peer |
| Authentication failure log | `neighbor ... password` (TCP MD5) mismatch, for example a lab key such as `Lab-Only-Key` on one side only |

Use `show ip bgp summary`, `show ip bgp neighbors`, the log (`bgp log-neighbor-changes` is on by default on IOS XE) and briefly `debug ip bgp`. After a policy change, `clear ip bgp 10.0.12.2 soft in` (or `out`) refreshes routes without resetting the session.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML), with three IOSv or Catalyst 8000v routers: R1 in AS 65001, R2 in AS 65002, R3 in AS 65003, R1 connected to both.

1. Configure eBGP from R1 to R2 and R3 on the link addresses. Watch the log for `%BGP-5-ADJCHANGE: neighbor 10.0.12.2 Up` and check `show ip bgp summary`.
2. On R2 create Loopback10 10.20.0.1/16 and advertise it with `network 10.20.0.0 mask 255.255.0.0`. Then try `network 10.20.0.0 mask 255.255.255.0` and see that nothing new appears.
3. On R1 advertise 10.10.0.0/16 with a `Null0` static route; confirm next hop `0.0.0.0` and weight 32768 locally, and the AS path `65001` on R2.
4. Change R1's `remote-as` for R3 to a wrong ASN and read the NOTIFICATION in the log and the state in the summary.
5. Add second links between R1 and R2, peer on loopbacks with `update-source` and static routes; first omit `ebgp-multihop` and note the state, then add it.
6. Check the timers with `show ip bgp neighbors | include hold time`, then set `timers bgp 10 30` on R1, reset the session (`clear ip bgp 10.0.12.2`; new timers apply only to new sessions), and see the negotiated value on both routers.

## Key takeaways

- BGP runs over TCP 179 with manually configured neighbors; eBGP AD 20, iBGP AD 200; Cisco timers 60 s keepalive and 180 s hold.
- Messages: OPEN, KEEPALIVE, UPDATE, NOTIFICATION (and ROUTE-REFRESH). States: Idle, Connect, Active, OpenSent, OpenConfirm, Established.
- `neighbor IP remote-as ASN` builds the session; `network PREFIX mask MASK` advertises only an exact RIB match.
- eBGP uses TTL 1 and expects a directly connected peer; loopback peering needs a route, `update-source` and `ebgp-multihop` (or `disable-connected-check`).
- In `show ip bgp summary`, a number in State/PfxRcd means Established; a word means down.
- In `show ip bgp`: `*` valid, `>` best, `r` RIB failure; next hop 0.0.0.0 and weight 32768 mean locally originated; origin `i`, `e`, `?`.
- eBGP drops routes containing its own AS in the AS_PATH.
