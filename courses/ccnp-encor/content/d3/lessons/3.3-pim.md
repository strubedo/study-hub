## PIM basics

Protocol Independent Multicast builds multicast distribution trees between routers. "Protocol independent" means it has no routing protocol of its own: it uses whatever unicast routing table exists (OSPF, EIGRP, BGP, static) for its RPF checks.

| Item | Value |
|---|---|
| IP protocol | **103** |
| Hellos | To **224.0.0.13** (all PIM routers; FF02::D for IPv6), every **30 s**; neighbor holdtime 105 s (3.5 x hello) |
| Designated router (DR) | Per multi-access segment: **highest DR priority** (default 1), then **highest IP address** |
| Join/Prune refresh | Every 60 s |

On IOS XE, PIM is enabled per interface with `ip pim sparse-mode` after `ip multicast-routing` globally (`ip multicast-routing distributed` on IOS XE routers).

## Tree types and notation

| Notation | Tree | Root |
|---|---|---|
| **(S,G)** | Source tree, **shortest-path tree (SPT)** | The source S; each router's path follows its RPF toward S |
| **(\*,G)** | **Shared tree (RPT)** | The **rendezvous point (RP)**; one tree for all sources of group G |

## Dense mode, briefly

PIM dense mode (RFC 3973) floods every group everywhere, then routers with no receivers prune themselves back, and the flood-and-prune repeats every few minutes. It suits only small networks with receivers almost everywhere. Sparse mode is the norm and the focus of the exam.

## PIM sparse mode (RFC 7761)

Nothing is forwarded until someone asks. Receivers and sources meet at the **RP**:

1. A receiver sends an IGMP report for G. Its **last-hop router** (the DR on that segment) creates **(\*,G)** state and sends a **(\*,G) Join** hop by hop toward the RP, each router RPF-checking toward the RP's address. This builds the shared tree.
2. A source starts sending to G. Its **first-hop router** (the DR on the source's segment) encapsulates the packets in unicast **PIM Register** messages to the RP.
3. The RP decapsulates them and sends them down the shared tree. It also sends an **(S,G) Join** toward the source to receive the traffic natively.
4. When native (S,G) traffic arrives, the RP sends a **Register-Stop** to the first-hop router, which stops encapsulating. Until then, the DR keeps registering, so a missing Register-Stop means the RP is not joining the source (often an RPF or routing problem toward the source).
5. The last-hop router, having learned the source's address from the first packets, sends an **(S,G) Join** toward the **source** and switches to the **shortest-path tree**. Once traffic arrives on the SPT it sends an (S,G) **RP-bit Prune** up the shared tree so it no longer receives the same packets twice.

On Cisco routers the SPT switchover happens after the **first packet** by default (`ip pim spt-threshold 0`); `ip pim spt-threshold infinity` keeps receivers on the shared tree.

The **DR** matters twice: on the source's segment it registers the source to the RP, and on a receiver segment it sends the joins (the IGMP querier, by contrast, is the lowest IP address).

## Finding the RP

Every router must agree on the group-to-RP mapping.

| Method | How it works |
|---|---|
| **Static** | `ip pim rp-address 10.255.0.1 [ACL] [override]` on every router. Simple, no failover unless you use Anycast RP |
| **Auto-RP** (Cisco) | Candidate RPs announce themselves to **224.0.1.39**; a **mapping agent** picks one per group range (highest IP) and announces the mappings to **224.0.1.40**, which every router listens to. Those groups are themselves flooded in dense mode, so sparse-only networks need `ip pim autorp listener` |
| **BSR** (RFC 5059, standard, PIMv2) | Candidate BSRs elect one **bootstrap router** (highest priority, then highest IP). Candidate RPs unicast their information to the BSR, which floods the full RP set hop by hop in bootstrap messages to 224.0.0.13. Every router then picks the RP for each group the same way (RFC 7761): **longest matching group range** first, then the best (lowest) C-RP priority value, then a hash |

Commands: `ip pim send-rp-announce Loopback0 scope 16` and `ip pim send-rp-discovery Loopback0 scope 16` for Auto-RP; `ip pim bsr-candidate Loopback0` and `ip pim rp-candidate Loopback0` for BSR.

## Source-Specific Multicast (SSM, RFC 4607)

The receiver already knows the source, so no RP is needed:

- Receivers request a **channel (S,G)** with **IGMPv3** (INCLUDE mode).
- The last-hop router sends an **(S,G) Join** straight toward the source. Only **(S,G)** state exists; no shared tree, no Register, no RP.
- The IPv4 range is **232.0.0.0/8**. On IOS XE, `ip pim ssm default` enables SSM for 232/8 (or `ip pim ssm range ACL`), and the receiver interfaces need `ip igmp version 3`.
- Hosts that can only do IGMPv2 can use SSM mapping (the router maps the group to a source with a static or DNS rule).

SSM fits one-to-many applications such as IPTV and market data feeds, and removes the RP as a single point of failure.

## Bidirectional PIM (BIDIR-PIM, RFC 5015)

For many-to-many applications (where every host is both sender and receiver, such as trading floors or video conferencing), sparse mode creates (S,G) state for every source. Bidir PIM uses **only the shared tree**, in both directions:

- Traffic from sources flows **up** the shared tree toward the RP and **down** to receivers, with no registering and **no (S,G) state**, only (\*,G).
- On every link, a **designated forwarder (DF)** is elected per RP: the router with the best route to the RP. Only the DF forwards traffic toward the RP from that link and down onto it, which replaces the RPF check for loop prevention.
- The RP need not even be a real router address: it is just the root point of the tree.
- On IOS XE: `ip pim bidir-enable` and `ip pim rp-address 10.255.0.9 bidir`. Bidir groups show the `B` flag in `show ip mroute`.

## MSDP and Anycast RP

**MSDP** (RFC 3618) connects separate PIM-SM domains, each with its own RP. When an RP learns of a new source through a Register, it sends a **Source-Active (SA)** message with the (S,G) and its RP address to its MSDP peers. MSDP peers are RPs connected over **TCP port 639**; SA messages are flooded peer to peer with a peer-RPF check. An RP in another domain that has (\*,G) receivers joins the source directly with an (S,G) Join. The receiving domains never need to know each other's RPs.

**Anycast RP** (RFC 3446) uses MSDP inside one domain for RP redundancy and load sharing: two or more RPs share the **same address** (a /32 loopback advertised by each), so each router uses the nearest one, and the RPs peer with each other over MSDP (using their unique addresses) so each learns the sources registered at the others. If one RP fails, unicast routing simply moves everyone to the next. RFC 4610 does the same with PIM Register messages instead of MSDP.

```text
    Vlan30, Forward/Sparse, 01:12:40/00:02:51

    Vlan30, Forward/Sparse, 00:20:18/00:02:51
```

| Field | Meaning |
|---|---|
| `(*, 239.1.1.1) ... RP 10.255.0.1` | Shared-tree entry; the RP for the group |
| Flags `S` / `C` / `J` | Sparse mode; a directly **connected** receiver (IGMP); this entry is joining the SPT |
| Flags `T` on (S,G) | Traffic is arriving on the **shortest-path tree** |
| `P` | Pruned: no outgoing interfaces |
| `F` and `Registering` | First-hop router registering a source |
| `s` | SSM group; `B` bidir group; `L` the router itself joined the group |
| Incoming interface / RPF nbr | The RPF interface and the upstream PIM neighbor: toward the RP for (\*,G), toward the source for (S,G) |
| Outgoing interface list | Where packets are replicated; `Null` = nowhere |

Here R3 has a receiver on Vlan30, joined the shared tree through Gi0/0/1 toward the RP, and has switched to the SPT for source 10.50.1.10, whose unicast route goes through Gi0/0/2. The (\*,G) expiry shows `stopped` because a connected receiver keeps it alive.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML). Build four Catalyst 8000v or IOSv routers in a square R1–R2–R3–R4 with OSPF, a source host (or router) 10.50.1.10 behind R1 and a receiver behind R3; R4 is the RP on Loopback0.

1. `ip multicast-routing` (or `... distributed`), `ip pim sparse-mode` on every link and LAN, `ip pim rp-address <R4 loopback>` everywhere. Check `show ip pim neighbor`.
2. Join 239.1.1.1 on the receiver (`ip igmp join-group`), ping 239.1.1.1 from the source, and read `show ip mroute` on R1 (F flag, Registering), R4 and R3 (SJC and T flags).
3. Set `ip pim spt-threshold infinity` on R3 and see the (S,G) entry disappear from R3's path.
4. Replace the static RP with BSR (`ip pim bsr-candidate`, `ip pim rp-candidate`) and read `show ip pim rp mapping`.
5. Enable `ip pim ssm default`, IGMPv3 on R3's LAN, join (10.50.1.10, 232.1.1.1) and confirm the entry has the `s` flag and no RP.

## Key takeaways

- PIM: IP protocol 103, hellos to 224.0.0.13 every 30 s; DR = highest priority (default 1), then highest IP; RPF uses the unicast table.
- PIM-SM: receivers join (\*,G) toward the RP; the source's DR Registers to the RP; the RP joins (S,G) and sends Register-Stop; last-hop routers switch to the SPT after the first packet by default.
- RP discovery: static, Auto-RP (224.0.1.39 announce, 224.0.1.40 discovery, mapping agent), BSR (standard, bootstrap messages, candidate RPs).
- SSM: 232/8, IGMPv3, (S,G) only, no RP. Bidir: shared tree only, DF per link, no (S,G) state.
- MSDP: RPs exchange Source-Active messages over TCP 639 to connect PIM-SM domains; Anycast RP shares one RP address across several RPs with MSDP between them.
- `show ip mroute`: (\*,G) and (S,G), flags (S, C, J, T, F, P, s, B), incoming interface and RPF neighbor, outgoing interface list.
