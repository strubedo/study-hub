## Two ways to build a routing table

ENCOR asks you to compare EIGRP and OSPF, not to configure EIGRP in depth: what each router knows, and how it reacts when a path fails.

| | EIGRP | OSPF |
|---|---|---|
| Algorithm class | Advanced distance vector (Cisco once called it "hybrid") | Link state |
| What a router knows | Each neighbor's metric to each prefix (its reported distance) | The full topology of its area (the link-state database, LSDB) |
| Best path computed by | DUAL (Diffusing Update Algorithm) | SPF (Dijkstra) over the LSDB |
| Standard | Cisco, published as informational RFC 7868 | IETF: OSPFv2 RFC 2328, OSPFv3 RFC 5340 |
| IP protocol number | **88** | **89** |
| Multicast | **224.0.0.10** (IPv6 FF02::A) | **224.0.0.5** all OSPF routers, **224.0.0.6** DR/BDR (IPv6 FF02::5, FF02::6) |
| Default hello / hold or dead | **5 / 15 s** on LAN and high-speed links; 60 / 180 s on slow multipoint WAN interfaces | **10 / 40 s** broadcast and point-to-point; 30 / 120 s NBMA and point-to-multipoint |
| Metric | Composite: minimum bandwidth and cumulative delay by default | Cost: sum of outgoing interface costs |
| Hierarchy | Flat; summarize at any interface | Areas, with area 0 as the backbone |
| Updates | Partial and bounded, only on change; no periodic refresh | LSAs flooded on change and refreshed every 30 minutes |
| Load balancing | Equal cost, and **unequal cost** with `variance` | Equal cost only |
| Administrative distance | Internal **90**, external **170**, summary **5** | **110** for every OSPF route type |

## EIGRP and DUAL

An EIGRP router adds the cost of the link to each neighbor's advertised metric. The vocabulary is examined exactly:

- **Reported distance (RD)**, also called advertised distance (AD in older material): the neighbor's own metric to the prefix, as it advertised it.
- **Feasible distance (FD)**: the best total metric this router has had to the prefix since the route last went passive. Normally it equals the current best metric.
- **Successor**: the neighbor with the lowest total metric that also meets the feasibility condition. It is installed in the routing table.
- **Feasibility condition**: a neighbor qualifies if its **RD is strictly less than the FD**. A neighbor that is closer to the destination than this router has ever been cannot be routing back through this router, so its path is guaranteed loop free.
- **Feasible successor (FS)**: a neighbor that meets the feasibility condition but is not the best path. It is the precomputed backup.

```text
R1# show ip eigrp topology all-links
EIGRP-IPv4 Topology Table for AS(100)/ID(10.255.0.1)
Codes: P - Passive, A - Active, U - Update, Q - Query, R - Reply,
       r - reply Status, s - sia Status

P 10.50.0.0/24, 1 successors, FD is 28672, serno 112
        via 10.0.12.2 (28672/28416), GigabitEthernet0/0/1
        via 10.0.13.3 (54016/28160), GigabitEthernet0/0/2
        via 10.0.14.4 (28928/28672), GigabitEthernet0/0/3
```

Each `via` line reads (total metric / reported distance). 10.0.12.2 is the successor. 10.0.13.3 reports 28160, less than the FD of 28672, so it is a **feasible successor** despite its high total. 10.0.14.4 reports 28672, **not less than** the FD, so it fails the condition although its total (28928) is second best. Plain `show ip eigrp topology` lists only successors and feasible successors; `all-links` also shows paths that fail the condition.

**Route states.** A route is **passive** when it is stable. When the successor is lost:

1. If a feasible successor exists, the router switches to it immediately and locally, with no messages to other routers. This is EIGRP's fast convergence.
2. If not, the route goes **active**: the router sends a **query** to every neighbor and waits for a **reply** from each before it chooses a new successor. Neighbors with no alternative query their own neighbors, so a query can spread across the network.
3. A query that is not answered in time leaves the route **stuck in active** (SIA). Cisco's active timer is 3 minutes; SIA-query and SIA-reply messages let routers confirm a slow neighbor is still working before the adjacency is reset.

Summarization and **EIGRP stub** routers (which neighbors do not query) bound query scope, EIGRP's main scaling problem. Packets are Hello, Update, Query, Reply and Acknowledgement; updates, queries and replies use the Reliable Transport Protocol (RTP).

## The EIGRP metric

The classic composite metric uses five K values. Defaults are **K1 = 1, K2 = 0, K3 = 1, K4 = 0, K5 = 0**, and neighbors must have the same K values or they will not form an adjacency. With those defaults the formula reduces to:

```text
metric = 256 x ( 10^7 / minimum bandwidth in kbps  +  sum of delays in tens of microseconds )
```

- **Bandwidth**: the slowest link on the path, in kbps, from each outgoing interface's `bandwidth` value (`BW` in `show interfaces`). The division is truncated to an integer.
- **Delay**: the sum of the outgoing interface delays along the path, in tens of microseconds (`DLY` in `show interfaces` is in microseconds, so divide by 10). Gigabit Ethernet defaults to 10 µs, Fast Ethernet to 100 µs.
- Load and reliability (K2, K4, K5) are off by default and best left off.

Worked example, R1 to a LAN behind R5: R1's 1 Gbps link to R2 (DLY 10 µs), R2's 100 Mbps link to R5 (DLY 100 µs), R5's 1 Gbps LAN interface (DLY 10 µs):

```text
bandwidth term = 10^7 / 100000 = 100
delay term     = 1 + 10 + 1     = 12
metric         = 256 x (100 + 12) = 28672
```

R2 reports 256 x (100 + 10 + 1) = 28416, the RD in the topology above.

> **Exam tip:** Steer EIGRP with `delay`, not `bandwidth`: bandwidth also feeds QoS and OSPF cost, and only the path minimum counts.

**Wide metrics.** The classic formula cannot tell links faster than 1 Gbps apart well: 10^7 / 10,000,000 kbps is 1, and the delay table in RFC 7868 keeps classic delay at 10 µs for every speed from 1 Gbps up. **Named mode** (`router eigrp NAME`, then `address-family ipv4 unicast autonomous-system 100`) uses 64-bit **wide metrics**: throughput and latency are scaled by 65,536 and delay is kept in picoseconds, so 10, 40 and 100 Gbps links get different values. The 32-bit routing table gets the wide metric divided by `metric rib-scale` (default **128**), so named-mode metrics differ between `show ip route` and `show eigrp address-family ipv4 topology`. Interface settings go under `af-interface`, topology settings under `topology base`.

## The OSPF metric

OSPF cost is per outgoing interface, and a route's metric is the sum of the costs of the outgoing interfaces from this router to the destination, including the destination network's own interface on the far router.

```text
cost = reference bandwidth / interface bandwidth     (integer, minimum 1)
```

The default reference is **100 Mbps**, so 100 Mbps, 1 Gbps and 10 Gbps all cost **1**, and OSPF cannot prefer the faster link. Fix it on **every** router in the domain with `auto-cost reference-bandwidth` (in Mbps; IOS warns you to make it consistent):

```text
R1(config)# router ospf 1
R1(config-router)# auto-cost reference-bandwidth 100000
% OSPF: Reference bandwidth is changed.
        Please ensure reference bandwidth is consistent across all routers.
```

With 100,000 (100 Gbps), 100 Gbps costs 1, 10 Gbps 10, 1 Gbps 100, 100 Mbps 1000. `ip ospf cost N` on an interface overrides the calculation for that interface only.

> **Watch out:** Mixed reference bandwidths do not break adjacencies; they silently produce odd, asymmetric paths.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host, with four IOSv or Catalyst 8000v routers. These tools run Cisco's x86 images, so on an Apple silicon Mac use a remote x86 server or a Cisco DevNet sandbox with CML.

1. Build R1 with links to R2, R3 and R4, and give R2, R3 and R4 a link to R5, which has a loopback 10.50.0.1/24. Run `router eigrp 100` with `network 10.0.0.0` everywhere.
2. On R1, read `show ip eigrp topology` and `show ip eigrp topology all-links`. Set `delay` and `bandwidth` on the R1 and R2 links until you reproduce one successor, one feasible successor and one path that fails the feasibility condition.
3. Compute the metric from `show interfaces | include BW` and compare it with the FD.
4. Shut the successor's link with `debug eigrp fsm` running, with and without a feasible successor.
5. Replace EIGRP with OSPF (`router ospf 1`, `network 10.0.0.0 0.255.255.255 area 0`). Compare `show ip ospf interface brief` costs before and after `auto-cost reference-bandwidth 10000`.

## Key takeaways

- EIGRP is an advanced distance vector protocol using DUAL; OSPF is link state using SPF over a per-area LSDB.
- EIGRP: IP protocol 88, 224.0.0.10, hello 5 s / hold 15 s on fast links; OSPF: protocol 89, 224.0.0.5 and 224.0.0.6, hello 10 s / dead 40 s on broadcast and point-to-point.
- Feasibility condition: RD strictly less than FD. A feasible successor gives instant local failover; without one the route goes active and queries.
- Classic EIGRP metric with default K values: 256 x (10^7 / min BW kbps + sum of delays / 10 µs). Named mode uses 64-bit wide metrics, scaled into the RIB by `metric rib-scale` (default 128).
- OSPF cost = reference bandwidth (default 100 Mbps) / interface bandwidth, minimum 1; set `auto-cost reference-bandwidth` on every router.
- EIGRP packets: Hello, Update, Query, Reply, Acknowledgement; SIA after Cisco's 3-minute active timer.
