## Enabling OSPF on an interface

OSPFv2 runs as a process, `router ospf PROCESS-ID`. The process ID (1 to 65535) is local to the router: neighbors do not need to use the same number. There are two ways to put an interface in the process, and they can be mixed:

```text
R1(config)# router ospf 1
R1(config-router)# router-id 10.255.0.1
R1(config-router)# network 10.0.12.0 0.0.0.3 area 0
R1(config-router)# network 10.255.0.1 0.0.0.0 area 0
```

```text
R1(config)# interface GigabitEthernet0/0/2
R1(config-if)# ip ospf 1 area 0
```

- `network ADDRESS WILDCARD area AREA` enables OSPF on every interface whose **primary IP address** falls inside the address and wildcard, and advertises that interface's subnet. The statement matches interface addresses, not subnets: `network 10.0.12.0 0.0.0.3 area 0` matches only interfaces addressed 10.0.12.0 to 10.0.12.3. A `0.0.0.0` wildcard matches exactly one interface address; avoid overlapping statements that would match one interface into different areas.
- `ip ospf PROCESS-ID area AREA` on the interface does the same thing explicitly, and it takes precedence over a `network` statement that matches the same interface. `show ip ospf interface` says "Attached via Network Statement" or "Attached via Interface Enable", and `show ip protocols` lists the second kind under "Routing on Interfaces Configured Explicitly".

The area can be written as a number (`area 0`) or in dotted form (`area 0.0.0.0`); both mean the same 32-bit area ID.

## Router ID

Every OSPF router needs a unique 32-bit router ID (RID), written like an IPv4 address, picked when the process starts:

1. The `router-id` command under the process.
2. Otherwise, the highest IPv4 address on a loopback interface that is up.
3. Otherwise, the highest IPv4 address on any other up interface.

The interface does not have to run OSPF. The RID does not follow later interface changes. Changing `router-id` on a running process resets every adjacency: classic IOS prints a message asking you to reload or run `clear ip ospf process` before the new RID is used, while the IOS XE 17.x YANG model describes the new RID as taking effect immediately with peers reset. Check which your release does, and plan the change for a maintenance window either way. Always set `router-id` explicitly.

> **Watch out:** Two routers with the same RID in one area cannot both be represented in the LSDB. IOS logs a duplicate router ID message and the adjacency or routing fails. Cloned lab configurations are the usual cause.

## What must match for an adjacency

OSPF checks these when it receives a hello or a database description (DBD) packet. A mismatch stops the adjacency at a predictable point:

| Parameter | Where it is checked | Symptom of a mismatch |
|---|---|---|
| Area ID | Hello header | No neighbor; IOS logs a "mismatched area ID" message |
| Subnet and mask | Hello (ignored on point-to-point links) | No neighbor |
| Hello and dead intervals | Hello | No neighbor (`show ip ospf neighbor` empty on both sides) |
| Authentication type and key | Every packet | No neighbor |
| Stub area flag (E-bit), NSSA flag | Hello options | No neighbor |
| Unique router ID | Hello | Duplicate router ID message, unstable or missing routes |
| IP MTU | DBD packet | Stuck in **EXSTART** or **EXCHANGE** |
| Network type | Not checked directly | Broadcast versus point-to-point can reach FULL, but routes are missing |
| Not passive | Interface | No hellos sent, no neighbor |

The process ID, the reference bandwidth and the interface cost do **not** need to match.

> **Exam tip:** `ip ospf mtu-ignore` lets an adjacency form despite an MTU mismatch. The real fix is to make `ip mtu` match on both ends, because a large LSA update could still be dropped.

## The neighbor state machine

RFC 2328 defines the states a neighbor passes through:

| State | What has happened |
|---|---|
| **Down** | No hello received from the neighbor within the dead interval |
| Attempt | NBMA networks only: hellos are being sent to a manually configured neighbor |
| **Init** | A hello was received, but it does not list this router's RID: communication is one-way so far |
| **2-Way** | This router's RID appears in the neighbor's hello: two-way communication. DR and BDR election happens here |
| **ExStart** | The two routers choose master and slave (higher RID is master) and the starting DBD sequence number |
| **Exchange** | They exchange DBD packets describing the LSAs each has |
| **Loading** | Each sends link-state requests for LSAs it is missing or has older copies of, and receives link-state updates |
| **Full** | Databases are synchronized; the routers are adjacent |

A neighbor **stuck in Init** points at one-way communication: this router hears the neighbor, but the neighbor does not hear this router (an ACL dropping OSPF inbound on the far side, or a filtered or unidirectional link). **Stuck in ExStart or Exchange** almost always means an MTU mismatch. **2-Way** that never reaches Full is normal between two DROTHERs.

## DR and BDR on multiaccess networks

On a broadcast network (Ethernet), full adjacencies between every pair of routers would mean n(n-1)/2 adjacencies. OSPF elects a **designated router (DR)** and a **backup designated router (BDR)**:

- Every router forms a **full** adjacency with the DR and the BDR only. Routers that are neither (**DROTHERs**) stay in **2-Way** with each other.
- DROTHERs send LSAs to **224.0.0.6** (AllDRouters); the DR floods them back to everyone on **224.0.0.5** (AllSPFRouters).
- The DR originates the type 2 (network) LSA for the segment.

**Election**: the highest interface **priority** wins (`ip ospf priority`, 0 to 255, default **1**); a tie goes to the highest **router ID**, compared as a 32-bit number. Priority **0** means the router never becomes DR or BDR. The BDR is elected first and then promoted if no DR exists.

The election is **not preemptive**. A router that joins later with a higher priority or RID does not take over; it becomes DR only if the DR and BDR fail (or the OSPF processes are cleared). When the DR fails, the BDR becomes DR and a new BDR is elected. To control the outcome, set priorities and then clear the process or bring routers up in order.

```text
R2# show ip ospf neighbor

Neighbor ID     Pri   State           Dead Time   Address         Interface
10.255.0.1        1   FULL/DR         00:00:35    10.0.123.1      GigabitEthernet0/0/0
10.255.0.3        1   2WAY/DROTHER    00:00:33    10.0.123.3      GigabitEthernet0/0/0
10.255.0.4        1   FULL/BDR        00:00:38    10.0.123.4      GigabitEthernet0/0/0
```

All four routers have priority 1, yet the lowest RID is DR: R1 booted first and won an election with no competition, and non-preemption kept it there. Read the rest as: R2 is itself a DROTHER. It is Full with the DR (10.255.0.1) and BDR (10.255.0.4) and 2-Way with the other DROTHER, which is correct. The "Address" column is the neighbor's interface address; "Neighbor ID" is its RID.

## Network types

| Network type | Default on | DR/BDR | Hello / dead | Neighbor shows |
|---|---|---|---|---|
| Broadcast | Ethernet | Yes | 10 / 40 | `FULL/DR`, `FULL/BDR`, `2WAY/DROTHER` |
| Point-to-point | Serial (HDLC, PPP), GRE tunnels | No | 10 / 40 | `FULL/  -` |
| Non-broadcast (NBMA) | Frame Relay physical interfaces (legacy) | Yes, neighbors configured manually | 30 / 120 | |
| Point-to-multipoint | Configured only | No | 30 / 120 | |

Most Ethernet links between two routers are really point-to-point, but OSPF treats them as broadcast and elects a DR. Changing both ends to point-to-point removes the election and the 40-second wait timer, skips the type 2 LSA, and is the usual pairing with `/31` addressing:

```text
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ip ospf network point-to-point
```

Configure it on **both** ends. A broadcast interface facing a point-to-point interface has matching timers, so the neighbors can still reach FULL, but one describes the link as a transit network with a DR and the other as a point-to-point link; the SPF two-way check fails and routes across the link go missing. Point-to-point versus point-to-multipoint does not even form, because the hello and dead timers differ.

## Passive interfaces

A passive interface is still in OSPF and its subnet is still advertised, but the router sends no hellos and forms no adjacencies on it. Use it on user VLANs, loopbacks and host-facing ports, which also stops a rogue device from forming an adjacency.

```text
DSW1(config)# router ospf 1
DSW1(config-router)# passive-interface default
DSW1(config-router)# no passive-interface GigabitEthernet1/0/49
DSW1(config-router)# no passive-interface GigabitEthernet1/0/50
```

`passive-interface default` makes every interface passive, including ones added later, and `no passive-interface` opens the uplinks. That is the safer pattern on a distribution switch with dozens of SVIs. `show ip ospf interface` on a passive interface says "No Hellos (Passive interface)".

## Verification

```text
R1# show ip ospf interface brief
Interface    PID   Area            IP Address/Mask    Cost  State Nbrs F/C
Lo0          1     0               10.255.0.1/32      1     LOOP  0/0
Gi0/0/1      1     0               10.0.12.1/30       1     P2P   1/1
Gi0/0/0      1     0               10.0.123.1/24      1     DR    3/3
```

The State column shows the interface role (`DR`, `BDR`, `DROTH`, `P2P`, `LOOP`, `DOWN`, `WAIT`), and Nbrs F/C is full neighbors over total neighbors: `1/2` on a link means one neighbor is not Full.

`show ip ospf interface GigabitEthernet0/0/0` adds the details used in troubleshooting: "Network Type BROADCAST, Cost: 1", "State DR, Priority 1", the DR and BDR IDs and addresses, "Timer intervals configured, Hello 10, Dead 40, Wait 40, Retransmit 5", and "Neighbor Count is 3, Adjacent neighbor count is 3".

`show ip protocols` shows the process from the top: "Router ID 10.255.0.1", "Number of areas in this router is 1. 1 normal 0 stub 0 nssa", "Maximum path: 4", the `network` statements under "Routing for Networks", explicitly enabled interfaces, "Passive Interface(s)", the routers it has learned from under "Routing Information Sources", and "Distance: (default is 110)".

For adjacency problems use `debug ip ospf adj` (and `debug ip ospf hello` for timer, mask and area mismatches) briefly, and read the log.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML), with five IOSv or Catalyst 8000v routers: R1 to R4 on one unmanaged switch, plus a separate Ethernet link from R1 to R5.

1. Configure `router-id 10.255.0.N`, a Loopback0 of 10.255.0.N/32, and `ip ospf 1 area 0` on each router's LAN interface, its Loopback0 and both ends of the R1–R5 link. Check `show ip ospf neighbor` on a DROTHER: Full with DR and BDR, 2-Way with the other.
2. Set `ip ospf priority 100` on R3 and observe that nothing changes. Run `clear ip ospf process` on all four and watch R3 become DR.
3. Set priority 0 on R4, run `clear ip ospf process` on R4, and confirm it shows `DROTHER` everywhere.
4. Change the hello interval on one router (`ip ospf hello-interval 5`) and use `debug ip ospf hello` to see the mismatch; restore it.
5. Set `ip mtu 1400` on one end of the R1–R5 link and watch the neighbor stall in EXSTART/EXCHANGE; fix it.
6. Set `ip ospf network point-to-point` on both ends of R1–R5 and confirm `FULL/  -` and `P2P` in the interface brief.
7. Add `passive-interface default` with `no passive-interface` on the links and confirm the loopbacks are still in other routers' tables.

## Key takeaways

- Enable OSPF with `network ... area` (matches interface addresses by wildcard) or `ip ospf PID area N` on the interface (takes precedence).
- Router ID: `router-id`, else highest up loopback, else highest up interface; chosen at process start; must be unique.
- Adjacency needs matching area, subnet and mask, hello and dead timers, authentication and stub flags, plus unique RIDs; MTU mismatch stalls in ExStart/Exchange.
- States: Down, Init, 2-Way, ExStart, Exchange, Loading, Full. DROTHERs stay 2-Way with each other.
- DR election: highest priority (default 1, 0 = never), then highest RID; not preemptive.
- `ip ospf network point-to-point` on both ends removes the DR election on two-router Ethernet links; a broadcast/point-to-point mix loses routes.
- `passive-interface` stops hellos and adjacencies but still advertises the subnet; use `passive-interface default` on SVI-heavy switches.
- Verify with `show ip ospf neighbor`, `show ip ospf interface [brief]` and `show ip protocols`.
