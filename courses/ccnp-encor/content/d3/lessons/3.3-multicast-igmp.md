## The multicast model

Multicast sends one stream to a **group** address; the network replicates packets only where the tree branches, and only toward segments with interested receivers. Three protocols divide the work:

| Piece | Job |
|---|---|
| **IGMP** (IPv4) / MLD (IPv6) | Between hosts and their first router: which groups have receivers on this segment |
| **PIM** | Between routers: build distribution trees from sources to the segments with receivers (next lesson) |
| **IGMP snooping** | On switches: forward group traffic only to ports with receivers or routers |

Sources need no signalling: a source just sends to the group address. Receivers ask for traffic with IGMP. Topic 3.3.d is "describe", so the focus is how these pieces work and how to read their state.

## IPv4 multicast addresses

Multicast uses **224.0.0.0/4** (224.0.0.0 to 239.255.255.255, the old class D). RFC 5771 divides it:

| Range | Use |
|---|---|
| **224.0.0.0/24** | **Local Network Control Block**: link-local, sent with TTL 1 and never routed. 224.0.0.1 all systems, 224.0.0.2 all routers, 224.0.0.5/6 OSPF, 224.0.0.10 EIGRP, 224.0.0.13 all PIM routers, 224.0.0.18 VRRP, 224.0.0.22 IGMPv3, 224.0.0.102 HSRPv2 |
| 224.0.1.0/24 | Internetwork Control Block: routable control groups, such as 224.0.1.1 NTP, 224.0.1.39 and 224.0.1.40 (Cisco Auto-RP announce and discovery), 224.0.1.129 PTP |
| **232.0.0.0/8** | **Source-Specific Multicast** (RFC 4607) |
| **233.0.0.0/8** | **GLOP** (RFC 3180): 233.X.Y.0/24 where X.Y is a 16-bit AS number, so each AS owner has a /24 (233.252.0.0/14 is excluded and reused; 233.252.0.0/24 is reserved for documentation) |
| **239.0.0.0/8** | **Administratively scoped** (RFC 2365): private multicast, never forwarded beyond your organization; the multicast equivalent of RFC 1918 |
| Other ranges | AD-HOC blocks and reserved space |

IPv6 multicast uses FF00::/8 (FF02::1 all nodes, FF02::2 all routers, FF02::D all PIM routers, FF02::16 MLDv2 reports).

## Multicast IP to MAC mapping

RFC 1112 maps a group address to an Ethernet MAC by putting the **low-order 23 bits** of the IP address into the **low 23 bits** of `01-00-5E-00-00-00`.

The first 4 bits of every multicast address are `1110`, and the next 5 bits are dropped by the mapping, so **32 (2^5) IP groups share each MAC address**. Example for 239.130.5.10:

| Step | Value |
|---|---|
| Second octet 130 | 1000 0010; drop the top bit: 000 0010 = `02` |
| Third and fourth octets | 5 = `05`, 10 = `0A` |
| MAC | **`01-00-5E-02-05-0A`** (Cisco notation `0100.5e02.050a`) |

224.2.5.10, 225.2.5.10, 239.2.5.10 and 238.130.5.10 map to the same MAC. A host NIC filtering on that MAC also receives the others, and the IP stack discards what it did not join. Shortcut: take the second octet modulo 128, keep the last two octets.

## IGMPv2 (RFC 2236)

| Message | Sent by | To |
|---|---|---|
| **General membership query** | Querier | 224.0.0.1, periodically: "which groups have members here?" |
| **Group-specific query** | Querier | The group itself, after a Leave: "is anyone still in this group?" |
| **Membership report** (v2) | Host | The group address being joined; sent unsolicited when joining and in answer to queries |
| **Leave group** | Host | 224.0.0.2 (all routers) |

How it runs:

1. A host joining a group sends an unsolicited report at once.
2. The querier sends general queries every **query interval**. Each host waits a random time up to the **max response time** (10 s by default) before reporting; if it hears another host report the same group first, it suppresses its own (one report per group per segment is enough).
3. When a host leaves, it sends a Leave. The querier sends group-specific queries (last member query, by default 2 queries 1 s apart on IOS XE); if no report comes back, it stops forwarding the group on that interface.
4. Without a Leave (a host that just disappears), the group times out after the group membership interval (robustness x query interval + max response time).

**Querier election:** every router starts as querier; a router that hears a query from a **lower IP address** stops querying. The querier is therefore the **lowest IP address** on the segment. This is not the PIM designated router, which is the highest DR priority, then highest IP (next lesson), so the two roles are often on different routers.

**Query interval:** RFC 2236's default is 125 s, but IOS XE defaults to **60 s** (`ip igmp query-interval`), with a querier timeout of twice that, and a 10 s max response time (`ip igmp query-max-response-time`). IOS XE interfaces default to IGMPv2 (`ip igmp version 3` changes it).

## IGMPv3 (RFC 3376, now RFC 9776)

IGMPv3 adds **source filtering**: a host can say which sources it wants for a group.

| Mode | Meaning |
|---|---|
| **INCLUDE** (S1, S2) | Receive the group only from these sources |
| **EXCLUDE** (S3) | Receive the group from every source except these; EXCLUDE with an empty list = any source (the v2 behaviour) |

Other changes: all v3 reports go to **224.0.0.22** (not to the group address), there is no report suppression (the router learns every host's sources, which enables explicit tracking and fast leaves), a leave is a report changing to INCLUDE with no sources, and queries can be group-and-source-specific. IGMPv3 is what makes **SSM** possible: the host names the (S,G) channel it wants. IGMPv3 is backward compatible: a v3 router falls back to older behaviour for groups with v1 or v2 hosts. RFC 9776 (March 2025, Internet Standard) obsoletes RFC 3376 without changing the protocol's operation.

## IGMP snooping

A switch without snooping floods multicast to every port in the VLAN, like a broadcast. With **IGMP snooping** (enabled by default on Catalyst switches), the switch reads the IGMP messages passing through it, learns which ports have receivers for which group, and forwards group traffic only to those ports plus the **mrouter ports** (ports toward multicast routers, learned from queries and PIM hellos). Link-local groups (224.0.0.x) are still flooded.

Snooping depends on queries: if no router on the VLAN queries, hosts stop sending reports and the switch's entries age out. In a Layer 2-only VLAN, configure the **snooping querier** (`ip igmp snooping querier`) so the switch sends queries itself. Because of the 32:1 MAC overlap, avoid choosing groups that differ only in the bits the mapping drops.

## The RPF check

Unicast routing forwards on the destination. Multicast forwarding is the reverse: a router accepts a multicast packet only if it arrives on the interface the router would use to reach the **source** (or, on a shared tree, the RP). This is the **Reverse Path Forwarding (RPF) check**, and it is what stops multicast loops.

1. Look up the **source address** in the unicast routing table (or a multicast-specific table: static `ip mroute`, multicast BGP).
2. The outgoing interface of that route is the **RPF interface**; the next hop is the **RPF neighbor**.
3. Packets arriving on the RPF interface pass and are forwarded on the outgoing interface list. Packets arriving on any other interface **fail and are dropped**.

When several equal-cost paths exist, IOS picks the RPF neighbor with the **highest PIM neighbor IP address**. Common RPF failures come from asymmetric routing: a path where unicast routes toward the source go one way but multicast arrives another (for example, a tunnel carrying multicast while the unicast route to the source points to the physical link). Fixes are a static `ip mroute SOURCE MASK RPF-NEIGHBOR` or making the unicast routing match. `show ip rpf 10.50.1.10` shows the RPF interface and neighbor for a source, and `show ip mroute count` shows packets dropped for RPF failure.

## Reading `show ip igmp groups`

```text
R1# show ip igmp groups
IGMP Connected Group Membership
Group Address    Interface                Uptime    Expires   Last Reporter   Group Accounted
239.130.5.10     Vlan20                   00:42:17  00:02:41  10.1.20.37
239.1.1.1        Vlan20                   02:10:05  00:02:39  10.1.20.15
224.0.1.40       Loopback0                5d03h     00:02:11  10.255.0.1
```

Each line is a group with at least one receiver on that interface; Last Reporter is the host that answered last (not the only member), and Expires counts down until the group is removed if no report arrives. 224.0.1.40 on a loopback is the router itself listening for Auto-RP discovery. `show ip igmp interface Vlan20` shows the IGMP version, query interval, querier and PIM DR for the segment.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML). Use two routers R1 (10.1.20.2) and R2 (10.1.20.3) on one LAN segment with a third router acting as a host.

1. `ip multicast-routing` (on Catalyst 8000v: `ip multicast-routing distributed`) and `ip pim sparse-mode` on the LAN interfaces of R1 and R2. Check `show ip igmp interface` on both: R1 is the querier (lower IP).
2. Give R2 `ip pim dr-priority 200` and confirm R2 is the DR while R1 stays querier.
3. On the host router, `ip igmp join-group 239.130.5.10` on its LAN interface; read `show ip igmp groups` on R1. Remove it and watch the group-specific queries with `debug ip igmp`.
4. Set `ip igmp version 3` on R1 and the host and join an (S,G) with `ip igmp join-group 232.1.1.1 source 10.50.1.10`.
5. Calculate the MAC for each group you joined and compare with what a packet capture in your emulator shows.

## Key takeaways

- 224.0.0.0/4; 224.0.0.0/24 link-local (never routed); 232/8 SSM; 233/8 GLOP; 239/8 administratively scoped (private).
- MAC = 01-00-5E + low 23 bits of the group; 5 bits are lost, so 32 groups share each MAC.
- IGMPv2: general query to 224.0.0.1, group-specific query after a Leave, report to the group, Leave to 224.0.0.2; max response 10 s; querier = lowest IP.
- Query interval: 125 s in RFC 2236, 60 s by default on IOS XE.
- IGMPv3: INCLUDE/EXCLUDE source lists, reports to 224.0.0.22, no report suppression; required for SSM. RFC 9776 obsoletes RFC 3376.
- IGMP snooping limits flooding to receiver and mrouter ports; a VLAN without a router needs a snooping querier.
- RPF check: accept a packet only on the interface the router would use to reach its source; failures drop traffic and usually mean asymmetric routing.
