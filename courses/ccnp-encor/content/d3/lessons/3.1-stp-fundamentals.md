## Why spanning tree still matters

Redundant Layer 2 links create loops, and Ethernet frames have no TTL: a broadcast loops until the links saturate, MAC tables thrash and the CPU of every switch in the VLAN spikes. **Spanning Tree Protocol** builds a loop-free tree by blocking redundant ports and unblocks them when the active path fails. RSTP, MST and the protection features in the next three lessons all build on the election described here, so this lesson covers the shared mechanics.

## The bridge ID and the extended system ID

Every switch has a **bridge ID (BID)** of 8 bytes: a 2-byte priority field followed by a 6-byte MAC address. With per-VLAN spanning tree, one switch needs a different BID in every VLAN while keeping one base MAC, so IEEE 802.1t split the priority field:

| Bits | Field | Values |
|---|---|---|
| 4 | Bridge priority | 0–61440 in steps of **4096** (16 values); default **32768** |
| 12 | Extended system ID | The VLAN number (PVST+) or MST instance number |
| 48 | MAC address | The switch's base MAC |

Cisco switches enable the **extended system ID** permanently, which is why the priority you see is the configured priority **plus** the VLAN number:

```text
DSW1# show spanning-tree vlan 10

VLAN0010
  Spanning tree enabled protocol rstp
  Root ID    Priority    24586
             Address     aabb.cc00.0100
             This bridge is the root
             Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec

  Bridge ID  Priority    24586  (priority 24576 sys-id-ext 10)
             Address     aabb.cc00.0100
             Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec
             Aging Time  300 sec

Interface           Role Sts Cost      Prio.Nbr Type
------------------- ---- --- --------- -------- --------------------------------
Gi1/0/1             Desg FWD 4         128.1    P2p
Gi1/0/2             Desg FWD 4         128.2    P2p
Po1                 Desg FWD 3         128.2377 P2p
```

24586 = 24576 + 10. Because the priority must be a multiple of 4096, `spanning-tree vlan 10 priority 24000` is rejected.

## The election

STP compares **priority vectors** carried in BPDUs. Lower is always better. The process:

1. **Root bridge**: the switch with the lowest BID: lowest priority first, then lowest MAC. Every switch starts by claiming to be root and stops when it hears a better BID.
2. **Root port** on every non-root switch: the one port with the best path to the root. Tie-breakers in order:
   1. Lowest **root path cost** (the cost in the received BPDU plus the receiving port's own cost).
   2. Lowest **sender bridge ID**.
   3. Lowest **sender port priority**.
   4. Lowest **sender port number**.
3. **Designated port** on every segment: the port that advertises the best BPDU onto that link (lowest root path cost, then lowest BID, then lowest port ID). All ports of the root bridge are designated.
4. Every other port **blocks** (802.1D) or becomes **alternate** or **backup** (RSTP).

The **port ID** is the port priority (default **128**, 0–240 in steps of 16) followed by the port number, displayed as `128.1`. The sender's values break ties, not the receiver's: to influence which of two parallel links a downstream switch chooses as root port, change the port priority on the **upstream** switch.

Controlling the root:

```text
DSW1(config)# spanning-tree vlan 10,20 priority 24576
DSW2(config)# spanning-tree vlan 10,20 priority 28672
! or the macros:
DSW1(config)# spanning-tree vlan 10,20 root primary
DSW2(config)# spanning-tree vlan 10,20 root secondary
```

`root primary` is a one-time macro, not a stored setting: it writes a priority of 24576, or, if the current root already has a priority below 24576, a value 4096 below the current root's priority. `root secondary` writes 28672. The running configuration shows the resulting `priority` line. A later switch with a lower priority still takes over, so in production set explicit priorities on the distribution or core pair.

> **Exam tip:** Put the root where the traffic goes: on the distribution switch that is also the HSRP or VRRP active gateway for that VLAN. A root bridge on an access switch forces traffic across sub-optimal links.

## Path cost: short and long

Each port has a cost based on its speed. Two methods exist:

| Speed | Short (802.1D-1998, 16-bit) | Long (802.1D-2004 / 802.1t, 32-bit) |
|---|---|---|
| 10 Mb/s | 100 | 2,000,000 |
| 100 Mb/s | 19 | 200,000 |
| 1 Gb/s | 4 | 20,000 |
| 10 Gb/s | 2 | 2,000 |
| 100 Gb/s | (no distinct value) | 200 |
| 1 Tb/s | (no distinct value) | 20 |

PVST+ and Rapid PVST+ have traditionally used the **short** method by default on Catalyst switches, but do not assume it: real IOS XE captures from Catalyst 9000 switches in Rapid PVST+ mode show both "short" and "long", and the default has differed between releases and platforms. `show spanning-tree summary` prints the method in use ("Pathcost method used is short" or "long"). MST always uses long costs. Set `spanning-tree pathcost method long` (or `short`) explicitly on every switch in the domain, because a mix of methods makes cost comparisons meaningless. A port channel gets a lower cost than one member (for example 3 for two 1 Gb/s links with the short method). Override per port or per VLAN with `spanning-tree [vlan N] cost N`.

## Port states and timers in 802.1D

| State | Learns MACs | Forwards frames | Typical duration |
|---|---|---|---|
| Blocking | No | No | Up to max age (20 s) when a better path is lost |
| Listening | No | No | Forward delay (15 s) |
| Learning | Yes | No | Forward delay (15 s) |
| Forwarding | Yes | Yes | Stable |
| Disabled | No | No | Administratively down |

The root sends a configuration BPDU every **hello time (2 s)**; other switches relay it. **Max age (20 s)** is how long a switch keeps BPDU information without a refresh. **Forward delay (15 s)** is the time spent in each of listening and learning. A port therefore takes 30 s to forward after link-up, and an indirect failure takes up to 50 s (20 + 15 + 15). Change timers only on the root (it advertises them): `spanning-tree vlan 10 hello-time 2`, `forward-time 15`, `max-age 20`.

**Topology changes in 802.1D**: a switch whose port moves to forwarding or goes down sends a **TCN BPDU** toward the root; the root then sets the TC flag in its BPDUs for max age plus forward delay (35 s), and every switch ages its MAC table with the forward delay (15 s) instead of the normal 300 s.

## PVST+, Rapid PVST+ and MST

| Mode | Command | Standard behind it | Instances | Convergence |
|---|---|---|---|---|
| PVST+ | `spanning-tree mode pvst` | 802.1D per VLAN | One per VLAN | 30–50 s |
| Rapid PVST+ | `spanning-tree mode rapid-pvst` | 802.1w per VLAN | One per VLAN | Sub-second to a few seconds |
| MST | `spanning-tree mode mst` | 802.1s (now in 802.1Q) | One per group of VLANs | As RSTP |

Current Catalyst 9000 IOS XE releases default to **Rapid PVST+**; older Catalyst platforms defaulted to PVST+. `show spanning-tree summary` shows the mode on the first line. Per-VLAN modes let each VLAN have its own root, so you can forward VLAN 10 on one uplink and VLAN 20 on the other. The cost is one STP instance, and one set of BPDUs, per VLAN; MST fixes that by mapping many VLANs to a few instances.

Cisco PVST+ interoperates with standard 802.1D/802.1w switches through VLAN 1, which it also sends as untagged IEEE BPDUs to `0180.c200.0000`; per-VLAN BPDUs go to the Cisco address `0100.0ccc.cccd`.

## Reading `show spanning-tree`

The interface table abbreviates the role and the state:

| Role | Meaning | Sts | Meaning |
|---|---|---|---|
| `Root` | Root port | `FWD` | Forwarding |
| `Desg` | Designated port | `BLK` | Blocking (802.1D) or discarding (RSTP) |
| `Altn` | Alternate (RSTP: backup path to the root) | `LRN` / `LIS` | Learning / listening |
| `Back` | Backup (RSTP: second port on a shared segment) | `BKN*` | Broken: blocked by an inconsistency, reason in Type |
| `Mstr` | Master (MST boundary port toward the CIST root) | | |

The Type column shows the link type (`P2p`, `Shr`), `Edge` for PortFast ports, and notes such as `Peer(STP)` (the neighbour runs 802.1D), `Bound(PVST)` (MST boundary) or an inconsistency such as `*ROOT_Inc`.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (they run Cisco's x86 images; on an Apple silicon Mac use a remote x86 server or a CML instance in a DevNet Sandbox), with three IOSvL2 or Catalyst 9000v switches in a triangle: DSW1, DSW2 and ASW1, plus a fourth link between DSW1 and DSW2.

1. Create VLANs 10 and 20 on all three and trunk every link. Before configuring priorities, run `show spanning-tree vlan 10` on each switch and predict the root from the MAC addresses.
2. Set `spanning-tree vlan 10 priority 24576` on DSW1 and `spanning-tree vlan 20 priority 24576` on DSW2. Confirm that ASW1 uses different uplinks per VLAN.
3. Between DSW1 and DSW2 with two parallel links, find the blocked port on DSW2 and move it by changing `spanning-tree vlan 10 port-priority 64` on the matching DSW1 port.
4. Change `spanning-tree pathcost method long` on one switch only and observe the costs; then set it on all three.
5. Switch to `spanning-tree mode pvst` on all three, shut ASW1's root port and time the convergence; repeat with `rapid-pvst`.

## Key takeaways

- BID = 4-bit priority (0–61440 in steps of 4096, default 32768) + 12-bit extended system ID (VLAN) + MAC. Displayed priority = priority + VLAN.
- Root = lowest BID. Root port tie-breakers: root path cost, sender BID, sender port priority, sender port number. One designated port per segment; the rest block.
- `root primary` writes 24576, or 4096 below a current root that is already below 24576; `root secondary` writes 28672.
- Short costs: 10 Mb 100, 100 Mb 19, 1 Gb 4, 10 Gb 2. Long costs: 2,000,000 / 200,000 / 20,000 / 2,000, 200 for 100 Gb. MST always uses long; for PVST+ and Rapid PVST+ read the method from `show spanning-tree summary` and set it explicitly.
- 802.1D timers: hello 2 s, max age 20 s, forward delay 15 s: 30 s to forward, up to 50 s to reconverge.
- Modes: `pvst`, `rapid-pvst` (Catalyst 9000 default), `mst`. Check with `show spanning-tree summary`.
