## VRRP in one table

The Virtual Router Redundancy Protocol is the IETF standard FHRP. VRRPv2 (RFC 3768) is IPv4 only; **VRRPv3** (RFC 5798, now **RFC 9568**, which obsoletes 5798) covers IPv4 and IPv6. RFC 9568 renames the Master router to **Active Router** (and Master_Down_Interval to Active_Down_Interval); IOS XE output still says MASTER, so both words appear in this lesson.

| Item | VRRP |
|---|---|
| Transport | **IP protocol 112** (not UDP), TTL/hop limit 255 |
| Multicast | **224.0.0.18** (IPv4), **FF02::12** (IPv6) |
| Virtual router ID (VRID, the group) | 1–255 |
| Virtual MAC | **`0000.5e00.01XX`** for IPv4, **`0000.5e00.02XX`** for IPv6, XX = VRID in hex |
| Roles | One master (active router) forwards; all others are backups |
| Priority | **1–254** for backups, default **100**; **255** = the address owner; 0 = the master is leaving |
| Preemption | **On by default** |
| Advertisement interval | **1 second** (VRRPv3 counts in centiseconds: default 100; IOS XE configures it in milliseconds) |
| Authentication | VRRPv2 had simple text authentication (removed from the standard later); **VRRPv3 has none** |

Only the master sends advertisements. Backups listen and do not advertise.

## The address owner

If the virtual IP address **is** a router's own interface address, that router is the **IP address owner**: its priority is automatically 255, it always becomes master when it is up, and it preempts regardless of the preempt setting. Using a separate virtual address (the usual design) avoids this and lets you control the roles with priority.

## Timers and the master-down interval

A backup declares the master down after the **master-down interval** without an advertisement:

```text
Skew_Time            = ((256 - Priority) x Master_Adver_Interval) / 256
Master_Down_Interval = (3 x Master_Adver_Interval) + Skew_Time
```

With the default 1-second interval, a backup with priority 100 waits 3 + 156/256 = 3.609 s; one with priority 200 waits 3 + 56/256 = 3.219 s. The **skew** makes the highest-priority backup time out first, so it takes over before the others and they see its advertisements instead of all claiming the role at once. IOS XE shows the value in the `show vrrp` line "Master Down interval is 3609 msec". In VRRPv3 the backup uses the interval learned from the master's advertisements.

When a master shuts down cleanly it sends an advertisement with priority 0, and backups take over after only the skew time instead of the full interval.

## Election

The router with the highest priority becomes master; on equal priority, the **highest primary IP address** wins. Because preemption is on by default, a higher-priority backup that comes up later takes over immediately unless you configure `no preempt` or a preempt delay.

## IOS XE configuration: VRRPv3 form

VRRPv3 is enabled globally, after which groups are configured per address family:

```text
DSW1(config)# fhrp version vrrp v3
DSW1(config)# track 1 interface GigabitEthernet1/0/48 line-protocol
DSW1(config)# interface Vlan10
DSW1(config-if)# ip address 10.1.10.2 255.255.255.0
DSW1(config-if)# vrrp 10 address-family ipv4
DSW1(config-if-vrrp)# address 10.1.10.1 primary
DSW1(config-if-vrrp)# priority 120
DSW1(config-if-vrrp)# preempt delay minimum 30
DSW1(config-if-vrrp)# track 1 decrement 30
DSW1(config-if-vrrp)# timers advertise 1000
DSW1(config-if-vrrp)# exit-vrrp
```

| Sub-command | Meaning |
|---|---|
| `address A.B.C.D primary` | The virtual IP; `address ... secondary` adds more |
| `priority 1–254` | Default 100 |
| `preempt [delay minimum S]` | On by default; `no preempt` disables it |
| `track OBJECT decrement N` | Lowers the priority by N while the object is down (`track OBJECT shutdown` disables the group instead) |
| `timers advertise MSEC` | 100–40950 ms, default 1000 |
| `vrrpv2` | VRRPv2 compatibility mode, to interoperate with VRRPv2-only routers (IPv4 only) |
| `description`, `shutdown` | As usual |

For IPv6, `vrrp 10 address-family ipv6` with `address FE80::1 primary` (the first IPv6 virtual address must be link-local) and global addresses with `address 2001:DB8:10::1/64`.

> **Watch out:** after `fhrp version vrrp v3`, the old interface-level `vrrp N ip` commands are no longer used; the two forms do not mix on one router.

## IOS XE configuration: legacy VRRPv2 form

Without `fhrp version vrrp v3`, IOS XE uses the classic VRRPv2 interface commands:

```text
DSW1(config)# interface Vlan10
DSW1(config-if)# vrrp 10 ip 10.1.10.1
DSW1(config-if)# vrrp 10 priority 120
DSW1(config-if)# vrrp 10 preempt delay minimum 30
DSW1(config-if)# vrrp 10 track 1 decrement 30
DSW1(config-if)# vrrp 10 timers advertise 1
DSW1(config-if)# vrrp 10 authentication text <SECRET>
```

Here `vrrp 10 timers advertise` is in seconds (with a `msec` option), and the authentication command exists only in this form.

## Object tracking

Tracking works as in HSRP: the decrement is subtracted from the configured priority while the object is down. Because preemption is on by default, the backup with the higher priority takes over as soon as the master's priority drops below it, and the original master takes the role back when the object recovers. The address owner (255) cannot be tracked down this way, another reason to use a separate virtual address.

```text
DSW2# show vrrp brief

  Vl10                10 IPv4 100     0  N   Y  BACKUP  10.1.10.2 10.1.10.1

DSW2# show vrrp
Vlan10 - Group 10 - Address-Family IPv4
  State is BACKUP
  State duration 1 hours 12 mins 4 secs
  Virtual IP address is 10.1.10.1
  Virtual MAC address is 0000.5E00.010A
  Advertisement interval is 1000 msec
  Preemption enabled
  Priority is 100
  Master Router is 10.1.10.2, priority is 120
  Master Advertisement interval is 1000 msec (learned)
  Master Down interval is 3609 msec (expires in 3287 msec)

```

Read it in this order: the state, the virtual IP and MAC (VRID 10 = `0A`), **Priority is N (Configured M)** when tracking has lowered it, the tracked objects and their state, the master's address and priority, and the master-down interval. `show vrrp brief` gives one line per group: the `Own` column shows an address owner and `Pre` the preemption setting.

## HSRP, VRRP and GLBP compared

| | HSRP | VRRPv3 | GLBP |
|---|---|---|---|
| Standard | Cisco (RFC 2281 informational) | IETF RFC 9568 | Cisco |
| Transport, multicast | UDP 1985; 224.0.0.2 (v1) or 224.0.0.102 (v2) | IP protocol 112; 224.0.0.18, FF02::12 | UDP 3222; 224.0.0.102 |
| Roles | Active, standby, listen | Master (active router), backup | One AVG, up to four AVFs |
| Virtual MAC | `0000.0c07.acXX` / `0000.0c9f.fXXX` | `0000.5e00.01XX` / `0000.5e00.02XX` | One per AVF, assigned by the AVG |
| Default priority | 100 | 100 (255 for the owner) | 100 |
| Preemption default | Off | On | AVG off, AVF on |
| Timers | Hello 3 s, hold 10 s | Advertisement 1 s, master down about 3.6 s | Hello 3 s, hold 10 s |
| Load sharing in one group | No | No | Yes |
| Virtual IP may equal an interface IP | No | Yes (address owner) | No |

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML), with two Catalyst 8000v or Catalyst 9000v devices as DSW1 and DSW2 on a shared VLAN or segment and a host behind them.

1. Configure `fhrp version vrrp v3` and group 10 on both, DSW1 priority 120, DSW2 default. Check `show vrrp brief` on both and the host's ARP entry (`0000.5e00.010a`).
2. On DSW2 read the master-down interval, change DSW2's priority to 110 (still below DSW1's 120, so DSW2 stays backup) and read it again; compare both with the formula (3609 ms, then 3570 ms). A master shows "Master Down interval is unknown", so read the value on a backup.
3. Track DSW1's uplink with `track 1 decrement 30`, shut the uplink and watch DSW2 take over at once (preemption on by default); bring it back.
4. Change the virtual address to DSW1's interface address and observe priority 255 and `Own Y`.
5. Remove `fhrp version vrrp v3` (after removing the groups) and rebuild the group with the legacy `vrrp 10 ip` commands.

## Key takeaways

- VRRP: IETF, IP protocol 112, 224.0.0.18 / FF02::12, VRID 1–255, MAC `0000.5e00.01XX` (IPv4) and `0000.5e00.02XX` (IPv6).
- Priority 1–254 (default 100), 255 = address owner, 0 = master resigning; highest priority then highest IP wins; preemption **on** by default.
- Advertisement 1 s; master down = 3 x interval + (256 − priority) / 256 x interval; only the master advertises.
- IOS XE VRRPv3: `fhrp version vrrp v3`, then `vrrp N address-family ipv4` with `address ... primary`, `priority`, `preempt`, `track`, `timers advertise` (ms). Legacy: `vrrp N ip`, `vrrp N priority`, and so on.
- VRRPv3 has no authentication; VRRPv2 had text authentication.
- RFC 9568 says Active Router where IOS XE output says MASTER.
