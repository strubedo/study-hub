## What a trunk is and what can go wrong

An **802.1Q trunk** carries frames for many VLANs over one link. Each frame (except the native VLAN's) gets a 4-byte tag inserted after the source MAC address: a 16-bit TPID of `0x8100`, then 3 bits of priority (PCP, the CoS value), 1 DEI bit and a **12-bit VLAN ID**. VLAN IDs 0 and 4095 are reserved, so 1–4094 are usable. The **native VLAN** (VLAN 1 by default) is sent **untagged**, and untagged frames received on a trunk are placed in the native VLAN.

Catalyst 9000 switches support only 802.1Q, so there is no encapsulation to choose. Older Catalyst models that also supported Cisco ISL needed `switchport trunk encapsulation dot1q` before `switchport mode trunk` would be accepted; you will still meet that line in older configurations and exam exhibits.

When a trunk "does not work", the cause is almost always one of five things, and the troubleshooting in this lesson checks them in this order:

1. The link never became a trunk (DTP mode combination, `nonegotiate`, VTP domain mismatch).
2. The native VLAN differs at the two ends.
3. The VLAN is not in the **allowed** list.
4. The VLAN does not **exist** (is not active) on one of the switches.
5. The VLAN is allowed and active but **blocked by STP or pruned by VTP**.

## Static and dynamic trunking: DTP

**Dynamic Trunking Protocol (DTP)** is Cisco proprietary. It runs on switchports and negotiates whether a link becomes a trunk. The interface commands:

| Command | Administrative mode | Sends DTP? | Becomes a trunk when the peer is |
|---|---|---|---|
| `switchport mode access` | static access | Negotiates non-trunk | Never |
| `switchport mode trunk` | trunk | Yes | Always trunks (unconditionally) |
| `switchport mode dynamic desirable` | dynamic desirable | Yes, actively asks | trunk, desirable or auto |
| `switchport mode dynamic auto` | dynamic auto | Yes, but only answers | trunk or desirable |
| `switchport mode trunk` + `switchport nonegotiate` | trunk | **No** | Always trunks; the peer gets no DTP |

The default on Catalyst 9000 access ports is **dynamic auto**, which is why two new switches cabled together do not form a trunk on their own: auto plus auto stays access.

The resulting operational mode for each combination:

| Local \ Peer | access | trunk | dynamic desirable | dynamic auto |
|---|---|---|---|---|
| **access** | access | mismatch | access | access |
| **trunk** | mismatch | trunk | trunk | trunk |
| **dynamic desirable** | access | trunk | trunk | trunk |
| **dynamic auto** | access | trunk | trunk | **access** |

"Mismatch" means one end tags frames and the other does not: only the native VLAN on the trunk side meets the access VLAN on the other side, and every other VLAN is lost. The same happens with `nonegotiate` facing a dynamic port: the trunk side never sends DTP, so the dynamic auto or desirable side stays access.

`switchport nonegotiate` is only accepted on a port that is already `switchport mode trunk` or `access`; on a dynamic port IOS rejects it, because a dynamic port that cannot negotiate makes no sense.

> **Exam tip:** Only three combinations fail to trunk with dynamic modes: auto + auto, any dynamic mode + access, and any dynamic mode facing `trunk nonegotiate`. Learn the matrix by those exceptions.

> **Real world:** Best practice is to hard-code: `switchport mode trunk` plus `switchport nonegotiate` on infrastructure links, and `switchport mode access` on user ports. Leaving user ports in dynamic auto or desirable lets an attacker who speaks DTP turn an access port into a trunk (switch spoofing) and reach every VLAN.

DTP frames carry the **VTP domain name**. If two switches have different, non-empty VTP domain names, dynamic negotiation fails even with a working mode combination, and IOS logs a DTP domain mismatch message. Static trunks (`mode trunk`) are not affected.

## Reading the trunk state

`show interfaces trunk` lists only interfaces that are **currently trunking**. A port that should be a trunk but is missing from this output did not become one. When it is present, read its four sections in order:

```text
SW1# show interfaces trunk

Port        Mode             Encapsulation  Status        Native vlan
Gi1/0/23    on               802.1q         trunking      99
Gi1/0/24    desirable        802.1q         trunking      99
Po12        on               802.1q         trunking      99

Port        Vlans allowed on trunk
Gi1/0/23    10,20,30,99
Gi1/0/24    10,20,30,99
Po12        10,20,30,40,99

Port        Vlans allowed and active in management domain
Gi1/0/23    10,20,30,99
Gi1/0/24    10,20,30,99
Po12        10,20,30,99

Port        Vlans in spanning tree forwarding state and not pruned
Gi1/0/23    10,20,30,99
Gi1/0/24    none
Po12        10,20,30,99
```

- **Mode**: `on` is `switchport mode trunk`; `desirable` and `auto` are the DTP modes that negotiated a trunk.
- **Allowed on trunk**: the configured `switchport trunk allowed vlan` list.
- **Allowed and active in management domain**: the allowed VLANs that also **exist and are active** on this switch. Po12 allows VLAN 40, but VLAN 40 is missing here, so VLAN 40 is not created on SW1 (check `show vlan brief`).
- **Forwarding and not pruned**: the VLANs that actually pass. Gi1/0/24 shows `none` because STP blocks it for all of them (it is a redundant link), which is normal. A single VLAN missing from this line on a link that should forward it points to STP blocking for that VLAN or VTP pruning.

`show interfaces <if> switchport` explains a port that is **not** trunking:

```text
SW1# show interfaces GigabitEthernet1/0/24 switchport
Name: Gi1/0/24
Switchport: Enabled
Administrative Mode: dynamic auto
Operational Mode: static access
Administrative Trunking Encapsulation: dot1q
Operational Trunking Encapsulation: native
Negotiation of Trunking: On
Access Mode VLAN: 1 (default)
Trunking Native Mode VLAN: 1 (default)
Administrative Native VLAN tagging: enabled
Voice VLAN: none
<output omitted>
Trunking VLANs Enabled: ALL
Pruning VLANs Enabled: 2-1001
```

Administrative mode is what you configured; operational mode is the result of negotiation. "dynamic auto / static access" with "Negotiation of Trunking: On" means DTP ran and the peer did not ask for a trunk: the peer is also auto, or is access. "Negotiation of Trunking: Off" means `nonegotiate` (or an access port).

`show dtp interface <if>` shows the DTP state machine for a port: the administrative and operational trunk status and type, the neighbour's address, and counters of DTP packets sent and received. If the received counter stays at zero, the peer is not sending DTP (it is access, `nonegotiate`, or not a Cisco switch).

`show vlan brief` lists the VLANs that exist and their access ports. Trunk ports do not appear in it: a port missing from `show vlan brief` is often simply a trunk.

## Native VLAN mismatch

If SW1 uses native VLAN 99 and SW2 uses native VLAN 1, untagged frames from SW1's VLAN 99 arrive in SW2's VLAN 1 and the reverse: the two VLANs merge across the link. Symptoms:

- CDP logs the mismatch on both switches, for example `%CDP-4-NATIVE_VLAN_MISMATCH: Native VLAN mismatch discovered on GigabitEthernet1/0/24 (99), with SW2 GigabitEthernet1/0/24 (1).`
- PVST+ and Rapid PVST+ BPDUs carry the sending port's VLAN, so STP detects the inconsistency and **blocks the port for both VLANs**, logging `%SPANTREE-2-RECV_PVID_ERR`, then `%SPANTREE-2-BLOCK_PVID_PEER` (for the peer's VLAN) and `%SPANTREE-2-BLOCK_PVID_LOCAL` (for the local native VLAN). In `show spanning-tree` the port appears as `BKN*` with `*PVID_Inc` in the Type column.
- Hosts in either VLAN may get addresses from the wrong DHCP scope if STP is not blocking.

Fix: set the same native VLAN on both ends (`switchport trunk native vlan 99`). To remove untagged traffic altogether, use an unused VLAN as native, do not allow it on the trunk, or tag the native VLAN globally with `vlan dot1q tag native`. This also defends against **double-tagging** VLAN hopping, which only works when the attacker's access VLAN equals the trunk's native VLAN.

## Allowed VLAN list and pruning

```text
SW1(config-if)# switchport trunk allowed vlan 10,20,30
SW1(config-if)# switchport trunk allowed vlan add 40
SW1(config-if)# switchport trunk allowed vlan remove 30
SW1(config-if)# switchport trunk allowed vlan except 1-9
SW1(config-if)# switchport trunk allowed vlan all
```

> **Watch out:** `switchport trunk allowed vlan 40` **replaces** the list with VLAN 40 only. Forgetting the `add` keyword is the classic change-window outage: every other VLAN stops crossing the trunk at once. Always use `add` and `remove` on a live trunk.

The two ends do not have to match: each switch only sends the VLANs in its own list and drops received frames for VLANs not in it, so a VLAN missing at either end is effectively down. Removing a VLAN from a trunk also removes it from STP on that port, which can change the topology.

**Pruning** removes a VLAN from a trunk dynamically when the downstream switch has no ports in it, so broadcasts for that VLAN do not travel there. Manual pruning is just the allowed list. **VTP pruning** (`vtp pruning` on a VTP server) does it automatically; pruned VLANs disappear from the "forwarding state and not pruned" section. `switchport trunk pruning vlan` sets which VLANs are prune-eligible (2–1001 by default, as `Pruning VLANs Enabled` shows above).

## VTP, as far as it breaks trunks

**VLAN Trunking Protocol (VTP)** is Cisco proprietary and distributes the VLAN database over trunks. It matters for trunk troubleshooting in three ways:

- **Domain name mismatch** stops DTP negotiation (above) and stops VTP updates being accepted.
- **VLANs not created**: a switch in VTP **transparent** or **off** mode, or a client in a different domain, never learns a VLAN, so the VLAN is allowed on the trunk but not "active in management domain".
- **Revision number overwrite**: a switch added to the network with a higher configuration revision in the same domain (VTP versions 1 and 2) can overwrite every switch's VLAN database. VTP version 3 limits this with a primary server. Many enterprises run `vtp mode transparent` or `vtp mode off` for this reason.

`show vtp status` shows the version, domain name, mode, pruning state and configuration revision.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (they run Cisco's x86 images; on an Apple silicon Mac use a remote x86 server or a CML instance in a DevNet Sandbox). Use IOSvL2 nodes (lighter, classic IOS 15.2 syntax) or Catalyst 9000v nodes (IOS XE, much heavier). On IOSvL2 you will need `switchport trunk encapsulation dot1q` first.

1. Cable SW1 Gi1/0/1 to SW2 Gi1/0/1 (Gi0/1 on IOSvL2). Create VLANs 10, 20 and 99 on both switches.
2. Leave both ports at their default and run `show interfaces Gi1/0/1 switchport` and `show interfaces trunk`: auto plus auto, no trunk.
3. Set SW1 to `switchport mode dynamic desirable` and watch the trunk form. Then set SW1 to `switchport mode trunk` and `switchport nonegotiate` and see SW2 fall back to access.
4. Make both ends `switchport mode trunk`. Set `switchport trunk native vlan 99` on SW1 only and read the CDP and STP messages, `show spanning-tree vlan 99` and `show spanning-tree vlan 1`. Fix it.
5. Type `switchport trunk allowed vlan 20` on SW1 and see VLAN 10 disappear from every section of `show interfaces trunk`. Restore it with `add`.
6. Delete VLAN 20 on SW2 (`no vlan 20`) and see VLAN 20 drop out of "allowed and active in management domain" on SW2 only.

## Key takeaways

- 802.1Q inserts a 4-byte tag with a 12-bit VLAN ID; the native VLAN is untagged. Catalyst 9000 supports only 802.1Q.
- DTP is Cisco proprietary. Catalyst 9000 ports default to dynamic auto; auto + auto, dynamic + access and dynamic + `nonegotiate` never trunk.
- Hard-code infrastructure trunks with `switchport mode trunk` and `switchport nonegotiate`; DTP domain-name mismatches only affect dynamic negotiation.
- `show interfaces trunk` lists only trunking ports; read its sections in order: allowed, allowed and active (VLAN exists), forwarding and not pruned (STP or VTP pruning).
- `show interfaces switchport` compares administrative and operational mode; `show dtp interface` shows whether DTP packets are exchanged.
- Native VLAN mismatch: CDP log, STP `*PVID_Inc` blocking, merged VLANs. Fix both ends; consider `vlan dot1q tag native`.
- `switchport trunk allowed vlan N` replaces the list; use `add` and `remove`.
- VTP breaks trunks through domain mismatches, missing VLANs and revision-number overwrites.
