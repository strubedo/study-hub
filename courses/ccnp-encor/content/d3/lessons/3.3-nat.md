## The four address terms

Cisco describes every translation with four addresses. "Inside" and "outside" say **whose host** the address belongs to; "local" and "global" say **which side of the router sees** the address.

| Term | Cisco definition | Example |
|---|---|---|
| **Inside local** | The address assigned to an inside host | 10.1.20.15 (the PC's real address) |
| **Inside global** | The address that represents inside hosts to the outside | 203.0.113.10 (what the internet sees) |
| **Outside local** | The outside host's address as it appears to the inside | Usually the same as outside global |
| **Outside global** | The address assigned to the outside host by its owner | 198.51.100.25 (the web server) |

Outside local differs from outside global only when you translate the **outside** host's address too (`ip nat outside source`), for example when two merged networks use overlapping addresses. In ordinary internet access, outside local = outside global.

> **Exam tip:** ask "whose host is it?" (inside or outside) and then "who is looking?" (local = seen from the inside network, global = seen from the outside network). The inside global is the address on your public side; it belongs to an inside host.

RFC 3022 calls the two main types Basic NAT (address only) and NAPT (address and port); Cisco calls NAPT **PAT** or overload. RFC 2663 defines the general terminology.

## Marking inside and outside

Every translating interface must be marked:

```text
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# description LAN
R1(config-if)# ip address 10.1.20.1 255.255.255.0
R1(config-if)# ip nat inside
R1(config-if)# interface GigabitEthernet0/0/0
R1(config-if)# description ISP
R1(config-if)# ip address 203.0.113.2 255.255.255.248
R1(config-if)# ip nat outside
```

A packet is translated only when it moves between an `ip nat inside` interface and an `ip nat outside` interface. Forgetting one side (or swapping them) is the most common NAT fault: `show ip nat statistics` lists which interfaces are inside and outside, so check it first.

## Static NAT

A permanent one-to-one mapping, used for servers that outside hosts must reach:

```text
R1(config)# ip nat inside source static 10.1.10.20 203.0.113.3
```

The entry exists in the table from the moment it is configured, works in both directions, and uses one public address per inside host.

**Static PAT (port forwarding)** maps one protocol and port only, so one public address can front several servers:

```text
R1(config)# ip nat inside source static tcp 10.1.10.20 443 203.0.113.4 443 extendable
R1(config)# ip nat inside source static tcp 10.1.10.21 22 203.0.113.4 2222 extendable
```

Outside users connect to 203.0.113.4:443 and 203.0.113.4:2222. `extendable` allows the same inside local address to appear in more than one static entry (here 10.1.10.20 also has the one-to-one entry above); IOS normally adds the keyword itself when a second entry for the same address is configured. Instead of a fixed address you can name the outside interface (`... static tcp 10.1.10.20 443 interface GigabitEthernet0/0/0 443`), which suits a DHCP-assigned public address.

## Dynamic NAT with a pool

```text
R1(config)# ip access-list standard NAT-USERS
R1(config-std-nacl)# permit 10.1.20.0 0.0.0.255
R1(config-std-nacl)# exit
R1(config)# ip nat pool PUBLIC 203.0.113.3 203.0.113.6 prefix-length 29
R1(config)# ip nat inside source list NAT-USERS pool PUBLIC
```

- The ACL selects **which inside local addresses** are translated (permit = translate). It is not a security filter.
- The pool lists the inside global addresses (`netmask 255.255.255.248` works instead of `prefix-length 29`).
- Without `overload`, each inside host takes **one whole pool address** for as long as its translation lives. With four addresses, the fifth host is not translated and its packets are dropped; `show ip nat statistics` shows the pool 100% allocated and misses climbing.

## PAT (overload)

```text
R1(config)# ip nat inside source list NAT-USERS pool PUBLIC overload
```

or, with the outside interface's own address:

```text
R1(config)# ip nat inside source list NAT-USERS interface GigabitEthernet0/0/0 overload
```

`overload` makes the router translate address **and** port, so thousands of inside hosts share one public address; each flow is identified by the inside global address and port. IOS keeps the original source port when it is free and picks another when it is not. With a pool, PAT uses the first address until its ports run out, then the next. Interface overload is the normal small-office and branch configuration.

## ACL or route-map

`ip nat inside source route-map NAME pool|interface ... [overload]` selects traffic with a route-map instead of an ACL. A route-map can match the **outgoing interface or next hop** as well as an ACL, so a router with two ISPs can translate to ISP-A's address when traffic leaves through ISP-A and to ISP-B's address otherwise:

```text
route-map NAT-ISPA permit 10
 match ip address NAT-USERS
 match interface GigabitEthernet0/0/0
ip nat inside source route-map NAT-ISPA interface GigabitEthernet0/0/0 overload
```

Route-map entries also create fully extended translation entries (with the outside addresses), which helps when the same inside host talks through different exits.

## Order of operations

The routing decision and the translation happen in opposite order in the two directions:

| Direction | Order |
|---|---|
| Inside to outside | Inbound ACL on the inside interface (sees the **inside local** source), **routing**, then **NAT** (local to global), then the outbound ACL on the outside interface (sees the **inside global** source) |
| Outside to inside | Inbound ACL on the outside interface (sees the **inside global** destination), **NAT** (global to local), then **routing** toward the inside local address |

Consequences:

- Inside to outside, a route toward the destination must exist **before** translation, or the packet is dropped before NAT sees it.
- An inbound ACL on the outside interface must permit the **inside global** address (the public one), because NAT has not yet translated it back. Writing it with the server's private address is a classic mistake.
- Outside to inside, the route used is the one to the inside **local** address, after translation.

IOS, and IOS XE on platforms that support it, also has the **NAT Virtual Interface** (NVI), enabled with `ip nat enable` on interfaces instead of inside and outside, which removes the inside/outside distinction and the domain-specific order. ENCOR expects classic inside/outside NAT; just recognise NVI if you see it.

## Timeouts

Dynamic translations are removed after a period without traffic. The general timeout is 24 hours, with shorter per-protocol timers such as UDP and DNS entries; TCP entries are removed shortly after FIN or RST. They are changed with `ip nat translation timeout SECONDS` and the specific keywords (`udp-timeout`, `tcp-timeout`, `dns-timeout`, `finrst-timeout`, `icmp-timeout`, `syn-timeout`). Static entries never time out.

## Verification

```text
R1# show ip nat translations
Pro  Inside global         Inside local          Outside local         Outside global
---  203.0.113.3           10.1.10.20            ---                   ---
tcp  203.0.113.4:443       10.1.10.20:443        ---                   ---
tcp  203.0.113.2:51034     10.1.20.15:51034      198.51.100.25:443     198.51.100.25:443
udp  203.0.113.2:1024      10.1.20.16:53172      198.51.100.53:53      198.51.100.53:53
Total number of translations: 4
```

| Line | Reading |
|---|---|
| `---` protocol, no ports, no outside | A static one-to-one entry (always present) |
| `tcp ... :443`, no outside | A static port-forwarding entry |
| Full four columns with ports | Dynamic PAT flows: 10.1.20.15 kept its source port 51034; 10.1.20.16's port 53172 was changed to 1024 because of a collision or port allocation |

```text
R1# show ip nat statistics
Total active translations: 4 (2 static, 2 dynamic; 3 extended)
Outside interfaces:
  GigabitEthernet0/0/0
Inside interfaces:
  GigabitEthernet0/0/1
Hits: 18842  Misses: 37
Expired translations: 412
Dynamic mappings:
-- Inside Source
[Id: 1] access-list NAT-USERS interface GigabitEthernet0/0/0 refcount 2
```

The interface lists, the mapping (ACL and pool or interface) and the pool allocation lines (`total addresses 4, allocated 4 (100%), misses 37` for an exhausted pool) answer most NAT questions. Misses count packets that needed a new translation.

| Tool | Use |
|---|---|
| `clear ip nat translation *` | Removes all **dynamic** entries (needed after changing a NAT rule, because existing entries keep being used); specific entries can be cleared by inside and outside addresses |
| `debug ip nat` | Shows each translation, for example `NAT: s=10.1.20.15->203.0.113.2, d=198.51.100.25 [8812]`; use with an ACL (`debug ip nat 10`) on a busy router |
| `show ip nat translations verbose` | Adds creation time, last use and remaining timeout per entry |

## Troubleshooting checklist

| Symptom | Cause |
|---|---|
| No translations at all | Missing `ip nat inside` / `ip nat outside`, ACL does not permit the source, or no route out |
| Some hosts work, later hosts fail | Dynamic pool without `overload`, pool exhausted |
| Port forwarding fails from outside | Outside ACL written with the private address; server's default gateway is not the NAT router; wrong port pair order (inside port first, then global port) |
| Changes have no effect | Old dynamic entries still in the table: `clear ip nat translation *` |
| Translation exists but replies never return | The ISP has no route back to the inside global addresses (pool not routed to you) |

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML). Build three LAN hosts PC1 to PC3 in 10.1.20.0/24 (VPCS nodes or small routers acting as hosts) – R1 – ISP, with a server 10.1.10.20 behind R1 and a loopback 198.51.100.25 on ISP. Give ISP a static route for 203.0.113.0/29 toward R1.

1. Mark the interfaces, configure PAT with `interface ... overload`, and generate traffic (`ping`, `telnet 198.51.100.25 80` from a router host). Read `show ip nat translations` and `show ip nat statistics`.
2. Replace it with a pool of two addresses without `overload`, generate traffic from three hosts and watch the third fail and the misses counter climb; add `overload` and clear the table.
3. Add `ip nat inside source static tcp 10.1.10.20 80 203.0.113.4 8080` and connect from ISP to 203.0.113.4 port 8080.
4. Apply an inbound ACL on R1's outside interface permitting only the server's private address, see the forwarding fail, and correct it to the inside global address.
5. Run `debug ip nat` with an ACL during a ping and read the `s=` and `d=` fields.

## Key takeaways

- Inside local = the inside host's real address; inside global = how it appears outside; outside local = the outside host as seen inside; outside global = the outside host's real address.
- Translation happens only between `ip nat inside` and `ip nat outside` interfaces.
- Static: `ip nat inside source static LOCAL GLOBAL`; port forwarding: `... static tcp LOCAL PORT GLOBAL PORT`; dynamic: ACL + `ip nat pool` + `ip nat inside source list ... pool`; PAT: add `overload` (pool or `interface`).
- Without `overload`, each host consumes a whole pool address and the pool can run out.
- Inside to outside: routing, then NAT. Outside to inside: NAT, then routing. Outside inbound ACLs see the inside global address.
- Verify with `show ip nat translations` and `show ip nat statistics`; clear dynamic entries with `clear ip nat translation *` after changes; `debug ip nat` with an ACL.
