## Path operations in practice

The previous lesson covered how each protocol computes a metric. This one covers what the router does with those metrics: which path wins, how traffic is shared across several paths, how the router chooses between protocols, and how OSPF area types shape what routers in an area know.

## How each protocol chooses a path

A router first prefers the **longest prefix match**, then, between sources offering the same prefix, the lowest **administrative distance**, and only then the protocol's own metric.

**EIGRP** installs its successor: the lowest total composite metric among neighbors that meet the feasibility condition. **OSPF** compares route types before cost: an **intra-area** route (`O`) beats an **inter-area** route (`O IA`), which beats an external type 1 (`O E1` / `O N1`), which beats an external type 2 (`O E2` / `O N2`), whatever the costs.

## Load balancing and path operations

Both protocols install up to `maximum-paths` equal-cost routes (default **4** on IOS XE; up to 32 depending on platform) and let CEF share traffic per destination flow.

Only EIGRP can use unequal-cost paths. `variance N` (default **1**, range 1–128) installs any **feasible successor** whose metric is less than N times the FD. Traffic is shared in inverse proportion to the metrics (`traffic share count` in `show ip route`).

```text
R1(config)# router eigrp 100
R1(config-router)# variance 2
```

Take the topology from the previous lesson: successor 10.0.12.2 at 28672, feasible successor 10.0.13.3 at 54016 (RD 28160), and 10.0.14.4 at 28928 (RD 28672, failing the condition). With `variance 2`, R1 installs 10.0.12.2 (28672) and 10.0.13.3 (54016, below 2 x 28672 = 57344). 10.0.14.4 is never installed, at any variance, because it is not a feasible successor.

`show ip route 10.50.0.0` then lists both next hops, each with a "traffic share count" (inverse to its metric), and `show ip protocols` shows "EIGRP maximum metric variance 2". OSPF has no equivalent: to share over unequal links, make their costs equal with `ip ospf cost`.

**Path operations after a failure.** EIGRP switches to a feasible successor locally and immediately, and only queries when none exists. OSPF floods a new LSA describing the failed link, and every router in the area reruns SPF; routers in other areas only see changed type 3 LSAs from the ABR. On current hardware the computation itself is quick; how fast the failure is detected (hold or dead timer, carrier loss, or BFD) usually decides convergence time.

## Administrative distance

When two sources offer the same prefix and length, the lower administrative distance wins and the metrics are never compared, because metrics of different protocols mean different things. Longest match still comes first: a /24 from any protocol beats a /16 from any other.

| Source | AD | | Source | AD |
|---|---|---|---|---|
| Connected | 0 | | OSPF (all types) | 110 |
| Static | 1 | | IS-IS | 115 |
| EIGRP summary | 5 | | RIP | 120 |
| eBGP | 20 | | EIGRP external | 170 |
| EIGRP internal | 90 | | iBGP and locally generated BGP | 200 |

Change it with `distance eigrp INTERNAL EXTERNAL` (classic mode), `distance ospf intra-area N inter-area N external N`, or `distance bgp EXTERNAL INTERNAL LOCAL`.

For example, R1 learns 10.20.0.0/16 as an EIGRP external route (AD 170) and as an OSPF inter-area route (AD 110). OSPF's route is installed whatever the metrics. To prefer EIGRP for its external routes, lower their distance below 110:

```text
R1(config)# router eigrp 100
R1(config-router)# distance eigrp 90 100
```

Now the EIGRP route (AD 100) is installed and the OSPF route waits as the backup, appearing only if the EIGRP route disappears. `show ip route 10.20.0.0` names the installed source on its "Known via" line, with its distance.

## OSPF area types

Areas limit LSA flooding and SPF scope. Every non-backbone area must touch area 0 through an area border router (ABR). The area type decides which LSAs an ABR lets in:

| Area type | Type 1, 2 (intra-area) | Type 3 (inter-area) | Type 4, 5 (external) | Type 7 | Default route |
|---|---|---|---|---|---|
| Backbone (area 0) / normal | Yes | Yes | Yes | No | Only if originated |
| Stub (`area N stub`) | Yes | Yes | **No** | No | ABR injects a type 3 default |
| Totally stubby (`area N stub no-summary` on the ABR) | Yes | **Only the default** | No | No | Type 3 default |
| NSSA (`area N nssa`) | Yes | Yes | No | **Yes** (local ASBR) | Not automatic; `area N nssa default-information-originate` adds a type 7 default |
| Totally NSSA (`area N nssa no-summary` on the ABR) | Yes | **Only the default** | No | Yes | Type 3 default |

Every router in a stub or NSSA area must agree on the type (the flag is in every hello); `no-summary` matters only on the ABR. The NSSA ABR translates type 7 into type 5 for the rest of the domain.

Two design notes:

- A **stub** or **totally stubby** area cannot contain an ASBR, because type 5 LSAs are not allowed in it. Use an **NSSA** when a branch area must redistribute something (a connected partner network, a static route to a local Internet link) but should still be shielded from the domain's external routes.
- A **virtual link** cannot cross a stub area or NSSA.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host, with four IOSv or Catalyst 8000v routers. These tools run Cisco's x86 images, so on an Apple silicon Mac use a remote x86 server or a Cisco DevNet sandbox with CML.

1. Reuse the EIGRP topology from the previous lesson. Configure `variance 2` and check `show ip route 10.50.0.0` for two next hops and their traffic share counts; raise and lower the variance and predict which paths appear.
2. Run OSPF on the same routers as well. Find a prefix learned by both and confirm OSPF (110) wins over EIGRP external (170) but loses to EIGRP internal (90). Apply `distance eigrp 90 100` and watch the external route take over.
3. Split the OSPF domain into area 0 (R1, R2) and area 1 (R2, R3, R4). Redistribute a loopback on R1.
4. Make area 1 a stub on all its routers; on R3 confirm `show ip route ospf` lost the `O E2` routes and gained an `O*IA` default.
5. Add `no-summary` on the ABR only and confirm the `O IA` routes are gone except the default.
6. Change area 1 to an NSSA, redistribute a loopback on R4, and find the `O N2` route on R3 and the translated `O E2` route on R1.

## Key takeaways

- Longest match first, then lowest administrative distance, then the protocol's metric.
- OSPF prefers intra-area, then inter-area, then E1/N1, then E2/N2, whatever the costs.
- Both protocols load-share over up to `maximum-paths` equal-cost paths (default 4); only EIGRP does unequal-cost sharing, with `variance`, and only over feasible successors.
- AD: connected 0, static 1, EIGRP summary 5, eBGP 20, EIGRP internal 90, OSPF 110, IS-IS 115, RIP 120, EIGRP external 170, iBGP 200.
- Stub: no type 4 or 5, default injected. Totally stubby: also no type 3 except the default. NSSA: no type 5, but type 7 from a local ASBR. Totally NSSA: NSSA plus only a default type 3.
- Every router in the area must agree on stub or NSSA; `no-summary` is configured on the ABR.
