## Why areas

In one big area every router holds every link of the network and reruns SPF whenever any link anywhere flaps. Areas split the LSDB: routers keep the full topology only of their own area and see other areas as a list of prefixes with costs, the way a distance vector protocol would. That shrinks the database, contains SPF runs, and gives you the points where summarization and filtering happen.

Rules for a multi-area OSPFv2 design:

- **Area 0** is the backbone. Every other area must attach to it, and inter-area traffic always crosses it (area 1 to area 2 goes through area 0).
- Area 0 must be contiguous. A virtual link through a transit area can repair a broken backbone, but treat it as a temporary fix.
- An interface belongs to exactly one area; a router can have interfaces in several.

## Router roles

| Role | Definition | Originates |
|---|---|---|
| Internal router | All OSPF interfaces in one area | Type 1 (and type 2 if DR) |
| Backbone router | At least one interface in area 0 | Type 1 for area 0 |
| **ABR** (area border router) | Interfaces in area 0 and at least one other area; keeps one LSDB per area | Type 3 and type 4 into each area; translates type 7 to type 5 for an NSSA |
| **ASBR** (autonomous system boundary router) | Redistributes routes from another source (static, connected, EIGRP, BGP) into OSPF | Type 5, or type 7 inside an NSSA |

`show ip protocols` states the role: "It is an area border router", "It is an autonomous system boundary router", or both.

## LSA types

| Type | Name in `show ip ospf database` | Originated by | Flooded | Link State ID |
|---|---|---|---|---|
| 1 Router | Router Link States | Every router | Within its area | Originating router's RID |
| 2 Network | Net Link States | The DR of a transit segment | Within its area | DR's interface address |
| 3 Summary | Summary Net Link States | ABR | Into an area, describing prefixes from other areas | Network address |
| 4 ASBR summary | Summary ASB Link States | ABR | Into an area, describing how to reach an ASBR in another area | ASBR's RID |
| 5 AS external | Type-5 AS External Link States | ASBR | Whole domain except stub areas and NSSAs | External network address |
| 7 NSSA external | Type-7 AS External Link States | ASBR inside an NSSA | Only inside that NSSA; the ABR translates it to type 5 | External network address |

Type 1 and 2 LSAs carry the topology; SPF runs over them. Type 3 LSAs carry only a prefix and a cost, so a change inside area 1 produces new type 3 LSAs in area 0 instead of an SPF run in area 0. An ABR regenerates each type 3 with itself as the advertising router; that is why "ADV Router" on a type 3 is always an ABR.

## Reading OSPF routes

```text
R5# show ip route ospf
<legend omitted>
Gateway of last resort is 10.0.25.2 to network 0.0.0.0

O*E2  0.0.0.0/0 [110/1] via 10.0.25.2, 01:12:44, GigabitEthernet0/0/0
      10.0.0.0/8 is variably subnetted, 18 subnets, 4 masks
O IA     10.0.12.0/30 [110/2] via 10.0.25.2, 01:12:44, GigabitEthernet0/0/0
O        10.1.4.0/24 [110/2] via 10.0.45.4, 00:40:10, GigabitEthernet0/0/1
O E1     10.98.0.0/16 [110/22] via 10.0.25.2, 00:03:01, GigabitEthernet0/0/0
O E2     10.99.0.0/16 [110/20] via 10.0.25.2, 00:03:01, GigabitEthernet0/0/0
O IA     10.255.0.1/32 [110/3] via 10.0.25.2, 01:12:44, GigabitEthernet0/0/0
O IA     10.255.0.2/32 [110/2] via 10.0.25.2, 01:12:44, GigabitEthernet0/0/0
```

The subnet count in the header covers R5's whole table, including its connected and local routes; `show ip route ospf` lists only the OSPF ones, in address order.

| Code | Meaning | From LSA |
|---|---|---|
| `O` | Intra-area | Types 1 and 2 |
| `O IA` | Inter-area | Type 3 |
| `O E1` / `O E2` | External type 1 / type 2 | Type 5 |
| `O N1` / `O N2` | NSSA external type 1 / type 2 | Type 7 |
| `*` | Candidate default | |

**E1 versus E2.** An **E2** route's metric is only the external seed metric set at redistribution (default **20** for most sources, **1** for BGP and for a default route from `default-information originate`); it stays the same across the whole domain. When two E2 routes have the same metric, the one with the lower internal cost to its ASBR (the forward metric) wins, but that cost is not added to the displayed metric. An **E1** route's metric is the seed metric **plus** the internal cost to reach the ASBR, so it grows with distance and lets each router pick its nearest exit. E2 is the default (`redistribute ... metric-type 1` gives E1). Whatever the metrics, OSPF prefers intra-area over inter-area over E1/N1 over E2/N2.

## Summarization

OSPF summarizes only at area boundaries (ABR) and redistribution points (ASBR), never inside an area, because routers in an area must share an identical LSDB.

**Inter-area summarization** on the ABR, for prefixes of the named area:

```text
R2(config)# router ospf 1
R2(config-router)# area 1 range 10.1.0.0 255.255.252.0
```

Instead of four type 3 LSAs for 10.1.0.0/24 to 10.1.3.0/24, R2 advertises one type 3 for 10.1.0.0/22 into area 0 (and from there into other areas), as long as at least one component route exists in area 1. Its cost is derived from the component routes (RFC 2328 uses the highest component cost) unless you set `area 1 range ... cost N`. A flap of 10.1.2.0/24 no longer changes anything outside area 1.

**External summarization** on the ASBR, for redistributed routes (types 5 and 7):

```text
R1(config-router)# summary-address 10.200.0.0 255.255.0.0
```

`area range` does nothing for external routes, and `summary-address` does nothing for internal ones. An NSSA ABR can also apply `summary-address` to the type 7 routes it translates.

**The discard route.** When a summary is active, the router that creates it installs a route for the summary pointing to **Null0**:

```text
R2# show ip route 10.1.0.0 255.255.252.0 longer-prefixes | include Null0
O        10.1.0.0/22 is a summary, 00:21:07, Null0
```

If area 1 has 10.1.0.0/24 to 10.1.2.0/24 but no 10.1.3.0/24, a packet for 10.1.3.9 arriving at R2 matches the /22 and is dropped there. Without the discard route R2 would follow its default route back toward the core, which would send it back to R2, looping until the TTL expires.

## Filtering

In a link-state protocol you cannot filter LSAs inside an area: every router must have the same database. Filtering happens at ABRs and ASBRs, or only on the local routing table.

| Tool | Where | What it does |
|---|---|---|
| `area 1 range 10.1.0.0 255.255.252.0 not-advertise` | ABR | Suppresses the summary **and** its components: no type 3 for any of them leaves area 1 |
| `area 1 filter-list prefix NAME in` | ABR | Filters type 3 LSAs the ABR generates **into** area 1 |
| `area 1 filter-list prefix NAME out` | ABR | Filters type 3 LSAs generated from area 1's routes **out** to other areas |
| `distribute-list prefix NAME in` (router mode) | Any router | Stops matching OSPF routes from being installed in **this router's** RIB. LSAs are still received, stored and flooded |
| `distribute-list NAME out PROTOCOL` | ASBR | Filters which routes are redistributed into OSPF |
| `summary-address ... not-advertise` | ASBR | Suppresses matching external routes |

```text
R2(config)# ip prefix-list NO-LAB seq 5 deny 10.1.3.0/24
R2(config)# ip prefix-list NO-LAB seq 10 permit 0.0.0.0/0 le 32
R2(config)# router ospf 1
R2(config-router)# area 1 filter-list prefix NO-LAB out
```

The trailing `permit 0.0.0.0/0 le 32` matters: a prefix list ends with an implicit deny, so without it every type 3 leaving area 1 is dropped.

> **Watch out:** `distribute-list in` hides a route only on the router where you configure it. Routers behind it still learn the prefix from the flooded LSAs and may forward traffic to that router, which then drops it or uses a less specific route. Use it to choose between sources on one router, not to hide a network from an area.

## Default routes

An ASBR advertises a default route into a normal area with:

```text
R1(config-router)# default-information originate
```

That originates an external type 2 default (metric **1**) **only if R1 has a default route in its own routing table** from another source, such as a static default toward the ISP. `default-information originate always` advertises it regardless, which is useful when the default route comes from a protocol that might be briefly absent, but dangerous if R1 can lose its own exit: routers keep sending traffic to it. `metric` and `metric-type 1` options adjust the route. Stub, totally stubby and totally NSSA ABRs inject their own type 3 default automatically; an NSSA ABR needs `area N nssa default-information-originate`.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML), with four IOSv or Catalyst 8000v routers (R1, R2, R4, R5).

1. Build R1–R2 in area 0, R2–R5 and R5–R4 in area 1 with a LAN 10.1.4.0/24 on R4, and give R5 loopbacks 10.1.0.1/24 to 10.1.3.1/24 with `ip ospf network point-to-point` so they appear as /24s.
2. On R1 read `show ip route ospf` (`O IA` routes) and on R2 `show ip ospf database` (two router LSA sets).
3. Configure `area 1 range 10.1.0.0 255.255.252.0` on R2. Check R1's routing table (one `O IA` /22) and R2's Null0 discard route.
4. Add `area 1 filter-list prefix NO-LAB out` for 10.1.3.0/24 (remove the range first) and confirm only that prefix disappears on R1.
5. On R1 add `ip route 0.0.0.0 0.0.0.0 Null0` as a stand-in ISP route, then `default-information originate`; see `O*E2` on R5. Remove the static and watch the default vanish; add `always` and watch it return.
6. Redistribute a loopback on R1 with `redistribute connected subnets` and compare E2 and E1 metrics on R5 (`metric-type 1`).
7. Try `distribute-list prefix NO-LAB in` on R2 and confirm with `show ip ospf database` that the LSA is still there.

## Key takeaways

- Area 0 is the backbone; every area attaches to it. ABRs join areas; ASBRs redistribute.
- LSA 1 router and 2 network stay in their area; 3 summary (ABR) carries inter-area prefixes; 4 locates an ASBR; 5 external floods everywhere except stub and NSSA areas; 7 lives only in an NSSA and is translated to 5.
- Codes: `O` intra, `O IA` inter, `O E1`/`O E2` external, `O N1`/`O N2` NSSA. E2 keeps the seed metric (default 20); E1 adds internal cost.
- Summarize internal routes with `area N range` on the ABR and external routes with `summary-address` on the ASBR; both install a Null0 discard route.
- Filter type 3s with `area N filter-list prefix ... in|out` or `area N range ... not-advertise`; `distribute-list in` filters only the local RIB.
- `default-information originate` needs a default in the RIB; `always` removes that condition.
