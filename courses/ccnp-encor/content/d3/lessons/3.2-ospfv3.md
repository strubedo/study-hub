## What changed from OSPFv2

OSPFv3 (RFC 5340) is OSPF rebuilt for IPv6. The algorithms are unchanged: the same areas, area types, neighbor states, DR and BDR election, network types, SPF and route types. What changed is how addresses are carried and how a router identifies its neighbors.

| | OSPFv2 | OSPFv3 |
|---|---|---|
| Runs over | IPv4, protocol 89 | IPv6, next header 89 |
| Multicast | 224.0.0.5 / 224.0.0.6 | **FF02::5** (AllSPFRouters) / **FF02::6** (AllDRouters) |
| Hello source | Interface IPv4 address | Interface **link-local** address |
| Runs per | IP subnet: neighbors must share subnet and mask | **Link**: neighbors need only link-local addresses; global prefixes do not have to match |
| Router ID | 32-bit | Still **32-bit**, dotted decimal; must be set by hand if the router has no IPv4 address |
| Neighbors identified by | Interface address on broadcast networks | Always the router ID |
| Addresses in router and network LSAs | Yes | **No**: they describe topology only; prefixes moved to new LSAs |
| Authentication | In the OSPF header | Removed from the header; IPsec (AH/ESP) or the authentication trailer (RFC 7166) |
| Multiple instances per link | No | Yes: an **Instance ID** in the header |
| Address families | IPv4 only | IPv6, and IPv4 with the address-family extension (RFC 5838) |

Next hops in the IPv6 routing table are the neighbor's link-local address plus the outgoing interface:

```text
R1# show ipv6 route ospf
<legend omitted>
OI  2001:DB8:0:23::/64 [110/2]
     via FE80::2, GigabitEthernet0/0/1
OI  2001:DB8:5:1::/64 [110/3]
     via FE80::2, GigabitEthernet0/0/1
```

That is normal: OSPFv3 exchanges link-local addresses, so a link-local next hop is not a fault. Note the IPv6 route codes: `O` intra-area, `OI` inter-area (both routes here come from area 1 through the ABR R2), `OE1` / `OE2` external, `ON1` / `ON2` NSSA. Setting static link-local addresses such as `FE80::2` on each interface makes this output, and `show ipv6 ospf neighbor detail`, much easier to read.

## The router ID trap

The router ID is still a 32-bit number, and OSPFv3 takes it from the router's IPv4 addresses by the same rules as OSPFv2. On a router with **no IPv4 address at all**, OSPFv3 cannot pick one, the process does not start, and no neighbors form. IOS logs a message saying it could not pick a router ID and asking you to configure one. Configure it explicitly:

```text
R6(config)# ipv6 router ospf 1
R6(config-rtr)# router-id 10.255.0.6
```

It does not need to be a configured or reachable IPv4 address, only unique.

## LSA types

RFC 5340 keeps the numbering but renames two LSAs and adds two:

| LS type | Name | Function code | Scope | Carries |
|---|---|---|---|---|
| 0x2001 | Router-LSA | 1 | Area | The router's links and neighbors; **no prefixes** |
| 0x2002 | Network-LSA | 2 | Area | The routers attached to a transit link (from the DR); **no prefix** |
| 0x2003 | **Inter-Area-Prefix-LSA** | 3 | Area | Was the type 3 summary: a prefix from another area (ABR) |
| 0x2004 | **Inter-Area-Router-LSA** | 4 | Area | Was the type 4 ASBR summary |
| 0x4005 | AS-External-LSA | 5 | AS | External prefix (ASBR) |
| 0x2007 | NSSA-LSA | 7 | Area | External prefix inside an NSSA |
| 0x0008 | **Link-LSA** | 8 | **Link-local** | The router's link-local address on that link, its IPv6 prefixes on the link, and its options; never leaves the link |
| 0x2009 | **Intra-Area-Prefix-LSA** | 9 | Area | The IPv6 prefixes of a router (or, from the DR, of a transit link), referenced to its router or network LSA |

The payoff of moving prefixes out of router and network LSAs: adding or removing an IPv6 prefix changes only a type 9 LSA, so routers recompute routes to prefixes without a full SPF of the topology. The upper bits of the LS type encode flooding scope (link, area or AS) and whether a router that does not understand the type should still flood it.

```text
R1# show ipv6 ospf database

                Link (Type-8) Link States (Area 0)
```

This capture was taken while the R1–R2 link (Gi0/0/1) still had the default broadcast network type, with R2 as DR: that is why a network LSA and an intra-area prefix LSA referencing it exist. After `ipv6 ospf network point-to-point` (configured below) they disappear, and each router's link prefixes are carried in intra-area prefix LSAs referencing its router LSA. The router LSA shows the `B` bit on the ABR (`E` marks an ASBR). The Link ID of network and link LSAs is an **interface ID**, not an address. Each intra-area prefix LSA points to the router LSA (0x2001) or network LSA (0x2002) whose prefixes it carries.

## Configuration: traditional mode

Classic OSPFv3 configuration for IPv6 uses a router process plus interface commands. There is **no `network` command**: interfaces are enabled individually.

```text
R1(config)# ipv6 unicast-routing
R1(config)# ipv6 router ospf 1
R1(config-rtr)# router-id 10.255.0.1
R1(config-rtr)# passive-interface Loopback0
R1(config-rtr)# exit
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ipv6 address 2001:DB8:0:12::1/64
R1(config-if)# ipv6 address FE80::1 link-local
R1(config-if)# ipv6 ospf 1 area 0
R1(config-if)# ipv6 ospf network point-to-point
```

Without `ipv6 unicast-routing` the router acts as an IPv6 host and does not route IPv6 at all.

## Configuration: address-family mode

The newer form, `router ospfv3`, supports both address families in one process, each with its own LSDB and adjacencies (the IPv4 family uses a different Instance ID range, so an IPv4 and an IPv6 instance can run on the same link):

```text
R1(config)# router ospfv3 1
R1(config-router)# router-id 10.255.0.1
R1(config-router)# address-family ipv6 unicast
R1(config-router-af)# passive-interface Loopback0
R1(config-router-af)# exit-address-family
R1(config-router)# exit
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ospfv3 1 ipv6 area 0
R1(config-if)# ospfv3 network point-to-point
```

`ospfv3 1 ipv4 area 0` on an interface (which also needs an IPv4 address and IPv6 enabled) adds the IPv4 family over OSPFv3. Per-interface settings such as `ospfv3 cost`, `ospfv3 priority`, `ospfv3 hello-interval` mirror the `ip ospf` commands. Area types work as in OSPFv2: `area 1 stub`, `area 1 stub no-summary`, `area 1 nssa`, and summarization is `area 1 range 2001:DB8:1::/48` inside the address family.

> **Exam tip:** `ipv6 ospf 1 area 0` (traditional) and `ospfv3 1 ipv6 area 0` (address-family) do the same thing on an interface. Recognize both, and remember that neither has a `network` statement.

## Authentication

OSPFv3 has no authentication field. There are two ways to protect it:

- **IPsec**: AH or ESP with manually configured keys (OSPF multicast cannot use IKE), per interface or per area. For example `ospfv3 authentication ipsec spi 500 sha1 <KEY>` on the interface, or `area 0 authentication ipsec spi 500 sha1 <KEY>` in the process. The SPI and key must match on every router on the link.
- **Authentication trailer** (RFC 7166): an HMAC appended after the OSPFv3 packet, the same idea as OSPFv2 cryptographic authentication, without IPsec. IOS XE configures it with a key chain (`ospfv3 authentication key-chain NAME`) using HMAC-SHA algorithms.

Both ends must use the same method and keys; a mismatch shows up as no neighbor.

## Verification

| Command | Shows |
|---|---|
| `show ipv6 ospf neighbor` / `show ospfv3 neighbor` | Neighbor ID (RID), priority, state, dead time, the neighbor's **interface ID** (no address column) |
| `show ipv6 ospf interface brief` / `show ospfv3 interface brief` | Interfaces, area, cost, state, neighbors |
| `show ipv6 ospf interface Gi0/0/1` | Link-local address, interface ID, network type, timers, DR/BDR |
| `show ipv6 ospf database` / `show ospfv3 database` | LSDB by LSA type |
| `show ipv6 route ospf` | Routes with link-local next hops |
| `show ipv6 protocols` | Processes, interfaces, areas |

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML), with three IOSv or Catalyst 8000v routers.

1. Enable `ipv6 unicast-routing`. Address R1–R2 with 2001:DB8:0:12::/64 and R2–R3 with 2001:DB8:0:23::/64, link-local FE80::N on every interface.
2. Configure R1 and R2 in traditional mode (`ipv6 router ospf 1`; `ipv6 ospf 1 area 0` on the R1–R2 link, `ipv6 ospf 1 area 1` on R2's link to R3) and R3 in address-family mode (`router ospfv3 1`, `ospfv3 1 ipv6 area 1` on its interfaces). Confirm they interoperate.
3. Remove every IPv4 address from R3, clear the process, and watch it fail to pick a router ID; then configure `router-id 10.255.0.3`.
4. Read `show ipv6 ospf database` on R2 and find the Link (type 8) and Intra-Area-Prefix (type 9) LSAs.
5. Change the global prefix on one side of R1–R2 to a different /64 and confirm the adjacency stays up.
6. Add `ospfv3 authentication ipsec spi 500 sha1` with a placeholder 40-hex-digit key (for example forty zeros, lab only) on one end, watch the adjacency drop, then add it to the other end.

## Key takeaways

- OSPFv3 keeps OSPF's algorithms, areas, states and DR election; it runs per link, uses link-local sources and next hops, and multicasts to FF02::5 and FF02::6.
- The router ID is still 32-bit; a router without IPv4 addresses needs `router-id`.
- Router and network LSAs carry no prefixes; Link LSA (type 8, link scope) carries link-local addresses and link prefixes, Intra-Area-Prefix LSA (type 9) carries a router's or transit link's prefixes; types 3 and 4 are renamed Inter-Area-Prefix and Inter-Area-Router.
- Configure per interface: `ipv6 ospf PID area N` (traditional) or `ospfv3 PID ipv6 area N` (address-family); no `network` command.
- Authentication: IPsec AH/ESP or the RFC 7166 authentication trailer; the header has no authentication field.
- Verify with `show ospfv3 neighbor` or `show ipv6 ospf neighbor`, `show ipv6 ospf interface`, `show ipv6 ospf database` and `show ipv6 route ospf`.
