## Why MST

Rapid PVST+ runs one spanning-tree instance per VLAN. With 500 VLANs on a trunk, a switch computes 500 trees and sends 500 BPDUs every hello time, yet a typical campus only needs **two** different topologies: "forward on the left uplink" and "forward on the right uplink". **Multiple Spanning Tree** (IEEE 802.1s, now part of 802.1Q) maps many VLANs to a small number of **instances**, each with its own root and its own forwarding topology, and runs RSTP mechanics (proposal and agreement, alternate ports, edge ports) inside each instance. It is also the standard choice when Cisco switches share a Layer 2 domain with other vendors, which do not run PVST+.

```text
DSW1(config)# spanning-tree mode mst
```

## Regions

MST switches only cooperate fully with switches in the **same region**. Two switches are in the same region only when all three of these match exactly:

| Attribute | Command | Default |
|---|---|---|
| Region **name** (case sensitive) | `name CAMPUS` | Empty |
| **Revision** number | `revision 1` | 0 |
| **VLAN-to-instance mapping** | `instance 1 vlan 10-19` | All VLANs in instance 0 |

The mapping is not sent in full. Each BPDU carries the name, the revision and a 16-byte **configuration digest**, an HMAC-MD5 hash of the 4096-entry VLAN-to-instance table. If any of the three differs, the neighbour is in a different region and the link becomes a **region boundary**. One VLAN mapped differently is enough.

```text
DSW1(config)# spanning-tree mst configuration
DSW1(config-mst)# name CAMPUS
DSW1(config-mst)# revision 1
DSW1(config-mst)# instance 1 vlan 10-19
DSW1(config-mst)# instance 2 vlan 20-29
DSW1(config-mst)# show pending
Pending MST configuration
Name      [CAMPUS]
Revision  1     Instances configured 3

Instance  Vlans mapped
--------  ---------------------------------------------------------------------
0         1-9,30-4094
1         10-19
2         20-29
-------------------------------------------------------------------------------
DSW1(config-mst)# exit
```

The changes are applied when you leave the sub-mode (`exit`; `abort` discards them). Applying a new mapping restarts the MST instances on the switch, so change it in a maintenance window, and make the identical change on every switch in the region: until all match, the region is split.

> **Watch out:** You can map VLANs that do not exist yet, and you should. Map every planned VLAN range to an instance up front, so that creating a VLAN later never changes the digest and never splits the region.

## Instances: IST, MSTI, CIST and CST

- **Instance 0, the IST (Internal Spanning Tree)**, always exists and carries every VLAN not mapped elsewhere. It is the only instance that sends BPDUs; the information for the other instances rides in **M-records** inside those BPDUs.
- **Instances 1 and up (MSTIs)** carry the VLANs you map to them. They exist only inside a region: an MSTI never crosses a boundary. Cisco and the standard allow up to 64 MSTIs plus the IST; platform limits can be lower.
- The **CST (Common Spanning Tree)** is the single tree that connects regions, legacy 802.1D/802.1w bridges and PVST+ switches. To the CST, a whole MST region looks like **one big switch**.
- The **CIST (Common and Internal Spanning Tree)** is the IST inside each region plus the CST between them: one tree spanning the whole network. Its root is the **CIST root**; each region also has a **CIST regional root**, the switch in the region with the best path to the CIST root (it is the CIST root itself in the region that contains it).

Inside a region MST does not rely on max age to limit BPDU propagation. The IST regional root sends BPDUs with a hop count of **max hops (default 20)**, every switch decrements it, and information is discarded when it reaches zero. Hello time (2 s), forward delay (15 s) and max age (20 s) still apply at the boundary and to the CST. MST always uses the **long** path-cost method (1 Gb/s = 20,000).

## Root and priority per instance

Each instance has its own root, configured per instance number instead of per VLAN:

```text
DSW1(config)# spanning-tree mst 0-1 priority 24576
DSW1(config)# spanning-tree mst 2 priority 28672
DSW2(config)# spanning-tree mst 0-1 priority 28672
DSW2(config)# spanning-tree mst 2 priority 24576
! or: spanning-tree mst 1 root primary / root secondary
```

The extended system ID now carries the **instance number**, so DSW1 shows priority 24577 for MST1. Port cost and priority can also be set per instance (`spanning-tree mst 1 cost 10000`, `spanning-tree mst 1 port-priority 64`). Timers are global: `spanning-tree mst hello-time`, `forward-time`, `max-age` and `max-hops`.

The design above sends instance 1 (VLANs 10–19) up DSW1's side and instance 2 (VLANs 20–29) up DSW2's, just as you would with Rapid PVST+, with two instances instead of twenty.

## Interaction with other regions and PVST+

At a **boundary port** (toward another region, an 802.1D/802.1w bridge or a PVST+ switch), only the IST/CIST is visible. The port takes one role and state for **all** VLANs, decided by the CIST; in the MSTIs it shows the role `Mstr` (master) if it is the region's path toward the CIST root. The Type column marks the boundary, for example `Bound(PVST)` toward a Rapid PVST+ switch or `Bound(RSTP)` toward a single-instance RSTP bridge.

Toward a PVST+ or Rapid PVST+ switch, Cisco MST uses **PVST simulation**: it sends the CIST BPDU replicated in every VLAN and checks the PVST+ BPDUs it receives. The rules are strict because one boundary port state must suit every VLAN:

- If the **CIST root is inside the MST region**, every PVST+ BPDU received on the boundary must be **inferior** to the CIST root, for every VLAN.
- If the **CIST root is on the PVST+ side** (the VLAN 1 root there), the PVST+ root for every other VLAN must be **equal to or better** than the VLAN 1 root.

If either rule is broken, the boundary port is blocked as **PVST simulation inconsistent**: `BKN*` with `*PVST_Inc` in `show spanning-tree`, "broken (PVST Sim. Inconsistent)" in the detail view, and a `%SPANTREE-2-PVSTSIM_FAIL` message. It recovers by itself when the offending BPDUs stop.

> **Real world:** Put the root of every VLAN inside the MST region, normally on the core or distribution pair, and give the PVST+ switches the default priority. That keeps the first rule satisfied permanently during a PVST+ to MST migration.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (they run Cisco's x86 images; on an Apple silicon Mac use a remote x86 server or a CML instance in a DevNet Sandbox), with DSW1, DSW2 and ASW1 (IOSvL2 or Catalyst 9000v) in a triangle, plus an optional fourth switch SW4 left in Rapid PVST+.

1. Create VLANs 10, 11, 20 and 21 on all switches. On each, configure `spanning-tree mst configuration` with name `CAMPUS`, revision 1, instance 1 for VLANs 10–19 and instance 2 for VLANs 20–29, then `spanning-tree mode mst`.
2. Make DSW1 the root of MST0 and MST1 and DSW2 the root of MST2. On ASW1, confirm different root ports per instance with `show spanning-tree mst 1` and `show spanning-tree mst 2`.
3. Change the revision on ASW1 to 2 and observe that ASW1 is now its own region: `show spanning-tree mst` shows boundary ports and MST1/MST2 no longer follow DSW1 and DSW2. Compare `show spanning-tree mst configuration digest` on both, then fix it.
4. Connect SW4 (Rapid PVST+) to DSW2 and see the `Bound(PVST)` port. Give SW4 `spanning-tree vlan 20 priority 4096` and watch the boundary go `*PVST_Inc`; remove the priority to recover.

## Key takeaways

- MST (802.1s) maps many VLANs to a few instances, each running RSTP; it is the standards-based multi-instance option.
- A region is defined by name, revision and VLAN-to-instance map (sent as a digest); any difference creates a boundary. Map VLANs before they exist.
- Instance 0 is the IST: it carries unmapped VLANs and is the only instance that sends BPDUs (MSTI data in M-records). The CIST is the IST plus the CST between regions.
- Configure with `spanning-tree mst configuration` (`name`, `revision`, `instance N vlan ...`), applied on exit; roots with `spanning-tree mst N priority` or `root primary`.
- Max hops (default 20) limits BPDUs inside a region; MST uses long path costs.
- Boundary ports have one state for all VLANs. With PVST+ neighbours, keep the root for every VLAN inside the region or the port goes PVST simulation inconsistent.
- Verify with `show spanning-tree mst configuration`, `show spanning-tree mst [N]` and the Type column (`Bound(...)`, `*PVST_Inc`).
