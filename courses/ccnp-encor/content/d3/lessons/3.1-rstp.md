## What RSTP changes

**Rapid Spanning Tree Protocol** (IEEE 802.1w, folded into 802.1D-2004) keeps the same election (root bridge, root port, designated port, same BID and cost rules) but replaces the timer-driven state machine with a **handshake**. On point-to-point links a port can move to forwarding in well under a second instead of 30 seconds. Cisco's per-VLAN implementation is **Rapid PVST+**, the default mode on current Catalyst 9000 releases:

```text
SW1(config)# spanning-tree mode rapid-pvst
```

RSTP is backward compatible: a port that receives 802.1D BPDUs falls back to 802.1D behaviour on that port, and `show spanning-tree` shows `Peer(STP)` in the Type column.

## Port states and roles

RSTP merges the three non-forwarding 802.1D states into one:

| 802.1D state | RSTP state | Learns MACs | Forwards |
|---|---|---|---|
| Disabled, blocking, listening | **Discarding** | No | No |
| Learning | **Learning** | Yes | No |
| Forwarding | **Forwarding** | Yes | Yes |

Cisco output still prints discarding as `BLK`.

The roles:

| Role | What it is | Normal state |
|---|---|---|
| **Root** | Best path to the root bridge (one per non-root switch) | Forwarding |
| **Designated** | Best port on a segment toward the leaves | Forwarding |
| **Alternate** | Receives a better BPDU from **another switch** than it would send: a pre-computed backup **root** port | Discarding |
| **Backup** | Receives a better BPDU from **its own switch** (another port on the same shared segment, such as a hub) | Discarding |
| **Disabled** | Administratively down | n/a |

The alternate port is the key to fast convergence: if the root port fails, the switch promotes its best alternate port to root port and puts it into **forwarding immediately**, with no listening or learning. The 802.1D UplinkFast and BackboneFast features are built into RSTP.

## Link types and edge ports

RSTP only uses the fast handshake on **point-to-point** links:

| Link type | Detected from | Rapid transition |
|---|---|---|
| **Point-to-point** (`P2p`) | Full duplex | Yes, by proposal and agreement |
| **Shared** (`Shr`) | Half duplex | No: falls back to timers (2 x forward delay) |
| **Edge** (`Edge`) | PortFast configured | Forwards immediately at link-up |

Override detection with `spanning-tree link-type point-to-point` or `shared` on the interface, for example on a full-duplex link that really is shared or on a half-duplex link that is really point-to-point.

An **edge port** is a port that connects to an end host and should never receive a BPDU: configure it with `spanning-tree portfast`. It goes straight to forwarding and never causes a topology change. If an edge port receives a BPDU, it immediately loses its edge status and becomes a normal spanning-tree port.

## Proposal and agreement

When a point-to-point link comes up between DSW1 (closer to the root) and ASW1:

1. Both ports start as **designated discarding**. DSW1 sends a BPDU with the **proposal** flag set.
2. ASW1 sees that DSW1's BPDU is better than its own information, so the port that received it becomes ASW1's new **root port**.
3. ASW1 performs **sync**: it moves all its non-edge designated ports to discarding, so that opening the new root port cannot create a loop. Edge ports and ports that are already alternate or discarding are left alone.
4. ASW1 sends an **agreement** back on its root port, which goes to forwarding.
5. DSW1 receives the agreement and moves its designated port to **forwarding** immediately.
6. ASW1 now sends proposals on its own designated ports, and the handshake ripples down the tree one link at a time.

If no agreement comes back, for example because the neighbour is a 802.1D switch or the link is shared, the designated port falls back to the slow path: discarding, then learning, then forwarding, each for forward delay.

> **Exam tip:** A designated port that takes 30 s to forward on an RSTP switch is waiting for an agreement that never comes. Look for `Shr` (half duplex), `Peer(STP)` (legacy neighbour) or a port where the far end does not run spanning tree at all.

## Failure detection and topology changes

Every RSTP switch generates its own BPDUs every hello time (2 s) instead of only relaying the root's. If a port receives no BPDU for **three hello times (6 s)**, its information ages out. Physical link loss is detected at once.

Topology change handling is also different:

- Only a **non-edge** port moving **to forwarding** is a topology change. A port going down is not (its MAC entries are flushed locally), and edge ports never trigger one.
- The switch that detects the change starts a **TC While** timer (twice the hello time) on its non-edge designated ports and root port, sends BPDUs with the **TC flag** set on them, and flushes the MAC addresses learned on those ports.
- Every switch that receives a TC BPDU flushes the MACs learned on all its ports except the one the TC arrived on, and propagates the TC. There is no TCN-to-root step.

The practical lesson: an access port without PortFast generates a topology change every time a PC boots, and every switch in the VLAN flushes its MAC table. `show spanning-tree vlan N detail` shows the count and the source:

```text
ASW1# show spanning-tree vlan 20

             Address     aabb.cc00.0100
             Cost        4
             Port        1 (GigabitEthernet1/0/1)
             Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec

             Address     aabb.cc00.0300
             Hello Time   2 sec  Max Age 20 sec  Forward Delay 15 sec

------------------- ---- --- --------- -------- --------------------------------
Gi1/0/1             Root FWD 4         128.1    P2p
Gi1/0/2             Altn BLK 4         128.2    P2p
Gi1/0/14            Desg FWD 4         128.14   P2p
Gi1/0/15            Desg FWD 19        128.15   P2p Edge
```

- `protocol rstp` confirms Rapid PVST+ for this VLAN (`ieee` would mean PVST+, `mstp` MST).
- Gi1/0/2 is the **alternate**: if Gi1/0/1 fails it becomes root port and forwards at once.
- Gi1/0/14 is a host port **without** PortFast (no `Edge`), which matches the topology-change source above. Gi1/0/15 is an edge port at 100 Mb/s (cost 19).

Other useful commands: `show spanning-tree summary` (mode and global features), `show spanning-tree interface Gi1/0/2 detail`, `show spanning-tree root` (root and root port per VLAN), and `debug spanning-tree events` in a lab.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (they run Cisco's x86 images; on an Apple silicon Mac use a remote x86 server or a CML instance in a DevNet Sandbox), with DSW1, DSW2 and ASW1 (IOSvL2 or Catalyst 9000v) in a triangle and a host on ASW1.

1. Configure `spanning-tree mode rapid-pvst` on all three and make DSW1 the root for VLAN 20. Identify the alternate port on ASW1.
2. Start a continuous ping from the host to DSW1's SVI, shut ASW1's root port, and count lost pings. Repeat with `spanning-tree mode pvst` everywhere and compare.
3. Leave the host port without PortFast, bounce it a few times, and watch the topology change counter and "from" interface in `show spanning-tree vlan 20 detail`. Add `spanning-tree portfast` and repeat.
4. Force `duplex half` on one inter-switch link (where the image allows it) or `spanning-tree link-type shared`, and observe `Shr` and the slower transition.
5. Run `debug spanning-tree events` while bringing a link up to see the proposal, sync and agreement messages, then `undebug all`.

## Key takeaways

- RSTP (802.1w) keeps the 802.1D election but converges by handshake; Cisco runs it per VLAN as Rapid PVST+ (`spanning-tree mode rapid-pvst`).
- States: discarding, learning, forwarding. Roles: root, designated, alternate (backup root port), backup (same shared segment), disabled.
- Fast transitions need point-to-point links (full duplex) or edge ports (PortFast); shared links fall back to timers.
- Proposal, sync (block non-edge designated ports), agreement, forward: then the next hop down.
- BPDUs every 2 s from every switch; information expires after three missed hellos (6 s).
- Only non-edge ports moving to forwarding generate topology changes; TC BPDUs flush MAC tables. Find the source with `show spanning-tree vlan N detail`.
