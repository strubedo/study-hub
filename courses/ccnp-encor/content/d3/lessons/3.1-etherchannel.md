## Why bundle links

An **EtherChannel** (port channel, link aggregation group) combines several physical Ethernet links into one logical link. Spanning tree sees **one** port, so every member forwards instead of all but one blocking; losing a member does not cause an STP recalculation, only a re-hash of traffic onto the remaining members. The logical interface is `interface Port-channel N`; members join it with `channel-group N mode ...`.

There are three ways to form one:

| Method | Standard | Modes | Notes |
|---|---|---|---|
| **LACP** | IEEE 802.3ad, now **802.1AX** | `active`, `passive` | Use this. Works with servers, hypervisors, firewalls, other vendors |
| **PAgP** | Cisco proprietary | `desirable`, `auto` | Cisco-to-Cisco only; not supported on Nexus |
| **Static** | none | `on` | No negotiation at all: bundles unconditionally |

## Mode compatibility

| Local \ Peer | active | passive | desirable | auto | on |
|---|---|---|---|---|---|
| **active** | Yes | Yes | No | No | No |
| **passive** | Yes | **No** | No | No | No |
| **desirable** | No | No | Yes | Yes | No |
| **auto** | No | No | Yes | **No** | No |
| **on** | No | No | No | No | Yes |

The pattern is the same as DTP: one side must start negotiation. `passive` + `passive` and `auto` + `auto` both wait forever. LACP and PAgP never talk to each other, and `on` never talks to either protocol.

> **Watch out:** `on` facing a negotiating mode is worse than a failed bundle. The `on` side forwards over all its members as one channel, while the other side treats them as separate ports. Broadcasts sent out of one member come back on another, and MAC addresses flap. **EtherChannel misconfig guard** (enabled by default) detects the inconsistency from the BPDUs it receives and err-disables the port channel with reason `channel-misconfig`. Avoid `on` except where the far end cannot negotiate.

## Member consistency

Members are bundled only if they match. Check these first:

- Same **speed and duplex**.
- Same **switchport mode**: all access or all trunk; all Layer 2 or all Layer 3 (`no switchport`).
- Access ports: same **access VLAN**. Trunks: same **native VLAN** and same **allowed VLAN list** (and, where used, the same trunk encapsulation and pruning list).
- Not a SPAN destination, and no conflicting port security configuration.

Different STP port costs or port priorities on members do **not** stop bundling. A member that does not match the others is **suspended**, shown as `(s)` in `show etherchannel summary`, and IOS logs a message naming the mismatched attribute, for example `%EC-5-CANNOT_BUNDLE2: Gi1/0/3 is not compatible with Gi1/0/1 and will be suspended (native vlan of Gi1/0/3 is 1, Gi1/0/1 is 99)`.

> **Real world:** Configure the **port channel** interface, not the members, after the bundle exists: changes to `interface Port-channel N` are copied to all members, which keeps them consistent. Use `interface range` when you first add the members.

## Configuring Layer 2 and Layer 3 port channels

Layer 2 trunk with LACP:

```text
SW1(config)# interface range GigabitEthernet1/0/1 - 2
SW1(config-if-range)# switchport mode trunk
SW1(config-if-range)# channel-group 1 mode active
Creating a port-channel interface Port-channel 1
SW1(config-if-range)# exit
SW1(config)# interface Port-channel1
SW1(config-if)# switchport trunk allowed vlan 10,20,30
```

Layer 3 port channel: the members must be routed ports **before** they join, so that the automatically created port channel is also routed. The IP address goes on the port channel, never on the members.

```text
DSW1(config)# interface range TenGigabitEthernet1/1/1 - 2
DSW1(config-if-range)# no switchport
DSW1(config-if-range)# channel-group 10 mode active
DSW1(config-if-range)# exit
DSW1(config)# interface Port-channel10
DSW1(config-if)# ip address 10.0.12.1 255.255.255.252
```

Changing a member to `no switchport` after it has joined a Layer 2 channel, or mixing routed and switched members, does not convert the channel: the change is refused or the mismatched member is not bundled. Remove the members from the channel, convert them, then add them back. In `show etherchannel summary`, `S` means a Layer 2 channel and `R` a Layer 3 channel.

## LACP details

- **System ID** = LACP **system priority** (default **32768**, lower is better) + the switch MAC address. `lacp system-priority N` sets it globally; `show lacp sys-id` displays it.
- **Port ID** = LACP **port priority** (default **32768**, lower is better) + port number. `lacp port-priority N` on the member.
- An LACP channel can have **up to 16 members configured**: up to **8 active** and up to 8 **hot-standby**. The switch with the better (lower) system ID decides which ports are active, by port priority and then port number. A hot-standby port is shown as `(H)` and is activated when an active member fails.
- `lacp max-bundle N` on the port channel limits the number of active members (for example 4 active and the rest hot standby). A minimum-links setting on the port channel (`port-channel min-links N`, 2–8, on Catalyst switches; the IOS XE models also contain a router-style `lacp min-bundle`) brings the channel down if too few members are bundled; the summary shows `M` for "minimum links not met".
- Timers (802.1AX): **slow** rate, one LACPDU every **30 s** with a **90 s** timeout (3 missed), is the default; **fast** rate, every **1 s** with a **3 s** timeout. `lacp rate fast` on a member asks the **partner** to send fast LACPDUs to this port. Each side's transmit rate is set by what its partner requests, so the two directions can differ; a rate mismatch does not stop bundling.
- LACPDUs go to the Slow Protocols multicast address `0180.c200.0002`. PAgP uses the Cisco multicast `0100.0ccc.cccc`, the same address as CDP, DTP and VTP.

PAgP and `on` channels support up to **8** members. How many port channels a switch supports depends on the platform.

## Load balancing

An EtherChannel does not split one flow across members. The switch hashes selected header fields of each frame to pick a member, so all frames of a flow take the same link and stay in order.

```text
SW1(config)# port-channel load-balance src-dst-ip
SW1# show etherchannel load-balance
EtherChannel Load-Balancing Configuration:
        src-dst-ip
<output omitted>
```

The options include `src-mac`, `dst-mac`, `src-dst-mac`, `src-ip`, `dst-ip`, `src-dst-ip`, `src-port`, `dst-port`, `src-dst-port` and `src-dst-mixed-ip-port` (IP addresses and Layer 4 ports). The method is global on Catalyst switches, applies to frames leaving the switch, and each end chooses its own. Current Catalyst 9000 releases are generally documented with `src-dst-ip` as the default, but older Catalyst switches used `src-mac`, so read the method from `show etherchannel load-balance` rather than assuming it.

> **Exam tip:** "One member carries almost all the traffic" means the hash input has too little variety: a router-to-router link with one MAC pair under `src-dst-mac`, or a backup server talking to one target under `src-dst-ip`. Add Layer 4 ports (`src-dst-mixed-ip-port`) to spread more. No method can push a single flow faster than one member.

## Troubleshooting

Start with `show etherchannel summary`:

```text
SW1# show etherchannel summary
Flags:  D - down        P - bundled in port-channel
        I - stand-alone s - suspended
        H - Hot-standby (LACP only)
        R - Layer3      S - Layer2
        U - in use      f - failed to allocate aggregator

        M - not in use, minimum links not met
        u - unsuitable for bundling
        w - waiting to be aggregated
        d - default port

        A - formed by Auto LAG

Number of channel-groups in use: 3
Number of aggregators:           3

Group  Port-channel  Protocol    Ports
------+-------------+-----------+-----------------------------------------------
1      Po1(SU)         LACP      Gi1/0/1(P)      Gi1/0/2(P)
2      Po2(SD)         LACP      Gi1/0/3(I)      Gi1/0/4(I)
3      Po3(SU)         PAgP      Gi1/0/5(P)      Gi1/0/6(s)
```

Reading it:

| Port-channel flag | Meaning | Member flag | Meaning |
|---|---|---|---|
| `SU` | Layer 2, in use (up) | `P` | Bundled, forwarding |
| `RU` | Layer 3, in use | `I` | Stand-alone: no LACP or PAgP partner, forwarding as an individual port |
| `SD` / `RD` | Down: no member bundled | `s` | Suspended: configuration mismatch or the partner is not negotiating |
| `M` | Minimum links not met | `H` | LACP hot standby |
| | | `D` | Member link down |
| | | `w` | Waiting to be aggregated (briefly, while negotiating) |

- **Po2 `SD` with members `(I)`**: no LACP partner. The peer is `passive` too, runs PAgP or `on`, has no `channel-group` at all, or the cabling goes to a different switch. Stand-alone members still forward individually, so STP blocks one of them. With `port-channel standalone-disable` in effect on the port channel, LACP members without a partner are suspended `(s)` instead of stand-alone; the IOS XE 17.18 YANG models list that as the default, so check which flag your release shows.
- **Gi1/0/6 `(s)`**: compare it with Gi1/0/5 (`show running-config interface`, `show interfaces Gi1/0/6 switchport`) and read the log.
- **Po err-disabled**: `show interfaces status err-disabled` names the reason, usually `channel-misconfig`; fix both ends, then `shutdown` / `no shutdown` the port channel.

Then go deeper:

```text
SW1# show lacp neighbor
Flags:  S - Device is requesting Slow LACPDUs
        F - Device is requesting Fast LACPDUs
        A - Device is in Active mode       P - Device is in Passive mode

Channel group 1 neighbors

                  LACP port                        Admin  Oper   Port    Port
Port      Flags   Priority  Dev ID          Age    key    Key    Number  State
Gi1/0/1   SA      32768     aabb.cc00.0200  12s    0x0    0x1    0x101   0x3D
Gi1/0/2   SA      32768     aabb.cc00.0200  15s    0x0    0x1    0x102   0x3D
```

`show lacp neighbor` proves a partner exists, shows its system MAC (Dev ID: all members should show the **same** partner), its mode (`A` or `P`) and the rate it requests (`S` or `F`). `show lacp internal` shows the same for the local ports; `show lacp sys-id` shows the local system priority and MAC. For PAgP use `show pagp neighbor`. `show etherchannel port-channel` lists each channel's protocol, age and member states (`Active`, `Passive`, `Desirable-Sl`...), and `show etherchannel 1 detail` shows every member's partner information.

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (they run Cisco's x86 images; on an Apple silicon Mac use a remote x86 server or a CML instance in a DevNet Sandbox), with two IOSvL2 or Catalyst 9000v switches and four links between them. Virtual switches do not enforce every hardware check (speed mismatches in particular cannot be reproduced), so focus on modes and VLAN consistency.

1. Bundle Gi1/0/1–2 as `channel-group 1 mode active` on SW1 and `passive` on SW2. Verify with `show etherchannel summary` (`SU`, both `P`) and `show lacp neighbor`.
2. Change SW1 to `passive` as well, so both sides are passive: watch both ports become `(I)` (or `(s)` where standalone-disable is in effect) and Po1 go `SD`.
3. Bundle Gi1/0/3–4 with `desirable` on SW1 and `auto` on SW2 (PAgP); then try `on` on one side only and watch the misconfig guard err-disable the channel.
4. Configure a different native VLAN on one member and find the `(s)` flag and log message.
5. Make Po10 a Layer 3 channel with `no switchport` before `channel-group`, address it, and ping across.
6. Set `lacp max-bundle 1` on Po1 and see one member go `(H)`; shut the active member and watch the standby take over.

## Key takeaways

- LACP (802.1AX): `active`/`passive`. PAgP (Cisco): `desirable`/`auto`. Static: `on`. At least one side must actively negotiate, and the protocols never mix.
- `on` facing a negotiating or unconfigured peer can loop; misconfig guard err-disables the channel (`channel-misconfig`).
- Members must match speed, duplex, switchport mode, access VLAN or native and allowed VLANs; a mismatched member is suspended `(s)`. STP cost differences do not matter.
- Layer 3 channel: `no switchport` on the members before `channel-group`; IP address on the port channel.
- LACP defaults: system and port priority 32768 (lower wins), slow rate 30 s with 90 s timeout, fast 1 s with 3 s timeout; up to 8 active plus 8 hot-standby, `lacp max-bundle` limits active members.
- Load balancing is per flow by hash; `port-channel load-balance` is global; check the method in use with `show etherchannel load-balance`.
- Troubleshoot with `show etherchannel summary` flags (`SU`/`RU`/`SD`, `P`/`I`/`s`/`H`/`D`), then `show lacp neighbor`, `show etherchannel port-channel` and the log.
