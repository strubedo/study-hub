## Where this fits

Lesson 1.1 compared HSRP, VRRP and GLBP at the design level: what an FHRP protects against and how the three differ. This lesson is the configuration and verification view of **HSRP** on IOS XE; the next lesson does the same for VRRP.

HSRP is Cisco's protocol, documented in informational RFC 2281 (version 1). The routers in a **standby group** share a virtual IP address and a virtual MAC address; the **active** router answers ARP for the virtual IP and forwards traffic sent to the virtual MAC, the **standby** router monitors it and takes over if it disappears, and any others wait in the listen state.

## Version 1 and version 2

| | HSRPv1 (default) | HSRPv2 |
|---|---|---|
| Group numbers | 0–255 | 0–4095 (match group to VLAN number) |
| Hellos sent to | 224.0.0.2 (all routers) | 224.0.0.102 |
| Transport | UDP 1985 | UDP 1985 |
| Virtual MAC | `0000.0c07.acXX`, XX = group in hex | `0000.0c9f.fXXX`, XXX = group in hex |
| Millisecond timers advertised | No | Yes |
| IPv6 | No | Yes (required for HSRP for IPv6) |

`standby version 2` is set per interface and applies to every group on it. v1 and v2 do **not** interoperate: if one router runs v1 and the other v2 for the same group, they never hear each other and both become active.

Group 10 uses `0000.0c07.ac0a` in v1 and `0000.0c9f.f00a` in v2; group 300 (v2 only) uses `0000.0c9f.f12c`.

## States

| State | What the router is doing |
|---|---|
| **Initial** | HSRP starting, or the interface just came up. `show standby brief` shows `Init` |
| **Learn** | Has no virtual IP configured and has not yet heard one from the active router |
| **Listen** | Knows the virtual IP; is neither active nor standby; listens to hellos |
| **Speak** | Sends hellos and takes part in the election for active and standby |
| **Standby** | Next in line; sends hellos and monitors the active router |
| **Active** | Owns the virtual MAC and IP, answers ARP for the virtual IP, forwards traffic |

Only the active and standby routers send periodic hellos; listening routers stay quiet.

## Election and preemption

1. **Highest priority** wins (0–255, default **100**).
2. On equal priority, the **highest interface IP address** wins.
3. **Preemption is off by default.** Without `standby N preempt`, a router that comes up later, or recovers, with a higher priority does **not** take over from a working active router. It becomes active only when the current active router fails.

So in a pair where DSW1 should be active: give DSW1 a higher priority **and** configure preemption on DSW1, or DSW1 stays standby after a reload.

## Timers

The default hello is **3 seconds** and the hold time **10 seconds** (the active router is declared down after 10 seconds without a hello). `standby N timers 1 3` sets hello 1 s and hold 3 s; `standby N timers msec 200 msec 750` sets sub-second values. The hold time must be greater than the hello time, and RFC 2281 says it should be at least three times the hello. Faster timers or BFD (`standby bfd`) shorten failover; set the same values on all members.

## Basic configuration

```text
DSW1(config)# interface Vlan10
DSW1(config-if)# ip address 10.1.10.2 255.255.255.0
DSW1(config-if)# standby version 2
DSW1(config-if)# standby 10 ip 10.1.10.1
DSW1(config-if)# standby 10 priority 110
DSW1(config-if)# standby 10 preempt delay minimum 60
DSW1(config-if)# standby 10 authentication md5 key-string <SECRET>

DSW2(config)# interface Vlan10
DSW2(config-if)# ip address 10.1.10.3 255.255.255.0
DSW2(config-if)# standby version 2
DSW2(config-if)# standby 10 ip 10.1.10.1
DSW2(config-if)# standby 10 preempt
DSW2(config-if)# standby 10 authentication md5 key-string <SECRET>
```

- `standby 10 ip 10.1.10.1` sets the virtual IP. It must be in the interface subnet and not equal to any interface address. On the other routers the virtual IP can be omitted (they learn it), but configuring it everywhere is clearer.
- `preempt delay minimum 60` waits 60 seconds after DSW1 is able to preempt before it takes over, so routing protocols and uplinks have converged when DSW1 becomes active again after a reload. `reload` and `sync` delay options also exist.
- Authentication: `standby N authentication text STRING` sends a clear-text string (when none is configured, RFC 2281's default text is `cisco`); `standby N authentication md5 key-string KEY` or `... md5 key-chain NAME` uses an MD5 digest. A mismatch makes the routers ignore each other's hellos, so both become active.
- Multiple groups on one interface (for example group 10 active on DSW1 and group 11 active on DSW2, each with half the hosts using its virtual IP) give load sharing; one group never load-shares by itself.

## Object tracking

Priority should follow the health of the uplink, not just the router. Define a track object and link it to the group:

```text
DSW1(config)# track 1 interface GigabitEthernet1/0/48 line-protocol
DSW1(config)# track 2 ip route 0.0.0.0 0.0.0.0 reachability
DSW1(config)# interface Vlan10
DSW1(config-if)# standby 10 track 1 decrement 20
DSW1(config-if)# standby 10 track 2 decrement 20
```

When a tracked object goes down, its decrement is subtracted from the configured priority; when it comes back, the priority is restored. Two objects down subtract both decrements. With DSW1 at 110 and DSW2 at 100, one failure brings DSW1 to 90 and DSW2 can take over, **but only if DSW2 has `preempt` configured**; DSW1 then needs `preempt` to take the role back once its uplink returns. If no decrement is given, Cisco uses 10, which cannot drop a router from 110 below 100: always state the decrement. IP SLA objects (`track 3 ip sla 10 reachability`) track reachability beyond the first hop.

## HSRP for IPv6

HSRP for IPv6 needs version 2. `standby 20 ipv6 autoconfig` builds a link-local virtual address from the virtual MAC; hosts learn the gateway from Router Advertisements sent by the active router, using the virtual link-local address as the source. Prefixes can be added with `standby 20 ipv6 2001:DB8:20::1/64`. The IPv6 groups use a different virtual MAC range and multicast address (FF02::66) from IPv4.

## Verification

```text
DSW1# show standby brief
                     P indicates configured to preempt.
                     |
Interface   Grp  Pri P State   Active          Standby         Virtual IP
Vl10        10   110 P Active  local           10.1.10.3       10.1.10.1
Vl11        11   100 P Standby 10.1.11.3       local           10.1.11.1
```

`P` shows preemption; `local` means this router. Here DSW1 is active for group 10 and standby for group 11.

```text
DSW1# show standby Vlan10
Vlan10 - Group 10 (version 2)
  State is Active
    5 state changes, last state change 02:14:37
    Track object 1 state Up decrement 20
    Track object 2 state Up decrement 20
  Virtual IP address is 10.1.10.1
  Active virtual MAC address is 0000.0c9f.f00a (MAC In Use)
    Local virtual MAC address is 0000.0c9f.f00a (v2 default)
  Hello time 3 sec, hold time 10 sec
    Next hello sent in 1.264 secs
  Authentication MD5, key-string
  Preemption enabled, delay min 60 secs
  Active router is local
  Standby router is 10.1.10.3, priority 100 (expires in 9.808 sec)
  Priority 110 (configured 110)
  Group name is "hsrp-Vl10-10" (default)
```

| Line | Use |
|---|---|
| `Group 10 (version 2)` | Version; with no `(version 2)` the group runs v1 |
| `Track object ... state ... decrement` | Which tracked objects are down and what they cost |
| `Active virtual MAC address` | v1 or v2 format confirms the version and the group |
| `Priority 90 (configured 110)` | The current priority after tracking decrements, against the configured value |
| `Preemption enabled` / `disabled` | Whether this router will take over |
| `Standby router is unknown` | No other router heard: authentication, version, group number or VLAN problem |

`debug standby events` (or `debug standby terse`) shows state changes and the reason for each.

## Troubleshooting checklist

| Symptom | Likely cause |
|---|---|
| Both routers show Active | They cannot hear each other: version mismatch, authentication mismatch, different group numbers, VLAN not carried on the trunk between them, or an ACL blocking UDP 1985 |
| Higher-priority router stays Standby | `preempt` missing on that router |
| Uplink fails but the router stays Active | No tracking, decrement too small, or the peer has no `preempt` |
| Traffic flaps after a reload | No preempt delay: the router preempts before its routing has converged |
| Duplicate address warnings | Virtual IP equal to an interface address |

## Lab it yourself

Platform: Cisco Modeling Labs, GNS3 or EVE-NG on a Windows, Linux or Intel Mac host (on an Apple silicon Mac, a remote x86 server or a Cisco DevNet sandbox with CML). Use two IOSvL2 or Catalyst 9000v switches as DSW1 and DSW2 with SVIs for VLAN 10 and 11, an uplink router R1 above them, and a host in each VLAN.

1. Configure group 10 active on DSW1 and group 11 active on DSW2 (version 2, preempt on both, priorities 110 and 100). Check `show standby brief` and the host's ARP entry for the gateway: the MAC is the virtual MAC.
2. Ping continuously from the host and shut DSW1's SVI; count the lost pings; repeat with `standby 10 timers msec 200 msec 750`.
3. Add `track 1 interface ... line-protocol` for DSW1's uplink with decrement 20, shut the uplink and watch `Priority 90 (configured 110)` and the failover.
4. Remove `preempt` from DSW1, restore everything, and observe that DSW1 stays standby.
5. Set `standby version 1` on DSW2 only (DSW1 keeps version 2) and watch both switches go active for both groups; restore version 2, then set authentication on one switch only and compare.

## Key takeaways

- HSRPv1: groups 0–255, 224.0.0.2, MAC `0000.0c07.acXX`. HSRPv2: groups 0–4095, 224.0.0.102, MAC `0000.0c9f.fXXX`. Both UDP 1985; v1 and v2 do not interoperate.
- States: Initial, Learn, Listen, Speak, Standby, Active; only active and standby send periodic hellos.
- Highest priority (default 100) then highest IP wins; **no preemption by default**; hello 3 s, hold 10 s.
- `standby N ip`, `priority`, `preempt [delay minimum S]`, `track OBJ decrement D`, `authentication md5 key-string`, `timers`, `standby version 2`.
- Tracking subtracts the decrement from the configured priority; the peer needs `preempt` for the failover to happen.
- `show standby brief` for the summary, `show standby` for priority, tracking, timers, virtual MAC and version.
