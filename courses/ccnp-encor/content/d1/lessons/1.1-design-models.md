## Why design models matter on ENCOR

Topic 1.1.a asks you to *explain* high-level enterprise designs: two-tier, three-tier, fabric and cloud. Expect questions that describe a site (number of access switches, buildings, growth plans, where routing happens) and ask which model fits, or which layer does a given job. You are not asked to size a campus, but you are expected to know what each layer is for and what breaks when a layer is skipped.

Every Cisco campus design leans on the same four principles:

| Principle | What it means in practice |
|---|---|
| **Hierarchy** | Each layer has one job (connect endpoints, aggregate and apply policy, switch fast). Problems and changes stay inside one layer |
| **Modularity** | The network is built from repeatable blocks (an access-distribution block per building, a WAN edge block, a data center block). Adding a building means adding a block, not redesigning the core |
| **Resiliency** | Redundant devices and links, fast convergence, no single point of failure in the paths that matter (lesson 1.1 high availability) |
| **Flexibility** | Room to add services, bandwidth and new technologies (fabric overlays, cloud) without a forklift change |

## The three layers

| Layer | Role | Typical features |
|---|---|---|
| **Access** | Where endpoints connect: PCs, phones, APs, printers, IoT | PoE, port security, 802.1X/MAB, QoS trust and marking at the edge, voice VLAN, BPDU guard, DHCP snooping, dynamic ARP inspection |
| **Distribution** | Aggregates access switches for one building or block; boundary between Layer 2 and Layer 3 in a traditional design | FHRP default gateways, inter-VLAN routing, route summarization toward the core, policy (ACLs, QoS), STP root placement |
| **Core** | High-speed backbone that interconnects distribution blocks, the data center, WAN and internet edge | Fast Layer 3 switching, redundancy, minimal policy, no endpoints and no per-user features |

> **Exam tip:** The core should do as little as possible apart from forwarding fast. If an answer puts ACLs, user authentication or endpoint ports in the core, it is the distractor.

## Three-tier design

Access, distribution and core are separate devices. Use it when the campus has several buildings or many distribution blocks: without a core, every distribution pair would need links to every other distribution pair, and the link count grows quadratically (a full mesh of *n* blocks needs *n(n-1)/2* connections). A core turns that mesh into a hub: each block connects only to the core.

Benefits: scales to many blocks, isolates failures to one block, lets the core be upgraded independently. Cost: more devices, more links, more to manage.

## Two-tier (collapsed core) design

The core and distribution functions run on the same pair of switches. This suits a single building or a small campus where there are only one or two distribution blocks, so a separate core would add cost without adding paths. The collapsed core pair still provides FHRP gateways, routing to the WAN and data center, and policy.

When the site grows (a second building, a new data center room), the usual step is to add a dedicated core and turn the collapsed pair into an ordinary distribution block.

## Layer 2 access vs routed access

In the traditional design the access-to-distribution links are **Layer 2 trunks**: VLANs span from access to distribution, the distribution pair runs an FHRP, and STP blocks one of the redundant uplinks unless each VLAN is confined to one access switch. In a **routed access** design the access switch is the default gateway and the uplinks are routed point-to-point links:

| | Layer 2 access | Routed access |
|---|---|---|
| Default gateway | Distribution (FHRP) | Access switch SVI |
| Uplink redundancy | STP blocks one uplink, or FHRP plus careful STP tuning | Equal-cost multipath (ECMP) through the IGP; no STP blocking on uplinks |
| Convergence | STP and FHRP timers | IGP convergence |
| VLAN spanning | A VLAN can span several access switches | A VLAN stays on one access switch |
| Fits | Legacy apps that need a VLAN across closets | Modern campus, and the underlay for an SD-Access fabric |

> **Real world:** Routed access is also what Catalyst Center builds when it automates an SD-Access underlay, so learning it once pays off twice.

## Fabric designs

A **fabric** separates the physical network (the **underlay**) from logical networks built over it (the **overlay**). The underlay is a simple routed network whose only job is to carry packets between device loopbacks. The overlay uses tunnels (VXLAN in both SD-Access and data-center EVPN fabrics) to give endpoints Layer 2 or Layer 3 connectivity wherever they plug in.

| Fabric | Where | Control plane | Data plane |
|---|---|---|---|
| **Spine-leaf** (Clos) | Data center | BGP EVPN (or a controller such as ACI) | VXLAN |
| **SD-Access** | Campus | LISP | VXLAN with a group tag (lesson 1.3) |
| **Catalyst SD-WAN** | WAN | OMP | IPsec (or GRE) tunnels (lesson 1.2) |

Spine-leaf rules are worth knowing: every leaf connects to every spine, leaves never connect to each other, and spines never connect to each other. Any leaf is therefore exactly two hops (leaf-spine-leaf) from any other leaf, which gives predictable latency and lets you scale bandwidth by adding spines and ports by adding leaves. That suits the east-west traffic of virtualized servers, where the classic three-tier model was built for north-south (client to server) traffic.

## Cloud in the enterprise design

Cloud is now one more block in the design, not a separate world:

| Model | Who manages what | Example use |
|---|---|---|
| **IaaS** | Provider runs hardware and hypervisor; you run OS, apps and virtual network | Virtual routers (Catalyst 8000V) and servers in a public cloud VPC/VNet |
| **PaaS** | Provider also runs the OS and runtime | Managed databases, serverless functions |
| **SaaS** | Provider runs the whole application | Microsoft 365, Webex, Salesforce |

Deployment models are **public**, **private** (on premises, cloud-style automation), **hybrid** (on premises and public cloud joined, workloads move between them) and **multicloud** (more than one public provider).

Design questions for the cloud block are about **connectivity** and **where traffic exits**:

- Site-to-site IPsec VPN over the internet: cheap and quick, best-effort performance.
- A private dedicated circuit to the provider (each provider has its own name for it): predictable latency and bandwidth, higher cost.
- SD-WAN extended into the cloud (virtual WAN Edges in the cloud, or direct internet access at branches for SaaS) so that branch users do not backhaul SaaS traffic through headquarters.

> **Watch out:** "Cloud" on ENCOR is architecture, not a provider exam. Know the service and deployment models and the connectivity trade-offs, not vendor product names.

## Choosing a model

| Situation | Best fit |
|---|---|
| One building, a few access closets | Two-tier collapsed core |
| Many buildings, several distribution blocks, a data center and a WAN edge | Three-tier with a dedicated core |
| Data center with heavy server-to-server traffic | Spine-leaf fabric |
| Campus that needs segmentation and mobility without stretching VLANs | SD-Access fabric over a routed underlay |
| Branches consuming SaaS and IaaS | Cloud block plus SD-WAN with local internet breakout |

## Lab it yourself

Build a two-tier campus in Cisco Modeling Labs (CML Free), GNS3 or EVE-NG (they run Cisco's x86 images on Windows, Linux or an Intel Mac; on an Apple silicon Mac run them on a remote x86 server, or use a Cisco DevNet sandbox) using IOSvL2 or Catalyst 8000V/9000v images: two distribution switches `DSW1` and `DSW2` connected to each other, and two access switches `ASW1` and `ASW2` dual-homed to both.

1. Layer 2 access: create VLAN 10 on all four switches, trunk the uplinks, give `DSW1` the SVI `10.1.10.2/24` and `DSW2` `10.1.10.3/24`, and run HSRP group 10 with virtual IP `10.1.10.1`. Check `show spanning-tree vlan 10` on `ASW1` and note the blocked uplink.
2. Convert to routed access: make the uplinks routed (`no switchport`, a /31 or /30 from `10.255.0.0/24`), move the VLAN 10 gateway to `ASW1`, and run OSPF on all links. Check `show ip route ospf` on `ASW2` and look for two equal-cost paths.
3. Compare `show spanning-tree summary` before and after, and time convergence while you shut one uplink (`show ip route` and a continuous ping between the two access-layer SVIs).

## Key takeaways

- Hierarchy, modularity, resiliency and flexibility drive every campus design.
- Access connects and secures endpoints, distribution aggregates and applies policy, core only switches fast.
- Two-tier collapses core and distribution for small sites; three-tier adds a core when the number of blocks makes a distribution mesh impractical.
- Routed access replaces STP-blocked uplinks with ECMP and IGP convergence, and is the natural underlay for SD-Access.
- Fabrics separate a simple routed underlay from VXLAN (or IPsec in SD-WAN) overlays; spine-leaf keeps every leaf two hops from every other.
- Cloud adds IaaS, PaaS and SaaS blocks; the design decisions are connectivity (VPN, private circuit, SD-WAN) and where traffic exits.
