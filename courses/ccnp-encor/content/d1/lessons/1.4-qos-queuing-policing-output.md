## From marking to action

Marking (previous lesson) only labels packets. Something has to act on the labels where congestion happens. On IOS XE that is a policy-map with **queuing** (CBWFQ and LLQ), **congestion avoidance** (WRED), and **rate control** (policing and shaping). This lesson reads each one in configuration and in `show policy-map interface`.

## Queuing happens only on output, and only under congestion

An output queuing policy only reorders packets when the egress interface is congested, that is, when packets arrive faster than the interface (or a shaper) can send them and its transmit queue fills. Until then, packets leave in arrival order and your carefully written bandwidth guarantees do nothing. Two consequences:

- Queuing actions (`priority`, `bandwidth`, `fair-queue`, `random-detect`, `queue-limit`) are valid only in an **output** policy.
- If the physical port is faster than the real bottleneck (a 1 Gbps handoff to a 50 Mbps WAN service), the port never congests; the provider drops your traffic instead. The fix is **hierarchical QoS**: a parent policy shapes to the contracted rate, which creates congestion where you control it, and a child policy queues inside the shaper.

## CBWFQ: bandwidth guarantees per class

Class-Based Weighted Fair Queuing gives each class its own queue and a **minimum** share during congestion. Unused bandwidth is shared among the classes that need it.

| Command | Meaning |
|---|---|
| `bandwidth 10000` | Guarantee 10,000 kbps |
| `bandwidth percent 20` | Guarantee 20% of the interface (or parent shaper) rate |
| `bandwidth remaining percent 30` | 30% of what is left after the priority classes are served |
| `bandwidth remaining ratio 3` | A relative weight of the remaining bandwidth |
| `fair-queue` | Flow-based fair queuing inside the class (usually `class-default`) |
| `queue-limit 128 packets` | Maximum depth of the class queue before tail drop |

> **Watch out:** Use one style of `bandwidth` within a policy-map. IOS XE rejects some combinations, such as `bandwidth` in one class and `bandwidth remaining` in a sibling class.

## LLQ: a strict priority queue for real-time traffic

Low Latency Queuing adds a **strict priority** queue to CBWFQ: packets in a `priority` class are always sent before any other queue is served, which gives voice the low delay and jitter that EF (RFC 3246) asks for.

- `priority percent 10` or `priority 5000` (kbps) gives a priority queue **with a built-in conditional policer**: during congestion, traffic above that rate is dropped (counted as `b/w exceed drops`), so the priority class cannot starve the others. Without congestion it may use more.
- `priority level 1` and `priority level 2` create two priority queues (level 1 is served first). A priority level without a rate has no built-in limit, so pair it with an explicit `police` command.
- Keep the priority class small: a common design guideline is no more than about a third of the link for all priority traffic combined.

## Congestion avoidance: WRED

When a queue fills, **tail drop** discards every arriving packet. All TCP flows back off together and ramp up together (**TCP global synchronization**), so the link oscillates between congested and underused. **WRED** (weighted random early detection) drops a few packets **before** the queue is full:

| Average queue depth | Action |
|---|---|
| Below the minimum threshold | No drops |
| Between minimum and maximum | Random drops; the probability rises linearly to 1/*mark probability denominator* at the maximum threshold (1/10 = 10% in the example below) |
| Above the maximum threshold | Every new packet is dropped (tail drop) |

`random-detect dscp-based` gives each DSCP its own thresholds, so AF13 starts dropping before AF12 and AF11, which is exactly how the AF drop precedence is realized. With `random-detect ecn`, packets from ECN-capable senders (RFC 3168) are marked instead of dropped while the queue is between the thresholds. Do not apply WRED to voice: UDP does not back off, so dropping it early only hurts quality.

## Policing vs shaping

Both enforce a rate using a **token bucket**: the committed information rate (**CIR**), the committed burst (**Bc**) and the interval **Tc = Bc / CIR**.

| | Policing | Shaping |
|---|---|---|
| Excess traffic | Dropped or re-marked immediately | Buffered and sent later |
| Delay and jitter | None added | Adds delay (queuing) |
| TCP behavior | Drops cause retransmits and a sawtooth throughput | Smooth, TCP adapts to the delay |
| Direction | Input or output | Output only |
| Typical place | Provider ingress, limiting a class (scavenger, priority), re-marking out-of-contract traffic | Enterprise WAN egress to match a sub-rate service, the parent in hierarchical QoS |
| Burst units in IOS XE | Bc in **bytes** | Bc in **bits** |

Policer variants:

| Type | Rates and buckets | Results |
|---|---|---|
| Single-rate two-color | CIR, Bc | conform, exceed |
| Single-rate three-color (RFC 2697) | CIR, Bc, Be | conform, exceed, violate |
| Two-rate three-color (RFC 2698) | CIR and PIR, each with its own bucket | conform, exceed, violate |

Each result maps to an action: `transmit`, `drop`, `set-dscp-transmit <value>` (re-mark and send), and others. A typical re-marking policer for AF41 video:

```text
policy-map VIDEO-IN
 class VIDEO
  police cir 10000000 pir 20000000
   conform-action transmit
   exceed-action set-dscp-transmit af42
   violate-action drop
```

## A complete hierarchical policy

```text
class-map match-any VOICE
 match dscp ef
class-map match-any VIDEO
 match dscp af41
class-map match-any BULK
 match dscp af11
!
policy-map WAN-CHILD
 class VOICE
  priority percent 10
 class VIDEO
  bandwidth remaining percent 40
 class BULK
  bandwidth remaining percent 20
  random-detect dscp-based
 class class-default
  bandwidth remaining percent 40
  fair-queue
!
policy-map WAN-PARENT
 class class-default
  shape average 50000000
  service-policy WAN-CHILD
!
interface GigabitEthernet0/0/1
 description 1 Gbps handoff, 50 Mbps WAN service
 service-policy output WAN-PARENT
```

Reading it: everything leaving `GigabitEthernet0/0/1` is shaped to 50 Mbps. Inside that, voice is served first and limited to 10% of 50 Mbps (5 Mbps) during congestion. The remaining bandwidth (at least 45 Mbps) is split 40/20/40 between video, bulk and everything else. Bulk data gets DSCP-based WRED, and unclassified traffic is fair-queued by flow.

How to read it:

| Line | Tells you |
|---|---|
| `Service-policy output: WAN-PARENT`, then `Service-policy : WAN-CHILD` | Which policy, which direction, and the hierarchy (the child is indented under the parent class) |
| `Class-map: VOICE (match-any)` and `Match:` | The class, its match type and criteria |
| `packets, bytes` | Packets that matched the class (classification counters) |
| `offered rate` / `drop rate` | Recent arrival rate into the class and the rate being dropped (the averaging interval is shown, 30 seconds or 5 minutes depending on `load-interval` and platform) |
| `(queue depth/total drops/no-buffer drops)` | Current queue depth and cumulative drops for the class queue |
| `(pkts output/bytes output)` | What was actually transmitted |
| `shape (average) cir 50000000, bc 200000` | The shaper: 50 Mbps with Bc 200,000 bits, so Tc = 200,000 / 50,000,000 = 4 ms |
| `Priority: 10% (5000 kbps) ... b/w exceed drops` | LLQ rate and how many priority packets the conditional policer dropped |
| `bandwidth remaining 20%` | The CBWFQ share |
| WRED table | Per-DSCP transmitted, random drops (WRED working), tail drops (queue full), thresholds and mark probability |

In this capture, BULK is offered about 46 Mbps into a 50 Mbps shaper while voice is busy: it suffers both random drops (WRED) and tail drops (average queue depth, 58 packets, above the maximum threshold of 32), and its `drop rate` equals the parent's, so BULK is where all the loss is. Voice shows no exceed drops, so the priority queue is sized correctly.

> **Exam tip:** Counters in a class prove classification; drops in a class prove congestion in that class. A class with zero packets usually means the `match` is wrong (a typo in the DSCP, `match-all` with exclusive criteria, or markings that were reset upstream), not that QoS is "not working".

> **Real world:** Catalyst 9000 switches print a shorter format (packet counts only, `(total drops)` and `(bytes output)` per class, and a different WRED table), because queuing is done in hardware with fixed queue structures. The reading logic is the same.

## Lab it yourself

In CML, GNS3 or EVE-NG (Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a Cisco DevNet sandbox) connect `R1` and `R2` (Catalyst 8000V) on `10.1.12.0/24`:

1. On `R1` configure the class-maps, `WAN-CHILD` and `WAN-PARENT` above, but shape to `2000000` (2 Mbps) so a virtual router can congest it, and apply `WAN-PARENT` outbound on `GigabitEthernet1` (the interface toward `R2`).
2. From a host or `R1` itself generate traffic toward `R2` with mixed markings: `ping 10.1.12.2 tos 184 size 200 repeat 100000 timeout 0` for EF in one session and `ping 10.1.12.2 tos 40 size 1400 repeat 100000 timeout 0` (ToS 40 = DSCP 10, AF11) in another.
3. Run `show policy-map interface GigabitEthernet1 output` repeatedly. Confirm the shaper is active, voice has no exceed drops, and BULK shows WRED random drops.
4. Build a flat policy `POLICE-2M` (only `class class-default` with `police cir 2000000`, no child), apply it outbound in place of `WAN-PARENT` (`no service-policy output WAN-PARENT` first), and compare the drop pattern and the counters. Do not simply swap the shaper for a policer inside `WAN-PARENT`: a queuing child policy needs a queuing action (normally `shape`) in its parent, and a parent that only polices is rejected.

## Key takeaways

- Queuing is output-only and acts only during congestion; hierarchical QoS (parent shaper, child queuing) creates congestion at the contracted rate.
- CBWFQ guarantees a minimum per class with `bandwidth`, `bandwidth percent` or `bandwidth remaining`; `fair-queue` shares a class fairly between flows.
- LLQ `priority` is strict priority with a conditional policer when a rate is given; `priority level 1|2` without a rate needs an explicit `police`.
- WRED drops randomly between the minimum and maximum thresholds to avoid TCP global synchronization; DSCP-based WRED implements AF drop precedence; never on voice.
- Policing drops or re-marks (input or output, Bc in bytes); shaping buffers (output only, Bc in bits); Tc = Bc / CIR.
- In `show policy-map interface`, match counters prove classification, drops prove congestion, and `b/w exceed drops` shows an undersized priority class.
