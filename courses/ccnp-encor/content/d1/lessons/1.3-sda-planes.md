## What SD-Access is

Cisco SD-Access is a campus **fabric**: a routed underlay of Catalyst switches, a VXLAN overlay that carries user traffic, LISP to track where every endpoint is, and Cisco TrustSec group tags to enforce policy. **Catalyst Center** (formerly Cisco DNA Center) automates and assures it, and **Cisco ISE** provides identity and group policy.

The result: endpoints keep their IP address and policy wherever they connect, segmentation is built in at two levels, and no VLAN has to be stretched across the campus.

## The planes

| Plane | Technology | Job |
|---|---|---|
| **Control plane** | LISP (RFC 9300 data plane, RFC 9301 control plane) | Maps each endpoint identity (EID: IP or MAC) to the routing locator (RLOC: the loopback of the edge node it sits behind) |
| **Data plane** | VXLAN (RFC 7348) with the Group Policy extension | Encapsulates the endpoint's frame or packet between RLOCs, carrying the virtual network ID and the source group tag |
| **Policy plane** | Cisco TrustSec: SGTs and SGACLs | Classifies endpoints into scalable groups and enforces group-to-group rules |
| **Management plane** | Catalyst Center (with ISE) | Design, provision, policy and assurance workflows; pushes the configuration to every fabric device |

> **Exam tip:** SD-Access uses LISP for the control plane but **VXLAN** for the data plane, not LISP encapsulation. That split is a favorite question.

## Underlay and overlay

- **Underlay**: the physical, routed network that connects the fabric devices' loopbacks. It is a routed-access design (no STP between fabric devices) running an IGP. Catalyst Center **LAN automation** builds it with **IS-IS**; a manually built underlay can use another IGP, though IS-IS is the usual choice. VXLAN over IPv4 adds 50 bytes: the outer IPv4 (20), UDP (8) and VXLAN (8) headers plus the inner Ethernet header (14), which now travels as payload. A 1500-byte host packet therefore becomes a 1550-byte underlay IP packet (before the outer Ethernet header), so the underlay MTU must be raised; jumbo frames are the norm.
- **Overlay**: the logical networks built on top. Each **virtual network (VN)** is a VRF, giving **macro-segmentation** (no traffic between VNs without going outside the fabric through a fusion device or firewall). Inside a VN, **scalable group tags (SGTs)** give **micro-segmentation** between groups that share the same subnet or VN.

## LISP in the fabric

LISP separates **who** an endpoint is (EID) from **where** it is (RLOC):

1. An endpoint connects to an edge node and is authenticated (802.1X, MAB or web authentication with ISE), which places it in a VLAN/VN and assigns an SGT.
2. The edge node registers the endpoint's EID with the **control plane node** using a LISP **Map-Register** (UDP 4342).
3. When another edge node needs to reach that EID, it queries the control plane node with a **Map-Request** and receives a **Map-Reply** with the RLOC (the first edge's loopback). The result is cached in the edge's map-cache.
4. If the endpoint roams to another edge, the new edge registers it, the control plane node updates the mapping and notifies the old edge, and traffic follows the endpoint without the endpoint changing its IP address.

The control plane node is therefore a LISP **Map-Server/Map-Resolver** (MS/MR) and acts as the fabric's **host tracking database**. Edge nodes are LISP **xTRs** (ingress and egress tunnel routers).

## VXLAN with the Group Policy ID

Standard VXLAN (RFC 7348) carries a 24-bit **VXLAN Network Identifier** (VNI) in a header after an outer UDP header (destination port 4789). SD-Access uses the **VXLAN Group Policy Option** (VXLAN-GPO, described in the IETF draft draft-smith-vxlan-group-policy), which reuses reserved bits of the header to carry a 16-bit **Group Policy ID**: the source endpoint's SGT.

| Field | Carries |
|---|---|
| VNI (24 bits) | The VN (Layer 3 VNI for routed traffic) or the Layer 2 segment (Layer 2 VNI for bridged traffic) |
| Group Policy ID (16 bits) | The source SGT, so the egress edge can enforce policy without a lookup of the source |
| Outer IP header | Source and destination RLOCs (edge or border loopbacks) |

Because the SGT rides in every packet, the **egress** edge node knows both the source group (from the header) and the destination group (from its own local endpoint table) and applies the SGACL there.

## Fabric roles

| Role | What it does |
|---|---|
| **Control plane node** | LISP Map-Server/Map-Resolver: the database of EID-to-RLOC mappings. Usually deployed in pairs; often co-located on border nodes in smaller sites |
| **Border node** | Connects the fabric to everything outside it: data center, WAN, internet, shared services, traditional campus. Translates between fabric and non-fabric routing and VRF/SGT information. An **internal** border imports known networks (shared services, data center), an **external** border is the default exit (gateway of last resort) for unknown destinations; a border can do both (sometimes called an anywhere border). A **Layer 2 border** extends a fabric subnet onto a traditional VLAN (lesson 1.3, traditional campus interoperation) |
| **Edge node** | The access switch where endpoints connect. Authenticates endpoints, registers them with the control plane node, provides the **anycast gateway** (the same gateway IP and MAC for a subnet on every edge), and encapsulates and decapsulates VXLAN (it is the VTEP). Enforces SGACLs on egress |
| **Intermediate node** | An underlay-only router or switch between edges and borders. Forwards IP packets between RLOCs; knows nothing about LISP, VNs or endpoints. Must simply support the larger MTU |
| **Extended node** | A non-fabric switch (often industrial or compact) connected to an edge node to extend connectivity to places such as factory floors; its ports are put into VNs by the edge |
| **Fabric WLC and fabric APs** | Wireless can join the fabric: the WLC registers wireless clients with the control plane node and APs send client traffic as VXLAN to the edge. Wireless detail is outside ENCOR v1.2 |

Catalyst Center's own API uses the role names `CONTROL_PLANE_NODE`, `EDGE_NODE` and `BORDER_NODE` when it adds a device to a fabric site; intermediate nodes are not fabric roles at all.

> **Watch out:** The intermediate node is part of the underlay only. If a question says a device "has no knowledge of endpoints or VNs and only routes between loopbacks", it is an intermediate node, not a border or control plane node.

## A packet across the fabric

Host A (`10.10.10.21`, group Employees, SGT 4) on edge `ASW1` (RLOC `192.168.255.11`) sends to host B (`10.10.20.33`, group Printers, SGT 9) on edge `ASW2` (RLOC `192.168.255.12`), both in VN CAMPUS:

1. Host A sends to its anycast gateway on `ASW1`.
2. `ASW1` looks up `10.10.20.33` in its LISP map-cache; on a miss it sends a Map-Request to the control plane node and caches the Map-Reply: RLOC `192.168.255.12`.
3. `ASW1` encapsulates the packet in VXLAN: VNI of VN CAMPUS, Group Policy ID 4, outer destination `192.168.255.12`.
4. Intermediate nodes route the outer packet using the underlay IGP.
5. `ASW2` decapsulates, sees source SGT 4, knows host B is SGT 9, checks the SGACL for 4 to 9, and delivers or drops.

## Lab it yourself

Full SD-Access needs Catalyst Center, ISE and Catalyst 9000 hardware; the Cisco DevNet "Catalyst Center" (SD-Access) sandbox is browser based and works on any OS. For the building blocks:

1. In CML, GNS3 or EVE-NG (Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server) build three Catalyst 8000V or Catalyst 9000v nodes in a line: `ASW1` - `DSW1` - `ASW2`. Give each a Loopback0 in `192.168.255.0/24` and run IS-IS (`router isis`, `net 49.0001.0000.0000.0011.00`, `ip router isis` on the links and loopback) as the underlay. Verify with `show isis neighbors` and `show ip route isis`: `DSW1` is now an intermediate node.
2. Read the LISP and VXLAN sections of RFC 9301 and RFC 7348 and identify the Map-Register, Map-Request and Map-Reply steps above.
3. In the sandbox, open the fabric site and note which devices are control plane, border and edge nodes, and which VNs and scalable groups exist.

## Key takeaways

- SD-Access planes: LISP control plane, VXLAN data plane, TrustSec policy plane, Catalyst Center management.
- Underlay = routed IGP network (IS-IS when LAN automation builds it) between loopbacks, with a raised MTU for the 50-byte VXLAN overhead; overlay = VNs (VRFs) and SGTs.
- Edges register endpoints (Map-Register) with the control plane node (MS/MR); other edges resolve them (Map-Request/Map-Reply) and tunnel to the RLOC.
- VXLAN-GPO carries the VNI (24 bits) and the source SGT in a 16-bit Group Policy ID; policy is enforced at the egress edge.
- Roles: control plane node, border node (internal, external, Layer 2), edge node (anycast gateway, VTEP), intermediate node (underlay only), extended node.
