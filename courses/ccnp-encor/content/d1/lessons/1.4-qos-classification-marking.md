## What "interpret QoS configurations" means

Topic 1.4 asks you to **interpret**: read an MQC configuration or `show policy-map interface` output and say what happens to traffic. This lesson covers the models, the markings and how MQC classifies and marks. The next lesson covers queuing, policing, shaping, WRED and reading the counters.

## Why QoS, and the three models

Congestion happens wherever a fast interface feeds a slower one (a 1 Gbps LAN into a 100 Mbps WAN) or many interfaces feed one. QoS decides **who waits and who is dropped** when that happens. It manages four things: **bandwidth**, **delay** (latency), **jitter** (variation in delay) and **loss**.

| Model | How | Used for |
|---|---|---|
| **Best effort** | No QoS; first in, first out | The default |
| **IntServ** | Each flow reserves resources end to end with RSVP; every hop keeps per-flow state | Rare in enterprises (does not scale); seen with MPLS TE |
| **DiffServ** | Packets are marked into a small number of classes; each hop applies a **per-hop behavior** (PHB) to the class, with no per-flow state | The enterprise standard and the ENCOR focus |

## Markings: where QoS information lives

| Layer | Field | Size | Values |
|---|---|---|---|
| Layer 2 (802.1Q tag) | **PCP**, commonly called CoS | 3 bits | 0-7; only exists on trunks and voice VLAN tagged frames |
| Layer 3 (IPv4 ToS byte, IPv6 Traffic Class) | **DSCP** (RFC 2474) | 6 bits (the upper 6 bits of the byte) | 0-63 |
| Layer 3, legacy | IP Precedence | 3 bits (the upper 3 bits of DSCP) | 0-7 |
| Layer 3 | ECN (RFC 3168) | 2 bits (the low 2 bits of the byte) | Congestion signaling, not a class |
| MPLS | Traffic Class (EXP) | 3 bits | 0-7 |

Because the DSCP is the upper six bits of the byte, the **ToS byte value is DSCP x 4** (EF 46 appears as ToS 184, `0xB8`), and the **IP Precedence equals DSCP divided by 8**, rounded down (EF 46 gives precedence 5).

## DSCP values and PHBs

| PHB | RFC | Codepoint (binary) | Decimal | Meaning |
|---|---|---|---|---|
| Default (DF, CS0) | 2474 | 000000 | 0 | Best effort |
| Class Selector CS1-CS7 | 2474 | xxx000 | 8, 16, 24, 32, 40, 48, 56 | Backward compatible with IP Precedence 1-7 |
| Assured Forwarding AFxy | 2597 | xxx yy0 | 8x + 2y | Class x (1-4) gets its own bandwidth; y (1-3) is drop precedence |
| Expedited Forwarding EF | 3246 | 101110 | 46 | Low loss, low latency, low jitter |

The AF grid (RFC 2597) is worth memorizing; within a class, **a higher drop precedence (y) is dropped first**:

| | Low drop (y=1) | Medium drop (y=2) | High drop (y=3) |
|---|---|---|---|
| AF1x | AF11 = 10 | AF12 = 12 | AF13 = 14 |
| AF2x | AF21 = 18 | AF22 = 20 | AF23 = 22 |
| AF3x | AF31 = 26 | AF32 = 28 | AF33 = 30 |
| AF4x | AF41 = 34 | AF42 = 36 | AF43 = 38 |

> **Exam tip:** AF class number does not mean "better". AF4x is not guaranteed to beat AF1x; each AF class gets whatever bandwidth the policy gives it. Only the drop precedence inside one class has a defined order.

RFC 4594 gives the recommended service class for each marking. The ones that come up most:

| Service class (RFC 4594) | DSCP |
|---|---|
| Network control (routing protocols) | CS6 |
| Telephony (voice bearer) | EF |
| Signaling (call setup) | CS5 |
| Multimedia conferencing (interactive video) | AF41, AF42, AF43 |
| Real-time interactive | CS4 |
| Multimedia streaming | AF31, AF32, AF33 |
| Broadcast video | CS3 |
| Low-latency data (transactional) | AF21, AF22, AF23 |
| OAM (network management) | CS2 |
| High-throughput data (bulk) | AF11, AF12, AF13 |
| Standard | DF (CS0) |
| Low-priority data (scavenger) | CS1 |

> **Watch out:** RFC 4594 puts call signaling at CS5, but Cisco IP phones and many Cisco QoS designs mark signaling CS3. Read the marking the question or exhibit gives you rather than assuming one or the other.

## Trust boundary

Classification and marking should happen **as close to the source as possible**, and markings from untrusted sources should be ignored or rewritten. The point where you start trusting markings is the **trust boundary**: typically the access port, trusting a Cisco IP phone (detected by CDP or LLDP) but re-marking traffic from the PC behind it. On Catalyst 9000 switches, ports trust DSCP and CoS by default (there is no `mls qos` global command as on older Catalyst switches); to distrust a port you apply an ingress policy that re-marks.

## MQC: the three building blocks

Every IOS XE QoS configuration uses the Modular QoS CLI:

1. **`class-map`**: what traffic (classification).
2. **`policy-map`**: what to do with each class (marking, queuing, policing, shaping, dropping).
3. **`service-policy`**: where and in which direction to apply it (interface, `input` or `output`).

```text
class-map match-any VOICE
 match dscp ef
class-map match-all WEB-FROM-GUESTS
 match access-group name GUEST-NET
 match protocol http
!
policy-map MARK-IN
 class VOICE
  set dscp ef
 class WEB-FROM-GUESTS
  set dscp cs1
 class class-default
  set dscp default
!
interface GigabitEthernet1/0/10
 service-policy input MARK-IN
```

Reading rules:

- **`match-any`**: a packet matches the class if **any** `match` line matches (logical OR). **`match-all`** (the default when you type only `class-map NAME`): **every** `match` line must match (logical AND). A `match-all` class with two mutually exclusive criteria (for example `match dscp ef` and `match dscp af41`) matches nothing.
- Classes in a policy-map are checked **top to bottom; the first match wins**. Traffic that matches no class goes to **`class-default`**, which always exists even if not typed.
- Common `match` criteria: `match dscp` (or `match ip dscp`), `match cos`, `match access-group name` (an ACL), `match protocol` (NBAR2 application recognition), `match precedence`, `match qos-group`.
- Common `set` actions: `set dscp`, `set cos`, `set precedence`, `set qos-group` (an internal label that never leaves the device).
- A policy-map can be applied in each direction on an interface; queuing actions are output-only (packets only queue on the way out). Marking and policing work in either direction.

> **Watch out:** In the example the guest class is `match-all`: only HTTP **from** the guest ACL is marked CS1. Guest traffic that is not HTTP falls through to `class-default` and is set to DSCP 0, not CS1.

## NBAR2

`match protocol <name>` uses Network-Based Application Recognition (NBAR2) to classify by application (deep packet inspection and signatures), not just by port. It is the way to classify traffic that uses dynamic or shared ports (for example to separate several applications that all run over HTTPS). It costs CPU or hardware resources, so classify with NBAR2 once at the edge and mark DSCP, then match the DSCP everywhere else.

## Lab it yourself

In CML, GNS3 or EVE-NG (Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a Cisco DevNet sandbox) with two Catalyst 8000V routers `R1` and `R2` on `10.1.12.0/24`:

1. On `R1` create the `MARK-IN` policy above (create the `GUEST-NET` ACL to permit `10.1.12.0 0.0.0.255`) and apply it inbound on the interface toward `R2`.
2. From `R2` run `ping 10.1.12.1 tos 184 repeat 50` (ToS 184 = DSCP 46) and an ordinary ping.
3. On `R1` run `show policy-map interface GigabitEthernet1 input` and confirm the 50 packets counted in `VOICE`, the others in `class-default`.
4. Create `class-map match-all VOICE-ALL` with `match dscp ef` and `match dscp af41`, replace `class VOICE` with `class VOICE-ALL` in `MARK-IN` (with its `set dscp ef`), and repeat: the class now matches nothing.

## Key takeaways

- DiffServ marks packets into classes and applies a per-hop behavior; IntServ (RSVP) does not scale; best effort is no QoS.
- DSCP is 6 bits: EF = 46, AFxy = 8x + 2y, CSx = 8x, default 0. ToS byte = DSCP x 4; precedence = DSCP / 8.
- Within an AF class, a higher drop precedence (AFx3) is dropped before AFx1.
- RFC 4594: EF voice, CS5 signaling, AF4x interactive video, CS6 network control, CS1 scavenger.
- MQC = class-map (what) + policy-map (action) + service-policy (where and which direction); first matching class wins, the rest falls into class-default.
- `match-any` is OR, `match-all` (default) is AND.
- Mark close to the source and set a trust boundary at the access edge.
