## Why SPAN exists

A switch forwards a unicast frame only to the port where the destination MAC lives, so a protocol analyzer plugged into a spare port sees almost nothing. **SPAN** (Switched Port Analyzer, also called port mirroring) tells the switch to copy traffic from chosen **sources** to a **destination** port where an analyzer, IDS sensor or capture appliance is connected.

| Variant | Source and destination | Transport of the copies | Lesson |
|---|---|---|---|
| Local SPAN | Same switch (or same stack) | Inside the switch | This lesson |
| RSPAN | Different switches in one Layer 2 domain | A dedicated **remote-span VLAN** across trunks | 4.3 RSPAN |
| ERSPAN | Anywhere with IP reachability | **GRE** tunnel over a routed network | 4.3 ERSPAN |

All three use the global `monitor session <number>` command family; the session number only has local meaning on each device.

## Sources, directions and filters

A **source** is what you copy:

- **Source ports**: one or more physical ports, ranges or port-channels. Each can be copied in one direction: `rx` (received by the switch on that port), `tx` (transmitted by the switch out of that port) or `both` (the default when you omit it).
- **Source VLANs** (VSPAN): every port in the VLAN is a source; `rx` copies traffic entering the VLAN's ports.

A single session takes either source ports or source VLANs, not both. When a source port is a trunk, `monitor session N filter vlan <list>` limits the copy to the listed VLANs. Some platforms also accept `monitor session N filter ip access-group <ACL>` (and `ipv6` / `mac` ACLs) to mirror only matching packets.

> **Exam tip:** `rx` is traffic **received** by the switch on the source port (from the attached device), `tx` is traffic the switch **sends** out of it. To see both sides of a conversation on one port, use `both`. Copying `both` on a server port and the uplink at the same time duplicates every frame in the capture.

## The destination port

The destination port connects the analyzer. Once it is a SPAN destination:

- It no longer behaves as a normal switch port: it does not forward received traffic and does not learn MAC addresses, unless you add the `ingress` option (used by IDS sensors that send TCP resets back into a VLAN).
- It does not participate in spanning tree while the session is active, so never make it a link to another switch.
- By default it sends the copies **untagged** (native). `encapsulation replicate` keeps the original 802.1Q tags (and Layer 2 control frames such as CDP or BPDUs, depending on platform), which you want when the analyzer needs to see VLAN IDs.
- It can belong to only one session and cannot also be a source port.

> **Watch out:** A destination port has the same bandwidth as any other port. Mirroring `both` directions of a busy 10 Gb/s uplink onto a 1 Gb/s destination drops copies silently; the production traffic is not affected, but the capture is incomplete. Mirror fewer sources, one direction, or use a faster destination.

## Configuring local SPAN

```text
SW1(config)# monitor session 1 source interface GigabitEthernet1/0/1 - 2 both
SW1(config)# monitor session 1 destination interface GigabitEthernet1/0/24 encapsulation replicate
```

Monitoring a trunk uplink for two VLANs only:

```text
SW1(config)# monitor session 2 source interface TenGigabitEthernet1/1/1 rx
SW1(config)# monitor session 2 filter vlan 10 , 20
SW1(config)# monitor session 2 destination interface GigabitEthernet1/0/23
```

Monitoring a whole VLAN:

```text
SW1(config)# monitor session 3 source vlan 30 rx
SW1(config)# monitor session 3 destination interface GigabitEthernet1/0/22
```

To change a session, add or remove individual lines (`no monitor session 1 source interface GigabitEthernet1/0/2`). To delete it, `no monitor session 1`; `no monitor session all` removes every session. The number of sessions, and how many may be source or destination at once, is platform-specific; Catalyst 9000 data sheets and configuration guides list the limits per model.

On ISR 4000 and Catalyst 8000 routers, mirroring is normally done with **ERSPAN** (lesson 4.3 ERSPAN) or captured locally with **Embedded Packet Capture** (`monitor capture`), rather than with local SPAN to a physical port.

## Verifying

```text
SW1# show monitor session 1
Session 1
---------
Type                     : Local Session
Source Ports             :
    Both                 : Gi1/0/1-2
Destination Ports        : Gi1/0/24
    Encapsulation        : Replicate
          Ingress        : Disabled
```

```text
SW1# show monitor session 2
Session 2
---------
Type                     : Local Session
Source Ports             :
    RX Only              : Te1/1/1
Filter VLANs             : 10,20
Destination Ports        : Gi1/0/23
    Encapsulation        : Native
          Ingress        : Disabled
```

`show monitor` (or `show monitor session all`) lists every session; `show monitor session 1 detail` lists every field, including empty ones. The destination port also shows in `show interfaces status` with a monitoring state on many platforms.

What to check when the analyzer sees nothing:

1. Is the session listed and complete (has both a source and a destination)?
2. Is the direction right (`rx` when you needed `tx`)?
3. Does a VLAN filter exclude the traffic?
4. Is the analyzer's NIC in promiscuous mode, and does it expect tags (`encapsulation replicate`) or not?
5. Is the traffic actually crossing the source port (check interface counters)?

## Lab it yourself

Use a Catalyst 9000v (or IOSvL2 for the basic commands) in Cisco Modeling Labs, GNS3 or EVE-NG (Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a DevNet sandbox), with two Linux hosts in VLAN 10 and a third Linux VM running Wireshark or `tcpdump` as the analyzer. Some virtual switch images do not forward SPAN copies in their data plane; if captures stay empty while `show monitor` is correct, the image is the limit, not the configuration.

1. Put the hosts on Gi1/0/1 and Gi1/0/2 and the analyzer on Gi1/0/24.
2. Configure session 1 with Gi1/0/1 `both` to Gi1/0/24. Ping between the hosts and capture on the analyzer (`tcpdump -i eth1 -n`).
3. Change the source to `rx` only and see which direction of each echo disappears.
4. Connect a second switch (or a router with subinterfaces) to Gi1/0/3 as an 802.1Q trunk carrying VLANs 10 and 20 with a host in each VLAN behind it, mirror Gi1/0/3 with `filter vlan 10`, and compare captures with and without `encapsulation replicate` (`tcpdump -e` shows the 802.1Q tag).
5. Verify each step with `show monitor session 1` and `show monitor session 1 detail`.

## Key takeaways

- SPAN copies traffic from sources to a destination port; local SPAN keeps both on one switch, RSPAN carries copies in a remote-span VLAN, ERSPAN in GRE over IP.
- `monitor session N source interface X [rx | tx | both]` (default `both`) or `source vlan V`; `filter vlan` limits trunk sources; a session takes ports or VLANs, not both.
- `monitor session N destination interface Y [encapsulation replicate] [ingress ...]`: the destination stops normal switching and STP; default copies are untagged.
- An oversubscribed destination drops copies; production traffic is unaffected.
- Verify with `show monitor session N` (Type, Source Ports with direction, Destination Ports, Encapsulation).
