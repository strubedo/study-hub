## What NetFlow measures

NetFlow answers "who talked to whom, with what, and how much?" without capturing payloads. The device groups packets into **flows**, keeps a counter set per flow in a **flow cache**, and **exports** finished flow records to a **collector** (StealthWatch / Secure Network Analytics, an open-source collector, or a SIEM).

A flow is defined by its **key fields**. Every packet whose key fields match an existing cache entry updates that entry's counters; a packet with a new combination of key values creates a new entry.

- **Traditional NetFlow** (v5) had a fixed key: source and destination address, source and destination port, protocol, ToS and input interface, exported in a fixed v5 format.
- **Flexible NetFlow** (FNF), the IOS XE implementation, lets you choose the key and non-key fields yourself and exports with templates: **NetFlow v9** (RFC 3954) or **IPFIX** (RFC 7011, the IETF standard based on v9, version number 10, IANA port 4739). The template describes the fields, so the collector can decode any record you build.

## The building blocks

| Object | Holds | Command |
|---|---|---|
| Flow record | Key fields (`match`) and non-key fields (`collect`) | `flow record NAME` |
| Flow exporter | Where and how to send: destination, source, transport, protocol | `flow exporter NAME` |
| Flow monitor | One record, zero or more exporters, cache settings | `flow monitor NAME` |
| Sampler (optional) | Samples 1 of N packets to cut CPU or hardware load | `sampler NAME` |
| Interface | Attaches the monitor in one direction | `ip flow monitor NAME input` or `output` |

The dependency order is record and exporter first, then the monitor that references them, then the interface that references the monitor.

### Key versus non-key fields

- **`match` = key field**: part of the flow identity. Add `match ipv4 tos` and two packets that differ only in DSCP become two flows.
- **`collect` = non-key field**: information recorded about the flow but not used to separate flows, such as byte and packet counters, timestamps, the output interface or TCP flags. For a non-key field such as `collect interface output`, the value recorded is from the packets of that flow (the first packet, or accumulated for flags).

> **Exam tip:** Match builds the identity, collect builds the report. A question that says "flows from the same source and destination are split into many entries" points at too many `match` fields; "the collector shows flows but no byte counts" points at a missing `collect counter bytes`.

## Configuring Flexible NetFlow (router)

```text
R1(config)# flow record REC-IPV4
R1(config-flow-record)# description IPv4 5-tuple, ToS and input interface
R1(config-flow-record)# match ipv4 source address
R1(config-flow-record)# match ipv4 destination address
R1(config-flow-record)# match ipv4 protocol
R1(config-flow-record)# match transport source-port
R1(config-flow-record)# match transport destination-port
R1(config-flow-record)# match ipv4 tos
R1(config-flow-record)# match interface input
R1(config-flow-record)# collect interface output
R1(config-flow-record)# collect counter bytes long
R1(config-flow-record)# collect counter packets long
R1(config-flow-record)# exit
R1(config)# flow exporter EXP-COLLECTOR
R1(config-flow-exporter)# description Collector in the NOC
R1(config-flow-exporter)# destination 10.10.10.70
R1(config-flow-exporter)# source Loopback0
R1(config-flow-exporter)# transport udp 2055
R1(config-flow-exporter)# export-protocol netflow-v9
R1(config-flow-exporter)# exit
R1(config)# flow monitor MON-IPV4
R1(config-flow-monitor)# record REC-IPV4
R1(config-flow-monitor)# exporter EXP-COLLECTOR
R1(config-flow-monitor)# cache timeout active 60
R1(config-flow-monitor)# cache timeout inactive 15
R1(config-flow-monitor)# exit
R1(config)# interface GigabitEthernet0/0/1
R1(config-if)# ip flow monitor MON-IPV4 input
R1(config-if)# ip flow monitor MON-IPV4 output
```

Notes on each part:

- **Record**: IOS XE also ships predefined records (for example `netflow ipv4 original-input`) you can reference instead of building one.
- **Exporter**: `destination` is mandatory. `transport udp <port>` must match the collector's listening port (the IOS XE default is UDP 9995; collectors commonly listen on 2055, 9995 or, for IPFIX, 4739). `export-protocol` is `netflow-v9` by default, or `ipfix` (and `netflow-v5` for a v5-compatible record). `source` fixes the source address the collector sees. Other options: `dscp`, `ttl` (default 255), `template data timeout` (how often the template is re-sent, default 600 seconds, which matters because a collector that restarts cannot decode records until it sees the template again), and `option` lines that export interface or application tables.
- **Monitor**: one `record`, up to several `exporter` lines (export to two collectors), and the cache.
- **Interface**: `ip flow monitor` for IPv4 traffic and `ipv6 flow monitor` for IPv6, each `input` or `output`. A monitor with no exporter still builds a local cache you can read with `show` commands.

### Cache timeouts

A flow entry leaves the cache and is exported when:

| Trigger | Command | Typical default |
|---|---|---|
| **Inactive timeout**: no packets for the flow for this many seconds | `cache timeout inactive <s>` | 15 seconds |
| **Active timeout**: the flow has existed this long even though it is still active (long flows are exported in slices) | `cache timeout active <s>` | 1800 seconds (30 minutes) |
| Cache full | `cache entries <n>` sets the size | Emergency aging of entries |
| TCP session end (FIN or RST) and other events | `cache timeout event transaction-end` (optional) | Off |

A 30-minute active timeout makes a long download appear in the collector only every half hour, which spoils near-real-time graphs; one minute (`cache timeout active 60`) is a common operational choice.

> **Watch out:** You usually cannot change a record or exporter while a monitor that uses it is applied to an interface: IOS XE rejects the change. Remove `ip flow monitor` from the interfaces, edit, and re-apply. Plan the change window accordingly.

## Switches versus routers

| | ISR 4000 / Catalyst 8000 router | Catalyst 9000 switch |
|---|---|---|
| Where flows are cached | In the packet processor (QFP) or software | In hardware, with per-ASIC cache limits |
| Commands | `flow record` / `exporter` / `monitor`, `ip flow monitor` | Same commands |
| Timestamps | `collect timestamp sys-uptime first` / `last` | `collect timestamp absolute first` / `last` |
| Interfaces | Physical, subinterfaces, tunnels | Physical ports and, depending on platform and release, SVIs; Layer 2 records with `datalink flow monitor` |
| Restrictions | Few | Some fields, directions or combinations are not supported in hardware; check the platform's configuration guide |

Both platforms print `Cache type: Normal (Platform cache)` in the cache header, so the header does not tell you which kind of device you are on. Some switch platforms also impose sampling or require specific fields; when a record is rejected on a switch, the field set is the first thing to check.

In the record format, key fields print in upper case and non-key fields in lower case, which is a quick way to read back how a record was built. `format table` prints one flow per line and `format csv` suits copying into a spreadsheet; `show flow monitor MON-IPV4 cache sort highest counter bytes long top 10` gives the top talkers.

| Command | Use it to check |
|---|---|
| `show flow record [NAME]` | Which fields are match and which are collect |
| `show flow exporter [NAME]` | Destination, source, port, protocol (v9 or IPFIX) |
| `show flow exporter statistics` | Packets sent and send errors toward the collector |
| `show flow monitor NAME` | Record, exporters, cache size and timeouts |
| `show flow monitor NAME cache [format table\|record\|csv]` | The flows themselves |
| `show flow interface [INTF]` | Which monitors are applied, in which direction |

## Diagnosing FNF problems

- **Cache empty**: the monitor is not applied (`show flow interface`), applied in the wrong direction, or the traffic is not IPv4 (an `ip flow monitor` ignores IPv6).
- **Cache full, collector empty**: wrong destination or port, a missing route or ACL toward the collector, or the collector discards records because it never received the template (wait for the template timeout or shorten it). `show flow exporter statistics` shows whether packets leave.
- **Collector shows the wrong device address**: no `source` in the exporter, so the egress interface address is used.
- **Long flows appear late**: active timeout still at the default 30 minutes.

## Lab it yourself

Build R1 between two Linux hosts in Cisco Modeling Labs, GNS3 or EVE-NG (Windows, Linux or an Intel Mac; on an Apple silicon Mac use a remote x86 server or a DevNet sandbox), plus a collector VM running an open-source NetFlow v9/IPFIX collector (for example `nfcapd` from nfdump) listening on UDP 2055.

1. Configure the record, exporter and monitor above on a Catalyst 8000V and apply the monitor input and output on the host-facing interface.
2. Generate traffic (`curl`, `ping`, `iperf3`). Read `show flow monitor MON-IPV4 cache format table` and the record format.
3. Check `show flow exporter statistics` and the collector files (`nfdump -R <dir>`).
4. The record already has `match ipv4 tos`: mark one conversation with different DSCP values from the host (for example `ping -Q 184` and `ping -Q 0` on Linux) and watch it become several flows. Then remove the monitor from the interface, enter `no match ipv4 tos` under the record, re-apply the monitor and confirm the same traffic now forms one flow.
5. Change `export-protocol` to `ipfix` and the collector port to 4739; confirm decoding continues after the new template is received.
6. On a Catalyst 9000v (if your lab has one) repeat with `collect timestamp absolute first` and note any field the platform rejects.

## Key takeaways

- Flexible NetFlow = record (`match` key fields, `collect` non-key fields) + exporter (destination, source, `transport udp <port>`, `export-protocol netflow-v9 | ipfix`) + monitor (record, exporter, cache), applied with `ip flow monitor NAME input | output`.
- A new combination of key-field values creates a new flow; non-key fields are only reported.
- Flows export on inactive timeout (default 15 s), active timeout (default 1800 s, often lowered to 60 s), cache full or end events.
- NetFlow v9 (RFC 3954) and IPFIX (RFC 7011, version 10, port 4739) use templates; the IOS XE default export protocol is v9 and the default UDP port 9995.
- Verify with `show flow record`, `show flow exporter`, `show flow monitor NAME`, `show flow monitor NAME cache`, `show flow interface`.
- Catalyst 9000 caches in hardware and uses `collect timestamp absolute`; routers use `sys-uptime`; check platform restrictions on switches.
