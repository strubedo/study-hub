## What "AI-powered" means here

The v1.2 exam topic asks you to describe how Catalyst Center uses **AI-powered workflows** alongside traditional ones. Cisco publicly describes several capabilities under that heading. They share one idea: instead of fixed rules written by an operator, they use **models**, either machine-learning models trained on network data or knowledge bases encoding expert troubleshooting, and they **explain** what they find. This lesson covers each at the level Cisco documents publicly; exact feature names, licensing tiers and availability change from release to release.

| Capability | Kind of AI | What it produces |
|---|---|---|
| AI Network Analytics (AI-driven issues and insights) | Machine learning on telemetry, with learned baselines | Issues raised when behaviour deviates from the learned normal; trends and comparative insights |
| Machine Reasoning Engine (MRE) | Knowledge-based reasoning (expert-system workflows) | Automated root-cause analysis and checks, with conclusions and suggested fixes |
| AI Assistant | Generative AI (large language model) with a natural-language interface | Answers and guided troubleshooting from questions typed in plain language |
| AI Endpoint Analytics | Machine learning on endpoint attributes and traffic | Identification and grouping of endpoints that simple profiling cannot classify |

## AI Network Analytics: learned baselines instead of static thresholds

Traditional Assurance raises an issue when a metric crosses a threshold that someone chose. That fails in two directions: a single threshold is too tight for a busy site and too loose for a quiet one, and many problems are not a value crossing a line but a value that is unusual **for that place at that time**.

AI Network Analytics sends network telemetry (Cisco describes it as anonymized) to a Cisco cloud analytics service, where machine-learning models learn a **dynamic baseline** for each key performance indicator per site and time of day. Then:

- **AI-driven issues**: when a KPI deviates significantly from its own baseline, Catalyst Center raises an issue marked as AI-driven, rather than waiting for a fixed threshold to be crossed. The Intent API exposes this distinction directly: issues carry an `aiDriven` attribute that can be used as a filter.
- **Trends and insights**: the system highlights recurring patterns and changes over weeks rather than single events, to support capacity planning and proactive fixes.
- **Comparative analytics**: compares a site, building or device group against peers or against the network as a whole, to show whether a site's behaviour is unusual.

Because the baseline adapts, the same deviation can be an issue at one site and normal at another. AI Network Analytics must be enabled (it needs cloud connectivity and the appropriate license) before AI-driven issues appear.

> **Exam tip:** Static thresholds versus learned baselines is the core distinction. If a question describes "issues raised when behaviour differs from what is normal for this site at this time, without a threshold configured", the answer is the AI or machine-learning analytics, not a traditional Assurance rule.

## Machine Reasoning Engine: codified expert troubleshooting

The **Machine Reasoning Engine (MRE)** is a reasoning engine inside Catalyst Center that runs troubleshooting workflows built from Cisco's support expertise. A workflow is a decision tree of checks: it gathers device state (often by running `show` commands on the device), evaluates the results against its knowledge base, and follows the branch that fits, until it reaches a conclusion.

Where you meet it:

- **On an issue**: a button such as "run machine reasoning" starts an automated root-cause analysis for that issue and shows each step it took, the conclusion and the suggested remediation.
- **Reasoner workflows and tools**: on-demand checks, for example finding why an interface is down, investigating high CPU, or checking a device for known problems.
- **Security advisories**: matching each device's software and configuration against published Cisco PSIRT advisories, so you see which devices are actually exposed rather than just which run an affected release.

MRE is "AI" in the classic sense of automated reasoning, not machine learning: its strength is that it is explainable step by step, and its knowledge base is updated by Cisco.

## AI Assistant: natural language

Cisco has added an **AI Assistant**, a generative-AI interface, to Catalyst Center (as part of the AI Assistant offered across Cisco's management platforms). The operator types questions in plain language, such as what is wrong at a site, why a client cannot connect, or what changed recently, and the assistant answers from the Catalyst Center data (inventory, issues, health) and can guide troubleshooting steps. It is a front end to the same data and workflows: it does not replace Assurance or the traditional tools, it makes them faster to reach. Availability depends on release, region and licensing.

> **Watch out:** Do not overstate what these tools do. As Cisco describes them, they analyse data Catalyst Center already collects and propose actions; the configuration itself is still deployed through the provisioning workflows (templates, settings, SWIM) and whatever approvals you have set up. The exam asks you to describe them, not to configure them.

## AI Endpoint Analytics

**AI Endpoint Analytics** identifies endpoints (printers, cameras, medical or industrial devices, IoT) using several sources: deep packet inspection of the traffic they send, information from switches and Cisco ISE, and machine-learning clustering that groups similar unknown endpoints so an operator can label a whole group at once. The resulting endpoint labels can feed group-based policy (scalable groups) in Cisco ISE.

## Traditional and AI-powered workflows together

| Task | Traditional workflow | AI-powered workflow |
|---|---|---|
| Detect a problem | Issue when a KPI crosses a configured threshold | AI-driven issue when a KPI deviates from its learned baseline |
| Find the cause | Engineer reads Device 360, runs `show` commands, uses path trace | Machine Reasoning Engine runs a codified diagnosis and states a conclusion |
| Ask about the network | Navigate dashboards and filters | AI Assistant answers natural-language questions |
| Classify endpoints | Static profiling rules | ML clustering and DPI in AI Endpoint Analytics |
| Change the network | Templates, settings, SWIM, provisioning | Same: AI tools suggest, provisioning applies |

## Lab it yourself

The AI features need licenses and, for AI Network Analytics, cloud connectivity, so a home lab cannot reproduce them. Use a browser on any host operating system:

1. In a Cisco DevNet Catalyst Center sandbox, open Assurance issues and check whether any are marked AI-driven, and whether the AI analytics settings page is present.
2. Open an issue and look for the machine-reasoning option and the suggested actions; note the steps it lists.
3. In the API documentation, find the issues API and the `aiDriven` filter, and the security advisories API.
4. Read Cisco's public Catalyst Center data sheet and release notes for the current names and requirements of AI Network Analytics, the Machine Reasoning Engine and the AI Assistant.

## Key takeaways

- AI-powered workflows add learned models and automated reasoning on top of the same inventory and telemetry used by traditional workflows.
- AI Network Analytics learns dynamic baselines per site and time in a Cisco cloud service and raises AI-driven issues and insights when behaviour deviates; it complements, rather than removes, the threshold-based issues.
- The Machine Reasoning Engine runs knowledge-based troubleshooting workflows (root cause on issues, on-demand reasoners, PSIRT matching) and explains each step.
- The AI Assistant is a generative-AI natural-language front end to Catalyst Center data and troubleshooting.
- AI Endpoint Analytics classifies unknown endpoints with DPI and ML clustering, feeding group-based policy.
- AI tools detect, explain and suggest; configuration changes still flow through the normal provisioning workflows.
