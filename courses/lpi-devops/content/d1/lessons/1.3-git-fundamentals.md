## Concepts and repository structure

Git is a **distributed** version control system: every clone holds the full history, so commits, branches and logs work offline. A repository has two parts: the **working tree** (the files you edit) and the `.git` directory (the database).

Three areas matter for almost every command:

| Area | What it is | Moved by |
|------|------------|----------|
| Working tree | Files on disk | your editor |
| Index (staging area) | Snapshot of what the next commit will contain | `git add`, `git rm`, `git restore --staged` |
| Repository (commit history) | Committed snapshots | `git commit` |

Git stores four object types in `.git/objects`, each named by a hash (SHA-1 by default; SHA-256 repositories are supported):

* **blob**: file contents
* **tree**: a directory listing of blobs and trees
* **commit**: a tree + parent commit(s) + author, committer, message
* **tag**: an annotated tag object

A **branch** is only a movable pointer (a file under `.git/refs/heads/`) to a commit; **HEAD** points to the current branch (or directly to a commit when **detached**). Commits are snapshots, not diffs, and form a graph (a DAG). Useful contents of `.git`: `HEAD`, `config`, `index`, `objects/`, `refs/`.

```text
$ git config --global user.name  "Ada Example"
$ git config --global user.email "ada@example.com"
$ git config --global init.defaultBranch main
$ git init webshop
Initialized empty Git repository in /home/ada/webshop/.git/
$ git clone https://git.example.com/example/webshop.git
```

Configuration levels: `--system`, `--global` (`~/.gitconfig`), and repository-local (`.git/config`, the default); more local overrides more global.

## Managing files

```text
$ git status                 # long form
$ git status -s              # short: XY path (X = index, Y = working tree)
 M app.py                    #   modified, not staged
M  README.md                 #   modified and staged
?? notes.txt                 #   untracked
$ git add app.py             # stage a file ("git add -p" stages hunks)
$ git commit -m "Add health endpoint"
$ git commit --amend         # replace the last commit (rewrites history)
$ git diff                   # working tree vs index
$ git diff --staged          # index vs last commit (alias: --cached)
$ git log --oneline --graph --decorate --all
$ git show HEAD~1            # one commit, one parent back
```

Removing, renaming, undoing:

| Goal | Command |
|------|---------|
| Delete a tracked file and stage the removal | `git rm file` |
| Stop tracking but keep the file on disk | `git rm --cached file` |
| Rename/move and stage | `git mv old new` |
| Discard working tree changes to a file | `git restore file` |
| Unstage a file (keep edits) | `git restore --staged file` |
| Get a file from another commit | `git restore --source=HEAD~2 file` |
| Undo a commit by adding an inverse commit (safe for shared history) | `git revert <commit>` |
| Move branch back, keep changes staged | `git reset --soft <commit>` |
| Move branch back, unstage changes (default) | `git reset --mixed <commit>` |
| Move branch back, discard all changes | `git reset --hard <commit>` |

> **Watch out:** `git restore file` and `git reset --hard` permanently discard uncommitted work. `git restore` and `git switch` (Git 2.23+) split the overloaded `git checkout` into clearer commands; `checkout` still works.

> **Exam tip:** `revert` creates a new commit and is safe on pushed history; `reset` moves the branch pointer and rewrites history, so avoid it on commits others have.

### Stashing

`git stash` shelves uncommitted changes so you can switch context:

```text
$ git stash push -m "wip: retry logic"     # tracked changes; add -u to include untracked files
$ git stash list
stash@{0}: On main: wip: retry logic
$ git stash pop                            # apply the newest stash and drop it
$ git stash apply stash@{0}                # apply but keep it
$ git stash drop stash@{0}
```

### .gitignore

A `.gitignore` file lists untracked paths Git should not show or add. Pattern rules:

| Pattern | Matches |
|---------|---------|
| `*.log` | any file ending `.log`, in any directory |
| `/build` | `build` only at the level of the `.gitignore` (leading slash anchors) |
| `build/` | a directory named `build` (trailing slash = directories only) |
| `!keep.log` | negation: re-include a file an earlier pattern ignored |
| `doc/**/*.pdf` | PDFs at any depth under `doc/` |
| `**/temp` | `temp` anywhere |
| `?` and `[abc]` | one character; one of a set |
| `# comment` | comment line |

Key facts: later patterns override earlier ones; you **cannot** re-include a file if its parent directory is excluded; ignoring has **no effect on files already tracked** (run `git rm --cached file` first). Personal ignores go in `.git/info/exclude` or a global file set by `core.excludesFile`. Debug with `git check-ignore -v path`.

## SVN, CVS and centralized vs distributed

| | CVS / Subversion (SVN) | Git |
|---|------------------------|-----|
| Model | **Centralized**: one server holds the history; clients hold a working copy | **Distributed**: every clone has full history |
| Offline commits | No; commit goes straight to the server | Yes; commit locally, push later |
| Revision identity | CVS: per-file revisions (1.1, 1.2); SVN: global, sequential revision numbers | Hash per commit |
| Atomic commits | CVS: no (per file); SVN: yes | Yes |
| Branches | Directory copies (SVN, cheap-ish) or tagged files (CVS) | Pointers, very cheap |

CVS is the older of the two; SVN was built to fix its shortcomings. Both need server access for most operations, and a central server is a single point of failure, which Git's distributed model avoids (any clone can serve as backup).

## Lab it yourself

```text
$ mkdir demo && cd demo && git init
$ printf 'print("hi")\n' > app.py && printf '*.log\n__pycache__/\n' > .gitignore
$ touch debug.log && git status -s          # debug.log is not listed
$ git add . && git commit -m "Initial commit"
$ echo 'x' >> app.py && git stash push -m wip && git stash pop
$ git rm --cached app.py && git status -s    # D staged, file still on disk
```

## Key takeaways

* Git is distributed; the three areas are working tree, index and repository.
* Objects: blob, tree, commit, tag; a branch is a pointer, HEAD points to the current branch.
* `git restore` discards working-tree changes; `git restore --staged` unstages.
* `revert` adds an inverse commit; `reset --soft/--mixed/--hard` moves the branch (and index/tree for mixed/hard).
* `git rm --cached` untracks without deleting; `.gitignore` never affects tracked files.
* `.gitignore`: `*` wildcards, leading `/` anchors, trailing `/` for directories, `!` negates, `**` crosses directories.
* SVN/CVS are centralized; Git is distributed with local commits and cheap branches.
