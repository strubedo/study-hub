## Data types in PromQL

PromQL is a read-only query language. Every expression evaluates to one of:

| Type | Meaning | Example |
|---|---|---|
| **Instant vector** | A set of series, each with **one** sample at one timestamp | `http_requests_total` |
| **Range vector** | A set of series, each with **a range of samples** over a time window; written with a `[duration]` selector | `http_requests_total[5m]` |
| **Scalar** | A single number | `3.14` |
| **String** | A string (rarely used) | `"abc"` |

The selector `[5m]` turns an instant-vector selector into a range vector (the last five minutes of samples). You cannot graph a range vector directly; you apply a function that reduces it to an instant vector. Duration units: `s`, `m`, `h`, `d`, `w`, `y`.

## Label selectors (matchers)

Curly braces filter series by label. There are four matchers:

| Matcher | Meaning |
|---|---|
| `=` | label equals the value |
| `!=` | label does not equal the value |
| `=~` | label matches the **regular expression** (fully anchored) |
| `!~` | label does not match the regular expression |

```text
http_requests_total{job="webshop", code="200"}
http_requests_total{code=~"5.."}            # 500-599
http_requests_total{method!="GET", env!~"dev|test"}
```

The metric name is itself the label `__name__`. A selector must contain at least one matcher that does not match the empty string. `offset 1h` evaluates a selector one hour in the past: `http_requests_total offset 1h`.

## Rates from counters

Counters grow forever, so their raw value is rarely useful. Use these functions on **range vectors**:

| Function | Returns |
|---|---|
| `rate(v[5m])` | Per-second average increase over the window, handling counter resets; the standard choice for alerts and graphs |
| `irate(v[5m])` | Per-second rate from the **last two** samples in the window; reacts quickly, good for volatile graphs, noisy for alerts |
| `increase(v[1h])` | Total increase over the window (like `rate` times the window length) |

```text
rate(http_requests_total{job="webshop"}[5m])
increase(http_requests_total[1h])
```

> **Watch out:** `rate(http_requests_total)` without `[...]` is an error, because `rate` needs a range vector. Also, apply `rate()` first and `sum()` afterwards: `sum(rate(x[5m]))`, not `rate(sum(x)[5m])`, which would hide counter resets.

Use `rate` only on counters. For gauges use `delta()`, `deriv()` or the `_over_time` functions.

## Aggregation across series

Aggregation operators take an instant vector and combine series: `sum`, `avg`, `min`, `max`, `count`, `stddev`, `topk`, `bottomk`, `quantile`. The clauses `by` and `without` choose which labels survive.

```text
sum(rate(http_requests_total[5m]))                       # one total number
sum by (job) (rate(http_requests_total[5m]))             # one series per job
sum without (instance) (rate(http_requests_total[5m]))   # drop only `instance`, keep the rest
topk(3, sum by (instance) (rate(node_network_receive_bytes_total[5m])))
```

- `by (a, b)` keeps **only** labels `a` and `b`.
- `without (a)` keeps **all labels except** `a`.
- Both forms may be written before or after the expression.

## Aggregation over time

The `*_over_time` functions take a **range vector** and aggregate the samples of **each series** across time, returning an instant vector: `avg_over_time`, `min_over_time`, `max_over_time`, `sum_over_time`, `count_over_time`, `quantile_over_time`, `last_over_time`.

```text
avg_over_time(node_load1[1h])                 # mean 1-minute load over the last hour
max_over_time(container_memory_working_set_bytes[1d])
```

Do not confuse the two directions: `sum by (job)(...)` aggregates **across series** at one moment; `sum_over_time(...[1h])` aggregates **across time** within each series.

## Histograms and arithmetic

Percentiles come from histogram buckets. The `le` ("less or equal") label must be kept in the aggregation:

```text
histogram_quantile(0.95,
  sum by (le) (rate(http_request_duration_seconds_bucket[5m])))
```

Arithmetic and comparison operators work between vectors and scalars. Vector matching pairs series with the same label set; use `on(...)` or `ignoring(...)` to control which labels are compared. A comparison without `bool` filters rows, which is how alert expressions work.

```text
100 * (1 - avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])))   # CPU busy %
node_filesystem_avail_bytes / node_filesystem_size_bytes < 0.10                 # under 10% free
sum by (job) (rate(http_requests_total{code=~"5.."}[5m]))
  / sum by (job) (rate(http_requests_total[5m]))                                # error ratio
up == 0
```

## Querying from outside

The HTTP API serves PromQL at `/api/v1/query` (instant, `query=` and optional `time=`) and `/api/v1/query_range` (`start`, `end`, `step`):

```text
curl 'http://localhost:9090/api/v1/query?query=up'
{"status":"success","data":{"resultType":"vector","result":[
 {"metric":{"__name__":"up","instance":"localhost:9090","job":"prometheus"},"value":[1793000000.123,"1"]}]}}
```

`resultType` shows the data type (`vector`, `matrix` for range vectors, `scalar`, `string`). Samples carry values as strings. Grafana uses the same API through its Prometheus data source. The objectives mention "retrieving log data" with PromQL; strictly, PromQL queries **metrics**, while log lines are queried with other languages such as LogQL in Loki (next lesson).

## Lab it yourself

1. With Prometheus scraping itself, run `rate(prometheus_http_requests_total[5m])` and compare with `irate`.
2. Run `sum by (code) (rate(prometheus_http_requests_total[5m]))` and then the same with `without (handler, instance, job)`.
3. Run `avg_over_time(up[10m])` and then `up[10m]` to see the range vector output in the Table view.

## Key takeaways

- Instant vector = one sample per series; range vector = `[5m]` window of samples; `rate`, `irate`, `increase` and `*_over_time` need a range vector.
- Matchers: `=`, `!=`, `=~`, `!~` (regex).
- `rate` is the per-second average, `irate` uses the last two samples, `increase` is the total growth.
- `sum by (label)` keeps the listed labels; `without (label)` drops the listed ones.
- `avg_over_time` and friends aggregate across time within each series; `sum`/`avg` aggregate across series.
- Use `histogram_quantile(0.95, sum by (le) (rate(..._bucket[5m])))` for percentiles; always `rate` before `sum`.
