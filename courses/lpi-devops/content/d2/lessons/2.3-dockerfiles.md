## Dockerfile and Containerfile

A **Dockerfile** is a text recipe for building an image; a **Containerfile** is the same format under the vendor-neutral name (Podman and Buildah look for `Containerfile` first, then `Dockerfile`; Docker uses `Dockerfile`; `-f` selects another file). Each instruction that changes the filesystem creates a **layer**; layers are cached and shared.

```dockerfile
# syntax=docker/dockerfile:1
ARG NODE_VERSION=22
FROM node:${NODE_VERSION}-alpine AS build
WORKDIR /src
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:${NODE_VERSION}-alpine
ENV NODE_ENV=production
WORKDIR /app
COPY --from=build --chown=node:node /src/dist ./dist
USER node
EXPOSE 3000
VOLUME ["/app/uploads"]
ENTRYPOINT ["node", "dist/server.js"]
CMD ["--port", "3000"]
```

Build and run: `docker image build -t example/webshop:1.4.2 .` (same as `docker build`). Useful flags: `-f path`, `--build-arg KEY=value`, `--target stage`, `--no-cache`, `--platform`. The final `.` is the **build context** sent to the builder.

## The instructions

| Instruction | Purpose and gotchas |
|---|---|
| `FROM image[:tag] [AS name]` | Start a build stage from a base image; `FROM scratch` is empty. Only `ARG` may precede it |
| `COPY src dest` | Copy files from the build context (or `--from=stage`). `--chown=user:group` sets ownership. Preferred for local files |
| `ADD src dest` | Like COPY plus: extracts **local** tar archives and accepts URLs. Use COPY unless you need that |
| `RUN cmd` | Execute during the build and commit the result as a layer (package installs, compiles) |
| `WORKDIR /dir` | Set (and create) the working directory for later instructions and for the container |
| `ENV KEY=value` | Variable available at build **and** runtime in containers |
| `ARG NAME[=default]` | **Build-time only** variable, set with `--build-arg`; not in the running container's environment, but recorded in `docker history`, so never pass secrets |
| `USER user[:group]` | Run later instructions and the container as this (non-root) user |
| `EXPOSE 3000[/udp]` | Documentation of the listening port. **Does not publish** it; use `-p` or `-P` |
| `VOLUME ["/data"]` | Declares a mount point; creates an anonymous volume unless one is supplied. Changes to that path made later in the Dockerfile are discarded |
| `CMD` | Default command or default arguments for ENTRYPOINT; replaced by arguments to `docker run` |
| `ENTRYPOINT` | The executable; arguments to `docker run` are appended; replace with `--entrypoint` |

Others you may meet: `LABEL`, `HEALTHCHECK`, `STOPSIGNAL`, `SHELL`, `ONBUILD`, and `# syntax=` parser directives. Only the **last** `CMD` and the last `ENTRYPOINT` take effect.

> **Exam tip:** ENV is runtime and build, ARG is build-only. EXPOSE only documents.

### Shell form versus exec form

| | Shell form | Exec form |
|---|---|---|
| Syntax | `CMD node server.js` | `CMD ["node", "server.js"]` (JSON array, double quotes) |
| Runs as | `/bin/sh -c "node server.js"` | The program directly |
| PID 1 | `sh` | `node` |
| Signals (SIGTERM from `docker stop`) | Not forwarded by the shell, so the app may be killed after the 10 s timeout | Delivered to the app |
| Variable expansion | Yes (`$HOME`) | No (no shell), unless you call `sh -c` |

### CMD versus ENTRYPOINT

| Dockerfile | `docker run img` | `docker run img --port 9000` |
|---|---|---|
| `CMD ["nginx","-g","daemon off;"]` | runs nginx | **replaces** CMD: tries to run `--port 9000` and fails |
| `ENTRYPOINT ["ping"]` | `ping` with no host | `ping --port 9000` (arguments appended) |
| `ENTRYPOINT ["ping"]` + `CMD ["-c","3","192.0.2.1"]` | `ping -c 3 192.0.2.1` | `ping --port 9000` (CMD replaced, ENTRYPOINT kept) |

Use ENTRYPOINT (exec form) for the fixed executable and CMD for overridable default arguments. A shell-form ENTRYPOINT ignores CMD and run arguments entirely.

## Layers and the build cache

Docker reuses a cached layer while the instruction and its inputs are unchanged; the first changed instruction invalidates everything after it. Put rarely changing steps first: copy the dependency manifest, install dependencies, **then** copy the source. Combine related `RUN` steps (install packages and clean the package lists in the same `RUN`) so cleanup happens in the same layer; deleting a file in a later layer does not shrink the image. Pin base image versions (or digests) for reproducible builds.

## Multi-stage builds

Each `FROM` starts a new stage. `COPY --from=<stage>` takes artifacts from an earlier stage, and everything else (compilers, source, caches) is left behind, producing small images with a smaller attack surface. `docker build --target build .` stops at a named stage (useful for test stages).

```dockerfile
FROM golang:1.23 AS build
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -o /out/webshop ./cmd/webshop

FROM gcr.io/distroless/static-debian12
COPY --from=build /out/webshop /webshop
USER 65532:65532
ENTRYPOINT ["/webshop"]
```

## .dockerignore

The file `.dockerignore` in the **root of the build context** lists paths excluded from the context (and so from `COPY . .`). It keeps the context small and keeps secrets and junk out of the image.

```text
.git
node_modules
*.log
.env
**/*.tmp
!keep.tmp
```

Patterns are relative to the context root; `**` matches any number of directories; a leading `!` re-includes an exception; later lines win. (Podman and Buildah also honour `.containerignore`.)

## Lab it yourself

1. Build the Go example or any small app twice; the second build shows `CACHED` steps.
2. Edit one source file and see which layers rebuild; then reorder `COPY` and `RUN npm ci` and compare.
3. Compare `docker image ls` sizes of single-stage vs multi-stage builds.
4. Run an image with an ENTRYPOINT/CMD pair as `docker run img --port 9000` and note what changes.

## Key takeaways

- Containerfile is the neutral name for Dockerfile; Podman checks `Containerfile` first.
- COPY for local files, ADD only for local tar extraction or URLs; RUN executes at build time.
- ENV persists into the container, ARG is build-time only, EXPOSE only documents, VOLUME declares a mount point.
- Prefer exec form (JSON array) so the app is PID 1 and receives signals.
- ENTRYPOINT is the executable; CMD supplies default arguments that `docker run` arguments replace.
- Order instructions from least to most frequently changing for cache hits.
- Multi-stage builds ship only the artifacts; `.dockerignore` trims the build context.
