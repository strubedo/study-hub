## OCI image names

An image reference has the form

```text
[registry-host[:port]/][namespace/]repository[:tag][@digest]
registry.example.com:5000/example/webshop:1.4.2@sha256:9f86d0...
```

| Part | Meaning | Default when omitted |
|---|---|---|
| Registry host | Where the image is stored | `docker.io` (Docker Hub) |
| Namespace | User, organisation or project | `library` for Docker Official Images (Docker Hub) |
| Repository | Image name | none |
| Tag | Mutable label for a version | `latest` |
| Digest | `sha256:` hash of the image manifest; **immutable** | none |

So `nginx` means `docker.io/library/nginx:latest`, and `example/webshop` means `docker.io/example/webshop:latest`. A first path component that contains a `.` or `:` or is `localhost` is treated as a registry host. Tags can be moved to a new image (`latest` is just a convention); a digest always identifies the same content. When both tag and digest are given, the digest decides. Reference by digest in production for reproducibility: `docker pull example/webshop@sha256:...`. Podman does not assume Docker Hub for short names; it uses `unqualified-search-registries` from `registries.conf`.

## Logging in, tagging, pushing

```text
docker login registry.example.com             # prompts for user and password/token
docker image tag example/webshop:1.4.2 registry.example.com/example/webshop:1.4.2
docker image push registry.example.com/example/webshop:1.4.2
docker logout registry.example.com
```

`docker tag` adds another name to the *same* image ID (no copy). The push target is determined by the **registry prefix in the tag**, so you must tag with the registry host first. `docker login` with no host uses Docker Hub. Credentials are stored in `~/.docker/config.json` (base64 text, which is not encryption) unless a **credential helper** (`credsStore`) is configured. In CI, prefer `docker login --password-stdin` with an access token. Registries speak the OCI Distribution API over HTTPS; a plain-HTTP registry must be listed in `insecure-registries`. Private registry options: Docker Hub private repositories, GitHub Container Registry, Harbor, Quay, or the open source `registry:2` image. The Podman commands are identical (`podman login`, `podman push`).

> **Exam tip:** "Push is denied or tries to reach Docker Hub": the image is not tagged with the registry host (and namespace) or the user is not logged in.

## Image scanners

An **image scanner** unpacks the image layers, builds an inventory of installed OS packages and language dependencies (and sometimes configuration issues and secrets), and compares them against **vulnerability databases** (NVD, distro security trackers, GitHub advisories), reporting CVEs with severity and the fixed version. It can run in CI to fail a build above a severity threshold, and it should be repeated on stored images because new CVEs appear after the build.

| Scanner | Example |
|---|---|
| **Trivy** (Aqua Security) | `trivy image --severity HIGH,CRITICAL example/webshop:1.4.2` |
| **Grype** (Anchore; pairs with Syft for SBOMs) | `grype example/webshop:1.4.2 --fail-on high` |
| **Docker Scout** | `docker scout cves example/webshop:1.4.2`, `docker scout quickview` |
| Clair | Registry-integrated service used by Quay |

Limits: only known, published vulnerabilities; false positives (vulnerable code not reachable) and false negatives (software copied in without a package record); results depend on database freshness.

## Container security risks and mitigations

Containers share the host kernel, so isolation is weaker than a VM's: a kernel bug or misconfiguration can allow container escape.

| Risk | Mitigation |
|---|---|
| Running as root in the container | `USER` non-root; `docker run -u`; rootless engines |
| Excess privileges | Avoid `--privileged`; `--cap-drop ALL --cap-add NET_BIND_SERVICE`; `--security-opt no-new-privileges` |
| Docker socket exposure | Never mount `/var/run/docker.sock` into containers; restrict the `docker` group |
| Vulnerable or bloated images | Small trusted bases (slim, Alpine, distroless), multi-stage builds, scan and rebuild regularly |
| Mutable or untrusted images | Pin versions or digests, use trusted registries, sign and verify images (Docker Content Trust, Sigstore cosign) |
| Secrets in images | Never `ENV`/`ARG`/`COPY` secrets: they remain in layers and history. Use runtime secrets (Compose/Swarm/Kubernetes secrets) or BuildKit `RUN --mount=type=secret` |
| Writable filesystem | `--read-only` plus `--tmpfs` for scratch paths |
| Resource exhaustion | `--memory`, `--cpus`, `--pids-limit` |
| Kernel attack surface | Default seccomp profile, AppArmor/SELinux, user namespaces; keep the host patched |

## Build tools: buildx, BuildKit, Podman build, Buildah

| Tool | Facts |
|---|---|
| **BuildKit** | Modern build engine behind `docker build` (default since Docker Engine 23.0): parallel stage execution, better caching, `RUN --mount` (secret, ssh, cache). Older engines: `DOCKER_BUILDKIT=1` |
| **Docker Buildx** | CLI plugin exposing BuildKit's full feature set: `docker buildx build`, builder instances (`docker buildx create --use`), **multi-platform** images (`--platform linux/amd64,linux/arm64`), `--push`, cache export/import |
| **Podman build** | `podman build -t ... -f Containerfile .`; uses Buildah's library; no daemon |
| **Buildah** | Daemonless tool that builds OCI/Docker-format images either from a Dockerfile/Containerfile (`buildah build`, older `buildah bud`) or step by step (`buildah from`, `buildah copy`, `buildah run`, `buildah commit`) without a Dockerfile; can build rootless |

```text
docker buildx build --platform linux/amd64,linux/arm64 \
  -t registry.example.com/example/webshop:1.4.2 --push .
```

## Lab it yourself

1. `docker image tag` an image for `localhost:5000/example/webshop:1.4.2`, run `docker run -d -p 5000:5000 registry:2`, push, delete the local image and pull it back.
2. Run `trivy image alpine:3.20` or `grype alpine:3.20` and compare to an older tag.
3. Add `USER`, `--read-only` and `--cap-drop ALL` to a run command and see what breaks.

## Key takeaways

- Format: `registry/namespace/repo:tag@digest`; defaults are `docker.io`, `library`, `latest`.
- Tags are mutable, digests are immutable.
- Push needs the registry host in the tag plus `docker login`; credentials land in `~/.docker/config.json`.
- Scanners match package inventories to CVE databases; Trivy, Grype and Docker Scout are common.
- Mitigate with non-root users, dropped capabilities, minimal pinned images, no secrets in layers and no Docker socket mounts.
- BuildKit is the engine, buildx the CLI front end (multi-platform); Buildah and `podman build` are the daemonless alternatives.
