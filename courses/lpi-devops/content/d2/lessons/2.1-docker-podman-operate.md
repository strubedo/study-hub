## Docker architecture

Docker Engine is a **client-server** system. The `docker` CLI talks over a REST API (by default the Unix socket `/var/run/docker.sock`) to the **daemon `dockerd`**. The daemon manages images, networks and volumes and delegates container lifecycle to **containerd**, which starts a `containerd-shim` per container, which in turn runs the low-level OCI runtime **runc** to create the namespaces and cgroups. A container is therefore an ordinary Linux process (or process tree) isolated with namespaces and limited with cgroups; it shares the host kernel.

| Component | Role |
|---|---|
| `docker` CLI | Client; sends API requests |
| `dockerd` | Daemon: API, images, networks, volumes |
| containerd | High-level runtime: image pull/unpack, container lifecycle |
| runc | OCI runtime that actually creates the container |
| Registry | Stores images (Docker Hub, a private registry) |

> **Watch out:** Access to the Docker socket is effectively root on the host. Membership of the `docker` group is not a harmless privilege.

## Podman architecture

Podman is **daemonless**: the `podman` command forks and execs the container directly, with a small monitor process (**conmon**) per container and an OCI runtime (**crun** or **runc**). There is no long-running root daemon and no single point of failure. Podman is **rootless by default** when run as a normal user, and its CLI is deliberately Docker-compatible (`alias docker=podman` works for most commands). Podman also has **pods** like Kubernetes: a group of containers sharing network and IPC namespaces (`podman pod create`, `podman run --pod`), and it can read and write Kubernetes YAML (`podman kube generate`, `podman kube play`). Networking uses **Netavark** (with **aardvark-dns** for name resolution); rootless networking uses **pasta** (Podman 5 default; slirp4netns previously). Image and build work is shared with **Buildah** and **Skopeo** libraries.

| | Docker | Podman |
|---|---|---|
| Daemon | `dockerd` (root) | none (fork/exec) |
| Rootless | optional mode | default for non-root users |
| Pods | no | yes |
| Compose | `docker compose` plugin | `podman-compose` or `podman compose` |
| Local storage | `/var/lib/docker` | `~/.local/share/containers` (rootless) |

Both implement the **OCI** specs (image, runtime, distribution), so an image built by one runs on the other.

## Images and registries

An **image** is a read-only stack of layers plus metadata; a **container** is a running (or stopped) instance with a thin writable layer on top. Images come from an **OCI registry**.

```text
docker image pull nginx:1.27          # = docker.io/library/nginx:1.27
docker image ls                       # local images
docker image inspect nginx:1.27       # JSON metadata
docker image history nginx:1.27       # layers and the instruction that made each
docker image rm nginx:1.27            # remove (alias: docker rmi)
docker image prune                    # remove dangling images (-a: all unused)
docker image save -o webshop.tar example/webshop:1.4.2
docker image load -i webshop.tar
```

The old short forms (`docker pull`, `docker images`, `docker rmi`) still work; the exam objectives use the `docker image *` management-command forms. The same subcommands exist for `podman image *`. Podman resolves an unqualified name such as `nginx` using `unqualified-search-registries` in `registries.conf` (and may prompt you to pick one), so scripts should use fully qualified names like `docker.io/library/nginx`.

## Running containers

`docker container run` (short: `docker run`) creates and starts a container. The flags to know:

| Flag | Meaning |
|---|---|
| `-d`, `--detach` | Run in the background, print the container ID |
| `-i` / `-t` / `-it` | Keep STDIN open / allocate a pseudo-TTY / both for an interactive shell |
| `--rm` | Remove the container automatically when it exits |
| `--name web` | Give the container a name (unique per host) |
| `-p 8080:80` | Publish container port 80 on host port 8080 (`HOST:CONTAINER`); `-p 127.0.0.1:8080:80` binds one host address; `-p 53:53/udp` for UDP; `-P` publishes all `EXPOSE`d ports to random host ports |
| `-e KEY=value` | Set an environment variable (`--env-file` reads many) |
| `-v name:/data` | Mount a volume or bind mount (see next lesson); `--mount` is the explicit form |
| `--network appnet` | Attach to a network |
| `--restart unless-stopped` | Restart policy (`no`, `on-failure[:N]`, `always`, `unless-stopped`) |
| `--memory 256m`, `--cpus 1.5` | Resource limits (cgroups) |
| `-u 1000:1000`, `--read-only` | Run as a user; read-only root filesystem |

Arguments after the image name replace the image's `CMD`: `docker run --rm alpine:3.20 echo hi`. `--entrypoint` replaces the `ENTRYPOINT`.

```text
$ docker container run -d --name web -p 8080:80 -e TZ=UTC nginx:1.27
$ docker container ls            # running only; add -a for stopped too
CONTAINER ID   IMAGE        COMMAND                  STATUS         PORTS                  NAMES
3f1c9a7b2d10   nginx:1.27   "/docker-entrypoint.…"   Up 5 seconds   0.0.0.0:8080->80/tcp   web
```

> **Exam tip:** `docker run` of an image that is not local pulls it first. A container whose main process exits stops; with `-d` and no foreground process the container exits immediately.

## Operating and accessing containers

| Task | Command |
|---|---|
| Shell in a running container | `docker container exec -it web sh` (starts a *new* process) |
| Attach to main process | `docker container attach web` (detach with `Ctrl-p Ctrl-q`) |
| Logs | `docker container logs -f --tail 50 web` (STDOUT/STDERR of PID 1) |
| Inspect | `docker container inspect web` (JSON; `-f '{{.NetworkSettings.IPAddress}}'`) |
| Processes / usage | `docker container top web`, `docker container stats` |
| Stop / start / restart | `docker container stop web` (SIGTERM, then SIGKILL after 10 s), `start`, `restart` |
| Kill | `docker container kill web` (SIGKILL by default; `-s` for another signal) |
| Remove | `docker container rm web` (`-f` to force, `prune` for all stopped) |
| Copy files | `docker container cp web:/etc/nginx/nginx.conf .` |
| Port mappings | `docker container port web` |

`docker container ls -a` shows stopped containers; they keep their writable layer until removed. `docker container run --rm` avoids the leftovers. The Podman equivalents are identical: `podman container run`, `podman exec`, `podman logs`, `podman ps`.

> **Real world:** Logs only work this way if the app writes to STDOUT/STDERR. Apps that write log files inside the container hide them from `docker logs`.

## Lab it yourself

1. `docker container run -d --name web -p 8080:80 nginx:1.27`, then `curl -I http://localhost:8080`.
2. `docker container exec -it web sh` and run `ls /usr/share/nginx/html`.
3. `docker container logs web`, then `docker container stop web && docker container rm web`.
4. Repeat with `podman` as a normal user and note there is no daemon (`pgrep dockerd` vs `pgrep conmon`).

## Key takeaways

- Docker is CLI, `dockerd`, containerd, runc; Podman is daemonless with conmon and crun/runc.
- Podman is rootless by default and supports pods and Kubernetes YAML; both follow OCI specs.
- Use `docker image *` and `docker container *` management commands; the same subcommands exist for Podman.
- `-d`, `-it`, `--rm`, `--name`, `-p HOST:CONTAINER`, `-e` and `-v` cover most `docker container run` usage.
- `exec` starts a new process; `attach` connects to PID 1; `logs` reads PID 1's output.
- `stop` sends SIGTERM then SIGKILL; `kill` sends SIGKILL; stopped containers persist until `rm`.
- Arguments after the image name replace `CMD`; `--entrypoint` replaces `ENTRYPOINT`.
