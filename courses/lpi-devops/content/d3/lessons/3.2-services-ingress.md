## Why Services exist

Pod IPs change every time a Pod is replaced. A **Service** (`v1`) gives a set of Pods one stable virtual IP and DNS name and load-balances across the ready ones. The Service finds its Pods through a **label selector**; the matching Pod IPs are tracked as EndpointSlices (`kubectl get endpointslices`, or `kubectl get endpoints`). A Pod that fails its readiness probe is removed from the endpoints.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
  namespace: prod
spec:
  type: ClusterIP
  selector:
    app: webshop
  ports:
  - name: http
    port: 80          # port the Service listens on
    targetPort: 8080  # port on the Pods (number or named port)
    protocol: TCP
```

If the selector matches no Pod labels, the Service exists but has no endpoints (`kubectl get endpoints web` shows `<none>`), a classic troubleshooting item. `targetPort` defaults to the value of `port`.

## Service types

| Type | Reachable from | Notes |
|---|---|---|
| `ClusterIP` (default) | Inside the cluster only | Virtual IP from the service CIDR |
| `NodePort` | Outside via `<any node IP>:<nodePort>` | Opens the same port on every node, default range **30000-32767**; includes a ClusterIP. Set `nodePort:` or let it be allocated |
| `LoadBalancer` | Outside via an external load balancer | Needs a cloud provider (or an add-on such as MetalLB on bare metal); builds on NodePort and ClusterIP; the address appears in `EXTERNAL-IP` |
| `ExternalName` | Inside | No proxying and no selector: the cluster DNS returns a **CNAME** (`externalName: db.example.com`) |
| Headless (`clusterIP: None`) | Inside | No virtual IP; DNS returns the individual Pod IPs. Used with StatefulSets |

```text
$ kubectl get svc -n prod
NAME   TYPE        CLUSTER-IP     EXTERNAL-IP   PORT(S)        AGE
web    NodePort    10.96.44.120   <none>        80:31080/TCP   3m
db     ClusterIP   None           <none>        5432/TCP       3m
```

`80:31080/TCP` reads as service port 80, node port 31080.

**Service DNS:** inside the cluster, `web` resolves from the same namespace; `web.prod` or `web.prod.svc.cluster.local` from anywhere. Pods also get `WEB_SERVICE_HOST`-style environment variables, but DNS is the way to discover services.

`kubectl expose deployment web --port=80 --target-port=8080 --type=NodePort` builds this object from a Deployment's selector. `kubectl port-forward svc/web 8080:80` tunnels a local port for testing.

> **Exam tip:** `port` is the Service's own port, `targetPort` the Pod's container port, `nodePort` the port on every node. A NodePort outside 30000-32767 is rejected by default.

## Ingress

A Service of type NodePort or LoadBalancer exposes one service per port or per load balancer. **Ingress** (`networking.k8s.io/v1`) routes **HTTP/HTTPS** to many Services by host name and URL path, and handles TLS termination, all behind one entry point.

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: webshop
  namespace: prod
spec:
  ingressClassName: nginx
  tls:
  - hosts: [shop.example.com]
    secretName: shop-example-tls
  rules:
  - host: shop.example.com
    http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api
            port:
              number: 80
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web
            port:
              number: 80
```

* An Ingress object **does nothing by itself**. An **Ingress controller** (NGINX-based, Traefik, HAProxy, Envoy-based, cloud controllers) must be installed; it watches Ingress objects and configures a proxy. Kubernetes does not ship one by default.
* The community **ingress-nginx** controller was retired in March 2026 (no further releases or security fixes), so new clusters should pick another controller (Traefik, HAProxy, Envoy-based, a cloud controller) or move to Gateway API. The Ingress API itself is unchanged and is still what the exam tests.
* `ingressClassName` selects which controller handles the object (an `IngressClass` resource names it).
* `pathType`: `Exact` (exact match), `Prefix` (match on path elements, `/api` matches `/api` and `/api/v1` but not `/apiary`), `ImplementationSpecific` (up to the controller).
* The backends are Services, referenced by `service.name` and `port.number` (or `port.name`). The controller itself is usually exposed with a LoadBalancer or NodePort Service.
* TLS: `tls.secretName` points to a Secret of type `kubernetes.io/tls` (keys `tls.crt`, `tls.key`) in the same namespace.
* Ingress handles only HTTP(S). The newer **Gateway API** is its more expressive successor, but Ingress remains the exam topic.

```text
client -> DNS shop.example.com -> LoadBalancer -> Ingress controller Pods
          -> /api -> Service api -> Pods     / -> Service web -> Pods
```

> **Watch out:** Creating an Ingress on a cluster with no controller leaves `ADDRESS` empty forever. The first thing to check is whether a controller and a matching IngressClass exist.

## Lab it yourself

On minikube enable the ingress add-on (`minikube addons enable ingress`) or install a controller on kind. Create two Deployments with `nginx` and `httpd`, expose both with ClusterIP Services, write an Ingress with two paths and test with `curl -H 'Host: shop.example.com' http://<ingress-address>/`. Verify with `kubectl get endpoints` that each Service has Pod IPs, then change the Service selector to a wrong label and watch the endpoints disappear.

## Key takeaways

- A Service gives Pods a stable virtual IP and DNS name and selects Pods by label.
- Types: ClusterIP (default, internal), NodePort (30000-32767 on every node), LoadBalancer (external LB from a provider), ExternalName (DNS CNAME, no selector); headless uses `clusterIP: None`.
- `port` is the Service port, `targetPort` the container port, `nodePort` the node port.
- Only Pods passing readiness are in the Service endpoints.
- Ingress routes HTTP(S) by host and path to Services and terminates TLS.
- An Ingress needs an Ingress controller to work, and `ingressClassName` picks it.
- Ingress apiVersion is `networking.k8s.io/v1`, Service apiVersion `v1`.
