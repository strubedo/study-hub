## Windows Defender Firewall with Advanced Security

Windows Server ships with a stateful, host-based firewall that is **on by default** for every profile. It drops unsolicited inbound traffic that does not match an allow rule, and it allows replies to traffic the server itself started. Out of the box, **inbound is blocked and outbound is allowed** on all three profiles. Manage it in `wf.msc` (Windows Defender Firewall with Advanced Security), with Group Policy, or with the `NetSecurity` PowerShell module.

### Profiles

A *network location profile* is a set of firewall settings that Windows applies to a network connection based on where the connection is.

| Profile | Applied when | Typical use |
|---|---|---|
| **Domain** | The server can authenticate to a domain controller (network location awareness detects the domain network) | Member servers on the corporate LAN |
| **Private** | An administrator designates the network as private | Trusted workgroup or lab network |
| **Public** | Default for a network that is not identified as domain or private | Untrusted networks; the most restrictive choice |

Each network adapter gets its own profile, so a server with a LAN NIC and a DMZ NIC can run two profiles at once. A domain controller's NIC should land in the Domain profile; if the DC starts the firewall before the network is identified, it can land in Public, which is why a DC may need `Restart-NetAdapter` or a restart of the Network Location Awareness service (`NlaSvc`) after a boot-order issue.

Per-profile settings live in `Set-NetFirewallProfile`: whether the firewall is enabled, `-DefaultInboundAction` and `-DefaultOutboundAction` (`Allow` or `Block`), whether locally created rules merge with GPO rules (`-AllowLocalFirewallRules`), and logging. Logging is off until you turn it on:

```powershell
Set-NetFirewallProfile -Profile Domain,Private,Public -Enabled True
Set-NetFirewallProfile -Profile Domain -LogBlocked True -LogAllowed False `
  -LogFileName '%SystemRoot%\System32\LogFiles\Firewall\pfirewall.log' -LogMaxSizeKilobytes 20480
```

The default log is `%SystemRoot%\System32\LogFiles\Firewall\pfirewall.log` at **4,096 KB**; the maximum is 32,767 KB. When the file hits its limit, the oldest entries are discarded. Microsoft's guidance is to raise the size to at least 20,480 KB and use a separate file per profile.

> **Watch out:** Turning the firewall off is never the fix for a connectivity problem on a server. Create or enable the specific rule. The OSConfig security baseline (see the baselines lesson) *enforces* the firewall on all three profiles with inbound default-deny.

### Rules

A rule combines a **direction** (inbound or outbound), an **action** (allow or block), and matching criteria: program or service, protocol, local and remote ports, local and remote addresses, interface types, and the profile(s) it applies to. Roles and features create their own rules, grouped by `DisplayGroup` (for example *File and Printer Sharing* or *Remote Desktop*), when you install them. Many are created disabled and enabled on demand.

How the firewall decides, in simplified order: Windows service hardening rules, then connection security (IPsec) rules, then authenticated-bypass rules, **block rules**, **allow rules**, and finally the profile default action. The key exam point: **an explicit block rule beats an allow rule**, except for authenticated-bypass allow rules.

```powershell
# Create: allow SMB from the server subnet only, Domain profile only
New-NetFirewallRule -DisplayName 'SMB-In from 192.168.10.0/24' -Direction Inbound `
  -Protocol TCP -LocalPort 445 -RemoteAddress 192.168.10.0/24 -Action Allow -Profile Domain

# Enable a built-in group
Enable-NetFirewallRule -DisplayGroup 'Remote Desktop'

# Find the rules that match a port, with their filters
Get-NetFirewallPortFilter -Protocol TCP | Where-Object LocalPort -eq 3389 |
  Get-NetFirewallRule | Select-Object DisplayName, Enabled, Direction, Action, Profile
```

The rule object is split into pieces you query separately: `Get-NetFirewallRule` returns the rule, while `Get-NetFirewallPortFilter`, `Get-NetFirewallAddressFilter` and `Get-NetFirewallApplicationFilter` return its match criteria. Other cmdlets: `Set-NetFirewallRule`, `Remove-NetFirewallRule`, `Disable-NetFirewallRule`, `Copy-NetFirewallRule`, `Get-NetFirewallProfile`.

Rules can come from several **policy stores**. Local rules live in the *PersistentStore*; GPO rules arrive from Group Policy. To see what is actually in effect after merging, query `-PolicyStore ActiveStore`. To edit a GPO from PowerShell, use `-GPOSession` with `Open-NetGPO`/`Save-NetGPO` or `-PolicyStore corp.example.com\Server Firewall GPO`.

For fleets, configure rules in a GPO at *Computer Configuration > Policies > Windows Settings > Security Settings > Windows Defender Firewall with Advanced Security*. If the GPO sets "Apply local firewall rules" to **No**, locally created rules are ignored, which is a common reason a hand-made rule "does not work".

> **Exam tip:** Ports you should recognize: RDP 3389, WinRM 5985 (HTTP) and 5986 (HTTPS), SMB 445, DNS 53, Kerberos 88, LDAP 389, LDAPS 636, SSH 22.

### Reading the firewall log and events

Dropped connections appear in `pfirewall.log` as `DROP` lines with the source, destination, port and protocol. Security-log events 5152 (packet dropped) and 5156 (connection allowed) require the *Filtering Platform* audit subcategories and are noisy; use the text log first. Changes to rules are recorded in the *Windows Firewall With Advanced Security/Firewall* operational log.

## Microsoft Defender Antivirus on Windows Server

Microsoft Defender Antivirus (MDAV) is **installed and enabled by default on Windows Server 2016 and later**. The Windows Security app is part of the OS on Desktop Experience installs of 2019 and later. On Server Core, you manage MDAV with PowerShell or Group Policy.

The server feature name is `Windows-Defender`, with the optional `Windows-Defender-GUI` for a user interface on installs that need it. Reinstall or remove with the usual feature cmdlets:

```powershell
Install-WindowsFeature -Name Windows-Defender
Uninstall-WindowsFeature -Name Windows-Defender      # removes it (not normally advised)
```

### Day-to-day PowerShell (the `Defender` module)

```powershell
Get-MpComputerStatus                       # engine, signature age, real-time protection state, AMRunningMode
Update-MpSignature                         # pull the latest security intelligence
Start-MpScan -ScanType QuickScan           # or FullScan, or CustomScan -ScanPath D:\Data
Get-MpThreat; Get-MpThreatDetection        # what was found
Set-MpPreference -DisableRealtimeMonitoring $false
Add-MpPreference -ExclusionPath 'D:\SQLData'
Add-MpPreference -ExclusionProcess 'sqlservr.exe'
Get-MpPreference | Select-Object ExclusionPath, ExclusionProcess
```

Use `Add-MpPreference` to append to a list such as exclusions; `Set-MpPreference` **replaces** the value, so using it for exclusions wipes the existing list. The same settings exist in Group Policy under *Computer Configuration > Administrative Templates > Windows Components > Microsoft Defender Antivirus*.

### Updates on a server

By default, Windows Update does not install updates automatically on Server, so security intelligence updates will not arrive unless you allow them. Fix this with the *Configure Automatic Updates* policy or SConfig: one option installs all updates automatically, and another lets Defender download and install only security intelligence updates automatically while other updates are not installed automatically. Also keep the Defender services running (`WinDefend`, `WdNisSvc`, `Sense` if onboarded).

### Exclusions

Server roles have **automatic exclusions**: on Windows Server 2016 and later, MDAV applies exclusions for the files and processes of installed roles (DNS, DHCP, AD DS, Hyper-V, and so on) so the roles are not scanned unnecessarily. You add custom exclusions only for products without Microsoft-defined ones. An exclusion is a trade of safety for performance, so scope it tightly: exclude a path or process, not a whole drive.

### Active versus passive mode

MDAV runs in **active mode** (the real-time scanner) when it is the only antivirus. If a non-Microsoft antivirus registers with Windows, or the server is onboarded to **Microsoft Defender for Endpoint** and the endpoint detection and response (EDR) sensor takes over, MDAV can run in **passive mode**: it does not remediate but still receives updates and can scan on demand. You can force passive mode with the `ForceDefenderPassiveMode` registry value (DWORD 1) under `HKLM\SOFTWARE\Policies\Microsoft\Windows Advanced Threat Protection`. `AMRunningMode` in `Get-MpComputerStatus` tells you which mode is in effect.

OSConfig also ships a Defender baseline scenario, `Defender/Antivirus/WindowsServer/2025`, covered in the baselines lesson.

## Lab it yourself

1. On `FS01`, run `Get-NetFirewallProfile | Select Name, Enabled, DefaultInboundAction, DefaultOutboundAction` and confirm all three are enabled with inbound Block and outbound Allow.
2. Turn on dropped-packet logging for the Domain profile, then from another VM run `Test-NetConnection FS01 -Port 8080` and find the `DROP` line in `pfirewall.log`.
3. Create an inbound allow rule for TCP 8080 limited to `192.168.10.0/24`, repeat the test, and compare. Then add a block rule for one host and prove the block rule wins.
4. Run `Get-MpComputerStatus | Select AMRunningMode, AntivirusSignatureLastUpdated, RealTimeProtectionEnabled`, then `Update-MpSignature` and `Start-MpScan -ScanType QuickScan`.
5. Download the EICAR test string in a text file on a test folder and watch `Get-MpThreatDetection`. Add the folder to `-ExclusionPath` and observe the difference.

## Key takeaways

- Default on every profile: firewall on, inbound blocked, outbound allowed; logging is off until enabled (default log 4,096 KB).
- Domain, Private and Public are chosen per adapter; Public is the default for unidentified networks.
- An explicit block rule overrides an allow rule, apart from authenticated bypass.
- `Get-NetFirewallRule` returns the rule; port, address and application criteria come from the separate `*Filter` cmdlets.
- A GPO that disables local rule merging makes locally created rules ineffective.
- MDAV is installed and active by default on Server 2016 and later; the feature is `Windows-Defender`.
- `Add-MpPreference` appends exclusions, `Set-MpPreference` replaces them; roles get automatic exclusions.
- Passive mode comes from a non-Microsoft AV or Defender for Endpoint onboarding, and `AMRunningMode` shows it.
