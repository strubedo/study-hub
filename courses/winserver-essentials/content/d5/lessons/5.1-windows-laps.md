## The problem LAPS solves

If every server shares the same local Administrator password, one stolen hash lets an attacker walk across the whole estate (a pass-the-hash and lateral-movement attack). **Windows LAPS** (Local Administrator Password Solution) gives every machine a unique, random, regularly rotated password for a local administrator account and stores it centrally where only authorized people can read it. It also covers the **Directory Services Restore Mode (DSRM)** password on domain controllers.

Windows LAPS is built into Windows Server 2019 and 2022 (with the April 11, 2023 update or later) and **into Windows Server 2025**; it needs no download and no extra license. It is **not** the same product as the old *Microsoft LAPS* MSI (AdmPwd), which is deprecated. Windows LAPS can run in *legacy emulation mode* to honor old LAPS policy during migration, but then it stores passwords in clear text and cannot use encryption or history. The two must not be mixed on one machine: if the legacy client-side extension is installed, Windows LAPS defers to it.

## Where the password can be backed up

| Device joined to | Can back up to |
|---|---|
| Windows Server Active Directory only | Active Directory only |
| Microsoft Entra ID only | Entra ID only |
| Hybrid (both) | Either, **not both** |

`BackupDirectory` is the policy that picks the target: **0** disabled (the default, so nothing happens until you configure it), **1** Microsoft Entra ID, **2** Active Directory. Entra ID backup needs a Microsoft Entra ID Free or higher license; AD backup needs none.

## Setting it up for Active Directory

1. **Extend the schema** once per forest (as a Schema Admin):
   ```powershell
   Update-LapsADSchema
   ```
   This adds the `msLAPS-*` attributes to the computer class (`msLAPS-Password`, `msLAPS-EncryptedPassword`, `msLAPS-PasswordExpirationTime`, and related attributes). The legacy attribute is `ms-Mcs-AdmPwd`, a different attribute.
2. **Let computers write their own password** on an OU of computers:
   ```powershell
   Set-LapsADComputerSelfPermission -Identity 'OU=Servers,DC=corp,DC=example,DC=com'
   ```
3. **Grant read and reset rights** to the people or groups who need them:
   ```powershell
   Set-LapsADReadPasswordPermission  -Identity 'OU=Servers,DC=corp,DC=example,DC=com' -AllowedPrincipals 'CORP\LAPS-Readers'
   Set-LapsADResetPasswordPermission -Identity 'OU=Servers,DC=corp,DC=example,DC=com' -AllowedPrincipals 'CORP\LAPS-Admins'
   ```
   `Find-LapsADExtendedRights` shows who already holds extended rights on an OU, which is how you spot over-permissioned groups.
4. **Configure policy** with the Group Policy template at *Computer Configuration > Policies > Administrative Templates > System > LAPS*. The template `LAPS.admx` is part of Windows but is **not copied to a Central Store automatically**; copy it yourself if you use one.
5. **Process policy and verify**:
   ```powershell
   Invoke-LapsPolicyProcessing           # on the client, apply now
   Get-LapsADPassword -Identity FS01 -AsPlainText
   Reset-LapsPassword                    # force a rotation on this machine
   ```
   `Get-LapsADPassword` also reads encrypted passwords and password history, and honours `-Port` and `-RecoveryMode` for DC and offline scenarios. You can also read the password in **Active Directory Users and Computers** on the computer's *LAPS* tab.

> **Exam tip:** The three permission cmdlets (`Set-LapsADComputerSelfPermission`, `Set-LapsADReadPasswordPermission`, `Set-LapsADResetPasswordPermission`) and `Update-LapsADSchema` are the setup sequence. Missing `Set-LapsADComputerSelfPermission` is the classic reason a client never stores its password.

## Policy settings and defaults

Windows LAPS reads policy from several registry roots in priority order (CSP, then Group Policy, then local configuration, then legacy LAPS) and uses the **first root that has any setting defined**. Settings are never inherited across roots, so a partial policy leaves the rest at defaults.

| Setting | Default | Supported range or values |
|---|---|---|
| `BackupDirectory` | Disabled | 0, 1 (Entra), 2 (AD) |
| `AdministratorAccountName` | Built-in Administrator (found by its well-known RID) | Custom account must already exist; Windows LAPS does not create it |
| `PasswordAgeDays` | 30 | 1-365 (minimum 7 when backing up to Entra) |
| `PasswordLength` | 14 | 8-64 |
| `PasswordComplexity` | 4 (upper, lower, digits, special) | 1-4; 5-8 are 2025/24H2-only (readability variant, passphrases) |
| `PassphraseLength` | 6 words | 3-10; Server 2025 / Windows 11 24H2 and later |
| `PostAuthenticationResetDelay` | 24 hours | 0-24; 0 disables post-authentication actions |
| `PostAuthenticationActions` | 3 (reset password and sign out) | 1 reset only, 3 reset + sign out, 5 reset + reboot, 11 reset + sign out + end processes (11 is 2025/24H2+) |
| `ADPasswordEncryptionEnabled` | True | Needs **domain functional level 2016 or later** |
| `ADPasswordEncryptionPrincipal` | Domain Admins | User or group allowed to decrypt |
| `ADEncryptedPasswordHistorySize` | 0 | 0-12 |
| `ADBackupDSRMPassword` | False | Domain controllers only |
| `PasswordExpirationProtectionEnabled` | True | Stops a password outliving its expiry via policy |

Rules worth remembering: changing `PasswordAgeDays` does not alter the current password's expiry or trigger a rotation; the password must satisfy the machine's local password policy or LAPS fails with event **10027**; a malformed `ADPasswordEncryptionPrincipal` stops the backup altogether.

**Encryption.** With AD encryption on, the password is stored in `msLAPS-EncryptedPassword`, protected so only the specified principal can decrypt it. Without it (or in emulation mode) the password is in clear text in the directory, readable by anyone with the read right.

**Post-authentication actions.** After someone *uses* a LAPS password to sign in, LAPS waits `PostAuthenticationResetDelay` hours and then rotates it, optionally signing the session out or rebooting. This shortens the life of a password that has been revealed.

## What changed in Windows Server 2025

2025 (and Windows 11 24H2) added:

- **Passphrases** (`PasswordComplexity` 6-8, `PassphraseLength` 3-10 words).
- **Improved-readability passwords** (`PasswordComplexity` 5) that avoid look-alike characters.
- **Automatic account management**: LAPS can create and manage a dedicated local admin account for you. Settings: `AutomaticAccountManagementEnabled` (default False), `AutomaticAccountManagementTarget` (0 built-in Administrator, 1 new custom account; default 1), `AutomaticAccountManagementNameOrPrefix` (default `WLapsAdmin`), `AutomaticAccountManagementEnableAccount` (default False, so the account stays disabled until needed), and `AutomaticAccountManagementRandomizeName` (adds a random six-digit suffix at every rotation; names are capped at 20 characters so the base is at most 14). When automatic management is on, `AdministratorAccountName` is ignored.
- `PostAuthenticationActions` value **11**.

> **Real world:** Randomizing the account name defeats attackers who spray the well-known `Administrator` name, but it also breaks scripts that assume the name. Pair it with `Get-LapsADPassword`, which returns the current account name along with the password.

## Troubleshooting and monitoring

Windows LAPS writes to its own operational log: **Applications and Services Logs > Microsoft > Windows > LAPS > Operational**. Use it to find why a password was not stored (permissions, schema not updated, bad policy, unsupported complexity on an older OS). An older OS that does not understand a newer value falls back to the default, so keep separate GPOs for 2022 and 2025 when you use passphrases.

OSConfig adds a `LAPS/WindowsServer/2025/MemberServer` scenario (member servers only) to apply a LAPS baseline; see the baselines lesson.

## Lab it yourself

1. On `DC01`, run `Update-LapsADSchema`, then create `OU=Servers` and move `FS01` into it.
2. Run `Set-LapsADComputerSelfPermission` for the OU, and grant `CORP\LAPS-Readers` the read permission.
3. In a new GPO linked to the OU, enable *Configure password backup directory = Active Directory*, set password age to 7 days, length 20, and enable password encryption.
4. On `FS01`, run `gpupdate /force; Invoke-LapsPolicyProcessing`, then on `DC01` run `Get-LapsADPassword -Identity FS01 -AsPlainText`.
5. Sign in to `FS01` with that password, then run `Reset-LapsPassword` and confirm the old one no longer works. Check the LAPS Operational log for the matching events.

## Key takeaways

- Windows LAPS is native in Server 2019/2022 (April 2023+) and 2025; legacy Microsoft LAPS is deprecated.
- Backup target is AD or Entra ID, never both; the default `BackupDirectory` is Disabled.
- AD setup: `Update-LapsADSchema`, then `Set-LapsADComputerSelfPermission` and the read/reset permission cmdlets.
- Defaults: 30 days, 14 characters, complexity 4, post-auth action 3 after 24 hours, encryption on with Domain Admins as the decryptor.
- Encryption needs domain functional level 2016 or later.
- 2025 adds passphrases, readable passwords, automatic account management and post-auth action 11.
- Retrieve with `Get-LapsADPassword`; rotate with `Reset-LapsPassword`; diagnose in the LAPS Operational log.
