## What Active Directory Domain Services is

Active Directory Domain Services (AD DS) is a directory database plus the services around it: authentication (Kerberos, with NTLM as a fallback), authorization data (group memberships and security identifiers), a policy engine (Group Policy) and a locator service built on DNS. The database lives on **domain controllers (DCs)**. Every writable DC holds a full copy of its own domain and replicates changes to the others, so there is no single "master" for ordinary changes.

## The logical structure

| Term | What it is | Why it matters |
|---|---|---|
| Forest | The security boundary and the outermost container. One schema, one configuration partition, one global catalog, shared by every domain in it | Enterprise Admins govern the forest; trusts between domains inside it are automatic and transitive |
| Domain | An administrative and replication unit, with its own accounts, password and lockout policy (unless a fine-grained policy overrides it) and its own domain partition | Named like `corp.example.com`, NetBIOS name `CORP` |
| Tree | Domains that share a contiguous DNS namespace, for example `corp.example.com` and `emea.corp.example.com` | A second namespace in the same forest (`fabrikam.com`) forms a second tree |
| Organizational unit (OU) | A container inside a domain for users, computers and groups | The unit you link GPOs to and delegate control on. It is not a security principal |
| Site | A set of well-connected IP subnets, mapped to physical locations | Controls client DC selection and replication scheduling |

A forest has one **schema** (the definition of object classes and attributes), and the schema and configuration partitions replicate to every DC in the forest. The domain partition replicates only inside its domain. The **global catalog (GC)** is a partial, read-only view of every object in the forest, held on DCs flagged as GC servers.

> **Exam tip:** The forest, not the domain, is the security boundary. A domain is an administrative and replication boundary. Domain Admins of one domain cannot be fully isolated from other domains in the same forest.

### Directory partitions

Every DC holds the schema, configuration and domain partitions. DNS-integrated zones add application partitions (`DomainDnsZones`, `ForestDnsZones`). Knowing which partition a change belongs to tells you how far it replicates.

## Sites and subnets

A client asks DNS for SRV records to find a DC, and uses its own IP subnet to find the **site** it belongs to. If subnets are not defined in Active Directory Sites and Services, clients cannot be matched to a site and can authenticate against a DC across a WAN. Sites also drive intersite replication: replication between sites travels over **site links** with a cost, a schedule and an interval.

## DNS and the global catalog

AD DS depends on DNS. DCs register SRV records (for example `_ldap._tcp.dc._msdcs.corp.example.com`) so clients can locate services. The usual design is to install **DNS Server** on every DC and use an AD-integrated zone, so the zone is stored in the directory and replicates with it. Member servers and clients must use the DC's DNS server as their DNS server, never a public resolver alone.

The global catalog answers forest-wide searches on TCP 3268 (3269 over TLS) and supplies universal group membership during sign-in. Make every DC a GC unless you have a reason not to; the exception to remember is the infrastructure master in a multi-domain forest (next lesson).

## Preparing and promoting a domain controller

Prerequisites: a static IP address, DNS pointing at a DC (or at itself for the first DC), a unique computer name, correct time, and the **Active Directory Domain Services** role. A new forest on Windows Server 2025 must run at the Windows Server 2016 functional level or later, and a new DC can join only a domain that is already at 2016 or later.

```powershell
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools
```

### First DC in a new forest

```powershell
$dsrm = Read-Host -AsSecureString 'DSRM password'
Install-ADDSForest -DomainName corp.example.com -DomainNetbiosName CORP `
    -InstallDns -SafeModeAdministratorPassword $dsrm
```

Parameters worth knowing for `Install-ADDSForest`: `-DomainName` (required), `-DomainNetbiosName`, `-InstallDns`, `-SafeModeAdministratorPassword` (the Directory Services Restore Mode password), `-DomainMode` and `-ForestMode`, `-DatabasePath`, `-LogPath`, `-SysvolPath`, `-NoRebootOnCompletion`, `-SkipPreChecks` and `-Force`. The cmdlet reboots the server when it completes unless you pass `-NoRebootOnCompletion`. `-CreateDnsDelegation` (with `-DnsDelegationCredential`) is only for creating a delegation in an existing parent DNS zone, so leave it off for a lab forest root.

> **Watch out:** The DSRM password is not the domain Administrator password. It is the local recovery account used in Directory Services Restore Mode. Store it; you cannot sign in to a DC for authoritative restores without it.

### Additional DC in an existing domain

```powershell
Install-ADDSDomainController -DomainName corp.example.com -InstallDns `
    -Credential (Get-Credential CORP\Administrator) `
    -SiteName 'Default-First-Site-Name' -SafeModeAdministratorPassword $dsrm
```

Useful `Install-ADDSDomainController` parameters: `-SiteName`, `-NoGlobalCatalog` (do not make it a GC), `-ReadOnlyReplica` (make it an RODC), `-InstallationMediaPath` (install from media to reduce initial replication traffic), `-ReplicationSourceDC`, `-CriticalReplicationOnly`, `-MoveInfrastructureOperationMasterRoleIfNecessary`, `-UseExistingAccount` and `-Credential`. The account must be a member of Domain Admins to add a DC to a domain; promoting into a forest for the first time, or to a new domain, needs Enterprise Admins. `Install-ADDSDomain` creates a child or new-tree domain (`-NewDomainName`, `-ParentDomainName`, `-DomainType`).

The wizard in Server Manager (flag notification, **Promote this server to a domain controller**) offers the same choices: add a DC to an existing domain, add a new domain to a forest, or add a new forest. Windows prepares the forest and domain schema (adprep) automatically when the signed-in account has the rights.

### Demoting

```powershell
Uninstall-ADDSDomainController -DemoteOperationMasterRole -LocalAdministratorPassword $pw
```

Then remove the role with `Uninstall-WindowsFeature`. Demote a DC gracefully; if it is gone for good, clean up its metadata instead (Active Directory Users and Computers removes the metadata when you delete the DC computer object, and the FSMO roles must be seized first if the DC held any).

## Verifying a healthy DC

```powershell
Get-ADDomainController -Discover -Service ADWS
dcdiag /v
Get-ADDomain | Select-Object DNSRoot, NetBIOSName, DomainMode, PDCEmulator, RIDMaster
Get-ADForest | Select-Object Name, ForestMode, SchemaMaster, DomainNamingMaster
```

Also check that `SYSVOL` and `NETLOGON` shares exist (`net share`) and that the DC registered its SRV records in DNS.

## What changed in Windows Server 2025

Only items Microsoft documents:

- **Functional level 10** (Windows Server 2025 domain and forest level) exists. The only feature it adds is the optional 32k database page size. Windows Server 2019 and 2022 introduced no new level; their highest level remains 2016.
- **New AD DS installs use a 32k-page-capable database** but run in 8k page simulation mode for compatibility. An in-place-upgraded DC keeps its 8k database.
- **LDAP signing and sealing are required by default on new Windows Server 2025 deployments**; an upgraded DC preserves existing policy.
- **Schema updates** (`sch89.ldf` to `sch91.ldf`), `fixupObjectState` to repair objects, channel-binding audit events 3074 and 3075, and improved DC locator behavior. Remote mailslots are disabled by default for DC discovery.
- Computer accounts can no longer be set to the default password (the name of the computer) by DCs that apply the policy, and ADUC and ADAC no longer create pre-Windows 2000 accounts.

## Lab it yourself

Use two Hyper-V VMs from the free evaluation, `DC01` and `DC02`, on a private virtual switch in `192.168.10.0/24`.

1. On DC01 set a static IP `192.168.10.10/24`, DNS `127.0.0.1` after promotion (point at itself).
2. **GUI:** Server Manager, **Add roles and features**, tick **Active Directory Domain Services**, then use the flag notification to promote, choose **Add a new forest**, root domain `corp.example.com`.
3. **PowerShell alternative:** run the `Install-ADDSForest` command above on a fresh DC01.
4. After the reboot run `Get-ADDomain`, `dcdiag /v` and open **Active Directory Sites and Services** to see `Default-First-Site-Name`. Add subnet `192.168.10.0/24` to it.
5. On DC02 set DNS to `192.168.10.10`, install the role and run `Install-ADDSDomainController` as shown. Confirm both DCs with `Get-ADDomainController -Filter * | Select Name, IsGlobalCatalog, Site`.
6. Check the database page size of each DC: `Get-ADObject -LDAPFilter '(ObjectClass=nTDSDSA)' -SearchBase 'CN=Configuration,DC=corp,DC=example,DC=com' -Properties msDS-JetDBPageSize | Format-List DistinguishedName,msDS-JetDBPageSize`. 32768 means 32k-capable, 8192 means an 8k database, and no value means a Windows Server 2022 or earlier DC.

## Key takeaways

- The forest is the security boundary; the domain is the replication and administrative unit; OUs are for delegation and GPO links.
- Schema and configuration replicate forest-wide; the domain partition replicates only within its domain; the GC is a partial read-only forest view.
- AD DS needs DNS; DCs register SRV records, and clients must use DC DNS servers.
- `Install-ADDSForest` creates the first DC; `Install-ADDSDomainController` adds replicas and RODCs; both need a DSRM password.
- Subnets must be mapped to sites or clients may use remote DCs.
- Windows Server 2025 adds functional level 10, a 32k-page-capable database (in 8k simulation mode until enabled) and LDAP signing required by default on new deployments.
