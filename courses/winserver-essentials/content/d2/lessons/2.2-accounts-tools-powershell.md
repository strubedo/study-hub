## User and computer accounts

Both are **security principals**: each has a SID, can be a member of groups, can be granted permissions and can authenticate. Computer accounts authenticate with a machine account password that Windows changes automatically (every 30 days by default) without any administrator action.

### User account names

| Attribute | Example | Notes |
|---|---|---|
| `sAMAccountName` (pre-Windows 2000 logon) | `CORP\jsmith` | Unique in the domain; limited to 20 characters |
| `userPrincipalName` (UPN) | `jsmith@corp.example.com` | Unique in the forest; the form used by modern clients and Microsoft Entra sync |
| Distinguished name | `CN=John Smith,OU=Sales,DC=corp,DC=example,DC=com` | Changes if you move the object |
| SID | `S-1-5-21-...-1104` | Never reused; permissions are bound to the SID, not the name |

Common account tasks: reset a password, force a change at next sign-in, unlock after lockout, disable or enable, set an expiry date, restrict logon workstations or hours, and move to an OU. A **disabled** account cannot sign in; a **locked-out** account is blocked by the lockout policy until it times out or an admin unlocks it.

### Computer accounts

A computer account is created when a machine joins the domain, in `CN=Computers` unless you pre-create it in an OU or redirect the default location with `redircmp`. `CN=Users` and `CN=Computers` are *containers*, not OUs, so you cannot link a GPO to them; move objects to your own OUs. By default an authenticated user can join up to 10 computers to the domain (`ms-DS-MachineAccountQuota`), which many organizations set to 0 and replace with a delegated join permission or a pre-staged account.

```powershell
Add-Computer -DomainName corp.example.com -OUPath 'OU=Servers,DC=corp,DC=example,DC=com' -Restart
Test-ComputerSecureChannel -Verbose
Test-ComputerSecureChannel -Repair -Credential CORP\Administrator
Reset-ComputerMachinePassword -Server DC01 -Credential CORP\Administrator
```

`Test-ComputerSecureChannel` returns `False` when the machine and domain disagree about the machine account password, the classic cause of "The trust relationship between this workstation and the primary domain failed". `-Repair` fixes it without rejoining. For machines that cannot reach a DC at join time, `djoin.exe` performs an **offline domain join** with a blob.

> **Watch out:** Windows Server 2025 DCs can refuse to set a computer account password to the default (the computer name in lowercase) when the policy **Domain controller: Refuse setting default machine account password** is enabled. ADUC and ADAC no longer allow creating pre-Windows 2000 computer accounts that rely on that default.

## ADUC and ADAC

| Tool | Command | Strengths |
|---|---|---|
| **Active Directory Users and Computers** | `dsa.msc` | Classic MMC. Create and manage users, groups, computers, OUs, delegate control, pre-create RODC accounts, **Advanced Features** view for the Attribute Editor |
| **Active Directory Administrative Center** | `dsac.exe` | Task-oriented console built on PowerShell. Has the **Windows PowerShell History** pane, which shows the exact cmdlet each GUI action ran; managing **fine-grained password policies**; restoring from the **Recycle Bin** (**Deleted Objects** container); global search and saved queries |
| **Active Directory Sites and Services** | `dssite.msc` | Sites, subnets, site links, GC and replication |
| **Active Directory Domains and Trusts** | `domain.msc` | Functional levels, trusts, UPN suffixes |
| **ADSI Edit** | `adsiedit.msc` | Raw attribute editing, use with care |
| **Group Policy Management** | `gpmc.msc` | GPOs (next topic) |

In ADUC, **View, Advanced Features** reveals the Attribute Editor tab and hidden containers. On any OU, right-click, **Properties**, **Object** tab: tick **Protect object from accidental deletion** (this adds a deny-delete ACE for Everyone, and the new-OU wizard ticks it by default).

> **Real world:** Do the task once in ADAC, read the PowerShell History pane, and you have a working script. This is the fastest way to learn the AD cmdlets.

## The Active Directory PowerShell module

The `ActiveDirectory` module talks to **Active Directory Web Services (ADWS)** on TCP 9389 on a DC. It is present on any DC and is installed on a member server or client through RSAT:

```powershell
Install-WindowsFeature RSAT-AD-PowerShell                    # server
Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0   # Windows client
Import-Module ActiveDirectory                                # auto-loads on first use
Get-Command -Module ActiveDirectory | Measure-Object
```

Cmdlets follow verb-AD-noun naming. Key ones:

| Task | Cmdlet |
|---|---|
| Find objects | `Get-ADUser`, `Get-ADComputer`, `Get-ADGroup`, `Get-ADOrganizationalUnit`, `Get-ADObject` |
| Create | `New-ADUser`, `New-ADComputer`, `New-ADGroup`, `New-ADOrganizationalUnit` |
| Change | `Set-ADUser`, `Set-ADAccountPassword`, `Set-ADAccountExpiration`, `Move-ADObject` |
| Status | `Enable-ADAccount`, `Disable-ADAccount`, `Unlock-ADAccount`, `Search-ADAccount` |
| Membership | `Add-ADGroupMember`, `Remove-ADGroupMember`, `Get-ADGroupMember`, `Get-ADPrincipalGroupMembership` |
| Delete and restore | `Remove-ADObject`, `Restore-ADObject` |
| Domain info | `Get-ADDomain`, `Get-ADForest`, `Get-ADDomainController` |

```powershell
$pw = Read-Host -AsSecureString 'Initial password'
New-ADOrganizationalUnit -Name Sales -Path 'DC=corp,DC=example,DC=com'
New-ADUser -Name 'John Smith' -SamAccountName jsmith -UserPrincipalName jsmith@corp.example.com `
    -Path 'OU=Sales,DC=corp,DC=example,DC=com' -AccountPassword $pw -Enabled $true `
    -ChangePasswordAtLogon $true
Get-ADUser jsmith -Properties LastLogonDate, PasswordLastSet, LockedOut, MemberOf
Search-ADAccount -LockedOut | Unlock-ADAccount
Search-ADAccount -AccountInactive -TimeSpan 90.00:00:00 -UsersOnly
```

### Filters and properties

`-Filter` uses PowerShell-style syntax (for example `-Filter "Department -eq 'Sales'"`), `-LDAPFilter` takes raw LDAP (`(&(objectClass=user)(department=Sales))`), and `-SearchBase` / `-SearchScope` limit where to look. `Get-ADUser` returns only a default set of properties; ask for others with `-Properties`, or `-Properties *` for everything. A user created with `New-ADUser` is **disabled** and has no password unless you set one and pass `-Enabled $true`; a blank or non-compliant password fails the password policy.

Bulk creation from a CSV is a standard exam scenario:

```powershell
Import-Csv .\newusers.csv | ForEach-Object {
    New-ADUser -Name "$($_.First) $($_.Last)" -SamAccountName $_.Sam -Path $_.OU `
        -AccountPassword (ConvertTo-SecureString $_.Pw -AsPlainText -Force) -Enabled $true
}
```

> **Exam tip:** `Get-ADUser -Filter *` returns every user; `Search-ADAccount -LockedOut` and `-AccountDisabled` find accounts by status. `-WhatIf` works on all changing cmdlets.

## Lab it yourself

1. On DC01 open ADAC (`dsac.exe`), create an OU `Sales` and a user `jsmith` through the **New, User** form. Open the **Windows PowerShell History** pane at the bottom and copy the `New-ADUser` command it generated.
2. Re-create two more users with PowerShell from a CSV as above.
3. In ADUC, enable **Advanced Features**, open `jsmith`, and view the Attribute Editor. Compare `sAMAccountName`, `userPrincipalName` and `objectSid`.
4. Join `FS01` to the domain with `Add-Computer`, then find its account with `Get-ADComputer FS01 -Properties OperatingSystem, PasswordLastSet`. Move it to an `OU=Servers` OU with `Move-ADObject`.
5. Break the channel: stop FS01, run `Reset-ComputerMachinePassword` on a copy, or restore an old checkpoint, then repair it with `Test-ComputerSecureChannel -Repair`.

## Key takeaways

- Users and computers are security principals identified by SIDs; the UPN is forest-unique and `sAMAccountName` is domain-unique (max 20 characters).
- Default `Users` and `Computers` are containers, not OUs; you cannot link GPOs to them.
- ADAC's PowerShell History pane shows the cmdlet behind each GUI action.
- The `ActiveDirectory` module uses ADWS (TCP 9389) and installs with `RSAT-AD-PowerShell`.
- `New-ADUser` creates a disabled account unless you set a password and `-Enabled $true`.
- `Test-ComputerSecureChannel -Repair` fixes a broken machine account trust without rejoining.
