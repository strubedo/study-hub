## Why FSMO roles exist

Active Directory is multi-master: any writable DC accepts changes. A few operations cannot safely be multi-master, so they are assigned to a single DC at a time. These are the **Flexible Single Master Operations (FSMO)** roles, also called operations master roles. There are five: two per forest and three per domain.

| Role | Scope | Held by default | What it does | If it is offline |
|---|---|---|---|---|
| Schema master | Forest (1) | First DC in the forest | Only DC that accepts schema changes | No schema updates (adprep, Exchange-style extensions); everything else works |
| Domain naming master | Forest (1) | First DC in the forest | Adds and removes domains and application partitions | You cannot add or remove a domain or a DNS application partition |
| PDC emulator | Domain (1 per domain) | First DC in the domain | Processes password changes and forwards bad-password attempts, is the time source for the domain, is the default DC for GPMC, and takes urgent replication of password changes | Time drifts, password changes and lockouts behave inconsistently, DC-based GPO editing defaults break. The most noticeable role to lose |
| RID master | Domain (1 per domain) | First DC in the domain | Hands each DC a pool of relative IDs (RIDs) so every new SID is unique | DCs keep creating objects until their pool runs out, then new users, groups and computers fail |
| Infrastructure master | Domain (1 per domain) | First DC in the domain | Updates references (names and SIDs) to security principals in other domains that are members of its groups | Stale cross-domain group member names; nothing visible in a single-domain forest |

Microsoft's placement guidance says the roles are assigned automatically to the first DC in the forest (schema and domain naming) and the first DC in each domain (the other three), and that you should keep the PDC emulator and RID master on reliable, well-connected DCs. The default RID pool handed to a DC is 500 RIDs (documented in the Active Directory technical specifications; the Learn operations-master page does not state the number).

> **Exam tip:** Five roles, 2 forest-wide and 3 per domain. A forest with three domains has 2 + 3 x 3 = 11 FSMO role instances.

### The infrastructure master rule

Do not put the infrastructure master on a global catalog server in a multi-domain forest, because a GC already holds partial data for every domain and the role would never find anything to update. Two documented exceptions make it irrelevant: every DC is a GC, or the forest has only one domain. In a single-domain forest, which is what most labs and small businesses run, this rule does not matter.

## Finding, moving and seizing roles

```powershell
Get-ADForest | Select-Object SchemaMaster, DomainNamingMaster
Get-ADDomain | Select-Object PDCEmulator, RIDMaster, InfrastructureMaster
netdom query fsmo
```

**Transfer** is the planned, clean move; both DCs are online and the old holder hands over its state:

```powershell
Move-ADDirectoryServerOperationMasterRole -Identity DC02 `
    -OperationMasterRole PDCEmulator, RIDMaster, InfrastructureMaster
```

The `-OperationMasterRole` values are `PDCEmulator`, `RIDMaster`, `InfrastructureMaster`, `SchemaMaster` and `DomainNamingMaster` (or the numbers 0 to 4). GUI equivalents: **Active Directory Users and Computers** (PDC, RID, Infrastructure through **Operations Masters**), **Active Directory Domains and Trusts** (domain naming master) and the **Active Directory Schema** snap-in (schema master). The Schema snap-in must be registered with `regsvr32 schmmgmt.dll` first.

**Seize** is the emergency path when the holder is permanently dead: add `-Force` to the same cmdlet (`Move-ADDirectoryServerOperationMasterRole -Identity DC02 -OperationMasterRole RIDMaster -Force`) or use `ntdsutil` (`roles`, `connections`, `seize ...`). After seizing, **never bring the old holder back online** with its old copy of the directory, especially for the RID master, schema master or domain naming master. Duplicate role holders and duplicate RID pools corrupt the directory. If the old DC returns, format it or clean its metadata and rebuild it.

> **Watch out:** Use transfer for maintenance, demotion and decommissioning. Demoting a DC with `Uninstall-ADDSDomainController -DemoteOperationMasterRole` moves the roles to another DC for you.

## Functional levels

A **domain functional level (DFL)** and **forest functional level (FFL)** define the oldest DC operating system a domain or forest allows and unlock features that depend on it. Raising a level does not need hardware or an OS change; it needs every DC to meet the new minimum.

| Level | Numeric value (`-DomainMode`) | Oldest DC allowed | Notes |
|---|---|---|---|
| Windows Server 2012 R2 | 6 | 2012 R2 | Not supported with a Windows Server 2025 DC |
| Windows Server 2016 | 7 (`WinThreshold`) | 2016 | Highest level for 2019 and 2022; minimum for any new forest or new DC on 2025 |
| Windows Server 2025 | 10 | 2025 | Only 2025 DCs allowed; required for the 32k database page feature |

The interoperability matrix in Microsoft's functional-level article shows a 2025 DC at the 2025 or 2016 level, a 2022, 2019 or 2016 DC at the 2016 or 2012 R2 level, and a 2012 R2 DC at 2012 R2 only. Windows Server 2019 and 2022 never introduced their own levels, and Microsoft has no plans to retrofit them.

### Raising a level

Raise every domain first, then the forest. The forest level cannot be higher than any domain level, and a domain level can exceed the forest level.

```powershell
Set-ADDomainMode -Identity corp.example.com -DomainMode Windows2025Domain
Set-ADForestMode -Identity corp.example.com -ForestMode Windows2025Forest
Get-ADDomain  | Select-Object DomainMode
Get-ADForest  | Select-Object ForestMode
```

GUI: **Active Directory Domains and Trusts** (right-click the domain, **Raise Domain Functional Level**; right-click the root node, **Raise Forest Functional Level**). Raising is a one-way operation for practical purposes, so test replication health first: `repadmin /replsummary` and `dcdiag`. In a Hyper-V lab, take a checkpoint of both DCs before raising, then delete the checkpoint afterwards (restoring one DC from a snapshot into a live domain causes USN rollback).

### Optional features gated on the level

- **Active Directory Recycle Bin** needs forest level 2008 R2 or higher, and cannot be disabled once enabled:
  ```powershell
  Enable-ADOptionalFeature 'Recycle Bin Feature' -Scope ForestOrConfigurationSet -Target corp.example.com
  ```
  Deleted objects keep all attributes and can be restored with `Get-ADObject -Filter 'isDeleted -eq $true' -IncludeDeletedObjects | Restore-ADObject`.
- **Database 32k pages** (new in 2025) needs every DC on Windows Server 2025 with a 32k-capable database, domain and forest at level 10, and Enterprise Admins rights:
  ```powershell
  Enable-ADOptionalFeature -Identity 'Database 32k pages feature' `
      -Scope ForestOrConfigurationSet -Target corp.example.com
  ```
  It is forest-wide and cannot be reverted. After it is on, only 32k-format backups can restore a 2025 DC, and older 8k backups are unusable except through a complete authoritative forest recovery. Multi-valued attributes can then hold about 3,200 values, up from roughly 1,200 to 1,300 values with 8k pages (Microsoft's replication-error 8304 article).

> **Exam tip:** Level 10 is the new Windows Server 2025 forest and domain functional level. It adds only the 32k page feature and is supported only with 2025 DCs. Raise it only after all DCs are 2025.

## Lab it yourself

1. On DC01 run `netdom query fsmo` and the two `Get-AD*` commands; all five roles are on DC01.
2. Transfer the PDC emulator and RID master to DC02 with `Move-ADDirectoryServerOperationMasterRole`, then re-run `netdom query fsmo`. GUI equivalent: ADUC, right-click the domain, **Operations Masters**, change on the **PDC** and **RID** tabs while connected to DC02.
3. Run `w32tm /query /source` on DC02 and DC01. Both should now follow the domain time hierarchy rooted at the forest PDC emulator, not the VM host clock.
4. Check `Get-ADDomain | Select DomainMode` and `Get-ADForest | Select ForestMode`. If they are not already `Windows2025Domain` and `Windows2025Forest`, raise them in Active Directory Domains and Trusts after taking VM checkpoints.
5. Enable the Recycle Bin with the command above, delete a test user, and bring it back with `Restore-ADObject`.

## Key takeaways

- Five FSMO roles: schema master and domain naming master once per forest; PDC emulator, RID master and infrastructure master once per domain.
- Transfer for planned moves, seize with `-Force` or `ntdsutil` only when the holder is permanently lost, and never return a seized-from DC to service.
- The PDC emulator matters most day to day (time, password changes, lockouts); the infrastructure master must not share a GC in a multi-domain forest.
- Windows Server 2025 adds functional level 10; 2019 and 2022 reuse level 7 (2016).
- A 2025 DC cannot operate at a functional level below 2016.
- Recycle Bin and 32k pages are one-way forest-wide optional features enabled with `Enable-ADOptionalFeature`.
