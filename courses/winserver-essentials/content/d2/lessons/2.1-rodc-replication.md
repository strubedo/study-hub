## Read-only domain controllers

A **read-only domain controller (RODC)** holds a read-only copy of the AD DS database and of SYSVOL, and it never accepts or originates directory changes. It is meant for branch offices and other places where physical security is weak, the link to the main site is slow or unreliable, or no local administrator should have full DC rights.

### What makes an RODC different

| Feature | Writable DC | RODC |
|---|---|---|
| Directory changes | Accepts and replicates them | Rejects them; clients are referred to a writable DC |
| Replication | Two-way with partners | **One-way inbound only**, from a writable DC; nothing replicates out of an RODC |
| Account secrets | All stored | Only the accounts allowed by the Password Replication Policy |
| Local administration | Domain-level rights | **Administrator role separation**: a delegated user or group can be local administrator of the RODC without domain rights |
| DNS | Writable copy of AD-integrated zones | Read-only copy of the zones (clients that need to register records are redirected to a writable DNS server) |
| Global catalog | Optional | Optional |

Each RODC gets its own Kerberos account, `krbtgt_<number>`, so a compromised RODC cannot be used to forge tickets for the whole domain. If a user whose credentials are not cached signs in at the branch, the RODC forwards the authentication request to a writable DC, so the WAN link still matters for those users. If the link is down, users with cached credentials can still sign in; others cannot.

### Password Replication Policy (PRP)

The PRP decides whose password secrets the RODC may cache. Two lists live on each RODC computer object, and two security groups feed them:

- **Allowed RODC Password Replication Group**: domain local group, no members by default, so a new RODC caches no user credentials until you decide.
- **Denied RODC Password Replication Group**: contains high-privilege accounts and groups (such as Domain Admins and Enterprise Admins, and the krbtgt accounts). Deny always supersedes allow.

```powershell
Add-ADDomainControllerPasswordReplicationPolicy -Identity RODC01 `
    -AllowedList 'CN=Branch Users,OU=Groups,DC=corp,DC=example,DC=com'
Get-ADDomainControllerPasswordReplicationPolicy -Identity RODC01 -Allowed
```

> **Exam tip:** Add accounts that sign in at the branch to the allowed list; keep privileged accounts in the denied list. The recommended pattern is a global group of branch users added to the RODC's allowed list, with a **pre-populated** cache so the first morning sign-in does not need the WAN.

### Deploying an RODC

Two common paths:

1. **Direct promotion**, using the same cmdlet as any replica DC with `-ReadOnlyReplica`:
   ```powershell
   Install-ADDSDomainController -DomainName corp.example.com -ReadOnlyReplica `
       -SiteName 'Branch1' -InstallDns `
       -DelegatedAdministratorAccountName 'CORP\Branch1-Admins' `
       -Credential (Get-Credential CORP\Administrator) -SafeModeAdministratorPassword $dsrm
   ```
   `-AllowPasswordReplicationAccountName` and `-DenyPasswordReplicationAccountName` set the PRP in the same command. `-DelegatedAdministratorAccountName` enables role separation. `-NoGlobalCatalog` and `-InstallationMediaPath` also apply.
2. **Staged (delegated) installation**: a domain admin pre-creates the RODC account, and a local user at the branch finishes it without domain admin rights.
   ```powershell
   Add-ADDSReadOnlyDomainControllerAccount -DomainControllerAccountName RODC01 `
       -DomainName corp.example.com -SiteName Branch1 `
       -DelegatedAdministratorAccountName 'CORP\Branch1-Admins'
   ```
   On the branch server run the promotion with `-UseExistingAccount`. In Active Directory Users and Computers you can also right-click the **Domain Controllers** OU and choose **Pre-create Read-only Domain Controller account**.

A writable DC must exist in the domain, and the RODC's site needs a site link to a site that has a writable DC so it has a replication source.

> **Watch out:** An RODC is not a backup DC for a site that needs writes. It cannot hold FSMO roles, and cmdlets such as `Complete-ADServiceAccountMigration` and password-changing applications do not work against it.

## Replication basics

All DCs in a domain must converge on the same data. Replication is:

- **Multi-master** for ordinary data between writable DCs (the RODC being the one-way exception).
- **Pull-based, notified by push**: a DC that changes data sends a *notification* to its partners, which then *pull* the changes.
- **Per directory partition**: schema and configuration go forest-wide; each domain partition goes only to that domain's DCs; GCs also pull a partial attribute set of other domains; application partitions go to the DCs that host them.
- Driven by **USNs** (update sequence numbers) and **up-to-dateness vectors**, so a DC only transfers what a partner does not already have. Conflicts are resolved by version number, then timestamp, then DC GUID.

### Intrasite and intersite

| Aspect | Within a site | Between sites |
|---|---|---|
| Topology | Built automatically by the **Knowledge Consistency Checker (KCC)** as a ring with no more than three hops between any two DCs (extra shortcuts are added as DCs grow) | One **Inter-Site Topology Generator (ISTG)** per site builds connections over **site links** through **bridgehead servers** |
| Trigger | Change notification after 15 seconds to the first partner and 3 seconds to each other partner by default | Schedule and interval. Notification is **off** by default |
| Interval | Event-driven; urgent replication for a few critical events (below) | Site link replication interval, default **180 minutes**, minimum 15 |
| Compression | None | Compressed |

Site links have a **cost**; the cheapest path wins. Site link bridging is on by default, so links are transitive. A site link is created in **Active Directory Sites and Services** under **Inter-Site Transports**, **IP**.

Urgent replication, sent immediately instead of waiting 15 seconds, applies to a short list of events: account lockout, changes to the account lockout policy or domain password policy, a DC computer account password change, a change of RID master role owner, and changes to local security authority secrets.

### The KCC and SYSVOL

The KCC runs on every DC, by default about every 15 minutes, and rebuilds connection objects when DCs are added or fail. Do not create manual connections unless you have a clear reason. SYSVOL (the Policies and Scripts folders) is replicated by **DFS Replication**, not by the AD replication engine. If a GPO exists in AD but its files are missing on a DC, the problem is SYSVOL replication, not AD replication.

### Checking health

```powershell
repadmin /replsummary
repadmin /showrepl DC02
repadmin /syncall /AdeP
Get-ADReplicationFailure -Target DC02
Get-ADReplicationPartnerMetadata -Target DC02 | Select Partner, LastReplicationSuccess
dcdiag /test:replications
```

`repadmin /replsummary` summarises failures per DC. A DC that has not replicated within the **tombstone lifetime** (180 days by default on new forests) can have lingering objects and may need to be demoted and rebuilt. Raising the 32k page feature should be preceded by a clean `repadmin /replsummary`.

## Lab it yourself

1. In **Active Directory Sites and Services** create a site `Branch1`, add subnet `192.168.20.0/24` to it, and create an IP site link `HQ-Branch1` with cost 100 and interval 15 minutes.
2. Add a third VM `RODC01` on `192.168.20.0/24` pointing DNS at DC01. Promote it with the `-ReadOnlyReplica` command above (or the Server Manager wizard: **Add a domain controller to an existing domain**, tick **Read only domain controller (RODC)**).
3. In ADUC open the properties of the `RODC01` computer account, **Password Replication Policy** tab, and add a test group to the allowed list. Click **Advanced** to see which accounts are cached.
4. Create a user in a writable DC, then run `repadmin /showrepl` on RODC01 and `Get-ADUser jsmith -Server RODC01` to see it replicate.
5. Try to create a user on RODC01 (`New-ADUser -Server RODC01 ...`) and note the referral error.

## Key takeaways

- RODCs are one-way inbound, cache only the passwords the PRP allows, and give delegated local administration through role separation.
- Deny supersedes allow in the Password Replication Policy; the Denied RODC Password Replication Group protects privileged accounts.
- `Install-ADDSDomainController -ReadOnlyReplica` promotes an RODC; `Add-ADDSReadOnlyDomainControllerAccount` stages one.
- Intrasite replication is notification-driven (15 s then 3 s); intersite is scheduled over site links (default 180 minutes) through bridgeheads chosen by the ISTG.
- KCC builds topology; `repadmin /replsummary`, `/showrepl`, `/syncall` and `Get-ADReplicationFailure` diagnose it.
- SYSVOL replicates with DFS Replication, separate from AD replication.
