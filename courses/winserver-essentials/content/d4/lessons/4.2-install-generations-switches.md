## Installing the Hyper-V role

Hyper-V is a Windows Server role that installs a type 1 hypervisor beneath the management operating system. The host needs a 64-bit processor with **second-level address translation (SLAT)**, VM Monitor Mode Extensions, hardware-assisted virtualization turned on in firmware (Intel VT or AMD-V), and hardware-enforced Data Execution Prevention (the XD or NX bit). Plan for at least 4 GB of RAM, and far more in practice because every VM needs its own.

```powershell
Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart
Get-WindowsFeature Hyper-V
```

On Server Core, `-IncludeManagementTools` installs only the Hyper-V PowerShell module; run Hyper-V Manager from another machine and connect to the host. In Server Manager the wizard also offers to create a virtual switch, set up live migration and choose default storage locations. Members of the local **Administrators** or **Hyper-V Administrators** group can manage VMs.

Set the default storage paths so VM files do not land on the system volume:

```powershell
Set-VMHost -VirtualMachinePath 'D:\Hyper-V\VMs' -VirtualHardDiskPath 'D:\Hyper-V\VHDs'
```

Host and VM limits for Windows Server 2025, from Microsoft's scalability page:

| Item | Maximum |
|---|---|
| Logical processors per host | 2,048 |
| Host memory | 4 PB with 5-level paging; 256 TB with 4-level paging |
| Running VMs per host | 1,024 |
| Virtual processors per VM | 2,048 (Generation 2, set with PowerShell only); 64 (Generation 1) |
| Memory per VM | 240 TB (Generation 2); 1 TB (Generation 1) |
| Virtual hard disk size | 64 TB (VHDX); 2,040 GB (VHD) |
| Virtual SCSI controllers; SCSI disks | 4; 256 |
| Virtual network adapters | 64 (Generation 2); 8 plus 4 legacy (Generation 1) |
| Checkpoints per VM | 50 (storage permitting) |

> **Exam tip:** Remember the pairs: 240 TB and 2,048 vCPUs for Generation 2, and 1 TB and 64 vCPUs for Generation 1. A guest operating system may support less than Hyper-V does, so always check the guest's own limits.

Windows Server 2025 also changes NUMA behavior. A VM that needs more virtual cores than a single physical NUMA node can offer no longer silently spans nodes: you must enable NUMA spanning on both the host and the VM, and Microsoft advises benchmarking your workload first. Other 2025 Hyper-V additions are GPU partitioning with live migration, **dynamic processor compatibility** for clusters, and **workgroup clusters** whose nodes are not domain joined.

## Generation 1 vs Generation 2

You choose a VM's generation at creation time and **cannot change it afterward**. Generation is a property of the VM, not of the VHDX, which is why a bootable VHDX built for one generation will not boot on the other.

| Feature | Generation 1 | Generation 2 |
|---|---|---|
| Firmware | Legacy BIOS | UEFI |
| Boot disk controller | IDE | SCSI (boot from VHDX on SCSI) |
| Secure Boot | No | Yes, enabled by default |
| Virtual TPM, shielded VMs | No | Yes |
| Network adapters | Synthetic and legacy | Synthetic only; PXE boot over IPv4 or IPv6 |
| Floppy, legacy COM, PS/2 devices | Yes | No (COM ports can be added for debugging, which requires disabling Secure Boot) |
| Boot volume maximum | 2 TB (VHDX), 2,040 GB (VHD) | 64 TB (VHDX) |
| Online boot-disk resize | No | Yes |
| Guest OS | Older 32-bit and legacy 64-bit systems | Supported 64-bit Windows and many Linux distributions |
| DVD drive | Physical or ISO | ISO images only; `New-VM` creates none by default |

Microsoft's guidance is to choose Generation 2 unless you use an existing BIOS-based VHD, need an operating system Generation 2 does not support, or need a boot method it lacks. Secure Boot has templates: use **Microsoft Windows** for Windows guests, **Microsoft UEFI Certificate Authority** for most Linux distributions, and **Open Source Shielded VM** for Linux shielded VMs. If a Linux ISO will not boot on a new Generation 2 VM, the Secure Boot template is the first thing to check.

```powershell
New-VM -Name APP01 -Generation 2 -MemoryStartupBytes 4GB -NewVHDPath 'D:\Hyper-V\VHDs\APP01.vhdx' `
       -NewVHDSizeBytes 60GB -SwitchName 'External'
Set-VMFirmware -VMName APP01 -EnableSecureBoot On -SecureBootTemplate MicrosoftUEFICertificateAuthority
```

> **Watch out:** Generation 2 does not support a physical CD or DVD drive, and Microsoft does not support running a UEFI shell or arbitrary UEFI applications in the guest.

## Virtual switches

A Hyper-V virtual switch is a software Layer 2 Ethernet switch. It connects VM network adapters to each other and, depending on type, to the host and the physical network. There are three types:

| Type | VMs reach each other | VMs reach the management OS | VMs reach the physical network | Typical use |
|---|---|---|---|---|
| External | Yes | Optional (share the adapter) | Yes, through a physical NIC | Production VMs |
| Internal | Yes | Yes | No | Lab networks with host access, NAT |
| Private | Yes | No | No | Fully isolated test segments |

```powershell
# External: the NetAdapterName parameter implies the type
New-VMSwitch -Name 'External' -NetAdapterName 'Ethernet' -AllowManagementOS $true

# Internal or private
New-VMSwitch -Name 'LabInternal' -SwitchType Internal
New-VMSwitch -Name 'LabIsolated' -SwitchType Private

Connect-VMNetworkAdapter -VMName APP01 -SwitchName 'LabInternal'
Set-VMNetworkAdapterVlan -VMName APP01 -Access -VlanId 20
```

An external switch binds to one physical adapter (or a team) and optionally shares it with the management OS (`-AllowManagementOS`), which creates a `vEthernet (name)` adapter on the host. When you bind the switch to the only NIC, the host briefly loses connectivity, so do it from the console or with care over remote sessions. VLAN tagging is set per VM adapter with `Set-VMNetworkAdapterVlan`, in access or trunk mode. For host teaming, a Hyper-V switch can use **Switch Embedded Teaming** (`-EnableEmbeddedTeaming $true`). Hyper-V's virtual switch supports Ethernet only.

For an isolated lab that still needs internet access, create an internal switch, give the host adapter an address and use `New-NetNat` to NAT the subnet.

> **Exam tip:** "VMs and the host must communicate but VMs must not reach the physical LAN" is **Internal**. "VMs must be completely isolated from the host and the network" is **Private**. Only **External** touches a physical NIC.

## Lab it yourself

The cleanest lab for the whole Hyper-V topic is nested virtualization: run Hyper-V inside a VM on your laptop. Microsoft supports this on Intel VT-x with EPT (host Windows Server 2016 or later, or Windows 10 or later) and on recent AMD EPYC and Ryzen processors (host Windows Server 2022 or later, or Windows 11 or later).

1. On the laptop's Hyper-V, create a Generation 2 VM named `HV01` with at least 4 vCPUs and 8 GB of RAM, and install Windows Server 2025 from the evaluation ISO.
2. With HV01 powered off, run on the laptop:
   `Set-VMProcessor -VMName HV01 -ExposeVirtualizationExtensions $true`
   `Get-VMNetworkAdapter -VMName HV01 | Set-VMNetworkAdapter -MacAddressSpoofing On`
   Nested virtualization requires the outer VM to be off when you change this, and dynamic memory does not resize while Hyper-V runs inside the VM, so give it a fixed amount.
3. Inside HV01 run `Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart`.
4. Create one switch of each type with `New-VMSwitch`, create a Generation 1 and a Generation 2 VM, and compare `Get-VMFirmware`, `Get-VMBios`, and the devices shown by `Get-VMHardDiskDrive`.
5. Try to change the generation of a VM in Hyper-V Manager (you cannot).

## Key takeaways

- Install with `Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart`; hardware needs SLAT, VT or AMD-V, and DEP.
- 2025 limits: 2,048 vCPUs and 240 TB RAM for Generation 2; 64 vCPUs and 1 TB for Generation 1; VHDX to 64 TB.
- Generation 2: UEFI, Secure Boot (default on), vTPM, SCSI boot, 64 TB boot disk, no legacy devices; generation cannot be changed later.
- Use the UEFI CA Secure Boot template for most Linux guests.
- External, Internal and Private switches differ by who the VMs can reach; `-NetAdapterName` implies External.
- Nested virtualization needs `ExposeVirtualizationExtensions`, MAC address spoofing on the outer VM's adapter, and the VM off when you set it.
- 2025 adds NUMA-spanning rules, dynamic processor compatibility and workgroup clusters.
