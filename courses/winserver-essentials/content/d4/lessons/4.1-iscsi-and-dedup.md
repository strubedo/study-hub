## iSCSI in one picture

**iSCSI** carries SCSI block commands over ordinary TCP/IP networks. A server that offers storage is the **target**; a server that consumes it is the **initiator**. To the initiator, an iSCSI LUN looks like a locally attached raw disk, which it then initializes, partitions and formats like any other. The default iSCSI TCP port is **3260**.

| Term | Meaning |
|---|---|
| iSCSI Target Server | The Windows Server role service that serves virtual disks as LUNs |
| iSCSI virtual disk | A **VHDX file** on the target server that backs a LUN |
| iSCSI target | The named endpoint (an **IQN**) that initiators log in to; one target can map several virtual disks |
| Initiator | The client, built into Windows as the **Microsoft iSCSI Initiator** (service `MSiSCSI`) |
| Target portal | The IP address and port of the target server that the initiator discovers |
| IQN | iSCSI Qualified Name, for example `iqn.1991-05.com.microsoft:fs01.corp.example.com` |

> **Exam tip:** The target server stores LUNs as `.vhdx` files. The file must use a `.vhdx` extension and cannot live on a network share or in a compressed, sparse or transacted folder.

## Setting up the target (HV01 or FS01 as the storage server)

The role service is `FS-iSCSITarget-Server` under File and Storage Services. The cmdlets come from the `IscsiTarget` module:

```powershell
Install-WindowsFeature -Name FS-iSCSITarget-Server -IncludeManagementTools

# Create a 100 GB virtual disk (dynamic by default; -UseFixed for fixed)
New-IscsiVirtualDisk -Path 'E:\iSCSIVirtualDisks\LUN1.vhdx' -Size 100GB

# Create a target and say which initiators may log in
New-IscsiServerTarget -TargetName 'Target1' `
  -InitiatorIds @('IPAddress:192.168.10.21','IPAddress:192.168.10.22')

# Map the virtual disk to the target
Add-IscsiVirtualDiskTargetMapping -TargetName 'Target1' `
  -Path 'E:\iSCSIVirtualDisks\LUN1.vhdx' -Lun 0
```

`-InitiatorIds` identifies who may connect. Identifiers can be an IQN (`IQN:...`), IP address (`IPAddress:...`), DNS name or MAC address; an initiator not listed cannot see the target. LUN numbers must be unique per target. `Get-IscsiVirtualDisk`, `Get-IscsiServerTarget` and `Remove-IscsiVirtualDisk` inspect and clean up. `Import-IscsiVirtualDisk` attaches a VHDX that already exists, because `New-IscsiVirtualDisk` returns an error for a path that exists. Windows Firewall rules for the iSCSI Service are created when the role service is added, but check them if discovery fails.

## Connecting the initiator

```powershell
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI

New-IscsiTargetPortal -TargetPortalAddress 192.168.10.5
Get-IscsiTarget
Connect-IscsiTarget -NodeAddress 'iqn.1991-05.com.microsoft:fs01-target1-target' -IsPersistent $true

# The LUN now appears as a raw disk
Get-Disk | Where-Object BusType -eq 'iSCSI'
```

`-IsPersistent $true` re-establishes the session at boot. Without it the disk disappears after a restart, a classic exam scenario. After connecting, use `Initialize-Disk`, `New-Partition` and `Format-Volume` exactly as with a local disk. Multiple initiators writing to the same LUN need a cluster-aware file system such as a Cluster Shared Volume, not plain NTFS, or the volume will be corrupted.

> **Watch out:** iSCSI traffic is not encrypted by default. Put it on a dedicated VLAN or physical network, use CHAP authentication where supported, and use MPIO (the Multipath I/O feature) for redundant paths.

## Data Deduplication

**Data Deduplication** reduces space by storing each unique chunk of data once. Files are split into variable-size chunks, unique chunks go into a **chunk store** in the System Volume Information folder, optionally compressed, and the original file becomes a reparse point pointing at the chunks. A file system filter (`Dedup.sys`) makes this transparent to applications. It is a **post-processing** feature: new or changed files are written normally and optimized later by scheduled jobs, so it needs idle time. It is not enabled by default.

Install it with the `FS-Data-Deduplication` feature:

```powershell
Install-WindowsFeature -Name FS-Data-Deduplication
Enable-DedupVolume -Volume 'E:' -UsageType Default
Get-DedupVolume
Get-DedupStatus
Start-DedupJob -Volume 'E:' -Type Optimization
```

The three **usage types** set sensible policies:

| Usage type | Target workload | Min file age | Optimize in-use files | Optimize partial files |
|---|---|---|---|---|
| Default | General purpose file server: team shares, Work Folders, folder redirection, software shares | 3 days | No | No |
| HyperV | VDI servers | 3 days | Yes | Yes |
| Backup | Virtualized backup apps such as DPM | 0 days | Yes | No |

Job types are **Optimization** (chunk, deduplicate), **GarbageCollection** (reclaim unreferenced chunks) and **Scrubbing** (integrity check). `Set-DedupVolume` changes settings such as `-MinimumFileAgeDays`, `-ExcludeFolder` and `-ExcludeFileType`; `Get-DedupSchedule` and `Set-DedupSchedule` control timing. Run the free **DDPEval.exe** evaluation tool (installed with the feature in `C:\Windows\System32`) before enabling it to see predicted savings on a volume or share.

Facts to know:

- **Recommended workloads**: general purpose file servers, VDI, and virtualized backup. General Hyper-V hosts, SQL and line-of-business servers might benefit but should be evaluated first, because the random reads of database-like workloads suit flash better than spinning disks.
- **Memory**: at minimum 300 MB plus 50 MB per TB of logical data; optimally about 1 GB per TB.
- **Volumes**: supported on NTFS, and on ReFS since Windows Server 2019; Microsoft documents volumes of up to 64 TB, and the cmdlet will not enable dedup on a volume smaller than 2 GB. Only files of at least 32 KB are considered. It is not supported on volumes with multiple storage tiers.
- **Failover clusters**: every node needs the feature installed. Dedup is supported on Storage Spaces Direct volumes (mirror or parity).
- **Not supported or discouraged**: nested virtualization (do not enable dedup inside a lab VM that hosts other VMs), Windows 10 clients, Windows Search indexing of deduplicated files, Robocopy copying the chunk store, and a hard quota on the root of a deduplicated volume (a soft quota is fine).
- **Backup**: Windows Server Backup backs up an optimized volume as-is. Configure Storage Replica so dedup does not run on the secondary copy.

> **Exam tip:** Dedup is post-processing and per volume, not inline. Savings appear after the optimization job runs and only for files older than the minimum file age. `Enable-DedupVolume` without `-UsageType` is not the same as picking one; always specify the type that matches the workload.

> **Real world:** Dedup on a VDI or file server volume often saves more than half the space, while already-compressed media and encrypted data save almost nothing. Run DDPEval first and set expectations from its numbers.

## Lab it yourself

Run both roles in one lab VM, or use two VMs on an internal switch named `Lab`.

1. On FS01 install `FS-iSCSITarget-Server`, create a 20 GB iSCSI virtual disk and a target that allows the initiator's IP address, and map the disk.
2. On HV01 (or a second VM) start `MSiSCSI`, add the portal, connect the target with `-IsPersistent $true`, then initialize and format the new disk as NTFS with a 64 KB allocation unit.
3. Reboot the initiator and confirm the disk returns. Repeat once without `-IsPersistent` to see it drop.
4. Install `FS-Data-Deduplication` on the initiator. Copy a few copies of the same ISO to the volume, run `DDPEval.exe E:\`, then `Enable-DedupVolume -Volume E: -UsageType Default -MinimumFileAgeDays 0` and `Start-DedupJob -Volume E: -Type Optimization`.
5. Check `Get-DedupStatus` for SavedSpace. If your lab host runs the VMs on a nested Hyper-V setup, remember Microsoft does not support dedup inside a nested-virtualization VM that hosts other VMs; a data disk for test files is fine for learning, not for production.

## Key takeaways

- iSCSI uses TCP port 3260; the target stores LUNs as VHDX files and the initiator sees raw disks.
- Target workflow: `New-IscsiVirtualDisk`, `New-IscsiServerTarget -InitiatorIds`, `Add-IscsiVirtualDiskTargetMapping`.
- Initiator workflow: start `MSiSCSI`, `New-IscsiTargetPortal`, `Connect-IscsiTarget -IsPersistent $true`, then initialize and format.
- Isolate or secure iSCSI traffic; use CHAP and MPIO; shared LUNs need a cluster-aware file system.
- Data Deduplication is post-processing, per volume, with usage types Default, HyperV and Backup.
- Default policy skips files younger than three days; Backup uses zero days; HyperV optimizes open files.
- Dedup works on NTFS and ReFS (2019+), not on volumes with multiple tiers, and needs memory sized to the data.
