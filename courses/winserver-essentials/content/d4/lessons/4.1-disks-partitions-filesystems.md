## From raw disk to usable volume

Every disk that Windows Server uses goes through the same chain: a **physical disk** is initialized with a **partition style** (MBR or GPT), carved into **partitions**, and each partition is formatted with a **file system** to become a **volume** with a drive letter or mount point. Learn the chain, because every troubleshooting question about "the disk is not showing up" or "only 2 TB is usable" maps to one link in it.

## MBR vs GPT

| Item | MBR | GPT |
|---|---|---|
| Partitions | 4 primary, or 3 primary plus 1 extended holding logical drives | Up to 128 in Windows (the specification allows more) |
| Addressable size | About 2 TB (32-bit sector addresses; 4,294,967,295 sectors of 512 bytes is roughly 2.2 TB) | Beyond 2 TB; Windows file systems top out at 256 TB (NTFS) |
| Redundancy | One partition table | Primary and backup partition tables, each CRC-protected |
| Boot firmware | BIOS (and the only style BIOS can boot from) | UEFI required to boot from it; data-only use works on BIOS systems |
| Protective MBR | Not applicable | Every GPT disk carries a type 0xEE protective MBR so old tools do not see "unpartitioned" space |

A disk is either MBR or GPT, never both. A basic MBR disk needs extended partitions once you pass four volumes; GPT does not.

> **Exam tip:** "A 4 TB disk shows only 2 TB usable" means the disk was initialized as MBR. The fix is to convert to GPT. "Cannot boot from a GPT disk" on an old server means the firmware is BIOS, not UEFI.

Initialize and convert with PowerShell:

```powershell
Get-Disk | Where-Object PartitionStyle -eq 'RAW'
Initialize-Disk -Number 2 -PartitionStyle GPT
```

Converting a disk that already has data is a different tool. Disk Management and `Initialize-Disk` work on empty disks. For a Windows boot disk, Microsoft ships `MBR2GPT.exe`, which converts in place without data loss but requires the machine to be switched to UEFI afterward. Any other conversion route means backing up, wiping, and restoring.

> **Watch out:** Generation 2 Hyper-V VMs are UEFI, so their system disks are GPT. Generation 1 VMs are BIOS and boot from MBR disks. This is why you cannot just attach a Generation 1 system disk to a Generation 2 VM (covered in the Hyper-V lessons).

## Basic and dynamic disks

Servers use **basic disks** by default: partitions that Windows reads straight from the partition table. **Dynamic disks** are an older Logical Disk Manager scheme that allows spanned, striped and software-RAID volumes. A dynamic disk has a single LDM partition plus a hidden database at the end of the disk, and no extended partitions. Dynamic disks still exist for compatibility, but for new resilient storage you use **Storage Spaces** (next lesson) instead. Stay on basic disks unless a legacy requirement says otherwise.

## Building volumes in PowerShell

The Storage module covers the whole chain. A typical sequence on a new data disk:

```powershell
Initialize-Disk -Number 2 -PartitionStyle GPT
New-Partition -DiskNumber 2 -UseMaximumSize -AssignDriveLetter |
    Format-Volume -FileSystem NTFS -NewFileSystemLabel 'Data' -Confirm:$false
```

`New-Volume` collapses partition creation and formatting into one cmdlet and is the standard way to create a volume from a Storage Spaces virtual disk. Other cmdlets to know: `Get-Disk`, `Get-Partition`, `Get-Volume`, `Resize-Partition`, `Set-Disk -IsOffline`, and `Clear-Disk -RemoveData` (destructive).

For volumes that will hold very large files, such as VHDX files bigger than 1 TB, or volumes that will use Data Deduplication, Microsoft's NTFS guidance is a 64 KB allocation unit and large file record segments:

```powershell
Format-Volume -DriveLetter E -FileSystem NTFS -AllocationUnitSize 65536 -UseLargeFRS
```

Server Manager (File and Storage Services > Volumes and Disks) and Windows Admin Center expose the same operations graphically. The classic `diskpart.exe` still works and shows up in scripts and recovery environments.

## NTFS vs ReFS

Both are first-class file systems on Windows Server 2025. NTFS is the default and the safest answer when a question lacks a reason to pick anything else. ReFS (Resilient File System) is built for resilience and large virtualization and backup workloads.

| Capability | NTFS | ReFS |
|---|---|---|
| Maximum volume and file size | 256 TB | 35 PB |
| Bootable (system) volume | Yes | No in production; ReFS boot is only in Windows Server Insider Preview |
| Disk quotas | Yes | No |
| Shrink a volume | Yes | No |
| Removable media | Yes | No |
| Offloaded Data Transfer (ODX), object IDs, transactions, short names | Yes | No |
| Block cloning (near-instant file copies and VHDX merges by metadata) | No | Yes |
| Sparse VDL (fast creation of fixed VHDX) | No | Yes |
| Integrity streams and automatic repair (with Storage Spaces mirror or parity) | No | Yes |
| Mirror-accelerated parity | No | Yes, on Storage Spaces Direct |
| Data Deduplication role | Yes | Yes, since Windows Server 2019 |
| File system encryption (EFS) | Yes | Windows Server 2025 only |
| BitLocker, ACLs, USN journal, hard links, CSV | Yes | Yes (ReFS CSVs do not use Direct I/O on SAN storage, so use NTFS for SAN CSVs) |
| Thin provisioning and trim | Yes | On Storage Spaces only |

> **Exam tip:** ReFS cannot be the boot or removable volume and cannot be shrunk or used with disk quotas. NTFS is the answer for the system volume, FSRM-style quotas and SAN-attached CSVs.

### What is new in 2025 for ReFS

Windows Server 2025 adds native ReFS deduplication and compression for active workloads such as file servers and virtual desktops. Microsoft's step-by-step deployment article for it targets Azure Local, and the command-line surface is `refsutil dedup` (scan with `/s`, deduplicate with `/d`) and `refsutil compression` (formats LZ4 and ZSTD). It uses block cloning and runs as one-time or scheduled jobs. Do not confuse it with the long-standing **Data Deduplication** server role, which also supports ReFS volumes since Windows Server 2019 and which the iSCSI and dedup lesson covers. Also new: block cloning support for Dev Drive, and NVMe performance improvements.

> **Real world:** Use ReFS for Hyper-V and backup data volumes on Storage Spaces or Storage Spaces Direct, where integrity streams can self-heal and block cloning makes checkpoint merges and synthetic backups fast. Keep the OS volume, SAN-attached volumes and anything needing quotas on NTFS.

## Lab it yourself

Hyper-V can run inside a VM, so you can build all of this on a single laptop. On the physical host, with the lab VM powered off, run `Set-VMProcessor -VMName HV01 -ExposeVirtualizationExtensions $true` (a Generation 2 VM works best). For this lesson you do not need nested Hyper-V at all, only extra virtual disks.

1. Create three 10 GB dynamic VHDX files and attach them to a Windows Server 2025 VM with `New-VHD` and `Add-VMHardDiskDrive`.
2. Inside the VM, run `Get-Disk` and note the RAW disks. Initialize one as MBR and one as GPT, then compare `Get-Disk | Select Number, PartitionStyle`.
3. Create a volume on each with `New-Partition ... | Format-Volume`, one NTFS and one ReFS (`-FileSystem ReFS`).
4. Try `Resize-Partition -DiskNumber 2 -PartitionNumber 2 -Size 5GB` on the NTFS volume (works) and on the ReFS volume (fails, because ReFS cannot shrink).
5. Run `fsutil fsinfo volumeinfo E:` on both and compare the reported flags.

## Key takeaways

- MBR: four primary partitions and about 2 TB; GPT: 128 partitions in Windows, huge disks, backup table and CRCs.
- BIOS boots only MBR; GPT boot needs UEFI. A disk is never both, but GPT carries a protective MBR.
- `Initialize-Disk`, `New-Partition`, `Format-Volume` and `New-Volume` are the core Storage cmdlets; use `MBR2GPT.exe` for in-place boot disk conversion.
- NTFS: boot volume, quotas, shrink, removable media. ReFS: 35 PB, integrity streams, block cloning, sparse VDL, no shrink.
- ReFS supports the Data Deduplication role since Windows Server 2019; 2025 adds native ReFS dedup and compression (`refsutil`).
- Use a 64 KB allocation unit and `-UseLargeFRS` for NTFS volumes that hold large VHDX files or deduplicated data.
- Prefer basic disks plus Storage Spaces over dynamic disks for new designs.
