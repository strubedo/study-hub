## Virtual hard disks: VHD vs VHDX

Hyper-V stores a VM's disks as files. **VHDX** is the current format; the older **VHD** is kept only for compatibility with older Hyper-V releases. For Windows Server 2025 hosts convert old VHDs to VHDX unless you must move the VM somewhere that lacks VHDX support.

| Property | VHD | VHDX |
|---|---|---|
| Maximum size | 2,040 GB | 64 TB |
| Power-failure protection | No | Yes, metadata updates are logged |
| Large-sector and 4 KB-aligned performance | Limited | Better; larger block sizes for dynamic and differencing disks |
| Custom metadata | No | Yes |
| Online resize of a Generation 2 boot disk | n/a | Yes |

Each format has three **types**:

| Type | Behavior | Use it for |
|---|---|---|
| Fixed | Allocates the full size on the host immediately | Predictable performance, production databases |
| Dynamically expanding | File grows as the guest writes, up to the maximum size | Most general-purpose VMs, labs, space efficiency |
| Differencing | A child that records changes against a read-only parent | Checkpoints (the `.avhdx` files), VDI-style templates |

```powershell
New-VHD -Path 'D:\Hyper-V\VHDs\data1.vhdx' -SizeBytes 100GB -Dynamic
New-VHD -Path 'D:\Hyper-V\VHDs\fixed1.vhdx' -SizeBytes 50GB -Fixed
New-VHD -Path 'D:\Hyper-V\VHDs\child.vhdx' -ParentPath 'D:\Hyper-V\VHDs\base.vhdx' -Differencing
Add-VMHardDiskDrive -VMName APP01 -Path 'D:\Hyper-V\VHDs\data1.vhdx' -ControllerType SCSI
Get-VHD -Path 'D:\Hyper-V\VHDs\data1.vhdx' | Select VhdType, FileSize, Size
```

Maintenance cmdlets: `Resize-VHD` (grow, and shrink after you shrink the guest partition), `Convert-VHD` (change format, type or block size; the disk must not be attached), `Optimize-VHD` (compact a dynamic disk; the disk must be unattached or attached read-only), `Mount-VHD`/`Dismount-VHD` and `Merge-VHD` for differencing chains. Moving a VM's storage while it runs is **storage migration** (`Move-VMStorage`).

> **Watch out:** Dynamic disks can fill the host volume while the guest still reports free space. Thin provisioning plus Dynamic Memory is how a host gets overcommitted; monitor the volume that stores the VHDX files.

> **Exam tip:** Fixed has the most predictable performance; dynamic has the smallest footprint. Checkpoints create differencing disks, so a VM with many checkpoints reads through a long chain and is slower.

## Checkpoints: standard vs production

A **checkpoint** captures a point in time so you can revert. Hyper-V has two types:

| | Production checkpoint | Standard checkpoint |
|---|---|---|
| Mechanism | Guest-level Volume Shadow Copy Service on Windows, or a file system freeze on Linux | Saved state: disk, device and memory state |
| Memory state saved | No | Yes |
| Result when applied | VM is **off** and boots like a restored backup; applications are consistent | VM resumes exactly as it was, including open applications |
| Default type | **Yes**, selected by default | No |
| Fit | Production, and domain controllers or replicated apps | Dev/test where you need running state |

Standard checkpoints are not application-consistent and, per Microsoft, can cause data consistency problems for systems that replicate between nodes, such as Active Directory. That is the reason domain controllers should use production checkpoints at most, and why you never revert a DC's state casually.

The checkpoint type is a per-VM setting with four values:

```powershell
Set-VM -Name APP01 -CheckpointType Production      # default; falls back to standard if the production checkpoint fails
Set-VM -Name APP01 -CheckpointType ProductionOnly  # no fallback: if production fails, no checkpoint is taken
Set-VM -Name APP01 -CheckpointType Standard
Set-VM -Name APP01 -CheckpointType Disabled

Checkpoint-VM -Name APP01 -SnapshotName 'Before patch'
Get-VMCheckpoint -VMName APP01
Restore-VMCheckpoint -Name 'Before patch' -VMName APP01 -Confirm:$false
Remove-VMCheckpoint -VMName APP01 -Name 'Before patch'
```

Removing a checkpoint merges its differencing disk into the parent; the merge runs in the background and takes time proportional to the changes recorded. A VM supports up to **50** checkpoints, limited by storage. **Automatic checkpoints** are an optional setting (`Set-VM -AutomaticCheckpointsEnabled`) that makes Hyper-V take a checkpoint when the VM starts. Checkpoints are not a backup: they live on the same storage as the VM and a deleted or corrupt parent breaks the chain.

> **Exam tip:** "Revert the VM to a data-consistent state without saving RAM" is a **production** checkpoint. "Keep the running application exactly as it was" is **standard**. After applying a production checkpoint the VM is powered off.

## Dynamic Memory

**Dynamic Memory** lets Hyper-V adjust a running VM's RAM between a minimum and maximum as demand changes, which raises VM density per host. The guest must support it (all supported Windows Server and Windows guests, and many Linux distributions do) and it is enabled per VM.

| Setting | Meaning |
|---|---|
| Startup RAM | Memory the VM has when it boots; also all it has during OS install or upgrade |
| Minimum RAM | Lowest amount after startup; as low as 32 MB, and no higher than Startup RAM |
| Maximum RAM | Ceiling; from Startup RAM up to 1 TB in the Hyper-V Manager settings |
| Memory buffer | Percentage of extra memory Hyper-V tries to keep available above actual demand |
| Memory weight (priority) | Decides who gets memory first when the host is short |

```powershell
Set-VMMemory -VMName APP01 -DynamicMemoryEnabled $true `
  -StartupBytes 2GB -MinimumBytes 1GB -MaximumBytes 8GB -Buffer 20 -Priority 80
Get-VMMemory -VMName APP01
```

While a VM runs you can raise its maximum or lower its minimum. If minimum is below startup memory and the VM restarts under host memory pressure, Hyper-V can use **smart paging**, a temporary on-disk file, so the restart succeeds. Smart paging applies only to restarts, not to cold starts from Off, not to running VMs under pressure, and not to cluster failover, and it is transient. Dynamic Memory cannot be combined with Virtual NUMA: a dynamic-memory VM presents a single virtual NUMA node. Keep it off for memory-hungry or NUMA-aware workloads such as large SQL Server instances, and VMs that host nested Hyper-V do not resize memory while Hyper-V runs inside them, even with Dynamic Memory enabled.

## Integration services

**Integration services** are the guest-side components that talk to the host over VMBus. They are built into current Windows Server and client guests, delivered through Windows Update, so there is no ISO to mount for supported guests. The services you can toggle per VM:

| Service | Purpose |
|---|---|
| Heartbeat | Host can tell whether the guest OS is responding |
| Time synchronization | Syncs guest clock to the host (note: domain members should normally follow their domain hierarchy) |
| Shutdown | Graceful guest shutdown from the host |
| Data Exchange (key-value pair) | Exchange of host and guest info |
| Backup (VSS) | Required for production checkpoints and online backups |
| Guest services | File copy from host to guest with `Copy-VMFile` |

```powershell
Get-VMIntegrationService -VMName APP01
Enable-VMIntegrationService -VMName APP01 -Name 'Guest Service Interface'
Copy-VMFile -VMName APP01 -SourcePath C:\tools\setup.msi -DestinationPath C:\Temp -FileSource Host -CreateFullPath
```

> **Real world:** If production checkpoints keep falling back to standard, the usual cause is the Backup (VSS) integration service disabled or VSS failing inside the guest, which you can see in the guest's event log.

## Lab it yourself

On the nested HV01 from the previous lesson (or any Hyper-V host):

1. Create a Generation 2 VM with a dynamic VHDX. Compare `Get-VHD` `FileSize` against `Size`.
2. Run `Checkpoint-VM`, create a file in the guest, apply the checkpoint, and note whether the VM comes back running (standard) or off (production). Switch types with `Set-VM -CheckpointType` and repeat.
3. Enable Dynamic Memory with `Set-VMMemory`; watch `Get-VM | Select Name, MemoryAssigned, MemoryDemand` while you load the guest.
4. Disable the Backup (VSS) integration service with `Disable-VMIntegrationService` and take a production checkpoint; observe the fallback to standard.
5. Convert the dynamic disk with `Convert-VHD -VHDType Fixed` after shutting down the VM.

## Key takeaways

- VHDX: 64 TB, power-failure resilient; VHD: 2,040 GB. Types are fixed, dynamic and differencing.
- Checkpoints use differencing disks; production (VSS, no memory, VM off after apply) is the default; standard saves memory.
- `ProductionOnly` refuses to fall back to a standard checkpoint; `Disabled` turns checkpoints off. Maximum 50 per VM.
- Standard checkpoints and replicated systems like AD do not mix.
- Dynamic Memory uses Startup, Minimum, Maximum, buffer and weight; smart paging only helps restarts; no Virtual NUMA with Dynamic Memory.
- Integration services are built into supported guests and updated by Windows Update; VSS integration underpins production checkpoints.
