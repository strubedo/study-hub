## SMB shares in brief

A file server publishes folders as **SMB shares**. Clients connect to `\\FS01\Finance` over TCP port 445. The **Server** service (LanmanServer) does the sharing. Install the role service with `Install-WindowsFeature FS-FileServer`, then create shares from **Server Manager > File and Storage Services > Shares** (the *New Share Wizard* offers profiles such as SMB Share - Quick, SMB Share - Advanced and SMB Share - Applications), from **Computer Management > Shared Folders**, or from PowerShell.

Windows also creates **administrative shares** automatically: `C$` and the other drive roots, `ADMIN$` (the Windows folder) and `IPC$` (named pipes for remote management). A trailing `$` hides a share from browsing; it does not secure it. Only administrators can use the admin shares by default.

```powershell
New-Item -Path D:\Shares\Finance -ItemType Directory
New-SmbShare -Name 'Finance' -Path 'D:\Shares\Finance' `
    -FullAccess 'CORP\Domain Admins' -ChangeAccess 'CORP\GG-Finance-Users' `
    -FolderEnumerationMode AccessBased -CachingMode None

Get-SmbShare
Get-SmbShareAccess -Name Finance
Grant-SmbShareAccess -Name Finance -AccountName 'CORP\GG-Finance-Auditors' -AccessRight Read -Force
Revoke-SmbShareAccess -Name Finance -AccountName 'CORP\GG-Finance-Auditors' -Force
```

`New-SmbShare` access parameters are `-FullAccess`, `-ChangeAccess`, `-ReadAccess` and `-NoAccess`. If you give none, the share gets Read for Everyone. `Grant-SmbShareAccess`, `Revoke-SmbShareAccess`, `Block-SmbShareAccess` and `Unblock-SmbShareAccess` adjust the share's access later. Other per-share switches you may be asked about: `-EncryptData $true` (encrypt this share's traffic), `-ContinuouslyAvailable` (clustered continuous availability), `-ConcurrentUserLimit` and `-ScopeName`.

## Share permissions vs NTFS permissions

A share has two permission layers, and a user's access is the **more restrictive** of the two.

| | **Share permissions** | **NTFS permissions** |
|---|---|---|
| Where they apply | Network access to the share only | Local and network access |
| Levels | Read, Change, Full Control | Full Control, Modify, Read & Execute, List Folder Contents, Read, Write, plus special permissions |
| Granularity | Whole share | Per folder and file, with inheritance |
| Set in | Share properties, `Grant-SmbShareAccess` | Security tab, `icacls`, `Get-Acl`/`Set-Acl` |
| Works on FAT/exFAT/ReFS? | Yes (shares only) | NTFS and ReFS |

Inside each layer, the allow permissions a user gets from their own account and all of their groups **accumulate**, and an explicit **Deny** wins over an Allow. Compute the share result, compute the NTFS result, and take the lower of the two.

| Share | NTFS | Effective over the network |
|---|---|---|
| Full Control | Read | Read |
| Read | Modify | Read |
| Change | Full Control | Change (cannot change permissions or take ownership, since those are Full Control rights on the share) |
| Full Control | Modify | Modify |
| Change | Read | Read |
| Allow (any) | Deny (Read) | No access: the Deny in either layer wins |

> **Exam tip:** Cumulative within a layer, most restrictive across layers. A user in Group A (share: Read) and Group B (share: Change) gets Change at the share level; then NTFS is evaluated the same way; then the lower of the two applies.

The common best practice is to give **Everyone** or **Authenticated Users** Full Control on the share and do the real work with NTFS permissions, so you manage access in one place. You still need share permissions, because the default Read on a new share would otherwise cap everyone. Use AD groups (the AGDLP pattern from Domain 2), not individual users.

### Effective access and the pitfalls

In **Properties > Security > Advanced > Effective Access**, choose **Select a user** to see what that user would get from the NTFS ACL, including group membership, inheritance and deny entries. It does not include the share permissions, so check those separately with `Get-SmbShareAccess`. A user whose group membership just changed must sign out and in (or get a new Kerberos ticket) because group membership is in the access token, which is built at logon.

Other points worth knowing:

- **Inheritance.** New files and folders inherit from the parent unless inheritance is blocked. Add explicit entries at the right level and avoid blocking inheritance low in the tree.
- **Copy vs move.** A copy takes the permissions of its destination folder. A move within the same NTFS volume keeps the original permissions; a move to another volume behaves like a copy.
- **Ownership.** The owner can always change permissions. Administrators can take ownership (`takeown`, or the **Owner** link in Advanced Security Settings).
- **Special permissions** exist beneath the standard sets, such as *Traverse folder*, which lets a user pass through a folder to a subfolder they have access to without having read access to the folder itself.
- **`icacls`** is the command-line editor: `icacls D:\Shares\Finance /grant "CORP\GG-Finance-Users:(OI)(CI)M"` grants Modify to a folder, its subfolders and files. `(OI)` means object inherit, `(CI)` container inherit.

```powershell
(Get-Acl D:\Shares\Finance).Access | Format-Table IdentityReference, FileSystemRights, AccessControlType, IsInherited
icacls D:\Shares\Finance
```

## Access-based enumeration

By default anyone who can open a share sees every file and folder name in it, even the ones they cannot read. **Access-based enumeration (ABE)** filters the folder listing so users see only what they have at least Read access to. It is a convenience and a minor information-hiding measure, not an access control: it does not stop a user who knows a path from trying it, and NTFS still decides access.

Enable it per share: in the *New Share Wizard* or share properties tick **Enable access-based enumeration**, or use `-FolderEnumerationMode AccessBased` on `New-SmbShare` or `Set-SmbShare` (the default is `Unrestricted`). It applies to the share it is set on; a DFS namespace has its own, separate ABE setting, as the DFS lesson explains. A large directory with many different ACLs costs the server more CPU for each listing.

```powershell
Set-SmbShare -Name Finance -FolderEnumerationMode AccessBased -Force
Get-SmbShare -Name Finance | Select-Object Name, FolderEnumerationMode
```

> **Watch out:** ABE hides based on permission to *list/read* the item. If you grant *Traverse* without Read on a folder, the user can reach what is below by typing the full path but will not see the folder in the listing, which is how a "drop box" style tree is typically built.

## Offline Files

**Offline Files** lets a client keep a cached copy of a network file and work disconnected, then sync back. There are two sides.

On the **server**, each share has a **caching setting** that tells clients how to cache it:

| Setting (`-CachingMode`) | Meaning |
|---|---|
| `Manual` (default) | Users choose which files to make available offline |
| `Documents` | Opened documents and programs cached automatically (documents only) |
| `Programs` | Documents and programs cached automatically, for read-only application shares |
| `BranchCache` | Manual caching plus BranchCache hosted caching for branch offices |
| `None` | Offline caching disabled |

On the **client**, the Offline Files feature and the Sync Center manage the cache; **Always Offline** mode makes a slow link behave as if it were disconnected and syncs in the background. Group Policy under *Network > Offline Files* turns the feature on or off. Typical scenario: folder redirection of users' Documents with Offline Files so laptops work away from the office.

Do not cache database files, user profile roots or anything opened by several people at once with write conflicts. Set those shares to `None`. When two edits collide after a sync, the user is prompted to keep either version or both.

## Key takeaways

- Share permissions (Read, Change, Full Control) apply over the network only; NTFS applies everywhere; the effective permission is the most restrictive of the two.
- Within a layer permissions accumulate across groups, and an explicit Deny beats Allow.
- Common design: share Full Control for Authenticated Users, real control with NTFS permissions on AD groups.
- The Effective Access tab evaluates NTFS only, not share permissions.
- `New-SmbShare` takes `-FullAccess`, `-ChangeAccess`, `-ReadAccess`, `-NoAccess` and `-FolderEnumerationMode AccessBased`.
- ABE hides items users cannot read; it does not secure them.
- Share caching modes are Manual (default), Documents, Programs, BranchCache and None.
