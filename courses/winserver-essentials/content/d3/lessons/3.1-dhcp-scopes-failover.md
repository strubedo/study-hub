## DHCP in one paragraph

A DHCP server hands out IP configuration in a four-message exchange known as **DORA**: Discover (client broadcast), Offer, Request, Acknowledge. The address is **leased**, not given. A client tries to renew at 50 percent of the lease (T1) and, failing that, rebinds with any server at 87.5 percent (T2). Clients on other subnets reach the server through a **relay agent** (a router configured with an IP helper address, or a Windows server running RRAS relay), which forwards the broadcast as unicast to the server. Windows DHCP serves UDP 67, and clients use UDP 68.

Install with `Install-WindowsFeature DHCP -IncludeManagementTools`. Manage with **DHCP** console (`dhcpmgmt.msc`) or the **DhcpServer** PowerShell module.

## Authorization in Active Directory

A Windows DHCP server that is a member of a domain will **not lease addresses until it is authorized** in Active Directory. This protects against rogue servers: a domain-joined server that is not in the authorized list keeps running the service but does not answer clients. Authorization stores the server's name and address in the directory (under the `NetServices` container in the Configuration partition). By default an Enterprise Admin can authorize; the right can be delegated.

```powershell
Install-WindowsFeature DHCP -IncludeManagementTools

# Local groups "DHCP Administrators" and "DHCP Users" (the post-install wizard does this in the GUI)
Add-DhcpServerSecurityGroup

# Authorize in AD (run as an account allowed to do so)
Add-DhcpServerInDC -DnsName 'dhcp01.corp.example.com' -IPAddress 10.0.0.30
Get-DhcpServerInDC

```

In the console (or after authorizing with PowerShell), right-click the server in **DHCP**, choose **Authorize**, and refresh; the red or green arrow beside the server shows the state.

> **Exam tip:** Authorization applies to Windows DHCP servers in an AD domain. A DHCP server that is authorized in AD but whose service is stopped does nothing, and a DHCP server that is running but unauthorized does not lease. Unauthorize with `Remove-DhcpServerInDC`.

## Scopes, exclusions and reservations

A **scope** is a contiguous range of addresses for one subnet, plus its lease duration. A **superscope** groups scopes for multinets (a legacy feature). A **multicast scope** is separate. A scope's range includes everything the server can hand out, and you carve out what it must not.

- **Exclusion range**: addresses inside the range that the server never leases (static servers, routers, printers).
- **Reservation**: a fixed address tied to a client's MAC address (the `ClientId`). The client still uses DHCP, so the reservation is also where you give a device a specific address *and* the scope's options. A reservation address can be inside or outside an exclusion range, but it must be inside the scope range.
- **Lease duration**: the default for a Windows scope is 8 days. Use shorter leases (hours) for guest Wi-Fi where devices come and go, longer for stable wired clients.

```powershell
Add-DhcpServerv4Scope -Name 'LAN10' -StartRange 10.0.10.1 -EndRange 10.0.10.254 `
    -SubnetMask 255.255.255.0 -LeaseDuration 8.00:00:00 -State Active

Add-DhcpServerv4ExclusionRange -ScopeId 10.0.10.0 -StartRange 10.0.10.1 -EndRange 10.0.10.20

Add-DhcpServerv4Reservation -ScopeId 10.0.10.0 -IPAddress 10.0.10.50 `
    -ClientId '00-15-5D-01-02-03' -Name 'printer01' -Description 'Floor 2 printer'

Get-DhcpServerv4Scope
Get-DhcpServerv4Lease -ScopeId 10.0.10.0
```

`Add-DhcpServerv4Scope` takes `-State` as `Active` or `InActive`; a scope that is inactive does not hand out leases. In the GUI, right-click **IPv4 > New Scope**, run through the wizard and choose **Yes, I want to configure these options now** to set the options during creation.

## Options

**DHCP options** deliver configuration other than the address. Common ones:

| Option | Number | Typical value |
|---|---|---|
| Router (default gateway) | 3 | 10.0.10.1 |
| DNS servers | 6 | 10.0.0.10, 10.0.0.11 |
| DNS domain name | 15 | corp.example.com |
| WINS/NBT node type | 46 | Legacy; do not deploy WINS |
| Boot server host name / bootfile | 66 / 67 | PXE and network boot |

Options can be set at four levels, and the more specific level wins over the server level:

1. **Server** options apply to every scope on the server.
2. **Scope** options override server options for that subnet.
3. **Policy** options (conditional assignment based on vendor class, user class, MAC prefix and similar conditions) apply to matching clients on top of the scope.
4. **Reservation** options apply to that one client and override the scope's.

```powershell
Set-DhcpServerv4OptionValue -ScopeId 10.0.10.0 -Router 10.0.10.1 `
    -DnsServer 10.0.0.10, 10.0.0.11 -DnsDomain 'corp.example.com'

# Server level (applies unless a scope overrides it)
Set-DhcpServerv4OptionValue -DnsDomain 'corp.example.com'

Get-DhcpServerv4OptionValue -ScopeId 10.0.10.0
```

DHCP can also keep DNS current. The server can register A and PTR records for the clients, and it can do so for clients that do not update DNS themselves. Configure that with `Set-DhcpServerv4DnsSetting` (parameters such as `-DynamicUpdates`, `-DeleteDnsRROnLeaseExpiry`, `-UpdateDnsRRForOlderClients`). Better still, give the DHCP server a dedicated service account for DNS registration with `Set-DhcpServerDnsCredential`, rather than adding DHCP servers to the privileged `DnsUpdateProxy` group, because records created by `DnsUpdateProxy` members have no owner protection.

## DHCP failover

A single DHCP server is a single point of failure. Windows Server 2012 introduced **DHCP failover**, which lets two servers share one scope and its **lease database in real time**, with no split of the address range. It supports **IPv4 scopes only**; there is no failover for IPv6 scopes. The two servers talk over **TCP port 647**, and their clocks must stay within one minute of each other (setup fails with a critical error if the time difference is larger).

There are two modes. Choose per relationship, and you cannot mix both modes on the same scope.

| | **Load balance** (default) | **Hot standby** |
|---|---|---|
| Who leases | Both servers, in a ratio | Active server leases; standby waits |
| Default split | 50:50 (any 0 to 100) | n/a; standby reserves 5 percent of the scope |
| Typical site | Both servers on the same subnet or site | Active at a branch, standby in the data center |
| Failure behavior | Surviving partner takes over after MCLT | Standby serves renewals and leases from its reserve, then the whole pool after MCLT |

Hot standby has a **reserve**: the percentage of the address pool (default 5 percent) the standby may use for brand-new clients while the active server is unreachable.

### States and MCLT

The relationship moves through states: **Normal** (both up and in sync), **Communication Interrupted** (one partner cannot reach the other, but the cause is not known), and **Partner Down** (an administrator or the automatic timer declares the partner down). The **maximum client lead time (MCLT)** is the safety margin that makes this safe. Each server leases an address only for the MCLT beyond what its partner knows about; the default is **1 hour**. During Communication Interrupted a server can renew existing leases for the lease duration, but gives new clients only a lease of MCLT length. When it enters Partner Down, it waits for the MCLT to expire and then takes over 100 percent of the address pool, which means that the old partner cannot have leased any of those addresses in the meantime.

Going from Communication Interrupted to Partner Down is a deliberate action by default, because a network split would otherwise cause both servers to think the other is down. You can instead enable **automatic state transition** and set the **state switch interval** so the transition happens after a timeout.

```powershell
# Load balance 50:50 for one scope
Add-DhcpServerv4Failover -ComputerName dhcp01 -Name 'dhcp01-dhcp02' `
    -PartnerServer dhcp02.corp.example.com -ScopeId 10.0.10.0 `
    -LoadBalancePercent 50 -SharedSecret 'S3cr3t!Lab' -AutoStateTransition $true -StateSwitchInterval 00:30:00

# Hot standby instead: dhcp01 active, 5% reserve
Add-DhcpServerv4Failover -ComputerName dhcp01 -Name 'branch-hq' `
    -PartnerServer dhcp-hq.corp.example.com -ScopeId 10.0.20.0 `
    -ServerRole Active -ReservePercent 5 -MaxClientLeadTime 01:00:00

Get-DhcpServerv4Failover
Invoke-DhcpServerv4FailoverReplication -ComputerName dhcp01 -Name 'dhcp01-dhcp02'
```

The **shared secret** turns on message authentication between the partners. The GUI path is right-click the scope or **IPv4**, **Configure Failover**, which walks you through partner, mode and secret.

**Replication** copies scope configuration, options, reservations and exclusions between partners. Changes to options are not automatic everywhere: after editing a scope on one partner use **Replicate Scope** in the console or `Invoke-DhcpServerv4FailoverReplication`. Lease data replicates continuously.

> **Watch out:** Replication copies *scope* configuration (properties, reservations, scope options, policies), not server-level settings, and failover works on a per-scope basis, so you add the relationship for scopes explicitly. Configure the same server-level options on both partners. Also, if a partner is a domain controller or DNS dynamic update uses credentials, set the DNS credentials on both.

> **Real world:** Before failover, admins used a **split scope** (about 80/20 across two servers, each with its own database). It still works and is the only option for IPv6, but failover is simpler and uses the whole address space on either server.

## Lab it yourself

Add a second server `DC02` or `FS01` with the DHCP role and clock-sync both to the DC.

**GUI**

1. On `DHCP01`, open **DHCP**, right-click the server and **Authorize**. Refresh until the arrow is green.
2. **IPv4 > New Scope**: `LAN10`, 10.0.10.1 to 10.0.10.254, /24. Exclude 10.0.10.1 to 10.0.10.20. Set router and DNS options.
3. In **Reservations** add a client by MAC address.
4. Right-click the scope, **Configure Failover**, add `DHCP02`, choose **Load balance**, 50 percent, enter a shared secret, finish. Then try Hot standby on a second scope.

**PowerShell**

```powershell
Get-DhcpServerInDC
Get-DhcpServerv4Failover | Format-List Name, Mode, PartnerServer, LoadBalancePercent, MaxClientLeadTime, State
Get-DhcpServerv4Lease -ScopeId 10.0.10.0 -ComputerName dhcp02
```

Stop the DHCP service on DHCP01, release and renew from a client, and watch DHCP02 take over. Use `Get-DhcpServerv4Failover` on DHCP02 to see the state change to Communication Interrupted.

## Key takeaways

- A domain-joined Windows DHCP server must be authorized in AD (`Add-DhcpServerInDC`) before it leases.
- Exclusions remove addresses from a scope; reservations bind an address to a MAC and can have their own options.
- Options can be set at server, scope, policy and reservation level; scope overrides server, and a reservation overrides the scope.
- Failover supports IPv4 only, uses TCP 647, and needs clocks within one minute.
- Load balance defaults to 50:50; hot standby reserves 5 percent for the standby; default MCLT is 1 hour.
- Failover states: Normal, Communication Interrupted, Partner Down; automatic state transition is optional.
- Replicate scope changes with `Invoke-DhcpServerv4FailoverReplication`; server-level options are not replicated.
