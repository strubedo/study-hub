## DFS Namespaces: one path for many servers

As an organization adds file servers, users are left remembering `\\FS01\Finance`, `\\FS02\Projects` and `\\OLD-FS\Archive`. **DFS Namespaces (DFS-N)** gives them a single virtual tree, such as `\\corp.example.com\Public\Finance`, where each folder points at one or more real shared folders called **folder targets**. When you move data to a new server, you update the target and users never notice. DFS-N does not copy data; it only hands out **referrals**, lists of target paths the client then connects to over SMB.

Parts of a namespace:

- **Namespace root**: the top of the tree, hosted on one or more **namespace servers** (root targets).
- **Folders**: virtual subfolders; a folder with targets points to real shares, a folder with none only organizes the tree.
- **Folder targets**: UNC paths of shares (`\\FS01\Finance`, `\\FS02\Finance`).
- **Referral**: the ordered target list the client caches for a time-to-live and then uses.

### Namespace types

| | **Domain-based** | **Stand-alone** |
|---|---|---|
| Path | `\\corp.example.com\Public` | `\\FS01\Public` |
| Configuration stored in | Active Directory | The namespace server's registry |
| Multiple root servers for availability | Yes | Only via a failover cluster |
| Requires AD DS | Yes | No |
| Modes | **Windows Server 2008 mode** (access-based enumeration, more scalability) or Windows 2000 Server mode | n/a (a stand-alone namespace also supports ABE) |

Choose domain-based when you want multiple namespace servers for availability and a name that follows the domain, not a server. Choose stand-alone for a non-domain environment or to host the root on a failover cluster. The 2008 mode requires the domain functional level to be at least Windows Server 2008, which every 2025 environment is.

Referral ordering uses **Active Directory site costing**: clients get targets in their own site first, then by increasing site cost, with random ordering inside a cost group by default. You can change the order to lowest cost or exclude out-of-site targets. If you enable **target failback** the client returns to the preferred target once it is back. Referrals are cached by the client for the **time to live** configured on the root (`Set-DfsnRoot -TimeToLiveSec`) or folder (`Set-DfsnFolder`).

```powershell
Install-WindowsFeature FS-DFS-Namespace, RSAT-DFS-Mgmt-Con -IncludeManagementTools   # on namespace servers

# Domain-based namespace in 2008 mode, root share created by the cmdlet
New-DfsnRoot -Path '\\corp.example.com\Public' -TargetPath '\\FS01\Public' -Type DomainV2

# Add a second root server for availability
New-DfsnRootTarget -Path '\\corp.example.com\Public' -TargetPath '\\FS02\Public'

# Folders and targets
New-DfsnFolder -Path '\\corp.example.com\Public\Finance' -TargetPath '\\FS01\Finance'
New-DfsnFolderTarget -Path '\\corp.example.com\Public\Finance' -TargetPath '\\FS02\Finance'

# Access-based enumeration on the namespace
Set-DfsnRoot -Path '\\corp.example.com\Public' -EnableAccessBasedEnumeration $true
Get-DfsnRoot; Get-DfsnFolderTarget -Path '\\corp.example.com\Public\Finance'
```

`-Type` takes `Standalone`, `DomainV1` (2000 mode) or `DomainV2` (2008 mode). The GUI is **DFS Management** (`dfsmgmt.msc`): right-click **Namespaces > New Namespace**, pick the namespace server, name, type, then right-click the namespace > **New Folder**.

> **Exam tip:** ABE on a namespace is a separate setting from ABE on the underlying shares, so enable it where you want folders hidden: on the namespace (domain-based namespaces need 2008 mode) and, for the folder targets, on each share. Share and NTFS permissions still control access to the targets; DFS-N has no permissions of its own beyond who can manage it.

## DFS Replication: keeping targets in sync

Two targets for the same folder are only useful if they contain the same data. **DFS Replication (DFS-R)** is a multi-master, state-based replication engine for folders. It detects changes with the NTFS change journal and a database, and it uses **remote differential compression (RDC)** to send only changed blocks of a file, which suits WAN links.

The model:

- A **replication group** is a set of servers (**members**) that replicate one or more **replicated folders**.
- **Connections** are one-way links between members; they are usually created in pairs, giving bidirectional replication. **Topology** choices include full mesh, hub and spoke, or a custom layout.
- A **primary member** supplies the authoritative copy for the **initial sync**; the other members' conflicting content is moved to the preexisting folder. After the first sync all members are equal.
- Each member has a hidden `DfsrPrivate` folder with the **staging** area (where the compressed file is built before sending; default quota 4096 MB), `ConflictAndDeleted` (files that lost a conflict or were deleted, default quota 4096 MB) and `PreExisting`.
- Conflict handling is **last writer wins** for file edits; the losing file moves to `ConflictAndDeleted`.

```powershell
Install-WindowsFeature FS-DFS-Replication, RSAT-DFS-Mgmt-Con -IncludeManagementTools

New-DfsReplicationGroup -GroupName 'RG-Finance' |
  New-DfsReplicatedFolder -FolderName 'Finance'
Add-DfsrMember -GroupName 'RG-Finance' -ComputerName FS01, FS02
Add-DfsrConnection -GroupName 'RG-Finance' -SourceComputerName FS01 -DestinationComputerName FS02
Set-DfsrMembership -GroupName 'RG-Finance' -FolderName 'Finance' -ComputerName FS01 `
    -ContentPath 'D:\Shares\Finance' -PrimaryMember $true -Force
Set-DfsrMembership -GroupName 'RG-Finance' -FolderName 'Finance' -ComputerName FS02 `
    -ContentPath 'D:\Shares\Finance' -Force

Get-DfsrBacklog -GroupName 'RG-Finance' -FolderName 'Finance' `
    -SourceComputerName FS01 -DestinationComputerName FS02
Update-DfsrConfigurationFromAD -ComputerName FS01, FS02
```

`Get-DfsrBacklog` counts files waiting to replicate from one member to another; a backlog that does not shrink indicates a connectivity, quota or database problem. Replication group configuration is stored in Active Directory, so DFS-R is for domain-joined servers, and AD replication latency delays when new settings reach members (`Update-DfsrConfigurationFromAD` polls immediately). DFS-R is also the engine for **SYSVOL replication** on domain controllers, as covered in Domain 2.

Cautions the exam likes to test:

- DFS-R is **not a backup**. A deleted file replicates as a deletion; it is recoverable from `ConflictAndDeleted` only for a while.
- It does not handle two users editing the same file on different members at once without a loser; use a client-side lock strategy or a single active target for such data (set the other targets' referral order to prefer one).
- DFS-N and DFS-R are independent. You can use either without the other, and are commonly combined: DFS-N provides the name, DFS-R keeps the targets synchronized.

## File Server Resource Manager

**File Server Resource Manager (FSRM)** is a role service of the file server for managing the data on volumes and folders. Install with `Install-WindowsFeature FS-Resource-Manager -IncludeManagementTools`. Open **File Server Resource Manager** (`fsrm.msc`). The parts that matter here are quotas and file screens, plus storage reports and classification.

To send e-mail notifications, FSRM needs an SMTP server and addresses configured: **Options** in the console, or `Set-FsrmSetting -SmtpServer smtp.corp.example.com -AdminEmailAddress fsadmin@corp.example.com -FromEmailAddress fsrm@corp.example.com`.

### Quotas

An FSRM quota limits the space a **folder or volume** may use. (Unlike NTFS quotas, which are per user per volume, FSRM quotas are per folder path.)

- **Hard quota**: the folder cannot exceed the limit; writes fail with a disk-full style error.
- **Soft quota**: the limit is monitored but not enforced, useful for reports and warnings.
- **Thresholds**: percentages of the limit (for example 85, 95, 100) with actions: send e-mail, log an event, run a command, or generate a report.
- **Quota template**: reusable limit and thresholds. Change a template and you can update every quota derived from it.
- **Auto apply quota**: applies a template to every existing and *future* subfolder of a parent, typical for home folders.

```powershell
New-FsrmQuotaTemplate -Name '5 GB Hard' -Size 5GB
$email = New-FsrmAction -Type Email -MailTo '[Admin Email];[Source Io Owner Email]' `
    -Subject 'Quota at [Quota Threshold]% for [Quota Path]' -Body 'The folder is nearly full.'
$t90 = New-FsrmQuotaThreshold -Percentage 90 -Action $email
New-FsrmQuota -Path 'D:\Shares\Projects' -Size 50GB -Threshold $t90
New-FsrmAutoQuota -Path 'D:\Shares\Home' -Template '5 GB Hard'
Get-FsrmQuota
```

`-SoftLimit` on `New-FsrmQuota` or the template makes the quota soft. The GUI path is **Quota Management > Quota Templates / Quotas > Create Quota**; choose *Auto apply template and create quotas on existing and new subfolders* for home folders.

### File screening

A **file screen** controls which file types can be saved in a path. It matches **file names and extensions** (using **file groups** like Audio and Video Files, Executable Files, Image Files, or your own group of patterns), not the actual content.

- **Active screening** blocks matching files from being saved. **Passive screening** only logs or notifies, and is a good first step.
- **File screen exceptions** carve out a subfolder where a normally blocked type is allowed.
- **File screen templates** bundle groups, mode and notifications, just like quota templates.

```powershell
New-FsrmFileGroup -Name 'Block Media' -IncludePattern @('*.mp3','*.mp4','*.mkv')
New-FsrmFileScreenTemplate -Name 'Block Media Template' -IncludeGroup 'Block Media' -Active
New-FsrmFileScreen -Path 'D:\Shares\Projects' -Template 'Block Media Template'
Get-FsrmFileScreen
```

FSRM also provides **storage reports** (large files, duplicate files, files by owner or type, quota usage), either scheduled or on demand, which tell you where space is going before you set quotas.

> **Watch out:** A file screen does not scan or remove files already in the folder, and renaming `movie.mkv` to `movie.dat` defeats a name-based screen. Combine screens with permissions and anti-malware, not in place of them.

## Lab it yourself

Use `FS01` and `FS02` (add an extra data disk, `D:`, on each), plus the Domain 2 `corp.example.com`.

**GUI**

1. In **DFS Management**, **New Namespace**: server FS01, name `Public`, *Domain-based namespace*, 2008 mode. Add a folder `Finance` targeting `\\FS01\Finance`; add `\\FS02\Finance` as a second target and, when asked, **create a replication group**. Walk the wizard: choose FS01 as the primary member and a full-mesh topology.
2. Right-click the namespace > **Properties > Advanced** and view the referral ordering and TTL settings.
3. In **File Server Resource Manager > Quota Management > Quotas > Create Quota**: path `D:\Shares\Home`, *Auto apply template*, template `100 MB Limit` (a built-in template). Under **File Screening Management** create a screen on `D:\Shares\Projects` with the built-in *Block Executable Files* template.

**PowerShell**

```powershell
Get-DfsnRoot | Format-List Path, Type, State, Flags
Get-DfsrState -ComputerName FS02
Get-DfsrBacklog -GroupName 'RG-Finance' -FolderName Finance -SourceComputerName FS01 -DestinationComputerName FS02
Get-FsrmQuota | Format-Table Path, Size, SoftLimit, Usage
```

Copy a 150 MB test file into an auto-quota home folder and note the failure, then copy a `.exe` into the screened folder and read the event in the Application log.

## Key takeaways

- DFS-N gives one virtual path to many shares through referrals; domain-based namespaces store configuration in AD and can have multiple root servers; stand-alone uses the registry, with a cluster for availability.
- Domain-based 2008 mode adds access-based enumeration and larger scale; turn ABE on for the namespace with `Set-DfsnRoot -EnableAccessBasedEnumeration $true`.
- DFS-R is multi-master, uses RDC, needs a primary member for initial sync and resolves conflicts by last writer wins, with losers in `ConflictAndDeleted`.
- DFS-R is not a backup and is configured in AD; check progress with `Get-DfsrBacklog`.
- FSRM hard quotas block writes, soft quotas only monitor; thresholds run actions; auto-apply quotas cover new subfolders.
- File screens block by file name and extension; active mode blocks, passive logs; exceptions create allowed subfolders.
- Quotas and screens need `FS-Resource-Manager`; e-mail actions need an SMTP server configured in FSRM options.
