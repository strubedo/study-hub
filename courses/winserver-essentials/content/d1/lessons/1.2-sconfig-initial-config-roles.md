## SConfig

**SConfig** (the Server Configuration tool) is a text menu for the common first-hour tasks. It is the main local tool on Server Core, and it also runs on Desktop Experience: open PowerShell and type `SConfig`.

Behavior worth knowing:

- Since Windows Server 2022, Server Core **runs SConfig automatically** after sign-in, and it is PowerShell-based, so it restarts itself if the window is closed. `SConfig.cmd` still works but is no longer developed.
- You must be a member of the local **Administrators** group.
- You can use SConfig at the console or over **Remote Desktop**, but **not inside a remote PowerShell session**.
- It is not meant for configuring more than a handful of servers; use unattend.xml answer files, deployment tooling or PowerShell for scale.

### The main menu

| # | Option | What it does |
|---|---|---|
| 1 | Domain/workgroup | Join a domain (can also rename the computer) or a workgroup |
| 2 | Computer name | Rename; restart required |
| 3 | Add local administrator | Add a user or group to local Administrators |
| 4 | Configure remote management | Enable/disable remote management (PowerShell remoting, Windows Admin Center, some MMC snap-ins) and enable/disable ping |
| 5 | Update settings | Automatic, download only (the default) or manual |
| 6 | Install updates | Quality updates (all or recommended); feature updates only apply to Azure Local |
| 7 | Remote desktop | Enable with NLA or any client, or disable |
| 8 | Network settings | DHCP or static IPv4, mask, gateway, DNS servers |
| 9 | Date and time | Opens the Date and Time applet |
| 10 | Telemetry settings | Diagnostic data level |
| 11 | Windows activation | View status, activate, install a product key |
| 12 | Log off user | |
| 13 | Restart server | |
| 14 | Shut down server | |
| 15 | Exit to command line (PowerShell) | Drops to PowerShell; type `SConfig` to return |

Defaults: remote management is enabled for the **domain network** when the server is domain joined, or for the **local subnet** in a workgroup; **response to ping is off**; updates are **download only**; if no DHCP server answers, the NIC gets an APIPA address. When Automatic updates is chosen, checks and installs happen daily at **3:00 AM** server time.

> **Exam tip:** To enable ping on a Core server through SConfig: option **4**, then the ping option. To configure a static IP: option **8**, choose the adapter, then the address option.

> **Watch out:** Joining a domain requires that the server can resolve the domain controller's DNS name and that you have an account permitted to join computers. Set the DNS server (to DC01, for example) *before* option 1.

## The same work in PowerShell

PowerShell does everything SConfig does and scales better. The core initial-configuration cmdlets:

```powershell
Rename-Computer -NewName FS01
New-NetIPAddress -InterfaceAlias 'Ethernet' -IPAddress 192.168.10.21 -PrefixLength 24 -DefaultGateway 192.168.10.1
Set-DnsClientServerAddress -InterfaceAlias 'Ethernet' -ServerAddresses 192.168.10.10
Set-TimeZone -Id 'Eastern Standard Time'
Add-Computer -DomainName corp.example.com -Credential CORP\Administrator -Restart
```

Activation uses the Software Licensing Management Tool:

```text
slmgr.vbs /ipk <product key>     install a key
slmgr.vbs /ato                   activate online
slmgr.vbs /dlv                   detailed license info (shows EVAL for evaluations)
```

On a pay-as-you-go machine activation comes from Azure through Arc instead of a key.

## Roles, role services and features

- A **role** is the primary job of the server (AD DS, DNS Server, DHCP Server, File and Storage Services, Web Server (IIS), Hyper-V).
- A **role service** is an optional component of a role (for example DFS Namespaces under File and Storage Services, or Windows Authentication under IIS).
- A **feature** is a supporting capability that is not a role (Failover Clustering, BitLocker, Windows Server Backup, SNMP, Telnet Client).

**Server Manager** (Desktop Experience) runs the *Add Roles and Features Wizard*, which can target the local server, remote servers in the pool, or an offline VHD. Management tools (consoles and PowerShell modules) are separate checkboxes.

In PowerShell the **ServerManager** module handles it:

| Cmdlet | Use |
|---|---|
| `Get-WindowsFeature` | List roles, role services and features with install state |
| `Install-WindowsFeature` | Install |
| `Uninstall-WindowsFeature` | Remove (with `-Remove` also deletes payload from disk) |

Useful `Install-WindowsFeature` parameters: `-Name`, `-IncludeAllSubFeature`, `-IncludeManagementTools`, `-Restart`, `-Source` (a share holding feature files), `-ComputerName` (install remotely) and `-Vhd` (offline VHD). `-WhatIf` previews the result.

```text
PS C:\> Get-WindowsFeature Web-Server, DNS

Display Name                                            Name           Install State
------------                                            ----           -------------
[ ] Web Server (IIS)                                    Web-Server         Available
[ ] DNS Server                                          DNS                Available

PS C:\> Install-WindowsFeature -Name Web-Server -IncludeManagementTools
```

> **Watch out:** `-IncludeManagementTools` installs the management consoles. On Server Core the GUI consoles cannot run locally, so use remote tools instead. Installing a role is not the same as configuring it: AD DS and DHCP still need promotion or authorization afterward.

Some roles are not available on Server Core; Microsoft maintains the list, and the **App Compatibility Feature on Demand** fills part of the gap for legacy tools.

Features on Demand such as OpenSSH install through `Add-WindowsCapability`; see the remote management lesson.

## Lab it yourself

1. Install a Server Core VM in Hyper-V. When SConfig appears, use option 8 to set 192.168.10.21/24, gateway 192.168.10.1, DNS 192.168.10.10; use option 2 to rename it FS01.
2. Choose option 4 and enable response to ping; ping it from your host.
3. Choose option 15, then run `Get-WindowsFeature | Where-Object Installed`.
4. Run `Install-WindowsFeature -Name FS-FileServer -WhatIf`, then without `-WhatIf`, then `Uninstall-WindowsFeature -Name FS-FileServer`.
5. Without a domain controller in the lab, join a workgroup only; if you have DC01, set DNS to it and use option 1.

## Key takeaways

- SConfig auto-starts on Server Core since 2022; it works locally or over RDP, not in a remote PowerShell session.
- Know the menu: 1 domain, 2 name, 4 remote management and ping, 5/6 updates, 8 network, 11 activation, 15 PowerShell.
- Ping is off by default; remote management is on for the domain network (or local subnet in a workgroup).
- Set DNS to a domain controller before joining the domain.
- Role is the main job, role service is a part of it, feature is a supporting capability.
- `Install-WindowsFeature` with `-IncludeManagementTools`, `-IncludeAllSubFeature`, `-Source`, `-ComputerName` covers most installs; `Get-WindowsFeature` shows state.
