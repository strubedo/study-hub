## Two installation options

Setup offers four entries for each edition you have media for, for example:

- Windows Server 2025 Standard
- Windows Server 2025 Standard **with Desktop Experience**
- Windows Server 2025 Datacenter
- Windows Server 2025 Datacenter **with Desktop Experience**

The entries *without* "Desktop Experience" are **Server Core**. Microsoft recommends Server Core unless you need the graphical shell or an application that requires it.

| | Server Core | Server with Desktop Experience |
|---|---|---|
| Local interface | Command line: PowerShell, SConfig, cmd | Standard Windows GUI |
| Disk use | Smaller (about 4 GB less) | Larger |
| Local role management | PowerShell (or remote tools) | Server Manager or PowerShell |
| Roles and features | Some are unavailable; the **App Compatibility Feature on Demand** adds some GUI-era tools for compatibility | All available |
| Remote management | Windows Admin Center, RSAT, Server Manager, PowerShell | Same |
| Attack surface and patching | Smaller, fewer updates touch it | Larger |

Key facts:

- **You cannot convert between the two after installation.** Moving from Server Core to Desktop Experience (or the reverse) requires a clean install or a migration.
- Since Windows Server 2022, Server Core starts **PowerShell** as its default shell and launches **SConfig** automatically at sign-in.
- Evaluation images behave the same way: a Desktop Experience evaluation cannot be converted to a Core retail edition.

> **Exam tip:** "Switch from Core to Desktop Experience without reinstalling" is always the wrong answer on Windows Server 2016 and later.

To check which option a server uses:

```powershell
(Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion').InstallationType
```

The value is `Server Core` or `Server`.

## In-place upgrade paths

An **in-place upgrade** installs the new version over the old one and keeps settings, roles and data. Starting with Windows Server 2025, a non-clustered server can jump up to **four versions** at a time; for 2022 and earlier targets the limit is two. Cluster rolling upgrades always move one version at a time.

Supported paths using installation media:

| From | To 2016 | To 2019 | To 2022 | To 2025 |
|---|---|---|---|---|
| Windows Server 2012 | Yes | No | No | **No** |
| Windows Server 2012 R2 | Yes | Yes | No | **Yes** |
| Windows Server 2016 | n/a | Yes | Yes | **Yes** |
| Windows Server 2019 | n/a | n/a | Yes | **Yes** |
| Windows Server 2022 | n/a | n/a | n/a | **Yes** |

So 2012 R2 is the oldest version that goes straight to 2025. A plain 2012 server must first step to 2012 R2 (or 2016).

**Windows Update** can also deliver the upgrade to 2025, but only from **Windows Server 2019 or 2022** that already has the required cumulative update installed. The server must not be clustered.

### Restrictions on licensed (non-evaluation) servers

- No 32-bit to 64-bit, and no change of **language**.
- **No switching** between Server Core and Desktop Experience during the upgrade.
- No upgrade from prerelease builds, and no upgrade *to* an evaluation copy.
- The edition is kept by default. **Standard to Datacenter** (and to Azure Edition) is allowed during upgrade; **downgrades** (Datacenter to Standard, Azure Edition to either) are not.
- Disable **NIC Teaming** before upgrading; re-enable afterward.
- Servers booting from **VHD**, and Windows Storage Server editions, are unsupported.
- Unlike Windows client, each Windows Server upgrade needs its own license and key.

> **Watch out:** Microsoft's guidance is **not** to in-place upgrade Active Directory domain controllers, because an upgrade does not deliver the AD improvements in 2025. Install a new Server 2025 machine, promote it as a domain controller, move FSMO roles, and demote the old one. A DC also cannot be converted from evaluation to retail.

Before any upgrade: take a full backup and test the restore, collect diagnostics (`Get-ComputerInfo`, `systeminfo`, `ipconfig /all`), shut down or migrate VMs, and check that roles support upgrade. Clustered servers use Cluster-Aware Updating or a **cluster OS rolling upgrade** instead.

### Methods other than in-place

| Method | When |
|---|---|
| Clean install | Fresh start or unsupported in-place scenario |
| Migration | Move roles to a different server, one role at a time |
| Cluster OS rolling upgrade | Keep a Hyper-V or Scale-Out File Server cluster running |
| License (edition) conversion | Same release, change edition or license type |

## Edition conversion with DISM

Within one release you can change edition without reinstalling:

```text
C:\> DISM /online /Get-CurrentEdition
Current Edition : ServerStandardEval

C:\> DISM /online /Get-TargetEditions
Editions that can be upgraded to:
Target Edition : ServerDatacenter
Target Edition : ServerStandard

C:\> DISM /online /Set-Edition:ServerStandard /ProductKey:<retail key> /AcceptEula
```

Rules from Microsoft's conversion article:

- **Evaluation to retail:** always run `/Get-TargetEditions` first. Evaluation Standard converts to retail Standard or Datacenter; evaluation **Datacenter converts only to Datacenter**. A Standard *Core* evaluation converts only to Datacenter *Core*.
- **Standard to Datacenter** is possible at any time with `/Set-Edition:ServerDatacenter`. Running `setup.exe` as a repair or upgrade keeps the same edition.
- An **Essentials** server converts to full retail with `slmgr.vbs /ipk <key>`.
- A domain controller cannot be converted from evaluation to retail.

Microsoft's evaluation runs **180 days** from the Evaluation Center.

## Lab it yourself

1. Install the evaluation twice in Hyper-V: once **Standard** (Core) and once **Standard with Desktop Experience**. Run the `InstallationType` command on both.
2. On the Core VM sign in and notice SConfig starts by itself inside a PowerShell window.
3. On either VM run `DISM /online /Get-CurrentEdition` and `/Get-TargetEditions`. Do not run `/Set-Edition` unless you have a key.
4. If you have a 2022 evaluation VM, mount the 2025 ISO and take a checkpoint before running `setup.exe` to try the in-place upgrade.

## Key takeaways

- Server Core is the default recommendation; you cannot convert to or from Desktop Experience after installation.
- Server 2025 can be reached in place from 2012 R2 and later (up to four versions); 2012 non-R2 cannot jump directly.
- Windows Update upgrades to 2025 work from 2019 and 2022 only, with the required cumulative update.
- Upgrades keep the language and the Core/Desktop choice; edition may go up (Standard to Datacenter) but not down.
- Do not in-place upgrade domain controllers; promote new ones and demote old ones.
- DISM `/Get-TargetEditions` then `/Set-Edition ... /AcceptEula` converts evaluation and Standard installs; an evaluation Datacenter only becomes Datacenter.
