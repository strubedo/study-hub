## Which edition, and why it matters

Windows Server 2025 ships as **Standard**, **Datacenter** and **Datacenter: Azure Edition**, plus an **Essentials** edition for very small organizations. All of them share the same core roles (AD DS, DNS, DHCP, file services, Hyper-V and so on). The differences are in a short list of features, in how many virtual machines the license covers, and in where the edition can run.

| Item | Standard | Datacenter | Datacenter: Azure Edition |
|---|---|---|---|
| Windows Server VMs per license | 2 (plus one Hyper-V host) | Unlimited (plus one Hyper-V host) | Unlimited (plus one Hyper-V host) |
| Hyper-V isolated containers | Up to 2 | Unlimited | Unlimited |
| Storage Spaces Direct | No | Yes | Yes |
| Storage Replica | 1 partnership, 1 resource group, one volume up to 2 TB | Unlimited | Unlimited |
| Network Controller, Host Guardian Hyper-V Support | No | Yes | Yes |
| GPU partitioning | Yes, for standalone servers | Yes, including clusters | Yes, for standalone servers |
| SMB over QUIC server | Yes (new in 2025) | Yes (new in 2025) | Yes |
| Hotpatching | Through Azure Arc | Through Azure Arc | Built in |
| Automatic VM Activation (AVMA) | Only as a guest of a Datacenter host | Yes | Yes |
| KMS host | Yes | Yes | No (activated by Azure) |

These values come from Microsoft's edition and "locks and limits" comparison pages for Windows Server 2025. Two limits apply to every edition: up to 64 sockets, and a maximum number of users that is "based on CALs" rather than a hard cap.

> **Exam tip:** "Unlimited VMs" or "Storage Spaces Direct" in a requirement points to Datacenter. "Two VMs on a standalone host" points to Standard. Neither Standard nor Datacenter has a user cap built into the OS; CALs set that.

### Datacenter: Azure Edition

Azure Edition is built for virtual machines on **Azure** and **Azure Local**. It is activated by Azure, so it can never be a KMS host, and it adds Azure-specific capabilities such as Azure Extended Networking and built-in hotpatching. Do not plan it for a generic on-premises host with a retail key.

### Essentials edition

Essentials is a fixed-capacity edition for small businesses. Microsoft's licensing material describes it as limited to **25 users and 50 devices**, with caps on processors, cores and memory, and with no CALs to buy. That information lives in Microsoft licensing datasheets rather than on Learn, so treat the exact numbers as "verify against the current datasheet before you buy". What Learn does document is the way out: a server running Essentials can be converted to the full retail edition by installing a retail, volume-license or OEM key with `slmgr.vbs /ipk <key>`.

> **Watch out:** "Essentials" in this course title means essential administration skills. The Essentials *edition* is only one item in topic 1.1.

## Core-based licensing

Standard and Datacenter are licensed by the **physical cores** in the server, not by sockets or by virtual cores. Microsoft's licensing terms set these minimums:

- every physical core in the server must be licensed;
- at least **8 core licenses per physical processor**;
- at least **16 core licenses per server**.

So a host with two processors of six cores each (12 physical cores) still needs **16** core licenses, because of the per-server minimum. A single-socket host with 12 cores needs 12 (above the 8-per-processor floor), but the per-server floor lifts it to 16. A two-socket host with 16 cores each needs 32.

Virtual cores never change the count. A guest with 16 vCPUs on a host licensed for 16 physical cores consumes no additional core licenses.

> **Watch out:** The 8-per-processor and 16-per-server minimums are in Microsoft's licensing terms and datasheets, not restated on the Learn edition pages. Licensing outcomes ultimately follow your agreement (Product Terms), so confirm with a licensing partner for real purchases.

### Virtualization rights

Once all cores in a host are licensed:

- **Standard** lets you run **two** Windows Server operating system environments (VMs) plus the Hyper-V host role used only to host and manage them. To run more VMs, license all cores again ("stack") for each additional pair.
- **Datacenter** lets you run **unlimited** VMs on that host.

The rights belong to the *host's* licenses, regardless of hypervisor brand. Microsoft's own page confirms the 2-versus-unlimited split in the locks and limits table; the stacking rule is part of the licensing terms.

## CALs

A **Client Access License** gives a user or a device the right to access a server. In the traditional model Standard and Datacenter servers need CALs for the users or devices that use them (a **User CAL** per person or a **Device CAL** per device), the CAL version must be at least the server version, and **Remote Desktop Services** access needs separate RDS CALs on top. The CAL rules are licensing terms rather than Learn documentation, so they are listed as such in the unverified notes for this course.

Microsoft's pay-as-you-go page (next lesson) adds one thing you can cite directly: with Arc pay-as-you-go there are **no CALs required for standard functionality**, but **RDS CALs are still required**.

## Choosing quickly

| Requirement | Pick |
|---|---|
| One or two VMs on a standalone server, no S2D | Standard |
| Dense virtualization, S2D, Network Controller, shielded VM hosting | Datacenter |
| Windows Server VMs in Azure or Azure Local with built-in hotpatching | Datacenter: Azure Edition |
| Under about 25 users, no virtualization, simple needs | Essentials (check current caps) |

## Lab it yourself

1. Download the free **180-day evaluation** of Windows Server 2025 from the Microsoft Evaluation Center.
2. In Hyper-V on your lab PC, create a Generation 2 VM (4 GB RAM, 60 GB disk) and install **Standard (Desktop Experience)** from the ISO.
3. In PowerShell, run `DISM /online /Get-CurrentEdition` and note the edition name (an evaluation shows an `Eval` suffix).
4. Run `Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors` and work out how many core licenses a physical server with that processor would need.
5. Run `DISM /online /Get-TargetEditions` and note which editions the evaluation can convert to.

## Key takeaways

- Standard covers 2 VMs per fully licensed host; Datacenter and Azure Edition cover unlimited VMs.
- S2D, Network Controller and Host Guardian Hyper-V Support are Datacenter features; Standard gets limited Storage Replica (one 2 TB volume).
- Core licensing: license every physical core, minimum 8 per processor and 16 per server; vCPUs do not count.
- Azure Edition is activated by Azure, cannot be a KMS host, and is meant for Azure and Azure Local VMs.
- SMB over QUIC server moved down from Azure Edition to Standard and Datacenter in 2025.
- Essentials is fixed capacity (25 users and 50 devices per Microsoft's licensing material); verify exact caps before buying.
- Traditional licensing needs CALs, and RDS needs its own CALs; pay-as-you-go removes the base CAL requirement but not RDS CALs.
