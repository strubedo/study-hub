## Windows Update on a server

Servers receive the same kinds of updates as clients: monthly **quality updates** (which include security fixes) and **feature updates**. On Windows Server, a *feature update* in the Windows client sense is an OS upgrade, and feature updates from Microsoft Update are offered through SConfig only on Azure Local. To move Windows Server to a newer version you use installation media or the Windows Update upgrade path described earlier.

Where update behavior is controlled:

| Tool | What it does |
|---|---|
| SConfig option 5 | Automatic (daily 3:00 AM), download only (default), or manual |
| SConfig option 6 | Search and install quality updates now |
| Settings > Windows Update | Desktop Experience GUI |
| Group Policy | Fleet-wide Windows Update client settings, including the WSUS server address |
| Azure Update Manager | Orchestrates updates for Azure and Azure Arc-enabled servers |
| `Get-HotFix` | Lists installed updates |

> **Real world:** Automatic install on a production server is rarely what you want. Download-only plus a maintenance window, or Azure Update Manager schedules, is the common design.

## WSUS concepts

**Windows Server Update Services (WSUS)** is a server role that downloads updates from Microsoft Update once, lets you **approve** and **decline** them, and serves them to clients on your network.

| Concept | Meaning |
|---|---|
| Upstream / downstream | An upstream WSUS gets updates from Microsoft Update (or another WSUS); downstream servers pull from it |
| Computer groups | Target groups you approve updates for (for example Pilot and Production) |
| Classifications and products | Filters for what the server synchronizes |
| Client targeting | By server-side assignment or client-side through Group Policy |
| Database | Windows Internal Database or SQL Server |
| Reporting and PowerShell | Cmdlets exist for the most common admin tasks |

Clients are pointed at the WSUS server with Group Policy: **Computer Configuration > Administrative Templates > Windows Components > Windows Update > Specify intranet Microsoft update service location**.

**Status:** Microsoft lists WSUS as *no longer actively developed*. All existing capabilities remain, and the role continues to ship in Windows Server 2025, is supported for production, and receives security and quality updates. It is deprecated, not removed. Microsoft points toward Azure Update Manager, Windows Update for Business or Intune for new designs. The **Windows Internal Database** that WSUS commonly uses is also marked deprecated and will be removed in a future release.

> **Exam tip:** "WSUS in Server 2025" is a trap in both directions: it is not removed, and it is not receiving new features.

## Hotpatching

**Hotpatching** installs OS security updates **without a restart** by patching the in-memory code of running processes.

### The baseline cycle

- A **baseline** is a normal cumulative update that **requires a restart**.
- After a baseline, the next **two months** deliver **hotpatches** with no restart. Example: a January baseline means February and March are hotpatch months.
- That makes **four planned baselines and eight hotpatch releases** per year (baselines every three months).
- An **unplanned baseline** (for example a zero-day that cannot be hotpatched) replaces a hotpatch month and requires a restart.
- Non-security updates, .NET updates and non-Windows updates (drivers, firmware) are **not** in the hotpatch stream and still need restarts.
- Hotpatches do not support automatic rollback: uninstall the update and install the last functional baseline, which needs a restart.

### Where it works

| Platform | Details |
|---|---|
| Datacenter: Azure Edition | Hotpatch built in on Azure and Azure Local VMs |
| Windows Server 2025 Standard or Datacenter | Through **Azure Arc**: connect the Connected Machine agent and enable Hotpatch in Azure Arc |

Microsoft's current documentation states Arc-enabled Hotpatch for Windows Server 2025 is available **at no extra cost** (it earlier had a charge, so older articles may disagree). Prerequisites for the Arc route:

- Windows Server 2025 **build 26100.1742 or later** (no preview or Insider builds).
- Standard or Datacenter, **Server Core or Desktop Experience**.
- **Virtualization-based security** (virtual secure mode) running. At minimum that means **UEFI with Secure Boot**, so a Hyper-V VM must be **Generation 2**.
- An Azure subscription and the machine **Arc-enabled**.

If the portal reports that Virtual Secure Mode is not running, enable a VBS-dependent feature (Credential Guard, memory integrity/HVCI, System Guard Secure Launch, Secured-core server) and retry.

Patch orchestration for Arc-connected machines comes from **Azure Update Manager**, Group Policy-configured Windows Update client settings, SConfig on Server Core, or third-party tools.

> **Watch out:** Hotpatch is not available by simply installing a different update on any server. On-premises Standard or Datacenter must be Arc-enabled, and a Generation 1 VM or a BIOS-boot server fails the prerequisite.

## Lab it yourself

1. On the Core VM from the last lesson, open SConfig, use option 5 to leave updates on **Download only**, then option 6 to search quality updates.
2. Run `Get-HotFix | Sort-Object InstalledOn -Descending | Select-Object -First 5`.
3. If you have an Azure free account, onboard the lab VM (Generation 2, Secure Boot on) to Azure Arc and open the Updates blade; check whether Hotpatch can be turned on.
4. Optional: add the WSUS role to a lab server through Server Manager's Add Roles and Features Wizard on a Desktop Experience VM just to see the console and computer groups; no real synchronization is needed.

## Key takeaways

- SConfig 5 sets automatic/download-only/manual; SConfig 6 installs quality updates; Group Policy points clients at WSUS.
- WSUS approves updates for computer groups, supports upstream/downstream, is deprecated (no new features) but still supported in 2025.
- Hotpatch cycle: baseline with restart, then two hotpatch months, four baselines a year.
- Hotpatch covers Windows security updates only; drivers, .NET and other updates still need restarts.
- 2025 Standard and Datacenter get hotpatch through Arc, with VBS, UEFI and Secure Boot, and build 26100.1742 or later.
- Azure Edition has hotpatch built in on Azure and Azure Local.
