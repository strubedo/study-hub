## Why manage SD-WAN centrally

A branch SD-WAN design is the same few objects repeated on every site: two or three underlay members, one or two overlay tunnels, a zone per transport, a handful of performance SLAs and the same SD-WAN rules. Configured by hand on fifty FortiGates, those objects drift: a typo in one health-check server, a rule order that differs on three sites, a member cost nobody remembers changing. FortiManager solves this by keeping one copy of the design and pushing it to every device, while each FortiGate still makes its own forwarding decisions locally.

Keep that split in mind for the exam:

| Job | Done by |
|---|---|
| SLA probing, member selection, rule matching, routing, session handling | The FortiGate, always |
| Storing the configuration, templating it, installing it, showing monitoring data from many devices | FortiManager |

If FortiManager goes offline, SD-WAN keeps working on every FortiGate. You only lose central changes and central monitoring.

## FortiManager basics you need for SD-WAN

### ADOMs

An administrative domain (ADOM) is a separate management space with its own devices, policy packages, objects, provisioning templates and metadata variables. Each ADOM has a FortiOS version; FortiGates running FortiOS 7.6 belong in a 7.6 ADOM. SD-WAN templates, overlay templates and metadata variables are all **per ADOM**, so a template built in ADOM `Retail` is not visible from ADOM `Branches`.

### Device layer and ADOM layer

FortiManager keeps two kinds of configuration for each managed FortiGate:

| Layer | Where you edit it | Holds |
|---|---|---|
| Device layer (device database) | Device Manager, provisioning templates, SD-WAN Manager | Interfaces, routing, SD-WAN, system settings: anything that is per device |
| ADOM layer | Policy & Objects | Policy packages, firewall objects, normalized interfaces, metadata variables |

SD-WAN configuration (`config system sdwan`) is device-level, so SD-WAN templates install with **Install Device Settings (only)**. Firewall policies that use the SD-WAN zones live in a policy package and install with **Install Policy Package & Device Settings**.

### FGFM and the managed device

FortiManager and FortiGate talk over the FortiGate-FortiManager protocol (FGFM), TLS on **TCP 541**. On the FortiGate the link is configured under `config system central-management`:

```text
FGT-Branch1 # config system central-management
FGT-Branch1 (central-management) # set type fortimanager
FGT-Branch1 (central-management) # set fmg "192.0.2.50"
FGT-Branch1 (central-management) # end
```

The device is then authorized in Device Manager, or FortiManager adds it by IP address, and its configuration is imported into the device database.

### Config status

Device Manager > Device & Groups (Table View) shows how the FortiManager copy compares with the device:

| Config Status | Meaning |
|---|---|
| Synchronized | FortiManager and the FortiGate match |
| Modified | Changed on FortiManager, not installed yet |
| Auto-update | Changed on the FortiGate and automatically synced into FortiManager |
| Modified (recent auto-updated) | Changed on FortiManager, and recent device-side changes were auto-synced |
| Out of Sync | Changed on the FortiGate and **not** synced to FortiManager |
| Conflict | An install failed, or both sides changed without auto-sync |
| Unknown | Connection down, or no revision yet (for example a model device) |

A Conflict is resolved one of two ways: retrieve the device configuration (revision history, **Retrieve Config**, then re-import the policy), or push FortiManager's copy with **Install Device Settings (only)**.

### Installing

| Operation | What it does | Preview |
|---|---|---|
| Install Policy Package & Device Settings | Copies the policy package into the device layer, then installs the difference | Yes |
| Install Device Settings (only) | Installs the device layer only (interfaces, routes, SD-WAN, templates) | Yes |
| Quick Install (Device DB) | Installs the device layer at once | **No** preview, can't be cancelled |

> **Exam tip:** FortiManager installs only the *difference* between its device database and the FortiGate. The Install Preview shows the exact CLI it will send, and metadata variables appear there with their **resolved** values.

## The SD-WAN Manager pane in FortiManager 7.6

FortiManager 7.6 groups SD-WAN work in its own top-level module, **SD-WAN Manager**:

| Menu | Contents |
|---|---|
| Network > Devices | Devices with SD-WAN management enabled; works like Device Manager |
| Network > Monitor | The SD-WAN Monitor (map, table, template and history views) |
| Templates | Template Groups, IPsec Tunnel, BGP, Static Route and CLI templates used for SD-WAN |
| Overlay Orchestration | SD-WAN overlay templates (the overlay wizard) |
| Rules | **SD-WAN templates**: zones and members, SD-WAN rules, performance SLAs, neighbors, duplication |

The module can be hidden: `config system admin setting` → `set show-sdwan-manager disable` (default `enable`). The GUI equivalent is **Show SD-WAN Manager** in System Settings > Advanced > Misc Settings. Then SD-WAN devices, templates and monitoring are handled from Device Manager instead (provisioning templates live in Device Manager > Provisioning Templates either way).

> **Watch out:** In the 7.6 menus (checked in the 7.6.3, 7.6.4 and 7.6.5 guides), SD-WAN templates sit under **SD-WAN Manager > Rules**, not under SD-WAN Manager > Templates, while the overlay wizard is under **Overlay Orchestration**. The two are different features. Don't confuse the SD-WAN *template* (rules, SLAs, members) with the SD-WAN *overlay template* (IPsec, BGP and CLI generation).

### Enabling SD-WAN management on a device

A FortiGate appears in SD-WAN Manager > Network > Devices only when SD-WAN management is enabled for it, and it must be enabled before the device can be used in an SD-WAN overlay template.

* Existing device: Device Manager > Device & Groups, select the device(s), **More > Enable SD-WAN Management**. The device is then grayed out in Device Manager, with links to the SD-WAN Manager dashboard and its device database.
* Model device: Add Device > Add Model Device, turn on **Managed by SD-WAN Manager**.
* To stop: **More > Disable SD-WAN Management**; the device leaves the SD-WAN Manager Devices table and is managed from Device Manager again.

## Per-device management or SD-WAN templates

FortiManager supports two ways to hold a FortiGate's SD-WAN configuration:

| | Per-device management | Central management |
|---|---|---|
| Where | Device database > **Network > SD-WAN** for one device | **SD-WAN template** assigned to devices or device groups |
| Good for | One-off sites, hubs with unique settings, quick fixes | Many branches with the same design |
| What you configure | Zones, members, SLAs, rules, neighbors, duplication for that device | The same sections, once, for every assigned device |

The FortiManager guide is explicit: if you want per-device management, **don't assign an SD-WAN template** to that device. Assigning a template means the template owns the device's SD-WAN configuration.

After an SD-WAN template is installed, any change made locally on the FortiGate to SD-WAN, Performance SLA or SD-WAN Rules leaves the template **out of sync** with the device. The fix is to make the same change in the template on FortiManager and install again; otherwise the next install puts the template's values back.

## The SD-WAN Monitor

SD-WAN Manager > Network > Monitor (reached from Device Manager instead when the SD-WAN Manager module is hidden) pulls SLA, interface and rule data from the FortiGates. A dropdown filters by all devices or an SD-WAN device group; Template View has its own template selector.

| View | What it shows |
|---|---|
| Map View | Devices on a map; filters **Show Unhealthy Devices Only** (devices that don't meet the performance SLA) and **Show Unhealthy Interfaces Only**; click a device for details |
| Table View | Per device and SD-WAN interface: Upload, Download, Measured Bandwidth, Link Mode, Errors (TX/RX), Applications; donut charts such as Devices by Link Status act as filters |
| Template View | Pick an SD-WAN overlay template: hubs show as a star, spokes as a device icon; tunnel lines green (up) or red (down) |
| History View | Charts for one device plus an **SD-WAN Rules** widget: selected members have a check mark, red interfaces are down |

Template View colours a spoke by its health checks: green when all pass, orange when some pass, red when all fail. A hub without health checks is coloured by its underlays instead (all up, some up, all down).

Two details worth memorising:

* **Port bandwidth usage** on the map needs the **estimated bandwidth** configured on the FortiGate interfaces used by SD-WAN.
* **SD-WAN monitoring history is disabled by default.** Without it, FortiManager shows only the **last 10 minutes**, read live from the FortiGates, and stores nothing. Enable it in the CLI:

```text
FMG-HQ # config system admin setting
FMG-HQ (setting) # set sdwan-monitor-history enable
FMG-HQ (setting) # end
```

With history enabled, data is kept for 180 days by default (`rtm-max-monitor-by-days`, 1-180), with a per-device size cap `rtm-max-monitor-by-size`. History costs disk space and processing on a FortiManager that manages many devices, so enable it only when you need data older than 10 minutes.

> **Real world:** The monitor is only as good as what the FortiGates measure. If a branch has no performance SLA, FortiManager has no SLA data to show for it. Fix the template, not the monitor.

The Table View can also run an on-demand **FortiGuard speed test** on WAN-role interfaces, but only with the SD-WAN Underlay Bandwidth and Quality Monitoring Service subscription (up to 10 tests per day). A trial lab won't have it.

## Use cases

| Requirement | FortiManager feature |
|---|---|
| Roll the same SLAs and rules to 40 branches | SD-WAN template assigned to a device group |
| Bring up IPsec overlays and BGP to two hubs for every branch | SD-WAN overlay template (Lesson 3.1 overlay) plus an SD-WAN template |
| Give every branch its own gateway IP or LAN subnet in shared templates | ADOM-level metadata variables |
| Preconfigure a branch before it ships | Model device with **Managed by SD-WAN Manager**, then zero-touch install when it connects |
| See which branches are out of SLA right now | SD-WAN Monitor, Show Unhealthy Devices Only |
| One hub with unique settings | Per-device SD-WAN in the device database, no template |

## Lab it yourself

The FortiManager-VM trial manages **3 devices/VDOMs** in up to **2 ADOMs**, with no FortiGuard. The FortiGate-VM trial is limited to 3 interfaces, 3 firewall policies and 3 routes.

1. Point your FortiGate-VM (`FGT-Branch1`) at the FortiManager-VM (`FMG-HQ`) with `config system central-management` and authorize it in Device Manager.
2. Note the Config Status, then change a static route on the FortiGate and watch it change (Auto-update or Out of Sync, depending on your settings).
3. Select the device and choose **More > Enable SD-WAN Management**. Confirm it now appears in SD-WAN Manager > Network > Devices.
4. Add a model device `FGT-Branch2` with **Managed by SD-WAN Manager** on. It counts toward the 3-device limit.
5. Open SD-WAN Manager > Network > Monitor and compare Map View and Table View for the real device. With history disabled, check that only the last 10 minutes are available.

## Key takeaways

* FortiManager stores and pushes SD-WAN configuration; the FortiGate still probes, selects members and routes on its own.
* SD-WAN settings are device-level: they install with Install Device Settings (only); policies using zones install with the policy package.
* FGFM uses TCP 541. Config statuses: Synchronized, Modified, Auto-update, Out of Sync, Conflict, Unknown.
* FortiManager 7.6 has an SD-WAN Manager module: Network (Devices, Monitor), Templates, Overlay Orchestration, Rules (SD-WAN templates). `show-sdwan-manager` hides it.
* A device must have SD-WAN management enabled to appear in SD-WAN Manager and to be used in an overlay template.
* Assigning an SD-WAN template means central management; local SD-WAN changes on the FortiGate then put the template out of sync.
* SD-WAN monitoring history is off by default (last 10 minutes only); `sdwan-monitor-history enable` stores up to 180 days by default.
