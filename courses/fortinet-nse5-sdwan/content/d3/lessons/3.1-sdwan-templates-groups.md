## SD-WAN templates in one sentence

An SD-WAN template is one copy of `config system sdwan` (zones, members, health checks, rules and optional neighbors and duplication) that FortiManager installs on every FortiGate or device group you assign it to. It is the central-management alternative to editing SD-WAN per device in the device database.

The benefits FortiManager lists are the ones you'd expect: one template deployed to many FortiGates, zero-touch deployment without local configuration, a uniform design, fewer configuration errors, and central monitoring of performance SLAs.

## Where templates live

In FortiManager 7.6 go to **SD-WAN Manager > Rules**. The content pane lists the SD-WAN templates in the current ADOM, with **Create New**, **Edit**, **Delete**, **Import** and **Assign to Device/Group** in the toolbar. Make sure you're in the right ADOM first: templates are per ADOM.

## Building a template

Create New opens the template with these sections, which mirror the FortiGate's Network > SD-WAN page:

| Section | What you configure | Required |
|---|---|---|
| Name | Template name | Yes |
| SD-WAN Zones | Zones and interface members | Yes |
| SD-WAN Rules | The rules (services), in order | Usually |
| Performance SLA | Health checks and SLA targets (defaults are offered) | Usually |
| Neighbor | BGP neighbors tied to SD-WAN members and an SLA | Optional |
| Duplication | Packet duplication rules | Optional |
| Advanced Options | Global SD-WAN options (hover for descriptions) | Optional |

### Zones and members

A member needs a **Sequence Number**, the **Interface Member** (the port name), the **SD-WAN Zone**, the **Gateway IP**, a **Status** toggle and optional **Installation Target**s. Interface Member and Gateway IP accept metadata variables, which is how one template serves branches whose ISP gateways differ.

> **Watch out:** Normalized interfaces are **not supported** for SD-WAN template members. Bind members by interface name (`port1`, `HUB1-VPN1`) or with a metadata variable that resolves to a name. Normalized interfaces are for policy packages.

As on the FortiGate, zones are what firewall policies reference; members can't be selected in policies. The default zone is `virtual-wan-link`.

### Rules

The rule dialog has the same building blocks as FortiOS: name, IP version, source address and user groups, destination address, protocol and port range, Internet Service and Application criteria, then **Outgoing Interface**: the strategy (Manual, Best Quality or Lowest Cost (SLA)), the interface preference order (top = preferred), zone preference, the measured SLA for Best Quality or the required SLA target for Lowest Cost (SLA), and advanced options. FortiManager's rule order matters exactly as it does on the FortiGate: the first matching rule wins.

> **Exam tip:** Since FortiOS 7.4.1 the old Maximize Bandwidth (SLA) strategy is load balancing inside a Manual or Lowest Cost (SLA) rule (`set load-balance enable`). Some FortiManager field help still uses the old name. Answer exam questions with the 7.6 FortiOS behaviour.

### Performance SLA

A performance SLA in the template has a name, IP version, **Probe Mode** (Active by default, Passive, Prefer-passive, Remote, Agent Based), protocol (Ping, TCP ECHO, UDP ECHO, HTTP, TWAMP, DNS, TCP Connect, FTP), servers, **Participants** (specific members or All SD-WAN Members), **Embedded Measure Health**, SLA targets (latency, jitter, packet loss, plus priority in SLA / out of SLA), link status settings (check interval, failures before inactive, restore link after) and the action when inactive: **Update Static Route** or **Cascade Interfaces**.

The participants must already exist as members in the same template.

### Neighbors and duplication

A **Neighbor** entry ties a BGP neighbor IP to one or more interface members and a performance SLA, with a role of Standalone, Primary or Secondary. The BGP neighbor itself must already exist for the devices (normally from a BGP template). When several members are selected for a neighbor, route failover happens only when all of them are down. **Duplication** configures packet duplication. Both are NSE 7-level design topics; for Core you just need to know they are part of the template.

## Importing a template from a FortiGate

If a branch already has a working SD-WAN configuration, **Import** builds a template from it: name the template, pick the device, add a description. FortiManager adds the prefix **Import** to templates imported from FortiGate devices. Review the result: imported member names, gateways and server IPs are that device's literal values, so replace site-specific values with metadata variables before you assign the template to other branches.

## Assigning and installing

1. Select the template and click **Assign to Device/Group**, move FortiGates or device groups to Selected Entries, and click OK.
2. Install with the Install Wizard, **Install Device Settings (only)**.
3. Check the result in SD-WAN Manager > Network > Monitor.

Nothing changes on the FortiGate until the install runs. FortiManager's guide gives the template order as interface template, then IPsec template, then SD-WAN template: the SD-WAN template references tunnel interfaces that must already exist. Template groups (below) enforce the order for you.

Two install blockers come up again and again:

| Problem | Why | Fix |
|---|---|---|
| Install fails on a new FortiGate | Some models ship with a default policy that references a physical interface, and an interface that is referenced directly in a firewall policy can't become an SD-WAN member | Delete the default policy (CLI/GUI), or first install a policy package that doesn't contain it |
| Template shows out of sync | Someone changed SD-WAN, Performance SLA or SD-WAN Rules locally on the FortiGate | Make the change in the template and reinstall; local edits are overwritten otherwise |

A typical Install Preview for a branch assigned to template `Branch-SDWAN`:

```text
FMG-HQ  Install Preview  FGT-Branch1 (root)

config system sdwan
    set status enable
    config zone
        edit "underlay"
        next
    end
    config members
        edit 1
            set interface "port1"
            set zone "underlay"
            set gateway 203.0.113.1
        next
        edit 2
            set interface "port2"
            set zone "underlay"
            set gateway 198.51.100.1
            set cost 10
        next
    end
    config health-check
        edit "Internet_HC"
            set server "8.8.8.8"
            set members 1 2
            config sla
                edit 1
                    set latency-threshold 150
                    set jitter-threshold 30
                    set packetloss-threshold 2
                next
            end
        next
    end
end
```

If the template used `$(wan1_gw)` for member 1's gateway, the preview would already show the resolved `203.0.113.1` for this device.

## Template groups

Branches need more than SD-WAN: IPsec tunnels, BGP, static routes, a few CLI lines. Assigning five templates to every device is error prone, so FortiManager lets you bundle them in a **template group** and assign the group instead.

* Where: **SD-WAN Manager > Templates > Template Groups**, or **Device Manager > Provisioning Templates > Template Group**.
* Assign to: one or more devices or VDOMs, or a device group. Device & Groups (Table View) then shows the group name in the **Provisioning Templates** column.
* Contents: **one template of each type**. Types include system, threat weight, IPsec tunnel, static route, BGP, NSX-T service, **SD-WAN**, FortiSwitch, FortiExtender, CLI template and CLI template group. AP profiles are the exception: several can be selected.
* Order: FortiManager installs the member templates **in the correct order** (for example the IPsec template before templates that configure the tunnel interfaces) and uninstalls them in the correct order too.

> **Exam tip:** A template group can't contain two SD-WAN templates or two IPsec templates. If a branch needs settings from two templates of the same type, merge them, or use a CLI template group for extra CLI.

## The other provisioning templates SD-WAN uses

| Template | SD-WAN role |
|---|---|
| IPsec tunnel | Standard overlay tunnels for many devices; metadata variables make per-device values; tunnels can be mapped to normalized interfaces for policies |
| BGP | BGP settings for hubs and branches (neighbors, networks, router ID) |
| Static route | Static routes, typically a default route to an SD-WAN zone |
| CLI | CLI or Jinja scripts for anything the other templates don't cover; CLI template groups combine several |

## Preview, validate, compare

FortiManager gives you three ways to see what a template will do, and they differ in one important detail:

| Tool | Where | Shows metadata variables as |
|---|---|---|
| **Preview CLI Configuration** | Right-click a provisioning template; pick a device from the Device dropdown | **Variable names**, not resolved values |
| **Validate** | **CLI templates** only: select an assigned CLI template > More > Validate | Each device's **resolved value**; Show Missing Variable Devices Only, click a value to edit it, Preview Script, Re-validate |
| **Install Preview** | Install Wizard | **Resolved real values** for the target device |

Provisioning templates also keep **revisions**: each save creates one, and View Diff shows a JSON diff between two revisions. Templates can be exported as JSON and imported into another ADOM or FortiManager.

## Use cases

* **Uniform DIA at every store:** one template with zone `underlay` (`port1`, `port2`), `Internet_HC` and rule `Critical-DIA`; gateways come from metadata variables; assigned to device group `Stores`.
* **Brownfield onboarding:** import the SD-WAN of the best-run branch, rename it from `Import...`, replace literals with variables, assign to the rest.
* **Hub and branch bundle:** template group `BRANCH` = IPsec + BGP + static route + SD-WAN + CLI; assign it to the branch device group so new members get everything in the right order.

## Lab it yourself

On the FortiManager-VM trial with one real FortiGate-VM (3 interfaces: LAN `port3`, WAN `port1`/`port2`):

1. Import the FortiGate's SD-WAN as a template and note the `Import` prefix.
2. Create a metadata variable `wan2_gw` and use it as member 2's Gateway IP.
3. Assign the template to the device, open Install Preview and confirm the resolved gateway. Compare with Preview CLI Configuration, which shows the variable name.
4. Change the health-check interval locally on the FortiGate, then look at the template and device status in FortiManager.
5. Build a template group with the SD-WAN template and a CLI template and assign it instead of the single template.

## Key takeaways

* SD-WAN templates are in SD-WAN Manager > Rules, per ADOM, and install with Install Device Settings (only).
* Sections: SD-WAN Zones (members and zones), SD-WAN Rules, Performance SLA, Neighbor, Duplication, Advanced Options.
* Members are bound by interface name or metadata variable; normalized interfaces aren't supported for members.
* Imported templates get an `Import` prefix; replace device-specific literals before reuse.
* Delete a default policy that references a future member interface before installing; local SD-WAN edits put the template out of sync.
* Template groups hold one template per type (AP profiles excepted) and FortiManager installs them in the right order.
* Preview CLI Configuration shows variable names; Install Preview shows resolved values.
