## Where SD-WAN shows up in the FortiGate GUI

FortiOS 7.6 gives you four places to watch SD-WAN without touching the CLI:

| Place | Answers the question |
|---|---|
| Network > SD-WAN > **SD-WAN Zones** tab | How is traffic spread over the members right now? |
| Network > SD-WAN > **SD-WAN Rules** tab | Which member is each rule using, and is the rule being hit? |
| Network > SD-WAN > **Performance SLAs** tab | How healthy is each member, measured by each health check? |
| Dashboard > **Network** (SD-WAN, Static & Dynamic Routing, IPsec widgets) and FortiView | What is the overall status, which routes and policy routes are active, where did a session go? |

Domain 1 introduced these views; this lesson is about reading them to analyse behaviour.

## SD-WAN Zones tab: interface usage

Above the zone and member table, the SD-WAN Zones tab has three selectable views:

| View | Shows | Use it to |
|---|---|---|
| **Bandwidth** | Downloaded and uploaded traffic per interface | Spot a saturated member or confirm a spillover threshold is being reached |
| **Volume** | Donut charts of received and sent bytes per interface | Check a `measured-volume-based` (Volume) implicit rule or volume-ratio design |
| **Sessions** | Donut chart of active sessions per interface | Check `source-ip-based` or `weight-based` (Sessions) distribution |

Match the view to the implicit rule's `load-balance-mode`. A Sessions donut that is 50/50 can still be a Volume donut that is 90/10: a few heavy users on one member move most of the bytes.

> **Exam tip:** These charts show *where traffic went*, not *why*. They can't tell you whether an SD-WAN rule or the implicit rule chose the member. For that, use the SD-WAN Rules tab, traffic logs (`vwlid`/`vwlname`) or `diagnose firewall proute list`.

## SD-WAN Rules tab: what each rule is doing

Each rule row lists its members and a **Hit Count**.

* The member the rule is currently using has a **checkmark** next to its name in the Members column.
* **Hover over the checkmark** to see a tooltip with the reason that member was selected (for example, it meets the SLA and is first in the order).
* If several members are selected, only the **highest ranked** one is highlighted, except for load-balancing rules, where all members in use are marked.
* A hit count that stays at zero while users complain means traffic isn't matching the rule: check the rule's source, destination and protocol, the rule order, and whether a route problem makes FortiOS skip the rule (Lesson 3.3).

The GUI picture corresponds directly to `diagnose sys sdwan service4`: the checkmark is the first `selected` member in the output.

## Performance SLAs tab: member health

Select a performance SLA (health check) in the table to see live charts for each participating member:

| Chart | Unit |
|---|---|
| **Packet Loss** | Percentage of probes lost |
| **Latency** | Current latency in ms |
| **Jitter** | Jitter in ms |

Hover a line to see the value for a member at a given time. The table shows each health check's servers, the link-quality data and the configured thresholds. A coloured **arrow** shows each member's status at the last check: **green** means the member is active (alive), **red** means it is inactive (dead for that health check).

What the GUI does *not* show directly is the SLA target bitmap. A member can have a green arrow (alive) and still be **out of SLA** because its latency is over the target. In the CLI that is `state(alive)` with an `sla_map` bit cleared; in logs it is `Member status changed. Member out-of-sla.`

> **Watch out:** Alive and in-SLA are different tests. "Dead" comes from `failtime` consecutive probe failures and affects every rule using that member; "out of SLA" compares measured values against the targets of one SLA entry and matters only to rules that require that SLA target.

## Network dashboard widgets

Dashboard > **Network** groups networking widgets; each can be expanded to full screen and saved as a monitor.

| Widget | Use for SD-WAN |
|---|---|
| **SD-WAN** | Summary of SD-WAN status, including ADVPN shortcut information |
| **Static & Dynamic Routing** | Active routes in the routing table; toggle to **Policy** to see active policy routes, which include your policy routes, **SD-WAN rules** and Internet Service static routes |
| **IPsec** | Overlay tunnel status (site-to-site and dial-up) |

The Policy view of the routing widget is the GUI equivalent of `diagnose firewall proute list`. It reminds you of the lookup order: policy routes, including SD-WAN rules, are evaluated before the routing table.

Monitors can also be added from the Comprehensive dashboard template, which includes an **SD-WAN Monitor** alongside the Routing, IPsec and other non-FortiView monitors.

## FortiView: following sessions

**Dashboard > FortiView Sessions** shows the destination interface of each session, which is the quickest GUI check that steering works. Fortinet's own example uses a source-IP-based implicit rule with two members: hosts with even source addresses leave one member and odd addresses the other. FortiView Policies, drilled down on the SD-WAN policy, shows which interfaces the policy's traffic used. The real-time (now) view of FortiView Sessions reads the session table; historical FortiView views need a log device (disk or FortiAnalyzer) and traffic logging on the policy (`set logtraffic all`, or `utm` for security events only).

## How FortiManager gets the same data

FortiManager's SD-WAN Monitor (Lesson 3.1) reads the FortiGates' monitoring REST API, the same data the GUI uses:

| REST endpoint | Data |
|---|---|
| `/api/v2/monitor/virtual-wan/health-check` | Health-check status per member |
| `/api/v2/monitor/virtual-wan/sla-log` | Short SLA history |
| `/api/v2/monitor/virtual-wan/interface-log` | Interface bandwidth history |

On the FortiGate those histories are short (about 10 minutes of SLA data, 15 minutes of interface data). Long-term trending needs FortiManager SD-WAN monitoring history, FortiAnalyzer, or periodic SLA logs.

The FortiManager map's port bandwidth usage depends on the interfaces' **estimated bandwidth**:

```text
FGT-Branch1 # config system interface
FGT-Branch1 (interface) # edit "port1"
FGT-Branch1 (port1) # set estimated-upstream-bandwidth 50000
FGT-Branch1 (port1) # set estimated-downstream-bandwidth 200000
FGT-Branch1 (port1) # end
```

Values are in kbps.

## Reading the views together

| Symptom in the GUI | Likely meaning | Confirm with |
|---|---|---|
| Rule `DC-Apps` has a checkmark on `HUB1-VPN2`, not `HUB1-VPN1` | VPN1 is dead or out of SLA, or VPN2 is better (Best Quality) | Performance SLAs tab; `diagnose sys sdwan service4` |
| Hit count of `Critical-DIA` is 0 | Traffic doesn't match, a rule above catches it, or FIB checks fail | `diagnose firewall proute list`; `diagnose debug flow` |
| Sessions donut 50/50, Volume donut 85/15 | Session-based distribution with uneven users | Expected; consider Volume or Spillover mode |
| Red arrow on `port2` in `Internet_HC` | `port2` failed `failtime` probes in a row | `diagnose sys sdwan health-check Internet_HC`; event log 0100022921 |
| Green arrow but rule avoids the member | Alive but out of SLA | `sla_map` in `diagnose sys sdwan health-check` |

## Lab it yourself

With the FortiGate-VM trial (LAN `port3`, WAN members `port1` and `port2` in zone `underlay`) and a Linux router between `port2` and its gateway:

1. Create `Internet_HC` (ping) with an SLA of 100 ms latency. Generate traffic from a LAN host and look at Bandwidth, Volume and Sessions.
2. On the Linux router add delay: `tc qdisc add dev eth1 root netem delay 150ms`. Watch the Latency chart and note that the arrow stays green.
3. Create a Lowest Cost (SLA) rule that requires the SLA target and watch its checkmark move to `port1`.
4. Add `loss 100%` to the netem rule and watch the arrow go red after `failtime` failures.
5. Open Dashboard > Network, expand Static & Dynamic Routing and switch to Policy.

No FortiGuard is needed; ping probes to your own lab host work offline.

## Key takeaways

* SD-WAN Zones tab: Bandwidth, Volume (donuts of bytes) and Sessions (donut of sessions) per member.
* SD-WAN Rules tab: checkmark = member in use, tooltip = reason, Hit Count = rule matches.
* Performance SLAs tab: Packet Loss, Latency, Jitter charts per member; green arrow = active, red = inactive.
* Alive is not the same as in SLA; the GUI arrow shows only alive/dead.
* Dashboard > Network: SD-WAN widget, Static & Dynamic Routing (Policy view lists SD-WAN rules), IPsec widget.
* FortiView Sessions shows each session's destination interface; it needs traffic logging.
* FortiManager reads the same data through the FortiGate REST API; estimated bandwidth is needed for bandwidth usage views.
