## The minimum working DIA configuration

A basic DIA setup uses all the SD-WAN components from the previous lesson. They must be in place in this order:

1. **Free the interfaces.** An interface can become an SD-WAN member only if nothing else references it: no firewall policy, no static route, no other config. Remove those references first.
2. **Enable SD-WAN, create a zone and add the members** with their ISP gateways.
3. **Add a static route to the zone.** Without it, the members have no route and the FortiGate has no default route.
4. **Add a firewall policy** from the LAN to the zone, with NAT.
5. **Add a performance SLA** so that a dead ISP is detected and its route removed.
6. **(Optional) Add SD-WAN rules.** Without rules, the **implicit rule** balances sessions across the ECMP routes.

The CLI for `FGT-Branch1` (port1 and port2 to two ISPs, port3 to the LAN):

```text
FGT-Branch1 # config system sdwan
FGT-Branch1 (sdwan) # set status enable
FGT-Branch1 (sdwan) # config zone
FGT-Branch1 (zone) # edit "underlay"
FGT-Branch1 (underlay) # next
FGT-Branch1 (zone) # end
FGT-Branch1 (sdwan) # config members
FGT-Branch1 (members) # edit 1
FGT-Branch1 (1) # set interface "port1"
FGT-Branch1 (1) # set zone "underlay"
FGT-Branch1 (1) # set gateway 203.0.113.1
FGT-Branch1 (1) # next
FGT-Branch1 (members) # edit 2
FGT-Branch1 (2) # set interface "port2"
FGT-Branch1 (2) # set zone "underlay"
FGT-Branch1 (2) # set gateway 198.51.100.1
FGT-Branch1 (2) # next
FGT-Branch1 (members) # end
FGT-Branch1 (sdwan) # config health-check
FGT-Branch1 (health-check) # edit "Internet_HC"
FGT-Branch1 (Internet_HC) # set server "198.51.100.10"
FGT-Branch1 (Internet_HC) # set members 1 2
FGT-Branch1 (Internet_HC) # next
FGT-Branch1 (health-check) # end
FGT-Branch1 (sdwan) # end

FGT-Branch1 # config router static
FGT-Branch1 (static) # edit 1
FGT-Branch1 (1) # set sdwan-zone "underlay"
FGT-Branch1 (1) # next
FGT-Branch1 (static) # end

FGT-Branch1 # config firewall policy
FGT-Branch1 (policy) # edit 1
FGT-Branch1 (1) # set name "LAN-to-Internet"
FGT-Branch1 (1) # set srcintf "port3"
FGT-Branch1 (1) # set dstintf "underlay"
FGT-Branch1 (1) # set srcaddr "all"
FGT-Branch1 (1) # set dstaddr "all"
FGT-Branch1 (1) # set action accept
FGT-Branch1 (1) # set schedule "always"
FGT-Branch1 (1) # set service "ALL"
FGT-Branch1 (1) # set nat enable
FGT-Branch1 (1) # set logtraffic all
FGT-Branch1 (1) # next
FGT-Branch1 (policy) # end
```

Points worth noticing:

* `set status enable` is required. SD-WAN is **disabled** by default. (Exception outside the 7.6.3 exam baseline: from FortiOS 7.6.5, factory-default configs of some desktop models with two WAN ports already contain an SD-WAN zone with both WAN ports, a health check and a policy to the zone.)
* A member with no `set zone` lands in the default zone **`virtual-wan-link`**.
* The health check uses default protocol `ping`, default mode `active` and the default timers (500 ms interval, 5 failures before inactive, 5 successes to recover). `update-static-route` is enabled by default.
* The static route has no `dst`, so it is 0.0.0.0/0. A static route through an SD-WAN zone gets **administrative distance 1** by default, not the usual 10.
* The GUI equivalents are **Network > SD-WAN > SD-WAN Zones** (*Create New > SD-WAN Zone* / *SD-WAN Member*), **Performance SLAs** tab, **Network > Static Routes** (Interface = the zone) and **Policy & Objects > Firewall Policy** (Outgoing Interface = the zone).

The result in the routing table is one ECMP default route with a next hop per member:

```text
FGT-Branch1 # get router info routing-table all
...
Routing table for VRF=0
S*      0.0.0.0/0 [1/0] via 203.0.113.1, port1
                  [1/0] via 198.51.100.1, port2
C       10.1.1.0/24 is directly connected, port3
C       198.51.100.0/29 is directly connected, port2
C       203.0.113.0/29 is directly connected, port1
```

The `[1/0]` after the prefix is distance/metric. When a route has a non-default priority or weight, FortiOS adds a second bracket at the end of the line, `[priority/weight]` (for example `, [10/0]`); with the default priority 1 it's usually omitted.

> **Watch out:** On a DHCP member you leave `gateway` at 0.0.0.0 and the FortiGate uses the gateway it learns from the ISP. A DHCP interface also installs its own default route (distance 5) when *Retrieve default gateway from server* is on. Know which route wins, and if you want the zone route to be the only default, check both `get router info routing-table all` and `get router info routing-table database`.

## The SD-WAN Setup wizard

FortiOS 7.6 has a guided **SD-WAN Setup wizard**:

* **Where:** Network > SD-WAN > SD-WAN Zones. With no SD-WAN configuration, the page offers *Begin SD-WAN setup wizard*. Otherwise use *Create New > SD-WAN Wizard*.
* **Licence:** the wizard is shown only when the FortiGate has a valid **SD-WAN Underlay and Application Monitoring** licence. The same licence is needed to download the FortiGuard SLA database.
* **Steps:** *Interface* (new or existing zone, **at most two** underlay interfaces), *Networking* (gateway Dynamic/Specify, cost, fallback priority), *Performance SLA* (FortiGuard SLA database target or Manual server), *Rule* (Best quality, Lowest cost (SLA) or Maximize bandwidth, or skip and use the implicit rule) and *Review*.
* **What it doesn't do:** it doesn't create the **static route** or the **firewall policy**. You still add a default route to the new zone, plus a policy.

> **Exam tip:** "The wizard completed but nothing reaches the internet" is answered by the missing default static route to the zone, or the missing policy.

> **Real world:** The permanent FortiGate-VM trial has no FortiGuard licences, so the wizard isn't visible there. Configure SD-WAN manually, as above.

## Traffic distribution and member health

Once traffic flows, you need to answer two questions: *how is traffic spread across members*, and *how healthy is each member*.

**In the GUI:**

| Page | Shows |
|------|-------|
| Network > SD-WAN > **SD-WAN Zones** | Zones and members, with charts for **Bandwidth** (download/upload per member), **Volume** (donut of bytes sent/received) and **Sessions** (donut of active sessions per member) |
| Network > SD-WAN > **Performance SLAs** | Each health check with live **Packet Loss**, **Latency** and **Jitter** charts per member. A green arrow means the member was up at the last check and a red arrow means it was down. The values are for the health-check server currently in use. |
| Network > SD-WAN > **SD-WAN Rules** | Each rule, its members and hit count. The implicit rule is the `sd-wan` entry at the bottom. |
| Dashboard > FortiView Sessions | The destination interface of individual sessions, to see which member a flow uses |

**In the CLI:**

```text
FGT-Branch1 # diagnose sys sdwan health-check Internet_HC
Health Check(Internet_HC):
Seq(1 port1): state(alive), packet-loss(0.000%) latency(11.842), jitter(0.611) sla_map=0x0
Seq(2 port2): state(alive), packet-loss(0.000%) latency(23.506), jitter(1.274) sla_map=0x0
```

On a 7.6 unit each member line can also show `mos(...)` and `bandwidth-up/dw/bi(...)` before `sla_map`. The exhibits in this course trim those fields, as the "SD-WAN related diagnose commands" page of the Administration Guide does.

`sla_map=0x0` doesn't mean "bad" here. This health check has no SLA target defined, so there is no bit to set. `diagnose sys sdwan member` lists each member's interface, gateway and priority, plus load-balancing counters that depend on the implicit-rule mode (session counts, volume room or spillover state).

> **Exam tip:** With the default `source-ip-based` implicit rule, a single client always hashes to the same member. If "all traffic goes to port1" in a lab with one test PC, that is normal. Test with several source IPs, or look at the Sessions chart.

## SD-WAN widgets

Dashboards are built from widgets. All the widgets on the Network dashboard can be expanded to full screen and saved as a monitor.

* **Dashboard > Network** (Optimal template) includes the **SD-WAN** widget: a summary of SD-WAN status, including ADVPN shortcut information. It also includes the **Static & Dynamic Routing** widget (active routes, including the ECMP zone routes; toggle to *Policy* to see policy routes and SD-WAN rules), plus **DHCP**, **IPsec** and **IP Pool Utilization**.
* **Interface Bandwidth** (*Add Widget > Network*) charts throughput on up to 25 interfaces, which is handy for the members.
* FortiAnalyzer and FortiManager add historical SD-WAN dashboards and reports (Domain 3).

## Traffic logs and SD-WAN events

**Forward traffic logs.** When a session is logged (policy `logtraffic all`), the log carries the SD-WAN decision as well as `dstintf`:

| Field | Meaning |
|-------|---------|
| `vwlid` | ID of the SD-WAN rule (service) the session matched |
| `vwlname` | Name of that SD-WAN rule |
| `vwlquality` | Quality information of the matched rule. It reads like a member line of `diagnose sys sdwan service4`, for example `Seq_num(1 port1 underlay), alive, sla(0x1), gid(0), cfg_order(0), local cost(0), selected` for a Lowest Cost (SLA) rule |
| `replysrcintf` / `replydstintf` | Reply-direction source and destination interfaces (useful when the return path differs from the original direction) |

**SD-WAN event logs** are under **Log & Report > System Events**, in the **SD-WAN Events** subtype (always available). They are `type="event" subtype="sdwan"`. The ones to recognise:

| Log ID | logdesc | When |
|--------|---------|------|
| `0113022923` | SDWAN status | A state change: member in or out of SLA (`Member status changed. Member out-of-sla.`), number of passing members changed, a rule's member order changed, or a member stopped or resumed forwarding (`Member link is unreachable or miss threshold. Stop forwarding traffic.`) |
| `0113022925` | SDWAN SLA information | **Periodic** per-member SLA reports, every `sla-fail-log-period` / `sla-pass-log-period` seconds (both default to 0, which means off) |
| `0113022924` | SDWAN volume status | A member enters or leaves the conservative state under volume or session-ratio balancing |
| `0100022921` | Routing information changed | `subtype="system"`, level critical: a health check removed or re-added the static routes of a member (`Static route on interface port1 may be removed by health-check ...`) |

An example of a member failing its SLA:

```text
date=2026-10-27 time=09:14:02 eventtime=1793117642118872011 tz="-0700" logid="0113022923"
type="event" subtype="sdwan" level="notice" vd="root" logdesc="SDWAN status"
eventtype="Health Check" healthcheck="Internet_HC" slatargetid=1 member="2"
msg="Member status changed. Member out-of-sla."
```

> **Watch out:** `0113022923` with `eventtype="Health Check"` reports a member's SLA state. `0100022921` reports that routes were withdrawn, which happens only when a member is **dead** and `update-static-route` is enabled. An out-of-SLA but alive member keeps its routes.

## Lab it yourself

1. On the trial VM, configure the DIA example above (one route, one policy).
2. From the LAN client, browse and ping. Watch Network > SD-WAN > SD-WAN Zones > Sessions, then add a second client IP (or a secondary address) to see the source-IP hash place it on the other ISP.
3. Shut down the "ISP-A" router's interface. Within about 2.5 s `diagnose sys sdwan health-check` shows port1 `state(dead)`, the zone route loses its port1 next hop, and Log & Report > System Events shows the 0100022921 and 0113022923 events.
4. Restore the link and time the recovery (5 successful probes).

## Key takeaways

* Basic DIA order: free the interfaces, enable SD-WAN and add members to a zone, add a static route to the zone, add a firewall policy to the zone, add a performance SLA, then optional rules.
* SD-WAN is disabled by default. Members default to the `virtual-wan-link` zone, and zone static routes default to distance 1.
* The SD-WAN Setup wizard (max two interfaces) needs the SD-WAN Underlay and Application Monitoring licence and doesn't create the static route or the policy.
* Use the SD-WAN Zones charts (Bandwidth, Volume, Sessions) for distribution, the Performance SLAs charts for member health, and `diagnose sys sdwan health-check` / `member` in the CLI.
* The Network dashboard holds the SD-WAN and Routing widgets. Interface Bandwidth tracks up to 25 interfaces.
* Traffic logs show `vwlid`, `vwlname` and `vwlquality`. SD-WAN events use log IDs 0113022923 (status), 0113022925 (periodic SLA), 0113022924 (volume) and 0100022921 (routes changed).
