## From a single call to an agent

A chat reply is one model call. A tool-using reply (previous lesson) is a short loop: call, tool result, answer. An **agent** extends that loop so the model keeps going on its own until the goal is met.

```text
Goal from the user
  loop:
    1. Model looks at the goal, the history and the latest tool results
    2. Model decides: call a tool, or finish
    3. If it called a tool, the harness runs it and appends the result
    4. Repeat until the model says it is done, or a limit is hit
```

That repeat-until-done cycle is the **agent loop**. The software around the model that runs tools, tracks state and enforces limits is often called the **harness**. An agent differs from a fixed chain (Lesson 3.1) in who chooses the next step: in a chain you decided the sequence in advance; in an agent, the model decides each step from what it just saw.

| Chain / workflow | Agent |
|---|---|
| Steps fixed in advance by you | Model chooses steps at run time |
| Predictable, easy to test and audit | Flexible, handles unforeseen cases |
| Cost and latency known | Cost and latency vary; can loop or wander |
| Best when the process is well understood | Best when the path cannot be scripted |

A sound rule is to use the simplest design that works: a single prompt first, then a chain, then an agent only when the task really needs open-ended decisions.

### Risks of agents

Giving a model tools and autonomy raises the stakes. Domain 4's topics apply here in full.

- **Compounding mistakes.** A wrong assumption early carries through many steps without a human noticing.
- **Real side effects.** Deleted files, pushed commits, a changed firewall rule or an email sent to a customer cannot be un-sent.
- **Prompt injection.** Anything the agent reads (a web page, an email, a README, a ticket) can contain instructions aimed at the agent. Content from outside is data, not commands.
- **Excessive permissions.** An agent holding admin credentials can do admin damage by accident or by manipulation.
- **Cost and runaway loops.** Repeating a failing step uses tokens until a limit stops it.
- **Over-trust.** Fluent progress reports can describe work that did not happen as stated.

Controls that matter:

1. **Least privilege.** Give a read-only credential unless a write is required. Use a lab or a sandbox first.
2. **Human approval** for destructive or irreversible actions, with the exact command shown.
3. **Limits** on steps, time and spend.
4. **A reviewable record** (logs, diffs, git history) and a way to roll back.
5. **Isolation** from sensitive data and from the open internet where possible.

## Computer use

Some agents operate a computer the way a person does: they receive screenshots and send mouse and keyboard actions. Anthropic's documentation describes its computer use tool as providing screenshot capabilities and mouse and keyboard control for autonomous desktop interaction, implemented as an Anthropic-defined tool that runs in your application, in an environment you control. OpenAI also documents a computer-use tool. The same documentation warns that computer use has unique risks, especially on the internet, and recommends precautions: use a dedicated virtual machine or container with minimal privileges, keep sensitive data and account logins away from the model, limit internet access to an allowlist of domains, and ask a human to confirm decisions with real-world consequences.

Computer use is slower and more brittle than a proper API or CLI, so prefer a structured tool when one exists.

## Coding assistants

Coding assistants are agents specialised for software and scripts. They read a codebase, edit files and run commands, usually asking permission along the way. Three you should recognise (details as of October 2026, from the vendors' own pages):

| Tool | Vendor | Where it runs and what it does |
|---|---|---|
| **Claude Code** | Anthropic | An agentic coding tool that reads your codebase, edits files, runs commands and integrates with development tools. Available in the terminal, IDE extensions, a desktop app and the browser. Reads a `CLAUDE.md` file at the start of every session for project instructions. Connects to tools through MCP. Can run non-interactively (`claude -p`) in scripts and CI |
| **Codex** | OpenAI | A coding agent available in the ChatGPT apps and in several forms. **Codex CLI** works against a local repository from the terminal, editing files and running your installed tools, with permission and sandbox controls. **Codex Cloud** runs tasks in a configured cloud environment connected to your GitHub repositories, each task in its own workspace, and you review results and open a pull request. `AGENTS.md` holds project instructions. There is also an IDE extension |
| **Gemini CLI** | Google | An open-source terminal agent. Its repository now states it is maintained for **Gemini Code Assist Standard / Enterprise** and Code Assist for GitHub on Google Cloud. It says free individual access and Google AI Pro / Ultra moved to **Antigravity CLI** on June 18, 2026, and that Gemini CLI is not tuned for Gemini 4 and later |

Gemini CLI is a good example of why you check the repository's README before choosing a tool: a product you read about in a tutorial may have moved.

### What they do well

- Explain unfamiliar code, config or scripts and trace where something happens.
- Make multi-file changes, write tests, and run the tests to see if they pass.
- Draft automation: Ansible playbooks, Python with Netmiko, PowerShell, Terraform.
- Work in a loop: edit, run, read the error, fix. This is where the tool loop pays off.

### How to prompt a coding agent

1. **State the goal and the acceptance check.** "Add a `--timeout` option to `backup.py`. Done when `pytest tests/test_backup.py` passes and the default stays 30 seconds."
2. **Point to the relevant files** rather than hoping it finds them.
3. **Ask for a plan first** on anything non-trivial, and approve it.
4. **Keep changes small and reviewable.** One task per branch or commit.
5. **Put standing project rules in the instruction file** (`CLAUDE.md`, `AGENTS.md`): how to run tests, naming conventions, things never to touch.
6. **Review the diff yourself.** Passing tests do not prove the change is right, particularly if the agent wrote the tests.
7. **Use permission prompts deliberately.** Approving everything blindly removes the safety net.

```text
Goal: Add retry with backoff to fetch_config() in netbackup/ssh.py.

Context: Devices are reachable via Netmiko. Tests are in tests/ and
run with `pytest -q`. Do not touch netbackup/inventory.yaml.

Plan first. Then implement. Done when all tests pass and a new test
covers the retry. Show me the diff; do not commit.
```

> **Watch out:** Never give a coding agent production credentials, and do not let it run commands against live network devices unless each command is shown to you first. A lab is the right place to learn.

> **Exam tip:** What distinguishes a coding assistant from a plain chatbot is the tool loop: it can read your files, change them and run commands, then react to the results. That autonomy is also the source of the risk.

## Image generation prompts

Image generation is another tool the model can use (previous lesson). OpenAI documents an image generation tool in the Responses API that takes a text prompt and optional input images, and Google documents native image generation in Gemini that works conversationally with text and images. The OpenAI docs also note the tool can revise your prompt before generating and exposes the revised prompt in its output; Google's docs state generated images carry a SynthID watermark (as of October 2026).

Image prompts follow the same principle as text prompts: specify what you want, not what you hope it guesses. A useful checklist:

| Element | Example for a network diagram illustration |
|---|---|
| **Subject** | A small-office network: one firewall, two switches, a wireless access point |
| **Style / medium** | Clean flat vector illustration, thin lines |
| **Composition** | Top-down, firewall at the top, devices in a tidy hierarchy, plenty of margin |
| **Colour** | White background, dark blue and orange accents |
| **Text in the image** | Quote exact labels: "FW-01", "SW-1", "SW-2". Keep them short |
| **Constraints** | No people, no logos, no brand names |
| **Format** | Landscape 16:9 |

Tips:

1. **Iterate in small steps.** Both OpenAI and Google describe multi-turn refinement: change one thing at a time ("make the lines thinner", "move the AP to the right") instead of rewriting everything.
2. **Describe the change, not just the problem.** "Make the background plain white" beats "it looks messy".
3. **Quote any text exactly,** and check spelling in the result; embedded text is a common weak spot.
4. **Use an input image for edits** (recolour, remove an object, restyle) where the tool supports it.
5. **Do not trust diagrams for accuracy.** An image model draws something that looks like a network diagram; it does not know your topology. Generate decorative art with a model; draw real diagrams in a diagram tool or from a text format (Mermaid, draw.io) that you control.
6. **Mind rights and policy.** Avoid real people and brands, and check the vendor's usage policy and the licensing of the output for commercial use.

Example prompt:

```text
Flat vector illustration, landscape 16:9, white background.
A small-office network seen from above: a firewall labelled "FW-01"
at the top, two switches labelled "SW-1" and "SW-2" below it, and a
wireless access point on the right. Thin dark-blue lines, orange
accents on the firewall. No people, no logos. Leave wide margins.
```

## Try it yourself

1. **Same image, two assistants.** Send the example prompt to two image-capable assistants. Compare composition, spelling of "FW-01" and style. Then give a single change instruction ("move the access point to the left; keep everything else") and see how much else changes.
2. **Agent loop on paper.** Take a coding assistant (Claude Code, Codex, or an IDE or chat assistant if you have no CLI) and give it a small task in a throwaway folder: `Write a Python script that converts a CSV of VLAN IDs and names into Cisco IOS "vlan" and "name" commands, with a test.` Watch the cycle: it writes, runs the test, reads the failure, fixes. Record what it asked permission for.
3. **Review the diff.** Open the generated test and the script. Is the test meaningful, or does it only assert what the code already does? Add a bad input (a duplicate VLAN ID) and see how each assistant handles it.
4. **Plan-first.** Repeat a second small task with the instruction `Plan first and wait for my approval.` Compare how the process feels.

## Key takeaways

- An agent runs the tool loop repeatedly, with the model choosing each next step until it finishes or hits a limit.
- Chains have fixed steps; agents choose their own. Use the simplest design that works.
- Agent risks include compounding errors, irreversible side effects, prompt injection, over-broad permissions and runaway cost.
- Controls: least privilege, human approval for destructive actions, step and spend limits, logs, isolation and a lab first.
- Computer use drives a desktop through screenshots and input; run it in a locked-down environment.
- Claude Code, Codex and Gemini CLI are terminal or IDE coding agents; check the vendor page, because products move (Gemini CLI now targets Code Assist enterprise users).
- Prompt coding agents with a goal, an acceptance check, relevant files and a plan; keep project rules in `CLAUDE.md` or `AGENTS.md`; review every diff.
- Image prompts specify subject, style, composition, colour, exact text and constraints, then iterate one change at a time.
- Do not use an image model for accurate technical diagrams.
