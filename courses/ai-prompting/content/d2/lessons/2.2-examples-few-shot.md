## Zero-shot, one-shot, few-shot

An **example** in a prompt shows the model what a correct answer looks like. The three names describe how many you give:

| Name | Examples | Typical use |
|---|---|---|
| **Zero-shot** | None; instructions only | Simple, well-known tasks |
| **One-shot** | One | You mainly need to show a format |
| **Few-shot** (multishot) | A handful, often 3 to 5 | Classification, extraction, formatting, tone matching |

Both Anthropic and Google describe how the model picks up the pattern from examples. Anthropic says a few well-crafted examples (few-shot or multishot prompting) improve accuracy and consistency, and that examples are among the most reliable ways to steer output format, tone and structure. Google's guide is even stronger: it recommends always including few-shot examples, says prompts without them are likely to be less effective, and adds that you can sometimes remove instructions if the examples are clear enough.

### A few-shot classifier for syslog severity

```text
Classify each syslog line as ACTION or NOISE. Reply with one word.

Line: %LINK-3-UPDOWN: Interface GigabitEthernet1/0/12, changed state to down
Label: ACTION

Line: %SYS-5-CONFIG_I: Configured from console by admin on vty0 (192.0.2.55)
Label: NOISE

Line: %SPANTREE-2-ROOTCHANGE: Root Changed for vlan 20
Label: ACTION

Line: %SEC_LOGIN-5-LOGIN_SUCCESS: Login Success [user: admin] [Source: 192.0.2.55]
Label:
```

The examples do three things that instructions alone would struggle to do: they define the label set, show the one-word output format, and imply the judgment (state changes that affect users matter; routine logins do not).

## Choosing good examples

The vendor guides give consistent advice.

1. **Relevant.** Mirror the real task and real inputs. Anthropic lists relevance first.
2. **Diverse.** Cover edge cases and vary them so the model does not lock onto an accidental pattern. Anthropic notes that diversity avoids unintended patterns, and OpenAI says to show a diverse range of possible inputs with desired outputs.
3. **Consistent.** Google stresses that examples must share the same structure and formatting, down to XML tags, white space, newlines and example separators, because the main job of an example is to show the response format.
4. **Not too many.** Google warns that too many examples can lead the model to overfit its response to them. Anthropic suggests 3 to 5 as a good number. Treat these as starting points to test, not laws.
5. **Aligned with your instructions.** OpenAI says for reasoning models that examples must align closely with the prompt instructions; discrepancies between the two may produce poor results.
6. **Correct.** A wrong example teaches a wrong lesson; the model copies mistakes as readily as successes.
7. **Balanced.** If four of five examples are ACTION, expect an ACTION bias.

> **Watch out:** Over-copying is the standard failure mode. If every example output begins with "Summary:" or happens to be exactly 40 words, the model will tend to do the same. If your examples show an IP address in every answer, the model may add one when none is relevant. Vary the incidental features.

### Formatting examples so they are not confused with instructions

Mark where examples start and stop. Anthropic suggests wrapping examples in `<example>` tags, with multiple examples inside `<examples>`, so the model can distinguish them from instructions. OpenAI's sample developer message puts examples in an Examples section in the Markdown structure of the prompt. Either way, keep input and output labels identical in every example.

```text
<examples>
  <example>
    <input>Gi1/0/12 flapping, CRC errors rising</input>
    <output>{"severity": "high", "check": "cable and SFP"}</output>
  </example>
  <example>
    <input>NTP server unreachable for 2 minutes then recovered</input>
    <output>{"severity": "low", "check": "none unless it repeats"}</output>
  </example>
</examples>
```

Note the examples use the same keys and the same output shape. If the real task will include negative or ambiguous cases, include one: the model otherwise has no guide to what you want there.

## Examples, instructions and different model types

- **Standard (non-reasoning) models** such as the GPT models benefit, according to OpenAI, from precise instructions and explicit logic; examples are one of the main tools.
- **Reasoning models** often need fewer examples. OpenAI's reasoning guidance says to try zero-shot first and add few-shot examples only if needed. Anthropic notes that multishot examples still work with thinking: worked examples shape how the model approaches similar problems in its thinking.
- **Ground truth beats generated examples.** Prefer real, anonymised samples from your environment to invented ones, and replace any addresses, hostnames or secrets with documentation addresses (192.0.2.0/24, 198.51.100.0/24, example.com) before pasting.

### Zero-shot first, then add

A practical sequence:

1. Start zero-shot with clear instructions (Lesson 2.1).
2. If the model gets the format or judgment wrong, add **one** example that shows it.
3. If it is still inconsistent, add two or three varied examples including a hard case.
4. Re-test on a few inputs you did not use as examples.

That last step matters: you want to know the model learned the rule, not memorised your samples.

## Try it yourself

Run in two assistants, fresh chat each time.

1. **Zero-shot vs few-shot.** Create 8 invented log lines (mix of link-down, config changes, login events, STP changes). Prompt A: `Label each line ACTION or NOISE.` Prompt B: use the four-example prompt above, then the 8 lines. Compare consistency and format. Which one added commentary despite the one-word instruction?
2. **Bad example, bad behaviour.** Modify the examples so every ACTION line contains "Gi1/0". Run again with a new ACTION line about an unrelated interface. Does the label shift?
3. **Format cloning.** Give one example of a change-ticket summary in a specific four-line format, then ask for a summary of a new invented change in the same format. Check how closely each assistant matches the layout, including punctuation.

## Key takeaways

- Zero-shot means no examples, one-shot means one, few-shot means a handful (commonly 3 to 5).
- Examples are one of the most reliable ways to control format, tone and judgment.
- Good examples are relevant, diverse, consistently formatted, correct and aligned with your instructions.
- Too many or too uniform examples cause overfitting and copying of incidental features.
- Wrap or label examples so the model can tell them from instructions; use identical labels throughout.
- Google recommends including few-shot examples; OpenAI advises trying zero-shot first with reasoning models.
- Test on inputs that are not your examples.
- Use placeholder data in any pasted examples.
