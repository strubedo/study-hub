## Getting output you can use

Free-form prose is fine for reading but awkward for scripts, spreadsheets and tickets. When the output will be consumed by another tool or pasted into a form, specify its shape. There are four levels, from weakest to strongest guarantee.

1. **Describe the format in the prompt** ("a table with columns ...").
2. **Give an output template or an example** of the exact shape.
3. **Prefill** the start of the response (some Claude models only; see below).
4. **Use the API's structured-output feature**, which constrains the model to a JSON schema.

## Tables, JSON and templates in the prompt

You can ask for any common format in plain language:

- A **table**: "Output a Markdown table with columns Interface, Status, Issue."
- **JSON**: "Return only a JSON object with keys device (string), severity (low, medium, high), and actions (array of strings). No text outside the JSON."
- **CSV**, **YAML**, a numbered list, or a fixed template.

A **template** is the most reliable of these. Show the exact skeleton, with placeholders:

```text
Fill in this template exactly. Keep the headings and order. Write
"not stated" for any field the input does not cover.

Change summary: <one sentence>
Devices affected: <comma-separated hostnames>
Risk: <low | medium | high> - <one-sentence reason>
Rollback: <command or procedure>
```

The "not stated" rule is important: a template that demands every field invites the model to invent values for the ones it cannot fill.

Tips:

- Say "only" and "nothing else": "Return only the JSON object" avoids a friendly preamble that breaks a parser.
- Define allowed values (an enum) for categories rather than free text.
- Provide an example with the same keys, types and ordering (Lesson 2.2).
- State what to do for missing data (null, empty array or "not stated").
- Ask for a field to hold uncertainty, such as `"confidence": "low"`, if you want to triage later. This is a prompt convention, not a calibrated probability.

> **Watch out:** A model that is told to output JSON may still add a sentence before it, wrap it in a code fence, use a trailing comma or invent a key. For anything automated, validate the output in code, and use the platform's structured-output feature where it exists.

## Structured outputs in the APIs

All three vendors offer a feature that goes beyond asking nicely.

- **OpenAI Structured Outputs.** You supply a JSON Schema (with `strict: true`) and the API ensures the response adheres to it. OpenAI describes it as the evolution of JSON mode: both ensure valid JSON, but only Structured Outputs ensures adherence to the schema. It also makes safety refusals programmatically detectable and removes the need for strongly worded prompts to get consistent formatting. OpenAI recommends it over JSON mode when possible. Support depends on the model, so check the compatibility note.
- **Google Gemini structured output.** Google's prompting guide says you can specify simple JSON formats in the prompt but recommends the Gemini API's structured output feature for a more complex JSON Schema.
- **Anthropic structured outputs.** Anthropic's prompting guide points to its structured outputs feature, designed to constrain Claude's responses to a given schema, and also says newer models can reliably match complex schemas when told to, especially if you add retries. For classification it suggests tools with an enum field or structured outputs.

The common principle: a schema enforced by the platform is stronger than a format requested in prose, but it only controls *shape*. It does not make the values true. A valid JSON object can still contain a wrong VLAN ID.

| Level | Guarantees valid syntax? | Guarantees your schema? | Guarantees correct facts? |
|---|---|---|---|
| Plain request in the prompt | No | No | No |
| Template or example | Usually | Usually | No |
| Prefill (supported Claude models) | Helps | No | No |
| Platform structured output | Yes | Yes (supported schema subset) | No |

## Prefilling the response

**Prefilling** means writing the first words of the assistant's reply yourself, and letting the model continue from there. If you start the reply with `{`, the model continues with the JSON body and skips the greeting. If you start with `Classification:`, it continues from there.

In the Claude API this was done by supplying a partial assistant message as the last turn. Anthropic's current guide says, precisely:

- Starting with Claude 4.6 models (and Claude Mythos Preview), prefilled responses on the last assistant turn are **no longer supported**. A request with a prefilled assistant message to those models returns a 400 error.
- Earlier models continue to support prefills, and adding assistant messages elsewhere in the conversation is not affected.
- The recommended replacements are: structured outputs or tools with an enum for format and classification; direct instructions such as "Respond directly without preamble" for removing introductions; and moving a continuation into the user message ("Your previous response was interrupted and ended with ... Continue from where you left off").

So whether prefill is available depends on the model and API. Google's guide describes a related idea it calls partial input completion: because models work like autocomplete, you can give the beginning of the output (and examples) and let the model continue, including a response prefix after an example. OpenAI's prompt-engineering guide does not mention a prefill feature for the Responses API, so for OpenAI use templates and Structured Outputs.

> **Exam tip:** "Prefill" is a technique name in the Anthropic docs. A correct modern answer notes that it is unsupported on recent Claude models, and that structured outputs or explicit instructions replace it.

### Prefill-style behaviour without a prefill

In a chat app you cannot set a prefill. You can approximate it:

- End your prompt with the beginning of the format: "Respond starting with the line `Risk:`".
- Provide an output template and say "Begin your reply with the template's first line".
- Use output tags: "Put your answer in `<answer>` tags."

These influence the output but do not force it the way a prefill or schema does.

## Choosing a format

| Need | Best choice |
|---|---|
| Human reading | Short prose, or a table for comparisons |
| Pasting into a ticket | Fixed template |
| Feeding a script | JSON with a schema (platform structured output if available) and validate in code |
| Spreadsheet | CSV or a Markdown table (check that commas inside fields are quoted) |
| Mixed explanation and data | Tags: explanation in `<analysis>`, data in `<result>` |

## Try it yourself

Run in two assistants.

1. **JSON discipline.** Prompt: `Extract device, interface and error count from these three invented lines and return JSON.` (Provide lines such as `sw-access-07 Gi1/0/12 CRC 4821`.) Run it, then rerun with `Return only a JSON array of objects with keys device, interface, crc_errors (integer). No text before or after, no code fences.` Paste each result into a JSON validator. Which responses parse?
2. **Template with gaps.** Use the change template above and supply a change description missing a rollback. See whether each assistant writes "not stated" or invents a rollback.
3. **Prefill substitute.** Ask for a classification with `Reply with only one of: ACTION, NOISE` for a tricky log line, then rerun adding `Begin your reply with the word`. Notice that prompt-only methods are not guarantees. If you have API access, check whether your chosen model supports prefill or structured outputs before building on it.

## Key takeaways

- Specify output shape: table, JSON, CSV or a fixed template; templates with placeholders are the most dependable prompt-only method.
- Tell the model what to write when data is missing so it does not invent it.
- Platform structured outputs (OpenAI Structured Outputs, Gemini structured output, Anthropic structured outputs) enforce a schema; prompting alone does not.
- A schema guarantees shape, never truth; validate values in code.
- Prefill means starting the model's reply for it; Anthropic says it is unsupported from Claude 4.6 models on (400 error) but still works on earlier models.
- Replace prefill with structured outputs, direct no-preamble instructions or moving continuations to the user message.
- Google describes response prefixes and partial input completion; OpenAI points to templates and Structured Outputs instead.
- Output tags such as `<answer>` make responses easy to parse.
