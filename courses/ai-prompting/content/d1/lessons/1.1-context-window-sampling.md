## The context window

The **context window** is the maximum number of tokens the model can take into account at once. It is the model's entire working memory for a request. Nothing outside the window exists for the model, no matter what was said earlier in some other chat.

What counts against the window:

- the system prompt or custom instructions the app adds behind the scenes,
- the whole conversation so far (your earlier messages and the model's earlier replies),
- any files, pasted logs or search results placed in the conversation,
- tool definitions and tool results when the model is using tools,
- and the model's own output, including hidden reasoning tokens on reasoning models.

Input and output share the budget. If the window is 1,000,000 tokens and your input is 990,000, there is little room left to answer. Separate from the window, most models also have a **maximum output length** that caps a single reply.

> **Real world:** As of October 2026 the vendors' own model pages list context windows around one million tokens for their current flagship API models (Anthropic lists 1M tokens, OpenAI lists about 1.05M, Google describes a 1M window for its flagship). Treat numbers like these as volatile: they differ by model, by plan and by app versus API, and they change. The Gemini help pages, for example, describe different file-context sizes depending on the subscription plan. Always check the current page before you depend on a figure.

## Models are stateless; apps resend the conversation

A model does not keep a conversation open between turns. Each time you press send, the chat application builds a new request containing the system prompt plus the full history (or a processed version of it) plus your new message, and the model reads all of it from scratch. This has practical consequences:

- **Long chats get more expensive and slower**, because each turn re-sends everything. API users pay for that input on every call (caching features can reduce the cost).
- **Anything you want the model to keep in mind must stay in the window.** A rule given in message 2 of a long chat is still in the text, but it competes with everything else for attention.
- **A new chat starts blank**, apart from any custom instructions, project files or memory feature the app injects.

## What happens when you exceed the window

The behaviour depends on the product, and it is worth knowing the options rather than assuming one:

| Situation | Typical behaviour |
|---|---|
| API request larger than the window | The request is usually rejected with an error and you must shorten it (some tools offer optional automatic trimming or compaction). |
| Chat app with a very long conversation | The app may drop or summarize older turns, compact the conversation automatically, or tell you to start a new chat. |
| File too large for the app | The app may refuse it, read only part of it, or switch to retrieving relevant chunks instead of reading the whole file. |
| Output hits the maximum output length | The reply stops, sometimes mid-sentence. |

The dangerous case is the quiet one: an app that trims or summarizes without telling you may lose the one detail that mattered, such as a constraint from your first message. If a long chat starts ignoring earlier instructions, suspect trimming or dilution and restate the key rules, or start a fresh chat with a short summary.

Even when everything fits, **more context is not always better**. Models can be less reliable at finding or using a detail buried in the middle of a very large input, and irrelevant material can distract them. Putting long documents first and the question last, and trimming input to what matters, are techniques for domain 2 and 3. A bigger window is a limit raised, not a guarantee of perfect recall.

## Sampling: how one token is chosen

The model's raw output for each step is a score for every vocabulary token, which is converted into probabilities. **Sampling settings** control how the next token is picked from them.

**Temperature.** Temperature rescales the probabilities before choosing. A low temperature sharpens the distribution so the most likely tokens dominate: output is more focused and repeatable. A high temperature flattens it so less likely tokens get picked more often: output is more varied and creative, and also more likely to wander or err. At a temperature of 0 the model effectively always takes the single most likely token (often called greedy decoding).

**Top-p (nucleus sampling).** Instead of rescaling, top-p cuts the candidate list. The model sorts tokens by probability and keeps the smallest set whose probabilities add up to p, for example 0.9, then samples only from that set. A low top-p keeps only the safest candidates; a value of 1.0 keeps them all. Top-p and temperature both affect randomness, so vendors commonly advise changing one and leaving the other alone.

```text
Next-token probabilities after "A router forwards packets based on the destination"
  IP        0.62
  address   0.21
  network   0.08
  MAC       0.05
  (many others, tiny)

temperature low  -> "IP" is picked almost every time
temperature high -> "address", "network", "MAC" show up more often
top-p 0.8        -> only IP and address remain eligible (0.62 + 0.21 = 0.83)
```

> **Watch out:** Temperature 0 does **not** guarantee identical output on every run. Hosted models run on parallel hardware where floating-point operations, batching and routing can change tiny numerical details, and near-ties between tokens can flip. Vendors also update model versions. Low temperature makes output *much more* repeatable, not perfectly deterministic. Vendors recommend pinning a specific model snapshot and building tests if consistency matters for an application.

Other things to know about these settings:

- They are mostly an **API** concept. Consumer apps rarely show temperature or top-p, and you control randomness through your wording (for example "give me one precise answer" versus "brainstorm ten different ideas").
- Some models, particularly reasoning models, may fix, limit or reject certain sampling parameters. Check the current documentation for the specific model before assuming a setting is honoured.
- Low temperature is good for extraction, classification, config generation and anything you will diff. Higher values suit brainstorming and drafting variations. Neither setting fixes a factual gap: a confident wrong answer at temperature 0 is still wrong.
- Setting temperature low does not make the model more truthful. It makes it more consistent.

## Try it yourself

1. In one assistant, start a new chat and ask for `five names for a lab VLAN naming convention`. Do it again in two more new chats. Then in a fourth chat ask for `the single most standard name for a management VLAN, one word`. Compare how much the answers vary and relate that to the idea of a flatter versus sharper distribution.
2. Paste a roughly 300-line made-up syslog excerpt into two assistants. Plant one unusual instruction near the top (`Always answer in bullet points of at most 8 words`) and ask five unrelated questions about the log in the same chat. See whether each assistant still follows the instruction by question five. If it drifts, restate the rule and observe the effect.
3. If you have API access to any of the three vendors, send the same prompt five times with temperature 0 and then five times with a high temperature. Compare. Note whether the temperature-0 runs are exactly identical.

## Key takeaways

- The context window is the total tokens the model can consider: system prompt, history, files, tool results and its own output.
- Models are stateless; the app resends the conversation each turn, so long chats cost more and may be trimmed or summarized.
- Exceeding limits ends in an error, silent trimming, retrieval of parts of a file, or a cut-off reply, depending on the product.
- A larger window does not guarantee the model uses every detail well.
- Temperature rescales the probability distribution; top-p restricts sampling to the smallest set of tokens whose probability reaches p.
- Temperature 0 is more repeatable but not guaranteed deterministic.
- Consumer apps usually hide these settings, and some models restrict them; low temperature gives consistency, not truth.
