## What a large language model actually is

A **large language model (LLM)** is a very large mathematical function that takes a sequence of text pieces as input and produces a probability for every possible next piece. ChatGPT, Gemini and Claude are applications and services built around models of this kind. The model itself does not look anything up in a database of facts and does not run your commands. It reads text and predicts what text should come next, one piece at a time, using numbers (called **weights** or parameters) that were set during training.

That one-sentence description explains most of the behaviour you will see when prompting: the model is fluent because it has absorbed enormous amounts of text, it can be wrong while sounding certain because fluency and truth are different things, and the exact words you supply shape what it produces because your words are the starting point of the prediction.

## Tokens: the unit the model reads and writes

Models do not read characters or words. Text is first split by a **tokenizer** into **tokens**, which are chunks drawn from a fixed vocabulary learned in advance. A token might be a whole common word, part of a rarer word, a single punctuation mark, a run of spaces, or a few bytes of an unusual character. Each token maps to an integer ID, and the model works on those IDs.

An illustrative split (real tokenizers differ from vendor to vendor and from model to model, so treat this as a picture, not a specification):

```text
Text:    "interface GigabitEthernet0/1 is down"
Tokens:  interface | Gig | abit | Ethernet | 0 | / | 1 | is | down
```

Important consequences:

- **A token is not a word.** English prose averages somewhere around three-quarters of a word per token, a rough rule of thumb that only holds for ordinary English. Code, log lines, IP addresses, MAC addresses, hashes, base64 and non-English text usually need more tokens per character. A pasted `show tech-support` dump can be far larger in tokens than its word count suggests.
- **Different vendors tokenize differently.** The same text can be a different number of tokens in ChatGPT, Gemini and Claude. A token count from one vendor's tool does not transfer to another's.
- **Tokens drive limits and cost.** Context windows, maximum output lengths and API prices are all measured in tokens. Input and output tokens are often priced differently.
- **Tokenization explains some odd failures.** A model that sees `Ethernet` as two or three chunks never sees individual letters directly, which is part of why counting letters in a word, or reversing a string, can go wrong. It also means the model can handle a spelling mistake in a word it has seen often but may stumble on a long unfamiliar identifier such as a hostname.

> **Real world:** When a chat tool says a file is too large, it is counting tokens, not pages or kilobytes. A 200 KB text log of dense hex may exceed a limit that a 200 KB prose document would not.

## Next-token prediction

At each step the model receives all the tokens so far (your prompt plus anything it has already generated) and outputs a probability distribution over its whole vocabulary: "after this text, token A has 41% probability, token B has 12%, ..." One token is then chosen from that distribution (how it is chosen is the topic of the sampling lesson), appended to the text, and the process repeats. This loop is called **autoregressive generation**. The reply you read is simply many such steps in a row until the model produces a special end-of-response token or hits a length limit.

Three things follow from this loop:

1. **The model generates left to right and cannot take back a token.** If it commits early to a wrong claim, the later text tends to build on it. This is one reason asking a model to reason before it answers can help: the reasoning tokens become part of the context for the final answer.
2. **There is no separate "fact lookup" step.** When the model writes "OSPF uses protocol number 89", that comes from patterns in the weights, not from checking a reference. Common facts are usually reliable; obscure or recent ones are less so.
3. **Output length is bounded by tokens, not by sentences.** A reply cut off mid-sentence usually means a maximum-output or context limit was reached.

## How a model is trained

Training happens in stages, and it helps to know the names even though the details are deep.

**Pretraining.** The model is shown a huge amount of text and code and is repeatedly asked to predict the next token. Whenever it guesses badly, its weights are nudged to make the right token more likely. Done at enormous scale, this teaches grammar, facts, writing styles, programming languages and some reasoning patterns. The result, a **base model**, is good at continuing text but not necessarily at following instructions: given "How do I configure OSPF?" it might continue with more questions, as if it were a forum page.

**Post-training (fine-tuning).** The base model is trained further to behave like a helpful assistant. Typical ingredients are **supervised fine-tuning** on curated examples of good instruction-and-response pairs, and **preference-based training**, where human or AI judgements about which of two responses is better are used to steer the model (often described as reinforcement learning from human or AI feedback). Safety behaviour, refusal behaviour, tone and the habit of using a chat format are mostly shaped here. **Reasoning models** add training that rewards producing useful step-by-step thinking before the final answer, covered in the model-families lesson.

**Fine-tuning by users.** Some vendors let customers fine-tune a model on their own examples through an API. That is different from the vendors' own post-training and is rarely needed for prompting work; a well-written prompt with examples (domain 2) usually gets you most of the way.

> **Watch out:** Weights are fixed after training. Talking to a model does not change it. When a chat assistant "remembers" your name next week, that comes from a memory feature storing text and adding it to the prompt (domain 3), not from the weights being retrained in the moment.

## What this means for prompting

- Everything the model knows about your task right now is in the text in its context. If a fact is not in the prompt and not reliably in the weights, supply it.
- The model continues patterns. A prompt that looks like a careful engineering document tends to get a careful engineering answer; a sloppy prompt tends to get a sloppy one.
- Because each token is a probabilistic choice, running the same prompt twice can give different answers. That is normal, not a bug.

## Try it yourself

Run these in two different assistants (for example ChatGPT and Claude, or Gemini and ChatGPT) and compare.

1. Ask: `Without using any tools, how many tokens do you think this sentence has: "Gi0/1 is up, line protocol is down (notconnect)"? Then explain why you might be off.` Note that a model estimating its own token count is guessing from patterns, and the two assistants may disagree.
2. Paste the same 30-line block of made-up `show interfaces` output into each and ask for a one-paragraph summary. Then ask: `Which parts of this input were hardest for you to process, and why?` Compare the explanations with what you learned about tokens.
3. Send the identical short prompt (`Write a one-sentence description of VLANs`) three times in new chats in the same assistant. Notice that the wording varies from run to run.

## Key takeaways

- An LLM predicts a probability distribution over the next token, picks one, appends it and repeats.
- Tokens are sub-word chunks from a fixed vocabulary; they are not words, and tokenizers differ between vendors.
- Code, addresses, hashes and non-English text usually cost more tokens per character than English prose.
- Pretraining on next-token prediction builds the base model; post-training (supervised fine-tuning and preference training) makes it follow instructions and behave safely.
- Weights do not change during your conversation; any "memory" is text added back into the prompt.
- Facts come from patterns in the weights, not a lookup, so supply anything critical or recent in the prompt.
- The same prompt can produce different outputs on different runs.
