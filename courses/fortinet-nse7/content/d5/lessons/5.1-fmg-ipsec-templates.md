## Two ways FortiManager builds IPsec

FortiManager 7.6 offers two workflows for IPsec. They solve different problems:

| | IPsec tunnel templates (Device Manager) | VPN Manager (IPsec VPN communities) |
|---|---|---|
| Where | Device Manager > Provisioning Templates > IPsec Tunnel Templates | VPN Manager > IPsec VPN Communities |
| Model | Per-tunnel template, assigned to devices or device groups, usually inside a template group | A community (topology) with member gateways. FortiManager derives the phase 1s, phase 2s and routes |
| Topologies | Anything you can express per device: single hub, dual hub, ADVPN | Full Meshed, Star, Dial up |
| SD-WAN fit | Designed for it: normalized interfaces, metadata variables, used by the SD-WAN overlay template | Older, community-centric workflow |
| Scale | Large: one template serves every branch in a device group | Fine for moderate meshes and stars |

For SD-WAN overlays, Fortinet's 7.6 guidance points to **IPsec templates**, usually generated by the **SD-WAN overlay template**, the Overlay Orchestration wizard covered in domain 2. Know both for the exam.

## IPsec tunnel templates

An IPsec template standardises tunnel configuration so that every branch gets the same phase 1/phase 2 with only the per-device values changing. Templates can be assigned to individual devices or device groups, and FortiManager installs the result on the next install.

Fields worth knowing in the Create New IPsec Tunnel dialog:

| Field | What it does |
|---|---|
| Routing: **Automatic** / Manual | Automatic creates static routes to the **Remote Subnet** entries through the tunnel. This is template *autorouting*. Manual creates no routes, which suits BGP designs |
| Remote Device | IP Address, Dynamic DNS (FQDN), or **Dynamic** for a dial-up hub. Dynamic exposes IPv4 Start IP / End IP / Netmask for addresses handed to dial-up peers |
| Local ID | Lets a hub with several dial-up tunnels on one interface match the right one by peer ID |
| Network Overlay | Sets a network ID. Distinct IDs are needed for several tunnels between the same two FortiGate IPs |
| FEC Health Check | Health check used for adaptive FEC on that tunnel |
| Authentication | Pre-shared key, or Signature with a certificate and peer CA |
| Tunnel Interface Setup | IP and remote IP for the tunnel interface, if the design addresses tunnels |
| Advanced Options | Everything else from the phase 1 CLI, including ADVPN settings |

Fields marked with a magnifying glass accept **ADOM-level metadata variables**, written as `$(variable)` inside the template. This is how one template serves many devices. A branch template can set its tunnel IP or LAN subnet from `$(branch_id)`. Fortinet's IPsec template example builds each branch LAN as 192.168.`branch_id`.0/24 with branch_id 1, 2, … per device. Metadata values are set per device (or per device group). Give every device a value before you install, because a missing value leaves the template field unresolved for that device.

### Recommended IPsec templates

FortiManager ships three recommended templates. You **Activate** one, answer a short wizard, and FortiManager creates an editable copy:

| Template | Assumes | Wizard asks for |
|---|---|---|
| `HUB_IPSec_Recommended` | A hub for the SD-WAN provisioning template; Remote Device = Dynamic (dial-up) | Enable ADVPN, outgoing interface, IPv4 start/end IP and netmask, pre-shared key |
| `Branch_IPSec_Recommended` | A branch dialling a hub, with several tunnels for SD-WAN | Enable ADVPN, outgoing interface, **Local ID** (so the hub can identify it), remote gateway (hub IP), pre-shared key |
| `IPSec_Fortinet_Recommended` | No role assumption | Outgoing interface, remote gateway, pre-shared key |

ADVPN is enabled either in the wizard of the hub or branch recommended template, or later in the advanced settings of any IPsec template. Use metadata variables for fields that must be unique per device, such as the Local ID.

### Single and dual hub-and-spoke with templates

| Design | Templates |
|---|---|
| Single hub, two underlays | Hub template with `VPN1` and `VPN2` (dial-up, one per hub WAN). Branch template with `HUB1-VPN1` and `HUB1-VPN2` |
| Dual hub | One hub template per hub (`HUB1_IPsec`, `HUB2_IPsec`). One branch template with `HUB1-VPN1`, `HUB1-VPN2`, `HUB2-VPN1`, `HUB2-VPN2` |

These names are what the SD-WAN overlay template generates. It also creates BGP templates (`BRANCH_BGP`, `HUB1_BGP`, …), CLI templates (loopbacks, router ID from `branch_id`), template groups per hub and for the branches, and the `branch_id` metadata variable.

### Template groups and SD-WAN members

A **template group** bundles the provisioning templates a device needs (IPsec, BGP, CLI, SD-WAN, static route) and is assigned to a device group. A new FortiGate added to the branch device group receives the whole set at its next install. That is how ZTP device blueprints scale.

To make the tunnels usable in SD-WAN templates and policy packages, map them to **normalized interfaces**. The overlay template creates `VPN1` / `VPN2` and per-device mappings for `HUB1`, `HUB2` and `HUB-Lo`. The SD-WAN template then places `HUB1-VPN1` and `HUB1-VPN2` in zone `HUB1` as members.

> **Exam tip:** IPsec templates do **not** configure SD-WAN rules or firewall policies. After assigning the templates you still need an SD-WAN template (zones, members, health checks, rules) and policy packages, then an install.

## VPN Manager (IPsec VPN communities)

VPN Manager builds a whole topology from one object:

1. **Create the community** with the VPN Topology Setup Wizard. Choose Full Meshed (every gateway to every other), Star (every gateway to a central hub) or Dial up (gateways with dynamic addresses connect to a hub). Then set authentication (certificate template or pre-shared key, generated or specified), the IKE profile (IKE version **2 by default** in the community settings, proposals, DH groups), and optional VPN zones.
2. **Add gateways**. *Managed* gateways are FortiGates in the same ADOM. *External* gateways are anything else, configured by hand on that device.
3. Install. FortiManager generates the phase 1/phase 2 interfaces, routes (when routing is Automatic) and zones on each managed gateway.

Gateway options to recognise:

| Option | Applies to | Purpose |
|---|---|---|
| Role: Hub / Spoke | Star, Dial up | Who is the hub |
| Hub-to-Hub Interface | Star, Dial up hubs | Required when there are several hubs |
| Routing: Manual / Automatic | All | Automatic generates routes to protected subnets |
| Summary Network(s) | Hubs | Summary routes advertised to spokes instead of every protected subnet |
| Add Route, mode config, IP assignment | Dial up | `add-route`, `mode-cfg`, address range or user group for dial-up peers |
| Network Overlay | IKEv2 communities | Network ID, so several tunnels can share the same gateway pair |
| `route-overlap` (advanced) | Gateways | `allow`, `use-new` or `use-old` when protected subnets overlap |

> **Watch out:** In VPN Manager, the exchange mode setting (main/aggressive) applies only to IKEv1. FortiManager notes that aggressive mode is needed for IKEv1 when several dial-up phase 1s share an interface IP and peers are identified by local ID. In IKEv2, network IDs solve the same problem.

### Templates or VPN Manager?

- Choose **IPsec templates** (or the overlay template that generates them) for SD-WAN: per-device variables, normalized interfaces, BGP templates, ADVPN 1.0/2.0 options, template groups for ZTP.
- Choose **VPN Manager** for a straightforward full mesh or star of FortiGates where routes to protected subnets are all you need, or when mixing in external gateways.

## Lab it yourself

The FortiManager-VM trial (3 devices/VDOMs, 2 ADOMs, no FortiGuard) can manage the FortiGate-VM trial plus model devices. Activate `HUB_IPSec_Recommended` and `Branch_IPSec_Recommended`, assign them to a model hub and a model branch, set a `branch_id` metadata value, and preview the generated CLI without installing. You can also install the hub template on your one real trial FortiGate. A working dual-hub install needs three real FortiGates, beyond one trial per FortiCloud account, so use the paid on-demand labs for that. Keep each install within the FortiGate trial caps of 3 interfaces, 3 policies and 3 routes. Automatic routing adds routes, so one remote subnet per tunnel is the maximum that fits.

## Key takeaways

- IPsec templates live in Device Manager > Provisioning Templates and are assigned to devices or device groups, usually through template groups.
- Routing Automatic (autorouting) creates static routes to the Remote Subnet. Manual suits BGP.
- Metadata variables (`$(branch_id)` and others) make one template fit many devices.
- Recommended templates: `HUB_IPSec_Recommended` (dial-up hub), `Branch_IPSec_Recommended` (Local ID, remote hub), `IPSec_Fortinet_Recommended` (generic). ADVPN can be enabled in the first two.
- Dual hub means one hub template per hub and one branch template with tunnels to both.
- VPN Manager communities are Full Meshed, Star or Dial up, with managed or external gateways, hub/spoke roles and summary networks.
