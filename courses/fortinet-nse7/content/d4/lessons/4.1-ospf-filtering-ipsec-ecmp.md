## Routing objects: one toolbox for every protocol

FortiOS keeps its route-filtering objects under **Network > Routing Objects** (CLI `config router ...`), and the same objects are used by OSPF, BGP and RIP:

| Object | CLI | Matches | Typical use |
|---|---|---|---|
| Access list | `config router access-list` | A prefix, optionally with `exact-match` or a Cisco-style `wildcard` | OSPF `distribute-list-in`, OSPF `config distribute-list` (what gets redistributed), BGP `distribute-list-in/out`, route-map `match-ip-address` |
| Prefix list | `config router prefix-list` | A prefix plus optional `ge` / `le` length bounds | BGP `prefix-list-in/out`, OSPF `distribute-list-in`, route-map `match-ip-address` |
| Route map | `config router route-map` | Ordered rules: `match-*` conditions, `set-*` actions, `action permit` or `deny` | Redistribution (`routemap` in OSPF, `route-map` in BGP), BGP `route-map-in/out`, OSPF `default-information-route-map` and `distribute-route-map-in` |
| AS path list | `config router aspath-list` | Regular expression on AS_PATH | BGP `filter-list-in/out`, route-map `match-as-path` |
| Community list | `config router community-list` | Standard or expanded community matches | Route-map `match-community` |

Each list is a sequence of numbered **rules**; the first matching rule decides, and anything that matches no rule is denied, just as with IOS lists and route maps. A rule's `action` defaults to **permit** in access lists, prefix lists and route maps (7.6.0 CLI Reference).

### Access lists are not IOS ACLs

The FortiOS access list is a *route* filter, closer to a Quagga/FRR access list than to an IOS standard ACL:

```text
config router access-list
    edit "AL-BRANCH-LANS"
        config rule
            edit 1
                set prefix 10.1.0.0 255.255.0.0
                set exact-match disable
            next
        end
    next
end
```

With `exact-match disable` (the default) the rule matches 10.1.0.0/16 **and every more-specific prefix inside it** (10.1.1.0/24, 10.1.2.0/24 ...). With `exact-match enable` only 10.1.0.0/16 itself matches. If you really want IOS wildcard logic, there is a separate `set wildcard <address> <wildcard>` option.

### Prefix lists work the way you expect

```text
config router prefix-list
    edit "PL-LAN-24S"
        config rule
            edit 1
                set prefix 10.1.0.0 255.255.0.0
                set ge 24
                set le 24
            next
        end
    next
end
```

This matches only /24s inside 10.1.0.0/16. Without `ge`/`le` the rule matches the prefix exactly. The semantics are identical to `ip prefix-list ... ge 24 le 24` on IOS.

### Route maps

```text
config router route-map
    edit "RM-CONNECTED-TO-OSPF"
        config rule
            edit 10
                set match-ip-address "PL-LAN-24S"
                set set-metric 50
                set set-metric-type external-type1
            next
        end
    next
end
```

Notable `match-*` options: `match-ip-address` and `match-ip-nexthop` (access list **or** prefix list), `match-interface`, `match-metric`, `match-route-type` (external-type1/2), `match-tag`, `match-community`, `match-as-path`, `match-origin`, `match-vrf`. Notable `set-*` options: `set-metric`, `set-metric-type`, `set-tag`, `set-route-tag`, `set-priority`, `set-weight`, `set-local-preference`, `set-community` (with `set-community-additive`), `set-aspath`, `set-ip-nexthop`, `set-origin`.

> **Watch out:** `set-tag` and `set-route-tag` are different fields. `set-tag` writes the protocol tag (for example the OSPF external route tag). `set-route-tag` writes the **route tag in the FortiOS routing table**, which is what SD-WAN rules can match through a `route-tag` address object (lesson 4.4).

## Redistribution into OSPF

```text
config router ospf
    config redistribute "connected"
        set status enable
        set routemap "RM-CONNECTED-TO-OSPF"
    end
    config redistribute "static"
        set status enable
        set metric 100
        set metric-type 1
    end
end
```

What to remember:

- Redistribution entries are a fixed, read-only table (one per source protocol, such as `connected`, `static`, `rip`, `bgp`). You don't create them; you enable them.
- There is no `subnets` keyword to forget: classless prefixes are redistributed as they are.
- With no metric anywhere, external routes get `default-metric` (10) and type 2. Precedence is route-map `set-metric` over the entry's `metric` over `default-metric`.
- The router becomes an **ASBR** once it redistributes or originates a default route; `get router info ospf status` says so ("This router is an ASBR").
- `config distribute-list` (with `set access-list` and `set protocol`) is an older way to limit what each protocol redistributes. A route map on the redistribute entry is more flexible.

### Filtering what OSPF installs

OSPF is link state: every router in an area must have the same LSDB, so you can't filter LSAs between neighbors in the same area. What you can do:

- `set distribute-list-in "<access list or prefix list>"`: stop matching OSPF routes from being **installed in the routing table** on this FortiGate. The LSAs are still flooded.
- `set distribute-route-map-in "<route map>"`: the same for external routes, with route-map logic.
- Summarize or filter at area borders (`config area` → `config range`, `config filter-list`) and at the ASBR (`config summary-address`).

> **Exam tip:** If an exhibit shows a route in `get router info ospf database` (the LSA is there) but not in `get router info routing-table all`, look for `distribute-list-in` on that FortiGate, or for a better route from another source with a lower distance.

## OSPF over IPsec

OSPF needs an interface with an IP address to send hellos. A route-based (interface-mode) IPsec tunnel gets one under `config system interface`:

```text
config system interface
    edit "HUB1-VPN1"
        set ip 10.10.1.1 255.255.255.255
        set remote-ip 10.10.1.254 255.255.255.0
    next
end
```

The `remote-ip` mask decides what the connected route covers. A /32 on both ends is a pure point-to-point link; a wider remote-ip mask (as in hub-and-spoke) gives a connected route for the whole overlay subnet.

For a site-to-site tunnel, Fortinet's example "OSPF with IPsec VPN for network redundancy" builds two tunnels to the same peer over two ISPs, gives each tunnel interface a /32 with a `remote-ip`, adds the tunnel subnets to `config network`, and sets on each `ospf-interface`:

```text
config router ospf
    config ospf-interface
        edit "pri"
            set interface "HUB1-VPN1"
            set cost 10
            set network-type point-to-point
        next
        edit "sec"
            set interface "HUB1-VPN2"
            set cost 20
            set network-type point-to-point
        next
    end
end
```

The cost difference makes VPN1 primary and VPN2 backup; equal costs would give ECMP. Set the network type explicitly: an `ospf-interface` entry defaults to broadcast, which would force a DR/BDR election on a link that only ever has two routers.

Things that bite on tunnels:

| Issue | Why | Fix |
|---|---|---|
| Neighbor stuck in ExStart/Exchange | The two tunnel ends report different interface MTUs in their DBD packets | Match the MTU or `set mtu-ignore enable` |
| Slow failover | Dead interval (40 s default) is the only failure detector if DPD and BFD are off | Tune hello/dead, use BFD (`set bfd enable` under OSPF and on the interface), keep DPD on the tunnel |
| Flood of SPF runs on all spokes | One big area over many tunnels | Use BGP on the overlay, or separate areas |
| Hub with dial-up spokes | Many spokes on one dial-up phase 1 | The 7.6 "ADVPN with OSPF" example requires `net-device enable` on the hub phase 1; with BGP Fortinet uses `net-device disable` instead |

> **Real world:** OSPF over a dial-up hub works for a handful of sites, but each spoke receives every other spoke's LSAs and runs SPF on every change. That is why the FortiManager SD-WAN overlay template only offers BGP for the overlay and why NSE 7 treats OSPF mainly as the LAN-side protocol.

## ECMP with OSPF

When OSPF finds two paths with the same cost to the same prefix, both next hops go into the routing table:

```text
O       10.11.101.0/24 [110/2] via 10.11.103.2, port2, 00:39:34
                       [110/2] via 10.11.102.1, port1, 00:39:34
```

FortiOS ECMP rules:

- Routes must have the same destination, distance and metric (for static routes also the same priority) and come from the **same protocol**.
- The number of paths is capped by `config system settings` → `set ecmp-max-paths` (default **255**; `1` disables ECMP). There is no OSPF-specific `maximum-paths` command as there is on IOS.
- The hashing method is `v4-ecmp-mode` under `config system settings` (default **source-ip-based**; also weight-based, usage-based, source-dest-ip-based). When SD-WAN is enabled this setting moves to `config system sdwan` → `set load-balance-mode`, which adds measured-volume-based.

## Use cases

| Scenario | Design |
|---|---|
| Data-center FortiGate between core switches and an SD-WAN hub role | OSPF to the core for LAN prefixes; BGP to the spokes; redistribute OSPF into BGP with a route map that permits only the DC summaries, and redistribute BGP (or just a default) into OSPF |
| Two sites, two ISPs, two tunnels | OSPF point-to-point on both tunnels, cost decides primary/backup or ECMP, BFD for fast failover |
| Branch with an L3 switch stack | OSPF area 0 between the FortiGate and the switch, `default-information-originate enable` so the switch follows the FortiGate's default route |
| Mixed-vendor LAN | Align `auto-cost-ref-bandwidth` with the Cisco routers |

## Lab it yourself

In the **FortiGate-VM trial**, build one route-based IPsec tunnel from port2 to a Linux strongSwan or Cisco IOS peer (low encryption only), give the tunnel interface an IP and remote-ip, and run OSPF point-to-point over it. One tunnel, one LAN policy pair and at most three prefixes stay inside the 3-interface / 3-policy / 3-route limits. A two-tunnel primary/backup or ECMP test needs a second underlay and a second tunnel interface; if the trial refuses the extra interface or the routes push you past three, that is the cap, and the test needs a fully licensed VM.

## Key takeaways

- Access lists, prefix lists, route maps, AS path lists and community lists are shared by OSPF and BGP; first match wins and the end is an implicit deny.
- A FortiOS access list matches a prefix **and everything more specific** unless `exact-match enable` is set; `wildcard` gives IOS-style matching.
- OSPF redistribution uses `config redistribute "<proto>"` with `status`, `metric`, `metric-type` and `routemap`; there is no `subnets` keyword.
- `distribute-list-in` stops OSPF routes from being installed locally; it doesn't stop LSA flooding.
- OSPF over IPsec needs tunnel interface IPs (`ip` + `remote-ip`) in a `config network` prefix; set `network-type point-to-point` and explicit costs.
- ECMP needs same prefix, distance, metric and protocol; capped by `ecmp-max-paths` (default 255) and hashed by `v4-ecmp-mode` (or SD-WAN `load-balance-mode`).
